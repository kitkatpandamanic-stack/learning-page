# JavaScript: PandaDev vs the outside world

Date: 2026-10-16. Repo: `main` at `e5e43cb`. Compared against [research/summary.md](../research/summary.md) and the five research files (written 2026-10-15). Paths below are relative to `content/courses/javascript/` unless they start with `content/` or `learning-site-content/`. Counts come from greps and scripts run on 2026-10-16.

**Verdict**

1. Broad and deep: 34 of the 36 consensus topics appear somewhere in the course. Only **Dates** is missing, and **Recursion** is written but not merged.
2. Levels 2–3 are well above typical free courses: security, system design, code review and leadership, plus exercises where the learner's own tests must catch planted bugs.
3. The weak spot is the Level 0–1 order: arrays, debugging, closures, `this`, hoisting and Map/Set arrive one or two levels later than the consensus, and `for…in` is never taught.
4. Lessons follow "worked example + exercise + quiz" closely and many quizzes use real misconceptions as wrong answers. Graduated hints, predict-before-run prompts and placement checks are mostly absent, and 6 Level 0 exercises only check printed output.
5. Few factual problems: 4 dated lines and 3 internal slips, mirrored in RU. EN/RU structure matches in all 112 lesson and problem pairs.

## Lesson quality findings

From a full read of all 72 EN lessons, the pending recursion lesson, and the task text of the 40 problems.

**Concepts used before they're taught**

- Function hoisting and the TDZ: the `todo-app/03-saving-with-localstorage.mdx` solution calls `loadTasks()` (line 482) before its declaration (line 490), and the hint (line 465) relies on TDZ ordering. Both are taught only in L3 `engine-internals/01`.
- Regular expressions are used without ever being taught: `testing/01-first-tests.mdx` (lines 270, 511–512, `toMatch`), `design-patterns/03:265`, `realtime-chat/01:296`, `performance/03` (`/^W\//`). The JS course has no regex lesson; Python has one (gaps.md #3).
- Prototypes: `Object.create`, `Object.getPrototypeOf` and `__proto__` drive L3 examples (`engine-internals/04`, `design-patterns/01`, `security/01`) with no lesson that explains the prototype chain.
- Recursion and stack overflow: `errors-and-debugging/01-reading-errors.mdx:131` explains `Maximum call stack size exceeded` before recursion exists on `main` (the pending branch adds a link).
- Accepted on purpose (callouts already explain it): DOM glue in the L0 capstone, the Promise preview in L1 `try-catch`.

**Factual slips (EN and RU alike)**

- `performance/02-fast-code-in-the-browser.mdx:202` (RU `:202`) says the Events lesson taught `event.target.closest(...)`. It taught `matches()` (`dom-and-events/02-events.mdx:172`), and `closest` has 0 hits at L1.
- `errors-and-debugging/01-reading-errors.mdx:147`: "the error **names** are always the same" across browsers. Firefox reports runaway recursion as `InternalError`. The pending branch already fixes this line.
- `classes/01-classes.mdx:89`: methods "stored once on the class". They live on `Panda.prototype`, which the exercise test on line 279 checks.

**EN/RU**

- Structure: a script compared every pair (exercise, quiz, hint, CodeExample, TryIt and `check:` counts, quiz answer indices, code fences, `xp`, `duration`). All 112 pairs (72 lessons + 40 problems) match. The 4 flagged lessons were false positives (the word "check:" in prose).
- Meaning: one RU twin per module and capstone (24) was read against EN, covering quizzes and recaps. No meaning mismatches were found. The RU twins repeat the EN slips above, so every fix needs both files.

**Length and difficulty jumps** (word counts include code)

- Median words per module lesson: L0 573 (391–1,204), L1 1,594 (1,296–1,891), L2 2,683 (2,145–4,584), L3 4,403 (3,277–6,048). Capstone parts reach 8,885 words (`realtime-chat/02`).
- L0 → L1 is a 2.8× step. Most L0 lessons are under 720 words, with one example per idea and no "common mistakes" section except `basics/04`.
- The pending recursion lesson is 3,651 words: 2.3× the L1 median, and longer than every other L1 lesson.
- Durations stay at 22–25 min for 3,300–8,900-word L3 lessons (gaps.md #8 still applies).

**Weak exercise tests**

- 6 L0 exercises only check printed output (`expectedOutput`): `basics/03`, `operators-and-conditions/01`, `03-if-else`, `loops/01`, `02`, `03`. Printing the literal answer (`console.log("95")`) passes.
- The L0 mini-project "Grade calculator" (`03-if-else`) is tested with `marks = 85` only. The invalid-marks branch and the A/C/F branches are never checked.
- Source-text checks are brittle: `functions/02` (`isEven.toString().includes("=>")`) and `errors-and-debugging/02` (`safeQuantity.toString().includes("catch")`).
- Strong by contrast: L1+ exercises test functions with several inputs, and 7 lessons check the learner's own tests by planting bugs.

**Fit with the design rules in summary.md**

- Worked examples (rule 4): strong. There are 362 CodeExamples and 59 TryIt blocks over 72 lessons, most with exact output. Capstones open with a plan (subgoal-style). Support fades across capstone parts.
- Predict before run (rule 5): weak. Only `engine-internals/02` asks learners to write down an answer before checking. 51 of 116 quizzes are trace or predict questions (counted with a keyword search, so approximate), but every CodeExample shows its output right away.
- Misconception-based distractors (rule 11): strong. Examples: `[3, 20, 100].sort()` → `[100, 20, 3]`, `0 || 10`, `async f()` returns a Promise, `dataset` ids are strings, `toBe` on objects, `super()` before `this`. No confidence rating anywhere.
- Graduated hints (rule 10): weak. 71 exercises have 68 hints; only `basics/04` has two hint steps, 4 L0 exercises have none (`basics/03`, `operators-and-conditions/01`, `02`, `loops/02`), and many hints are almost the solution (for example `testing/03`, `react/04`).
- Placement for engineers (rule 13): absent. There are no "Already know this?" summaries (gaps.md #5).
- Parsons problems (rule 6): absent. There is no component for them (app work).

## Strengths

- **The top confusion is taught head-on.** Returning a value from async code, a forgotten `await`, `forEach` with `async`, `return await` inside `try`, and parallel vs sequential awaits all have their own runnable demos (`async/01-03`). Learners hit these constantly: 18,840 and 1,374 linked duplicates [learner-struggles S2].
- **Learners' own tests are graded by planting bugs** (`__retest`: `testing/01-03`, `node-and-express/03`, `weather-dashboard/01`, `realtime-chat/01-02`). This turns the most-cited feedback weakness (auto-graders only say what's wrong [learning-science S17]) into practice at writing good tests.
- **Senior content most free courses lack.** None of the 5 surveyed JS syllabi has system design, architecture or mentoring [courses]. PandaDev has 3 lessons each on security, design patterns and system design and leadership, plus a design-to-launch capstone.
- **Security depth:** XSS contexts and URL schemes, NoSQL operator injection, prototype pollution, ReDoS, CSRF tokens, CORS misconfiguration, secret scanning and the 2025 npm supply-chain incidents. These match the L3 security row [industry-levels S6, S20].
- **Modern, accurate APIs throughout:** Express 5, `AbortSignal.timeout`, `structuredClone`, `??`/`?.`, `Object.hasOwn`, `scheduler.yield()`, INP instead of FID, `node --watch`/`--env-file`, Vite and React with Strict Mode.
- **Deterministic runnable back-end and network code in the browser** (practice API, in-memory Express, supertest and `ws`), so fetch, API and WebSocket exercises are tested, not just read.
- **Consistent shape:** every lesson but one has an Exercise, all 72 have quizzes with explanations, and EN/RU parity is perfect.
