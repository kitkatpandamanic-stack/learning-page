# TypeScript: PandaDev vs the outside world

Compared on 2026-10-16. PandaDev side: `content/courses/typescript/` (all 62 EN lessons read in full, RU twins checked by script and spot-read), `content/practice/typescript/` (40 problems) and the in-browser checker in `src/lib/runner/`. Outside side: the five research files from 2026-10-15 and `research/summary.md`. No web requests were made for this file. Facts marked "verified locally" were checked with the repo's TypeScript 6.0.3 and the local Node v24.21.0.

**Verdict**

1. PandaDev's TypeScript course is far more complete than the free courses the research found: 62 lessons over four levels, 17 of them at Level 3. Research found only 2 TS syllabi (one paid) and no free source for Level 3 topics [courses].
2. Of the 26 consensus topics, 15 are covered at the right level, 4 are partial, 3 come later than the consensus, 3 come earlier, and 1 is missing (decorators).
3. It is unusually current. The checker runs TypeScript 6.0.3 with `strict: true`, and the lessons teach the 6.0 defaults, `erasableSyntaxOnly`, `verbatimModuleSyntax`, Node's type stripping and the TS 7 Go port. They never use ts-node, `moduleResolution: node`, `outFile` or `target: es5` [official-docs S11, S19].
4. The main weaknesses are at the two ends of the audience. Level 0 says "from scratch" but uses JavaScript features it never explains, and JS developers get no fast track. Enums, `as const`/`satisfies`, intersections and string indexing arrive late or are never taught head-on.
5. Factual slips are few, and all are small: decorators are missing from the "not erasable" list, one compiled-output sample is wrong, TS 7 is described only through 6.0 deprecations, and the SDK's CI tests on Node 20, which reached end of life on 2026-04-30.

## Out of date or incorrect

Only cases checked against the files (and, where marked, run locally). Every fix applies to the `.ru.mdx` twin too: the line numbers given are the same in both, unless noted.

1. **Decorators are missing from the "not erasable" list, so the advice for running TS under Node is incomplete.** `build-performance/01-how-the-compiler-works.mdx:146` says "Everything else is erasable", and the recap at line 535 repeats the list. Line 298 says the `erasableSyntaxOnly` tsconfig "makes the editor warn you about everything Node would reject". Verified locally: TS 6.0.3 accepts `@d class A {}` under `--erasableSyntaxOnly` and emits `__esDecorate` helpers, while `node deco.ts` fails with a syntax error. **Fix:** add standard (TC39) decorators to the list, say they are back at Stage 2.7 [official-docs S6] and that Node rejects them [official-docs S11], and note that `erasableSyntaxOnly` does not flag them.
2. **Wrong compiled output.** `dom-and-tooling/03-tsconfig-and-the-compiler.mdx:124` and `:131` show `dist/main.js` ending in `export {};`, saying it "just marks the file as a module". Verified locally with the lesson's own options (strict, `es2022`, `esnext`, `bundler`, `verbatimModuleSyntax`, `rootDir`/`outDir`): TS 6.0.3 writes `"use strict";` at the top and no `export {}`. You only get `export {}` with `"moduleDetection": "force"`, which PandaDev's runner and `tsc --init` set. **Fix:** either add `"moduleDetection": "force"` to the config in that lesson, or show `"use strict";` and drop the sentence.
3. **TS 7 described only through 6.0.** `dom-and-tooling/03-tsconfig-and-the-compiler.mdx:86` says "Very old targets like `es5` are deprecated in TypeScript 6". Since 7.0 (2026-07-08) they are hard errors, and so are `moduleResolution: node`, `baseUrl` as a lookup root, `outFile` and `esModuleInterop: false` [official-docs S19]. **Fix:** "deprecated in 6.0 and an error in 7.0", plus a one-line list of those options.
4. **An overbroad promise.** `build-performance/01-how-the-compiler-works.mdx:367` says "Your code, your `tsconfig.json` and everything in this course work the same in both." But 7.0 has no stable programmatic API yet, and the TS team tells tools built on it to stay on 6.0 [official-docs S19]. The course teaches several such tools: typescript-eslint's type-aware rules (`leadership/01`), typescript-strict-plugin (`leadership/02`) and tsd (`testing/03`). **Fix:** "your code and tsconfig work the same; tools built on the compiler API still need TypeScript 6 installed next to 7 (`@typescript/typescript6`)."
5. **The SDK tests on a dead Node version.** `typed-sdk/03-shipping-it.mdx:401` has the CI matrix `node: [20, 22, 24]`. Node 20 reached end of life on 2026-04-30, and Node 26 becomes Active LTS on 2026-10-28 (official-docs, "Node.js versions", citing S8). **Fix:** `[22, 24, 26]`. The related promises "Node 20+" (`typed-sdk/01-designing-the-sdk.mdx:34`, `typed-sdk/03-shipping-it.mdx:348`, `:498`) and `"engines": { "node": ">=20" }` (`typed-sdk/03:335`) should either move to 22 or say that 20 is end-of-life. A lower priority: `testing/03-testing-types.mdx:441`, `fullstack-todos/03-the-react-client.mdx:425` and `typed-sdk/03-shipping-it.mdx:427` pin `node-version: 22`, which is maintenance LTS until 2027-04-30. That's not wrong, but 24 is the better default.

Checked and found correct: TS5112, `tsc --init` turning on `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`, Node rejecting enums, parameter properties and `<T>x` assertions (all verified locally), "Node 22.18 and newer" [official-docs S11], `types: []` and `baseUrl` deprecation in 6.0 [official-docs S19], and React 19's `SubmitEvent` and `FormEvent` deprecation.

## Lesson quality findings

**Concepts used before they're taught (Level 0, which says "Learn it from scratch").** The course never explains these JavaScript features, but uses them in examples, hints or solutions:

- the ternary `? :`: `arrays-and-objects/02-object-types-and-interfaces.mdx:54`, and in the `arrays-and-objects/03` mini-project solution (line 309);
- object spread `{ ...a, ...b }`: `arrays-and-objects/03-typed-data.mdx:182`, commented only as "a new object";
- array spread: `functions/02-optional-default-and-rest.mdx:100` and `arrays-and-objects/01-arrays-and-tuples.mdx:66`;
- `.map`: `functions/03-arrow-functions-and-callbacks.mdx:98`, described only by its types. The module's mini-project needs `ops.map(...)`, and only the hint shows it. What `map` actually does is explained one module later, in `arrays-and-objects/01:108`;
- tuple destructuring: `arrays-and-objects/01:85`.

The few other forward uses are flagged in the text, which is fine: `if` in `basics/03`, and `async` in `generics/03` ("Level 2").

**Length and difficulty jumps** (word counts from `wc -w`, which includes code):

- L0 lessons are 921–1,652 words. L1 lessons are 2,538–4,223, and L2 lessons 3,654–7,231.
- Capstone parts run from 2,386 words (L0) to 11,949 (`typed-sdk/02`), with durations capped at 18–25 minutes.
- 9 non-capstone lessons are over 5,000 words.
- The step from L0 to L1 is the steepest. `classes/01` alone has 9 sections, from fields and parameter properties through `#private`, `this`, getters and setters to `static`. That goes against "one new element at a time" (design rule 8 [learning-science S8]).

**Exercises.** The tests are strong overall:

- Type tests with `@ts-expect-error` are built into most L1–L3 exercises.
- 8 lessons use mutation checks (`__retest`), so learners' own tests must catch planted bugs.

Two weak spots:

- `habit-tracker/01-modelling-habits.mdx:853` and `habit-tracker/02-the-habit-store.mdx:1237` check that learners "added a Vitest test" only by counting passes (`__vitest.passed >= 6` and `>= 5`). Any trivial `expect(1).toBe(1)` passes.
- `dom-and-tooling/03` says "No `!` and no `as`", but nothing enforces it. The tests catch most misuse indirectly.

**Design rules** (`summary.md` → "Lesson, exercise, quiz and motivation design rules"). The course follows some rules well:

- **Rules 1, 3 and 11:** every lesson has 1–2 quizzes (100 in total), each with an explanation and distractors built from real misconceptions ("TypeScript converts it", "`as` checks it").
- **Rule 4:** capstones fade the support from part to part.
- **Rule 16:** every lesson has one Exercise. 9 of 17 modules end with a mini-project, and none of the 5 L3 modules has one.

Others are missing or weak:

- **Rule 5, predict before running:** this happens only in a few L0 quizzes. `CodeExample` always shows the output straight away.
- **Rule 10, graduated hints:** each exercise has a single `Hint`, which often contains most of the solution (for example `generics/03` and `react/01`).
- **Rule 13, placement checks:** there's no placement check or "already know this?" path for JS developers.

**EN/RU.** A script compared all 62 pairs: quiz answer indices, the number of Exercise, Quiz, CodeExample and TryIt blocks, duration, XP and `##` sections all match in every pair. Test strings and outputs differ only where text is translated. Spot-reads of passages from all 17 modules and 4 capstones (including the TS 6/7, Node-stripping and enum passages) found no meaning mismatches. One terminology inconsistency: parameter properties are called «свойства-параметры» in 4 RU files (`classes/01`, `dom-and-tooling/03`, `node/02`, `typed-sdk/02`) but «параметры-свойства» in 2 (`build-performance/01`, 6 times, and `async-and-apis/02`). Pick the term `classes/01` introduces.

**Practice.** There are 40 problems (12 easy, 18 medium, 10 hard), linked to 9 L0, 18 L1, 4 L2 and 9 L3 lessons. None covers React, Node or testing (also in `gaps.md` #2).

## Strengths

- **Coverage where free courses stop.** TS has the fewest free syllabi of any language (2, one paid), and none covers advanced type-level programming, declaration files or build performance [courses]. PandaDev has 17 L3 lessons on exactly these, plus code review and adoption.
- **Current with 2026 TypeScript.** The checker is TS 6.0.3 with `strict: true`, and the lessons teach what changed. The research says older tutorials go wrong on non-strict configs, enums under Node and ts-node [summary, "Current versions → TypeScript"], and PandaDev avoids all three:
  - TS 6 defaults: `strict`, `types: []`, TS5112, and the `baseUrl` deprecation (TS5101).
  - `erasableSyntaxOnly` and `verbatimModuleSyntax`.
  - Node lessons deliberately avoid parameter properties (`node/02:258`, `typed-sdk/02:412`).
  - Unions are preferred over enums, and there's no ts-node anywhere.
  - Library versions are current too: React 19, Express 5, Vitest and zod.
- **Misconceptions taught head-on.** The erasure idea ("types don't check data") runs from L0 to L3, which matches confusion #6 and the Handbook's own warning [learning-science S54].
- **Tests and types as one skill.** There are typed fakes and mocks, and type tests. Mutation-checked exercises make learners write tests that really catch bugs. That's something industry ladders value ("writes good tests") [industry-levels S11, S21].
- **Honest senior judgement.** Many L3 lessons end with a "when not to" section, such as over-clever conditional types, deriving vs writing out, and builders vs options objects. That matches the interview advice that over-engineered types are a common mistake [industry-levels S18].

## Recommendations

Ranked by impact for learners. Research on TypeScript is the thinnest of the four languages: 2 syllabi, no learner misconception studies, and Stack Overflow data mostly from before `satisfies` and TS 7 existed [summary, "Weak spots in the method"]. Treat the ● ratings on L2–L3 rows as weak evidence.

1. **Close the JavaScript gaps in Level 0.** Add a short "JavaScript you'll see" section, or a lesson, before `functions/03`. It should cover what `map` and `filter` do, the ternary, and array and object spread, and those features should only be used after it. **Why:** the course says "from scratch" but uses them unexplained (see quality findings), while both syllabi assume JS first [courses S4, S24]. It also follows rule 8, one new element at a time [learning-science S8]. **Who:** newcomers. **Effort:** S–M. **Type:** fix existing.
2. **Add a fast track for JavaScript developers.** A placement quiz, or a "Coming from JavaScript?" summary at the start of L0 and L1, that lets them skip to `unions-and-narrowing`. **Why:** guidance that helps beginners slows experts down [learning-science S8, S9], and the Handbook has entry pages by background [official-docs S17]. Most TS learners already know JS, and industry treats "TS in depth" as the junior → middle step [industry-levels S25] (also `gaps.md` #5). **Who:** engineers. **Effort:** M. **Type:** new lesson, or a site feature.
3. **Teach enums properly, then the alternative.** Add a short L1 lesson or section (for example `unions-and-narrowing/04` or a section in `control-flow/02`) on reading enums: string vs numeric, reverse mapping, converting a string, looping over values. Then show why Node rejects them, and the `as const` + union replacement that L3 `build-performance/01` now has. **Why:** a ●● L1 topic, a large Stack Overflow cluster [learner-struggles S1], and code learners will meet [industry-levels S3; official-docs S11]. **Who:** both. **Effort:** M. **Type:** new lesson.
4. **Move `as const` and `satisfies` to Level 1.** Add a section to `unions-and-narrowing/03` next to `as`, and keep the deep comparison at L3. **Why:** consensus L1, ●●● [industry-levels S3; courses S4]. They're used from L2 `testing/01` onwards. **Who:** both. **Effort:** S. **Type:** fix existing.
5. **Teach string indexing head-on.** Cover the TS7053 implicit-`any` error, why `Object.keys` returns `string[]` (structural typing), `keyof typeof`, and `Record` vs index signatures, naming the syntax. Put it in `generics/01` or `generics/03`. **Why:** confusion #4b, 1.14M views, isn't taught anywhere [learner-struggles S1]. **Who:** both. **Effort:** S. **Type:** fix existing.
6. **Bring TS 7 up to date, and add a migration path.** Apply fixes 1–4 from "Out of date or incorrect", then add a "From 6 to 7" section to `build-performance/02`. It should say to clear the deprecations first, try `--stableTypeOrdering`, and that `ignoreDeprecations: "6.0"` doesn't carry over. It should also cover `--checkers`/`--builders`, running `tsc6` alongside, and which tools stay on 6.0. **Why:** 7.0 has been the npm `latest` since July [official-docs S19; learner-struggles S14], and this is a ● L3 topic. **Who:** engineers. **Effort:** S–M. **Type:** fix existing.
7. **Finish the `interface` vs `type` story and teach intersections.** Add declaration merging to the `arrays-and-objects/02` table, and an intersections section to L1 `unions-and-narrowing/01`. It should cover combining shapes, conflicts that collapse to `never`, and `extends` vs `&`. **Why:** the most-voted TS question (2,811 votes, 104 linked) [learner-struggles S1, S2], and intersections are an L1 ●●● topic [summary]. **Who:** both. **Effort:** S. **Type:** fix existing.
8. **Split or check the longest lessons.** That's the 9 non-capstone lessons over 5,000 words (for example `node/03`, `node/02` and `async-and-apis/03`) and the capstone parts over 8,000 words. Either split them, or add more quizzes partway through and set realistic durations. Stop pasting the whole schema library into every later starter. **Why:** short lessons with a check each time [courses S1, S5, S21, S22] (provider practice, opinion-level evidence), retrieval practice [learning-science S28, S29], and `gaps.md` #8. **Who:** everyone. **Effort:** L. **Type:** restructure.
9. **Add a short decorators section, not a module.** Show what they look like in Angular, NestJS or Lit, compare standard and `experimentalDecorators`, explain Stage 2.7, and say that Node rejects them (fix 1). It could go at the end of `classes/02` or in `build-performance/01`. **Why:** ●● L2 [industry-levels S3; official-docs S6, S11]. Keep it small, because the proposal stepped back. **Who:** engineers. **Effort:** S. **Type:** fix existing.
10. **Make "write a test" checks real in the L1 capstone.** Add `__retest` mutations to `habit-tracker/01` and `/02`, as L2 does, so a trivial passing test no longer earns the check. **Why:** feedback should say what's wrong; a bare pass count can't [learning-science S17, S18]. **Who:** newcomers. **Effort:** S. **Type:** fix existing.
