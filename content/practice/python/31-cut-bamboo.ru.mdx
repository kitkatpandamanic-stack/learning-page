В зоопарке есть несколько стеблей бамбука разной длины и `k` голодных панд. Каждая панда должна получить один кусок, и все куски должны быть **одинаковой** целой длины, чтобы никто не обиделся. Напишите `longest_piece(stalks, k)`, которая возвращает самую большую длину куска, при которой это возможно.

- `stalks` — список длин стеблей (целые числа, 1 или больше), а `k` не меньше 1.
- Стебель длины `s` даёт `s // length` кусков; остаток пропадает, а куски от разных стеблей склеивать нельзя.
- Можно нарезать больше `k` кусков — нужно *хотя бы* `k`.
- Если не хватает даже кусков длины 1 (или стеблей нет вообще), верните `0`.

```python
longest_piece([8, 5, 10], 4)    # 5: куски по 5 дают 1 + 1 + 2 = 4
longest_piece([8, 5, 10], 5)    # 4: 2 + 1 + 2 = 5
longest_piece([8, 5, 10], 1)    # 10
longest_piece([8, 5, 10], 23)   # 1
longest_piece([8, 5, 10], 24)   # 0: бамбука всего 23 см
```

Стебли бывают длиной до миллиарда единиц, поэтому перебирать все длины по одной слишком медленно.

Допишите `longest_piece(stalks, k)`, чтобы функция быстро находила самый длинный честный кусок.

<Hint>

Если куски длины `L` подходят, то подходит и любая меньшая длина, а если `L` не подходит, то не подойдёт и никакая большая. Такая картина «да, да, …, да, нет, нет» — именно то, что нужно для двоичного поиска (binary search).

</Hint>

<Hint>

Ищите последнюю подходящую длину между `0` и `max(stalks)`. Для средней длины `mid` посчитайте куски с помощью `sum(s // mid for s in stalks)` и оставьте ту половину, где ещё есть ответ. Берите `mid = (lo + hi + 1) // 2`, чтобы цикл не застрял.

</Hint>

<Solution>

```python
def longest_piece(stalks, k):
    lo, hi = 0, max(stalks, default=0)
    # Инвариант: длина lo подходит (0 «подходит» всегда), длины больше hi — нет.
    while lo < hi:
        mid = (lo + hi + 1) // 2
        pieces = sum(s // mid for s in stalks)
        if pieces >= k:
            lo = mid
        else:
            hi = mid - 1
    return lo

print(longest_piece([8, 5, 10], 4))  # 5
```

Это двоичный поиск по *ответу*, а не по списку: каждая догадка проверяется за O(n), а деление диапазона возможных длин пополам требует O(log M) догадок, где M — длина самого длинного стебля. Итого O(n log M) — около 30 раундов даже для миллиарда.

</Solution>
