Калькулятору «Панда 3000» нужен мозг. Напишите `calculate(expression)`, которая вычисляет значение арифметического выражения (expression), заданного строкой, и возвращает его как `int`.

- Числа — целые, состоят из цифр (без десятичной точки). Пробелы в любом месте игнорируются.
- `+`, `-` и `*` работают как обычно, а `^` означает «в степени», так что `2 ^ 10` равно 1024.
- `^` связывает сильнее всех и группируется справа: `2 ^ 3 ^ 2` — это `2 ^ 9` = 512. Затем идёт `*`, затем `+` и `-`, которые группируются слева: `10 - 4 - 3` равно 3. Скобки `( )` перекрывают всё это.
- `-` там, где ожидается число (в начале, после `(` или сразу после `+`, `-` или `*`), меняет знак того, что идёт следом, и связывает слабее, чем `^`: `-2 ^ 2` равно -4, а `2 * -3` равно -6.
- Всё остальное вызывает `ValueError`: неизвестные символы (включая `/` и `.`), пропущенное число (`"1 +"`, `""`, `"2 ** 3"`), два числа подряд или непарные скобки. В корректных выражениях число никогда не возводится в отрицательную степень.

```python
calculate("3 + 4 * 2")          # 11
calculate("(3 + 4) * 2")        # 14
calculate("2 ^ 3 ^ 2")          # 512
calculate("-2 ^ 2")             # -4
calculate("-(2 + 3) * 4")       # -20
calculate("2 * (1 + 2) ^ 2")    # 18
calculate("(1 + 2")             # ValueError
```

Встроенный в Python `eval()` здесь не поможет: в Python `^` означает совсем другое.

Допишите `calculate(expression)`, не используя `eval`.

<Hint>

Сначала разбейте текст на токены (tokens): `re.findall(r"\d+|\S", expression)` даёт числа и отдельные символы, и всё, что не является последовательностью цифр или одним из `+ - * ^ ( )`, можно сразу отклонить.

</Hint>

<Hint>

Напишите по одной маленькой функции на каждый уровень приоритета, и пусть каждая вызывает следующую, более сильную: `expr` обрабатывает `+`/`-`, вызывая `term`; `term` обрабатывает `*`, вызывая `unary`; `unary` обрабатывает ведущий `-` или вызывает `power`; а `power` читает число или `expr` в скобках и, если дальше идёт `^`, снова вызывает `power` для показателя степени — так `^` группируется справа. Все функции продвигают одну общую позицию по токенам.

</Hint>

<Solution>

```python
import re

def calculate(expression):
    tokens = re.findall(r"\d+|\S", expression)
    for token in tokens:
        if not token.isdigit() and token not in "+-*^()":
            raise ValueError(f"unexpected {token!r}")
    pos = 0

    def peek():
        return tokens[pos] if pos < len(tokens) else None

    def take():
        nonlocal pos
        token = peek()
        if token is None:
            raise ValueError("unexpected end of expression")
        pos += 1
        return token

    def expr():  # term (+|- term)*
        value = term()
        while peek() in ("+", "-"):
            if take() == "+":
                value += term()
            else:
                value -= term()
        return value

    def term():  # unary (* unary)*
        value = unary()
        while peek() == "*":
            take()
            value *= unary()
        return value

    def unary():  # -unary | power
        if peek() == "-":
            take()
            return -unary()
        return power()

    def power():  # atom (^ power)?  группировка справа
        base = atom()
        if peek() == "^":
            take()
            return base ** power()
        return base

    def atom():  # number | ( expr )
        token = take()
        if token.isdigit():
            return int(token)
        if token == "(":
            value = expr()
            if take() != ")":
                raise ValueError("missing )")
            return value
        raise ValueError(f"expected a number, got {token!r}")

    value = expr()
    if pos != len(tokens):
        raise ValueError(f"unexpected {tokens[pos]!r}")
    return value

print(calculate("3 + 4 * 2"))  # 11
```

Это парсер рекурсивного спуска (recursive descent parser): каждый уровень приоритета — функция, которая вызывает более сильный уровень для своих операндов, поэтому `*` применяется раньше `+` без всяких особых случаев. `power` вызывает саму себя для показателя степени — именно поэтому `^` группируется справа, — а финальная проверка позиции ловит остатки вроде второго числа или лишней `)`. Каждый токен читается один раз, так что работа занимает O(n) для n токенов.
