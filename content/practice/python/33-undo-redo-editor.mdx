Write a class `Editor` for a one-line text box with undo and redo, the way real editors behave:

- `Editor(limit=None)` starts with `text` equal to `""`. `limit` is how many changes can be undone (the oldest ones are forgotten first); `None` means no limit.
- `type(chars)` adds `chars` to the end of `text`.
- `delete(count)` removes the last `count` characters (all of them if there are fewer).
- `undo()` reverts the most recent change that hasn't been undone and returns `True`, or returns `False` if there is nothing to undo.
- `redo()` re-applies the most recently undone change and returns `True`, or returns `False` if there is nothing to redo.
- A new `type` or `delete` that changes the text clears everything that could be redone. A call that doesn't change the text (typing `""`, `delete(0)`, deleting from empty text) isn't a change at all: it doesn't count for undo and doesn't clear redo.

```python
e = Editor()
e.type("bamboo")
e.delete(3)      # text is now 'bam'
e.undo()         # True, text is 'bamboo'
e.undo()         # True, text is ''
e.undo()         # False, nothing left
e.redo()         # True, text is 'bamboo'
e.type("!")      # text is 'bamboo!', and the redo history is gone
e.redo()         # False

small = Editor(limit=2)
for word in ["a", "b", "c"]:
    small.type(word)
small.undo(); small.undo()   # text is 'a'
small.undo()                 # False: only 2 changes are remembered
```

Undo and redo are both "last in, first out": the most recent change is the first one to come back. What if you saved a snapshot of the whole `text` before each change?

<Hint>

Keep two stacks. Send every edit through one helper, say `_change(new_text)`: if the new text equals the old one, do nothing; otherwise push the old `text` onto the undo stack, clear the redo stack and set the new text. `undo` pops from the undo stack and pushes the current text onto the redo stack; `redo` does the reverse. For the limit, make the undo stack a `collections.deque(maxlen=limit)`: it drops its oldest item by itself when it's full, and `maxlen=None` means unlimited.

</Hint>

<Solution>

```python
from collections import deque

class Editor:
    def __init__(self, limit=None):
        self.text = ""
        self._undo = deque(maxlen=limit)
        self._redo = []

    def _change(self, new_text):
        if new_text == self.text:
            return
        self._undo.append(self.text)
        self._redo.clear()
        self.text = new_text

    def type(self, chars):
        self._change(self.text + chars)

    def delete(self, count):
        if count > 0:
            self._change(self.text[:-count])

    def undo(self):
        if not self._undo:
            return False
        self._redo.append(self.text)
        self.text = self._undo.pop()
        return True

    def redo(self):
        if not self._redo:
            return False
        self._undo.append(self.text)
        self.text = self._redo.pop()
        return True


e = Editor()
e.type("bamboo")
e.delete(3)
print(e.text)  # bam
```

Each stack holds snapshots of the text, so undo and redo are just moving the current text between two stacks, O(1) apart from copying strings. Routing every edit through `_change` keeps the rules in one place: no-op edits are skipped, and real ones clear the redo stack.

</Solution>
