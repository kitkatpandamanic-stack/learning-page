The Panda Calculator 3000 needs a brain. Write `calculate(expression)` that works out the value of an arithmetic expression given as a string and returns it as an `int`.

- Numbers are whole numbers made of digits (no decimal points). Spaces anywhere are ignored.
- `+`, `-` and `*` work as usual, and `^` means "to the power of", so `2 ^ 10` is 1024.
- `^` binds tightest and groups from the right: `2 ^ 3 ^ 2` is `2 ^ 9` = 512. Then `*`, then `+` and `-`, which group from the left: `10 - 4 - 3` is 3. Brackets `( )` override all of this.
- A `-` where a number is expected (at the start, after `(`, or right after `+`, `-` or `*`) negates what follows, and binds more loosely than `^`: `-2 ^ 2` is -4 and `2 * -3` is -6.
- Anything else raises `ValueError`: unknown characters (including `/` and `.`), a missing number (`"1 +"`, `""`, `"2 ** 3"`), two numbers in a row, or unmatched brackets. Valid expressions never raise a number to a negative power.

```python
calculate("3 + 4 * 2")          # 11
calculate("(3 + 4) * 2")        # 14
calculate("2 ^ 3 ^ 2")          # 512
calculate("-2 ^ 2")             # -4
calculate("-(2 + 3) * 4")       # -20
calculate("2 * (1 + 2) ^ 2")    # 18
calculate("(1 + 2")             # ValueError
```

Python's own `eval()` won't help: in Python, `^` means something else entirely.

<Hint>

First split the text into tokens: `re.findall(r"\d+|\S", expression)` gives numbers and single characters, and you can reject anything that isn't a digit run or one of `+ - * ^ ( )` straight away. Then write one function per level, each calling the next tighter one: `expr` handles `+`/`-` by calling `term`, `term` handles `*` by calling `unary`, `unary` handles a leading `-` or calls `power`, and `power` reads a number or a bracketed `expr` and, if a `^` follows, calls `power` again for the exponent so that `^` groups from the right. All the functions move one shared position forward through the tokens. At the end, if any tokens are left over, raise `ValueError`.

</Hint>

`peek()` looks at the current token (or `None` at the end), and `take()` returns it and moves on, raising `ValueError` if there's nothing left; use `nonlocal pos` to share the position.

<Solution>

```python
import re

def calculate(expression):
    tokens = re.findall(r"\d+|\S", expression)
    for token in tokens:
        if not token.isdigit() and token not in "+-*^()":
            raise ValueError(f"unexpected {token!r}")
    pos = 0

    def peek():
        return tokens[pos] if pos < len(tokens) else None

    def take():
        nonlocal pos
        token = peek()
        if token is None:
            raise ValueError("unexpected end of expression")
        pos += 1
        return token

    def expr():  # term (+|- term)*
        value = term()
        while peek() in ("+", "-"):
            if take() == "+":
                value += term()
            else:
                value -= term()
        return value

    def term():  # unary (* unary)*
        value = unary()
        while peek() == "*":
            take()
            value *= unary()
        return value

    def unary():  # -unary | power
        if peek() == "-":
            take()
            return -unary()
        return power()

    def power():  # atom (^ power)?  right-grouping
        base = atom()
        if peek() == "^":
            take()
            return base ** power()
        return base

    def atom():  # number | ( expr )
        token = take()
        if token.isdigit():
            return int(token)
        if token == "(":
            value = expr()
            if take() != ")":
                raise ValueError("missing )")
            return value
        raise ValueError(f"expected a number, got {token!r}")

    value = expr()
    if pos != len(tokens):
        raise ValueError(f"unexpected {tokens[pos]!r}")
    return value

print(calculate("3 + 4 * 2"))  # 11
```

This is a recursive descent parser: each precedence level is a function that calls the tighter level for its operands, so `*` is applied before `+` without any special cases. `power` calls itself for the exponent, which is what makes `^` group from the right, and the final position check catches leftovers like a second number or a stray `)`. Each token is read once, so it runs in O(n) for n tokens.

</Solution>
