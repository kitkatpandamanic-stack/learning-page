The panda weather app asks a slow server for forecasts, so it keeps recent answers in a cache. Answers go stale, though, and memory is limited. Write a class `ExpiringCache` that handles both.

- `new ExpiringCache({ capacity, ttl, now })`: `capacity` is the most entries it holds, `ttl` is how long an entry lives in milliseconds, and `now` is a function that returns the current time in ms (default `Date.now`; tests pass a fake clock). `now()` never goes backwards. A `capacity` that isn't a whole number of at least 1, or a `ttl` that isn't more than 0, throws a `RangeError`.
- An entry is **used** when it is stored with `set` or read with `get`. It **expires** `ttl` ms after its last use: once `now()` reaches `lastUse + ttl`, the cache acts as if it was never there.
- `set(key, value)` stores or replaces the value and uses the entry. If that makes more than `capacity` live entries, the **least recently used** one is removed. It returns the cache.
- `get(key)` returns the value of a live entry (and uses it), or `undefined`.
- `has(key)` says whether `key` has a live entry, **without** using it.
- `delete(key)` removes the entry and returns whether there was a live one.
- The `size` getter counts live entries, and `keys()` returns the live keys as an array, least recently used first.
- Every method except `keys` must take O(1) time on average, even with 50,000 entries.

```js
let clock = 0;
const cache = new ExpiringCache({ capacity: 2, ttl: 1000, now: () => clock });
cache.set("rain", "🌧️").set("sun", "☀️");
cache.get("rain");      // "🌧️" (now "sun" is the least recently used)
cache.set("snow", "❄️"); // "sun" is removed to make room
cache.keys();           // ["rain", "snow"]

clock = 999;
cache.get("rain");      // "🌧️", and it now lives until 1999
clock = 1000;
cache.has("snow");      // false: set at 0, never used since
clock = 1999;
cache.get("rain");      // undefined
cache.size;             // 0
```

<Hint>

A `Map` remembers the order in which keys were added, and deleting and re-adding a key moves it to the end. How could that order tell you both which entry was used least recently and which ones have expired?

</Hint>

<Hint>

Store `{ value, expires }` for each key, with `expires = now() + ttl` on every use, and mark a use by `delete` and `set` so the key moves to the end. Then the first key (`map.keys().next().value`) is the least recently used one. Because every entry gets the same `ttl`, the map is also sorted by expiry time, so stale entries are always at the front: write a private `#prune()` that deletes from the front while entries have expired and stops at the first live one, and call it at the start of every method. In `set`, remove the first key when the size goes over `capacity`. Check the options in the constructor and throw a `RangeError` for bad ones.

</Hint>

<Solution>

```js
class ExpiringCache {
  #entries = new Map(); // key -> { value, expires }, least recently used first
  #capacity;
  #ttl;
  #now;

  constructor({ capacity, ttl, now = Date.now }) {
    if (!Number.isInteger(capacity) || capacity < 1) {
      throw new RangeError("capacity must be a whole number of at least 1");
    }
    if (!(ttl > 0)) throw new RangeError("ttl must be more than 0");
    this.#capacity = capacity;
    this.#ttl = ttl;
    this.#now = now;
  }

  // Expired entries are always at the front, so stop at the first live one.
  #prune() {
    const time = this.#now();
    for (const [key, entry] of this.#entries) {
      if (entry.expires > time) break;
      this.#entries.delete(key);
    }
  }

  set(key, value) {
    this.#prune();
    this.#entries.delete(key);
    this.#entries.set(key, { value, expires: this.#now() + this.#ttl });
    if (this.#entries.size > this.#capacity) {
      this.#entries.delete(this.#entries.keys().next().value);
    }
    return this;
  }

  get(key) {
    this.#prune();
    const entry = this.#entries.get(key);
    if (!entry) return undefined;
    this.#entries.delete(key);
    entry.expires = this.#now() + this.#ttl;
    this.#entries.set(key, entry);
    return entry.value;
  }

  has(key) {
    this.#prune();
    return this.#entries.has(key);
  }

  delete(key) {
    this.#prune();
    return this.#entries.delete(key);
  }

  get size() {
    this.#prune();
    return this.#entries.size;
  }

  keys() {
    this.#prune();
    return [...this.#entries.keys()];
  }
}

let clock = 0;
const cache = new ExpiringCache({ capacity: 2, ttl: 1000, now: () => clock });
cache.set("rain", 1);
cache.set("sun", 2);
console.log(cache.get("rain")); // 1
```

The `Map` does double duty: its insertion order is the "least recently used" order, and because every use moves an entry to the end with a fresh expiry time, it's the expiry order too. That's why `#prune` only ever looks at the front. Each entry is removed at most once, so all methods except `keys` are O(1) on average.

</Solution>
