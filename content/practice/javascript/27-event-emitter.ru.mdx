В приложении заповедника панд много частей, которым нужно узнавать о событиях вроде `"feeding"` («кормление») или `"visitor"` («посетитель»). Напишите класс (class) `Emitter`, который позволяет коду подписываться на именованные события (event) и объявлять о них.

- `on(event, listener)` добавляет обработчик (listener) для `event` и возвращает **функцию отписки** (unsubscribe function). Вызов этой функции удаляет этот обработчик. Повторный вызов ничего не делает.
- `once(event, listener)` работает как `on`, но обработчик автоматически удаляется сразу после первого вызова. Он тоже возвращает функцию отписки, и она работает до этого первого вызова.
- `emit(event, ...args)` вызывает все обработчики `event` с аргументами `args` в том порядке, в котором их добавили, и возвращает, сколько обработчиков вызвано (`0` для события, которое никто не слушает).
- Если одну и ту же функцию добавить дважды, она вызывается дважды.
- `emit` работает с теми обработчиками, которые были на момент его начала: обработчики, добавленные или удалённые другим обработчиком во время `emit`, начинают влиять только со следующего `emit`.
- `listenerCount(event)` возвращает, сколько обработчиков сейчас есть у `event`.

```js
const news = new Emitter();
const off = news.on("feeding", (food, kg) => console.log(`Корм: ${food}, ${kg} кг`));
news.once("feeding", () => console.log("Первое кормление за день!"));

news.emit("feeding", "бамбук", 2);  // выводит обе строки, возвращает 2
news.emit("feeding", "яблоки", 1);  // выводит "Корм: яблоки, 1 кг", возвращает 1
off();
news.emit("feeding", "бамбук", 3);  // ничего не выводит, возвращает 0
news.listenerCount("feeding");      // 0
```

<Hint>

Храните обработчики в `Map`, где ключ — имя события, а значение — массив функций-обработчиков. `emit` может перебирать копию массива (`[...list]`) — тогда правило «изменения ждут следующего emit» выполняется само собой.

</Hint>

<Hint>

Два добавления одной и той же функции должны оставаться отдельными, поэтому не удаляйте обработчик поиском по функции. Оберните каждый обработчик в маленький объект вроде `{ listener }`, и пусть функция отписки удаляет именно этот объект (найдите его через `indexOf`). Обработчик `once` может отписать сам себя перед вызовом настоящего обработчика.

</Hint>

<Solution>

```js
class Emitter {
  #listeners = new Map(); // событие -> массив { listener }

  on(event, listener) {
    const entry = { listener };
    if (!this.#listeners.has(event)) this.#listeners.set(event, []);
    this.#listeners.get(event).push(entry);
    return () => {
      const list = this.#listeners.get(event) ?? [];
      const index = list.indexOf(entry);
      if (index !== -1) list.splice(index, 1);
    };
  }

  once(event, listener) {
    const off = this.on(event, (...args) => {
      off();
      listener(...args);
    });
    return off;
  }

  emit(event, ...args) {
    const list = [...(this.#listeners.get(event) ?? [])];
    for (const entry of list) entry.listener(...args);
    return list.length;
  }

  listenerCount(event) {
    return this.#listeners.get(event)?.length ?? 0;
  }
}

const news = new Emitter();
news.on("feeding", (food) => console.log("Корм: " + food));
console.log(news.emit("feeding", "бамбук")); // Корм: бамбук, затем 1
```

Каждая подписка получает свой маленький объект-запись, а функция отписки — это замыкание (closure), которое помнит именно эту запись, поэтому повторное добавление одной и той же функции не создаёт проблем. `emit` перебирает снимок списка, так что обработчики, которые подписываются или отписываются во время его работы, не собьют цикл.

</Solution>
