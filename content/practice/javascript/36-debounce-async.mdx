The panda shop's search box asks the server for suggestions on every key press. Typing "bamboo" would send six requests! Write `debounceAsync(fn, ms)` that returns a new function, `debounced`, which only really calls `fn` once the calls stop for a moment.

- Every call of `debounced(...args)` returns a promise and **restarts** a timer of `ms` milliseconds.
- When the timer runs out without a new call, `fn` is called **once**, with the arguments of the **last** call. Every promise returned since the previous run of `fn` (a "group" of calls) settles with that one result: it resolves with `fn`'s value, or rejects with its error. `fn` may return a value, return a promise or throw.
- A call made after the timer ran out starts a **new** group, even if `fn` is still busy with the previous one.
- `debounced.cancel()` stops the waiting timer, so `fn` isn't called for the current group, and rejects all of that group's promises with an `Error` whose message is `"Cancelled"`. If nothing is waiting, it does nothing.

```js
const search = debounceAsync(async (text) => {
  console.log("Asking the server about", text);
  return [`${text} shoots`, `${text} leaves`];
}, 200);

const p1 = search("b");
const p2 = search("bam");
const p3 = search("bamboo");
// 200 ms after the last call: Asking the server about bamboo
await p1;  // ["bamboo shoots", "bamboo leaves"], and so are p2 and p3
```

<Hint>

A closure can remember state between calls of `debounced`: the timer, the latest arguments, and the callers still waiting for an answer. Each promise needs its `resolve` and `reject` saved so you can settle it later.

</Hint>

<Hint>

Keep three things in the closure: the timer id, `lastArgs`, and `waiting`, an array of `{ resolve, reject }` pairs. Each call saves its arguments, does `clearTimeout`, pushes its pair inside `new Promise(...)` and starts a new `setTimeout`. When the timer fires, take the group out **first** (`const group = waiting; waiting = [];`), so calls that arrive while `fn` runs start a new group. Then run `new Promise((res) => res(fn(...lastArgs)))` and settle every pair in `group` with the value or the error. `cancel` does nothing without a pending timer; otherwise it clears it, takes the group out the same way and rejects each pair with `new Error("Cancelled")`.

</Hint>

<Solution>

```js
function debounceAsync(fn, ms) {
  let timer = null;
  let lastArgs = [];
  let waiting = []; // { resolve, reject } for each call in the group

  function debounced(...args) {
    lastArgs = args;
    clearTimeout(timer);
    const promise = new Promise((resolve, reject) => {
      waiting.push({ resolve, reject });
    });
    timer = setTimeout(() => {
      timer = null;
      const group = waiting;
      waiting = [];
      new Promise((res) => res(fn(...lastArgs))).then(
        (value) => group.forEach((caller) => caller.resolve(value)),
        (error) => group.forEach((caller) => caller.reject(error)),
      );
    }, ms);
    return promise;
  }

  debounced.cancel = () => {
    if (timer === null) return;
    clearTimeout(timer);
    timer = null;
    const group = waiting;
    waiting = [];
    group.forEach((caller) => caller.reject(new Error("Cancelled")));
  };

  return debounced;
}

const shout = debounceAsync((text) => text.toUpperCase(), 50);
shout("b");
console.log(await shout("bamboo")); // BAMBOO
```

The closure holds the pending timer and the `resolve`/`reject` functions of every promise in the current group. Swapping in a fresh `waiting` array before calling `fn` is what lets a new group form while the old one is still running. Each call and each settled group does a constant amount of work per caller.

</Solution>
