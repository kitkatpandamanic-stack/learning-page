Building the new panda playground is a list of jobs, and some jobs need others done first: you can't paint the slide before it's built. Write `buildOrder(needs)` that puts the jobs in a working order.

- `needs` is an object: each key is a job, and its value is an array of the jobs it needs first. A job that only appears inside an array is a job too, with no needs of its own. Listing the same need twice is the same as listing it once.
- Return an array of **every** job, once each, where every job comes after all the jobs it needs.
- Whenever several jobs could go next, take the one that comes first **alphabetically** (compare the names with `<`). This makes the answer unique.
- If the jobs can't all be ordered, because some of them need each other in a circle (a job that needs itself counts too), throw an `Error` whose message is `"Cycle: "` followed by **all** the jobs that can never be done, sorted alphabetically and joined with `", "`. That includes jobs stuck waiting for a job in the circle.

```js
buildOrder({
  paint: ["build"],
  build: ["dig", "buy wood"],
  "buy wood": [],
});
// ["buy wood", "dig", "build", "paint"]

buildOrder({ c: [], b: [], a: [] });        // ["a", "b", "c"]

buildOrder({ a: ["b"], b: ["c"], c: ["a"], d: ["a"], e: [] });
// Error: Cycle: a, b, c, d
```

Finish `buildOrder(needs)`.

<Hint>

This is a **topological sort**. Think about which jobs can go first (the ones that need nothing), and what finishing a job does for the jobs that were waiting for it.

</Hint>

<Hint>

Collect every job (keys and needs) and, for each one, count how many **different** jobs it still waits for; also keep the reverse lists of which jobs need each job. Start a sorted list of ready jobs (count 0). Repeatedly take the alphabetically smallest ready job, add it to the order, and lower the count of every job that needs it; a job that reaches 0 goes into the ready list in its sorted place. If the ready list runs out while some jobs are left, those leftovers are exactly the stuck ones: throw `new Error("Cycle: " + ...)` with them sorted and joined by `", "`.

</Hint>

<Solution>

```js
function buildOrder(needs) {
  const waitingFor = new Map(); // job -> Set of jobs it still needs
  const neededBy = new Map();   // job -> jobs that need it
  const addJob = (job) => {
    if (!waitingFor.has(job)) {
      waitingFor.set(job, new Set());
      neededBy.set(job, []);
    }
  };
  for (const [job, list] of Object.entries(needs)) {
    addJob(job);
    for (const need of list) {
      addJob(need);
      if (!waitingFor.get(job).has(need)) {
        waitingFor.get(job).add(need);
        neededBy.get(need).push(job);
      }
    }
  }

  const left = new Map([...waitingFor].map(([job, set]) => [job, set.size]));
  const ready = [...left.keys()].filter((job) => left.get(job) === 0).sort();
  const order = [];
  while (ready.length > 0) {
    const job = ready.shift(); // the smallest ready job
    order.push(job);
    left.delete(job);
    for (const next of neededBy.get(job)) {
      left.set(next, left.get(next) - 1);
      if (left.get(next) === 0) {
        // insert in sorted position
        let i = 0;
        while (i < ready.length && ready[i] < next) i++;
        ready.splice(i, 0, next);
      }
    }
  }

  if (left.size > 0) {
    throw new Error("Cycle: " + [...left.keys()].sort().join(", "));
  }
  return order;
}

console.log(buildOrder({ paint: ["build"], build: ["dig"] })); // [ 'dig', 'build', 'paint' ]
```

This is **Kahn's algorithm** for a topological sort: count what each job waits for, start with the jobs that wait for nothing, and every finished job unlocks the jobs that needed it. Keeping the ready list sorted gives the alphabetical tie-break. Jobs in a cycle (and jobs behind one) never reach a count of 0, so they're exactly what's left at the end. With n jobs and e needs this is O(n² + e) because of the sorted inserts, or O((n + e) log n) with a priority queue.

</Solution>
