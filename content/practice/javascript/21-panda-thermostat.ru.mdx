Малые панды любят прохладу, поэтому в доме панд стоит умный термостат. Напишите класс (class) `Thermostat`, который хранит целевую температуру в **приватном поле** (private field), чтобы снаружи никто не мог выставить что-нибудь нелепое.

- `new Thermostat(target)` начинает с `target`. Целевая температура должна быть числом от `10` до `30` (включительно).
- Геттер `target` возвращает текущую цель, а сеттер `target` меняет её. Всё, что не является числом (или равно `NaN`), выбрасывает `TypeError`, а число вне диапазона 10–30 — `RangeError`. Конструктор (constructor) проверяет свой аргумент так же. Если значение вызвало ошибку, термостат не меняется.
- `warmer(step = 0.5)` и `cooler(step = 0.5)` поднимают или опускают цель на `step`, но никогда не выходят за пределы: вместо ошибки они останавливаются на `30` или `10`. Оба метода возвращают сам термостат, чтобы вызовы можно было выстраивать в цепочку.
- Геттер `history` возвращает массив всех целей, которые были у термостата, от старых к новым, начиная с цели из конструктора. Значение добавляется, только если цель действительно изменилась. Изменение возвращённого массива не должно менять термостат.
- У объекта нет публичных полей: `Object.keys(thermostat)` равно `[]`.

```js
const t = new Thermostat(20);
t.warmer().warmer(2).cooler();
t.target;               // 22
t.warmer(20).target;    // 30 (останавливается на пределе)
t.target = 25;
t.history;              // [20, 20.5, 22.5, 22, 30, 25]
t.target = 40;          // RangeError
new Thermostat("21");   // TypeError
```

<Hint>

Поля, имена которых начинаются с `#`, приватные: их не видно в `Object.keys` и до них не добраться снаружи класса. Каким методам нужно проверять значение, а каким достаточно его ограничить?

<Hint>

Объявите `#target;` и `#history = [];` в начале класса. Всю проверку поместите в сеттер `target` (сначала `TypeError`, потом `RangeError`), а конструктор пусть выполняет `this.target = target` — так правила живут в одном месте. `warmer` и `cooler` не должны выбрасывать ошибку, поэтому они ограничивают значение через `Math.min(30, ...)` / `Math.max(10, ...)`. Пропускайте каждое изменение через один приватный вспомогательный метод, который игнорирует равные значения и добавляет новые в историю, а геттер истории пусть возвращает копию.

</Hint>

<Solution>

```js
class Thermostat {
  static MIN = 10;
  static MAX = 30;

  #target;
  #history = [];

  constructor(target) {
    this.target = target;
  }

  get target() {
    return this.#target;
  }

  set target(value) {
    if (typeof value !== "number" || Number.isNaN(value)) {
      throw new TypeError("Цель должна быть числом");
    }
    if (value < Thermostat.MIN || value > Thermostat.MAX) {
      throw new RangeError("Цель должна быть от 10 до 30");
    }
    this.#change(value);
  }

  warmer(step = 0.5) {
    this.#change(Math.min(Thermostat.MAX, this.#target + step));
    return this;
  }

  cooler(step = 0.5) {
    this.#change(Math.max(Thermostat.MIN, this.#target - step));
    return this;
  }

  get history() {
    return [...this.#history];
  }

  #change(value) {
    if (value === this.#target) return;
    this.#target = value;
    this.#history.push(value);
  }
}

const t = new Thermostat(20);
t.warmer();
console.log(t.target); // 20.5
```

Вся проверка живёт в сеттере, которым пользуется и конструктор, а каждое изменение проходит через приватный метод `#change`, поэтому история не может разойтись с целью. Геттер `history` отдаёт копию, и настоящий массив остаётся приватным.

</Solution>
