Сервер доставки бамбука немного капризный: иногда запрос падает, а попытка чуть позже срабатывает. Напишите асинхронную функцию `retry(task, options)`, которая не сдаётся.

- `task(attempt)` — функция, которая возвращает промис (promise) или обычное значение. `attempt` — номер попытки, начиная с `1`. Если `task` выбрасывает ошибку вместо того, чтобы вернуть значение, это тоже считается неудачей.
- Как только попытка удалась, `retry` разрешается (resolve) её значением.
- После неудачи, если попытки ещё остались, `retry` ждёт и пробует снова. Первое ожидание — `delay` мс, а каждое следующее — **вдвое** дольше предыдущего: 100, 200, 400, …
- После `attempts` неудачных попыток `retry` отклоняется (reject) с ошибкой **последней** попытки, не дожидаясь ещё раз.
- `options` — объект с полями `attempts` (по умолчанию `3`), `delay` (по умолчанию `100`) и `wait` — функцией для ожидания. `wait(ms)` возвращает промис, который разрешается через `ms` миллисекунд; по умолчанию это промис вокруг `setTimeout`. Всегда ждите через вызов `wait`, чтобы тесты могли подставить фальшивую функцию.
- Если `attempts` меньше 1, отклоните промис с `RangeError`, не вызывая `task`.

```js
let calls = 0;
const flaky = async () => {
  calls++;
  if (calls < 3) throw new Error("Сервер занят");
  return "🎋 доставлено";
};

await retry(flaky, { delay: 50 });   // "🎋 доставлено" после ожиданий в 50 и 100 мс

await retry(() => Promise.reject(new Error("Сервер недоступен")), { attempts: 2 });
// отклоняется с Error("Сервер недоступен") после одного ожидания в 100 мс
```

<Hint>

Здесь хорошо подходит цикл по попыткам с `try`/`catch` внутри. Осторожно: отклонённый промис попадёт в ваш `catch`, только если вы ждёте его через `await` внутри `try`.

</Hint>

<Hint>

Сначала выбросьте `RangeError`, если `attempts` меньше 1. Затем ведите `attempt` от `1` до `attempts`: в `try` — `return await task(attempt)`; в `catch` запомните ошибку и, если это не последняя попытка, выполните `await wait(delay * 2 ** (attempt - 1))`. После цикла выбросьте (`throw`) запомненную ошибку: внутри `async`-функции выброшенная ошибка отклоняет промис.

</Hint>

<Solution>

```js
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function retry(task, { attempts = 3, delay = 100, wait = sleep } = {}) {
  if (attempts < 1) throw new RangeError("attempts должно быть не меньше 1");
  let lastError;
  for (let attempt = 1; attempt <= attempts; attempt++) {
    try {
      return await task(attempt);
    } catch (error) {
      lastError = error;
      if (attempt < attempts) await wait(delay * 2 ** (attempt - 1));
    }
  }
  throw lastError;
}

let calls = 0;
const flaky = async () => {
  calls++;
  if (calls < 3) throw new Error("Сервер занят");
  return "доставлено";
};
console.log(await retry(flaky, { delay: 10 })); // доставлено
```

`return await` внутри `try` здесь важен: из-за него отклонённый промис выбрасывает ошибку прямо там, и `catch` её видит (простой `return task(attempt)` проскочил бы мимо `catch`). Ожидание удваивается после каждой неудачи — это называется **экспоненциальной задержкой** (exponential backoff) и даёт перегруженному серверу всё больше времени отдышаться.

</Solution>
