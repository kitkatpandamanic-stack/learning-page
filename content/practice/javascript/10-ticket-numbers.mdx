The panda café needs ticket numbers for orders, and the zoo needs different ones for visitors. Write a function `makeIdMaker(prefix, width)` that returns a **new function**. Each time you call that new function, it returns the next ID:

- IDs are the prefix, a dash, and a number: the first call gives number 1, then 2, 3 and so on.
- The number is padded with zeros on the left to `width` digits. `width` is optional and defaults to `3`: `"ord-001"`.
- Numbers that are already longer than `width` are not cut: after `"ord-999"` comes `"ord-1000"`.
- Every ID maker has its **own** counter. Making a second maker doesn't affect the first.

```js
const nextOrder = makeIdMaker("ord");
nextOrder(); // 'ord-001'
nextOrder(); // 'ord-002'

const nextVisitor = makeIdMaker("visitor", 5);
nextVisitor(); // 'visitor-00001'
nextOrder();   // 'ord-003'
```

Finish `makeIdMaker(prefix, width)` so it returns a function that hands out the IDs.

<Hint>

The returned function has to remember a number between calls, and each maker needs its own number. Where could a variable live so that only that one function can see it? This is called a closure.

</Hint>

<Hint>

Keep a counter in a `let` variable **inside** `makeIdMaker`, then return an arrow function that adds 1 to it and builds the ID from `prefix`, a dash and the number. For the padding, `String(7).padStart(3, "0")` gives `"007"`, and `padStart` never cuts a string that is already long enough.

</Hint>

<Hint>

```js
function makeIdMaker(prefix, width = 3) {
  let count = 0;
  return () => {
    count++;
    return ...; // prefix, a dash and the padded count
  };
}
```

</Hint>

<Solution>

```js
function makeIdMaker(prefix, width = 3) {
  let count = 0;
  return () => {
    count++;
    return prefix + "-" + String(count).padStart(width, "0");
  };
}

const nextOrder = makeIdMaker("ord");
console.log(nextOrder()); // ord-001
console.log(nextOrder()); // ord-002
```

The returned function **closes over** `count`, `prefix` and `width`, so it remembers them between calls. Each call to `makeIdMaker` runs the function body again and so creates a brand-new `count`, which is why two makers never share a counter.

</Solution>
