Shoppers keep typing "bambo" and "pnada" into the panda shop's search. Write two functions that power a "Did you mean…?" box.

**`editDistance(a, b)`** returns the smallest number of single-character edits that turn string `a` into string `b`. An edit is inserting one character, deleting one character, or replacing one character with another. Upper and lower case are different characters here. Strings can be up to **2,000 characters** long, so trying every possible series of edits is far too slow: use dynamic programming, O(len(a) × len(b)).

**`suggest(word, dictionary, maxDistance = 2)`** returns the dictionary words that are close to `word`:

- Compare **lower-cased** versions of `word` and each dictionary word, but return the words spelled as they are in the dictionary.
- Keep the words whose distance is at most `maxDistance` (an exact match has distance `0` and is kept).
- Sort them by distance, closest first. Words at the same distance are sorted alphabetically with `<` (so capital letters come before lower-case ones).
- A word that is in the dictionary more than once (spelled exactly the same) appears only once.

```js
editDistance("kitten", "sitting");    // 3 (k→s, e→i, add g)
editDistance("panda", "pandas");      // 1
editDistance("Bao", "bao");           // 1
editDistance("", "abc");              // 3

const dictionary = ["bamboo", "banana", "bambi", "bamboos", "panda", "Panda", "band", "bam"];
suggest("bambo", dictionary);         // ["bambi", "bamboo", "bam", "bamboos"]
suggest("PANDA", dictionary);         // ["Panda", "panda", "band"]
suggest("xyz", dictionary);           // []
```

Finish `editDistance(a, b)` and `suggest(word, dictionary, maxDistance)`.

<Hint>

Let `d[i][j]` be the distance between the first `i` characters of `a` and the first `j` characters of `b`. Turning something into an empty string takes one deletion per character, so `d[i][0] = i` and `d[0][j] = j`. Every other cell is the smallest of: `d[i-1][j] + 1` (delete), `d[i][j-1] + 1` (insert) and `d[i-1][j-1]` plus `0` if `a[i-1] === b[j-1]`, else `1` (replace).

</Hint>

<Hint>

Each row only needs the row above it, so you can keep just two arrays instead of the whole table. For `suggest`, remove duplicates with `new Set(dictionary)`, compute each distance once, and sort with a comparator that compares distances first and falls back to comparing the words.

</Hint>

<Solution>

```js
function editDistance(a, b) {
  let previous = Array.from({ length: b.length + 1 }, (_, j) => j);
  for (let i = 1; i <= a.length; i++) {
    const row = [i];
    for (let j = 1; j <= b.length; j++) {
      const replace = previous[j - 1] + (a[i - 1] === b[j - 1] ? 0 : 1);
      row[j] = Math.min(previous[j] + 1, row[j - 1] + 1, replace);
    }
    previous = row;
  }
  return previous[b.length];
}

function suggest(word, dictionary, maxDistance = 2) {
  const target = word.toLowerCase();
  return [...new Set(dictionary)]
    .map((entry) => ({ entry, distance: editDistance(target, entry.toLowerCase()) }))
    .filter(({ distance }) => distance <= maxDistance)
    .sort((x, y) => {
      if (x.distance !== y.distance) return x.distance - y.distance;
      return x.entry < y.entry ? -1 : x.entry > y.entry ? 1 : 0;
    })
    .map(({ entry }) => entry);
}

console.log(editDistance("kitten", "sitting")); // 3
console.log(suggest("bambo", ["bamboo", "banana", "bambi"])); // [ 'bambi', 'bamboo' ]
```

This is the **Levenshtein distance**, a classic dynamic programming problem: each cell of the table is built from three neighbours that were already computed, so the whole table takes O(len(a) × len(b)) time instead of the exponential time of trying every edit sequence. Keeping only the previous row cuts the memory to O(len(b)).

</Solution>
