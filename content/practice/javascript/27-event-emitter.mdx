The panda sanctuary's app has lots of parts that need to hear about things like `"feeding"` or `"visitor"`. Write a class `Emitter` that lets code subscribe to named events and announce them.

- `on(event, listener)` adds a listener for `event` and returns an **unsubscribe function**. Calling that function removes this listener. Calling it again does nothing.
- `once(event, listener)` works like `on`, but the listener is removed automatically right after its first call. It also returns an unsubscribe function, which works before that first call.
- `emit(event, ...args)` calls every listener of `event` with `args`, in the order they were added, and returns how many listeners it called (`0` for an event nobody listens to).
- Adding the same function twice means it's called twice.
- `emit` works on the listeners that existed when it started: listeners added or removed by a listener during an `emit` only make a difference from the next `emit` on.
- `listenerCount(event)` returns how many listeners `event` currently has.

```js
const news = new Emitter();
const off = news.on("feeding", (food, kg) => console.log(`Eat ${kg} kg of ${food}`));
news.once("feeding", () => console.log("First feeding of the day!"));

news.emit("feeding", "bamboo", 2);  // prints both lines, returns 2
news.emit("feeding", "apples", 1);  // prints "Eat 1 kg of apples", returns 1
off();
news.emit("feeding", "bamboo", 3);  // prints nothing, returns 0
news.listenerCount("feeding");      // 0
```

<Hint>

A `Map` from event name to a list of listeners is a good store. Two things need care: the same function can be added twice, and listeners may subscribe or unsubscribe while `emit` is running.

</Hint>

<Hint>

Keep the map in a private field like `#listeners`. Wrap each listener in its own small object like `{ listener }` and push that, so the unsubscribe function can remove exactly that entry with `indexOf` and `splice`, even if the same function was added twice. `once` can call `on` with a wrapper that unsubscribes itself before calling the real listener. In `emit`, loop over a copy (`[...list]`), so changes made during the loop wait for the next `emit`, and return the copy's length.

</Hint>

<Solution>

```js
class Emitter {
  #listeners = new Map(); // event -> array of { listener }

  on(event, listener) {
    const entry = { listener };
    if (!this.#listeners.has(event)) this.#listeners.set(event, []);
    this.#listeners.get(event).push(entry);
    return () => {
      const list = this.#listeners.get(event) ?? [];
      const index = list.indexOf(entry);
      if (index !== -1) list.splice(index, 1);
    };
  }

  once(event, listener) {
    const off = this.on(event, (...args) => {
      off();
      listener(...args);
    });
    return off;
  }

  emit(event, ...args) {
    const list = [...(this.#listeners.get(event) ?? [])];
    for (const entry of list) entry.listener(...args);
    return list.length;
  }

  listenerCount(event) {
    return this.#listeners.get(event)?.length ?? 0;
  }
}

const news = new Emitter();
news.on("feeding", (food) => console.log("Eat " + food));
console.log(news.emit("feeding", "bamboo")); // Eat bamboo, then 1
```

Each subscription gets its own little entry object, and the unsubscribe function is a closure that remembers exactly that entry, so adding the same function twice is no problem. `emit` loops over a snapshot of the list, so listeners that subscribe or unsubscribe while it's running can't confuse the loop.

</Solution>
