Погодное приложение для панд запрашивает прогнозы у медленного сервера, поэтому хранит недавние ответы в кеше (cache). Но ответы устаревают, а память ограничена. Напишите класс (class) `ExpiringCache`, который справляется и с тем, и с другим.

- `new ExpiringCache({ capacity, ttl, now })`: `capacity` — сколько записей кеш хранит максимум, `ttl` — сколько миллисекунд живёт запись, а `now` — функция, которая возвращает текущее время в мс (по умолчанию `Date.now`; тесты передают фальшивые часы). `now()` никогда не идёт назад. Если `capacity` — не целое число не меньше 1 или `ttl` не больше 0, выбрасывается `RangeError`.
- Запись **используется**, когда её сохраняют через `set` или читают через `get`. Она **истекает** через `ttl` мс после последнего использования: как только `now()` достигает `lastUse + ttl`, кеш ведёт себя так, будто записи никогда не было.
- `set(key, value)` сохраняет или заменяет значение и использует запись. Если живых записей становится больше `capacity`, удаляется **дольше всех не использованная** (least recently used). Метод возвращает кеш.
- `get(key)` возвращает значение живой записи (и использует её) или `undefined`.
- `has(key)` сообщает, есть ли у `key` живая запись, **не** используя её.
- `delete(key)` удаляет запись и возвращает, была ли она живой.
- Геттер `size` считает живые записи, а `keys()` возвращает живые ключи массивом — начиная с дольше всех не использованного.
- Каждый метод, кроме `keys`, должен в среднем работать за O(1), даже при 50 000 записей.

```js
let clock = 0;
const cache = new ExpiringCache({ capacity: 2, ttl: 1000, now: () => clock });
cache.set("rain", "🌧️").set("sun", "☀️");
cache.get("rain");      // "🌧️" (теперь дольше всех не использовался "sun")
cache.set("snow", "❄️"); // "sun" удаляется, чтобы освободить место
cache.keys();           // ["rain", "snow"]

clock = 999;
cache.get("rain");      // "🌧️", и теперь запись живёт до 1999
clock = 1000;
cache.has("snow");      // false: записана в 0 и с тех пор не использовалась
clock = 1999;
cache.get("rain");      // undefined
cache.size;             // 0
```

<Hint>

`Map` помнит порядок, в котором добавлялись ключи, а если ключ удалить и добавить снова, он переезжает в конец. Как этот порядок может подсказать и то, какая запись дольше всех не использовалась, и то, какие записи уже истекли?

</Hint>

<Hint>

Храните для каждого ключа `{ value, expires }`, где при каждом использовании `expires = now() + ttl`, а использование отмечайте через `delete` и `set`, чтобы ключ переезжал в конец. Тогда первый ключ (`map.keys().next().value`) дольше всех не использовался. Раз у всех записей одинаковый `ttl`, `Map` заодно отсортирован по времени истечения, и устаревшие записи всегда в начале: напишите приватный метод `#prune()`, который удаляет записи с начала, пока они истекли, и останавливается на первой живой, и вызывайте его в начале каждого метода. В `set` удаляйте первый ключ, когда размер превышает `capacity`. Проверьте параметры в конструкторе и выбрасывайте `RangeError` для неправильных.

</Hint>

<Solution>

```js
class ExpiringCache {
  #entries = new Map(); // ключ -> { value, expires }, дольше всех не использованные — первыми
  #capacity;
  #ttl;
  #now;

  constructor({ capacity, ttl, now = Date.now }) {
    if (!Number.isInteger(capacity) || capacity < 1) {
      throw new RangeError("capacity должно быть целым числом не меньше 1");
    }
    if (!(ttl > 0)) throw new RangeError("ttl должно быть больше 0");
    this.#capacity = capacity;
    this.#ttl = ttl;
    this.#now = now;
  }

  // Истёкшие записи всегда в начале, поэтому останавливаемся на первой живой.
  #prune() {
    const time = this.#now();
    for (const [key, entry] of this.#entries) {
      if (entry.expires > time) break;
      this.#entries.delete(key);
    }
  }

  set(key, value) {
    this.#prune();
    this.#entries.delete(key);
    this.#entries.set(key, { value, expires: this.#now() + this.#ttl });
    if (this.#entries.size > this.#capacity) {
      this.#entries.delete(this.#entries.keys().next().value);
    }
    return this;
  }

  get(key) {
    this.#prune();
    const entry = this.#entries.get(key);
    if (!entry) return undefined;
    this.#entries.delete(key);
    entry.expires = this.#now() + this.#ttl;
    this.#entries.set(key, entry);
    return entry.value;
  }

  has(key) {
    this.#prune();
    return this.#entries.has(key);
  }

  delete(key) {
    this.#prune();
    return this.#entries.delete(key);
  }

  get size() {
    this.#prune();
    return this.#entries.size;
  }

  keys() {
    this.#prune();
    return [...this.#entries.keys()];
  }
}

let clock = 0;
const cache = new ExpiringCache({ capacity: 2, ttl: 1000, now: () => clock });
cache.set("rain", 1);
cache.set("sun", 2);
console.log(cache.get("rain")); // 1
```

`Map` работает здесь за двоих: порядок вставки — это порядок «дольше всех не использованных», а поскольку каждое использование переносит запись в конец со свежим временем истечения, это ещё и порядок истечения. Поэтому `#prune` смотрит только в начало. Каждая запись удаляется не больше одного раза, так что все методы, кроме `keys`, в среднем работают за O(1).

</Solution>
