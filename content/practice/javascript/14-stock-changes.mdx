The panda shop counts its stock every evening as an object of item name → number, like `{ bamboo: 12, apples: 3 }`. Write a function `stockChanges(before, after)` that compares yesterday's count with today's and returns an object with three parts:

- `added`: an array of the names that are in `after` but not in `before`, sorted A to Z.
- `removed`: an array of the names that are in `before` but not in `after`, sorted A to Z.
- `changed`: an object with one key for each name that is in **both** with a **different** number. Its value is the difference `after − before` (negative when stock went down). Its keys are sorted A to Z.

Names whose number didn't change appear nowhere.

Edge cases: a name with the number `0` is still in the object (it's not "removed"), and item names can be any text, even ones like `"toString"` that look like built-in object methods. Don't change either object.

```js
stockChanges(
  { bamboo: 12, apples: 3, tea: 5, cups: 0 },
  { bamboo: 9, tea: 5, cups: 4, honey: 2 },
);
// {
//   added: [ 'honey' ],
//   removed: [ 'apples' ],
//   changed: { bamboo: -3, cups: 4 }
// }

stockChanges({ a: 1 }, { a: 1 }); // { added: [], removed: [], changed: {} }
```

Compare the names in both directions: names in `after` can be added or changed, and names in `before` can be removed. Be careful how you ask "is this name in the object?" when a count can be `0` or a name can be `toString`.

<Solution>

```js
function stockChanges(before, after) {
  const added = [];
  const removed = [];
  const changed = {};
  for (const name of Object.keys(after).sort()) {
    if (!Object.hasOwn(before, name)) added.push(name);
    else if (after[name] !== before[name]) {
      changed[name] = after[name] - before[name];
    }
  }
  for (const name of Object.keys(before).sort()) {
    if (!Object.hasOwn(after, name)) removed.push(name);
  }
  return { added, removed, changed };
}

console.log(stockChanges(
  { bamboo: 12, apples: 3, tea: 5, cups: 0 },
  { bamboo: 9, tea: 5, cups: 4, honey: 2 },
));
```

Two passes over sorted keys find everything, so it's O(n log n) for n names because of the sorting. `Object.hasOwn` is the safe membership test: it ignores the methods every object inherits and doesn't care whether the value is `0`.

</Solution>
