Строительство новой площадки для панд — это список работ, и некоторым работам нужно, чтобы другие были сделаны раньше: нельзя покрасить горку, пока её не построили. Напишите `buildOrder(needs)`, которая выстраивает работы в рабочем порядке. Названия работ в примерах — английские (`paint` — «покрасить», `build` — «построить», `dig` — «копать», `buy wood` — «купить доски»): так проще следить за алфавитным порядком.

- `needs` — объект (object): каждый ключ — работа, а его значение — массив работ, которые ей нужны раньше. Работа, которая встречается только внутри массива, — тоже работа, без собственных требований. Одно и то же требование, указанное дважды, — то же самое, что указанное один раз.
- Верните массив из **всех** работ, каждая по одному разу, где каждая работа идёт после всех работ, которые ей нужны.
- Когда следующей может пойти любая из нескольких работ, берите ту, что раньше **по алфавиту** (сравнивайте названия через `<`). Так ответ становится единственным.
- Если все работы упорядочить нельзя, потому что некоторые нужны друг другу по кругу (работа, которой нужна она сама, тоже считается), выбросьте `Error` с сообщением `"Cycle: "` («Цикл: »), за которым идут **все** работы, которые никогда не удастся выполнить, — отсортированные по алфавиту и соединённые через `", "`. Сюда входят и работы, которые застряли в ожидании работы из круга.

```js
buildOrder({
  paint: ["build"],
  build: ["dig", "buy wood"],
  "buy wood": [],
});
// ["buy wood", "dig", "build", "paint"]

buildOrder({ c: [], b: [], a: [] });        // ["a", "b", "c"]

buildOrder({ a: ["b"], b: ["c"], c: ["a"], d: ["a"], e: [] });
// Error: Cycle: a, b, c, d
```

<Hint>

Сначала соберите все работы (ключи и требования) в `Set`. Для каждой работы посчитайте, скольких **разных** работ она ещё ждёт, и запомните обратное направление: для каждой работы — список работ, которым она нужна. Работы, которые ничего не ждут, готовы.

</Hint>

<Hint>

Снова и снова берите готовую работу, которая раньше всех по алфавиту, добавляйте её в порядок и уменьшайте счётчик ожидания у каждой работы, которой она нужна; работы, у которых счётчик дошёл до 0, становятся готовыми. Если готовые работы закончились раньше, чем все работы упорядочены, то оставшиеся — ровно те, что никогда не удастся выполнить.

</Hint>

<Solution>

```js
function buildOrder(needs) {
  const waitingFor = new Map(); // работа -> Set работ, которые ей ещё нужны
  const neededBy = new Map();   // работа -> работы, которым она нужна
  const addJob = (job) => {
    if (!waitingFor.has(job)) {
      waitingFor.set(job, new Set());
      neededBy.set(job, []);
    }
  };
  for (const [job, list] of Object.entries(needs)) {
    addJob(job);
    for (const need of list) {
      addJob(need);
      if (!waitingFor.get(job).has(need)) {
        waitingFor.get(job).add(need);
        neededBy.get(need).push(job);
      }
    }
  }

  const left = new Map([...waitingFor].map(([job, set]) => [job, set.size]));
  const ready = [...left.keys()].filter((job) => left.get(job) === 0).sort();
  const order = [];
  while (ready.length > 0) {
    const job = ready.shift(); // самая первая по алфавиту готовая работа
    order.push(job);
    left.delete(job);
    for (const next of neededBy.get(job)) {
      left.set(next, left.get(next) - 1);
      if (left.get(next) === 0) {
        // вставляем на место по порядку
        let i = 0;
        while (i < ready.length && ready[i] < next) i++;
        ready.splice(i, 0, next);
      }
    }
  }

  if (left.size > 0) {
    throw new Error("Cycle: " + [...left.keys()].sort().join(", "));
  }
  return order;
}

console.log(buildOrder({ paint: ["build"], build: ["dig"] })); // [ 'dig', 'build', 'paint' ]
```

Это **алгоритм Кана** (Kahn's algorithm) для топологической сортировки (topological sort): посчитайте, чего ждёт каждая работа, начните с работ, которые ничего не ждут, и каждая завершённая работа открывает дорогу тем, кому она была нужна. Отсортированный список готовых работ даёт выбор по алфавиту. Работы в цикле (и работы за ним) никогда не доходят до счётчика 0, поэтому именно они и остаются в конце. При n работах и e требованиях это O(n² + e) из-за вставок по порядку или O((n + e) log n) с очередью с приоритетом.

</Solution>
