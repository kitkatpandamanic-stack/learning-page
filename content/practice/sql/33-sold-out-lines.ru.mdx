Плохие новости в магазине панды: некоторые товары **распроданы** (`stock` равен 0), и заказы, которые всё ещё в статусе **`paid`** (ещё не отправлены), их не получат. Уберите эти позиции из `order_items`: удалите каждую позицию заказа, если у её товара `stock = 0` **и** у её заказа статус `'paid'`.

Заказы `shipped` и `delivered` уже покинули склад, поэтому их позиции **должны остаться**, даже если товар распродан. Не удаляйте заказы, только позиции.

Завершите `DELETE` с помощью `RETURNING`, чтобы магазин мог написать покупателям: верните **`order_id`**, **`product`** (название товара) и **`quantity`**. Порядок возвращённых строк не важен.

```sql
-- order_id | product   | quantity
--        8 | Earl Grey |        2
--       13 | Earl Grey |        1
-- …
```

Напишите `DELETE`, который убирает распроданные товары из оплаченных заказов и возвращает `order_id`, `product` и `quantity`.

<Hint>

Условия относятся к `products` и `orders`, а удалять нужно строки из `order_items`. Для этого у `DELETE` в PostgreSQL есть предложение `USING`.

</Hint>

<Hint>

Напишите `DELETE FROM order_items AS oi USING products AS p, orders AS o WHERE …`. Сопоставьте каждую позицию с её товаром и заказом через `p.id = oi.product_id` и `o.id = oi.order_id`, затем добавьте `p.stock = 0` и `o.status = 'paid'`. В `RETURNING` можно использовать и столбцы таблиц из `USING`, например `p.name AS product`.

</Hint>

<Hint>

```sql
DELETE FROM order_items AS oi
USING products AS p, orders AS o
WHERE p.id = oi.product_id
  AND o.id = oi.order_id
  AND ...  -- товар распродан, а заказ всё ещё оплачен
RETURNING ...;
```

</Hint>

<Solution>

```sql
DELETE FROM order_items AS oi
USING products AS p, orders AS o
WHERE p.id = oi.product_id
  AND o.id = oi.order_id
  AND p.stock = 0
  AND o.status = 'paid'
RETURNING oi.order_id, p.name AS product, oi.quantity;
```

Подзапросы тоже работают: `WHERE product_id IN (SELECT id FROM products WHERE stock = 0) AND order_id IN (SELECT id FROM orders WHERE status = 'paid')`, но тогда `RETURNING` не увидит название товара без ещё одного подзапроса.

</Solution>
