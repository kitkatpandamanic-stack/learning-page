The panda sanctuary weighs its pandas every few weeks 🐼, and the vet wants to see how each one is doing. The starter creates a `panda_weights` table (the rows were typed in any old order).

For every weigh-in, show:

- `panda`, `weighed_on` and `kg`, as they are in the table,
- `days_since`: how many days have passed since **the same panda's** previous weigh-in,
- `change_kg`: the weight now minus the weight at that previous weigh-in.

A panda's **first** weigh-in has nothing to compare with, so both new columns are `NULL` there. Sort by panda, then by date.

```sql
-- panda | weighed_on | kg    | days_since | change_kg
-- Bao   | 2025-03-01 |  98.0 |            |
-- Bao   | 2025-03-15 |  99.5 |         14 |       1.5
-- …
```

Add `days_since` and `change_kg`, comparing each weigh-in with the previous one of the same panda.

<Hint>

`lag(column) OVER (PARTITION BY panda ORDER BY weighed_on)` reads the value from the panda's previous row. Subtracting two dates gives a number of days. Since both columns use the same window, you can name it once with `WINDOW w AS (…)` and write `OVER w`.

</Hint>

<Solution>

```sql
CREATE TABLE panda_weights (
  panda text NOT NULL,
  weighed_on date NOT NULL,
  kg numeric(5, 1) NOT NULL
);

INSERT INTO panda_weights (panda, weighed_on, kg) VALUES
  ('Bao', '2025-03-01', 98.0), ('Mochi', '2025-03-03', 84.0),
  ('Bao', '2025-04-05', 101.2), ('Lulu', '2025-03-10', 112.3),
  ('Bao', '2025-03-15', 99.5), ('Mochi', '2025-03-24', 86.5),
  ('Mochi', '2025-04-07', 86.5), ('Lulu', '2025-04-14', 110.9),
  ('Bao', '2025-04-19', 100.4);

SELECT panda, weighed_on, kg,
  weighed_on - lag(weighed_on) OVER w AS days_since,
  kg - lag(kg) OVER w AS change_kg
FROM panda_weights
WINDOW w AS (PARTITION BY panda ORDER BY weighed_on)
ORDER BY panda, weighed_on;
```
