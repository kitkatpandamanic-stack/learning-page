The panda shop is adding baskets 🛒. The starter code creates a `baskets` table holding two baskets: **Nina Novak's** (customer 20) and **Tom Baker's** (customer 19). Nina just pressed "Buy". Do her checkout:

1. First add a guard to `products`: a **`CHECK` constraint named `stock_not_negative`** so that `stock` can **never go below 0**. If a checkout would oversell, the database refuses it and the whole transaction is rolled back.
2. Then, **between `BEGIN` and `COMMIT`**:
   - create **one order** for customer 20, `ordered_at` `'2025-07-01 10:00'`, status `'paid'`,
   - copy every line of her basket into `order_items` at the product's **current price**,
   - **lower each product's stock** by the quantity she bought,
   - **empty her basket** (Tom's basket stays).
3. Finish with a query listing her order's lines: **`product`** (name), **`quantity`**, **`unit_price`** and **`line_total`** (`quantity × unit_price`), sorted by product name.

Don't type the new order's id: get it from the database (a data-modifying CTE with `RETURNING` is the neat way).

```sql
-- product       | quantity | unit_price | line_total
-- Matcha Powder |        2 |      14.00 |      28.00
-- …
```

Add the guard, check out Nina's basket in one transaction, and list her order's lines.

<Hint>

The guard is `ALTER TABLE products ADD CONSTRAINT stock_not_negative CHECK (stock >= 0)`. For the order lines, `WITH new_order AS (INSERT INTO orders … RETURNING id) INSERT INTO order_items … SELECT new_order.id, b.product_id, b.quantity, p.price FROM new_order CROSS JOIN baskets AS b JOIN products AS p …` creates the order and its lines in one statement. Lower the stock with `UPDATE products AS p … FROM baskets AS b WHERE …`.

</Hint>

<Solution>

```sql
CREATE TABLE baskets (
  customer_id integer NOT NULL REFERENCES customers (id),
  product_id integer NOT NULL REFERENCES products (id),
  quantity integer NOT NULL CHECK (quantity > 0),
  PRIMARY KEY (customer_id, product_id)
);

INSERT INTO baskets (customer_id, product_id, quantity) VALUES
  (20, 2, 2),
  (20, 15, 1),
  (20, 5, 3),
  (19, 8, 5);

ALTER TABLE products
  ADD CONSTRAINT stock_not_negative CHECK (stock >= 0);

BEGIN;

WITH new_order AS (
  INSERT INTO orders (customer_id, ordered_at, status)
  VALUES (20, '2025-07-01 10:00', 'paid')
  RETURNING id
)
INSERT INTO order_items (order_id, product_id, quantity, unit_price)
SELECT new_order.id, b.product_id, b.quantity, p.price
FROM new_order
CROSS JOIN baskets AS b
JOIN products AS p ON p.id = b.product_id
WHERE b.customer_id = 20;

UPDATE products AS p
SET stock = p.stock - b.quantity
FROM baskets AS b
WHERE b.product_id = p.id
  AND b.customer_id = 20;

DELETE FROM baskets WHERE customer_id = 20;

COMMIT;

SELECT p.name AS product, oi.quantity, oi.unit_price,
  oi.quantity * oi.unit_price AS line_total
FROM orders AS o
JOIN order_items AS oi ON oi.order_id = o.id
JOIN products AS p ON p.id = oi.product_id
WHERE o.customer_id = 20
ORDER BY product;
```

The guard lives in the table, not in your checkout code, so it protects every future statement too. Had Tom checked out instead, the `UPDATE` would fail on `stock_not_negative`, the transaction would be aborted, and his order and order lines would vanish with the `ROLLBACK`.

</Solution>
