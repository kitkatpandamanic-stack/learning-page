The panda shop's courier keeps asking where some parcels should go 📦. A few customers never filled in their city, so the `city` column is empty (`NULL`) for them.

Show the **`name`**, **`email`** and **`country`** of every customer whose **city is missing**, sorted **by name**.

```sql
-- name        | email              | country
-- Omar Haddad | omar@pandadev.test | Egypt
-- …
```

Careful: `city = NULL` looks right but never matches anything.

<Exercise
  language="sql"
  title="Customers without a city"
  starter={`-- name, email and country of customers with no city,
-- sorted by name
SELECT name, email, country, city
FROM customers
ORDER BY name;
`}
  tests={[
    { name: "Columns are name, email, country", check: "columns.join() === 'name,email,country'" },
    { name: "Only customers without a city", check: "rows.map(r => r.name).join() === 'Omar Haddad,Zara Khan'" },
    { name: "Emails are there for the reminder", check: "rows.map(r => r.email).join() === 'omar@pandadev.test,zara@pandadev.test'" },
    { name: "Works when the data changes", check: "(r => r.map(x => x.name).join() === 'Tom Baker,Zara Khan')(await rerun(\"UPDATE customers SET city = 'Cairo' WHERE name = 'Omar Haddad'; UPDATE customers SET city = NULL WHERE name = 'Tom Baker'\"))" },
    { name: "No rows when every customer has a city", check: "(r => r.length === 0)(await rerun(\"UPDATE customers SET city = 'Somewhere' WHERE city IS NULL\"))" },
  ]}
>

Keep only the customers whose city is missing.

<Hint>

`NULL` means "unknown", so comparing with `=` gives unknown too. Use `IS NULL` instead.

</Hint>

<Solution>

```sql
SELECT name, email, country
FROM customers
WHERE city IS NULL
ORDER BY name;
```

</Solution>

</Exercise>
