Магазин панды рассылает бесплатный пробник нового улуна 🍵 всем, кто **покупал чай**. Покупатель подходит, если у него есть **хотя бы один неотменённый заказ**, в котором есть товар из категории **`tea`**.

Выведите **`name`** и **`country`** каждого такого покупателя, **по одному разу**, отсортировав по имени.

Осторожно: некоторые покупатели заказывали чай только в заказах, которые потом были **отменены**. Пробник им не положен. А покупатель, который купил чай дважды, всё равно получает **одну** строку.

```sql
-- name         | country
-- Anna Ivanova | Russia
-- Chloe Martin | France
-- …
```

Оставьте только тех покупателей, для которых **существует** подходящий заказ с чаем.

<Hint>

Для каждого покупателя важно только, **существует** ли подходящий заказ, а не сколько их. В SQL есть ключевое слово, которое задаёт именно этот вопрос. Помните, что отменённые заказы не считаются.

</Hint>

<Hint>

Во внешнем запросе оставьте только таблицу `customers`, тогда каждый покупатель появится не больше одного раза. В `WHERE EXISTS (…)` соедините `orders`, `order_items` и `products`. Внутри свяжите заказ с покупателем из внешнего запроса через `o.customer_id = c.id` и проверьте `o.status <> 'cancelled'` и `p.category = 'tea'`.

</Hint>

<Hint>

```sql
SELECT c.name, c.country
FROM customers AS c
WHERE EXISTS (
  SELECT 1
  FROM orders AS o
  JOIN order_items AS oi ON oi.order_id = o.id
  JOIN products AS p ON p.id = oi.product_id
  WHERE ...  -- этот покупатель, не отменён, чай
)
ORDER BY c.name;
```

</Hint>

<Solution>

```sql
SELECT c.name, c.country
FROM customers AS c
WHERE EXISTS (
  SELECT 1
  FROM orders AS o
  JOIN order_items AS oi ON oi.order_id = o.id
  JOIN products AS p ON p.id = oi.product_id
  WHERE o.customer_id = c.id
    AND o.status <> 'cancelled'
    AND p.category = 'tea'
)
ORDER BY c.name;
```

Можно было бы соединить все таблицы и добавить `DISTINCT`, но `EXISTS` говорит ровно то, что вы имеете в виду, и может остановиться на первом совпадении.

</Solution>

</Exercise>
