В заповеднике панд взвешивают каждые несколько недель 🐼, и ветеринар хочет видеть, как идут дела у каждой. Стартовый код создаёт таблицу `panda_weights` (строки в неё вносили в произвольном порядке).

Для каждого взвешивания выведите:

- `panda`, `weighed_on` и `kg` — как они есть в таблице,
- `days_since`: сколько дней прошло с предыдущего взвешивания **той же панды**,
- `change_kg`: текущий вес минус вес на том предыдущем взвешивании.

**Первое** взвешивание панды сравнивать не с чем, поэтому оба новых столбца там равны `NULL`. Отсортируйте по панде, затем по дате.

```sql
-- panda | weighed_on | kg    | days_since | change_kg
-- Bao   | 2025-03-01 |  98.0 |            |
-- Bao   | 2025-03-15 |  99.5 |         14 |       1.5
-- …
```

Добавьте `days_since` и `change_kg`, сравнивая каждое взвешивание с предыдущим взвешиванием той же панды.

<Hint>

`lag(column) OVER (PARTITION BY panda ORDER BY weighed_on)` берёт значение из предыдущей строки этой панды. Разность двух дат — это число дней. Оба столбца используют одно и то же окно, поэтому его можно один раз назвать с помощью `WINDOW w AS (…)` и писать `OVER w`.

</Hint>

<Solution>

```sql
CREATE TABLE panda_weights (
  panda text NOT NULL,
  weighed_on date NOT NULL,
  kg numeric(5, 1) NOT NULL
);

INSERT INTO panda_weights (panda, weighed_on, kg) VALUES
  ('Bao', '2025-03-01', 98.0), ('Mochi', '2025-03-03', 84.0),
  ('Bao', '2025-04-05', 101.2), ('Lulu', '2025-03-10', 112.3),
  ('Bao', '2025-03-15', 99.5), ('Mochi', '2025-03-24', 86.5),
  ('Mochi', '2025-04-07', 86.5), ('Lulu', '2025-04-14', 110.9),
  ('Bao', '2025-04-19', 100.4);

SELECT panda, weighed_on, kg,
  weighed_on - lag(weighed_on) OVER w AS days_since,
  kg - lag(kg) OVER w AS change_kg
FROM panda_weights
WINDOW w AS (PARTITION BY panda ORDER BY weighed_on)
ORDER BY panda, weighed_on;
```

</Solution>
