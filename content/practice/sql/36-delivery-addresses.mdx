Panda shop customers can now save several delivery addresses 📦. Create a table **`addresses`** with these columns:

| column | rules |
| --- | --- |
| `id` | an identity primary key |
| `customer_id` | required, a real customer; **deleting the customer deletes their addresses** |
| `label` | required, like `Home` or `Work`; **can't be empty or only spaces** |
| `line` | required, the address itself |
| `is_default` | required, **false by default** |

And two rules that need more than a column constraint:

1. A customer can't have two addresses with the same label, **ignoring upper and lower case**: `Home` and `home` clash. Different customers can of course both have a `Home`.
2. Each customer has **at most one default address**. Any number of non-default addresses is fine.

Then add these addresses, and finish with a list of **`customer`** (the customer's name), **`label`** and **`is_default`**, sorted by customer name, then label:

| customer_id | label | line | is_default |
| --- | --- | --- | --- |
| 18 | Home | 12 Hanok Lane, Seoul | true |
| 18 | Work | 1 Tower Road, Seoul | false |
| 20 | Home | 5 Bridge Street, Prague | true |
| 19 | Gym | 9 Canal Street, Manchester | *(leave it out)* |

```sql
-- customer   | label | is_default
-- Grace Kim  | Home  | t
-- Grace Kim  | Work  | f
-- …
```

>

Create `addresses` with all its rules, add the four addresses and list them.

<Hint>

`ON DELETE CASCADE` goes on the foreign key, and `CHECK (trim(label) <> '')` refuses blank labels. A plain `UNIQUE` can't ignore case or look only at some rows, but a unique **index** can: `CREATE UNIQUE INDEX … ON addresses (customer_id, lower(label))` is an expression index, and `… ON addresses (customer_id) WHERE is_default` is a partial one.

</Hint>

<Solution>

```sql
CREATE TABLE addresses (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  customer_id integer NOT NULL REFERENCES customers (id) ON DELETE CASCADE,
  label text NOT NULL CHECK (trim(label) <> ''),
  line text NOT NULL,
  is_default boolean NOT NULL DEFAULT false
);

CREATE UNIQUE INDEX addresses_label_per_customer
  ON addresses (customer_id, lower(label));

CREATE UNIQUE INDEX addresses_one_default
  ON addresses (customer_id)
  WHERE is_default;

INSERT INTO addresses (customer_id, label, line, is_default) VALUES
  (18, 'Home', '12 Hanok Lane, Seoul', true),
  (18, 'Work', '1 Tower Road, Seoul', false),
  (20, 'Home', '5 Bridge Street, Prague', true);

INSERT INTO addresses (customer_id, label, line) VALUES
  (19, 'Gym', '9 Canal Street, Manchester');

SELECT c.name AS customer, a.label, a.is_default
FROM addresses AS a
JOIN customers AS c ON c.id = a.customer_id
ORDER BY customer, a.label;
```

The partial index only contains rows `WHERE is_default`, so it compares the default addresses alone: a second default for the same customer clashes, and non-default rows never do. To move a customer's default, unset the old one first, then set the new one.

</Solution>
