The panda company's org chart has one CEO (the employee with no manager), and everyone else reports to someone through `employees.manager_id`. The people **directly under the CEO** each lead a **branch** of the tree 🌳.

For **every employee except the CEO**, show:

- **`name`**: the employee's name,
- **`branch`**: the name of the person directly under the CEO whose branch they're in (people directly under the CEO are in their own branch),
- **`level`**: how many steps below the CEO they are (1 for the branch leaders, 2 for their reports, and so on).

Sort by `branch`, then `level`, then `name`.

```sql
-- name           | branch      | level
-- Alan Turing    | Alan Turing |     1
-- Ada Lovelace   | Alan Turing |     2
-- Barbara Liskov | Alan Turing |     2
-- Ken Thompson   | Alan Turing |     3
-- …
```

Follow the managers, not the `department_id` column: a team can be moved under another branch without changing department, and the tree can grow any number of levels deep.

Write a recursive query that gives every employee below the CEO their `branch` and `level`.

<Hint>

Use `WITH RECURSIVE`. The anchor selects the branch leaders (people whose manager has no manager) with `name AS branch` and `1 AS level`. The recursive part joins `employees AS e ON e.manager_id = tree.id` and simply **carries** `tree.branch` down, adding 1 to the level.

</Hint>

<Solution>

```sql
WITH RECURSIVE tree AS (
  SELECT e.id, e.name, e.name AS branch, 1 AS level
  FROM employees AS e
  JOIN employees AS boss ON boss.id = e.manager_id
  WHERE boss.manager_id IS NULL
  UNION ALL
  SELECT e.id, e.name, tree.branch, tree.level + 1
  FROM employees AS e
  JOIN tree ON e.manager_id = tree.id
)
SELECT name, branch, level
FROM tree
ORDER BY branch, level, name;
```

You could also start the recursion at the CEO with `level` 0 and a `NULL` branch, and set the branch with `coalesce(tree.branch, e.name)` on the way down; then filter out the CEO at the end.

</Solution>
