В магазине панды появляются корзины 🛒. Заготовка создаёт таблицу `baskets` с двумя корзинами: корзиной **Nina Novak** (покупатель 20) и корзиной **Tom Baker** (покупатель 19). Nina только что нажала «Купить». Оформите её заказ:

1. Сначала добавьте в `products` защиту: **ограничение `CHECK` с именем `stock_not_negative`**, чтобы `stock` **никогда не опускался ниже 0**. Если при оформлении заказа продаётся больше, чем есть на складе, база данных отклонит изменение, и вся транзакция откатится.
2. Затем **между `BEGIN` и `COMMIT`**:
   - создайте **один заказ** для покупателя 20 с `ordered_at` `'2025-07-01 10:00'` и статусом `'paid'`,
   - скопируйте каждую позицию её корзины в `order_items` по **текущей цене** товара,
   - **уменьшите запас каждого товара** на купленное количество,
   - **очистите её корзину** (корзина Tom остаётся).
3. Завершите решение запросом, который выводит позиции её заказа: **`product`** (название), **`quantity`**, **`unit_price`** и **`line_total`** (`quantity × unit_price`), отсортированные по названию товара.

Не вписывайте id нового заказа вручную: получите его от базы данных (изящнее всего это сделать через CTE, изменяющее данные (data-modifying CTE), с `RETURNING`).

```sql
-- product       | quantity | unit_price | line_total
-- Matcha Powder |        2 |      14.00 |      28.00
-- …
```

Добавьте защиту, оформите корзину Nina одной транзакцией и выведите позиции её заказа.

<Hint>

Защита — это `ALTER TABLE products ADD CONSTRAINT stock_not_negative CHECK (stock >= 0)`. Для позиций заказа `WITH new_order AS (INSERT INTO orders … RETURNING id) INSERT INTO order_items … SELECT new_order.id, b.product_id, b.quantity, p.price FROM new_order CROSS JOIN baskets AS b JOIN products AS p …` создаёт заказ и его позиции одной инструкцией. Уменьшите запас с помощью `UPDATE products AS p … FROM baskets AS b WHERE …`.

</Hint>

<Solution>

```sql
CREATE TABLE baskets (
  customer_id integer NOT NULL REFERENCES customers (id),
  product_id integer NOT NULL REFERENCES products (id),
  quantity integer NOT NULL CHECK (quantity > 0),
  PRIMARY KEY (customer_id, product_id)
);

INSERT INTO baskets (customer_id, product_id, quantity) VALUES
  (20, 2, 2),
  (20, 15, 1),
  (20, 5, 3),
  (19, 8, 5);

ALTER TABLE products
  ADD CONSTRAINT stock_not_negative CHECK (stock >= 0);

BEGIN;

WITH new_order AS (
  INSERT INTO orders (customer_id, ordered_at, status)
  VALUES (20, '2025-07-01 10:00', 'paid')
  RETURNING id
)
INSERT INTO order_items (order_id, product_id, quantity, unit_price)
SELECT new_order.id, b.product_id, b.quantity, p.price
FROM new_order
CROSS JOIN baskets AS b
JOIN products AS p ON p.id = b.product_id
WHERE b.customer_id = 20;

UPDATE products AS p
SET stock = p.stock - b.quantity
FROM baskets AS b
WHERE b.product_id = p.id
  AND b.customer_id = 20;

DELETE FROM baskets WHERE customer_id = 20;

COMMIT;

SELECT p.name AS product, oi.quantity, oi.unit_price,
  oi.quantity * oi.unit_price AS line_total
FROM orders AS o
JOIN order_items AS oi ON oi.order_id = o.id
JOIN products AS p ON p.id = oi.product_id
WHERE o.customer_id = 20
ORDER BY product;
```

Защита живёт в таблице, а не в вашем коде оформления заказа, поэтому она охраняет и все будущие инструкции. Если бы заказ оформлял Tom, `UPDATE` упал бы на `stock_not_negative`, транзакция была бы прервана, а его заказ и позиции заказа исчезли бы при `ROLLBACK`.

</Solution>
