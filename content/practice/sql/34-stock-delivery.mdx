A van just pulled up at the panda shop 🚚. The starter code saves its delivery note in a table called `delivery`: one row per **box**, with the product's `name`, `category`, `price` and how many items are in it (`items`). Some products came in **more than one box**.

Put the delivery on the shelves with **one `INSERT … ON CONFLICT`** into `products`:

- A product the shop **already sells** (same `name`) gets its `stock` **increased** by all the items delivered for it. Its `price` and `category` stay as they are, even if the delivery note says something else.
- A product the shop **doesn't sell yet** is added, with the delivered items as its stock.

`products` has no rule that names are unique yet, and `ON CONFLICT (name)` needs one, so **add a unique constraint on `products.name` first**. End the upsert with `RETURNING name, stock`. The order of the returned rows doesn't matter.

```sql
-- name         | stock
-- Jasmine Tea  |    60   -- 40 on the shelf + 12 + 8 delivered
-- Lychee Tea   |    25   -- new
-- …
```

Use the rows in `delivery`, not a list of values typed by hand: tomorrow's van brings a different note.

Make product names unique, then add the delivery to `products` with one upsert that returns `name` and `stock`.

<Hint>

`ON CONFLICT (name)` only works when `name` has a unique constraint, so that comes first. Watch out: some products came in two boxes.

</Hint>

<Hint>

1. Add the constraint with `ALTER TABLE products ADD CONSTRAINT … UNIQUE (name)`.
2. Add the boxes up per product: `INSERT INTO products (name, category, price, stock) SELECT name, …, sum(items) FROM delivery GROUP BY name`. Without the grouping, `ON CONFLICT` would touch the same row twice, which is an error.
3. In `DO UPDATE SET stock = …`, `products.stock` is the old value and `EXCLUDED.stock` is what you tried to insert. Set only `stock`, so the price and category stay as they are.

</Hint>

<Hint>

```sql
ALTER TABLE products ADD CONSTRAINT products_name_key UNIQUE (name);
INSERT INTO products (name, category, price, stock)
SELECT name, min(category), min(price), ...
FROM delivery
GROUP BY name
ON CONFLICT (name) DO UPDATE
SET stock = ...  -- the old stock plus the delivered items
RETURNING name, stock;
```

Keep the starter's `CREATE TABLE delivery` and `INSERT` above this.

</Hint>

<Solution>

```sql
CREATE TABLE delivery (
  name text NOT NULL,
  category text NOT NULL,
  price numeric(8, 2) NOT NULL,
  items integer NOT NULL
);

INSERT INTO delivery (name, category, price, items) VALUES
  ('Jasmine Tea', 'tea', 6.50, 12),
  ('Earl Grey', 'tea', 5.25, 20),
  ('Lychee Tea', 'tea', 7.20, 15),
  ('Kite', 'toys', 14.00, 6),
  ('Jasmine Tea', 'tea', 6.50, 8),
  ('Bamboo Yo-yo', 'toys', 3.40, 30),
  ('Lychee Tea', 'tea', 7.20, 10);

ALTER TABLE products ADD CONSTRAINT products_name_key UNIQUE (name);

INSERT INTO products (name, category, price, stock)
SELECT name, min(category), min(price), sum(items)
FROM delivery
GROUP BY name
ON CONFLICT (name) DO UPDATE
SET stock = products.stock + EXCLUDED.stock
RETURNING name, stock;
```

Only `stock` is in the `SET` list, so the Kite keeps its shop price of 15.00 even though the delivery note says 14.00. `min(category)` and `min(price)` just pick a value for each name; `GROUP BY name, category, price` works too, as long as every box of a product has the same price.

</Solution>
