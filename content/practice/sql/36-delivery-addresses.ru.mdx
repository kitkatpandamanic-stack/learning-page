Покупатели магазина панды теперь могут сохранять несколько адресов доставки 📦. Создайте таблицу **`addresses`** с этими столбцами:

| столбец | правила |
| --- | --- |
| `id` | первичный ключ, столбец идентификации (identity) |
| `customer_id` | обязательный, существующий покупатель; **при удалении покупателя удаляются и его адреса** |
| `label` | обязательный, например `Home` или `Work`; **не может быть пустым или состоять только из пробелов** |
| `line` | обязательный, сам адрес |
| `is_default` | обязательный, **по умолчанию false** |

И два правила, для которых ограничения на столбце уже не хватит:

1. У покупателя не может быть двух адресов с одинаковой меткой **без учёта регистра**: `Home` и `home` конфликтуют. А вот у разных покупателей, конечно, может быть по своему `Home`.
2. У каждого покупателя **не больше одного адреса по умолчанию**. Адресов не по умолчанию может быть сколько угодно.

Затем добавьте эти адреса и завершите решение списком из **`customer`** (имя покупателя), **`label`** и **`is_default`**, отсортированным по имени покупателя, затем по метке:

| customer_id | label | line | is_default |
| --- | --- | --- | --- |
| 18 | Home | 12 Hanok Lane, Seoul | true |
| 18 | Work | 1 Tower Road, Seoul | false |
| 20 | Home | 5 Bridge Street, Prague | true |
| 19 | Gym | 9 Canal Street, Manchester | *(не указывайте)* |

```sql
-- customer   | label | is_default
-- Grace Kim  | Home  | t
-- Grace Kim  | Work  | f
-- …
```

<Hint>

Правила для столбцов — это обычные ограничения. С двумя дополнительными правилами сложнее: обычный `UNIQUE` не умеет игнорировать регистр или смотреть только на часть строк. А уникальный **индекс** умеет и то, и другое.

</Hint>

<Hint>

1. Добавьте `NOT NULL`, где нужно, `ON DELETE CASCADE` на внешний ключ, `CHECK (trim(label) <> '')` против пустых меток и `DEFAULT false` для `is_default`.
2. `CREATE UNIQUE INDEX … ON addresses (customer_id, lower(label))` — это индекс по выражению (expression index), поэтому `Home` и `home` конфликтуют.
3. `CREATE UNIQUE INDEX … ON addresses (customer_id) WHERE is_default` — это частичный индекс (partial index): он сравнивает только адреса по умолчанию.
4. Вставьте строки (для адреса спортзала не указывайте `is_default`), затем присоедините `customers` для списка.

</Hint>

<Solution>

```sql
CREATE TABLE addresses (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  customer_id integer NOT NULL REFERENCES customers (id) ON DELETE CASCADE,
  label text NOT NULL CHECK (trim(label) <> ''),
  line text NOT NULL,
  is_default boolean NOT NULL DEFAULT false
);

CREATE UNIQUE INDEX addresses_label_per_customer
  ON addresses (customer_id, lower(label));

CREATE UNIQUE INDEX addresses_one_default
  ON addresses (customer_id)
  WHERE is_default;

INSERT INTO addresses (customer_id, label, line, is_default) VALUES
  (18, 'Home', '12 Hanok Lane, Seoul', true),
  (18, 'Work', '1 Tower Road, Seoul', false),
  (20, 'Home', '5 Bridge Street, Prague', true);

INSERT INTO addresses (customer_id, label, line) VALUES
  (19, 'Gym', '9 Canal Street, Manchester');

SELECT c.name AS customer, a.label, a.is_default
FROM addresses AS a
JOIN customers AS c ON c.id = a.customer_id
ORDER BY customer, a.label;
```

Частичный индекс содержит только строки `WHERE is_default`, поэтому сравнивает между собой лишь адреса по умолчанию: второй адрес по умолчанию у того же покупателя вызывает конфликт, а строки не по умолчанию не конфликтуют никогда. Чтобы сменить адрес по умолчанию, сначала снимите отметку со старого, а затем поставьте на новый.

</Solution>
