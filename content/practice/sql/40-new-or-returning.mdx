The panda shop's investors ask one question every month: is the money coming from **new** customers or from customers who **come back**? 📈 Build the answer for every month with sales.

The rules:

- Only orders that **aren't cancelled** count, for revenue and for deciding who is new.
- An order's revenue is the sum of `quantity * unit_price` over its lines.
- A customer's **first order** is their earliest non-cancelled order. Its revenue is **new** revenue; every later order of theirs is **returning** revenue. (A cancelled order doesn't make anyone a returning customer.)

Return one row per month with **`month`** (text like `'2025-03'`), **`new_revenue`**, **`returning_revenue`** and **`returning_pct`**: returning revenue as a percentage of the month's revenue, rounded to 1 decimal. Show **0, not NULL**, when a month has no new or no returning revenue. Sort by `month`.

```sql
-- month   | new_revenue | returning_revenue | returning_pct
-- 2025-01 |      518.30 |                 0 |           0.0
-- …
-- 2025-03 |      367.67 |            158.13 |          30.1
-- …
```

Split each month's revenue into new and returning, with the returning share.

<Hint>

First work out when each customer's first non-cancelled order was. Then every order is either that one (new money) or a later one (returning money). An aggregate with `FILTER` can sum both kinds in one `GROUP BY`.

</Hint>

<Hint>

1. CTE `order_totals`: one row per non-cancelled order with its customer, time and total. Drop cancelled orders here, before you look for first orders.
2. CTE `first_orders`: each customer's `min(ordered_at)` from `order_totals`.
3. Join the two, group by `to_char(ordered_at, 'YYYY-MM')`, and split the revenue with `sum(total) FILTER (WHERE …)`. Wrap each sum in `coalesce(…, 0)`.
4. The percentage is `100 * returning_revenue / (new_revenue + returning_revenue)`, rounded to 1 decimal.

</Hint>

<Hint>

```sql
WITH order_totals AS (
  ...  -- id, customer_id, ordered_at, total; no cancelled orders
),
first_orders AS (
  SELECT customer_id, min(ordered_at) AS first_at
  FROM order_totals
  GROUP BY customer_id
),
monthly AS (
  SELECT to_char(t.ordered_at, 'YYYY-MM') AS month,
    coalesce(sum(t.total) FILTER (WHERE ...), 0) AS new_revenue,
    coalesce(sum(t.total) FILTER (WHERE ...), 0) AS returning_revenue
  FROM order_totals AS t
  JOIN first_orders AS f ON f.customer_id = t.customer_id
  GROUP BY month
)
SELECT month, new_revenue, returning_revenue,
  ... AS returning_pct
FROM monthly
ORDER BY month;
```

</Hint>

<Solution>

```sql
WITH order_totals AS (
  SELECT o.id, o.customer_id, o.ordered_at,
    sum(oi.quantity * oi.unit_price) AS total
  FROM orders AS o
  JOIN order_items AS oi ON oi.order_id = o.id
  WHERE o.status <> 'cancelled'
  GROUP BY o.id
),
first_orders AS (
  SELECT customer_id, min(ordered_at) AS first_at
  FROM order_totals
  GROUP BY customer_id
),
monthly AS (
  SELECT to_char(t.ordered_at, 'YYYY-MM') AS month,
    coalesce(sum(t.total) FILTER (WHERE t.ordered_at = f.first_at), 0) AS new_revenue,
    coalesce(sum(t.total) FILTER (WHERE t.ordered_at > f.first_at), 0) AS returning_revenue
  FROM order_totals AS t
  JOIN first_orders AS f ON f.customer_id = t.customer_id
  GROUP BY month
)
SELECT month, new_revenue, returning_revenue,
  round(100 * returning_revenue / (new_revenue + returning_revenue), 1) AS returning_pct
FROM monthly
ORDER BY month;
```

The cancelled filter has to sit in `order_totals`, before the first orders are found: customer 12's first order (January) was cancelled, so their delivered order in March counts as **new** money.

</Solution>
