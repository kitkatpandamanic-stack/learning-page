Инвесторы магазина панды каждый месяц задают один и тот же вопрос: приходят деньги от **новых** покупателей или от тех, кто **возвращается**? 📈 Постройте ответ для каждого месяца с продажами.

Правила:

- Учитываются только **неотменённые** заказы — и для выручки, и для определения новых покупателей.
- Выручка заказа — это сумма `quantity * unit_price` по его позициям.
- **Первый заказ** покупателя — его самый ранний неотменённый заказ. Его выручка — **новая**; выручка каждого следующего заказа этого покупателя — **повторная**. (Отменённый заказ не делает покупателя вернувшимся.)

Верните одну строку на месяц со столбцами **`month`** (текст вида `'2025-03'`), **`new_revenue`**, **`returning_revenue`** и **`returning_pct`**: повторная выручка в процентах от выручки месяца, округлённая до 1 знака после запятой. Показывайте **0, а не NULL**, если в месяце нет новой или повторной выручки. Отсортируйте по `month`.

```sql
-- month   | new_revenue | returning_revenue | returning_pct
-- 2025-01 |      518.30 |                 0 |           0.0
-- …
-- 2025-03 |      367.67 |            158.13 |          30.1
-- …
```

Разделите выручку каждого месяца на новую и повторную и посчитайте долю повторной.

<Hint>

Сначала выясните, когда был первый неотменённый заказ каждого покупателя. Тогда любой заказ — либо этот самый (новые деньги), либо более поздний (повторные деньги). Агрегатная функция с `FILTER` может посчитать обе суммы в одном `GROUP BY`.

</Hint>

<Hint>

1. CTE `order_totals`: одна строка на каждый неотменённый заказ с покупателем, временем и суммой. Отменённые заказы отбрасывайте именно здесь, до поиска первых заказов.
2. CTE `first_orders`: `min(ordered_at)` каждого покупателя из `order_totals`.
3. Соедините их, сгруппируйте по `to_char(ordered_at, 'YYYY-MM')` и разделите выручку с помощью `sum(total) FILTER (WHERE …)`. Оберните каждую сумму в `coalesce(…, 0)`.
4. Процент — это `100 * returning_revenue / (new_revenue + returning_revenue)`, округлённый до 1 знака.

</Hint>

<Hint>

```sql
WITH order_totals AS (
  ...  -- id, customer_id, ordered_at, total; без отменённых заказов
),
first_orders AS (
  SELECT customer_id, min(ordered_at) AS first_at
  FROM order_totals
  GROUP BY customer_id
),
monthly AS (
  SELECT to_char(t.ordered_at, 'YYYY-MM') AS month,
    coalesce(sum(t.total) FILTER (WHERE ...), 0) AS new_revenue,
    coalesce(sum(t.total) FILTER (WHERE ...), 0) AS returning_revenue
  FROM order_totals AS t
  JOIN first_orders AS f ON f.customer_id = t.customer_id
  GROUP BY month
)
SELECT month, new_revenue, returning_revenue,
  ... AS returning_pct
FROM monthly
ORDER BY month;
```

</Hint>

<Solution>

```sql
WITH order_totals AS (
  SELECT o.id, o.customer_id, o.ordered_at,
    sum(oi.quantity * oi.unit_price) AS total
  FROM orders AS o
  JOIN order_items AS oi ON oi.order_id = o.id
  WHERE o.status <> 'cancelled'
  GROUP BY o.id
),
first_orders AS (
  SELECT customer_id, min(ordered_at) AS first_at
  FROM order_totals
  GROUP BY customer_id
),
monthly AS (
  SELECT to_char(t.ordered_at, 'YYYY-MM') AS month,
    coalesce(sum(t.total) FILTER (WHERE t.ordered_at = f.first_at), 0) AS new_revenue,
    coalesce(sum(t.total) FILTER (WHERE t.ordered_at > f.first_at), 0) AS returning_revenue
  FROM order_totals AS t
  JOIN first_orders AS f ON f.customer_id = t.customer_id
  GROUP BY month
)
SELECT month, new_revenue, returning_revenue,
  round(100 * returning_revenue / (new_revenue + returning_revenue), 1) AS returning_pct
FROM monthly
ORDER BY month;
```

Фильтр отменённых заказов должен стоять в `order_totals`, до поиска первых заказов: первый заказ покупателя 12 (в январе) был отменён, поэтому его доставленный заказ в марте считается **новыми** деньгами.

</Solution>
