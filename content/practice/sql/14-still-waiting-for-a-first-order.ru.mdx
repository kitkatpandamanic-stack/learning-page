Магазин панды хочет отправить **приветственную скидку** 🎁 покупателям, которые зарегистрировались, но так ничего и не купили. Покупатель считается «ничего не купившим», если у него **нет ни одного заказа** или **есть только отменённые**.

Выведите таких покупателей со столбцами `name`, `email` и `joined_on`. Отсортируйте по `joined_on`, **от самых давних**, затем по `name`.

```sql
-- name       | email               | joined_on
-- Grace Kim  | grace@pandadev.test | 2024-11-23
-- …
```

Сейчас у каждого покупателя с отменённым заказом есть и настоящий, но это может измениться: запрос должен работать и тогда, когда единственный заказ покупателя отменён.

Оставьте только покупателей без неотменённых заказов, начиная с самых давних.

<Hint>

Вы ищете покупателей, для которых в другой таблице **нет** подходящей строки. Какое соединение сохраняет покупателя, даже если у него нет заказов? Не забудьте о покупателях, у которых все заказы отменены.

</Hint>

<Hint>

`LEFT JOIN orders` сохраняет всех покупателей и заполняет столбцы заказа значением NULL, если пары не нашлось. Условие на статус, `o.status <> 'cancelled'`, поставьте в часть `ON`, чтобы отменённые заказы никогда не находили пару: в `WHERE` оно отбросило бы и строки с NULL. Затем `WHERE o.id IS NULL` оставит покупателей без пары. Отсортируйте по `c.joined_on, c.name`.

</Hint>

<Hint>

```sql
SELECT c.name, c.email, c.joined_on
FROM customers AS c
LEFT JOIN orders AS o
  ON o.customer_id = c.id AND ...  -- отменённые заказы не находят пару
WHERE ...                          -- подходящего заказа нет
ORDER BY c.joined_on, c.name;
```

</Hint>

<Solution>

```sql
SELECT c.name, c.email, c.joined_on
FROM customers AS c
LEFT JOIN orders AS o
  ON o.customer_id = c.id AND o.status <> 'cancelled'
WHERE o.id IS NULL
ORDER BY c.joined_on, c.name;
```

`WHERE NOT EXISTS (SELECT 1 FROM orders AS o WHERE o.customer_id = c.id AND o.status <> 'cancelled')` работает ничуть не хуже.

</Solution>
