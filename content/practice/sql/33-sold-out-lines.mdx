Bad news at the panda shop: some products have **sold out** (`stock` is 0), and orders that are still **`paid`** (not shipped yet) can't get them. Remove those lines from `order_items`: delete every order line whose product has `stock = 0` **and** whose order has the status `'paid'`.

Orders that are `shipped` or `delivered` already left the warehouse, so their lines **must stay**, even for sold-out products. Don't delete any orders, only lines.

End the `DELETE` with `RETURNING` so the shop can email the customers: return **`order_id`**, **`product`** (the product's name) and **`quantity`**. The order of the returned rows doesn't matter.

```sql
-- order_id | product   | quantity
--        8 | Earl Grey |        2
--       13 | Earl Grey |        1
-- …
```

Write the `DELETE` that removes sold-out products from paid orders and returns `order_id`, `product` and `quantity`.

<Hint>

`DELETE FROM order_items AS oi USING products AS p, orders AS o WHERE …` lets you join the other two tables: match `p.id` and `o.id`, then add the two conditions. `RETURNING` can use columns from the `USING` tables too, like `p.name AS product`.

</Hint>

<Solution>

```sql
DELETE FROM order_items AS oi
USING products AS p, orders AS o
WHERE p.id = oi.product_id
  AND o.id = oi.order_id
  AND p.stock = 0
  AND o.status = 'paid'
RETURNING oi.order_id, p.name AS product, oi.quantity;
```

Subqueries work as well: `WHERE product_id IN (SELECT id FROM products WHERE stock = 0) AND order_id IN (SELECT id FROM orders WHERE status = 'paid')`, but then `RETURNING` can't see the product's name without another subquery.

</Solution>
