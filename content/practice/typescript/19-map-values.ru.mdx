У массивов есть `map`, а у объектов — нет. Напишите `mapValues(obj, fn)`, которая возвращает **новый** объект с теми же ключами, что и у `obj`, где каждое значение равно `fn(value, key)`.

- Ключи сохраняют исходный порядок.
- `fn` получает значение **и** его ключ.
- Исходный объект не меняется. Пустой объект даёт `{}`.

```ts
const prices = { tea: 2, cake: 3.5 };
mapValues(prices, (p) => p * 2);                 // { tea: 4, cake: 7 }
mapValues(prices, (p, key) => key + ": £" + p);  // { tea: "tea: £2", cake: "cake: £3.5" }
```

Типы: результат должен сохранять **точные ключи** входного объекта, а тип значений брать из колбэка (callback). После `const labels = mapValues(prices, (p) => "£" + p)`:

- `labels.tea` — это `string`,
- `labels.coffee` — ошибка компиляции (такого ключа нет),
- внутри колбэка `p` — это `number`, а `key` — `"tea" | "cake"`.

Используйте три параметра типа: `K extends string` для ключей, `V` для входных значений и `R` для результата колбэка, с `obj: Record<K, V>` и возвращаемым типом `Record<K, R>`.

Сделайте `mapValues` дженериком, чтобы тесты типов проходили, и соберите новый объект. Строки с `@ts-expect-error` проходят, только если в этой строке **есть** ошибка.

Понадобятся три параметра типа: ключи, старый тип значений и новый тип значений. Какой служебный тип описывает объект с известными ключами и одним типом значений?

</Hint>

<Hint>

Сигнатура такая: `function mapValues<K extends string, V, R>(obj: Record<K, V>, fn: (value: V, key: K) => R): Record<K, R>`. Начните результат с `{} as Record<K, R>`: он заполнится в цикле. Пройдите циклом по `Object.keys(obj) as K[]`: `Object.keys` всегда возвращает `string[]`, поэтому TypeScript нужно сказать, что эти строки — ключи объекта. Для каждого ключа запишите в результат `fn(obj[key], key)`. Новый объект не трогает старый и сохраняет порядок ключей.

</Hint>

```ts
function mapValues<K extends string, V, R>(
  obj: Record<K, V>,
  fn: (value: V, key: K) => R,
): Record<K, R> {
  const result = {} as Record<K, R>;
  for (const key of Object.keys(obj) as K[]) {
    result[key] = ...; // вызовите fn со значением и ключом
  }
  return result;
```

<Solution>

```ts
function mapValues<K extends string, V, R>(
  obj: Record<K, V>,
  fn: (value: V, key: K) => R,
): Record<K, R> {
  const result = {} as Record<K, R>;
  for (const key of Object.keys(obj) as K[]) {
    result[key] = fn(obj[key], key);
  }
  return result;
}

function typeTests() {
  const prices = { tea: 2, cake: 3.5 };
  const labels = mapValues(prices, (p) => "£" + p.toFixed(2));
  const tea: string = labels.tea;
  // @ts-expect-error: кофе нет
  labels.coffee;
  // @ts-expect-error: теперь значения — строки
  const cake: number = labels.cake;
  // @ts-expect-error: цены — числа, у них нет toUpperCase
  mapValues(prices, (p) => p.toUpperCase());
}

console.log(mapValues({ tea: 2, cake: 3.5 }, (p) => p * 2)); // { tea: 4, cake: 7 }
```

Сопоставляя `{ tea: 2, cake: 3.5 }` с `Record<K, V>`, TypeScript выводит `K = "tea" | "cake"` и `V = number`, а `R` берётся из того, что возвращает колбэк. Два утверждения типа (`as`) — честно признанные пробелы: пустой объект ещё не является полным `Record<K, R>`, а `Object.keys` не может гарантировать, что во время выполнения нет лишних ключей. Один проход — это O(n).

</Solution>
