The PandaDev command-line tool takes arguments like `serve --port 8080 --open notes.md`. Write `parseArgs(spec, argv)`: the **spec** says which options exist and what kind each one is, and the result's type is derived from it, so `flags.port` is a `number | undefined` without anyone writing that type by hand.

```ts
type Kind = "string" | "number" | "boolean";
type Spec = Record<string, Kind>;
type Parsed<S extends Spec> =
  | { ok: true; flags: Flags<S>; positional: string[] }
  | { ok: false; error: string };
```

`Flags<S>` has every key of the spec: `"boolean"` options are `boolean`; `"string"` and `"number"` options are `string | undefined` and `number | undefined`. In the result, every key of the spec is present: booleans default to `false`, the others to `undefined`.

Rules for reading `argv` (an array of strings) from left to right:

- `--name value` and `--name=value` set a string or number option. Without `=`, the next argument is the value, unless there is none or it starts with `--`: then it's the error `"--name needs a value"`.
- Numbers are converted with `Number(value)`; an empty or non-finite result is the error `` `--port expects a number, got "abc"` `` (the raw value in double quotes).
- `--flag` sets a boolean to `true` and `--no-flag` sets it to `false`. A boolean given a value (`--flag=yes`) is the error `"--flag doesn't take a value"`.
- An option that isn't in the spec is the error `"Unknown option --name"`. If an option appears twice, the last one wins.
- Anything that doesn't start with `--` is positional (so `-` and `-5` are positional, or values). After a lone `--`, every remaining argument is positional.
- Stop at the first error and return `{ ok: false, error }`.

```ts
const spec = { port: "number", open: "boolean", host: "string" } as const;
parseArgs(spec, ["serve", "--port", "8080", "--open", "notes.md"]);
// { ok: true,
//   flags: { port: 8080, open: true, host: undefined },
//   positional: ["serve", "notes.md"] }
parseArgs(spec, ["--port=abc"]);
// { ok: false, error: '--port expects a number, got "abc"' }
```

<Hint>

For the types, a lookup type from kind names to TypeScript types does most of the work, mapped over the spec's keys. At runtime, walk `argv` with an index, so you can take the next argument as a value when an option needs one.

</Hint>

<Hint>

Write `type KindType = { string: string; number: number; boolean: boolean }`, then `Flags<S> = { -readonly [K in keyof S]: S[K] extends "boolean" ? boolean : KindType[S[K]] | undefined }`. Use a `const` type parameter so a spec written inline keeps its literal kinds: `parseArgs<const S extends Spec>(spec: S, argv: readonly string[]): Parsed<S>`. It also makes the keys `readonly`, which is why `Flags` removes that with `-readonly`. Inside, work with plain types (`const flags: Record<string, unknown> = {}`, filled with the defaults first) and cast once at the end. In the loop: a lone `--` makes the rest positional; anything not starting with `--` is positional; split `--x=y` at the **first** `=` with `indexOf`. Try `no-` only when the exact name isn't in the spec, and only for booleans. A missing value is the next argument (`i++`), unless there is none or it starts with `--`. On any error, return `{ ok: false, error }` right away.

</Hint>

function parseArgs<const S extends Spec>(spec: S, argv: readonly string[]): Parsed<S> {
  const flags: Record<string, unknown> = {};
  for (const [name, kind] of Object.entries(spec)) {
    flags[name] = kind === "boolean" ? false : undefined;

<Solution>

```ts
// ===== Type-test helpers: don't change =====
type Expect<T extends true> = T;
type Equal<A, B> =
  (<X>() => X extends A ? 1 : 2) extends
  (<X>() => X extends B ? 1 : 2) ? true : false;

type Kind = "string" | "number" | "boolean";
type Spec = Record<string, Kind>;

type KindType = { string: string; number: number; boolean: boolean };
type Flags<S extends Spec> = {
  -readonly [K in keyof S]: S[K] extends "boolean"
    ? boolean
    : KindType[S[K]] | undefined;
};

type Parsed<S extends Spec> =
  | { ok: true; flags: Flags<S>; positional: string[] }
  | { ok: false; error: string };

function parseArgs<const S extends Spec>(
  spec: S,
  argv: readonly string[],
): Parsed<S> {
  const flags: Record<string, unknown> = {};
  for (const [name, kind] of Object.entries(spec)) {
    flags[name] = kind === "boolean" ? false : undefined;
  }
  const positional: string[] = [];
  const fail = (error: string): Parsed<S> => ({ ok: false, error });

  for (let i = 0; i < argv.length; i++) {
    const arg = argv[i];
    if (arg === "--") {
      positional.push(...argv.slice(i + 1));
      break;
    }
    if (!arg.startsWith("--")) {
      positional.push(arg);
      continue;
    }
    const eq = arg.indexOf("=");
    let name = eq === -1 ? arg.slice(2) : arg.slice(2, eq);
    let value = eq === -1 ? undefined : arg.slice(eq + 1);
    let kind: Kind | undefined = spec[name];
    let negated = false;
    if (kind === undefined && name.startsWith("no-")) {
      const base = name.slice(3);
      if (spec[base] === "boolean") {
        name = base;
        kind = "boolean";
        negated = true;
      }
    }
    if (kind === undefined) return fail("Unknown option --" + name);
    if (kind === "boolean") {
      if (value !== undefined) {
        return fail("--" + name + " doesn't take a value");
      }
      flags[name] = !negated;
      continue;
    }
    if (value === undefined) {
      const next = argv[i + 1];
      if (next === undefined || next.startsWith("--")) {
        return fail("--" + name + " needs a value");
      }
      value = next;
      i++;
    }
    if (kind === "number") {
      const n = Number(value);
      if (value.trim() === "" || !Number.isFinite(n)) {
        return fail(
          "--" + name + ' expects a number, got "' + value + '"',
        );
      }
      flags[name] = n;
    } else {
      flags[name] = value;
    }
  }
  return { ok: true, flags: flags as Flags<S>, positional };
}

// ===== Type tests: don't change these =====
function typeTests() {
  const r = parseArgs(
    { port: "number", open: "boolean", host: "string" },
    [],
  );
  if (r.ok) {
    type cases = [
      Expect<Equal<typeof r.flags, {
        port: number | undefined;
        open: boolean;
        host: string | undefined;
      }>>,
    ];
    // @ts-expect-error: there is no "debug" option
    r.flags.debug;
  }
  // @ts-expect-error: "date" is not a Kind
  parseArgs({ when: "date" }, []);
}

const spec = { port: "number", open: "boolean", host: "string" } as const;
console.log(parseArgs(spec, ["serve", "--port", "8080", "--open"]));
```

`Flags<S>` maps every option name to the TypeScript type of its kind through the `KindType` lookup, and the `const` type parameter keeps `"number"` from widening to `string`, so the spec is the single source of truth for both parsing and types. The parser is one left-to-right pass with an index it can advance to consume a value: O(n) in the number of arguments.

</Solution>
