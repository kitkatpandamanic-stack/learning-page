Строители (builders) читаются приятно: `request().method("GET").url("/pandas").build()`, но обычный строитель позволяет вызвать `build()` слишком рано и падает только во время выполнения. Напишите такой, в котором TypeScript **отслеживает**, что уже задано, и `build()` просто не существует, пока не заданы и метод, и URL.

```ts
type Method = "GET" | "POST" | "PUT" | "DELETE";
type Req = {
  method: Method;
  url: string;
  headers: Record<string, string>;
  body?: string;
};
```

`request()` возвращает пустой строитель. Методы строителя:

- `method(m)` и `url(u)` задают эти части (повторный вызов заменяет старое значение).
- `header(name, value)` задаёт заголовок. Имена хранятся в нижнем регистре, поэтому `"X-Token"` и `"x-token"` — один и тот же заголовок (побеждает последнее значение).
- `query(name, value)` добавляет параметр запроса (`value` — `string` или `number`). Параметры добавляются к URL в порядке передачи, кодируются так же, как это делает `URLSearchParams` (`"red panda"` → `red+panda`), после `?`, или после `&`, если в URL уже есть `?`.
- `json(body)` записывает в `body` результат `JSON.stringify(body)` и задаёт заголовок `content-type` равным `application/json`.
- `build()` возвращает `Req`. Запрос `GET` с телом выбрасывает `TypeError` с сообщением `"GET requests can't have a body"`. Ключ `body` присутствует, только если тело было задано.

Каждый метод строителя возвращает **новый** строитель и не меняет старый, поэтому недостроенный строитель можно переиспользовать как шаблон. В типах `build` доступен только после вызовов и `method`, и `url`: используйте параметры типа вроде `Builder<HasMethod, HasUrl>`.

```ts
const api = request().header("Accept", "application/json");
api.method("GET").url("/pandas").query("q", "red panda").build();
// { method: "GET", url: "/pandas?q=red+panda",
//   headers: { accept: "application/json" } }
api.method("POST").url("/pandas").json({ name: "Mei" }).build().body;
// '{"name":"Mei"}'
request().method("GET").build(); // ❌ ошибка типов: URL ещё нет
```

<Hint>

Опишите строитель дженерик-типом, а не классом: `type Builder<M extends boolean, U extends boolean> = { method(m: Method): Builder<true, U>; url(u: string): Builder<M, true>; header(…): Builder<M, U>; … } & ([M, U] extends [true, true] ? { build(): Req } : {})`. Кортеж `[M, U]` проверяет оба флага сразу.

</Hint>

<Hint>

Во время выполнения храните части в простом объекте `State` (`method?`, `url?`, `headers`, `query` как список пар, `body?`) и напишите `make(state)`, которая возвращает объект, чьи методы вызывают `make({ ...state, … })` со скопированными заголовками или списком параметров. Дайте ей возвращаемый тип `Builder<true, true>`: объект со всеми методами, включая `build`, подходит и под `Builder<false, false>`, поэтому `request()` может просто вернуть `make({ headers: {}, query: [] })`. Строку запроса закодирует `new URLSearchParams(pairs).toString()`.

</Hint>

<Solution>

```ts
type Method = "GET" | "POST" | "PUT" | "DELETE";
type Req = {
  method: Method;
  url: string;
  headers: Record<string, string>;
  body?: string;
};

type Builder<M extends boolean, U extends boolean> = {
  method(m: Method): Builder<true, U>;
  url(u: string): Builder<M, true>;
  header(name: string, value: string): Builder<M, U>;
  query(name: string, value: string | number): Builder<M, U>;
  json(body: unknown): Builder<M, U>;
} & ([M, U] extends [true, true] ? { build(): Req } : {});

type State = {
  method?: Method;
  url?: string;
  headers: Record<string, string>;
  query: [string, string][];
  body?: string;
};

function make(state: State): Builder<true, true> {
  return {
    method: (method) => make({ ...state, method }),
    url: (url) => make({ ...state, url }),
    header: (name, value) =>
      make({
        ...state,
        headers: { ...state.headers, [name.toLowerCase()]: value },
      }),
    query: (name, value) =>
      make({ ...state, query: [...state.query, [name, String(value)]] }),
    json: (body) =>
      make({
        ...state,
        body: JSON.stringify(body),
        headers: { ...state.headers, "content-type": "application/json" },
      }),
    build(): Req {
      const { method, url, headers, query, body } = state;
      if (method === undefined || url === undefined) {
        throw new TypeError("A request needs a method and a URL");
      }
      if (method === "GET" && body !== undefined) {
        throw new TypeError("GET requests can't have a body");
      }
      const search = new URLSearchParams(query).toString();
      const fullUrl = search === ""
        ? url
        : url + (url.includes("?") ? "&" : "?") + search;
      const req: Req = { method, url: fullUrl, headers: { ...headers } };
      if (body !== undefined) req.body = body;
      return req;
    },
  };
}

function request(): Builder<false, false> {
  return make({ headers: {}, query: [] });
}

// ===== Тесты типов: не меняйте их =====
function typeTests() {
  const a: Req = request().method("GET").url("/a").build();
  const b: Req = request().url("/b").header("x", "1").method("PUT").build();
  // @ts-expect-error: URL ещё нет
  request().method("GET").build();
  // @ts-expect-error: метода ещё нет
  request().url("/a").query("q", 1).build();
  // @ts-expect-error: FETCH — не Method
  request().method("FETCH");
  return [a, b];
}

const api = request().header("Accept", "application/json");
const req = api.method("GET").url("/pandas").query("q", "red panda").build();
console.log(req);
```

Два логических параметра типа — это **фантомное** состояние: во время выполнения их нет, но возвращаемый тип каждого метода их обновляет, а условное пересечение добавляет `build`, только когда оба равны `true`. Один и тот же объект во время выполнения подходит под любое состояние типа, потому что строитель, у которого `build` есть, остаётся корректным строителем, у которого его «ещё нет» (лишние члены разрешены). Каждый вызов копирует маленький объект состояния, поэтому шаблоны нельзя случайно изменить.

</Solution>
