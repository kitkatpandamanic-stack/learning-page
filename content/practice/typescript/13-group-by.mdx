Write a generic `groupBy(items, keyOf)`. It calls `keyOf(item)` for every item and collects the items into an object of arrays, one array per key:

- Groups appear in the order their key is **first seen**, and items keep their original order inside each group.
- An empty array gives `{}`.
- The input array is not changed.

```ts
const pandas = [
  { name: "Mei", zoo: "Chengdu" },
  { name: "Bao", zoo: "Edinburgh" },
  { name: "Lin", zoo: "Chengdu" },
];
groupBy(pandas, (p) => p.zoo);
// { Chengdu: [Mei, Lin], Edinburgh: [Bao] }
```

Now the types. When the key callback returns a union of literals, like `"Chengdu" | "Edinburgh"`, the result should know the possible group names:

- The function has two type parameters: `T` for the items and `K extends string` for the keys the callback returns.
- It returns `Partial<Record<K, T[]>>`. `Partial`, because a group only exists if at least one item landed in it, so reading a group gives `T[] | undefined` and forces callers to handle the missing case.
- A misspelt group name (`byZoo.Paris`) and a callback that returns a non-string (`(p) => p.age`) are compile errors.

Make `groupBy` generic so the type tests pass, and group the items. The `@ts-expect-error` lines pass only when that line **is** an error.

<Hint>

The signature is `function groupBy<T, K extends string>(items: readonly T[], keyOf: (item: T) => K): Partial<Record<K, T[]>>`. Start with `const groups: Partial<Record<K, T[]>> = {};`, then for each item read `groups[key]`: push onto it if it exists, otherwise create `[item]`.

</Hint>

<Solution>

```ts
function groupBy<T, K extends string>(
  items: readonly T[],
  keyOf: (item: T) => K,
): Partial<Record<K, T[]>> {
  const groups: Partial<Record<K, T[]>> = {};
  for (const item of items) {
    const key = keyOf(item);
    const group = groups[key];
    if (group) group.push(item);
    else groups[key] = [item];
  }
  return groups;
}

type Zoo = "Chengdu" | "Edinburgh";
function typeTests(pandas: { name: string; zoo: Zoo; age: number }[]) {
  const byZoo = groupBy(pandas, (p) => p.zoo);
  const first: string | undefined = byZoo.Chengdu?.[0].name;
  // @ts-expect-error: a group may be missing, so check it first
  byZoo.Edinburgh.length;
  // @ts-expect-error: not a zoo
  byZoo.Paris;
  // @ts-expect-error: keys must be strings
  groupBy(pandas, (p) => p.age);
}

console.log(groupBy(["apple", "avocado", "kiwi"], (w) => w[0]));
```

TypeScript infers `K` from what the callback returns: `p.zoo` gives the union `Zoo`, while `w[0]` gives plain `string`, so the same function produces precise keys when it can and a general lookup otherwise. One pass over the items makes it O(n). (Plain objects list integer-like keys such as `"2"` before the others, so use a `Map` if you ever need first-seen order for numeric keys.)

</Solution>
