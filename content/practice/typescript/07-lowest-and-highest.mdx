The weather panda records the temperature every hour and wants the day's range. Write `minMax(temps)` that returns a **tuple** `[lowest, highest]`.

Two type requirements make this function safe to use:

- The return type is the tuple `[number, number]`, not `number[]`, so callers can destructure `const [lo, hi] = minMax(...)` and both are known to be numbers.
- An empty array has no lowest or highest value, so calling `minMax([])` should not compile at all. Use a **non-empty array type** for the parameter: `readonly [number, ...number[]]` means "one number, then any number of further numbers".

```ts
minMax([12, 7, 19, 7]);   // [7, 19]
minMax([-3]);             // [-3, -3]
minMax([]);               // ❌ compile error
```

Give `minMax` a non-empty tuple parameter and a `[number, number]` return type, then compute the range.

<Hint>

The type test wants `minMax([])` to be an error. How can a tuple type say "at least one number"? A rest element after the first item helps.

</Hint>

<Hint>

The signature is `function minMax(temps: readonly [number, ...number[]]): [number, number]`. Because the first item always exists now, start both `lo` and `hi` at `temps[0]`. Loop over every reading and update `lo` when you see something smaller and `hi` when you see something bigger. Return `[lo, hi]` and don't sort the input, so it stays unchanged.

</Hint>

<Solution>

```ts
function minMax(
  temps: readonly [number, ...number[]],
): [number, number] {
  let lo = temps[0];
  let hi = temps[0];
  for (const t of temps) {
    if (t < lo) lo = t;
    if (t > hi) hi = t;
  }
  return [lo, hi];
}

function typeTests() {
  const [lo, hi]: [number, number] = minMax([12, 7, 19]);
  // @ts-expect-error: an empty array has no range
  minMax([]);
}

console.log(minMax([12, 7, 19, 7])); // [ 7, 19 ]
```

Because the tuple type guarantees a first element, `temps[0]` is a `number` and the edge case "what do I return for an empty list?" disappears: the compiler refuses the call instead. One pass over the array makes it O(n).

</Solution>
