Часто нужен один «столбец» из массива объектов: все имена, все возрасты. Напишите `pluck(items, key)`, которая возвращает новый массив со значением `key` из каждого элемента, по порядку.

```ts
const pandas = [
  { name: "Mei", age: 4 },
  { name: "Bao", age: 7 },
];
pluck(pandas, "name");   // ["Mei", "Bao"]  (тип: string[])
pluck(pandas, "age");    // [4, 7]          (тип: number[])
pluck(pandas, "colour"); // ❌ ошибка компиляции: такого свойства нет
```

Самое интересное здесь — типы:

- `key` должен быть одним из имён свойств (property) элемента (`keyof T`), чтобы опечатка была ошибкой компиляции.
- Тип результата должен зависеть от ключа: `"name"` даёт `string[]`, `"age"` даёт `number[]`. Именно это описывает **тип доступа по индексу** (indexed access type) `T[K]`.

Пустой массив даёт пустой массив.

Сделайте `pluck` дженериком, чтобы тесты типов проходили, и верните выбранные значения. Строки с `@ts-expect-error` проходят, только если в этой строке **есть** ошибка.

<Hint>

Сигнатура такая: `function pluck<T, K extends keyof T>(items: readonly T[], key: K): T[K][]`. Тело — один вызов `map`.

</Hint>

<Solution>

```ts
function pluck<T, K extends keyof T>(
  items: readonly T[],
  key: K,
): T[K][] {
  return items.map((item) => item[key]);
}

function typeTests() {
  const pandas = [{ name: "Mei", age: 4 }];
  const names: string[] = pluck(pandas, "name");
  const ages: number[] = pluck(pandas, "age");
  // @ts-expect-error: такого свойства нет
  pluck(pandas, "colour");
  // @ts-expect-error: возрасты — это числа, а не строки
  const wrong: string[] = pluck(pandas, "age");
}

console.log(pluck([{ name: "Mei", age: 4 }], "name")); // [ 'Mei' ]
```

TypeScript выводит `T` из массива, а `K` — из переданного ключа (литерал `"age"`, а не просто `string`), поэтому `T[K]` превращается в тип именно этого свойства. Ограничение (constraint) `K extends keyof T` и делает опечатку в ключе ошибкой компиляции.

</Solution>
