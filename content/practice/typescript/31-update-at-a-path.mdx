App state is often a nested object that must never be changed in place: you build a new object instead, copying only the branches on the way to the change and **sharing** everything else (this is how React and Redux spot changes cheaply). Write a typed `setIn` and `updateIn` for that.

First the types. For a state object `T`:

- `Path<T>` is the union of **every** dotted path into `T`: object properties give both their own path and the paths inside them. Arrays and other non-plain values are leaves (no paths inside them). For `{ user: { name: string; tags: string[] }; count: number }` that's `"user" | "user.name" | "user.tags" | "count"`.
- `PathValue<T, P>` is the type at path `P` (`PathValue<State, "user">` is the whole `user` object type).

Then the functions. Every object on the path exists (no optional objects in the middle):

- `setIn(obj, path, value)` returns a new object with `value` at `path`. Every object on the way to the change is copied (with spread); every other branch is the **same** object as before. `obj` is never changed. If the value at `path` is already `value` (by `Object.is`), return `obj` itself.
- `updateIn(obj, path, fn)` is `setIn` with `fn(oldValue)` as the new value.

```ts
const state = {
  user: { name: "Mei", prefs: { theme: "light", size: 14 } },
  tags: ["new"],
};
const next = setIn(state, "user.prefs.theme", "dark");
next.user.prefs.theme;          // "dark"
state.user.prefs.theme;         // "light": unchanged
next.tags === state.tags;       // true: shared
next.user === state.user;       // false: copied on the way
setIn(state, "user.name", "Mei") === state; // true: nothing changed
updateIn(state, "user.prefs.size", (n) => n + 2).user.prefs.size; // 16
```

Write `Path`, `PathValue`, `setIn` and `updateIn`. The `Expect<Equal<…>>` lines and the `@ts-expect-error` lines are type tests; the second kind passes only when that line **is** an error.

<Hint>

Both types are recursive. `Path` can map over the keys of `T` and, for object values, glue the key to the inner paths with a template literal type; `PathValue` can peel off one key at a time with `infer`. The runtime side is a recursion too: copy only the objects on the path.

</Hint>

<Hint>

`Path` walks the string keys and turns the result into a union with `{ [K in keyof T & string]: … }[keyof T & string]`. For each key: an array gives just `K`; an object gives `K` plus a template literal of `K`, a dot and `Path<T[K]>`; anything else gives `K`. Check arrays **before** `object`, because arrays are objects too. `PathValue` checks whether `P` looks like `Head.Rest` (two `infer`s in a template literal) and recurses into `T[Head]`, otherwise it's `T[P]`. At runtime, split the path and recurse with a helper on `unknown`: `setAt(obj, keys, value)` takes the first key, works out the new child (the value itself for the last key, otherwise `setAt(child, rest, value)`), returns `obj` unchanged if `Object.is(oldChild, newChild)`, and otherwise `{ ...obj, [key]: newChild }`. `updateIn` reads the old value by walking the keys, then calls `setIn`. Cast once at the boundary (`as T`).

</Hint>

<Hint>

```ts
type Path<T> = {
  [K in keyof T & string]: T[K] extends readonly unknown[]
    ? K
    : T[K] extends object
      ? ... // K, plus K + "." + every path inside T[K]
      : K;
}[keyof T & string];

function setAt(obj: unknown, keys: string[], value: unknown): unknown {
  const [key, ...rest] = keys;
  const current = obj as Record<string, unknown>;
  const child = rest.length === 0 ? value : setAt(current[key], rest, value);
  // same child as before? return obj. Otherwise copy obj with the new child
}

function setIn<T, P extends Path<T>>(obj: T, path: P, value: PathValue<T, P>): T {
  return setAt(obj, path.split("."), value) as T;
}
```

`PathValue` and `updateIn` are still yours to write.

<Solution>

```ts
// ===== Type-test helpers: don't change =====
type Expect<T extends true> = T;
type Equal<A, B> =
  (<X>() => X extends A ? 1 : 2) extends
  (<X>() => X extends B ? 1 : 2) ? true : false;

type Path<T> = {
  [K in keyof T & string]: T[K] extends readonly unknown[]
    ? K
    : T[K] extends object
      ? K | `${K}.${Path<T[K]>}`
      : K;
}[keyof T & string];

type PathValue<T, P extends string> =
  P extends `${infer Head}.${infer Rest}`
    ? Head extends keyof T
      ? PathValue<T[Head], Rest>
      : never
    : P extends keyof T
      ? T[P]
      : never;

type Bag = Record<string, unknown>;

function setAt(obj: unknown, keys: string[], value: unknown): unknown {
  const [key, ...rest] = keys;
  const current = obj as Bag;
  const child =
    rest.length === 0 ? value : setAt(current[key], rest, value);
  if (Object.is(current[key], child)) return obj;
  return { ...current, [key]: child };
}

function getAt(obj: unknown, keys: string[]): unknown {
  let value = obj;
  for (const key of keys) value = (value as Bag)[key];
  return value;
}

function setIn<T, P extends Path<T>>(
  obj: T,
  path: P,
  value: PathValue<T, P>,
): T {
  return setAt(obj, path.split("."), value) as T;
}

function updateIn<T, P extends Path<T>>(
  obj: T,
  path: P,
  fn: (old: PathValue<T, P>) => PathValue<T, P>,
): T {
  const old = getAt(obj, path.split(".")) as PathValue<T, P>;
  return setIn(obj, path, fn(old));
}

// ===== Type tests: don't change these =====
type Theme = "light" | "dark";
type State = {
  user: { name: string; prefs: { theme: Theme; size: number } };
  tags: string[];
  count: number;
};

type cases = [
  Expect<Equal<
    Path<State>,
    | "user" | "user.name" | "user.prefs"
    | "user.prefs.theme" | "user.prefs.size" | "tags" | "count"
  >>,
  Expect<Equal<PathValue<State, "user.prefs.theme">, Theme>>,
  Expect<Equal<
    PathValue<State, "user.prefs">,
    { theme: Theme; size: number }
  >>,
];

function typeTests(state: State) {
  setIn(state, "user.prefs", { theme: "dark", size: 12 });
  updateIn(state, "count", (n) => n + 1);
  // @ts-expect-error: "blue" is not a Theme
  setIn(state, "user.prefs.theme", "blue");
  // @ts-expect-error: there is no user.age
  setIn(state, "user.age", 3);
}

const state: State = {
  user: { name: "Mei", prefs: { theme: "light", size: 14 } },
  tags: ["new"],
  count: 0,
};
const next = setIn(state, "user.prefs.theme", "dark");
console.log(next.user.prefs, next.tags === state.tags);
```

`Path` recurses through the type and offers both the object's own path and the paths inside it, while `PathValue` follows a path back down to its type, so `setIn` only accepts values that fit. At runtime, the recursion copies just the d objects on a path of depth d (O(d) work plus the spread of each copied object) and returns the old object wherever nothing changed, which is what makes "same value, same object" fall out for free.

</Solution>
