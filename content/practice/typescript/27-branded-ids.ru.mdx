В магазине панды ID пользователей и ID заказов — это строки, поэтому `ordersOf(order.id, orders)` спокойно компилируется и ничего не возвращает. Дайте каждому ID собственный **брендированный тип** (branded type), чтобы TypeScript их различал, и сделайте проверяющие конструкторы единственным способом получить такой ID.

- `UserId` — строка с брендом `"UserId"`. `toUserId(raw)` обрезает пробелы в `raw` и принимает `"u_"`, за которым идут от 3 до 12 строчных латинских букв или цифр. Возвращает обрезанную строку как `UserId` или выбрасывает `Error` с сообщением `"Invalid user id: <raw>"` (с исходным `raw`).
- `OrderId` — строка с брендом `"OrderId"`. `toOrderId(raw)` обрезает пробелы в `raw` и принимает `"ord-"`, за которым идут ровно 6 цифр, иначе выбрасывает `"Invalid order id: <raw>"`.
- `ordersOf(user, orders)` возвращает ID заказов, у которых `owner` равен `user`, начиная с наибольшего `total` (заказы с одинаковой суммой сохраняют исходный порядок). Массив `orders` менять нельзя.

```ts
type Order = { id: OrderId; owner: UserId; total: number };

const mei = toUserId(" u_mei ");   // "u_mei"
toUserId("mei");                    // выбрасывает "Invalid user id: mei"
const big = toOrderId("ord-000042");
ordersOf(mei, [
  { id: toOrderId("ord-000001"), owner: mei, total: 5 },
  { id: big, owner: mei, total: 30 },
]);                                 // ["ord-000042", "ord-000001"]
```

Брендированное значение во время выполнения остаётся обычной строкой, и его можно использовать везде, где ожидается `string`; бренд существует только для проверки типов.

Добавьте бренды двум типам ID, напишите их умные конструкторы и `ordersOf`. Строки с `@ts-expect-error` — это тесты типов: они проходят, только когда в этой строке **есть** ошибка.

<Hint>

Бренд — это пересечение (intersection) со свойством, которого нет ни у одной настоящей строки: `type UserId = string & { readonly __brand: "UserId" };`. У обычных строк нет `__brand`, поэтому их нельзя присвоить, а два бренда различаются, поэтому ID не смешиваются. Умный конструктор — единственное место с приведением: `return id as UserId;`.

</Hint>

<Hint>

Регулярные выражения: `/^u_[a-z0-9]{3,12}$/` и `/^ord-\d{6}$/`, проверяйте ими `raw.trim()`. В `ordersOf` `filter` создаёт новый массив, затем `sort((a, b) => b.total - a.total)` (сортировка в JavaScript стабильная), затем `map` в ID.

</Hint>

<Solution>

```ts
type UserId = string & { readonly __brand: "UserId" };
type OrderId = string & { readonly __brand: "OrderId" };

type Order = { id: OrderId; owner: UserId; total: number };

function toUserId(raw: string): UserId {
  const id = raw.trim();
  if (!/^u_[a-z0-9]{3,12}$/.test(id)) {
    throw new Error("Invalid user id: " + raw);
  }
  return id as UserId;
}

function toOrderId(raw: string): OrderId {
  const id = raw.trim();
  if (!/^ord-\d{6}$/.test(id)) {
    throw new Error("Invalid order id: " + raw);
  }
  return id as OrderId;
}

function ordersOf(user: UserId, orders: readonly Order[]): OrderId[] {
  return orders
    .filter((order) => order.owner === user)
    .sort((a, b) => b.total - a.total)
    .map((order) => order.id);
}

// ===== Тесты типов: не меняйте их =====
function typeTests(u: UserId, o: OrderId, orders: Order[]) {
  ordersOf(u, orders);
  const text: string = u; // UserId всё ещё строка
  // @ts-expect-error: OrderId — не UserId
  ordersOf(o, orders);
  // @ts-expect-error: обычная строка — не UserId
  ordersOf("u_mei", orders);
  // @ts-expect-error: ID нельзя создать без его конструктора
  const fake: OrderId = "ord-123456";
  return [text, fake];
}

const mei = toUserId(" u_mei ");
console.log(ordersOf(mei, [
  { id: toOrderId("ord-000001"), owner: mei, total: 5 },
  { id: toOrderId("ord-000042"), owner: mei, total: 30 },
]));
```

TypeScript сравнивает типы по форме, поэтому два псевдонима обычной `string` взаимозаменяемы. Пересечение с разными свойствами `__brand` делает формы разными, ничего не меняя во время выполнения, а приведения `as` живут только в конструкторах, сразу после проверки. `ordersOf` работает за O(n log n) из-за сортировки, а `filter` создаёт копию, благодаря которой входной массив остаётся нетронутым.

</Solution>
