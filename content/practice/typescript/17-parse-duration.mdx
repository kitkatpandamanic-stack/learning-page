The panda nap timer lets keepers type durations like `"1h 30m"` or `"45s"`. Write `parseDuration(text)` that returns the duration in **seconds**, or `null` if the text isn't a valid duration.

A valid duration is one or more **parts** separated by spaces (any number of spaces; spaces at the start and end are ignored). Each part is:

- a whole number of one or more digits (`0` is allowed),
- immediately followed by a unit: `h` (hours), `m` (minutes) or `s` (seconds), lower case.

Each unit may appear **at most once**, in any order. Anything else gives `null`: an empty or blank string, a missing number (`"h"`), a missing or unknown unit (`"10"`, `"3d"`), a decimal (`"1.5h"`), a space inside a part (`"10 m"`), or a repeated unit (`"5m 5m"`).

```ts
parseDuration("1h 30m");     // 5400
parseDuration("  45s ");     // 45
parseDuration("30m 1h");     // 5400
parseDuration("1.5h");       // null
parseDuration("5m 5m");      // null
```

The return type is `number | null`, so a caller can't use the result as a number without checking for `null` first. The type test below checks that.

Return the total number of seconds, or `null` for invalid text, with an honest return type.

<Hint>

`text.trim().split(/\s+/)` splits on runs of spaces (check for a blank string first: splitting `""` gives `[""]`). Match each part with `/^(\d+)([hms])$/`; keep a `Set` of units you've seen to catch repeats.

</Hint>

<Solution>

```ts
const SECONDS: Record<string, number> = { h: 3600, m: 60, s: 1 };

function parseDuration(text: string): number | null {
  const trimmed = text.trim();
  if (trimmed === "") return null;
  const seen = new Set<string>();
  let total = 0;
  for (const part of trimmed.split(/\s+/)) {
    const match = /^(\d+)([hms])$/.exec(part);
    if (!match) return null;
    const unit = match[2];
    if (seen.has(unit)) return null;
    seen.add(unit);
    total += Number(match[1]) * SECONDS[unit];
  }
  return total;
}

function typeTests() {
  const maybe: number | null = parseDuration("5m");
  // @ts-expect-error: the result can be null, check it first
  const sure: number = parseDuration("5m");
}

console.log(parseDuration("1h 30m")); // 5400
```

The regex accepts exactly one valid part, so every other shape of input falls through to `return null`. Returning `number | null` instead of a magic value like `-1` or `0` puts the failure in the type, so a caller writing `parseDuration(input) * 1000` gets a compile error until they handle `null`. The work is O(length of the text).

</Solution>
