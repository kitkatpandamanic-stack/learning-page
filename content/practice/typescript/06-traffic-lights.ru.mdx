У пешеходного перехода для панд возле зоопарка стоит светофор с тремя цветами: `"red"`, `"amber"` и `"green"`. Сейчас в коде цвет описан обычным `string`, поэтому опечатка вроде `"gren"` или бессмысленный цвет вроде `"blue"` проходят незамеченными.

1. Замените `type Light = string` на **объединение строковых литералов** (литеральных типов, literal types), чтобы разрешены были только три настоящих цвета.
2. Напишите `nextLight(light: Light): Light`. Светофор переключается по кругу `red → green → amber → red`.
3. Напишите `stepsUntilGreen(light: Light): number`: сколько вызовов `nextLight` нужно, чтобы дойти до зелёного (`0`, если уже зелёный).

```ts
nextLight("red");         // "green"
nextLight("amber");       // "red"
stepsUntilGreen("amber"); // 2   (amber → red → green)
nextLight("blue");        // ❌ ошибка компиляции, как только Light станет объединением
```

Превратите `Light` в объединение и реализуйте обе функции. Строки с `@ts-expect-error` — тесты типов: они проходят, только если в этой строке **есть** ошибка.

<Hint>

`type Light = "red" | "amber" | "green";`. Для `nextLight` хорошо подходит `switch (light)` с одним `case` на каждый цвет. Для `stepsUntilGreen` вызывайте `nextLight` в цикле `while` и считайте шаги — или тоже используйте `switch`.

</Hint>

<Solution>

```ts
type Light = "red" | "amber" | "green";

function nextLight(light: Light): Light {
  switch (light) {
    case "red":
      return "green";
    case "green":
      return "amber";
    case "amber":
      return "red";
  }
}

function stepsUntilGreen(light: Light): number {
  let steps = 0;
  let current = light;
  while (current !== "green") {
    current = nextLight(current);
    steps++;
  }
  return steps;
}

function typeTests() {
  const ok: Light = "amber";
  // @ts-expect-error
  const typo: Light = "gren";
  // @ts-expect-error
  nextLight("blue");
}

console.log(nextLight("red")); // green
```

Раз `switch` покрывает все члены объединения, TypeScript знает, что функция всегда что-то возвращает, и `default` не нужен (добавьте четвёртый цвет — и компилятор сообщит о недостающем `return`). Подошёл бы и `enum Light { Red, Amber, Green }`, но литеральное объединение не создаёт лишнего объекта во время выполнения и позволяет передавать обычные строки вроде `"red"`.

</Solution>
