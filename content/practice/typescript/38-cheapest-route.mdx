Red pandas travel between bamboo groves along one-way paths, and every path takes a number of minutes. Write `shortestPath(graph, from, to)`, which finds the quickest route.

The graph is an object from each node's name to its outgoing edges, `{ [neighbour]: minutes }`:

```ts
const forest = {
  den: { river: 4, meadow: 1 },
  meadow: { river: 2, hill: 7 },
  river: { hill: 3 },
  hill: {},
};
shortestPath(forest, "den", "hill");
// { distance: 6, path: ["den", "meadow", "river", "hill"] }
```

- Return `{ distance, path }` for a shortest route: `distance` is the total weight and `path` lists the nodes from `from` to `to`. If several routes are equally short, return any one of them.
- If `from` and `to` are the same node, return `{ distance: 0, path: [from] }`. If `to` can't be reached, return `null`.
- Weights can be `0` but not negative: if any edge in the graph has a negative weight, throw a `RangeError` with the message `"Negative edge weight: a -> b"`.
- It must be fast: use **Dijkstra's algorithm** with a binary heap as the priority queue, so a graph with 20,000 nodes takes milliseconds, not seconds.

The types check the names: edges may only point at nodes of the graph, `from` and `to` must be nodes of the graph, and `path` is typed with the node names.

Make `shortestPath` generic and implement Dijkstra's algorithm with a binary heap. The `Expect<Equal<…>>` line and the `@ts-expect-error` lines are type tests; the second kind passes only when that line **is** an error.

<Hint>

**Types:** `function shortestPath<N extends string>(graph: Record<N, Partial<Record<NoInfer<N>, number>>>, from: NoInfer<N>, to: NoInfer<N>)`. `N` is inferred from the graph's keys only; `NoInfer` makes TypeScript **check** the edge targets and the two names against it instead of widening `N` to include them.

</Hint>

<Hint>

**Algorithm:** keep `dist` (best known distance per node) and `prev` (the node you came from) in `Map`s, and a min-heap of `[distance, node]` pairs. Pop the closest node; skip it if it was already finished; stop when it's `to`. For each edge, if `d + weight` beats `dist.get(next)`, update both maps and push `[d + weight, next]`. Rebuild the path by following `prev` back from `to` (push, then reverse once). The heap is an array where the children of `i` are `2i + 1` and `2i + 2`: push = add at the end and swap upwards; pop = move the last item to the top and swap downwards.

</Hint>

<Solution>

```ts
// ===== Type-test helpers: don't change =====
type Expect<T extends true> = T;
type Equal<A, B> =
  (<X>() => X extends A ? 1 : 2) extends
  (<X>() => X extends B ? 1 : 2) ? true : false;

class MinHeap<T> {
  private items: [number, T][] = [];

  get size(): number {
    return this.items.length;
  }

  push(priority: number, value: T): void {
    const items = this.items;
    items.push([priority, value]);
    let i = items.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (items[parent][0] <= items[i][0]) break;
      [items[parent], items[i]] = [items[i], items[parent]];
      i = parent;
    }
  }

  pop(): [number, T] | undefined {
    const items = this.items;
    const top = items[0];
    const last = items.pop();
    if (items.length > 0 && last) {
      items[0] = last;
      let i = 0;
      while (true) {
        const left = 2 * i + 1;
        const right = left + 1;
        let min = i;
        if (left < items.length && items[left][0] < items[min][0]) {
          min = left;
        }
        if (right < items.length && items[right][0] < items[min][0]) {
          min = right;
        }
        if (min === i) break;
        [items[min], items[i]] = [items[i], items[min]];
        i = min;
      }
    }
    return top;
  }
}

function shortestPath<N extends string>(
  graph: Record<N, Partial<Record<NoInfer<N>, number>>>,
  from: NoInfer<N>,
  to: NoInfer<N>,
): { distance: number; path: N[] } | null {
  const edges = (node: N) =>
    Object.entries(graph[node] ?? {}) as [N, number][];
  for (const node of Object.keys(graph) as N[]) {
    for (const [next, weight] of edges(node)) {
      if (weight < 0) {
        throw new RangeError(
          "Negative edge weight: " + node + " -> " + next,
        );
      }
    }
  }
  const dist = new Map<N, number>([[from, 0]]);
  const prev = new Map<N, N>();
  const done = new Set<N>();
  const heap = new MinHeap<N>();
  heap.push(0, from);
  while (heap.size > 0) {
    const [d, node] = heap.pop()!;
    if (done.has(node)) continue;
    done.add(node);
    if (node === to) break;
    for (const [next, weight] of edges(node)) {
      const candidate = d + weight;
      if (candidate < (dist.get(next) ?? Infinity)) {
        dist.set(next, candidate);
        prev.set(next, node);
        heap.push(candidate, next);
      }
    }
  }
  if (!done.has(to)) return null;
  const path: N[] = [to];
  while (path[path.length - 1] !== from) {
    path.push(prev.get(path[path.length - 1])!);
  }
  return { distance: dist.get(to)!, path: path.reverse() };
}
```

Dijkstra's algorithm always finishes the closest unfinished node next, and with non-negative weights that node's distance can't improve later, which is why negative weights are rejected up front. The heap makes "closest next" cost O(log n), for O((V + E) log V) overall instead of O(V²) for scanning every node each time; stale heap entries are simply skipped when popped.
