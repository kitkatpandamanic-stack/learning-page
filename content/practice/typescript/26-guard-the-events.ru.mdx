Игра присылает журнал ввода в виде JSON-текста. Большинство записей в порядке, но некоторые сломаны, а `JSON.parse` отдаёт `any`, который TypeScript за вас не проверит. Считайте данные `unknown` и **докажите** форму каждой записи, прежде чем её использовать.

```ts
type AppEvent =
  | { type: "click"; x: number; y: number }
  | { type: "key"; key: string; shift: boolean }
  | { type: "scroll"; delta: number };
```

Напишите три функции:

- `isAppEvent(value: unknown): value is AppEvent`: `true` только для объекта (не `null` и не массива), у которого `type` — один из трёх, и все поля этого вида есть и имеют правильный тип. Числа должны быть конечными (`Number.isFinite`). Лишние поля разрешены.
- `parseEvents(json: string)` возвращает `{ events, skipped }`: корректные записи в исходном порядке и количество пропущенных. Если текст — не корректный JSON или не JSON-массив, верните `null`.
- `countByType(events: AppEvent[])` возвращает счётчики `{ click, key, scroll }`, причём все три ключа есть всегда. Её возвращаемый тип должен быть `Record<AppEvent["type"], number>`.

```ts
parseEvents('[{"type":"click","x":1,"y":2},{"type":"key","key":"a"},7]');
// { events: [ { type: 'click', x: 1, y: 2 } ], skipped: 2 }
parseEvents("not json");  // null
parseEvents('{"type":"scroll","delta":3}'); // null: не массив
countByType([{ type: "scroll", delta: -40 }]);
// { click: 0, key: 0, scroll: 1 }
```

<Solution>

```ts
type AppEvent =
  | { type: "click"; x: number; y: number }
  | { type: "key"; key: string; shift: boolean }
  | { type: "scroll"; delta: number };

const isNumber = (v: unknown): v is number =>
  typeof v === "number" && Number.isFinite(v);

function isAppEvent(value: unknown): value is AppEvent {
  if (typeof value !== "object" || value === null) return false;
  if (Array.isArray(value)) return false;
  const v = value as Record<string, unknown>;
  switch (v.type) {
    case "click":
      return isNumber(v.x) && isNumber(v.y);
    case "key":
      return typeof v.key === "string" && typeof v.shift === "boolean";
    case "scroll":
      return isNumber(v.delta);
    default:
      return false;
  }
}

function parseEvents(
  json: string,
): { events: AppEvent[]; skipped: number } | null {
  let data: unknown;
  try {
    data = JSON.parse(json);
  } catch {
    return null;
  }
  if (!Array.isArray(data)) return null;
  const events = data.filter(isAppEvent);
  return { events, skipped: data.length - events.length };
}

function countByType(
  events: AppEvent[],
): Record<AppEvent["type"], number> {
  const counts = { click: 0, key: 0, scroll: 0 };
  for (const event of events) counts[event.type]++;
  return counts;
}

// ===== Тесты типов: не меняйте их =====
function typeTests(input: unknown) {
  if (isAppEvent(input)) {
    const kind: "click" | "key" | "scroll" = input.type;
    if (input.type === "click") {
      const x: number = input.x;
    }
  }
  const counts = countByType([]);
  const clicks: number = counts.click;
  // @ts-expect-error: события "drag" нет
  counts.drag;
}

console.log(parseEvents('[{"type":"scroll","delta":3},"oops"]'));
```

Возвращаемый тип защитника `value is AppEvent` сообщает TypeScript, что именно доказывает результат `true`, а передача такого защитника в `filter` одним шагом превращает `any[]` в `AppEvent[]`. `Record<AppEvent["type"], number>` берёт ключи из объединения, поэтому при добавлении четвёртого вида событий `countByType` перестанет компилироваться, пока его счётчики не включат новый вид. Разбор работает за O(n) от числа записей.

</Solution>
