Instead of throwing, a function can **return** its failure. The usual shape is a generic discriminated union:

```ts
type Result<T> =
  | { ok: true; value: T }
  | { ok: false; error: string };
```

A success carries a `value`, a failure carries an `error` message, and TypeScript only lets you read `value` after checking `ok`. The starter uses a loose interface with two optional fields instead, which allows nonsense like `{ ok: true, error: "?" }` and makes every `value` possibly `undefined`. Replace it with the union above, then write:

1. `parseAge(text: string): Result<number>`. Trim the text first. It must be digits only (no sign, no decimal point): otherwise fail with the error `"not a number"`. A number above 150 fails with `"too old"`. Anything else succeeds with the number.
2. `collectResults<T>(results: readonly Result<T>[]): Result<T[]>`. If every result succeeded, return a success with all the values in order. Otherwise return the **first** failure's error. No results is a success with an empty array.

```ts
parseAge(" 42 ");   // { ok: true, value: 42 }
parseAge("4.5");    // { ok: false, error: "not a number" }
parseAge("200");    // { ok: false, error: "too old" }
collectResults([parseAge("3"), parseAge("7")]);   // { ok: true, value: [3, 7] }
collectResults([parseAge("3"), parseAge("x"), parseAge("999")]);
// { ok: false, error: "not a number" }
```

<Solution>

```ts
type Result<T> =
  | { ok: true; value: T }
  | { ok: false; error: string };

function parseAge(text: string): Result<number> {
  const trimmed = text.trim();
  if (!/^\d+$/.test(trimmed)) {
    return { ok: false, error: "not a number" };
  }
  const age = Number(trimmed);
  if (age > 150) return { ok: false, error: "too old" };
  return { ok: true, value: age };
}

function collectResults<T>(results: readonly Result<T>[]): Result<T[]> {
  const values: T[] = [];
  for (const r of results) {
    if (!r.ok) return { ok: false, error: r.error };
    values.push(r.value);
  }
  return { ok: true, value: values };
}

function typeTests() {
  const r = parseAge("3");
  if (r.ok) {
    const age: number = r.value;
  } else {
    const message: string = r.error;
  }
  // @ts-expect-error: check ok before reading the value
  const unchecked: number = r.value;
  // @ts-expect-error: a success can't have an error instead of a value
  const bad: Result<number> = { ok: true, error: "?" };
}

console.log(parseAge(" 42 ")); // { ok: true, value: 42 }
```

With the union, checking `r.ok` narrows `r` to exactly one member, so `r.value` is a plain `T` after `if (r.ok)` and `r.error` is a `string` in the other branch. Failures become part of the function's type, which callers can't forget to handle the way they can forget a `try`/`catch`. `collectResults` is a single O(n) pass that stops at the first failure.

</Solution>
