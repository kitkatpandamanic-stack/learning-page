The panda leaderboard sorts by score (highest first), then by name for ties. Write `sortBy(items, ...keys)`, a reusable multi-key sort whose types reject keys that make no sense.

A **sort key** is either a property name (ascending) or `{ key, order }` with `order` `"asc"` or `"desc"`:

```ts
type Sortable = string | number | null | undefined;
type SortKey<T> = SortableKey<T> | { key: SortableKey<T>; order: "asc" | "desc" };
```

`SortableKey<T>` is the union of `T`'s keys whose values are `Sortable` (so `string[]` or object properties can't be used). Rules:

- Items are compared by the first key; only when those values are equal, by the second key, and so on.
- Numbers and strings compare with `<` and `>` (so `"B"` comes before `"a"`).
- `null` and `undefined` values always go **last**, in both orders.
- Items that are equal on every key keep their original order (a stable sort).
- `sortBy` returns a **new** array and never changes `items`. With no keys, it returns a copy in the original order.

```ts
const pandas = [
  { name: "Mei", score: 40, nickname: "Ace" },
  { name: "Bo", score: 55 },
  { name: "Lin", score: 40, nickname: "Lulu" },
];
sortBy(pandas, { key: "score", order: "desc" }, "name").map((p) => p.name);
// ["Bo", "Lin", "Mei"]
sortBy(pandas, "nickname").map((p) => p.name);
// ["Mei", "Lin", "Bo"]: Bo has no nickname, so he goes last
```

Write `SortableKey<T>` and a generic `sortBy` that follows the rules. The `@ts-expect-error` lines are type tests: they pass only when that line **is** an error.

<Hint>

Filter keys by their value type with a mapped type, then index it: `{ [K in keyof T]-?: T[K] extends Sortable ? K : never }[keyof T]`. The `-?` matters for optional properties like `nickname`. The function is `function sortBy<T>(items: readonly T[], ...keys: SortKey<T>[]): T[]`.

</Hint>

<Hint>

Turn every key into `{ key, order }` first (a string key is `typeof k === "object" ? k : { key: k, order: "asc" }`). Then `[...items].sort((a, b) => …)`: for each key, compare `a[key]` and `b[key]`; handle `== null` first (missing goes last, before `order` is applied), then return `-1` / `1` (flipped for `"desc"`) or move on to the next key when equal. Return `0` at the end; JavaScript's sort is stable.

</Hint>

<Solution>

```ts
type Sortable = string | number | null | undefined;

type SortableKey<T> = {
  [K in keyof T]-?: T[K] extends Sortable ? K : never;
}[keyof T];

type SortKey<T> =
  | SortableKey<T>
  | { key: SortableKey<T>; order: "asc" | "desc" };

function sortBy<T>(items: readonly T[], ...keys: SortKey<T>[]): T[] {
  const rules = keys.map((k) =>
    typeof k === "object" ? k : { key: k, order: "asc" as const },
  );
  return [...items].sort((a, b) => {
    for (const { key, order } of rules) {
      const x = a[key] as Sortable;
      const y = b[key] as Sortable;
      if (x == null && y == null) continue;
      if (x == null) return 1; // missing values always last
      if (y == null) return -1;
      if (x === y) continue;
      const result = x < y ? -1 : 1;
      return order === "desc" ? -result : result;
    }
    return 0;
  });
}

  name: string;
  score: number;
  nickname?: string;
  friends: string[];
};

```

The mapped type keeps a key `K` only when `T[K]` is sortable and turns the others into `never`, which disappears from the final union. The comparator walks the keys in order and returns at the first difference, placing missing values last before applying the direction. Sorting a copy costs O(n log n · k) for k keys, and `Array.prototype.sort` is stable, so full ties keep their order.
