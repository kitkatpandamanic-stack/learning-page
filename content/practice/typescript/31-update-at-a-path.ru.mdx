Состояние приложения часто хранится во вложенном объекте, который нельзя менять на месте: вместо этого строится новый объект, в котором копируются только ветки на пути к изменению, а всё остальное **разделяется** со старым (так React и Redux дёшево замечают изменения). Напишите для этого типизированные `setIn` и `updateIn`.

Сначала типы. Для объекта состояния `T`:

- `Path<T>` — объединение **всех** путей через точку внутрь `T`: свойства-объекты дают и собственный путь, и пути внутри себя. Массивы и прочие не-простые значения — листья (путей внутрь них нет). Для `{ user: { name: string; tags: string[] }; count: number }` это `"user" | "user.name" | "user.tags" | "count"`.
- `PathValue<T, P>` — тип по пути `P` (`PathValue<State, "user">` — это весь тип объекта `user`).

Теперь функции. Все объекты на пути существуют (в середине нет необязательных объектов):

- `setIn(obj, path, value)` возвращает новый объект с `value` по пути `path`. Каждый объект на пути к изменению копируется (через spread); каждая другая ветка — **тот же самый** объект, что и раньше. `obj` никогда не меняется. Если по пути `path` уже лежит `value` (по `Object.is`), верните сам `obj`.
- `updateIn(obj, path, fn)` — это `setIn` с новым значением `fn(oldValue)`.

```ts
const state = {
  user: { name: "Mei", prefs: { theme: "light", size: 14 } },
  tags: ["new"],
};
const next = setIn(state, "user.prefs.theme", "dark");
next.user.prefs.theme;          // "dark"
state.user.prefs.theme;         // "light": не изменилось
next.tags === state.tags;       // true: общий
next.user === state.user;       // false: скопирован по пути
setIn(state, "user.name", "Mei") === state; // true: ничего не изменилось
updateIn(state, "user.prefs.size", (n) => n + 2).user.prefs.size; // 16
```

<Hint>

`Path` проходит по строковым ключам и превращает результат в объединение через `{ [K in keyof T & string]: … }[keyof T & string]`. Для каждого ключа: массив даёт просто `K`; объект даёт `K` плюс шаблонный литерал из `K`, точки и `Path<T[K]>`; всё остальное даёт `K`. Проверяйте массивы **до** `object`, потому что массивы — тоже объекты. `PathValue` проверяет, похож ли `P` на `Head.Rest` (два `infer` в шаблонном литерале), и спускается в `T[Head]`, а иначе это `T[P]`. Во время выполнения разбейте путь и спускайтесь рекурсивно с помощником, работающим с `unknown`: `setAt(obj, keys, value)` берёт первый ключ, вычисляет нового потомка (само значение для последнего ключа, иначе `setAt(child, rest, value)`), возвращает `obj` без изменений, если `Object.is(oldChild, newChild)`, а иначе — `{ ...obj, [key]: newChild }`. `updateIn` читает старое значение, проходя по ключам, а затем вызывает `setIn`. Приведите тип один раз на границе (`as T`).

</Hint>

```ts
// ===== Помощники для тестов типов: не меняйте =====
type Expect<T extends true> = T;
type Equal<A, B> =
  (<X>() => X extends A ? 1 : 2) extends
  (<X>() => X extends B ? 1 : 2) ? true : false;

type Path<T> = {
  [K in keyof T & string]: T[K] extends readonly unknown[]
    ? K
    : T[K] extends object
      ? K | `${K}.${Path<T[K]>}`
      : K;
}[keyof T & string];

type PathValue<T, P extends string> =
  P extends `${infer Head}.${infer Rest}`
    ? Head extends keyof T
      ? PathValue<T[Head], Rest>
      : never
    : P extends keyof T
      ? T[P]
      : never;

type Bag = Record<string, unknown>;

function setAt(obj: unknown, keys: string[], value: unknown): unknown {
  const [key, ...rest] = keys;
  const current = obj as Bag;
  const child =
    rest.length === 0 ? value : setAt(current[key], rest, value);
  if (Object.is(current[key], child)) return obj;
  return { ...current, [key]: child };
}

function getAt(obj: unknown, keys: string[]): unknown {
  let value = obj;
  for (const key of keys) value = (value as Bag)[key];
  return value;
}

function setIn<T, P extends Path<T>>(
  obj: T,
  path: P,
  value: PathValue<T, P>,
): T {
  return setAt(obj, path.split("."), value) as T;
}

function updateIn<T, P extends Path<T>>(
  obj: T,
  path: P,
  fn: (old: PathValue<T, P>) => PathValue<T, P>,
): T {
  const old = getAt(obj, path.split(".")) as PathValue<T, P>;
  return setIn(obj, path, fn(old));
}

// ===== Тесты типов: не меняйте их =====
type Theme = "light" | "dark";
type State = {
  user: { name: string; prefs: { theme: Theme; size: number } };
  tags: string[];
  count: number;
};

type cases = [
  Expect<Equal<
    Path<State>,
    | "user" | "user.name" | "user.prefs"
    | "user.prefs.theme" | "user.prefs.size" | "tags" | "count"
  >>,
  Expect<Equal<PathValue<State, "user.prefs.theme">, Theme>>,
  Expect<Equal<
    PathValue<State, "user.prefs">,
    { theme: Theme; size: number }
  >>,
];

function typeTests(state: State) {
  setIn(state, "user.prefs", { theme: "dark", size: 12 });
  updateIn(state, "count", (n) => n + 1);
  // @ts-expect-error: "blue" — не Theme
  setIn(state, "user.prefs.theme", "blue");
  // @ts-expect-error: user.age не существует
  setIn(state, "user.age", 3);
}

const state: State = {
  user: { name: "Mei", prefs: { theme: "light", size: 14 } },
  tags: ["new"],
  count: 0,
};
const next = setIn(state, "user.prefs.theme", "dark");
console.log(next.user.prefs, next.tags === state.tags);
```

`Path` рекурсивно проходит по типу и предлагает как собственный путь объекта, так и пути внутри него, а `PathValue` спускается по пути обратно к его типу, поэтому `setIn` принимает только подходящие значения. Во время выполнения рекурсия копирует только d объектов на пути глубины d (O(d) работы плюс spread каждого скопированного объекта) и возвращает старый объект везде, где ничего не изменилось, — поэтому правило «то же значение — тот же объект» получается само собой.

</Solution>
