In the panda shop, user IDs and order IDs are both strings, so `ordersOf(order.id, orders)` compiles happily and returns nothing. Give each ID its own **branded type**, so TypeScript tells them apart, and make validating constructors the only way to get one.

- `UserId` is a string branded `"UserId"`. `toUserId(raw)` trims `raw` and accepts `"u_"` followed by 3 to 12 lowercase letters or digits. It returns the trimmed string as a `UserId`, or throws an `Error` with the message `"Invalid user id: <raw>"` (the original `raw`).
- `OrderId` is a string branded `"OrderId"`. `toOrderId(raw)` trims `raw` and accepts `"ord-"` followed by exactly 6 digits, otherwise it throws `"Invalid order id: <raw>"`.
- `ordersOf(user, orders)` returns the IDs of the orders whose `owner` is `user`, biggest `total` first (orders with equal totals keep their original order). It must not change the `orders` array.

```ts
type Order = { id: OrderId; owner: UserId; total: number };

const mei = toUserId(" u_mei ");   // "u_mei"
toUserId("mei");                    // throws "Invalid user id: mei"
const big = toOrderId("ord-000042");
ordersOf(mei, [
  { id: toOrderId("ord-000001"), owner: mei, total: 5 },
  { id: big, owner: mei, total: 30 },
]);                                 // ["ord-000042", "ord-000001"]
```

A branded value is still a string at runtime and can be used anywhere a `string` is expected; the brand only exists for the type checker.

Brand the two ID types, write their smart constructors and `ordersOf`. The `@ts-expect-error` lines are type tests: they pass only when that line **is** an error.

<Hint>

A brand is an intersection with a property that no real string has: `type UserId = string & { readonly __brand: "UserId" };`. Plain strings don't have `__brand`, so they aren't assignable, and the two brands differ, so the IDs don't mix. The smart constructor is the one place that casts: `return id as UserId;`.

</Hint>

<Hint>

Regexes: `/^u_[a-z0-9]{3,12}$/` and `/^ord-\d{6}$/`, tested on `raw.trim()`. For `ordersOf`, `filter` makes a new array, then `sort((a, b) => b.total - a.total)` (JavaScript's sort is stable), then `map` to the IDs.

</Hint>

<Solution>

```ts
type UserId = string & { readonly __brand: "UserId" };
type OrderId = string & { readonly __brand: "OrderId" };

type Order = { id: OrderId; owner: UserId; total: number };

function toUserId(raw: string): UserId {
  const id = raw.trim();
  if (!/^u_[a-z0-9]{3,12}$/.test(id)) {
    throw new Error("Invalid user id: " + raw);
  }
  return id as UserId;
}

function toOrderId(raw: string): OrderId {
  const id = raw.trim();
  if (!/^ord-\d{6}$/.test(id)) {
    throw new Error("Invalid order id: " + raw);
  }
  return id as OrderId;
}

function ordersOf(user: UserId, orders: readonly Order[]): OrderId[] {
  return orders
    .filter((order) => order.owner === user)
    .sort((a, b) => b.total - a.total)
    .map((order) => order.id);
}

// ===== Type tests: don't change these =====
function typeTests(u: UserId, o: OrderId, orders: Order[]) {
  ordersOf(u, orders);
  const text: string = u; // a UserId is still a string
  // @ts-expect-error: an OrderId is not a UserId
  ordersOf(o, orders);
  // @ts-expect-error: a plain string is not a UserId
  ordersOf("u_mei", orders);
  // @ts-expect-error: an ID can't be made without its constructor
  const fake: OrderId = "ord-123456";
  return [text, fake];
}

const mei = toUserId(" u_mei ");
console.log(ordersOf(mei, [
  { id: toOrderId("ord-000001"), owner: mei, total: 5 },
  { id: toOrderId("ord-000042"), owner: mei, total: 30 },
]));
```

TypeScript compares types by shape, so two plain `string` aliases are interchangeable. Intersecting with a different `__brand` property makes the shapes differ without changing anything at runtime, and the `as` casts live only in the constructors, right after validation. `ordersOf` is O(n log n) because of the sort, and `filter` makes the copy that keeps the input untouched.

</Solution>
