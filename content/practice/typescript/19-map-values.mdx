Arrays have `map`, objects don't. Write `mapValues(obj, fn)` that returns a **new** object with the same keys as `obj`, where each value is `fn(value, key)`.

- Keys stay in their original order.
- `fn` receives the value **and** its key.
- The original object is not changed. An empty object gives `{}`.

```ts
const prices = { tea: 2, cake: 3.5 };
mapValues(prices, (p) => p * 2);                 // { tea: 4, cake: 7 }
mapValues(prices, (p, key) => key + ": £" + p);  // { tea: "tea: £2", cake: "cake: £3.5" }
```

Types: the result must keep the **exact keys** of the input and take the value type from the callback. After `const labels = mapValues(prices, (p) => "£" + p)`:

- `labels.tea` is a `string`,
- `labels.coffee` is a compile error (there's no such key),
- inside the callback, `p` is a `number` and `key` is `"tea" | "cake"`.

Use three type parameters: `K extends string` for the keys, `V` for the input values and `R` for the callback's result, with `obj: Record<K, V>` and the return type `Record<K, R>`.

Make `mapValues` generic so the type tests pass, and build the new object. The `@ts-expect-error` lines pass only when that line **is** an error.

<Hint>

The signature is `function mapValues<K extends string, V, R>(obj: Record<K, V>, fn: (value: V, key: K) => R): Record<K, R>`. Start the result as `{} as Record<K, R>` (it fills up in the loop), and loop over `Object.keys(obj) as K[]`: `Object.keys` always returns `string[]`, so you have to tell TypeScript these strings are the object's keys.

</Hint>

<Solution>

```ts
function mapValues<K extends string, V, R>(
  obj: Record<K, V>,
  fn: (value: V, key: K) => R,
): Record<K, R> {
  const result = {} as Record<K, R>;
  for (const key of Object.keys(obj) as K[]) {
    result[key] = fn(obj[key], key);
  }
  return result;
}

function typeTests() {
  const prices = { tea: 2, cake: 3.5 };
  const labels = mapValues(prices, (p) => "£" + p.toFixed(2));
  const tea: string = labels.tea;
  // @ts-expect-error: there's no coffee
  labels.coffee;
  // @ts-expect-error: the values are strings now
  const cake: number = labels.cake;
  // @ts-expect-error: prices are numbers, they have no toUpperCase
  mapValues(prices, (p) => p.toUpperCase());
}

console.log(mapValues({ tea: 2, cake: 3.5 }, (p) => p * 2)); // { tea: 4, cake: 7 }
```

Matching `{ tea: 2, cake: 3.5 }` against `Record<K, V>` lets TypeScript infer `K = "tea" | "cake"` and `V = number`, and `R` comes from whatever the callback returns. The two `as` casts are the honest gaps: an empty object isn't a full `Record<K, R>` yet, and `Object.keys` can't promise there are no extra keys at runtime. One pass makes it O(n).

</Solution>
