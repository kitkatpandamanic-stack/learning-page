The panda café stacks plates, the browser stacks pages for its Back button, and an editor stacks undo steps. One generic class can do all three. Write a class `Stack<T>`:

- `push(...items: T[])` puts the items on top, **in order** (the last one ends up on top), and returns the new size.
- `pop()` removes and returns the top item, or `undefined` if the stack is empty.
- `peek()` returns the top item without removing it, or `undefined` if the stack is empty.
- A getter `size` gives the number of items.
- `toArray()` returns a copy of the items from bottom to top (changing the copy doesn't change the stack).
- `static from<U>(items: Iterable<U>): Stack<U>` builds a stack from any iterable (an array, a `Set`, a string…), first item at the bottom.

The items live in a `private` array, so code outside the class can't reach in. The starter uses `any` everywhere: the `@ts-expect-error` lines are type tests, and they pass only when that line **is** an error. With a proper `T`, pushing a string onto a `Stack<number>` is an error, and so is treating `pop()` as if it always returned a value.

```ts
const plates = new Stack<string>();
plates.push("blue", "green"); // 2
plates.peek();                // "green"
plates.pop();                 // "green"
plates.size;                  // 1

const letters = Stack.from("abc"); // Stack<string>
letters.toArray();                 // ["a", "b", "c"]
new Stack<number>().pop();         // undefined
```

Make `Stack` generic and fill in its methods so the type tests and the checks pass.

<Hint>

Write `class Stack<T>` and use `T` wherever the starter says `any`. The array becomes `private items: T[] = [];`. The static method has its own type parameter, because a static member can't use the class's `T`: `static from<U>(items: Iterable<U>): Stack<U>`.

</Hint>

<Hint>

`Array.from(items)` turns any iterable into an array, and `this.items.at(-1)` reads the last item (or `undefined`). Use `.length`, not truthiness, so a `0` on the stack still counts.

</Hint>

<Solution>

```ts
class Stack<T> {
  private items: T[] = [];

  push(...items: T[]): number {
    this.items.push(...items);
    return this.items.length;
  }

  pop(): T | undefined {
    return this.items.pop();
  }

  peek(): T | undefined {
    return this.items.at(-1);
  }

  get size(): number {
    return this.items.length;
  }

  toArray(): T[] {
    return [...this.items];
  }

  static from<U>(items: Iterable<U>): Stack<U> {
    const stack = new Stack<U>();
    stack.push(...Array.from(items));
    return stack;
  }
}

// ===== Type tests: don't change these =====
function typeTests() {
  const nums = Stack.from([1, 2, 3]);
  const top: number | undefined = nums.pop();
  // @ts-expect-error: a Stack<number> only takes numbers
  nums.push("4");
  // @ts-expect-error: pop() can return undefined
  const sure: number = nums.pop();
  // @ts-expect-error: the items are private
  nums.items;
  return [top, sure];
}

const plates = new Stack<string>();
plates.push("blue", "green");
console.log(plates.pop(), plates.size); // green 1
```

The class's type parameter `T` ties every method together: whatever type you push is the type `pop` and `peek` hand back (plus `undefined` for an empty stack). A static method belongs to the class itself, not to one `Stack<T>`, so `from` declares its own `U` and TypeScript infers it from the argument. Every operation is O(1) except `toArray` and `from`, which are O(n).

</Solution>
