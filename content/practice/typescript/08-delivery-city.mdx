The bamboo delivery service stores customers like this. Not every customer has given an address, and an address may be missing its city or postcode:

```ts
interface Customer {
  name: string;
  address?: {
    city?: string;
    postcode?: string;
  };
}
```

Write two functions:

- `deliveryCity(customer)` returns the customer's city, or `"Unknown"` if there is no address or no city. An empty string `""` counts as a real (if unhelpful) city and is returned as it is.
- `label(customer)` returns `"<name>, <city>, <postcode>"`, using `"Unknown"` for a missing city and `"no postcode"` for a missing postcode.

The starter reads `customer.address.city` directly. TypeScript rejects it with "'customer.address' is possibly 'undefined'.", and rightly so: it would crash for a customer with no address.

```ts
deliveryCity({ name: "Mei", address: { city: "Chengdu" } }); // "Chengdu"
deliveryCity({ name: "Bao" });                                // "Unknown"
label({ name: "Bao", address: { postcode: "EH12" } });        // "Bao, Unknown, EH12"
```

    { name: "No address gives Unknown", check: "deliveryCity({ name: 'Bao' }) === 'Unknown'" },
    { name: "Address without city gives Unknown", check: "deliveryCity({ name: 'Lin', address: { postcode: 'EH12' } }) === 'Unknown'" },
    { name: "An empty city is kept", check: "deliveryCity({ name: 'Su', address: { city: '' } }) === ''" },
    { name: "Label with everything", check: "label({ name: 'Mei', address: { city: 'Chengdu', postcode: '610000' } }) === 'Mei, Chengdu, 610000'" },
    { name: "Label fills in the gaps", check: "label({ name: 'Bao', address: { postcode: 'EH12' } }) === 'Bao, Unknown, EH12' && label({ name: 'Lin' }) === 'Lin, Unknown, no postcode'" },
  ]}
>

Fix `deliveryCity` and write `label` so they handle every missing piece.

<Hint>

`customer.address?.city` stops and gives `undefined` when `address` is missing. Then `?? "Unknown"` replaces only `null`/`undefined`, so an empty string survives (`||` would replace it too).

</Hint>

<Solution>

```ts
interface Customer {
  name: string;
  address?: {
    city?: string;
    postcode?: string;
  };
}

function deliveryCity(customer: Customer): string {
  return customer.address?.city ?? "Unknown";
}

function label(customer: Customer): string {
  const postcode = customer.address?.postcode ?? "no postcode";
  return `${customer.name}, ${deliveryCity(customer)}, ${postcode}`;
}

console.log(deliveryCity({ name: "Bao" })); // Unknown
```

`?.` turns "crash on a missing object" into "give `undefined`", and TypeScript tracks that: the type of `customer.address?.city` is `string | undefined`. `?? "Unknown"` removes the `undefined`, which is why the function can promise to return a plain `string`.

</Solution>

</Exercise>
