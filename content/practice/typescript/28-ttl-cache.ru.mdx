Виджет погоды не должен каждую секунду заново спрашивать сервер, но и вчерашний прогноз показывать тоже не должен. Напишите дженерик-класс `TtlCache<K, V>`, записи которого истекают по прошествии **времени жизни** (time to live, TTL).

Часы **внедряются** снаружи: конструктор принимает `now` — функцию, возвращающую текущее время в миллисекундах (по умолчанию `Date.now`), поэтому тесты могут двигать время вручную.

- `new TtlCache<K, V>(defaultTtlMs, now?)`. TTL, который не больше 0, выбрасывает `RangeError` (и здесь, и в `set`).
- `set(key, value, ttlMs?)` хранит значение до `now() + ttl` (`ttlMs` заменяет TTL по умолчанию для этой записи) и возвращает сам кэш, чтобы вызовы можно было объединять в цепочку. Повторный `set` того же ключа заменяет значение и перезапускает его таймер.
- Запись, сохранённая в момент `t` с TTL `d`, **истекает**, как только `now() >= t + d`. Истёкшие записи ведут себя так, будто их никогда не было, и удаляются, когда их находят.
- `get(key)` возвращает значение или `undefined`, если записи нет или она истекла. `has(key)` возвращает логическое значение.
- `getOrSet(key, make)` возвращает свежее значение, если оно есть; иначе вызывает `make()`, сохраняет результат с TTL по умолчанию и возвращает его.
- `prune()` удаляет все истёкшие записи и возвращает, сколько удалено. Геттер `size` возвращает число **не** истёкших записей.

```ts
let time = 0;
const forecasts = new TtlCache<string, string>(1000, () => time);
forecasts.set("Paris", "sunny").set("Oslo", "snow", 5000);
time = 999;  forecasts.get("Paris"); // "sunny"
time = 1000; forecasts.get("Paris"); // undefined: истекло
forecasts.size;                      // 1 (только Oslo)
```

<Solution>

```ts
type Entry<V> = { value: V; expiresAt: number };

function checkTtl(ttl: number): number {
  if (!(ttl > 0)) throw new RangeError("TTL must be positive");
  return ttl;
}

class TtlCache<K, V> {
  private entries = new Map<K, Entry<V>>();
  private readonly defaultTtlMs: number;
  private readonly now: () => number;

  constructor(defaultTtlMs: number, now: () => number = Date.now) {
    this.defaultTtlMs = checkTtl(defaultTtlMs);
    this.now = now;
  }

  set(key: K, value: V, ttlMs = this.defaultTtlMs): this {
    const expiresAt = this.now() + checkTtl(ttlMs);
    this.entries.set(key, { value, expiresAt });
    return this;
  }

  get(key: K): V | undefined {
    return this.fresh(key)?.value;
  }

  has(key: K): boolean {
    return this.fresh(key) !== undefined;
  }

  getOrSet(key: K, make: () => V): V {
    const entry = this.fresh(key);
    if (entry) return entry.value;
    const value = make();
    this.set(key, value);
    return value;
  }

  prune(): number {
    let removed = 0;
    for (const key of [...this.entries.keys()]) {
      if (!this.fresh(key)) removed++;
    }
    return removed;
  }

  get size(): number {
    this.prune();
    return this.entries.size;
  }

  private fresh(key: K): Entry<V> | undefined {
    const entry = this.entries.get(key);
    if (!entry) return undefined;
    if (this.now() < entry.expiresAt) return entry;
    this.entries.delete(key);
    return undefined;
  }
}

// ===== Тесты типов: не меняйте их =====
function typeTests() {
  const cache = new TtlCache<string, number>(1000);
  cache.set("a", 1).set("b", 2);
  const maybe: number | undefined = cache.get("a");
  // @ts-expect-error: значения — числа
  cache.set("c", "3");
  // @ts-expect-error: get может ничего не найти
  const sure: number = cache.get("a");
  // @ts-expect-error: ключи — строки
  cache.has(1);
  return [maybe, sure];
}

let time = 0;
const forecasts = new TtlCache<string, string>(1000, () => time);
forecasts.set("Paris", "sunny").set("Oslo", "snow", 5000);
time = 1000;
console.log(forecasts.get("Paris"), forecasts.size); // undefined 1
```

Каждая запись помнит, когда истекает, а один приватный помощник решает, свежая ли она, и лениво удаляет устаревшие, поэтому `get`, `has` и `getOrSet` работают за O(1). `prune` и `size` обходят все записи — O(n). Часы, переданные аргументом конструктора, убирают `Date.now` из логики, и именно это делает тайминги тестируемыми.
