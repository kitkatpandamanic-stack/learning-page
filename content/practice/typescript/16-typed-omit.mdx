Before the zoo's API sends a keeper's record to the browser, it removes private fields like `password`. Write a generic helper `omit(obj, keys)` that returns a **shallow copy** of `obj` without the listed keys.

Runtime rules:

- The original object is not changed, and the result is a new object even when `keys` is empty.
- Every other property is copied in its original order, with the same values (nested objects are shared, not cloned).
- Naming the same key twice is fine.

Type rules (this is where the work is):

- `keys` may only contain keys of `obj`: `omit(keeper, ["emial"])` is a compile error.
- The return type is `Omit<T, K>`, so a removed property no longer exists on the result: `safe.password` is a compile error, while `safe.name` is still a `string`.

```ts
const keeper = { id: 7, name: "Mei", password: "bamboo123" };
const safe = omit(keeper, ["password"]);   // { id: 7, name: "Mei" }
safe.password;                             // ❌ compile error
omit(keeper, ["id", "password"]);          // { name: "Mei" }
```

<Hint>

TypeScript already has an `Omit` utility type for the result. What you need is a way to say "the keys must be real property names of `obj`", which is what `keyof` is for.

</Hint>

<Hint>

The signature is `function omit<T extends object, K extends keyof T>(obj: T, keys: readonly K[]): Omit<T, K>`. Because `K` is inferred as the literal `"password"`, the result type drops exactly that property. For the body, make a shallow copy with `{ ...obj }`, `delete` each key from the copy (not from `obj`), and return the copy. Repeated keys are harmless.

</Hint>

<Hint>

```ts
function omit<T extends object, K extends keyof T>(
  obj: T,
  keys: readonly K[],
): Omit<T, K> {
  const copy = { ...obj };
  // remove every key in keys from the copy
  return copy;

```

<Solution>

```ts
function omit<T extends object, K extends keyof T>(
  obj: T,
  keys: readonly K[],
): Omit<T, K> {
  const copy = { ...obj };
  for (const key of keys) {
    delete copy[key];
  }
  return copy;
}

function typeTests() {
  const keeper = { id: 7, name: "Mei", password: "bamboo123" };
  const safe = omit(keeper, ["password"]);
  const name: string = safe.name;
  const id: number = safe.id;
  // @ts-expect-error: password was removed
  safe.password;
  // @ts-expect-error: not a key of keeper
  omit(keeper, ["emial"]);
}

console.log(omit({ id: 7, name: "Mei", password: "x" }, ["password"]));
```

`K extends keyof T` limits the keys to real property names, and because TypeScript infers `K` as the literal `"password"` (not just `string`), `Omit<T, K>` can drop exactly that property from the result type. Copying is O(number of properties); the spread makes sure `delete` never touches the caller's object.

</Solution>
