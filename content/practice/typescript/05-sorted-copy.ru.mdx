Таблица рекордов хранит очки в `readonly number[]`, чтобы никто случайно не изменил исходный список. А коду, который их показывает, нужны очки, **отсортированные от меньшего к большему**.

Напишите `sortedCopy(scores)`, которая возвращает **новый** массив (array) с очками по возрастанию чисел. Исходный массив должен остаться ровно таким, каким был.

В заготовке типы уже правильные, но в теле вызывается `scores.sort(...)`. TypeScript это отвергает: `sort` меняет массив на месте, поэтому у массива только для чтения такого метода нет. Исправьте тело функции, а не типы.

Осторожно, классическая ловушка JavaScript: `.sort()` без функции сравнения сортирует как **текст**, поэтому `[10, 9, 1]` превратился бы в `[1, 10, 9]`.

```ts
const scores: readonly number[] = [10, 9, 1];
sortedCopy(scores);   // [1, 9, 10]
scores;               // по-прежнему [10, 9, 1]
```

Верните отсортированную копию `scores`, не изменяя исходный массив.

<Hint>

Сначала скопируйте, потом сортируйте копию: `[...scores]` — обычный (изменяемый) `number[]`. Передайте `sort` функцию сравнения `(a, b) => a - b`, чтобы он сравнивал числа, а не текст.

</Hint>

<Solution>

```ts
function sortedCopy(scores: readonly number[]): number[] {
  return [...scores].sort((a, b) => a - b);
}

const scores: readonly number[] = [10, 9, 1];
console.log(sortedCopy(scores)); // [ 1, 9, 10 ]
```

`readonly number[]` прячет все изменяющие методы (`sort`, `push`, `splice`…), поэтому ошибка «отсортировал чужой массив на месте» ловится ещё при компиляции. Распаковка в новый массив даёт копию, которую менять можно. (В современных средах есть ещё `scores.toSorted((a, b) => a - b)` — он сам возвращает копию.)

</Solution>
