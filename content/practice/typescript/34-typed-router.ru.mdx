Веб-фреймворки читают `"/users/:id"` и передают вашему обработчику типизированный `params.id`. Напишите маленький роутер (router), который делает обе половины: **типы** берутся из строки-шаблона, а **сопоставление** выбирает для пути правильный маршрут (route).

Сначала тип. `Params<P>` превращает шаблон в объектный тип с одним свойством `string` для каждого сегмента `:name`:

```ts
Params<"/users/:id/posts/:postId"> // { id: string; postId: string }
Params<"/about">                   // {}
```

Затем класс `Router<R>`, где `R` — то, что возвращает каждый обработчик:

- `add(pattern, handler)` регистрирует маршрут и возвращает роутер (чтобы вызовы можно было объединять в цепочку). Обработчик получает `Params<typeof pattern>`.
- `handle(path)` находит лучший подходящий маршрут, вызывает его обработчик с параметрами и возвращает результат либо возвращает `undefined`, если ни один маршрут не подошёл.

Правила сопоставления:

- Разбивайте шаблоны и пути по `/` и игнорируйте пустые куски, так что `"/users/7/"`, `"users/7"` и `"//users//7"` — один и тот же путь. Всё, начиная с `?`, игнорируется.
- Маршрут подходит, если у него столько же сегментов, каждый статический сегмент совпадает (с учётом регистра), а каждый сегмент `:name` получает соответствующий кусок пути, декодированный через `decodeURIComponent`.
- Если подходят несколько маршрутов, сравнивайте их сегменты слева направо: на первой позиции, где у одного статический сегмент, а у другого параметр, побеждает статический. Если такого не случилось, побеждает маршрут, добавленный первым.

```ts
const router = new Router<string>()
  .add("/users/:id", (p) => "user " + p.id)
  .add("/users/me", () => "my profile")
  .add("/", () => "home");
router.handle("/users/42");      // "user 42"
router.handle("/users/me");      // "my profile": статический сегмент побеждает :id
router.handle("/users/mei%20li"); // "user mei li"
router.handle("/users");         // undefined
router.handle("/?tab=new");      // "home"
```

Напишите `Params` и дженерик `Router<R>`. Строки `Expect<Equal<…>>` и строки с `@ts-expect-error` — это тесты типов; вторые проходят, только когда в этой строке **есть** ошибка.

<Hint>

Сначала соберите имена, затем сопоставьте их. `ParamNames<P>` проверяет ``P extends `${infer Seg}/${infer Rest}` ``: если да, это `Name<Seg> | ParamNames<Rest>`, иначе `Name<P>`. `Name<S>` — это `N`, когда ``S extends `:${infer N}` ``, и `never` в остальных случаях. Затем `Params<P> = { [K in ParamNames<P>]: string }` — это `{}`, если имён нет. Метод: `add<P extends string>(pattern: P, handler: (params: Params<P>) => R): this`.

</Hint>

<Hint>

Храните каждый маршрут как список сегментов плюс обработчик (один раз приведите обработчик к `(params: Record<string, string>) => R`: TypeScript не может связать сохранённый обработчик с его собственным шаблоном). В `handle` перебирайте все маршруты; храните лучшее совпадение и заменяйте его, только если новое **более специфично**: на первом индексе, где ровно один из двух сегментов начинается с `:`, побеждает статический.

</Hint>

```ts
// ===== Помощники для тестов типов: не меняйте =====
type Expect<T extends true> = T;
type Equal<A, B> =
  (<X>() => X extends A ? 1 : 2) extends
  (<X>() => X extends B ? 1 : 2) ? true : false;

type Name<S extends string> = S extends `:${infer N}` ? N : never;
type ParamNames<P extends string> =
  P extends `${infer Seg}/${infer Rest}`
    ? Name<Seg> | ParamNames<Rest>
    : Name<P>;
type Params<P extends string> = { [K in ParamNames<P>]: string };

type Route<R> = {
  segments: string[];
  handler: (params: Record<string, string>) => R;
};

const split = (path: string) =>
  path.split("?")[0].split("/").filter((s) => s !== "");
const isParam = (segment: string) => segment.startsWith(":");

function matchRoute(
  segments: string[],
  parts: string[],
): Record<string, string> | null {
  if (segments.length !== parts.length) return null;
  const params: Record<string, string> = {};
  for (let i = 0; i < segments.length; i++) {
    if (isParam(segments[i])) {
      params[segments[i].slice(1)] = decodeURIComponent(parts[i]);
    } else if (segments[i] !== parts[i]) {
      return null;
    }
  }
  return params;
}

// Специфичнее ли a, чем b? (оба подошли к одному и тому же пути)
function moreSpecific(a: string[], b: string[]): boolean {
  for (let i = 0; i < a.length; i++) {
    if (isParam(a[i]) !== isParam(b[i])) return !isParam(a[i]);
  }
  return false;
}

class Router<R> {
  private routes: Route<R>[] = [];

  add<P extends string>(
    pattern: P,
    handler: (params: Params<P>) => R,
  ): this {
    this.routes.push({
      segments: split(pattern),
      handler: handler as (params: Record<string, string>) => R,
    });
    return this;
  }

  handle(path: string): R | undefined {
    const parts = split(path);
    let best: { route: Route<R>; params: Record<string, string> } | null =
      null;
    for (const route of this.routes) {
      const params = matchRoute(route.segments, parts);
      if (!params) continue;
      if (!best || moreSpecific(route.segments, best.route.segments)) {
        best = { route, params };
      }
    }
    return best ? best.route.handler(best.params) : undefined;
  }
}

// ===== Тесты типов: не меняйте их =====
type cases = [
  Expect<Equal<
    Params<"/users/:id/posts/:postId">,
    { id: string; postId: string }
  >>,
  Expect<Equal<Params<"/about/team">, {}>>,
  Expect<Equal<Params<":lang/docs">, { lang: string }>>,
];

function typeTests(router: Router<string>) {
  router.add("/users/:id", (p) => p.id.toUpperCase());
  // @ts-expect-error: у этого маршрута нет параметра "name"
  router.add("/users/:id", (p) => p.name);
  // @ts-expect-error: обработчики Router<string> возвращают строки
  router.add("/count", () => 42);
}

const router = new Router<string>()
  .add("/users/:id", (p) => "user " + p.id)
  .add("/users/me", () => "my profile");
console.log(router.handle("/users/42"), router.handle("/users/me"));
```

`ParamNames` проходит по шаблону по одному `/` за раз с помощью `infer`, оставляя только куски `:name`, а сопоставленный тип превращает это объединение в объект, поэтому каждый обработчик видит ровно свои параметры. Во время выполнения каждый маршрут проверяется один раз и сравнивается с лучшим на данный момент — O(маршруты × сегменты) на запрос. Настоящие роутеры строят дерево сегментов, чтобы пропускать большинство маршрутов, но правило специфичности там то же самое.

</Solution>
