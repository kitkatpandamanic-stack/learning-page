Прежде чем API зоопарка отправит запись о смотрителе в браузер, он удаляет приватные поля вроде `password`. Напишите дженерик-помощник `omit(obj, keys)`, который возвращает **поверхностную копию** `obj` без перечисленных ключей.

Правила во время выполнения:

- Исходный объект не меняется, а результат — новый объект, даже если `keys` пустой.
- Все остальные свойства копируются в исходном порядке и с теми же значениями (вложенные объекты общие, а не клонированные).
- Один и тот же ключ можно указать дважды.

Правила для типов (здесь и вся работа):

- В `keys` могут быть только ключи `obj`: `omit(keeper, ["emial"])` — ошибка компиляции.
- Возвращаемый тип — `Omit<T, K>`, поэтому удалённого свойства у результата больше нет: `safe.password` — ошибка компиляции, а `safe.name` по-прежнему `string`.

```ts
const keeper = { id: 7, name: "Mei", password: "bamboo123" };
const safe = omit(keeper, ["password"]);   // { id: 7, name: "Mei" }
safe.password;                             // ❌ ошибка компиляции
omit(keeper, ["id", "password"]);          // { name: "Mei" }
```

Типизируйте `omit`, чтобы тесты типов проходили, и верните копию. Строки с `@ts-expect-error` проходят, только если в этой строке **есть** ошибка.

<Hint>

Для результата в TypeScript уже есть служебный тип `Omit`. Нужно ещё сказать, что ключи должны быть настоящими именами свойств `obj`, — для этого есть `keyof`.

</Hint>

<Hint>

Сигнатура такая: `function omit<T extends object, K extends keyof T>(obj: T, keys: readonly K[]): Omit<T, K>`. Поскольку `K` выводится как литерал `"password"`, тип результата теряет ровно это свойство. В теле сделайте поверхностную копию через `{ ...obj }`, удалите каждый ключ оператором `delete` из копии (а не из `obj`) и верните копию. Повторяющиеся ключи ничему не мешают.

</Hint>

<Hint>

```ts
function omit<T extends object, K extends keyof T>(
  obj: T,
  keys: readonly K[],
): Omit<T, K> {
  const copy = { ...obj };
  // удалите из копии каждый ключ из keys
  return copy;
}
```

</Hint>

<Solution>

```ts
function omit<T extends object, K extends keyof T>(
  obj: T,
  keys: readonly K[],
): Omit<T, K> {
  const copy = { ...obj };
  for (const key of keys) {
    delete copy[key];
  }
  return copy;
}

function typeTests() {
  const keeper = { id: 7, name: "Mei", password: "bamboo123" };
  const safe = omit(keeper, ["password"]);
  const name: string = safe.name;
  const id: number = safe.id;
  // @ts-expect-error: password удалён
  safe.password;
  // @ts-expect-error: у keeper нет такого ключа
  omit(keeper, ["emial"]);
}

console.log(omit({ id: 7, name: "Mei", password: "x" }, ["password"]));
```

`K extends keyof T` ограничивает ключи настоящими именами свойств, а поскольку TypeScript выводит `K` как литерал `"password"` (а не просто `string`), `Omit<T, K>` может убрать из типа результата именно это свойство. Копирование занимает O(число свойств); spread гарантирует, что `delete` никогда не тронет объект вызывающего кода.

</Solution>
