Вместо того чтобы выбрасывать исключение (exception), функция может **вернуть** свою неудачу. Обычно для этого используют дженерик-размеченное объединение:

```ts
type Result<T> =
  | { ok: true; value: T }
  | { ok: false; error: string };
```

Успех несёт `value`, неудача — сообщение `error`, а TypeScript разрешает читать `value` только после проверки `ok`. В заготовке вместо этого свободный интерфейс с двумя необязательными полями: он допускает бессмыслицу вроде `{ ok: true, error: "?" }`, и любое `value` в нём может быть `undefined`. Замените его объединением выше, а затем напишите:

1. `parseAge(text: string): Result<number>`. Сначала обрежьте пробелы по краям. В тексте должны быть только цифры (без знака и без десятичной точки), иначе — неудача с ошибкой `"not a number"`. Число больше 150 — неудача с `"too old"`. Всё остальное — успех с этим числом.
2. `collectResults<T>(results: readonly Result<T>[]): Result<T[]>`. Если все результаты успешные, верните успех со всеми значениями по порядку. Иначе верните ошибку **первой** неудачи. Пустой список — успех с пустым массивом.

```ts
parseAge(" 42 ");   // { ok: true, value: 42 }
parseAge("4.5");    // { ok: false, error: "not a number" }
parseAge("200");    // { ok: false, error: "too old" }
collectResults([parseAge("3"), parseAge("7")]);   // { ok: true, value: [3, 7] }
collectResults([parseAge("3"), parseAge("x"), parseAge("999")]);
// { ok: false, error: "not a number" }
```

Сделайте `Result<T>` размеченным объединением и реализуйте обе функции. Строки с `@ts-expect-error` проходят, только если в этой строке **есть** ошибка.

<Hint>

`/^\d+$/.test(trimmed)` проверяет «только цифры» (и не проходит для пустой строки). В `collectResults` пройдите по результатам циклом: как только встретится неудача, верните её (`if (!r.ok) return { ok: false, error: r.error }`), иначе добавляйте `r.value` в массив, а после цикла верните успех.

</Hint>

<Solution>

```ts
type Result<T> =
  | { ok: true; value: T }
  | { ok: false; error: string };

function parseAge(text: string): Result<number> {
  const trimmed = text.trim();
  if (!/^\d+$/.test(trimmed)) {
    return { ok: false, error: "not a number" };
  }
  const age = Number(trimmed);
  if (age > 150) return { ok: false, error: "too old" };
  return { ok: true, value: age };
}

function collectResults<T>(results: readonly Result<T>[]): Result<T[]> {
  const values: T[] = [];
  for (const r of results) {
    if (!r.ok) return { ok: false, error: r.error };
    values.push(r.value);
  }
  return { ok: true, value: values };
}

function typeTests() {
  const r = parseAge("3");
  if (r.ok) {
    const age: number = r.value;
  } else {
    const message: string = r.error;
  }
  // @ts-expect-error: проверьте ok, прежде чем читать value
  const unchecked: number = r.value;
  // @ts-expect-error: у успеха не может быть error вместо value
  const bad: Result<number> = { ok: true, error: "?" };
}

console.log(parseAge(" 42 ")); // { ok: true, value: 42 }
```

С объединением проверка `r.ok` сужает `r` ровно до одного члена: после `if (r.ok)` у `r.value` тип просто `T`, а в другой ветке `r.error` — это `string`. Неудачи становятся частью типа функции, и вызывающий код не может забыть их обработать — в отличие от `try`/`catch`, про который забыть легко. `collectResults` — один проход за O(n), который останавливается на первой неудаче.

</Solution>
