The weather widget shouldn't ask the server again every second, but it shouldn't show yesterday's forecast either. Write a generic class `TtlCache<K, V>` whose entries expire after a **time to live** (TTL).

The clock is **injected**: the constructor takes `now`, a function returning the current time in milliseconds (default `Date.now`), so tests can move time by hand.

- `new TtlCache<K, V>(defaultTtlMs, now?)`. A TTL that isn't greater than 0 throws a `RangeError` (here and in `set`).
- `set(key, value, ttlMs?)` stores the value until `now() + ttl` (`ttlMs` overrides the default for this entry) and returns the cache itself, so calls can be chained. Setting a key again replaces the value and restarts its timer.
- An entry stored at time `t` with TTL `d` is **expired** once `now() >= t + d`. Expired entries behave as if they were never there, and are deleted when found.
- `get(key)` returns the value, or `undefined` if it's missing or expired. `has(key)` returns a boolean.
- `getOrSet(key, make)` returns the fresh value if there is one; otherwise it calls `make()`, stores the result with the default TTL and returns it.
- `prune()` deletes every expired entry and returns how many it deleted. The getter `size` returns the number of entries that are **not** expired.

```ts
let time = 0;
const forecasts = new TtlCache<string, string>(1000, () => time);
forecasts.set("Paris", "sunny").set("Oslo", "snow", 5000);
time = 999;  forecasts.get("Paris"); // "sunny"
time = 1000; forecasts.get("Paris"); // undefined: expired
forecasts.size;                      // 1 (only Oslo)
```

<Solution>

```ts
type Entry<V> = { value: V; expiresAt: number };

function checkTtl(ttl: number): number {
  if (!(ttl > 0)) throw new RangeError("TTL must be positive");
  return ttl;
}

class TtlCache<K, V> {
  private entries = new Map<K, Entry<V>>();
  private readonly defaultTtlMs: number;
  private readonly now: () => number;

  constructor(defaultTtlMs: number, now: () => number = Date.now) {
    this.defaultTtlMs = checkTtl(defaultTtlMs);
    this.now = now;
  }

  set(key: K, value: V, ttlMs = this.defaultTtlMs): this {
    const expiresAt = this.now() + checkTtl(ttlMs);
    this.entries.set(key, { value, expiresAt });
    return this;
  }

  get(key: K): V | undefined {
    return this.fresh(key)?.value;
  }

  has(key: K): boolean {
    return this.fresh(key) !== undefined;
  }

  getOrSet(key: K, make: () => V): V {
    const entry = this.fresh(key);
    if (entry) return entry.value;
    const value = make();
    this.set(key, value);
    return value;
  }

  prune(): number {
    let removed = 0;
    for (const key of [...this.entries.keys()]) {
      if (!this.fresh(key)) removed++;
    }
    return removed;
  }

  get size(): number {
    this.prune();
    return this.entries.size;
  }

  private fresh(key: K): Entry<V> | undefined {
    const entry = this.entries.get(key);
    if (!entry) return undefined;
    if (this.now() < entry.expiresAt) return entry;
    this.entries.delete(key);
    return undefined;
  }
}

  const maybe: number | undefined = cache.get("a");

  cache.set("c", "3");
  // @ts-expect-error: get can miss
  const sure: number = cache.get("a");
  // @ts-expect-error: the keys are strings
  cache.has(1);
  return [maybe, sure];
}

forecasts.set("Paris", "sunny").set("Oslo", "snow", 5000);

```

Every entry remembers when it expires, and one private helper decides freshness and deletes stale entries lazily, so `get`, `has` and `getOrSet` are O(1). `prune` and `size` walk all entries, O(n). Taking the clock as a constructor argument keeps `Date.now` out of the logic, which is what makes the timing testable.

</Solution>
