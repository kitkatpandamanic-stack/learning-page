A panda's profile on the zoo website looks like this:

```ts
interface Profile {
  readonly id: number;
  name: string;
  age: number;
  bio: string;
}
```

The edit form sends only the fields that changed. Write:

1. A type `ProfileChanges`: every field of `Profile` **except `id`**, all optional. Build it from `Profile` with the utility types `Partial` and `Omit` rather than writing the fields out again.
2. `updateProfile(profile, changes)` that returns a **new** profile with the changes applied. The original must not change.

One real-world wrinkle: some forms send a field as `undefined` when it was left alone. A change whose value is `undefined` is **ignored** (the old value stays).

```ts
const mei = { id: 1, name: "Mei", age: 4, bio: "Loves bamboo" };
updateProfile(mei, { age: 5 });            // { id: 1, name: "Mei", age: 5, bio: "Loves bamboo" }
updateProfile(mei, { name: undefined });   // same values as mei
updateProfile(mei, { id: 2 });             // ❌ compile error
```

Define `ProfileChanges` with utility types and implement `updateProfile`. The `@ts-expect-error` lines pass only when that line **is** an error.

<Hint>

`Omit<Profile, "id">` removes the id, and wrapping it in `Partial<…>` makes the rest optional. In the function, copy the profile with `{ ...profile }`, then for each field check `if (changes.age !== undefined)` before copying it over (a truthiness check would skip `0` and `""`).

</Hint>

<Solution>

```ts
interface Profile {
  readonly id: number;
  name: string;
  age: number;
  bio: string;
}

type ProfileChanges = Partial<Omit<Profile, "id">>;

function updateProfile(
  profile: Profile,
  changes: ProfileChanges,
): Profile {
  const updated = { ...profile };
  if (changes.name !== undefined) updated.name = changes.name;
  if (changes.age !== undefined) updated.age = changes.age;
  if (changes.bio !== undefined) updated.bio = changes.bio;
  return updated;
}

function typeTests() {
  const p: Profile = { id: 1, name: "Mei", age: 4, bio: "" };
  updateProfile(p, { age: 5, bio: "Sleepy" });
  updateProfile(p, {});
  // @ts-expect-error: age is a number
  updateProfile(p, { age: "five" });
  // @ts-expect-error: the id can't be changed
  updateProfile(p, { id: 2 });
}

const mei = { id: 1, name: "Mei", age: 4, bio: "Loves bamboo" };
console.log(updateProfile(mei, { age: 5 }));
```

Deriving `ProfileChanges` from `Profile` keeps the two in sync: add a field to `Profile` and it becomes editable automatically. A plain `{ ...profile, ...changes }` would be shorter, but it copies `name: undefined` over the real name, which is exactly the bug the explicit `!== undefined` checks avoid.

</Solution>
