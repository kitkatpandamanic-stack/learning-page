The bamboo shop's orders are stored as one loose object full of optional fields, so a "paid" order without a payment time slips through. Replace the loose types with **discriminated unions**, then write the state machine that moves an order along.

An `Order` is one of four shapes, told apart by `status`. Every shape has `items: string[]`:

- `"cart"`: nothing else.
- `"paid"`: also `paidAt: number`.
- `"shipped"`: also `paidAt: number` and `tracking: string`.
- `"cancelled"`: also `reason: string`.

An `OrderEvent` is one of `{ type: "add"; item: string }`, `{ type: "pay"; at: number }`, `{ type: "ship"; tracking: string }` or `{ type: "cancel"; reason: string }`.

`transition(order, event)` returns the next order, **without changing** the one it was given:

- `add` works on a cart: a new cart with the item added at the end.
- `pay` works on a cart with at least one item: a paid order with `paidAt` set to `event.at`.
- `ship` works on a paid order: a shipped order with the tracking code (it keeps `items` and `paidAt`).
- `cancel` works on a cart or a paid order: a cancelled order with the reason (it keeps `items`).
- Any other combination is ignored: return the **same** order object.

`describe(order)` returns `"cart: N items"`, `"paid at <paidAt>"`, `"shipped: <tracking>"` or `"cancelled: <reason>"`. Use a `switch` on `status` with an exhaustive `never` check in the `default` branch.

```ts
const cart: Order = { status: "cart", items: [] };
const one = transition(cart, { type: "add", item: "tea" });
const paid = transition(one, { type: "pay", at: 1700 });
describe(paid);                                    // "paid at 1700"
transition(cart, { type: "pay", at: 5 }) === cart; // true: empty carts can't be paid
transition(paid, { type: "ship", tracking: "PD-7" });
// { status: "shipped", items: ["tea"], paidAt: 1700, tracking: "PD-7" }
```

<Solution>

```ts
type Order =
  | { status: "cart"; items: string[] }
  | { status: "paid"; items: string[]; paidAt: number }
  | {
      status: "shipped";
      items: string[];
      paidAt: number;
      tracking: string;
    }
  | { status: "cancelled"; items: string[]; reason: string };

type OrderEvent =
  | { type: "add"; item: string }
  | { type: "pay"; at: number }
  | { type: "ship"; tracking: string }
  | { type: "cancel"; reason: string };

function assertNever(value: never): never {
  throw new Error("Unexpected value: " + JSON.stringify(value));
}

function transition(order: Order, event: OrderEvent): Order {
  switch (event.type) {
    case "add":
      if (order.status !== "cart") return order;
      return { status: "cart", items: [...order.items, event.item] };
    case "pay":
      if (order.status !== "cart" || order.items.length === 0) {
        return order;
      }
      return { status: "paid", items: order.items, paidAt: event.at };
    case "ship":
      if (order.status !== "paid") return order;
      return { ...order, status: "shipped", tracking: event.tracking };
    case "cancel":
      if (order.status !== "cart" && order.status !== "paid") {
        return order;
      }
      return {
        status: "cancelled",
        items: order.items,
        reason: event.reason,
      };
    default:
      return assertNever(event);
  }
}

function describe(order: Order): string {
  switch (order.status) {
    case "cart":
      return "cart: " + order.items.length + " items";
    case "paid":
      return "paid at " + order.paidAt;
    case "shipped":
      return "shipped: " + order.tracking;
    case "cancelled":
      return "cancelled: " + order.reason;
    default:
      return assertNever(order);
  }
}

// ===== Type tests: don't change these =====
// @ts-expect-error: a paid order needs paidAt
const noDate: Order = { status: "paid", items: ["tea"] };
// @ts-expect-error: "lost" is not a status
const lost: Order = { status: "lost", items: [] };
// @ts-expect-error: a ship event needs a tracking code
const badEvent: OrderEvent = { type: "ship" };

const cart: Order = { status: "cart", items: ["tea"] };
console.log(describe(transition(cart, { type: "pay", at: 1700 })));
```

Each `case` on `event.type` narrows the event, and each `order.status` check narrows the order, so `event.item`, `order.paidAt` and friends are only reachable where they really exist. Impossible orders (paid without a time, a status nobody handles) no longer compile, and `assertNever` turns a forgotten case into a type error instead of a silent bug.

</Solution>
