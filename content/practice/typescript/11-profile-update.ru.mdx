Профиль панды на сайте зоопарка выглядит так:

```ts
interface Profile {
  readonly id: number;
  name: string;
  age: number;
  bio: string;
}
```

Форма редактирования присылает только изменившиеся поля. Напишите:

1. Тип `ProfileChanges`: все поля `Profile`, **кроме `id`**, и все необязательные. Соберите его из `Profile` с помощью утилитных типов (utility types) `Partial` и `Omit`, а не переписывайте поля заново.
2. `updateProfile(profile, changes)`, которая возвращает **новый** профиль с применёнными изменениями. Исходный профиль меняться не должен.

Одна жизненная деталь: некоторые формы присылают поле со значением `undefined`, если его не трогали. Изменение со значением `undefined` **игнорируется** (остаётся старое значение).

```ts
const mei = { id: 1, name: "Mei", age: 4, bio: "Loves bamboo" };
updateProfile(mei, { age: 5 });            // { id: 1, name: "Mei", age: 5, bio: "Loves bamboo" }
updateProfile(mei, { name: undefined });   // те же значения, что у mei
updateProfile(mei, { id: 2 });             // ❌ ошибка компиляции
```

Опишите `ProfileChanges` через утилитные типы и реализуйте `updateProfile`. Строки с `@ts-expect-error` проходят, только если в этой строке **есть** ошибка.

<Hint>

`ProfileChanges` не нужно писать вручную: соберите его из `Profile` с помощью утилитных типов. Какой из них убирает ключ, а какой делает все поля необязательными?

</Hint>

<Hint>

`Omit<Profile, "id">` убирает id, а обёртка `Partial<…>` делает остальные поля необязательными. В функции скопируйте профиль через `{ ...profile }`, чтобы исходный объект не изменился. Затем для каждого из полей `name`, `age` и `bio` переносите изменение, только если оно `!== undefined`. Проверка на истинность пропустила бы `0` и `""`, а разворот `changes` скопировал бы `undefined` поверх настоящих значений.

</Hint>

<Hint>

```ts
type ProfileChanges = Partial<Omit<Profile, "id">>;

function updateProfile(
  profile: Profile,
  changes: ProfileChanges,
): Profile {
  const updated = { ...profile };
  if (changes.name !== undefined) updated.name = changes.name;
  // то же самое для age и bio
  return updated;
}
```

</Hint>

<Solution>

```ts
interface Profile {
  readonly id: number;
  name: string;
  age: number;
  bio: string;
}

type ProfileChanges = Partial<Omit<Profile, "id">>;

function updateProfile(
  profile: Profile,
  changes: ProfileChanges,
): Profile {
  const updated = { ...profile };
  if (changes.name !== undefined) updated.name = changes.name;
  if (changes.age !== undefined) updated.age = changes.age;
  if (changes.bio !== undefined) updated.bio = changes.bio;
  return updated;
}

function typeTests() {
  const p: Profile = { id: 1, name: "Mei", age: 4, bio: "" };
  updateProfile(p, { age: 5, bio: "Sleepy" });
  updateProfile(p, {});
  // @ts-expect-error: age — это число
  updateProfile(p, { age: "five" });
  // @ts-expect-error: id менять нельзя
  updateProfile(p, { id: 2 });
}

const mei = { id: 1, name: "Mei", age: 4, bio: "Loves bamboo" };
console.log(updateProfile(mei, { age: 5 }));
```

Если выводить `ProfileChanges` из `Profile`, два типа всегда остаются согласованными: добавьте поле в `Profile` — и его сразу можно будет редактировать. Простое `{ ...profile, ...changes }` было бы короче, но оно скопирует `name: undefined` поверх настоящего имени — а это ровно та ошибка, от которой защищают явные проверки `!== undefined`.

</Solution>

</Exercise>
