Builders read nicely, `request().method("GET").url("/pandas").build()`, but the usual kind lets you call `build()` too early and only fails at runtime. Write one where TypeScript **tracks** what has been set, so `build()` simply doesn't exist until both the method and the URL are there.

```ts
type Method = "GET" | "POST" | "PUT" | "DELETE";
type Req = {
  method: Method;
  url: string;
  headers: Record<string, string>;
  body?: string;
};
```

`request()` returns an empty builder. Builder methods:

- `method(m)` and `url(u)` set those parts (calling one again replaces the old value).
- `header(name, value)` sets a header. Names are stored in lowercase, so `"X-Token"` and `"x-token"` are the same header (the last value wins).
- `query(name, value)` adds a query parameter (`value` is a `string` or a `number`). Parameters are added to the URL in the order they were given, encoded like `URLSearchParams` does (`"red panda"` → `red+panda`), after `?`, or after `&` if the URL already contains a `?`.
- `json(body)` sets `body` to `JSON.stringify(body)` and the header `content-type` to `application/json`.
- `build()` returns the `Req`. A `GET` request with a body throws a `TypeError` with the message `"GET requests can't have a body"`. The `body` key is only present if a body was set.

Every builder method returns a **new** builder and leaves the old one unchanged, so a half-built builder can be reused as a template. In the types, `build` is only available once both `method` and `url` have been called: use type parameters such as `Builder<HasMethod, HasUrl>`.

```ts
const api = request().header("Accept", "application/json");
api.method("GET").url("/pandas").query("q", "red panda").build();
// { method: "GET", url: "/pandas?q=red+panda",
//   headers: { accept: "application/json" } }
api.method("POST").url("/pandas").json({ name: "Mei" }).build().body;
// '{"name":"Mei"}'
request().method("GET").build(); // ❌ type error: no URL yet
```

Make the builder immutable, track `method` and `url` in its type, and make `build` follow the rules. The `@ts-expect-error` lines are type tests: they pass only when that line **is** an error.

<Hint>

Let the builder's type carry two boolean type parameters that say whether the method and the URL are set, and let each method's return type switch the right one to `true`. A conditional type can then add `build` only when both are `true`.

<Solution>

```ts
type Method = "GET" | "POST" | "PUT" | "DELETE";
type Req = {
  method: Method;
  url: string;
  headers: Record<string, string>;
  body?: string;
};

type Builder<M extends boolean, U extends boolean> = {
  method(m: Method): Builder<true, U>;
  url(u: string): Builder<M, true>;
  header(name: string, value: string): Builder<M, U>;
  query(name: string, value: string | number): Builder<M, U>;
  json(body: unknown): Builder<M, U>;
} & ([M, U] extends [true, true] ? { build(): Req } : {});

type State = {
  method?: Method;
  url?: string;
  headers: Record<string, string>;
  query: [string, string][];
  body?: string;
};

function make(state: State): Builder<true, true> {
  return {
    method: (method) => make({ ...state, method }),
    url: (url) => make({ ...state, url }),
    header: (name, value) =>
      make({
        ...state,
        headers: { ...state.headers, [name.toLowerCase()]: value },
      }),
    query: (name, value) =>
      make({ ...state, query: [...state.query, [name, String(value)]] }),
    json: (body) =>
      make({
        ...state,
        body: JSON.stringify(body),
        headers: { ...state.headers, "content-type": "application/json" },
      }),
    build(): Req {
      const { method, url, headers, query, body } = state;
      if (method === undefined || url === undefined) {
        throw new TypeError("A request needs a method and a URL");
      }
      if (method === "GET" && body !== undefined) {
        throw new TypeError("GET requests can't have a body");
      }
      const search = new URLSearchParams(query).toString();
      const fullUrl = search === ""
        ? url
        : url + (url.includes("?") ? "&" : "?") + search;
      const req: Req = { method, url: fullUrl, headers: { ...headers } };
      if (body !== undefined) req.body = body;
      return req;
    },
  };
}

function request(): Builder<false, false> {
  return make({ headers: {}, query: [] });
}

// ===== Type tests: don't change these =====
function typeTests() {
  const a: Req = request().method("GET").url("/a").build();
  const b: Req = request().url("/b").header("x", "1").method("PUT").build();
  // @ts-expect-error: no URL yet
  request().method("GET").build();
  // @ts-expect-error: no method yet
  request().url("/a").query("q", 1).build();
  // @ts-expect-error: FETCH is not a Method
  request().method("FETCH");
  return [a, b];
}

const api = request().header("Accept", "application/json");
const req = api.method("GET").url("/pandas").query("q", "red panda").build();
console.log(req);
```

The two boolean type parameters are **phantom** state: they never exist at runtime, but every method's return type updates them, and the conditional intersection only adds `build` when both are `true`. One runtime object serves every type state, because a builder that has `build` is still a valid builder that "doesn't have it yet" (extra members are allowed). Each call copies the small state object, so templates can't be changed by accident.

</Solution>
