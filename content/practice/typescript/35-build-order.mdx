A build tool knows which tasks depend on which: `test` needs `build`, `build` needs `install`. Write the two functions at the heart of such a tool. Tasks are given as an object from each task's name to the list of tasks it **depends on**:

```ts
const tasks = {
  install: [],
  lint: ["install"],
  build: ["install"],
  test: ["build", "lint"],
} as const;
```

- `buildOrder(tasks)` returns every task once, each after all of its dependencies. Whenever several tasks are ready, take the **alphabetically smallest** first (compare names with `<`). For `tasks`: `["install", "build", "lint", "test"]`.
- `waves(tasks)` groups tasks for running in parallel: wave 0 holds the tasks with no dependencies, and each later wave holds the tasks whose dependencies are all in earlier waves. Each wave is sorted alphabetically. For `tasks`: `[["install"], ["build", "lint"], ["test"]]`.
- If some tasks can never run (they're in a cycle, or depend on one), both functions throw a `CycleError`: an `Error` with `name` `"CycleError"`, a `stuck` array with those tasks sorted alphabetically, and the message `"Cycle among: a, b, c"` (the stuck names joined with `", "`).

A task that depends on itself is a cycle, and listing a dependency twice counts as once.

The types matter too: a dependency must be one of the object's own task names, so `{ test: ["biuld"], build: [] }` is a type error, and the result is typed with the task names, not as `string[]`. (A task object stored in a variable needs `as const`, as above, so its dependency lists keep their literal names instead of widening to `string[]`.)

```ts
buildOrder({ a: [], b: ["a"], c: [] });    // ["a", "b", "c"]
waves({ a: [], b: ["a"], c: [] });         // [["a", "c"], ["b"]]
buildOrder({ x: ["y"], y: ["x"], z: ["x"], ok: [] });
// throws CycleError: "Cycle among: x, y, z"
```

Make both functions generic over the task names and implement them. The `Expect<Equal<…>>` lines and the `@ts-expect-error` line are type tests; the second kind passes only when that line **is** an error.

<Hint>

This is a topological sort. For each task, how many of its dependencies are still unfinished, and which tasks could run right now? For the types, look at `NoInfer`: it lets the task names come from the keys only.

</Hint>

<Hint>

Type it as `function buildOrder<T extends string>(tasks: Record<T, readonly NoInfer<T>[]>): T[]`, so a misspelled dependency is checked against the keys instead of widening `T`. Inside, `Object.keys(tasks) as T[]` gives the names. Then use **Kahn's algorithm**: count each task's distinct unfinished dependencies (`new Set(deps).size`) and keep a map from each task to the tasks that depend on it. For `buildOrder`, keep taking the smallest task whose count is 0, add it to the result, and count down its dependents. For `waves`, take *all* tasks with count 0 at once as one sorted wave. If the ready tasks run out before every task is placed, the rest are stuck: throw a `CycleError` with them sorted.

</Hint>

```ts
function buildOrder<T extends string>(tasks: Record<T, readonly NoInfer<T>[]>): T[] {
  const names = Object.keys(tasks) as T[];
  const waiting = new Map<T, number>();
  const dependents = new Map<T, T[]>(names.map((n) => [n, []]));
  for (const name of names) {
    const deps = new Set(tasks[name]);
    waiting.set(name, deps.size);
    for (const dep of deps) dependents.get(dep)?.push(name);
  }
  const ready = names.filter((n) => waiting.get(n) === 0);
  const order: T[] = [];
  while (ready.length > 0) {
    // take the smallest ready task, add it to order,
    // and count down its dependents (a count of 0 means ready)
  }
  // fewer tasks in order than in names? throw a CycleError
  return order;
}
```

<Solution>

```ts
// ===== Type-test helpers: don't change =====
type Expect<T extends true> = T;
type Equal<A, B> =
  (<X>() => X extends A ? 1 : 2) extends
  (<X>() => X extends B ? 1 : 2) ? true : false;

class CycleError extends Error {
  readonly stuck: string[];

  constructor(stuck: string[]) {
    super("Cycle among: " + stuck.join(", "));
    this.name = "CycleError";
    this.stuck = stuck;
  }
}

const byName = (a: string, b: string) => (a < b ? -1 : a > b ? 1 : 0);

function prepare<T extends string>(tasks: Record<T, readonly T[]>) {
  const names = Object.keys(tasks) as T[];
  const waiting = new Map<T, number>();
  const dependents = new Map<T, T[]>(names.map((n) => [n, []]));
  for (const name of names) {
    const deps = new Set(tasks[name]);
    waiting.set(name, deps.size);
    for (const dep of deps) dependents.get(dep)?.push(name);
  }
  // Marks a task as done; returns the tasks that just became ready
  const finish = (name: T): T[] => {
    const ready: T[] = [];
    for (const next of dependents.get(name) ?? []) {
      const left = waiting.get(next)! - 1;
      waiting.set(next, left);
      if (left === 0) ready.push(next);
    }
    return ready;
  };
  const initial = names.filter((n) => waiting.get(n) === 0);
  const stuck = (done: Set<T>) =>
    new CycleError(names.filter((n) => !done.has(n)).sort(byName));
  return { names, finish, initial, stuck };
}

function buildOrder<T extends string>(
  tasks: Record<T, readonly NoInfer<T>[]>,
): T[] {
  const { names, finish, initial, stuck } = prepare(tasks);
  const ready = [...initial];
  const order: T[] = [];
  while (ready.length > 0) {
    ready.sort(byName);
    const name = ready.shift()!;
    order.push(name);
    ready.push(...finish(name));
  }
  if (order.length < names.length) throw stuck(new Set(order));
  return order;
}

function waves<T extends string>(
  tasks: Record<T, readonly NoInfer<T>[]>,
): T[][] {
  const { names, finish, initial, stuck } = prepare(tasks);
  const result: T[][] = [];
  const done = new Set<T>();
  let wave = initial;
  while (wave.length > 0) {
    wave.sort(byName);
    result.push(wave);
    for (const name of wave) done.add(name);
    wave = wave.flatMap(finish);
  }
  if (done.size < names.length) throw stuck(done);
  return result;
}

// ===== Type tests: don't change these =====
function typeTests() {
  const order = buildOrder({
    install: [],
    build: ["install"],
    test: ["build"],
  });
  const groups = waves({ a: [], b: ["a"] });
  type cases = [
    Expect<Equal<typeof order, ("install" | "build" | "test")[]>>,
    Expect<Equal<typeof groups, ("a" | "b")[][]>>,
  ];
  // @ts-expect-error: there is no "lint" task
  buildOrder({ build: ["lint"], test: ["build"] });
}

const tasks = {
  install: [],
  lint: ["install"],
  build: ["install"],
  test: ["build", "lint"],
} as const;
console.log(buildOrder(tasks));
console.log(waves(tasks));
```

Kahn's algorithm keeps a count of unfinished dependencies per task and releases a task when its count reaches 0; tasks that are never released are exactly the ones in or behind a cycle. Building the graph is O(V + E). Sorting the ready list each step makes `buildOrder` O(V² log V) in the worst case (a binary heap would bring it to O((V + E) log V)), which is plenty for build graphs; `waves` sorts each wave once.

</Solution>
