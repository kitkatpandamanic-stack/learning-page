Редактор PandaDev сохраняет настройки пользователя **патчами**: только то, что изменилось, на любой глубине. `Partial<Settings>` здесь не хватает, потому что он делает необязательным только верхний уровень. Напишите `DeepPartial<T>` и две функции, которые делают патчи полезными.

`DeepPartial<T>` делает каждое свойство необязательным на любой глубине простых объектов. Массивы, функции и `Date` — это **листья**: их тип остаётся ровно таким, какой есть (патч заменяет массив целиком, а не правит отдельные элементы).

- `mergeDeep(base, patch)` возвращает новое значение: для каждого ключа `patch`, значение которого не `undefined`, если с обеих сторон **простые объекты** (созданные через `{}`, не массивы, не `null`, не даты…), сливайте их рекурсивно; иначе значение из патча заменяет значение из основы. `undefined` в патче означает «оставить как есть»; `null` — настоящее значение. Ни один аргумент не меняется.
- `diff(before, after)` возвращает **минимальный** патч, превращающий `before` в `after`: в нём остаются только ключи с различающимися значениями, с рекурсией в простые объекты с обеих сторон (вложенный объект без различий не попадает в патч, поэтому для равных входов получается `{}`). Массивы равны, если у них одинаковая длина и одинаковые элементы (`Object.is`, поэлементно); остальные значения сравниваются через `Object.is`. Ключи, которые есть только в `before`, игнорируются.

`mergeDeep(before, diff(before, after))` возвращает объект, глубоко равный `after`.

```ts
const settings = {
  theme: { mode: "light", accent: "green" },
  fontSize: 14,
  plugins: ["git"],
};
mergeDeep(settings, { theme: { mode: "dark" }, plugins: ["git", "vim"] });
// { theme: { mode: "dark", accent: "green" }, fontSize: 14, plugins: ["git", "vim"] }
diff(settings, { ...settings, theme: { mode: "light", accent: "red" } });
// { theme: { accent: "red" } }
```

Напишите `DeepPartial`, `mergeDeep` и `diff`. Строка `Expect<Equal<…>>` и строка с `@ts-expect-error` — это тесты типов; вторая проходит, только когда в этой строке **есть** ошибка. С `Partial` из заготовки вложенный патч вроде `{ theme: { mode: "dark" } }` даже не компилируется.

<Hint>

Сначала проверьте листья, затем спускайтесь рекурсивно: `T extends readonly unknown[] | Date | ((...args: never[]) => unknown) ? T : T extends object ? { [K in keyof T]?: DeepPartial<T[K]> } : T`. Во время выполнения нужен помощник `isPlainObject(value: unknown): value is Record<string, unknown>`: `typeof value === "object" && value !== null && Object.getPrototypeOf(value) === Object.prototype` (массивы и даты эту проверку не проходят).

</Hint>

<Hint>

Обе функции обходят патч или объект `after` через `Object.entries`, собирая новый `Record<string, unknown>`. В `diff` ключ добавляется, когда значения различаются: спускайтесь рекурсивно, если с обеих сторон простые объекты (и сохраняйте результат, только если в нём есть ключи), сравнивайте массивы поэлементно, а для всего остального используйте `Object.is`. Приведите тип один раз в конце (`as T` / `as DeepPartial<T>`): TypeScript не может проследить рекурсию.

</Hint>

<Solution>

```ts
// ===== Помощники для тестов типов: не меняйте =====
type Expect<T extends true> = T;
type Equal<A, B> =
  (<X>() => X extends A ? 1 : 2) extends
  (<X>() => X extends B ? 1 : 2) ? true : false;

type Leaf = readonly unknown[] | Date | ((...args: never[]) => unknown);

type DeepPartial<T> = T extends Leaf
  ? T
  : T extends object
    ? { [K in keyof T]?: DeepPartial<T[K]> }
    : T;

type Bag = Record<string, unknown>;

function isPlainObject(value: unknown): value is Bag {
  return (
    typeof value === "object" &&
    value !== null &&
    Object.getPrototypeOf(value) === Object.prototype
  );
}

function merge(base: unknown, patch: Bag): Bag {
  const result: Bag = isPlainObject(base) ? { ...base } : {};
  for (const [key, value] of Object.entries(patch)) {
    if (value === undefined) continue;
    result[key] =
      isPlainObject(value) && isPlainObject(result[key])
        ? merge(result[key], value)
        : value;
  }
  return result;
}

function mergeDeep<T>(base: T, patch: DeepPartial<T>): T {
  return merge(base, patch as Bag) as T;
}

function sameArray(a: unknown[], b: unknown[]): boolean {
  return a.length === b.length && a.every((x, i) => Object.is(x, b[i]));
}

function changes(before: Bag, after: Bag): Bag {
  const patch: Bag = {};
  for (const [key, value] of Object.entries(after)) {
    const old = before[key];
    if (isPlainObject(old) && isPlainObject(value)) {
      const inner = changes(old, value);
      if (Object.keys(inner).length > 0) patch[key] = inner;
    } else if (Array.isArray(old) && Array.isArray(value)) {
      if (!sameArray(old, value)) patch[key] = value;
    } else if (!Object.is(old, value)) {
      patch[key] = value;
    }
  }
  return patch;
}

function diff<T>(before: T, after: T): DeepPartial<T> {
  return changes(before as Bag, after as Bag) as DeepPartial<T>;
}

// ===== Тесты типов: не меняйте их =====
type Mode = "light" | "dark";
type Settings = {
  theme: { mode: Mode; accent: string };
  fontSize: number;
  plugins: string[];
  savedAt: Date;
  onSave: (text: string) => void;
};

type cases = [
  Expect<Equal<DeepPartial<Settings>, {
    theme?: { mode?: Mode; accent?: string };
    fontSize?: number;
    plugins?: string[];
    savedAt?: Date;
    onSave?: (text: string) => void;
  }>>,
];

function typeTests(settings: Settings) {
  const next: Settings = mergeDeep(settings, { theme: { mode: "dark" } });
  // @ts-expect-error: "blue" — не Mode
  mergeDeep(settings, { theme: { mode: "blue" } });
  return next;
}

const settings = {
  theme: { mode: "light", accent: "green" },
  fontSize: 14,
  plugins: ["git"],
};
console.log(mergeDeep(settings, { theme: { mode: "dark" } }));
```

`DeepPartial` останавливается на листьях до рекурсии, иначе массивы превратились бы в объекты с необязательными числовыми ключами, а функции потеряли бы сигнатуру вызова. Обе функции времени выполнения обходят только присутствующие ключи и копируют только посещённые объекты, поэтому работают за O(размер патча или нового значения). Именно проверка `isPlainObject` не даёт сливать по ключам даты, массивы и экземпляры классов.

</Solution>
