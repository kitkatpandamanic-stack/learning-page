The zoo keeps its pandas in an array, and the keepers keep writing the same `filter`, `sort` and `map` chains. Build a small typed query class for arrays of objects, where TypeScript knows which comparisons make sense and which fields come out.

```ts
const pandas = [
  { name: "Mei", age: 4, zoo: "Chengdu", vip: true },
  { name: "Bo", age: 9, zoo: "Edinburgh", vip: false },
  { name: "Lin", age: 2, zoo: "Chengdu", vip: false },
];
Query.from(pandas)
  .where("zoo", "=", "Chengdu")
  .where("age", ">=", 3)
  .select("name", "age")
  .run(); // [{ name: "Mei", age: 4 }]
```

`Query.from(rows)` starts a query over an array. Every other method returns a **new** query and leaves the old one unchanged (so a query can be reused as a base), and nothing is computed until `run()` or `first()`, which read the array **at that moment**.

- `where(key, op, value)` keeps the rows that pass; several `where`s must all pass. The operators, and the types they accept:
  - `"="` and `"!="` (with `===` / `!==`): any key; `value` has that key's type.
  - `"<"`, `"<="`, `">"`, `">="`: only keys whose values are numbers or strings; `value` has that key's type. A row whose value is `null` or `undefined` never passes.
  - `"includes"`: only string keys; the row's string must contain `value` (a `string`).
  - `"in"`: any key; `value` is an array of that key's type, and the row's value must be one of them.
- `orderBy(key, direction = "asc")` sorts with `<` and `>` (stable; `null`/`undefined` last). Calling it again replaces the earlier order.
- `limit(n)` keeps at most `n` rows. A negative or non-integer `n` throws a `RangeError` straight away.
- `select(...keys)` makes the results contain only those keys, in that order, as new objects. Its type narrows too: after `select("name")`, results are `{ name: string }`.
- `run()` returns the result array, and `first()` the first result or `undefined`. Whatever order the methods were called in, `run()` filters first, then sorts, then limits, then selects (like SQL).

<Hint>

Two type tools carry this one: a helper type that picks the keys whose values have a given type, and **overloads** for `where`, one signature per family of operators. A second type parameter on the class can remember which keys were selected.

</Hint>

K : never }[keyof T]`. Write four overload signatures for `where` (for example `where<K extends KeysOf<T, string>>(key: K, op: "includes", value: string): Query<T, S>`), then one implementation signature `where(key: keyof T, op: Op, value: unknown): Query<T, S>`. `select<K extends keyof T>(...keys: K[]): Query<T, K>` and `run(): Pick<T, S>[]`.

**Runtime:** keep the query's parts in one readonly `state` object (rows, a list of filter functions, the order, the limit, the selected keys) and give the class a private constructor that takes it. Every method returns `new Query({ ...state, … })`. `run()` does `rows.filter(every filter)`, then a stable sort of that copy (missing values last), then `slice(0, limit)`, then, if keys were selected, maps each row to `Object.fromEntries(keys.map((k) => [k, row[k]]))`.

</Hint>

<Solution>

```ts
// ===== Type-test helpers: don't change =====
type Expect<T extends true> = T;
type Equal<A, B> =
  (<X>() => X extends A ? 1 : 2) extends
  (<X>() => X extends B ? 1 : 2) ? true : false;

type KeysOf<T, V> = {
  [K in keyof T]-?: T[K] extends V ? K : never;
}[keyof T];
type Compare = "<" | "<=" | ">" | ">=";
type Op = "=" | "!=" | Compare | "includes" | "in";
type Direction = "asc" | "desc";

type State<T> = {
  readonly rows: readonly T[];
  readonly filters: readonly ((row: T) => boolean)[];
  readonly order?: { key: keyof T; direction: Direction };
  readonly limit?: number;
  readonly keys?: readonly (keyof T)[];
};

function test(v: unknown, op: Op, value: unknown): boolean {
  switch (op) {
    case "=":
      return v === value;
    case "!=":
      return v !== value;
    case "includes":
      return typeof v === "string" && v.includes(value as string);
    case "in":
      return (value as unknown[]).includes(v);
  }
  if (v == null) return false;
  const a = v as number | string;
  const b = value as number | string;
  if (op === "<") return a < b;
  if (op === "<=") return a <= b;
  if (op === ">") return a > b;
  return a >= b;
}

class Query<T, S extends keyof T = keyof T> {
  private readonly state: State<T>;

  private constructor(state: State<T>) {
    this.state = state;
  }

  static from<R>(rows: readonly R[]): Query<R> {
    return new Query<R>({ rows, filters: [] });
  }

  where<K extends keyof T>(key: K, op: "=" | "!=", value: T[K]): Query<T, S>;
  where<K extends KeysOf<T, number | string>>(
    key: K,
    op: Compare,
    value: T[K],
  ): Query<T, S>;
  where<K extends KeysOf<T, string>>(
    key: K,
    op: "includes",
    value: string,
  ): Query<T, S>;
  where<K extends keyof T>(
    key: K,
    op: "in",
    value: readonly T[K][],
  ): Query<T, S>;
  where(key: keyof T, op: Op, value: unknown): Query<T, S> {
    const filter = (row: T) => test(row[key], op, value);
    return this.with({ filters: [...this.state.filters, filter] });
  }

  orderBy(key: keyof T, direction: Direction = "asc"): Query<T, S> {
    return this.with({ order: { key, direction } });
  }

  limit(n: number): Query<T, S> {
    if (!Number.isInteger(n) || n < 0) {
      throw new RangeError("limit must be a whole number, 0 or more");
    }
    return this.with({ limit: n });
  }

  select<K extends keyof T>(...keys: K[]): Query<T, K> {
    return new Query<T, K>({ ...this.state, keys });
  }

  run(): Pick<T, S>[] {
    const { rows, filters, order, limit, keys } = this.state;
    let result = rows.filter((row) => filters.every((f) => f(row)));
    if (order) {
      const { key, direction } = order;
      const sign = direction === "asc" ? 1 : -1;
      result.sort((a, b) => {
        const x = a[key];
        const y = b[key];
        if (x == null || y == null) {
          return x == null ? (y == null ? 0 : 1) : -1;
        }
        return x < y ? -sign : x > y ? sign : 0;
      });
    }
    if (limit !== undefined) result = result.slice(0, limit);
    if (!keys) return result;
    return result.map(
      (row) =>
        Object.fromEntries(keys.map((k) => [k, row[k]])) as Pick<T, S>,
    );
  }

  first(): Pick<T, S> | undefined {
    return this.run()[0];
  }

  private with(changes: Partial<State<T>>): Query<T, S> {
    return new Query<T, S>({ ...this.state, ...changes });
  }
}

// ===== Type tests: don't change these =====
type Panda = { name: string; age: number; zoo: string; vip: boolean };

function typeTests(pandas: Panda[]) {
  const q = Query.from(pandas)
    .where("age", ">", 3)
    .where("zoo", "in", ["Chengdu", "Edinburgh"])
    .where("name", "includes", "e")
    .select("name", "zoo");
  type cases = [
    Expect<Equal<ReturnType<typeof q.run>, { name: string; zoo: string }[]>>,
  ];
  // @ts-expect-error: age is a number
  Query.from(pandas).where("age", "=", "3");
  // @ts-expect-error: "includes" only works on strings
  Query.from(pandas).where("age", "includes", "3");
  // @ts-expect-error: booleans can't be compared with <
  Query.from(pandas).where("vip", "<", true);
  // @ts-expect-error: age wasn't selected
  Query.from(pandas).select("name").first()?.age;
}

  { name: "Mei", age: 4, zoo: "Chengdu", vip: true },
  { name: "Bo", age: 9, zoo: "Edinburgh", vip: false },
  { name: "Lin", age: 2, zoo: "Chengdu", vip: false },

console.log(young.select("name").run()); // [ { name: 'Lin' }, { name: 'Mei' } ]
```

The overloads let each operator family state its own rules (which keys, which value type), while one implementation does the work. The second type parameter `S` records the selected keys, so `select` returns a `Query<T, K>` and `run` returns `Pick<T, S>[]`. Because every method copies a small state object and `run` does the work, queries are cheap to build and reuse; running one costs O(n·f) for f filters plus O(n log n) for the sort.
