Зоопарк хранит своих панд в массиве, а смотрители снова и снова пишут одни и те же цепочки `filter`, `sort` и `map`. Напишите маленький типизированный класс запросов к массивам объектов, в котором TypeScript знает, какие сравнения имеют смысл и какие поля попадут в результат.

```ts
const pandas = [
  { name: "Mei", age: 4, zoo: "Chengdu", vip: true },
  { name: "Bo", age: 9, zoo: "Edinburgh", vip: false },
  { name: "Lin", age: 2, zoo: "Chengdu", vip: false },
];
Query.from(pandas)
  .where("zoo", "=", "Chengdu")
  .where("age", ">=", 3)
  .select("name", "age")
  .run(); // [{ name: "Mei", age: 4 }]
```

`Query.from(rows)` начинает запрос по массиву. Каждый другой метод возвращает **новый** запрос и не меняет старый (поэтому запрос можно переиспользовать как основу), и ничего не вычисляется до `run()` или `first()`, которые читают массив **в этот момент**.

- `where(key, op, value)` оставляет строки, которые проходят условие; если `where` несколько, должны выполняться все. Операторы и типы, которые они принимают:
  - `"="` и `"!="` (через `===` / `!==`): любой ключ; `value` имеет тип этого ключа.
  - `"<"`, `"<="`, `">"`, `">="`: только ключи, значения которых — числа или строки; `value` имеет тип этого ключа. Строка, у которой значение `null` или `undefined`, никогда не проходит.
  - `"includes"`: только строковые ключи; строка в записи должна содержать `value` (типа `string`).
  - `"in"`: любой ключ; `value` — массив значений типа этого ключа, и значение в записи должно быть одним из них.
- `orderBy(key, direction = "asc")` сортирует через `<` и `>` (стабильно; `null`/`undefined` в конце). Повторный вызов заменяет прежний порядок.
- `limit(n)` оставляет не больше `n` строк. Отрицательное или нецелое `n` сразу выбрасывает `RangeError`.
- `select(...keys)` оставляет в результатах только эти ключи, в этом порядке, в виде новых объектов. Его тип тоже сужается: после `select("name")` результаты имеют тип `{ name: string }`.
- `run()` возвращает массив результатов, а `first()` — первый результат или `undefined`. В каком бы порядке ни вызывались методы, `run()` сначала фильтрует, затем сортирует, затем ограничивает, затем выбирает поля (как в SQL).

<Hint>

**Типы:** `class Query<T, S extends keyof T = keyof T>` со `static from<R>(rows: readonly R[]): Query<R>`. Вспомогательный тип выбирает ключи по типу значения: `type KeysOf<T, V> = { [K in keyof T]-?: T[K] extends V ? K : never }[keyof T]`. Затем напишите четыре сигнатуры перегрузки (overload) для `where` (по одной на группу операторов, например `where<K extends KeysOf<T, string>>(key: K, op: "includes", value: string): Query<T, S>`), а за ними — одну сигнатуру реализации `where(key: keyof T, op: Op, value: unknown): Query<T, S>`. `select<K extends keyof T>(...keys: K[]): Query<T, K>` и `run(): Pick<T, S>[]`.

</Hint>

<Hint>

**Во время выполнения:** храните части запроса в одном readonly-объекте `state` (строки, список функций-фильтров, порядок, лимит, выбранные ключи) и дайте классу приватный конструктор, который его принимает. Каждый метод возвращает `new Query({ ...state, … })`. `run()` делает `rows.filter(все фильтры)`, затем стабильную сортировку копии, затем `slice(0, limit)`, а затем, если ключи выбраны, превращает каждую строку в `Object.fromEntries(keys.map((k) => [k, row[k]]))`.

</Hint>

```ts
// ===== Помощники для тестов типов: не меняйте =====
type Expect<T extends true> = T;
type Equal<A, B> =
  (<X>() => X extends A ? 1 : 2) extends
  (<X>() => X extends B ? 1 : 2) ? true : false;

type KeysOf<T, V> = {
  [K in keyof T]-?: T[K] extends V ? K : never;
}[keyof T];
type Compare = "<" | "<=" | ">" | ">=";
type Op = "=" | "!=" | Compare | "includes" | "in";
type Direction = "asc" | "desc";

type State<T> = {
  readonly rows: readonly T[];
  readonly filters: readonly ((row: T) => boolean)[];
  readonly order?: { key: keyof T; direction: Direction };
  readonly limit?: number;
  readonly keys?: readonly (keyof T)[];
};

function test(v: unknown, op: Op, value: unknown): boolean {
  switch (op) {
    case "=":
      return v === value;
    case "!=":
      return v !== value;
    case "includes":
      return typeof v === "string" && v.includes(value as string);
    case "in":
      return (value as unknown[]).includes(v);
  }
  if (v == null) return false;
  const a = v as number | string;
  const b = value as number | string;
  if (op === "<") return a < b;
  if (op === "<=") return a <= b;
  if (op === ">") return a > b;
  return a >= b;
}

class Query<T, S extends keyof T = keyof T> {
  private readonly state: State<T>;

  private constructor(state: State<T>) {
    this.state = state;
  }

  static from<R>(rows: readonly R[]): Query<R> {
    return new Query<R>({ rows, filters: [] });
  }

  where<K extends keyof T>(key: K, op: "=" | "!=", value: T[K]): Query<T, S>;
  where<K extends KeysOf<T, number | string>>(
    key: K,
    op: Compare,
    value: T[K],
  ): Query<T, S>;
  where<K extends KeysOf<T, string>>(
    key: K,
    op: "includes",
    value: string,
  ): Query<T, S>;
  where<K extends keyof T>(
    key: K,
    op: "in",
    value: readonly T[K][],
  ): Query<T, S>;
  where(key: keyof T, op: Op, value: unknown): Query<T, S> {
    const filter = (row: T) => test(row[key], op, value);
    return this.with({ filters: [...this.state.filters, filter] });
  }

  orderBy(key: keyof T, direction: Direction = "asc"): Query<T, S> {
    return this.with({ order: { key, direction } });
  }

  limit(n: number): Query<T, S> {
    if (!Number.isInteger(n) || n < 0) {
      throw new RangeError("limit must be a whole number, 0 or more");
    }
    return this.with({ limit: n });
  }

  select<K extends keyof T>(...keys: K[]): Query<T, K> {
    return new Query<T, K>({ ...this.state, keys });
  }

  run(): Pick<T, S>[] {
    const { rows, filters, order, limit, keys } = this.state;
    let result = rows.filter((row) => filters.every((f) => f(row)));
    if (order) {
      const { key, direction } = order;
      const sign = direction === "asc" ? 1 : -1;
      result.sort((a, b) => {
        const x = a[key];
        const y = b[key];
        if (x == null || y == null) {
          return x == null ? (y == null ? 0 : 1) : -1;
        }
        return x < y ? -sign : x > y ? sign : 0;
      });
    }
    if (limit !== undefined) result = result.slice(0, limit);
    if (!keys) return result;
    return result.map(
      (row) =>
        Object.fromEntries(keys.map((k) => [k, row[k]])) as Pick<T, S>,
    );
  }

  first(): Pick<T, S> | undefined {
    return this.run()[0];
  }

  private with(changes: Partial<State<T>>): Query<T, S> {
    return new Query<T, S>({ ...this.state, ...changes });
  }
}

// ===== Тесты типов: не меняйте их =====
type Panda = { name: string; age: number; zoo: string; vip: boolean };

function typeTests(pandas: Panda[]) {
  const q = Query.from(pandas)
    .where("age", ">", 3)
    .where("zoo", "in", ["Chengdu", "Edinburgh"])
    .where("name", "includes", "e")
    .select("name", "zoo");
  type cases = [
    Expect<Equal<ReturnType<typeof q.run>, { name: string; zoo: string }[]>>,
  ];
  // @ts-expect-error: age — число
  Query.from(pandas).where("age", "=", "3");
  // @ts-expect-error: "includes" работает только со строками
  Query.from(pandas).where("age", "includes", "3");
  // @ts-expect-error: логические значения нельзя сравнивать через <
  Query.from(pandas).where("vip", "<", true);
  // @ts-expect-error: age не был выбран
  Query.from(pandas).select("name").first()?.age;
}

const pandas = [
  { name: "Mei", age: 4, zoo: "Chengdu", vip: true },
  { name: "Bo", age: 9, zoo: "Edinburgh", vip: false },
  { name: "Lin", age: 2, zoo: "Chengdu", vip: false },
];
const young = Query.from(pandas).where("age", "<", 5).orderBy("age");
console.log(young.select("name").run()); // [ { name: 'Lin' }, { name: 'Mei' } ]
```

Перегрузки позволяют каждому семейству операторов задать свои правила (какие ключи, какой тип значения), а работу делает одна реализация. Второй параметр типа `S` запоминает выбранные ключи, поэтому `select` возвращает `Query<T, K>`, а `run` — `Pick<T, S>[]`. Поскольку каждый метод лишь копирует маленький объект состояния, а работу делает `run`, запросы дёшево строить и переиспользовать; выполнение стоит O(n·f) для f фильтров плюс O(n log n) на сортировку.

</Solution>
