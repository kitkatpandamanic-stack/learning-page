Два крошечных помощника, которые рано или поздно появляются в любом проекте: `first(items)` возвращает первый элемент массива, а `last(items)` — последний. Если массив пустой, обе функции возвращают `undefined`.

Часть на JavaScript простая. Вся суть — в TypeScript: помощники должны работать с **любым** типом элементов и сохранять его. У `first([3, 1, 2])` тип `number | undefined`, у `first(["bamboo"])` — `string | undefined` и так далее. Возвращать `any` нельзя: это выключило бы проверку типов для всего, что использует результат.

Сделайте обе функции дженериками (generic) по типу элемента `T`: пусть они принимают `readonly T[]` (чтобы подходили и массивы только для чтения) и возвращают `T | undefined`.

```ts
first([3, 1, 2]);           // 3       (тип: number | undefined)
last(["tea", "bamboo"]);    // "bamboo" (тип: string | undefined)
first([]);                  // undefined
```

Сделайте `first` и `last` дженериками, чтобы тесты типов проходили, и возвращайте правильные элементы. Строки с `@ts-expect-error` — это тесты типов: они проходят, только если в этой строке **есть** ошибка, поэтому с `any` заготовка падает с сообщением "Unused '@ts-expect-error' directive."

<Hint>

Объявите параметр типа после имени функции: `function first<T>(items: readonly T[]): T | undefined`. Внутри `items[0]` и `items[items.length - 1]` дают нужные элементы (или `undefined` для пустого массива).

</Hint>

<Solution>

```ts
function first<T>(items: readonly T[]): T | undefined {
  return items[0];
}

function last<T>(items: readonly T[]): T | undefined {
  return items[items.length - 1];
}

function typeTests() {
  const scores: readonly number[] = [3, 1, 2];
  const top: number | undefined = first(scores);
  const name: string | undefined = last(["tea", "bamboo"]);
  // @ts-expect-error
  const sure: number = first([1, 2]);
  // @ts-expect-error
  const wrong: string | undefined = last([1, 2]);
}

console.log(first([3, 1, 2])); // 3
```

TypeScript выводит `T` из аргумента, поэтому `first([3, 1, 2])` возвращает `number | undefined`, и писать `<number>` не нужно. `| undefined` в возвращаемом типе — это честность: без `noUncheckedIndexedAccess` у `items[0]` тип просто `T`, и только аннотация напоминает вызывающему коду, что у пустого массива нет первого элемента.

</Solution>
