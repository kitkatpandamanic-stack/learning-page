The bamboo delivery API sometimes fails for a moment and works a second later. Write `retry(task, options)`, which keeps calling an async `task` until it succeeds, waiting longer between tries.

```ts
type RetryOptions = {
  attempts: number; // total number of tries, at least 1
  delayMs: number;  // wait before the 2nd try; doubles after that
  sleep?: (ms: number) => Promise<void>;
  shouldRetry?: (error: unknown) => boolean;
};
```

- `task` receives the attempt number (1, 2, 3…) and returns a promise. `retry` resolves with the first value a task resolves with, and its type is the task's type: retrying a `Promise<number>` task gives a `Promise<number>`.
- After a failed try, if tries are left, wait `delayMs`, then `2 * delayMs`, then `4 * delayMs`… before the next one. Never wait after the last try.
- Waiting uses `options.sleep(ms)` if given (tests pass a fake that records the delays), otherwise a real `setTimeout`.
- If `shouldRetry(error)` returns `false`, stop at once and reject with that **same** error. Without `shouldRetry`, every error is retried.
- When all tries have failed, reject with a `RetryError`: a subclass of `Error` with the message `"Failed after N attempts"`, a `name` of `"RetryError"`, `attempts` (the number of tries made) and `lastError` (whatever the last try threw, typed `unknown`).

```ts
const waits: number[] = [];
const sleep = async (ms: number) => { waits.push(ms); };

await retry(async (n) => {
  if (n < 3) throw new Error("busy");
  return "delivered on try " + n;
}, { attempts: 5, delayMs: 100, sleep });
// "delivered on try 3", and waits is [100, 200]

await retry(() => Promise.reject(new Error("down")), {
  attempts: 3, delayMs: 100, sleep,
});
// rejects with RetryError: "Failed after 3 attempts", lastError.message "down"
```

<Solution>

```ts
type RetryOptions = {
  attempts: number;
  delayMs: number;
  sleep?: (ms: number) => Promise<void>;
  shouldRetry?: (error: unknown) => boolean;
};

class RetryError extends Error {
  readonly attempts: number;
  readonly lastError: unknown;

  constructor(attempts: number, lastError: unknown) {
    super("Failed after " + attempts + " attempts");
    this.name = "RetryError";
    this.attempts = attempts;
    this.lastError = lastError;
  }
}

const realSleep = (ms: number) =>
  new Promise<void>((resolve) => setTimeout(resolve, ms));

async function retry<T>(
  task: (attempt: number) => Promise<T>,
  options: RetryOptions,
): Promise<T> {
  const sleep = options.sleep ?? realSleep;
  const shouldRetry = options.shouldRetry ?? (() => true);
  let lastError: unknown;
  for (let attempt = 1; attempt <= options.attempts; attempt++) {
    try {
      return await task(attempt);
    } catch (error) {
      if (!shouldRetry(error)) throw error;
      lastError = error;
      if (attempt < options.attempts) {
        await sleep(options.delayMs * 2 ** (attempt - 1));
      }
    }
  }
  throw new RetryError(options.attempts, lastError);
}

// ===== Type tests: don't change these =====
async function typeTests() {
  const n: number = await retry(async () => 5, {
    attempts: 2,
    delayMs: 1,
  });
  // @ts-expect-error: retry resolves with what the task resolves with
  const s: string = await retry(async () => 5, {
    attempts: 2,
    delayMs: 1,
  });
  // @ts-expect-error: attempts is required
  await retry(async () => 1, { delayMs: 10 });
  return [n, s];
}

const waits: number[] = [];
const result = await retry(async (n) => {
  if (n < 3) throw new Error("busy");
  return "delivered on try " + n;
}, { attempts: 5, delayMs: 100, sleep: async (ms) => { waits.push(ms); } });
console.log(result, waits); // delivered on try 3 [ 100, 200 ]
```

The type parameter `T` flows from the task's `Promise<T>` to `retry`'s own result, so callers keep their real types instead of `any`. Errors stay `unknown` all the way through (that's what `catch` gives you), and `RetryError` carries the last one for whoever handles it. With n attempts there are at most n calls and n − 1 waits, and injecting `sleep` makes the timing testable without real delays.

</Solution>
