You often need one column out of an array of objects: all the names, all the ages. Write `pluck(items, key)` that returns a new array with the value of `key` from every item, in order.

```ts
const pandas = [
  { name: "Mei", age: 4 },
  { name: "Bao", age: 7 },
];
pluck(pandas, "name");   // ["Mei", "Bao"]  (type: string[])
pluck(pandas, "age");    // [4, 7]          (type: number[])
pluck(pandas, "colour"); // ❌ compile error: not a property
```

The types are the interesting part:

- `key` must be one of the item's property names (`keyof T`), so a typo is a compile error.
- The result type must follow the key: `"name"` gives `string[]`, `"age"` gives `number[]`. That's what the **indexed access type** `T[K]` describes.

An empty array gives an empty array.

<Hint>

The return type depends on which key you pass: `"name"` gives strings, `"age"` gives numbers. Look at `keyof` and indexed access types like `T[K]`.

</Hint>

<Hint>

Use two type parameters: `T` for the item type and `K extends keyof T` for the key, so a missing property like `"colour"` is an error. The parameters are `items: readonly T[]` and `key: K`, and the return type is `T[K][]`, an array of that one property's type. The body maps each item to `item[key]`.

</Hint>

<Hint>

```ts
function pluck<T, K extends keyof T>(
  items: readonly T[],
  key: K,
): ... { // an array of the property's type
  return items.map(...);
}
```

</Hint>

<Solution>

```ts
function pluck<T, K extends keyof T>(
  items: readonly T[],
  key: K,
): T[K][] {
  return items.map((item) => item[key]);
}

function typeTests() {
  const pandas = [{ name: "Mei", age: 4 }];
  const names: string[] = pluck(pandas, "name");
  const ages: number[] = pluck(pandas, "age");
  // @ts-expect-error: no such property
  pluck(pandas, "colour");
  // @ts-expect-error: ages are numbers, not strings
  const wrong: string[] = pluck(pandas, "age");
}

console.log(pluck([{ name: "Mei", age: 4 }], "name")); // [ 'Mei' ]
```

TypeScript infers `T` from the array and `K` from the key you pass (the literal `"age"`, not just `string`), so `T[K]` resolves to the type of that one property. The constraint `K extends keyof T` is what turns a misspelt key into a compile error.

</Solution>
