Two tiny helpers that every project ends up writing: `first(items)` returns the first item of an array and `last(items)` returns the last one. If the array is empty, both return `undefined`.

The JavaScript part is easy. The TypeScript part is the point: the helpers must work for **any** item type and keep it. `first([3, 1, 2])` has the type `number | undefined`, `first(["bamboo"])` has the type `string | undefined`, and so on. Returning `any` is not allowed: it would switch the checker off for everything that uses the result.

Make both functions generic over the item type `T`, accept a `readonly T[]` (so read-only arrays work too) and return `T | undefined`.

```ts
first([3, 1, 2]);           // 3       (type: number | undefined)
last(["tea", "bamboo"]);    // "bamboo" (type: string | undefined)
first([]);                  // undefined
```

Make `first` and `last` generic so the type tests pass, and return the right items. The `@ts-expect-error` lines are type tests: they pass only when that line **is** an error, so with `any` the starter fails with "Unused '@ts-expect-error' directive."

<Hint>

Declare the type parameter after the function name: `function first<T>(items: readonly T[]): T | undefined`. Inside, `items[0]` and `items[items.length - 1]` give you the items (or `undefined` for an empty array).

</Hint>

<Solution>

```ts
function first<T>(items: readonly T[]): T | undefined {
  return items[0];
}

function last<T>(items: readonly T[]): T | undefined {
  return items[items.length - 1];
}

function typeTests() {
  const scores: readonly number[] = [3, 1, 2];
  const top: number | undefined = first(scores);
  const name: string | undefined = last(["tea", "bamboo"]);
  // @ts-expect-error
  const sure: number = first([1, 2]);
  // @ts-expect-error
  const wrong: string | undefined = last([1, 2]);
}

console.log(first([3, 1, 2])); // 3
```

TypeScript infers `T` from the argument, so `first([3, 1, 2])` returns `number | undefined` without you writing `<number>`. The `| undefined` in the return type is honest: without `noUncheckedIndexedAccess`, `items[0]` is typed as plain `T`, so the annotation is what reminds callers that an empty array has no first item.

</Solution>
