В кафе панды стопкой складывают тарелки, браузер — страницы для кнопки «Назад», а редактор — шаги отмены. Со всеми тремя справится один дженерик (generic) класс. Напишите класс `Stack<T>`:

- `push(...items: T[])` кладёт элементы наверх **по порядку** (последний оказывается сверху) и возвращает новый размер.
- `pop()` снимает и возвращает верхний элемент или `undefined`, если стопка пуста.
- `peek()` возвращает верхний элемент, не снимая его, или `undefined`, если стопка пуста.
- Геттер `size` возвращает количество элементов.
- `toArray()` возвращает копию элементов снизу вверх (изменения копии не затрагивают стопку).
- `static from<U>(items: Iterable<U>): Stack<U>` строит стопку из любого итерируемого объекта (массива, `Set`, строки…); первый элемент оказывается внизу.

Элементы хранятся в `private`-массиве, так что код снаружи класса до них не доберётся. В заготовке везде `any`: строки с `@ts-expect-error` — это тесты типов (type tests), и они проходят, только когда в этой строке **есть** ошибка. С настоящим `T` положить строку в `Stack<number>` — ошибка, и считать, что `pop()` всегда возвращает значение, — тоже.

```ts
const plates = new Stack<string>();
plates.push("blue", "green"); // 2
plates.peek();                // "green"
plates.pop();                 // "green"
plates.size;                  // 1

const letters = Stack.from("abc"); // Stack<string>
letters.toArray();                 // ["a", "b", "c"]
new Stack<number>().pop();         // undefined
```

<Hint>

Напишите `class Stack<T>` и используйте `T` везде, где в заготовке стоит `any`. Массив становится `private items: T[] = [];`. У статического метода свой параметр типа (type parameter), потому что статический член не может использовать `T` класса: `static from<U>(items: Iterable<U>): Stack<U>`.

</Hint>

<Hint>

`Array.from(items)` превращает любой итерируемый объект в массив, а `this.items.at(-1)` читает последний элемент (или `undefined`). Используйте `.length`, а не проверку на истинность, чтобы `0` в стопке тоже считался.

</Hint>

<Solution>

```ts
class Stack<T> {
  private items: T[] = [];

  push(...items: T[]): number {
    this.items.push(...items);
    return this.items.length;
  }

  pop(): T | undefined {
    return this.items.pop();
  }

  peek(): T | undefined {
    return this.items.at(-1);
  }

  get size(): number {
    return this.items.length;
  }

  toArray(): T[] {
    return [...this.items];
  }

  static from<U>(items: Iterable<U>): Stack<U> {
    const stack = new Stack<U>();
    stack.push(...Array.from(items));
    return stack;
  }
}

// ===== Тесты типов: не меняйте их =====
function typeTests() {
  const nums = Stack.from([1, 2, 3]);
  const top: number | undefined = nums.pop();
  // @ts-expect-error: Stack<number> принимает только числа
  nums.push("4");
  // @ts-expect-error: pop() может вернуть undefined
  const sure: number = nums.pop();
  // @ts-expect-error: элементы приватные
  nums.items;
  return [top, sure];
}

const plates = new Stack<string>();
plates.push("blue", "green");
console.log(plates.pop(), plates.size); // green 1
```

Параметр типа `T` связывает все методы класса: какой тип вы положили, такой `pop` и `peek` и вернут (плюс `undefined` для пустой стопки). Статический метод принадлежит самому классу, а не конкретному `Stack<T>`, поэтому `from` объявляет свой `U`, и TypeScript выводит его из аргумента. Все операции работают за O(1), кроме `toArray` и `from` — они O(n).

</Solution>
