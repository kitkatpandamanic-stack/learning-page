Open any modern JavaScript project and you'll see `...`, `?.` and `??` everywhere. You met them briefly in Level 1. Now it's time to really master them, because they're how professional code **copies data without changing it**, **unpacks big objects** in one line and **survives missing data** without crashing. 🧰

Why does this matter so much? In real apps, data flows through many functions: a server sends a user object, one function adds a setting, another renders it. If any of them quietly **changes** (mutates) the shared object, you get bugs that are very hard to track down. The tools in this lesson make it easy to always work on fresh copies instead.

## Spread with arrays

The **spread** syntax `...` takes an array (or anything you can loop over, like a string) and spreads its items out, as if you'd typed them one by one:

<CodeExample output={`[ 'apple', 'kiwi', 'bread', 'carrot' ]
[ 'apple', 'kiwi' ] [ 'apple', 'kiwi', 'mango' ]
95
[ 'p', 'a', 'n', 'd', 'a' ]`}>

```js
const fruits = ["apple", "kiwi"];
const veg = ["carrot"];

const basket = [...fruits, "bread", ...veg];
console.log(basket);

const copy = [...fruits];
copy.push("mango");
console.log(fruits, copy);

const scores = [72, 95, 88];
console.log(Math.max(...scores));
console.log([..."panda"]);
```

</CodeExample>

- `[...a, ...b]` **merges** arrays, and you can put new items anywhere in between.
- `[...fruits]` makes a **copy**, so pushing to `copy` leaves `fruits` alone.
- `Math.max(...scores)` spreads the array into separate **arguments**: it's the same as `Math.max(72, 95, 88)`.

## Spread with objects

With objects, spread copies every property into a new object. This is the standard way to "change" an object without mutating it: copy it and override what's different. When a key appears twice, the **later** one wins:

<CodeExample output={`{ name: 'Mei', theme: 'dark', volume: 5 }
light
{ id: 1, name: 'Mei', theme: 'light', volume: 5 }
light`}>

```js
const user = { name: "Mei", theme: "light", volume: 5 };

const updated = { ...user, theme: "dark" };
console.log(updated);
console.log(user.theme); // the original is untouched

const withId = { id: 1, ...user };
console.log(withId);

const oops = { theme: "dark", ...user }; // order matters!
console.log(oops.theme);
```

</CodeExample>

In `oops`, `theme: "dark"` comes first and then `...user` copies `theme: "light"` over it. Put the spread **first** and your changes **after** it.

In real projects you'll write `{ ...state, something: newValue }` constantly. React, which you'll learn later in this level, is built around exactly this kind of update.

## Rest parameters

**Rest** looks the same (`...`) but does the opposite job: instead of spreading values out, it **collects** them into an array. In a function's parameters, `...numbers` gathers all the arguments into a real array, however many there are:

<CodeExample output={`[ 1, 2 ]
3
[ 5, 10, 15, 20 ]
50
[]
0
Winners: Mei, Sam, Ali`}>

```js
function sum(...numbers) {
  console.log(numbers);
  return numbers.reduce((total, n) => total + n, 0);
}

console.log(sum(1, 2));
console.log(sum(5, 10, 15, 20));
console.log(sum());

function logWithLabel(label, ...values) {
  console.log(`${label}:`, values.join(", "));
}

logWithLabel("Winners", "Mei", "Sam", "Ali");
```

</CodeExample>

In `logWithLabel`, the first argument goes into `label` and **the rest** go into `values`. That's why the rest parameter must always come **last**: `function f(...values, label)` is a `SyntaxError`.

<Callout type="tip" title="Spread or rest? Look at where the dots are">

The three dots mean two opposite things, depending on where they stand:

- **Spread** is where a value is *used*: in an array `[...a]`, an object `{ ...o }` or a function call `f(...args)`. It **unpacks**.
- **Rest** is where a variable is *created*: in parameters `function f(...args)` or destructuring `const [a, ...others] = list`. It **packs**.

</Callout>

## Rest in destructuring

Rest works in destructuring too. For objects, it collects every property you **didn't** name. That gives you a neat way to remove a property without touching the original:

<CodeExample output={`{ id: 7, name: 'Mei', email: 'mei@example.com' }
Mei [ 'Sam', 'Ali' ]`}>

```js
const user = {
  id: 7,
  name: "Mei",
  password: "bamboo123",
  email: "mei@example.com",
};

const { password, ...safeUser } = user;
console.log(safeUser);

const [winner, ...rest] = ["Mei", "Sam", "Ali"];
console.log(winner, rest);
```

</CodeExample>

This pattern is everywhere in back-end code: you load a user from the database, then send `safeUser` to the browser so the password never leaves the server.

## Nested destructuring

Real data is nested: an order has a customer, the customer has an address. Destructuring can follow that shape in one go. You can **rename** (`id: orderId`) and give **defaults** (`postcode = "none"`) at any level:

<CodeExample output={`1042 Mei Chengdu none
Bamboo cup`}>

```js
const order = {
  id: 1042,
  customer: { name: "Mei", address: { city: "Chengdu" } },
  items: [
    { title: "Bamboo cup", price: 8 },
    { title: "Panda mug", price: 12 },
  ],
};

const {
  id: orderId,
  customer: {
    name,
    address: { city, postcode = "none" },
  },
  items: [firstItem],
} = order;

console.log(orderId, name, city, postcode);
console.log(firstItem.title);
```

</CodeExample>

Read `customer: { name }` as *"go into `customer` and take `name` out"*. Note that `customer` itself does **not** become a variable here; only the names at the ends do.

<Callout type="warning" title="Don't go too deep">

Nested destructuring crashes if a level in the middle is missing: if `order.customer` were `undefined`, you'd get a `TypeError`. And a five-level pattern is hard to read. One or two levels is usually the sweet spot; for anything deeper or optional, use optional chaining (below).

</Callout>

### Options objects with defaults

The most useful place for destructuring with defaults is a function's parameters. Instead of five arguments in a fixed order, the function takes one **options object**, and every option has a default:

<CodeExample output={`<button class="medium">Save</button>
<button class="small">OK</button>
<button class="medium">OK</button>`}>

```js
function createButton({ label = "OK", size = "medium" } = {}) {
  return `<button class="${size}">${label}</button>`;
}

console.log(createButton({ label: "Save" }));
console.log(createButton({ size: "small" }));
console.log(createButton());
```

</CodeExample>

The `= {}` at the end is the default for the **whole** object, so calling `createButton()` with nothing still works. Callers only pass what they want to change, in any order, and the call reads clearly: `createButton({ size: "small" })` says exactly what it means. Many libraries you'll use (`fetch`, Express, Vitest) take options objects like this.

## Optional chaining in depth

You know `user.address?.city`: if the part before `?.` is `null` or `undefined`, the whole expression stops and gives `undefined` instead of crashing. It has two more forms, for brackets and for calling functions:

<CodeExample output={`Sam
undefined
Hi!
undefined`}>

```js
const data = {
  user: { name: "Mei", friends: ["Sam", "Ali"] },
  greet() {
    return "Hi!";
  },
};
const empty = {};

console.log(data.user?.friends?.[0]);
console.log(empty.user?.friends?.[0]);
console.log(data.greet?.());
console.log(empty.greet?.());
```

</CodeExample>

- `obj?.prop` reads a property.
- `obj?.[key]` reads with brackets: array items or a key in a variable.
- `fn?.()` calls a function **only if it exists**. Handy for optional callbacks like `options.onDone?.()`.

Use `?.` where data is **allowed** to be missing (an optional field from an API, say). Don't sprinkle it everywhere: if something should always be there, a loud crash tells you about the bug much sooner than a quiet `undefined`.

## ?? versus ||

To give a fallback value, people used to write `value || "default"`. The trouble is that `||` falls back for **every** falsy value, including `0`, `""` and `false`, which are often perfectly good answers. The **nullish coalescing** operator `??` only falls back for `null` and `undefined`:

<CodeExample output={`50
0
"Anonymous"
""
false
default`}>

```js
const settings = { volume: 0, nickname: "", darkMode: false };

console.log(settings.volume || 50); // 😬 the user chose 0!
console.log(settings.volume ?? 50);

console.log(JSON.stringify(settings.nickname || "Anonymous"));
console.log(JSON.stringify(settings.nickname ?? "Anonymous"));

console.log(settings.darkMode ?? true);
console.log(settings.missing ?? "default");
```

</CodeExample>

The user turned the volume down to `0`, and `||` threw that choice away. With `??` the `0` is kept. As a rule of thumb, use `??` for defaults, and keep `||` for real *"either this or that"* logic. (`JSON.stringify` is only there to make the empty string `""` visible.)

There's also an assignment version, `??=`, which sets a variable only if it's currently `null` or `undefined`: `options.retries ??= 3`.

## Shallow copies and structuredClone

Spread makes a **shallow** copy: it copies the top level only. Nested arrays and objects are still **shared** between the copy and the original. Watch what happens:

<CodeExample output={`{
  name: 'Mei',
  tags: [ 'admin', 'editor' ],
  address: { city: 'Paris' }
}`}>

```js
const original = {
  name: "Mei",
  tags: ["admin"],
  address: { city: "Chengdu" },
};

const shallow = { ...original };
shallow.name = "Sam";
shallow.tags.push("editor");
shallow.address.city = "Paris";

console.log(original);
```

</CodeExample>

The name is safe (strings are copied), but `tags` and `address` changed in the **original** too, because both objects point to the same inner array and object. There are two fixes:

1. Copy every level you change, as in `{ ...user, settings: { ...user.settings, volume: 3 } }`. This is what you'll do most of the time.
2. Make a **deep** copy with the built-in `structuredClone`, which copies every level:

<CodeExample output={`[ 'admin' ] Chengdu
[ 'admin', 'editor' ] Paris
true`}>

```js
const original = {
  name: "Mei",
  tags: ["admin"],
  address: { city: "Chengdu" },
  joined: new Date("2024-05-01"),
};

const deep = structuredClone(original);
deep.tags.push("editor");
deep.address.city = "Paris";

console.log(original.tags, original.address.city);
console.log(deep.tags, deep.address.city);
console.log(deep.joined instanceof Date);
```

</CodeExample>

<Callout type="note" title="What structuredClone can't copy">

`structuredClone` handles plain objects, arrays, dates, Maps, Sets and more. It can't copy **functions**, and class instances come back as plain objects without their methods:

```js
structuredClone({ greet() {} });
// DataCloneError: greet() {} could not be cloned.
```

You might also see the old trick `JSON.parse(JSON.stringify(obj))`. It works for simple data but turns dates into strings and drops `undefined` values, so prefer `structuredClone`.

</Callout>

<Hint>

1. `const { password, ...rest } = user;` then return `rest`.
2. Combine `?.` (in case `settings` is missing) with `??` (so `0` is kept).
3. Spread at two levels: `{ ...user, settings: { ...user.settings, ...changes } }`.

<Solution>

```js
const user = {
  id: 7,
  name: "Mei",
  password: "bamboo123",
  settings: { theme: "light", volume: 0 },
};

function withoutPassword(user) {
  const { password, ...rest } = user;
  return rest;
}

function getVolume(user) {
  return user.settings?.volume ?? 50;
}

function updateSettings(user, changes) {
  return {
    ...user,
    settings: { ...user.settings, ...changes },
  };
}

function total(...prices) {
  return prices.reduce((sum, price) => sum + price, 0);
}

console.log(withoutPassword(user));
console.log(getVolume(user));            // 0
console.log(getVolume({ name: "Sam" })); // 50
console.log(updateSettings(user, { theme: "dark" }));
console.log(user.settings.theme);        // still "light"
console.log(total(4, 10, 6));            // 20
```

</Solution>

## Recap

- **Spread** `...` unpacks: `[...a, ...b]` merges arrays, `{ ...obj, key: value }` copies an object with changes (later keys win), `f(...args)` passes array items as arguments.
- **Rest** `...` packs: `function f(...args)` collects arguments into an array, and `const { password, ...rest } = user` collects the leftover properties.
- Destructuring can go **nested**, with renaming (`id: orderId`) and defaults (`size = "medium"`). Options objects with defaults make functions easy to call.
- `?.` works as `obj?.prop`, `obj?.[key]` and `fn?.()`. Use it where data is allowed to be missing.
- Use `??` for defaults: unlike `||`, it keeps `0`, `""` and `false`.
- Spread copies are **shallow**. Copy each level you change, or use `structuredClone` for a deep copy.
