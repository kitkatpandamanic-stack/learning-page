В JavaScript функция — это **значение (value)**, такое же, как число или массив. Её можно сохранить в переменной, передать в другую функцию и даже вернуть из функции. Добавьте к этому **замыкания (closures)** — функции, которые помнят, где они родились, — и вы получите одни из самых мощных приёмов языка: приватные данные, кэширование и трюк debounce, который не даёт поисковой строке завалить сервер запросами. 🔒

Вы уже пользовались этими идеями, просто не называли их: каждый вызов `map`, `filter` и `addEventListener` принимает функцию в качестве аргумента. В этом уроке вы научитесь писать такие инструменты сами.

## Функции — это значения

Функция может жить в переменной или в свойстве объекта, а ещё её можно передать другой функции, чтобы та вызвала её позже:

<CodeExample output={`ПРИВЕТ!
время панды...
function`}>

```js
const shout = (text) => text.toUpperCase() + "!";
const whisper = (text) => text.toLowerCase() + "...";

const voices = { shout, whisper };
console.log(voices.shout("привет"));

function speak(text, voice) {
  return voice(text);
}

console.log(speak("Время панды", whisper));
console.log(typeof shout);
```

</CodeExample>

Заметьте: `speak("Время панды", whisper)` передаёт `whisper` **без** скобок. `whisper` — это сама функция, а `whisper("Привет")` вызвала бы её сразу и передала бы вместо неё *результат*. Путать эти две записи — одна из самых частых ошибок новичков. Например, `button.addEventListener("click", save())` запускает `save` сразу, а не по клику.

## Функции высшего порядка

Функция, которая **принимает** функцию в качестве аргумента или **возвращает** её, называется **функцией высшего порядка (higher-order function)**. `map` и `filter` — функции высшего порядка, и никакой магии в них нет. Вот как их можно написать самостоятельно:

<CodeExample output={`[ 10, 24, 60 ]
[ 12, 30 ]`}>

```js
function myMap(array, transform) {
  const result = [];
  for (const item of array) {
    result.push(transform(item));
  }
  return result;
}

function myFilter(array, keep) {
  const result = [];
  for (const item of array) {
    if (keep(item)) result.push(item);
  }
  return result;
}

const prices = [5, 12, 30];
console.log(myMap(prices, (p) => p * 2));
console.log(myFilter(prices, (p) => p > 10));
```

</CodeExample>

Цикл написан **один раз**, а часть, которая меняется (*что* делать с каждым элементом), передаётся в виде функции. В этом и весь смысл функций высшего порядка: они отделяют скучный повторяющийся механизм от интересной части.

## Функции, которые возвращают функции

Функция может ещё и **создать** новую функцию и вернуть её. Здесь `multiplyBy` — маленькая фабрика функций:

<CodeExample output={`10
15
[ 3, 6, 9 ]
40`}>

```js
function multiplyBy(factor) {
  return (n) => n * factor;
}

const double = multiplyBy(2);
const triple = multiplyBy(3);

console.log(double(5));
console.log(triple(5));
console.log([1, 2, 3].map(triple));
console.log(multiplyBy(10)(4));
```

</CodeExample>

`multiplyBy(2)` возвращает стрелочную функцию `(n) => n * factor`. Но постойте: к моменту вызова `double(5)` функция `multiplyBy` уже завершилась. Откуда возвращённая функция всё ещё знает, что `factor` равен `2`?

## Замыкания

Когда функция создаётся, она сохраняет связь с переменными вокруг себя. Даже после того как внешняя функция вернула результат, внутренняя по-прежнему может читать **и менять** эти переменные. Функция вместе с переменными, которые она помнит, называется **замыканием (closure)**.

Поэтому замыкания идеально подходят для состояния, которое должно сохраняться между вызовами:

<CodeExample output={`1
2
3
1
4`}>

```js
function makeCounter() {
  let count = 0;
  return () => {
    count += 1;
    return count;
  };
}

const clicks = makeCounter();
console.log(clicks());
console.log(clicks());
console.log(clicks());

const likes = makeCounter(); // совершенно новый count
console.log(likes());
console.log(clicks());
```

</CodeExample>

Каждый вызов `makeCounter()` создаёт **новую** переменную `count` и новую функцию, которая её помнит. Поэтому у `clicks` и `likes` свои собственные счётчики, и они никогда не мешают друг другу.

<Callout type="note" title="Замыкание помнит переменные, а не значения">

Внутренняя функция не делает снимок `count` в момент создания. Она держится за **саму переменную**, поэтому всегда видит последнее значение, а её изменения сохраняются до следующего раза. Вот почему `clicks()` продолжает считать дальше.

</Callout>

## Приватное состояние

Никто снаружи `makeCounter` не может добраться до `count` напрямую: единственный способ — через функцию, которую вы вернули. Это делает замыкания простым способом держать данные **приватными**. Верните объект из функций — и у вас получится маленький модуль с контролируемым публичным интерфейсом:

<CodeExample output={`12
undefined
Недостаточно денег`}>

```js
function createWallet(start = 0) {
  let balance = start; // приватно: его видят только эти функции

  return {
    deposit(amount) {
      if (amount <= 0) throw new Error("Сумма должна быть положительной");
      balance += amount;
    },
    spend(amount) {
      if (amount > balance) throw new Error("Недостаточно денег");
      balance -= amount;
    },
    getBalance() {
      return balance;
    },
  };
}

const wallet = createWallet(10);
wallet.deposit(5);
wallet.spend(3);
console.log(wallet.getBalance());
console.log(wallet.balance); // снаружи недоступно

try {
  wallet.spend(100);
} catch (error) {
  console.log(error.message);
}
```

</CodeExample>

Изменить `balance` можно только через `deposit` и `spend`, которые сначала проверяют правила. Никто не сможет написать `wallet.balance = 1000000`. Это решает ту же задачу, что и приватные поля классов `#private`, с которыми вы познакомились на Уровне 1, и в реальном коде вы встретите оба стиля.

## Полезные обёртки: once и memoize

Функции высшего порядка особенно хороши в роли **обёрток (wrappers)**: вы даёте им функцию и получаете обратно её улучшенную версию. Две классические обёртки — `once`, которая гарантирует, что функция выполнится только один раз, и `memoize`, которая запоминает результаты, чтобы медленная работа не повторялась.

`once` пригодится для кода настройки, который нельзя запускать дважды, — например, для подключения к базе данных или показа приветственного тура:

<CodeExample output={`Готовим всё для Mei...
Готово, Mei!
Готово, Mei!`}>

```js
function once(fn) {
  let called = false;
  let result;
  return (...args) => {
    if (!called) {
      called = true;
      result = fn(...args);
    }
    return result;
  };
}

const setUp = once((name) => {
  console.log(`Готовим всё для ${name}...`);
  return `Готово, ${name}!`;
});

console.log(setUp("Mei"));
console.log(setUp("Sam")); // fn больше не запускается
```

</CodeExample>

Обёртка принимает любые аргументы через rest (`...args`) и передаёт их дальше через spread (`fn(...args)`), поэтому работает с **любой** функцией.

**Мемоизация (memoizing)** — это кэширование результатов функции по аргументу. Кэш живёт в замыкании, поэтому сохраняется между вызовами, но остаётся скрытым:

<CodeExample output={`Усердно считаем 9...
81
(из кэша: 9)
81
Усердно считаем 4...
16`}>

```js
function memoize(fn) {
  const cache = {};
  return (n) => {
    if (n in cache) {
      console.log(`(из кэша: ${n})`);
      return cache[n];
    }
    const result = fn(n);
    cache[n] = result;
    return result;
  };
}

function slowSquare(n) {
  console.log(`Усердно считаем ${n}...`);
  return n * n;
}

const fastSquare = memoize(slowSquare);
console.log(fastSquare(9));
console.log(fastSquare(9));
console.log(fastSquare(4));
```

</CodeExample>

Мемоизация имеет смысл только для **чистых (pure)** функций — тех, что для одних и тех же входных данных всегда возвращают один и тот же результат и больше ничего не меняют. Мемоизация «получить текущее время» или «загрузить последние сообщения» давала бы устаревшие ответы. (В следующем уроке вы познакомитесь с `Map`, который служит кэшем даже лучше обычного объекта.)

## Идея debounce

Представьте поисковую строку, которая запрашивает у сервера результаты при каждом нажатии клавиши. Набор слова «panda» отправил бы пять запросов, а важен только последний. **Debounce** (подавление дребезга) ждёт, пока вызовы на мгновение *прекратятся*, а затем запускает функцию один раз с последними аргументами:

<CodeExample output={`Сделано 4 вызова
Ищем "panda"`}>

```js
function debounce(fn, ms) {
  let timer;
  return (...args) => {
    clearTimeout(timer); // отменяем предыдущее ожидание
    timer = setTimeout(() => fn(...args), ms);
  };
}

const search = debounce((text) => {
  console.log(`Ищем "${text}"`);
}, 200);

// Кто-то быстро печатает: p, pa, pan, panda
search("p");
search("pa");
search("pan");
search("panda");
console.log("Сделано 4 вызова");
```

</CodeExample>

Переменная `timer` живёт в замыкании и общая для всех вызовов. Каждый вызов отменяет предыдущий таймер и запускает новый, поэтому 200 мс ожидания переживает только последний вызов. На реальной странице вы бы написали `input.addEventListener("input", debounce(runSearch, 300))`. В реальных проектах часто импортируют готовый, хорошо протестированный `debounce` из библиотеки вроде Lodash, но теперь вы знаете, что внутри никакой магии нет.

## Классическая ошибка с var в цикле

Замыкания объясняют одну из самых знаменитых головоломок JavaScript. В старом коде вместо `let` используется `var`, а `var` **не** ограничен блоком: на весь цикл приходится одна-единственная `i`. Здесь таймеры срабатывают уже после того, как циклы закончились:

<CodeExample output={`var: 4
var: 4
var: 4
let: 1
let: 2
let: 3`}>

```js
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(`var: ${i}`), 10);
}

for (let j = 1; j <= 3; j++) {
  setTimeout(() => console.log(`let: ${j}`), 20);
}
```

</CodeExample>

Все три колбэка с `var` замыкаются на **одну и ту же** `i`, и к моменту их запуска цикл уже довёл её до `4`. С `let` каждый проход цикла получает **свежую** `j`, поэтому каждый колбэк помнит своё значение.

<Callout type="warning" title="Используйте let и const, а не var">

`var` по-прежнему допустим в JavaScript, поэтому вы встретите его в старых руководствах и ответах на Stack Overflow. Но он «вытекает» из блоков и вызывает ошибки вроде этой. В своём коде по умолчанию используйте `const`, а `let` — когда переменная должна меняться. Линтеры вроде ESLint могут подсветить каждый `var` за вас (правило `no-var`).

</Callout>

Соберите небольшой набор помощников на замыканиях:

1. `createCounter(start = 0, step = 1)` возвращает объект с тремя методами. `next()` прибавляет `step` к счётчику и возвращает новое значение, `reset()` возвращает счётчик к `start` и возвращает его, а `value()` возвращает текущее значение. Счётчик остаётся приватным (у объекта есть только эти методы).
2. `once(fn)` возвращает функцию, которая при **первом** вызове вызывает `fn` со своими аргументами, а при всех следующих возвращает тот первый результат, больше не вызывая `fn`.
3. `memoize(fn)` принимает функцию с одним аргументом и возвращает версию, которая запоминает результаты, так что `fn` выполняется только один раз для каждого нового аргумента. Каждой мемоизированной функции нужен **собственный** кэш.

Сейчас `once` и `memoize` просто возвращают `fn` без изменений, поэтому она запускается при каждом вызове.

<Hint>

1. Методы могут читать и менять `count`, потому что замыкаются на него: `count += step; return count;`.
2. Заведите `let called = false;` и `let result;` внутри `once` и верните `(...args) => { ... }`, которая вызывает `fn(...args)`, только пока `called` равно `false`.
3. Создайте `const cache = {};` **внутри** `memoize` (а не снаружи, иначе все мемоизированные функции делили бы один кэш). Перед вызовом `fn` проверьте `arg in cache`.

</Hint>

<Solution>

```js
function createCounter(start = 0, step = 1) {
  let count = start; // приватно: его видят только методы ниже
  return {
    next() {
      count += step;
      return count;
    },
    reset() {
      count = start;
      return count;
    },
    value() {
      return count;
    },
  };
}

function once(fn) {
  let called = false;
  let result;
  return (...args) => {
    if (!called) {
      called = true;
      result = fn(...args);
    }
    return result;
  };
}

function memoize(fn) {
  const cache = {};
  return (arg) => {
    if (!(arg in cache)) {
      cache[arg] = fn(arg);
    }
    return cache[arg];
  };
}

const tickets = createCounter(100, 10);
console.log(tickets.next());  // 110
console.log(tickets.next());  // 120
console.log(tickets.reset()); // 100

const greet = once((name) => `Добро пожаловать, ${name}!`);
console.log(greet("Mei")); // Добро пожаловать, Mei!
console.log(greet("Sam")); // Добро пожаловать, Mei!

const square = memoize((n) => {
  console.log(`Считаем ${n}...`);
  return n * n;
});
console.log(square(7)); // Считаем 7..., затем 49
console.log(square(7)); // 49 (без подсчёта)
```

</Solution>

## Итоги

- Функции — это **значения**: их можно сохранять, передавать (`speak(text, whisper)`, без скобок) и возвращать.
- **Функция высшего порядка** принимает или возвращает функцию. `map` и `filter` — это просто циклы, в которые передана меняющаяся часть.
- **Замыкание** — это функция плюс переменные, которые она помнит с места своего создания. Она хранит сами переменные, поэтому видит и сохраняет изменения.
- Замыкания дают **приватное состояние**: `makeCounter` и `createWallet` прячут свои данные за возвращаемыми функциями.
- Обёртки вроде `once`, `memoize` и `debounce` принимают функцию и возвращают улучшенную; `(...args) => fn(...args)` пропускает любые аргументы дальше.
- `var` делит одну переменную на весь цикл, и это ломает замыкания. Используйте `let` и `const`.
