Массивы и объекты могут хранить почти что угодно, но не всегда это лучший инструмент. Подсчёт слов с помощью объекта преподносит странные сюрпризы, а удаление дубликатов из массива требует больше кода, чем хотелось бы. Для этих задач в JavaScript есть две специальные коллекции — **Map** и **Set**. А когда вы поймёте, как на самом деле работает `for...of`, вы сможете делать **свои собственные** объекты перебираемыми с помощью **генераторов (generators)** — включая последовательности, которые никогда не заканчиваются. ♾️

## Map: настоящее хранилище «ключ — значение»

Ключи объекта (object) — всегда **строки** (или символы). Всё остальное, что вы используете как ключ, тихо превращается в строку. А **Map** хранит ключи ровно такими, какие они есть:

<CodeExample output={`[ '1', 'true' ]
Map(3) { 1 => 'один', '1' => 'строка один', true => 'да' }
один | строка один`}>

```js
const scores = {};
scores[1] = "один";
scores[true] = "да";
console.log(Object.keys(scores));

const map = new Map();
map.set(1, "один");
map.set("1", "строка один");
map.set(true, "да");
console.log(map);
console.log(map.get(1), "|", map.get("1"));
```

</CodeExample>

Объект превратил `1` и `true` в строки `'1'` и `'true'`. А Map хранит число `1` и строку `"1"` как два разных ключа.

### Работа с Map

Вместо точек и квадратных скобок у Map свои методы: `set`, `get`, `has`, `delete`, а ещё свойство `size`. Map можно создать из массива пар `[ключ, значение]`, а `for...of` возвращает эти пары **в том порядке, в котором вы их добавляли**:

<CodeExample output={`3
true false
0
apples: 8
milk: 2`}>

```js
const stock = new Map([
  ["apples", 3],
  ["bread", 1],
]);

stock.set("milk", 2);
stock.set("apples", stock.get("apples") + 5);

console.log(stock.size);
console.log(stock.has("bread"), stock.has("eggs"));
console.log(stock.get("eggs") ?? 0);

stock.delete("bread");

for (const [item, count] of stock) {
  console.log(`${item}: ${count}`);
}
```

</CodeExample>

Для отсутствующего ключа `get` возвращает `undefined`, поэтому `?? 0` из первого урока даёт аккуратное значение по умолчанию. Если нужна только одна сторона, используйте `stock.keys()`, `stock.values()` и `stock.entries()`.

### Объекты в роли ключей

А вот чего обычные объекты просто не умеют. Map может использовать в качестве ключа **любое значение, даже другой объект**:

<CodeExample output={`3
{ '[object Object]': 1 }`}>

```js
const mei = { name: "Mei" };
const sam = { name: "Sam" };

const visits = new Map();
visits.set(mei, 3);
visits.set(sam, 1);
console.log(visits.get(mei));

const asObject = {};
asObject[mei] = 3;
asObject[sam] = 1;
console.log(asObject);
```

</CodeExample>

Вариант с объектом превратил обоих пользователей в одну и ту же строку `'[object Object]'`, поэтому счётчик Sam перезаписал счётчик Mei. Map держит их раздельно.

### Преобразование между объектами и Map

<CodeExample output={`Map(3) { 'tea' => 3, 'cake' => 4, 'scone' => 2.5 }
{ tea: 3, cake: 4, scone: 2.5 }
{}`}>

```js
const prices = { tea: 3, cake: 4 };

const priceMap = new Map(Object.entries(prices));
priceMap.set("scone", 2.5);

console.log(priceMap);
console.log(Object.fromEntries(priceMap));
console.log(JSON.stringify(priceMap)); // 😬
```

</CodeExample>

`JSON.stringify` не понимает Map и молча выдаёт `{}`. Перед сохранением в `localStorage` или отправкой на сервер преобразуйте Map через `Object.fromEntries(map)`.

<Callout type="tip" title="Map или объект?">

Используйте **объект** для *записи* с фиксированными, заранее известными полями — например, для пользователя с `name` и `email`, особенно если он потом станет JSON. Используйте **Map** для *коллекции*, в которую ключи добавляются и удаляются во время работы программы: счётчики, кэши, поиск по id. Map создан для частого добавления и удаления, у него есть `size`, он сохраняет порядок вставки и принимает любые ключи. Помните `memoize` из прошлого урока? Его кэш лучше было бы сделать через `new Map()`.

</Callout>

## Set: уникальные значения

**Set** (множество) — это коллекция, в которой каждое значение может встречаться только **один раз**. Добавление того, что там уже есть, ничего не делает. Поэтому удалить дубликаты можно одной строкой:

<CodeExample output={`Set(3) { 'mei', 'sam', 'ali' }
3
[ 'mei', 'sam', 'ali' ]
true false`}>

```js
const visitors = ["mei", "sam", "mei", "ali", "sam", "mei"];

const unique = new Set(visitors);
console.log(unique);
console.log(unique.size);
console.log([...unique]);

unique.add("zoe");
unique.add("mei"); // уже есть: игнорируется
console.log(unique.has("zoe"), unique.has("bob"));
```

</CodeExample>

`[...new Set(array)]` — стандартный способ убрать дубликаты из массива. А `set.has(value)` на больших списках работает гораздо быстрее, чем `array.includes(value)`, потому что Set не нужно просматривать каждый элемент.

Вместе со spread и `filter` множества позволяют легко сравнивать две группы:

<CodeExample output={`[ 'js' ]
Set(4) { 'js', 'css', 'html', 'python' }
[ 'css', 'html' ]`}>

```js
const mine = new Set(["js", "css", "html"]);
const yours = new Set(["js", "python"]);

const both = [...mine].filter((tag) => yours.has(tag));
const either = new Set([...mine, ...yours]);
const onlyMine = [...mine].filter((tag) => !yours.has(tag));

console.log(both);
console.log(either);
console.log(onlyMine);
```

</CodeExample>

<Callout type="note" title="Новые методы Set">

В браузерах начиная с 2024 года (и в Node 22+) такие сравнения встроены, поэтому в свежем коде вы можете их встретить:

```js
mine.intersection(yours); // Set(1) { 'js' }
mine.union(yours);        // Set(4) { 'js', 'css', 'html', 'python' }
mine.difference(yours);   // Set(2) { 'css', 'html' }
```

Если вашему приложению нужно поддерживать старые браузеры, варианты со spread и `filter` выше работают везде.

</Callout>

## Коротко о WeakMap

**WeakMap** — это особый Map, ключами которого могут быть только **объекты**, и держит он их «слабо»: если объект больше нигде в программе не используется, его можно удалить из памяти, и запись в WeakMap исчезнет вместе с ним. Поэтому WeakMap — безопасное место, чтобы прикрепить дополнительные данные к чужим объектам, не вызывая утечки памяти:

<CodeExample output={`{ clicks: 1 }
true`}>

```js
const metadata = new WeakMap();

let button = { label: "Сохранить" };
metadata.set(button, { clicks: 0 });
metadata.get(button).clicks += 1;

console.log(metadata.get(button));
console.log(metadata.has(button));

button = null; // теперь объект может удалить сборщик мусора,
// и его запись в WeakMap исчезнет вместе с ним
```

</CodeExample>

Плата за это — у WeakMap нет `size`, и его нельзя перебрать в цикле. В повседневном коде он вам понадобится редко, но библиотеки используют WeakMap для кэшей, привязанных к DOM-элементам или объектам. (Есть и парный ему **WeakSet**.)

## Как на самом деле работает for...of

`for...of` работает с массивами, строками, Map и Set, но **не** с обычными объектами. Spread и деструктуризация массивов подчиняются тому же правилу:

<CodeExample output={`h
e
y
1
2
a b
9
TypeError: panda is not iterable`}>

```js
for (const letter of "hey") console.log(letter);
for (const n of new Set([1, 2])) console.log(n);

const [first, second] = new Set(["a", "b", "c"]);
console.log(first, second);
console.log(Math.max(...new Set([4, 9, 2])));

const panda = { name: "Bao", age: 4 };
try {
  for (const value of panda) console.log(value);
} catch (error) {
  console.log(`${error.name}: ${error.message}`);
}
```

</CodeExample>

Значения, с которыми это работает, называются **перебираемыми (iterables)**. У перебираемого значения есть особый метод, хранящийся под ключом `Symbol.iterator`, который выдаёт **итератор (iterator)** — объект с методом `next()`. Каждый вызов `next()` возвращает следующее значение и признак того, закончилась ли последовательность (`done`). Это соглашение называется **протоколом итерации (iteration protocol)**, и его можно выполнить вручную:

<CodeExample output={`{ value: 'red', done: false }
{ value: 'green', done: false }
{ value: undefined, done: true }`}>

```js
const colours = ["red", "green"];
const iterator = colours[Symbol.iterator]();

console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());
```

</CodeExample>

Вот и всё, что `for...of` делает за кулисами: снова и снова вызывает `next()`, пока `done` не станет `true`. Поэтому **всё**, что следует протоколу, можно перебирать в цикле, раскладывать через spread и деструктурировать. Чтобы перебрать обычный объект, сначала превратите его в перебираемое значение с помощью `Object.entries(obj)`, `Object.keys(obj)` или `Object.values(obj)`.

## Генераторы

Писать методы `next()` вручную муторно. **Функция-генератор (generator function)** сделает эту работу за вас. Её объявляют со звёздочкой, `function*`, а внутри используют `yield`, чтобы выдавать значения по одному:

<CodeExample output={`Старт!
{ value: 3, done: false }
{ value: 2, done: false }
1
Поехали!`}>

```js
function* countdown(from) {
  console.log("Старт!");
  for (let n = from; n > 0; n--) {
    yield n;
  }
  console.log("Поехали!");
}

const launch = countdown(3);
console.log(launch.next());
console.log(launch.next());

for (const n of launch) {
  console.log(n);
}
```

</CodeExample>

Присмотритесь к порядку:

1. Вызов `countdown(3)` пока **не** выполняет ни строчки её кода. Он просто возвращает итератор (**объект-генератор**, generator object).
2. Каждый `next()` выполняет функцию до следующего `yield`, выдаёт это значение и **ставится на паузу** прямо там, запоминая все свои переменные.
3. Цикл `for...of` продолжает с того места, где мы остановились (`1`), а когда функция заканчивается, `done` становится `true`, и цикл останавливается.

Главная новая идея здесь — функция, которая может остановиться посередине и продолжить позже. Это ещё и отличная разминка перед следующим модулем, где `await` тоже ставит функции на паузу.

### Делаем свои объекты перебираемыми

Поместите метод-генератор под ключ `Symbol.iterator`, и ваш собственный класс заработает с `for...of` и spread:

<CodeExample output={`♪ Bamboo Blues
♪ Panda Pop
2`}>

```js
class Playlist {
  #songs = [];

  add(song) {
    this.#songs.push(song);
    return this;
  }

  *[Symbol.iterator]() {
    for (const song of this.#songs) {
      yield `♪ ${song}`;
    }
  }
}

const mix = new Playlist().add("Bamboo Blues").add("Panda Pop");

for (const track of mix) {
  console.log(track);
}
console.log([...mix].length);
```

</CodeExample>

Песни остаются приватными, но перебрать плейлист может кто угодно. `*[Symbol.iterator]() { ... }` — это просто генератор, записанный как метод с вычисляемым именем.

## Ленивые последовательности

Поскольку генератор встаёт на паузу после каждого `yield`, он вычисляет **следующее** значение, только когда его кто-то попросит. Это называется **ленивостью (lazy evaluation)**, и благодаря ей генератор может описывать последовательность, которая **никогда не заканчивается**, — если брать из неё только часть:

<CodeExample output="[ 2, 4, 6, 8, 10 ]">

```js
function* naturals() {
  let n = 1;
  while (true) {
    yield n;
    n++;
  }
}

function* take(iterable, count) {
  if (count <= 0) return;
  for (const item of iterable) {
    yield item;
    count--;
    if (count === 0) return;
  }
}

function* filter(iterable, keep) {
  for (const item of iterable) {
    if (keep(item)) yield item;
  }
}

const evens = filter(naturals(), (n) => n % 2 === 0);
console.log([...take(evens, 5)]);
```

</CodeExample>

`while (true)` выглядит пугающе, но это безопасно: `naturals` встаёт на паузу на каждом `yield`. `filter` забирает из него числа, только когда об этом просит `take`, а `take` останавливается после пяти. Всего создаётся лишь десять чисел. А вот `[...naturals()]` сам по себе *действительно* работал бы вечно, потому что spread продолжает запрашивать значения, пока не получит `done`.

В реальных проектах ленивые последовательности полезны, например, для построчного чтения огромного файла, постраничного обхода результатов API или генерации id — там, где строить весь массив заранее было бы расточительно по памяти или вообще невозможно.

<Callout type="warning" title="Генератор можно использовать только один раз">

Объект-генератор — это итератор, и если он закончился, то закончился навсегда. В примере с обратным отсчётом второй `for...of` по `launch` ничего бы не вывел. Чтобы начать заново, снова вызовите функцию-генератор и получите свежий генератор: `countdown(3)`. (Playlist можно перебирать много раз, потому что каждый цикл вызывает `[Symbol.iterator]()` и получает новый генератор.)

</Callout>

В новом JavaScript (с 2025 года) появились ещё и **вспомогательные методы итераторов (iterator helpers)**, так что вам могут встретиться цепочки вроде этой — они делают то же самое, что наши `filter` и `take`:

```js
naturals().filter((n) => n % 2 === 0).take(5).toArray();
// [ 2, 4, 6, 8, 10 ]
```

</Hint>

<Solution>

```js
const posts = [
  { title: "Трюки со spread", tags: ["js", "beginner"] },
  { title: "Замыкания", tags: ["js", "functions"] },
  { title: "CSS Grid", tags: ["css", "beginner"] },
];

function uniqueTags(posts) {
  const tags = new Set();
  for (const post of posts) {
    for (const tag of post.tags) {
      tags.add(tag);
    }
  }
  return [...tags].sort();
}

function countWords(text) {
  const counts = new Map();
  for (const word of text.toLowerCase().split(" ")) {
    counts.set(word, (counts.get(word) ?? 0) + 1);
  }
  return counts;
}

function* chunk(iterable, size) {
  let batch = [];
  for (const item of iterable) {
    batch.push(item);
    if (batch.length === size) {
      yield batch;
      batch = [];
    }
  }
  if (batch.length > 0) {
    yield batch;
  }
}
```

## Итоги

- **Map** хранит пары «ключ — значение» с ключами любого типа (даже объектами), сохраняет порядок вставки и умеет `set`, `get`, `has`, `delete` и `size`. Преобразуйте через `new Map(Object.entries(obj))` и `Object.fromEntries(map)`; `JSON.stringify` с Map не справляется.
- Используйте объекты для записей с фиксированными полями, а Map — для растущих коллекций вроде счётчиков и кэшей.
- **Set** хранит уникальные значения: `[...new Set(array)]` убирает дубликаты, а `has` быстро проверяет, есть ли элемент.
- **WeakMap** прикрепляет данные к объектам, не удерживая их в памяти.
- `for...of`, spread и деструктуризация массивов работают с любым **перебираемым значением** — чем-то с методом `[Symbol.iterator]()`, который возвращает итератор с `next()`.
- **Генератор** (`function*` с `yield`) встаёт на паузу на каждом `yield` и продолжает при следующем `next()`. С ним легко писать итераторы и строить **ленивые**, даже бесконечные, последовательности.
