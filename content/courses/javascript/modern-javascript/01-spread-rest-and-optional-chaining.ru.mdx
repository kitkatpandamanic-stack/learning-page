Откройте любой современный проект на JavaScript, и вы повсюду увидите `...`, `?.` и `??`. Вы уже мельком встречали их на Уровне 1. Теперь пора освоить их по-настоящему: именно так профессиональный код **копирует данные, не меняя их**, **распаковывает большие объекты** одной строкой и **не падает, когда данных нет**. 🧰

Почему это так важно? В реальных приложениях данные проходят через множество функций: сервер присылает объект пользователя, одна функция добавляет настройку, другая его отрисовывает. Если какая-то из них тихо **изменит** (мутирует) общий объект, появятся ошибки, которые очень трудно отследить. Инструменты из этого урока помогают всегда работать со свежими копиями.

## Spread с массивами

Синтаксис **spread** (оператор расширения) `...` берёт массив (или что угодно, что можно перебрать в цикле, например строку) и «раскладывает» его элементы, как будто вы написали их по одному:

<CodeExample output={`[ 'apple', 'kiwi', 'bread', 'carrot' ]
[ 'apple', 'kiwi' ] [ 'apple', 'kiwi', 'mango' ]
95
[ 'p', 'a', 'n', 'd', 'a' ]`}>

```js
const fruits = ["apple", "kiwi"];
const veg = ["carrot"];

const basket = [...fruits, "bread", ...veg];
console.log(basket);

const copy = [...fruits];
copy.push("mango");
console.log(fruits, copy);

const scores = [72, 95, 88];
console.log(Math.max(...scores));
console.log([..."panda"]);
```

</CodeExample>

- `[...a, ...b]` **объединяет** массивы, а новые элементы можно вставить где угодно между ними.
- `[...fruits]` создаёт **копию**, поэтому `push` в `copy` не трогает `fruits`.
- `Math.max(...scores)` раскладывает массив на отдельные **аргументы (arguments)**: это то же самое, что `Math.max(72, 95, 88)`.

## Spread с объектами

С объектами spread копирует все свойства в новый объект. Это стандартный способ «изменить» объект, не мутируя его: скопировать и переопределить то, что отличается. Если ключ встречается дважды, побеждает **более поздний**:

<CodeExample output={`{ name: 'Mei', theme: 'dark', volume: 5 }
light
{ id: 1, name: 'Mei', theme: 'light', volume: 5 }
light`}>

```js
const user = { name: "Mei", theme: "light", volume: 5 };

const updated = { ...user, theme: "dark" };
console.log(updated);
console.log(user.theme); // оригинал не тронут

const withId = { id: 1, ...user };
console.log(withId);

const oops = { theme: "dark", ...user }; // порядок важен!
console.log(oops.theme);
```

</CodeExample>

В `oops` сначала идёт `theme: "dark"`, а затем `...user` записывает поверх него `theme: "light"`. Ставьте spread **первым**, а свои изменения — **после** него.

В реальных проектах вы будете постоянно писать `{ ...state, something: newValue }`. React, который вы изучите позже на этом уровне, построен именно на таких обновлениях.

## Остаточные параметры (rest)

**Rest** выглядит так же (`...`), но делает обратную работу: вместо того чтобы раскладывать значения, он их **собирает** в массив. В параметрах функции `...numbers` собирает все аргументы в настоящий массив, сколько бы их ни было:

<CodeExample output={`[ 1, 2 ]
3
[ 5, 10, 15, 20 ]
50
[]
0
Победители: Mei, Sam, Ali`}>

```js
function sum(...numbers) {
  console.log(numbers);
  return numbers.reduce((total, n) => total + n, 0);
}

console.log(sum(1, 2));
console.log(sum(5, 10, 15, 20));
console.log(sum());

function logWithLabel(label, ...values) {
  console.log(`${label}:`, values.join(", "));
}

logWithLabel("Победители", "Mei", "Sam", "Ali");
```

</CodeExample>

В `logWithLabel` первый аргумент попадает в `label`, а **все остальные** — в `values`. Поэтому остаточный параметр всегда должен стоять **последним**: `function f(...values, label)` — это `SyntaxError`.

<Callout type="tip" title="Spread или rest? Смотрите, где стоят точки">

Три точки означают две противоположные вещи — в зависимости от того, где они стоят:

- **Spread** — там, где значение *используется*: в массиве `[...a]`, в объекте `{ ...o }` или в вызове функции `f(...args)`. Он **распаковывает**.
- **Rest** — там, где переменная *создаётся*: в параметрах `function f(...args)` или в деструктуризации `const [a, ...others] = list`. Он **упаковывает**.

</Callout>

## Rest в деструктуризации

Rest работает и в деструктуризации (destructuring). Для объектов он собирает все свойства, которые вы **не** назвали. Так можно аккуратно убрать свойство, не трогая оригинал:

<CodeExample output={`{ id: 7, name: 'Mei', email: 'mei@example.com' }
Mei [ 'Sam', 'Ali' ]`}>

```js
const user = {
  id: 7,
  name: "Mei",
  password: "bamboo123",
  email: "mei@example.com",
};

const { password, ...safeUser } = user;
console.log(safeUser);

const [winner, ...rest] = ["Mei", "Sam", "Ali"];
console.log(winner, rest);
```

</CodeExample>

Этот приём повсюду встречается в серверном коде: вы загружаете пользователя из базы данных, а потом отправляете в браузер `safeUser`, чтобы пароль никогда не покидал сервер.

## Вложенная деструктуризация

Реальные данные вложены: у заказа есть покупатель, у покупателя — адрес. Деструктуризация может пройти по этой структуре за один раз. На любом уровне можно **переименовывать** (`id: orderId`) и задавать **значения по умолчанию** (`postcode = "none"`):

<CodeExample output={`1042 Mei Chengdu none
Bamboo cup`}>

```js
const order = {
  id: 1042,
  customer: { name: "Mei", address: { city: "Chengdu" } },
  items: [
    { title: "Bamboo cup", price: 8 },
    { title: "Panda mug", price: 12 },
  ],
};

const {
  id: orderId,
  customer: {
    name,
    address: { city, postcode = "none" },
  },
  items: [firstItem],
} = order;

console.log(orderId, name, city, postcode);
console.log(firstItem.title);
```

</CodeExample>

Читайте `customer: { name }` как *«зайди в `customer` и достань оттуда `name`»*. Обратите внимание: сам `customer` здесь переменной **не** становится — переменными становятся только имена на концах.

<Callout type="warning" title="Не забирайтесь слишком глубоко">

Вложенная деструктуризация падает, если какого-то промежуточного уровня нет: будь `order.customer` равен `undefined`, вы получили бы `TypeError`. К тому же шаблон на пять уровней трудно читать. Обычно оптимально один-два уровня, а для всего, что глубже или может отсутствовать, используйте опциональную цепочку (о ней ниже).

</Callout>

### Объекты параметров со значениями по умолчанию

Самое полезное место для деструктуризации со значениями по умолчанию — параметры функции. Вместо пяти аргументов в строгом порядке функция принимает один **объект параметров (options object)**, и у каждого параметра есть значение по умолчанию:

<CodeExample output={`<button class="medium">Сохранить</button>
<button class="small">OK</button>
<button class="medium">OK</button>`}>

```js
function createButton({ label = "OK", size = "medium" } = {}) {
  return `<button class="${size}">${label}</button>`;
}

console.log(createButton({ label: "Сохранить" }));
console.log(createButton({ size: "small" }));
console.log(createButton());
```

</CodeExample>

`= {}` в конце — это значение по умолчанию для **всего** объекта, поэтому вызов `createButton()` без аргументов тоже работает. Вызывающий код передаёт только то, что хочет изменить, в любом порядке, и вызов читается понятно: `createButton({ size: "small" })` говорит ровно то, что имеет в виду. Многие библиотеки, с которыми вы будете работать (`fetch`, Express, Vitest), принимают такие объекты параметров.

## Опциональная цепочка подробнее

Вы уже знаете `user.address?.city`: если часть перед `?.` равна `null` или `undefined`, всё выражение останавливается и даёт `undefined` вместо падения. У **опциональной цепочки (optional chaining)** есть ещё две формы — для квадратных скобок и для вызова функций:

<CodeExample output={`Sam
undefined
Hi!
undefined`}>

```js
const data = {
  user: { name: "Mei", friends: ["Sam", "Ali"] },
  greet() {
    return "Hi!";
  },
};
const empty = {};

console.log(data.user?.friends?.[0]);
console.log(empty.user?.friends?.[0]);
console.log(data.greet?.());
console.log(empty.greet?.());
```

</CodeExample>

- `obj?.prop` читает свойство.
- `obj?.[key]` читает через квадратные скобки: элементы массива или ключ из переменной.
- `fn?.()` вызывает функцию, **только если она существует**. Удобно для необязательных колбэков вроде `options.onDone?.()`.

Используйте `?.` там, где данным **разрешено** отсутствовать (например, необязательное поле из API). Не расставляйте его повсюду: если что-то должно быть всегда, громкое падение сообщит об ошибке гораздо раньше, чем тихий `undefined`.

## ?? против ||

Чтобы задать запасное значение, раньше писали `value || "default"`. Проблема в том, что `||` подставляет запасное значение для **любого** ложного значения, включая `0`, `""` и `false`, а это часто вполне нормальные ответы. Оператор `??` (nullish coalescing) подставляет запасное значение только для `null` и `undefined`:

<CodeExample output={`50
0
"Аноним"
""
false
default`}>

```js
const settings = { volume: 0, nickname: "", darkMode: false };

console.log(settings.volume || 50); // 😬 пользователь выбрал 0!
console.log(settings.volume ?? 50);

console.log(JSON.stringify(settings.nickname || "Аноним"));
console.log(JSON.stringify(settings.nickname ?? "Аноним"));

console.log(settings.darkMode ?? true);
console.log(settings.missing ?? "default");
```

</CodeExample>

Пользователь убавил громкость до `0`, а `||` выбросил этот выбор. С `??` значение `0` сохраняется. Простое правило: используйте `??` для значений по умолчанию, а `||` оставьте для настоящей логики *«либо то, либо это»*. (`JSON.stringify` здесь нужен только для того, чтобы пустая строка `""` была видна.)

Есть и версия с присваиванием, `??=`, которая записывает значение, только если переменная сейчас равна `null` или `undefined`: `options.retries ??= 3`.

## Поверхностные копии и structuredClone

Spread делает **поверхностную** (shallow) копию: копирует только верхний уровень. Вложенные массивы и объекты остаются **общими** для копии и оригинала. Посмотрите, что происходит:

<CodeExample output={`{
  name: 'Mei',
  tags: [ 'admin', 'editor' ],
  address: { city: 'Paris' }
}`}>

```js
const original = {
  name: "Mei",
  tags: ["admin"],
  address: { city: "Chengdu" },
};

const shallow = { ...original };
shallow.name = "Sam";
shallow.tags.push("editor");
shallow.address.city = "Paris";

console.log(original);
```

</CodeExample>

Имя в безопасности (строки копируются), а вот `tags` и `address` изменились и в **оригинале**, потому что оба объекта указывают на один и тот же внутренний массив и объект. Исправить это можно двумя способами:

1. Копировать каждый уровень, который вы меняете, например `{ ...user, settings: { ...user.settings, volume: 3 } }`. Чаще всего вы будете делать именно так.
2. Сделать **глубокую** (deep) копию встроенной функцией `structuredClone`, которая копирует все уровни:

<CodeExample output={`[ 'admin' ] Chengdu
[ 'admin', 'editor' ] Paris
true`}>

```js
const original = {
  name: "Mei",
  tags: ["admin"],
  address: { city: "Chengdu" },
  joined: new Date("2024-05-01"),
};

const deep = structuredClone(original);
deep.tags.push("editor");
deep.address.city = "Paris";

console.log(original.tags, original.address.city);
console.log(deep.tags, deep.address.city);
console.log(deep.joined instanceof Date);
```

</CodeExample>

<Callout type="note" title="Что structuredClone не умеет копировать">

`structuredClone` справляется с обычными объектами, массивами, датами, Map, Set и многим другим. Но он не может копировать **функции**, а экземпляры классов возвращаются обычными объектами без своих методов:

```js
structuredClone({ greet() {} });
// DataCloneError: greet() {} could not be cloned.
```

Вам может встретиться и старый трюк `JSON.parse(JSON.stringify(obj))`. Для простых данных он работает, но превращает даты в строки и выбрасывает значения `undefined`, так что лучше используйте `structuredClone`.

</Callout>

<Hint>

1. `const { password, ...rest } = user;`, а затем верните `rest`.
2. Сочетайте `?.` (на случай, если `settings` нет) с `??` (чтобы `0` сохранился).
3. Используйте spread на двух уровнях: `{ ...user, settings: { ...user.settings, ...changes } }`.

<Solution>

```js
const user = {
  id: 7,
  name: "Mei",
  password: "bamboo123",
  settings: { theme: "light", volume: 0 },
};

function withoutPassword(user) {
  const { password, ...rest } = user;
  return rest;
}

function getVolume(user) {
  return user.settings?.volume ?? 50;
}

function updateSettings(user, changes) {
  return {
    ...user,
    settings: { ...user.settings, ...changes },
  };
}

function total(...prices) {
  return prices.reduce((sum, price) => sum + price, 0);
}

console.log(withoutPassword(user));
console.log(getVolume(user));            // 0
console.log(getVolume({ name: "Sam" })); // 50
console.log(updateSettings(user, { theme: "dark" }));
console.log(user.settings.theme);        // всё ещё "light"
console.log(total(4, 10, 6));            // 20
```

</Solution>

## Итоги

- **Spread** `...` распаковывает: `[...a, ...b]` объединяет массивы, `{ ...obj, key: value }` копирует объект с изменениями (более поздние ключи побеждают), `f(...args)` передаёт элементы массива как аргументы.
- **Rest** `...` упаковывает: `function f(...args)` собирает аргументы в массив, а `const { password, ...rest } = user` собирает оставшиеся свойства.
- Деструктуризация бывает **вложенной**, с переименованием (`id: orderId`) и значениями по умолчанию (`size = "medium"`). Объекты параметров со значениями по умолчанию делают функции удобными для вызова.
- `?.` работает в формах `obj?.prop`, `obj?.[key]` и `fn?.()`. Используйте его там, где данным разрешено отсутствовать.
- Для значений по умолчанию используйте `??`: в отличие от `||`, он сохраняет `0`, `""` и `false`.
- Копии через spread — **поверхностные**. Копируйте каждый уровень, который меняете, или используйте `structuredClone` для глубокой копии.
