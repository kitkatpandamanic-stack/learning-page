Панды, рыбы и попугаи совсем разные, но все они **животные**: у всех есть имя, и все они едят. Вместо того чтобы повторять этот общий код в каждом классе, можно один раз написать его в **родительском** классе, а другие классы его **унаследуют**. Это называется **наследованием** (inheritance).

## `extends`: строим на основе другого класса

<CodeExample output={`Мэй ест.
Мэй лезет на дерево. 🌳
true`}>

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  eat() {
    console.log(`${this.name} ест.`);
  }
}

class Panda extends Animal {
  climb() {
    console.log(`${this.name} лезет на дерево. 🌳`);
  }
}

const mei = new Panda("Мэй");
mei.eat();
mei.climb();
console.log(mei instanceof Animal);
```

</CodeExample>

`class Panda extends Animal` делает `Panda` **подклассом** (subclass, или дочерним классом) класса `Animal` — его **родительского** класса (parent class). Панда получает всё, что есть у животного, включая конструктор и `eat()`, плюс собственный метод `climb()`.

## `super()`: вызываем конструктор родителя

Если подклассу нужен свой конструктор, он **обязан** первым делом вызвать `super(...)`. Этот вызов запускает конструктор родителя, чтобы выполнилась общая настройка:

<CodeExample output={`Panda { name: 'Мэй', favouriteFood: 'бамбук' }`}>

```js
class Animal {
  constructor(name) {
    this.name = name;
  }
}

class Panda extends Animal {
  constructor(name, favouriteFood) {
    super(name); // запускает конструктор Animal
    this.favouriteFood = favouriteFood;
  }
}

const mei = new Panda("Мэй", "бамбук");
console.log(mei);
```

</CodeExample>

<Callout type="warning" title="Сначала super(), потом this">

Пока `super()` не выполнился, объекта ещё не существует, поэтому использовать `this` нельзя. Если забыть про него, вы получите ошибку вроде такой:

```js
// ReferenceError: Must call super constructor in derived class
// before accessing 'this' or returning from derived constructor
```

</Callout>

## Переопределение методов

Подкласс может **переопределить** (override) метод, объявив метод с тем же именем. Чтобы заодно вызвать версию родителя, используйте `super.methodName()`:

<CodeExample output={`Рекс — животное.
Мэй — животное. Очень пушистое! 🐼
Пузырёк плавает.`}>

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  describe() {
    return `${this.name} — животное.`;
  }
}

class Panda extends Animal {
  describe() {
    return `${super.describe()} Очень пушистое! 🐼`;
  }
}

class Fish extends Animal {
  describe() {
    return `${this.name} плавает.`;
  }
}

const zoo = [
  new Animal("Рекс"),
  new Panda("Мэй"),
  new Fish("Пузырёк"),
];

for (const animal of zoo) {
  console.log(animal.describe());
}
```

</CodeExample>

Цикл одинаково вызывает `describe()` у каждого животного, но каждое отвечает по-своему. `Panda` дополняет фразу родителя с помощью `super.describe()`, а `Fish` полностью её заменяет.

## Проверяем тип с помощью `instanceof`

`instanceof` спрашивает: «Этот объект создан из этого класса или из одного из его потомков?»

<CodeExample output={`true
true
false`}>

```js
class Animal {}
class Panda extends Animal {}
class Fish extends Animal {}

const mei = new Panda();

console.log(mei instanceof Panda);
console.log(mei instanceof Animal);
console.log(mei instanceof Fish);
```

</CodeExample>

## Приватные поля и методы

В прошлом уроке `_score` был приватным только по договорённости. Поставьте `#` перед именем поля или метода, и оно станет **по-настоящему приватным** (private): трогать его сможет только код внутри класса.

<CodeExample output={`8
PiggyBank {}
Добавьте целое число монет больше 0`}>

```js
class PiggyBank {
  #coins = 0;

  add(coins) {
    if (!this.#isValid(coins)) {
      throw new Error("Добавьте целое число монет больше 0");
    }
    this.#coins += coins;
  }

  get coins() {
    return this.#coins;
  }

  #isValid(n) {
    return Number.isInteger(n) && n > 0;
  }
}

const bank = new PiggyBank();
bank.add(5);
bank.add(3);
console.log(bank.coins);
console.log(bank);

try {
  bank.add(-100);
} catch (err) {
  console.log(err.message);
}
```

</CodeExample>

- `#coins` — приватное **поле**, а `#isValid` — приватный **метод**.
- При выводе `bank` ничего не видно: приватные данные скрыты от внешнего мира.
- Прочитать монеты можно только через публичный геттер `coins`, а изменить — только через `add()`, который сначала проверяет значение.

Попытка добраться до приватного поля снаружи класса не просто блокируется — это **синтаксическая ошибка** (syntax error), так что код даже не запустится:

```js
console.log(bank.#coins);
// SyntaxError: Private field '#coins' must be declared
// in an enclosing class
```

<Callout type="tip" title="Зачем вообще что-то прятать?">

Приватные поля защищают правила вашего объекта. Если бы кто угодно мог написать `bank.coins = -999`, все ваши проверки потеряли бы смысл. Держите данные приватными и открывайте только те методы, которыми должны пользоваться другие.

</Callout>

## Собственные классы ошибок

`Error` — тоже класс, а значит, его можно расширить! Собственный тип ошибки позволяет различать разные проблемы в блоке `catch`:

<CodeExample output={`Возраст установлен: 7
ValidationError: Недопустимый возраст: -2`}>

```js
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}

function setAge(age) {
  if (!Number.isInteger(age) || age < 0) {
    throw new ValidationError(`Недопустимый возраст: ${age}`);
  }
  return age;
}

for (const value of [7, -2]) {
  try {
    console.log(`Возраст установлен: ${setAge(value)}`);
  } catch (err) {
    if (err instanceof ValidationError) {
      console.log(`${err.name}: ${err.message}`);
    } else {
      throw err; // это не наша ошибка, передаём её дальше
    }
  }
}
```

</CodeExample>

- `super(message)` позволяет `Error` сохранить сообщение за вас.
- Если задать `this.name`, ошибка будет показывать в сообщениях свой настоящий тип.
- В `catch` оператор `instanceof` проверяет, **какого вида** ошибка произошла, чтобы вы обрабатывали только ожидаемые.

## Композиция или наследование

Наследование означает «**является**»: панда *является* животным. Но им легко злоупотребить. Длинные цепочки вроде `Animal → Mammal → Bear → Panda → BabyPanda` трудно менять. Часто проще собирать объекты из других объектов — это называется **композицией** (composition) и означает «**содержит**»:

<CodeExample output={`Двигатель заводится: врум! 🚗
Машина «Лада» готова к поездке.`}>

```js
class Engine {
  start() {
    console.log("Двигатель заводится: врум! 🚗");
  }
}

class Car {
  constructor(model) {
    this.model = model;
    this.engine = new Engine(); // у машины ЕСТЬ двигатель
  }

  drive() {
    this.engine.start();
    console.log(`Машина «${this.model}» готова к поездке.`);
  }
}

new Car("Лада").drive();
```

</CodeExample>

<Callout type="note" title="Хорошее практическое правило">

Используйте наследование, когда потомок действительно **является** более конкретной версией родителя и разделяет большую часть его поведения. В остальных случаях выбирайте композицию. Держите цепочки наследования короткими: одного-двух уровней обычно более чем достаточно.

</Callout>

6. **`SavingsAccount`** (сберегательный счёт) расширяет `BankAccount`. Его конструктор принимает `(owner, balance, rate)`, а `addInterest()` начисляет проценты: вносит на счёт `balance * rate`.

Объявите `#balance = 0;` в начале `BankAccount` и задайте `this.#balance = balance;` в конструкторе. Подкласс не видит приватные поля родителя, поэтому внутри `SavingsAccount` используйте публичный геттер `this.balance` и `this.deposit(...)`. Не забудьте вызвать в его конструкторе `super(owner, balance)` до `this.rate = rate`.

<Solution>

```js
class InsufficientFundsError extends Error {
  constructor(message) {
    super(message);
    this.name = "InsufficientFundsError";
  }
}

class BankAccount {
  #balance = 0;

  constructor(owner, balance = 0) {
    this.owner = owner;
    this.#balance = balance;
  }

  get balance() {
    return this.#balance;
  }

  #checkAmount(amount) {
    if (typeof amount !== "number" || amount <= 0) {
      throw new Error("Сумма должна быть числом больше 0");
    }
  }

  deposit(amount) {
    this.#checkAmount(amount);
    this.#balance += amount;
    return this.#balance;
  }

  withdraw(amount) {
    this.#checkAmount(amount);
    if (amount > this.#balance) {
      throw new InsufficientFundsError(
        `Нельзя снять ${amount}, баланс: ${this.#balance}`,
      );
    }
    this.#balance -= amount;
    return this.#balance;
  }
}

class SavingsAccount extends BankAccount {
  constructor(owner, balance, rate) {
    super(owner, balance);
    this.rate = rate;
  }

  addInterest() {
    return this.deposit(this.balance * this.rate);
  }
}

const account = new BankAccount("Мэй", 100);
account.deposit(50);
account.withdraw(30);
console.log(account.balance); // 120

try {
  account.withdraw(500);
} catch (err) {
  console.log(`${err.name}: ${err.message}`);
}

const savings = new SavingsAccount("Бао", 200, 0.05);
savings.addInterest();
console.log(savings.balance); // 210
```

</Solution>

</Exercise>

## Итоги

- `class Child extends Parent` наследует конструктор и методы родителя.
- В конструкторе подкласса вызывайте `super(...)` до использования `this`; `super.method()` позволяет переиспользовать метод родителя, который вы переопределили.
- `instanceof` проверяет, создан ли объект из класса или одного из его подклассов.
- Имена, начинающиеся с `#`, **приватные**: использовать их может только код внутри класса.
- Расширяйте `Error`, чтобы создавать собственные ошибки вроде `ValidationError`, и проверяйте их через `instanceof`.
- Наследование означает «является», композиция — «содержит». Если сомневаетесь, выбирайте композицию.
