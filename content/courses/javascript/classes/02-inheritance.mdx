Pandas, fish and parrots are all different, but they're all **animals**: they all have a name and they all eat. Instead of repeating that shared code in every class, you can write it once in a **parent** class and let other classes **inherit** it.

## `extends`: building on another class

<CodeExample output={`Mei is eating.
Mei climbs a tree. 🌳
true`}>

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  eat() {
    console.log(`${this.name} is eating.`);
  }
}

class Panda extends Animal {
  climb() {
    console.log(`${this.name} climbs a tree. 🌳`);
  }
}

const mei = new Panda("Mei");
mei.eat();
mei.climb();
console.log(mei instanceof Animal);
```

</CodeExample>

`class Panda extends Animal` makes `Panda` a **subclass** (or child class) of `Animal`, its **parent** class. A panda gets everything an animal has, including the constructor and `eat()`, plus its own `climb()` method.

## `super()`: calling the parent constructor

If the subclass needs its own constructor, it **must** call `super(...)` first. That runs the parent's constructor so the shared setup happens:

<CodeExample output={`Panda { name: 'Mei', favouriteFood: 'bamboo' }`}>

```js
class Animal {
  constructor(name) {
    this.name = name;
  }
}

class Panda extends Animal {
  constructor(name, favouriteFood) {
    super(name); // runs Animal's constructor
    this.favouriteFood = favouriteFood;
  }
}

const mei = new Panda("Mei", "bamboo");
console.log(mei);
```

</CodeExample>

<Callout type="warning" title="super() comes before this">

Until `super()` has run, the object doesn't exist yet, so you can't use `this`. Forgetting it gives an error like:

```js
// ReferenceError: Must call super constructor in derived class
// before accessing 'this' or returning from derived constructor
```

</Callout>

## Overriding methods

A subclass can **override** a method by defining one with the same name. Use `super.methodName()` to call the parent's version as well:

<CodeExample output={`Rex is an animal.
Mei is an animal. A very fluffy one! 🐼
Bubbles is swimming.`}>

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  describe() {
    return `${this.name} is an animal.`;
  }
}

class Panda extends Animal {
  describe() {
    return `${super.describe()} A very fluffy one! 🐼`;
  }
}

class Fish extends Animal {
  describe() {
    return `${this.name} is swimming.`;
  }
}

const zoo = [
  new Animal("Rex"),
  new Panda("Mei"),
  new Fish("Bubbles"),
];

for (const animal of zoo) {
  console.log(animal.describe());
}
```

</CodeExample>

The loop calls `describe()` the same way on every animal, yet each one answers in its own way. `Panda` builds on the parent's sentence with `super.describe()`, while `Fish` replaces it completely.

## Checking types with `instanceof`

`instanceof` asks "was this object made from this class, or one of its children?":

<CodeExample output={`true
true
false`}>

```js
class Animal {}
class Panda extends Animal {}
class Fish extends Animal {}

const mei = new Panda();

console.log(mei instanceof Panda);
console.log(mei instanceof Animal);
console.log(mei instanceof Fish);
```

</CodeExample>

## Private fields and methods

In the last lesson, `_score` was private only by agreement. Put a `#` in front of a field or method name and it becomes **truly private**: only code inside the class can touch it.

<CodeExample output={`8
PiggyBank {}
Add a whole number of coins above 0`}>

```js
class PiggyBank {
  #coins = 0;

  add(coins) {
    if (!this.#isValid(coins)) {
      throw new Error("Add a whole number of coins above 0");
    }
    this.#coins += coins;
  }

  get coins() {
    return this.#coins;
  }

  #isValid(n) {
    return Number.isInteger(n) && n > 0;
  }
}

const bank = new PiggyBank();
bank.add(5);
bank.add(3);
console.log(bank.coins);
console.log(bank);

try {
  bank.add(-100);
} catch (err) {
  console.log(err.message);
}
```

</CodeExample>

- `#coins` is a private **field** and `#isValid` is a private **method**.
- Printing `bank` shows nothing: private data is hidden from the outside world.
- The only way to read the coins is the public `coins` getter, and the only way to change them is `add()`, which validates first.

Trying to reach a private field from outside the class isn't just blocked, it's a **syntax error**, so the code won't even start:

```js
console.log(bank.#coins);
// SyntaxError: Private field '#coins' must be declared
// in an enclosing class
```

<Callout type="tip" title="Why bother hiding things?">

Private fields protect your object's rules. If anyone could write `bank.coins = -999`, all your validation would be pointless. Keep data private and expose only the methods you want people to use.

</Callout>

## Custom error classes

`Error` is a class too, so you can extend it! A custom error type lets you tell different problems apart in a `catch` block:

<CodeExample output={`Age set to 7
ValidationError: Invalid age: -2`}>

```js
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}

function setAge(age) {
  if (!Number.isInteger(age) || age < 0) {
    throw new ValidationError(`Invalid age: ${age}`);
  }
  return age;
}

for (const value of [7, -2]) {
  try {
    console.log(`Age set to ${setAge(value)}`);
  } catch (err) {
    if (err instanceof ValidationError) {
      console.log(`${err.name}: ${err.message}`);
    } else {
      throw err; // not ours, so pass it on
    }
  }
}
```

</CodeExample>

- `super(message)` lets `Error` store the message for you.
- Setting `this.name` makes the error show its real type in messages.
- In the `catch`, `instanceof` checks **which kind** of error happened, so you only handle the ones you expect.

## Composition vs inheritance

Inheritance means "**is a**": a panda *is an* animal. But it's easy to overuse. Long chains like `Animal → Mammal → Bear → Panda → BabyPanda` get hard to change. Often it's simpler to build objects out of other objects, which is called **composition** and means "**has a**":

<CodeExample output={`Engine starts: vroom! 🚗
Kei car is ready to go.`}>

```js
class Engine {
  start() {
    console.log("Engine starts: vroom! 🚗");
  }
}

class Car {
  constructor(model) {
    this.model = model;
    this.engine = new Engine(); // a car HAS an engine
  }

  drive() {
    this.engine.start();
    console.log(`${this.model} is ready to go.`);
  }
}

new Car("Kei car").drive();
```

</CodeExample>

<Callout type="note" title="A good rule of thumb">

Use inheritance when the child really **is a** more specific version of the parent and shares most of its behaviour. Otherwise, prefer composition. Keep inheritance chains short: one or two levels is usually plenty.

</Callout>

1. **`InsufficientFundsError`** extends `Error` and sets `this.name = "InsufficientFundsError"`.
2. **`BankAccount`** stores its money in a **private** `#balance` field, starting at the `balance` argument (default `0`).
3. A **`balance` getter** returns the current balance.
4. **`deposit(amount)`** adds money and returns the new balance. If `amount` isn't above 0, throw an `Error`.
5. **`withdraw(amount)`** removes money and returns the new balance. Throw an `Error` if `amount` isn't above 0, and throw an `InsufficientFundsError` if it's more than the balance.
6. **`SavingsAccount`** extends `BankAccount`. Its constructor takes `(owner, balance, rate)`, and `addInterest()` deposits `balance * rate`.

<Hint>

Declare `#balance = 0;` at the top of `BankAccount` and set `this.#balance = balance;` in the constructor. A subclass can't see its parent's private fields, so inside `SavingsAccount` use the public `this.balance` getter and `this.deposit(...)`. Remember to call `super(owner, balance)` in its constructor before `this.rate = rate`.

</Hint>

<Solution>

```js
class InsufficientFundsError extends Error {
  constructor(message) {
    super(message);
    this.name = "InsufficientFundsError";
  }
}

class BankAccount {
  #balance = 0;

  constructor(owner, balance = 0) {
    this.owner = owner;
    this.#balance = balance;
  }

  get balance() {
    return this.#balance;
  }

  #checkAmount(amount) {
    if (typeof amount !== "number" || amount <= 0) {
      throw new Error("Amount must be a number above 0");
    }
  }

  deposit(amount) {
    this.#checkAmount(amount);
    this.#balance += amount;
    return this.#balance;
  }

  withdraw(amount) {
    this.#checkAmount(amount);
    if (amount > this.#balance) {
      throw new InsufficientFundsError(
        `Can't withdraw ${amount}, balance is ${this.#balance}`,
      );
    }
    this.#balance -= amount;
    return this.#balance;
  }
}

class SavingsAccount extends BankAccount {
  constructor(owner, balance, rate) {
    super(owner, balance);
    this.rate = rate;
  }

  addInterest() {
    return this.deposit(this.balance * this.rate);
  }
}

const account = new BankAccount("Mei", 100);
account.deposit(50);
account.withdraw(30);
console.log(account.balance); // 120

try {
  account.withdraw(500);
} catch (err) {
  console.log(`${err.name}: ${err.message}`);
}

const savings = new SavingsAccount("Bao", 200, 0.05);
savings.addInterest();
console.log(savings.balance); // 210
```

</Solution>

## Recap

- `class Child extends Parent` inherits the parent's constructor and methods.
- In a subclass constructor, call `super(...)` before using `this`; use `super.method()` to reuse a parent's method you've overridden.
- `instanceof` checks whether an object was made from a class or one of its subclasses.
- Names starting with `#` are **private**: only code inside the class can use them.
- Extend `Error` to make custom errors like `ValidationError` and check them with `instanceof`.
- Inheritance means "is a"; composition means "has a". Prefer composition when in doubt.
