Компоненты из прошлого урока при одних и тех же пропсах всегда показывали одно и то же. Настоящие интерфейсы меняются: счётчик растёт, поле заполняется текстом, пункт отмечается выполненным. В React данные, которые меняются со временем и должны обновлять экран, называются **состоянием (state)**. В этом уроке вы дадите компонентам состояние, научитесь реагировать на события и узнаете главное правило, благодаря которому приложения на React предсказуемы: **никогда не меняйте состояние на месте — заменяйте его**. 🔁

## Почему обычной переменной недостаточно

Попробуем сделать кнопку «лайк» с обычной переменной. Нажмите **«Запустить»** и щёлкните по кнопке несколько раз:

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function LikeButton() {
  let likes = 0;

  function handleClick() {
    likes = likes + 1;
    console.log("теперь лайков:", likes);
  }

  return <button onClick={handleClick}>🤍 Лайков: {likes}</button>;
}

createRoot(document.getElementById("root")).render(<LikeButton />);`}
/>

Вывод показывает, что число растёт, но на кнопке по-прежнему 0. Проблемы две:

1. Изменение локальной переменной ничего не сообщает React, поэтому он не делает **повторный рендер (re-render)** — то есть не вызывает `LikeButton` снова.
2. Даже если бы вызвал, `let likes = 0` выполнилась бы заново и начала с нуля. Функция-компонент забывает свои локальные переменные после каждого рендера.

## useState: память компонента

**Хук (hook)** **`useState`** решает обе проблемы. Он даёт текущее значение и **функцию-сеттер (setter)**. Вызов сеттера сохраняет новое значение **и** просит React снова отрисовать компонент:

<TryIt
  language="react"
  code={`import { useState } from "react";
import { createRoot } from "react-dom/client";

function LikeButton() {
  const [likes, setLikes] = useState(0);
  console.log("рендер, likes =", likes);

  return (
    <button onClick={() => setLikes(likes + 1)}>
      💜 Лайков: {likes}
    </button>
  );
}

createRoot(document.getElementById("root")).render(
  <>
    <LikeButton />{" "}
    <LikeButton />
  </>
);`}
/>

- `useState(0)` задаёт **начальное** значение. Оно используется только при первом рендере.
- Хук возвращает массив из двух элементов, который мы деструктурируем: `[likes, setLikes]`. По соглашению их называют `[thing, setThing]`.
- У каждой кнопки **своё** состояние: щелчок по одной не меняет другую.

Функции, имя которых начинается с `use`, называются **хуками**. Чтобы они работали, соблюдайте два правила: вызывайте их только **внутри компонентов** (или своих хуков) и только на **верхнем уровне** — никогда внутри `if`, циклов или вложенных функций. React различает хуки по порядку вызова, поэтому этот порядок должен быть одинаковым при каждом рендере.

### Состояние — это снимок

Вот что удивляет всех. Нажмите **+3 (неверно)**:

<TryIt
  language="react"
  code={`import { useState } from "react";
import { createRoot } from "react-dom/client";

function Counter() {
  const [count, setCount] = useState(0);
  console.log("рендер, count =", count);

  function addThreeWrong() {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
    console.log("в этом рендере всё ещё", count);
  }

  function addThreeRight() {
    setCount((c) => c + 1);
    setCount((c) => c + 1);
    setCount((c) => c + 1);
  }

  return (
    <>
      <h2>{count}</h2>
      <button onClick={addThreeWrong}>+3 (неверно)</button>{" "}
      <button onClick={addThreeRight}>+3 (верно)</button>
    </>
  );
}

createRoot(document.getElementById("root")).render(<Counter />);`}
/>

Прибавляется только 1. Внутри одного рендера `count` — это **фиксированное значение** (снимок, snapshot), поэтому все три вызова означают `setCount(0 + 1)`. Сеттер не меняет `count` сразу — он планирует новый рендер с новым значением. Кроме того, React **объединяет (batches)** три вызова в один рендер.

Когда новое значение зависит от старого, передайте вместо него **функцию-обновитель (updater function)**: `setCount((c) => c + 1)`. React вызывает её с самым свежим значением, поэтому три таких вызова действительно прибавят 3.

## Обработка событий

Вы уже пользовались **`onClick`**. Пропсы событий в React работают как `addEventListener`, но обработчик передаётся прямо в JSX. Все привычные события на месте, в camelCase: `onClick`, `onChange`, `onSubmit`, `onKeyDown`, `onMouseEnter`...

```jsx
function Toolbar({ onDelete }) {
  function handleSave(event) {
    console.log("Сохраняем!", event.target);
  }

  return (
    <>
      <button onClick={handleSave}>Сохранить</button>
      <button onClick={() => onDelete(42)}>Удалить №42</button>
    </>
  );
}
```

- Передавайте функцию, **а не вызывайте её**: `onClick={handleSave}`, а не `onClick={handleSave()}`. Со скобками она выполнится во время рендера, и если она меняет состояние, вы получите бесконечный цикл рендеров.
- Чтобы передать аргументы, оберните вызов в стрелочную функцию: `onClick={() => onDelete(42)}`.
- Обработчик получает **объект события** с `target`, `key`, `preventDefault()` и прочим — так же, как в [уроке о событиях](/learn/javascript/events).
- Передача функции **в пропсе** (как `onDelete`) — это способ, которым дочерний компонент сообщает родителю, что что-то произошло. По соглашению имена таких пропсов начинаются с `on`.

## Обновляем массивы и объекты

React решает, нужен ли повторный рендер, сравнивая старое и новое состояние через `Object.is`. Если **мутировать** массив (`push`, `splice`, `item.done = true`), это всё ещё **тот же самый массив**, и React может решить, что ничего не изменилось, и пропустить обновление. Решение — считать состояние **доступным только для чтения** и всегда создавать **новый** массив или объект:

<CodeExample output={`true [ 'мука', 'яйца', 'молоко' ]
3 1 false
{ id: 2, name: 'яйца', got: true }
{ id: 2, name: 'яйца', got: false }
true`}>

```js
const list = ["мука", "яйца"];
const before = list;
list.push("молоко");
console.log(Object.is(before, list), list);

const items = [
  { id: 1, name: "мука", got: false },
  { id: 2, name: "яйца", got: false },
];

const added = [...items, { id: 3, name: "молоко", got: false }];
const removed = items.filter((item) => item.id !== 1);
const toggled = items.map((item) =>
  item.id === 2 ? { ...item, got: !item.got } : item
);

console.log(added.length, removed.length, Object.is(items, toggled));
console.log(toggled[1]);
console.log(items[1]);
console.log(toggled[0] === items[0]);
```

</CodeExample>

После `push` переменные `before` и `list` указывают на один и тот же объект (`true`) — именно поэтому React не видит изменения. Три версии без мутаций — это шаблоны, которые вы будете писать снова и снова:

| Чтобы... | Пишите |
| --- | --- |
| добавить элемент | `setItems([...items, newItem])` |
| удалить элемент | `setItems(items.filter((i) => i.id !== id))` |
| изменить один элемент | `setItems(items.map((i) => i.id === id ? { ...i, got: true } : i))` |
| изменить поле объекта | `setUser({ ...user, name: "Mei" })` |

Исходный `items[1]` остался нетронутым, а неизменённые элементы (`toggled[0]`) переиспользуются как есть, поэтому копия обходится дёшево.

<Callout type="danger" title="Не мутируйте состояние">

`items.push(x); setItems(items)` — самая частая ошибка в React. Иногда кажется, что всё работает, а потом экран перестаёт обновляться или показывает старые данные. Методам, которые **изменяют** массив (`push`, `pop`, `splice`, `sort`, `reverse`), сначала нужна копия: `[...items].sort(...)` или более новый метод без мутации `items.toSorted(...)`.

</Callout>

## Управляемые поля ввода и формы

Чтобы читать, что вводит пользователь, храните текст поля в состоянии и свяжите оба направления: **`value`** показывает состояние, а **`onChange`** обновляет его при каждом нажатии клавиши. Это называется **управляемым полем ввода (controlled input)**, потому что содержимое поля всегда контролирует React:

<TryIt
  language="react"
  code={`import { useState } from "react";
import { createRoot } from "react-dom/client";

let nextId = 3;

function Ingredients() {
  const [items, setItems] = useState([
    { id: 1, name: "мука" },
    { id: 2, name: "яйца" },
  ]);
  const [text, setText] = useState("");

  function handleSubmit(event) {
    event.preventDefault();
    const name = text.trim();
    if (!name) return;
    setItems([...items, { id: nextId++, name }]);
    setText("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={text}
        onChange={(event) => setText(event.target.value)}
        placeholder="Добавьте ингредиент"
      />
      <button>Добавить</button>
      <p>Вы вводите: {text || "(пока ничего)"}</p>
      <ul>
        {items.map((item) => (
          <li key={item.id}>{item.name}</li>
        ))}
      </ul>
    </form>
  );
}

createRoot(document.getElementById("root")).render(<Ingredients />);`}
/>

Текст живёт в состоянии, поэтому очистить поле — это просто `setText("")`, а абзац обновляется прямо во время ввода. Формы работают так же, как в обычном JavaScript: слушайте **`onSubmit`** на `<form>` (тогда сработают и кнопка, и клавиша Enter) и вызывайте **`event.preventDefault()`**, чтобы браузер не перезагрузил страницу.

Обратите внимание: `nextId` живёт **за пределами** компонента. Он не показывается на экране, ему нужно просто продолжать считать. В реальном приложении id обычно приходит с сервера или из `crypto.randomUUID()`.

## Поднятие состояния

А если одно и то же состояние нужно двум компонентам? Например, поле поиска фильтрует список рецептов. Поле знает текст, но он нужен и списку. Решение — **поднять состояние (lift state up)** в ближайшего общего родителя и передать его вниз через пропсы вместе с функцией для его изменения:

<TryIt
  language="react"
  code={`import { useState } from "react";
import { createRoot } from "react-dom/client";

const RECIPES = [
  { id: 1, name: "Bamboo Shoot Stir-fry" },
  { id: 2, name: "Pancakes" },
  { id: 3, name: "Tomato Soup" },
  { id: 5, name: "Guacamole" },
];

function SearchBox({ value, onChange }) {
  return (
    <input
      value={value}
      onChange={(event) => onChange(event.target.value)}
      placeholder="Поиск рецептов"
    />
  );
}

function RecipeList({ recipes }) {
  if (recipes.length === 0) return <p>Рецепты не найдены.</p>;
  return (
    <ul>
      {recipes.map((r) => <li key={r.id}>{r.name}</li>)}
    </ul>
  );
}

function App() {
  const [query, setQuery] = useState("");
  const matches = RECIPES.filter((r) =>
    r.name.toLowerCase().includes(query.toLowerCase())
  );

  return (
    <>
      <SearchBox value={query} onChange={setQuery} />
      <p>Рецептов: {matches.length} из {RECIPES.length}</p>
      <RecipeList recipes={matches} />
    </>
  );
}

createRoot(document.getElementById("root")).render(<App />);`}
/>

Данные текут **вниз** через пропсы (`value`, `recipes`), а события — **вверх** через пропсы-колбэки (`onChange`). У `SearchBox` и `RecipeList` нет состояния вообще, поэтому их легко переиспользовать и тестировать. В React такой однонаправленный поток данных — норма: у каждой части состояния **один владелец**.

## Вычисляйте значения, а не храните их

Посмотрите ещё раз на `matches` выше: это не состояние. Оно **вычисляется** из `query` при каждом рендере. Новички часто кладут его в состояние тоже:

```jsx
// ❌ Два состояния, которые приходится синхронизировать вручную
const [query, setQuery] = useState("");
const [matches, setMatches] = useState(RECIPES);

function handleChange(text) {
  setQuery(text);
  setMatches(RECIPES.filter((r) => r.name.includes(text)));
}

// ✅ Одно состояние, всё остальное вычисляется во время рендера
const [query, setQuery] = useState("");
const matches = RECIPES.filter((r) => r.name.includes(query));
```

Первая версия работает, пока кто-нибудь не добавит второй способ изменить `query` и не забудет про `setMatches`. Тогда на экране окажется список, который не соответствует полю поиска. Спросите себя: **можно ли вычислить это из пропсов или другого состояния?** Если да, это не состояние. Количества, суммы, отфильтрованные и отсортированные списки, «валидна ли форма?» — всё это вычисляемые значения.

<Callout type="tip" title="Держите состояние минимальным">

Хорошее состояние в React — это **наименьший** набор данных, который нужен приложению: что ввёл пользователь, какие элементы существуют, какой из них выбран. Всё, что можно из этого вычислить, вычисляйте при рендере. Кода меньше, и рассинхронизироваться нечему.

</Callout>

```jsx
import { useState } from "react";
import { createRoot } from "react-dom/client";

let nextId = 3;

function ShoppingList() {
  const [items, setItems] = useState([
    { id: 1, name: "бамбук", got: false },
    { id: 2, name: "рис", got: false },
  ]);
  const [text, setText] = useState("");

  function handleSubmit(event) {
    event.preventDefault();
    const name = text.trim();
    if (!name) return;
    setItems([...items, { id: nextId++, name, got: false }]);
    setText("");
  }

  function toggle(id) {
    setItems(
      items.map((item) =>
        item.id === id ? { ...item, got: !item.got } : item
      )
    );
  }

  function remove(id) {
    setItems(items.filter((item) => item.id !== id));
  }

  const left = items.filter((item) => !item.got).length;

  return (
    <div>
      <form onSubmit={handleSubmit}>
        <input
          name="item"
          placeholder="Добавьте товар"
          value={text}
          onChange={(event) => setText(event.target.value)}
        />
        <button type="submit">Добавить</button>
      </form>
      <ul>
        {items.map((item) => (
          <li key={item.id} className={item.got ? "got" : ""}>
            <label>
              <input
                type="checkbox"
                checked={item.got}
                onChange={() => toggle(item.id)}
              />
              {item.name}
            </label>{" "}
            <button
              className="remove"
              onClick={() => remove(item.id)}
            >
              Удалить
            </button>
          </li>
        ))}
      </ul>
      <p className="count">Осталось: {left} из {items.length}</p>
    </div>
  );
}
```

## Итоги

- **Состояние** — это данные, которые меняются и должны обновлять экран. `const [value, setValue] = useState(initial)` даёт компоненту память; вызов сеттера перерисовывает его.
- Вызывайте хуки только на **верхнем уровне** компонента. Состояние — это **снимок** для каждого рендера; используйте **функцию-обновитель** `setCount((c) => c + 1)`, когда новое значение зависит от старого.
- Пропсы событий вроде `onClick={handleClick}` принимают функцию: передавайте её, а не вызывайте. Чтобы передать аргументы, используйте стрелочную функцию; пропсы-колбэки (`onChange`, `onDelete`) позволяют детям общаться с родителями.
- Никогда не мутируйте состояние: создавайте новые массивы и объекты с помощью **spread**, `filter` и `map`.
- **Управляемые поля ввода** используют `value` + `onChange`; формы — `onSubmit` с `event.preventDefault()`.
- **Поднимайте состояние** в ближайшего общего родителя, когда оно нужно нескольким компонентам, и **вычисляйте** всё, что можно вычислить, вместо того чтобы хранить.
