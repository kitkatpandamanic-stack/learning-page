Пора собрать весь модуль воедино. Вы создадите **каталог рецептов**: поиск рецептов по названию или ингредиенту, фильтр по тегам, щелчок по рецепту открывает его ингредиенты и шаги, а возврат к списку не сбрасывает поиск. Всё загружается из учебного API, с правильными состояниями загрузки, ошибки и пустого результата. По пути вы напишете свой первый **пользовательский хук (custom hook)**, а в конце узнаете, как создать это же приложение как настоящий проект на своём компьютере. 🍜

## План

Прежде чем писать код, React-разработчики набрасывают две вещи: **компоненты** и **где живёт состояние**.

```text
App                     состояние: search, tag, selectedId
├── (selectedId равен null)
│   ├── SearchBar       пропсы: value, onChange
│   ├── TagFilter       пропсы: active, onSelect
│   └── RecipeList      пропсы: search, tag, onSelect
│                       загружает /recipes?search=…&tag=…
└── (selectedId задан)
    └── RecipeDetail    пропсы: id, onBack
                        загружает /recipes/:id
```

Несколько решений и их причины:

- **Текст поиска, тег и выбранный рецепт живут в `App`.** Они нужны нескольким компонентам, поэтому подняты в ближайшего общего родителя. Бонус: когда страница рецепта заменяет список, поле поиска исчезает со страницы, но его текст в безопасности в `App` и возвращается вместе с полем.
- **У `SearchBar` и `TagFilter` нет состояния.** Они показывают то, что им передали, и сообщают об изменениях через `onChange` и `onSelect`.
- **Каждый компонент сам загружает данные, которые показывает.** `RecipeList` загружает список, `RecipeDetail` — один рецепт. Обоим нужна одинаковая логика загрузки и ошибок, поэтому мы напишем её **один раз**.
- **Поиском занимается API.** `GET /recipes?search=rice&tag=vegan` ищет по названиям и ингредиентам и фильтрует по тегу на сервере — так же, как это делало бы настоящее приложение с тысячами рецептов.

## Собираем URL

Маленькая обычная функция превращает поиск и тег в URL. `URLSearchParams` позаботится о пробелах и специальных символах, а пустые части мы не добавляем:

```js
const API = "https://api.pandadev.test";

function recipesUrl(search, tag) {
  const params = new URLSearchParams();

}
```

Держать такую логику **за пределами** компонентов — хорошая практика: она никак не связана с React, поэтому её легко читать и легко тестировать с Vitest.

## Свой хук для загрузки данных

В прошлом уроке каждому компоненту, загружающему данные, требовался один и тот же код: `useState` + `useEffect` + загрузка + ошибка. Когда логика компонентов повторяется, вынесите её в **пользовательский хук**: функцию, имя которой начинается с **`use`** и которая вызывает другие хуки.

```jsx
function useJson(url) {
  const [result, setResult] = useState({ url: null });

  useEffect(() => {
    const controller = new AbortController();
    fetch(url, { signal: controller.signal })
      .then(async (res) => {
        const body = await res.json();
        if (!res.ok) throw new Error(body.error ?? `HTTP ${res.status}`);
        setResult({ url, data: body, error: null });
      })
      .catch((err) => {
        if (err.name === "AbortError") return;
        setResult({ url, data: null, error: err.message });
      });
    return () => controller.abort();
  }, [url]);

  if (result.url !== url) {
    return { data: null, error: null, loading: true };
  }
  return { data: result.data, error: result.error, loading: false };
}
```

Как это работает:

- Эффект загружает `url` при каждом его изменении, а очистка **прерывает (abort)** предыдущий запрос, поэтому медленный старый ответ никогда не перезапишет более новый.
- Для ошибок хук берёт сообщение самого API (`{ error: "Recipe not found" }`), если оно есть.
- Результат **помнит, к какому URL он относится**. Если это не текущий URL, новые данные ещё не пришли — значит, идёт загрузка. `loading` **вычисляется**, а не хранится: нет `setLoading`, который можно забыть, и старые данные никогда не покажутся под новым поиском.

Каждый компонент, который вызывает `useJson`, получает **собственное** состояние — так же, как при двух вызовах `useState`. Здесь хук обслуживает сразу два запроса, причём второй зависит от вашего выбора:

Хуки должны выполняться в одном и том же порядке при каждом рендере, поэтому они никогда не могут стоять после `if (...) return`.

<Callout type="tip" title="Называйте его use-что-то">

Префикс `use` — не украшение. Он сообщает React (и линтеру), что функция вызывает хуки, поэтому правила хуков проверяются и внутри неё. Вспомогательная функция, которая **не** вызывает хуков, как `recipesUrl`, должна быть обычной функцией без этого префикса.

</Callout>

## Переключаемся между списком и рецептом

Страница рецепта — это просто **условный рендер** по `selectedId`. `null` означает «покажи список», число — «покажи этот рецепт»:

```jsx
function App() {
  const [search, setSearch] = useState("");
  const [tag, setTag] = useState("all");
  const [selectedId, setSelectedId] = useState(null);

  if (selectedId) {
    return (
      <RecipeDetail
        id={selectedId}
        onBack={() => setSelectedId(null)}
      />
    );
  }
  return (
    <>
      <SearchBar value={search} onChange={setSearch} />
      {/* TagFilter и RecipeList, с onSelect={setSelectedId} */}
    </>
  );
}
```

Передавать сам сеттер в пропсе (`onChange={setSearch}`, `onSelect={setSelectedId}`) вполне нормально, когда дочерний компонент просто сообщает новое значение. В больших приложениях используют **роутер (router)** (например, React Router), чтобы у каждого рецепта был свой URL вроде `/recipes/3` и работала кнопка «Назад» в браузере. Идея та же: какой компонент показан, зависит от состояния.

## Состояния загрузки, ошибки и пустого результата

У списка **четыре** состояния, и в хорошем приложении продумано каждое:

| Состояние | Что показать |
| --- | --- |
| загрузка | `Загрузка...` (или скелетон/спиннер) |
| ошибка | сообщение об ошибке, в идеале — со способом повторить попытку |
| пусто | `Рецепты не найдены.`, чтобы пользователь знал, что поиск сработал |
| данные | список |

Чаще всего забывают про пустое состояние: без него неудачный поиск показывает пустое место, которое выглядит как ошибка.

```jsx
import { useState, useEffect } from "react";
import { createRoot } from "react-dom/client";

const API = "https://api.pandadev.test";
const TAGS = ["all", "vegan", "vegetarian", "quick", "breakfast"];

function recipesUrl(search, tag) {
  const params = new URLSearchParams();
  if (search.trim()) params.set("search", search.trim());
  if (tag !== "all") params.set("tag", tag);
  const query = params.toString();
  return query ? `${API}/recipes?${query}` : `${API}/recipes`;
}

function useJson(url) {
  const [result, setResult] = useState({ url: null });

  useEffect(() => {
    const controller = new AbortController();
    fetch(url, { signal: controller.signal })
      .then(async (res) => {
        const body = await res.json();
        if (!res.ok) throw new Error(body.error ?? `HTTP ${res.status}`);
        setResult({ url, data: body, error: null });
      })
      .catch((err) => {
        if (err.name === "AbortError") return;
        setResult({ url, data: null, error: err.message });
      });
    return () => controller.abort();
  }, [url]);

  if (result.url !== url) {
    return { data: null, error: null, loading: true };
  }
  return { data: result.data, error: result.error, loading: false };
}

function SearchBar({ value, onChange }) {
  return (
    <input
      name="search"
      placeholder="Поиск по рецептам и ингредиентам"
      value={value}
      onChange={(event) => onChange(event.target.value)}
    />
  );
}

function TagFilter({ active, onSelect }) {
  return (
    <div className="tags">
      {TAGS.map((tag) => (
        <button
          key={tag}
          className={tag === active ? "active" : ""}
          onClick={() => onSelect(tag)}
        >
          {tag}
        </button>
      ))}
    </div>
  );
}

function RecipeList({ search, tag, onSelect }) {
  const { data, loading, error } = useJson(recipesUrl(search, tag));

  if (loading) return <p className="status">Загрузка...</p>;
  if (error) return <p className="error">{error}</p>;
  if (data.length === 0) {
    return <p className="empty">Рецепты не найдены.</p>;
  }
  return (
    <ul className="recipes">
      {data.map((recipe) => (
        <li key={recipe.id}>
          <button
            className="recipe"
            onClick={() => onSelect(recipe.id)}
          >
            {recipe.name}
          </button>{" "}
          {recipe.minutes} мин
        </li>
      ))}
    </ul>
  );
}

function RecipeDetail({ id, onBack }) {
  const { data, loading, error } = useJson(`${API}/recipes/${id}`);

  return (
    <article className="detail">
      <button className="back" onClick={onBack}>← Назад</button>
      {loading ? (
        <p className="status">Загрузка...</p>
      ) : error ? (
        <p className="error">{error}</p>
      ) : (
        <>
          <h2>{data.name}</h2>
          <p className="meta">
            {data.minutes} мин · порций: {data.servings}
          </p>
          <h3>Ингредиенты</h3>
          <ul className="ingredients">

          </ul>
          <h3>Шаги</h3>
          <ol className="steps">
            {data.steps.map((step) => <li key={step}>{step}</li>)}
          </ol>
        </>
      )}
    </article>
  );
}

function App() {

  const [tag, setTag] = useState("all");
```

## Создаём настоящий проект

Здесь JSX за вас компилирует страница урока. На своём компьютере стандартный способ начать приложение на React — **Vite**, быстрый инструмент сборки и сервер для разработки:

```bash
npm create vite@latest recipe-browser -- --template react
cd recipe-browser
npm install
npm run dev
```

`npm run dev` выводит локальный адрес (обычно `http://localhost:5173`). Откройте его, измените файл, сохраните — и страница сразу обновится. Разделите приложение на файлы так, как подсказывает план:

```text
recipe-browser/
├── index.html              <div id="root"></div>
├── package.json
└── src/
    ├── main.jsx            createRoot(...).render(<App />)
    ├── App.jsx
    ├── api.js              API и recipesUrl
    ├── hooks/
    │   └── useJson.js
    └── components/
        ├── SearchBar.jsx
        ├── TagFilter.jsx
        ├── RecipeList.jsx
        └── RecipeDetail.jsx
```

`main.jsx` — это точка входа. Шаблон Vite оборачивает приложение в `<StrictMode>`, поэтому в режиме разработки вы увидите, что каждый эффект выполняется дважды. `useJson` к этому готов: его очистка прерывает первый запрос.

```jsx title="src/main.jsx"
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

Учебный API существует только внутри PandaDev, поэтому в настоящем приложении направьте `API` на реальный сервис, а адрес храните не в коде, а в **переменной окружения (environment variable)** Vite. Переменные, которые начинаются с `VITE_`, из файла `.env` доступны через `import.meta.env`:

```bash title=".env"
VITE_API_URL=https://api.example.com
```

```js title="src/api.js"
export const API = import.meta.env.VITE_API_URL;
```

Для практики подойдут бесплатные публичные API с рецептами, например TheMealDB. Их JSON выглядит иначе, поэтому `recipesUrl` и компоненты придётся под него адаптировать. Когда всё готово, `npm run build` создаёт оптимизированную папку `dist/`, которую можно выложить на любой статический хостинг.

<Callout type="note" title="Никогда не храните секреты во фронтенд-коде">

Всё в приложении на React, включая значения `import.meta.env`, попадает в JavaScript, который **кто угодно** может прочитать в своём браузере. Публичные адреса — это нормально, секретные ключи API — нет. Настоящие приложения хранят секретные ключи на **сервере**, который обращается к API за них, — именно этому посвящён модуль про Node.js и Express.

</Callout>

## Итоги

- Сначала план: набросайте **дерево компонентов**, затем решите, **где живёт каждая часть состояния** (в ближайшем общем родителе всех, кому она нужна).
- Обычную логику, например сборку URL с `URLSearchParams`, держите в обычных функциях за пределами компонентов.
- **Пользовательский хук** (`useJson`) — это функция `use...`, которая вызывает другие хуки. Так несколько компонентов разделяют логику, а состояние у каждого своё.
- Страница подробностей может быть простым **условным рендером** по состоянию `selectedId`; роутеры дают каждому экрану свой URL.
- Продумывайте все четыре состояния списка: **загрузку, ошибку, пустой результат и данные**.
- Начинайте настоящие проекты с `npm create vite@latest`, раскладывайте компоненты по файлам и храните настройки в переменных окружения `VITE_` — но никогда не секреты.
