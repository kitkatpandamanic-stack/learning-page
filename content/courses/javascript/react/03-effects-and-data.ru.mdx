До сих пор ваши компоненты были **чистыми (pure)**: они принимают пропсы и состояние и возвращают JSX — и больше ничего. Но приложениям нужно общаться и с внешним миром: загружать данные из API, запускать таймер, менять заголовок страницы. Это **побочные эффекты (side effects)**, и для них в React есть отдельное место — хук **`useEffect`**. В этом уроке вы с его помощью загрузите настоящие данные из учебного API PandaDev — с правильными состояниями загрузки и ошибки. 🌐

## Рендер должен оставаться чистым

React может вызывать ваш компонент много раз: при каждом изменении состояния, при повторном рендере родителя и дважды в режиме разработки, чтобы ловить ошибки (подробнее ниже). Поэтому тело компонента должно только **вычислять** JSX. Если бы оно загружало данные напрямую, каждый рендер отправлял бы новый запрос, ответ менял бы состояние, это вызывало бы рендер, а тот — новый запрос...

```jsx
function Recipes() {
  const [recipes, setRecipes] = useState([]);

  // ❌ Выполняется при КАЖДОМ рендере, а setRecipes вызывает новый рендер
  fetch(`${API}/recipes`)
    .then((res) => res.json())
    .then(setRecipes);

  return <p>Рецептов: {recipes.length}</p>;
}
```

Получается бесконечный цикл запросов. Побочные эффекты должны выполняться **после** рендера и только тогда, когда изменилось что-то важное для них.

## Ваш первый эффект

`useEffect(fn)` говорит React: *«после того как обновишь экран, выполни `fn`»*. Запустите код и нажмите на кнопку:

<TryIt
  language="react"
  code={`import { useState, useEffect } from "react";
import { createRoot } from "react-dom/client";

function Clicker() {
  const [count, setCount] = useState(0);
  console.log("1. рендер, count =", count);

  useEffect(() => {
    console.log("2. эффект, на экране", count);
    document.title = \`Нажатий: \${count}\`;
  });

  return (
    <button onClick={() => setCount(count + 1)}>
      Нажатий: {count}
    </button>
  );
}

createRoot(document.getElementById("root")).render(<Clicker />);`}
/>

Сначала всегда идёт рендер, потом эффект. Установка `document.title` (текста на вкладке браузера) — типичный эффект: он меняет что-то **за пределами** React.

## Массив зависимостей

Эффект без второго аргумента выполняется после **каждого** рендера. Обычно это слишком часто. Второй аргумент — **массив зависимостей (dependency array)** — перечисляет значения, которые использует эффект, и React перезапускает эффект, только когда одно из них изменилось:

| Вы пишете | Эффект выполняется |
| --- | --- |
| `useEffect(fn)` | после каждого рендера |
| `useEffect(fn, [])` | один раз, после первого рендера |
| `useEffect(fn, [name])` | после первого рендера и каждый раз, когда меняется `name` |

Понажимайте обе кнопки и посмотрите, какие эффекты выполняются:

<TryIt
  language="react"
  code={`import { useState, useEffect } from "react";
import { createRoot } from "react-dom/client";

function Demo() {
  const [count, setCount] = useState(0);

  useEffect(() => {

  useEffect(() => {
    console.log("теперь name =", name);

      <button onClick={() => setCount(count + 1)}>
        Счётчик: {count}

/>

Правило простое: **каждое значение из компонента, которое читает эффект, должно быть в массиве** (пропсы, состояние и всё, что из них вычислено). Если пропустить хотя бы одно, эффект будет использовать старое значение — а такую ошибку трудно заметить.

<Callout type="tip" title="Пусть линтер следит за вами">

В реальных проектах ESLint-плагин `eslint-plugin-react-hooks` проверяет массивы зависимостей и предупреждает, если чего-то не хватает. В шаблоне React для Vite он уже включён. Не заглушайте его: если он ругается, исправление почти всегда — добавить зависимость или вынести код из эффекта.

</Callout>

## Загрузка данных

Загрузка данных — самый частый эффект. Хороший компонент, загружающий данные, обрабатывает **три состояния**: ещё загружается, ошибка и загружено. В PandaDev встроен учебный API, поэтому эти уроки работают без интернета и всегда дают одинаковые ответы. Настоящие API работают точно так же.

<TryIt
  language="react"
  code={`import { useState, useEffect } from "react";
import { createRoot } from "react-dom/client";

const API = "https://api.pandadev.test";

function VeganRecipes() {
  const [recipes, setRecipes] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    async function load() {
      try {
        const res = await fetch(\`\${API}/recipes?tag=vegan\`);
        if (!res.ok) throw new Error(\`HTTP \${res.status}\`);
        setRecipes(await res.json());
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }
    load();
  }, []);

  if (loading) return <p>Загрузка...</p>;
  if (error) return <p>😿 Что-то пошло не так: {error}</p>;
  return (
    <ul>
      {recipes.map((r) => (
        <li key={r.id}>{r.name} ({r.minutes} мин)</li>
      ))}
    </ul>
  );
}

createRoot(document.getElementById("root")).render(<VeganRecipes />);`}
/>

Сначала вы на мгновение увидите **Загрузка...**, а затем список. Чтобы увидеть состояние ошибки, замените URL на `${API}/status/500` и запустите ещё раз.

Зачем внутренняя функция `load`? Потому что сама функция эффекта **не может быть `async`**. Асинхронная функция всегда возвращает промис (promise), а React ожидает, что эффект вернёт либо ничего, либо **функцию очистки (cleanup)**:

```jsx
// ❌ Эффект возвращает промис
useEffect(async () => {
  const res = await fetch(url);
}, []);

// ✅ Объявите асинхронную функцию внутри и вызовите её
useEffect(() => {
  async function load() {
    const res = await fetch(url);
  }
  load();
}, []);
```

## Очистка: отменяем устаревшие запросы

Эффект может **вернуть функцию**. React вызывает эту функцию **очистки (cleanup)** перед повторным запуском эффекта и когда компонент исчезает со страницы. Здесь отменяют то, что начал эффект: останавливают таймер, удаляют обработчик, отменяют запрос.

Отмена важна для поиска. Быстро наберите **pa**: сначала отправится запрос для `p`, затем для `pa`. Если ответ для `p` придёт **последним**, страница покажет результаты не того поиска. Если в функции очистки использовать **`AbortController`**, каждый новый поиск отменяет предыдущий запрос:

<TryIt
  language="react"
  code={`import { useState, useEffect } from "react";
import { createRoot } from "react-dom/client";

const API = "https://api.pandadev.test";

function RecipeSearch() {
  const [query, setQuery] = useState("");
  const [recipes, setRecipes] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const controller = new AbortController();
    const params = new URLSearchParams({ search: query });

    fetch(\`\${API}/recipes?\${params}\`, { signal: controller.signal })
      .then((res) => res.json())
      .then((data) => {
        setRecipes(data);
        setLoading(false);
      })
      .catch((err) => {
        if (err.name === "AbortError") {
          console.log(\`Поиск "\${query}" отменён\`);
        }
      });

    return () => controller.abort();
  }, [query]);

  function handleChange(event) {
    setQuery(event.target.value);
    setLoading(true);
  }

  return (
    <>
      <input
        value={query}
        onChange={handleChange}
        placeholder="Например: soup, rice, mushrooms"
      />
      {loading ? (
        <p>Ищем...</p>
      ) : (
        <ul>
          {recipes.map((r) => <li key={r.id}>{r.name}</li>)}
        </ul>
      )}
    </>
  );
}

createRoot(document.getElementById("root")).render(<RecipeSearch />);`}
/>

Печатайте быстро — и увидите в выводе отменённые поиски. Порядок событий для одного нажатия клавиши такой: рендер с новым `query`, **очистка** предыдущего эффекта (отмена старого запроса), затем новый эффект (отправка нового запроса).

Обратите внимание: `setLoading(true)` вызывается в **обработчике события**, а не в эффекте. Новый поиск начинается потому, что пользователь печатает, — значит, этому вызову место именно там.

Если что-то отменить нельзя (не каждое асинхронное API принимает `signal`), используйте **флаг ignore**. Ответ всё равно придёт, но старый эффект будет знать, что он устарел:

```jsx
useEffect(() => {
  let ignore = false;
  fetch(url)
    .then((res) => res.json())
    .then((data) => {
      if (!ignore) setRecipes(data);
    });
  return () => {
    ignore = true;
  };
}, [url]);
```

<Callout type="note" title="Почему мой эффект выполняется дважды?">

В реальных проектах приложение оборачивают в `<StrictMode>` (в шаблоне Vite так и сделано). **Только в режиме разработки** Strict Mode рендерит каждый компонент дважды и сразу после первого рендера выполняет каждый эффект, его очистку и снова эффект. В поиске выше вы бы увидели один отменённый запрос при запуске. Это сделано нарочно: если приложение ломается, когда эффект выполняется дважды, значит, у вас не хватает очистки. В продакшене эффекты выполняются один раз.

</Callout>

## Когда эффект не нужен

Эффекты нужны для синхронизации с тем, что находится **за пределами** React. Многие эффекты, которые пишут новички, вообще не нужны: они делают приложение медленнее и добавляют ошибок. Три частых случая:

**1. Значения, которые можно вычислить.** Вычисляйте их во время рендера, как в прошлом уроке:

```jsx
// ❌ Лишнее состояние и лишний рендер
const [visible, setVisible] = useState([]);
useEffect(() => {
  setVisible(recipes.filter((r) => r.tags.includes(tag)));
}, [recipes, tag]);

// ✅ Просто вычислите
const visible = recipes.filter((r) => r.tags.includes(tag));
```

**2. Действия, вызванные пользователем.** Помещайте их в обработчик события. Версия с эффектом срабатывает каждый раз, когда `saved` меняется по **любой** причине, а не только после щелчка:

```jsx
// ❌ Отправляем запрос, потому что изменилось какое-то состояние
useEffect(() => {
  if (saved) fetch(`${API}/todos`, { method: "POST", body });
}, [saved]);

// ✅ Отправляем, когда пользователь нажимает кнопку
function handleSave() {
  fetch(`${API}/todos`, { method: "POST", body });
}
```

**3. Сброс состояния при изменении пропса.** Вместо эффекта дайте компоненту **`key`**: новый ключ заставляет React начать с чистого листа, с новым состоянием.

```jsx
// ✅ Новый recipeId — совершенно новый RecipeNotes с пустым состоянием
<RecipeNotes key={recipeId} recipeId={recipeId} />
```

Хорошая проверка: *«Этот код здесь потому, что компонент **на экране**?»* Загрузка данных, которые он показывает, подключение к чату, запуск часов — это эффект. *«Он здесь потому, что пользователь **что-то сделал**?»* — это обработчик события.

В больших проектах данные обычно загружают с помощью библиотеки вроде **TanStack Query** или **SWR** либо средствами фреймворка (Next.js, React Router). Они берут на себя кеширование, повторные попытки и устаревшие ответы, но внутри делают то же самое, что вы только что написали вручную.

<Hint>

Внутри `useEffect(() => { ... }, [id])` напишите `let ignore = false;` и `async function load()` с `try / catch / finally`: `const res = await fetch(...)`, `const data = await res.json()`, затем `if (ignore) return;` и `if (res.ok)`. В `finally` — `if (!ignore) setLoading(false)`. Вызовите `load()` и верните `() => { ignore = true; }`. Для JSX хорошо подходит цепочка тернарных операторов: `loading ? (...) : error ? (...) : (...)`. `·` — это символ «средняя точка», скопируйте его из этого текста.

</Hint>

```jsx
import { useState, useEffect } from "react";
import { createRoot } from "react-dom/client";

const API = "https://api.pandadev.test";

function RecipeViewer() {
  const [id, setId] = useState(1);
  const [recipe, setRecipe] = useState(null);
  const [error, setError] = useState(null);
  const [loading, setLoading] = useState(true);

  function handleChange(event) {
    setId(Number(event.target.value));
    setLoading(true);
  }

  useEffect(() => {
    let ignore = false;

    async function load() {
      try {
        const res = await fetch(`${API}/recipes/${id}`);
        const data = await res.json();
        if (ignore) return;
        if (res.ok) {
          setRecipe(data);
          setError(null);
        } else {
          setRecipe(null);
          setError(data.error);
        }
      } catch (err) {
        if (!ignore) setError(err.message);
      } finally {
        if (!ignore) setLoading(false);
      }
    }

    load();
    return () => {
      ignore = true;
    };
  }, [id]);

  return (
    <div>
      <label>
        Рецепт №{" "}
        <input
          type="number"
          name="id"
          min="1"
          value={id}
          onChange={handleChange}
        />
      </label>
      {loading ? (
        <p className="status">Загрузка...</p>
      ) : error ? (
        <p className="error">{error}</p>
      ) : (
        <article>
          <h2>{recipe.name}</h2>
          <p className="meta">
            {recipe.minutes} мин · порций: {recipe.servings}
          </p>
          <ul className="ingredients">
            {recipe.ingredients.map((item) => (
              <li key={item}>{item}</li>
            ))}
          </ul>
        </article>
      )}
    </div>
  );
}

createRoot(document.getElementById("root")).render(
  <RecipeViewer />
);
```

## Итоги

- Рендер должен оставаться **чистым**. Побочные эффекты (загрузка данных, таймеры, заголовок страницы, подписки) помещают в **`useEffect`**, который выполняется **после** того, как React обновит экран.
- **Массив зависимостей** решает, когда эффект выполняется: без массива — после каждого рендера, `[]` — один раз, `[a, b]` — когда меняется `a` или `b`. Перечисляйте каждое значение, которое читает эффект.
- Загружайте данные `async`-функцией **внутри** эффекта и обрабатывайте состояния **загрузки**, **ошибки** и **готовых данных**. Проверяйте `res.ok`.
- Возвращайте функцию **очистки**, чтобы отменить эффект: прервите запрос с помощью `AbortController` или поставьте флаг **ignore**, чтобы отбрасывать устаревшие ответы.
- Strict Mode в режиме разработки запускает эффекты дважды, чтобы найти недостающую очистку.
- Эффект **не нужен** для значений, которые можно вычислить (вычисляйте их), для реакции на действия пользователя (используйте обработчик события) и для сброса состояния (используйте `key`).
