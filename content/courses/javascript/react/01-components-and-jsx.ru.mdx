В [списке дел](/learn/javascript/state-and-rendering) из уровня 1 вы использовали **шаблон рендера**: все данные хранятся в одном месте, а функция `render()` заново строит по ним страницу при каждом изменении. Это работает, но каждый `createElement`, каждый `innerHTML = ""` и каждый обработчик события вы писали вручную. **React** — это библиотека, которая берёт эту часть работы на себя. Сегодня это самый популярный способ создавать пользовательские интерфейсы в вебе. ⚛️

## Зачем нужен React?

Главная идея React умещается в одну строку:

```text
UI = f(state)
```

Страница — это **результат функции** от ваших данных. Вы описываете, как должен выглядеть экран при текущих данных, а React сам вычисляет, какие изменения в DOM нужны, чтобы к этому прийти. Эта идея вам уже знакома по обычному JavaScript:

<CodeExample output={`<p>Рецептов пока нет</p>
<p>Рецептов: 2 (Pancakes, Soup)</p>`}>

```js
function recipeSummary(recipes) {
  if (recipes.length === 0) return "<p>Рецептов пока нет</p>";
  const names = recipes.join(", ");
  return `<p>Рецептов: ${recipes.length} (${names})</p>`;
}

console.log(recipeSummary([]));
console.log(recipeSummary(["Pancakes", "Soup"]));
```

</CodeExample>

Одни и те же данные на входе — одна и та же страница на выходе. Что добавляет React:

- **Компоненты (components)**: вместо одного огромного `render()` вы делите страницу на маленькие функции, которые можно переиспользовать (`RecipeCard`, `SearchBar`, `App`).
- **Эффективные обновления**: React сравнивает новый результат со старым и трогает только те части DOM, которые действительно изменились. Поэтому поля ввода сохраняют фокус и введённый текст.
- **Встроенные состояние и события**: меняете данные — React сам перерисовывает страницу (это тема следующего урока).

Такой стиль называют **декларативным (declarative)**: вы говорите, *что* должно быть на странице, а не *как* шаг за шагом её менять.

## Ваш первый компонент

**Компонент (component)** — это функция JavaScript, имя которой начинается с **заглавной буквы** и которая возвращает разметку. Нажмите **«Запустить»**:

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function Greeting() {
  return <h1>Привет от React! 🐼</h1>;
}

const root = createRoot(document.getElementById("root"));
root.render(<Greeting />);`}
/>

Здесь происходят три вещи:

1. `import { createRoot } from "react-dom/client"` загружает инструменты React для браузера (с `import` вы познакомились в [уроке о модулях](/learn/javascript/modules)).
2. `createRoot(...)` передаёт React пустой элемент на странице — `<div id="root">`. С этого момента всё внутри него — забота React.
3. `root.render(<Greeting />)` рисует там компонент `Greeting`. Компонент используется как HTML-тег.

Так начинается любое приложение на React — обычно с одного компонента верхнего уровня под названием `App`.

## JSX: похожий на HTML синтаксис в JavaScript

Этот `<h1>` внутри функции JavaScript — это **JSX**. Это не HTML и не строка: перед запуском в браузере инструмент сборки превращает его в обычные вызовы функций.

```jsx
// Что вы пишете:
const title = <h1 className="big">Hi!</h1>;

// Примерно во что это превращается:
const title = React.createElement("h1", { className: "big" }, "Hi!");
```

JSX — это на самом деле JavaScript, поэтому в фигурные скобки `{}` можно поместить любое **выражение (expression)**: переменные, арифметику, вызовы функций, тернарный оператор.

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function RecipeOfTheDay() {
  const recipe = { name: "Pancakes", minutes: 25, servings: 4 };
  const perPerson = recipe.minutes / recipe.servings;

  return (
    <section className="card">
      <h2>{recipe.name.toUpperCase()}</h2>
      <p>Готово за {recipe.minutes} минут.</p>
      <p>Это {perPerson} минуты готовки на человека!</p>
      <hr />
    </section>
  );
}

createRoot(document.getElementById("root")).render(
  <RecipeOfTheDay />
);`}
/>

В JSX есть несколько правил, о которые поначалу спотыкаются все:

- **Возвращайте один корневой элемент.** Двум элементам рядом нужен общий родитель. Если лишний `<div>` не нужен, используйте **фрагмент (fragment)**: `<>...</>`.
- **Закрывайте каждый тег**, даже те, что HTML разрешает оставлять открытыми: `<img />`, `<input />`, `<br />`.
- **Атрибуты пишутся в camelCase**, а некоторые переименованы, потому что конфликтуют со словами JavaScript: `class` превращается в **`className`**, `for` — в **`htmlFor`**, `onclick` — в **`onClick`**.
- **Фигурные скобки принимают выражения, а не инструкции.** `{if (x) ...}` или `{for ...}` не сработают — используйте тернарный оператор, `&&` или `map` (о них ниже).
- Многострочный JSX после `return` оборачивайте в **круглые скобки**, иначе JavaScript вернёт `undefined` из-за пустой строки.

```jsx
// ❌ Два корня, "class" и незакрытый тег
return (
  <h1 class="title">Рецепты</h1>
  <input>
);

// ✅ Фрагмент, className и закрытый тег
return (
  <>
    <h1 className="title">Рецепты</h1>
    <input />
  </>
);
```

## Пропсы: передаём данные в компоненты

Компонент, который всегда показывает одно и то же, не слишком полезен. **Пропсы (props**, сокращение от properties — «свойства») позволяют родителю передать данные в компонент — точно так же, как аргументы в функцию. Они записываются как HTML-атрибуты, а компонент получает их **одним объектом**, который обычно сразу деструктурируют:

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function RecipeCard({ name, minutes, servings = 2 }) {
  return (
    <article>
      <h3>{name}</h3>
      <p>{minutes} мин · порций: {servings}</p>
    </article>
  );
}

function App() {
  return (
    <main>
      <h1>Кулинарная книга панды</h1>
      <RecipeCard name="Pancakes" minutes={25} servings={4} />
      <RecipeCard name="Guacamole" minutes={10} />
      <RecipeCard name="Tomato Soup" minutes={35} servings={4} />
    </main>
  );
}

createRoot(document.getElementById("root")).render(<App />);`}
/>

На что стоит обратить внимание:

- Строки можно передавать в кавычках (`name="Pancakes"`), а всё остальное — в фигурных скобках (`minutes={25}`, `tags={["vegan"]}`, `onPick={handlePick}`).
- Значения по умолчанию работают так же, как параметры по умолчанию: Guacamole получает `servings = 2`.
- Один компонент — три разные карточки. В этом весь смысл: написали один раз, используете везде.

<Callout type="warning" title="Пропсы только для чтения">

Компонент никогда не должен менять собственные пропсы (`props.minutes = 5` или `push` в массив из пропсов). Считайте их аргументами **чистой функции (pure function)**: одинаковые пропсы на входе — одинаковый JSX на выходе. Когда данные должны меняться со временем, это **состояние (state)** — с ним вы познакомитесь в следующем уроке.

</Callout>

## Children: компоненты-обёртки

Всё, что вы помещаете **между** открывающим и закрывающим тегом компонента, попадает в особый проп **`children`**. Он идеально подходит для компонентов-«обёрток»: карточек, панелей, макетов:

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function Panel({ title, children }) {
  return (
    <section
      style={{ border: "1px solid #7c3aed", borderRadius: 12,
               padding: "4px 16px", marginBottom: 12 }}
    >
      <h3>{title}</h3>
      {children}
    </section>
  );
}

function App() {
  return (
    <>
      <Panel title="Совет дня">
        <p>Дайте тесту для блинов постоять 10 минут.</p>
      </Panel>
      <Panel title="Список покупок">
        <ul>
          <li>Мука</li>
          <li>Яйца</li>
        </ul>
      </Panel>
    </>
  );
}

createRoot(document.getElementById("root")).render(<App />);`}
/>

`Panel` всё равно, что внутри: абзац, список или даже другие компоненты. Обратите внимание на **двойные фигурные скобки** в `style={{ ... }}`: внешняя пара означает «выражение JavaScript», а внутренняя — это объект со свойствами CSS (в camelCase, например `borderRadius`).

## Рендер списков с ключами

Чтобы показать список, превратите **массив данных** в **массив JSX** с помощью `map`. React отрисовывает элементы массива один за другим:

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

const recipes = [
  { id: 1, name: "Bamboo Shoot Stir-fry", minutes: 20 },
  { id: 2, name: "Pancakes", minutes: 25 },
  { id: 5, name: "Guacamole", minutes: 10 },
];

function RecipeList() {
  return (
    <ul>
      {recipes.map((recipe) => (
        <li key={recipe.id}>
          {recipe.name} ({recipe.minutes} мин)
        </li>
      ))}
    </ul>
  );
}

createRoot(document.getElementById("root")).render(<RecipeList />);`}
/>

Каждому элементу нужен **ключ (`key`)** — значение, которое **уникально среди соседей** и **не меняется** для этого элемента. Когда список меняется, React по ключам понимает, где какой элемент, и может переместить, добавить или удалить ровно те элементы, что нужно. Удалите `key={recipe.id}` и нажмите **«Запустить»** — React пожалуется в выводе:

```text
Each child in a list should have a unique "key" prop.

Check the render method of `RecipeList`. See https://react.dev/link/warning-keys for more information.
```

Это значит: «У каждого дочернего элемента списка должен быть уникальный проп "key"».

<Callout type="tip" title="Используйте id, а не индексы">

Лучший ключ — это **id из ваших данных** (`recipe.id`). Индекс массива (`map((r, i) => <li key={i}>`) убирает предупреждение, но если элементы добавляются, удаляются или сортируются, индекс 0 вдруг начинает принадлежать другому элементу, и React может перепутать их состояние (например, в каком поле ввода какой текст). Используйте индекс только для списков, которые никогда не меняются.

</Callout>

## Условный рендер

Раз JSX — это JavaScript, показывать что-то по условию можно уже знакомыми средствами:

- **Ранний `return`** — когда весь компонент должен показать что-то другое.
- **Тернарный оператор** `cond ? a : b` внутри JSX — чтобы выбрать одно из двух.
- **`cond && <Thing />`** — чтобы показать что-то или ничего.

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function RecipeCard({ name, minutes, tags }) {
  return (
    <li>
      <strong>{name}</strong>{" "}
      {minutes <= 15 && <span>⚡ Быстро</span>}
      <br />
      {tags.length > 0 ? tags.join(", ") : "Без тегов"}
    </li>
  );
}

function RecipeList({ recipes }) {
  if (recipes.length === 0) {
    return <p>Рецепты не найдены.</p>;
  }
  return (
    <ul>
      {recipes.map((r) => (
        <RecipeCard key={r.id} {...r} />
      ))}
    </ul>
  );
}

const recipes = [
  { id: 5, name: "Guacamole", minutes: 10, tags: ["vegan"] },
  { id: 3, name: "Tomato Soup", minutes: 35, tags: ["soup"] },
  { id: 9, name: "Toast", minutes: 3, tags: [] },
];

createRoot(document.getElementById("root")).render(
  <>
    <RecipeList recipes={recipes} />
    <RecipeList recipes={[]} />
  </>
);`}
/>

Здесь спрятаны два новых приёма: `{" "}` добавляет пробел между двумя элементами на разных строках, а `{...r}` **разворачивает (spread)** все свойства рецепта в пропсы (то же самое, что написать `name={r.name} minutes={r.minutes} tags={r.tags}`). Ключ `key` ставится на компонент внутри `map`, а не на `<li>` внутри него.

Классическая ошибка с `&&`: React отрисовывает число `0`. Поэтому `{recipes.length && <List />}` на пустом списке покажет одинокий **0**. Делайте условие настоящим логическим значением: `{recipes.length > 0 && <List />}`.

## В реальных проектах

В настоящем приложении каждый компонент обычно лежит в своём файле и экспортируется, а JSX за вас обрабатывает инструмент сборки (например, Vite — вы настроите его в конце этого модуля):

import RecipeCard from "./RecipeCard.jsx";

```jsx
import { createRoot } from "react-dom/client";

const recipes = [
  { id: 1, name: "Bamboo Shoot Stir-fry", minutes: 20,
    tags: ["vegan", "asian"] },
  { id: 5, name: "Guacamole", minutes: 10, tags: ["vegan"] },
  { id: 7, name: "Banana Smoothie", minutes: 5, tags: [] },
];

function RecipeCard({ name, minutes, tags }) {
  return (
    <li className="recipe">
      <h2>{name}</h2>
      <p className="time">{minutes} мин</p>
      {minutes <= 10 && <span className="badge">Быстро</span>}

  return (
    <ul className="recipes">
      {recipes.map((recipe) => (
        <RecipeCard key={recipe.id} {...recipe} />
      ))}
    </ul>
  );
}

createRoot(document.getElementById("root")).render(
  <RecipeList recipes={recipes} />
);
```

## Итоги

- React строит страницу из ваших данных: **UI = f(state)**. Вы описываете, что показать, а React эффективно обновляет DOM.
- `createRoot(element).render(<App />)` запускает приложение React внутри элемента на странице.
- **JSX** превращается в вызовы `React.createElement`. Правила: один корень (или фрагмент `<>...</>`), каждый тег закрыт, атрибуты в camelCase, `className` и `htmlFor`, а `{}` — для выражений.
- **Компоненты** — это функции с заглавной буквы, которые возвращают JSX. **Пропсы** передают данные внутрь, как аргументы функции, и доступны только для чтения. **`children`** — это всё, что находится между тегами.
- Списки рендерятся через `map`, и каждому элементу нужен стабильный уникальный **`key`** (id, а не индекс).
- Показывайте элементы по условию с помощью раннего `return`, **тернарного оператора** или **`&&`** (с настоящим логическим значением, чтобы не отрисовать случайный `0`).
