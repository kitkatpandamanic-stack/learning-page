Time to put the whole module together. You'll build a **recipe browser**: search recipes by name or ingredient, filter them by tag, click one to see its ingredients and steps, and go back to the list without losing your search. It loads everything from the practice API, with proper loading, error and empty states. Along the way you'll write your first **custom hook**, and at the end you'll see how to start the same app as a real project on your computer. 🍜

## The plan

Before writing code, React developers sketch two things: the **components** and **where the state lives**.

```text
App                     state: search, tag, selectedId
├── (selectedId is null)
│   ├── SearchBar       props: value, onChange
│   ├── TagFilter       props: active, onSelect
│   └── RecipeList      props: search, tag, onSelect
│                       loads /recipes?search=…&tag=…
└── (selectedId is set)
    └── RecipeDetail    props: id, onBack
                        loads /recipes/:id
```

Some decisions, and why:

- **The search text, the tag and the selected recipe live in `App`.** Several components need them, so they're lifted up to the closest common parent. A bonus: when the detail view replaces the list, the search box disappears from the page, but its text is safe in `App` and comes back with it.
- **`SearchBar` and `TagFilter` hold no state.** They show what they're given and report changes through `onChange` and `onSelect`.
- **Each component loads the data it shows.** `RecipeList` loads the list, `RecipeDetail` loads one recipe. Both need the same loading/error logic, so we'll write it **once**.
- **The API does the searching.** `GET /recipes?search=rice&tag=vegan` searches names and ingredients and filters by tag on the server, just like a real app with thousands of recipes would.

## Building the URL

A small, plain function turns the search and the tag into a URL. `URLSearchParams` takes care of spaces and special characters, and we leave out empty parts:

<CodeExample output={`https://api.pandadev.test/recipes

https://api.pandadev.test/recipes?search=rice&tag=vegan

```js
const API = "https://api.pandadev.test";

function recipesUrl(search, tag) {
  const params = new URLSearchParams();
  if (search.trim()) params.set("search", search.trim());
  if (tag !== "all") params.set("tag", tag);
  const query = params.toString();
  return query ? `${API}/recipes?${query}` : `${API}/recipes`;
}

console.log(recipesUrl("  soup ", "all"));
console.log(recipesUrl("rice", "vegan"));
```

## A custom hook for loading data

In the last lesson every component that loaded data needed the same `useState` + `useEffect` + loading + error code. When component logic repeats, extract it into a **custom hook**: a function whose name starts with **`use`** and that calls other hooks.

```jsx
function useJson(url) {
  const [result, setResult] = useState({ url: null });

  useEffect(() => {
    const controller = new AbortController();
    fetch(url, { signal: controller.signal })
      .then(async (res) => {
        const body = await res.json();
        if (!res.ok) throw new Error(body.error ?? `HTTP ${res.status}`);
        setResult({ url, data: body, error: null });
      })
      .catch((err) => {
        if (err.name === "AbortError") return;
        setResult({ url, data: null, error: err.message });
      });
    return () => controller.abort();
  }, [url]);

  if (result.url !== url) {
    return { data: null, error: null, loading: true };
  }
  return { data: result.data, error: result.error, loading: false };
}
```

How it works:

- The effect loads `url` whenever it changes, and the cleanup **aborts** the previous request, so a slow old answer can never overwrite a newer one.
- For errors, it uses the API's own message (`{ error: "Recipe not found" }`) when there is one.
- The result **remembers which URL it belongs to**. If that isn't the current URL, the new data hasn't arrived yet, so we're loading. `loading` is **derived**, not stored: there's no `setLoading` to forget, and the old data is never shown under a new search.

Each component that calls `useJson` gets **its own** state, just like calling `useState` twice. Here it powers two requests at once, and the second one depends on what you pick:

<Callout type="tip" title="Name it use-something">

The `use` prefix isn't decoration. It tells React (and the linter) that the function calls hooks, so the rules of hooks are checked inside it too. A helper that **doesn't** call any hooks, like `recipesUrl`, should be a normal function without the prefix.

</Callout>

## Switching between the list and the details

The detail view is just **conditional rendering** on `selectedId`. `null` means "show the list"; a number means "show that recipe":

```jsx
function App() {
  const [search, setSearch] = useState("");
  const [tag, setTag] = useState("all");
  const [selectedId, setSelectedId] = useState(null);

  if (selectedId) {
    return (
      <RecipeDetail
        id={selectedId}
        onBack={() => setSelectedId(null)}
      />
    );
  }
  return (
    <>
      <SearchBar value={search} onChange={setSearch} />
      {/* TagFilter and RecipeList, with onSelect={setSelectedId} */}
    </>
  );
}
```

Passing the setter itself as a prop (`onChange={setSearch}`, `onSelect={setSelectedId}`) is fine when the child just reports a new value. In bigger apps you'd use a **router** (like React Router) so each recipe gets its own URL, such as `/recipes/3`, and the browser's Back button works too. The idea is the same: which component is shown depends on state.

## Loading, error and empty states

A list has **four** states, and a polished app designs each one:

| State | Show |
| --- | --- |
| loading | `Loading...` (or a skeleton/spinner) |
| error | the error message, ideally with a way to retry |
| empty | `No recipes found.`, so users know the search worked |
| data | the list |

The empty state is the one most often forgotten: without it, an unsuccessful search shows a blank space that looks like a bug.

Build the recipe browser from the plan. `recipesUrl` and `useJson` are ready; you write the components and `App`:

1. **`App`** holds three states: `search` (starts `""`), `tag` (starts `"all"`) and `selectedId` (starts `null`). If a recipe is selected, show only `RecipeDetail`; otherwise show `SearchBar`, `TagFilter` and `RecipeList`.
2. **`SearchBar`**: a controlled `<input name="search">` that calls `onChange` with the new text.
3. **`TagFilter`**: a `<div className="tags">` with one `<button>` per tag in `TAGS` (the button text is the tag). The active tag's button gets `className="active"`; clicking one calls `onSelect(tag)`.
4. **`RecipeList`**: load `recipesUrl(search, tag)` with `useJson`, then show `<p className="status">Loading...</p>`, `<p className="error">` with the message, `<p className="empty">No recipes found.</p>` for an empty list, or a `<ul className="recipes">` with an `<li>` per recipe containing `<button className="recipe">` with the recipe's name. Clicking it calls `onSelect(recipe.id)`.
5. **`RecipeDetail`**: load `` `${API}/recipes/${id}` `` with `useJson` and show an `<article className="detail">` with a `<button className="back">` that calls `onBack`, then the loading or error message, or an `<h2>` with the name, a `<p className="meta">` like `35 min · serves 4`, a `<ul className="ingredients">` and an `<ol className="steps">`.

Try it in the preview: search for `rice`, pick **vegetarian**, open a recipe and go back.

```jsx
import { useState, useEffect } from "react";
import { createRoot } from "react-dom/client";

const API = "https://api.pandadev.test";
const TAGS = ["all", "vegan", "vegetarian", "quick", "breakfast"];

function recipesUrl(search, tag) {
  const params = new URLSearchParams();
  if (search.trim()) params.set("search", search.trim());
  if (tag !== "all") params.set("tag", tag);
  const query = params.toString();
  return query ? `${API}/recipes?${query}` : `${API}/recipes`;
}

function useJson(url) {
  const [result, setResult] = useState({ url: null });

  useEffect(() => {
    const controller = new AbortController();
    fetch(url, { signal: controller.signal })
      .then(async (res) => {
        const body = await res.json();
        if (!res.ok) throw new Error(body.error ?? `HTTP ${res.status}`);
        setResult({ url, data: body, error: null });
      })
      .catch((err) => {
        if (err.name === "AbortError") return;
        setResult({ url, data: null, error: err.message });
      });
    return () => controller.abort();
  }, [url]);

  if (result.url !== url) {
    return { data: null, error: null, loading: true };
  }
  return { data: result.data, error: result.error, loading: false };
}

function SearchBar({ value, onChange }) {
  return (
    <input
      name="search"
      placeholder="Search recipes or ingredients"
      value={value}
      onChange={(event) => onChange(event.target.value)}
    />
  );
}

function TagFilter({ active, onSelect }) {
  return (
    <div className="tags">
      {TAGS.map((tag) => (
        <button
          key={tag}
          className={tag === active ? "active" : ""}
          onClick={() => onSelect(tag)}
        >
          {tag}
        </button>
      ))}
    </div>
  );
}

function RecipeList({ search, tag, onSelect }) {
  const { data, loading, error } = useJson(recipesUrl(search, tag));

  if (loading) return <p className="status">Loading...</p>;
  if (error) return <p className="error">{error}</p>;
  if (data.length === 0) {
    return <p className="empty">No recipes found.</p>;
  }
  return (
    <ul className="recipes">
      {data.map((recipe) => (
        <li key={recipe.id}>
          <button
            className="recipe"
            onClick={() => onSelect(recipe.id)}
          >
            {recipe.name}
          </button>{" "}
          {recipe.minutes} min
        </li>
      ))}
    </ul>
  );
}

function RecipeDetail({ id, onBack }) {
  const { data, loading, error } = useJson(`${API}/recipes/${id}`);

  return (
    <article className="detail">
      <button className="back" onClick={onBack}>← Back</button>
      {loading ? (
        <p className="status">Loading...</p>
      ) : error ? (
        <p className="error">{error}</p>
      ) : (
        <>
          <h2>{data.name}</h2>
          <p className="meta">
            {data.minutes} min · serves {data.servings}
          </p>
          <h3>Ingredients</h3>
          <ul className="ingredients">
            {data.ingredients.map((item) => (
              <li key={item}>{item}</li>
            ))}
          </ul>
          <h3>Steps</h3>
          <ol className="steps">
            {data.steps.map((step) => <li key={step}>{step}</li>)}
          </ol>
        </>
      )}
    </article>
  );
}

function App() {
  const [search, setSearch] = useState("");
  const [tag, setTag] = useState("all");
  const [selectedId, setSelectedId] = useState(null);

  return (
    <main>
      <h1>🐼 Recipe browser</h1>
      {selectedId ? (
        <RecipeDetail
          id={selectedId}
          onBack={() => setSelectedId(null)}
        />
      ) : (
        <>
          <SearchBar value={search} onChange={setSearch} />
          <TagFilter active={tag} onSelect={setTag} />
          <RecipeList
            search={search}
            tag={tag}
            onSelect={setSelectedId}
          />
        </>
      )}
    </main>
  );
}

createRoot(document.getElementById("root")).render(<App />);
```

## Starting a real project

Here, the lesson page compiles your JSX for you. On your own computer, the standard way to start a React app is **Vite**, a fast build tool and development server:

```bash
npm create vite@latest recipe-browser -- --template react
cd recipe-browser
npm install
npm run dev
```

`npm run dev` prints a local address (usually `http://localhost:5173`). Open it, edit a file, save, and the page updates instantly. Split the app into files the way the plan suggests:

```text
recipe-browser/
├── index.html              <div id="root"></div>
├── package.json
└── src/
    ├── main.jsx            createRoot(...).render(<App />)
    ├── App.jsx
    ├── api.js              API and recipesUrl
    ├── hooks/
    │   └── useJson.js
    └── components/
        ├── SearchBar.jsx
        ├── TagFilter.jsx
        ├── RecipeList.jsx
        └── RecipeDetail.jsx
```

`main.jsx` is the entry point. Vite's template wraps the app in `<StrictMode>`, so in development you'll see each effect run twice: `useJson` is ready for that, because its cleanup aborts the first request.

```jsx title="src/main.jsx"
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

The practice API only exists inside PandaDev, so for a real app point `API` at a real one, and keep the address in a Vite **environment variable** instead of the code. Variables starting with `VITE_` in a `.env` file are available as `import.meta.env`:

```bash title=".env"
VITE_API_URL=https://api.example.com
```

```js title="src/api.js"
export const API = import.meta.env.VITE_API_URL;
```

Free public APIs such as TheMealDB have recipe data to practise with; their JSON looks different, so you'd adapt `recipesUrl` and the components to it. When you're happy, `npm run build` creates an optimised `dist/` folder you can deploy to any static host.

<Callout type="note" title="Never put secrets in front-end code">

Everything in a React app, including `import.meta.env` values, ends up in JavaScript that **anyone** can read in their browser. Public addresses are fine; secret API keys are not. Real apps keep secret keys on a **server** that calls the API for them, which is exactly what the Node.js & Express module is about.

</Callout>

## Recap

- Plan first: sketch the **component tree**, then decide **where each piece of state lives** (the closest common parent of everything that needs it).
- Keep plain logic, like building a URL with `URLSearchParams`, in normal functions outside components.
- A **custom hook** (`useJson`) is a `use...` function that calls other hooks, so several components can share logic while each keeps its own state.
- A detail view can be plain **conditional rendering** on a `selectedId` state; routers give each view its own URL.
- Design all four states of a list: **loading, error, empty and data**.
- Start real projects with `npm create vite@latest`, split components into files, and keep configuration in `VITE_` environment variables, never secrets.
