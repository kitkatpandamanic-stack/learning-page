In the Level 1 [to-do app](/learn/javascript/state-and-rendering) you used the **render pattern**: keep all the data in one place, and rebuild the page from it with a `render()` function whenever something changes. It works, but you wrote every `createElement`, every `innerHTML = ""` and every event listener by hand. **React** is a library that does that part for you, and it's the most popular way to build user interfaces on the web today. ⚛️

## Why React?

The big idea behind React fits in one line:

```text
UI = f(state)
```

The page is the **result of a function** of your data. You describe what the screen should look like for the current data, and React works out which DOM changes are needed to get there. You already know the idea from plain JavaScript:

<CodeExample output={`<p>No recipes yet</p>
<p>2 recipes: Pancakes, Soup</p>`}>

```js
function recipeSummary(recipes) {
  if (recipes.length === 0) return "<p>No recipes yet</p>";
  const names = recipes.join(", ");
  return `<p>${recipes.length} recipes: ${names}</p>`;
}

console.log(recipeSummary([]));
console.log(recipeSummary(["Pancakes", "Soup"]));
```

</CodeExample>

Same data in, same page out. What React adds:

- **Components**: you split the page into small, reusable functions (`RecipeCard`, `SearchBar`, `App`) instead of one giant `render()`.
- **Efficient updates**: React compares the new result with the old one and only touches the parts of the DOM that really changed, so your input boxes keep their focus and text.
- **State and events built in**: change the data, and React re-renders for you (that's the next lesson).

This style is called **declarative**: you say *what* the page should show, not *how* to change it step by step.

## Your first component

A **component** is a JavaScript function whose name starts with a **capital letter** and that returns some markup. Press **Run**:

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function Greeting() {
  return <h1>Hello from React! 🐼</h1>;
}

const root = createRoot(document.getElementById("root"));
root.render(<Greeting />);`}
/>

Three things are happening:

1. `import { createRoot } from "react-dom/client"` loads React's tools for the browser (you met `import` in the [modules lesson](/learn/javascript/modules)).
2. `createRoot(...)` hands an empty element on the page, `<div id="root">`, over to React. Everything inside it is React's job from now on.
3. `root.render(<Greeting />)` draws the `Greeting` component there. You use a component like an HTML tag.

Every React app starts like this, usually with one top-level component called `App`.

## JSX: HTML-like syntax in JavaScript

That `<h1>` inside a JavaScript function is **JSX**. It isn't HTML and it isn't a string: a build tool turns it into plain function calls before the browser runs it.

```jsx
// What you write:
const title = <h1 className="big">Hi!</h1>;

// Roughly what it becomes:
const title = React.createElement("h1", { className: "big" }, "Hi!");
```

Because JSX is really JavaScript, you can put any JavaScript **expression** inside curly braces `{}`: variables, maths, function calls, ternaries.

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function RecipeOfTheDay() {
  const recipe = { name: "Pancakes", minutes: 25, servings: 4 };
  const perPerson = recipe.minutes / recipe.servings;

  return (
    <section className="card">
      <h2>{recipe.name.toUpperCase()}</h2>
      <p>Ready in {recipe.minutes} minutes.</p>
      <p>That's {perPerson} minutes of cooking per person!</p>
      <hr />
    </section>
  );
}

createRoot(document.getElementById("root")).render(
  <RecipeOfTheDay />
);`}
/>

JSX has a few rules that trip up everyone at first:

- **Return one root element.** Two siblings side by side need a parent. If you don't want an extra `<div>`, use a **fragment**: `<>...</>`.
- **Close every tag**, including ones HTML lets you leave open: `<img />`, `<input />`, `<br />`.
- **Attributes are camelCase**, and a few are renamed because they clash with JavaScript words: `class` becomes **`className`**, `for` becomes **`htmlFor`**, `onclick` becomes **`onClick`**.
- **Curly braces take expressions, not statements.** `{if (x) ...}` or `{for ...}` won't work; use a ternary, `&&` or `map` instead (more on those below).
- Wrap multi-line JSX in **round brackets** after `return`, or JavaScript returns `undefined` from the empty line.

```jsx
// ❌ Two roots, "class" and an unclosed tag
return (
  <h1 class="title">Recipes</h1>
  <input>
);

// ✅ A fragment, className and a closed tag
return (
  <>
    <h1 className="title">Recipes</h1>
    <input />
  </>
);
```

## Props: passing data to components

A component that always shows the same thing isn't very useful. **Props** (short for properties) let a parent pass data into a component, just like arguments to a function. You write them like HTML attributes, and the component receives them as **one object**, which we usually destructure straight away:

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function RecipeCard({ name, minutes, servings = 2 }) {
  return (
    <article>
      <h3>{name}</h3>
      <p>{minutes} min · serves {servings}</p>
    </article>
  );
}

function App() {
  return (
    <main>
      <h1>Panda's cookbook</h1>
      <RecipeCard name="Pancakes" minutes={25} servings={4} />
      <RecipeCard name="Guacamole" minutes={10} />
      <RecipeCard name="Tomato Soup" minutes={35} servings={4} />
    </main>
  );
}

createRoot(document.getElementById("root")).render(<App />);`}
/>

Some details worth noticing:

- Strings can be passed in quotes (`name="Pancakes"`); anything else goes in curly braces (`minutes={25}`, `tags={["vegan"]}`, `onPick={handlePick}`).
- Default values work just like default parameters: Guacamole gets `servings = 2`.
- One component, three different cards. That's the whole point: write it once, reuse it everywhere.

<Callout type="warning" title="Props are read-only">

A component must never change its own props (`props.minutes = 5` or pushing into a prop array). Think of them as the arguments of a **pure function**: same props in, same JSX out. When data needs to change over time, that's **state**, which you'll meet in the next lesson.

</Callout>

## Children: components that wrap content

Anything you put **between** a component's opening and closing tags arrives in a special prop called **`children`**. It's perfect for "wrapper" components like cards, panels and layouts:

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function Panel({ title, children }) {
  return (
    <section
      style={{ border: "1px solid #7c3aed", borderRadius: 12,
               padding: "4px 16px", marginBottom: 12 }}
    >
      <h3>{title}</h3>
      {children}
    </section>
  );
}

function App() {
  return (
    <>
      <Panel title="Tip of the day">
        <p>Rest pancake batter for 10 minutes.</p>
      </Panel>
      <Panel title="Shopping list">
        <ul>
          <li>Flour</li>
          <li>Eggs</li>
        </ul>
      </Panel>
    </>
  );
}

createRoot(document.getElementById("root")).render(<App />);`}
/>

`Panel` doesn't care what's inside it: a paragraph, a list, even other components. Notice the **double braces** in `style={{ ... }}`: the outer pair means "a JavaScript expression", the inner pair is the object of CSS properties (camelCase, like `borderRadius`).

## Rendering lists with keys

To show a list, turn an **array of data** into an **array of JSX** with `map`. React renders arrays of elements one after another:

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

const recipes = [
  { id: 1, name: "Bamboo Shoot Stir-fry", minutes: 20 },
  { id: 2, name: "Pancakes", minutes: 25 },
  { id: 5, name: "Guacamole", minutes: 10 },
];

function RecipeList() {
  return (
    <ul>
      {recipes.map((recipe) => (
        <li key={recipe.id}>
          {recipe.name} ({recipe.minutes} min)
        </li>
      ))}
    </ul>
  );
}

createRoot(document.getElementById("root")).render(<RecipeList />);`}
/>

Each item needs a **`key`**: a value that is **unique among its siblings** and **stays the same** for that item. When the list changes, React uses keys to work out which item is which, so it can move, add or remove just the right elements. Delete `key={recipe.id}` and press **Run**: React complains in the output.

```text
Each child in a list should have a unique "key" prop.

Check the render method of `RecipeList`. See https://react.dev/link/warning-keys for more information.
```

<Callout type="tip" title="Use ids, not indexes">

The best key is an **id from your data** (`recipe.id`). The array index (`map((r, i) => <li key={i}>`) silences the warning, but if items are added, removed or sorted, index 0 suddenly belongs to a different item, and React can mix up their state (for example, which input box holds which text). Use the index only for lists that never change.

</Callout>

## Conditional rendering

Since JSX is JavaScript, you show things conditionally with JavaScript you already know:

- **An early `return`**, when a whole component should show something different.
- **A ternary** `cond ? a : b` inside JSX, to choose between two things.
- **`cond && <Thing />`**, to show something or nothing.

<TryIt
  language="react"
  code={`import { createRoot } from "react-dom/client";

function RecipeCard({ name, minutes, tags }) {
  return (
    <li>
      <strong>{name}</strong>{" "}
      {minutes <= 15 && <span>⚡ Quick</span>}
      <br />
      {tags.length > 0 ? tags.join(", ") : "No tags"}
    </li>
  );
}

function RecipeList({ recipes }) {
  if (recipes.length === 0) {
    return <p>No recipes found.</p>;
  }
  return (
    <ul>
      {recipes.map((r) => (
        <RecipeCard key={r.id} {...r} />
      ))}
    </ul>
  );
}

const recipes = [
  { id: 5, name: "Guacamole", minutes: 10, tags: ["vegan"] },
  { id: 3, name: "Tomato Soup", minutes: 35, tags: ["soup"] },
  { id: 9, name: "Toast", minutes: 3, tags: [] },
];

createRoot(document.getElementById("root")).render(
  <>
    <RecipeList recipes={recipes} />
    <RecipeList recipes={[]} />
  </>
);`}
/>

Two new tricks hide in there: `{" "}` adds a space between two elements on separate lines, and `{...r}` **spreads** all the recipe's properties in as props (the same as writing `name={r.name} minutes={r.minutes} tags={r.tags}`). The `key` goes on the component inside `map`, not on the `<li>` inside it.

One classic mistake with `&&`: React renders the number `0`. So `{recipes.length && <List />}` shows a lonely **0** on an empty list. Make the condition a real boolean: `{recipes.length > 0 && <List />}`.

## In real projects

In a real app each component usually lives in its own file and is exported, and the build tool (like Vite, which you'll set up at the end of this module) handles JSX for you:

```jsx title="src/RecipeCard.jsx"
export default function RecipeCard({ name, minutes }) {
  return <li>{name} ({minutes} min)</li>;
}
```

```jsx title="src/App.jsx"
import RecipeCard from "./RecipeCard.jsx";

export default function App() {
  return <ul><RecipeCard name="Pancakes" minutes={25} /></ul>;
}
```

Here in the lessons everything sits in one file, so you can see it all at once.

## Recap

- React builds the page from your data: **UI = f(state)**. You describe what to show; React updates the DOM efficiently.
- `createRoot(element).render(<App />)` starts a React app inside an element on the page.
- **JSX** turns into `React.createElement` calls. Rules: one root (or a fragment `<>...</>`), close every tag, camelCase attributes, `className` and `htmlFor`, and `{}` for expressions.
- **Components** are capitalised functions that return JSX. **Props** pass data in, like function arguments, and are read-only. **`children`** is whatever sits between the tags.
- Render lists with `map`, and give each item a stable, unique **`key`** (an id, not the index).
- Show things conditionally with an early `return`, a **ternary** or **`&&`** (with a real boolean, so you never render a stray `0`).
