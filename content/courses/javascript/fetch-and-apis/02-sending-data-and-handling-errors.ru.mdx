Читать данные — это только половина дела. Приложения ещё и **отправляют** данные: новую задачу, изменённый профиль, удалённое фото. А настоящие сети капризны: серверы отказывают, отвечают медленно или на мгновение падают. В этом уроке вы научитесь отправлять данные с помощью `fetch`, а затем напишете небольшого надёжного помощника для запросов — такого, на которые опираются настоящие проекты. 🛠️

## Отправляем данные с POST

`fetch` принимает второй аргумент — **объект настроек** (options). Чтобы что-то создать, нужно задать три настройки:

- `method: "POST"`;
- **заголовок** (header) `Content-Type`, который сообщает серверу, что тело — это JSON;
- само тело `body`, превращённое в JSON-**строку** с помощью `JSON.stringify`.

<CodeExample output={`201 Created
{ id: 4, title: 'Learn fetch options', done: false }`}>

```js
const response = await fetch("https://api.pandadev.test/todos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Learn fetch options" }),
});

console.log(response.status, response.statusText);
const todo = await response.json();
console.log(todo);
```

</CodeExample>

API отвечает **201 Created** и присылает обратно новую задачу вместе с `id`, который ей выдал сервер. Это обычная схема: вы отправляете то, что знаете, сервер дополняет остальное (id, даты, значения по умолчанию) и возвращает объект целиком.

Если серверу не нравится то, что вы отправили, он отвечает **400 Bad Request**, а хорошие API объясняют причину в теле ответа:

<CodeExample output={`400 { error: 'title is required' }
400 { error: 'title is required' }`}>

```js
const API = "https://api.pandadev.test";

// ❌ Забыли JSON.stringify: тело превращается в "[object Object]"
const oops = await fetch(`${API}/todos`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: { title: "Buy bamboo" },
});
console.log(oops.status, await oops.json());

// ❌ Вообще забыли title
const empty = await fetch(`${API}/todos`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ done: true }),
});
console.log(empty.status, await empty.json());
```

</CodeExample>

<Callout type="warning" title="Тело должно быть строкой">

`fetch` не превращает объекты в JSON за вас. Если передать объект в `body`, он будет преобразован через `String(...)`, и получится бесполезный текст `"[object Object]"`. Всегда пишите `body: JSON.stringify(data)` и добавляйте заголовок `Content-Type: application/json`: многие серверы (в том числе Express, как вы увидите позже) без него игнорируют JSON в теле.

</Callout>

## Изменяем и удаляем

`PATCH` меняет только те поля, которые вы отправили; `PUT` заменяет объект целиком. `DELETE` удаляет его и обычно отвечает **204 No Content**, что и означает ровно то, что написано: **тела нет**, поэтому не вызывайте на таком ответе `.json()` (он выбросит `SyntaxError`).

<CodeExample output={`200 { id: 2, title: 'Build the movie app', done: true }
204 No Content
[ 'Learn fetch', 'Build the movie app' ]`}>

```js
const API = "https://api.pandadev.test";
const json = { "Content-Type": "application/json" };

// PATCH: меняем только отправленные поля
const patched = await fetch(`${API}/todos/2`, {
  method: "PATCH",
  headers: json,
  body: JSON.stringify({ done: true }),
});
console.log(patched.status, await patched.json());

// DELETE: 204 No Content, читать нечего
const deleted = await fetch(`${API}/todos/3`, { method: "DELETE" });
console.log(deleted.status, deleted.statusText);

const list = await fetch(`${API}/todos`).then((r) => r.json());
console.log(list.map((todo) => todo.title));
```

</CodeExample>

Этот набор операций (создать, прочитать, обновить, удалить) называется **CRUD**, а API, который сопоставляет их с HTTP-методами и адресами вроде `/todos` и `/todos/2`, называется **REST API**:

| Запрос | Что делает | При успехе |
| --- | --- | --- |
| `GET /todos` | список всех задач | 200 + список |
| `POST /todos` | создаёт задачу | 201 + новая задача |
| `GET /todos/2` | читает одну задачу | 200 + задача |
| `PATCH /todos/2` | меняет часть полей | 200 + обновлённая задача |
| `DELETE /todos/2` | удаляет задачу | 204, без тела |

## Надёжный помощник для запросов

Посмотрите, сколько кода понадобилось для каждого запроса: настройки, заголовки, `JSON.stringify`, проверка `ok`, чтение сообщения об ошибке. Повторите это по всему приложению — и появятся баги. Поэтому в настоящих проектах пишут **одного** помощника, который делает всё это сам и при проблеме выбрасывает нормальную ошибку с сообщением от самого API:

<CodeExample output={`{ id: 4, title: 'Write a request helper', done: false }
null
ApiError 404: Todo not found
ApiError 400: city is required
ApiError 418: I'm a teapot`}>

```js
const API = "https://api.pandadev.test";

class ApiError extends Error {
  constructor(status, message) {
    super(message);
    this.name = "ApiError";
    this.status = status;
  }
}

async function request(path, { method = "GET", body } = {}) {
  const options = { method, headers: {} };
  if (body !== undefined) {
    options.headers["Content-Type"] = "application/json";
    options.body = JSON.stringify(body);
  }

  const response = await fetch(API + path, options);
  // 204 или тело не в формате JSON: вместо падения берём null
  const data = await response.json().catch(() => null);

  if (!response.ok) {
    const message = data?.error ?? `HTTP ${response.status}`;
    throw new ApiError(response.status, message);
  }
  return data;
}

const todo = await request("/todos", {
  method: "POST",
  body: { title: "Write a request helper" },
});
console.log(todo);
console.log(await request(`/todos/${todo.id}`, { method: "DELETE" }));

for (const path of ["/todos/99", "/weather", "/status/418"]) {
  try {
    await request(path);
  } catch (error) {
    console.log(`${error.name} ${error.status}: ${error.message}`);
  }
}
```

</CodeExample>

Надёжным этого помощника делают несколько деталей:

- **Деструктуризация со значениями по умолчанию** (`{ method = "GET", body } = {}`) позволяет вызывать `request("/todos")` вообще без настроек.
- **`response.json().catch(() => null)`** справляется и с 204 (тела нет), и с серверами, которые вместо JSON присылают HTML-страницу с ошибкой.
- **`ApiError` хранит код ответа**, поэтому вызывающий код может реагировать по-разному: при 404 показать «не найдено», при 401 попросить войти, при 503 предложить попробовать позже.
- **`data?.error ?? ...`** берёт сообщение API, если оно есть, а иначе подставляет код ответа. Каждый API называет это поле по-своему (`error`, `message`, `detail`…), так что именно эту строку вы будете подстраивать.

<Callout type="tip" title="В настоящих проектах">

Команды часто берут для этого небольшую библиотеку, например `ky` или `axios`: в них уже есть работа с JSON, ошибки при плохих кодах ответа, тайм-ауты и повторы. Они построены ровно на идеях из этого урока, так что после собственного помощника в них не останется ничего загадочного:

```js
import ky from "ky";

const todo = await ky
  .post("https://api.example.com/todos", { json: { title: "Hi" } })
  .json();
```

</Callout>

## Тайм-ауты с AbortSignal

А если сервер так и не ответит? По умолчанию `fetch` ждёт очень долго, а пользователь смотрит на крутящийся индикатор загрузки. Сдавайтесь после разумного срока с помощью **`AbortSignal.timeout(ms)`**, переданного в настройку `signal`. Когда время выходит, `fetch` отклоняет промис с ошибкой по имени `TimeoutError` — это **тайм-аут** (timeout):

<CodeExample output={`Сдались через 500 мс
Быстрый запрос: { waited: 200 }`}>

```js
const API = "https://api.pandadev.test";

// /delay/1500 отвечает через 1,5 секунды: для нас слишком долго
try {
  const response = await fetch(`${API}/delay/1500`, {
    signal: AbortSignal.timeout(500),
  });
  console.log("Ответ:", response.status);
} catch (error) {
  if (error.name === "TimeoutError") {
    console.log("Сдались через 500 мс");
  } else {
    throw error;
  }
}

const fast = await fetch(`${API}/delay/200`, {
  signal: AbortSignal.timeout(500),
});
console.log("Быстрый запрос:", await fast.json());
```

</CodeExample>

Иногда запрос нужно отменить самому — например, когда пользователь начал новый поиск, а старый ещё не ответил. **`AbortController`** даёт вам сигнал и «кнопку» `abort()`. После отмены `fetch` отклоняет промис с ошибкой `AbortError`:

<CodeExample output={`Запрос отправлен...
AbortError
Отменён? true`}>

```js
const API = "https://api.pandadev.test";
const controller = new AbortController();

const search = fetch(`${API}/movies?search=panda`, {
  signal: controller.signal,
});
console.log("Запрос отправлен...");

// Пользователь ввёл что-то новое, и этот ответ уже не нужен
controller.abort();

try {
  await search;
} catch (error) {
  console.log(error.name);
}
console.log("Отменён?", controller.signal.aborted);
```

</CodeExample>

Проверяйте `error.name` (`"TimeoutError"`, `"AbortError"`), а не сообщение: сообщения в разных браузерах разные.

## Повторы с нарастающей задержкой

Некоторые сбои **временные**: сервер перезапускается или перегружен и отвечает **503 Service Unavailable**. Если попробовать снова чуть позже, часто всё получается. Эндпоинт `/flaky` учебного API дважды отвечает ошибкой, а потом успехом, так что можно потренироваться:

<CodeExample output={`Получили 503, повтор через 100 мс
Получили 503, повтор через 200 мс
{ ok: true, attempt: 3 }
Без повтора для HTTP 404`}>

```js
const API = "https://api.pandadev.test";
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function getWithRetry(path, retries = 3) {
  for (let attempt = 0; ; attempt++) {
    const response = await fetch(API + path);
    const data = await response.json();
    if (response.ok) return data;

    const canRetry = response.status >= 500 && attempt < retries;
    if (!canRetry) throw new Error(`HTTP ${response.status}`);

    const delay = 100 * 2 ** attempt; // 100, 200, 400...
    console.log(`Получили ${response.status}, повтор через ${delay} мс`);
    await wait(delay);
  }
}

console.log(await getWithRetry("/flaky"));

try {
  await getWithRetry("/status/404");
} catch (error) {
  console.log("Без повтора для", error.message);
}
```

</CodeExample>

Удвоение паузы с каждой попыткой называется **экспоненциальной задержкой** (exponential backoff). Если сервер и так еле справляется, тысяча приложений, долбящих его каждые 10 мс, сделают только хуже; нарастающая пауза даёт ему время прийти в себя. Настоящие приложения ещё добавляют немного случайности («джиттер», jitter), чтобы все эти приложения не повторяли запрос в один и тот же момент, и повторяют также сетевые ошибки (тот самый `TypeError` из прошлого урока).

<Callout type="danger" title="Повторяйте только то, что безопасно повторить">

Повторяйте ошибки **5xx**, тайм-ауты и сетевые сбои, но никогда — **4xx**: 404 или 400 в следующий раз завершатся точно так же. И осторожнее с `POST`: если первый запрос *дошёл* до сервера, а потерялся только ответ, повтор создаст **дубликат** заказа или платежа. `GET`, `PUT` и `DELETE` можно безопасно повторять; `POST` требует особой осторожности (API вроде Stripe принимают для этого «ключ идемпотентности», idempotency key).

</Callout>

Допишите небольшой клиент для списка дел из учебного API.

1. `request(path, { method, body, timeout })`:
   - если есть `body`, отправьте его как JSON (заголовок `Content-Type` плюс `JSON.stringify`);
   - сдавайтесь через `timeout` миллисекунд с помощью `AbortSignal.timeout`;
   - прочитайте JSON из ответа, а если его нет (как у 204), используйте `null`;
   - если ответ не ok, выбросьте `new ApiError(status, message)`, взяв в качестве сообщения поле `error` из ответа API;
   - иначе верните данные.
2. `getWithRetry(path, retries = 2)` вызывает `request(path)`. Если он падает с **ошибкой сервера** (`status` 500 или больше), функция ждёт `100 * 2 ** attempt` мс и пробует снова, но не больше `retries` раз. Любая другая ошибка сразу выбрасывается дальше — как и последняя ошибка, когда повторы закончились.

Сначала запустите код: часть «Попробуйте» внизу должна вывести новую задачу, `null`, а затем `ApiError 400: title is required`.

<Hint>

Соберите настройки так же, как в помощнике `request` из урока, и добавьте `signal: AbortSignal.timeout(timeout)`. Тело прочитайте так: `const data = await response.json().catch(() => null);`, а ошибку выбросьте так: `` throw new ApiError(response.status, data?.error ?? `HTTP ${response.status}`) ``. В `getWithRetry` используйте `for (let attempt = 0; ; attempt++)` с `try { return await request(path); } catch (error) { ... }`; внутри `catch` выбрасывайте ошибку дальше, если `error.status < 500` или `attempt >= retries`, а иначе вызывайте `await wait(100 * 2 ** attempt)`. Не забудьте `await` в `return await request(path)`, иначе `catch` не увидит ошибку!

</Hint>

<Solution>

```js
const API = "https://api.pandadev.test";
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

class ApiError extends Error {
  constructor(status, message) {
    super(message);
    this.name = "ApiError";
    this.status = status;
  }
}

async function request(
  path,
  { method = "GET", body, timeout = 1000 } = {},
) {
  const options = {
    method,
    headers: {},
    signal: AbortSignal.timeout(timeout),
  };
  if (body !== undefined) {
    options.headers["Content-Type"] = "application/json";
    options.body = JSON.stringify(body);
  }

  const response = await fetch(API + path, options);
  const data = await response.json().catch(() => null);
  if (!response.ok) {
    throw new ApiError(
      response.status,
      data?.error ?? `HTTP ${response.status}`,
    );
  }
  return data;
}

async function getWithRetry(path, retries = 2) {
  for (let attempt = 0; ; attempt++) {
    try {
      return await request(path);
    } catch (error) {
      const serverError = error.status >= 500;
      if (!serverError || attempt >= retries) throw error;
      await wait(100 * 2 ** attempt);
    }
  }
}

// Попробуйте
const todo = await request("/todos", {
  method: "POST",
  body: { title: "Feed the pandas" },
});
console.log(todo);
console.log(await request(`/todos/${todo.id}`, { method: "DELETE" }));

try {
  await request("/todos", { method: "POST", body: { title: "" } });
} catch (error) {
  console.log(`${error.name} ${error.status}: ${error.message}`);
}
```

</Solution>

## Итоги

- Данные отправляют так: `fetch(url, { method, headers, body })`, где `body: JSON.stringify(data)`, плюс заголовок `Content-Type: application/json`.
- `POST` создаёт (201 Created), `PATCH` меняет часть полей, `PUT` заменяет целиком, `DELETE` удаляет (часто 204 No Content — тела, которое можно прочитать, нет). Вместе они образуют **REST** API для **CRUD**.
- Один помощник `request` отправляет JSON, безопасно читает ответ и выбрасывает `ApiError` с кодом ответа и сообщением самого API.
- `signal: AbortSignal.timeout(ms)` прекращает ждать медленный запрос (`TimeoutError`); `AbortController` позволяет отменить запрос самому (`AbortError`).
- Временные сбои (5xx, тайм-ауты, сетевые ошибки) повторяйте с **экспоненциальной задержкой**, 4xx — никогда, а с повтором `POST` будьте осторожны.
