Почти любое настоящее приложение общается с сервером. Приложение погоды запрашивает прогноз на сегодня, магазин — список товаров, чат — новые сообщения. И все они делают это одинаково: отправляют **HTTP-запрос** (HTTP request) к **API** (адресу, который сделан для программ, а не для людей) и получают в ответ **JSON**. В JavaScript для этого есть инструмент **`fetch`**. 🌐

## HTTP за две минуты

Любой разговор с сервером — это **запрос** (request), за которым следует **ответ** (response). У запроса есть:

- **метод** (method): что вы хотите сделать;
- **URL**: с чем вы хотите это сделать;
- необязательные **заголовки** (headers) — дополнительная информация, например «я отправляю JSON», — и **тело** (body), то есть данные, которые вы отправляете.

Ответ возвращается с **кодом ответа** (status code), заголовками и телом. Вот как запрос и ответ на самом деле выглядят в виде текста:

```text
GET /movies/3 HTTP/1.1
Host: api.pandadev.test
Accept: application/json

HTTP/1.1 200 OK
Content-Type: application/json

{"id":3,"title":"Midnight in the Forest","year":2015,...}
```

Методы, которые вы будете использовать чаще всего, и коды ответа, которые стоит знать наизусть:

| Метод | Значит |
| --- | --- |
| `GET` | прочитать что-то |
| `POST` | создать что-то |
| `PUT` / `PATCH` | заменить / изменить что-то |
| `DELETE` | удалить что-то |

| Код | Значит |
| --- | --- |
| `200` OK | всё получилось |
| `201` Created | создано что-то новое |
| `204` No Content | всё получилось, но тела нет |
| `400` Bad Request / `404` Not Found | ошибка на вашей стороне: неверные данные / такого нет |
| `500` Internal Server Error / `503` Service Unavailable | проблема на стороне сервера |

Простое правило: **2xx** — успех, **4xx** — клиент (то есть вы) сделал что-то не так, **5xx** — сломался сервер.

<Callout type="note" title="Учебный API PandaDev">

В PandaDev встроен учебный API по адресу `https://api.pandadev.test`, поэтому эти уроки работают без интернета и всегда дают одинаковые ответы. В нём есть фильмы, погода, рецепты, пользователи, посты и список дел, который можно менять. Настоящие API работают точно так же — меняется только URL.

</Callout>

## Ваш первый fetch

`fetch(url)` отправляет `GET`-запрос и возвращает **промис** (promise) объекта `Response`. Прочитать тело как JSON — это второй шаг со своим промисом:

<CodeExample output={`200 true
Midnight in the Forest
2015, режиссёр — Ada Brooks
[ 'drama', 'mystery' ]`}>

```js
const response = await fetch("https://api.pandadev.test/movies/3");
console.log(response.status, response.ok);

const movie = await response.json();
console.log(movie.title);
console.log(`${movie.year}, режиссёр — ${movie.director}`);
console.log(movie.genres);
```

</CodeExample>

Зачем два `await`? Сервер сначала присылает **код ответа и заголовки**, а тело может прийти позже (в нём могут быть мегабайты). Первый `await` ждёт начала ответа, так что код ответа можно проверить сразу; затем `response.json()` ждёт всё тело целиком и превращает текст JSON в объект JavaScript.

## Читаем ответ

Объект `Response` рассказывает об ответе всё:

<CodeExample output={`200
OK
true
application/json; charset=utf-8
string 123
The Bamboo Heist`}>

```js
const response = await fetch("https://api.pandadev.test/movies/1");

console.log(response.status);        // 200
console.log(response.statusText);    // "OK"
console.log(response.ok);            // true для 200–299
console.log(response.headers.get("content-type"));

const text = await response.text();  // тело как есть
console.log(typeof text, text.length);
const movie = JSON.parse(text);      // то же, что делает .json()
console.log(movie.title);
```

</CodeExample>

На самом деле `response.json()` — это просто `response.text()`, а затем `JSON.parse`. Используйте `.text()`, когда API присылает обычный текст или HTML.

<Callout type="warning" title="Тело можно прочитать только один раз">

Тело — это **поток** (stream): как только `.json()` или `.text()` его прочитали, его больше нет. Повторный вызов `.json()` на том же ответе выбросит `TypeError`. Прочитайте тело один раз, сохраните результат в переменную и работайте с ней.

</Callout>

## Строка запроса: URL и URLSearchParams

Многие эндпоинты (endpoint) принимают параметры в **строке запроса** (query string) — части URL после `?`: `/movies?search=bamboo&genre=comedy`. Так и хочется склеить её шаблонной строкой, но у некоторых символов в URL особый смысл (`&`, `?`, `#`, `+`, пробелы…), и они всё ломают:

<CodeExample output={`[ [ 'search', 'tea ' ], [ ' cake', '' ] ]
https://api.pandadev.test/movies?search=tea+%26+cake&limit=3
[ [ 'search', 'tea & cake' ], [ 'limit', '3' ] ]`}>

```js
const search = "tea & cake";

// ❌ Склеиваем строки: & разрезает значение надвое
const bad = new URL(
  `https://api.pandadev.test/movies?search=${search}`,
);
console.log([...bad.searchParams]);

// ✅ URLSearchParams сам всё закодирует
const url = new URL("https://api.pandadev.test/movies");
url.searchParams.set("search", search);
url.searchParams.set("limit", 3);
console.log(url.href);
console.log([...url.searchParams]);
```

</CodeExample>

Со склеенной строкой сервер искал бы `"tea "` и получил бы загадочный лишний параметр `" cake"`. Свойство **`searchParams`** объекта `URL` безопасно кодирует каждое значение (`&` превращается в `%26`, пробелы — в `+`). Числа тоже подходят: они превращаются в текст.

Объект `URL` можно передать прямо в `fetch`. Список фильмов разбит на **страницы** (pagination): API отвечает одной страницей результатов и сведениями, которых хватит, чтобы запросить следующую:

<CodeExample output={`Страница 2 из 2
Всего комедий: 4
- Ninja Pandas II (5.9)
- Tea for Two Thousand (6.7)`}>

```js
const url = new URL("https://api.pandadev.test/movies");
url.searchParams.set("genre", "comedy");
url.searchParams.set("limit", 2);
url.searchParams.set("page", 2);

const response = await fetch(url);
const data = await response.json();

console.log(`Страница ${data.page} из ${data.totalPages}`);
console.log(`Всего комедий: ${data.total}`);
for (const movie of data.results) {
  console.log(`- ${movie.title} (${movie.rating})`);
}
```

</CodeExample>

<Callout type="tip" title="new URL(path, base)">

`new URL("/movies", "https://api.pandadev.test")` присоединяет путь к базовому URL. В настоящих проектах базовый адрес хранят в одной константе (`const API = "https://..."`), и переход с тестового сервера на настоящий — это изменение одной строки.

</Callout>

## Когда что-то пошло не так: 404 и сетевые ошибки

А вот сюрприз, на котором попадаются все: **`fetch` не выбрасывает ошибку при 404 или 500**. С точки зрения `fetch` сервер *ответил*, значит, запрос удался. Вы получаете обычный `Response`, у которого `ok` равно `false`:

<CodeExample output={`/movies/2 → 200 true
/movies/99 → 404 false
/status/500 → 500 false`}>

```js
const API = "https://api.pandadev.test";

for (const path of ["/movies/2", "/movies/99", "/status/500"]) {
  try {
    const response = await fetch(API + path);
    console.log(path, "→", response.status, response.ok);
  } catch (error) {
    console.log(path, "→ ответа нет:", error.name);
  }
}
```

</CodeExample>

(`/status/500` — учебный эндпоинт, который отвечает тем кодом, который вы укажете в URL.) Блок `catch` ни разу не выполнился. `fetch` **отклоняет** промис (rejects) только тогда, когда ответа нет вообще: пользователь без интернета, домена не существует или браузер заблокировал запрос. Тогда вы получите `TypeError`:

```text
TypeError: Failed to fetch
```

Значит, обрабатывать нужно два разных вида сбоев:

| Что случилось | Что делает `fetch` | Как это заметить |
| --- | --- | --- |
| Сервер отказал (404, 500…) | выполняет промис | `response.ok === false` |
| Ответа нет совсем (нет сети…) | отклоняет промис | `try/catch` вокруг `await fetch(...)` |

<Callout type="danger" title="Всегда проверяйте response.ok">

Код вроде `const movie = await (await fetch(url)).json();` преспокойно «работает» и на 404: `movie` становится `{ error: 'Movie not found' }`, а на странице появляется *undefined (undefined)*. Проверяйте `response.ok` (или `response.status`), прежде чем доверять телу ответа.

</Callout>

## Маленький помощник getJSON

Проверять `ok` каждый раз утомительно, поэтому в настоящих проектах `fetch` оборачивают в небольшую функцию-помощник, которая **превращает плохой код ответа в ошибку**. Тогда один `try/catch` справляется с обоими видами сбоев:

<CodeExample output={`[ 'Panda Express to Mars', 'Ninja Pandas II' ]
[ 'mei', 'sam', 'ada' ]
HTTP 404 для /movies/42`}>

```js
const API = "https://api.pandadev.test";

async function getJSON(path, params = {}) {
  const url = new URL(path, API);
  for (const [key, value] of Object.entries(params)) {
    url.searchParams.set(key, value);
  }

  const response = await fetch(url);
  if (!response.ok) {
    throw new Error(`HTTP ${response.status} для ${url.pathname}`);
  }
  return response.json();
}

const page = await getJSON("/movies", { search: "panda" });
console.log(page.results.map((movie) => movie.title));

const users = await getJSON("/users");
console.log(users.map((user) => user.username));

try {
  await getJSON("/movies/42");
} catch (error) {
  console.log(error.message);
}
```

</CodeExample>

Обратите внимание: `return response.json()` написано без `await`. Возвращать промис из `async`-функции можно — `await` в вызывающем коде его дождётся.

Раз `getJSON` возвращает промис, несколько запросов можно выполнить **одновременно** с помощью `Promise.all`, который вы видели в модуле «Асинхронный JavaScript»:

<CodeExample output={`[ 'The Bamboo Heist', 'The Last Dumpling', 'The Great Bamboo Race' ]
параллельно`}>

```js
const API = "https://api.pandadev.test";

async function getJSON(path) {
  const response = await fetch(API + path);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

const start = Date.now();
const movies = await Promise.all(
  [1, 4, 12].map((id) => getJSON(`/movies/${id}`)),
);
const took = Date.now() - start;

console.log(movies.map((movie) => movie.title));
console.log(took < 300 ? "параллельно" : "по очереди");
```

</CodeExample>

Каждый запрос занимает около 100 мс, поэтому три параллельных запроса занимают около 100 мс, а не 300.

## В настоящих проектах: ключи API

Большинство настоящих API хотят знать, кто к ним обращается, поэтому выдают вам **ключ API** (API key). Обычно его отправляют в заголовке:

```js
const url = new URL("https://api.themoviedb.org/3/search/movie");
url.searchParams.set("query", "panda");

const response = await fetch(url, {
  headers: { Authorization: `Bearer ${API_KEY}` },
});
```

Помните о двух вещах. Во-первых, всё, что есть во фронтенд-коде на JavaScript, может прочитать любой посетитель, поэтому **секретным ключам место на вашем сервере**, а не в коде для браузера. Во-вторых, браузер разрешает странице читать ответы с другого домена, только если тот сервер это позволяет (это правило безопасности называется **CORS**); если API этого не позволяет, запрос падает с тем же `TypeError`, что и без интернета. Обе проблемы решаются вызовом таких API со своего сервера — этим вы займётесь в модуле «Node.js и Express».

## Итоги

- У HTTP-запроса есть **метод** (`GET`, `POST`, `PATCH`, `DELETE`…), **URL**, заголовки и, возможно, тело; у ответа — **код ответа**, заголовки и тело. 2xx — успех, 4xx — ошибка клиента, 5xx — проблема сервера.
- `const response = await fetch(url)` даёт код ответа и заголовки; `await response.json()` читает тело (только один раз!).
- Собирайте строку запроса через `new URL(path, base)` и `url.searchParams.set(...)`, а не склеиванием строк.
- `fetch` **не выбрасывает ошибку при 404 или 500**: проверяйте `response.ok`. Промис отклоняется (с `TypeError`) только тогда, когда ответа нет вообще.
- Небольшой помощник `getJSON`, который выбрасывает ошибку при плохом коде ответа, делает остальной код короче, а `Promise.all` выполняет несколько запросов параллельно.
- Секретным ключам API не место в коде для браузера.
