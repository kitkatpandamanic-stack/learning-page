Пора собрать что-то настоящее: **приложение для поиска фильмов**. Вы вводите название, нажимаете «Найти», и страница показывает подходящие фильмы из учебного API. А потом вы сделаете его профессиональным — таким, каким пользователи ожидают видеть настоящие приложения: с сообщением о загрузке, понятными ошибками, сообщением «ничего не найдено» и кнопкой **«Загрузить ещё»** для длинных списков результатов. 🎬

## План

Прежде чем писать код, перечислите, что нужно странице и что может произойти:

```text
<form>  [ поле поиска ] [Найти]           ← submit: новый поиск
<p id="status">  Найдено фильмов: 6       ← загрузка / найдено / пусто / ошибка
<ul id="results">                         ← по одному <li> на фильм
<button id="more">Загрузить ещё</button>  ← следующая страница, скрыта на последней
```

Любой запрос в приложении находится в одном из **четырёх состояний** (state), и хорошая страница что-то показывает для каждого из них:

| Состояние | Что видит пользователь |
| --- | --- |
| загрузка | «Загрузка...», кнопки отключены, чтобы по ним нельзя было кликнуть дважды |
| успех | результаты и их количество |
| пусто | «Ничего не найдено.» вместо пустой страницы |
| ошибка | понятное сообщение вместо зависшей страницы |

Ещё приложению нужно кое-что **помнить**: текущий поисковый запрос и номер страницы. Хватит двух переменных — `query` и `page`.

## Шаг 1: ищем и показываем результаты

Начните со сценария, в котором всё идёт хорошо. Слушайте событие `submit` (тогда сработает и Enter), соберите URL через `searchParams`, выполните запрос и создайте по одному `<li>` на каждый фильм:

<TryIt
  html={`<form id="search">
  <input name="q" value="panda">
  <button>Найти</button>
</form>
<ul id="results"></ul>`}
  code={`const API = "https://api.pandadev.test";
const form = document.querySelector("#search");
const list = document.querySelector("#results");

form.addEventListener("submit", async (event) => {
  event.preventDefault();
  const query = form.elements.q.value.trim();

  const url = new URL("/movies", API);
  url.searchParams.set("search", query);
  const response = await fetch(url);
  const data = await response.json();

  list.replaceChildren(); // убираем старые результаты
  for (const movie of data.results) {
    const item = document.createElement("li");
    item.textContent = \`\${movie.title} (\${movie.year})\`;
    list.append(item);
  }
  console.log(\`Найдено: \${data.total} по запросу "\${query}"\`);
});

form.requestSubmit(); // ищем один раз при открытии страницы`}
/>

Попробуйте `bamboo`, `the` или пустой запрос (ему подходит любой фильм). `form.elements.q` находит поле ввода по его `name`, а `list.replaceChildren()` без аргументов очищает список перед тем, как туда попадут новые результаты.

<Callout type="danger" title="Никогда не вставляйте данные из API в innerHTML">

Так и хочется написать `` list.innerHTML += `<li>${movie.title}</li>` ``. Но данные с сервера (или от других пользователей) могут содержать HTML. «Название» вроде `<img src=x onerror="stealCookies()">` **выполнит код** на вашей странице. Такая атака называется **межсайтовым скриптингом** (cross-site scripting, XSS). Создавайте элементы и задавайте `textContent` — он всегда показывает текст как текст.

</Callout>

## Шаг 2: состояния загрузки, ошибки и пустого результата

Теперь обработайте остальные три состояния. Схема всегда одна и та же:

1. **Перед** запросом: покажите «Загрузка...» и отключите кнопку.
2. В `try`: проверьте `response.ok`, покажите результаты или сообщение о пустом результате.
3. В `catch`: покажите понятное сообщение об ошибке (а подробности для себя выведите через `console.error`).
4. В `finally`: снова включите кнопку, что бы ни случилось.

Поставьте в предпросмотре галочку **«Изобразить ошибку сервера»** и выполните поиск ещё раз, чтобы увидеть состояние ошибки:

<TryIt

  </label>

  event.preventDefault();

  status.textContent = "Загрузка...";       // 1. загрузка

      ? "Ничего не найдено."                // 2. пусто

Заметили проблему? По запросу `the` написано **Найдено фильмов: 6**, а в списке только 5. API отдаёт результаты **страницами** по 5 штук (если не попросить другой `limit`), так что нужен способ получить остальные.

<Callout type="tip" title="Ошибки — для разработчиков, сообщения — для пользователей">

`HTTP 500` или `TypeError: Failed to fetch` большинству пользователей ничего не говорят. Покажите короткое понятное сообщение о том, что можно сделать («Попробуйте ещё раз»), а технические подробности отправьте в консоль — или, в настоящих проектах, в сервис отслеживания ошибок вроде Sentry.

</Callout>

## Шаг 3: «Загрузить ещё»

Для постраничной загрузки (pagination) нужны два изменения:

- Код поиска выносится в функцию **`loadPage()`**, которая запрашивает текущую страницу `page` и **добавляет** её результаты в конец списка.
- **Новый поиск** сбрасывает `page` на 1 и очищает список; кнопка **«Загрузить ещё»** увеличивает `page` на 1 и снова вызывает `loadPage()`, не очищая список.

Когда остановиться, подскажет ответ API: `{ page, totalPages, total, results }`. Скрывайте кнопку на последней странице:

```js
more.hidden = data.page >= data.totalPages;
```

И отключайте её, пока страница загружается. Иначе нетерпеливый двойной клик загрузит одну и ту же страницу дважды, и в списке каждый фильм окажется по два раза.

## В настоящих проектах

На настоящих страницах поиска встречаются ещё две проблемы:

- **Поиск по мере ввода** отправляет запрос на каждое нажатие клавиши. **Debounce** (из урока про замыкания) ждёт, пока пользователь сделает паузу в наборе, скажем, на 300 мс, и только потом ищет.
- **Ответы могут прийти не по порядку.** Пользователь ищет `pan`, а затем сразу `panda`: если первый запрос медленнее, его устаревшие результаты придут *последними* и затрут правильные. Решение — отменять предыдущий запрос через `AbortController` каждый раз, когда начинается новый поиск:

```js
let controller;

async function search(query) {
  controller?.abort(); // отменяем предыдущий поиск, если он был
  controller = new AbortController();
  try {
    const response = await fetch(urlFor(query), {
      signal: controller.signal,
    });
    showResults(await response.json());
  } catch (error) {
    if (error.name === "AbortError") return; // заменён: игнорируем
    showError();
  }
}
```

Настоящие API фильмов, например TMDB или OMDb, работают так же, как учебный, только с одним дополнительным шагом: нужно зарегистрироваться, получить ключ API и отправлять его с каждым запросом.

Допишите приложение для поиска фильмов. Страница, переменные и помощник `showMovies` уже готовы — вам остаётся написать `loadPage()` и два обработчика событий.

1. **Поиск** (событие `submit` формы): не дайте странице перезагрузиться, сохраните текст **без пробелов по краям** (`trim`) в `query`, установите `page` в `1`, очистите `#results`, скройте `#more` и вызовите `loadPage()`.
2. **`loadPage()`**:
   - сначала запишите в `#status` текст `Загрузка...` и **отключите** `#more`;
   - запросите `/movies` с параметрами строки запроса `search` (текст поиска), `page` и `limit=4`;
   - при успехе добавьте фильмы через `showMovies(data.results)`, запишите в `#status` текст `Найдено фильмов: <total>` (например, `Найдено фильмов: 6`) или `Ничего не найдено.`, если фильмов нет, и **скройте** `#more`, когда `data.page >= data.totalPages` (иначе покажите её);
   - если ответ не ok или ответа нет вообще, запишите в `#status` текст `Что-то пошло не так. Попробуйте ещё раз.`;
   - что бы ни случилось, в конце снова включите `#more`.
3. **«Загрузить ещё»** (клик по `#more`): перейдите на следующую страницу и вызовите `loadPage()`, сохранив уже показанные фильмы.

Попробуйте в предпросмотре: найдите `the`, а затем нажмите **«Загрузить ещё»**.

<Hint>

Соберите URL через `new URL("/movies", API)` и три вызова `url.searchParams.set(...)`. Оберните запрос в `try { ... } catch (error) { ... } finally { more.disabled = false; }`, а внутри `try` сами выбросьте ошибку при `!response.ok` — тогда 500 попадёт в тот же `catch`, что и сетевая ошибка. В обработчике `submit` список очищает `list.replaceChildren()`; обработчик клика — это просто `page++; loadPage();`.

<Solution>

```js
const API = "https://api.pandadev.test";
const form = document.querySelector("#search");
const input = document.querySelector("input[name=q]");
const status = document.querySelector("#status");
const list = document.querySelector("#results");
const more = document.querySelector("#more");

let query = "";
let page = 1;

function showMovies(movies) {
  for (const movie of movies) {
    const item = document.createElement("li");
    item.textContent = `${movie.title} (${movie.year})`;
    list.append(item);
  }
}

async function loadPage() {
  status.textContent = "Загрузка...";
  more.disabled = true;

  const url = new URL("/movies", API);
  url.searchParams.set("search", query);
  url.searchParams.set("page", page);
  url.searchParams.set("limit", 4);

  try {
    const response = await fetch(url);
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const data = await response.json();

    showMovies(data.results);
    status.textContent = data.total === 0
      ? "Ничего не найдено."
      : `Найдено фильмов: ${data.total}`;
    more.hidden = data.page >= data.totalPages;
  } catch (error) {
    console.error(error);
    status.textContent = "Что-то пошло не так. Попробуйте ещё раз.";
  } finally {
    more.disabled = false;
  }
}

form.addEventListener("submit", (event) => {
  event.preventDefault();
  query = input.value.trim();
  page = 1;
  list.replaceChildren();
  more.hidden = true;
  loadPage();
});

more.addEventListener("click", () => {
  page++;
  loadPage();
});
```

</Solution>

## Итоги

- Сначала спланируйте страницу и её **четыре состояния**: загрузка, успех, пустой результат и ошибка.
- Слушайте `submit` на форме, собирайте URL через `searchParams`, выполняйте запрос и отрисовывайте каждый результат через `createElement` + `textContent` (никогда не используйте `innerHTML` с данными из API).
- Перед запросом показывайте «Загрузка...» и отключайте кнопки. Используйте `try/catch/finally`, чтобы и плохой код ответа, и сетевая ошибка, и успех оставляли страницу в разумном состоянии.
- Постраничная загрузка: новый поиск сбрасывает `page` и очищает список; «Загрузить ещё» увеличивает `page` и **добавляет** результаты в конец; скрывайте кнопку, когда `page >= totalPages`.
- В настоящих приложениях применяйте debounce к поиску по мере ввода и отменяйте устаревшие запросы через `AbortController`.

Теперь вы умеете получать данные из любого API и отправлять данные обратно. Дальше вы позаботитесь о том, чтобы код продолжал работать по мере роста проекта: будете писать **автоматические тесты** (tests) с Vitest. 🐼
