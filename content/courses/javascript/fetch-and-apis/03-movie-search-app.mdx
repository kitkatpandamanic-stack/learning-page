Time to build something real: a **movie search app**. You type a title, press Search, and the page shows the matching films from the practice API. Then you'll make it feel professional, the way users expect real apps to behave: a loading message, friendly errors, a "nothing found" message, and a **Load more** button for long result lists. 🎬

## The plan

Before writing code, list what the page needs and what can happen:

```text
<form>  [ search box ] [Search]      ← submit: start a new search
<p id="status">  Found 6 movies      ← loading / found / empty / error
<ul id="results">                    ← one <li> per movie
<button id="more">Load more</button> ← next page, hidden on the last one
```

Every request in an app is in one of **four states**, and a good page shows something for each:

| State | What the user sees |
| --- | --- |
| loading | "Loading...", buttons disabled so they can't double-click |
| success | the results, and how many there are |
| empty | "No movies found." instead of a blank page |
| error | a friendly message instead of a frozen page |

The app also has to **remember** a little: the current search text and which page it's on. Two variables, `query` and `page`, are enough.

## Step 1: search and show the results

Start with the happy path. Listen for `submit` (so Enter works too), build the URL with `searchParams`, fetch, and create one `<li>` per movie:

<TryIt
  html={`<form id="search">
  <input name="q" value="panda">
  <button>Search</button>
</form>
<ul id="results"></ul>`}
  code={`const API = "https://api.pandadev.test";
const form = document.querySelector("#search");
const list = document.querySelector("#results");

form.addEventListener("submit", async (event) => {
  event.preventDefault();
  const query = form.elements.q.value.trim();

  const url = new URL("/movies", API);
  url.searchParams.set("search", query);
  const response = await fetch(url);
  const data = await response.json();

  list.replaceChildren(); // remove the old results
  for (const movie of data.results) {
    const item = document.createElement("li");
    item.textContent = \`\${movie.title} (\${movie.year})\`;
    list.append(item);
  }
  console.log(\`\${data.total} found for "\${query}"\`);
});

form.requestSubmit(); // search once when the page opens`}
/>

Try `bamboo`, `the` or an empty search (which matches every movie). `form.elements.q` finds the input by its `name`, and `list.replaceChildren()` with no arguments empties the list before the new results go in.

<Callout type="danger" title="Never put API data into innerHTML">

It's tempting to write `` list.innerHTML += `<li>${movie.title}</li>` ``. But data from a server (or from other users) can contain HTML. A "title" like `<img src=x onerror="stealCookies()">` would **run code** on your page. This attack is called **cross-site scripting (XSS)**. Create elements and set `textContent`, which always shows text as text.

</Callout>

## Step 2: loading, error and empty states

Now handle the other three states. The pattern is always the same:

1. **Before** the request: show "Loading..." and disable the button.
2. In `try`: check `response.ok`, show the results, or the empty message.
3. In `catch`: show a friendly error (and log the details for yourself with `console.error`).
4. In `finally`: enable the button again, whatever happened.

Tick **Simulate a server error** in the preview and search again to see the error state:

<TryIt
  html={`<form id="search">
  <input name="q" value="the">
  <button>Search</button>
  <label>
    <input type="checkbox" id="broken"> Simulate a server error
  </label>

<ul id="results"></ul>`}
  code={`const API = "https://api.pandadev.test";
const form = document.querySelector("#search");
const button = form.querySelector("button");
const broken = document.querySelector("#broken");
const status = document.querySelector("#status");
const list = document.querySelector("#results");

form.addEventListener("submit", async (event) => {
  event.preventDefault();
  const url = new URL("/movies", API);
  url.searchParams.set("search", form.elements.q.value.trim());
  if (broken.checked) url.pathname = "/status/500";

  list.replaceChildren();
  status.textContent = "Loading...";        // 1. loading
  button.disabled = true;
  try {
    const response = await fetch(url);
    if (!response.ok) throw new Error(\`HTTP \${response.status}\`);
    const data = await response.json();

    for (const movie of data.results) {
      const item = document.createElement("li");
      item.textContent = \`\${movie.title} (\${movie.year})\`;
      list.append(item);
    }
    status.textContent = data.total === 0
      ? "No movies found."                  // 2. empty
      : \`Found \${data.total} movies\`;       // 3. success
  } catch (error) {
    console.error(error);
    status.textContent = "Something went wrong."; // 4. error
  } finally {
    button.disabled = false;
  }
});

form.requestSubmit();`}
/>

Did you spot the problem? Searching for `the` says **Found 6 movies**, but only 5 are listed. The API sends results in **pages** of 5 (unless you ask for another `limit`), so we need a way to get the rest.

<Callout type="tip" title="Errors are for developers, messages are for users">

`HTTP 500` or `TypeError: Failed to fetch` means nothing to most users. Show a short, friendly message that says what they can do ("Please try again"), and send the technical details to the console, or in real projects to an error-tracking service like Sentry.

</Callout>

## Step 3: Load more

Pagination needs two changes:

- The search code is split into a **`loadPage()`** function that fetches the current `page` and **appends** its results.
- A **new search** resets `page` to 1 and empties the list; the **Load more** button adds 1 to `page` and calls `loadPage()` again, without emptying the list.

The API's answer tells you when to stop: `{ page, totalPages, total, results }`. Hide the button on the last page:

```js
more.hidden = data.page >= data.totalPages;
```

And disable it while a page is loading. Otherwise an impatient double-click loads the same page twice, and the list shows every movie twice.

## In real projects

Two more problems appear in real search pages:

- **Searching as you type** sends a request for every key press. A **debounce** (from the closures lesson) waits until the user pauses typing for, say, 300 ms before searching.
- **Answers can arrive out of order.** Search for `pan`, then quickly for `panda`: if the first request is slower, its old results arrive *last* and overwrite the right ones. The fix is to cancel the previous request with an `AbortController` each time a new search starts:

```js
let controller;

async function search(query) {
  controller?.abort(); // cancel the previous search, if any
  controller = new AbortController();
  try {
    const response = await fetch(urlFor(query), {
      signal: controller.signal,
    });
    showResults(await response.json());
  } catch (error) {
    if (error.name === "AbortError") return; // replaced: ignore
    showError();
  }
}
```

Real movie APIs, like TMDB or OMDb, work just like the practice one, with one extra step: you sign up for an API key and send it with every request.

1. **Search** (form `submit`): stop the page from reloading, save the **trimmed** text in `query`, set `page` to `1`, empty `#results`, hide `#more` and call `loadPage()`.

```js
const API = "https://api.pandadev.test";
const form = document.querySelector("#search");
const input = document.querySelector("input[name=q]");
const status = document.querySelector("#status");
const list = document.querySelector("#results");
const more = document.querySelector("#more");

let query = "";
let page = 1;

function showMovies(movies) {
  for (const movie of movies) {
    const item = document.createElement("li");
    item.textContent = `${movie.title} (${movie.year})`;
    list.append(item);
  }
}

async function loadPage() {
  status.textContent = "Loading...";
  more.disabled = true;

  const url = new URL("/movies", API);
  url.searchParams.set("search", query);
  url.searchParams.set("page", page);
  url.searchParams.set("limit", 4);

  try {
    const response = await fetch(url);
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const data = await response.json();

    showMovies(data.results);
    status.textContent = data.total === 0
      ? "No movies found."
      : `Found ${data.total} movies`;
    more.hidden = data.page >= data.totalPages;
  } catch (error) {
    console.error(error);
    status.textContent = "Something went wrong. Please try again.";
  } finally {
    more.disabled = false;
  }
}

form.addEventListener("submit", (event) => {
  event.preventDefault();
  query = input.value.trim();
  page = 1;
  list.replaceChildren();
  more.hidden = true;
  loadPage();
});

more.addEventListener("click", () => {
  page++;
  loadPage();
});
```

## Recap

- Plan the page and its **four states** first: loading, success, empty and error.
- Listen for `submit` on the form, build the URL with `searchParams`, fetch, and render each result with `createElement` + `textContent` (never `innerHTML` with API data).
- Before a request: show "Loading..." and disable buttons. Use `try/catch/finally` so a bad status, a network error and success all end with the page in a sensible state.
- Pagination: a new search resets `page` and empties the list; Load more increments `page` and **appends**; hide the button when `page >= totalPages`.
- In real apps, debounce search-as-you-type and cancel stale requests with an `AbortController`.
