You can already loop over an array with `for...of`. But some jobs come up so often (*"double every number"*, *"keep only the passing scores"*, *"add everything up"*) that arrays have **built-in methods** for them.

Each of these methods takes a **function** as its argument. The method calls your function once for every item. A function passed to another function like this is called a **callback**, and this is where short arrow functions really shine.

## forEach: do something with each item

<CodeExample output={`1. Mei
2. Sam
3. Ali`}>

```js
const names = ["Mei", "Sam", "Ali"];

names.forEach((name, index) => {
  console.log(`${index + 1}. ${name}`);
});
```

</CodeExample>

The callback receives the **item** and, if you want it, its **index**. `forEach` is like a `for...of` loop that also hands you the index. It doesn't give anything back.

## map: transform every item

`map` builds a **new** array by running every item through your callback. Whatever the callback returns goes into the new array:

<CodeExample output={`[ 2, 4, 6 ]
[ 'MEI', 'SAM' ]
[ 1, 2, 3 ]`}>

```js
const numbers = [1, 2, 3];
const doubled = numbers.map((n) => n * 2);
console.log(doubled);

const loud = ["mei", "sam"].map((name) => name.toUpperCase());
console.log(loud);

console.log(numbers); // the original is unchanged
```

</CodeExample>

The new array always has the **same length** as the original.

<Callout type="warning" title="Don't forget to return">

With curly braces, an arrow function needs `return`. Without it, the callback gives back `undefined`:

```js
[1, 2, 3].map((n) => { n * 2 });        // [ undefined, undefined, undefined ]
[1, 2, 3].map((n) => { return n * 2; }); // [ 2, 4, 6 ]
[1, 2, 3].map((n) => n * 2);             // [ 2, 4, 6 ]
```

</Callout>

## filter: keep only some items

`filter` keeps the items for which your callback returns `true` and drops the rest:

<CodeExample output={`[ 72, 95, 88 ]
[ 'kiwi', 'fig' ]`}>

```js
const scores = [72, 45, 95, 30, 88];
const passed = scores.filter((score) => score >= 50);
console.log(passed);

const fruits = ["banana", "kiwi", "fig", "mango"];
const short = fruits.filter((fruit) => fruit.length <= 4);
console.log(short);
```

</CodeExample>

## find and findIndex: the first match

When you only need **one** item, `find` returns the first one that matches. `findIndex` returns its position instead:

<CodeExample output={`45
1
undefined
-1`}>

```js
const scores = [72, 45, 95, 30, 88];

console.log(scores.find((s) => s < 50));
console.log(scores.findIndex((s) => s < 50));

console.log(scores.find((s) => s > 100));      // no match
console.log(scores.findIndex((s) => s > 100)); // no match
```

</CodeExample>

Notice that `30` is also below 50, but `find` stops at the **first** match. Use `filter` when you want all of them.

## some and every: yes/no questions

<CodeExample output={`true
false`}>

```js
const ages = [12, 15, 19, 11];

console.log(ages.some((age) => age >= 18));  // at least one?
console.log(ages.every((age) => age >= 12)); // all of them?
```

</CodeExample>

## reduce: boil an array down to one value

`reduce` walks through the array while carrying a running result, often called the **accumulator**. The callback gets the accumulator and the current item, and returns the new accumulator. The second argument to `reduce` is the starting value:

<CodeExample output={`20
95`}>

```js
const prices = [4, 10, 6];
const total = prices.reduce((sum, price) => sum + price, 0);
console.log(total);

const scores = [72, 45, 95, 30];
const best = scores.reduce((max, s) => (s > max ? s : max), 0);
console.log(best);
```

</CodeExample>

Here's how `total` is worked out, step by step:

| Step | `sum` (going in) | `price` | Callback returns |
| ---- | ---------------- | ------- | ---------------- |
| 1    | `0` (the start)  | `4`     | `4`              |
| 2    | `4`              | `10`    | `14`             |
| 3    | `14`             | `6`     | `20`             |

<Callout type="tip" title="Always give reduce a starting value">

Pass a starting value like `0`, `""`, `[]` or `{}` as the second argument. Without one, `reduce` on an empty array crashes with a `TypeError`.

</Callout>

## Chaining methods

Because `map` and `filter` return arrays, you can call another method straight on the result. This is called **chaining**, and it reads like a recipe:

<CodeExample output="100">

```js
const prices = [12, 5, 30, 8];

const result = prices
  .filter((p) => p >= 8)           // [12, 30, 8]
  .map((p) => p * 2)               // [24, 60, 16]
  .reduce((sum, p) => sum + p, 0); // 100

console.log(result);
```

</CodeExample>

Putting each step on its own line makes long chains easy to read.

## Sorting

`sort()` puts the items in order. It works nicely for words, but numbers hold a nasty surprise:

<CodeExample output={`[ 'Ali', 'Mei', 'Sam', 'Zoe' ]
[ 1, 10, 100, 25, 5 ]`}>

```js
const names = ["Sam", "Zoe", "Ali", "Mei"];
names.sort();
console.log(names);

const numbers = [10, 5, 100, 1, 25];
numbers.sort();
console.log(numbers); // 😱
```

</CodeExample>

By default, `sort` turns every item into a **string** and sorts them like words in a dictionary. As text, `"100"` comes before `"25"` because `"1"` comes before `"2"`.

To sort numbers properly, give `sort` a **compare function**. It receives two items, `a` and `b`, and returns:

- a **negative** number to put `a` first,
- a **positive** number to put `b` first,
- `0` to leave them as they are.

`a - b` does exactly that for ascending order, and `b - a` for descending:

<CodeExample output={`[ 1, 5, 10, 25, 100 ]
[ 100, 25, 10, 5, 1 ]
[ 10, 5, 100, 1, 25 ]`}>

```js
const numbers = [10, 5, 100, 1, 25];

const ascending = [...numbers].sort((a, b) => a - b);
const descending = [...numbers].sort((a, b) => b - a);

console.log(ascending);
console.log(descending);
console.log(numbers); // untouched, because we sorted copies
```

</CodeExample>

<Callout type="warning" title="sort changes the original array">

Unlike `map` and `filter`, `sort` reorders the array **in place**. That's why the example above copies first with `[...numbers]`. Modern browsers also have `toSorted()`, which returns a sorted copy for you.

</Callout>

| Method              | Gives back                        | Changes the original? |
| ------------------- | --------------------------------- | --------------------- |
| `forEach(fn)`       | nothing (`undefined`)             | No                    |
| `map(fn)`           | new array, same length            | No                    |
| `filter(fn)`        | new array with the matching items | No                    |
| `find(fn)`          | first matching item or `undefined` | No                   |
| `some(fn)` / `every(fn)` | `true` or `false`            | No                    |
| `reduce(fn, start)` | one value                         | No                    |
| `sort(compare)`     | the same, now sorted, array       | **Yes**               |

A teacher needs three helpers for the class results. Use array methods rather than writing loops by hand:

1. `passingScores(scores)` returns only the scores of `50` or more, sorted from **highest to lowest**.
2. `average(scores)` returns the average score (the total divided by the number of scores).
3. `allPassed(scores)` returns `true` if **every** score is `50` or more.

<Hint>

Chain `filter` and `sort` for the first one, and remember the compare function: `(a, b) => b - a`. Use `reduce` to get the total for the average, and `every` for the last one.

</Hint>

<Solution>

```js
const scores = [72, 45, 95, 30, 88, 60];

function passingScores(scores) {
  return scores
    .filter((score) => score >= 50)
    .sort((a, b) => b - a);
}

function average(scores) {
  const total = scores.reduce((sum, score) => sum + score, 0);
  return total / scores.length;
}

function allPassed(scores) {
  return scores.every((score) => score >= 50);
}

console.log(passingScores(scores)); // [ 95, 88, 72, 60 ]
console.log(average(scores));       // 65
console.log(allPassed(scores));     // false
```

</Solution>

</Exercise>

## Recap

- Array methods take a **callback** that runs once per item.
- `forEach` just loops; `map` transforms; `filter` keeps matches.
- `find`/`findIndex` give the first match; `some`/`every` answer yes/no.
- `reduce(fn, start)` combines everything into one value.
- Chain methods to build a step-by-step recipe.
- `sort` compares as text by default and changes the original: use `(a, b) => a - b` for numbers and sort a copy.
