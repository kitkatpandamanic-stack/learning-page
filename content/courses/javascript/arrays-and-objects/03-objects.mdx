Arrays are great for a list of similar things. But how would you store everything about **one** panda: its name, its age and its favourite food? An **object** groups related values together, and gives each one a name.

## Creating an object

Write an object with curly braces. Inside, each `key: value` pair is called a **property**:

<CodeExample output={`{ name: 'Bao', age: 4, food: 'bamboo', isSleepy: true }
Bao`}>

```js
const panda = {
  name: "Bao",
  age: 4,
  food: "bamboo",
  isSleepy: true,
};

console.log(panda);
console.log(panda.name);
```

</CodeExample>

The **key** is the property's name (`name`, `age`…) and the **value** can be anything: a string, a number, a boolean, an array, even another object. The comma after the last property is optional, but it makes adding new lines easier.

## Dot vs bracket notation

There are two ways to read a property:

<CodeExample output={`Bao
4
bamboo
undefined`}>

```js
const panda = { name: "Bao", age: 4, "favourite food": "bamboo" };

console.log(panda.name);              // dot notation
console.log(panda["age"]);            // bracket notation
console.log(panda["favourite food"]); // keys with spaces need brackets
console.log(panda.colour);            // no such property
```

</CodeExample>

Dot notation is shorter, so use it most of the time. You **need** brackets when the key has spaces or dashes, or when the key is stored in a **variable**:

<CodeExample output={`name: Bao
age: 4`}>

```js
const panda = { name: "Bao", age: 4 };
const fields = ["name", "age"];

for (const field of fields) {
  console.log(`${field}: ${panda[field]}`);
}
```

</CodeExample>

<Callout type="warning" title="panda.field is not panda[field]">

`panda.field` looks for a property literally called `"field"`, which doesn't exist. `panda[field]` uses the **value** of the `field` variable, like `"name"`. This mix-up is a very common bug.

</Callout>

## Adding, changing and deleting properties

<CodeExample output={`{ name: 'Bao', age: 5, city: 'Chengdu' }
true`}>

```js
const panda = { name: "Bao", age: 4, isSleepy: true };

panda.age = 5;          // change
panda.city = "Chengdu"; // add
delete panda.isSleepy;  // remove

console.log(panda);
console.log("city" in panda); // does it have this key?
```

</CodeExample>

Just like arrays, objects are stored by **reference**. A `const` object can still have its properties changed; you just can't point the variable at a different object.

## Methods and this

A property whose value is a function is called a **method**. Inside a method, the keyword `this` means *the object the method was called on*:

<CodeExample output={`Hi, I'm Bao!
Bao is now 5`}>

```js
const panda = {
  name: "Bao",
  age: 4,
  greet() {
    return `Hi, I'm ${this.name}!`;
  },
  haveBirthday() {
    this.age++;
    console.log(`${this.name} is now ${this.age}`);
  },
};

console.log(panda.greet());
panda.haveBirthday();
```

</CodeExample>

When you call `panda.greet()`, `this` is whatever is before the dot: `panda`. You've been using methods all along: `console.log` is the `log` method of the `console` object!

<Callout type="note" title="Arrow functions and this">

Arrow functions don't get their own `this`, so `greet: () => this.name` would **not** see the panda. Use the short `greet() { ... }` form for methods that need `this`.

</Callout>

## Looping over an object

`Object.keys`, `Object.values` and `Object.entries` turn an object into arrays, so you can use everything you know about arrays:

<CodeExample output={`[ 'apples', 'bread', 'milk' ]
[ 3, 1, 2 ]
apples: 3
bread: 1
milk: 2`}>

```js
const basket = { apples: 3, bread: 1, milk: 2 };

console.log(Object.keys(basket));
console.log(Object.values(basket));

for (const [item, count] of Object.entries(basket)) {
  console.log(`${item}: ${count}`);
}
```

</CodeExample>

`Object.entries` gives an array of `[key, value]` pairs, like `[ [ 'apples', 3 ], [ 'bread', 1 ], [ 'milk', 2 ] ]`. The `[item, count]` in the loop unpacks each pair into two variables. That trick is called **destructuring**.

## Destructuring

**Destructuring** pulls values out of an object or array into variables in one line.

### Objects

<CodeExample output={`Bao 4
Bao lives in Unknown
Bao`}>

```js
const panda = { name: "Bao", age: 4 };

const { name, age } = panda; // same as: const name = panda.name; ...
console.log(name, age);

const { city = "Unknown" } = panda; // a default for missing keys
console.log(`${name} lives in ${city}`);

const { name: pandaName } = panda; // a different variable name
console.log(pandaName);
```

</CodeExample>

It works in function parameters too, which is very common:

<CodeExample output="Bao is 4 years old">

```js
function describe({ name, age }) {
  return `${name} is ${age} years old`;
}

console.log(describe({ name: "Bao", age: 4 }));
```

</CodeExample>

### Arrays

With arrays, values are picked by **position**. `...rest` collects whatever is left over:

<CodeExample output={`Mei Sam
[ 'Ali', 'Zoe' ]
2 1`}>

```js
const podium = ["Mei", "Sam", "Ali", "Zoe"];

const [first, second, ...others] = podium;
console.log(first, second);
console.log(others);

let a = 1;
let b = 2;
[a, b] = [b, a]; // swap two variables
console.log(a, b);
```

</CodeExample>

## Spread: copying and merging objects

The spread syntax `...` works on objects too. It copies all the properties into a new object. When the same key appears twice, the **later** one wins:

<CodeExample output={`{ theme: 'dark', fontSize: 14, sound: true }
{ theme: 'light', fontSize: 14 }
{ theme: 'light', fontSize: 20 }`}>

```js
const defaults = { theme: "light", fontSize: 14 };
const choices = { theme: "dark", sound: true };

const settings = { ...defaults, ...choices };
console.log(settings);
console.log(defaults); // unchanged

const bigger = { ...defaults, fontSize: 20 }; // copy + change
console.log(bigger);
```

</CodeExample>

<Callout type="tip" title="A shallow copy">

Spread copies only the **top level**. If a property holds an array or another object, the copy and the original still share that inner array or object.

</Callout>

## Optional chaining

Reading a property of `undefined` crashes your program with a `TypeError`. When something might be missing, use **optional chaining** `?.`: it stops and gives `undefined` instead of crashing.

<CodeExample output={`Chengdu
undefined
No city given`}>

```js
const mei = { name: "Mei", address: { city: "Chengdu" } };
const sam = { name: "Sam" }; // no address!

console.log(mei.address?.city);
console.log(sam.address?.city);
console.log(sam.address?.city ?? "No city given");
```

</CodeExample>

The `??` operator (**nullish coalescing**) gives a fallback value when the left side is `null` or `undefined`. Unlike `||`, it keeps "falsy but real" values such as `0` and `""`.

<Hint>

For `describePet`, write `function describePet({ name, type, age })`. For `birthday`, spread the pet into a new object and then set `age: pet.age + 1`. For `ownerCity`, combine `?.` with `??`.

<Solution>

```js
const pet = {
  name: "Bao",
  type: "panda",
  age: 4,
  owner: { name: "Mei", city: "Chengdu" },
};

function describePet({ name, type, age }) {
  return `${name} is a ${age} year old ${type}`;
}

function birthday(pet) {
  return { ...pet, age: pet.age + 1 };
}

function ownerCity(pet) {
  return pet.owner?.city ?? "Unknown";
}

console.log(describePet(pet));
console.log(birthday(pet));
console.log(pet.age); // still 4
console.log(ownerCity(pet));
console.log(ownerCity({ name: "Pip", type: "cat", age: 2 }));
```

## Recap

- Objects group related values as `key: value` **properties**.
- Use `obj.key` normally and `obj[variable]` when the key is in a variable or has spaces.
- Add or change with `obj.key = value`; remove with `delete obj.key`.
- Methods are functions inside objects; `this` is the object before the dot.
- `Object.keys`, `Object.values` and `Object.entries` turn objects into arrays.
- Destructuring unpacks values: `const { name } = obj` and `const [first] = arr`.
- `{ ...a, ...b }` copies and merges (later keys win); `?.` and `??` handle missing data safely.
