In [the last lesson](/learn/javascript/recursion) you walked comment threads, menus and JSON with functions that call themselves. Every one of those calls waits on the **call stack** until its answer comes back, and in Chrome and Node the stack only has room for roughly ten thousand of them.

Most of the time that's plenty. This lesson is about the times it isn't: when a plain loop is the better tool, how to walk a tree that's too deep for the call stack, and why a trick that works in some other languages won't help you in JavaScript. 🐼

## When a loop is better

Every call takes a place on the stack until it returns. A loop doesn't. For a long, **flat** job, recursion gains nothing and crashes on big inputs:

<CodeExample output={`500000500000
RangeError: Maximum call stack size exceeded`}>

```js
function sumToLoop(n) {
  let total = 0;
  for (let i = 1; i <= n; i++) {
    total += i;
  }
  return total;
}

function sumTo(n) {
  if (n === 0) return 0;
  return n + sumTo(n - 1);
}

console.log(sumToLoop(1000000));
console.log(sumTo(1000000));
```

</CodeExample>

| Use a **loop** when...                               | Use **recursion** when...                              |
| ---------------------------------------------------- | ------------------------------------------------------ |
| you go through items **one after another**           | the data is **nested** (threads, folders, menus, JSON) |
| the input can be very long (many thousands of steps) | the depth is small, even if the data is big            |
| the loop reads just as clearly                       | the recursive version is much shorter and clearer      |

A wide tree is fine for recursion: a thread with a million comments that's only 20 replies deep never has more than about 20 calls waiting at once. What matters is the **depth**. Be careful when the depth is controlled by someone else, like JSON sent to your server: a payload nested 100,000 levels deep is an easy way to crash code that walks it recursively.

If a tree really can be very deep, you can walk it with a loop and an array as your own to-do list instead of the call stack. `push(...comment.replies)` adds every reply to the list:

<CodeExample output="5">

```js
const thread = [
  {
    author: "Mei",
    replies: [
      { author: "Tom", replies: [{ author: "Mei", replies: [] }] },
      { author: "Zara", replies: [] },
    ],
  },
  { author: "Ada", replies: [] },
];

function countComments(comments) {
  const toVisit = [...comments]; // our own to-do list
  let count = 0;
  while (toVisit.length > 0) {
    const comment = toVisit.pop();
    count++;
    toVisit.push(...comment.replies); // add its replies to the list
  }
  return count;
}

console.log(countComments(thread));
```

</CodeExample>

- The to-do list starts with the top-level comments. `[...comments]` makes a **copy**, so `pop()` empties our list, not the array the caller passed in (arrays are references, as you saw in [Arrays](/learn/javascript/arrays)).
- Each turn of the loop takes one comment off the end, counts it and puts its replies on the list. When the list is empty, every comment has been visited.
- The waiting work now lives in an ordinary array, which can hold millions of items, so the depth no longer matters. The comments are visited in a different order than the recursive version visits them, which is fine for counting.

It's longer and a bit harder to read, so use recursion for normal trees and switch to this version only when the depth can get out of hand.

## Tail calls: why JavaScript won't save you

A **tail call** is a call that's the very last thing a function does, with nothing left to do after it returns. `return n + sumTo(n - 1)` is **not** one: the addition still has to happen afterwards. You can rewrite it so it is, by carrying the running total down in a parameter:

<CodeExample output={`10
RangeError: Maximum call stack size exceeded`}>

```js
function sumTo(n, total = 0) {
  if (n === 0) return total;
  return sumTo(n - 1, total + n); // nothing is left to do after this call
}

console.log(sumTo(4));
console.log(sumTo(1000000));
```

</CodeExample>

After a tail call the waiting call has nothing left to do, so an engine could throw it away and reuse its place on the stack. That would make this recursion run like a loop. Some languages promise to do that, which is called **tail-call optimisation**. The JavaScript standard asks for it too: ES2015 (the 2015 edition of JavaScript) added **proper tail calls** for code running in **strict mode**, a stricter set of rules that [modules](/learn/javascript/modules) switch on automatically.

In practice, only **Safari** (its engine is called JavaScriptCore) ships them. **Chrome, Edge and Node** (the V8 engine) and **Firefox** don't. The V8 team built it in 2016 but never turned it on by default, partly because calls that vanish from the stack make bugs harder to trace, and Firefox never shipped it either. So in most places your code runs, the version above still crashes. Don't count on tail calls in JavaScript. When the depth can be huge, use a loop.

<Callout type="note" title="Memoisation, later">

Some recursive functions do the same work over and over: the famous one is Fibonacci, where each number is the sum of the two before it. The cure is to remember answers you've already worked out. You'll build a `memoize` helper for that in [Closures and Higher-Order Functions](/learn/javascript/closures-and-higher-order-functions).

</Callout>

```js
const home = {
  name: "home",
  files: [{ name: "notes.txt", size: 3 }],
  folders: [
    {
      name: "photos",
      files: [
        { name: "bao.jpg", size: 120 },
        { name: "lin.jpg", size: 95 },
      ],
      folders: [
        { name: "2025", files: [{ name: "zoo.jpg", size: 210 }], folders: [] },
      ],
    },
    { name: "music", files: [], folders: [] },
  ],
};

// Builds a chain of folders, each one inside the next, levels deep,
// with a 1 KB file in every folder
function makeDeepFolder(levels) {
  let folder = { name: "bottom", files: [{ name: "a.txt", size: 1 }], folders: [] };
  for (let i = 2; i <= levels; i++) {
    folder = { name: "box", files: [{ name: "a.txt", size: 1 }], folders: [folder] };
  }
  return folder;
}

function totalSize(folder) {
  const toVisit = [folder]; // our own to-do list
  let total = 0;
  while (toVisit.length > 0) {
    const current = toVisit.pop();
    for (const file of current.files) {
      total += file.size;
    }
    toVisit.push(...current.folders);
  }
  return total;
}

function deepestLevel(folder) {
  const toVisit = [{ folder: folder, level: 1 }]; // each folder with its level
  let deepest = 0;
  while (toVisit.length > 0) {
    const item = toVisit.pop();
    if (item.level > deepest) deepest = item.level;
    for (const sub of item.folder.folders) {
      toVisit.push({ folder: sub, level: item.level + 1 });
    }
  }
  return deepest;
}

console.log(deepestLevel(home));
console.log(totalSize(makeDeepFolder(100000)));
console.log(deepestLevel(makeDeepFolder(100000)));
```

## Recap

- Every recursive call keeps a place on the call stack until it returns. A loop doesn't, so use a **loop** for long, flat jobs.
- What crashes recursion is **depth**, not size. Take extra care when someone else controls the depth, like JSON sent to your server.
- To walk a very deep tree, keep your own **to-do list**: start with a new array holding the top, `pop()` an item, `push()` its children, and stop when the list is empty. Anything a recursive version would pass as a parameter, like the level, goes on the list next to the item.
- A **tail call** is the last thing a function does. The standard asks engines to reuse its place on the stack in strict mode, but only Safari does, so don't rely on it.
