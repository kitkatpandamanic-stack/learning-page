На комментарий можно ответить. На ответ тоже можно ответить, и так сколько угодно глубоко, пока люди продолжают разговор. Цикл `for...of` проходит **один** уровень массива. А как обойти данные, если неизвестно, сколько в них уровней? 🌳

Ответ — **рекурсия** (recursion): функция решает задачу, **вызывая саму себя** для части поменьше, пока эта часть не станет такой маленькой, что ответ очевиден.

## Функция, которая вызывает саму себя

Вот обратный отсчёт совсем без цикла:

<CodeExample output={`3
2
1
Подъём, Bao!`}>

```js
function countdown(n) {
  if (n === 0) {
    console.log("Подъём, Bao!");
    return;
  }
  console.log(n);
  countdown(n - 1); // функция вызывает саму себя
}

countdown(3);
```

</CodeExample>

`countdown(3)` печатает `3` и вызывает `countdown(2)`. Тот печатает `2` и вызывает `countdown(1)`, который печатает `1` и вызывает `countdown(0)`. Теперь `n` равно `0`, поэтому функция печатает «Подъём» и возвращается, **больше не** вызывая себя. Останавливает её именно этот `if`.

## Базовый и рекурсивный случаи

У каждой рекурсивной функции две части:

- **Базовый случай** (base case): задача настолько маленькая, что ответ известен сразу, без новых вызовов. В `countdown` это `n === 0`.
- **Рекурсивный случай** (recursive case): сделать немного работы и снова вызвать функцию для **меньшей** задачи, на шаг ближе к базовому случаю. В `countdown` это `countdown(n - 1)`.

Обычно рекурсивные функции **возвращают** значение. Здесь `sumTo(n)` складывает все целые числа от `1` до `n`. Заметьте: `sumTo(4)` — это просто `4 + sumTo(3)`, та же задача, только на единицу меньше.

<CodeExample output={`10
1
5050`}>

```js
function sumTo(n) {
  if (n === 0) return 0;     // базовый случай: складывать больше нечего
  return n + sumTo(n - 1);   // рекурсивный случай: задача поменьше
}

console.log(sumTo(4));
console.log(sumTo(1));
console.log(sumTo(100));
```

</CodeExample>

По той же схеме считается классический **факториал** (factorial): `5!` — это `5 × 4 × 3 × 2 × 1`, то есть `5 × 4!`.

<CodeExample output="120">

```js
function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}

console.log(factorial(5));
```

</CodeExample>

<Callout type="tip" title="Думайте на один шаг">

Не пытайтесь проследить в голове каждый вызов. Когда пишете рекурсивный случай, **представьте, что функция уже работает** для меньшей задачи: «если `sumTo(3)` даёт `6`, то `sumTo(4)` — это `4 + 6`». Потом проверьте базовый случай. Если обе части верны, верна и вся функция.

</Callout>

## Смотрим на стек вызовов

Как JavaScript следит за всеми вызовами, которые ещё не закончились? Каждый вызов получает собственный набор переменных (свою `n`), а сами вызовы складываются в стопку — **стек вызовов** (call stack). Вызов функции кладёт новый вызов **наверх** стопки. Когда вызов возвращает значение, его снимают сверху, и вызов под ним продолжает работу с того места, где ждал.

Пусть `sumTo` рассказывает, что делает. Дополнительный параметр `depth` считает глубину, а `"  ".repeat(depth)` повторяет два пробела `depth` раз, так что более глубокие вызовы получают больший отступ:

<CodeExample output={`sumTo(3) начинается
  sumTo(2) начинается
    sumTo(1) начинается
      sumTo(0) начинается
      базовый случай: return 0
    sumTo(1) возвращает 1 + 0 = 1
  sumTo(2) возвращает 2 + 1 = 3
sumTo(3) возвращает 3 + 3 = 6
6`}>

```js
function sumTo(n, depth = 0) {
  const indent = "  ".repeat(depth);
  console.log(`${indent}sumTo(${n}) начинается`);
  if (n === 0) {
    console.log(`${indent}базовый случай: return 0`);
    return 0;
  }
  const rest = sumTo(n - 1, depth + 1);
  console.log(`${indent}sumTo(${n}) возвращает ${n} + ${rest} = ${n + rest}`);
  return n + rest;
}

console.log(sumTo(3));
```

</CodeExample>

Посмотрите на форму вывода. Вызовы идут **вниз** (стек **растёт**), пока один из них не дойдёт до базового случая. Потом ответы поднимаются **вверх** (стек **сворачивается**): каждый ждущий вызов получает свой ответ, заканчивает своё сложение и возвращает результат. В самый глубокий момент стек выглядит так:

```text
sumTo(0)    ← наверху: выполняет базовый случай
sumTo(1)    ждёт sumTo(0)
sumTo(2)    ждёт sumTo(1)
sumTo(3)    ждёт sumTo(2)
ваш код     ждёт sumTo(3)
```

У каждого вызова своя `n`. Когда `sumTo(2)` наконец возвращает результат, у `sumTo(3)` переменная `n` всё ещё равна `3`, поэтому он может посчитать `3 + 3`.

## Вложенные массивы

По-настоящему рекурсия окупается на **вложенных** данных: в массиве могут лежать числа **и другие массивы**, а в них ещё массивы... Цикл справляется с одним уровнем. Для более глубоких функция вызывает саму себя каждый раз, когда находит очередной массив.

Сначала нужна проверка. `typeof` для массива говорит `"object"`, поэтому отличить массив от другого объекта он не может. А `Array.isArray(value)` может:

<CodeExample output={`object
true
false
21
0`}>

```js
console.log(typeof [1, 2]);
console.log(Array.isArray([1, 2]));
console.log(Array.isArray(7));

function sumAll(items) {
  let total = 0;
  for (const item of items) {
    if (Array.isArray(item)) {
      total += sumAll(item); // массив: заходим внутрь
    } else {
      total += item;         // число: просто прибавляем
    }
  }
  return total;
}

console.log(sumAll([1, [2, 3], [4, [5, [6]]]]));
console.log(sumAll([]));
```

</CodeExample>

Где здесь базовый случай? Он спрятан в цикле: число никогда не вызывает функцию снова, а в пустом массиве нечего перебирать, поэтому `sumAll([])` сразу возвращает `0`. Каждый вызов уходит на уровень глубже, а вложенность где-то обязательно заканчивается, так что вызовы всегда останавливаются.

## Обход дерева: ветка комментариев

Вот задача из начала урока. Каждый комментарий — объект с автором `author`, текстом `text` и массивом ответов `replies`, и каждый ответ — тоже комментарий. Данные такой формы называют **деревом** (tree): так устроены ветки комментариев, папки на компьютере, меню с подменю и элементы веб-страницы.

<CodeExample output={`Mei: Bao опять уснул в бамбуке
  Tom: Bao в своём репертуаре
    Mei: Каждый божий день
  Zara: Фото, пожалуйста!
Ada: Кормление в 15:00
5`}>

```js
const thread = [
  {
    author: "Mei",
    text: "Bao опять уснул в бамбуке",
    replies: [
      {
        author: "Tom",
        text: "Bao в своём репертуаре",
        replies: [{ author: "Mei", text: "Каждый божий день", replies: [] }],
      },
      { author: "Zara", text: "Фото, пожалуйста!", replies: [] },
    ],
  },
  { author: "Ada", text: "Кормление в 15:00", replies: [] },
];

function printThread(comments, depth = 0) {
  for (const comment of comments) {
    console.log(`${"  ".repeat(depth)}${comment.author}: ${comment.text}`);
    printThread(comment.replies, depth + 1); // ответы, на уровень глубже
  }
}

function countComments(comments) {
  let count = 0;
  for (const comment of comments) {
    count += 1 + countComments(comment.replies);
  }
  return count;
}

printThread(thread);
console.log(countComments(thread));
```

</CodeExample>

- `printThread` передаёт `depth + 1` **вниз**, к ответам, поэтому каждый уровень сдвинут чуть сильнее. Передавать информацию вниз, более глубоким вызовам, вы будете постоянно.
- `countComments` передаёт ответы **вверх**: каждый комментарий считается за `1` плюс все комментарии под ним. Сколько их «под ним», за нас считает рекурсивный вызов.
- Базовый случай — комментарий с `replies: []`: циклу в следующем вызове нечего делать, и вызов возвращает `0`, ничего больше не вызывая.

## Данные любой формы

JSON от API обычно смешанный: объекты с массивами, в которых объекты, в которых снова массивы. Чтобы обойти **любую** форму, функция задаёт о каждом значении три вопроса:

1. Это массив? Тогда обойти каждый элемент.
2. Это объект? Тогда обойти каждое значение через `Object.entries`.
3. Что-то другое (строка, число, `null`)? Внутри ничего нет, останавливаемся. Это базовый случай.

Функция `findAll` собирает все значения, лежащие под заданным ключом, на любой глубине:

<CodeExample output={`[ 'Mei', 'Bao', 'Lin', 'Tom', 'Ada' ]
[ 4, 2 ]
[]`}>

```js
const zoo = {
  city: "Чэнду",
  keepers: [
    { name: "Mei", pandas: [{ name: "Bao", age: 4 }, { name: "Lin", age: 2 }] },
    { name: "Tom", pandas: [] },
  ],
  vet: { name: "Ada", phone: null },
};

function findAll(value, key, found = []) {
  if (Array.isArray(value)) {
    for (const item of value) {
      findAll(item, key, found);
    }
  } else if (typeof value === "object" && value !== null) {
    for (const [k, v] of Object.entries(value)) {
      if (k === key) found.push(v);
      findAll(v, key, found);
    }
  }
  // всё остальное (строка, число, null) внутри ничего не содержит
  return found;
}

console.log(findAll(zoo, "name"));
console.log(findAll(zoo, "age"));
console.log(findAll(zoo, "email"));
```

</CodeExample>

Всё держится на двух деталях:

- **Порядок проверок важен.** Массивы — тоже объекты, поэтому `Array.isArray` идёт первым. И вспомните урок [«Типы данных»](/learn/javascript/data-types): `typeof null` равно `"object"`, поэтому проверка `value !== null` не даёт `Object.entries(null)` упасть на телефоне ветеринара `phone`.
- **Один массив `found` передаётся во все вызовы**, и каждый вызов добавляет в него найденное. Значение по умолчанию `found = []` срабатывает только при самом первом вызове, без третьего аргумента. Каждый раз, когда это происходит, JavaScript создаёт новый пустой массив, так что два разных поиска никогда не смешивают результаты.

Этот обход «в три вопроса» — скелет многих настоящих инструментов: глубокого сравнения двух объектов, глубокого копирования, слияния настроек или превращения вложенных настроек в плоские ключи вроде `"theme.colors.bg"`.

## Когда она не останавливается: Maximum call stack size exceeded

У стека вызовов есть предел. В Chrome и Node это примерно десять тысяч вызовов в глубину (точное число зависит от того, сколько хранит каждый вызов). Если базового случая нет или функция до него не доходит, вызовы копятся, пока JavaScript не сдастся и не бросит ошибку:

<CodeExample output={`Подъём!
RangeError: Maximum call stack size exceeded`}>

```js
function countdown(n) {
  if (n === 0) return "Подъём!";
  return countdown(n - 2); // 5, 3, 1, -1, -3... до 0 никогда не дойдёт
}

console.log(countdown(4));
console.log(countdown(5));
```

</CodeExample>

`countdown(4)` идёт 4, 2, 0 и останавливается. `countdown(5)` идёт 5, 3, 1, -1... и перепрыгивает через `0`, так что базовый случай не наступает никогда. Исправление — базовый случай, который нельзя пропустить: `if (n <= 0)`.

<Callout type="note" title="Браузеры формулируют по-разному">

Chrome, Edge и Node пишут `RangeError: Maximum call stack size exceeded` («превышен максимальный размер стека вызовов»), Safari — то же самое с точкой в конце. Firefox называет эту ошибку `InternalError: too much recursion` («слишком много рекурсии»). Смысл у всех один: функция вызывала саму себя и не остановилась. Как читать трассировку стека, которая приходит вместе с ошибкой, вы узнаете в уроке [«Как читать сообщения об ошибках»](/learn/javascript/reading-errors).

</Callout>

<Callout type="warning" title="Прежде чем запускать рекурсивную функцию, проверьте">

1. Есть ли базовый случай?
2. Работает ли **каждый** рекурсивный вызов с **меньшей** задачей (меньшим числом, более короткой или более глубокой частью данных)?
3. Может ли любой вход дойти до базового случая? Подумайте про `0`, отрицательные числа и пустые массивы.

</Callout>

## Частые ошибки

**Забыть `return` в рекурсивном случае.** Вызов происходит, ответ вычисляется, но тут же выбрасывается, и функция возвращает `undefined`:

<CodeExample output="undefined">

```js
function sumTo(n) {
  if (n === 0) return 0;
  n + sumTo(n - 1); // ответ вычисляется... и выбрасывается
}

console.log(sumTo(3));
```

</CodeExample>

**Вызвать себя, но не использовать результат.** Если в `countComments` написать отдельной строкой `countComments(comment.replies);`, функция обойдёт все ответы и не посчитает ни одного. Результат нужно прибавить: `count += 1 + countComments(...)`.

**Сдаться слишком рано при поиске.** Если поиск заглянул в первую ветку и ничего не нашёл, он должен перейти к следующей, а не сразу возвращать «не найдено». Это пригодится в упражнении ниже.

**Данные, которые содержат сами себя.** Если `a.friend = b`, а `b.friend = a`, обход вроде `findAll` будет ходить по кругу бесконечно и закончится той же `RangeError`. Настоящие инструменты глубокого копирования и сравнения запоминают, какие объекты уже видели. Попробуйте это в задаче [«Клонируйте всё семейное древо панд»](/practice/javascript/deep-clone).

          { label: "Сухие стебли", url: "/shop/dried" },
        ],
      },
      { label: "Игрушки", url: "/shop/toys" },
    ],
  },
  {
    label: "О нас",
    children: [{ label: "Наши панды", url: "/about/pandas" }],
  },
];

function countLinks(items) {
  let count = 0;
  for (const item of items) {
    if (item.url) count++;
    if (item.children) count += countLinks(item.children);
  }
  return count;
}

function breadcrumbs(items, label) {
  for (const item of items) {
    if (item.label === label) return [item.label];
    if (item.children) {
      const path = breadcrumbs(item.children, label);
      if (path !== null) return [item.label, ...path];
    }
  }
  return null;
}

console.log(countLinks(menu));
console.log(breadcrumbs(menu, "Сухие стебли"));
console.log(breadcrumbs(menu, "Воздушные змеи"));

## Итоги

- **Рекурсивная** функция вызывает саму себя для **уменьшенной** версии задачи.
- Ей нужен **базовый случай**, который отвечает без нового вызова, и **рекурсивный случай**, который к нему приближает. Не забывайте `return` перед рекурсивным результатом.
- Каждый вызов ждёт в **стеке вызовов** со своими переменными. По пути вниз стек растёт, а когда ответы поднимаются наверх, сворачивается.
- Рекурсия подходит для **вложенных** данных: массивов в массивах, веток комментариев, меню, JSON. Сначала проверяйте `Array.isArray`, потом `typeof value === "object" && value !== null`.
- Если базового случая нет или его можно перепрыгнуть, всё заканчивается `RangeError: Maximum call stack size exceeded` (в Firefox — `InternalError: too much recursion`).
