A comment can have replies. Those replies can have replies of their own, and so on, as deep as people keep talking. A `for...of` loop walks through **one** level of an array. How do you walk through data when you don't know how many levels it has? 🌳

The answer is **recursion**: a function that solves a problem by **calling itself** on a smaller piece of it, until the piece is so small the answer is obvious.

## A function that calls itself

Here's a countdown with no loop at all:

<CodeExample output={`3
2
1
Wake up, Bao!`}>

```js
function countdown(n) {
  if (n === 0) {
    console.log("Wake up, Bao!");
    return;
  }
  console.log(n);
  countdown(n - 1); // the function calls itself
}

countdown(3);
```

</CodeExample>

`countdown(3)` prints `3`, then calls `countdown(2)`. That one prints `2` and calls `countdown(1)`, which prints `1` and calls `countdown(0)`. Now `n` is `0`, so the function prints the wake-up message and returns **without** calling itself again. That `if` is what stops it.

## Base case and recursive case

Every recursive function has two parts:

- The **base case**: a problem so small that you know the answer straight away, with no more calls. In `countdown` it's `n === 0`.
- The **recursive case**: do a little work, then call the function again on a **smaller** problem, one step closer to the base case. In `countdown` it's `countdown(n - 1)`.

Recursive functions usually **return** a value. Here `sumTo(n)` adds up all the whole numbers from `1` to `n`. Notice that `sumTo(4)` is just `4 + sumTo(3)`: the same problem, one size smaller.

<CodeExample output={`10
1
5050`}>

```js
function sumTo(n) {
  if (n === 0) return 0;     // base case: nothing left to add
  return n + sumTo(n - 1);   // recursive case: a smaller problem
}

console.log(sumTo(4));
console.log(sumTo(1));
console.log(sumTo(100));
```

</CodeExample>

The same shape gives you the classic **factorial**: `5!` means `5 × 4 × 3 × 2 × 1`, and that's `5 × 4!`.

<CodeExample output="120">

```js
function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}

console.log(factorial(5));
```

</CodeExample>

<Callout type="tip" title="Think one step at a time">

Don't try to follow every call in your head. When you write the recursive case, **pretend the function already works** for the smaller problem: "if `sumTo(3)` gives me `6`, then `sumTo(4)` is `4 + 6`." Then check that the base case is right. If both parts are right, the whole thing works.

</Callout>

## Watching the call stack

How does JavaScript keep track of all those calls that haven't finished yet? Every call gets its own private set of variables (its own `n`), and the calls are kept in a pile called the **call stack**. Calling a function puts a new call on **top** of the pile. When a call returns, it's taken off the top, and the call underneath carries on from where it was waiting.

Let's make `sumTo` print what it's doing. The extra `depth` parameter counts how deep we are, and `"  ".repeat(depth)` repeats two spaces `depth` times, so deeper calls are indented further:

<CodeExample output={`sumTo(3) starts
  sumTo(2) starts
    sumTo(1) starts
      sumTo(0) starts
      base case: return 0
    sumTo(1) returns 1 + 0 = 1
  sumTo(2) returns 2 + 1 = 3
sumTo(3) returns 3 + 3 = 6
6`}>

```js
function sumTo(n, depth = 0) {
  const indent = "  ".repeat(depth);
  console.log(`${indent}sumTo(${n}) starts`);
  if (n === 0) {
    console.log(`${indent}base case: return 0`);
    return 0;
  }
  const rest = sumTo(n - 1, depth + 1);
  console.log(`${indent}sumTo(${n}) returns ${n} + ${rest} = ${n + rest}`);
  return n + rest;
}

console.log(sumTo(3));
```

</CodeExample>

Read the output as a shape. The calls go **down** (the stack **grows**) until one hits the base case. Then the answers come back **up** (the stack **unwinds**): each waiting call gets its answer, finishes its own addition and returns. At the deepest moment, the stack looks like this:

```text
sumTo(0)    ← on top: running the base case
sumTo(1)    waiting for sumTo(0)
sumTo(2)    waiting for sumTo(1)
sumTo(3)    waiting for sumTo(2)
your code   waiting for sumTo(3)
```

Every call keeps its own `n`. When `sumTo(2)` finally returns, `sumTo(3)` still has `n` equal to `3`, so it can work out `3 + 3`.

## Nested arrays

Recursion really pays off when data is **nested**: an array can hold numbers **and other arrays**, which hold more arrays... A loop handles one level. For the deeper levels, the function calls itself whenever it finds another array.

First, a check we need. `typeof` says `"object"` for an array, so it can't tell arrays apart from other objects. `Array.isArray(value)` can:

<CodeExample output={`object
true
false
21
0`}>

```js
console.log(typeof [1, 2]);
console.log(Array.isArray([1, 2]));
console.log(Array.isArray(7));

function sumAll(items) {
  let total = 0;
  for (const item of items) {
    if (Array.isArray(item)) {
      total += sumAll(item); // an array: go inside it
    } else {
      total += item;         // a number: just add it
    }
  }
  return total;
}

console.log(sumAll([1, [2, 3], [4, [5, [6]]]]));
console.log(sumAll([]));
```

</CodeExample>

Where's the base case? It's hidden in the loop: a number never causes another call, and an empty array has nothing to loop over, so `sumAll([])` returns `0` straight away. Each call goes one level deeper, and the nesting has to end somewhere, so the calls always stop.

## Walking a tree: a comment thread

Here's the problem from the start of the lesson. Each comment is an object with an `author`, a `text` and an array of `replies`, and every reply is a comment too. Data shaped like this is called a **tree**: comment threads, folders on your computer, menus with submenus, and the elements on a web page all work this way.

<CodeExample output={`Mei: Bao fell asleep in the bamboo again
  Tom: Classic Bao
    Mei: Every single day
  Zara: Photo please!
Ada: Feeding time is at 3
5`}>

```js
const thread = [
  {
    author: "Mei",
    text: "Bao fell asleep in the bamboo again",
    replies: [
      {
        author: "Tom",
        text: "Classic Bao",
        replies: [{ author: "Mei", text: "Every single day", replies: [] }],
      },
      { author: "Zara", text: "Photo please!", replies: [] },
    ],
  },
  { author: "Ada", text: "Feeding time is at 3", replies: [] },
];

function printThread(comments, depth = 0) {
  for (const comment of comments) {
    console.log(`${"  ".repeat(depth)}${comment.author}: ${comment.text}`);
    printThread(comment.replies, depth + 1); // the replies, one level deeper
  }
}

function countComments(comments) {
  let count = 0;
  for (const comment of comments) {
    count += 1 + countComments(comment.replies);
  }
  return count;
}

printThread(thread);
console.log(countComments(thread));
```

</CodeExample>

- `printThread` passes `depth + 1` **down** to the replies, so each level is indented a bit more. Passing information down to the deeper calls is a pattern you'll use all the time.
- `countComments` passes answers **up**: each comment counts as `1`, plus however many comments are under it. The recursive call works out "however many are under it" for us.
- The base case is a comment with `replies: []`: the loop inside the next call has nothing to do, so it returns `0` without calling anything.

## Data of any shape

JSON from an API is usually a mix: objects that hold arrays, which hold objects, which hold more arrays. To walk **any** shape, a function asks three questions about each value:

1. Is it an array? Then visit every item.
2. Is it an object? Then visit every value, with `Object.entries`.
3. Anything else (a string, a number, `null`)? There's nothing inside, so stop. This is the base case.

This `findAll` collects every value stored under a given key, at any depth:

<CodeExample output={`[ 'Mei', 'Bao', 'Lin', 'Tom', 'Ada' ]
[ 4, 2 ]
[]`}>

```js
const zoo = {
  city: "Chengdu",
  keepers: [
    { name: "Mei", pandas: [{ name: "Bao", age: 4 }, { name: "Lin", age: 2 }] },
    { name: "Tom", pandas: [] },
  ],
  vet: { name: "Ada", phone: null },
};

function findAll(value, key, found = []) {
  if (Array.isArray(value)) {
    for (const item of value) {
      findAll(item, key, found);
    }
  } else if (typeof value === "object" && value !== null) {
    for (const [k, v] of Object.entries(value)) {
      if (k === key) found.push(v);
      findAll(v, key, found);
    }
  }
  // anything else (a string, a number, null) has nothing inside
  return found;
}

console.log(findAll(zoo, "name"));
console.log(findAll(zoo, "age"));
console.log(findAll(zoo, "email"));
```

</CodeExample>

Two details make this work:

- **The order of the checks matters.** Arrays are objects too, so `Array.isArray` comes first. And remember from [Data Types](/learn/javascript/data-types) that `typeof null` is `"object"`, so `value !== null` stops `Object.entries(null)` from crashing on the vet's `phone`.
- **One `found` array is passed down to every call**, and each call pushes into it. The default `found = []` only kicks in on your first call, the one without a third argument. JavaScript creates a fresh empty array every time that happens, so two separate searches never share results.

This three-question walk is the skeleton of many real tools: comparing two objects deeply, copying them deeply, merging settings, or turning nested settings into flat `"theme.colors.bg"` keys.

## When it never stops: Maximum call stack size exceeded

The call stack has a limit. In Chrome and Node it's roughly ten thousand calls deep (the exact number depends on how much each call stores). If the base case is missing, or the function never reaches it, the calls pile up until JavaScript gives up and throws an error:

<CodeExample output={`Wake up!
RangeError: Maximum call stack size exceeded`}>

```js
function countdown(n) {
  if (n === 0) return "Wake up!";
  return countdown(n - 2); // 5, 3, 1, -1, -3... never 0
}

console.log(countdown(4));
console.log(countdown(5));
```

</CodeExample>

`countdown(4)` goes 4, 2, 0 and stops. `countdown(5)` goes 5, 3, 1, -1... and jumps straight over `0`, so the base case never happens. The fix is a base case that can't be missed: `if (n <= 0)`.

<Callout type="note" title="Browsers word it differently">

Chrome, Edge and Node say `RangeError: Maximum call stack size exceeded`, and Safari says the same with a full stop at the end. Firefox calls it `InternalError: too much recursion`. They all mean the same thing: a function kept calling itself and never stopped. You'll learn to read the stack trace that comes with it in [Reading Error Messages](/learn/javascript/reading-errors).

</Callout>

<Callout type="warning" title="Before you run a recursive function, check">

1. Is there a base case?
2. Does **every** recursive call work on a **smaller** problem (a smaller number, a shorter or deeper-inside piece of the data)?
3. Can every input reach the base case? Think about `0`, negative numbers and empty arrays.

</Callout>

## Common mistakes

**Forgetting `return` in the recursive case.** The call happens and the answer is worked out, but it's thrown away, so the function gives back `undefined`:

<CodeExample output="undefined">

```js
function sumTo(n) {
  if (n === 0) return 0;
  n + sumTo(n - 1); // works out the answer... and throws it away
}

console.log(sumTo(3));
```

</CodeExample>

**Calling yourself but ignoring the result.** In `countComments`, writing `countComments(comment.replies);` on its own line would visit every reply and count none of them. The result has to be added: `count += 1 + countComments(...)`.

**Stopping too early when searching.** If a search looks inside the first branch and finds nothing, it must carry on with the next branch instead of returning "not found" straight away. You'll need this in the exercise below.

**Data that contains itself.** If `a.friend = b` and `b.friend = a`, a walk like `findAll` goes round in a circle forever and ends with the same `RangeError`. Real deep-copy and deep-compare tools remember which objects they've already visited. Try that in the practice problem [Clone the whole panda family tree](/practice/javascript/deep-clone).

2. `breadcrumbs(items, label)` returns an array of labels from the top of the menu down to the item with that `label`. For `"Dried stalks"` that's `["Shop", "Bamboo", "Dried stalks"]`, and for a top-level item like `"Home"` it's just `["Home"]`. If no item has that label, return `null`.

<Hint>

Both functions loop over `items`, and both call themselves on `item.children` when an item has children (`if (item.children)`). For `countLinks`, add up as you go, like `countComments` in the lesson.

</Hint>

<Hint>

In `breadcrumbs`, a matching item's path is just `[item.label]`. For an item with children, ask the recursive call for the path inside them. Only after the loop has checked every item do you know the answer is `null`.

</Hint>

```js
const menu = [
  { label: "Home", url: "/" },
  {
    label: "Shop",
    url: "/shop",
    children: [
      {
        label: "Bamboo",
        children: [
          { label: "Fresh shoots", url: "/shop/fresh" },
          { label: "Dried stalks", url: "/shop/dried" },
        ],
      },
      { label: "Toys", url: "/shop/toys" },
    ],
  },
  {
    label: "About",
    children: [{ label: "Our pandas", url: "/about/pandas" }],
  },
];

function countLinks(items) {
  let count = 0;
  for (const item of items) {
    if (item.url) count++;
    if (item.children) count += countLinks(item.children);
  }
  return count;
}

function breadcrumbs(items, label) {
  for (const item of items) {
    if (item.label === label) return [item.label];
    if (item.children) {
      const path = breadcrumbs(item.children, label);
      if (path !== null) return [item.label, ...path];
    }
  }
  return null;
}

console.log(countLinks(menu));
console.log(breadcrumbs(menu, "Dried stalks"));
console.log(breadcrumbs(menu, "Kites"));
```

</Solution>

## Recap

- A **recursive** function calls itself on a **smaller** version of the problem.
- It needs a **base case** that answers without another call, and a **recursive case** that moves towards it. Don't forget to `return` the recursive result.
- Each call waits on the **call stack** with its own variables. The stack grows on the way down and unwinds as answers come back up.
- Recursion fits **nested** data: arrays inside arrays, comment threads, menus, JSON. Check `Array.isArray` first, then `typeof value === "object" && value !== null`.
- A base case that's missing or can be skipped ends in `RangeError: Maximum call stack size exceeded` (`InternalError: too much recursion` in Firefox).
