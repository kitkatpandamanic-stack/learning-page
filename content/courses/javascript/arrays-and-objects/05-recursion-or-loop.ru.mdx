В [прошлом уроке](/learn/javascript/recursion) вы обходили ветки комментариев, меню и JSON функциями, которые вызывают сами себя. Каждый такой вызов ждёт в **стеке вызовов**, пока не получит свой ответ, а в Chrome и Node места в стеке хватает примерно на десять тысяч вызовов.

Обычно этого с запасом. Этот урок — о случаях, когда не хватает: когда обычный цикл подходит лучше, как обойти дерево, слишком глубокое для стека вызовов, и почему приём, который выручает в некоторых других языках, в JavaScript не поможет. 🐼

## Когда лучше цикл

Каждый вызов занимает место в стеке, пока не вернётся. Цикл — нет. На длинной **плоской** задаче рекурсия ничего не даёт и падает на больших входных данных:

<CodeExample output={`500000500000
RangeError: Maximum call stack size exceeded`}>

```js
function sumToLoop(n) {
  let total = 0;
  for (let i = 1; i <= n; i++) {
    total += i;
  }
  return total;
}

function sumTo(n) {
  if (n === 0) return 0;
  return n + sumTo(n - 1);
}

console.log(sumToLoop(1000000));
console.log(sumTo(1000000));
```

</CodeExample>

| **Цикл**, когда...                                  | **Рекурсия**, когда...                          |
| --------------------------------------------------- | ----------------------------------------------- |
| вы идёте по элементам **один за другим**            | данные **вложенные** (ветки, папки, меню, JSON) |
| вход может быть очень длинным (многие тысячи шагов) | глубина небольшая, даже если данных много       |
| цикл читается так же понятно                        | рекурсивная версия заметно короче и понятнее    |

Широкое дерево рекурсии не страшно: в ветке с миллионом комментариев, но глубиной всего 20 ответов, одновременно ждут не больше примерно 20 вызовов. Важна именно **глубина**. Будьте осторожны, когда глубину контролирует кто-то другой, например JSON, который присылают на ваш сервер: данные с вложенностью в 100 000 уровней легко роняют код, который обходит их рекурсией.

Если дерево и правда может быть очень глубоким, обойдите его циклом, а вместо стека вызовов заведите свой список дел — массив. `push(...comment.replies)` добавляет в список все ответы:

<CodeExample output="5">

```js
const thread = [
  {
    author: "Mei",
    replies: [
      { author: "Tom", replies: [{ author: "Mei", replies: [] }] },
      { author: "Zara", replies: [] },
    ],
  },
  { author: "Ada", replies: [] },
];

function countComments(comments) {
  const toVisit = [...comments]; // наш собственный список дел
  let count = 0;
  while (toVisit.length > 0) {
    const comment = toVisit.pop();
    count++;
    toVisit.push(...comment.replies); // добавляем его ответы в список
  }
  return count;
}

console.log(countComments(thread));
```

</CodeExample>

- Список дел начинается с комментариев верхнего уровня. `[...comments]` делает **копию**, поэтому `pop()` опустошает наш список, а не массив, который передали в функцию (массивы — это ссылки, вы видели это в уроке [«Массивы»](/learn/javascript/arrays)).
- На каждом шаге цикл снимает с конца один комментарий, считает его и кладёт в список его ответы. Когда список опустел, все комментарии посещены.
- Отложенная работа теперь живёт в обычном массиве, а в нём помещаются миллионы элементов, так что глубина больше не важна. Комментарии обходятся не в том порядке, что в рекурсивной версии, но для подсчёта это неважно.

Так длиннее и читается чуть труднее, поэтому для обычных деревьев берите рекурсию, а на эту версию переходите, только когда глубина может выйти из-под контроля.

## Хвостовые вызовы: почему JavaScript вас не спасёт

**Хвостовой вызов** (tail call) — это вызов, который функция делает самым последним, когда после него больше ничего не нужно делать. `return n + sumTo(n - 1)` — **не** хвостовой: сложение ещё предстоит сделать после. Функцию можно переписать так, чтобы вызов стал хвостовым, если передавать накопленную сумму вниз через параметр:

<CodeExample output={`10
RangeError: Maximum call stack size exceeded`}>

```js
function sumTo(n, total = 0) {
  if (n === 0) return total;
  return sumTo(n - 1, total + n); // после этого вызова делать уже нечего
}

console.log(sumTo(4));
console.log(sumTo(1000000));
```

</CodeExample>

После хвостового вызова ждущему вызову делать нечего, поэтому движок мог бы выбросить его и переиспользовать его место в стеке. Тогда такая рекурсия работала бы как цикл. Некоторые языки это гарантируют, и называется это **оптимизацией хвостовых вызовов** (tail-call optimisation). Стандарт JavaScript тоже этого требует: в ES2015 (издание JavaScript 2015 года) появились **«правильные» хвостовые вызовы** (proper tail calls) для кода в **строгом режиме** (strict mode) — более строгом наборе правил, который [модули](/learn/javascript/modules) включают автоматически.

На практике их поддерживает только **Safari** (его движок называется JavaScriptCore). **Chrome, Edge и Node** (движок V8) и **Firefox** — нет. Команда V8 реализовала их в 2016 году, но так и не включила по умолчанию, отчасти потому, что исчезающие из стека вызовы мешают искать ошибки, а Firefox их тоже так и не выпустил. Поэтому почти везде, где работает ваш код, версия выше всё равно падает. Не рассчитывайте на хвостовые вызовы в JavaScript. Когда глубина может быть огромной, используйте цикл.

<Callout type="note" title="Мемоизация — позже">

Некоторые рекурсивные функции снова и снова делают одну и ту же работу. Самый известный пример — числа Фибоначчи, где каждое число равно сумме двух предыдущих. Лекарство — запоминать уже посчитанные ответы. Помощника `memoize` для этого вы напишете в уроке [«Замыкания и функции высшего порядка»](/learn/javascript/closures-and-higher-order-functions).

</Callout>

// и в каждой папке файл на 1 КБ
function makeDeepFolder(levels) {
  let folder = { name: "bottom", files: [{ name: "a.txt", size: 1 }], folders: [] };
  for (let i = 2; i <= levels; i++) {
    folder = { name: "box", files: [{ name: "a.txt", size: 1 }], folders: [folder] };
  }
  return folder;

function totalSize(folder) {
  const toVisit = [folder]; // наш собственный список дел
  let total = 0;
  while (toVisit.length > 0) {
    const current = toVisit.pop();
    for (const file of current.files) {
      total += file.size;
    }
    toVisit.push(...current.folders);
  }
  return total;
}

  const toVisit = [{ folder: folder, level: 1 }]; // каждая папка со своим уровнем
  let deepest = 0;
  while (toVisit.length > 0) {
    const item = toVisit.pop();
    if (item.level > deepest) deepest = item.level;
    for (const sub of item.folder.folders) {
      toVisit.push({ folder: sub, level: item.level + 1 });
    }
  }
  return deepest;
}

## Итоги

- Каждый рекурсивный вызов занимает место в стеке вызовов, пока не вернётся. Цикл — нет, поэтому для длинных плоских задач берите **цикл**.
- Рекурсию роняет **глубина**, а не размер данных. Будьте особенно осторожны, когда глубину контролирует кто-то другой, например JSON, который присылают на ваш сервер.
- Чтобы обойти очень глубокое дерево, ведите свой **список дел**: начните с нового массива, где лежит верхний элемент, снимайте элемент через `pop()`, кладите его детей через `push()` и остановитесь, когда список опустеет. Всё, что рекурсивная версия передавала бы параметром (например, уровень), кладите в список рядом с элементом.
- **Хвостовой вызов** — последнее, что делает функция. Стандарт просит движки переиспользовать его место в стеке в строгом режиме, но так делает только Safari, поэтому не рассчитывайте на это.

С рекурсией всё. Дальше, в уроке [«Работа с реальными данными»](/learn/javascript/working-with-data), вы примените массивы и объекты к настоящим записям и соберёте мини-проект модуля.
