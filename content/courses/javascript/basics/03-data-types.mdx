Every value in JavaScript has a **type**. The type decides what you can do with the value: you can multiply numbers, but not sentences.

## Strings: text

```js
const greeting = "Hello";
const name = 'Panda';
const message = `Hi, ${name}!`; // Hi, Panda!
```

Strings can use double quotes, single quotes or backticks. Backticks let you insert values with `${...}`; these are called **template literals**. You'll use them a lot in the next lesson.

## Numbers

JavaScript uses one type for whole numbers and decimals:

<CodeExample output="24">

```js
const age = 12;
const price = 9.99;
console.log(age * 2);
```

</CodeExample>

<Callout type="warning" title="Numbers in quotes are strings">

`"12"` and `12` are different! The first is text that happens to contain digits. Keep numbers you want to do maths with **out** of quotes.

</Callout>

## Booleans: true or false

```js
const isLoggedIn = true;
const hasFinished = false;
```

Booleans answer yes/no questions. You'll use them all the time with `if` statements in the next module.

## `undefined` and `null`

<CodeExample output="undefined">

```js
let nickname;
console.log(nickname);

const middleName = null;
```

</CodeExample>

- `undefined` means "no value has been given yet".
- `null` means "intentionally empty": you, the programmer, set it on purpose.

## Checking a type with `typeof`

```js
console.log(typeof "hi");      // "string"
console.log(typeof 42);        // "number"
console.log(typeof true);      // "boolean"
console.log(typeof undefined); // "undefined"
```

<Callout type="note" title="A famous quirk">

`typeof null` gives `"object"`, not `"null"`. This is a bug from the very first version of JavaScript in 1995 that can never be fixed without breaking old websites.

</Callout>
