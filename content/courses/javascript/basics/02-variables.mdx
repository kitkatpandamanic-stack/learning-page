A **variable** is a named box that holds a value. Instead of writing the same value over and over, you store it once and refer to it by name.

## Creating a variable with `const`

<CodeExample output="Panda">

```js
const name = "Panda";
console.log(name);
```

</CodeExample>

- `const` creates a variable whose value **cannot be reassigned**.
- `name` is the variable's name.
- `=` puts the value on the right into the box on the left.

<Callout type="note">

Notice there are no quotes around `name` inside `console.log`. Without quotes, JavaScript looks up the variable and prints its **value**. With quotes, `"name"` would just print the word *name*.

</Callout>

## Changing values with `let`

If the value needs to change later, use `let`:

<CodeExample output={`0
10`}>

```js {4}
let score = 0;
console.log(score);

score = 10;
console.log(score);
```

</CodeExample>

You only write `let` the first time. After that, just use the name.

Trying to reassign a `const` causes an error:

```js
const lives = 3;
lives = 2; // TypeError: Assignment to constant variable.
```

## Which one should I use?

Use `const` by default. Switch to `let` only when you know the value will change, like a score or a counter. This makes your code easier to read, because anyone can see which values stay fixed.

<Callout type="warning" title="What about var?">

Older code uses `var`. It works differently in surprising ways, so modern JavaScript uses `let` and `const` instead. You can safely ignore `var` for now.

</Callout>

## Naming rules

- Names can contain letters, digits, `_` and `$`, but **cannot start with a digit**.
- Names are case-sensitive: `score` and `Score` are different variables.
- Use **camelCase** for multi-word names: `playerName`, `highScore`.

```js
const playerName = "Mei";
let highScore = 120;
```

## Recap

- Variables store values under a name.
- `const` cannot be reassigned; `let` can.
- Prefer `const`, and use `let` when the value changes.
- Use camelCase names like `playerName`.
