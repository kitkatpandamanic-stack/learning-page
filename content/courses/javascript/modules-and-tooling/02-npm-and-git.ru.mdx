Настоящие проекты не начинаются с нуля. Разработчики переиспользуют код, которым поделились другие, и хранят историю каждого изменения, чтобы откатывать ошибки и работать в команде. Сделать это возможным помогают два инструмента: **npm** и **Git**. Вы будете пользоваться обоими почти в каждом JavaScript-проекте, так что давайте освоим самое главное. 🐼

<Callout type="note" title="Эти команды выполняются на вашем компьютере">

Всё в этом уроке происходит в **терминале** (terminal) на вашем компьютере, а не в запуске кода на PandaDev. Строки в блоках `bash` — это команды, которые нужно ввести; текст после них — то, что вы можете увидеть.

</Callout>

## Node.js и npm

**Node.js** позволяет запускать JavaScript вне браузера: на вашем компьютере или на сервере. Устанавливая Node (с сайта nodejs.org; надёжный выбор — версия **LTS**), вы получаете и **npm** — **Node Package Manager**, менеджер пакетов Node.

npm подключает вас к **реестру npm** (npm registry) — огромной онлайн-библиотеке бесплатных **пакетов** (packages) с переиспользуемым кодом: помощники для работы с датами, инструменты для тестирования, целые фреймворки вроде React. Проверьте, что оба установлены:

```bash
node --version
npm --version
```

С помощью Node можно запустить любой JavaScript-файл:

```bash
node hello.js
```

## Создаём проект с помощью `npm init`

В главной папке каждого npm-проекта лежит файл **`package.json`**. Он описывает проект: название, версию, нужные пакеты и удобные команды. Создайте его так:

```bash
mkdir panda-app
cd panda-app
npm init -y
```

`npm init` задаёт несколько вопросов, а `-y` отвечает на все: «да, используй значения по умолчанию». Получится примерно такой файл:

```json title="package.json"
{
  "name": "panda-app",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  }
}
```

## Устанавливаем пакеты

Используйте `npm install` (или короче — `npm i`) и название пакета:

```bash
npm install dayjs
```

Происходят три вещи:

1. npm скачивает пакет (и всё, от чего он зависит) в папку **`node_modules`**.
2. Пакет добавляется в **`dependencies`** в `package.json`.
3. Файл **`package-lock.json`** записывает **точную** версию каждого установленного пакета.

После этого пакет можно импортировать в коде — так же, как ваши собственные модули:

```js title="index.js"
import dayjs from "dayjs";

console.log(dayjs().format("D MMMM YYYY"));
```

### `dependencies` и `devDependencies`

Некоторые пакеты нужны только **во время разработки** — например, инструмент для тестирования. Устанавливайте их с флагом `--save-dev` (или `-D`):

```bash
npm install --save-dev vitest
```

```json title="package.json"
{
  "name": "panda-app",
  "version": "1.0.0",
  "type": "module",
  "dependencies": {
    "dayjs": "^1.11.13"
  },
  "devDependencies": {
    "vitest": "^3.2.4"
  }
}
```

- **`dependencies`** (зависимости): пакеты, которые нужны приложению для **работы** (например, библиотека для дат).
- **`devDependencies`** (зависимости для разработки): пакеты, которые нужны только для **сборки или тестирования**. Готовому приложению они не нужны.

### Номера версий и `^`

Версии пакетов следуют **семантическому версионированию** (semantic versioning, semver): `MAJOR.MINOR.PATCH`, например `1.11.13`.

| Часть | Увеличивается, когда... | Пример |
| --- | --- | --- |
| **PATCH** | Исправлены баги | `1.11.13` → `1.11.14` |
| **MINOR** | Добавлены новые возможности, ничего не сломано | `1.11.13` → `1.12.0` |
| **MAJOR** | Изменилось что-то, что может сломать ваш код | `1.11.13` → `2.0.0` |

**`^`** (caret, «крышечка») в `"^1.11.13"` означает «эта версия или любая более новая, пока число MAJOR остаётся `1`». Так вы получаете исправления и новые возможности, но не ломающие изменения. А lock-файл фиксирует, какая именно версия у вас установлена, чтобы у всех в команде была одна и та же.

## npm-скрипты

Раздел `"scripts"` хранит команды под короткими именами, чтобы никому не приходилось запоминать длинные:

```json title="package.json"
{
  "scripts": {
    "start": "node index.js",
    "test": "vitest"
  }
}
```

Скрипт запускается командой `npm run <имя>`:

```bash
npm run start
npm run test
```

`start` и `test` встречаются так часто, что для них есть сокращения: `npm start` и `npm test`.

## `npx`: запускаем команду из пакета

Некоторые пакеты — это **инструменты**, которые запускают из терминала. `npx` запускает их без глобальной установки. Если пакета нет в вашем проекте, npx временно его скачает:

```bash
npx vitest
npx prettier --write .
```

`npx` часто встречается в инструкциях по настройке — например, чтобы создать новое приложение из шаблона.

## `node_modules`: никогда не коммитьте

В `node_modules` легко могут оказаться **тысячи** файлов и сотни мегабайт. Её никогда не редактируют и никогда не передают другим. Любой может в точности восстановить её по `package.json` и `package-lock.json`:

```bash
npm install
```

`npm install` без названия пакета устанавливает всё, что перечислено в проекте. Это первое, что нужно сделать, скачав чужой проект.

<Callout type="warning" title="Коммитьте lock-файл, игнорируйте node_modules">

Всегда сохраняйте `package.json` и `package-lock.json` в Git. Всегда **игнорируйте** `node_modules`. Чуть ниже вы увидите, как это сделать с помощью `.gitignore`.

</Callout>

## Git: история вашего кода

**Git** — это **система контроля версий** (version control). Она делает **снимки** проекта, которые называются **коммитами** (commits), поэтому вы можете:

- видеть, что, когда и почему изменилось;
- вернуться к версии, которая работала;
- безопасно пробовать идеи в отдельной **ветке** (branch);
- работать с другими людьми над одним и тем же кодом.

Папка, которую отслеживает Git, называется **репозиторием** (repository, или коротко **repo**).

## Ваши первые коммиты

Превратите папку проекта в репозиторий:

```bash
git init
```

В любой момент проверяйте, что видит Git, с помощью `git status`. Это команда, которой вы будете пользоваться чаще всего:

```bash
git status
```

```text
On branch main
Untracked files:
  index.js
  package.json
```

Сохранение снимка — это два шага: **подготовьте** (stage) нужные изменения командой `git add`, а затем **закоммитьте** (commit) их с сообщением:

```bash
git add index.js package.json
git commit -m "Добавить первую версию приложения про панду"
```

`git add .` подготавливает сразу все изменения в папке. Чтобы посмотреть историю, используйте `git log`:

```bash
git log --oneline
```

```text
3f2a9c1 Добавить первую версию приложения про панду
```

<Callout type="tip" title="Пишите полезные сообщения коммитов">

Опишите коротким предложением, **что** делает коммит: `Исправить итог для пустой корзины` гораздо лучше, чем `всякое` или `изменения`. Делайте маленькие целенаправленные коммиты почаще, а не один огромный в конце дня.

</Callout>

## Игнорируем файлы с помощью `.gitignore`

Создайте в главной папке проекта файл `.gitignore`. Git не будет отслеживать ничего, что подходит под шаблоны в нём:

```text title=".gitignore"
node_modules/
.env
dist/
.DS_Store
```

- `node_modules/` можно восстановить командой `npm install`.
- В файлах `.env` часто хранятся **секреты** вроде API-ключей.
- `dist/` — результат сборки, который можно сгенерировать заново.

## Ветки

**Ветка** — это отдельная линия работы. В ней можно делать новую функцию, не трогая рабочий код в `main`:

```bash
git switch -c dark-mode
# ...редактируем файлы...
git add .
git commit -m "Добавить переключатель тёмной темы"
```

`git switch -c` создаёт новую ветку и переходит в неё (в старых руководствах используют `git checkout -b`, которая делает то же самое). Когда функция готова, вернитесь в `main` и **слейте** (merge) в неё ветку:

```bash
git switch main
git merge dark-mode
```

`git branch` показывает список веток и отмечает текущую звёздочкой `*`.

## Отправляем код на GitHub

**GitHub** — это сайт, который хранит Git-репозитории онлайн: ваш код в сохранности, а другие могут его посмотреть и помочь. Git и GitHub — разные вещи: Git работает на вашем компьютере, а GitHub хранит копии репозиториев.

Создав на GitHub пустой репозиторий, подключите его и **отправьте** (push) свои коммиты:

```bash
git remote add origin https://github.com/your-name/panda-app.git
git push -u origin main
```

- `origin` — привычное имя для вашей основной онлайн-копии.
- `-u` запоминает связь, так что в следующий раз хватит простого `git push`.
- `git pull` делает обратное — скачивает новые коммиты с GitHub.

<Callout type="danger" title="Никогда не коммитьте секреты">

Пароли, API-ключи и токены никогда не должны попадать в коммит — даже в приватном репозитории. После отправки они навсегда остаются в истории. Храните их в файле `.env`, который указан в `.gitignore`. Если ключ случайно утёк, сразу же **отзовите его** и создайте новый.

</Callout>

## Итоги

- **Node.js** запускает JavaScript вне браузера; **npm** устанавливает пакеты из реестра npm.
- `npm init -y` создаёт **`package.json`**; `npm install name` добавляет **зависимость**, а с `-D` — **зависимость для разработки** (devDependency).
- `^1.2.3` принимает более новые minor- и patch-версии, но не новую major-версию. Lock-файл фиксирует точные версии.
- **Скрипты** запускаются через `npm run name`; **npx** запускает инструменты из пакетов без глобальной установки.
- Никогда не коммитьте **`node_modules`**: `npm install` восстановит её.
- Основы Git: `git init`, `git status`, `git add`, `git commit -m`, `git log`.
- Используйте **ветки** для новой работы, **`.gitignore`** — для файлов, которые Git должен пропускать, и `git push` — чтобы сохранить копию на **GitHub**.
