До сих пор весь ваш код жил в одном файле. Для маленьких программ это нормально, но в настоящем приложении могут быть тысячи строк. Листать один гигантский файл в поисках нужной функции очень быстро надоедает! **Модули** (modules) позволяют разбить код на отдельные файлы, у каждого из которых своя задача, и делиться частями кода между ними.

## Зачем разбивать код на модули?

**Модуль** — это просто JavaScript-файл, который может **экспортировать** (export) что-то, то есть делиться этим, и **импортировать** (import) что-то из других файлов, то есть пользоваться этим. Модули дают вам:

- **Порядок**: `cart.js` отвечает за корзину, `prices.js` — за цены. Вы всегда знаете, где искать.
- **Повторное использование**: напишите вспомогательную функцию один раз и импортируйте её везде, где она нужна.
- **Собственную область видимости** (scope): переменные одного модуля не могут случайно столкнуться с переменными другого.
- **Понятные связи**: строки `import` в начале файла точно показывают, от чего он зависит.

<Callout type="note" title="Примеры в этом уроке">

Запуск кода на PandaDev работает с одним файлом за раз, поэтому примеры из нескольких файлов ниже показаны просто как файлы (имя файла указано сверху). Попробуйте их позже на своём компьютере — в Node или в браузере.

</Callout>

## Именованный экспорт

Поставьте `export` перед всем, чем хотите поделиться: переменными, функциями или классами.

```js title="math.js"
export const PI = 3.14159;

export function add(a, b) {
  return a + b;
}

export function circleArea(radius) {
  return PI * radius * radius;
}

// Не экспортируется: использовать её может только этот файл
function secretHelper() {}
```

Затем **импортируйте** их по имени в фигурных скобках:

```js title="main.js"
import { add, circleArea } from "./math.js";

console.log(add(2, 3)); // 5
console.log(circleArea(1)); // 3.14159
```

- Имена в `{ }` должны в точности **совпадать** с экспортированными.
- Путь начинается с `./` (что значит «в этой папке») и включает расширение `.js`.
- Вы импортируете только то, что нужно. `secretHelper` не был экспортирован, поэтому `main.js` не может его использовать.

Можно также экспортировать всё одним списком в конце файла:

```js title="math.js"
const PI = 3.14159;
function add(a, b) {
  return a + b;
}

export { PI, add };
```

## Экспорт по умолчанию

У файла также может быть **один экспорт по умолчанию** (default export) — главное, что этот файл предоставляет. Его часто используют, когда в файле один класс или одна функция:

```js title="ShoppingCart.js"
export default class ShoppingCart {
  items = [];

  add(item) {
    this.items.push(item);
  }
}
```

При импорте экспорта по умолчанию фигурные скобки **не** нужны, а имя можно выбрать любое:

```js title="main.js"
import ShoppingCart from "./ShoppingCart.js";

const cart = new ShoppingCart();
cart.add("bamboo");
```

В файле могут быть оба вида экспорта. Сначала идёт экспорт по умолчанию, затем именованные — в фигурных скобках:

```js title="main.js"
import formatPrice, { TAX_RATE } from "./prices.js";
```

| | Именованный экспорт | Экспорт по умолчанию |
| --- | --- | --- |
| Сколько в одном файле | Сколько угодно | Не больше одного |
| Экспорт | `export function add() {}` | `export default function () {}` |
| Импорт | `import { add } from "./x.js"` | `import anything from "./x.js"` |
| Имя при импорте | Должно совпадать | Любое |

<Callout type="tip" title="Многие команды предпочитают именованный экспорт">

Поскольку имена должны совпадать, именованный экспорт сохраняет одно и то же имя во всём проекте: по такому коду проще искать, а инструментам проще автоматически добавлять импорты. Экспорт по умолчанию всё равно встречается часто, особенно для классов и компонентов.

</Callout>

## Переименование с помощью `as`

Что, если два модуля экспортируют что-то с одинаковым именем? Переименуйте при импорте с помощью `as`:

```js title="main.js"
import { format as formatDate } from "./dates.js";
import { format as formatPrice } from "./prices.js";

console.log(formatDate(new Date()));
console.log(formatPrice(9.5));
```

`as` работает и при экспорте: `export { add as sum };` делится функцией `add` под именем `sum`.

## Импорт всего сразу: `import * as`

Чтобы забрать **все** именованные экспорты разом, импортируйте их как один объект — его называют **пространством имён** (namespace):

```js title="main.js"
import * as math from "./math.js";

console.log(math.PI); // 3.14159
console.log(math.add(2, 3)); // 5
```

Это удобно, когда модуль экспортирует много родственных вспомогательных функций, а запись `math.add` сразу показывает, откуда взялась `add`.

## У модулей своя область видимости

У каждого модуля **своя закрытая область видимости**. Переменные, объявленные на верхнем уровне модуля, **не** глобальные: другие файлы видят только то, что вы экспортировали. Вдобавок:

- Модули **всегда выполняются в строгом режиме** (strict mode), поэтому небрежные ошибки вроде использования необъявленной переменной становятся ошибками.
- Код модуля выполняется **один раз** — при первом импорте. Повторный импорт из другого файла переиспользует те же экспорты.

До появления модулей разработчики получали закрытую область видимости, оборачивая код в функцию, которая сразу же вызывается. Такую функцию называют **IIFE** (Immediately Invoked Function Expression — немедленно вызываемое функциональное выражение). Она возвращает объект только с теми частями, которыми хочет поделиться, — прямо как список экспортов:

<CodeExample output={`2
undefined`}>

```js
const counter = (() => {
  let count = 0; // приватная: её видят только функции ниже

  function increment() {
    count++;
    return count;
  }

  return { increment }; // это «экспорты»
})();

counter.increment();
console.log(counter.increment());
console.log(counter.count);
```

</CodeExample>

`count` живёт внутри функции, поэтому внешний мир может изменить её только через `increment()`. Настоящие модули дают такую приватность бесплатно и с гораздо более приятным синтаксисом. Но IIFE вы ещё встретите в старом коде.

## Модули в браузере

Чтобы использовать модули на веб-странице, добавьте `type="module"` к тегу script. Загружать нужно только входной файл — остальное он импортирует сам:

```html title="index.html"
<script type="module" src="main.js"></script>
```

Скрипты-модули автоматически становятся **отложенными** (deferred): они ждут, пока HTML будет прочитан, так что к моменту запуска вашего кода элементы страницы уже существуют.

<Callout type="warning" title="Используйте локальный сервер">

Если открыть `index.html` двойным щелчком (адрес вида `file://`), браузеры из соображений безопасности блокируют импорт модулей. Вместо этого запустите небольшой локальный сервер, например расширение **Live Server** в VS Code.

</Callout>

## Модули в Node.js

Node.js (JavaScript вне браузера, подробнее о нём — в следующем уроке) поддерживает те же `import` и `export`. Сообщите Node, что ваш проект их использует, добавив `"type": "module"` в `package.json`:

```json title="package.json"
{
  "name": "my-app",
  "type": "module"
}
```

Затем запустите входной файл из терминала (terminal):

```bash
node main.js
```

Другой вариант — дать файлу расширение `.mjs`: тогда Node считает его модулем без всяких настроек.

<Callout type="note" title="Вам встретится и require()">

Старый код для Node использует другую систему — **CommonJS**: `const fs = require("fs")` и `module.exports = ...`. Она делает то же самое. В новом коде используйте `import` и `export` — официальный стандарт, который работает и в браузере, и в Node.

</Callout>

С помощью шаблона IIFE создайте «модуль» `scoreboard` (таблица очков). Храните очки **приватно** внутри функции и верните объект всего с двумя функциями:

- `add(name, points)` добавляет очки к счёту этого игрока.
- `total(name)` возвращает сумму очков игрока или `0`, если он ещё ничего не набрал.

<Hint>

Внутри IIFE создайте `const scores = {};`. В `add`: если `scores[name]` равно `undefined`, сначала присвойте ему `0`, а потом добавьте очки. В `total` сделайте ту же проверку перед `return`. В конце напишите `return { add, total };`.

</Hint>

<Solution>

```js
const scoreboard = (() => {
  const scores = {};

  function add(name, points) {
    if (scores[name] === undefined) {
      scores[name] = 0;
    }
    scores[name] += points;
  }

  function total(name) {
    if (scores[name] === undefined) {
      return 0;
    }
    return scores[name];
  }

  return { add, total };
})();

scoreboard.add("Мэй", 10);
scoreboard.add("Мэй", 5);
console.log(scoreboard.total("Мэй")); // 15
```

</Solution>

## Итоги

- **Модуль** — это файл, который делится кодом через `export` и использует код других файлов через `import`.
- **Именованные экспорты** импортируются в фигурных скобках с совпадающими именами; единственный **экспорт по умолчанию** импортируется без скобок и под любым именем.
- Переименовывайте с помощью `as` или забирайте всё сразу через `import * as name`.
- У модулей **своя область видимости**, они выполняются в **строгом режиме** и только один раз.
- В браузере используйте `<script type="module">`, а в Node — `"type": "module"` (или расширение `.mjs`).
