Ваше приложение со списком дел работает, но память у него как у золотой рыбки 🐠: перезагрузите страницу — и все задачи исчезнут. Так происходит потому, что `tasks` живёт в переменной, а переменные стираются при каждой новой загрузке страницы. В этой заключительной части вы будете сохранять задачи **прямо в браузере**, чтобы они остались на месте и завтра.

Вам пригодятся **JSON** из модуля **«Массивы и объекты»**, **try/catch** из модуля **«Ошибки и отладка»**, `reduce`, чтобы исправить коварную ошибку с id, и вы бегло посмотрите, как **классы (classes)** и **модули (modules)** могли бы упорядочить приложение.

## Знакомьтесь: localStorage

Каждый браузер выделяет каждому сайту небольшое хранилище под названием **`localStorage`**. Всё, что вы туда положите, остаётся там после перезагрузки, после закрытия вкладки и даже после перезапуска компьютера. Вам понадобятся четыре его метода:

| Метод                              | Что делает                                                   |
| ---------------------------------- | ------------------------------------------------------------ |
| `localStorage.setItem(key, value)` | сохраняет `value` под именем `key`                           |
| `localStorage.getItem(key)`        | возвращает сохранённое значение или `null`, если его нет     |
| `localStorage.removeItem(key)`     | удаляет одну эту запись                                      |
| `localStorage.clear()`             | удаляет всё, что сохранил этот сайт                          |

Нажмите **«Запустить»** несколько раз в этом примере и смотрите, как растёт число:

<TryIt
  html={`<p id="visits"></p>
<button id="forget">Забудь меня</button>`}

/>

В первый раз `getItem` возвращает `null`, потому что ничего ещё не сохранено. После этого он возвращает сохранённое число... но в виде **строки**! `localStorage` умеет хранить только **текст**. Всё, что вы сохраняете, сначала превращается в строку.

<Callout type="note" title="localStorage в превью">

В вашем собственном браузере `localStorage` действительно сохраняется между перезагрузками страницы. Превью на PandaDev работают в закрытой песочнице, где настоящий `localStorage` запрещён, поэтому сайт его **имитирует**: он запоминает то, что сохранил ваш код, а повторное нажатие **«Запустить»** работает как перезагрузка страницы. Нажмите **«Сбросить»**, чтобы стереть сохранённые данные и начать с чистого листа.

</Callout>

## Сохраняем массивы и объекты как JSON

Раз `localStorage` хранит только строки, что будет, если сохранить массив `tasks` напрямую? Давайте проверим:

<TryIt
  html={`<p>Смотрите консоль под превью. 👇</p>`}
  code={`const tasks = [{ id: 1, text: "Полить бамбук", done: false }];

localStorage.setItem("oops", tasks);
console.log(localStorage.getItem("oops"));

localStorage.setItem("pandadev-todos", JSON.stringify(tasks));
const text = localStorage.getItem("pandadev-todos");
console.log(text);

const back = JSON.parse(text);
console.log(back[0].text, back[0].done);`}
/>

Если сохранить массив напрямую, получится бесполезный текст `[object Object]`, и задачи потеряются. Решение — знакомая вам пара методов JSON:

- **Сохранение:** `JSON.stringify(tasks)` превращает массив в JSON-текст, а `setItem` его сохраняет.
- **Загрузка:** `getItem` возвращает текст, а `JSON.parse` снова превращает его в настоящий массив объектов.

Так появляется наша первая функция. Ключ храним в константе, чтобы он везде был написан одинаково:

```js
const STORAGE_KEY = "pandadev-todos";

function saveTasks() {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(tasks));
}
```

## Сохраняем после каждого изменения

Когда нужно сохранять? После **каждого** изменения `tasks`: добавления, отметки, удаления и очистки. Приложение построено по паттерну отрисовки, поэтому за каждым изменением уже следует вызов `render()`. Отсюда изящный приём: одна вспомогательная функция, которая делает и то и другое.

```js
function saveAndRender() {
  saveTasks();
  render();
}
```

Затем в обработчиках, которые **меняют задачи** (форма, список и **«Очистить выполненные»**), вызывайте `saveAndRender()` вместо `render()`. Кнопки-фильтры меняют только то, что **показывается**, а не сами задачи, поэтому они по-прежнему вызывают обычный `render()`.

## Безопасно загружаем задачи

При запуске страницы мы читаем сохранённый текст обратно. Здесь возможны две проблемы:

1. **Ещё ничего не сохранено** (самый первый визит). `getItem` возвращает `null`.
2. **Сохранённые данные повреждены.** Возможно, старая версия приложения сохранила что-то другое или кто-то отредактировал данные вручную в инструментах разработчика браузера. Тогда `JSON.parse` **выбрасывает** `SyntaxError`, и без защиты всё приложение упадёт, так ничего и не нарисовав.

Вот где `try/catch` оправдывает своё существование: если разбор не удался, мы перехватываем ошибку и начинаем с пустого списка. Стоит сделать ещё одну проверку. `JSON.parse` с радостью прочитает и `"привет"` или `42`, а это никакие не списки задач. **`Array.isArray(value)`** — встроенная проверка, которая даёт `true` только для массивов:

<CodeExample output={`true
false
false`}>

```js
console.log(Array.isArray([1, 2]));
console.log(Array.isArray("привет"));
console.log(Array.isArray(null));
```

</CodeExample>

Если собрать всё вместе, `loadTasks()` всегда возвращает массив, что бы ни лежало в хранилище:

<TryIt
  html={`<p>Смотрите консоль под превью. 👇</p>`}
  code={`const STORAGE_KEY = "pandadev-todos";

function loadTasks() {
  const saved = localStorage.getItem(STORAGE_KEY);
  if (saved === null) return [];

  try {
    const data = JSON.parse(saved);
    return Array.isArray(data) ? data : [];
  } catch (error) {
    console.warn("Сохранённые задачи повреждены, начинаем с чистого листа.");
    return [];
  }
}

localStorage.removeItem(STORAGE_KEY);
console.log("Ничего не сохранено:", loadTasks());

localStorage.setItem(STORAGE_KEY, '[{"id":1,"text":"Вздремнуть","done":true}]');
console.log("Корректные данные:", loadTasks());

localStorage.setItem(STORAGE_KEY, "{ ой, это не JSON");
console.log("Повреждённые данные:", loadTasks());

localStorage.setItem(STORAGE_KEY, '"привет"');
console.log("Не список:", loadTasks());`}
/>

Теперь при запуске приложения `tasks` берётся из хранилища, а не из жёстко прописанного списка:

```js
let tasks = loadTasks();
```

<Callout type="warning" title="Что не стоит хранить в localStorage">

`localStorage` отлично подходит для списков дел, настроек и черновиков. Но он **не** годится для паролей, токенов и любых секретов: любой JavaScript, работающий на странице, может его прочитать. К тому же он маленький (около 5 МБ на сайт) и принадлежит одному браузеру на одном устройстве, так что настоящую базу данных он не заменит.

</Callout>

## Исправляем следующий id

Тут нас подстерегает коварная ошибка. В части 1 `nextId` начинался с фиксированного числа. Но теперь `tasks` может вернуться из хранилища с id `1`, `2` и `7`. Если `nextId` снова начнётся с `3`, новая задача получит id `3`... а следующая — `7`, который **уже занят**. Две задачи с одинаковым id — и отметка одной может отметить другую!

Решение: после загрузки начинать счёт с **наибольшего id + 1**. `reduce` находит наибольший id, перенося через все шаги самое большое значение, встреченное на данный момент:

<CodeExample output={`8
1`}>

```js
function findNextId(savedTasks) {
  const biggest = savedTasks.reduce(
    (max, task) => (task.id > max ? task.id : max),
    0,
  );
  return biggest + 1;
}

console.log(findNextId([{ id: 1 }, { id: 7 }, { id: 3 }]));
console.log(findNextId([]));
```

</CodeExample>

Для пустого списка `reduce` просто возвращает начальное значение `0`, поэтому первая задача получает id `1`. В приложении:

```js
let tasks = loadTasks();
let nextId = findNextId(tasks);
```

## Функции или класс?

В модуле «Классы и ООП» вы научились объединять данные и работающие с ними функции в **класс (class)**. Может, сделать приложение классом `TodoList`? Можно и так:

<CodeExample output={`Дома осталось задач: 1
На работе осталось задач: 1`}>

```js
class TodoList {
  tasks = [];
  nextId = 1;

  add(text) {
    const clean = text.trim();
    if (clean === "") return;
    this.tasks.push({ id: this.nextId, text: clean, done: false });
    this.nextId++;
  }

  toggle(id) {
    const task = this.tasks.find((task) => task.id === id);
    if (task) task.done = !task.done;
  }

  get left() {
    return this.tasks.filter((task) => !task.done).length;
  }
}

const home = new TodoList();
const work = new TodoList();
home.add("Полить бамбук");
home.add("Вздремнуть на солнышке");
home.toggle(1);
work.add("Написать отчёт");

console.log(`Дома осталось задач: ${home.left}`);
console.log(`На работе осталось задач: ${work.left}`);
```

</CodeExample>

Для **этого** приложения мы оставим обычные функции. Список всего **один**, всё приложение помещается в один скрипт, а уже написанные функции короткие и легко тестируются. Класс начинает окупаться, когда нужно **несколько** списков (как `home` и `work` выше) или когда приложение разрастается настолько, что его стоит разбить на **модули**. Тогда логика задач, код хранилища и код работы с DOM могли бы жить каждый в своём файле:

```js
// main.js (более крупная версия приложения)
import { TodoList } from "./todo-list.js";
import { loadTasks, saveTasks } from "./storage.js";
import { render } from "./render.js";
```

Оба стиля хороши. Важнее всего идея, которая за ними стоит: **состояние в одном месте, его меняют маленькие функции, а рисует `render()`**.

```js
const form = document.querySelector("#add-form");
const input = document.querySelector("#new-task");
const list = document.querySelector("#task-list");
const count = document.querySelector("#count");
const filters = document.querySelector("#filters");
const filterButtons = document.querySelectorAll("#filters button");
const clearButton = document.querySelector("#clear-done");

const STORAGE_KEY = "pandadev-todos";

let tasks = loadTasks();
let nextId = findNextId(tasks);
let filter = "all";

function saveTasks() {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(tasks));
}

function loadTasks() {
  const saved = localStorage.getItem(STORAGE_KEY);
  if (saved === null) return [];

  try {
    const data = JSON.parse(saved);
    return Array.isArray(data) ? data : [];
  } catch (error) {
    console.warn("Сохранённые задачи повреждены, начинаем с чистого листа.");
    return [];
  }
}

function findNextId(savedTasks) {
  const biggest = savedTasks.reduce(
    (max, task) => (task.id > max ? task.id : max),
    0,
  );
  return biggest + 1;
}

function saveAndRender() {
  saveTasks();
  render();
}

function addTask(text) {
  const clean = text.trim();
  if (clean === "") return;

  tasks.push({ id: nextId, text: clean, done: false });
  nextId++;
}

function toggleTask(id) {
  const task = tasks.find((task) => task.id === id);
  if (task) {
    task.done = !task.done;
  }
}

function deleteTask(id) {
  tasks = tasks.filter((task) => task.id !== id);
}

function clearCompleted() {
  tasks = tasks.filter((task) => !task.done);
}

function visibleTasks() {
  if (filter === "active") return tasks.filter((t) => !t.done);
  if (filter === "done") return tasks.filter((t) => t.done);
  return tasks;
}

function createTaskItem(task) {
  const li = document.createElement("li");
  li.dataset.id = task.id;
  if (task.done) {
    li.classList.add("done");
  }

  const label = document.createElement("label");
  const checkbox = document.createElement("input");
  checkbox.type = "checkbox";
  checkbox.className = "toggle";
  checkbox.checked = task.done;
  checkbox.dataset.id = task.id;

  const text = document.createElement("span");
  text.className = "text";
  text.textContent = task.text;
  label.append(checkbox, text);

  const remove = document.createElement("button");
  remove.className = "delete";
  remove.textContent = "✕";
  remove.dataset.id = task.id;

  li.append(label, remove);
  return li;
}

function render() {
  list.replaceChildren();
  visibleTasks().forEach((task) => {
    list.append(createTaskItem(task));
  });

  const left = tasks.filter((task) => !task.done).length;
  count.textContent = left === 1 ? "Осталась 1 задача" : `Осталось задач: ${left}`;

  filterButtons.forEach((button) => {
    const chosen = button.dataset.filter === filter;
    button.classList.toggle("active", chosen);
  });
}

form.addEventListener("submit", (event) => {
  event.preventDefault();
  addTask(input.value);
  input.value = "";
  saveAndRender();
});

list.addEventListener("click", (event) => {
  const id = Number(event.target.dataset.id);
  if (event.target.matches(".toggle")) {
    toggleTask(id);
    saveAndRender();
  } else if (event.target.matches(".delete")) {
    deleteTask(id);
    saveAndRender();
  }
});

filters.addEventListener("click", (event) => {
  if (event.target.matches("button")) {
    filter = event.target.dataset.filter;
    render();
  }
});

clearButton.addEventListener("click", () => {
  clearCompleted();
  saveAndRender();
});

render();
```

## Что вы построили

- **`localStorage`** хранит данные в браузере между перезагрузками, но только в виде **строк**, поэтому задачи сохраняются через `JSON.stringify` и читаются обратно через `JSON.parse`.
- **`saveAndRender()`** сохраняет задачи после каждого их изменения, а кнопки-фильтры только перерисовывают список.
- **`loadTasks()`** всегда возвращает массив: `[]`, если данных нет, если JSON повреждён (ошибку перехватывает `try/catch`) или если там не список.
- **`findNextId()`** с помощью `reduce` сохраняет уникальность id после загрузки.
- Вы осознанно выбрали **функции вместо класса** и увидели, как класс `TodoList` и модули могли бы упорядочить более крупную версию.
