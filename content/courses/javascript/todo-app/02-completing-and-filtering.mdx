Your app can show and add tasks. Now it's time to make the list **interactive**! In this part you'll add a checkbox to tick tasks off, a ✕ button to delete them, **All / Active / Done** filter buttons, a "2 tasks left" counter and a **Clear completed** button. ✅

You'll use `find` and `filter` from **Arrays & Objects**, and **event delegation** with `dataset` from **The DOM & Events**. And every feature follows the same recipe from Part 1: **change the state, then `render()`**.

## Finding a task by its id

Every feature in this part starts the same way: "the user clicked on task number 3, now do something to it". Two array methods do the heavy lifting:

- **`find`** returns the task object with a matching id, so we can change it.
- **`filter`** returns a new array **without** the matching task, which is exactly what deleting means.

<CodeExample output={`{ id: 1, text: 'Water the bamboo', done: true }
{ id: 3, text: 'Nap in the sun', done: false }`}>

```js
let tasks = [
  { id: 1, text: "Water the bamboo", done: false },
  { id: 2, text: "Learn the DOM", done: true },
  { id: 3, text: "Nap in the sun", done: false },
];

function toggleTask(id) {
  const task = tasks.find((task) => task.id === id);
  if (task) {
    task.done = !task.done;
  }
}

function deleteTask(id) {
  tasks = tasks.filter((task) => task.id !== id);
}

toggleTask(1);
deleteTask(2);
tasks.forEach((task) => console.log(task));
```

</CodeExample>

A few things to notice:

- `task.done = !task.done` **flips** a boolean: `false` becomes `true` and `true` becomes `false`. One line handles both ticking and un-ticking.
- `find` gives back the **same object** that's inside the array (objects are references), so changing `task.done` changes the task in `tasks` too.
- `filter` builds a **new** array, so `deleteTask` puts it back into `tasks`. That's why `tasks` was declared with `let` in Part 1, not `const`.
- The `if (task)` check means a wrong id does nothing, instead of crashing with "Cannot set properties of undefined".

## Checkboxes and delete buttons

Each item needs two new controls: a **checkbox** for done, and a **delete button**. Both store the task's id in `data-id`, so a click on either one knows which task it belongs to.

We'll wrap the checkbox and the text in a **`<label>`**. That's a nice HTML trick: clicking anywhere on a label's text also clicks the checkbox inside it, so users don't have to aim for the tiny box.

```js
const label = document.createElement("label");

const checkbox = document.createElement("input");
checkbox.type = "checkbox";
checkbox.className = "toggle";
checkbox.checked = task.done;
checkbox.dataset.id = task.id;

label.append(checkbox, text);
```

`append` can take **several** elements at once and adds them in order. Here's the whole item in action, with a listener that only **logs** what was clicked (you'll make it do the real work in the exercise):

## One listener for the whole list

That listener is **event delegation**: one listener on the `<ul>` handles clicks for every item, even the ones `render()` creates later. Since `render()` throws away and rebuilds all the items every time, adding listeners to each item would mean adding them all over again after every render. With delegation you add **one** listener, once.

Inside it, `event.target.matches(".toggle")` and `event.target.matches(".delete")` tell you **what** was clicked, and `event.target.dataset.id` tells you **which task**.

<CodeExample output={`false
true`}>

```js
const idFromPage = "2"; // dataset values are always strings

console.log(idFromPage === 2);
console.log(Number(idFromPage) === 2);
```

</CodeExample>

<Callout type="warning" title="Turn the id back into a number">

Our ids are **numbers**, but `dataset` always gives you **strings**. `tasks.find((task) => task.id === "2")` finds nothing, because `2 === "2"` is `false`. Always convert with `Number(event.target.dataset.id)` before you look the task up.

</Callout>

## Filtering the list

Filtering adds a second piece of **state**: which tasks the user wants to see. We'll store it in a variable called `filter`, which is `"all"`, `"active"` or `"done"`:

<CodeExample output={`[ 'Water the bamboo', 'Learn the DOM', 'Nap in the sun' ]
[ 'Water the bamboo', 'Nap in the sun' ]
[ 'Learn the DOM' ]`}>

```js
const tasks = [
  { id: 1, text: "Water the bamboo", done: false },
  { id: 2, text: "Learn the DOM", done: true },
  { id: 3, text: "Nap in the sun", done: false },
];
let filter = "all";

function visibleTasks() {
  if (filter === "active") return tasks.filter((t) => !t.done);
  if (filter === "done") return tasks.filter((t) => t.done);
  return tasks;
}

console.log(visibleTasks().map((t) => t.text));
filter = "active";
console.log(visibleTasks().map((t) => t.text));
filter = "done";
console.log(visibleTasks().map((t) => t.text));
```

</CodeExample>

(Don't mix up our `filter` **variable** with the array's `.filter()` **method**: they just share a name.)

`render()` then loops over `visibleTasks()` instead of `tasks`. The filter buttons are three ordinary buttons with a `data-filter` attribute. One delegated listener on their container sets `filter` and re-renders. To highlight the chosen button, `classList.toggle` takes an optional **second argument**: `true` means "add the class", `false` means "remove it".

function render() {
  filterButtons.forEach((button) => {
    const chosen = button.dataset.filter === filter;
    button.classList.toggle("active", chosen);
  });
  showing.textContent = \`Showing: \${filter} tasks\`;

  if (event.target.matches("button")) {
    filter = event.target.dataset.filter;
    render();
  }
});

render();`}
/>

<Callout type="tip" title="Filter what you show, not what you store">

Filtering must never **remove** tasks from `tasks`. The state keeps every task; `render()` just chooses which ones to draw. Switch back to **All** and they're all still there.

</Callout>

## Counting what's left

The footer shows how many tasks are still to do. It always counts **all** unfinished tasks, not just the visible ones, and it gets the grammar right for exactly one task:

<CodeExample output={`0 tasks left
1 task left
3 tasks left`}>

```js
function leftText(count) {
  const word = count === 1 ? "task" : "tasks";
  return `${count} ${word} left`;
}

console.log(leftText(0));
console.log(leftText(1));
console.log(leftText(3));
```

</CodeExample>

In the app, the count is `tasks.filter((task) => !task.done).length`, and `render()` updates `#count` with the text every time it runs. Because **every** change goes through `render()`, the counter can never get out of date.

## Clearing completed tasks

The last feature is the easiest. **Clear completed** keeps only the tasks that aren't done:

```js
function clearCompleted() {
  tasks = tasks.filter((task) => !task.done);
}
```

Then, as always, call `render()`.

Make the list interactive. The starter is your Part 1 app with a few new things selected for you, plus `let filter = "all";`.

1. **`toggleTask(id)`** flips `done` for the task with that id. **`deleteTask(id)`** removes it. **`clearCompleted()`** removes every finished task. (All three only change `tasks`.)
2. **`visibleTasks()`** returns the tasks that match `filter`: all of them for `"all"`, unfinished ones for `"active"`, finished ones for `"done"`.
3. In **`createTaskItem`**, put a checkbox (class `toggle`, ticked when the task is done) and the text `<span>` inside a `<label>`, then add a delete button (class `delete`, text `✕`). The checkbox and the button both get `data-id` set to the task's id.
4. In **`render()`**, draw only `visibleTasks()`, show `N tasks left` in `#count` (`1 task left` for exactly one, counting **all** unfinished tasks), and give the filter button whose `data-filter` matches `filter` the class `active` (and remove it from the others).
5. Add **one** click listener on the list: a click on a `.toggle` calls `toggleTask`, a click on a `.delete` calls `deleteTask`, then `render()`. Remember `Number()`!
6. A click on a button in **`#filters`** sets `filter` to its `data-filter` and renders. **Clear completed** calls `clearCompleted()` and renders.

  { id: 1, text: "Water the bamboo", done: false },

  const clean = text.trim();
  if (clean === "") return;

  tasks.push({ id: nextId, text: clean, done: false });
  nextId++;

function toggleTask(id) {
  const task = tasks.find((task) => task.id === id);
  if (task) {
    task.done = !task.done;
  }
}

function deleteTask(id) {
  tasks = tasks.filter((task) => task.id !== id);
}

function clearCompleted() {
  tasks = tasks.filter((task) => !task.done);
}

function visibleTasks() {
  if (filter === "active") return tasks.filter((t) => !t.done);
  if (filter === "done") return tasks.filter((t) => t.done);
  return tasks;
}

  const li = document.createElement("li");
  li.dataset.id = task.id;
  if (task.done) {
    li.classList.add("done");

  const label = document.createElement("label");
  const checkbox = document.createElement("input");
  checkbox.type = "checkbox";
  checkbox.className = "toggle";
  checkbox.checked = task.done;
  checkbox.dataset.id = task.id;

  const text = document.createElement("span");
  text.className = "text";
  text.textContent = task.text;
  label.append(checkbox, text);

  const remove = document.createElement("button");
  remove.className = "delete";
  remove.textContent = "✕";
  remove.dataset.id = task.id;

  li.append(label, remove);
  return li;
}

function render() {
  list.replaceChildren();
  visibleTasks().forEach((task) => {
    list.append(createTaskItem(task));
  });

  const left = tasks.filter((task) => !task.done).length;

  filterButtons.forEach((button) => {
    const chosen = button.dataset.filter === filter;
    button.classList.toggle("active", chosen);
  });
}

  event.preventDefault();

## What you built

- **`toggleTask`**, **`deleteTask`** and **`clearCompleted`** change the state with `find` and `filter`, and never touch the page.
- Each item has a **checkbox** inside a `<label>` and a **delete button**, both carrying the task's id in `data-id`.
- **One delegated listener** on the list handles every checkbox and delete button, including ones added later. `Number()` turns the `dataset` string back into an id.
- A **`filter`** state variable and **`visibleTasks()`** decide what `render()` draws, while `tasks` keeps everything.
- `render()` also keeps the **"N tasks left"** counter and the highlighted filter button up to date, so they can never go stale.

There's just one problem left: press **Run** again (which is like reloading the page) and all your new tasks are gone. In Part 3 you'll fix that with `localStorage`.
