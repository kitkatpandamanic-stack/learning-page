Добро пожаловать в итоговый проект уровня 1! За три части вы соберёте настоящее **приложение со списком дел (to-do app)**: в нём можно добавлять задачи, отмечать их выполненными, удалять, фильтровать и (самое приятное) оно **помнит ваши задачи** после перезагрузки страницы. 🐼📝

Вы примените почти всё из уровня 1: **массивы объектов** и методы массивов, **DOM** и **события (events)**, **паттерн отрисовки (render pattern)**, `dataset`, **JSON** и **try/catch**. Вот план:

- **Часть 1 (эта):** храним задачи в массиве, выводим их на страницу, добавляем новые через форму.
- **Часть 2:** отмечаем задачи выполненными, удаляем, фильтруем и считаем, сколько осталось.
- **Часть 3:** сохраняем всё в браузере с помощью `localStorage`, чтобы задачи переживали перезагрузку.

## План: состояние, затем отрисовка

Прежде чем писать код, решим, как будет работать приложение. Мы используем **паттерн отрисовки** из модуля «DOM и события»:

1. Все данные приложения живут в одной переменной — **состоянии (state)**: массиве задач.
2. Одна функция, **`render()`**, очищает список на странице и заново строит его по состоянию.
3. Когда пользователь что-то делает (отправляет форму, нажимает кнопку), мы **меняем состояние**, а затем вызываем `render()`.

```text
  пользователь что-то делает  ──▶  меняем состояние  ──▶  render()
          ▲                                                   │
          └──────────────── страница показывает состояние ◀───┘
```

Мы **никогда** не добавляем и не удаляем элементы `<li>` вручную. Если страница выглядит не так, искать нужно всего в двух местах: в состоянии или в `render()`. Именно это не даёт такому приложению превратиться в спагетти по мере роста.

## Задачи как объекты

Каждой задаче нужно несколько фрагментов информации, поэтому **объект (object)** подходит идеально:

- **`id`**: число, разное у каждой задачи, чтобы всегда можно было найти нужную.
- **`text`**: текст задачи.
- **`done`**: `true`, когда задача выполнена, и `false` до тех пор.

Всё состояние — это **массив (array)** таких объектов:

<CodeExample output={`Изучить DOM
2
[ 'Полить бамбук', 'Изучить DOM', 'Вздремнуть на солнышке' ]`}>

```js
const tasks = [
  { id: 1, text: "Полить бамбук", done: false },
  { id: 2, text: "Изучить DOM", done: true },
  { id: 3, text: "Вздремнуть на солнышке", done: false },
];

console.log(tasks[1].text);
console.log(tasks.filter((task) => !task.done).length);
console.log(tasks.map((task) => task.text));
```

</CodeExample>

С ним работают все знакомые вам методы массивов: `filter` — для невыполненных задач, `map` — чтобы получить только тексты, `find` — чтобы найти одну задачу. Все они пригодятся вам в части 2.

### Почему бы просто не использовать позицию?

Вы можете спросить, зачем вообще нужен `id`, если у каждой задачи и так есть индекс (`0`, `1`, `2`...). Проблема в том, что **индексы меняются**. Удалите первую задачу — и все остальные сдвинутся на одну позицию вверх. Покажите только невыполненные задачи — и позиции на странице перестанут совпадать с позициями в массиве. А `id` принадлежит самой задаче и **никогда не меняется**, поэтому всегда указывает на нужную.

## Добавляем задачи с уникальными id

Чтобы у каждой задачи был свой id, будем хранить **счётчик** в переменной. Новая задача берёт текущее число, а затем счётчик увеличивается на единицу:

<CodeExample output={`{ id: 1, text: 'Полить бамбук', done: false }
{ id: 2, text: 'Изучить DOM', done: false }
Задач: 2, следующий id: 3`}>

```js
const tasks = [];
let nextId = 1;

function addTask(text) {
  const clean = text.trim();
  if (clean === "") return;

  tasks.push({ id: nextId, text: clean, done: false });
  nextId++;
}

addTask("Полить бамбук");
addTask("   Изучить DOM   ");
addTask("     ");

tasks.forEach((task) => console.log(task));
console.log(`Задач: ${tasks.length}, следующий id: ${nextId}`);
```

</CodeExample>

Две мелочи делают приложение аккуратным:

- **`trim()`** убирает пробелы в начале и в конце, поэтому `"   Изучить DOM   "` сохраняется как `"Изучить DOM"`.
- Если после обрезки ничего не осталось, **`return`** досрочно завершает функцию, и пустые задачи игнорируются.

Заметьте: `addTask` меняет только **состояние**. Страницу она не трогает вообще. Рисовать — работа `render()`.

## Рисуем задачи

Теперь превратим состояние в страницу. Разделим работу на две функции:

- **`createTaskItem(task)`** создаёт и возвращает `<li>` для **одной** задачи.
- **`render()`** очищает список, а затем добавляет по одному элементу на каждую задачу.

Каждый `<li>` помнит id своей задачи в **data-атрибуте** (`li.dataset.id`). Пока он нам не нужен, но в части 2 именно по нему клик поймёт, к какой задаче он относится. Выполненные задачи получают класс `done`, чтобы CSS мог их зачеркнуть.

<TryIt

  code={`const list = document.querySelector("#task-list");

const tasks = [
  { id: 1, text: "Полить бамбук", done: false },
  { id: 2, text: "Изучить DOM", done: true },
  { id: 3, text: "Вздремнуть на солнышке", done: false },
];

function createTaskItem(task) {
  const li = document.createElement("li");
  li.dataset.id = task.id;
  if (task.done) {
    li.classList.add("done");
  }

  const text = document.createElement("span");
  text.className = "text";
  text.textContent = task.text;

  li.append(text);
  return li;
}

function render() {
  list.replaceChildren();
  tasks.forEach((task) => {
    list.append(createTaskItem(task));
  });
}

render();
console.log("Задач на странице:", list.children.length);`}

Поменяйте у первой задачи `done: false` на `done: true` и нажмите **«Запустить»**: страница следует за состоянием.

<Callout type="danger" title="Задачи — это ввод пользователя, поэтому используйте textContent">

Каждый текст задачи вводит пользователь. Если бы вы собирали элемент через `` li.innerHTML = `<span>${task.text}</span>` ``, кто-нибудь мог бы ввести в качестве задачи HTML (и даже скрипт), и он бы выполнился на странице. Создавать элементы и задавать им `textContent` всегда безопасно — поэтому `createTaskItem` делает именно так.

</Callout>

## Подключаем форму

Последний кусочек — форма. Рецепт вы уже знаете из урока про события:

1. Слушайте событие **`submit`** на `<form>` (оно срабатывает и на кнопку, и на нажатие Enter).
2. Вызовите **`event.preventDefault()`**, чтобы страница не перезагружалась.
3. **Измените состояние** с помощью `addTask(input.value)`.
4. Очистите поле ввода и вызовите **`render()`**.

```js
form.addEventListener("submit", (event) => {
  event.preventDefault();
  addTask(input.value);
  input.value = "";
  render();
});
```

И не забудьте вызвать `render()` в самом **конце** скрипта, чтобы начальные задачи отрисовались при загрузке страницы.

<Callout type="tip" title="Держите обязанности раздельно">

`addTask` меняет данные, `render` рисует страницу, а обработчик события (event listener) связывает их. У каждой функции **одна задача**. Когда что-то сломается, вы будете точно знать, куда смотреть: неправильные данные — значит `addTask`, неправильная страница — значит `render`.

</Callout>

## Что вы построили

- Понятный **план**: состояние живёт в одном массиве, `render()` его рисует, а каждое событие меняет состояние и затем вызывает отрисовку.
- Задачи — это **объекты** `{ id, text, done }` в массиве, а **счётчик** `nextId` даёт каждой уникальный id, который никогда не меняется.
- **`addTask(text)`** обрезает пробелы и игнорирует пустой ввод, не трогая страницу.
- **`createTaskItem(task)`** безопасно строит один `<li>` с помощью `createElement` и `textContent` и хранит id в `data-id`.
- **`render()`** заново строит весь список по состоянию, а обработчик **submit** связывает с этим форму.

В части 2 вы сделаете список интерактивным: задачи можно будет отмечать выполненными, удалять и фильтровать.
