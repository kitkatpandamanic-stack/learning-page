Колбэки работают, но они вкладываются друг в друга, заставляют проверять ошибки на каждом шаге, и приходится доверять чужому коду, что он вызовет их ровно один раз. **Промис (promise)** решает всё это. Это объект, который обозначает значение, которое **ещё не готово**. Он похож на пейджер, который вам выдают при заказе на фуд-корте: вы занимаетесь своими делами, а пейджер сообщит, когда еда готова (или что на кухне всё закончилось). Почти любое современное API, включая `fetch`, отдаёт вам промисы. 🤝

## Создаём промис

Промис всегда находится в одном из трёх состояний:

- **pending** (ожидание): всё ещё ждёт;
- **fulfilled** (выполнен): завершился успешно и получил **значение (value)**;
- **rejected** (отклонён): завершился неудачей с **причиной (reason)** — обычно это `Error`.

Когда промис выполнен или отклонён, говорят, что он **завершён (settled)**, и больше он уже никогда не меняется.

Промис создаётся с помощью `new Promise(executor)`. **Исполнитель (executor)** — это функция, которая получает две функции: `resolve` и `reject`. Она запускает медленную работу и вызывает `resolve(value)` при успехе или `reject(error)` при неудаче. Чтобы воспользоваться значением, передайте колбэк в `.then()`:

<CodeExample output={`Кухня: начинаем готовить пиццу
Получили промис, продолжаем
Доставлено: 🍕 Маргарита`}>

```js
const pizza = new Promise((resolve, reject) => {
  console.log("Кухня: начинаем готовить пиццу");
  setTimeout(() => {
    resolve("🍕 Маргарита");
  }, 100);
});

console.log("Получили промис, продолжаем");

pizza.then((food) => {
  console.log("Доставлено:", food);
});
```

</CodeExample>

Обратите внимание на порядок: исполнитель запускается **сразу**, пока промис создаётся. Ждёт значения только колбэк из `.then()`.

Промис завершается **только один раз**. Все вызовы `resolve` или `reject` после первого игнорируются, поэтому промис не может «перезвонить дважды», как это бывает с API на колбэках, в котором есть баг:

<CodeExample output="первый">

```js
const answer = new Promise((resolve, reject) => {
  resolve("первый");
  resolve("второй"); // игнорируется
  reject(new Error("слишком поздно")); // игнорируется
});

answer.then((value) => console.log(value));
```

</CodeExample>

Если вывести через `console.log` сам промис в консоли браузера, вы увидите его состояние, а не значение:

```js
console.log(pizza); // Promise {<pending>}
// ...через 100 мс:
console.log(pizza); // Promise {<fulfilled>: '🍕 Маргарита'}
```

Прочитать значение прямо из объекта промиса нельзя. Вы всегда получаете его через `.then()` (или через `await` — в следующем уроке).

## then, catch и finally

Чаще всего вы не создаёте промисы сами: их вам отдаёт какая-нибудь функция. А вы реагируете на них с помощью трёх методов:

- `.then(callback)` срабатывает, когда промис **выполнен**, и получает значение;
- `.catch(callback)` срабатывает, когда промис **отклонён**, и получает ошибку;
- `.finally(callback)` срабатывает в любом случае — идеально для уборки, например чтобы спрятать индикатор загрузки.

<CodeExample output={`Ваш заказ: 🍕 грибная пицца
Заказ закрыт
Извините: Пиццу с ананасом не делаем
Заказ закрыт`}>

```js
function orderPizza(topping) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (topping === "ананасовая") {
        reject(new Error("Пиццу с ананасом не делаем"));
      } else {
        resolve(`🍕 ${topping} пицца`);
      }
    }, 100);
  });
}

for (const topping of ["грибная", "ананасовая"]) {
  orderPizza(topping)
    .then((pizza) => console.log("Ваш заказ:", pizza))
    .catch((error) => console.log("Извините:", error.message))
    .finally(() => console.log("Заказ закрыт"));
}
```

</CodeExample>

Оба заказа стартуют в один и тот же момент и завершаются через 100 мс. Цикл не ждёт первую пиццу, прежде чем заказать вторую.

## Промисификация setTimeout

`setTimeout` работает на колбэках. Обернуть API на колбэках в промис — это называется **промисификацией (promisifying)**, и `setTimeout` — классический первый пример. Этот крошечный помощник `wait` настолько удобен, что вы встретите его во многих проектах:

<CodeExample output={`Ждём...
Прошло 50 мс
Прошло 100 мс`}>

```js
function wait(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

console.log("Ждём...");
wait(50).then(() => console.log("Прошло 50 мс"));
wait(100).then(() => console.log("Прошло 100 мс"));
```

</CodeExample>

`resolve` передаётся прямо в `setTimeout`, поэтому таймер выполняет промис, когда срабатывает. Значение при этом `undefined`, но здесь нам важно только *когда*.

Для значений, которые у вас уже есть, есть два сокращения: `Promise.resolve(value)` создаёт уже выполненный промис, а `Promise.reject(error)` — уже отклонённый. Они пригодятся в тестах и тогда, когда функция обязана всегда возвращать промис.

## Цепочки

Вот трюк, благодаря которому промисы намного приятнее колбэков: **`.then()` возвращает новый промис**, который выполняется с тем значением, которое вернул ваш колбэк. Поэтому к нему можно прицепить следующий `.then()` и так далее. Это называется **цепочкой промисов (promise chain)**:

<CodeExample output="21">

```js
Promise.resolve(2)
  .then((n) => n * 10) // 20
  .then((n) => n + 1) // 21
  .then((n) => console.log(n));
```

</CodeExample>

Если колбэк возвращает **промис**, цепочка ждёт этот промис и передаёт его значение дальше. Так асинхронные шаги выполняются один за другим. Вот пример с адом колбэков из прошлого урока, переписанный на промисах:

<CodeExample output={`Получен пользователь Mei
Получено постов: 2
Лайков у поста "Бамбук": 42`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// Ненастоящие серверные функции, теперь они возвращают промисы
const getUser = (id) => wait(50).then(() => ({ id, name: "Mei" }));
const getPosts = (user) => wait(50).then(() => ["Бамбук", "Сон"]);
const getLikes = (post) => wait(50).then(() => 42);

getUser(1)
  .then((user) => {
    console.log("Получен пользователь", user.name);
    return getPosts(user);
  })
  .then((posts) => {
    console.log(`Получено постов: ${posts.length}`);
    return getLikes(posts[0]);
  })
  .then((likes) => console.log(`Лайков у поста "Бамбук": ${likes}`))
  .catch((error) => console.log("Не удалось:", error.message));
```

</CodeExample>

Код остаётся **плоским**, сколько бы шагов ни было, а один `.catch()` в конце обрабатывает ошибки всех шагов.

<Callout type="warning" title="Возвращайте значение из then">

Если ваш колбэк в `.then()` запускает ещё один асинхронный шаг, **верните** его промис через `return`. Без `return` колбэк вернёт `undefined`, и следующий шаг выполнится сразу, ничего не дожидаясь:

```js
getUser(1)
  .then((user) => {
    getPosts(user); // ❌ нет return
  })
  .then((posts) => console.log(posts)); // undefined
```

В стрелочной функции без фигурных скобок, `(user) => getPosts(user)`, значение возвращается автоматически.

</Callout>

## Ошибки идут вниз по цепочке

Отклонение пропускает все `.then()`, пока не дойдёт до `.catch()`. А внутри любого колбэка `throw` работает так же, как отклонение: промис, который вернул этот `.then()`, отклоняется с этой ошибкой. Кроме того, `.catch()` может **восстановиться**, вернув значение, и цепочка продолжится уже с него:

<CodeExample output={`Шаг 1
Перехвачено: Шаг 2 сломался
Продолжаем: настройки по умолчанию`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

wait(50)
  .then(() => {
    console.log("Шаг 1");
    throw new Error("Шаг 2 сломался");
  })
  .then(() => console.log("Шаг 3")) // пропускается
  .catch((error) => {
    console.log("Перехвачено:", error.message);
    return "настройки по умолчанию";
  })
  .then((value) => console.log("Продолжаем:", value));
```

</CodeExample>

Всё как с `try/catch`: ошибка перепрыгивает через оставшуюся часть «try» и попадает в ближайший «catch».

<Callout type="danger" title="Всегда обрабатывайте отклонения">

Отклонённый промис, у которого нигде нет `.catch()`, — это **необработанное отклонение (unhandled rejection)**. Браузер выведет в консоль красную ошибку, а Node.js остановит всю программу:

```text
Uncaught (in promise) Error: Пиццу с ананасом не делаем
```

Либо заканчивайте каждую цепочку `.catch()`, либо **возвращайте** промис через `return`, чтобы его обработал код, который вызвал вашу функцию.

</Callout>

## Запускаем промисы вместе

Часто у вас есть несколько независимых задач: загрузить профиль, фотографии и список друзей. Незачем ждать окончания одной, чтобы начать следующую. Запустите их все, а потом объедините их промисы. В примерах ниже `download` и `failingDownload` делают вид, что общаются с сервером:

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

const download = (name, ms) =>
  wait(ms).then(() => `${name} (${ms} мс)`);

const failingDownload = (name, ms) =>
  wait(ms).then(() => {
    throw new Error(`Не удалось загрузить ${name}`);
  });
```

### Promise.all: ждём их все

`Promise.all(promises)` выполняется с **массивом всех значений** в том же порядке, в каком вы передали промисы (а не в том, в каком они завершились):

<CodeExample output={`[ 'профиль (80 мс)', 'фото (40 мс)', 'друзья (60 мс)' ]`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const download = (name, ms) =>
  wait(ms).then(() => `${name} (${ms} мс)`);

Promise.all([
  download("профиль", 80),
  download("фото", 40),
  download("друзья", 60),
]).then((results) => console.log(results));
```

</CodeExample>

Все три загрузки идут **одновременно**, поэтому всё вместе занимает около 80 мс (столько, сколько самая медленная), а не 40 + 60 + 80 = 180 мс.

Но если **любой** промис отклоняется, `Promise.all` сразу отклоняется с этой ошибкой, а остальные результаты выбрасываются:

<CodeExample output="Ошибка: Не удалось загрузить фото">

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const download = (name, ms) =>
  wait(ms).then(() => `${name} (${ms} мс)`);
const failingDownload = (name, ms) =>
  wait(ms).then(() => {
    throw new Error(`Не удалось загрузить ${name}`);
  });

Promise.all([download("профиль", 80), failingDownload("фото", 40)])
  .then((results) => console.log(results))
  .catch((error) => console.log("Ошибка:", error.message));
```

</CodeExample>

### Promise.allSettled: ждём все и сохраняем каждый результат

Когда некоторые неудачи допустимы (показать загрузившиеся фото и пропустить сломанные), используйте `Promise.allSettled`. Он никогда не отклоняется. Он отдаёт по одному объекту на каждый промис, где `status` равен `"fulfilled"` (и есть `value`) или `"rejected"` (и есть `reason`):

<CodeExample output={`✅ профиль (80 мс)
❌ Не удалось загрузить фото
✅ друзья (60 мс)`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const download = (name, ms) =>
  wait(ms).then(() => `${name} (${ms} мс)`);
const failingDownload = (name, ms) =>
  wait(ms).then(() => {
    throw new Error(`Не удалось загрузить ${name}`);
  });

Promise.allSettled([
  download("профиль", 80),
  failingDownload("фото", 40),
  download("друзья", 60),
]).then((results) => {
  for (const result of results) {
    if (result.status === "fulfilled") {
      console.log("✅", result.value);
    } else {
      console.log("❌", result.reason.message);
    }
  }
});
```

</CodeExample>

### Promise.race и Promise.any: побеждает первый

`Promise.race` завершается так же, как **первый завершившийся промис**, — неважно, успешно или нет. `Promise.any` ждёт **первого успеха** и не обращает внимания на неудачи (он отклоняется с `AggregateError`, только если неудачей завершились все промисы):

<CodeExample output={`race: Не удалось загрузить зеркало A
any: зеркало B (50 мс)`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const download = (name, ms) =>
  wait(ms).then(() => `${name} (${ms} мс)`);
const failingDownload = (name, ms) =>
  wait(ms).then(() => {
    throw new Error(`Не удалось загрузить ${name}`);
  });

const mirrors = () => [
  failingDownload("зеркало A", 20),
  download("зеркало B", 50),
];

Promise.race(mirrors())
  .then((value) => console.log("race:", value))
  .catch((error) => console.log("race:", error.message));

Promise.any(mirrors())
  .then((value) => console.log("any:", value))
  .catch((error) => console.log("any:", error.message));
```

</CodeExample>

Зеркало A ломается первым, поэтому `race` отклоняется. А `any` не обращает на это внимания и дожидается зеркала B. Классическое применение `race` — **тайм-аут (timeout)**: устроить гонку между настоящей работой и таймером, который отклоняется. Именно это вы и напишете в упражнении.

| Метод                    | Выполняется, когда…           | Отклоняется, когда…              |
| ------------------------ | ----------------------------- | -------------------------------- |
| `Promise.all(list)`      | выполнены все (массив значений) | отклонился первый               |
| `Promise.allSettled(list)` | завершены все (массив `{ status, ... }`) | никогда                 |
| `Promise.race(list)`     | первый завершившийся выполнен | первый завершившийся отклонён    |
| `Promise.any(list)`      | выполнился первый             | отклонены все (`AggregateError`) |

Виджет погоды запрашивает прогноз у сервера, но некоторые серверы мучительно медленные. Вместо того чтобы вечно крутить индикатор загрузки, виджет должен через какое-то время сдаться. Напишите два помощника, используя промисы с `.then()`/`.catch()`:

1. `wait(ms)` возвращает промис, который выполняется через `ms` миллисекунд.
2. `withTimeout(promise, ms)` возвращает новый промис, который:
   - выполняется с тем же значением, если `promise` выполнился за `ms` миллисекунд;
   - отклоняется с той же ошибкой, если `promise` за это время отклонился;
   - иначе отклоняется с ``new Error(`Время ожидания истекло: ${ms} мс`)``, например `Время ожидания истекло: 50 мс`.

Код внизу пробует оба сервера. Когда вы закончите, он выведет погоду от быстрого сервера и сообщение о тайм-ауте для медленного.

<Hint>

`wait` — это помощник из урока: `new Promise((resolve) => setTimeout(resolve, ms))`. Для `withTimeout` создайте второй промис, который отклоняется через `ms` миллисекунд (например, `wait(ms).then(() => { throw new Error(...); })`), а затем верните `Promise.race([promise, thatTimer])`. Кто завершится первым, тот и победил.

</Hint>

<Solution>

```js
function wait(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

function withTimeout(promise, ms) {
  const timer = wait(ms).then(() => {
    throw new Error(`Время ожидания истекло: ${ms} мс`);
  });
  return Promise.race([promise, timer]);
}

const fastServer = wait(20).then(() => "Солнечно");
const slowServer = wait(150).then(() => "Дождь");

withTimeout(fastServer, 100)
  .then((weather) => console.log("Быстрый сервер:", weather))
  .catch((error) => console.log("Быстрый сервер:", error.message));

withTimeout(slowServer, 50)
  .then((weather) => console.log("Медленный сервер:", weather))
  .catch((error) => console.log("Медленный сервер:", error.message));
```

## Итоги

- **Промис** обозначает значение, которое придёт позже. Сначала он в состоянии **pending**, а затем один раз завершается: **выполняется** (fulfilled) со значением или **отклоняется** (rejected) с ошибкой.
- `new Promise((resolve, reject) => { ... })` создаёт промис; исполнитель запускается сразу. Такая обёртка над API на колбэках называется **промисификацией**, например `wait(ms)`.
- `.then()` получает значение, `.catch()` — ошибку, а `.finally()` выполняется в любом случае.
- `.then()` возвращает новый промис, поэтому шаги можно связывать в **цепочку**. Возвращайте значения (или промисы), чтобы передать их дальше по цепочке.
- Выброшенная ошибка или отклонение перескакивает к ближайшему `.catch()`, который может восстановиться. Всегда обрабатывайте отклонения.
- `Promise.all` (все должны выполниться успешно), `allSettled` (каждый результат), `race` (первый завершившийся) и `any` (первый успех) запускают задачи **одновременно**.
