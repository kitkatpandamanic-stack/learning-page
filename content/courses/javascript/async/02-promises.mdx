Callbacks work, but they nest, they make you check for errors at every step, and you have to trust other code to call them exactly once. A **promise** solves all of that. It's an object that stands for a value that **isn't ready yet**, like the buzzer you get when you order at a food court: you can carry on with your day, and the buzzer tells you when your food is ready (or that the kitchen ran out). Almost every modern API, including `fetch`, gives you promises. 🤝

## Creating a promise

A promise is always in one of three states:

- **pending**: still waiting;
- **fulfilled**: finished successfully, with a **value**;
- **rejected**: failed, with a **reason** (usually an `Error`).

Once a promise is fulfilled or rejected, we say it's **settled**, and it never changes again.

You create one with `new Promise(executor)`. The **executor** is a function that receives two functions, `resolve` and `reject`. It starts the slow work and calls `resolve(value)` when it succeeds or `reject(error)` when it fails. To use the value, pass a callback to `.then()`:

<CodeExample output={`Kitchen: starting the pizza
Got a promise, carrying on
Delivered: 🍕 Margherita`}>

```js
const pizza = new Promise((resolve, reject) => {
  console.log("Kitchen: starting the pizza");
  setTimeout(() => {
    resolve("🍕 Margherita");
  }, 100);
});

console.log("Got a promise, carrying on");

pizza.then((food) => {
  console.log("Delivered:", food);
});
```

</CodeExample>

Notice the order: the executor runs **immediately**, while the promise is being created. Only the `.then()` callback waits for the value.

A promise settles **only once**. Every `resolve` or `reject` after the first is ignored, so a promise can't "call you back twice" the way a buggy callback API can:

<CodeExample output="first">

```js
const answer = new Promise((resolve, reject) => {
  resolve("first");
  resolve("second"); // ignored
  reject(new Error("too late")); // ignored
});

answer.then((value) => console.log(value));
```

</CodeExample>

If you `console.log` a promise itself in the browser console, you see its state rather than its value:

```js
console.log(pizza); // Promise {<pending>}
// ...100 ms later:
console.log(pizza); // Promise {<fulfilled>: '🍕 Margherita'}
```

You can't read the value straight off the promise object. You always get it through `.then()` (or `await`, next lesson).

## then, catch and finally

Most of the time you don't create promises yourself: a function gives you one. You react to it with three methods:

- `.then(callback)` runs when the promise is **fulfilled** and receives the value;
- `.catch(callback)` runs when it's **rejected** and receives the error;
- `.finally(callback)` runs either way, which is perfect for clean-up like hiding a loading spinner.

<CodeExample output={`Enjoy your 🍕 mushroom pizza
Order closed
Sorry: We don't do pineapple
Order closed`}>

```js
function orderPizza(topping) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (topping === "pineapple") {
        reject(new Error("We don't do pineapple"));
      } else {
        resolve(`🍕 ${topping} pizza`);
      }
    }, 100);
  });
}

for (const topping of ["mushroom", "pineapple"]) {
  orderPizza(topping)
    .then((pizza) => console.log("Enjoy your", pizza))
    .catch((error) => console.log("Sorry:", error.message))
    .finally(() => console.log("Order closed"));
}
```

</CodeExample>

Both orders start at the same moment and finish 100 ms later. The loop doesn't wait for the first pizza before ordering the second.

## Promisifying setTimeout

`setTimeout` is callback-based. Wrapping a callback API in a promise is called **promisifying** it, and `setTimeout` is the classic first example. This tiny `wait` helper is so handy that you'll see it in many projects:

<CodeExample output={`Waiting...
50 ms later
100 ms later`}>

```js
function wait(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

console.log("Waiting...");
wait(50).then(() => console.log("50 ms later"));
wait(100).then(() => console.log("100 ms later"));
```

</CodeExample>

`resolve` is passed straight to `setTimeout`, so the timer fulfils the promise when it fires. The value is `undefined`, but here we only care about *when*.

For values you already have, there are two shortcuts: `Promise.resolve(value)` makes an already-fulfilled promise, and `Promise.reject(error)` an already-rejected one. They're useful in tests and when a function must always return a promise.

## Chaining

Here's the trick that makes promises so much nicer than callbacks: **`.then()` returns a new promise**, which is fulfilled with whatever your callback returns. So you can attach the next `.then()` to it, and so on. That's a **promise chain**:

<CodeExample output="21">

```js
Promise.resolve(2)
  .then((n) => n * 10) // 20
  .then((n) => n + 1) // 21
  .then((n) => console.log(n));
```

</CodeExample>

If a callback returns a **promise**, the chain waits for that promise and passes its value on. That's how you run async steps one after another. Here's the callback hell example from the last lesson, rewritten with promises:

<CodeExample output={`Got user Mei
Got 2 posts
"Bamboo" has 42 likes`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// Pretend server functions that now return promises
const getUser = (id) => wait(50).then(() => ({ id, name: "Mei" }));
const getPosts = (user) => wait(50).then(() => ["Bamboo", "Naps"]);
const getLikes = (post) => wait(50).then(() => 42);

getUser(1)
  .then((user) => {
    console.log("Got user", user.name);
    return getPosts(user);
  })
  .then((posts) => {
    console.log(`Got ${posts.length} posts`);
    return getLikes(posts[0]);
  })
  .then((likes) => console.log(`"Bamboo" has ${likes} likes`))
  .catch((error) => console.log("Failed:", error.message));
```

</CodeExample>

The code stays **flat** no matter how many steps there are, and one `.catch()` at the end handles errors from every step.

<Callout type="warning" title="Return from then">

If your `.then()` callback starts another async step, **return** its promise. Without `return`, the callback gives back `undefined`, and the next step runs immediately without waiting:

```js
getUser(1)
  .then((user) => {
    getPosts(user); // ❌ no return
  })
  .then((posts) => console.log(posts)); // undefined
```

With an arrow function and no curly braces, `(user) => getPosts(user)`, the return is automatic.

</Callout>

## Errors travel down the chain

A rejection skips every `.then()` until it reaches a `.catch()`. And inside any callback, `throw` works just like rejecting: the promise returned by that `.then()` is rejected with the error. A `.catch()` can also **recover** by returning a value, and the chain carries on from there:

<CodeExample output={`Step 1
Caught: Step 2 broke
Carrying on with default settings`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

wait(50)
  .then(() => {
    console.log("Step 1");
    throw new Error("Step 2 broke");
  })
  .then(() => console.log("Step 3")) // skipped
  .catch((error) => {
    console.log("Caught:", error.message);
    return "default settings";
  })
  .then((value) => console.log("Carrying on with", value));
```

</CodeExample>

This is just like `try/catch`: the error jumps over the rest of the "try" part and lands in the nearest "catch".

<Callout type="danger" title="Always handle rejections">

A rejected promise with no `.catch()` anywhere is an **unhandled rejection**. The browser prints a red error in the console, and Node.js stops the whole program:

```text
Uncaught (in promise) Error: We don't do pineapple
```

Either end every chain with `.catch()`, or **return** the promise so the code that called you can handle it.

</Callout>

## Running promises together

Often you have several independent tasks: load the profile, the photos and the friends list. There's no need to wait for one before starting the next. Start them all, then combine their promises. For the examples below, `download` and `failingDownload` pretend to talk to a server:

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

const download = (name, ms) =>
  wait(ms).then(() => `${name} (${ms} ms)`);

const failingDownload = (name, ms) =>
  wait(ms).then(() => {
    throw new Error(`${name} failed`);
  });
```

### Promise.all: wait for all of them

`Promise.all(promises)` is fulfilled with an **array of all the values**, in the same order as the promises you passed in (not the order in which they finished):

<CodeExample output={`[ 'profile (80 ms)', 'photos (40 ms)', 'friends (60 ms)' ]`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const download = (name, ms) =>
  wait(ms).then(() => `${name} (${ms} ms)`);

Promise.all([
  download("profile", 80),
  download("photos", 40),
  download("friends", 60),
]).then((results) => console.log(results));
```

</CodeExample>

All three downloads run **at the same time**, so the whole thing takes about 80 ms (the slowest one), not 40 + 60 + 80 = 180 ms.

But if **any** promise rejects, `Promise.all` rejects straight away with that error, and the other results are thrown away:

<CodeExample output="Failed: photos failed">

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const download = (name, ms) =>
  wait(ms).then(() => `${name} (${ms} ms)`);
const failingDownload = (name, ms) =>
  wait(ms).then(() => {
    throw new Error(`${name} failed`);
  });

Promise.all([download("profile", 80), failingDownload("photos", 40)])
  .then((results) => console.log(results))
  .catch((error) => console.log("Failed:", error.message));
```

</CodeExample>

### Promise.allSettled: wait for all, keep every result

When some failures are fine (show the photos that loaded, skip the broken ones), use `Promise.allSettled`. It never rejects. It gives you one object per promise, with `status` set to `"fulfilled"` (plus `value`) or `"rejected"` (plus `reason`):

<CodeExample output={`✅ profile (80 ms)
❌ photos failed
✅ friends (60 ms)`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const download = (name, ms) =>
  wait(ms).then(() => `${name} (${ms} ms)`);
const failingDownload = (name, ms) =>
  wait(ms).then(() => {
    throw new Error(`${name} failed`);
  });

Promise.allSettled([
  download("profile", 80),
  failingDownload("photos", 40),
  download("friends", 60),
]).then((results) => {
  for (const result of results) {
    if (result.status === "fulfilled") {
      console.log("✅", result.value);
    } else {
      console.log("❌", result.reason.message);
    }
  }
});
```

</CodeExample>

### Promise.race and Promise.any: the first one wins

`Promise.race` settles like the **first promise to settle**, whether it succeeded or failed. `Promise.any` waits for the **first success** and ignores failures (it only rejects, with an `AggregateError`, if every promise fails):

<CodeExample output={`race: mirror A failed
any: mirror B (50 ms)`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const download = (name, ms) =>
  wait(ms).then(() => `${name} (${ms} ms)`);
const failingDownload = (name, ms) =>
  wait(ms).then(() => {
    throw new Error(`${name} failed`);
  });

const mirrors = () => [
  failingDownload("mirror A", 20),
  download("mirror B", 50),
];

Promise.race(mirrors())
  .then((value) => console.log("race:", value))
  .catch((error) => console.log("race:", error.message));

Promise.any(mirrors())
  .then((value) => console.log("any:", value))
  .catch((error) => console.log("any:", error.message));
```

</CodeExample>

Mirror A fails first, so `race` rejects. `any` shrugs that off and waits for mirror B. A classic use of `race` is a **timeout**: race the real work against a timer that rejects. You'll build exactly that in the exercise.

| Method                   | Fulfils when…                 | Rejects when…                    |
| ------------------------ | ----------------------------- | -------------------------------- |
| `Promise.all(list)`      | all fulfil (array of values)  | the first one rejects            |
| `Promise.allSettled(list)` | all have settled (array of `{ status, ... }`) | never                |
| `Promise.race(list)`     | the first to settle fulfils   | the first to settle rejects      |
| `Promise.any(list)`      | the first one fulfils         | all reject (`AggregateError`)    |

A weather widget asks a server for the forecast, but some servers are painfully slow. Rather than show a spinner forever, the widget should give up after a while. Write two helpers, using promises with `.then()`/`.catch()`:

1. `wait(ms)` returns a promise that fulfils after `ms` milliseconds.
2. `withTimeout(promise, ms)` returns a new promise that:
   - fulfils with the same value if `promise` fulfils within `ms` milliseconds;
   - rejects with the same error if `promise` rejects within that time;
   - otherwise rejects with ``new Error(`Timed out after ${ms} ms`)``, for example `Timed out after 50 ms`.

The code at the bottom tries both servers. When you're done, it prints the fast server's weather and a timeout message for the slow one.

<Hint>

`wait` is the helper from the lesson: `new Promise((resolve) => setTimeout(resolve, ms))`. For `withTimeout`, make a second promise that rejects after `ms` milliseconds (for example `wait(ms).then(() => { throw new Error(...); })`), then return `Promise.race([promise, thatTimer])`. Whichever settles first wins.

```js
function wait(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

function withTimeout(promise, ms) {
  const timer = wait(ms).then(() => {
    throw new Error(`Timed out after ${ms} ms`);
  });
  return Promise.race([promise, timer]);
}

const fastServer = wait(20).then(() => "Sunny");
const slowServer = wait(150).then(() => "Rain");

withTimeout(fastServer, 100)
  .then((weather) => console.log("Fast server:", weather))
  .catch((error) => console.log("Fast server:", error.message));

withTimeout(slowServer, 50)
  .then((weather) => console.log("Slow server:", weather))
  .catch((error) => console.log("Slow server:", error.message));
```

## Recap

- A **promise** stands for a value that arrives later. It's **pending**, then settles once: **fulfilled** with a value or **rejected** with an error.
- `new Promise((resolve, reject) => { ... })` creates one; the executor runs immediately. Wrapping a callback API like this is called **promisifying** it, e.g. `wait(ms)`.
- `.then()` gets the value, `.catch()` the error, and `.finally()` runs either way.
- `.then()` returns a new promise, so you can **chain** steps. Return values (or promises) to pass them down the chain.
- A thrown error or rejection skips to the next `.catch()`, which can recover. Always handle rejections.
- `Promise.all` (all must succeed), `allSettled` (every result), `race` (first to settle) and `any` (first success) run tasks **at the same time**.
