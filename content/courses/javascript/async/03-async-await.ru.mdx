Цепочки промисов плоские, но в них всё равно полно маленьких колбэков, а передавать значения с одного шага на более поздний неудобно. **`async` и `await`** позволяют писать асинхронный код, который читается сверху вниз, как самый обычный код. Они построены на промисах, так что всё из [прошлого урока](/learn/javascript/promises) по-прежнему в силе; по сути, это просто более приятный способ это записать. Именно так написана большая часть JavaScript-кода, который вы будете читать на работе. ✨

## Асинхронные функции

Поставьте ключевое слово `async` перед функцией, и она **всегда будет возвращать промис**. Если функция возвращает значение, промис выполняется с этим значением. Если функция выбрасывает ошибку, промис отклоняется:

<CodeExample output={`true
Привет!
Упс`}>

```js
async function getGreeting() {
  return "Привет!";
}

const failing = async () => {
  throw new Error("Упс");
};

const result = getGreeting();
console.log(result instanceof Promise);
result.then((value) => console.log(value));

failing().catch((error) => console.log(error.message));
```

</CodeExample>

`async` работает с любыми функциями: с объявлениями функций, стрелочными функциями (`async () => {}`) и методами классов (`async load() {}`).

## await

Внутри `async`-функции **`await`** ставит функцию на паузу, пока промис не завершится, а затем отдаёт вам его значение. Никаких `.then()` не нужно:

<CodeExample output={`Кипятим воду...
А пока читаем новости
Завариваем чай...
Готово: 🍵 Зелёный чай`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function makeTea() {
  console.log("Кипятим воду...");
  await wait(100);
  console.log("Завариваем чай...");
  await wait(50);
  return "🍵 Зелёный чай";
}

makeTea().then((tea) => console.log("Готово:", tea));
console.log("А пока читаем новости");
```

</CodeExample>

Посмотрите на порядок. `await` ставит на паузу **только `makeTea`**, а не всю программу. Пока функция ждёт, цикл событий может выполнять другой код — поэтому новости прочитаны раньше, чем заварился чай. Когда промис завершается, функция продолжает с того места, где остановилась. За кулисами всё, что идёт после `await`, работает как колбэк в `.then()`.

Вот ещё раз пример из трёх шагов из двух прошлых уроков. Сравните его с пирамидой колбэков:

<CodeExample output={`Пост "Бамбук" (Mei) — лайков: 42`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

const getUser = (id) => wait(50).then(() => ({ id, name: "Mei" }));
const getPosts = (user) => wait(50).then(() => ["Бамбук", "Сон"]);
const getLikes = (post) => wait(50).then(() => 42);

async function showLikes(userId) {
  const user = await getUser(userId);
  const posts = await getPosts(user);
  const likes = await getLikes(posts[0]);
  console.log(`Пост "${posts[0]}" (${user.name}) — лайков: ${likes}`);
}

showLikes(1);
```

</CodeExample>

Каждый результат попадает в обычную переменную, и `user` по-прежнему доступен в последней строке. Ни вложенности, ни цепочки.

<Callout type="note" title="await нужна async-функция">

`await` работает только внутри `async`-функции (или на верхнем уровне модуля — об этом ниже). Внутри обычной функции это `SyntaxError`:

```js
function load() {
  const data = await getData(); // ❌ SyntaxError
}
```

</Callout>

## Ошибки: try, catch и finally

Когда промис, которого вы ждёте через `await`, **отклоняется**, `await` **выбрасывает** ошибку. Поэтому асинхронные ошибки обрабатываются тем же `try/catch/finally`, который вы уже знаете:

<CodeExample output={`⏳ Загрузка Mei...
У Mei уровень 7
Индикатор загрузки скрыт
⏳ Загрузка Zed...
❌ Нет профиля для Zed
Индикатор загрузки скрыт`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function loadProfile(name) {
  await wait(50);
  if (name !== "Mei") {
    throw new Error(`Нет профиля для ${name}`);
  }
  return { name, level: 7 };
}

async function showProfile(name) {
  console.log(`⏳ Загрузка ${name}...`);
  try {
    const profile = await loadProfile(name);
    console.log(`У ${profile.name} уровень ${profile.level}`);
  } catch (error) {
    console.log("❌", error.message);
  } finally {
    console.log("Индикатор загрузки скрыт");
  }
}

await showProfile("Mei");
await showProfile("Zed");
```

</CodeExample>

Этот шаблон вы будете писать снова и снова в настоящих приложениях: показать состояние загрузки, выполнить запрос в `try`, показать данные или сообщение об ошибке и прибраться в `finally`.

Если `async`-функция не перехватывает ошибку, её промис отклоняется, и разбираться с этим приходится вызывающему коду: либо своим `try/catch` вокруг `await`, либо через `.catch()`.

## Общаемся с API

Ждать таймер полезно для обучения, но настоящая причина существования асинхронного кода — это сеть. В PandaDev встроено учебное API, поэтому эти уроки работают без интернета и всегда дают одни и те же ответы. Настоящие API работают точно так же.

Браузерная функция **`fetch(url)`** отправляет запрос (request) и возвращает промис **ответа (response)**. Чтение тела ответа как JSON через `res.json()` — это второй промис, поэтому здесь два `await`:

<CodeExample output={`200
{ id: 1, name: 'Mei Lin', username: 'mei', email: 'mei@pandadev.test' }
Sam Ortiz <sam@pandadev.test>`}>

```js
const API = "https://api.pandadev.test";

async function getUser(id) {
  const res = await fetch(`${API}/users/${id}`);
  console.log(res.status);
  return res.json();
}

const mei = await getUser(1);
console.log(mei);

const sam = await (await fetch(`${API}/users/2`)).json();
console.log(`${sam.name} <${sam.email}>`);
```

</CodeExample>

`200` — это HTTP-**код ответа (status code)**, означающий «OK». Всё о `fetch`, кодах ответа и обработке ошибок вы узнаете в следующем модуле. А пока это просто функция, которая возвращает промис, — такая же, как те, что вы уже писали. Настоящему API обычно нужен ещё ключ и другой адрес, но форма кода та же:

```js
const res = await fetch("https://api.example.com/v1/users/1", {
  headers: { Authorization: "Bearer YOUR_API_KEY" },
});
const user = await res.json();
```

## По очереди или все сразу?

Каждый `await` дожидается своего промиса, прежде чем выполнится следующая строка. Это ровно то, что нужно, когда шагу **нужен результат** предыдущего шага. Но когда задачи друг от друга не зависят, ждать их по одной — пустая трата времени. Вместо этого запустите их все и ждите через `Promise.all`:

<CodeExample output={`По очереди:
  начало: фото
  готово: фото
  начало: музыка
  готово: музыка
Одновременно:
  начало: фото
  начало: музыка
  готово: музыка
  готово: фото`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function download(name, ms) {
  console.log(`  начало: ${name}`);
  await wait(ms);
  console.log(`  готово: ${name}`);
  return name;
}

console.log("По очереди:");
await download("фото", 60);
await download("музыка", 40);

console.log("Одновременно:");
await Promise.all([download("фото", 60), download("музыка", 40)]);
```

</CodeExample>

По очереди это занимает 60 + 40 = 100 мс. Одновременно — ровно столько, сколько самая медленная задача, 60 мс. С настоящими запросами, каждый из которых длится полсекунды, это разница между шустрой страницей и тормозящей.

Простое правило:

- **Последовательно** (`await`, `await`): когда шагу 2 нужен результат шага 1, например *войти в систему, а потом загрузить мои заказы*.
- **Параллельно** (`await Promise.all([...])`): когда задачи независимы, например *загрузить профиль, друзей и уведомления*.

<Callout type="tip" title="Остерегайтесь случайных водопадов">

```js
const profile = await getProfile(id);
const friends = await getFriends(id); // не нужно было ждать profile!
```

Такой код легко написать, и он незаметно тормозит: второй запрос стартует только после того, как закончился первый. Если ни одна строка не использует результат другой, пишите `const [profile, friends] = await Promise.all([getProfile(id), getFriends(id)]);`. Деструктуризация массива даёт каждому результату своё имя.

</Callout>

## Циклы с await

`await` можно использовать внутри цикла `for...of`. Каждый проход ждёт предыдущего, поэтому элементы обрабатываются **по одному, по порядку**. Для **параллельной** работы превратите элементы в промисы через `map` и дождитесь их всех с помощью `Promise.all`:

<CodeExample output={`Сохранено: заметки
Сохранено: фото
Всё сохранено, по одному
Сохранено: музыка
Сохранено: видео
Всё сохранено, одновременно
[ 'Mei Lin', 'Sam Ortiz', 'Ada Brooks' ]`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function save(item) {
  await wait(50);
  console.log("Сохранено:", item);
}

async function saveInOrder(items) {
  for (const item of items) {
    await save(item); // ждём, прежде чем начать следующий проход
  }
  console.log("Всё сохранено, по одному");
}

async function saveAtOnce(items) {
  await Promise.all(items.map((item) => save(item)));
  console.log("Всё сохранено, одновременно");
}

await saveInOrder(["заметки", "фото"]);
await saveAtOnce(["музыка", "видео"]);

// Та же идея с учебным API
const API = "https://api.pandadev.test";
const getUser = async (id) => (await fetch(`${API}/users/${id}`)).json();
const users = await Promise.all([1, 2, 3].map((id) => getUser(id)));
console.log(users.map((user) => user.name));
```

</CodeExample>

`Promise.all` сохраняет результаты в том же порядке, что и id, даже если ответы приходят в другом порядке.

<Callout type="danger" title="forEach не ждёт">

`forEach` вызывает ваш колбэк и игнорирует то, что он возвращает, включая промис из `async`-колбэка. Поэтому он убегает вперёд, и код после него выполняется раньше, чем закончится работа:

<CodeExample output={`Всё сохранено! (Или нет?)
Следующий шаг
Сохранено: заметки
Сохранено: фото`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function save(item) {
  await wait(50);
  console.log("Сохранено:", item);
}

async function saveAll(items) {
  items.forEach(async (item) => {
    await save(item); // ❌ этого никто не ждёт
  });
  console.log("Всё сохранено! (Или нет?)");
}

await saveAll(["заметки", "фото"]);
console.log("Следующий шаг");
```

</CodeExample>

Используйте вместо него `for...of` или `Promise.all` с `map`. То же касается `filter`, `some` и других методов массивов: они не понимают `async`-колбэки.

</Callout>

## await верхнего уровня

Во многих примерах этого урока `await` используется вне какой-либо функции. Это называется **await верхнего уровня (top-level await)**. Он работает в **модулях (modules)** JavaScript — а именно их вы и так используете в современных проектах — и в консоли браузера. Он не работает в старых тегах `<script>` без `type="module"` и в файлах CommonJS с `require`:

```html
<script type="module">
  const res = await fetch("/api/settings");
  const settings = await res.json();
  console.log(settings.theme);
</script>
```

В Node.js модулями считаются файлы с расширением `.mjs` или все файлы проекта, в `package.json` которого есть `"type": "module"`, так что await верхнего уровня работает и там.

## Частые ошибки

### Забытый await

Это самый частый баг в асинхронном коде. Без `await` вы получаете **промис**, а не значение:

<CodeExample output={`[object Promise]5
true
100`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function getScore() {
  await wait(20);
  return 95;
}

const score = getScore(); // ❌ забыли await
console.log(score + 5);
console.log(score instanceof Promise);

const realScore = await getScore(); // ✅
console.log(realScore + 5);
```

</CodeExample>

Если вы видите на странице `[object Promise]` или `undefined` там, где должно быть свойство объекта (`user.name` у промиса равно `undefined`), ищите пропущенный `await`.

### return промиса из try без await

Более коварный вариант: `return somePromise` внутри `try` отдаёт промис **до того**, как он завершился, поэтому если он отклонится позже, ваш `catch` этого не увидит. Внутри `try` используйте `return await`:

<CodeExample output={`Ускользнула: Нет профиля для Zed
Гость`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function loadProfile(name) {
  await wait(50);
  throw new Error(`Нет профиля для ${name}`);
}

async function brokenLoad(name) {
  try {
    return loadProfile(name); // ❌ catch не видит ошибку
  } catch {
    return { name: "Гость" };
  }
}

async function fixedLoad(name) {
  try {
    return await loadProfile(name); // ✅ ждёт внутри try
  } catch {
    return { name: "Гость" };
  }
}

try {
  console.log((await brokenLoad("Zed")).name);
} catch (error) {
  console.log("Ускользнула:", error.message);
}
console.log((await fixedLoad("Zed")).name);
```

</CodeExample>

Другие классические ошибки вы уже встречали: `forEach` с `async`-колбэком и ожидание независимых задач по одной.

<Hint>

В `getUserSummary` используйте `const [user, posts] = await Promise.all([getJSON(...), getJSON(...)]);`, а затем сложите лайки через `posts.reduce((sum, post) => sum + post.likes, 0)`.
```js
const API = "https://api.pandadev.test";

// Дано: загружает JSON из учебного API, выбрасывает ошибку при сбое
async function getJSON(path) {
  const res = await fetch(API + path);
  const data = await res.json();
  if (!res.ok) {
    throw new Error(data.error);
  }
  return data;
}

async function getUserSummary(id) {
  const [user, posts] = await Promise.all([
    getJSON(`/users/${id}`),
    getJSON(`/posts?userId=${id}`),
  ]);
  const likes = posts.reduce((sum, post) => sum + post.likes, 0);
  return `${user.name} (постов: ${posts.length}, лайков: ${likes})`;
}

async function printSummaries(ids) {
  for (const id of ids) {
    try {
      console.log(await getUserSummary(id));
    } catch (error) {
      console.log(`Не удалось загрузить пользователя ${id}: ${error.message}`);
    }
  }
  console.log("Готово");
}

await printSummaries([1, 9, 3]);
```

## Итоги

- **`async`-функция** всегда возвращает промис: `return` выполняет его, а выброшенная ошибка — отклоняет.
- **`await`** ставит на паузу только текущую async-функцию, пока промис не завершится, а затем отдаёт его значение; остальная программа продолжает работать.
- Отклонённый промис заставляет `await` **выбросить** ошибку, поэтому используйте `try/catch/finally` для состояний загрузки, ошибки и уборки.
- `await` один за другим — для **зависимых** шагов; `await Promise.all([...])` — для **независимых**, и это гораздо быстрее.
- В циклах используйте `for...of` с `await` (по порядку) или `Promise.all` с `map` (параллельно). `forEach` не ждёт.
- **await верхнего уровня** работает в модулях и в консоли браузера.
- Частые баги: забытый `await` (вы получаете промис, `[object Promise]`), `return` без `await` внутри `try` и `async`-колбэки в `forEach`.
