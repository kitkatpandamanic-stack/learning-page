До сих пор ваш код в основном выполнялся сверху вниз, и каждая строка заканчивалась до того, как начиналась следующая. Но настоящие приложения много времени проводят в **ожидании**: ответа сервера, окончания таймера или клика пользователя. В этом модуле вы узнаете, как JavaScript ждёт, не замирая. Начнём с самого старого инструмента для этого — **колбэков (callbacks)**. Затем будут промисы и `async`/`await` — именно так написана большая часть современного кода. ⏳

## Почему коду приходится ждать

Некоторые операции быстрые: сложить числа или изменить строку — дело нескольких наносекунд. Другие медленные, потому что зависят от чего-то за пределами вашей программы:

- **сетевые запросы**: получение данных от сервера может занять от 20 миллисекунд до нескольких секунд;
- **таймеры**: «покажи это сообщение через 3 секунды»;
- **файлы и базы данных** (в Node.js);
- **люди**: клик или нажатие клавиши может случиться сейчас, позже или никогда.

JavaScript выполняет ваш код в **одном потоке (single thread)**: в каждый момент он может делать только что-то одно. Если бы он стоял на месте, пока ждёт сервер, вся страница бы зависла: кнопки не реагировали бы, ничего бы не прокручивалось. Вместо этого JavaScript говорит *«позови меня, когда будет готово»* и занимается другой работой. Код, который вот так выполняется позже, называется **асинхронным (asynchronous)**, или коротко async.

Проще всего увидеть это на `setTimeout(callback, ms)` — он запускает функцию после задержки в миллисекундах:

<CodeExample output={`Заказываем пиццу...
Смотрим телевизор, пока ждём
🍕 Пицца доставлена!`}>

```js
console.log("Заказываем пиццу...");

setTimeout(() => {
  console.log("🍕 Пицца доставлена!");
}, 100);

console.log("Смотрим телевизор, пока ждём");
```

</CodeExample>

`setTimeout` не ждёт. Он **планирует** функцию и сразу возвращается, поэтому последняя строка выполняется раньше. Через 100 миллисекунд пицца приезжает.

## Колбэки

**Колбэк (callback)**, или функция обратного вызова, — это функция, которую вы передаёте другой функции, чтобы та вызвала её позже. Вы уже пользовались ими: функции, которые вы передаёте в `map` и `forEach`, — это колбэки, которые выполняются сразу, а те, что вы передаёте в `addEventListener`, срабатывают всякий раз, когда происходит событие.

Вот ненастоящий сервер, который «загружает» пользователя за 100 мс. Ответ ещё не готов, когда `loadUser` возвращается, поэтому вызывающий код передаёт колбэк, который этот ответ получит:

<CodeExample output={`Загрузка...
Привет, Mei!`}>

```js
const users = { 1: "Mei", 2: "Sam" };

// Ненастоящий сервер: отвечает через 100 мс
function loadUser(id, callback) {
  setTimeout(() => {
    callback(users[id]);
  }, 100);
}

loadUser(1, (name) => {
  console.log(`Привет, ${name}!`);
});
console.log("Загрузка...");
```

</CodeExample>

Почему бы просто не вернуть имя через `return`? Потому что, когда функция возвращается, таймер ещё не сработал, и возвращать нечего:

<CodeExample output="undefined">

```js
const users = { 1: "Mei", 2: "Sam" };

function loadUserName(id) {
  let name;
  setTimeout(() => {
    name = users[id]; // выполнится через 100 мс...
  }, 100);
  return name; // ...а это выполняется прямо сейчас
}

console.log(loadUserName(1));
```

</CodeExample>

Это ошибка номер один у новичков в асинхронном коде. Значение, которое приходит позже, можно использовать только **внутри** кода, который выполняется позже.

### Колбэки с ошибкой первым аргументом

А если загрузка не удалась? Node.js сделал популярным такое соглашение: **первый** аргумент колбэка — это ошибка (или `null`, если всё прошло хорошо), а результат идёт вторым. Поэтому такие колбэки называют **error-first callbacks** («ошибка первой»):

<CodeExample output={`Найден: Sam
Не удалось: Нет пользователя с id 7`}>

```js
const users = { 1: "Mei", 2: "Sam" };

function loadUser(id, callback) {
  setTimeout(() => {
    if (users[id]) {
      callback(null, users[id]);
    } else {
      callback(new Error(`Нет пользователя с id ${id}`));
    }
  }, 100);
}

function show(error, name) {
  if (error) {
    console.log("Не удалось:", error.message);
    return;
  }
  console.log("Найден:", name);
}

loadUser(2, show);
loadUser(7, show);
```

</CodeExample>

Этот стиль вам ещё встретится в старом коде на Node.js и в библиотеках, например `fs.readFile(path, (error, data) => { ... })`.

## Таймеры

Таймеры срабатывают в порядке **времени**, а не в том порядке, в котором вы их написали. Задержка `0` означает не «сейчас», а «как можно скорее, после текущего кода»:

<CodeExample output={`Старт
A (0 мс)
B (30 мс)
C (60 мс)`}>

```js
setTimeout(() => console.log("C (60 мс)"), 60);
setTimeout(() => console.log("A (0 мс)"), 0);
setTimeout(() => console.log("B (30 мс)"), 30);
console.log("Старт");
```

</CodeExample>

`setTimeout` возвращает id, который можно передать в `clearTimeout`, чтобы отменить таймер. Его родственник `setInterval` вызывает колбэк снова и снова, каждые `ms` миллисекунд, пока вы не остановите его через `clearInterval`:

<CodeExample output={`3
2
1
Пуск!`}>

```js
const reminder = setTimeout(() => {
  console.log("Этого вы никогда не увидите");
}, 100);
clearTimeout(reminder); // отменён

let count = 3;
const id = setInterval(() => {
  console.log(count);
  count--;
  if (count === 0) {
    clearInterval(id);
    console.log("Пуск!");
  }
}, 50);
```

</CodeExample>

<Callout type="tip" title="Задержка — это минимум">

`setTimeout(fn, 100)` означает «не раньше чем через 100 мс». Если JavaScript занят, когда время вышло, колбэку придётся подождать, пока он освободится. Поэтому таймеры хороши для «покажи это вскоре», но не годятся для точного отсчёта времени. Чтобы измерить, сколько что-то заняло, сравните `Date.now()` или `performance.now()` до и после.

</Callout>

## Цикл событий

Так кто же следит за всеми этими колбэками? Над этим работают вместе несколько частей:

- **Стек вызовов (call stack)** — это код, который выполняется прямо сейчас. JavaScript выполняет его до конца, не прерываясь.
- **Браузер** (или Node.js) следит за всем, что ожидает: таймерами, сетевыми запросами, обработчиками событий. Ваш JavaScript в это время не занят.
- Когда таймер заканчивается или происходит клик, его колбэк попадает в **очередь задач (task queue)** — очередь колбэков, которые ждут своей очереди.
- **Цикл событий (event loop)** — это простой цикл: *когда стек вызовов пуст, взять следующую задачу из очереди и выполнить её.* И так повторять бесконечно.

```text
   ваш код            ожидание              готово к запуску
 ┌────────────┐   ┌──────────────┐   ┌───────────────────────┐
 │ стек       │ → │ таймеры, HTTP│ → │ очередь задач: cb1,cb2│
 └────────────┘   │ клики, ...   │   └───────────┬───────────┘
       ↑          └──────────────┘               │
       └── цикл событий: стек пуст? запустить ───┘
```

Вот почему таймер на `0` мс всё равно ждёт, пока закончится **весь** текущий код, сколько бы времени это ни заняло:

<CodeExample output={`Цикл завершён: 12499997500000
Таймер: наконец моя очередь`}>

```js
setTimeout(() => console.log("Таймер: наконец моя очередь"), 0);

let total = 0;
for (let i = 0; i < 5_000_000; i++) {
  total += i;
}
console.log("Цикл завершён:", total);
```

</CodeExample>

### Микрозадачи проходят без очереди

Есть ещё одна очередь. Колбэки промисов (с ними вы познакомитесь в следующем уроке) и `queueMicrotask` попадают в **очередь микрозадач (microtask queue)**. После каждого завершённого фрагмента кода цикл событий выполняет **все** ожидающие микрозадачи и только потом берёт следующую задачу. Поэтому колбэки промисов всегда выполняются раньше таймеров, которые уже ждут:

<CodeExample output={`1. начало скрипта
2. конец скрипта
3. промис (микрозадача)
4. queueMicrotask (микрозадача)
5. таймер (задача)`}>

```js
console.log("1. начало скрипта");

setTimeout(() => console.log("5. таймер (задача)"), 0);

Promise.resolve().then(() => {
  console.log("3. промис (микрозадача)");
});
queueMicrotask(() => console.log("4. queueMicrotask (микрозадача)"));

console.log("2. конец скрипта");
```

</CodeExample>

Шаг за шагом:

| Шаг | Что выполняется                          | Почему                                              |
| --- | ---------------------------------------- | --------------------------------------------------- |
| 1   | `1. начало скрипта`, `2. конец скрипта`  | Синхронный код всегда завершается первым            |
| 2   | `3. промис`, `4. queueMicrotask`         | Стек пуст: дальше выполняются все микрозадачи       |
| 3   | `5. таймер`                              | Только потом цикл событий берёт задачу              |

<Callout type="warning" title="Не блокируйте цикл событий">

Пока выполняется ваш код, ничего другого происходить не может: ни кликов, ни таймеров, ни обновлений экрана. Цикл, который длится 3 секунды, замораживает страницу на 3 секунды. Делайте каждый кусок работы коротким. Действительно тяжёлой работе (обработке изображений, огромным вычислениям) место в **Web Worker** — отдельном потоке. PandaDev запускает код уроков именно в нём, поэтому бесконечный цикл здесь не заморозит сайт.

</Callout>

## Ад колбэков

Колбэки работают, но в реальных задачах часто нужно несколько шагов, и каждому нужен результат предыдущего. Загрузить пользователя, потом его посты, потом лайки первого поста. С колбэками каждый шаг оказывается **внутри** предыдущего:

<CodeExample output={`Пост "Бамбук" (Mei) — лайков: 42`}>

```js
// Ненастоящие серверные функции, каждая отвечает через 50 мс
function getUser(id, callback) {
  setTimeout(() => callback(null, { id, name: "Mei" }), 50);
}
function getPosts(user, callback) {
  setTimeout(() => callback(null, ["Бамбук", "Сон"]), 50);
}
function getLikes(post, callback) {
  setTimeout(() => callback(null, 42), 50);
}

getUser(1, (error, user) => {
  if (error) return console.log(error.message);
  getPosts(user, (error, posts) => {
    if (error) return console.log(error.message);
    getLikes(posts[0], (error, likes) => {
      if (error) return console.log(error.message);
      console.log(`Пост "${posts[0]}" (${user.name}) — лайков: ${likes}`);
    });
  });
});
```

</CodeExample>

Разработчики называют такую форму **адом колбэков (callback hell)** или *пирамидой судьбы (pyramid of doom)*. Каждый новый шаг сдвигает код всё правее, а проблемы накапливаются:

- **Ошибки приходится проверять вручную на каждом уровне**, и `try/catch` вокруг всей конструкции не поможет, потому что колбэки выполняются позже (вы видели это в уроке [Обработка ошибок с помощью try/catch](/learn/javascript/try-catch)).
- **Объединять задачи неудобно.** «Загрузить эти три вещи одновременно и продолжить, когда всё готово» требует счётчиков и флагов.
- **Вы отдаёте управление.** Вы доверяете `getUser` вызвать ваш колбэк ровно один раз. Библиотека с багом может вызвать его дважды — или ни разу.

Промисы решают все три проблемы, и о них — [следующий урок](/learn/javascript/promises).

Напишите `countdown(from, onTick, onDone)` для экрана запуска ракеты. Функция принимает число и **два колбэка**:

1. Каждые **20 мс** вызывайте `onTick` со следующим числом: сначала `from`, потом `from - 1` и так далее до `1`.
2. После тика для `1` остановите таймер и один раз вызовите `onDone()`.

Сама `countdown` должна возвращаться сразу, чтобы программа вывела `Отсчёт начался` раньше первого числа.

<Hint>

`setInterval(callback, 20)` даёт вам тик каждые 20 мс. Храните текущее число в переменной снаружи колбэка. Внутри колбэка: если число дошло до `0`, вызовите `clearInterval(id)` и `onDone()`; иначе вызовите `onTick` с этим числом, а затем уменьшите его на единицу.

</Hint>

<Solution>

```js
function countdown(from, onTick, onDone) {
  let current = from;
  const id = setInterval(() => {
    if (current === 0) {
      clearInterval(id);
      onDone();
      return;
    }
    onTick(current);
    current--;
  }, 20);
}

countdown(
  3,
  (n) => console.log(n),
  () => console.log("Поехали! 🚀"),
);
console.log("Отсчёт начался");
```

</Solution>

</Exercise>

## Итоги

- Медленная работа (сеть, таймеры, файлы, люди) выполняется **асинхронно**: JavaScript планирует её и продолжает работу, а не замирает.
- **Колбэк** — это функция, переданная другой функции, чтобы та вызвала её позже. Значение, которое приходит позже, можно использовать только внутри этого колбэка, а не вернуть через `return`.
- **Колбэки с ошибкой первым аргументом** получают `(error, result)`; проверьте ошибку, прежде чем использовать результат.
- `setTimeout`/`clearTimeout` запускают код один раз после задержки, `setInterval`/`clearInterval` повторяют его. Задержка — это минимум, а не обещание точного времени.
- **Цикл событий** запускает следующую задачу, только когда стек вызовов пуст. **Микрозадачи** (колбэки промисов) выполняются раньше следующей задачи.
- Вложенные колбэки приводят к **аду колбэков**: глубокой вложенности, повторяющимся проверкам ошибок и задачам, которые трудно объединять. Лекарство — промисы.
