Promise chains are flat, but they're still full of little callbacks, and passing values from one step to a later one gets clumsy. **`async` and `await`** let you write asynchronous code that reads from top to bottom, just like ordinary code. They're built on promises, so everything from the [last lesson](/learn/javascript/promises) still applies; it's mostly a nicer way to write it. This is how most JavaScript you'll read at work is written. ✨

## async functions

Put the keyword `async` in front of a function, and it **always returns a promise**. If the function returns a value, the promise is fulfilled with it. If the function throws, the promise is rejected:

<CodeExample output={`true
Hello!
Oops`}>

```js
async function getGreeting() {
  return "Hello!";
}

const failing = async () => {
  throw new Error("Oops");
};

const result = getGreeting();
console.log(result instanceof Promise);
result.then((value) => console.log(value));

failing().catch((error) => console.log(error.message));
```

</CodeExample>

`async` works on every kind of function: declarations, arrow functions (`async () => {}`) and class methods (`async load() {}`).

## await

Inside an `async` function, **`await`** pauses the function until a promise settles, and then gives you its value. No `.then()` needed:

<CodeExample output={`Boiling water...
Meanwhile, reading the news
Steeping the tea...
Ready: 🍵 Green tea`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function makeTea() {
  console.log("Boiling water...");
  await wait(100);
  console.log("Steeping the tea...");
  await wait(50);
  return "🍵 Green tea";
}

makeTea().then((tea) => console.log("Ready:", tea));
console.log("Meanwhile, reading the news");
```

</CodeExample>

Look at the order. `await` pauses **only `makeTea`**, not the whole program. While the function waits, the event loop is free to run other code, which is why the news gets read before the tea is steeped. When the promise settles, the function carries on from where it stopped. Behind the scenes, everything after an `await` works like a `.then()` callback.

Here's the three-step example from the last two lessons once more. Compare it with the callback pyramid:

<CodeExample output={`Mei's "Bamboo" has 42 likes`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

const getUser = (id) => wait(50).then(() => ({ id, name: "Mei" }));
const getPosts = (user) => wait(50).then(() => ["Bamboo", "Naps"]);
const getLikes = (post) => wait(50).then(() => 42);

async function showLikes(userId) {
  const user = await getUser(userId);
  const posts = await getPosts(user);
  const likes = await getLikes(posts[0]);
  console.log(`${user.name}'s "${posts[0]}" has ${likes} likes`);
}

showLikes(1);
```

</CodeExample>

Every result gets a normal variable, and `user` is still available in the last line. No nesting, no chain.

<Callout type="note" title="await needs an async function">

`await` only works inside an `async` function (or at the top level of a module, more on that below). Inside a normal function it's a `SyntaxError`:

```js
function load() {
  const data = await getData(); // ❌ SyntaxError
}
```

</Callout>

## Errors: try, catch and finally

When an awaited promise **rejects**, `await` **throws** the error. So you handle async errors with the same `try/catch/finally` you already know:

<CodeExample output={`⏳ Loading Mei...
Mei is level 7
Spinner hidden
⏳ Loading Zed...
❌ No profile for Zed
Spinner hidden`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function loadProfile(name) {
  await wait(50);
  if (name !== "Mei") {
    throw new Error(`No profile for ${name}`);
  }
  return { name, level: 7 };
}

async function showProfile(name) {
  console.log(`⏳ Loading ${name}...`);
  try {
    const profile = await loadProfile(name);
    console.log(`${profile.name} is level ${profile.level}`);
  } catch (error) {
    console.log("❌", error.message);
  } finally {
    console.log("Spinner hidden");
  }
}

await showProfile("Mei");
await showProfile("Zed");
```

</CodeExample>

This is the pattern you'll write again and again in real apps: show a loading state, `try` the request, show the data or an error message, and clean up in `finally`.

If an `async` function doesn't catch an error, its promise rejects, and the caller has to deal with it, either with its own `try/catch` around `await`, or with `.catch()`.

## Talking to an API

Waiting for a timer is nice for learning, but the real reason async code exists is the network. PandaDev has a practice API built in, so these lessons work offline and always give the same answers. Real APIs work the same way.

The browser's **`fetch(url)`** function sends a request and returns a promise of the **response**. Reading the response body as JSON with `res.json()` is a second promise, so there are two `await`s:

<CodeExample output={`200
{ id: 1, name: 'Mei Lin', username: 'mei', email: 'mei@pandadev.test' }
Sam Ortiz <sam@pandadev.test>`}>

```js
const API = "https://api.pandadev.test";

async function getUser(id) {
  const res = await fetch(`${API}/users/${id}`);
  console.log(res.status);
  return res.json();
}

const mei = await getUser(1);
console.log(mei);

const sam = await (await fetch(`${API}/users/2`)).json();
console.log(`${sam.name} <${sam.email}>`);
```

</CodeExample>

`200` is the HTTP **status code** for "OK". You'll learn all about `fetch`, status codes and error handling in the next module. For now, it's simply a function that returns a promise, like the ones you've been writing. A real API usually also wants a key and a different address, but the code has the same shape:

```js
const res = await fetch("https://api.example.com/v1/users/1", {
  headers: { Authorization: "Bearer YOUR_API_KEY" },
});
const user = await res.json();
```

## One after another, or all at once?

Each `await` waits for its promise before the next line runs. That's exactly right when a step **needs the result** of the step before it. But when tasks don't depend on each other, waiting for them one by one wastes time. Start them all and wait with `Promise.all` instead:

<CodeExample output={`One after another:
  start photos
  done photos
  start music
  done music
At the same time:
  start photos
  start music
  done music
  done photos`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function download(name, ms) {
  console.log(`  start ${name}`);
  await wait(ms);
  console.log(`  done ${name}`);
  return name;
}

console.log("One after another:");
await download("photos", 60);
await download("music", 40);

console.log("At the same time:");
await Promise.all([download("photos", 60), download("music", 40)]);
```

</CodeExample>

One after another takes 60 + 40 = 100 ms. At the same time takes only as long as the slowest task, 60 ms. With real requests that each take half a second, that's the difference between a snappy page and a sluggish one.

The rule of thumb:

- **Sequential** (`await`, `await`): when step 2 needs step 1's result, like *log in, then load my orders*.
- **Parallel** (`await Promise.all([...])`): when the tasks are independent, like *load the profile, the friends and the notifications*.

<Callout type="tip" title="Watch out for accidental waterfalls">

```js
const profile = await getProfile(id);
const friends = await getFriends(id); // didn't need to wait for profile!
```

Code like this is easy to write and quietly slow, because the second request only starts when the first one has finished. If neither line uses the other's result, write `const [profile, friends] = await Promise.all([getProfile(id), getFriends(id)]);`. Array destructuring gives each result its own name.

</Callout>

## Loops with await

You can use `await` inside a `for...of` loop. Each round waits for the one before, so the items are handled **one at a time, in order**. For **parallel** work, `map` the items to promises and wait for them all with `Promise.all`:

<CodeExample output={`Saved notes
Saved photos
All saved, one at a time
Saved music
Saved videos
All saved, at the same time
[ 'Mei Lin', 'Sam Ortiz', 'Ada Brooks' ]`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function save(item) {
  await wait(50);
  console.log("Saved", item);
}

async function saveInOrder(items) {
  for (const item of items) {
    await save(item); // waits before the next round
  }
  console.log("All saved, one at a time");
}

async function saveAtOnce(items) {
  await Promise.all(items.map((item) => save(item)));
  console.log("All saved, at the same time");
}

await saveInOrder(["notes", "photos"]);
await saveAtOnce(["music", "videos"]);

// The same idea with the practice API
const API = "https://api.pandadev.test";
const getUser = async (id) => (await fetch(`${API}/users/${id}`)).json();
const users = await Promise.all([1, 2, 3].map((id) => getUser(id)));
console.log(users.map((user) => user.name));
```

</CodeExample>

`Promise.all` keeps the results in the same order as the ids, even if the answers arrive in a different order.

<Callout type="danger" title="forEach doesn't wait">

`forEach` calls your callback and ignores what it returns, including the promise from an `async` callback. So it races ahead, and code after it runs before the work is done:

<CodeExample output={`All saved! (or are they?)
Next step
Saved notes
Saved photos`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function save(item) {
  await wait(50);
  console.log("Saved", item);
}

async function saveAll(items) {
  items.forEach(async (item) => {
    await save(item); // ❌ nobody waits for this
  });
  console.log("All saved! (or are they?)");
}

await saveAll(["notes", "photos"]);
console.log("Next step");
```

</CodeExample>

Use `for...of` or `Promise.all` with `map` instead. The same goes for `filter`, `some` and the other array methods: they don't understand `async` callbacks.

</Callout>

## Top-level await

Many examples in this lesson use `await` outside of any function. That's called **top-level await**. It works in JavaScript **modules**, which is what you use in modern projects anyway, and in the browser console. It doesn't work in old-style `<script>` tags without `type="module"` or in CommonJS files with `require`:

```html
<script type="module">
  const res = await fetch("/api/settings");
  const settings = await res.json();
  console.log(settings.theme);
</script>
```

In Node.js, files ending in `.mjs` or projects with `"type": "module"` in `package.json` are modules, so top-level await works there too.

## Common mistakes

### Forgetting await

This is the most common async bug of all. Without `await`, you get the **promise**, not the value:

<CodeExample output={`[object Promise]5
true
100`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function getScore() {
  await wait(20);
  return 95;
}

const score = getScore(); // ❌ forgot await
console.log(score + 5);
console.log(score instanceof Promise);

const realScore = await getScore(); // ✅
console.log(realScore + 5);
```

</CodeExample>

When you see `[object Promise]` on a page, or `undefined` where an object property should be (`user.name` on a promise is `undefined`), look for a missing `await`.

### Returning a promise from try without await

A sneakier version: `return somePromise` inside `try` hands the promise back **before** it has settled, so if it rejects later, your `catch` never sees it. Use `return await` inside `try`:

<CodeExample output={`Escaped: No profile for Zed
Guest`}>

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function loadProfile(name) {
  await wait(50);
  throw new Error(`No profile for ${name}`);
}

async function brokenLoad(name) {
  try {
    return loadProfile(name); // ❌ catch can't see the error
  } catch {
    return { name: "Guest" };
  }
}

async function fixedLoad(name) {
  try {
    return await loadProfile(name); // ✅ waits inside try
  } catch {
    return { name: "Guest" };
  }
}

try {
  console.log((await brokenLoad("Zed")).name);
} catch (error) {
  console.log("Escaped:", error.message);
}
console.log((await fixedLoad("Zed")).name);
```

</CodeExample>

The other classic mistakes you've already met: `forEach` with an `async` callback, and awaiting independent tasks one by one.

2. `printSummaries(ids)` goes through the ids **in order**. For each one, it prints the summary, or, if loading fails, `Could not load user 9: User not found` (the id and the error's message). At the very end, it prints `Done`, only after every summary has been printed.

<Hint>

In `getUserSummary`, use `const [user, posts] = await Promise.all([getJSON(...), getJSON(...)]);`, then add up the likes with `posts.reduce((sum, post) => sum + post.likes, 0)`. In `printSummaries`, use a `for...of` loop (not `forEach`) with `try { console.log(await getUserSummary(id)); } catch (error) { ... }` inside it.

<Solution>

```js
const API = "https://api.pandadev.test";

// Given: loads JSON from the practice API, throws on errors
async function getJSON(path) {
  const res = await fetch(API + path);
  const data = await res.json();
  if (!res.ok) {
    throw new Error(data.error);
  }
  return data;
}

async function getUserSummary(id) {
  const [user, posts] = await Promise.all([
    getJSON(`/users/${id}`),
    getJSON(`/posts?userId=${id}`),
  ]);
  const likes = posts.reduce((sum, post) => sum + post.likes, 0);
  return `${user.name} (posts: ${posts.length}, likes: ${likes})`;
}

async function printSummaries(ids) {
  for (const id of ids) {
    try {
      console.log(await getUserSummary(id));
    } catch (error) {
      console.log(`Could not load user ${id}: ${error.message}`);
    }
  }
  console.log("Done");
}

await printSummaries([1, 9, 3]);
```

## Recap

- An **`async` function** always returns a promise: returning fulfils it, throwing rejects it.
- **`await`** pauses only the current async function until a promise settles, then gives you its value; the rest of the program keeps running.
- A rejected promise makes `await` **throw**, so use `try/catch/finally` for loading, error and clean-up states.
- `await` one after another for **dependent** steps; `await Promise.all([...])` for **independent** ones, which is much faster.
- In loops, use `for...of` with `await` (in order) or `Promise.all` with `map` (in parallel). `forEach` doesn't wait.
- **Top-level await** works in modules and the browser console.
- Common bugs: a forgotten `await` (you get a promise, `[object Promise]`), `return` without `await` inside `try`, and `async` callbacks in `forEach`.
