Every time your front-end code calls `fetch`, something on the other side answers: a **server**. Until now you've always been the one asking. In this module you switch sides and build the thing that answers, a **REST API**, using the same language you already know. That's possible thanks to **Node.js**, and the most popular way to build APIs with it is **Express**. 🐼

## What Node.js is

**Node.js** runs JavaScript **outside the browser**. It takes V8, the JavaScript engine from Chrome, and adds what a server needs instead of what a web page needs:

| In the browser | In Node.js |
| --- | --- |
| `document`, `window`, the DOM | no DOM at all |
| `fetch`, `localStorage` | `fetch`, plus reading and writing **files** (`node:fs`) |
| runs code a website sent you | runs code **you** chose, with full access to the machine |
| one user per tab | one process serving **many users** at once |

The language is identical: variables, functions, classes, promises and `async`/`await` all work the same. You've also used Node already: `npm` is a Node program, and the [npm & Git lesson](/learn/javascript/npm-and-git) ran `node hello.js`.

### One thread, many visitors

A server handles many requests at the same time, but Node runs your JavaScript on **one thread**. How? Most of a request's time is spent **waiting**: for a database, a file or another API. While one request waits, Node's **event loop** gets on with the next one, exactly like `await` in the browser:

<CodeExample output={`Mei: request arrives
Bao: request arrives
Bao: response sent after 100 ms
Mei: response sent after 300 ms
Both visitors served`}>

```js
const wait = (ms) => new Promise((done) => setTimeout(done, ms));

async function handleRequest(name, ms) {
  console.log(`${name}: request arrives`);
  await wait(ms); // pretend we're reading from a database
  console.log(`${name}: response sent after ${ms} ms`);
}

// Two visitors at once, one JavaScript thread
await Promise.all([
  handleRequest("Mei", 300),
  handleRequest("Bao", 100),
]);
console.log("Both visitors served");
```

</CodeExample>

Bao's quick request didn't have to wait for Mei's slow one. This is why Node is great at servers that do lots of waiting (most web APIs), and why you should never block it with long **synchronous** work: a loop that runs for 2 seconds freezes the server for **every** visitor.

## Setting up a real Express project

**Express** is a small framework that turns "a request arrived" into "call this function of mine". On your computer, a project starts like this:

```bash
mkdir notes-api
cd notes-api
npm init -y
npm pkg set type=module   # use import/export (ES modules)
npm install express
```

`"type": "module"` in `package.json` lets you use `import`/`export`, the same [modules](/learn/javascript/modules) you already know. Then create the server:

```js title="server.js"
import express from "express";

const app = express();

app.get("/", (req, res) => {
  res.send("Hello from the panda server!");
});

app.listen(3000, () => {
  console.log("Listening on http://localhost:3000");
});
```

```bash
node server.js            # start the server (Ctrl+C stops it)
node --watch server.js    # restart automatically when you save
curl http://localhost:3000
```

Open `http://localhost:3000` in your browser and you'll see the greeting. The server keeps running and waiting for requests until you stop it.

<Callout type="note" title="How Express works in these lessons">

The PandaDev editor runs in your browser, which can't open a real server port. So `import express from "express"` here gives you an **Express 5 compatible** version that works without a network: `app.listen()` simply calls its callback, and you send requests with **supertest**, the same tool real projects use to test their APIs. Your routes, middleware and handlers are written exactly as in a real project. Commands for your own computer are in `bash` blocks.

</Callout>

## Your first Express app

An Express app is a list of **routes**. Each route is an HTTP **method** (`get`, `post`, `put`, `patch`, `delete`), a **path**, and a **handler** function that receives two objects:

- **`req`** (the request): what the client sent, like the path, query string, headers and body.
- **`res`** (the response): what you send back, with helpers like `res.send()` and `res.json()`.

`request(app).get("/")` from supertest sends a GET request straight to your app and gives you the response:

<CodeExample output={`200 Hello from the panda server!
200 { status: 'ok', pandas: 3 }
application/json; charset=utf-8
404 Cannot GET /api/nope`}>

```js
import express from "express";
import request from "supertest";

const app = express();

app.get("/", (req, res) => {
  res.send("Hello from the panda server!");
});

app.get("/api/health", (req, res) => {
  res.json({ status: "ok", pandas: 3 });
});

const home = await request(app).get("/");
console.log(home.status, home.text);

const health = await request(app).get("/api/health");
console.log(health.status, health.body);
console.log(health.headers["content-type"]);

const missing = await request(app).get("/api/nope");
console.log(missing.status, missing.text);
```

</CodeExample>

- `res.send("text")` sends text (as HTML). `res.json(value)` turns any value into JSON and sets the `Content-Type` header to `application/json`. APIs almost always use `res.json`.
- On the test side, `res.text` is the raw text of the answer and `res.body` is the parsed JSON.
- When no route matches, Express answers **404** with `Cannot GET /api/nope`.

Express checks routes **from top to bottom** and the first one that matches the method and path handles the request.

### Reading the request

`req` carries everything the client sent. These are the parts you'll use most:

<CodeExample output={`GET /hello { lang: 'en' }
User-Agent: PandaBrowser/1.0
200 { message: 'Hi!' } yes`}>

```js
import express from "express";
import request from "supertest";

const app = express();

app.get("/hello", (req, res) => {
  console.log(req.method, req.path, req.query);
  console.log("User-Agent:", req.get("User-Agent"));
  res.set("X-Panda", "yes"); // a response header
  res.json({ message: "Hi!" });
});

const res = await request(app)
  .get("/hello?lang=en")
  .set("User-Agent", "PandaBrowser/1.0"); // a request header
console.log(res.status, res.body, res.headers["x-panda"]);
```

</CodeExample>

`req.get(name)` reads a request header (any capitalisation works), and `res.set(name, value)` adds one to the response. On the supertest side, `.set()` adds a header to the request.

## Status codes

Every response has a **status code** that tells the client what happened, before it even looks at the body. Express uses **200 OK** unless you say otherwise with `res.status(code)`:

| Code | Meaning | Typical use |
| --- | --- | --- |
| 200 | OK | a successful GET, PATCH or PUT |
| 201 | Created | a POST that created something |
| 204 | No Content | a successful DELETE (no body) |
| 400 | Bad Request | the client sent invalid data |
| 401 / 403 | Unauthorized / Forbidden | not logged in / not allowed |
| 404 | Not Found | no such route or item |
| 500 | Internal Server Error | a bug or crash on the server |

<CodeExample output={`201 { id: 2, name: 'Bao' }
204 ""
404 { error: 'Panda not found' }
[ { id: 2, name: 'Bao' } ]`}>

```js
import express from "express";
import request from "supertest";

const app = express();
app.use(express.json()); // reads JSON bodies (more next lesson)

const pandas = [{ id: 1, name: "Mei" }];
let nextId = 2;

app.post("/pandas", (req, res) => {
  const panda = { id: nextId++, name: req.body.name };
  pandas.push(panda);
  res.status(201).json(panda);
});

app.delete("/pandas/:id", (req, res) => {
  const index = pandas.findIndex(
    (p) => p.id === Number(req.params.id),
  );
  if (index === -1) {
    return res.status(404).json({ error: "Panda not found" });
  }
  pandas.splice(index, 1);
  res.sendStatus(204);
});

const created = await request(app)
  .post("/pandas")
  .send({ name: "Bao" });
console.log(created.status, created.body);

const deleted = await request(app).delete("/pandas/1");
console.log(deleted.status, JSON.stringify(deleted.text));

const again = await request(app).delete("/pandas/1");
console.log(again.status, again.body);
console.log(pandas);
```

</CodeExample>

- `res.status(201).json(panda)`: `status()` returns `res`, so you can chain the next call.
- `res.sendStatus(204)` sends just the status. A 204 never has a body, so `deleted.text` is empty.
- In supertest, `.send({ ... })` sends a JSON body. In a real server, `fetch` with `method: "POST"` and a JSON body does the same thing.
- Notice the early `return` before the 404. Without it, the handler would carry on and try to answer **twice**.

<Callout type="danger" title="One request, one response">

Each request gets **exactly one** response. If you forget the `return` and your code calls `res.json()` a second time, the client gets the first answer and Node reports an error:

```bash
Error [ERR_HTTP_HEADERS_SENT]: Cannot set headers after they are sent to the client
```

And if a handler never responds at all, the client just waits until it gives up. Make sure every path through a handler ends in exactly one `res.json()`, `res.send()`, `res.sendStatus()` or `res.end()`.

</Callout>

## Route params and query strings

There are two ways to put information in a URL, and APIs use both:

- **Route params** identify **which** item: `/movies/2`. You declare them with a colon in the path, `/movies/:id`, and read them from `req.params.id`.
- **Query strings** **filter or adjust** a list: `/movies?genre=comedy&after=2010`. Express parses them into `req.query`.

<CodeExample output={`200 [ 'Kung Fu Panda', 'Spirited Away', 'Paddington 2' ]
200 [ 'Kung Fu Panda', 'Paddington 2' ]
200 [ 'Paddington 2' ]
params: { id: '2' }
200 { id: 2, title: 'Spirited Away', year: 2001, genre: 'fantasy' }
params: { id: '42' }
404 { error: 'Movie not found' }`}>

```js
import express from "express";
import request from "supertest";

const movies = [
  { id: 1, title: "Kung Fu Panda", year: 2008, genre: "comedy" },
  { id: 2, title: "Spirited Away", year: 2001, genre: "fantasy" },
  { id: 3, title: "Paddington 2", year: 2017, genre: "comedy" },
];

const app = express();

app.get("/movies", (req, res) => {
  const { genre, after } = req.query;
  let results = movies;
  if (genre) {
    results = results.filter((m) => m.genre === genre);
  }
  if (after) {
    results = results.filter((m) => m.year > Number(after));
  }
  res.json(results.map((m) => m.title));
});

app.get("/movies/:id", (req, res) => {
  console.log("params:", req.params);
  const id = Number(req.params.id);
  const movie = movies.find((m) => m.id === id);
  if (!movie) {
    return res.status(404).json({ error: "Movie not found" });
  }
  res.json(movie);
});

const urls = [
  "/movies",
  "/movies?genre=comedy",
  "/movies?genre=comedy&after=2010",
  "/movies/2",
  "/movies/42",
];
for (const url of urls) {
  const res = await request(app).get(url);
  console.log(res.status, res.body);
}
```

</CodeExample>

Query parameters are **optional**: if the client leaves one out, it's simply `undefined` in `req.query`, so the `if` skips that filter. That's how one route can serve both "all movies" and "comedies after 2010".

<Callout type="warning" title="Params and query values are always strings">

A URL is text, so `req.params.id` is the **string** `"2"`, not the number `2`. This is one of the most common Express bugs:

```js
app.get("/notes/:id", (req, res) => {
  console.log(typeof req.params.id); // "string"
  // ❌ never matches: "1" === 1 is false
  const note = notes.find((n) => n.id === req.params.id);
  // ✅ convert first
  const fixed = notes.find((n) => n.id === Number(req.params.id));
});
```

The same goes for `req.query`: `?after=2010` gives `"2010"`. Convert with `Number()` before comparing or doing maths.

</Callout>

## Testing your API with supertest

So far we've just printed responses. In real projects you **test** an API the same way, with supertest inside Vitest (`npm install -D vitest supertest`). Supertest adds handy `.expect()` checks for the status and headers, and Vitest's `expect` checks the body:

<CodeExample output={`✓ GET /movies/:id > returns one movie as JSON
✓ GET /movies/:id > answers 404 for an unknown id
✓ GET /movies/:id > answers 404 for an id that isn't a number

Tests  3 passed (3)`}>

```js
import express from "express";
import request from "supertest";
import { describe, it, expect } from "vitest";

const movies = [
  { id: 1, title: "Kung Fu Panda", year: 2008 },
  { id: 2, title: "Spirited Away", year: 2001 },
];

const app = express();
app.get("/movies/:id", (req, res) => {
  const movie = movies.find((m) => m.id === Number(req.params.id));
  if (!movie) {
    return res.status(404).json({ error: "Movie not found" });
  }
  res.json(movie);
});

describe("GET /movies/:id", () => {
  it("returns one movie as JSON", async () => {
    const res = await request(app)
      .get("/movies/2")
      .expect(200)
      .expect("Content-Type", /json/);
    expect(res.body.title).toBe("Spirited Away");
  });

  it("answers 404 for an unknown id", async () => {
    const res = await request(app).get("/movies/99");
    expect(res.status).toBe(404);
    expect(res.body).toEqual({ error: "Movie not found" });
  });

  it("answers 404 for an id that isn't a number", async () => {
    await request(app).get("/movies/abc").expect(404);
  });
});
```

</CodeExample>

Supertest talks to the app **directly**, without starting a server or opening a port. That's why API tests are fast and don't need `app.listen()`. You'll build a complete test suite in the Notes API mini-project at the end of this module.

## Recap

- **Node.js** runs JavaScript outside the browser. One thread serves many requests because the **event loop** handles others while one waits; never block it with long synchronous work.
- A real project: `npm init -y`, `npm pkg set type=module`, `npm install express`, then `node server.js` (or `node --watch server.js`) starts a server that `app.listen(3000)` keeps running.
- Routes are a method + a path + a handler `(req, res) => { ... }`. Express tries them top to bottom; no match gives **404** `Cannot GET /path`.
- Answer with `res.json(value)`, set the status with `res.status(201)`, and use `res.sendStatus(204)` for "done, nothing to send". Every request gets **exactly one** response, so `return` after an early answer.
- `/movies/:id` → `req.params.id`; `?genre=comedy` → `req.query.genre`. Both are **strings**: convert with `Number()`.
- Test APIs with **supertest**: `await request(app).get("/movies/2").expect(200)`, then check `res.status` and `res.body` with Vitest.
