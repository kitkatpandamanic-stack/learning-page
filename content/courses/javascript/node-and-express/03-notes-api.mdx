Time to put the whole module together. You'll build a **Notes API**, the kind of back end a notes app on your phone talks to: clients can create notes, list and search them, read one, change it and delete it. Along the way you'll meet the **repository pattern**, which keeps your routes independent of how data is stored, and you'll test the API the way professional teams do, with Vitest and supertest in one file. 📝

## The plan

Good APIs are designed before they're coded. Ours has one resource, `notes`, mounted at `/api/notes`, with the five classic **CRUD** operations (Create, Read, Update, Delete):

| Request | Does | Success |
| --- | --- | --- |
| `GET /api/notes` | list notes, searched with `?search=bamboo` | 200 + an array |
| `POST /api/notes` | create a note from `{ title, text?, pinned? }` | 201 + the new note |
| `GET /api/notes/:id` | get one note | 200 + the note |
| `PATCH /api/notes/:id` | change some fields | 200 + the updated note |
| `DELETE /api/notes/:id` | delete it | 204, no body |

A note looks like `{ id: 1, title: "Buy bamboo", text: "", pinned: false }`. An unknown id gives **404** `{ error: "Note not found" }`, invalid data gives **400** `{ error: "Invalid note", details: [...] }`, and unknown routes give **404** `{ error: "Not found" }`.

## A repository for the data

Where do the notes live? In a real app, in a **database**. But your routes shouldn't care. The **repository pattern** puts all the storage code behind a small object with clear methods (`list`, `get`, `create`, `update`, `remove`), and the routes only ever call those methods. For now, our repository keeps notes in memory, in a `Map` from id to note:

<CodeExample output={`{ id: 2, title: 'Nap', text: 'After lunch', pinned: true }
true false
{ id: 3, title: 'Climb tree', text: '', pinned: false }
[ 2, 3 ]
undefined`}>

```js
function createNotesRepository() {
  const notes = new Map(); // id -> note
  let nextId = 1;

  return {
    async list() {
      return [...notes.values()];
    },
    async get(id) {
      return notes.get(id);
    },
    async create({ title, text = "", pinned = false }) {
      const note = { id: nextId++, title, text, pinned };
      notes.set(note.id, note);
      return note;
    },
    async update(id, changes) {
      const note = notes.get(id);
      if (!note) return undefined;
      const updated = { ...note, ...changes };
      notes.set(id, updated);
      return updated;
    },
    async remove(id) {
      return notes.delete(id);
    },
  };
}

const notes = createNotesRepository();
await notes.create({ title: "Buy bamboo" });
const nap = await notes.create({ title: "Nap", pinned: true });
console.log(await notes.update(nap.id, { text: "After lunch" }));
console.log(await notes.remove(1), await notes.remove(1));
console.log(await notes.create({ title: "Climb tree" }));
console.log((await notes.list()).map((n) => n.id));
console.log(await notes.get(1));
```

</CodeExample>

Three details matter:

- **The methods are `async`.** A real database always answers later, so a real repository returns promises. Making the in-memory one `async` too means the routes already use `await`, and swapping in a database won't change them.
- **Ids come from a counter that only goes up.** Note 1 was deleted, yet the next note got id 3, not 2. Using something like `notes.size + 1` would hand out an id that's **already taken** after a delete, silently overwriting a note. Databases use the same idea (auto-increment ids).
- **`update` builds a new object** with spread, `{ ...note, ...changes }`, so the fields you don't send stay as they were.

<Callout type="tip" title="Swapping in a real database">

Because the routes only talk to the repository, moving to a real database means writing **one** new object with the same methods. For example, with SQLite and the `better-sqlite3` package:

```js title="src/sqlite-notes.js"
import Database from "better-sqlite3";

export function createSqliteNotesRepository(file = "notes.db") {
  const db = new Database(file);
  return {
    async list() {
      return db.prepare("SELECT * FROM notes").all();
    },
    async get(id) {
      return db.prepare("SELECT * FROM notes WHERE id = ?").get(id);
    },
    // ...create, update and remove with INSERT, UPDATE, DELETE
  };
}
```

The app is created with `createApp({ notes: createSqliteNotesRepository() })` and nothing else changes. Tests keep using the fast in-memory version. (Real code would also turn SQLite's `0`/`1` back into `true`/`false` for `pinned`.)

</Callout>

## Parsing and validating input

Last lesson's `validateNote` returned a list of problems. This time we go one step further: **`parseNote`** either returns **clean data** containing only the allowed fields, or **throws** an `HttpError` with status 400 that the error middleware turns into a response. Routes then need just one line for validation. For `PATCH`, every field is optional, so it takes a `partial` option:

<CodeExample output={`{ title: 'Nap' }
{ pinned: true }
400 Invalid note
- title is required
- text must be a string
- pinned must be true or false`}>

```js
class HttpError extends Error {
  constructor(status, message, details) {
    super(message);
    this.status = status;
    this.details = details;
  }
}

// Returns clean data with only the allowed fields, or throws 400.
// partial: true is for PATCH, where every field is optional.
function parseNote(input, { partial = false } = {}) {
  const body = input ?? {};
  const errors = [];
  const data = {};
  if (!partial || body.title !== undefined) {
    const title = body.title;
    if (typeof title !== "string" || title.trim() === "") {
      errors.push("title is required");
    } else if (title.length > 100) {
      errors.push("title must be at most 100 characters");
    } else {
      data.title = title.trim();
    }
  }
  if (body.text !== undefined) {
    if (typeof body.text !== "string") {
      errors.push("text must be a string");
    } else {
      data.text = body.text;
    }
  }
  if (body.pinned !== undefined) {
    if (typeof body.pinned !== "boolean") {
      errors.push("pinned must be true or false");
    } else {
      data.pinned = body.pinned;
    }
  }
  if (errors.length > 0) {
    throw new HttpError(400, "Invalid note", errors);
  }
  return data;
}

console.log(parseNote({ title: " Nap ", id: 99, isAdmin: true }));
console.log(parseNote({ pinned: true }, { partial: true }));
try {
  parseNote({ text: 42, pinned: "yes" });
} catch (err) {
  console.log(err.status, err.message);
  for (const problem of err.details) console.log("-", problem);
}
```

</CodeExample>

Look at the first line of output: the client sent `id: 99` and `isAdmin: true`, and they were simply **dropped**. Copying `req.body` straight into your data would let clients overwrite ids or set fields they should never touch, a classic security hole called **mass assignment**. Picking allowed fields one by one closes it.

## Wiring up the routes

Now the app itself. `createApp` takes the repository as an **option** (dependency injection, like the config in the last lesson). A small helper, `findNote`, turns the `:id` text into a number and throws a 404 if there's no such note, so every route that needs one note can share it:

<CodeExample output={`201 { id: 1, title: 'Buy bamboo', text: '', pinned: true }
400 Invalid note
[ 'title is required', 'text must be a string' ]
{ id: 1, title: 'Buy bamboo', text: '', pinned: true }
{ error: 'Note not found' }
1`}>

```js
import express from "express";
import request from "supertest";

class HttpError extends Error {
  constructor(status, message, details) {
    super(message);
    this.status = status;
    this.details = details;
  }
}

function parseNote(input, { partial = false } = {}) {
  const body = input ?? {};
  const errors = [];
  const data = {};
  if (!partial || body.title !== undefined) {
    const title = body.title;
    if (typeof title !== "string" || title.trim() === "") {
      errors.push("title is required");
    } else if (title.length > 100) {
      errors.push("title must be at most 100 characters");
    } else {
      data.title = title.trim();
    }
  }
  if (body.text !== undefined) {
    if (typeof body.text !== "string") {
      errors.push("text must be a string");
    } else {
      data.text = body.text;
    }
  }
  if (body.pinned !== undefined) {
    if (typeof body.pinned !== "boolean") {
      errors.push("pinned must be true or false");
    } else {
      data.pinned = body.pinned;
    }
  }
  if (errors.length > 0) {
    throw new HttpError(400, "Invalid note", errors);
  }
  return data;
}

function createNotesRepository() {
  const notes = new Map();
  let nextId = 1;
  return {
    async list() {
      return [...notes.values()];
    },
    async get(id) {
      return notes.get(id);
    },
    async create({ title, text = "", pinned = false }) {
      const note = { id: nextId++, title, text, pinned };
      notes.set(note.id, note);
      return note;
    },
    async update(id, changes) {
      const note = notes.get(id);
      if (!note) return undefined;
      const updated = { ...note, ...changes };
      notes.set(id, updated);
      return updated;
    },
    async remove(id) {
      return notes.delete(id);
    },
  };
}

function createApp({ notes }) {
  const app = express();
  app.use(express.json());

  const router = express.Router();

  async function findNote(idText) {
    const note = await notes.get(Number(idText));
    if (!note) throw new HttpError(404, "Note not found");
    return note;
  }

  router.get("/", async (req, res) => {
    res.json(await notes.list());
  });

  router.post("/", async (req, res) => {
    const data = parseNote(req.body);
    const note = await notes.create(data);
    res.status(201).json(note);
  });

  router.get("/:id", async (req, res) => {
    res.json(await findNote(req.params.id));
  });

  app.use("/api/notes", router);

  app.use((req, res) => {
    res.status(404).json({ error: "Not found" });
  });

  app.use((err, req, res, next) => {
    const status = err.status ?? 500;
    if (status >= 500) console.log("Server error:", err);
    res.status(status).json({
      error: status >= 500 ? "Something went wrong" : err.message,
      details: err.details,
    });
  });

  return app;
}

const app = createApp({ notes: createNotesRepository() });
const api = request(app);

const created = await api
  .post("/api/notes")
  .send({ title: "Buy bamboo", pinned: true });
console.log(created.status, created.body);

const invalid = await api.post("/api/notes").send({ text: 7 });
console.log(invalid.status, invalid.body.error);
console.log(invalid.body.details);

console.log((await api.get("/api/notes/1")).body);
console.log((await api.get("/api/notes/2")).body);
console.log((await api.get("/api/notes")).body.length);
```

</CodeExample>

The routes are short because the hard work lives elsewhere: `parseNote` validates, `findNote` finds or throws 404, the repository stores, and the error handler formats every failure the same way. The error handler also sends `details` when there are any; `res.json` leaves out properties that are `undefined`, so a 404 has just `error`.

<Callout type="warning" title="Validate before you touch the data">

Always run `parseNote` **before** calling the repository. If you create the note first and validate afterwards, an invalid request still leaves a half-made note behind, even though the client got a 400 and thinks nothing happened.

</Callout>

## Testing the API with Vitest and supertest

In real projects every endpoint has tests, and API tests look just like the unit tests from the testing module, with supertest sending the requests. The key trick is giving **every test its own fresh app and repository** in `beforeEach`, so tests never depend on each other or on the order they run in. Here it is on a tiny version of the API:

<CodeExample output={`✓ Notes API > starts with no notes
✓ Notes API > creates a note and lists it
✓ Notes API > gives every test its own empty repository
✓ Notes API > rejects a note without a title

Tests  4 passed (4)`}>

```js
import express from "express";
import request from "supertest";
import { describe, it, expect, beforeEach } from "vitest";

function createNotesRepository() {
  const notes = new Map();
  let nextId = 1;
  return {
    async list() {
      return [...notes.values()];
    },
    async create({ title }) {
      const note = { id: nextId++, title };
      notes.set(note.id, note);
      return note;
    },
  };
}

function createApp({ notes }) {
  const app = express();
  app.use(express.json());
  app.get("/api/notes", async (req, res) => {
    res.json(await notes.list());
  });
  app.post("/api/notes", async (req, res) => {
    if (typeof req.body?.title !== "string") {
      return res.status(400).json({ error: "title is required" });
    }
    res.status(201).json(await notes.create(req.body));
  });
  return app;
}

describe("Notes API", () => {
  let api;

  beforeEach(() => {
    // a fresh app with an empty repository for every test
    api = request(createApp({ notes: createNotesRepository() }));
  });

  it("starts with no notes", async () => {
    const res = await api.get("/api/notes").expect(200);
    expect(res.body).toEqual([]);
  });

  it("creates a note and lists it", async () => {
    const res = await api
      .post("/api/notes")
      .send({ title: "Buy bamboo" })
      .expect(201);
    expect(res.body).toEqual({ id: 1, title: "Buy bamboo" });
    const list = await api.get("/api/notes");
    expect(list.body).toEqual([res.body]);
  });

  it("gives every test its own empty repository", async () => {
    const res = await api.post("/api/notes").send({ title: "Nap" });
    expect(res.body.id).toBe(1); // not 2: the last test's note is gone
  });

  it("rejects a note without a title", async () => {
    const res = await api.post("/api/notes").send({}).expect(400);
    expect(res.body.error).toBe("title is required");
  });
});
```

</CodeExample>

The third test proves the point: its note gets id **1** again, because the note from the test before it lived in a different repository. Supertest's `.expect(201)` and Vitest's `expect(...)` work together: use `.expect()` for the status and headers, and `expect` for the details of the body.

<Callout type="note" title="What to test in an API">

For each endpoint, test the **happy path** (the right status and body), **bad input** (400 with useful details), **missing things** (404), and **side effects**: after a `DELETE`, ask for the note again and check it's really gone. A test that only checks "DELETE answered 204" would pass even if nothing was deleted.

</Callout>

## Running it for real

On your computer, the Notes API is split into files, with `createApp` in one module and the server in another, so tests can import the app without starting a server:

```text
notes-api/
├── package.json
├── src/
│   ├── app.js          export function createApp({ notes }) { ... }
│   ├── notes.js        parseNote, HttpError
│   ├── repository.js   export function createNotesRepository() { ... }
│   └── server.js       createApp(...) and app.listen(port)
└── test/
    └── notes.test.js   import { createApp } from "../src/app.js";
```

```json title="package.json (scripts)"
{
  "type": "module",
  "scripts": {
    "dev": "node --watch src/server.js",
    "start": "node src/server.js",
    "test": "vitest"
  }
}
```

```bash
npm install express
npm install -D vitest supertest
npm run dev     # server on http://localhost:3000, restarts on save
npm test        # runs test/notes.test.js
```

With the server running, try it from another terminal with `curl`:

```bash
curl -X POST http://localhost:3000/api/notes \
  -H "Content-Type: application/json" \
  -d '{"title": "Buy bamboo"}'
curl "http://localhost:3000/api/notes?search=bamboo"
curl -X PATCH http://localhost:3000/api/notes/1 \
  -H "Content-Type: application/json" \
  -d '{"pinned": true}'
curl -i -X DELETE http://localhost:3000/api/notes/1
```

Your front end can call it with `fetch` too, exactly like the practice API. Stop the server and start it again, though, and every note is gone: they only lived in memory. That's the moment to write a database repository, and thanks to the repository pattern it's the **only** file you'd need to add.

```js
import express from "express";
import request from "supertest";
import { describe, it, expect, beforeEach } from "vitest";

// ---------- ready-made: don't change this part ----------

class HttpError extends Error {
  constructor(status, message, details) {
    super(message);
    this.status = status;
    this.details = details;
  }
}

function parseNote(input, { partial = false } = {}) {
  const body = input ?? {};
  const errors = [];
  const data = {};
  if (!partial || body.title !== undefined) {
    const title = body.title;
    if (typeof title !== "string" || title.trim() === "") {
      errors.push("title is required");
    } else if (title.length > 100) {
      errors.push("title must be at most 100 characters");
    } else {
      data.title = title.trim();
    }
  }
  if (body.text !== undefined) {
    if (typeof body.text !== "string") {
      errors.push("text must be a string");
    } else {
      data.text = body.text;
    }
  }
  if (body.pinned !== undefined) {
    if (typeof body.pinned !== "boolean") {
      errors.push("pinned must be true or false");
    } else {
      data.pinned = body.pinned;
    }
  }
  if (errors.length > 0) {
    throw new HttpError(400, "Invalid note", errors);
  }
  return data;
}

function createNotesRepository() {
  const notes = new Map();
  let nextId = 1;
  return {
    async list() {
      return [...notes.values()];
    },
    async get(id) {
      return notes.get(id);
    },
    async create({ title, text = "", pinned = false }) {
      const note = { id: nextId++, title, text, pinned };
      notes.set(note.id, note);
      return note;
    },
    async update(id, changes) {
      const note = notes.get(id);
      if (!note) return undefined;
      const updated = { ...note, ...changes };
      notes.set(id, updated);
      return updated;
    },
    async remove(id) {
      return notes.delete(id);
    },
  };
}

// ---------- your API ----------

function createApp({ notes }) {
  const app = express();
  app.use(express.json());
  const router = express.Router();

  async function findNote(idText) {
    const note = await notes.get(Number(idText));
    if (!note) throw new HttpError(404, "Note not found");
    return note;
  }

  router.get("/", async (req, res) => {
    let list = await notes.list();
    const search = req.query.search?.toLowerCase();
    if (search) {
      list = list.filter((note) =>
        `${note.title} ${note.text}`.toLowerCase().includes(search),
      );
    }
    res.json(list);
  });

  router.post("/", async (req, res) => {
    const note = await notes.create(parseNote(req.body));
    res.status(201).json(note);
  });

  router.get("/:id", async (req, res) => {
    res.json(await findNote(req.params.id));
  });

  router.patch("/:id", async (req, res) => {
    const changes = parseNote(req.body, { partial: true });
    const note = await findNote(req.params.id);
    res.json(await notes.update(note.id, changes));
  });

  router.delete("/:id", async (req, res) => {
    const note = await findNote(req.params.id);
    await notes.remove(note.id);
    res.sendStatus(204);
  });

  app.use("/api/notes", router);

  app.use((req, res) => {
    res.status(404).json({ error: "Not found" });
  });

  app.use((err, req, res, next) => {
    const status = err.status ?? 500;
    if (status >= 500) console.log("Server error:", err);
    res.status(status).json({
      error: status >= 500 ? "Something went wrong" : err.message,
      details: err.details,
    });
  });

  return app;
}

// ---------- tests ----------

describe("Notes API", () => {
  let api;

  beforeEach(() => {
    api = request(createApp({ notes: createNotesRepository() }));
  });

  it("creates a note", async () => {
    const res = await api
      .post("/api/notes")
      .send({ title: "Buy bamboo" })
      .expect(201);
    expect(res.body).toEqual({
      id: 1, title: "Buy bamboo", text: "", pinned: false,
    });
  });

  it("lists notes", async () => {
    await api.post("/api/notes").send({ title: "Nap" });
    const res = await api.get("/api/notes").expect(200);
    expect(res.body.map((n) => n.title)).toEqual(["Nap"]);
  });

  it("rejects a note without a title with 400", async () => {
    const res = await api
      .post("/api/notes")
      .send({ text: "No title here" })
      .expect(400);
    expect(res.body.details).toContain("title is required");
  });

  it("DELETE removes the note, so GET answers 404", async () => {
    const { body: note } = await api
      .post("/api/notes")
      .send({ title: "Temporary" });
    await api.delete(`/api/notes/${note.id}`).expect(204);
    await api.get(`/api/notes/${note.id}`).expect(404);
  });
});
```

## Recap

- Plan an API first: the resource, its **CRUD** routes, and the status code and body for each success and failure.
- The **repository pattern** hides storage behind `list/get/create/update/remove`. Make its methods `async` so a database can replace the in-memory `Map` without touching the routes. Pick ids with a counter that only goes up.
- **Parse, don't just validate**: return only the allowed fields (no mass assignment) or throw an `HttpError(400, ..., details)`. Validate before touching the data.
- Keep routes thin: a helper like `findNote` throws 404, and **one error handler** formats every error. Express 5 forwards errors from `async` handlers to it.
- `createApp({ notes })` takes its dependencies as options, so tests can pass a fresh repository.
- Test with Vitest + supertest: a fresh app in `beforeEach`, and tests for the happy path, bad input, 404s and side effects (after `DELETE`, check it's gone).
