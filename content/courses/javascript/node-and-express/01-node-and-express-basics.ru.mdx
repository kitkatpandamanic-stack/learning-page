Каждый раз, когда ваш фронтенд-код вызывает `fetch`, на другой стороне кто-то отвечает — **сервер (server)**. До сих пор вы всегда были тем, кто спрашивает. В этом модуле вы переходите на другую сторону и создаёте того, кто отвечает, — **REST API**, причём на уже знакомом вам языке. Это возможно благодаря **Node.js**, а самый популярный способ писать на нём API — **Express**. 🐼

## Что такое Node.js

**Node.js** запускает JavaScript **вне браузера**. Он берёт V8 — движок JavaScript из Chrome — и добавляет к нему то, что нужно серверу, а не веб-странице:

| В браузере | В Node.js |
| --- | --- |
| `document`, `window`, DOM | никакого DOM |
| `fetch`, `localStorage` | `fetch`, а ещё чтение и запись **файлов** (`node:fs`) |
| выполняет код, который прислал сайт | выполняет код, который выбрали **вы**, с полным доступом к компьютеру |
| один пользователь на вкладку | один процесс обслуживает **много пользователей** сразу |

Язык тот же самый: переменные, функции, классы, промисы и `async`/`await` работают точно так же. И с Node вы уже встречались: `npm` — это программа на Node, а в [уроке про npm и Git](/learn/javascript/npm-and-git) вы запускали `node hello.js`.

### Один поток, много посетителей

Сервер обрабатывает много запросов одновременно, но Node выполняет ваш JavaScript в **одном потоке (thread)**. Как так? Большую часть времени запрос **ждёт**: базу данных, файл или другой API. Пока один запрос ждёт, **цикл событий (event loop)** Node берётся за следующий — точно так же, как `await` в браузере:

<CodeExample output={`Mei: пришёл запрос
Bao: пришёл запрос
Bao: ответ отправлен через 100 мс
Mei: ответ отправлен через 300 мс
Оба посетителя обслужены`}>

```js
const wait = (ms) => new Promise((done) => setTimeout(done, ms));

async function handleRequest(name, ms) {
  console.log(`${name}: пришёл запрос`);
  await wait(ms); // как будто читаем из базы данных
  console.log(`${name}: ответ отправлен через ${ms} мс`);
}

// Два посетителя одновременно, один поток JavaScript
await Promise.all([
  handleRequest("Mei", 300),
  handleRequest("Bao", 100),
]);
console.log("Оба посетителя обслужены");
```

</CodeExample>

Быстрому запросу Bao не пришлось ждать медленный запрос Mei. Поэтому Node отлично подходит для серверов, которые много ждут (а это большинство веб-API), и поэтому его нельзя блокировать долгой **синхронной** работой: цикл, который крутится 2 секунды, замораживает сервер для **всех** посетителей.

## Настраиваем настоящий проект на Express

**Express** — небольшой фреймворк, который превращает «пришёл запрос» в «вызови вот эту мою функцию». На вашем компьютере проект начинается так:

```bash
mkdir notes-api
cd notes-api
npm init -y
npm pkg set type=module   # использовать import/export (ES-модули)
npm install express
```

`"type": "module"` в `package.json` разрешает `import`/`export` — те самые [модули](/learn/javascript/modules), которые вы уже знаете. Теперь создайте сервер:

```js title="server.js"
import express from "express";

const app = express();

app.get("/", (req, res) => {
  res.send("Привет от сервера панд!");
});

app.listen(3000, () => {
  console.log("Сервер слушает http://localhost:3000");
});
```

```bash
node server.js            # запустить сервер (Ctrl+C останавливает)
node --watch server.js    # перезапускать при каждом сохранении
curl http://localhost:3000
```

Откройте `http://localhost:3000` в браузере — и увидите приветствие. Сервер продолжает работать и ждать запросов, пока вы его не остановите.

<Callout type="note" title="Как Express работает в этих уроках">

Редактор PandaDev работает в вашем браузере, а браузер не может открыть настоящий серверный порт. Поэтому `import express from "express"` здесь даёт версию, **совместимую с Express 5**, которая работает без сети: `app.listen()` просто вызывает свой колбэк, а запросы вы отправляете через **supertest** — тот же инструмент, которым настоящие проекты тестируют свои API. Маршруты, middleware и обработчики пишутся ровно так же, как в реальном проекте. Команды для вашего компьютера показаны в блоках `bash`.

</Callout>

## Ваше первое приложение на Express

Приложение на Express — это список **маршрутов (routes)**. Каждый маршрут — это HTTP-**метод** (`get`, `post`, `put`, `patch`, `delete`), **путь (path)** и функция-**обработчик (handler)**, которая получает два объекта:

- **`req`** (запрос, request): то, что прислал клиент, — путь, строка запроса, заголовки и тело.
- **`res`** (ответ, response): то, что вы отправляете обратно, с помощниками вроде `res.send()` и `res.json()`.

`request(app).get("/")` из supertest отправляет GET-запрос прямо в ваше приложение и возвращает ответ:

<CodeExample output={`200 Привет от сервера панд!
200 { status: 'ok', pandas: 3 }
application/json; charset=utf-8
404 Cannot GET /api/nope`}>

```js
import express from "express";
import request from "supertest";

const app = express();

app.get("/", (req, res) => {
  res.send("Привет от сервера панд!");
});

app.get("/api/health", (req, res) => {
  res.json({ status: "ok", pandas: 3 });
});

const home = await request(app).get("/");
console.log(home.status, home.text);

const health = await request(app).get("/api/health");
console.log(health.status, health.body);
console.log(health.headers["content-type"]);

const missing = await request(app).get("/api/nope");
console.log(missing.status, missing.text);
```

</CodeExample>

- `res.send("text")` отправляет текст (как HTML). `res.json(value)` превращает любое значение в JSON и ставит заголовок `Content-Type` в `application/json`. API почти всегда используют `res.json`.
- На стороне теста `res.text` — это «сырой» текст ответа, а `res.body` — разобранный JSON.
- Если ни один маршрут не подошёл, Express отвечает **404** с текстом `Cannot GET /api/nope`.

Express проверяет маршруты **сверху вниз**, и запрос обрабатывает первый маршрут, у которого совпали метод и путь.

### Читаем запрос

В `req` есть всё, что прислал клиент. Чаще всего вам понадобятся вот эти части:

<CodeExample output={`GET /hello { lang: 'en' }
User-Agent: PandaBrowser/1.0
200 { message: 'Привет!' } yes`}>

```js
import express from "express";
import request from "supertest";

const app = express();

app.get("/hello", (req, res) => {
  console.log(req.method, req.path, req.query);
  console.log("User-Agent:", req.get("User-Agent"));
  res.set("X-Panda", "yes"); // заголовок ответа
  res.json({ message: "Привет!" });
});

const res = await request(app)
  .get("/hello?lang=en")
  .set("User-Agent", "PandaBrowser/1.0"); // заголовок запроса
console.log(res.status, res.body, res.headers["x-panda"]);
```

</CodeExample>

`req.get(name)` читает **заголовок (header)** запроса (регистр букв не важен), а `res.set(name, value)` добавляет заголовок к ответу. На стороне supertest `.set()` добавляет заголовок к запросу.

## Коды ответа

У каждого ответа есть **код ответа (status code)**, который сообщает клиенту, что произошло, ещё до того, как тот заглянет в тело. Express использует **200 OK**, если вы не указали другое через `res.status(code)`:

| Код | Значение | Когда обычно используют |
| --- | --- | --- |
| 200 | OK | успешный GET, PATCH или PUT |
| 201 | Created | POST, который что-то создал |
| 204 | No Content | успешный DELETE (без тела) |
| 400 | Bad Request | клиент прислал некорректные данные |
| 401 / 403 | Unauthorized / Forbidden | не вошёл в систему / нет доступа |
| 404 | Not Found | нет такого маршрута или элемента |
| 500 | Internal Server Error | баг или падение на сервере |

<CodeExample output={`201 { id: 2, name: 'Bao' }
204 ""
404 { error: 'Panda not found' }
[ { id: 2, name: 'Bao' } ]`}>

```js
import express from "express";
import request from "supertest";

const app = express();
app.use(express.json()); // читает JSON-тела (подробнее в следующем уроке)

const pandas = [{ id: 1, name: "Mei" }];
let nextId = 2;

app.post("/pandas", (req, res) => {
  const panda = { id: nextId++, name: req.body.name };
  pandas.push(panda);
  res.status(201).json(panda);
});

app.delete("/pandas/:id", (req, res) => {
  const index = pandas.findIndex(
    (p) => p.id === Number(req.params.id),
  );
  if (index === -1) {
    return res.status(404).json({ error: "Panda not found" });
  }
  pandas.splice(index, 1);
  res.sendStatus(204);
});

const created = await request(app)
  .post("/pandas")
  .send({ name: "Bao" });
console.log(created.status, created.body);

const deleted = await request(app).delete("/pandas/1");
console.log(deleted.status, JSON.stringify(deleted.text));

const again = await request(app).delete("/pandas/1");
console.log(again.status, again.body);
console.log(pandas);
```

</CodeExample>

- `res.status(201).json(panda)`: `status()` возвращает `res`, поэтому следующий вызов можно приписать цепочкой.
- `res.sendStatus(204)` отправляет только код. У ответа 204 никогда не бывает тела, поэтому `deleted.text` пустой.
- В supertest `.send({ ... })` отправляет JSON-тело. На настоящем сервере то же самое делает `fetch` с `method: "POST"` и JSON-телом.
- Обратите внимание на ранний `return` перед 404. Без него обработчик продолжил бы работу и попытался ответить **дважды**.

<Callout type="danger" title="Один запрос — один ответ">

Каждый запрос получает **ровно один** ответ. Если вы забудете `return` и код вызовет `res.json()` второй раз, клиент получит первый ответ, а Node сообщит об ошибке:

```bash
Error [ERR_HTTP_HEADERS_SENT]: Cannot set headers after they are sent to the client
```

А если обработчик вообще не ответит, клиент будет просто ждать, пока ему не надоест. Следите, чтобы каждый путь через обработчик заканчивался ровно одним вызовом `res.json()`, `res.send()`, `res.sendStatus()` или `res.end()`.

</Callout>

## Параметры маршрута и строка запроса

Передать информацию в URL можно двумя способами, и API используют оба:

- **Параметры маршрута (route params)** указывают, **какой именно** элемент нужен: `/movies/2`. Их объявляют двоеточием в пути, `/movies/:id`, и читают из `req.params.id`.
- **Строка запроса (query string)** **фильтрует или настраивает** список: `/movies?genre=comedy&after=2010`. Express разбирает её в `req.query`.

<CodeExample output={`200 [ 'Kung Fu Panda', 'Spirited Away', 'Paddington 2' ]
200 [ 'Kung Fu Panda', 'Paddington 2' ]
200 [ 'Paddington 2' ]
params: { id: '2' }
200 { id: 2, title: 'Spirited Away', year: 2001, genre: 'fantasy' }
params: { id: '42' }
404 { error: 'Movie not found' }`}>

```js
import express from "express";
import request from "supertest";

const movies = [
  { id: 1, title: "Kung Fu Panda", year: 2008, genre: "comedy" },
  { id: 2, title: "Spirited Away", year: 2001, genre: "fantasy" },
  { id: 3, title: "Paddington 2", year: 2017, genre: "comedy" },
];

const app = express();

app.get("/movies", (req, res) => {
  const { genre, after } = req.query;
  let results = movies;
  if (genre) {
    results = results.filter((m) => m.genre === genre);
  }
  if (after) {
    results = results.filter((m) => m.year > Number(after));
  }
  res.json(results.map((m) => m.title));
});

app.get("/movies/:id", (req, res) => {
  console.log("params:", req.params);
  const id = Number(req.params.id);
  const movie = movies.find((m) => m.id === id);
  if (!movie) {
    return res.status(404).json({ error: "Movie not found" });
  }
  res.json(movie);
});

const urls = [
  "/movies",
  "/movies?genre=comedy",
  "/movies?genre=comedy&after=2010",
  "/movies/2",
  "/movies/42",
];
for (const url of urls) {
  const res = await request(app).get(url);
  console.log(res.status, res.body);
}
```

</CodeExample>

Параметры строки запроса **необязательны**: если клиент какой-то не передал, в `req.query` он просто `undefined`, и `if` пропускает этот фильтр. Так один маршрут обслуживает и «все фильмы», и «комедии после 2010 года».

<Callout type="warning" title="Параметры и значения из строки запроса — всегда строки">

URL — это текст, поэтому `req.params.id` — это **строка** `"2"`, а не число `2`. Это одна из самых частых ошибок в Express:

```js
app.get("/notes/:id", (req, res) => {
  console.log(typeof req.params.id); // "string"
  // ❌ никогда не совпадёт: "1" === 1 — это false
  const note = notes.find((n) => n.id === req.params.id);
  // ✅ сначала преобразуйте
  const fixed = notes.find((n) => n.id === Number(req.params.id));
});
```

То же самое с `req.query`: `?after=2010` даёт `"2010"`. Преобразуйте через `Number()`, прежде чем сравнивать или считать.

</Callout>

## Тестируем API через supertest

Пока мы просто печатали ответы. В реальных проектах API **тестируют** точно так же — через supertest внутри Vitest (`npm install -D vitest supertest`). Supertest добавляет удобные проверки `.expect()` для кода ответа и заголовков, а `expect` из Vitest проверяет тело:

<CodeExample output={`✓ GET /movies/:id > возвращает один фильм в формате JSON
✓ GET /movies/:id > отвечает 404 на неизвестный id
✓ GET /movies/:id > отвечает 404 на id, который не число

Tests  3 passed (3)`}>

```js
import express from "express";
import request from "supertest";
import { describe, it, expect } from "vitest";

const movies = [
  { id: 1, title: "Kung Fu Panda", year: 2008 },
  { id: 2, title: "Spirited Away", year: 2001 },
];

const app = express();
app.get("/movies/:id", (req, res) => {
  const movie = movies.find((m) => m.id === Number(req.params.id));
  if (!movie) {
    return res.status(404).json({ error: "Movie not found" });
  }
  res.json(movie);
});

describe("GET /movies/:id", () => {
  it("возвращает один фильм в формате JSON", async () => {
    const res = await request(app)
      .get("/movies/2")
      .expect(200)
      .expect("Content-Type", /json/);
    expect(res.body.title).toBe("Spirited Away");
  });

  it("отвечает 404 на неизвестный id", async () => {
    const res = await request(app).get("/movies/99");
    expect(res.status).toBe(404);
    expect(res.body).toEqual({ error: "Movie not found" });
  });

  it("отвечает 404 на id, который не число", async () => {
    await request(app).get("/movies/abc").expect(404);
  });
});
```

</CodeExample>

Supertest обращается к приложению **напрямую**, не запуская сервер и не открывая порт. Поэтому тесты API быстрые и им не нужен `app.listen()`. Полноценный набор тестов вы напишете в мини-проекте «API заметок» в конце модуля.

Заповеднику панд нужен небольшой API для сайта. Данные и приложение готовы — добавьте три маршрута:

1. `GET /health` отвечает `{ status: "ok" }`. (У настоящих серверов есть такой маршрут проверки «здоровья», чтобы системы мониторинга могли убедиться, что сервер жив.)
2. `GET /pandas` отвечает массивом панд. Его фильтруют два **необязательных** параметра строки запроса, и их можно использовать вместе:
   - `?food=bamboo` оставляет только панд, у которых `food` равно `bamboo`;
   - `?minAge=4` оставляет только панд, у которых `age` **4 или больше**.
3. `GET /pandas/:id` отвечает одной пандой. Если панды с таким id нет, ответьте **404** с `{ error: "Panda not found" }`.

Пробуйте свои маршруты с помощью строк внизу. Проверки ещё и добавляют в массив новую панду, так что не прописывайте результаты вручную.

Начните `GET /pandas` с `let results = pandas;` и сужайте выборку: `if (food) { results = results.filter((p) => p.food === food); }`, и то же самое для `minAge` с условием `p.age >= Number(minAge)`. Для одной панды сравнивайте `p.id === Number(req.params.id)` и не забудьте `return` перед `res.status(404).json(...)`.

</Hint>

<Solution>

```js
import express from "express";
import request from "supertest";

const pandas = [
  { id: 1, name: "Mei", age: 4, food: "bamboo" },
  { id: 2, name: "Bao", age: 1, food: "apples" },
  { id: 3, name: "Lin", age: 9, food: "bamboo" },
];

const app = express();

app.get("/health", (req, res) => {
  res.json({ status: "ok" });
});

app.get("/pandas", (req, res) => {
  const { food, minAge } = req.query;
  let results = pandas;
  if (food) {
    results = results.filter((p) => p.food === food);
  }
  if (minAge) {
    results = results.filter((p) => p.age >= Number(minAge));
  }
  res.json(results);
});

app.get("/pandas/:id", (req, res) => {
  const panda = pandas.find((p) => p.id === Number(req.params.id));
  if (!panda) {
    return res.status(404).json({ error: "Panda not found" });
  }
  res.json(panda);
});

// Попробуйте свой API здесь:
const res = await request(app).get("/pandas/2");
console.log(res.status, res.body);
```

## Итоги

- **Node.js** запускает JavaScript вне браузера. Один поток обслуживает много запросов, потому что, пока один ждёт, **цикл событий** занимается другими; не блокируйте его долгой синхронной работой.
- Настоящий проект: `npm init -y`, `npm pkg set type=module`, `npm install express`, затем `node server.js` (или `node --watch server.js`) запускает сервер, который `app.listen(3000)` держит включённым.
- Маршрут — это метод + путь + обработчик `(req, res) => { ... }`. Express перебирает их сверху вниз; если ничего не подошло — **404** `Cannot GET /path`.
- Отвечайте через `res.json(value)`, задавайте код через `res.status(201)`, а для «готово, отправлять нечего» используйте `res.sendStatus(204)`. Каждый запрос получает **ровно один** ответ, поэтому ставьте `return` после раннего ответа.
- `/movies/:id` → `req.params.id`; `?genre=comedy` → `req.query.genre`. И то и другое — **строки**: преобразуйте через `Number()`.
- Тестируйте API через **supertest**: `await request(app).get("/movies/2").expect(200)`, а затем проверяйте `res.status` и `res.body` средствами Vitest.
