Every programmer sees errors every single day, including the professionals. An error message isn't the computer telling you off. It's a **clue** that says *what* went wrong and *where*. Learning to read errors calmly is one of the most useful skills you can have.

## The anatomy of an error

Here's a small bug. We forgot to pass a word to `shout`:

```js title="app.js"
function shout(word) {
  return word.toUpperCase() + "!";
}

shout();
```

In the browser console, it produces this:

```text
Uncaught TypeError: Cannot read properties of undefined (reading 'toUpperCase')
    at shout (app.js:2:15)
    at app.js:5:1
```

Let's take it apart:

- **Name**: `TypeError` is the *kind* of error. Each kind has typical causes, as you'll see below.
- **Message**: `Cannot read properties of undefined (reading 'toUpperCase')` says exactly what went wrong. We tried to call `.toUpperCase()` on something that was `undefined`.
- **Location**: `app.js:2:15` means file `app.js`, line **2**, column 15.
- **Stack trace**: the `at ...` lines show the chain of calls that led there, newest first. The error happened inside `shout`, which was called from line 5.

When an error isn't handled, the program **stops** at that line. Nothing after it runs:

<CodeExample output={`Starting...
ReferenceError: scroe is not defined`}>

```js
const score = 10;
console.log("Starting...");
console.log(scroe);
console.log("This line never runs");
```

</CodeExample>

In these lessons, errors appear in the output as `Name: message`, together with the line number.

## ReferenceError: a name JavaScript doesn't know

A **ReferenceError** means you used a variable or function name that doesn't exist where you're using it. Typical causes:

- A **typo**: `scroe` instead of `score`, or `Console.log` instead of `console.log`. Names are case-sensitive!
- Using a variable **outside its scope**, such as one declared inside a different function.
- Using a variable **before** the line that creates it:

<CodeExample output="ReferenceError: Cannot access 'total' before initialization">

```js
console.log(total);
const total = 5;
```

</CodeExample>

**Fix:** check the spelling carefully, and make sure the variable is declared earlier and in a scope you can see.

## TypeError: the wrong kind of value

A **TypeError** means the name exists, but its value can't do what you asked. This is the error you'll meet most often:

<CodeExample output="TypeError: Cannot read properties of undefined (reading 'name')">

```js
const users = [{ name: "Mei" }, { name: "Sam" }];
console.log(users[2].name); // there is no users[2]!
```

</CodeExample>

`users[2]` is `undefined`, and `undefined` has no properties. The message tells you which property you tried to read (`'name'`), so look at whatever comes **before** `.name`.

<CodeExample output="TypeError: user.getName is not a function">

```js
const user = { name: "Mei" };
console.log(user.getName());
```

</CodeExample>

| Message                                            | It usually means…                                                       |
| -------------------------------------------------- | ----------------------------------------------------------------------- |
| `Cannot read properties of undefined (reading 'x')` | The thing before `.x` is `undefined`: a missing item, a typo in a property name, or a function that didn't `return` |
| `x is not a function`                              | A typo in a method name, or calling something that isn't a function     |
| `x is not iterable`                                | `for...of` over something that isn't an array or string                 |
| `Assignment to constant variable.`                 | Changing a `const`; use `let` if it really needs to change              |

## SyntaxError: code JavaScript can't read

A **SyntaxError** means your code breaks the grammar rules of JavaScript: a missing bracket, quote or comma. JavaScript checks the whole program **before** running it, so with a syntax error nothing runs at all, not even the lines above it:

<CodeExample output="SyntaxError: missing ) after argument list">

```js
console.log("Start");
console.log("Hello";
```

</CodeExample>

**Fix:** look at the reported line and the line just before it. Count your brackets and quotes. Your code editor helps here too: it colours matching brackets and underlines mistakes in red.

## RangeError: a value outside the allowed range

A **RangeError** means a number was outside the range a function accepts:

<CodeExample output="RangeError: Invalid count value: -1">

```js
const line = "-".repeat(-1); // can't repeat -1 times!
console.log(line);
```

</CodeExample>

The RangeError you're most likely to meet is `Maximum call stack size exceeded`. It means a function calls itself (or two functions call each other) forever, until JavaScript runs out of room to keep track:

```js
function countdown(n) {
  console.log(n);
  countdown(n - 1); // never stops!
}
```

<Callout type="tip" title="How to read any error">

1. Read the **name** and the **message**, slowly. They usually tell you exactly what's wrong.
2. Go to the **line number**.
3. Ask: which value on that line could be `undefined`, misspelled or the wrong type?
4. Still stuck? Search for the message (without your own variable names). Someone has almost certainly had the same problem.

Error messages are worded slightly differently in different browsers, but the error **names** are always the same.

</Callout>

## Debugging with console.log

Some bugs don't crash. The program runs happily but gives the **wrong answer**. To find these, print values along the way and compare them with what you expected:

<CodeExample output={`total: 90 count: 4
22.5`}>

```js
function average(numbers) {
  let total = 0;
  for (let i = 1; i < numbers.length; i++) {
    total += numbers[i];
  }
  console.log("total:", total, "count:", numbers.length);
  return total / numbers.length;
}

console.log(average([10, 20, 30, 40])); // expected 25
```

</CodeExample>

The total should be `100`, but the log shows `90`. The first number is missing, and the culprit is `let i = 1`: indexes start at `0`! Tips for logging:

- **Label** your logs (`"total:"`) so you know which value is which.
- Log **inside** loops to watch a value change step by step.
- Delete debugging logs once the bug is fixed.

For arrays of objects, `console.table` is even better. In the browser console it draws a proper table with a row per item and a column per property. (In these lessons it prints like `console.log`.)

<CodeExample output="[ { name: 'Mei', score: 72 }, { name: 'Sam', score: 95 } ]">

```js
const results = [
  { name: "Mei", score: 72 },
  { name: "Sam", score: 95 },
];

console.table(results);
```

</CodeExample>

## Breakpoints and the debugger

For trickier bugs, browsers have a built-in **debugger** that can pause your program and let you look around. Open **DevTools** (`F12`, or `Cmd + Option + I` on a Mac) and go to the **Sources** tab (called **Debugger** in Firefox):

1. Open your file and click a **line number** to set a **breakpoint** (a blue or red marker).
2. Run the code again (for example, reload the page). It **pauses** just before that line.
3. Hover over variables, or check the **Scope** panel, to see their current values.
4. Use **Step over** to run one line at a time, and **Resume** to carry on.

You can also pause from inside your code with the `debugger` statement:

```js
function applyDiscount(price, percent) {
  debugger; // pauses here, but only while DevTools is open
  return price - (price * percent) / 100;
}
```

<Callout type="note">

The lesson editor ignores `debugger`, so try it in your browser's DevTools on a real page. Remember to remove `debugger` lines before you share your code!

</Callout>

## Recap

- An error has a **name**, a **message** and a **location** (file, line and column). The stack trace shows how the code got there.
- **ReferenceError**: unknown name (typo, wrong scope or used too early).
- **TypeError**: wrong kind of value, often `undefined` where you expected an object or function.
- **SyntaxError**: broken grammar, so nothing runs at all.
- **RangeError**: a value outside the allowed range.
- Use labelled `console.log`s, `console.table` and DevTools breakpoints (or `debugger`) to find bugs that don't crash.
