В прошлом уроке каждая ошибка останавливала программу. Это как раз то, что нужно, пока вы ищете баги. Но некоторые ошибки **ожидаемы**: пользователь вводит `"abc"` там, где должно быть число, сохранённые данные повреждены или сервер не отвечает. В таких случаях ошибку нужно **обработать** и продолжить работу. Именно для этого существуют `try` и `catch`.

## try и catch

Поместите рискованный код внутрь `try`. Если что-то в нём выбросит ошибку, JavaScript сразу перепрыгнет в `catch`:

<CodeExample output={`Не удалось прочитать настройки (SyntaxError)
Программа продолжает работу!`}>

```js
const text = "{ это не JSON }";

try {
  const settings = JSON.parse(text);
  console.log("Загружено:", settings); // пропускается
} catch (error) {
  console.log(`Не удалось прочитать настройки (${error.name})`);
}

console.log("Программа продолжает работу!");
```

</CodeExample>

- Если код в `try` выполняется **без** ошибок, блок `catch` пропускается.
- Если ошибка произошла, остаток `try` **пропускается**, а вместо него выполняется `catch`.
- В любом случае программа продолжается после всей конструкции `try/catch`.

## Объект ошибки

Блок `catch` получает ошибку в виде значения (мы назвали его `error`, но подойдёт любое имя). У каждого объекта ошибки есть `name` (имя) и `message` (сообщение):

<CodeExample output={`ReferenceError
missingValue is not defined
ReferenceError: missingValue is not defined`}>

```js
try {
  console.log(missingValue);
} catch (error) {
  console.log(error.name);
  console.log(error.message);
  console.log(String(error)); // и то и другое вместе
}
```

</CodeExample>

Если объект ошибки вам совсем не нужен, его можно не указывать: `try { ... } catch { ... }`.

## Выбрасываем свои ошибки

Вы можете создавать ошибки и сами — с помощью `throw`. Как и `return`, `throw` **сразу останавливает** функцию. Но вместо того чтобы вернуть значение, он выбрасывает ошибку, с которой придётся разбираться вызывающему коду:

<CodeExample output={`Error: Сумма должна быть больше 0
RangeError: Недостаточно денег: на балансе 50
Снято 20, осталось 30`}>

```js
function withdraw(balance, amount) {
  if (amount <= 0) {
    throw new Error("Сумма должна быть больше 0");
  }
  if (amount > balance) {
    throw new RangeError(`Недостаточно денег: на балансе ${balance}`);
  }
  return balance - amount;
}

for (const amount of [-5, 80, 20]) {
  try {
    const left = withdraw(50, amount);
    console.log(`Снято ${amount}, осталось ${left}`);
  } catch (error) {
    console.log(`${error.name}: ${error.message}`);
  }
}
```

</CodeExample>

`new Error("...")` создаёт ошибку общего вида. Можно использовать и встроенные типы из прошлого урока, например `TypeError` и `RangeError`, чтобы показать, *какого рода* проблема.

<Callout type="tip" title="Всегда выбрасывайте объект Error">

JavaScript позволяет написать `throw "oops"` (простую строку), но так делать не стоит. У строки нет ни `name`, ни `message`, ни трассировки стека, которая показала бы, откуда она взялась. Всегда пишите `throw new Error("oops")`.

</Callout>

## Проверка ввода

`throw` идеально подходит для проверки ввода (input). Функция громко отказывается принимать плохие данные, а вызывающий код решает, что с этим делать:

<CodeExample output={`12
Неверный возраст: "двенадцать" — не число
Неверный возраст: 150 не входит в диапазон от 0 до 130`}>

```js
function parseAge(text) {
  const age = Number(text);
  if (Number.isNaN(age)) {
    throw new TypeError(`"${text}" — не число`);
  }
  if (age < 0 || age > 130) {
    throw new RangeError(`${age} не входит в диапазон от 0 до 130`);
  }
  return age;
}

for (const input of ["12", "двенадцать", "150"]) {
  try {
    console.log(parseAge(input));
  } catch (error) {
    console.log(`Неверный возраст: ${error.message}`);
  }
}
```

</CodeExample>

`Number("двенадцать")` даёт `NaN` (*Not a Number*, «не число»), а `Number.isNaN` проверяет именно это. Такая проверка ввода называется **валидацией (validation)**, и она не даёт плохим данным вызвать запутанные баги где-нибудь позже.

## finally: код, который выполняется всегда

Блок `finally` выполняется **после** `try` и `catch` — была ошибка или нет. Это место для уборки, например чтобы спрятать индикатор загрузки:

<CodeExample output={`Сохранение...
Сохранено!
Готово
Сохранение...
Не удалось сохранить: Имя не может быть пустым
Готово`}>

```js
function save(name) {
  console.log("Сохранение...");
  try {
    if (name === "") {
      throw new Error("Имя не может быть пустым");
    }
    console.log("Сохранено!");
  } catch (error) {
    console.log(`Не удалось сохранить: ${error.message}`);
  } finally {
    console.log("Готово"); // выполняется оба раза
  }
}

save("Mei");
save("");
```

</CodeExample>

## Повторный выброс ошибок, которые вы не можете обработать

Перехватывайте только те ошибки, которые вы **ожидаете** и умеете обрабатывать. Всё остальное — скорее всего, настоящий баг, поэтому передайте его дальше с помощью `throw error`. Это называется **повторным выбросом (rethrowing)**. Чтобы проверить, какую ошибку вы поймали, используйте `instanceof`:

<CodeExample output={`Играть нельзя: Уровень должен быть не больше 10
ReferenceError: levle is not defined`}>

```js
function startLevel(level) {
  if (level > 10) {
    throw new RangeError("Уровень должен быть не больше 10");
  }
  return levle * 100; // упс, опечатка!
}

function play(level) {
  try {
    return startLevel(level);
  } catch (error) {
    if (error instanceof RangeError) {
      console.log(`Играть нельзя: ${error.message}`);
      return 0;
    }
    throw error; // это не нам обрабатывать: передаём дальше
  }
}

play(99);
play(3);
```

</CodeExample>

`play(99)` натыкается на ожидаемую `RangeError` и аккуратно её обрабатывает. `play(3)` натыкается на опечатку. Поскольку `play` выбрасывает её повторно, баг громко заявляет о себе, и вы можете его найти и исправить.

<Callout type="warning" title="Не глотайте ошибки">

Пустой `catch {}` скрывает все ошибки, включая ваши собственные баги. Тогда программа молча ломается где-то в другом месте, а такое отлаживать гораздо сложнее. Если вы перехватили ошибку, либо обработайте её как следует, либо выбросьте повторно.

</Callout>

## Ошибки в асинхронном коде

Некоторому коду приходится **ждать**: таймера, файла или ответа от сервера. Подробно вы изучите это на Уровне 2, а пока — небольшой анонс. **Promise** (промис) — это значение, которое появится *позже*. Внутри функции с `async` ключевое слово `await` ставит выполнение на паузу, пока промис не будет готов. Если промис завершается неудачей (говорят, что он **отклоняется**, rejects), `await` выбрасывает ошибку, и её ловит обычный `try/catch`:

<CodeExample output={`Загрузка Mei...
Результат Mei: 95
Завершено
Загрузка Bob...
Ошибка: Игрок Bob не найден
Завершено`}>

```js
// Ненастоящий сервер: отвечает через 100 миллисекунд
function fetchScore(player) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (player === "Mei") {
        resolve(95);
      } else {
        reject(new Error(`Игрок ${player} не найден`));
      }
    }, 100);
  });
}

async function showScore(player) {
  try {
    console.log(`Загрузка ${player}...`);
    const score = await fetchScore(player);
    console.log(`Результат ${player}: ${score}`);
  } catch (error) {
    console.log(`Ошибка: ${error.message}`);
  } finally {
    console.log("Завершено");
  }
}

await showScore("Mei");
await showScore("Bob");
```

</CodeExample>

В двух последних строках `await` используется вне какой-либо функции. Это называется **await верхнего уровня (top-level await)**. Он работает в этих уроках, в консоли браузера и в **модулях (modules)** JavaScript (с ними вы познакомитесь позже на этом уровне), но не в старых обычных скриптах.

<Callout type="danger" title="try/catch не дотянется до будущего">

Блок `try` вокруг `setTimeout` **не** перехватывает ошибки, выброшенные внутри колбэка таймера. К тому моменту, когда колбэк запустится, блок `try` давно завершится:

```js
try {
  setTimeout(() => {
    throw new Error("Слишком поздно!"); // НЕ перехватывается ниже
  }, 100);
} catch (error) {
  console.log("Это никогда не выполнится");
}
```

Поместите `try/catch` **внутрь** колбэка или оберните таймер в Promise и используйте `await`, как показано выше.

</Callout>

## Анонс: собственные классы ошибок

Большие программы часто создают собственные типы ошибок, чтобы отличать их друг от друга с помощью `instanceof`. Для этого используются **классы (classes)**, которые вы изучите в модуле «Классы и ООП», так что пока просто полюбуйтесь:

<CodeExample output={`ValidationError: Email должен содержать @
true`}>

```js
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}

try {
  throw new ValidationError("Email должен содержать @");
} catch (error) {
  console.log(`${error.name}: ${error.message}`);
  console.log(error instanceof ValidationError);
}
```

</CodeExample>

   - иначе верните число.
2. `safeQuantity(text)` вызывает `parseQuantity` внутри `try/catch`. Если всё получилось, верните количество. Если выброшена ошибка, выведите `Неверный ввод: ` и следом сообщение ошибки, а затем верните `1` как разумное значение по умолчанию.

<Hint>

`Number.isInteger(n)` возвращает `false` и для дробей, **и** для `NaN`, так что одна проверка покрывает и `"много"`, и `"2.5"`. Ошибку выбрасывайте так: `throw new TypeError("...")`. В блоке `catch` используйте `` `Неверный ввод: ${error.message}` ``.

```js
function parseQuantity(text) {
  const quantity = Number(text);
  if (!Number.isInteger(quantity)) {
    throw new TypeError("Количество должно быть целым числом");
  }
  if (quantity < 1 || quantity > 99) {
    throw new RangeError("Количество должно быть от 1 до 99");
  }
  return quantity;
}

function safeQuantity(text) {
  try {
    return parseQuantity(text);
  } catch (error) {
    console.log(`Неверный ввод: ${error.message}`);
    return 1;
  }
}

console.log(safeQuantity("3"));     // 3
console.log(safeQuantity("много")); // Неверный ввод: ..., затем 1
console.log(safeQuantity("500"));   // Неверный ввод: ..., затем 1
```

## Итоги

- `try { ... } catch (error) { ... }` обрабатывает ошибки, чтобы программа могла продолжить работу.
- У каждой ошибки есть `name` и `message`.
- `throw new Error("...")` (или `TypeError`, `RangeError`…) останавливает функцию и сообщает о проблеме; используйте это для проверки ввода.
- `finally` выполняется всегда, с ошибкой или без, поэтому идеально подходит для уборки.
- Перехватывайте только то, что можете обработать, а всё остальное выбрасывайте повторно через `throw error`.
- С `async`/`await` отклонённый промис выбрасывает ошибку на строке с `await`, поэтому оборачивайте его в `try/catch`. `try` вокруг `setTimeout` не может перехватить ошибки внутри колбэка.
