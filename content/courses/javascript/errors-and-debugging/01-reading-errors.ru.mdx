Каждый программист видит ошибки каждый день, и профессионалы тоже. Сообщение об ошибке (error) — это не выговор от компьютера. Это **подсказка**, которая говорит, *что* пошло не так и *где*. Умение спокойно читать ошибки — один из самых полезных навыков программиста.

## Из чего состоит ошибка

Вот небольшой баг. Мы забыли передать слово в функцию `shout`:

```js title="app.js"
function shout(word) {
  return word.toUpperCase() + "!";
}

shout();
```

В консоли (console) браузера получится вот что:

```text
Uncaught TypeError: Cannot read properties of undefined (reading 'toUpperCase')
    at shout (app.js:2:15)
    at app.js:5:1
```

Разберём по частям:

- **Имя (name)**: `TypeError` — это *вид* ошибки. У каждого вида есть типичные причины, ниже вы их увидите.
- **Сообщение (message)**: `Cannot read properties of undefined (reading 'toUpperCase')` — «не удаётся прочитать свойства undefined (чтение 'toUpperCase')». Оно точно описывает, что пошло не так: мы попытались вызвать `.toUpperCase()` у чего-то, что оказалось `undefined`.
- **Место**: `app.js:2:15` означает файл `app.js`, строка **2**, столбец 15.
- **Трассировка стека (stack trace)**: строки `at ...` показывают цепочку вызовов, которая привела к ошибке, — от самого нового к старому. Ошибка произошла внутри `shout`, а её вызвали из строки 5.

Если ошибку не обработать, программа **останавливается** на этой строке. Всё, что после неё, не выполняется:

<CodeExample output={`Запуск...
ReferenceError: scroe is not defined`}>

```js
const score = 10;
console.log("Запуск...");
console.log(scroe);
console.log("Эта строка не выполнится");
```

</CodeExample>

В этих уроках ошибки появляются в выводе в виде `Имя: сообщение` вместе с номером строки.

## ReferenceError: имя, которого JavaScript не знает

**ReferenceError** означает, что вы использовали имя переменной или функции, которого нет там, где вы его используете. Типичные причины:

- **Опечатка**: `scroe` вместо `score` или `Console.log` вместо `console.log`. Регистр в именах важен!
- Использование переменной **вне её области видимости (scope)**, например переменной, объявленной внутри другой функции.
- Использование переменной **до** строки, в которой она создаётся:

<CodeExample output="ReferenceError: Cannot access 'total' before initialization">

```js
console.log(total);
const total = 5;
```

</CodeExample>

**Как исправить:** внимательно проверьте написание и убедитесь, что переменная объявлена раньше и в той области видимости, откуда вы к ней обращаетесь.

## TypeError: значение не того вида

**TypeError** означает, что имя существует, но его значение не может сделать то, что вы просите. Эту ошибку вы будете встречать чаще всего:

<CodeExample output="TypeError: Cannot read properties of undefined (reading 'name')">

```js
const users = [{ name: "Mei" }, { name: "Sam" }];
console.log(users[2].name); // users[2] не существует!
```

</CodeExample>

`users[2]` равно `undefined`, а у `undefined` нет свойств. Сообщение подсказывает, какое свойство вы пытались прочитать (`'name'`), так что смотрите на то, что стоит **перед** `.name`.

<CodeExample output="TypeError: user.getName is not a function">

```js
const user = { name: "Mei" };
console.log(user.getName());
```

</CodeExample>

| Сообщение                                          | Обычно это значит…                                                      |
| -------------------------------------------------- | ----------------------------------------------------------------------- |
| `Cannot read properties of undefined (reading 'x')` | То, что перед `.x`, равно `undefined`: элемента нет, опечатка в имени свойства или функция ничего не вернула через `return` |
| `x is not a function`                              | Опечатка в имени метода или попытка вызвать то, что не является функцией |
| `x is not iterable`                                | `for...of` по тому, что не является массивом или строкой                |
| `Assignment to constant variable.`                 | Изменение `const`; если значение действительно должно меняться, используйте `let` |

## SyntaxError: код, который JavaScript не может прочитать

**SyntaxError** означает, что код нарушает правила грамматики JavaScript: не хватает скобки, кавычки или запятой. JavaScript проверяет всю программу **до** запуска, поэтому при синтаксической ошибке не выполняется вообще ничего — даже строки выше:

<CodeExample output="SyntaxError: missing ) after argument list">

```js
console.log("Старт");
console.log("Привет";
```

</CodeExample>

**Как исправить:** посмотрите на указанную строку и на строку перед ней. Пересчитайте скобки и кавычки. Тут помогает и редактор кода: он подсвечивает парные скобки и подчёркивает ошибки красным.

## RangeError: значение вне допустимого диапазона

**RangeError** означает, что число вышло за пределы диапазона, который принимает функция:

<CodeExample output="RangeError: Invalid count value: -1">

```js
const line = "-".repeat(-1); // нельзя повторить -1 раз!
console.log(line);
```

</CodeExample>

Чаще всего вам встретится RangeError `Maximum call stack size exceeded` («превышен максимальный размер стека вызовов»). Она означает, что функция вызывает саму себя (или две функции вызывают друг друга) бесконечно, пока у JavaScript не кончится место для учёта вызовов:

```js
function countdown(n) {
  console.log(n);
  countdown(n - 1); // никогда не останавливается!
}
```

<Callout type="tip" title="Как читать любую ошибку">

1. Медленно прочитайте **имя** и **сообщение**. Обычно они точно говорят, что не так.
2. Перейдите к **номеру строки**.
3. Спросите себя: какое значение в этой строке может быть `undefined`, написано с опечаткой или имеет не тот тип?
4. Всё ещё не получается? Поищите сообщение в интернете (без имён ваших переменных). Почти наверняка кто-то уже сталкивался с той же проблемой.

В разных браузерах сообщения об ошибках сформулированы немного по-разному, но **имена** ошибок всегда одинаковые.

</Callout>

## Отладка с помощью console.log

Некоторые баги не приводят к падению. Программа спокойно работает, но выдаёт **неправильный ответ**. Чтобы найти такие баги, выводите значения по ходу работы и сравнивайте их с ожидаемыми. Это и есть **отладка (debugging)**:

<CodeExample output={`сумма: 90 количество: 4
22.5`}>

```js
function average(numbers) {
  let total = 0;
  for (let i = 1; i < numbers.length; i++) {
    total += numbers[i];
  }
  console.log("сумма:", total, "количество:", numbers.length);
  return total / numbers.length;
}

console.log(average([10, 20, 30, 40])); // ожидаем 25
```

</CodeExample>

Сумма должна быть `100`, но в выводе `90`. Первое число потерялось, и виновник — `let i = 1`: индексы начинаются с `0`! Советы по выводу в консоль:

- **Подписывайте** вывод (`"сумма:"`), чтобы понимать, где какое значение.
- Выводите значения **внутри** циклов, чтобы следить, как они меняются шаг за шагом.
- Удаляйте отладочный вывод, когда баг исправлен.

Для массивов объектов ещё лучше подходит `console.table`. В консоли браузера он рисует настоящую таблицу: строка на каждый элемент и столбец на каждое свойство. (В этих уроках он печатает так же, как `console.log`.)

<CodeExample output="[ { name: 'Mei', score: 72 }, { name: 'Sam', score: 95 } ]">

```js
const results = [
  { name: "Mei", score: 72 },
  { name: "Sam", score: 95 },
];

console.table(results);
```

</CodeExample>

## Точки останова и отладчик

Для хитрых багов в браузерах есть встроенный **отладчик (debugger)**, который умеет ставить программу на паузу и давать вам осмотреться. Откройте **DevTools** (`F12` или `Cmd + Option + I` на Mac) и перейдите на вкладку **Sources** (в Firefox она называется **Debugger**):

1. Откройте свой файл и щёлкните по **номеру строки**, чтобы поставить **точку останова (breakpoint)** — синюю или красную метку.
2. Запустите код снова (например, перезагрузите страницу). Он **остановится** прямо перед этой строкой.
3. Наведите курсор на переменные или загляните в панель **Scope**, чтобы увидеть их текущие значения.
4. Кнопка **Step over** выполняет по одной строке за раз, а **Resume** продолжает работу.

Поставить паузу можно и прямо из кода — инструкцией `debugger`:

```js
function applyDiscount(price, percent) {
  debugger; // пауза здесь, но только когда открыты DevTools
  return price - (price * percent) / 100;
}
```

<Callout type="note">

Редактор в уроках игнорирует `debugger`, поэтому попробуйте его в DevTools вашего браузера на настоящей странице. И не забудьте удалить строки с `debugger`, прежде чем делиться кодом!

</Callout>

## Итоги

- У ошибки есть **имя**, **сообщение** и **место** (файл, строка и столбец). Трассировка стека показывает, как код туда попал.
- **ReferenceError**: неизвестное имя (опечатка, не та область видимости или использование слишком рано).
- **TypeError**: значение не того вида — часто `undefined` там, где вы ждали объект или функцию.
- **SyntaxError**: нарушена грамматика, поэтому не выполняется вообще ничего.
- **RangeError**: значение вне допустимого диапазона.
- Чтобы найти баги, которые не роняют программу, используйте подписанные `console.log`, `console.table` и точки останова в DevTools (или `debugger`).
