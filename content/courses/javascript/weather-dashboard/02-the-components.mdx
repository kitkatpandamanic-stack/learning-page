In Part 1 you built and tested the dashboard's foundations: `getWeather` talks to the API, and the helpers turn its numbers into friendly text. Now it gets a face. ⛅ In this part you'll build the **React components** (a search form, the current weather and the forecast) and connect them to the client, with proper **loading** and **error** states.

You'll use components, props and lists with keys from [Components and JSX](/learn/javascript/components-and-jsx), controlled forms from [State and Events](/learn/javascript/state-and-events), and effects with an `AbortController` plus the custom hook idea from the [Recipe browser](/learn/javascript/recipe-browser).

## The component plan

As in the recipe browser, sketch the components and decide where each piece of state lives before writing any JSX:

```text
App                     state: city
├── SearchForm          state: text      props: onSearch
├── (loading)           Loading...
├── (error)             😿 the message
└── (data)
    ├── CurrentWeather  props: weather
    └── ForecastList    props: forecast
```

The decisions behind it:

- **`App` owns the `city`.** It's the one value that decides what gets loaded, and `App` is where the loading happens.
- **`SearchForm` keeps its own `text`.** Half-typed text like `"Tok"` matters to nobody but the input box. The form only tells `App` when the user **submits**.
- **`CurrentWeather` and `ForecastList` have no state at all.** They show whatever they're given, so you can build them with sample data, reuse them anywhere, and they can never get out of sync with the data.

Why search on submit, when the recipe browser searched as you typed? Because a weather search only works for a **complete** city name (`"Lon"` is just a 404), and real weather APIs **count your requests**: free plans often allow around a thousand calls a day. Sending one request per keystroke would waste them on cities that don't exist.

## Step 3: loading the weather with a custom hook

Loading is the job for an **effect**: whenever `city` changes, call `getWeather`. In the recipe browser you wrote `useJson(url)`; the weather version follows the same pattern, but calls our **tested client** instead of `fetch` directly:

```jsx
const FORECAST_DAYS = 5;

function useWeather(city) {
  const [result, setResult] = useState({ city: null });

  useEffect(() => {
    if (!city) return;
    const controller = new AbortController();
    getWeather(city, {
      days: FORECAST_DAYS,
      signal: controller.signal,
    })
      .then((data) => setResult({ city, data, error: null }))
      .catch((err) => {
        if (err.name === "AbortError") return;
        setResult({ city, data: null, error: err.message });
      });
    return () => controller.abort();
  }, [city]);

  if (!city) return { data: null, error: null, loading: false };
  if (result.city !== city) {
    return { data: null, error: null, loading: true };
  }
  return { data: result.data, error: result.error, loading: false };
}
```

Every line here has a reason:

- **`getWeather` does the hard work.** The URL, the status check and the API's error message are all handled (and tested!) in the client. The hook only deals with React: state, the effect and the cleanup.
- **The cleanup aborts the old request.** Search for Tokyo and then quickly for London, and the Tokyo request is cancelled, so its late answer can never replace London's. That's the `signal` option from Part 1 paying off.
- **`AbortError` is ignored**, because a cancelled request isn't a failure the user needs to hear about.
- **`loading` is derived**, not stored: the result remembers which city it belongs to, and if that isn't the current city, the new answer hasn't arrived yet.
- **No city, no request.** An empty `city` means "nothing to load" (you'll use that for the empty state in Part 3).

The rule of thumb: **logic in plain, tested functions; React components only for showing state and handling events.**

## Step 4: putting it together

`App` holds the `city`, passes `setCity` to the form, and shows exactly **one** of the three states:

```jsx
function App() {
  const [city, setCity] = useState("London");
  const { data, loading, error } = useWeather(city);

  return (
    <main>
      <h1>🐼 Panda Weather</h1>
      <SearchForm onSearch={setCity} />
      {loading ? (
        <p className="status">Loading...</p>
      ) : error ? (
        <p className="error">😿 {error}</p>
      ) : (
        data && (
          <>
            <CurrentWeather weather={data} />
            <ForecastList forecast={data.forecast} />
          </>
        )
      )}
    </main>
  );
}
```

The `SearchForm` stays on the page in every state, so the user can always search again, even after an error. And because the error comes straight from the API (via `ApiError`), searching for a city that doesn't exist shows `😿 City not found` without any extra code.

import { useState, useEffect } from "react";
import { createRoot } from "react-dom/client";

// ---- The client from Part 1 ----
const API = "https://api.pandadev.test";

class ApiError extends Error {
  constructor(status, message) {
    super(message);
    this.name = "ApiError";
    this.status = status;
  }
}

function weatherUrl(city, days = 0) {
  const params = new URLSearchParams({ city: city.trim() });
  if (days > 0) params.set("days", days);
  return `${API}/weather?${params}`;
}

async function getWeather(
  city,
  { days = 0, signal, fetch: fetchFn = fetch } = {},
) {
  if (!city.trim()) throw new Error("Please enter a city");
  const res = await fetchFn(weatherUrl(city, days), { signal });
  const data = await res.json().catch(() => null);
  if (!res.ok) {
    const message = data?.error ?? `HTTP ${res.status}`;
    throw new ApiError(res.status, message);
  }
  return data;
}

const ICONS = {
  Sunny: "☀️",
  "Partly cloudy": "⛅",
  Cloudy: "☁️",
  Rain: "🌧️",
  Thunderstorm: "⛈️",
  Snow: "❄️",
  Fog: "🌫️",
  Windy: "💨",
};

function conditionIcon(condition) {
  return ICONS[condition] ?? "🌡️";
}

function formatTemp(celsius, unit = "C") {
  const value = unit === "F" ? (celsius * 9) / 5 + 32 : celsius;
  return `${Math.round(value)}°${unit}`;
}

function formatWind(kph, unit = "C") {
  if (unit === "F") return `${Math.round(kph / 1.609)} mph`;
  return `${kph} km/h`;
}

const DAY_NAMES = {
  Mon: "Monday",
  Tue: "Tuesday",
  Wed: "Wednesday",
  Thu: "Thursday",
  Fri: "Friday",
  Sat: "Saturday",
  Sun: "Sunday",
};

function dayLabel(day, index) {
  if (index === 0) return "Today";
  if (index === 1) return "Tomorrow";
  return DAY_NAMES[day] ?? day;
}

// ---- Loading the weather ----
const FORECAST_DAYS = 5;

function useWeather(city) {
  const [result, setResult] = useState({ city: null });

  useEffect(() => {
    if (!city) return;
    const controller = new AbortController();
    getWeather(city, {
      days: FORECAST_DAYS,
      signal: controller.signal,
    })
      .then((data) => setResult({ city, data, error: null }))
      .catch((err) => {
        if (err.name === "AbortError") return;
        setResult({ city, data: null, error: err.message });
      });
    return () => controller.abort();
  }, [city]);

  if (!city) return { data: null, error: null, loading: false };
  if (result.city !== city) {
    return { data: null, error: null, loading: true };
  }
  return { data: result.data, error: result.error, loading: false };
}

// ---- Components ----
function SearchForm({ onSearch }) {
  const [text, setText] = useState("");

  function handleSubmit(event) {
    event.preventDefault();
    if (text.trim()) onSearch(text.trim());
  }

  return (
    <form className="search" onSubmit={handleSubmit}>
      <input
        name="city"
        placeholder="Search for a city, e.g. Tokyo"
        value={text}
        onChange={(event) => setText(event.target.value)}
      />
      <button>Search</button>
    </form>
  );
}

function CurrentWeather({ weather }) {
  return (
    <section className="current">
      <h2>{weather.city}, {weather.country}</h2>
      <p className="temp">{formatTemp(weather.temperature)}</p>
      <p className="condition">
        {conditionIcon(weather.condition)} {weather.condition}
      </p>
      <ul className="details">
        <li>Feels like {formatTemp(weather.feelsLike)}</li>
        <li>Humidity {weather.humidity}%</li>
        <li>Wind {formatWind(weather.windKph)}</li>
      </ul>
    </section>
  );
}

function ForecastList({ forecast }) {
  return (
    <ol className="forecast">
      {forecast.map((day, index) => (
        <li key={day.day}>
          <span className="day">{dayLabel(day.day, index)}</span>
          <span className="icon">{conditionIcon(day.condition)}</span>
          <span className="range">
            {formatTemp(day.high)} / {formatTemp(day.low)}
          </span>
          <span className="rain">💧 {day.chanceOfRain}%</span>
        </li>
      ))}
    </ol>
  );
}

function App() {
  const [city, setCity] = useState("London");
  const { data, loading, error } = useWeather(city);

  return (
    <main>
      <h1>🐼 Panda Weather</h1>
      <SearchForm onSearch={setCity} />
      {loading ? (
        <p className="status">Loading...</p>
      ) : error ? (
        <p className="error">😿 {error}</p>
      ) : (
        data && (
          <>
            <CurrentWeather weather={data} />
            <ForecastList forecast={data.forecast} />
          </>
        )
      )}
    </main>
  );
}

createRoot(document.getElementById("root")).render(<App />);
