Your dashboard can already search and show the weather. In this last part you'll turn it into an app people would keep open: a **°C/°F switch**, **favourite cities** one click away, a list of **recent searches**, and all of it **remembered** when the page is opened again. 🌈

You'll reuse `localStorage`, JSON and `try/catch` from the Level 1 [to-do app](/learn/javascript/saving-with-localstorage), immutable array updates from [State and Events](/learn/javascript/state-and-events), and the testing habits from Part 1: the new logic goes into small, pure functions with Vitest tests before React ever sees it.

## Lists that change: pure helpers first

Recent searches and favourites are lists that change in two specific ways, and both rules are easy to get subtly wrong:

- **`addRecent(recent, city)`**: put `city` first, remove any older entry for the same city (ignoring case, so `tokyo` and `Tokyo` don't both appear) and keep at most five.
- **`toggleFavourite(favourites, city)`**: remove the city if it's there, add it if it isn't.

Both return a **new** array and never change the old one. React only re-renders when state gets a new value, and changing an array in place with `push` or `splice` would also change the "old" state that React is comparing against. `filter`, spread and `slice` all make new arrays:

```js
import { describe, it, expect } from "vitest";

const MAX_RECENT = 5;

function addRecent(recent, city) {
  const others = recent.filter(
    (name) => name.toLowerCase() !== city.toLowerCase(),
  );
  return [city, ...others].slice(0, MAX_RECENT);
}

function toggleFavourite(favourites, city) {
  if (favourites.includes(city)) {
    return favourites.filter((name) => name !== city);
  }
  return [...favourites, city];
}

console.log(addRecent(["Paris", "Tokyo"], "Cairo"));
console.log(addRecent(["Paris", "Tokyo"], "tokyo"));
console.log(toggleFavourite(["Oslo"], "Lima"));
console.log(toggleFavourite(["Oslo", "Lima"], "Oslo"));

describe("addRecent", () => {
  it("puts the new city first", () => {
    expect(addRecent(["Oslo"], "Rome")).toEqual(["Rome", "Oslo"]);
  });

  it("moves a repeated city to the front, whatever its case", () => {
    const recent = ["Oslo", "Rome", "Lima"];
    expect(addRecent(recent, "ROME")).toEqual(["ROME", "Oslo", "Lima"]);
  });

  it("keeps at most 5 cities", () => {
    const recent = ["a", "b", "c", "d", "e"];
    expect(addRecent(recent, "f")).toEqual(["f", "a", "b", "c", "d"]);
  });

  it("doesn't change the old list", () => {
    const recent = ["Oslo"];
    addRecent(recent, "Rome");
    expect(recent).toEqual(["Oslo"]);
  });
});
```

Because these are plain functions, they're tested in milliseconds, without rendering anything. The last test guards the immutability rule, which would otherwise only show up as a confusing "my list doesn't update" bug in the UI.

## Saving lists in localStorage

Saving works like the to-do app: `JSON.stringify` on the way in, `JSON.parse` on the way out, and a `try/catch` so broken data can't crash the app. One improvement: `storage` is a parameter that **defaults to `localStorage`**. The app never passes it, but tests can inject a fake, exactly like `fetch` in Part 1. (That also means these tests run here, where there's no real `localStorage`.)

<CodeExample output={`✓ loadList > reads back what saveList saved
✓ loadList > returns [] when nothing is saved
Saved favs was broken, starting fresh.
✓ loadList > returns [] when the JSON is broken
✓ loadList > returns [] when it isn't a list

Tests  4 passed (4)`}>

```js
import { describe, it, expect, beforeEach } from "vitest";

function loadList(key, storage = localStorage) {
  const saved = storage.getItem(key);
  if (saved === null) return [];
  try {
    const data = JSON.parse(saved);
    return Array.isArray(data) ? data : [];
  } catch (error) {
    console.warn(`Saved ${key} was broken, starting fresh.`);
    return [];
  }
}

function saveList(key, list, storage = localStorage) {
  storage.setItem(key, JSON.stringify(list));
}

// A fake localStorage: a Map with the same methods
function fakeStorage() {
  const data = new Map();
  return {
    getItem: (key) => data.get(key) ?? null,
    setItem: (key, value) => data.set(key, String(value)),
  };
}

describe("loadList", () => {
  let storage;
  beforeEach(() => {
    storage = fakeStorage();
  });

  it("reads back what saveList saved", () => {
    saveList("favs", ["Oslo", "Lima"], storage);
    expect(storage.getItem("favs")).toBe('["Oslo","Lima"]');
    expect(loadList("favs", storage)).toEqual(["Oslo", "Lima"]);
  });

  it.each([
    ["nothing is saved", null],
    ["the JSON is broken", "{ oops"],
    ["it isn't a list", '"Oslo"'],
  ])("returns [] when %s", (_case, saved) => {
    if (saved !== null) storage.setItem("favs", saved);
    expect(loadList("favs", storage)).toEqual([]);
  });
});
```

</CodeExample>

The warning in the middle is the app's own `console.warn`, printed while the "broken JSON" test runs. Vitest shows it too, which helps when a test fails for a reason you didn't expect.

## Loading saved data when the app starts

When `App` first renders, its state should come from storage. You could write `useState(loadList(FAVOURITES_KEY))`, but there's a catch: that line runs on **every** render, so the app would read and parse `localStorage` every time you type a letter, only for React to ignore the result (the initial value is only used once).

The fix is one new thing: pass `useState` a **function**. React calls it only for the first render, and uses what it returns as the starting value. This is called **lazy initial state**:

```jsx
// ❌ Reads localStorage on every render
const [favourites, setFavourites] = useState(loadList(FAVOURITES_KEY));

// ✅ Reads it once, for the first render
const [favourites, setFavourites] = useState(() =>
  loadList(FAVOURITES_KEY),
);
const [recent, setRecent] = useState(() => loadList(RECENT_KEY));
const [city, setCity] = useState(recent[0] ?? "");
```

The `city` starts as the **most recent search**, so reopening the dashboard shows the city you looked at last. `recent[0]` is a cheap array lookup, so it doesn't need a function. With no history at all, `?? ""` gives an empty city, and `useWeather` sends no request.

## Saving when the user acts

When should we save? Whenever the user **changes** a list: a search changes `recent`, the ☆ button changes `favourites`. Those are user actions, so, as the Effects lesson recommends, the saving goes in the **event handlers**, right next to the state update (just like `saveAndRender()` in the to-do app):

```jsx
function search(name) {
  setCity(name);
  const next = addRecent(recent, name);
  setRecent(next);
  saveList(RECENT_KEY, next);
}

function handleToggleFavourite() {
  const next = toggleFavourite(favourites, data.city);
  setFavourites(next);
  saveList(FAVOURITES_KEY, next);
}
```

Note that we calculate `next` once and use it twice. Writing `setRecent(addRecent(...))` and then `saveList(RECENT_KEY, recent)` would save the **old** list: state is a snapshot, and `recent` doesn't change until the next render.

<Callout type="tip" title="In real projects">

Another common pattern is an effect that saves whenever the state changes: `useEffect(() => saveList(KEY, favourites), [favourites])`. Writing to `localStorage` is "syncing with something outside React", which is what effects are for, so that's fine too. The handler version is more explicit about **when** saving happens; the effect version can't be forgotten in a new handler. Pick one style per project and stick to it.

</Callout>

## Empty and error states

A finished app designs every state, including the ones with nothing in them:

| Situation | Show |
| --- | --- |
| No city searched yet | `🔍 Search for a city to see its weather.` |
| No favourites yet | a hint: `Press ☆ Save to keep a city here.` |
| No recent searches | nothing at all (the list just isn't there) |
| Loading | `Loading...` |
| City not found, offline… | `😿` and the message |

The first two are **onboarding**: they tell a new user what to do instead of showing a blank page. The ☆ button only exists inside `CurrentWeather`, so it can't appear when there's an error or no data, and there's never a "save nothing" button to worry about.

```jsx
import { useState, useEffect } from "react";
import { createRoot } from "react-dom/client";

// ---- The client from Part 1 ----
const API = "https://api.pandadev.test";

class ApiError extends Error {
  constructor(status, message) {
    super(message);
    this.name = "ApiError";
    this.status = status;
  }
}

function weatherUrl(city, days = 0) {
  const params = new URLSearchParams({ city: city.trim() });
  if (days > 0) params.set("days", days);
  return `${API}/weather?${params}`;
}

async function getWeather(
  city,
  { days = 0, signal, fetch: fetchFn = fetch } = {},
) {
  if (!city.trim()) throw new Error("Please enter a city");
  const res = await fetchFn(weatherUrl(city, days), { signal });
  const data = await res.json().catch(() => null);
  if (!res.ok) {
    const message = data?.error ?? `HTTP ${res.status}`;
    throw new ApiError(res.status, message);
  }
  return data;
}

const ICONS = {
  Sunny: "☀️",
  "Partly cloudy": "⛅",
  Cloudy: "☁️",
  Rain: "🌧️",
  Thunderstorm: "⛈️",
  Snow: "❄️",
  Fog: "🌫️",
  Windy: "💨",
};

function conditionIcon(condition) {
  return ICONS[condition] ?? "🌡️";
}

function formatTemp(celsius, unit = "C") {
  const value = unit === "F" ? (celsius * 9) / 5 + 32 : celsius;
  return `${Math.round(value)}°${unit}`;
}

function formatWind(kph, unit = "C") {
  if (unit === "F") return `${Math.round(kph / 1.609)} mph`;
  return `${kph} km/h`;
}

const DAY_NAMES = {
  Mon: "Monday",
  Tue: "Tuesday",
  Wed: "Wednesday",
  Thu: "Thursday",
  Fri: "Friday",
  Sat: "Saturday",
  Sun: "Sunday",
};

function dayLabel(day, index) {
  if (index === 0) return "Today";
  if (index === 1) return "Tomorrow";
  return DAY_NAMES[day] ?? day;
}

// ---- Saving in the browser ----
const FAVOURITES_KEY = "pandadev-weather-favourites";
const RECENT_KEY = "pandadev-weather-recent";
const MAX_RECENT = 5;

function loadList(key, storage = localStorage) {
  const saved = storage.getItem(key);
  if (saved === null) return [];
  try {
    const data = JSON.parse(saved);
    return Array.isArray(data) ? data : [];
  } catch (error) {
    console.warn(`Saved ${key} was broken, starting fresh.`);
    return [];
  }
}

function saveList(key, list, storage = localStorage) {
  storage.setItem(key, JSON.stringify(list));
}

function addRecent(recent, city) {
  const others = recent.filter(
    (name) => name.toLowerCase() !== city.toLowerCase(),
  );
  return [city, ...others].slice(0, MAX_RECENT);
}

function toggleFavourite(favourites, city) {
  if (favourites.includes(city)) {
    return favourites.filter((name) => name !== city);
  }
  return [...favourites, city];
}

// ---- Loading the weather ----
const FORECAST_DAYS = 5;

function useWeather(city) {
  const [result, setResult] = useState({ city: null });

  useEffect(() => {
    if (!city) return;
    const controller = new AbortController();
    getWeather(city, {
      days: FORECAST_DAYS,
      signal: controller.signal,
    })
      .then((data) => setResult({ city, data, error: null }))
      .catch((err) => {
        if (err.name === "AbortError") return;
        setResult({ city, data: null, error: err.message });
      });
    return () => controller.abort();
  }, [city]);

  if (!city) return { data: null, error: null, loading: false };
  if (result.city !== city) {
    return { data: null, error: null, loading: true };
  }
  return { data: result.data, error: result.error, loading: false };
}

// ---- Components ----
function SearchForm({ onSearch }) {
  const [text, setText] = useState("");

  function handleSubmit(event) {
    event.preventDefault();
    if (text.trim()) onSearch(text.trim());
  }

  return (
    <form className="search" onSubmit={handleSubmit}>
      <input
        name="city"
        placeholder="Search for a city, e.g. Tokyo"
        value={text}
        onChange={(event) => setText(event.target.value)}
      />
      <button>Search</button>
    </form>
  );
}

function UnitSwitch({ unit, onChange }) {
  return (
    <div className="units">
      {["C", "F"].map((option) => (
        <button
          key={option}
          className={option === unit ? "active" : ""}
          onClick={() => onChange(option)}
        >
          °{option}
        </button>
      ))}
    </div>
  );
}

function Favourites({ cities, onSelect }) {
  return (
    <nav className="favourites">
      ⭐{" "}
      {cities.length === 0 ? (
        <span className="hint">
          No favourites yet. Press ☆ Save to keep a city here.
        </span>
      ) : (
        cities.map((city) => (
          <button key={city} onClick={() => onSelect(city)}>
            {city}
          </button>
        ))
      )}
    </nav>
  );
}

function RecentSearches({ cities, onSelect }) {
  if (cities.length === 0) return null;
  return (
    <nav className="recent">
      Recent:{" "}
      {cities.map((city) => (
        <button key={city} onClick={() => onSelect(city)}>
          {city}
        </button>
      ))}
    </nav>
  );
}

function CurrentWeather({ weather, unit, isFavourite, onToggle }) {
  return (
    <section className="current">
      <button className="favourite" onClick={onToggle}>
        {isFavourite ? "★ Saved" : "☆ Save"}
      </button>
      <h2>{weather.city}, {weather.country}</h2>
      <p className="temp">{formatTemp(weather.temperature, unit)}</p>
      <p className="condition">
        {conditionIcon(weather.condition)} {weather.condition}
      </p>
      <ul className="details">
        <li>Feels like {formatTemp(weather.feelsLike, unit)}</li>
        <li>Humidity {weather.humidity}%</li>
        <li>Wind {formatWind(weather.windKph, unit)}</li>
      </ul>
    </section>
  );
}

function ForecastList({ forecast, unit }) {
  return (
    <ol className="forecast">
      {forecast.map((day, index) => (
        <li key={day.day}>
          <span className="day">{dayLabel(day.day, index)}</span>
          <span className="icon">{conditionIcon(day.condition)}</span>
          <span className="range">
            {formatTemp(day.high, unit)} / {formatTemp(day.low, unit)}
          </span>
          <span className="rain">💧 {day.chanceOfRain}%</span>
        </li>
      ))}
    </ol>
  );
}

function App() {
  const [favourites, setFavourites] = useState(() =>
    loadList(FAVOURITES_KEY),
  );
  const [recent, setRecent] = useState(() => loadList(RECENT_KEY));
  const [city, setCity] = useState(recent[0] ?? "");
  const [unit, setUnit] = useState("C");
  const { data, loading, error } = useWeather(city);

  function search(name) {
    setCity(name);
    const next = addRecent(recent, name);
    setRecent(next);
    saveList(RECENT_KEY, next);
  }

  function handleToggleFavourite() {
    const next = toggleFavourite(favourites, data.city);
    setFavourites(next);
    saveList(FAVOURITES_KEY, next);
  }

  return (
    <main>
      <header>
        <h1>🐼 Panda Weather</h1>
        <UnitSwitch unit={unit} onChange={setUnit} />
      </header>
      <SearchForm onSearch={search} />
      <Favourites cities={favourites} onSelect={search} />
      <RecentSearches cities={recent} onSelect={search} />
      {!city ? (
        <p className="empty">
          🔍 Search for a city to see its weather.
        </p>
      ) : loading ? (
        <p className="status">Loading...</p>
      ) : error ? (
        <p className="error">😿 {error}</p>
      ) : (
        <>
          <CurrentWeather
            weather={data}
            unit={unit}
            isFavourite={favourites.includes(data.city)}
            onToggle={handleToggleFavourite}
          />
          <ForecastList forecast={data.forecast} unit={unit} />
        </>
      )}
    </main>
  );
}

createRoot(document.getElementById("root")).render(<App />);
```

## What you built

- A **°C/°F switch** that changes how the data is shown without loading anything again.
- **Pure, tested helpers** (`addRecent`, `toggleFavourite`) that update lists immutably, so React notices every change.
- **`loadList` and `saveList`**, which keep favourites and recent searches in `localStorage` as JSON and survive missing or broken data, with an injectable `storage` for tests.
- **Lazy initial state**, so saved data is read once when the app starts, and the last searched city comes back with it.
- Saving in the **event handlers**, right where the lists change.
- **Empty, loading and error states** for every part of the page.

Put together with Parts 1 and 2, that's a complete front-end app: a tested API client, formatting helpers, a custom data-loading hook, focused components and persistent settings.

## Take it further

The dashboard is finished, but there's plenty of room to grow. Ideas to try in a real project (`npm create vite@latest`, as in the [Recipe browser](/learn/javascript/recipe-browser) lesson):

- **Use a real weather API.** [Open-Meteo](https://open-meteo.com) is free and needs no API key: look the city up with its geocoding endpoint, then load the forecast for that latitude and longitude. Only `getWeather` (and its tests) change; the components don't even notice, because they only see the data `getWeather` returns. You may need to convert the real answer into the same shape as the practice API's.
- **Remember the unit.** Save `unit` under its own key, and load it with lazy initial state, so °F fans don't have to switch every time.
- **Use my location.** Add a button that calls `navigator.geolocation.getCurrentPosition` and loads the weather for those coordinates (the browser asks the user for permission first).
- **Keep it fresh.** Refresh the current city every ten minutes with `setInterval` inside an effect, and clear the interval in the cleanup. Show "Updated 2 minutes ago" under the temperature.
- **Test the components.** Install **React Testing Library** and write tests that render `CurrentWeather` with sample data, or type into `SearchForm` and check that `onSearch` was called, just like the checks in these exercises.
