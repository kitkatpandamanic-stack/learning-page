Ваша панель уже умеет искать и показывать погоду. В этой последней части вы превратите её в приложение, которое хочется держать открытым: **переключатель °C/°F**, **избранные города** в одном щелчке, список **недавних запросов** — и всё это **запоминается**, когда страницу открывают снова. 🌈

Вам пригодятся `localStorage`, JSON и `try/catch` из [списка дел](/learn/javascript/saving-with-localstorage) уровня 1, неизменяемое обновление массивов из урока [Состояние и события](/learn/javascript/state-and-events) и привычки тестирования из части 1: новая логика попадает в маленькие чистые функции с тестами Vitest ещё до того, как её увидит React.

## Изменяемые списки: сначала чистые функции

Недавние запросы и избранное — это списки, которые меняются двумя особыми способами, и в обоих правилах легко ошибиться незаметно:

- **`addRecent(recent, city)`**: ставит `city` первым, убирает старую запись того же города (без учёта регистра, чтобы `tokyo` и `Tokyo` не оказались в списке вместе) и хранит не больше пяти городов.
- **`toggleFavourite(favourites, city)`**: убирает город, если он есть, и добавляет, если его нет.

Обе функции возвращают **новый** массив и никогда не меняют старый. React перерисовывает компонент, только когда состояние получает новое значение, а изменение массива на месте через `push` или `splice` изменило бы и «старое» состояние, с которым React сравнивает новое. `filter`, spread и `slice` создают новые массивы:

import { describe, it, expect } from "vitest";

const MAX_RECENT = 5;

function addRecent(recent, city) {
  const others = recent.filter(
    (name) => name.toLowerCase() !== city.toLowerCase(),
  );
  return [city, ...others].slice(0, MAX_RECENT);
}

function toggleFavourite(favourites, city) {
  if (favourites.includes(city)) {
    return favourites.filter((name) => name !== city);
  }
  return [...favourites, city];
}

console.log(addRecent(["Paris", "Tokyo"], "Cairo"));
console.log(addRecent(["Paris", "Tokyo"], "tokyo"));
console.log(toggleFavourite(["Oslo"], "Lima"));
console.log(toggleFavourite(["Oslo", "Lima"], "Oslo"));

Недавние запросы запоминают то, что пользователь **ввёл** (`tokyo`), как история поиска в браузере, а избранное хранит написание API (`Tokyo`), потому что сохранить можно только город, который действительно нашёлся.

## Сохраняем списки в localStorage

Сохранение работает как в списке дел: `JSON.stringify` на входе, `JSON.parse` на выходе и `try/catch`, чтобы повреждённые данные не обрушили приложение. Одно улучшение: `storage` — это параметр, который **по умолчанию равен `localStorage`**. Приложение его не передаёт, а тесты могут подставить фейк — точно так же, как `fetch` в части 1. (Заодно это значит, что тесты работают и здесь, где настоящего `localStorage` нет.)

<CodeExample output={`✓ loadList > читает то, что сохранил saveList
✓ loadList > возвращает [], когда ничего не сохранено
Список favs повреждён, начинаем заново.
✓ loadList > возвращает [], когда JSON повреждён
✓ loadList > возвращает [], когда это не список

Tests  4 passed (4)`}>

```js
import { describe, it, expect, beforeEach } from "vitest";

function loadList(key, storage = localStorage) {
  const saved = storage.getItem(key);
  if (saved === null) return [];
  try {
    const data = JSON.parse(saved);
    return Array.isArray(data) ? data : [];
  } catch (error) {
    console.warn(`Список ${key} повреждён, начинаем заново.`);
    return [];
  }
}

function saveList(key, list, storage = localStorage) {
  storage.setItem(key, JSON.stringify(list));
}

// Фейковый localStorage: Map с такими же методами
function fakeStorage() {
  const data = new Map();
  return {
    getItem: (key) => data.get(key) ?? null,
    setItem: (key, value) => data.set(key, String(value)),
  };
}

describe("loadList", () => {
  let storage;
  beforeEach(() => {
    storage = fakeStorage();
  });

  it("читает то, что сохранил saveList", () => {
    saveList("favs", ["Oslo", "Lima"], storage);
    expect(storage.getItem("favs")).toBe('["Oslo","Lima"]');
    expect(loadList("favs", storage)).toEqual(["Oslo", "Lima"]);
  });

  it.each([
    ["ничего не сохранено", null],
    ["JSON повреждён", "{ oops"],
    ["это не список", '"Oslo"'],
  ])("возвращает [], когда %s", (_case, saved) => {
    if (saved !== null) storage.setItem("favs", saved);
    expect(loadList("favs", storage)).toEqual([]);
  });
});
```

</CodeExample>

Предупреждение посередине — это собственный `console.warn` приложения, напечатанный во время теста с «повреждённым JSON». Vitest тоже его показывает, и это помогает, когда тест падает по неожиданной причине.

<Callout type="note" title="localStorage в превью">

Как и в списке дел, превью имитируют `localStorage`: повторное нажатие **«Запустить»** работает как перезагрузка страницы, поэтому избранное его переживает, а **«Сбросить»** стирает всё. В вашем собственном браузере данные хранятся, пока пользователь их не очистит. Откройте инструменты разработчика (Application → Local Storage), чтобы увидеть JSON, который сохранило ваше приложение.

</Callout>

## Загружаем сохранённые данные при старте

При первом рендере `App` его состояние должно браться из хранилища. Можно написать `useState(loadList(FAVOURITES_KEY))`, но есть подвох: эта строка выполняется при **каждом** рендере, так что приложение читало бы и разбирало `localStorage` на каждую введённую букву, а React просто игнорировал бы результат (начальное значение используется только один раз).

Исправление — одна новая вещь: передайте в `useState` **функцию**. React вызовет её только при первом рендере и использует то, что она вернёт, как начальное значение. Это называется **ленивым начальным состоянием (lazy initial state)**:

```jsx
// ❌ Читает localStorage при каждом рендере
const [favourites, setFavourites] = useState(loadList(FAVOURITES_KEY));

// ✅ Читает его один раз, для первого рендера
const [favourites, setFavourites] = useState(() =>
  loadList(FAVOURITES_KEY),
);
const [recent, setRecent] = useState(() => loadList(RECENT_KEY));
const [city, setCity] = useState(recent[0] ?? "");
```

`city` начинается с **последнего запроса**, поэтому при повторном открытии панель показывает город, который вы смотрели последним. `recent[0]` — дешёвое обращение к массиву, поэтому функция здесь не нужна. Если истории нет совсем, `?? ""` даёт пустой город, и `useWeather` не отправляет запрос.

## Сохраняем, когда пользователь действует

Когда сохранять? Каждый раз, когда пользователь **меняет** список: поиск меняет `recent`, кнопка ☆ меняет `favourites`. Это действия пользователя, поэтому, как советует урок про эффекты, сохранение помещаем в **обработчики событий (event handlers)**, прямо рядом с обновлением состояния (так же, как `saveAndRender()` в списке дел):

```jsx
function search(name) {
  setCity(name);
  const next = addRecent(recent, name);
  setRecent(next);
  saveList(RECENT_KEY, next);
}

function handleToggleFavourite() {
  const next = toggleFavourite(favourites, data.city);
  setFavourites(next);
  saveList(FAVOURITES_KEY, next);
}
```

Обратите внимание: мы вычисляем `next` один раз и используем дважды. Если написать `setRecent(addRecent(...))`, а затем `saveList(RECENT_KEY, recent)`, сохранится **старый** список: состояние — это снимок, и `recent` не изменится до следующего рендера.

<Callout type="tip" title="В реальных проектах">

Другой распространённый паттерн — эффект, который сохраняет данные при каждом изменении состояния: `useEffect(() => saveList(KEY, favourites), [favourites])`. Запись в `localStorage` — это «синхронизация с чем-то вне React», а именно для этого и нужны эффекты, так что это тоже нормально. Вариант с обработчиками явно показывает, **когда** происходит сохранение; вариант с эффектом невозможно забыть в новом обработчике. Выберите один стиль на проект и придерживайтесь его.

</Callout>

## Пустые состояния и ошибки

В готовом приложении продумано каждое состояние, включая те, в которых ничего нет:

| Ситуация | Что показать |
| --- | --- |
| Город ещё не искали | `🔍 Найдите город, чтобы узнать погоду.` |
| Избранного пока нет | подсказку: `Нажмите «☆ Сохранить», чтобы добавить город.` |
| Нет недавних запросов | ничего (списка просто нет) |
| Загрузка | `Загрузка...` |
| Город не найден, нет сети… | `😿` и сообщение |

Первые два — это **онбординг (onboarding)**: они объясняют новому пользователю, что делать, вместо пустой страницы. Кнопка ☆ есть только внутри `CurrentWeather`, поэтому она не может появиться при ошибке или без данных, и беспокоиться о кнопке «сохранить ничего» не придётся.

- **Чистые протестированные функции** (`addRecent`, `toggleFavourite`), которые обновляют списки неизменяемо, чтобы React замечал каждое изменение.
- **`loadList` и `saveList`**, которые хранят избранное и недавние запросы в `localStorage` в виде JSON, переживают отсутствующие и повреждённые данные и позволяют подставить `storage` в тестах.
- **Ленивое начальное состояние**: сохранённые данные читаются один раз при старте приложения, а вместе с ними возвращается последний найденный город.
- Сохранение в **обработчиках событий**, прямо там, где меняются списки.
- **Пустые состояния, состояния загрузки и ошибки** для каждой части страницы.

Вместе с частями 1 и 2 это законченное фронтенд-приложение: протестированный API-клиент, функции форматирования, собственный хук для загрузки данных, компоненты с чёткими обязанностями и сохраняемые настройки.

## Что дальше

Панель готова, но расти ей есть куда. Идеи, которые стоит попробовать в настоящем проекте (`npm create vite@latest`, как в уроке [Каталог рецептов](/learn/javascript/recipe-browser)):

- **Подключите настоящий погодный API.** [Open-Meteo](https://open-meteo.com) бесплатен и не требует API-ключа: найдите город через его эндпоинт геокодирования, а затем загрузите прогноз для этих широты и долготы. Меняются только `getWeather` (и его тесты); компоненты даже не заметят, ведь они видят лишь данные, которые возвращает `getWeather`. Возможно, настоящий ответ придётся привести к той же форме, что у учебного API.
- **Запоминайте единицы.** Сохраняйте `unit` под отдельным ключом и загружайте через ленивое начальное состояние, чтобы любителям °F не приходилось переключаться каждый раз.
- **Используйте моё местоположение.** Добавьте кнопку, которая вызывает `navigator.geolocation.getCurrentPosition` и загружает погоду для этих координат (сначала браузер спросит у пользователя разрешение).
- **Поддерживайте свежесть.** Обновляйте текущий город каждые десять минут с помощью `setInterval` внутри эффекта и очищайте интервал в функции очистки. Показывайте под температурой «Обновлено 2 минуты назад».
- **Протестируйте компоненты.** Установите **React Testing Library** и напишите тесты, которые рендерят `CurrentWeather` с примерными данными или вводят текст в `SearchForm` и проверяют, что `onSearch` был вызван, — совсем как проверки в этих упражнениях.
