В части 1 вы построили и протестировали фундамент панели: `getWeather` общается с API, а функции форматирования превращают числа в понятный текст. Теперь у приложения появится лицо. ⛅ В этой части вы соберёте **компоненты React (components)** — форму поиска, текущую погоду и прогноз — и подключите их к клиенту с продуманными состояниями **загрузки** и **ошибки**.

Вам пригодятся компоненты, пропсы и списки с ключами из урока [Компоненты и JSX](/learn/javascript/components-and-jsx), управляемые формы из урока [Состояние и события](/learn/javascript/state-and-events), а также эффекты с `AbortController` и идея собственного хука из [Каталога рецептов](/learn/javascript/recipe-browser).

## План компонентов

Как и в каталоге рецептов, прежде чем писать JSX, набросайте компоненты и решите, где будет жить каждая часть состояния:

```text
App                     состояние: city
├── SearchForm          состояние: text      пропсы: onSearch
├── (загрузка)          Загрузка...
├── (ошибка)            😿 сообщение
└── (данные)
    ├── CurrentWeather  пропсы: weather
    └── ForecastList    пропсы: forecast
```

Решения, которые за этим стоят:

- **`city` принадлежит `App`.** Это единственное значение, от которого зависит, что загружать, а загрузка происходит именно в `App`.
- **`SearchForm` хранит свой `text` сам.** Недопечатанный текст вроде `"Tok"` не важен никому, кроме поля ввода. Форма сообщает `App` о поиске только тогда, когда пользователь его **отправляет**.
- **У `CurrentWeather` и `ForecastList` вообще нет состояния (state).** Они показывают то, что им передали, поэтому их можно собрать на примерных данных и использовать где угодно, и они никогда не разойдутся с данными.

Почему поиск по отправке формы, если каталог рецептов искал прямо во время ввода? Потому что поиск погоды работает только с **полным** названием города (`"Lon"` — это просто 404), а настоящие погодные API **считают ваши запросы**: бесплатные тарифы часто разрешают около тысячи вызовов в день. Отправлять запрос на каждое нажатие клавиши — значит тратить их на несуществующие города.

## Шаг 3: загружаем погоду собственным хуком

Загрузка — работа для **эффекта (effect)**: каждый раз, когда меняется `city`, вызываем `getWeather`. В каталоге рецептов вы написали `useJson(url)`; погодная версия устроена так же, но вызывает наш **протестированный клиент**, а не `fetch` напрямую:

```jsx
const FORECAST_DAYS = 5;

function useWeather(city) {
  const [result, setResult] = useState({ city: null });

  useEffect(() => {
    if (!city) return;
    const controller = new AbortController();
    getWeather(city, {
      days: FORECAST_DAYS,
      signal: controller.signal,
    })
      .then((data) => setResult({ city, data, error: null }))
      .catch((err) => {
        if (err.name === "AbortError") return;
        setResult({ city, data: null, error: err.message });
      });
    return () => controller.abort();
  }, [city]);

  if (!city) return { data: null, error: null, loading: false };
  if (result.city !== city) {
    return { data: null, error: null, loading: true };
  }
  return { data: result.data, error: result.error, loading: false };
}
```

У каждой строки здесь есть причина:

- **Всю тяжёлую работу делает `getWeather`.** URL, проверка кода ответа и сообщение об ошибке от API обрабатываются (и тестируются!) в клиенте. Хук занимается только React: состоянием, эффектом и очисткой.
- **Очистка (cleanup) отменяет старый запрос.** Найдите Tokyo, а затем быстро London — запрос для Tokyo отменится, и его запоздалый ответ никогда не заменит ответ для London. Вот где окупается опция `signal` из части 1.
- **`AbortError` игнорируется**, потому что отменённый запрос — не та неудача, о которой нужно сообщать пользователю.
- **`loading` вычисляется, а не хранится**: результат помнит, к какому городу он относится, и если это не текущий город, значит, новый ответ ещё не пришёл.
- **Нет города — нет запроса.** Пустой `city` означает «нечего загружать» (в части 3 это пригодится для пустого состояния).

import { useState, useEffect } from "react";

Простое правило: **логика — в обычных протестированных функциях; компоненты React — только для показа состояния и обработки событий.**

## Шаг 4: собираем всё вместе

`App` хранит `city`, передаёт `setCity` в форму и показывает ровно **одно** из трёх состояний:

```jsx
function App() {
  const [city, setCity] = useState("London");
  const { data, loading, error } = useWeather(city);

  return (
    <main>
      <h1>🐼 Панда-погода</h1>
      <SearchForm onSearch={setCity} />
      {loading ? (
        <p className="status">Загрузка...</p>
      ) : error ? (
        <p className="error">😿 {error}</p>
      ) : (
        data && (
          <>
            <CurrentWeather weather={data} />
            <ForecastList forecast={data.forecast} />
          </>
        )
      )}
    </main>
  );
}
```

`SearchForm` остаётся на странице в любом состоянии, так что пользователь всегда может поискать снова, даже после ошибки. А поскольку ошибка приходит прямо от API (через `ApiError`), поиск несуществующего города показывает `😿 City not found` без всякого дополнительного кода.

import { useState, useEffect } from "react";
import { createRoot } from "react-dom/client";

// ---- Клиент из части 1 ----
const API = "https://api.pandadev.test";

class ApiError extends Error {
  constructor(status, message) {
    super(message);
    this.name = "ApiError";
    this.status = status;
  }
}

function weatherUrl(city, days = 0) {
  const params = new URLSearchParams({ city: city.trim() });
  if (days > 0) params.set("days", days);
  return `${API}/weather?${params}`;
}

async function getWeather(
  city,
  { days = 0, signal, fetch: fetchFn = fetch } = {},
) {
  if (!city.trim()) throw new Error("Введите город");
  const res = await fetchFn(weatherUrl(city, days), { signal });
  const data = await res.json().catch(() => null);
  if (!res.ok) {
    const message = data?.error ?? `HTTP ${res.status}`;
    throw new ApiError(res.status, message);
  }
  return data;
}

const ICONS = {
  Sunny: "☀️",
  "Partly cloudy": "⛅",
  Cloudy: "☁️",
  Rain: "🌧️",
  Thunderstorm: "⛈️",
  Snow: "❄️",
  Fog: "🌫️",
  Windy: "💨",
};

function conditionIcon(condition) {
  return ICONS[condition] ?? "🌡️";
}

function formatTemp(celsius, unit = "C") {
  const value = unit === "F" ? (celsius * 9) / 5 + 32 : celsius;
  return `${Math.round(value)}°${unit}`;
}

function formatWind(kph, unit = "C") {
  if (unit === "F") return `${Math.round(kph / 1.609)} миль/ч`;
  return `${kph} км/ч`;
}

const DAY_NAMES = {
  Mon: "Понедельник",
  Tue: "Вторник",
  Wed: "Среда",
  Thu: "Четверг",
  Fri: "Пятница",
  Sat: "Суббота",
  Sun: "Воскресенье",
};

function dayLabel(day, index) {
  if (index === 0) return "Сегодня";
  if (index === 1) return "Завтра";
  return DAY_NAMES[day] ?? day;
}

// ---- Загрузка погоды ----
const FORECAST_DAYS = 5;

function useWeather(city) {
  const [result, setResult] = useState({ city: null });

  useEffect(() => {
    if (!city) return;
    const controller = new AbortController();
    getWeather(city, {
      days: FORECAST_DAYS,
      signal: controller.signal,
    })
      .then((data) => setResult({ city, data, error: null }))
      .catch((err) => {
        if (err.name === "AbortError") return;
        setResult({ city, data: null, error: err.message });
      });
    return () => controller.abort();
  }, [city]);

  if (!city) return { data: null, error: null, loading: false };
  if (result.city !== city) {
    return { data: null, error: null, loading: true };
  }
  return { data: result.data, error: result.error, loading: false };
}

// ---- Компоненты ----
function SearchForm({ onSearch }) {
  const [text, setText] = useState("");

  function handleSubmit(event) {
    event.preventDefault();
    if (text.trim()) onSearch(text.trim());
  }

  return (
    <form className="search" onSubmit={handleSubmit}>
      <input
        name="city"
        placeholder="Город, например Tokyo"
        value={text}
        onChange={(event) => setText(event.target.value)}
      />
      <button>Найти</button>
    </form>
  );
}

function CurrentWeather({ weather }) {
  return (
    <section className="current">
      <h2>{weather.city}, {weather.country}</h2>
      <p className="temp">{formatTemp(weather.temperature)}</p>
      <p className="condition">
        {conditionIcon(weather.condition)} {weather.condition}
      </p>
      <ul className="details">
        <li>Ощущается как {formatTemp(weather.feelsLike)}</li>
        <li>Влажность {weather.humidity}%</li>
        <li>Ветер {formatWind(weather.windKph)}</li>
      </ul>
    </section>
  );
}

function ForecastList({ forecast }) {
  return (
    <ol className="forecast">
      {forecast.map((day, index) => (
        <li key={day.day}>
          <span className="day">{dayLabel(day.day, index)}</span>
          <span className="icon">{conditionIcon(day.condition)}</span>
          <span className="range">
            {formatTemp(day.high)} / {formatTemp(day.low)}
          </span>
          <span className="rain">💧 {day.chanceOfRain}%</span>
        </li>
      ))}
    </ol>
  );
}

function App() {
  const [city, setCity] = useState("London");
  const { data, loading, error } = useWeather(city);

  return (
    <main>
      <h1>🐼 Панда-погода</h1>
      <SearchForm onSearch={setCity} />
      {loading ? (
        <p className="status">Загрузка...</p>
      ) : error ? (
        <p className="error">😿 {error}</p>
      ) : (
        data && (
          <>
            <CurrentWeather weather={data} />
            <ForecastList forecast={data.forecast} />
          </>
        )
      )}
    </main>
  );
}

createRoot(document.getElementById("root")).render(<App />);
