So far your code has only printed to the console. Now it's time to change a **real web page**! When a browser loads HTML, it turns it into a structure of objects called the **DOM** (Document Object Model). JavaScript can read and change those objects, and the page updates straight away. 🎨

In this module, examples come with a **live preview**: edit the code, press **Run**, and watch the page change.

## What is the DOM?

Take this small piece of HTML:

```html
<body>
  <h1>Panda Café</h1>
  <ul>
    <li>Bamboo tea</li>
    <li>Leaf cake</li>
  </ul>
</body>
```

The browser builds a **tree** from it. Every tag becomes an **element** object, and elements inside other elements become its **children**:

```text
document
└── body
    ├── h1  "Panda Café"
    └── ul
        ├── li  "Bamboo tea"
        └── li  "Leaf cake"
```

The whole tree is available in JavaScript through the global `document` object. Change an object in the tree, and the browser redraws that part of the page.

<TryIt
  html={`<h1>Panda Café</h1>
<ul>
  <li>Bamboo tea</li>
  <li>Leaf cake</li>
</ul>`}
  code={`const heading = document.querySelector("h1");

console.log(heading);
console.log(heading.textContent);

heading.textContent = "Panda Café is open! ☕";`}
/>

The heading on the page changed, even though the HTML still says "Panda Café". JavaScript changed the **DOM**, and the page always shows the DOM.

## Finding elements

Before you can change an element, you need to **select** it. `document.querySelector()` takes a **CSS selector** and returns the **first** element that matches:

| Selector         | Finds                                |
| ---------------- | ------------------------------------ |
| `"h1"`           | the first `<h1>` element             |
| `"#menu"`        | the element with `id="menu"`         |
| `".price"`       | the first element with class `price` |
| `"#menu li"`     | the first `<li>` inside `#menu`      |

To get **all** matching elements, use `document.querySelectorAll()`. It returns a **NodeList**, which works a lot like an array: it has `.length`, you can use indexes, and you can loop over it with `forEach` or `for...of`.

<TryIt
  html={`<h2 id="title">Today's menu</h2>
<ul id="menu">
  <li class="item">Bamboo tea</li>
  <li class="item">Leaf cake</li>
  <li class="item">Bamboo soup</li>
</ul>`}
  code={`const title = document.querySelector("#title");
console.log(title);

const items = document.querySelectorAll(".item");
console.log(items);
console.log(items.length);

items.forEach((item, index) => {
  item.textContent = \`\${index + 1}. \${item.textContent}\`;
});

console.log(document.querySelector("#nothing"));`}
/>

Notice the last line: if nothing matches, `querySelector` returns `null`.

<Callout type="warning" title="Watch out for null">

If you misspell a selector, you get `null`, and the next line fails with an error like `TypeError: Cannot set properties of null`. When you see that error, check your selector first: did you forget the `#` or the `.`?

</Callout>

## Changing text: textContent vs innerHTML

There are two common ways to change what's inside an element:

- **`textContent`** reads or sets the **plain text**. Any `<` and `>` are shown as characters, never turned into tags.
- **`innerHTML`** reads or sets the **HTML** inside the element. Tags in the string become real elements.

<TryIt
  html={`<p id="one"></p>
<p id="two"></p>`}
  code={`const one = document.querySelector("#one");
const two = document.querySelector("#two");

one.textContent = "I am <strong>very</strong> hungry";
two.innerHTML = "I am <strong>very</strong> hungry";

console.log(two.innerHTML);
console.log(two.textContent);`}
/>

The first paragraph shows the tags as text. The second one turns them into real bold text.

<Callout type="danger" title="Never put user input into innerHTML">

If you put text typed by a user into `innerHTML`, they could type HTML that runs their own code on your page. This kind of attack is called **XSS** (cross-site scripting). For anything that came from a user, always use `textContent`. Only use `innerHTML` for HTML that you wrote yourself.

</Callout>

## Changing styles and classes

Every element has a `style` object for **inline styles**. CSS property names with dashes become **camelCase**: `background-color` becomes `backgroundColor`, `font-size` becomes `fontSize`. Values are always strings, including the unit.

Changing lots of inline styles gets messy, though. A cleaner way is to write the styles in CSS and switch **classes** on and off with `classList`:

- `classList.add("name")` adds a class.
- `classList.remove("name")` removes it.
- `classList.toggle("name")` adds it if it's missing, removes it if it's there.
- `classList.contains("name")` returns `true` or `false`.

<TryIt
  html={`<style>
  .card { padding: 12px; border-radius: 12px; border: 2px solid #ffffff33; }
  .sold-out { opacity: 0.4; text-decoration: line-through; }
</style>
<p id="banner">Welcome to the café!</p>
<div class="card" id="tea">Bamboo tea</div>
<div class="card" id="cake">Leaf cake</div>`}
  code={`const banner = document.querySelector("#banner");
banner.style.color = "orange";
banner.style.fontSize = "24px";

const cake = document.querySelector("#cake");
cake.classList.add("sold-out");

console.log(cake.classList.contains("sold-out"));
console.log(cake.className);`}
/>

<Callout type="tip">

Prefer `classList` over setting lots of `style` properties. It keeps the look in CSS and the behaviour in JavaScript, and you can undo it with a single `classList.remove()`.

</Callout>

## Attributes

HTML attributes like `href`, `src`, `alt`, `disabled` and `placeholder` can be read and changed too. You can use the general methods `getAttribute()` and `setAttribute()`, or the matching **property** directly on the element:

<TryIt
  html={`<a id="link" href="#home">Go home</a>
<p><input id="search" placeholder="Search..."></p>
<button id="order">Order</button>`}
  code={`const link = document.querySelector("#link");
console.log(link.getAttribute("href"));

link.setAttribute("href", "#menu");
link.textContent = "See the menu";

const search = document.querySelector("#search");
search.placeholder = "Search for bamboo...";

const order = document.querySelector("#order");
order.disabled = true;
console.log(order.disabled);`}
/>

For true/false attributes like `disabled`, `checked` and `hidden`, the property is a **boolean**. Setting `order.disabled = true` greys the button out, and `false` turns it back on.

## Reading values from inputs

To find out what's in a form field, read its **`value`** property. For checkboxes, read **`checked`** instead (a boolean).

<TryIt
  html={`<p><input id="name" value="Mei"></p>
<p><input id="age" type="number" value="4"></p>
<label><input id="vip" type="checkbox" checked> VIP</label>`}
  code={`const panda = document.querySelector("#name").value;
const age = document.querySelector("#age").value;
const vip = document.querySelector("#vip").checked;

console.log(panda, age, vip);
console.log(typeof age);
console.log(Number(age) + 1);`}
/>

<Callout type="note" title="value is always a string">

Even for `type="number"`, `value` gives you a **string**. Convert it with `Number()` before doing maths, or `"4" + 1` will give you `"41"`.

</Callout>

Right now the code only runs once, when the page loads. In the next lesson you'll learn how to run code when the user **clicks** or **types**, so the page can react.

## Recap

- The **DOM** is the tree of objects the browser builds from your HTML. `document` is its root.
- `querySelector(selector)` finds the first match (or `null`); `querySelectorAll(selector)` finds all of them as a NodeList.
- `textContent` sets plain text; `innerHTML` sets HTML. Never put user input into `innerHTML`.
- Change looks with `element.style.camelCaseName` or, better, with `classList.add/remove/toggle`.
- Read and change attributes with `getAttribute`/`setAttribute` or properties like `href`, `disabled` and `placeholder`.
- Read form fields with `.value` (always a string) and checkboxes with `.checked`.
