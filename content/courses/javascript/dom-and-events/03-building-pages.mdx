So far you've changed elements that were already in the HTML. But most apps show things that **aren't known in advance**: new messages, search results, items added to a basket. In this lesson you'll **create** elements with JavaScript, build whole lists from arrays, and learn a simple pattern that keeps the page in sync with your data. 🏗️

## Creating an element

Making a new element takes three steps:

1. **Create** it with `document.createElement("tag")`.
2. **Fill it in**: set its `textContent`, classes, attributes and so on.
3. **Add it** to the page with `parent.append(element)`.

Until step 3, the element only exists in JavaScript. It's on the page only once you put it inside an element that's already there.

<TryIt
  html={`<style>
  .new { color: #22d3ee; font-weight: bold; }
</style>
<h2>Today's menu</h2>
<ul id="menu">
  <li>Bamboo tea</li>
  <li>Leaf cake</li>
</ul>`}
  code={`const menu = document.querySelector("#menu");

const item = document.createElement("li");
item.textContent = "Bamboo smoothie ✨";
item.classList.add("new");

console.log(item);
menu.append(item);

console.log(menu.children.length);`}
/>

`menu.children` is a live collection of the elements inside `#menu`, so its length is now 3.

## Adding and removing: append, prepend and remove

- `parent.append(element)` adds it as the **last** child.
- `parent.prepend(element)` adds it as the **first** child.
- `element.remove()` takes an element off the page.

Both `append` and `prepend` also accept plain strings, which are added as text.

<TryIt
  html={`<button id="add-first">Add to front</button>
<button id="add-last">Add to back</button>
<button id="remove-last">Remove last</button>
<ol id="queue">
  <li>Mei</li>
</ol>`}
  code={`const queue = document.querySelector("#queue");
let next = 1;

function makePanda() {
  const li = document.createElement("li");
  li.textContent = \`Panda \${next}\`;
  next++;
  return li;
}

document.querySelector("#add-first").addEventListener("click", () => {
  queue.prepend(makePanda());
});

document.querySelector("#add-last").addEventListener("click", () => {
  queue.append(makePanda());
});

document.querySelector("#remove-last").addEventListener("click", () => {
  const last = queue.lastElementChild;
  if (last) {
    last.remove();
  }
});`}
/>

`lastElementChild` is the last element inside the list, or `null` when the list is empty. That's why the code checks it before calling `remove()`.

## Building a list from data

Here is where arrays meet the DOM. Loop over an array, create one element per item, and append each one:

<TryIt
  html={`<style>
  .price { color: #a78bfa; margin-left: 8px; }
</style>
<h2>Bamboo shop</h2>
<ul id="products"></ul>`}
  code={`const products = [
  { name: "Fresh bamboo", price: 3 },
  { name: "Bamboo crisps", price: 2.5 },
  { name: "Leaf tea", price: 4 },
];

const list = document.querySelector("#products");

products.forEach((product) => {
  const li = document.createElement("li");
  li.textContent = product.name;

  const price = document.createElement("span");
  price.className = "price";
  price.textContent = \`£\${product.price.toFixed(2)}\`;

  li.append(price);
  list.append(li);
});

console.log(list.children.length, "products shown");`}
/>

Notice the `<span>` is created and appended **inside** the `<li>`. You can build up nested structures this way, piece by piece.

<Callout type="danger" title="Data goes in with textContent">

It's tempting to build HTML strings like `` li.innerHTML = `<b>${product.name}</b>` ``. If the data ever comes from a user (a comment, a username), that's an XSS hole. Creating elements and setting `textContent` is always safe.

</Callout>

## The render pattern

As an app grows, keeping the page and your data in sync gets tricky. A popular pattern that tools like React are built on goes like this:

1. Keep your data in a variable: the **state**.
2. Write one **`render()`** function that clears the list and rebuilds it from the state.
3. When something happens, **change the state**, then call `render()`.

You never edit the list by hand. The page is always just a picture of the state.

<TryIt
  html={`<form id="add-form">
  <input id="new-item" placeholder="Add a snack">
  <button>Add</button>
</form>
<ul id="snacks"></ul>
<p id="total"></p>`}
  code={`const snacks = ["Bamboo", "Apples"];

const list = document.querySelector("#snacks");
const total = document.querySelector("#total");

function render() {
  list.replaceChildren();
  snacks.forEach((snack) => {
    const li = document.createElement("li");
    li.textContent = snack;
    list.append(li);
  });
  total.textContent = \`\${snacks.length} snacks on the list\`;
}

const form = document.querySelector("#add-form");
const input = document.querySelector("#new-item");

form.addEventListener("submit", (event) => {
  event.preventDefault();
  if (input.value.trim() === "") return;

  snacks.push(input.value.trim());
  input.value = "";
  render();
});

render();`}
/>

`list.replaceChildren()` with nothing in the brackets removes everything inside the list, so `render()` starts from a clean slate every time. Also note the `render()` call at the very end: it draws the starting state when the page loads.

<Callout type="tip" title="Change the data, then render">

When a bug shows up, the render pattern makes it easy to find: either the **state** is wrong (check it with `console.log`) or `render()` draws it wrong. There's no third place for things to go out of sync.

</Callout>

## Storing extra info with dataset

Sometimes an element needs to remember some data that isn't shown, like the ID of the product it belongs to. HTML has **data attributes** for this: any attribute starting with `data-`. In JavaScript, you read and write them through **`element.dataset`**. Dashed names become camelCase: `data-panda-name` becomes `dataset.pandaName`.

<TryIt
  html={`<button data-panda-name="Mei" data-age="4">Mei</button>
<button data-panda-name="Bao" data-age="7">Bao</button>
<p id="about">Click a panda.</p>`}
  code={`const about = document.querySelector("#about");

document.querySelectorAll("button").forEach((button) => {
  button.addEventListener("click", () => {
    const { pandaName, age } = button.dataset;
    about.textContent = \`\${pandaName} is \${age} years old.\`;
    console.log(button.dataset);
  });
});

const first = document.querySelector("button");
first.dataset.favourite = "yes";
console.log(first.getAttribute("data-favourite"));`}
/>

Dataset values are always **strings**, so use `Number()` if you need to do maths with them.

Data attributes work really well with the render pattern and event delegation. Each delete button below stores the **index** of its item, and one listener on the list removes the right one from the state:

<TryIt
  html={`<style>
  li { margin: 6px 0; }
  li button { margin-left: 8px; padding: 2px 8px; }
</style>
<ul id="todos"></ul>`}
  code={`const todos = ["Eat bamboo", "Nap", "Roll down a hill"];
const list = document.querySelector("#todos");

function render() {
  list.replaceChildren();
  todos.forEach((todo, index) => {
    const li = document.createElement("li");
    li.textContent = todo;

    const button = document.createElement("button");
    button.textContent = "✕";
    button.dataset.index = index;

    li.append(button);
    list.append(li);
  });
}

list.addEventListener("click", (event) => {
  if (event.target.matches("button")) {
    const index = Number(event.target.dataset.index);
    console.log("Removing", todos[index]);
    todos.splice(index, 1);
    render();
  }
});

render();`}
/>

Because the listener is on the `<ul>`, it keeps working for buttons that `render()` creates later. That's event delegation paying off.

Time to build a colour picker that updates as you drag! Use what you've learned in the whole module:

1. **`showColour(colour)`** sets the background colour of `#preview` and puts the colour's hex code (like `#7c3aed`) in `#hex`. Call it once at the start with `picker.value`, so the page shows the starting colour.
2. When the picker fires an **`input`** event, show the new colour.
3. When **Save colour** is clicked, add `picker.value` to the `savedColours` array (**only if it isn't already in there**), then call `renderSaved()`.
4. **`renderSaved()`** clears `#saved` and creates one `<li>` per saved colour, with that colour as its background and the hex code stored in `data-color` (`li.dataset.color`).
5. Clicking a saved swatch sets the picker's value to that colour and shows it again. Use **one** listener on `#saved` (event delegation).

<Hint>

An `<input type="color">` gives you its colour as a hex string in `picker.value`. In `showColour`, set `preview.style.backgroundColor = colour`. For "no duplicates", check `savedColours.includes(colour)` before pushing. In the `#saved` click listener, use `event.target.matches("li")` and read `event.target.dataset.color`.

</Hint>

<Solution>

```js
const picker = document.querySelector("#picker");
const preview = document.querySelector("#preview");
const hex = document.querySelector("#hex");
const saveButton = document.querySelector("#save");
const saved = document.querySelector("#saved");

const savedColours = [];

function showColour(colour) {
  preview.style.backgroundColor = colour;
  hex.textContent = colour;
}

function renderSaved() {
  saved.replaceChildren();
  savedColours.forEach((colour) => {
    const swatch = document.createElement("li");
    swatch.style.backgroundColor = colour;
    swatch.dataset.color = colour;
    swatch.title = colour;
    saved.append(swatch);
  });
}

showColour(picker.value);

picker.addEventListener("input", () => {
  showColour(picker.value);
});

saveButton.addEventListener("click", () => {
  const colour = picker.value;
  if (!savedColours.includes(colour)) {
    savedColours.push(colour);
    renderSaved();
  }
});

saved.addEventListener("click", (event) => {
  if (event.target.matches("li")) {
    const colour = event.target.dataset.color;
    picker.value = colour;
    showColour(colour);
  }
});
```

## Recap

- Create elements with `document.createElement("tag")`, fill them in, then add them with `append` (end) or `prepend` (start). Take them away with `element.remove()`.
- Build lists from data by looping over an array and creating one element per item. Use `textContent` for the data, never `innerHTML`.
- **Render pattern**: keep the data in a state variable, write a `render()` function that rebuilds the page from it, and call `render()` after every change.
- `data-*` attributes store extra info on elements; read and write them with `element.dataset` (camelCase names, string values).
- Event delegation plus `dataset` lets one listener handle buttons that `render()` creates later.
