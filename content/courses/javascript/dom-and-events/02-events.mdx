In the last lesson your code changed the page once, as soon as it loaded. Real pages wait for the user to **do something**: click a button, type in a box, press a key, send a form. Each of those actions fires an **event**, and you can tell JavaScript what to do when it happens. 🖱️

## Listening for a click

`addEventListener` takes two things: the **name of the event** and a **function** to run each time it happens. That function is called an **event listener** (or **handler**).

<TryIt
  html={`<button id="like">🤍 Like</button>
<p id="info">Nobody likes this yet.</p>`}
  code={`const likeButton = document.querySelector("#like");
const info = document.querySelector("#info");
let likes = 0;

likeButton.addEventListener("click", () => {
  likes++;
  info.textContent = \`\${likes} pandas like this\`;
  likeButton.textContent = "💜 Liked";
});

console.log("Waiting for clicks...");`}
/>

Press **Run**, then click the button in the preview a few times. The code inside the arrow function runs on **every** click, while the code outside it runs only once.

<Callout type="warning" title="Pass the function, don't call it">

Write `button.addEventListener("click", sayHi)`, **without** brackets after `sayHi`. With brackets, `sayHi()` runs straight away, once, and its return value (usually `undefined`) is what gets passed as the listener. Your function then never runs on click.

</Callout>

## The event object

When an event fires, the browser calls your listener with an **event object** full of details. The most useful property is **`event.target`**: the element the event happened on. That lets one function handle several buttons:

<TryIt
  html={`<p>How do you feel today?</p>
<button class="mood">😄</button>
<button class="mood">😴</button>
<button class="mood">🤩</button>
<p id="result"></p>`}
  code={`const result = document.querySelector("#result");

function pickMood(event) {
  console.log(event.type, event.target);
  result.textContent = \`You feel \${event.target.textContent}\`;
}

const buttons = document.querySelectorAll(".mood");
buttons.forEach((button) => {
  button.addEventListener("click", pickMood);
});`}
/>

You can name the parameter anything, but `event` (or the short `e`) is what most developers use.

## Typing: input and change

Text fields have two handy events:

- **`input`** fires on **every change** to the value: each key typed, pasted or deleted.
- **`change`** fires when the change is **finished**: for a text box, when the user leaves it; for checkboxes and dropdowns, as soon as a new option is picked.

<TryIt
  html={`<p><input id="bio" placeholder="Write a short bio"></p>
<p id="counter">0 / 30</p>
<select id="snack">
  <option>Bamboo</option>
  <option>Apples</option>
  <option>Carrots</option>
</select>
<p id="choice"></p>`}
  code={`const bio = document.querySelector("#bio");
const counter = document.querySelector("#counter");

bio.addEventListener("input", () => {
  counter.textContent = \`\${bio.value.length} / 30\`;
  counter.style.color = bio.value.length > 30 ? "tomato" : "";
});

const snack = document.querySelector("#snack");
snack.addEventListener("change", () => {
  document.querySelector("#choice").textContent =
    \`Favourite snack: \${snack.value}\`;
});`}
/>

Use `input` when you want **live** updates, like a character counter or a search box that filters as you type.

## Keyboard events

The **`keydown`** event fires when a key is pressed. Read **`event.key`** to find out which one: `"a"`, `"A"`, `"Enter"`, `"Escape"`, `"ArrowUp"` and so on.

<TryIt
  html={`<p><input id="box" placeholder="Click here and press keys"></p>
<p id="last">Last key: none</p>`}
  code={`const box = document.querySelector("#box");
const last = document.querySelector("#last");

box.addEventListener("keydown", (event) => {
  last.textContent = \`Last key: \${event.key}\`;

  if (event.key === "Enter") {
    console.log("You pressed Enter! Text:", box.value);
    box.value = "";
  }
});`}
/>

Click inside the box first: key events go to the element that has **focus**.

## Forms and preventDefault

When a form is submitted (by clicking its button or pressing Enter in a field), the browser's **default behaviour** is to send the data to a server and **load a new page**. That reload would wipe out everything your JavaScript just did!

To handle the form yourself, listen for the **`submit`** event on the `<form>` and call **`event.preventDefault()`** first. It tells the browser: "don't do your usual thing, I've got this".

<TryIt
  html={`<form id="guestbook">
  <input id="guest" placeholder="Your name">
  <button>Sign the guestbook</button>
</form>
<p id="thanks"></p>`}
  code={`const guestbook = document.querySelector("#guestbook");
const guest = document.querySelector("#guest");
const thanks = document.querySelector("#thanks");

guestbook.addEventListener("submit", (event) => {
  event.preventDefault();

  const visitor = guest.value.trim();
  if (visitor === "") {
    thanks.textContent = "Please type your name first.";
    return;
  }

  thanks.textContent = \`Thanks for visiting, \${visitor}! 🐼\`;
  guest.value = "";
});`}
/>

<Callout type="tip" title="Listen on the form, not the button">

Listen for `submit` on the `<form>` rather than `click` on its button. Then it works for **both** clicking the button and pressing Enter, and the browser's built-in checks (like `required` fields) still work.

</Callout>

## Event delegation

Imagine a list with 100 items. Instead of adding 100 listeners, you can add **one** listener to the parent. Events **bubble up**: a click on an `<li>` also counts as a click on its `<ul>`. Inside the listener, `event.target` tells you which item was actually clicked. This trick is called **event delegation**.

<TryIt
  html={`<style>
  li { cursor: pointer; }
  .done { text-decoration: line-through; opacity: 0.5; }
</style>
<p>Click a chore to tick it off:</p>
<ul id="chores">
  <li>Water the bamboo</li>
  <li>Tidy the den</li>
  <li>Wash the bowls</li>
</ul>`}
  code={`const chores = document.querySelector("#chores");

chores.addEventListener("click", (event) => {
  if (event.target.matches("li")) {
    event.target.classList.toggle("done");
    console.log("Toggled:", event.target.textContent);
  }
});`}
/>

`event.target.matches("li")` checks whether the clicked element fits a CSS selector, so clicks on the gaps of the list itself are ignored. Delegation really shines in the next lesson, where you'll add new items to lists: the parent's listener works for them automatically.

Build a small sign-up form:

1. While the user types in `#username`, show how many characters they've typed in `#count` (use the `input` event).
2. When the form is submitted, stop the page from reloading. Then:
   - if the username is shorter than 3 characters, set `#message` to `Too short!`
   - otherwise set `#message` to `Welcome, <name>!` (for example `Welcome, Panda!`), clear the input and set `#count` back to `0`.

Try it in the preview: type a name and press Enter or click **Sign up**.

<Hint>

Add two listeners: `input.addEventListener("input", ...)` and `form.addEventListener("submit", (event) => { ... })`. The length of the text is `input.value.length`. In the submit listener, call `event.preventDefault()` first, then use an `if...else` on the length.

</Hint>

<Solution>

```js
const form = document.querySelector("#signup");
const input = document.querySelector("#username");
const count = document.querySelector("#count");
const message = document.querySelector("#message");

input.addEventListener("input", () => {
  count.textContent = input.value.length;
});

form.addEventListener("submit", (event) => {
  event.preventDefault();
  const username = input.value;

  if (username.length < 3) {
    message.textContent = "Too short!";
  } else {
    message.textContent = `Welcome, ${username}!`;
    input.value = "";
    count.textContent = 0;
  }
});
```

</Solution>

## Recap

- `element.addEventListener("event", listener)` runs `listener` every time the event happens. Pass the function, don't call it.
- Common events: `click`, `input` (every change), `change` (change finished), `keydown` (read `event.key`) and `submit`.
- The listener receives an **event object**; `event.target` is the element the event happened on.
- In a `submit` listener, call `event.preventDefault()` to stop the browser from reloading the page.
- **Event delegation**: one listener on a parent handles events from all its children, thanks to bubbling.
