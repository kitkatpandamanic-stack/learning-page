В первой части вы построили хранилище: модели `Project` и `Task` и репозиторий из небольших протестированных функций. Теперь мы надстроим над ним **веб-API**. Каждый запрос (request) будет получать собственную **сессию (session)** базы данных через `Depends`, входящие и исходящие данные будут проверять **схемы Pydantic**, а на запросы к несуществующим объектам API будет отвечать **404**. 🌐

Эта часть опирается на уроки [Тело запроса и валидация](/learn/python/request-validation) и [API списка дел](/learn/python/todo-api): инструменты те же, но теперь данные живут не в словаре, а в настоящей базе данных.

## Схемы: что приходит и что уходит

У нас уже есть **модели** SQLAlchemy, которые описывают таблицы. А API нужны **схемы (schemas)** Pydantic, которые описывают JSON. Их разделяют намеренно: клиент может прислать `name`, но никогда не должен выбирать `id`, а в ответе (response) может оказаться то, что вовсе не является столбцом, — например, список задач проекта. Как и в API списка дел, у каждой роли своя схема:

```python
class ProjectCreate(BaseModel):     # POST /projects
    name: str = Field(min_length=1, max_length=100)

class TaskCreate(BaseModel):        # POST /projects/{id}/tasks
    title: str = Field(min_length=1, max_length=200)

class TaskUpdate(BaseModel):        # PATCH: все поля необязательны
    title: str | None = Field(
        default=None, min_length=1, max_length=200
    )
    done: bool | None = None
```

Ограничения совпадают со столбцами `String(100)` и `String(200)`, поэтому слишком длинный текст отклоняется с кодом 422 ещё до того, как доберётся до базы данных.

### Читаем объекты SQLAlchemy с from_attributes

В схемах для ответа есть одна новая строка: **`model_config = ConfigDict(from_attributes=True)`**. Обычно Pydantic строит модель из **словаря**. С `from_attributes=True` он умеет читать и **атрибуты (attributes)** любого объекта — например, `Project` из SQLAlchemy:

<CodeExample output={`id=1 name='Garden'
{'id': 1, 'name': 'Garden', 'tasks': [{'id': 1, 'title': 'Dig', 'done': False, 'project_id': 1}]}
Input should be a valid dictionary or instance of PlainProject`}>

```python
from pydantic import BaseModel, ConfigDict, ValidationError
from sqlalchemy import ForeignKey, String, create_engine
from sqlalchemy.orm import (
    DeclarativeBase, Mapped, Session, mapped_column, relationship,
)

class Base(DeclarativeBase):
    pass

class Project(Base):
    __tablename__ = "projects"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))
    tasks: Mapped[list["Task"]] = relationship(
        back_populates="project", cascade="all, delete-orphan"
    )

class Task(Base):
    __tablename__ = "tasks"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(200))
    done: Mapped[bool] = mapped_column(default=False)
    project_id: Mapped[int] = mapped_column(ForeignKey("projects.id"))
    project: Mapped["Project"] = relationship(back_populates="tasks")

class TaskOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    title: str
    done: bool
    project_id: int

class ProjectOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    name: str

class ProjectDetail(ProjectOut):
    tasks: list[TaskOut]

class PlainProject(BaseModel):     # без from_attributes
    id: int
    name: str

engine = create_engine("sqlite://")
Base.metadata.create_all(engine)

with Session(engine) as session:
    garden = Project(name="Garden", tasks=[Task(title="Dig")])
    session.add(garden)
    session.commit()

    print(ProjectOut.model_validate(garden))
    print(ProjectDetail.model_validate(garden).model_dump())
    try:
        PlainProject.model_validate(garden)
    except ValidationError as error:
        print(error.errors()[0]["msg"])
```

</CodeExample>

- **`model_validate(garden)`** читает `garden.id` и `garden.name` и игнорирует всё остальное.
- **`ProjectDetail`** наследует `id` и `name` от `ProjectOut` и добавляет `tasks: list[TaskOut]`. Pydantic проходит по связи `garden.tasks` и превращает каждую `Task` в `TaskOut` — вложенный JSON без лишних усилий.
- Без `from_attributes` Pydantic отказывается принимать объект.

В эндпоинтах вам даже не придётся вызывать `model_validate` самим: вы возвращаете объект SQLAlchemy, а FastAPI преобразует его по `response_model`.

## Одна сессия на запрос

Каждому запросу нужна сессия базы данных, и после запроса сессию нужно **закрыть**, даже если эндпоинт (endpoint) упал. Это работа для **зависимости (dependency) с `yield`**: код до `yield` выполняется перед эндпоинтом, значение из `yield` получает эндпоинт, а код после `yield` выполняется, когда запрос завершён. Это тот же шаблон «подготовка, yield, уборка», что у фикстуры pytest или `@contextlib.contextmanager`:

<CodeExample output={`открываем сессию
работает эндпоинт
закрываем сессию
201 {'id': 1, 'name': 'Garden'}
открываем сессию
та же сессия: True
закрываем сессию
204`}>

```python
from fastapi import Depends, FastAPI
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field
from sqlalchemy import ForeignKey, String, create_engine
from sqlalchemy.orm import (
    DeclarativeBase, Mapped, Session, mapped_column, relationship,
)
from sqlalchemy.pool import StaticPool

class Base(DeclarativeBase):
    pass

class Project(Base):
    __tablename__ = "projects"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))
    tasks: Mapped[list["Task"]] = relationship(
        back_populates="project", cascade="all, delete-orphan"
    )

class Task(Base):
    __tablename__ = "tasks"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(200))
    done: Mapped[bool] = mapped_column(default=False)
    project_id: Mapped[int] = mapped_column(ForeignKey("projects.id"))
    project: Mapped["Project"] = relationship(back_populates="tasks")

class ProjectCreate(BaseModel):
    name: str = Field(min_length=1, max_length=100)

engine = create_engine(
    "sqlite://",
    connect_args={"check_same_thread": False},
    poolclass=StaticPool,
)
Base.metadata.create_all(engine)

def get_session():
    print("открываем сессию")
    with Session(engine) as session:
        yield session
    print("закрываем сессию")

def load_project(
    project_id: int, session: Session = Depends(get_session)
) -> Project:
    return session.get(Project, project_id)

app = FastAPI()

@app.post("/projects", status_code=201)
def api_create_project(
    data: ProjectCreate, session: Session = Depends(get_session)
):
    print("работает эндпоинт")
    project = Project(name=data.name)
    session.add(project)
    session.commit()
    return {"id": project.id, "name": project.name}

@app.delete("/projects/{project_id}", status_code=204)
def api_delete_project(
    project: Project = Depends(load_project),
    session: Session = Depends(get_session),
):
    print("та же сессия:", project in session)
    session.delete(project)
    session.commit()

client = TestClient(app)
response = client.post("/projects", json={"name": "Garden"})
print(response.status_code, response.json())
print(client.delete("/projects/1").status_code)
```

</CodeExample>

Посмотрите на второй запрос: сессия нужна и `api_delete_project`, и `load_project`. FastAPI вызывает `get_session` только **один раз за запрос** и отдаёт обоим **одну и ту же** сессию (`project in session` равно `True`). Это важно: объект, загруженный в одной сессии, нельзя просто так удалить через другую.

<Callout type="note" title="Зачем StaticPool и check_same_thread?">

FastAPI выполняет обычные эндпоинты, объявленные через `def`, в пуле **рабочих потоков (worker threads)**, чтобы один медленный запрос не задерживал остальные. Две настройки позволяют базе SQLite **в памяти** работать в таком режиме:

- `connect_args={"check_same_thread": False}`: по умолчанию модуль `sqlite3` в Python отказывается использовать соединение из другого потока — не из того, который его открыл.
- `poolclass=StaticPool`: база данных в памяти живёт **внутри одного соединения**. Обычно SQLAlchemy открывает несколько соединений, и каждое новое видело бы совершенно новую пустую базу (`no such table: projects`). `StaticPool` держит ровно одно соединение и раздаёт его всем.

С **файлом** базы данных (`"sqlite:///projects.db"`) нужен только `check_same_thread`, а для PostgreSQL не нужно ни то, ни другое. В настоящих проектах движок создают один раз, в `database.py`, по URL из настроек.

</Callout>

## Эндпоинты для проектов

Теперь по-настоящему. Эндпоинты тонкие: они берут данные запроса, вызывают функцию-репозиторий из первой части и возвращают результат. `response_model` превращает объекты SQLAlchemy в JSON, а `get_project_or_404` работает точно так же, как `get_todo_or_404` в API списка дел, только спрашивает базу данных:

<CodeExample output={`201 {'id': 1, 'name': 'Garden'}
[{'id': 1, 'name': 'Garden'}, {'id': 2, 'name': 'Kitchen'}]
{'id': 1, 'name': 'Garden', 'tasks': [{'id': 1, 'title': 'Dig', 'done': False, 'project_id': 1}]}
404 {'detail': 'Project not found'}
422 String should have at least 1 character`}>

```python
from fastapi import Depends, FastAPI, HTTPException
from fastapi.testclient import TestClient
from pydantic import BaseModel, ConfigDict, Field
from sqlalchemy import ForeignKey, String, create_engine, select
from sqlalchemy.orm import (
    DeclarativeBase, Mapped, Session, mapped_column, relationship,
)
from sqlalchemy.pool import StaticPool

class Base(DeclarativeBase):
    pass

class Project(Base):
    __tablename__ = "projects"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))
    tasks: Mapped[list["Task"]] = relationship(
        back_populates="project", cascade="all, delete-orphan"
    )

class Task(Base):
    __tablename__ = "tasks"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(200))
    done: Mapped[bool] = mapped_column(default=False)
    project_id: Mapped[int] = mapped_column(ForeignKey("projects.id"))
    project: Mapped["Project"] = relationship(back_populates="tasks")

def create_project(session: Session, name: str) -> Project:
    project = Project(name=name)
    session.add(project)
    session.commit()
    return project

def get_project(session: Session, project_id: int) -> Project | None:
    return session.get(Project, project_id)

def list_projects(session: Session) -> list[Project]:
    return list(session.scalars(select(Project).order_by(Project.id)))

def add_task(session: Session, project: Project, title: str) -> Task:
    task = Task(title=title, project=project)
    session.add(task)
    session.commit()
    return task

class ProjectCreate(BaseModel):
    name: str = Field(min_length=1, max_length=100)

class ProjectOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    name: str

class TaskOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    title: str
    done: bool
    project_id: int

class ProjectDetail(ProjectOut):
    tasks: list[TaskOut]

engine = create_engine(
    "sqlite://",
    connect_args={"check_same_thread": False},
    poolclass=StaticPool,
)
Base.metadata.create_all(engine)

def get_session():
    with Session(engine) as session:
        yield session

def get_project_or_404(
    project_id: int, session: Session = Depends(get_session)
) -> Project:
    project = get_project(session, project_id)
    if project is None:
        raise HTTPException(status_code=404, detail="Project not found")
    return project

app = FastAPI(title="Projects API")

@app.post("/projects", status_code=201, response_model=ProjectOut)
def api_create_project(
    data: ProjectCreate, session: Session = Depends(get_session)
):
    return create_project(session, data.name)

@app.get("/projects", response_model=list[ProjectOut])
def api_list_projects(session: Session = Depends(get_session)):
    return list_projects(session)

@app.get("/projects/{project_id}", response_model=ProjectDetail)
def api_get_project(project: Project = Depends(get_project_or_404)):
    return project

client = TestClient(app)
response = client.post("/projects", json={"name": "Garden"})
print(response.status_code, response.json())
client.post("/projects", json={"name": "Kitchen"})
print(client.get("/projects").json())

with Session(engine) as session:          # задача — способом из части 1
    add_task(session, get_project(session, 1), "Dig")
print(client.get("/projects/1").json())

response = client.get("/projects/99")
print(response.status_code, response.json())
response = client.post("/projects", json={"name": ""})
print(response.status_code, response.json()["detail"][0]["msg"])
```

</CodeExample>

На что стоит обратить внимание:

- Функции эндпоинтов называются **`api_...`**, потому что имена вроде `create_project` уже заняты репозиторием. В настоящем проекте они живут в разных файлах (`main.py` вызывал бы `repository.create_project(...)`), так что конфликта имён нет.
- `api_get_project` состоит из одной строки: зависимость уже нашла проект или ответила 404, а `response_model=ProjectDetail` добавляет его задачи.
- Пустое имя даже не доходит до нашего кода: Pydantic ответил **422** с тем же списком `detail`, который вы видели в уроке про валидацию.

<Callout type="warning" title="Не пускайте SQL в эндпоинты">

Очень хочется написать `session.scalars(select(Task)...)` прямо внутри эндпоинта. Не поддавайтесь: запрос к базе внутри эндпоинта можно протестировать только через HTTP, а похожие запросы начинают копироваться из эндпоинта в эндпоинт. Эндпоинты переводят между HTTP и Python, а с базой данных разговаривает репозиторий.

</Callout>

## Маршруты для задач

Задачи принадлежат проекту, поэтому **создание** и **получение списка** происходят внутри проекта: `POST /projects/{project_id}/tasks` и `GET /projects/{project_id}/tasks`. Эти эндпоинты используют `get_project_or_404`, поэтому на попытку добавить задачу в несуществующий проект API ответит 404.

Но у уже созданной задачи есть собственный уникальный id, поэтому `GET`, `PATCH` и `DELETE` используют короткий маршрут (route): **`/tasks/{task_id}`**. Длинные пути вроде `/projects/1/tasks/7` повторяют информацию и порождают неудобные вопросы (что, если задача 7 принадлежит проекту 2?). Вложенность не глубже одного уровня — распространённое правило REST.

Для упражнения вам понадобятся ещё две вещи:

- Фильтр `?done=` — это просто необязательный параметр запроса `done: bool | None = None`, который передаётся в `list_tasks`.
- Для `PATCH` вызов `data.model_dump(exclude_unset=True)` возвращает словарь только с теми полями, которые прислал клиент, например `{"done": True}`. Ровно этого и ждёт `update_task(session, task, changes)` из первой части.

1. `get_task_or_404(task_id, session)`: `Task` или **404** с `detail` `"Task not found"`.
2. `GET /projects/{project_id}`: проект вместе с задачами (`response_model=ProjectDetail`).
3. `DELETE /projects/{project_id}`: удалить проект (а с ним и его задачи), ответить **204**.
4. `POST /projects/{project_id}/tasks`: тело `TaskCreate`, ответ **201** с `TaskOut`.
5. `GET /projects/{project_id}/tasks`: задачи проекта списком, с необязательным параметром запроса `done`.

from fastapi import Depends, FastAPI, HTTPException
from fastapi.testclient import TestClient
from pydantic import BaseModel, ConfigDict, Field
from sqlalchemy import ForeignKey, String, create_engine, select
from sqlalchemy.orm import (
    DeclarativeBase, Mapped, Session, mapped_column, relationship,
)
from sqlalchemy.pool import StaticPool


# ---------- модели ----------

class Base(DeclarativeBase):
    pass


class Project(Base):
    __tablename__ = "projects"

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))
    tasks: Mapped[list["Task"]] = relationship(
        back_populates="project", cascade="all, delete-orphan"
    )


class Task(Base):
    __tablename__ = "tasks"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(200))
    done: Mapped[bool] = mapped_column(default=False)
    project_id: Mapped[int] = mapped_column(ForeignKey("projects.id"))
    project: Mapped["Project"] = relationship(back_populates="tasks")


# ---------- репозиторий ----------

def create_project(session: Session, name: str) -> Project:
    project = Project(name=name)
    session.add(project)
    session.commit()
    return project


def get_project(session: Session, project_id: int) -> Project | None:
    return session.get(Project, project_id)


def list_projects(session: Session) -> list[Project]:
    return list(session.scalars(select(Project).order_by(Project.id)))


def delete_project(session: Session, project: Project) -> None:
    session.delete(project)
    session.commit()


def add_task(session: Session, project: Project, title: str) -> Task:
    task = Task(title=title, project=project)
    session.add(task)
    session.commit()
    return task


def get_task(session: Session, task_id: int) -> Task | None:
    return session.get(Task, task_id)


def list_tasks(
    session: Session, project_id: int, done: bool | None = None
) -> list[Task]:
    stmt = select(Task).where(Task.project_id == project_id)
    if done is not None:
        stmt = stmt.where(Task.done == done)
    return list(session.scalars(stmt.order_by(Task.id)))


def update_task(session: Session, task: Task, changes: dict) -> Task:
    for field, value in changes.items():
        setattr(task, field, value)
    session.commit()
    return task


def delete_task(session: Session, task: Task) -> None:
    session.delete(task)
    session.commit()

class ProjectOut(BaseModel):

    id: int
    name: str


class TaskCreate(BaseModel):
    title: str = Field(min_length=1, max_length=200)


class TaskUpdate(BaseModel):
    title: str | None = Field(
        default=None, min_length=1, max_length=200
    )
    done: bool | None = None


class TaskOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    title: str
    done: bool
    project_id: int

    tasks: list[TaskOut]

def get_session():
    with Session(engine) as session:

def get_project_or_404(
    project_id: int, session: Session = Depends(get_session)
) -> Project:
    project = get_project(session, project_id)
    if project is None:
        raise HTTPException(status_code=404, detail="Project not found")
    return project


def get_task_or_404(

    if task is None:

    return task

## Что вы построили

- **Схемы Pydantic** для входных данных (`ProjectCreate`, `TaskCreate`, `TaskUpdate`) и для ответов (`ProjectOut`, `ProjectDetail`, `TaskOut`), которые читают объекты SQLAlchemy благодаря **`from_attributes=True`**.
- **Зависимость `get_session` с `yield`**, которая даёт каждому запросу одну сессию и всегда её закрывает.
- Движок, настроенный для базы в памяти, общей для нескольких потоков: **`StaticPool`** и **`check_same_thread=False`**.
- Девять **тонких эндпоинтов**, которые вызывают репозиторий; каждый **404** обрабатывают `get_project_or_404` и `get_task_or_404`, а каждый **422** — Pydantic.

API работает, но тесты пока есть только у репозитория. В **третьей части** мы напишем полный **набор тестов API**: свежая база данных для каждого теста, фикстура для клиента, параметризованные тесты ошибок и запуск всего этого на вашем компьютере. 🧪
