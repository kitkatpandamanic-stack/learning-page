String methods like `find()`, `split()` and `startswith()` are great when you know the **exact** text you're looking for. But what if you want "any phone number", "every date", or "a word that starts with a capital letter"? You need to describe a **pattern**. That's what **regular expressions** (regex for short) do, and Python's built-in `re` module speaks them fluently. 🔍

## Why regular expressions?

Say you want every number in a message. With string methods you'd split, strip punctuation and check `isdigit()` on each piece. With a regex it's one line:

<CodeExample output={`['3', '12', '2026']
['mei@example.com', 'sam@panda.dev']`}>

```python
import re

text = "Order 3 bamboo sticks for 12 pandas by 2026!"
print(re.findall(r"\d+", text))

contacts = "Email mei@example.com or sam@panda.dev today"
print(re.findall(r"\S+@\S+", contacts))
```

</CodeExample>

`\d+` means "one or more digits", and `\S+@\S+` means "some non-space characters, an `@`, then more non-space characters". `re.findall(pattern, text)` returns **every** piece of text that matches, as a list of strings.

<Callout type="tip" title="Strings first, regex second">

If a string method does the job (`"@" in email`, `line.startswith("ERROR")`), use it: it's faster to read. Reach for regex when the text you want has a **shape** rather than an exact value.

</Callout>

## Raw strings: r"..."

In normal strings, the backslash starts an escape: `"\n"` is a newline. Regex uses backslashes everywhere (`\d`, `\s`, `\b`), so we write patterns as **raw strings** with an `r` in front. In a raw string, a backslash is just a backslash:

<CodeExample output={`1
2
\\n`}>

```python
print(len("\n"))    # one character: a newline
print(len(r"\n"))   # two characters: \ and n
print(r"\n")
```

</CodeExample>

Without the `r`, some patterns quietly break (`"\b"` is a backspace character, not a word boundary) and others make Python print a `SyntaxWarning`. **Always write regex patterns as raw strings.**

## search, match and fullmatch

These three look for **one** match and give you a **match object**, or `None` if there's no match:

- **`re.search(pattern, text)`** finds the first match **anywhere** in the text.
- **`re.match(pattern, text)`** only matches at the **start** of the text.
- **`re.fullmatch(pattern, text)`** only matches if the **whole** text fits the pattern.

<CodeExample output={`Found 42 at position 7
None
<re.Match object; span=(0, 4), match='2026'>
None
True`}>

```python
import re

m = re.search(r"\d+", "Panda #42 is hungry")
print(f"Found {m.group()} at position {m.start()}")

print(re.match(r"\d+", "Room 101"))
print(re.match(r"\d+", "2026 was fun"))
print(re.fullmatch(r"\d+", "2026 was fun"))
print(re.fullmatch(r"\d+", "2026") is not None)
```

</CodeExample>

- `m.group()` is the matched text, and `m.start()` / `m.end()` say where it is.
- Because "no match" gives `None`, always check before using the result: `if m:`. Calling `.group()` on `None` raises an `AttributeError`.

## Character classes

A **character class** matches one character from a set. These are the ones you'll use most:

| Pattern | Matches one… |
| --- | --- |
| `\d` | digit, `0` to `9` |
| `\w` | "word" character: letter, digit or `_` |
| `\s` | whitespace: space, tab, newline |
| `\D`, `\W`, `\S` | anything **except** a digit, word character, whitespace |
| `.` | any character except a newline |
| `[aeiou]` | one of the listed characters |
| `[a-z]`, `[A-Z0-9]` | one character in a range |
| `[^0-9]` | any character **not** listed (`^` at the start of `[...]`) |

To match a special character literally, put a backslash in front: `\.` is a real dot, `\$` a dollar sign, `\(` a bracket.

<CodeExample output={`['e', 'i', 'o', 'e', 'a', 'o', 'o']
['A1', 'B2']
['3.50', '12.00']`}>

```python
import re

print(re.findall(r"[aeiou]", "Mei loves bamboo"))
print(re.findall(r"[A-Z]\d", "Seats A1, B2 and c3"))
print(re.findall(r"\d+\.\d\d", "Tea 3.50, cake 12.00, 7 forks"))
```

</CodeExample>

## Quantifiers: how many?

A **quantifier** after a character (or class) says how many times it repeats:

| Quantifier | Means |
| --- | --- |
| `*` | 0 or more |
| `+` | 1 or more |
| `?` | 0 or 1 (optional) |
| `{3}` | exactly 3 |
| `{2,4}` | 2 to 4 |
| `{2,}` | 2 or more |

<CodeExample output={`['colour', 'color']
['07700 900123']
['hmm', 'hmmmm']`}>

```python
import re

print(re.findall(r"colou?r", "colour or color?"))
print(re.findall(r"\d{5} \d{6}", "Call 07700 900123 or 123"))
print(re.findall(r"hm+", "hmm... hmmmm. h"))
```

</CodeExample>

### Greedy vs lazy

Quantifiers are **greedy**: they grab as much text as they can. Adding a `?` after them makes them **lazy**, so they take as little as possible:

<CodeExample output={`['<b>bold</b> and <i>italic</i>']
['<b>', '</b>', '<i>', '</i>']`}>

```python
import re

html = "<b>bold</b> and <i>italic</i>"
print(re.findall(r"<.+>", html))    # greedy: one huge match
print(re.findall(r"<.+?>", html))   # lazy: each tag
```

</CodeExample>

The greedy `.+` ran all the way to the **last** `>`. When a match is unexpectedly long, a missing `?` is usually why. (An even clearer fix here is `<[^>]+>`: "a `<`, then anything that isn't `>`, then `>`".)

## Anchors: where the match is

**Anchors** don't match characters, they match **positions**:

- `^` is the start of the text, and `$` is the end.
- `\b` is a **word boundary**: the edge between a word character and anything else.

<CodeExample output={`['cat']
['cat', 'cat', 'cat']
True
False`}>

```python
import re

text = "cat, category, concat"
print(re.findall(r"\bcat\b", text))   # the word "cat" only
print(re.findall(r"cat", text))       # cat anywhere

print(bool(re.search(r"^Hello", "Hello there")))
print(bool(re.search(r"^Hello", "Oh, Hello")))
```

</CodeExample>

## Groups: pulling out the parts

Brackets `( )` make a **group**. The whole pattern still has to match, but you can read each group's part separately. That's how you go from *finding* text to *extracting* data:

<CodeExample output={`2026-10-04
2026 10 04
('2026', '10', '04')
[('Mei', '92'), ('Sam', '78')]`}>

```python
import re

m = re.search(r"(\d{4})-(\d\d)-(\d\d)", "Due: 2026-10-04!")
print(m.group())       # the whole match (also m.group(0))
print(m.group(1), m.group(2), m.group(3))
print(m.groups())

scores = "Mei=92, Sam=78"
print(re.findall(r"(\w+)=(\d+)", scores))
```

</CodeExample>

When the pattern has groups, `findall` returns the **groups** of each match: a list of tuples, ready to loop over.

Inside a group, `|` means "or": `(cat|dog)s?` matches `cat`, `dogs` and so on. Groups also let a quantifier repeat several characters: `(ha)+` matches `hahaha`.

### Named groups

Numbers like `group(3)` are easy to mix up. A **named group** `(?P<name>...)` gives each part a name, and `groupdict()` turns the match into a dictionary:

<CodeExample output={`Sam
{'user': 'Sam', 'action': 'login', 'hour': '09'}`}>

```python
import re

pattern = r"(?P<user>\w+) did (?P<action>\w+) at (?P<hour>\d\d):\d\d"
m = re.search(pattern, "Sam did login at 09:15")

print(m.group("user"))
print(m.groupdict())
```

</CodeExample>

Remember that groups always give you **strings**: convert with `int()` when you need numbers.

## finditer, sub and split

**`re.finditer()`** is like `findall`, but gives you a full match object for each match, so you can use named groups and positions:

<CodeExample output={`Mei scored 92
Sam scored 78`}>

```python
import re

scores = "Mei=92, Sam=78"
for m in re.finditer(r"(?P<name>\w+)=(?P<score>\d+)", scores):
    print(m["name"], "scored", int(m["score"]))
```

</CodeExample>

(`m["name"]` is a short way to write `m.group("name")`.)

**`re.sub(pattern, replacement, text)`** replaces every match. In the replacement, `\1` (or `\g<name>`) puts a group's text back in. **`re.split(pattern, text)`** splits wherever the pattern matches, which is handy when the separators are messy:

<CodeExample output={`Too many spaces here
04/10/2026
['milk', 'eggs', 'bamboo', 'tea']`}>

```python
import re

print(re.sub(r"\s+", " ", "Too   many \t spaces   here"))
print(re.sub(r"(\d{4})-(\d\d)-(\d\d)", r"\3/\2/\1", "2026-10-04"))
print(re.split(r"\s*[,;]\s*", "milk, eggs;bamboo ,  tea"))
```

</CodeExample>

## Flags

**Flags** change how a pattern behaves. Pass them as the last argument:

- **`re.IGNORECASE`** (or `re.I`): upper and lower case match each other.
- **`re.MULTILINE`** (or `re.M`): `^` and `$` match at the start and end of **every line**, not just the whole text.
- **`re.VERBOSE`** (or `re.X`): spaces and newlines in the pattern are ignored, and `#` starts a comment, so you can lay out long patterns.

<CodeExample output={`['Panda', 'PANDA', 'panda']
['ERROR disk full', 'ERROR no bamboo']
('2026', '10', '04')`}>

```python
import re

print(re.findall(r"panda", "Panda PANDA panda", re.IGNORECASE))

log = "INFO start\nERROR disk full\nINFO ok\nERROR no bamboo"
print(re.findall(r"^ERROR.*$", log, re.MULTILINE))

date = re.compile(r"""
    (\d{4})   # year
    -(\d\d)   # month
    -(\d\d)   # day
""", re.VERBOSE)
print(date.search("Due 2026-10-04").groups())
```

</CodeExample>

Combine flags with `|`, for example `re.IGNORECASE | re.MULTILINE`.

## Compiling patterns

**`re.compile(pattern)`** turns a pattern into a reusable **pattern object** with the same methods: `.search()`, `.findall()`, `.sub()` and friends. Giving a pattern a good name makes code much easier to read, and you can use it again and again:

<CodeExample output={`['#python', '#regex']
['#bamboo']`}>

```python
import re

HASHTAG = re.compile(r"#\w+")

posts = ["Learning #python and #regex", "Lunch: #bamboo"]
for post in posts:
    print(HASHTAG.findall(post))
```

</CodeExample>

(Python also caches patterns you use with `re.search` and friends, so compiling is mostly about **readability**.)

## Validating vs extracting

There are two big jobs for regex, and they use different functions:

- **Validating**: "Is this whole string a valid code / username / postcode?" Use **`fullmatch`**, so nothing extra can sneak in at either end.
- **Extracting**: "Find the bits I want inside this text." Use **`search`**, **`findall`** or **`finditer`** with groups.

<CodeExample output={`True
False
True`}>

```python
import re

def is_valid_pin(text):
    return re.fullmatch(r"\d{4}", text) is not None

print(is_valid_pin("2580"))
print(is_valid_pin("25801"))           # too long
print(re.search(r"\d{4}", "25801") is not None)  # search says yes!
```

</CodeExample>

`search` happily found four digits **inside** `"25801"`, which is why validation needs `fullmatch` (or `^...$`).

<Callout type="warning" title="Know when to stop">

Regex is brilliant for small, regular shapes: dates, codes, log lines. It's the **wrong tool** for nested formats like **HTML** or **JSON** (use a parser such as `html.parser`, BeautifulSoup or the `json` module), and the full rules for **email addresses** are famously huge. For emails, a simple check like `\S+@\S+\.\S+` plus sending a confirmation email beats a 500-character pattern nobody can read.

</Callout>

## Testing your patterns

Patterns are easy to get *almost* right. Before you trust one, test it with a few strings that **should** match and a few that **shouldn't**, including the tricky edge cases:

<CodeExample output="All pattern tests passed">

```python
import re

TIME = re.compile(r"([01]\d|2[0-3]):[0-5]\d")

good = ["00:00", "09:30", "23:59"]
bad = ["24:00", "9:30", "12:60", "12:30pm"]

for text in good:
    assert TIME.fullmatch(text), f"should match: {text}"
for text in bad:
    assert not TIME.fullmatch(text), f"shouldn't match: {text}"
print("All pattern tests passed")
```

</CodeExample>

Sites like **regex101.com** (choose the Python flavour) show what each part of a pattern does and highlight matches as you type. They're great for building a pattern step by step.

For the order, use named groups like `(?P<id>\d+)`, `(?P<item>.+)` and `(?P<price>\d+\.\d+)`, then convert them with `int()` and `float()`. `tidy` is `re.sub(r"\s+", " ", text).strip()`.

import re

USERNAME = re.compile(r"[A-Za-z]\w{2,15}")
HASHTAG = re.compile(r"#(\w+)")
ORDER = re.compile(
    r"Order #(?P<id>\d+): (?P<qty>\d+) x (?P<item>.+) at (?P<price>\d+\.\d+)"
)

def is_valid_username(name):
    return USERNAME.fullmatch(name) is not None

def find_hashtags(text):
    return [tag.lower() for tag in HASHTAG.findall(text)]

def parse_order(line):
    m = ORDER.fullmatch(line)
    if not m:
        return None
    return {
        "id": int(m["id"]),
        "qty": int(m["qty"]),
        "item": m["item"],
        "price": float(m["price"]),
    }

def tidy(text):
    return re.sub(r"\s+", " ", text).strip()

print(is_valid_username("mei_2026"))
print(find_hashtags("Loving #Python and #regex_101 today"))
print(parse_order("Order #1042: 3 x Bamboo at 4.50"))
print(tidy("  too   many\t spaces "))

## Recap

- A **regular expression** describes a **pattern** of text. Use them when string methods can't describe what you want.
- Write patterns as **raw strings**: `r"\d+"`.
- `search` finds the first match anywhere, `match` only at the start, `fullmatch` only the whole string. No match gives `None`.
- `findall` returns all matches (or their groups), `finditer` gives match objects, `sub` replaces and `split` splits.
- Building blocks: classes (`\d`, `\w`, `\s`, `[a-z]`), quantifiers (`*`, `+`, `?`, `{2,4}`, lazy `+?`), anchors (`^`, `$`, `\b`).
- **Groups** `( )` and **named groups** `(?P<name>...)` extract parts; `groupdict()` gives a dict of strings.
- Flags: `re.IGNORECASE`, `re.MULTILINE`, `re.VERBOSE`. `re.compile` gives a pattern a name.
- Validate with `fullmatch`, extract with `search`/`findall`/`finditer`, test patterns with good and bad examples, and don't parse HTML with regex.
