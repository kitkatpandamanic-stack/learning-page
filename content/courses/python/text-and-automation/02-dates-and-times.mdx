Deadlines, opening hours, log timestamps, birthdays, "posted 3 hours ago"... almost every program deals with time. Time is also full of traps: months have different lengths, clocks jump forward and back, and "9:00" means different moments in London and Tokyo. Python's `datetime` and `zoneinfo` modules handle the hard parts for you, as long as you use them the right way. 🕰️

You've already met `date`, `timedelta` and `strftime` in the [Modules and imports](/learn/python/modules-and-imports) tour. Now let's go properly deep.

## date, time and datetime

The `datetime` module has three main types:

- **`date`**: a calendar day (year, month, day).
- **`time`**: a time of day (hour, minute, second).
- **`datetime`**: both together, a precise moment.

<CodeExample output={`2026-10-04
09:30:00
2026-10-04 14:30:00
2026 10 4 14 30
6 Sunday
2026-10-04 14:30:00`}>

```python
from datetime import date, time, datetime

birthday = date(2026, 10, 4)
alarm = time(9, 30)
meeting = datetime(2026, 10, 4, 14, 30)

print(birthday)
print(alarm)
print(meeting)
print(meeting.year, meeting.month, meeting.day,
      meeting.hour, meeting.minute)
print(meeting.weekday(), meeting.strftime("%A"))  # Monday is 0
print(datetime.combine(birthday, time(14, 30)))
```

</CodeExample>

- These objects are **immutable**. To change one part, make a new one with `.replace()`: `meeting.replace(hour=16)`.
- `meeting.date()` and `meeting.time()` split a `datetime` back into its parts.

To get the **current** date and time, use `date.today()` and `datetime.now()`. Their output changes every time you run them, so the examples in this lesson use fixed dates:

```python
from datetime import date, datetime, timezone

print(date.today())                 # e.g. 2026-10-04
print(datetime.now())               # e.g. 2026-10-04 14:30:12.345678
print(datetime.now(timezone.utc))   # the current moment in UTC
```

## timedelta: lengths of time

A **`timedelta`** is a duration: "3 days", "90 minutes". Add it to a date or datetime to move forward, subtract it to go back. Subtracting two datetimes gives you a `timedelta`:

<CodeExample output={`2026-10-05 02:30:00
1 day, 12:00:00
30 days, 3:15:00
30
2603700.0
True`}>

```python
from datetime import datetime, timedelta

start = datetime(2026, 10, 4, 14, 30)
print(start + timedelta(hours=12))
print(timedelta(hours=36))

deadline = datetime(2026, 11, 3, 17, 45)
left = deadline - start
print(left)
print(left.days)
print(left.total_seconds())
print(left > timedelta(weeks=4))
```

</CodeExample>

- A `timedelta` stores **days, seconds and microseconds**. `.days` is only the whole days part; for a total, use `.total_seconds()` and divide (by 60 for minutes, 3600 for hours).
- `timedelta` accepts `weeks`, `days`, `hours`, `minutes` and `seconds`, but **not months or years**, because they don't have a fixed length. More on that below.

## Formatting with strftime

**`strftime`** ("string format time") turns a date into text using **format codes**. The same codes work inside f-strings after a colon:

| Code | Meaning | Example |
| --- | --- | --- |
| `%Y` | year | `2026` |
| `%m` | month as a number | `10` |
| `%d` | day of the month | `04` |
| `%H` / `%M` / `%S` | hour (24h) / minute / second | `14` / `30` / `00` |
| `%I` and `%p` | hour (12h) and AM/PM | `02` `PM` |
| `%A` / `%a` | weekday name / short name | `Sunday` / `Sun` |
| `%B` / `%b` | month name / short name | `October` / `Oct` |

<CodeExample output={`04/10/2026
Sunday 04 October, 02:30 PM
Sun 04 Oct 2026, 14:30
4 October`}>

```python
from datetime import datetime

meeting = datetime(2026, 10, 4, 14, 30)

print(meeting.strftime("%d/%m/%Y"))
print(meeting.strftime("%A %d %B, %I:%M %p"))
print(f"{meeting:%a %d %b %Y, %H:%M}")
print(f"{meeting.day} {meeting:%B}")
```

</CodeExample>

Number codes like `%d` and `%I` always use two digits. For "4 October" without the zero, put `meeting.day` in the f-string instead, like the last line.

## Parsing with strptime

**`strptime`** ("string **parse** time") does the opposite: it reads text using the **same** format codes and gives you a `datetime`. The format must match the text exactly, or you get a `ValueError`:

<CodeExample output={`2026-10-04 14:30:00
2026-10-04
Can't read '2026-10-04': time data '2026-10-04' does not match format '%d/%m/%Y'`}>

```python
from datetime import datetime

dt = datetime.strptime("04/10/2026 14:30", "%d/%m/%Y %H:%M")
print(dt)

d = datetime.strptime("4 Oct 2026", "%d %b %Y").date()
print(d)

try:
    datetime.strptime("2026-10-04", "%d/%m/%Y")
except ValueError as error:
    print(f"Can't read '2026-10-04': {error}")
```

</CodeExample>

<Callout type="tip" title="A memory trick">

**strf**time **f**ormats a date into a string; **strp**time **p**arses a string into a date.

</Callout>

### ISO 8601: the best format for computers

`04/10/2026` is the 4th of October in the UK but April the 10th in the US! For files, APIs and databases, use the international **ISO 8601** format: `2026-10-04T14:30:00`. `isoformat()` writes it and `fromisoformat()` reads it, no format codes needed:

<CodeExample output={`2026-10-04T14:30:00
2026-10-04 14:30:00
2026-10-04 14:30:00+01:00
['2025-12-31', '2026-01-15', '2026-10-04']`}>

```python
from datetime import datetime

meeting = datetime(2026, 10, 4, 14, 30)
text = meeting.isoformat()
print(text)
print(datetime.fromisoformat(text))
print(datetime.fromisoformat("2026-10-04T14:30:00+01:00"))

# ISO dates even sort correctly as plain text
print(sorted(["2026-10-04", "2025-12-31", "2026-01-15"]))
```

</CodeExample>

## Comparing and sorting dates

Dates and datetimes compare with `<`, `>` and `==` like numbers, so `sorted()`, `min()` and `max()` just work. The trap is sorting dates while they're still **text** in a format like `dd/mm/yyyy`. Parse them first, for example with a `key` function:

<CodeExample output={`['01/12/2025', '15/01/2026', '28/02/2025']
['28/02/2025', '01/12/2025', '15/01/2026']
Latest: 2026-01-15`}>

```python
from datetime import datetime

dates = ["15/01/2026", "01/12/2025", "28/02/2025"]

def parse(text):
    return datetime.strptime(text, "%d/%m/%Y").date()

print(sorted(dates))             # wrong: compares text
print(sorted(dates, key=parse))  # right: compares dates
print("Latest:", max(parse(d) for d in dates))
```

</CodeExample>

## Naive vs aware datetimes

Every `datetime` so far has been **naive**: it doesn't know which time zone it's in. `14:30` could be in London, Tokyo or anywhere. An **aware** datetime carries a `tzinfo`, so it pins down one exact moment in the world:

<CodeExample output={`None
UTC
2026-10-04 12:00:00+00:00
can't compare offset-naive and offset-aware datetimes`}>

```python
from datetime import datetime, timezone

naive = datetime(2026, 10, 4, 12, 0)
aware = datetime(2026, 10, 4, 12, 0, tzinfo=timezone.utc)

print(naive.tzinfo)
print(aware.tzinfo)
print(aware)

try:
    print(naive < aware)
except TypeError as error:
    print(error)
```

</CodeExample>

The `+00:00` at the end is the **UTC offset**: how far this clock is from UTC (Coordinated Universal Time, the world's reference clock). Python refuses to compare naive and aware datetimes, because it can't know what the naive one means.

## Time zones with zoneinfo

**`zoneinfo.ZoneInfo`** knows the rules of every time zone in the world by name, like `"Europe/London"`, `"Asia/Tokyo"` or `"America/New_York"`, including when their clocks change. Make an aware datetime with `tzinfo=ZoneInfo(...)`, then convert it with **`.astimezone()`**:

<CodeExample output={`London:   2026-10-04 14:30:00+01:00
Tokyo:    2026-10-04 22:30:00+09:00
New York: 2026-10-04 09:30:00-04:00
UTC:      2026-10-04 13:30:00+00:00
True`}>

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

call = datetime(2026, 10, 4, 14, 30,
                tzinfo=ZoneInfo("Europe/London"))

print("London:  ", call)
print("Tokyo:   ", call.astimezone(ZoneInfo("Asia/Tokyo")))
print("New York:", call.astimezone(ZoneInfo("America/New_York")))
print("UTC:     ", call.astimezone(timezone.utc))

tokyo = call.astimezone(ZoneInfo("Asia/Tokyo"))
print(tokyo == call)   # same moment, different clocks
```

</CodeExample>

Converting doesn't change the **moment**, only how the clock shows it, so the Tokyo and London versions are equal. Notice London is `+01:00` here: in October the UK is on summer time (BST). `ZoneInfo` figures that out from the date.

<Callout type="note" title="Use zone names, not fixed offsets">

Write `ZoneInfo("Europe/London")`, not "+01:00". A fixed offset is only right for half the year, but a zone name knows every clock change, past and future. On your own computer, Windows may need `pip install tzdata` for `zoneinfo` to find the zone rules.

</Callout>

## Store in UTC, show in local time

The rule professionals follow:

1. **Store and calculate** times as aware datetimes in **UTC** (in files, databases, logs, APIs).
2. **Convert to the user's zone only when you show** a time to a person.

UTC never jumps forward or back, so arithmetic and sorting are always correct, and you can show the same moment to people in different countries.

<CodeExample output={`Saved: 2026-10-04T13:30:00+00:00
Mei (London) sees: 14:30
Kai (Tokyo) sees: 22:30`}>

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

saved = datetime(2026, 10, 4, 13, 30, tzinfo=timezone.utc)
print("Saved:", saved.isoformat())

users = {"Mei": "Europe/London", "Kai": "Asia/Tokyo"}
for name, zone in users.items():
    local = saved.astimezone(ZoneInfo(zone))
    city = zone.split("/")[1]
    print(f"{name} ({city}) sees: {local:%H:%M}")
```

</CodeExample>

## Date arithmetic pitfalls

### Months aren't a fixed length

There's no `timedelta(months=1)`, and "30 days later" isn't "one month later". To move by months, change the month number yourself and **clamp** the day to the last day of that month. `calendar.monthrange(year, month)[1]` gives the number of days in a month:

<CodeExample output={`2026-03-02
2026-02-28
2028-02-29
2027-01-15`}>

```python
import calendar
from datetime import date, timedelta

def add_months(d, months):
    index = d.month - 1 + months
    year = d.year + index // 12
    month = index % 12 + 1
    last_day = calendar.monthrange(year, month)[1]
    return d.replace(year=year, month=month,
                     day=min(d.day, last_day))

jan31 = date(2026, 1, 31)
print(jan31 + timedelta(days=30))   # not in February at all!
print(add_months(jan31, 1))
print(add_months(date(2028, 1, 31), 1))   # 2028 is a leap year
print(add_months(date(2026, 10, 15), 3))
```

</CodeExample>

### Daylight saving time

On 29 March 2026, UK clocks jump from 01:00 to 02:00, so that day only has **23 hours**. When you add a `timedelta` to a datetime in a named zone, Python moves the **wall clock** ("same time tomorrow"), not the real elapsed time:

<CodeExample output={`2026-03-29 12:00:00+01:00
1 day, 0:00:00
23:00:00`}>

```python
from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo

london = ZoneInfo("Europe/London")
before = datetime(2026, 3, 28, 12, 0, tzinfo=london)
after = before + timedelta(days=1)

print(after)                       # noon again, but now +01:00
print(after - before)              # wall-clock difference
utc = timezone.utc
print(after.astimezone(utc) - before.astimezone(utc))  # real time
```

</CodeExample>

"Same time tomorrow" is exactly what you want for a daily alarm, but for "how many hours did this job run?" you need the real time. That's one more reason to **calculate in UTC**.

## Inject "now" for testable code

Code that calls `datetime.now()` inside gives a different answer every time it runs, which makes it impossible to test. "Is this overdue?" depends on *when* you ask! The fix is simple: let the caller **pass in** `now`, and only fall back to the real clock when they don't:

<CodeExample output={`False
True
due in 2 days`}>

```python
from datetime import datetime, timedelta, timezone

def is_overdue(due, now=None):
    if now is None:
        now = datetime.now(timezone.utc)
    return now > due

def describe(due, now):
    days = (due - now).days
    if days < 0:
        return f"{-days} days late"
    return f"due in {days} days"

due = datetime(2026, 10, 10, 17, 0, tzinfo=timezone.utc)
monday = datetime(2026, 10, 5, 9, 0, tzinfo=timezone.utc)

print(is_overdue(due, now=monday))
print(is_overdue(due, now=monday + timedelta(weeks=1)))
print(describe(due, monday + timedelta(days=3)))
```

</CodeExample>

The real program calls `is_overdue(due)`, while tests pass a fixed `now` and get the same result every time. You'll use this trick a lot, starting with today's date in the Level 1 capstone, the [expense tracker](/learn/python/the-command-line).

<Hint>

Split the text with `text.rsplit(" ", 1)` to get the date-and-time part and the zone name. Parse the first part with `datetime.strptime(..., "%Y-%m-%d %H:%M")`, then add the zone with `.replace(tzinfo=ZoneInfo(zone))`. For `show_in`, use `.astimezone(ZoneInfo(zone))` and the format `"%a %d %b, %H:%M"`.
```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

def parse_meeting(text):
    when, zone = text.rsplit(" ", 1)
    local = datetime.strptime(when, "%Y-%m-%d %H:%M")
    return local.replace(tzinfo=ZoneInfo(zone))

def show_in(meeting, zone):
    local = meeting.astimezone(ZoneInfo(zone))
    return local.strftime("%a %d %b, %H:%M")

def minutes_until(meeting, now):
    utc = timezone.utc
    diff = meeting.astimezone(utc) - now.astimezone(utc)
    return int(diff.total_seconds() // 60)

def sort_meetings(texts):
    return sorted(texts, key=parse_meeting)

m = parse_meeting("2026-10-04 14:30 Europe/London")
print(m)
print(show_in(m, "Asia/Tokyo"))
now = datetime(2026, 10, 4, 12, 0, tzinfo=timezone.utc)
print(minutes_until(m, now))
print(sort_meetings([
    "2026-10-04 08:00 Europe/London",
    "2026-10-04 09:00 Asia/Tokyo",
]))
```

## Recap

- `date` is a day, `time` is a time of day, `datetime` is both. `timedelta` is a duration you add, subtract and compare.
- `strftime` **formats** a date as text; `strptime` **parses** text with the same codes (`%Y`, `%m`, `%d`, `%H`, `%M`...).
- Use **ISO 8601** (`isoformat()` / `fromisoformat()`) for files and APIs.
- Parse text dates before sorting or comparing them.
- **Naive** datetimes have no time zone; **aware** ones do. Use `ZoneInfo("Europe/London")` and `.astimezone()` to convert.
- **Store and calculate in UTC**, convert to local time only for display.
- Watch out for month lengths (no `timedelta(months=...)`) and daylight saving changes.
- Pass `now` into time-based functions so you can test them.
