Дедлайны, часы работы, отметки времени в логах, дни рождения, «опубликовано 3 часа назад»... почти каждая программа имеет дело со временем. И время полно ловушек: в месяцах разное число дней, часы переводят вперёд и назад, а «9:00» в Лондоне и в Токио — это разные моменты. Модули Python `datetime` и `zoneinfo` берут самое сложное на себя — если пользоваться ими правильно. 🕰️

Вы уже встречали `date`, `timedelta` и `strftime` в обзоре [Модули и импорт](/learn/python/modules-and-imports). Теперь разберёмся как следует.

## date, time и datetime

В модуле `datetime` три основных типа:

- **`date`**: календарный день (год, месяц, день).
- **`time`**: время суток (часы, минуты, секунды).
- **`datetime`**: и то и другое вместе — точный момент.

<CodeExample output={`2026-10-04
09:30:00
2026-10-04 14:30:00
2026 10 4 14 30
6 Sunday
2026-10-04 14:30:00`}>

```python
from datetime import date, time, datetime

birthday = date(2026, 10, 4)
alarm = time(9, 30)
meeting = datetime(2026, 10, 4, 14, 30)

print(birthday)
print(alarm)
print(meeting)
print(meeting.year, meeting.month, meeting.day,
      meeting.hour, meeting.minute)
print(meeting.weekday(), meeting.strftime("%A"))  # понедельник — это 0
print(datetime.combine(birthday, time(14, 30)))
```

</CodeExample>

- Эти объекты **неизменяемые** (immutable). Чтобы поменять одну часть, создайте новый объект через `.replace()`: `meeting.replace(hour=16)`.
- `meeting.date()` и `meeting.time()` разделяют `datetime` обратно на части.

Чтобы получить **текущие** дату и время, используйте `date.today()` и `datetime.now()`. Их вывод меняется при каждом запуске, поэтому в примерах этого урока даты фиксированные:

```python
from datetime import date, datetime, timezone

print(date.today())                 # например, 2026-10-04
print(datetime.now())               # например, 2026-10-04 14:30:12.345678
print(datetime.now(timezone.utc))   # текущий момент в UTC
```

Названия дней недели и месяцев (`Sunday`, `October`) Python выводит по-английски — это зависит от настроек языка системы (локали), и в этом уроке они остаются английскими.

## timedelta: промежутки времени

**`timedelta`** — это длительность: «3 дня», «90 минут». Прибавьте её к дате или datetime, чтобы сдвинуться вперёд, вычтите — чтобы назад. А разность двух datetime даёт `timedelta`:

<CodeExample output={`2026-10-05 02:30:00
1 day, 12:00:00
30 days, 3:15:00
30
2603700.0
True`}>

```python
from datetime import datetime, timedelta

start = datetime(2026, 10, 4, 14, 30)
print(start + timedelta(hours=12))
print(timedelta(hours=36))

deadline = datetime(2026, 11, 3, 17, 45)
left = deadline - start
print(left)
print(left.days)
print(left.total_seconds())
print(left > timedelta(weeks=4))
```

</CodeExample>

- `timedelta` хранит **дни, секунды и микросекунды**. `.days` — это только часть с целыми днями; для полной длительности используйте `.total_seconds()` и делите (на 60 для минут, на 3600 для часов).
- `timedelta` принимает `weeks`, `days`, `hours`, `minutes` и `seconds`, но **не месяцы и не годы**: у них нет фиксированной длины. Подробнее об этом ниже.

## Форматирование через strftime

**`strftime`** («string format time») превращает дату в текст с помощью **кодов формата** (format codes). Те же коды работают в f-строках после двоеточия:

| Код | Значение | Пример |
| --- | --- | --- |
| `%Y` | год | `2026` |
| `%m` | месяц числом | `10` |
| `%d` | день месяца | `04` |
| `%H` / `%M` / `%S` | час (24 ч) / минута / секунда | `14` / `30` / `00` |
| `%I` и `%p` | час (12 ч) и AM/PM | `02` `PM` |
| `%A` / `%a` | название дня недели / сокращённое | `Sunday` / `Sun` |
| `%B` / `%b` | название месяца / сокращённое | `October` / `Oct` |

<CodeExample output={`04/10/2026
Sunday 04 October, 02:30 PM
Sun 04 Oct 2026, 14:30
4 October`}>

```python
from datetime import datetime

meeting = datetime(2026, 10, 4, 14, 30)

print(meeting.strftime("%d/%m/%Y"))
print(meeting.strftime("%A %d %B, %I:%M %p"))
print(f"{meeting:%a %d %b %Y, %H:%M}")
print(f"{meeting.day} {meeting:%B}")
```

</CodeExample>

Числовые коды вроде `%d` и `%I` всегда дают две цифры. Чтобы получить «4 October» без нуля, подставьте в f-строку `meeting.day`, как в последней строке.

## Разбор через strptime

**`strptime`** («string **parse** time») делает обратное: читает текст по **тем же** кодам формата и возвращает `datetime`. Формат должен точно соответствовать тексту, иначе будет `ValueError`:

<CodeExample output={`2026-10-04 14:30:00
2026-10-04
Не удаётся прочитать '2026-10-04': time data '2026-10-04' does not match format '%d/%m/%Y'`}>

```python
from datetime import datetime

dt = datetime.strptime("04/10/2026 14:30", "%d/%m/%Y %H:%M")
print(dt)

d = datetime.strptime("4 Oct 2026", "%d %b %Y").date()
print(d)

try:
    datetime.strptime("2026-10-04", "%d/%m/%Y")
except ValueError as error:
    print(f"Не удаётся прочитать '2026-10-04': {error}")
```

</CodeExample>

<Callout type="tip" title="Как запомнить">

**strf**time — **f**ormat: форматирует дату в строку; **strp**time — **p**arse: разбирает строку в дату.

</Callout>

### ISO 8601: лучший формат для компьютеров

`04/10/2026` в Великобритании — это 4 октября, а в США — 10 апреля! Для файлов, API и баз данных используйте международный формат **ISO 8601**: `2026-10-04T14:30:00`. `isoformat()` записывает его, а `fromisoformat()` читает — никакие коды формата не нужны:

<CodeExample output={`2026-10-04T14:30:00
2026-10-04 14:30:00
2026-10-04 14:30:00+01:00
['2025-12-31', '2026-01-15', '2026-10-04']`}>

```python
from datetime import datetime

meeting = datetime(2026, 10, 4, 14, 30)
text = meeting.isoformat()
print(text)
print(datetime.fromisoformat(text))
print(datetime.fromisoformat("2026-10-04T14:30:00+01:00"))

# даты в ISO правильно сортируются даже как обычный текст
print(sorted(["2026-10-04", "2025-12-31", "2026-01-15"]))
```

</CodeExample>

## Сравнение и сортировка дат

Даты и datetime сравниваются через `<`, `>` и `==`, как числа, поэтому `sorted()`, `min()` и `max()` просто работают. Ловушка — сортировать даты, пока они ещё **текст** в формате вроде `dd/mm/yyyy`. Сначала разберите их, например функцией в `key`:

<CodeExample output={`['01/12/2025', '15/01/2026', '28/02/2025']
['28/02/2025', '01/12/2025', '15/01/2026']
Самая поздняя: 2026-01-15`}>

```python
from datetime import datetime

dates = ["15/01/2026", "01/12/2025", "28/02/2025"]

def parse(text):
    return datetime.strptime(text, "%d/%m/%Y").date()

print(sorted(dates))             # неправильно: сравнивает текст
print(sorted(dates, key=parse))  # правильно: сравнивает даты
print("Самая поздняя:", max(parse(d) for d in dates))
```

</CodeExample>

## Наивные и осведомлённые datetime

До сих пор все `datetime` были **наивными** (naive): они не знают, в каком они часовом поясе. `14:30` может быть в Лондоне, Токио или где угодно. **Осведомлённый** (aware) datetime несёт с собой `tzinfo`, поэтому обозначает один точный момент в мире:

<CodeExample output={`None
UTC
2026-10-04 12:00:00+00:00
can't compare offset-naive and offset-aware datetimes`}>

```python
from datetime import datetime, timezone

naive = datetime(2026, 10, 4, 12, 0)
aware = datetime(2026, 10, 4, 12, 0, tzinfo=timezone.utc)

print(naive.tzinfo)
print(aware.tzinfo)
print(aware)

try:
    print(naive < aware)
except TypeError as error:
    print(error)
```

</CodeExample>

`+00:00` в конце — это **смещение от UTC** (UTC offset): насколько эти часы отличаются от UTC (Coordinated Universal Time, всемирного координированного времени — эталонных часов мира). Python отказывается сравнивать наивные и осведомлённые datetime, потому что не может знать, что означает наивный.

## Часовые пояса с zoneinfo

**`zoneinfo.ZoneInfo`** знает правила каждого часового пояса (time zone) мира по названию — например, `"Europe/London"`, `"Asia/Tokyo"` или `"America/New_York"`, — включая то, когда там переводят часы. Создайте осведомлённый datetime с `tzinfo=ZoneInfo(...)`, а затем переведите его в другой пояс через **`.astimezone()`**:

<CodeExample output={`Лондон:   2026-10-04 14:30:00+01:00
Токио:    2026-10-04 22:30:00+09:00
Нью-Йорк: 2026-10-04 09:30:00-04:00
UTC:      2026-10-04 13:30:00+00:00
True`}>

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

call = datetime(2026, 10, 4, 14, 30,
                tzinfo=ZoneInfo("Europe/London"))

print("Лондон:  ", call)
print("Токио:   ", call.astimezone(ZoneInfo("Asia/Tokyo")))
print("Нью-Йорк:", call.astimezone(ZoneInfo("America/New_York")))
print("UTC:     ", call.astimezone(timezone.utc))

tokyo = call.astimezone(ZoneInfo("Asia/Tokyo"))
print(tokyo == call)   # тот же момент, разные часы
```

</CodeExample>

Перевод не меняет **момент** — только то, как его показывают часы, поэтому лондонская и токийская версии равны. Заметьте, что у Лондона здесь `+01:00`: в октябре в Великобритании действует летнее время (BST). `ZoneInfo` определяет это по дате.

<Callout type="note" title="Используйте названия поясов, а не фиксированные смещения">

Пишите `ZoneInfo("Europe/London")`, а не «+01:00». Фиксированное смещение верно только полгода, а название пояса знает обо всех переводах часов — прошлых и будущих. На вашем компьютере под Windows может понадобиться `pip install tzdata`, чтобы `zoneinfo` нашёл правила часовых поясов.

</Callout>

## Храните в UTC, показывайте в местном времени

Правило, которому следуют профессионалы:

1. **Храните и вычисляйте** время как осведомлённые datetime в **UTC** (в файлах, базах данных, логах, API).
2. **Переводите в пояс пользователя, только когда показываете** время человеку.

UTC никогда не переводят вперёд или назад, поэтому арифметика и сортировка всегда верны, а один и тот же момент можно показать людям в разных странах.

<CodeExample output={`Сохранено: 2026-10-04T13:30:00+00:00
Mei (London) видит: 14:30
Kai (Tokyo) видит: 22:30`}>

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

saved = datetime(2026, 10, 4, 13, 30, tzinfo=timezone.utc)
print("Сохранено:", saved.isoformat())

users = {"Mei": "Europe/London", "Kai": "Asia/Tokyo"}
for name, zone in users.items():
    local = saved.astimezone(ZoneInfo(zone))
    city = zone.split("/")[1]
    print(f"{name} ({city}) видит: {local:%H:%M}")
```

</CodeExample>

## Подводные камни арифметики дат

### У месяцев нет фиксированной длины

`timedelta(months=1)` не существует, а «через 30 дней» — это не «через месяц». Чтобы сдвинуться на месяцы, меняйте номер месяца сами и **ограничивайте** день последним днём этого месяца. `calendar.monthrange(year, month)[1]` даёт число дней в месяце:

<CodeExample output={`2026-03-02
2026-02-28
2028-02-29
2027-01-15`}>

```python
import calendar
from datetime import date, timedelta

def add_months(d, months):
    index = d.month - 1 + months
    year = d.year + index // 12
    month = index % 12 + 1
    last_day = calendar.monthrange(year, month)[1]
    return d.replace(year=year, month=month,
                     day=min(d.day, last_day))

jan31 = date(2026, 1, 31)
print(jan31 + timedelta(days=30))   # даже не февраль!
print(add_months(jan31, 1))
print(add_months(date(2028, 1, 31), 1))   # 2028 — високосный год
print(add_months(date(2026, 10, 15), 3))
```

</CodeExample>

### Летнее время

29 марта 2026 года часы в Великобритании переводят с 01:00 на 02:00, поэтому в этих сутках всего **23 часа**. Когда вы прибавляете `timedelta` к datetime в именованном поясе, Python сдвигает **показания часов на стене** («завтра в то же время»), а не реально прошедшее время:

<CodeExample output={`2026-03-29 12:00:00+01:00
1 day, 0:00:00
23:00:00`}>

```python
from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo

london = ZoneInfo("Europe/London")
before = datetime(2026, 3, 28, 12, 0, tzinfo=london)
after = before + timedelta(days=1)

print(after)                       # снова полдень, но уже +01:00
print(after - before)              # разница по настенным часам
utc = timezone.utc
print(after.astimezone(utc) - before.astimezone(utc))  # реальное время
```

</CodeExample>

«Завтра в то же время» — именно то, что нужно для ежедневного будильника, но для вопроса «сколько часов работала эта задача?» нужно реальное время. Это ещё одна причина **вычислять в UTC**.

## Передавайте «сейчас» снаружи, чтобы код можно было тестировать

Код, который внутри вызывает `datetime.now()`, при каждом запуске даёт разный ответ, и протестировать его невозможно. Ответ на вопрос «просрочено ли?» зависит от того, *когда* вы спрашиваете! Решение простое: пусть вызывающий код **передаёт** `now`, а реальные часы используются, только если он этого не сделал:

<CodeExample output={`False
True
осталось дней: 2`}>

```python
from datetime import datetime, timedelta, timezone

def is_overdue(due, now=None):
    if now is None:
        now = datetime.now(timezone.utc)
    return now > due

def describe(due, now):
    days = (due - now).days
    if days < 0:
        return f"просрочено на {-days} дн."
    return f"осталось дней: {days}"

due = datetime(2026, 10, 10, 17, 0, tzinfo=timezone.utc)
monday = datetime(2026, 10, 5, 9, 0, tzinfo=timezone.utc)

print(is_overdue(due, now=monday))
print(is_overdue(due, now=monday + timedelta(weeks=1)))
print(describe(due, monday + timedelta(days=3)))
```

</CodeExample>

Настоящая программа вызывает `is_overdue(due)`, а тесты передают фиксированное `now` и каждый раз получают один и тот же результат. Вы будете часто пользоваться этим приёмом, начиная с сегодняшней даты в итоговом проекте Уровня 1 — [трекере расходов](/learn/python/the-command-line).

Ваша команда работает в разных часовых поясах. Каждая встреча записана текстом: дата, время и название пояса, например `"2026-10-04 14:30 Europe/London"`.

- `parse_meeting(text)` возвращает **осведомлённый** datetime на это местное время в этом поясе.
- `show_in(meeting, zone)` переводит встречу в другой пояс и форматирует её как `"Sun 04 Oct, 22:30"`.
- `minutes_until(meeting, now)` возвращает **целое число минут** от `now` до встречи — отрицательное, если встреча уже началась. Функция должна правильно работать и при переводе часов на летнее время.
- `sort_meetings(texts)` возвращает тексты, отсортированные по **реальному моменту** каждой встречи (а не по алфавиту).

<Hint>

Разбейте текст через `text.rsplit(" ", 1)`, чтобы получить часть с датой и временем и название пояса. Первую часть разберите через `datetime.strptime(..., "%Y-%m-%d %H:%M")`, а затем добавьте пояс через `.replace(tzinfo=ZoneInfo(zone))`. Для `show_in` используйте `.astimezone(ZoneInfo(zone))` и формат `"%a %d %b, %H:%M"`. Для `minutes_until` переведите **оба** datetime в `timezone.utc` перед вычитанием, а затем используйте `int(diff.total_seconds() // 60)`. `sort_meetings` — это `sorted(texts, key=parse_meeting)`.

</Hint>

<Solution>

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

def parse_meeting(text):
    when, zone = text.rsplit(" ", 1)
    local = datetime.strptime(when, "%Y-%m-%d %H:%M")
    return local.replace(tzinfo=ZoneInfo(zone))

def show_in(meeting, zone):
    local = meeting.astimezone(ZoneInfo(zone))
    return local.strftime("%a %d %b, %H:%M")

def minutes_until(meeting, now):
    utc = timezone.utc
    diff = meeting.astimezone(utc) - now.astimezone(utc)
    return int(diff.total_seconds() // 60)

def sort_meetings(texts):
    return sorted(texts, key=parse_meeting)

m = parse_meeting("2026-10-04 14:30 Europe/London")
print(m)
print(show_in(m, "Asia/Tokyo"))
now = datetime(2026, 10, 4, 12, 0, tzinfo=timezone.utc)
print(minutes_until(m, now))
print(sort_meetings([
    "2026-10-04 08:00 Europe/London",
    "2026-10-04 09:00 Asia/Tokyo",
]))
```

</Solution>

</Exercise>

## Итоги

- `date` — это день, `time` — время суток, `datetime` — и то и другое. `timedelta` — длительность, которую можно прибавлять, вычитать и сравнивать.
- `strftime` **форматирует** дату в текст; `strptime` **разбирает** текст по тем же кодам (`%Y`, `%m`, `%d`, `%H`, `%M`...).
- Для файлов и API используйте **ISO 8601** (`isoformat()` / `fromisoformat()`).
- Разбирайте текстовые даты, прежде чем сортировать или сравнивать их.
- У **наивных** datetime нет часового пояса, у **осведомлённых** — есть. Для перевода используйте `ZoneInfo("Europe/London")` и `.astimezone()`.
- **Храните и вычисляйте в UTC**, переводите в местное время только для показа.
- Помните о разной длине месяцев (`timedelta(months=...)` не бывает) и о переводе часов.
- Передавайте `now` в функции, зависящие от времени, — тогда их можно тестировать.
