## Paths with pathlib

A **`Path`** object represents a location in the file system. Instead of gluing strings together with `"/"`, you join paths with the **`/` operator**, and Python uses the right separator for your operating system (`\` on Windows, `/` elsewhere):

<CodeExample output={`reports/2026/october.csv
october.csv
october
.csv
reports/2026
reports/2026/october.json
reports/2026/november.csv`}>

```python
from pathlib import Path

report = Path("reports") / "2026" / "october.csv"

print(report)
print(report.name)     # the file name
print(report.stem)     # the name without the suffix
print(report.suffix)   # the extension, with the dot
print(report.parent)   # the folder it's in
print(report.with_suffix(".json"))
print(report.with_name("november.csv"))
```

</CodeExample>

None of this touches the disk: a `Path` is just a name until you read, write or check it. `Path.cwd()` is the folder your script runs in and `Path.home()` is your home folder.

## Creating folders and checking what exists

**`mkdir()`** creates a folder. Two arguments make it safe to use in scripts:

- **`parents=True`** also creates any missing folders above it.
- **`exist_ok=True`** doesn't complain if the folder is already there.

<CodeExample output={`True True
False
True False
Hello!`}>

```python
import shutil
from pathlib import Path

base = Path("demo-project")
shutil.rmtree(base, ignore_errors=True)

notes = base / "docs" / "notes"
notes.mkdir(parents=True, exist_ok=True)
print(base.exists(), notes.is_dir())

readme = base / "README.md"
print(readme.exists())
readme.write_text("Hello!\n")
print(readme.is_file(), readme.is_dir())
print(readme.read_text().strip())
```

</CodeExample>

## Looking inside folders: iterdir, glob and rglob

- **`folder.iterdir()`** gives every file and folder directly inside `folder`.
- **`folder.glob("*.txt")`** gives the paths matching a **wildcard** pattern: `*` means "anything", so `*.txt` is "every `.txt` file".
- **`folder.rglob("*.txt")`** does the same, but also searches **all subfolders** ("recursive glob").

<CodeExample output={`Inside demo-files: ['notes.txt', 'photos', 'todo.txt']
Text files: ['notes.txt', 'todo.txt']
All jpgs: ['photos/2025/snow.jpg', 'photos/beach.jpg']`}>

```python
import shutil
from pathlib import Path

base = Path("demo-files")
shutil.rmtree(base, ignore_errors=True)
(base / "photos" / "2025").mkdir(parents=True)
for name in ["notes.txt", "todo.txt", "photos/beach.jpg",
             "photos/2025/snow.jpg"]:
    (base / name).write_text("demo")

print("Inside demo-files:", sorted(p.name for p in base.iterdir()))
print("Text files:", sorted(p.name for p in base.glob("*.txt")))
jpgs = [p.relative_to(base).as_posix() for p in base.rglob("*.jpg")]
print("All jpgs:", sorted(jpgs))
```

</CodeExample>

- The order of `iterdir()` and `glob()` depends on the operating system, so wrap them in `sorted()` when order matters.
- `p.relative_to(base)` drops the start of the path, and `.as_posix()` gives the text with `/` on every system.
- Glob patterns are **not** regular expressions: `*` is "any text" and `?` is "any one character". On Linux they're case-sensitive, so `*.jpg` doesn't find `PHOTO.JPG`.

## Organising a Downloads folder

Time for something useful: sort a messy folder into subfolders by file type. **`path.rename(new_path)`** moves a file to a new name or folder:

<CodeExample output={`cat.jpg -> images/
notes.txt -> documents/
photo.PNG -> images/
report.pdf -> documents/
setup.exe -> other/
song.mp3 -> music/
documents ['notes.txt', 'report.pdf']
images ['cat.jpg', 'photo.PNG']
music ['song.mp3']
other ['setup.exe']`}>

```python
import shutil
from pathlib import Path

downloads = Path("demo-downloads")
shutil.rmtree(downloads, ignore_errors=True)
downloads.mkdir()
for name in ["cat.jpg", "notes.txt", "song.mp3", "photo.PNG",
             "report.pdf", "setup.exe"]:
    (downloads / name).write_text("demo")

KINDS = {
    ".jpg": "images", ".png": "images",
    ".txt": "documents", ".pdf": "documents",
    ".mp3": "music",
}

for path in sorted(downloads.iterdir()):
    if not path.is_file():
        continue
    folder = KINDS.get(path.suffix.lower(), "other")
    target = downloads / folder
    target.mkdir(exist_ok=True)
    path.rename(target / path.name)
    print(f"{path.name} -> {folder}/")

for folder in sorted(downloads.iterdir()):
    print(folder.name, sorted(p.name for p in folder.iterdir()))
```

</CodeExample>

- `path.suffix.lower()` makes `.PNG` and `.png` the same.
- We loop over a **sorted list** of the folder's contents, made **before** we start moving things, so the new subfolders don't get processed too.

## Batch renaming safely: dry run first

Renaming many files at once is risky: a bug could give two files the same name and **overwrite** one of them. Professionals use a **dry run**: first **plan** the changes and print them, check the plan, and only then do it for real:

<CodeExample output={`would rename IMG_2041.jpg -> holiday-001.jpg
would rename IMG_2042.jpg -> holiday-002.jpg
would rename IMG_2050.jpg -> holiday-003.jpg
Renamed 3 files
['holiday-001.jpg', 'holiday-002.jpg', 'holiday-003.jpg', 'notes.txt']`}>

```python
import shutil
from pathlib import Path

photos = Path("demo-photos")
shutil.rmtree(photos, ignore_errors=True)
photos.mkdir()
for name in ["IMG_2042.jpg", "IMG_2041.jpg", "IMG_2050.jpg",
             "notes.txt"]:
    (photos / name).write_text("demo")

def plan_renames(folder, prefix):
    plan = []
    for number, old in enumerate(sorted(folder.glob("*.jpg")), 1):
        plan.append((old, old.with_name(f"{prefix}-{number:03}.jpg")))
    return plan

def apply_renames(plan, dry_run=True):
    done = 0
    for old, new in plan:
        if new.exists():
            print(f"SKIP {new.name}: it already exists")
        elif dry_run:
            print(f"would rename {old.name} -> {new.name}")
        else:
            old.rename(new)
            done += 1
    return done

plan = plan_renames(photos, "holiday")
apply_renames(plan)                       # look first...
count = apply_renames(plan, dry_run=False)  # ...then do it
print(f"Renamed {count} files")
print(sorted(p.name for p in photos.iterdir()))
```

</CodeExample>

`{number:03}` pads the number with zeros to three digits, so `holiday-010.jpg` sorts after `holiday-009.jpg`. Making `dry_run=True` the **default** means forgetting the argument is safe instead of destructive.

<Callout type="warning" title="rename can overwrite">

On macOS and Linux, `old.rename(new)` silently **replaces** `new` if it already exists. Always check `new.exists()` first (like `apply_renames` does) when you can't be sure the name is free.

</Callout>

## Copying and moving with shutil

`pathlib` handles single files and folders. For copying, and for moving between drives, use the **`shutil`** ("shell utilities") module:

| Function | Does |
| --- | --- |
| `shutil.copy(src, dst)` | Copies a file (to a file name or into a folder) |
| `shutil.copytree(src, dst)` | Copies a whole folder with everything inside |
| `shutil.move(src, dst)` | Moves a file or folder, even to another drive |
| `shutil.rmtree(folder)` | Deletes a folder and everything inside, permanently |

<CodeExample output={`['draft.txt', 'v1.txt']
['report.txt', 'v1.txt']
['report.txt']`}>

```python
import shutil
from pathlib import Path

base = Path("demo-shutil")
shutil.rmtree(base, ignore_errors=True)
(base / "backup").mkdir(parents=True)
(base / "draft.txt").write_text("My report")

shutil.copy(base / "draft.txt", base / "v1.txt")
print(sorted(p.name for p in base.glob("*.txt")))

shutil.move(base / "draft.txt", base / "report.txt")
print(sorted(p.name for p in base.glob("*.txt")))

shutil.copytree(base, Path("demo-shutil-copy"), dirs_exist_ok=True)
shutil.move(base / "v1.txt", base / "backup")
print(sorted(p.name for p in base.glob("*.txt")))
```

</CodeExample>

## Writing reports

Automation scripts often end by writing a **report**: a CSV for a spreadsheet, or JSON for another program. Here's a folder summary, counting files and bytes per type. `path.stat().st_size` is a file's size in bytes:

<CodeExample output={`{
  ".txt": {
    "files": 1,
    "bytes": 5
  },
  ".jpg": {
    "files": 2,
    "bytes": 3000
  }
}
type,files,bytes
.jpg,2,3000
.txt,1,5`}>

```python
import csv
import json
import shutil
from pathlib import Path

base = Path("demo-report")
shutil.rmtree(base, ignore_errors=True)
(base / "pics").mkdir(parents=True)
(base / "notes.txt").write_text("hello")
(base / "pics" / "a.jpg").write_text("x" * 1000)
(base / "pics" / "b.jpg").write_text("x" * 2000)

summary = {}
for path in sorted(base.rglob("*")):
    if path.is_file():
        stats = summary.setdefault(path.suffix, {"files": 0, "bytes": 0})
        stats["files"] += 1
        stats["bytes"] += path.stat().st_size

out = base / "reports"
out.mkdir(exist_ok=True)
(out / "summary.json").write_text(json.dumps(summary, indent=2))

with open(out / "summary.csv", "w", newline="") as file:
    writer = csv.writer(file)
    writer.writerow(["type", "files", "bytes"])
    for kind, stats in sorted(summary.items()):
        writer.writerow([kind, stats["files"], stats["bytes"]])

print((out / "summary.json").read_text())
print((out / "summary.csv").read_text().strip())
```

</CodeExample>

The CSV and JSON parts are exactly what you learned in [CSV and JSON](/learn/python/csv-and-json). Notice we wrote the reports into a subfolder **after** scanning, so the report files don't count themselves.

## Real scripts on your computer

On PandaDev your code runs in the browser. On your own computer, automation scripts usually run from the **terminal**, and often on a **schedule**.

### Command-line arguments with argparse

Hard-coding `Path("demo-downloads")` is fine for a demo, but a real tool should let you choose the folder when you run it. The built-in **`argparse`** module reads command-line arguments and even writes a `--help` page for you:

```python title="organise.py"
import argparse
from pathlib import Path

parser = argparse.ArgumentParser(description="Sort files by type.")
parser.add_argument("folder", type=Path, help="the folder to sort")
parser.add_argument("--dry-run", action="store_true",
                    help="only show what would happen")
args = parser.parse_args()

print(f"Sorting {args.folder} (dry run: {args.dry_run})")
# ... the organising code from above, using args.folder ...
```

```bash
python organise.py ~/Downloads --dry-run
python organise.py ~/Downloads
python organise.py --help
```

### Running scripts on a schedule

To run a script automatically, ask the operating system to do it:

- **macOS and Linux: cron.** Run `crontab -e` and add a line. The five fields are minute, hour, day of month, month and weekday:

```bash
# every Monday at 08:00, tidy the Downloads folder
0 8 * * 1 /usr/bin/python3 /home/mei/scripts/organise.py /home/mei/Downloads
```

- **Windows: Task Scheduler.** Open *Task Scheduler*, choose *Create Basic Task*, pick a trigger (for example "Weekly, Monday 08:00"), then *Start a program* with `python` as the program and the script's full path (and folder) as the arguments.

Scheduled scripts run without you watching, so use **full paths**, write what happened to a log file, and test with a dry run first.

## Mini-project: Log file analyser

Web servers write a line to an **access log** for every request. It's the first place developers look when a site is slow or broken. Each line looks like this:

```text
203.0.113.5 - - [04/Oct/2026:14:05:01 +0000] "GET /api/orders HTTP/1.1" 500 87
```

From left to right: the visitor's **IP address**, two fields we'll ignore (often `-`), the **time** in square brackets with its UTC offset, the **request** in quotes (method, path, protocol), the **status code** (`200` OK, `404` not found, `5xx` server errors) and the response **size** in bytes (`-` when there's no body).

Your analyser will use everything from this module: a **regex** with named groups to read each line, **datetime** to understand the times, and **pathlib** to read the log and save a report.

The starter creates `server-logs/access.log`. Build the analyser one function at a time, running your code after each one:

1. **`parse_line(line)`** uses a regex with **named groups** to return a dict with `"ip"`, `"time"`, `"method"`, `"path"`, `"status"` and `"size"`. The time must be an **aware** datetime converted to **UTC**; status and size are ints, and a size of `-` becomes `0`. Return `None` for any line that doesn't fit the format.
2. **`load_log(path)`** reads the file with `pathlib` and returns the parsed entries, skipping lines that don't fit.
3. **`status_counts(entries)`** returns a dict like `{200: 5, 404: 1}`.
4. **`top_paths(entries, n=3)`** returns the `n` most requested paths as `(path, count)` tuples, highest count first, with ties in alphabetical order.
5. **`busiest_hour(entries)`** returns the **start of the hour** (minutes and seconds set to zero) with the most requests. On a tie, the earliest hour wins.
6. **`error_bursts(entries, threshold=3)`** finds the minutes with at least `threshold` server errors (status **500 or above**). Return the start of each such minute, sorted.
7. **`write_report(entries, path)`** builds this text, writes it to `path` (creating any missing folders) and returns it:

```text
Requests: 11
Errors (5xx): 4
Busiest hour: 2026-10-04 14:00 UTC
Top paths:
  /api/orders 4
  /products 3
  / 2
Error bursts:
  2026-10-04 14:05 UTC
```

Each path and burst line starts with **two spaces**, the text ends with a newline, and when there are no bursts the last line is `  none`.

<Hint>

**The regex**: build it from left to right, one field at a time. `(?P<ip>\S+) \S+ \S+ ` covers the IP and the two ignored fields; `\[(?P<time>[^\]]+)\] ` is the time; `"(?P<method>[A-Z]+) (?P<path>\S+) [^"]*" ` is the request; then `(?P<status>\d{3}) (?P<size>\d+|-)`. Use `fullmatch(line.strip())` so broken lines give `None`.

**The time**: `datetime.strptime(m["time"], "%d/%b/%Y:%H:%M:%S %z")` reads it, `%z` included, then `.astimezone(timezone.utc)`.

**Counting**: `Counter(e["status"] for e in entries)` counts; wrap it in `dict()`. For `top_paths`, sort the counter's items with `key=lambda item: (-item[1], item[0])`. To group by hour or minute, count `e["time"].replace(minute=0, second=0)` or `.replace(second=0)`; the busiest hour is the smallest hour whose count equals the biggest count.

**The report**: build a list of lines, `"\n".join(lines) + "\n"`, then `path.parent.mkdir(parents=True, exist_ok=True)` before `write_text`. Format times with `f"{hour:%Y-%m-%d %H:%M} UTC"`.

</Hint>

LOG_LINE = re.compile(
    r'(?P<ip>\S+) \S+ \S+ \[(?P<time>[^\]]+)\] '
    r'"(?P<method>[A-Z]+) (?P<path>\S+) [^"]*" '
    r'(?P<status>\d{3}) (?P<size>\d+|-)'
)


def parse_line(line):
    m = LOG_LINE.fullmatch(line.strip())
    if not m:
        return None
    time = datetime.strptime(m["time"], "%d/%b/%Y:%H:%M:%S %z")
    size = m["size"]
    return {
        "ip": m["ip"],
        "time": time.astimezone(timezone.utc),
        "method": m["method"],
        "path": m["path"],
        "status": int(m["status"]),
        "size": 0 if size == "-" else int(size),
    }


def load_log(path):
    entries = []
    for line in Path(path).read_text().splitlines():
        entry = parse_line(line)
        if entry is not None:
            entries.append(entry)
    return entries


def status_counts(entries):
    return dict(Counter(e["status"] for e in entries))


def top_paths(entries, n=3):
    counts = Counter(e["path"] for e in entries)
    ranked = sorted(counts.items(), key=lambda item: (-item[1], item[0]))
    return ranked[:n]


def busiest_hour(entries):
    hours = Counter(
        e["time"].replace(minute=0, second=0, microsecond=0)
        for e in entries
    )
    most = max(hours.values())
    return min(hour for hour, count in hours.items() if count == most)


def error_bursts(entries, threshold=3):
    minutes = Counter(
        e["time"].replace(second=0, microsecond=0)
        for e in entries
        if e["status"] >= 500
    )
    return sorted(m for m, count in minutes.items() if count >= threshold)


def write_report(entries, path):
    errors = sum(1 for e in entries if e["status"] >= 500)
    lines = [
        f"Requests: {len(entries)}",
        f"Errors (5xx): {errors}",
        f"Busiest hour: {busiest_hour(entries):%Y-%m-%d %H:%M} UTC",
        "Top paths:",
    ]
    for page, count in top_paths(entries):
        lines.append(f"  {page} {count}")
    lines.append("Error bursts:")
    bursts = error_bursts(entries)
    for minute in bursts:
        lines.append(f"  {minute:%Y-%m-%d %H:%M} UTC")
    if not bursts:
        lines.append("  none")
    text = "\n".join(lines) + "\n"

    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(text)
    return text


entries = load_log("server-logs/access.log")
print(status_counts(entries))
print(write_report(entries, "server-logs/reports/summary.txt"))

## Recap

- `Path` objects join with `/` and have `.name`, `.stem`, `.suffix`, `.parent`, `.with_suffix()` and `.with_name()`.
- `mkdir(parents=True, exist_ok=True)` creates folders safely; `exists()`, `is_file()` and `is_dir()` check what's there.
- `iterdir()` lists a folder, `glob("*.txt")` filters it, and `rglob()` searches subfolders too. Sort the results.
- `rename()` moves or renames; plan batch changes with a **dry run** first and never overwrite by accident.
- `shutil` copies (`copy`, `copytree`), moves (`move`) and deletes (`rmtree`, permanently!).
- Finish automation with a CSV or JSON **report**.
- Real scripts take arguments with `argparse` and run on a schedule with **cron** or **Task Scheduler**.
- Regex + datetime + pathlib together turn a raw log file into useful answers.
