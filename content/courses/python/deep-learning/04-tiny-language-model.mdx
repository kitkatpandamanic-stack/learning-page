Time to put the whole module together. You'll build a **language model** that writes text, character by character: the same recipe as an LLM, just with the smallest model that works. It will learn which character tends to follow which, train with gradient descent and cross-entropy, and then generate new text with a seeded random generator and a temperature knob. 🐼✍️

It won't write poetry. But every piece of it, the vocabulary, the encoding, the softmax over the vocabulary, the training loop and the sampling, has an exact counterpart in a real LLM, and at the end you'll see what you'd change to climb from here towards GPT.

## The plan

1. **Vocabulary**: the set of characters in the text, each with an id. **Encode** text to ids and **decode** back.
2. **Training pairs**: for every position, the current character is the input and the next one is the target.
3. **Baseline**: a **counting** model, like the bigram word model in [How LLMs Work](/learn/python/how-llms-work), but for characters.
4. **Neural model**: a weight matrix, softmax and cross-entropy, trained with gradient descent.
5. **Generation**: sample one character at a time, with **temperature**.

## Vocabulary, encoding and decoding

## Training pairs

A bigram model predicts the next character from the current one. So the inputs are all characters except the last, and the targets are the same text shifted by one:

## The baseline: counting

The simplest model counts how often each character follows each other character, in a 26 × 26 table. **`np.add.at`** adds 1 at every `(x, y)` position, including repeated ones. Dividing each row by its total gives the probabilities of the next character:

<CodeExample output={`after 't': [('h', 0.42), (' ', 0.29), ('r', 0.08)]
counting model loss: 1.6476
guessing uniformly:  3.2581`}>

```python
import numpy as np

text = """the panda sat in the bamboo and ate the bamboo all day.
the little panda climbed a tall tree and fell asleep.
when the rain came, the pandas hid under the old tree.
a red panda is not a bear, but it likes bamboo too.
the panda keeper brings fresh bamboo every morning.
pandas sleep, eat and play, then they eat a bit more.
"""
vocab = sorted(set(text))
stoi = {ch: i for i, ch in enumerate(vocab)}
ids = np.array([stoi[ch] for ch in text])
x, y = ids[:-1], ids[1:]
V = len(vocab)

counts = np.zeros((V, V))
np.add.at(counts, (x, y), 1)          # counts[x, y] += 1
P = counts / counts.sum(axis=1, keepdims=True)

row = P[stoi["t"]]
top = np.argsort(row)[::-1][:3]
print("after 't':", [(vocab[i], float(row[i].round(2))) for i in top])

loss = -np.mean(np.log(P[x, y]))
print("counting model loss:", round(loss, 4))
print("guessing uniformly: ", round(np.log(V), 4))
```

</CodeExample>

After `t`, the model expects `h` most of the time, thanks to all those "the"s. To measure the whole model with one number, we use the **average negative log-likelihood** of the true next characters, which is the cross-entropy loss from [Neurons and Gradient Descent](/learn/python/neurons-and-gradient-descent). A model that knows nothing (every character equally likely) scores `log(26) = 3.258`; the counting model scores **1.65**.

For a bigram model, counting is the best possible fit to the training text: no bigram model can score lower on it. That makes it the perfect baseline for the neural version.

<Callout type="warning" title="Zero counts mean infinite loss">

Counting has a catch. Any pair that never appeared, say `"q"` after `"z"`, gets probability 0, and `-log(0)` is infinity: one unseen pair in new text and the loss is `inf`. The classic fix is **smoothing**: add 1 to every count before dividing (`counts + 1`), so nothing is impossible. A neural model has the same issue in a softer form, and **regularisation** plays the role of smoothing.

</Callout>

## A neural bigram model

Now the neural version. The model is a single weight matrix `W` of shape `(26, 26)`. To predict the character after character `i`:

1. Turn `i` into a **one-hot** vector: 26 zeros with a 1 at position `i`.
2. Multiply it by `W`. That gives 26 scores, the **logits**.
3. **Softmax** turns the logits into probabilities for the next character.

Multiplying a one-hot vector by a matrix just picks one row of the matrix, so step 1 and 2 are really "look up row `i`":

<CodeExample output={`[0. 0. 1. 0. 0.]
[-0.6  0.  -2.3 -0.2 -1.2]
[-0.6  0.  -2.3 -0.2 -1.2]`}>

```python
import numpy as np

rng = np.random.default_rng(0)
W = rng.normal(size=(5, 5)).round(1)
one_hot = np.eye(5)[2]          # token 2 as a one-hot vector
print(one_hot)
print(one_hot @ W)
print(W[2])                     # the same row, without the maths
```

</CodeExample>

That's exactly what an **embedding table** is: a matrix whose rows you look up by token id. Real frameworks do the lookup and skip the multiplication; we'll keep the one-hot version because it makes the gradient easy to read.

The training loop is the one from the first two lessons. With `X` the one-hot inputs (one row per training pair) and `Y` the one-hot targets, the softmax + cross-entropy gradient is `(P - Y) / n` for the logits, and the gradient for `W` is `X.T @ (P - Y) / n`:

<CodeExample output={`step   loss
   0  3.2581
  50  1.6897
 100  1.6668
 150  1.6600
 200  1.6567
 250  1.6548
 300  1.6536
P('h' after 't'): 0.416`}>

```python
import numpy as np

text = """the panda sat in the bamboo and ate the bamboo all day.
the little panda climbed a tall tree and fell asleep.
when the rain came, the pandas hid under the old tree.
a red panda is not a bear, but it likes bamboo too.
the panda keeper brings fresh bamboo every morning.
pandas sleep, eat and play, then they eat a bit more.
"""
vocab = sorted(set(text))
stoi = {ch: i for i, ch in enumerate(vocab)}
ids = np.array([stoi[ch] for ch in text])
x, y = ids[:-1], ids[1:]
V, n = len(vocab), len(x)

X = np.eye(V)[x]                 # (322, 26) one-hot inputs
Y = np.eye(V)[y]                 # (322, 26) one-hot targets
W = np.zeros((V, V))             # start knowing nothing

def softmax(z):
    e = np.exp(z - z.max(axis=1, keepdims=True))
    return e / e.sum(axis=1, keepdims=True)

print("step   loss")
for step in range(301):
    P = softmax(X @ W)                           # forward
    if step % 50 == 0:
        loss = -np.mean(np.log(P[np.arange(n), y]))
        print(f"{step:>4}  {loss:.4f}")
    W -= 50 * X.T @ (P - Y) / n                  # backward + step

after_t = softmax(W[stoi["t"]][None, :])[0]
print("P('h' after 't'):", round(after_t[stoi["h"]], 3))
```

</CodeExample>

The loss starts at 3.2581, which is `log(26)`: with `W` all zeros, every character gets the same probability. It drops quickly towards **1.65**, the counting model's score, and it can never go below it. The neural network has rediscovered the counts: after training, the softmax of each row of `W` approaches the rows of the counting table (and `W` itself approaches the **logarithm** of the counts, up to a constant per row).

The learning rate of 50 looks huge next to the 0.01 of the first lesson, but the gradient here is tiny: each row of `W` only gets the share of the gradient from the pairs that start with its character, divided by all 322 pairs. Much smaller and training crawls; much larger and the steps overshoot, as in the first lesson.

So why bother with a network, if counting gives the same answer? Because counting **only** works for this tiny model. Count tables for longer contexts explode: with 3 previous characters there are 26³ = 17 576 contexts, most of them never seen. A neural network can take a long context as input, share what it learns between similar contexts, and keep growing. Gradient descent is what scales; counting isn't.

## Generating text

To generate, start with a character, compute the probabilities for the next one, **sample** from them, append, and repeat. The **temperature** divides the logits before the softmax, as in the last lesson:

<CodeExample output={`T=0.3: the andandan t t the a the the the the. / the banda the a and a
T=1.0: the aslithit t r, ld a pandfrelin palery mbo. / whe ther d it a
T=1.5: the atrepay. / was thed areldwveng. / theesldalimbs n slat e it a`}>

```python
import numpy as np

text = """the panda sat in the bamboo and ate the bamboo all day.
the little panda climbed a tall tree and fell asleep.
when the rain came, the pandas hid under the old tree.
a red panda is not a bear, but it likes bamboo too.
the panda keeper brings fresh bamboo every morning.
pandas sleep, eat and play, then they eat a bit more.
"""
vocab = sorted(set(text))
stoi = {ch: i for i, ch in enumerate(vocab)}
ids = np.array([stoi[ch] for ch in text])
x, y = ids[:-1], ids[1:]
V, n = len(vocab), len(x)
X, Y = np.eye(V)[x], np.eye(V)[y]

def softmax(z):
    e = np.exp(z - z.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

W = np.zeros((V, V))
for step in range(300):
    W -= 50 * X.T @ (softmax(X @ W) - Y) / n

def generate(start, length, rng, temperature=1.0):
    i, out = stoi[start], start
    for _ in range(length):
        p = softmax(W[i] / temperature)
        i = rng.choice(V, p=p)
        out += vocab[i]
    return out.replace("\n", " / ")

for t in [0.3, 1.0, 1.5]:
    rng = np.random.default_rng(0)
    print(f"T={t}: {generate('t', 60, rng, t)}")
```

</CodeExample>

- At **T = 0.3** the model nearly always takes the most likely next character, so it gets stuck repeating "the" and "and": greedy-ish text is boring.
- At **T = 1.0** it samples from what it learned. You get pseudo-words with the right "feel" (`pandfrelin`, `palery`, spaces and full stops in sensible places), but no meaning: the model only ever sees **one** character of context.
- At **T = 1.5** unlikely characters get more chances, and it falls apart into noise.

Because the generator is seeded, the same seed gives the same text every time, which is what makes generated output testable.

## From here to GPT

Your model and a real LLM differ in **scale** and in **how much context** the model sees, not in kind. Here's the path from one to the other, each step a known milestone:

1. **More context.** Feed the last few characters (or tokens) instead of one: look up an **embedding** for each, join them, and pass them through an MLP with a hidden layer, the network from [A Neural Network from Scratch](/learn/python/a-neural-network-from-scratch). This is the classic neural language model of Bengio and colleagues, from 2003.
2. **Attention.** Replace the fixed window with causal **self-attention** over the whole context, wrapped in **transformer blocks** (attention, MLP, residuals, layer norm), as in [How LLMs Work](/learn/python/how-llms-work).
3. **Subword tokens** with BPE, instead of characters.
4. **Scale**: billions of weights, trillions of training tokens, thousands of GPUs, then instruction tuning and preference training.

The training loop stays the same throughout: predict the next token, cross-entropy, backprop, step. If you want to take step 1 and 2 yourself, Andrej Karpathy's free "Neural Networks: Zero to Hero" video course and his small open-source projects **makemore** and **nanoGPT** walk exactly this path in PyTorch.

On your own computer, the neural bigram model in PyTorch is tiny. `nn.Embedding(V, V)` is your `W`, used as a lookup table:

```python
# On your own computer: PyTorch
import torch
from torch import nn

model = nn.Embedding(V, V)            # row i = logits after token i
optimizer = torch.optim.SGD(model.parameters(), lr=50)
x_t, y_t = torch.tensor(x), torch.tensor(y)

for step in range(300):
    logits = model(x_t)                          # (n, V)
    loss = nn.functional.cross_entropy(logits, y_t)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

probs = torch.softmax(model.weight[stoi["t"]] / 0.8, dim=0)
next_id = torch.multinomial(probs, 1)            # sample
```

Build the whole tiny language model as tested functions, trained on a different story. 🐼📖

1. `build_vocab(text)` returns the **sorted** list of distinct characters.
2. `encode(text, vocab)` returns the list of ids (each character's position in `vocab`), and `decode(ids, vocab)` turns ids back into a string.
3. `counting_loss(ids, vocab_size)` builds the counting bigram model (no smoothing) from `ids` and returns its average negative log-likelihood on those same ids.
4. `train_bigram(ids, vocab_size, steps, learning_rate)` trains the neural bigram model: `W` starts as zeros, and each step computes `softmax(one_hot(x) @ W)`, records the loss (**before** the update) and takes a gradient descent step. Return `(W, losses)`.
5. `next_char_probs(W, idx, temperature=1.0)` returns the probabilities of the next character after id `idx`: the softmax of row `idx` of `W`, divided by the temperature.
6. `generate(W, vocab, start, length, seed, temperature=1.0)` starts from the character `start` and appends `length` characters, each sampled from `next_char_probs` with `np.random.default_rng(seed)`. Return the whole string (`length + 1` characters).

The checks call your functions on other text, compare the trained loss with your counting model, and make sure generation is repeatable with a seed.

```python
import numpy as np

STORY = """once upon a time a small panda lived by the river.
every morning she walked to the water to drink and look at the fish.
one day a fish said hello, and the panda said hello back.
they talked until the sun went down, then the panda went home to sleep.
"""

def build_vocab(text):
    return sorted(set(text))

def encode(text, vocab):
    stoi = {ch: i for i, ch in enumerate(vocab)}
    return [stoi[ch] for ch in text]

def decode(ids, vocab):
    return "".join(vocab[i] for i in ids)

def counting_loss(ids, vocab_size):
    ids = np.array(ids)
    x, y = ids[:-1], ids[1:]
    counts = np.zeros((vocab_size, vocab_size))
    np.add.at(counts, (x, y), 1)
    totals = counts.sum(axis=1, keepdims=True)
    P = counts / np.maximum(totals, 1)     # unused rows stay 0
    return -np.mean(np.log(P[x, y]))

def softmax(z):
    e = np.exp(z - z.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

def train_bigram(ids, vocab_size, steps, learning_rate):
    ids = np.array(ids)
    x, y = ids[:-1], ids[1:]
    X = np.eye(vocab_size)[x]
    Y = np.eye(vocab_size)[y]
    W = np.zeros((vocab_size, vocab_size))
    losses = []
    for _ in range(steps):
        P = softmax(X @ W)
        losses.append(-np.mean(np.log(P[np.arange(len(y)), y])))
        W -= learning_rate * X.T @ (P - Y) / len(y)
    return W, losses

def next_char_probs(W, idx, temperature=1.0):
    return softmax(W[idx] / temperature)

def generate(W, vocab, start, length, seed, temperature=1.0):
    rng = np.random.default_rng(seed)
    idx = vocab.index(start)
    out = start
    for _ in range(length):
        probs = next_char_probs(W, idx, temperature)
        idx = rng.choice(len(vocab), p=probs)
        out += vocab[idx]
    return out

vocab = build_vocab(STORY)
ids = encode(STORY, vocab)
W, losses = train_bigram(ids, len(vocab), 300, 50)
print("vocabulary:", len(vocab))
print("loss:", round(losses[0], 3), "->", round(losses[-1], 3))
print("counting:", round(counting_loss(ids, len(vocab)), 3))
print(generate(W, vocab, "t", 50, seed=1, temperature=0.8))
```

## Recap

- A character-level language model needs a **vocabulary** (sorted distinct characters), **encode** and **decode**, and training pairs made by shifting the text by one: the text labels itself.
- The **counting** bigram model (`np.add.at` into a table, rows divided by their totals) is the best bigram fit; its average negative log-likelihood is the baseline. Unseen pairs need **smoothing**.
- The **neural** bigram model is one matrix `W`: `one_hot(x) @ W` (a row lookup, like an **embedding**) gives logits, softmax gives probabilities, and gradient descent on the cross-entropy, with the gradient `X.T @ (P - Y) / n`, brings it to the counting model's loss.
- **Generation** samples one token at a time from the model's probabilities; a seeded generator makes it repeatable, and **temperature** trades boring for chaotic.
- A real LLM is the same loop with more context (embeddings, then attention in transformer blocks), subword tokens, and enormous scale.
