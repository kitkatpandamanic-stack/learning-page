Real data is messy. People leave fields empty, type `" london"` and `"LONDON"` for the same city, and write `"?"` where a price should be. Data scientists like to joke that 80% of the job is **cleaning** and 20% is complaining about cleaning. 🧹

In this lesson you'll clean a small, messy sales log from a panda-themed café chain, then answer real questions with **groupby**, and finally draw a chart.

The `dtypes` tell the story:

- **`qty` is `float64`**, not `int64`. One quantity is empty, and pandas marks missing numbers with **`NaN`** ("not a number"), which is a float. So the whole column became floats.
- **`price` is `str`**: because of the `"?"`, pandas couldn't read the column as numbers.
- **`city`** has extra spaces and three different spellings of Edinburgh. To a computer, `" edinburgh"`, `"EDINBURGH "` and `"Edinburgh"` are three different cities.
- **`date`** is just text, so you can't ask for "the month" yet.

Let's fix them one by one.

## Missing values: isna, dropna, fillna

**`isna()`** gives `True` for each missing value. Adding `.sum()` counts them per column (because `True` counts as 1), which is the quickest health check for any dataset:

<CodeExample output={`name    0
mood    1
naps    2
dtype: int64
  name   mood  naps
0  Mei  happy   3.0
   name   mood  naps
0   Mei  happy   3.0
2  Yuan    NaN   1.0
   name     mood  naps
0   Mei    happy   3.0
1   Bao   sleepy   0.0
2  Yuan  unknown   1.0
3   Lin   hungry   0.0`}>

```python
import pandas as pd

df = pd.DataFrame({
    "name": ["Mei", "Bao", "Yuan", "Lin"],
    "mood": ["happy", "sleepy", None, "hungry"],
    "naps": [3, None, 1, None],
})
print(df.isna().sum())

print(df.dropna())                  # drop rows with ANY gap
print(df.dropna(subset=["naps"]))   # only look at naps

filled = df.fillna({"mood": "unknown", "naps": 0})
print(filled)
```

</CodeExample>

- **`dropna()`** removes rows with a missing value. With `subset=[...]` it only looks at the columns you name.
- **`fillna(value)`** replaces gaps. Give it a dict to use a different value per column.

Both return a **new** DataFrame, so assign the result: `df = df.dropna(...)`.

<Callout type="tip" title="Dropping or filling is a decision">

There's no single right answer. A missing **quantity** in a sales log might really mean 0, so filling makes sense. A missing **price** can't be guessed, so dropping that row is safer. Filling with the column's average (`df["x"].fillna(df["x"].mean())`) is common, but it can hide problems. In real projects, write down what you did and why, and count how many rows each step removed.

</Callout>

## Fixing types: to_numeric, astype, to_datetime

Three tools cover most type problems:

- **`pd.to_numeric(column, errors="coerce")`** turns text into numbers, and turns anything that isn't a number (like `"?"`) into `NaN` instead of crashing.
- **`.astype(int)`** converts a column to another type. It only works if every value can be converted, so fill or drop gaps first.
- **`pd.to_datetime(column)`** turns date text into real dates. Then the **`.dt`** accessor gives you parts of each date.

<CodeExample output={`0    2.5
1    4.0
2    4.0
3    NaN
4    3.2
5    2.5
6    3.2
Name: price, dtype: float64
[3, 0, 2, 4, 5, 1, 2]
        date  month   day_name
0 2026-03-02      3     Monday
1 2026-03-02      3     Monday
2 2026-03-09      3     Monday
3 2026-03-15      3     Sunday
4 2026-04-01      4  Wednesday
5 2026-04-03      4     Friday
6 2026-04-12      4     Sunday
date     datetime64[us]
price           float64

```python
import io
import pandas as pd

csv_text = """date,city,item,price,qty
2026-03-02, edinburgh,Tea,2.50,3
2026-03-02,Vienna,Cake,4.00,
2026-03-09,EDINBURGH ,Cake,4.00,2
2026-03-15,vienna,Tea,?,4
2026-04-01,Vienna,Bun,3.20,5
2026-04-03,Edinburgh,Tea,2.50,1
2026-04-12,London,Bun,3.20,2

sales = pd.read_csv(io.StringIO(csv_text))

sales["price"] = pd.to_numeric(sales["price"], errors="coerce")
print(sales["price"])

print(sales["qty"].tolist())

print(sales[["date", "price"]].dtypes)
```

</CodeExample>

`.dt` also has `.year`, `.day`, `.month_name()` and more. In real projects you can often do this while loading: `pd.read_csv(file, parse_dates=["date"])`.

## Cleaning text with .str

Text columns have a **`.str`** accessor with the string methods you already know (`strip`, `lower`, `title`, `replace`, `startswith`...), applied to **every value at once**:

<CodeExample output={`[' edinburgh', 'Vienna', 'EDINBURGH ', 'vienna', 'Vienna', 'Edinburgh', 'London']

1     True
2     True
3     True
4    False

```python
import io
import pandas as pd

csv_text = """date,city,item,price,qty
2026-03-02, edinburgh,Tea,2.50,3
2026-03-02,Vienna,Cake,4.00,
2026-03-09,EDINBURGH ,Cake,4.00,2
2026-03-15,vienna,Tea,?,4
```

Methods can be **chained**: `.str.strip().str.title()` first removes the spaces, then fixes the capitals. Now all three Edinburghs are the same city.

## Grouping: split, apply, combine

Now the fun part. "What's the revenue **per city**?" is a **groupby** question. pandas:

1. **splits** the rows into groups (one per city),
2. **applies** a calculation to each group (like `sum`),
3. **combines** the results into a new Series or DataFrame.

Here's the whole cleaning pipeline followed by some grouping:

<CodeExample output={`city
Edinburgh    18.0
London        6.4
Vienna       16.0
Name: revenue, dtype: float64
      orders  revenue  avg_qty
item                          
Bun        2     22.4      3.5
Cake       2      8.0      1.0
Tea        2     10.0      2.0
        city  revenue
0  Edinburgh     18.0
1     Vienna     16.0
2     London      6.4`}>

```python
import io
import pandas as pd

csv_text = """date,city,item,price,qty
2026-03-02, edinburgh,Tea,2.50,3
2026-03-02,Vienna,Cake,4.00,
2026-03-09,EDINBURGH ,Cake,4.00,2
2026-03-15,vienna,Tea,?,4
2026-04-01,Vienna,Bun,3.20,5
2026-04-03,Edinburgh,Tea,2.50,1
2026-04-12,London,Bun,3.20,2
"""
sales = pd.read_csv(io.StringIO(csv_text))

# Clean
sales["city"] = sales["city"].str.strip().str.title()
sales["price"] = pd.to_numeric(sales["price"], errors="coerce")
sales = sales.dropna(subset=["price"])
sales["qty"] = sales["qty"].fillna(0).astype(int)
sales["revenue"] = sales["price"] * sales["qty"]

# Revenue per city
print(sales.groupby("city")["revenue"].sum())

# Several results per item with named aggregation
summary = sales.groupby("item").agg(
    orders=("revenue", "count"),
    revenue=("revenue", "sum"),
    avg_qty=("qty", "mean"),
)
print(summary)

# A tidy table, best city first
by_city = (sales.groupby("city", as_index=False)["revenue"]
           .sum()
           .sort_values("revenue", ascending=False)
           .reset_index(drop=True))
print(by_city)
```

</CodeExample>

- **`df.groupby("city")["revenue"].sum()`** reads like a sentence: *group by city, take revenue, add it up*. The group names become the index.
- **`.agg(new_name=("column", "function"))`** is called **named aggregation**. It builds several summary columns at once. Common functions: `"sum"`, `"mean"`, `"count"`, `"min"`, `"max"`, `"median"`.
- **`as_index=False`** keeps the groups as a normal column, which is handy for charts and for merging. `reset_index(drop=True)` renumbers the rows from 0.

You can also group by several columns: `sales.groupby(["city", "item"])["qty"].sum()`.

## Combining tables with merge

Data often lives in several tables. Say a second table holds the **manager** of each café. **`pd.merge()`** joins two DataFrames on a shared column, just like a SQL `JOIN`:

<CodeExample output={`        city  revenue manager
0  Edinburgh     17.5     Ana
1     London      6.4     NaN
2     Vienna     16.0   Felix
        city  revenue manager
0  Edinburgh     17.5     Ana
1     Vienna     16.0   Felix`}>

```python
import pandas as pd

revenue = pd.DataFrame({
    "city": ["Edinburgh", "London", "Vienna"],
    "revenue": [17.5, 6.4, 16.0],
})
managers = pd.DataFrame({
    "city": ["Vienna", "Edinburgh", "Paris"],
    "manager": ["Felix", "Ana", "Chloé"],
})

print(pd.merge(revenue, managers, on="city", how="left"))
print(pd.merge(revenue, managers, on="city"))   # how="inner"
```

</CodeExample>

The **`how`** argument decides which rows survive:

- **`"inner"`** (the default) keeps only cities found in **both** tables, so London and Paris disappear.
- **`"left"`** keeps **every** row of the left table and fills gaps with `NaN`. London has no manager yet.
- `"right"` and `"outer"` work the same way for the right table or both tables.

<Callout type="warning" title="Clean the key before merging">

`merge` matches values **exactly**. If one table says `"Edinburgh "` with a trailing space, the rows won't match and you'll silently lose data. Clean key columns with `.str.strip()` (and consistent capitals) first, and compare the row count before and after the merge.

</Callout>

```python
import io
import pandas as pd

csv_text = """date,stall,product,price,qty
2026-05-02,  fruit,apples,0.40,10
2026-05-02,Bakery,bread,2.10,
2026-05-03,FRUIT,pears,0.55,6

def clean(df):
    df = df.copy()
    df["stall"] = df["stall"].str.strip().str.title()
    df["price"] = pd.to_numeric(df["price"], errors="coerce")
```

## Recap

- Start every analysis with `df.dtypes` and `df.isna().sum()`: numbers stored as `str` and `NaN` gaps are the usual suspects.
- `dropna()` removes rows with gaps (`subset=` to choose columns), `fillna()` replaces them. Both return a new DataFrame.
- Fix types with `pd.to_numeric(..., errors="coerce")`, `.astype(int)` and `pd.to_datetime()` (then use `.dt.month`, `.dt.day_name()`...).
- The `.str` accessor runs string methods on a whole column: `.str.strip().str.title()`.
- `value_counts()` counts values; `groupby(...)[col].sum()` and `.agg(name=(col, func))` summarise each group.
- `pd.merge(left, right, on=..., how=...)` joins tables; clean the key column first.
- `series.plot(kind="bar")` plus `plt.show()` turns a result into a chart.
