До сих пор вы проверяли код так: запускали его и смотрели, что он печатает. Для десяти строк это работает. Но в настоящем проекте любое изменение может незаметно сломать то, что вы проверяли на прошлой неделе, а перепроверять всё вручную никто не станет. **Автоматические тесты (automated tests)** — это маленькие фрагменты кода, которые проверяют ваш код за вас: за секунду и каждый раз. В Python для этого почти все используют инструмент **pytest**. 🧪

## Зачем автоматизировать проверки?

Главную идею вы уже знаете. Инструкция `assert` проверяет, что условие истинно. Если это так, ничего не происходит. Если нет, Python выбрасывает `AssertionError`:

<CodeExample output={`Все проверки пройдены!
Проверка не пройдена: скидка 15% на 40`}>

```python
def apply_discount(price, percent):
    return price - price * percent / 100

assert apply_discount(200, 10) == 180
assert apply_discount(50, 0) == 50
print("Все проверки пройдены!")

try:
    assert apply_discount(40, 15) == 35, "скидка 15% на 40"
except AssertionError as error:
    print("Проверка не пройдена:", error)
```

</CodeExample>

Текст после запятой — необязательное сообщение. Эта проверка упала потому, что *мы* ожидали неправильное число: 15% скидки с 40 — это действительно 34. Проверки тоже бывают ошибочными, поэтому падение всегда означает «присмотритесь внимательнее», а не «код сломан».

Такие проверки быстро окупаются:

- **Регрессии ловятся.** **Регрессия (regression)** — это ошибка в том, что раньше работало. Тесты замечают её в момент появления.
- **Код можно менять без страха.** Переименовывайте, наводите порядок, ускоряйте: если тесты по-прежнему проходят, вы ничего не сломали.
- **Тесты документируют поведение.** Имя `test_free_shipping_over_50` сразу говорит следующему разработчику, что именно должен делать код.

## Ваши первые тесты на pytest

Набор разрозненных `assert` останавливается на первом же падении и не даёт никакой сводки. **pytest** это исправляет. Правила простые:

- **Тест (test)** — это функция, имя которой начинается с `test_`.
- Внутри неё используются обычные инструкции `assert`.
- pytest находит все тесты, запускает каждый отдельно и сообщает, что прошло, а что упало.

<CodeExample output={`...                                                  [100%]
3 passed in 0.01s`}>

```python
import pytest

def apply_discount(price, percent):
    return price - price * percent / 100

def test_ten_percent_off():
    assert apply_discount(200, 10) == 180

def test_zero_percent_changes_nothing():
    assert apply_discount(50, 0) == 50

def test_half_price():
    assert apply_discount(30, 50) == 15

pytest.main([__file__])
```

</CodeExample>

Каждая точка — один пройденный тест, а последняя строка подводит итог (`3 passed` — «3 прошли»). pytest ещё сообщает, сколько длился запуск: у вас время будет другим, и это нормально.

Последняя строка, `pytest.main([__file__])`, просит pytest запустить тесты из **этого** кода. Так мы запускаем тесты здесь, в браузере. В настоящем проекте тесты лежат в отдельных файлах, имена которых начинаются с `test_`, обычно в папке `tests`:

```text
shop/
├── pricing.py          # здесь живёт apply_discount
└── tests/
    └── test_pricing.py # from pricing import apply_discount
```

Тогда вы один раз устанавливаете pytest и запускаете его из папки проекта. Тесты он найдёт сам:

```bash
pip install pytest
pytest -q
```

Опция `-q` (quiet, «тихо») даёт ровно такой короткий отчёт, как на этой странице. Без неё pytest печатает ещё и заголовок, и имя каждого тестового файла.

## Читаем отчёт о падении

Пройденные тесты скучны (в хорошем смысле). Самое интересное — что pytest сообщает, когда тест **падает**. Вот счётчик слов с ошибкой:

<CodeExample output={`.F                                                   [100%]
========================= FAILURES =========================
____________________ test_double_space _____________________

    def test_double_space():
>       assert count_words("панды  едят") == 2
E       AssertionError: assert 3 == 2
E        +  where 3 = count_words('панды  едят')

lesson.py:10: AssertionError
================= short test summary info ==================
FAILED lesson.py::test_double_space - AssertionError: ass...
1 failed, 1 passed in 0.01s`}>

```python
import pytest

def count_words(text):
    return len(text.split(" "))

def test_simple_sentence():
    assert count_words("панды едят бамбук") == 3

def test_double_space():
    assert count_words("панды  едят") == 2

pytest.main([__file__])
```

</CodeExample>

Читайте сверху вниз:

1. `.F`: первый тест прошёл, второй упал (**F** — failed).
2. В разделе **FAILURES** («падения») у каждого упавшего теста есть свой блок с именем и кодом. Стрелка `>` указывает на строку, где произошло падение.
3. Строки с `E` — это ошибка (**E**rror). pytest показывает фактические значения: `count_words` вернула `3`, а тест ожидал `2`. Такие подробности вы получаете из обычного `assert`, потому что pytest переписывает проверки так, чтобы запомнить обе стороны.
4. `lesson.py:10` — файл и номер строки. (Код урока сохраняется как `lesson.py`.)
5. Сводка внизу перечисляет все падения, а затем итоги.

Теперь ошибка очевидна: `"панды  едят".split(" ")` даёт `['панды', '', 'едят']`, то есть три части. Исправление — `text.split()` без аргумента: так строка делится по любой последовательности пробельных символов.

<Callout type="tip" title="Убедитесь, что каждый тест хоть раз упал">

Тест, который никогда не может упасть, хуже, чем отсутствие теста: он создаёт ложное чувство безопасности. Написав тест, ненадолго сломайте код намеренно (или напишите тест до кода) и убедитесь, что тест покраснел. Потом исправьте и посмотрите, как он позеленеет.

</Callout>

## Подготовка, действие, проверка

Хорошие тесты короткие и состоят из одних и тех же трёх шагов. Их часто называют **arrange, act, assert** («подготовка, действие, проверка»):

1. **Подготовка (arrange)**: создайте нужные объекты и данные.
2. **Действие (act)**: сделайте то единственное, что вы тестируете.
3. **Проверка (assert)**: проверьте результат.

<CodeExample output={`..                                                   [100%]
2 passed in 0.01s`}>

```python
import pytest

class PiggyBank:
    def __init__(self):
        self.coins = []

    def add(self, amount):
        self.coins.append(amount)

    def total(self):
        return sum(self.coins)

def test_total_adds_up_all_coins():
    # Подготовка
    bank = PiggyBank()
    bank.add(2)
    bank.add(5)
    # Действие
    result = bank.total()
    # Проверка
    assert result == 7

def test_new_bank_is_empty():
    bank = PiggyBank()
    assert bank.total() == 0

pytest.main([__file__])
```

</CodeExample>

Обратите внимание на имена: `test_total_adds_up_all_coins` («итог складывает все монеты») описывает проверяемое **поведение**, а не то, какой метод вызывается. Если тест упадёт через полгода, одно только имя подскажет, что сломалось. Проверяйте одно поведение в одном тесте, чтобы падение указывало на одну конкретную вещь.

## Проверяем ошибки с pytest.raises

Иногда правильное поведение — это **и есть** ошибка. Если кто-то кладёт в копилку отрицательную монету, `add()` должен выбросить `ValueError`. Чтобы это проверить, оберните вызов в `with pytest.raises(...)`:

<CodeExample output={`...                                                  [100%]
3 passed in 0.01s`}>

```python
import pytest

class PiggyBank:
    def __init__(self):
        self.coins = []

    def add(self, amount):
        if amount <= 0:
            raise ValueError("сумма должна быть положительной")
        self.coins.append(amount)

def test_rejects_zero():
    bank = PiggyBank()
    with pytest.raises(ValueError):
        bank.add(0)

def test_explains_the_problem():
    with pytest.raises(ValueError, match="положительной"):
        PiggyBank().add(-5)

def test_nothing_is_saved_after_an_error():
    bank = PiggyBank()
    with pytest.raises(ValueError):
        bank.add(-1)
    assert bank.coins == []

pytest.main([__file__])
```

</CodeExample>

- Тест **проходит**, только если код внутри блока `with` выбрасывает это исключение (или его подкласс).
- Если ничего не выброшено, тест падает с сообщением `Failed: DID NOT RAISE <class 'ValueError'>`.
- `match="положительной"` дополнительно проверяет, что сообщение об ошибке содержит этот текст. (Это регулярное выражение, но обычные слова работают так, как вы ожидаете.)

## Сравниваем дробные числа с pytest.approx

Компьютер хранит дробные числа приблизительно, поэтому `0.1 + 0.2 == 0.3` — это `False`! Результаты типа float сравнивайте через **`pytest.approx`**: он допускает крошечную разницу:

<CodeExample output={`False
.                                                    [100%]
1 passed in 0.01s`}>

```python
import pytest

def test_split_the_bill():
    share = 1.0 / 3
    assert share * 3 == pytest.approx(1.0)
    assert 0.1 + 0.2 == pytest.approx(0.3)

if __name__ == "__main__":
    print(0.1 + 0.2 == 0.3)
    pytest.main([__file__])
```

</CodeExample>

В этом примере также используется идиома `if __name__ == "__main__":` из урока про модули. Когда pytest импортирует ваш код в поисках тестов, этот блок пропускается, и `print` выполняется только один раз. Код, который что-то делает (например, печатает), держите внутри этого блока, а на верхнем уровне оставляйте определения.

## Что тестировать?

Проверить все возможные входные данные невозможно, поэтому выбирайте с умом. Хороший набор тестов покрывает:

- **Обычный случай** («счастливый путь», happy path): типичный ввод, типичный результат.
- **Граничные случаи (edge cases)**: пустые строки и списки, ноль, один элемент, отрицательные числа, очень большие числа, странный текст вроде лишних пробелов или заглавных букв.
- **Границы (boundaries)**: если правила меняются на 18, проверьте 17 **и** 18. Ошибки на единицу (`>` вместо `>=`) прячутся именно там.
- **Ошибки**: неправильный ввод должен приводить к той ошибке, которую вы обещали.

В этом кинотеатре детский билет (от 5 до 17 лет) стоит £6, взрослый — £10, а пенсионный (65 лет и старше) — £7. Проверка границ находит ошибку, которую «счастливый путь» пропустил бы:

<CodeExample output={`....F                                                [100%]
========================= FAILURES =========================
____________ test_sixty_five_gets_senior_price _____________

    def test_sixty_five_gets_senior_price():
>       assert ticket_price(65) == 7
E       assert 10 == 7
E        +  where 10 = ticket_price(65)

lesson.py:25: AssertionError
================= short test summary info ==================
FAILED lesson.py::test_sixty_five_gets_senior_price - ass...
1 failed, 4 passed in 0.01s`}>

```python
import pytest

def ticket_price(age):
    if age < 5:
        return 0
    if age < 18:
        return 6
    if age > 65:
        return 7
    return 10

def test_toddlers_are_free():
    assert ticket_price(4) == 0

def test_five_year_olds_pay_child_price():
    assert ticket_price(5) == 6

def test_seventeen_is_still_a_child():
    assert ticket_price(17) == 6

def test_eighteen_pays_adult_price():
    assert ticket_price(18) == 10

def test_sixty_five_gets_senior_price():
    assert ticket_price(65) == 7

pytest.main([__file__])
```

</CodeExample>

В коде написано `age > 65`, поэтому 65-летний платит взрослую цену. Тест с возрастом `70` прошёл бы и скрыл ошибку. Если заменить условие на `age >= 65`, все пять тестов пройдут.

<Callout type="warning" title="Пишите тесты простыми">

Тесты должны быть настолько простыми, чтобы в них заведомо не было ошибок. Записывайте ожидаемое значение явно (`== 7`), а не вычисляйте его заново той же логикой, что и в коде. Иначе ошибка в этой логике скопируется в тест, и оба согласятся с неправильным ответом.

</Callout>

## Итоги

- **Автоматический тест** — это код, который проверяет ваш код; тесты ловят **регрессии** и позволяют уверенно менять код.
- pytest запускает каждую функцию с именем `test_...`; внутри используйте обычный `assert`. Запускайте его командой `pytest` в терминале (здесь — `pytest.main([__file__])`).
- В отчёте о падении `>` отмечает упавшую строку, а строки с `E` показывают фактические значения.
- Стройте тесты по схеме **подготовка, действие, проверка** (arrange, act, assert): одно поведение на тест и имя, которое это поведение описывает.
- `with pytest.raises(ValueError, match="..."):` проверяет, что код выбрасывает нужную ошибку.
- Числа с плавающей точкой сравнивайте через `pytest.approx`.
- Тестируйте обычный случай, **граничные случаи**, **границы** и ошибки — и убедитесь, что каждый тест хотя бы раз упал.
