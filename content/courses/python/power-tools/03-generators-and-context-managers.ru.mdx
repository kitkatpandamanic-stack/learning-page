Представьте файл логов на десять миллионов строк. Если сначала прочитать его целиком в список, программе понадобится память под десять миллионов строк ещё до того, как она что-то сделает. **Генератор (generator)** выдаёт строки **по одной** — только когда вы просите следующую, — поэтому он справится с файлом любого размера.

В этом уроке вы освоите два мощных инструмента, которыми профессионалы пользуются каждый день: **генераторы** (`yield`) для ленивых последовательностей и **менеджеры контекста (context managers)** (`with`), которые что-то подготавливают и всегда убирают за собой. 🎋

## yield: функция, которая встаёт на паузу

Обычная функция доходит до `return` и завершается. Функция, в которой есть **`yield`**, — это **генераторная функция (generator function)**: её вызов не выполняет тело, а возвращает объект-**генератор**. Каждый раз, когда вы просите значение, тело выполняется до следующего `yield`, отдаёт это значение и **встаёт на паузу** прямо там:

<CodeExample output={`generator
3
2
Пуск!
[3, 2, 1]`}>

```python
def countdown(start):
    n = start
    while n > 0:
        yield n        # отдаём n и встаём на паузу здесь
        n -= 1

gen = countdown(3)
print(type(gen).__name__)
print(next(gen))       # выполняется до первого yield
print(next(gen))       # продолжает с места паузы

print("Пуск!")
print(list(countdown(3)))
```

</CodeExample>

Сами вы редко будете вызывать `next()`. Цикл `for`, `list()`, `sum()` и им подобные запрашивают значения одно за другим, пока генератор не закончится (когда его тело завершается, Python незаметно выбрасывает `StopIteration`, и цикл останавливается).

## Лениво: значения только по требованию

Сравним функцию, которая строит целый список, с генератором. `print` внутри показывает, *когда* создаётся каждое значение:

<CodeExample output={`-- список --
создаём 1
создаём 2
создаём 3
используем 1
используем 2
используем 3
-- генератор --
создаём 1
используем 1
создаём 2
используем 2
создаём 3
используем 3`}>

```python
def squares_list(n):
    result = []
    for i in range(1, n + 1):
        print(f"создаём {i}")
        result.append(i * i)
    return result

def squares_gen(n):
    for i in range(1, n + 1):
        print(f"создаём {i}")
        yield i * i

print("-- список --")
for sq in squares_list(3):
    print(f"используем {int(sq ** 0.5)}")

print("-- генератор --")
for sq in squares_gen(3):
    print(f"используем {int(sq ** 0.5)}")
```

</CodeExample>

Версия со списком создаёт всё заранее, а генератор создаёт каждое значение **точно к моменту, когда оно нужно**. У этого два больших плюса:

- **Память**: в каждый момент существует только одно значение, поэтому генератор по огромному файлу или миллиону записей почти не расходует память.
- **Бесконечные последовательности**: генератор может продолжаться вечно, а вы просто перестаёте спрашивать, когда значений достаточно.

<CodeExample output={`[1, 1, 2, 3, 5, 8, 13, 21]
55`}>

```python
def fibonacci():
    a, b = 1, 1
    while True:          # никогда не заканчивается, и это нормально
        yield a
        a, b = b, a + b

numbers = []
for n in fibonacci():
    if n > 30:
        break
    numbers.append(n)
print(numbers)

for i, n in enumerate(fibonacci()):
    if i == 9:
        print(n)
        break
```

</CodeExample>

## Генераторные выражения

Как и у списковых включений (list comprehensions), у генераторов есть короткая форма — **генераторное выражение (generator expression)**. Поставьте **круглые скобки** вместо квадратных, и получится генератор:

<CodeExample output={`[1, 4, 9, 16]
<class 'generator'>
333333833333500000
True`}>

```python
nums = [1, 2, 3, 4]
print([n * n for n in nums])        # список: строится сразу
print(type(n * n for n in nums))    # генератор: ленивый

# Внутри вызова функции лишние скобки можно опустить
print(sum(n * n for n in range(1, 1_000_001)))
print(any(n > 3 for n in nums))
```

</CodeExample>

`sum(n * n for n in range(1, 1_000_001))` складывает миллион квадратов, ни разу не создавая список из миллиона чисел. А `any()` даже **останавливается досрочно**: он прекращает работу на первом же `True`.

<Callout type="warning" title="Генератор можно использовать только один раз">

Генератор помнит, где остановился, поэтому, закончившись, он остаётся пустым. Повторный проход по нему ничего не даёт — и никакой ошибки:

```python
squares = (n * n for n in [1, 2, 3])
print(sum(squares))   # 14
print(sum(squares))   # 0 — уже израсходован!
```

Если значения нужны больше одного раза, превратите их в список (`list(...)`) или вызовите генераторную функцию заново.

</Callout>

## Конвейеры из генераторов

Генераторы особенно хороши, когда их соединяют в цепочку: каждый шаг принимает итерируемый объект и выдаёт очищенные значения. Ничего не читается и не обрабатывается, пока конец цепочки этого не попросит, — совсем как конвейерная лента на фабрике. Вот конвейер, который читает числа из текста, похожего на файл, пропуская пустые строки и комментарии:

<CodeExample output={`[12, 7, 30]
49`}>

```python
import io

data = io.StringIO("12\n\n# поставка 2\n7\n30\n")

def clean(lines):
    for line in lines:
        line = line.strip()
        if line and not line.startswith("#"):
            yield line

def to_ints(lines):
    for line in lines:
        yield int(line)

print(list(to_ints(clean(data))))

data.seek(0)                         # перематываем «файл» в начало
print(sum(to_ints(clean(data))))
```

</CodeExample>

`io.StringIO` ведёт себя как открытый файл, и настоящий файл, открытый через `open()`, работает так же: цикл по нему читает **по одной строке за раз**. Значит, этот самый конвейер мог бы обработать файл, который намного больше памяти вашего компьютера.

## itertools: готовые инструменты для генераторов

В модуле **`itertools`** стандартной библиотеки есть быстрые строительные блоки для ленивых последовательностей. Вот несколько, которыми вы будете пользоваться часто:

<CodeExample output={`[10, 11, 12]
[0, 2, 4, 6, 8]
['a', 'b', 'c', 'd']
[(1, 2, 3), (4, 5, 6), (7,)]
[1, 3, 6, 10]`}>

```python
import itertools

counter = itertools.count(10)       # 10, 11, 12, ... бесконечно
print([next(counter) for _ in range(3)])

evens = (n for n in itertools.count() if n % 2 == 0)
print(list(itertools.islice(evens, 5)))     # первые 5

# chain: одно за другим, batched: группами по 3
print(list(itertools.chain(["a", "b"], ["c", "d"])))
print(list(itertools.batched(range(1, 8), 3)))
print(list(itertools.accumulate([1, 2, 3, 4])))   # нарастающие суммы
```

</CodeExample>

**`islice`** — ключ к бесконечным генераторам: он берёт только несколько первых значений (это как срез `[:5]`, но для всего ленивого). `batched` (Python 3.12+) отлично подходит, чтобы отправлять данные порциями — например, по 100 строк за раз в базу данных.

## with: всегда убираем за собой

Вы уже знаете `with open(...) as file:`. Смысл `with` — в гарантии: что бы ни случилось внутри блока, **даже ошибка**, уборка после него выполнится (здесь — файл закроется).

Объект, который работает с `with`, называется **менеджером контекста**. У него есть два специальных метода:

- **`__enter__`** выполняется в начале блока. То, что он возвращает, попадает в переменную после `as`.
- **`__exit__`** выполняется в конце, **всегда**, и получает сведения об ошибке, если она случилась.

<CodeExample output={`<pandas>
  Мэй
  Бао
</pandas>
<numbers>
  Ой, сейчас будет ошибка...
</numbers>
Поймали: что-то сломалось`}>

```python
class Tag:
    def __init__(self, name):
        self.name = name

    def __enter__(self):
        print(f"<{self.name}>")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print(f"</{self.name}>")
        return False   # не скрываем ошибки

with Tag("pandas"):
    print("  Мэй")
    print("  Бао")

try:
    with Tag("numbers"):
        print("  Ой, сейчас будет ошибка...")
        raise ValueError("что-то сломалось")
except ValueError as error:
    print(f"Поймали: {error}")
```

</CodeExample>

Посмотрите на второй блок: ошибка произошла, но `</numbers>` всё равно напечатался до того, как ошибка добралась до `except`. Это и есть гарантия. Если `__exit__` возвращает `True`, ошибка **проглатывается**; если `False` (или ничего), она летит дальше — и это почти всегда то, что вам нужно.

Менеджеры контекста в реальном мире работают ровно по этой схеме: открывают и закрывают файлы, подключаются к базам данных и отключаются от них, начинают транзакции (transactions) и **фиксируют или откатывают** их, захватывают и освобождают блокировки. В модуле про базы данных вы встретите `with Session(engine) as session:`.

## @contextlib.contextmanager: короткий путь

Писать класс довольно долго. Декоратор **`@contextlib.contextmanager`** превращает генераторную функцию в менеджер контекста: код **до** `yield` — это подготовка, выданное значение попадает в `as`, а код **после** `yield` — уборка. Поместите `yield` внутрь `try`/`finally`, чтобы уборка выполнялась даже после ошибки:

<CodeExample output={`внутри: {'theme': 'dark', 'debug': True}
после: {'theme': 'dark', 'debug': False}
после ошибки: {'theme': 'dark', 'debug': False}`}>

```python
from contextlib import contextmanager

settings = {"theme": "dark", "debug": False}

@contextmanager
def debug_mode(config):
    old = config["debug"]
    config["debug"] = True        # подготовка
    try:
        yield config              # здесь выполняется блок with
    finally:
        config["debug"] = old     # уборка, всегда

with debug_mode(settings) as config:
    print("внутри:", config)
print("после:", settings)

try:
    with debug_mode(settings):
        raise RuntimeError("тест упал")
except RuntimeError:
    print("после ошибки:", settings)
```

</CodeExample>

Шаблон «временно что-то поменять и обязательно вернуть как было» встречается очень часто, особенно в тестах. В `contextlib` есть и готовые помощники — например, `suppress`, который игнорирует один вид ошибок:

<CodeExample output={`удалён
готово`}>

```python
import os
from contextlib import suppress

with open("temp.txt", "w") as file:
    file.write("пока")

os.remove("temp.txt")
print("удалён")

with suppress(FileNotFoundError):
    os.remove("temp.txt")      # уже удалён: игнорируем
print("готово")
```

</CodeExample>

<Callout type="tip" title="Что выбрать?">

Используйте **генератор**, когда создаёте последовательность значений, которая может быть большой, медленной в создании или бесконечной; возвращайте **список**, когда он маленький и нужен несколько раз. Для большинства собственных менеджеров контекста используйте **`@contextmanager`**; класс с `__enter__`/`__exit__` пишите, когда у объекта есть и другие методы или состояние.

</Callout>

1. **`running_total(numbers)`**: генератор, который после каждого числа выдаёт сумму на текущий момент. `[1, 2, 3, 4]` даёт `1, 3, 6, 10`. Он должен быть ленивым, чтобы работать и с бесконечным итератором вроде `itertools.count()`.

Это должно происходить **даже если блок выбросит ошибку** (сама ошибка всё равно должна дойти до вызывающего кода).

```python
from contextlib import contextmanager

def running_total(numbers):
    total = 0
    for n in numbers:
        total += n
        yield total


def chunks(items, size):
    batch = []
    for item in items:
        batch.append(item)
        if len(batch) == size:
            yield batch
            batch = []
    if batch:
        yield batch


@contextmanager
def temp_value(data, key, value):
    missing = key not in data
    old = data.get(key)
    data[key] = value
    try:
        yield data
    finally:
        if missing:
            del data[key]
        else:
            data[key] = old


print(list(running_total([1, 2, 3, 4])))
print(list(chunks([1, 2, 3, 4, 5], 2)))
```

## Итоги

- Функция с **`yield`** — это генераторная функция: она возвращает генератор, который выдаёт значения **лениво**, вставая на паузу после каждого `yield`.
- Генераторы экономят память, могут быть **бесконечными** и удобно соединяются в **конвейеры**; генератор можно использовать только **один раз**.
- **Генераторные выражения** пишутся в круглых скобках: `sum(n * n for n in nums)`.
- В `itertools` есть ленивые помощники: `count`, `islice`, `chain`, `batched`, `accumulate`.
- `with` гарантирует уборку даже после ошибки. У **менеджера контекста** есть `__enter__` (подготовка, значение для `as`) и `__exit__` (уборка).
- `@contextlib.contextmanager` строит менеджер контекста из генератора: подготовка, затем `try: yield` / `finally:` с уборкой.
