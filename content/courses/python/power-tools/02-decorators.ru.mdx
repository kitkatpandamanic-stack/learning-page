Вы уже писали строки, которые начинаются с `@`: `@dataclass` над классом, `@property` над методом. Это **декораторы (decorators)**, и в профессиональном Python они повсюду. FastAPI с помощью `@app.get("/")` превращает функцию в веб-страницу, pytest использует `@pytest.fixture`, а свои декораторы вы можете написать сами, чтобы добавить к любой функции логирование, замер времени, кеширование или проверки — **не меняя её код**. 🎀

Чтобы понять, как они работают, сначала нужны две идеи: функции — это значения, и функции могут жить внутри других функций.

## Функции — это значения

В Python функция — это объект, как число или список. Её можно сохранить в переменной, положить в словарь или передать другой функции. Обратите внимание: здесь **нет скобок** — `shout` означает саму функцию, а `shout("привет")` её *вызывает*:

<CodeExample output={`ПРИВЕТ!
ПРИВЕТ!
привет...
['чай', 'панда', 'бамбук']`}>

```python
def shout(text):
    return text.upper() + "!"

def whisper(text):
    return text.lower() + "..."

say = shout              # без (): сохраняем саму функцию
print(say("привет"))

def speak(style, text):  # принимает функцию как аргумент
    return style(text)

print(speak(shout, "привет"))
print(speak(whisper, "ПРИВЕТ"))

words = ["бамбук", "чай", "панда"]
print(sorted(words, key=len))
```

</CodeExample>

Вы уже так делали: `key=len` передаёт функцию `len` в `sorted`, а та вызывает её для каждого элемента.

## Функции внутри функций

Функция может объявить другую функцию и **вернуть** её. Внутренняя функция запоминает переменные вокруг себя, даже когда внешняя функция уже завершилась. Это называется **замыканием (closure)**:

<CodeExample output={`10
15
6`}>

```python
def make_multiplier(factor):
    def multiply(number):
        return number * factor   # помнит factor
    return multiply

double = make_multiplier(2)
times_five = make_multiplier(5)

print(double(5))
print(times_five(3))
print(double(3))
```

</CodeExample>

И `double`, и `times_five` — это внутренняя функция `multiply`, но у каждой свой `factor`. Запомните эту идею: декоратор — это просто функция, которая вот так строит и возвращает новую функцию.

## Ваш первый декоратор

**Декоратор** — это функция, которая принимает функцию и возвращает новую, улучшенную. Обычно новая функция (её называют **обёрткой, wrapper**) делает что-то дополнительное, вызывает оригинал и возвращает его результат:

<CodeExample output={`Вызываем add
Готово: add
5`}>

```python
def announce(func):
    def wrapper(*args, **kwargs):
        print(f"Вызываем {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Готово: {func.__name__}")
        return result
    return wrapper

def add(a, b):
    return a + b

add = announce(add)   # заменяем add обёрнутой версией
print(add(2, 3))
```

</CodeExample>

Символ `@` — это сокращение ровно для строки `add = announce(add)`. Пишите его над `def`:

<CodeExample output={`Вызываем greet
Готово: greet
Привет, Мэй!`}>

```python
def announce(func):
    def wrapper(*args, **kwargs):
        print(f"Вызываем {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Готово: {func.__name__}")
        return result
    return wrapper

@announce
def greet(name, punctuation="!"):
    return f"Привет, {name}{punctuation}"

print(greet("Мэй"))
```

</CodeExample>

Зачем `*args, **kwargs`? Обёртка не знает, какие аргументы принимает декорируемая функция. `*args` собирает все позиционные аргументы в кортеж, а `**kwargs` — именованные аргументы в словарь; `func(*args, **kwargs)` передаёт их все дальше без изменений. Так один декоратор подходит для любой функции.

<Callout type="warning" title="Не забудьте return result">

Самый частый баг в декораторах: обёртка вызывает `func(...)`, но не **возвращает** её результат. Тогда каждая декорированная функция внезапно начинает возвращать `None`. Обёртка почти всегда должна заканчиваться на `return result` (или `return func(*args, **kwargs)`).

</Callout>

## Сохраняем имя с functools.wraps

Есть скрытая проблема. После декорирования имя и строка документации функции принадлежат `wrapper`, а это сбивает с толку сообщения об ошибках, отладчики и инструменты вроде pytest и FastAPI:

<CodeExample output={`wrapper
None
greet
Поздороваться с кем-нибудь.`}>

```python
import functools

def plain(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

def polite(func):
    @functools.wraps(func)   # копируем имя, строку документации...
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@plain
def hello(name):
    """Поздороваться с кем-нибудь."""
    return f"Привет, {name}"

@polite
def greet(name):
    """Поздороваться с кем-нибудь."""
    return f"Привет, {name}"

print(hello.__name__)
print(hello.__doc__)
print(greet.__name__)
print(greet.__doc__)
```

</CodeExample>

`@functools.wraps(func)` копирует в обёртку имя оригинала, его строку документации и аннотации типов. **Используйте его всегда**, когда пишете декоратор: это всего одна строка.

Вот стандартный шаблон, который вы будете писать снова и снова, — здесь он считает вызовы:

<CodeExample output={`Привет, Мэй
Привет, Сэм
say_hi вызвана 2 раза`}>

```python
import functools

def count_calls(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        wrapper.calls += 1
        return func(*args, **kwargs)
    wrapper.calls = 0   # у функций тоже бывают атрибуты
    return wrapper

@count_calls
def say_hi(name):
    print(f"Привет, {name}")

say_hi("Мэй")
say_hi("Сэм")
print(f"{say_hi.__name__} вызвана {say_hi.calls} раза")
```

</CodeExample>

## Декораторы с аргументами

А как же `@app.get("/items")` или `@repeat(3)` — декораторы, которые принимают собственные аргументы? Это **фабрики декораторов (decorator factories)**: функция принимает настройки и *возвращает декоратор*. Значит, нужен ещё один уровень вложенности:

<CodeExample output={`Бамбук!
Бамбук!
Бамбук!`}>

```python
import functools

def repeat(times):              # 1. принимает настройки
    def decorator(func):        # 2. принимает функцию
        @functools.wraps(func)
        def wrapper(*args, **kwargs):   # 3. выполняется при каждом вызове
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def cheer(food):
    print(f"{food}!")

cheer("Бамбук")
```

</CodeExample>

Читайте `@repeat(3)` в два шага: сначала выполняется `repeat(3)` и возвращает `decorator`, затем `decorator` применяется к `cheer`. Это то же самое, что `cheer = repeat(3)(cheer)`.

## Встроенные декораторы

В Python есть несколько декораторов, которыми вы будете пользоваться постоянно.

### @staticmethod и @classmethod

Вы уже знаете `@property` (метод, который читают как атрибут). Ещё два декоратора меняют то, что метод получает первым аргументом:

- **`@classmethod`** получает **класс** (`cls`) вместо объекта. Классический пример — альтернативный способ создавать объекты, например `from_string`.
- **`@staticmethod`** не получает ни `self`, ни `cls`. Это обычная функция, которая живёт в классе, потому что ей там самое место.

<CodeExample output={`Мэй, возраст 5
True
False
Бао, возраст 2`}>

```python
class Panda:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_string(cls, text):      # "Мэй,5" -> Panda
        name, age = text.split(",")
        return cls(name, int(age))

    @staticmethod
    def is_valid_name(name):
        return name.isalpha()

    @property
    def summary(self):
        return f"{self.name}, возраст {self.age}"

mei = Panda.from_string("Мэй,5")
print(mei.summary)
print(Panda.is_valid_name("Мэй"))
print(Panda.is_valid_name("М3й"))
print(Panda("Бао", 2).summary)
```

</CodeExample>

### @functools.cache

**`@functools.cache`** запоминает результат для каждого набора аргументов, который уже видел, поэтому повторные вызовы срабатывают мгновенно. Без него эта рекурсивная функция Фибоначчи сделала бы для `fib(60)` миллиарды вызовов, а с ним каждое значение вычисляется только один раз:

<CodeExample output={`1548008755920
CacheInfo(hits=58, misses=61, maxsize=None, currsize=61)`}>

```python
import functools

@functools.cache
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(60))
print(fib.cache_info())
```

</CodeExample>

Кешируйте только **чистые** функции — те, чей результат зависит только от аргументов (они не читают файлы, часы или случайные числа). Если хотите ограничить, сколько значений запоминается, используйте `@functools.lru_cache(maxsize=128)`.

## Почему фреймворки любят декораторы

Декоратору не обязательно что-то оборачивать. Многие просто **регистрируют** функцию где-нибудь и возвращают её без изменений. Вот крошечная версия того, что делает веб-фреймворк:

<CodeExample output={`['/', '/hello']
Добро пожаловать в PandaDev
Привет, панда!`}>

```python
routes = {}

def route(path):
    def decorator(func):
        routes[path] = func   # запоминаем, какая функция обрабатывает path
        return func           # возвращаем её без изменений
    return decorator

@route("/")
def home():
    return "Добро пожаловать в PandaDev"

@route("/hello")
def hello():
    return "Привет, панда!"

print(list(routes))
for path in routes:
    print(routes[path]())
```

</CodeExample>

Именно на этой идее построены настоящие фреймворки. Позже в курсе вы будете писать такой код:

```python
from fastapi import FastAPI
import pytest

app = FastAPI()

@app.get("/hello")          # регистрация: GET /hello запускает эту функцию
def hello() -> dict:
    return {"message": "Привет, панда!"}

@pytest.mark.parametrize("n", [1, 2, 3])   # запустить этот тест 3 раза
def test_positive(n):
    assert n > 0
```

<Callout type="tip" title="Когда писать свой декоратор">

Пишите декоратор, когда **одно и то же дополнительное поведение** нужно вокруг многих функций: логирование, замер времени, повторные попытки, проверка прав доступа, кеширование. Если оно нужно только одной функции, просто добавьте код в неё. И всегда сохраняйте результат и имя оригинала (`return result` и `@functools.wraps`).

</Callout>

Напишите два декоратора, которые можно использовать повторно:

1. **`count_calls(func)`** возвращает обёртку, которая считает свои вызовы в атрибуте `wrapper.calls` (начиная с `0`) и возвращает результат исходной функции. Используйте `@functools.wraps(func)`.
2. **`at_least(minimum)`** — это **фабрика** декораторов. Функция, которую она декорирует, должна выбрасывать `ValueError`, если её **первый** аргумент меньше `minimum`; в остальных случаях она работает как обычно и возвращает результат. Здесь тоже используйте `@functools.wraps`.

Когда обе функции готовы, `add(2, 3), add(10, 5), add.calls` выводит `5 15 2`, а `square_root(-4)` выбрасывает `ValueError`.

<Hint>

Для `at_least` обёртка находится **внутри** `decorator`: перед вызовом `func` проверьте `if args[0] < minimum: raise ValueError(...)` и верните `wrapper` из `decorator`.

</Hint>

```python
import functools

def count_calls(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        wrapper.calls += 1
        return func(*args, **kwargs)
    wrapper.calls = 0
    return wrapper


def at_least(minimum):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            if args[0] < minimum:
                raise ValueError(
                    f"{func.__name__}: нужно значение >= {minimum}"
                )
            return func(*args, **kwargs)
        return wrapper
    return decorator


@count_calls
def add(a, b):
    return a + b

@at_least(0)
def square_root(x):
    return x ** 0.5

print(add(2, 3), add(10, 5), add.calls)
print(square_root(16))
```

## Итоги

- Функции — это **значения**: их можно сохранять, передавать (`key=len`) и возвращать из других функций.
- Внутренняя функция, которая помнит переменные внешней, — это **замыкание**.
- **Декоратор** принимает функцию и возвращает новую; `@deco` над `def f` означает `f = deco(f)`.
- Пишите `wrapper(*args, **kwargs)`, вызывайте `func(*args, **kwargs)` и **возвращайте результат**.
- Всегда добавляйте `@functools.wraps(func)`, чтобы обёртка сохранила имя и строку документации оригинала.
- Декораторы с аргументами (`@repeat(3)`) — это **фабрики**: ещё один уровень вложенности.
- Встроенные декораторы: `@property`, `@classmethod` (получает `cls`, отлично подходит для альтернативных конструкторов), `@staticmethod`, `@functools.cache`.
- Фреймворки используют декораторы, чтобы **регистрировать** функции: `@app.get` в FastAPI, `@pytest.fixture` и `@pytest.mark.parametrize` в pytest.
