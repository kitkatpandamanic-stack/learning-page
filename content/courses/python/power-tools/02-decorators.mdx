You've already used a few lines that start with `@`: `@dataclass` above a class, `@property` above a method. Those are **decorators**, and they're everywhere in professional Python. FastAPI uses `@app.get("/")` to turn a function into a web page, pytest uses `@pytest.fixture`, and you can write your own to add logging, timing, caching or checks to any function **without changing its code**. 🎀

To understand how they work, we need two ideas first: functions are values, and functions can live inside other functions.

## Functions are values

In Python a function is an object, just like a number or a list. You can store it in a variable, put it in a dict, or pass it to another function. Notice there are **no brackets**: `shout` is the function itself, `shout("hi")` *calls* it:

<CodeExample output={`HI!
HI!
hi...
['tea', 'panda', 'bamboo']`}>

```python
def shout(text):
    return text.upper() + "!"

def whisper(text):
    return text.lower() + "..."

say = shout              # no () : we store the function
print(say("hi"))

def speak(style, text):  # takes a function as an argument
    return style(text)

print(speak(shout, "hi"))
print(speak(whisper, "HI"))

words = ["bamboo", "tea", "panda"]
print(sorted(words, key=len))
```

</CodeExample>

You've done this before: `key=len` passes the `len` function to `sorted`, which calls it on every item.

## Functions inside functions

A function can define another function and **return** it. The inner function remembers the variables around it, even after the outer function has finished. That's called a **closure**:

<CodeExample output={`10
15
6`}>

```python
def make_multiplier(factor):
    def multiply(number):
        return number * factor   # remembers factor
    return multiply

double = make_multiplier(2)
times_five = make_multiplier(5)

print(double(5))
print(times_five(3))
print(double(3))
```

</CodeExample>

`double` and `times_five` are both the inner `multiply` function, but each one carries its own `factor`. Hold on to this idea: a decorator is just a function that builds and returns a new function like this.

## Your first decorator

A **decorator** is a function that takes a function and returns a new, improved one. Usually the new function (called the **wrapper**) does something extra, calls the original, and returns its result:

<CodeExample output={`Calling add
Finished add
5`}>

```python
def announce(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Finished {func.__name__}")
        return result
    return wrapper

def add(a, b):
    return a + b

add = announce(add)   # replace add with the wrapped version
print(add(2, 3))
```

</CodeExample>

The `@` symbol is a shortcut for exactly that `add = announce(add)` line. Write it above the `def`:

<CodeExample output={`Calling greet
Finished greet
Hello, Mei!`}>

```python
def announce(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Finished {func.__name__}")
        return result
    return wrapper

@announce
def greet(name, punctuation="!"):
    return f"Hello, {name}{punctuation}"

print(greet("Mei"))
```

</CodeExample>

Why `*args, **kwargs`? The wrapper doesn't know what arguments the decorated function takes. `*args` collects any positional arguments into a tuple and `**kwargs` collects keyword arguments into a dict; `func(*args, **kwargs)` passes them all on unchanged. That way one decorator works for every function.

<Callout type="warning" title="Don't forget return result">

The most common decorator bug: the wrapper calls `func(...)` but doesn't **return** its result. Then every decorated function suddenly returns `None`. A wrapper should almost always end with `return result` (or `return func(*args, **kwargs)`).

</Callout>

## Keep the name with functools.wraps

There's a hidden problem. After decorating, the function's name and docstring belong to `wrapper`, which confuses error messages, debuggers and tools like pytest and FastAPI:

<CodeExample output={`wrapper
None
greet
Say hello to someone.`}>

```python
import functools

def plain(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

def polite(func):
    @functools.wraps(func)   # copy name, docstring...
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@plain
def hello(name):
    """Say hello to someone."""
    return f"Hello, {name}"

@polite
def greet(name):
    """Say hello to someone."""
    return f"Hello, {name}"

print(hello.__name__)
print(hello.__doc__)
print(greet.__name__)
print(greet.__doc__)
```

</CodeExample>

`@functools.wraps(func)` copies the original's name, docstring and type hints onto the wrapper. **Always use it** when you write a decorator; it costs one line.

Here's the standard template you'll write again and again, used here to count calls:

<CodeExample output={`Hi Mei
Hi Sam
say_hi was called 2 times`}>

```python
import functools

def count_calls(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        wrapper.calls += 1
        return func(*args, **kwargs)
    wrapper.calls = 0   # functions can have attributes too
    return wrapper

@count_calls
def say_hi(name):
    print(f"Hi {name}")

say_hi("Mei")
say_hi("Sam")
print(f"{say_hi.__name__} was called {say_hi.calls} times")
```

</CodeExample>

## Decorators with arguments

What about `@app.get("/items")` or `@repeat(3)`, decorators that take their own arguments? Those are **decorator factories**: a function that takes the settings and *returns a decorator*. That means one more level of nesting:

<CodeExample output={`Bamboo!
Bamboo!
Bamboo!`}>

```python
import functools

def repeat(times):              # 1. takes the settings
    def decorator(func):        # 2. takes the function
        @functools.wraps(func)
        def wrapper(*args, **kwargs):   # 3. runs on each call
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def cheer(food):
    print(f"{food}!")

cheer("Bamboo")
```

</CodeExample>

Read `@repeat(3)` in two steps: first `repeat(3)` runs and returns `decorator`, then `decorator` is applied to `cheer`. It's the same as `cheer = repeat(3)(cheer)`.

## Built-in decorators

Python ships with several decorators you'll use all the time.

### @staticmethod and @classmethod

You know `@property` (a method you read like an attribute). Two more change how methods receive their first argument:

- **`@classmethod`** gets the **class** (`cls`) instead of an object. Its classic use is an alternative way to create objects, like `from_string`.
- **`@staticmethod`** gets neither `self` nor `cls`. It's a plain function that lives in the class because it belongs there.

<CodeExample output={`Mei is 5
True
False
Bao is 2`}>

```python
class Panda:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_string(cls, text):      # "Mei,5" -> Panda
        name, age = text.split(",")
        return cls(name, int(age))

    @staticmethod
    def is_valid_name(name):
        return name.isalpha()

    @property
    def summary(self):
        return f"{self.name} is {self.age}"

mei = Panda.from_string("Mei,5")
print(mei.summary)
print(Panda.is_valid_name("Mei"))
print(Panda.is_valid_name("M3i"))
print(Panda("Bao", 2).summary)
```

</CodeExample>

### @functools.cache

**`@functools.cache`** remembers the result for every set of arguments it has seen, so repeated calls are instant. Without it, this recursive Fibonacci would make billions of calls for `fib(60)`; with it, each value is worked out only once:

<CodeExample output={`1548008755920
CacheInfo(hits=58, misses=61, maxsize=None, currsize=61)`}>

```python
import functools

@functools.cache
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(60))
print(fib.cache_info())
```

</CodeExample>

Only cache **pure** functions: ones whose result depends only on their arguments (no reading files, the clock or random numbers). Use `@functools.lru_cache(maxsize=128)` if you want to limit how much it remembers.

## Why frameworks love decorators

Decorators don't have to wrap anything. Many simply **register** a function somewhere and return it unchanged. Here's a tiny version of what a web framework does:

<CodeExample output={`['/', '/hello']
Welcome to PandaDev
Hello, panda!`}>

```python
routes = {}

def route(path):
    def decorator(func):
        routes[path] = func   # remember which function handles path
        return func           # return it unchanged
    return decorator

@route("/")
def home():
    return "Welcome to PandaDev"

@route("/hello")
def hello():
    return "Hello, panda!"

print(list(routes))
for path in routes:
    print(routes[path]())
```

</CodeExample>

That's the idea behind real frameworks. You'll write code like this later in the course:

```python
from fastapi import FastAPI
import pytest

app = FastAPI()

@app.get("/hello")          # register: GET /hello runs this function
def hello() -> dict:
    return {"message": "Hello, panda!"}

@pytest.mark.parametrize("n", [1, 2, 3])   # run this test 3 times
def test_positive(n):
    assert n > 0
```

<Callout type="tip" title="When to write your own">

Write a decorator when the **same extra behaviour** is needed around many functions: logging, timing, retrying, checking permissions, caching. If only one function needs it, just put the code in that function. And always keep the original's result and name (`return result` and `@functools.wraps`).

</Callout>

    def wrapper(*args, **kwargs):

    wrapper.calls = 0
    return wrapper

## Recap

- Functions are **values**: store them, pass them (`key=len`) and return them from other functions.
- An inner function that remembers variables from the outer one is a **closure**.
- A **decorator** takes a function and returns a new one; `@deco` above `def f` means `f = deco(f)`.
- Use `wrapper(*args, **kwargs)`, call `func(*args, **kwargs)`, and **return the result**.
- Always add `@functools.wraps(func)` so the wrapper keeps the original's name and docstring.
- Decorators with arguments (`@repeat(3)`) are **factories**: one more level of nesting.
- Built-ins: `@property`, `@classmethod` (gets `cls`, great for alternative constructors), `@staticmethod`, `@functools.cache`.
- Frameworks use decorators to **register** functions: FastAPI's `@app.get`, pytest's `@pytest.fixture` and `@pytest.mark.parametrize`.
