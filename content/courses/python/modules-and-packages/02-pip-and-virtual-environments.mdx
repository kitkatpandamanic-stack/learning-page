The standard library is big, but the Python community has written far more. Want to make web requests, build a website, draw charts or analyse spreadsheets? There's a **package** for that. In this lesson you'll learn to install packages with **pip** and keep every project tidy with a **virtual environment**. 📦

<Callout type="note" title="Do this on your own computer">

PandaDev's Python runs inside your browser, so it **can't install packages** with pip, and there's no terminal here. The commands in this lesson are for the terminal on your own computer (Terminal on macOS, PowerShell on Windows). Read along now and try them when you set up your first local project.

</Callout>

## Packages and PyPI

- A **package** is a collection of modules bundled together, ready to share. For example, `requests` (web requests), `rich` (colourful terminal output) or `pandas` (data analysis).
- **PyPI**, the Python Package Index at pypi.org, is the huge online library where people publish packages. It has hundreds of thousands of them.
- **pip** is the tool that downloads packages from PyPI and installs them. It comes with Python.

Once a package is installed, you import it just like a standard library module:

```python
import requests

response = requests.get("https://api.github.com")
print(response.status_code)   # 200
```

## Why virtual environments?

Imagine two projects on your computer. An old one needs version 1 of a package, a new one needs version 2. If you install everything into one shared Python, they fight, and one project breaks.

A **virtual environment** (often called a **venv**) is a private folder of packages for **one project**. Each project gets its own, so:

- projects can use different versions of the same package,
- you can see exactly what each project needs,
- deleting a project's packages is as easy as deleting the folder,
- you never mess up the Python your operating system relies on.

## Creating a virtual environment

Open a terminal **in your project folder** and run:

```bash
python -m venv .venv
```

This creates a folder called `.venv` holding a copy of Python and its own empty set of packages. (`-m venv` means "run the `venv` module". On some macOS and Linux machines the command is `python3` instead of `python`.)

## Activating it

Creating the venv isn't enough: you have to **activate** it, so that `python` and `pip` use it. The command depends on your system:

```bash
# macOS and Linux
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Windows (Command Prompt)
.venv\Scripts\activate.bat
```

Your prompt now starts with `(.venv)`, so you know it's active:

```bash
(.venv) mei@laptop my-project %
```

When you're done, type `deactivate` to switch back. Activate it again every time you open a new terminal to work on the project.

<Callout type="tip" title="Editors can do it for you">

VS Code and PyCharm notice a `.venv` folder in your project and offer to use it automatically. Pick it as the project's interpreter and new terminals will activate it for you.

</Callout>

## Installing packages with pip

With the venv active, install a package by name:

```bash
pip install requests
```

A few more commands you'll use:

```bash
pip install requests==2.32.3   # a specific version
pip install --upgrade requests # update to the newest version
pip uninstall requests         # remove it
pip list                       # show what's installed
```

<Callout type="warning" title="Check that the venv is active">

If you forget to activate the venv, `pip install` puts the package into your **global** Python instead. Look for `(.venv)` at the start of your prompt before installing. Running `python -m pip install requests` is also a safe habit: it always uses the pip that belongs to the `python` you're running.

</Callout>

## requirements.txt and pip freeze

How does a teammate (or you, on a new laptop) install the same packages? You keep a list in a file called **`requirements.txt`**. `pip freeze` prints every installed package with its exact version, and `>` saves that output to a file:

```bash
pip freeze > requirements.txt
```

The file looks like this:

```text title="requirements.txt"
certifi==2025.8.3
charset-normalizer==3.4.3
idna==3.10
requests==2.32.5
urllib3==2.5.0
```

`requests` needs a few helper packages of its own, so they're listed too. To install everything on another machine, create and activate a fresh venv, then run:

```bash
pip install -r requirements.txt
```

`-r` means "read the package names from this file". Pinning exact versions with `==` makes sure everyone runs the same code.

## Keep .venv out of Git

The `.venv` folder can hold thousands of files, and it only works on the computer that made it. **Never commit it.** Commit `requirements.txt` instead, and tell Git to ignore the venv by adding it to a `.gitignore` file in your project folder:

```text title=".gitignore"
.venv/
__pycache__/
```

(`__pycache__` holds compiled files Python makes automatically when you import your own modules. You don't need to share those either.)

## The whole workflow

Starting a new project from scratch looks like this:

```bash
mkdir weather-app
cd weather-app
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pip install requests
pip freeze > requirements.txt
```

And joining an existing project someone else made:

```bash
git clone https://github.com/someone/weather-app.git
cd weather-app
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

<Callout type="note" title="Other tools you'll hear about">

Many teams use newer tools such as **uv** or **Poetry**, which create the venv and track packages for you in one step. They're built on the same ideas you just learned: a venv per project and a file listing the exact packages.

</Callout>

## Recap

- A **package** is shareable code; **PyPI** is where packages live; **pip** installs them.
- `python -m venv .venv` creates a virtual environment: private packages for one project.
- Activate it with `source .venv/bin/activate` (macOS/Linux) or `.venv\Scripts\Activate.ps1` (Windows), and `deactivate` to leave.
- `pip install name`, `pip list`, `pip uninstall name`.
- `pip freeze > requirements.txt` saves exact versions; `pip install -r requirements.txt` restores them.
- Put `.venv/` in `.gitignore`; commit `requirements.txt`.
- PandaDev's browser Python can't pip install, so practise this on your own computer.
