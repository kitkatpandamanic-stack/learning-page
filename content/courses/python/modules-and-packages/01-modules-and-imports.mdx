A **module** is simply a Python file full of code you can reuse. Python ships with hundreds of them, called the **standard library** ("batteries included"). Need maths, dates, random numbers or counting? Someone has already written it. You just have to **import** it. 🔋

## import

`import math` loads the `math` module. You then use its contents with a dot: `math.something`.

<CodeExample output={`9.0
5 4
3.1416
5.0`}>

```python
import math

print(math.sqrt(81))
print(math.ceil(4.2), math.floor(4.8))
print(round(math.pi, 4))
print(math.dist((0, 0), (3, 4)))
```

</CodeExample>

`ceil` rounds **up**, `floor` rounds **down**, and `dist` measures the distance between two points.

## from … import and as

There are three common ways to import:

```python
import math                       # use math.sqrt(...)
from math import sqrt, pi         # use sqrt(...) and pi directly
import statistics as stats        # a shorter nickname: stats.mean(...)
```

- **`from module import name`** brings specific names in, so you don't need the prefix.
- **`as`** gives a module (or name) a nickname.

<CodeExample output={`80.8
88
88
12.0`}>

```python
import statistics as stats
from math import sqrt

scores = [72, 95, 88, 61, 88]
print(stats.mean(scores))
print(stats.median(scores))
print(stats.mode(scores))
print(sqrt(144))
```

</CodeExample>

<Callout type="tip" title="Which style should I use?">

`import math` is the clearest: anyone reading `math.sqrt` knows where it came from. Use `from … import` for a few names you use a lot. Avoid `from math import *`: it dumps everything into your file and makes it hard to tell where names come from. Put all imports at the **top** of your file.

</Callout>

## A tour of the standard library

### random

The `random` module picks things by chance. The output changes every time you run it, so here it is as a plain example:

```python
import random

print(random.randint(1, 6))            # a dice roll, e.g. 4
print(random.choice(["rock", "paper", "scissors"]))
print(random.random())                 # a float from 0 to 1

cards = ["A", "K", "Q", "J"]
random.shuffle(cards)                  # shuffles the list in place
print(cards)                           # e.g. ['Q', 'A', 'J', 'K']
```

Calling `random.seed(42)` first makes the "random" results the same every run, which is handy for testing.

### datetime

`datetime` works with dates and times. `date.today()` gives today's date; here we use fixed dates so the output never changes:

<CodeExample output={`2026-10-01
01 October 2026
Thursday
30`}>

```python
from datetime import date, timedelta

start = date(2026, 9, 1)
deadline = start + timedelta(days=30)

print(deadline)
print(deadline.strftime("%d %B %Y"))
print(deadline.strftime("%A"))
print((deadline - start).days)
```

</CodeExample>

- `timedelta(days=30)` is a length of time you can add to or subtract from a date.
- Subtracting two dates gives a `timedelta`; `.days` is the number of days.
- `strftime` formats a date: `%d` day, `%B` month name, `%Y` year, `%A` weekday.
- `date.fromisoformat("2026-09-01")` turns text into a date.

### collections: Counter and defaultdict

**`Counter`** counts things for you. **`defaultdict`** is a dict that creates a starting value (like an empty list) the first time you use a new key:

<CodeExample output={`3 0
[('the', 3), ('panda', 1)]
{'t': ['the', 'the', 'the'], 'p': ['panda'], 'a': ['ate', 'and', 'apple'], 'b': ['bamboo']}`}>

```python
from collections import Counter, defaultdict

words = "the panda ate the bamboo and the apple".split()

counts = Counter(words)
print(counts["the"], counts["kiwi"])
print(counts.most_common(2))

by_letter = defaultdict(list)
for word in words:
    by_letter[word[0]].append(word)
print(dict(by_letter))
```

</CodeExample>

A missing key in a `Counter` is `0` instead of a `KeyError`, and `defaultdict(list)` saves you from writing `if key not in d: d[key] = []` every time.

## Writing your own module

Any `.py` file is a module. Put some functions in `helpers.py`:

```python title="helpers.py"
def shout(text):
    return text.upper() + "!"

def average(numbers):
    return sum(numbers) / len(numbers)
```

Then, in another file **in the same folder**, import it by its file name without `.py`:

```python title="main.py"
import helpers
from helpers import average

print(helpers.shout("hello"))     # HELLO!
print(average([2, 4, 6]))         # 4.0
```

Run `python main.py` and Python finds `helpers.py` next to it. Splitting a big program into modules keeps each file short and focused.

<Callout type="note" title="Single files on PandaDev">

The editor here runs **one file** at a time, so you can't import your own `helpers.py` in the browser. Standard library modules like `math` and `json` work fine. Try the two-file version on your own computer.

</Callout>

## Running vs importing: `if __name__ == "__main__":`

When Python imports a module, it **runs the whole file**. If `helpers.py` had a `print("testing...")` at the bottom, it would print every time someone imported it! The fix is a special check.

Every module has a variable called `__name__`. When you **run** a file directly, it's `"__main__"`. When the file is **imported**, it's the module's name, like `"helpers"`.

<CodeExample output={`__main__
Running as a program: HELLO!`}>

```python
def shout(text):
    return text.upper() + "!"

def main():
    print(f"Running as a program: {shout('hello')}")

print(__name__)

if __name__ == "__main__":
    main()
```

</CodeExample>

Code inside `if __name__ == "__main__":` only runs when you start **this** file. When another file imports it, you get `shout` and `main` without anything running by itself. You'll see this pattern in almost every Python script.

## Exploring with dir() and help()

**`dir(module)`** lists every name inside a module. It's a quick way to explore:

<CodeExample output="['fabs', 'factorial', 'floor', 'fma', 'fmod', 'frexp', 'fsum']">

```python
import math

print([name for name in dir(math) if name.startswith("f")])
```

</CodeExample>

**`help()`** prints the documentation for a module or function. It's most useful in the interactive Python shell on your computer:

```python
import math
help(math.floor)
# floor(x, /)
#     Return the floor of x as an Integral.
```

The official Python docs at docs.python.org cover every standard library module with examples.

You've logged your study sessions as `(date, topic, minutes)` tuples. Use the standard library to write:

- `minutes_by_topic(log)`: a dict of each topic's **total** minutes, e.g. `{'python': 95, 'maths': 45, 'art': 20}`.
- `top_topic(log)`: the topic with the most total minutes.
- `days_spanned(log)`: how many days lie between the **earliest** and **latest** date (`7` for the log above). The log might not be in order!

<Hint>

A `Counter` can add up numbers: `totals[topic] += minutes`. Then `totals.most_common(1)[0][0]` is the top topic. For dates, turn every text date into a `date` with `date.fromisoformat(text)`, then subtract `min(...)` from `max(...)` and use `.days`.

</Hint>

<Solution>

```python
from collections import Counter
from datetime import date

log = [
    ("2026-09-01", "python", 30),
    ("2026-09-02", "maths", 45),
    ("2026-09-04", "python", 25),
    ("2026-09-07", "art", 20),
    ("2026-09-08", "python", 40),
]

def minutes_by_topic(log):
    totals = Counter()
    for day, topic, minutes in log:
        totals[topic] += minutes
    return dict(totals)

def top_topic(log):
    totals = Counter(minutes_by_topic(log))
    return totals.most_common(1)[0][0]

def days_spanned(log):
    dates = [date.fromisoformat(day) for day, _, _ in log]
    return (max(dates) - min(dates)).days

print(minutes_by_topic(log))
print(top_topic(log))
print(days_spanned(log))
```

</Solution>

## Recap

- A **module** is a `.py` file; the **standard library** has hundreds ready to use.
- `import math`, `from math import sqrt`, `import statistics as stats`.
- Handy modules: `math`, `random`, `datetime`, `collections` (`Counter`, `defaultdict`), `statistics`.
- Your own file `helpers.py` is imported with `import helpers`.
- Code under `if __name__ == "__main__":` runs only when the file is run directly.
- `dir()` lists what's inside a module; `help()` shows its documentation.
