Стандартная библиотека большая, но сообщество Python написало гораздо больше. Хотите отправлять веб-запросы, сделать сайт, рисовать графики или анализировать таблицы? Для этого есть **пакет (package)**. В этом уроке вы научитесь устанавливать пакеты через **pip** и держать каждый проект в порядке с помощью **виртуального окружения (virtual environment)**. 📦

<Callout type="note" title="Делайте это на своём компьютере">

Python на PandaDev работает прямо в браузере, поэтому он **не может устанавливать пакеты** через pip, и терминала здесь нет. Команды из этого урока предназначены для терминала (terminal) на вашем компьютере (Терминал в macOS, PowerShell в Windows). Сейчас просто читайте, а попробуете, когда заведёте свой первый локальный проект.

</Callout>

## Пакеты и PyPI

- **Пакет** — это набор модулей, собранных вместе и готовых к распространению. Например, `requests` (веб-запросы), `rich` (цветной вывод в терминале) или `pandas` (анализ данных).
- **PyPI** (Python Package Index, pypi.org) — огромная онлайн-библиотека, где люди публикуют пакеты. Их там сотни тысяч.
- **pip** — инструмент, который скачивает пакеты из PyPI и устанавливает их. Он поставляется вместе с Python.

Установленный пакет импортируют так же, как модуль стандартной библиотеки:

```python
import requests

response = requests.get("https://api.github.com")
print(response.status_code)   # 200
```

## Зачем нужны виртуальные окружения?

Представьте два проекта на вашем компьютере. Старому нужна версия 1 какого-то пакета, новому — версия 2. Если ставить всё в один общий Python, они начнут конфликтовать, и один из проектов сломается.

**Виртуальное окружение** (его часто называют **venv**) — это личная папка с пакетами для **одного проекта**. У каждого проекта своё окружение, поэтому:

- проекты могут использовать разные версии одного и того же пакета,
- точно видно, что нужно каждому проекту,
- удалить пакеты проекта так же просто, как удалить папку,
- вы никогда не испортите Python, на который опирается ваша операционная система.

## Создаём виртуальное окружение

Откройте терминал **в папке проекта** и выполните:

```bash
python -m venv .venv
```

Эта команда создаёт папку `.venv`, в которой лежит копия Python и собственный пустой набор пакетов. (`-m venv` означает «запустить модуль `venv`». На некоторых компьютерах с macOS и Linux команда называется `python3`, а не `python`.)

## Активируем его

Просто создать venv недостаточно: его нужно **активировать (activate)**, чтобы `python` и `pip` пользовались именно им. Команда зависит от системы:

```bash
# macOS и Linux
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Windows (командная строка)
.venv\Scripts\activate.bat
```

Теперь приглашение командной строки начинается с `(.venv)` — так видно, что окружение активно:

```bash
(.venv) mei@laptop my-project %
```

Когда закончите, введите `deactivate`, чтобы вернуться обратно. Активируйте окружение заново каждый раз, когда открываете новый терминал для работы над проектом.

<Callout type="tip" title="Редакторы могут сделать это за вас">

VS Code и PyCharm замечают папку `.venv` в проекте и сами предлагают её использовать. Выберите её как интерпретатор проекта, и новые терминалы будут активировать окружение автоматически.

</Callout>

## Устанавливаем пакеты через pip

Пока venv активно, установите пакет по имени:

```bash
pip install requests
```

Ещё несколько команд, которые вам пригодятся:

```bash
pip install requests==2.32.3   # конкретная версия
pip install --upgrade requests # обновить до самой новой версии
pip uninstall requests         # удалить пакет
pip list                       # показать, что установлено
```

<Callout type="warning" title="Проверьте, что venv активно">

Если забыть активировать venv, `pip install` поставит пакет в ваш **глобальный** Python. Перед установкой проверьте, что приглашение начинается с `(.venv)`. Полезная привычка — запускать `python -m pip install requests`: так всегда используется pip, который принадлежит именно тому `python`, который вы запускаете.

</Callout>

## requirements.txt и pip freeze

Как коллеге (или вам самим на новом ноутбуке) установить те же пакеты? Их список хранят в файле **`requirements.txt`**. `pip freeze` печатает все установленные пакеты с точными версиями, а `>` сохраняет этот вывод в файл:

```bash
pip freeze > requirements.txt
```

Файл выглядит так:

```text title="requirements.txt"
certifi==2025.8.3
charset-normalizer==3.4.3
idna==3.10
requests==2.32.5
urllib3==2.5.0
```

Пакету `requests` нужны несколько вспомогательных пакетов, поэтому они тоже попали в список. Чтобы установить всё на другом компьютере, создайте и активируйте новое venv, а затем выполните:

```bash
pip install -r requirements.txt
```

`-r` означает «прочитать имена пакетов из этого файла». Если зафиксировать точные версии через `==`, у всех будет работать один и тот же код.

## Не добавляйте .venv в Git

В папке `.venv` могут быть тысячи файлов, и работает она только на том компьютере, где её создали. **Никогда не коммитьте её.** Вместо этого коммитьте (commit) `requirements.txt`, а Git попросите игнорировать venv: добавьте его в файл `.gitignore` в папке проекта:

```text title=".gitignore"
.venv/
__pycache__/
```

(В `__pycache__` лежат скомпилированные файлы, которые Python создаёт автоматически, когда вы импортируете собственные модули. Ими тоже не нужно делиться.)

## Весь процесс целиком

Новый проект с нуля начинается так:

```bash
mkdir weather-app
cd weather-app
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pip install requests
pip freeze > requirements.txt
```

А подключение к существующему проекту, который сделал кто-то другой, — так:

```bash
git clone https://github.com/someone/weather-app.git
cd weather-app
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

<Callout type="note" title="О каких ещё инструментах вы услышите">

Многие команды пользуются более новыми инструментами, например **uv** или **Poetry**: они создают venv и отслеживают пакеты за один шаг. Но в их основе те же идеи, которые вы только что изучили: отдельное venv для каждого проекта и файл со списком точных пакетов.

</Callout>

## Итоги

- **Пакет** — это код, которым можно делиться; пакеты живут на **PyPI**, а устанавливает их **pip**.
- `python -m venv .venv` создаёт виртуальное окружение — личные пакеты для одного проекта.
- Активируйте его командой `source .venv/bin/activate` (macOS/Linux) или `.venv\Scripts\Activate.ps1` (Windows), а выйти можно через `deactivate`.
- `pip install name`, `pip list`, `pip uninstall name`.
- `pip freeze > requirements.txt` сохраняет точные версии; `pip install -r requirements.txt` восстанавливает их.
- Добавьте `.venv/` в `.gitignore` и коммитьте `requirements.txt`.
- Python на PandaDev работает в браузере и не умеет делать pip install, поэтому тренируйтесь на своём компьютере.
