Веб-сервер отвечает на сотни запросов. Скрейпер скачивает десятки страниц. Чат-бот общается с API. Что у них общего? Почти всё время они **ждут**: сеть, базу данных или файл. А пока обычная программа на Python ждёт, она не делает вообще ничего.

**Асинхронный Python** (модуль `asyncio`) позволяет одной программе запустить что-то медленное, заняться пока чем-то полезным и вернуться, когда результат будет готов. Без потоков и без дополнительных процессов: просто одна программа на Python, которая умеет грамотно ждать. ⏳

## Ждать или работать

Представьте панду, которая готовит завтрак. Чайник закипает 3 минуты, тост жарится в тостере 2 минуты. Разумная панда включает чайник, кладёт хлеб в тостер и ждёт **и то и другое одновременно**: завтрак готов через 3 минуты, а не через 5.

Обычный код на Python — это панда другого типа. Каждая строка заканчивается до того, как начнётся следующая, поэтому она смотрит на чайник, пока тот не закипит, и только *потом* берётся за тост. Вот этот вариант, где `time.sleep()` изображает медленную работу (0.2 и 0.1 секунды вместо минут):

<CodeExample output={`Включаю чайник
Чай готов
Включаю тостер
Тост готов
Заняло не меньше 0.3 с: True`}>

```python
import time

def make_tea():
    print("Включаю чайник")
    time.sleep(0.2)          # ждём и ничего не делаем
    print("Чай готов")

def make_toast():
    print("Включаю тостер")
    time.sleep(0.1)
    print("Тост готов")

start = time.perf_counter()
make_tea()
make_toast()
elapsed = time.perf_counter() - start
print("Заняло не меньше 0.3 с:", elapsed >= 0.3)
```

</CodeExample>

Медленно бывает по двум очень разным причинам:

- **Ожидание** (его ещё называют **I/O-bound**, то есть упирается во ввод-вывод): компьютер простаивает, пока что-то снаружи не ответит, — веб-запрос, запрос к базе данных или таймер. Здесь async великолепен.
- **Работа** (**CPU-bound**, упирается в процессор): процессор занят вычислениями, например уменьшает фотографии или обрабатывает числа. Async **не может** это ускорить, потому что ждать здесь нечего. Для такого нужны другие инструменты (о них в конце).

## Корутины: async def

Напишите `async` перед `def` — и получите **корутинную функцию (coroutine function)**. Её вызов **не** выполняет тело. Вместо этого он возвращает **объект корутины (coroutine object)**: приостановленный кусок работы, готовый к запуску.

Чтобы действительно его выполнить, передайте его в **`asyncio.run()`**. Эта функция запускает всю асинхронную машинерию, выполняет корутину до конца и возвращает её результат:

<CodeExample output={`coroutine
Включаю чайник
Чай готов
Результат: зелёный чай`}>

```python
import asyncio

async def make_tea(kind):
    print("Включаю чайник")
    await asyncio.sleep(0.1)
    print("Чай готов")
    return f"{kind} чай"

job = make_tea("зелёный")      # пока ничего не напечатано!
print(type(job).__name__)

result = asyncio.run(job)      # а вот теперь она выполняется
print("Результат:", result)
```

</CodeExample>

Обычно `asyncio.run()` вызывают **один раз**, в самом начале программы, для корутины с именем `main()`. Всё остальное происходит внутри неё:

```python
async def main():
    ...  # вся асинхронная часть программы

asyncio.run(main())
```

## await: остановись здесь, вернёмся позже

Внутри `async def` можно использовать **`await`**. Это означает: *«выполни эту другую корутину и отдай мне её результат. Если ей придётся ждать, пусть пока поработает что-то другое»*.

`asyncio.sleep(seconds)` — асинхронная версия `time.sleep()`: она ждёт, **не блокируя** программу. Корутины могут ожидать (`await`) другие корутины — так же, как обычные функции вызывают обычные функции:

<CodeExample output={`Включаю чайник
Чайник вскипел
Завариваю зелёный чай
Зелёный чай готов`}>

```python
import asyncio

async def boil_water():
    print("Включаю чайник")
    await asyncio.sleep(0.1)
    print("Чайник вскипел")
    return "кипяток"

async def make_tea(kind):
    water = await boil_water()    # ждём результат
    print(f"Завариваю {kind} чай")
    await asyncio.sleep(0.05)
    return f"{kind.capitalize()} чай готов"

async def main():
    message = await make_tea("зелёный")
    print(message)

asyncio.run(main())
```

</CodeExample>

Два правила, которые стоит запомнить:

- `await` работает только **внутри** `async def`. В обычной функции это `SyntaxError`.
- Ожидать можно только **ожидаемые объекты (awaitables)**: корутины, задачи (о них в следующем уроке) и ещё несколько асинхронных объектов. `await time.sleep(1)` — ошибка, потому что `time.sleep` — обычная функция.

Сама по себе такая программа всё ещё выполняется шаг за шагом. Волшебство начинается, когда корутин **больше одной**.

## Цикл событий

`asyncio.run()` запускает **цикл событий (event loop)** — своего рода менеджер списка дел, который следит за каждой выполняющейся корутиной. Работает он так:

1. Выполняет корутину, пока она не дойдёт до `await`, которому нужно подождать (например, `asyncio.sleep`).
2. Эта корутина **приостанавливается**. Цикл запоминает, чего она ждёт, и берёт другую корутину, которая готова продолжать.
3. Когда ожидание закончилось, приостановленная корутина возвращается в список «готовых» и продолжает работу **ровно с того места, где остановилась**, со всеми своими переменными.

`asyncio.gather()` передаёт циклу сразу несколько корутин и ждёт, пока все они закончат. (Как следует вы познакомитесь с ней в следующем уроке.) Теперь панда готовит завтрак по-умному:

<CodeExample output={`Включаю чайник
Включаю тостер
Тост готов
Чай готов
['чай', 'тост']
Быстрее 0.3 с: True`}>

```python
import asyncio
import time

async def make(item, switch_on, seconds):
    print(f"Включаю {switch_on}")
    await asyncio.sleep(seconds)   # пауза, пусть работают другие
    print(f"{item.capitalize()} готов")
    return item

async def main():
    start = time.perf_counter()
    results = await asyncio.gather(
        make("чай", "чайник", 0.2),
        make("тост", "тостер", 0.1),
    )
    elapsed = time.perf_counter() - start
    print(results)
    print("Быстрее 0.3 с:", elapsed < 0.3)

asyncio.run(main())
```

</CodeExample>

Внимательно прочитайте вывод. Оба прибора включаются сразу, а тост готов первым, потому что он быстрее. Всё вместе занимает около 0.2 секунды (самое долгое ожидание), а не 0.3 (сумма).

<Callout type="note" title="Конкурентно, а не параллельно">

Здесь по-прежнему только **одна** программа на Python, которая делает **одно** дело за раз. Цикл просто переключается на другую корутину, когда текущая ждёт. Это называется **конкурентностью (concurrency)**. Выполнять несколько вычислений буквально в один и тот же момент на нескольких ядрах процессора — это **параллелизм (parallelism)**, и asyncio этим не занимается. Для программ, которые в основном ждут, конкурентности вполне достаточно.

</Callout>

Корутины переключаются только на `await`. Между двумя `await` ваш код выполняется без перерывов, поэтому полузаконченных изменений, как бывает с потоками, не возникает. Благодаря этому асинхронный код гораздо проще понимать.

## Ошибка 1: забытый await

Это самая частая ошибка в асинхронном коде. Если вызвать корутинную функцию без `await`, вы просто создадите объект корутины и тут же его выбросите. Тело **так и не выполнится**:

<CodeExample output={`Бронирую столик...
<lesson>:9: RuntimeWarning: coroutine 'send_email' was never awaited
RuntimeWarning: Enable tracemalloc to get the object allocation traceback
Готово!`}>

```python
import asyncio

async def send_email(to):
    await asyncio.sleep(0.01)
    print(f"Письмо отправлено: {to}")

async def main():
    print("Бронирую столик...")
    send_email("mei@example.com")    # упс: нет await
    print("Готово!")

asyncio.run(main())
```

</CodeExample>

Ни письма, ни ошибки — только **предупреждение**: *coroutine 'send_email' was never awaited* («корутину так и не дождались»). (В настоящем проекте в предупреждении будет имя вашего файла, например `app.py:9`, а не `<lesson>`.) Исправление — одно слово: `await send_email("mei@example.com")`.

<Callout type="warning" title="Следите за «was never awaited»">

Если что-то асинхронное «просто не происходит», ищите пропущенный `await`. Помогают редакторы и линтеры: VS Code и PyCharm подчёркивают корутины без `await`, и проверщик типов **mypy** тоже о них сообщает. Никогда не игнорируйте `RuntimeWarning: coroutine ... was never awaited`.

</Callout>

## Ошибка 2: блокировка цикла событий

Цикл может переключать корутины только на `await`. В обычном блокирующем вызове вроде `time.sleep()` нет никакого `await`, поэтому цикл застревает, пока вызов не закончится. Тот же завтрак, но с `time.sleep` внутри корутины:

<CodeExample output={`Включаю чайник
Чай готов
Включаю тостер
Тост готов
Быстрее 0.3 с: False`}>

```python
import asyncio
import time

async def make(item, switch_on, seconds):
    print(f"Включаю {switch_on}")
    time.sleep(seconds)    # блокирует весь цикл!
    print(f"{item.capitalize()} готов")
    return item

async def main():
    start = time.perf_counter()
    await asyncio.gather(
        make("чай", "чайник", 0.2),
        make("тост", "тостер", 0.1),
    )
    elapsed = time.perf_counter() - start
    print("Быстрее 0.3 с:", elapsed < 0.3)

asyncio.run(main())
```

</CodeExample>

Снаружи это `async def`, но ведёт себя код точно как медленная обычная версия. Для веб-сервера это катастрофа: один блокирующий вызов замораживает **все** запросы, а не один.

Что блокирует: `time.sleep()`, библиотека `requests`, обычные драйверы баз данных, чтение огромных файлов и долгие вычисления. В настоящих проектах вы бы:

- использовали асинхронные версии библиотек: `asyncio.sleep`, `AsyncClient` из **httpx** вместо `requests`, асинхронные драйверы баз данных;
- выносили неизбежную блокирующую работу в фоновый поток с помощью `await asyncio.to_thread(func, args)`, чтобы цикл продолжал работать.

<Callout type="tip" title="Когда нужен async?">

Используйте async, когда программа **ждёт** многого: веб-серверы (FastAPI), API-клиенты, скрейперы, чат-боты. Не стоит связываться с ним в простых скриптах, которые делают всё по очереди, или в числовых расчётах. Async добавляет сложности, поэтому применяйте его там, где есть ожидание.

</Callout>

import asyncio

async def boil_water(seconds):

## Итоги

- Программы часто медленные потому, что **ждут** (I/O-bound), а не работают. Async позволяет одной программе ждать многого сразу.
- `async def` создаёт **корутинную функцию**; её вызов возвращает **объект корутины**, который пока не выполняется.
- `asyncio.run(main())` запускает **цикл событий** и выполняет вашу главную корутину. Вызывайте её один раз.
- `await` выполняет корутину и получает её результат; пока она ждёт, цикл выполняет другие корутины. Работает только внутри `async def`.
- Корутины переключаются только на `await`: это **конкурентность** в одном потоке, а не параллелизм.
- Забытый `await` означает, что код **так и не выполнится** (ищите *«was never awaited»*).
- Блокирующие вызовы вроде `time.sleep()` замораживают весь цикл: используйте `asyncio.sleep`, асинхронные библиотеки или `asyncio.to_thread`.
