A web server answers hundreds of requests. A scraper downloads dozens of pages. A chat bot talks to an API. What do they have in common? They spend almost all of their time **waiting**: for the network, a database or a file. While a normal Python program waits, it does nothing else at all.

**Async Python** (the `asyncio` module) lets one program start a slow thing, go and do something useful while it waits, and come back when the result is ready. No threads, no extra processes: just one Python program that is clever about waiting. ⏳

## Waiting vs working

Picture a panda making breakfast. Tea needs 3 minutes for the kettle, toast needs 2 minutes in the toaster. A sensible panda switches the kettle on, puts the toast in, and waits for **both at the same time**: breakfast is ready in 3 minutes, not 5.

Normal Python code is the other kind of panda. Each line finishes before the next one starts, so it stares at the kettle until it boils, and only *then* starts the toast. Here's that version, with `time.sleep()` standing in for the slow work (0.2 and 0.1 seconds instead of minutes):

<CodeExample output={`Kettle on
Tea ready
Toaster on
Toast ready
Took at least 0.3 s: True`}>

```python
import time

def make_tea():
    print("Kettle on")
    time.sleep(0.2)          # waiting, doing nothing
    print("Tea ready")

def make_toast():
    print("Toaster on")
    time.sleep(0.1)
    print("Toast ready")

start = time.perf_counter()
make_tea()
make_toast()
elapsed = time.perf_counter() - start
print("Took at least 0.3 s:", elapsed >= 0.3)
```

</CodeExample>

There are two very different kinds of slow:

- **Waiting** (also called **I/O-bound**): the computer is idle until something outside answers, like a web request, a database query or a timer. Async is brilliant at this.
- **Working** (**CPU-bound**): the processor is busy calculating, like resizing photos or crunching numbers. Async **can't** speed this up, because there's nothing to wait for. That needs other tools (more on that at the end).

## Coroutines: async def

Put `async` in front of `def` and you get a **coroutine function**. Calling it does **not** run its body. Instead, it hands you a **coroutine object**: a paused piece of work that's ready to run.

To actually run it, give it to **`asyncio.run()`**, which starts the async machinery, runs the coroutine to the end and returns its result:

<CodeExample output={`coroutine
Kettle on
Tea ready
Result: green tea`}>

```python
import asyncio

async def make_tea(kind):
    print("Kettle on")
    await asyncio.sleep(0.1)
    print("Tea ready")
    return f"{kind} tea"

job = make_tea("green")        # nothing printed yet!
print(type(job).__name__)

result = asyncio.run(job)      # now it runs
print("Result:", result)
```

</CodeExample>

You usually call `asyncio.run()` **once**, at the very start of your program, on a coroutine called `main()`. Everything else happens inside it:

```python
async def main():
    ...  # the whole async part of your program

asyncio.run(main())
```

## await: pause here, come back later

Inside an `async def` you can use **`await`**. It means: *"run this other coroutine and give me its result. If it has to wait, let something else run in the meantime."*

`asyncio.sleep(seconds)` is the async version of `time.sleep()`: it waits **without blocking**. Coroutines can `await` other coroutines, just like normal functions call normal functions:

<CodeExample output={`Kettle on
Kettle boiled
Steeping green tea
Green tea is ready`}>

```python
import asyncio

async def boil_water():
    print("Kettle on")
    await asyncio.sleep(0.1)
    print("Kettle boiled")
    return "hot water"

async def make_tea(kind):
    water = await boil_water()    # wait for the result
    print(f"Steeping {kind} tea")
    await asyncio.sleep(0.05)
    return f"{kind.capitalize()} tea is ready"

async def main():
    message = await make_tea("green")
    print(message)

asyncio.run(main())
```

</CodeExample>

Two rules to remember:

- `await` only works **inside** an `async def`. Using it in a normal function is a `SyntaxError`.
- You can only `await` things that are **awaitable**: coroutines, tasks (next lesson) and a few other async objects. `await time.sleep(1)` is an error, because `time.sleep` is a normal function.

On its own, this still runs one step after another. The magic starts when there's **more than one** coroutine.

## The event loop

`asyncio.run()` starts an **event loop**: a to-do list manager that keeps track of every coroutine that's in progress. It works like this:

1. Run a coroutine until it reaches an `await` that has to wait (like `asyncio.sleep`).
2. That coroutine is **paused**. The loop notes what it's waiting for and picks another coroutine that's ready to go.
3. When the wait is over, the paused coroutine goes back on the "ready" list and continues **from exactly where it stopped**, with all its variables intact.

`asyncio.gather()` hands several coroutines to the loop at once and waits until all are done. (You'll meet it properly in the next lesson.) Now the panda makes breakfast the smart way:

<CodeExample output={`Kettle on
Toaster on
Toast ready
Tea ready
['tea', 'toast']
Faster than 0.3 s: True`}>

```python
import asyncio
import time

async def make(item, switch_on, seconds):
    print(f"{switch_on} on")
    await asyncio.sleep(seconds)   # pause, let others run
    print(f"{item.capitalize()} ready")
    return item

async def main():
    start = time.perf_counter()
    results = await asyncio.gather(
        make("tea", "Kettle", 0.2),
        make("toast", "Toaster", 0.1),
    )
    elapsed = time.perf_counter() - start
    print(results)
    print("Faster than 0.3 s:", elapsed < 0.3)

asyncio.run(main())
```

</CodeExample>

Read the output carefully. Both things are switched on straight away, and the toast finishes first because it's quicker. The total time is about 0.2 seconds (the longest wait), not 0.3 (the sum).

<Callout type="note" title="Concurrent, not parallel">

There's still only **one** Python program doing **one** thing at a time. The loop simply switches to another coroutine whenever the current one is waiting. That's called **concurrency**. Doing several calculations at literally the same moment on several CPU cores is **parallelism**, and asyncio doesn't do that. For waiting-heavy programs, concurrency is all you need.

</Callout>

Coroutines only ever switch at an `await`. Between two `await`s, your code runs without interruption, so you never get half-finished updates the way you can with threads. That makes async code much easier to reason about.

## Mistake 1: forgetting await

This is the most common async bug. Call a coroutine function without `await` and you just create a coroutine object and throw it away. The body **never runs**:

<CodeExample output={`Booking a table...
<lesson>:9: RuntimeWarning: coroutine 'send_email' was never awaited
RuntimeWarning: Enable tracemalloc to get the object allocation traceback
Done!`}>

```python
import asyncio

async def send_email(to):
    await asyncio.sleep(0.01)
    print(f"Email sent to {to}")

async def main():
    print("Booking a table...")
    send_email("mei@example.com")    # oops: no await
    print("Done!")

asyncio.run(main())
```

</CodeExample>

No email, no error, just a **warning**: *coroutine 'send_email' was never awaited*. (In a real project the warning names your file, like `app.py:9`, instead of `<lesson>`.) The fix is one word: `await send_email("mei@example.com")`.

<Callout type="warning" title='Watch for "was never awaited"'>

If something async "just doesn't happen", look for a missing `await`. Editors and linters help: VS Code and PyCharm underline unawaited coroutines, and the type checker **mypy** reports them too. Never ignore a `RuntimeWarning: coroutine ... was never awaited`.

</Callout>

## Mistake 2: blocking the event loop

The loop can only switch coroutines at an `await`. A normal blocking call like `time.sleep()` has no `await`, so the loop is stuck until it returns. Same breakfast as before, but with `time.sleep` inside the coroutine:

<CodeExample output={`Kettle on
Tea ready
Toaster on
Toast ready
Faster than 0.3 s: False`}>

```python
import asyncio
import time

async def make(item, switch_on, seconds):
    print(f"{switch_on} on")
    time.sleep(seconds)    # blocks the whole loop!
    print(f"{item.capitalize()} ready")
    return item

async def main():
    start = time.perf_counter()
    await asyncio.gather(
        make("tea", "Kettle", 0.2),
        make("toast", "Toaster", 0.1),
    )
    elapsed = time.perf_counter() - start
    print("Faster than 0.3 s:", elapsed < 0.3)

asyncio.run(main())
```

</CodeExample>

It's `async def` on the outside, but it behaves exactly like the slow, normal version. In a web server this is a disaster: one blocking call freezes **every** request, not just one.

Things that block: `time.sleep()`, the `requests` library, normal database drivers, reading huge files, and long calculations. In real projects you'd:

- use async versions of libraries: `asyncio.sleep`, **httpx**'s `AsyncClient` instead of `requests`, async database drivers;
- push unavoidable blocking work into a background thread with `await asyncio.to_thread(func, args)`, so the loop keeps running.

<Callout type="tip" title="When should I use async?">

Use async when your program **waits** on many things: web servers (FastAPI), API clients, scrapers, chat bots. Don't bother for simple scripts that do one thing after another, or for number crunching. Async adds complexity, so use it where the waiting is.

</Callout>

## Recap

- Programs are often slow because they're **waiting** (I/O-bound), not working. Async lets one program wait for many things at once.
- `async def` creates a **coroutine function**; calling it returns a **coroutine object** that doesn't run yet.
- `asyncio.run(main())` starts the **event loop** and runs your top-level coroutine. Call it once.
- `await` runs a coroutine and gets its result; while it waits, the loop runs other coroutines. It only works inside `async def`.
- Coroutines switch only at `await`: that's **concurrency** on one thread, not parallelism.
- Forgetting `await` means the code **never runs** (look for *"was never awaited"*).
- Blocking calls like `time.sleep()` freeze the whole loop: use `asyncio.sleep`, async libraries, or `asyncio.to_thread`.
