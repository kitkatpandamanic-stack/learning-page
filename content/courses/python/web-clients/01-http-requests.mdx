In [Your First API with FastAPI](/learn/python/first-api) you built the **server** side of HTTP: endpoints that receive requests and answer with JSON. Now you'll switch sides and write the **client**: Python code that calls someone else's API. Weather services, payment providers, GitHub, AI models, your company's other services: they all speak the same HTTP you already know, so a few lines of Python can talk to any of them. 🌍

You'll use the most popular HTTP library in Python, **requests**, and its modern cousin **httpx**.

## The practice API

Real websites aren't reachable from the lessons on this site, so PandaDev has a **practice API** at `https://api.pandadev.test`. Your code really calls it with `requests` or `httpx`, but the answers come from your browser, and nothing leaves your computer. It has movies, weather, recipes, users, posts and a full to-do list (`GET`, `POST`, `PATCH`, `PUT`, `DELETE`), and every run starts with fresh data.

On your own computer you'd install the libraries first, and then any URL works:

```bash
pip install requests httpx
```

```python
import requests

r = requests.get("https://api.github.com/repos/python/cpython", timeout=10)
print(r.json()["stargazers_count"])
```

## Your first request

`requests.get(url)` sends a `GET` request and gives you back a **response** object:

<CodeExample output={`200
application/json; charset=utf-8
{'id': 1, 'name': 'Mei Lin', 'username': 'mei', 'email': 'mei@pandadev.test'}
Mei Lin is mei`}>

```python
import requests

response = requests.get(
    "https://api.pandadev.test/users/1", timeout=5
)
print(response.status_code)
print(response.headers["Content-Type"])

user = response.json()
print(user)
print(user["name"], "is", user["username"])
```

</CodeExample>

That's the mirror image of your FastAPI apps: there you **returned** a dict and FastAPI turned it into JSON; here `response.json()` turns the JSON back into a dict. The `timeout=5` means "give up after 5 seconds". You'll see later why every request needs one.

## Query parameters with params=

To filter or page through results, APIs take **query parameters** after a `?`. You could glue the URL together with an f-string, but let `params=` do it:

<CodeExample output={`https://api.pandadev.test/movies?genre=comedy&limit=2
4 found, page 1 of 2
2019 The Bamboo Heist
2021 The Last Dumpling
https://api.pandadev.test/recipes?search=soy+sauce
['Bamboo Shoot Stir-fry']`}>

```python
import requests

BASE = "https://api.pandadev.test"

params = {"genre": "comedy", "limit": 2}
r = requests.get(f"{BASE}/movies", params=params, timeout=5)
print(r.url)

data = r.json()
print(data["total"], "found, page", data["page"], "of",
      data["totalPages"])
for movie in data["results"]:
    print(movie["year"], movie["title"])

r = requests.get(f"{BASE}/recipes",
                 params={"search": "soy sauce"}, timeout=5)
print(r.url)
print([recipe["name"] for recipe in r.json()])
```

</CodeExample>

`r.url` shows the URL that was really requested. Notice that the space in `soy sauce` became `+`: URLs can't contain spaces, `&`, `#` or `?` inside a value, so they must be **encoded**. With an f-string like `f"{BASE}/recipes?search={text}"`, a search for `fish & chips` would silently turn into two broken parameters. `params=` always encodes correctly, and it simply leaves out parameters whose value is `None`.

The movie list is also **paginated**: 4 comedies were found, but you only got page 1 of 2. You'll learn to walk through all the pages in the next lesson.

## Reading the response

A response has everything the server sent back:

| Attribute | What it is |
| --- | --- |
| `r.status_code` | `200`, `404`, ... |
| `r.reason` | the words for it: `"OK"`, `"Not Found"` |
| `r.ok` | `True` for any status below 400 |
| `r.headers` | the response headers (a dict that ignores upper/lower case) |
| `r.text` | the body as a string |
| `r.json()` | the body parsed as JSON |
| `r.url` | the final URL |

The most important thing to understand: **a 404 or a 500 is not an exception**. The request worked, the server just answered "no". Your code carries on happily unless you check. The shortcut is **`raise_for_status()`**, which raises `requests.HTTPError` for any 4xx or 5xx answer and does nothing otherwise:

<CodeExample output={`404 Not Found False
{"error":"Movie not found"}
{'error': 'Movie not found'}
Failed: 404 Client Error: Not Found for url: https://api.pandadev.test/movies/99
Midnight in the Forest`}>

```python
import requests

BASE = "https://api.pandadev.test"

r = requests.get(f"{BASE}/movies/99", timeout=5)
print(r.status_code, r.reason, r.ok)
print(r.text)
print(r.json())

try:
    r.raise_for_status()
except requests.HTTPError as error:
    print("Failed:", error)

r = requests.get(f"{BASE}/movies/3", timeout=5)
r.raise_for_status()   # 200: does nothing
print(r.json()["title"])
```

</CodeExample>

<Callout type="warning" title="Check the status before you use the data">

A very common bug: `r.json()["title"]` on an error response. The body is `{"error": "Movie not found"}`, so you get a confusing `KeyError: 'title'` far away from the real problem. Call `r.raise_for_status()` (or check `r.status_code`) **right after** each request, so failures show up where they happen.

</Callout>

## Sending data: POST, PATCH and DELETE

`requests.post`, `requests.put`, `requests.patch` and `requests.delete` work just like `get`. To send a JSON body, pass a dict as **`json=`**. requests converts it to JSON and sets the `Content-Type: application/json` header for you. This is the practice API's to-do list, the same kind of API you built in [the To-do API project](/learn/python/todo-api):

<CodeExample output={`201 {'id': 4, 'title': 'Water the bamboo', 'done': False}
application/json
200 {'id': 4, 'title': 'Water the bamboo', 'done': True}
204 ''
404 {'error': 'Todo not found'}
400 {'error': 'title is required'}`}>

```python
import requests

BASE = "https://api.pandadev.test"

new = {"title": "Water the bamboo", "done": False}
r = requests.post(f"{BASE}/todos", json=new, timeout=5)
print(r.status_code, r.json())
print(r.request.headers["Content-Type"])
todo_id = r.json()["id"]

r = requests.patch(f"{BASE}/todos/{todo_id}",
                   json={"done": True}, timeout=5)
print(r.status_code, r.json())

r = requests.delete(f"{BASE}/todos/{todo_id}", timeout=5)
print(r.status_code, repr(r.text))

r = requests.get(f"{BASE}/todos/{todo_id}", timeout=5)
print(r.status_code, r.json())

r = requests.post(f"{BASE}/todos", json={"done": True}, timeout=5)
print(r.status_code, r.json())
```

</CodeExample>

- `r.request` is the request that was actually sent, handy for checking what went over the wire.
- `204 No Content` has an empty body, so calling `r.json()` on it would fail. Check the status first.
- The last request forgot the title, so the API answered `400 Bad Request`. (Your FastAPI apps answered 422 for invalid data; APIs differ, so read their docs.)

Don't confuse `json=` with `data=`: `data={"title": "..."}` sends the old **form** format (`title=...`), like an HTML form does. Most APIs want `json=`.

## Request headers: who you are and what you want

Headers travel with every request. Three you'll set often:

- **`Accept: application/json`** says which format you want back.
- **`User-Agent`** says which program is calling. requests sends `python-requests/<version>` by default; polite clients name themselves and give a contact.
- **`Authorization: Bearer <token>`** proves who you are. Most APIs give you a secret **API key** or **token** to send with each request.

<CodeExample output={`200 3 users
panda-report/1.0 (mei@example.com)
True
python-requests`}>

```python
import os
import requests

# Only for this demo: pretend the terminal set the variable
os.environ.setdefault("PANDA_API_TOKEN", "demo-token-123")

token = os.environ["PANDA_API_TOKEN"]
headers = {
    "Accept": "application/json",
    "User-Agent": "panda-report/1.0 (mei@example.com)",
    "Authorization": f"Bearer {token}",
}
r = requests.get("https://api.pandadev.test/users",
                 headers=headers, timeout=5)
print(r.status_code, len(r.json()), "users")

sent = r.request.headers
print(sent["User-Agent"])
print(sent["Authorization"].startswith("Bearer "))

r = requests.get("https://api.pandadev.test/users", timeout=5)
print(r.request.headers["User-Agent"].split("/")[0])
```

</CodeExample>

The practice API doesn't check tokens, but real ones answer `401 Unauthorized` without a valid one.

<Callout type="danger" title="Never write a token in your code">

Tokens are passwords. Code gets pushed to GitHub, pasted into chats and kept in git history forever, and bots scan public repositories for keys within minutes. Read secrets from an **environment variable** instead, set outside the code (or loaded from a `.env` file that is listed in `.gitignore`):

```bash
export PANDA_API_TOKEN="paste-your-token-here"
python report.py
```

Then `os.environ["PANDA_API_TOKEN"]` fails loudly with a `KeyError` if it's missing, which is exactly what you want. And never print a token, not even "just to debug".

</Callout>

## Sessions: settings shared by many requests

Real clients make many requests to the same API with the same headers. A **`requests.Session`** remembers headers (and cookies) for every request made through it, and it reuses the network connection, which makes repeated requests to the same server noticeably faster:

<CodeExample output={`Sam Ortiz
['Debugging like a detective', "CSS is hard, and that's fine"]
31
panda-report/1.0`}>

```python
import requests

BASE = "https://api.pandadev.test"

session = requests.Session()
session.headers.update({
    "User-Agent": "panda-report/1.0",
    "Accept": "application/json",
})

def api_get(path, **params):
    r = session.get(BASE + path, params=params, timeout=5)
    r.raise_for_status()
    return r.json()

print(api_get("/users/2")["name"])
print([p["title"] for p in api_get("/posts", userId=3)])
print(api_get("/weather", city="Cairo")["temperature"])

r = session.get(BASE + "/users", timeout=5)
print(r.request.headers["User-Agent"])
session.close()
```

</CodeExample>

The small `api_get` helper is a pattern you'll see in many projects: **one place** that knows the base URL, the timeout and how errors are handled. A `Session` also works as a context manager (`with requests.Session() as session:`), which closes it for you.

## Always set a timeout

Here's a surprise: by default, requests waits **forever**. If a server accepts the connection and then never answers, your program hangs, and a scheduled job can sit there for days. Always pass `timeout=`. The practice API's `/delay/<ms>` endpoint answers slowly on purpose:

<CodeExample output={`Gave up: ReadTimeout
{'waited': 200}`}>

```python
import requests

BASE = "https://api.pandadev.test"

try:
    requests.get(f"{BASE}/delay/500", timeout=0.2)
except requests.Timeout as error:
    print("Gave up:", type(error).__name__)

r = requests.get(f"{BASE}/delay/200", timeout=2)
print(r.json())
```

</CodeExample>

The first request needed 0.5 s but was only allowed 0.2 s, so it raised **`requests.Timeout`** (more precisely `ReadTimeout`). The second one was quick enough. You can also give two numbers, `timeout=(3, 10)`: up to 3 s to connect and 10 s to wait for the answer.

## httpx: the modern alternative

**httpx** has almost the same API as requests, plus a few modern extras: a default timeout of 5 seconds, a `base_url` for clients, HTTP/2, and an **async** client (you'll use it in the next lesson). Its `Client` is the equivalent of a `Session`:

<CodeExample output={`200 True
Tokyo: 22°C, Rain
201 {'id': 4, 'title': 'Try httpx', 'done': False}
Failed: 404 {'error': 'Movie not found'}`}>

```python
import httpx

client = httpx.Client(
    base_url="https://api.pandadev.test",
    headers={"User-Agent": "panda-report/1.0"},
    timeout=5,
)
with client:
    r = client.get("/weather", params={"city": "Tokyo"})
    print(r.status_code, r.is_success)
    w = r.json()
    print(f"{w['city']}: {w['temperature']}°C, {w['condition']}")

    r = client.post("/todos", json={"title": "Try httpx"})
    print(r.status_code, r.json())

    r = client.get("/movies/99")
    try:
        r.raise_for_status()
    except httpx.HTTPStatusError as error:
        print("Failed:", error.response.status_code,
              error.response.json())
```

</CodeExample>

| | requests | httpx |
| --- | --- | --- |
| Quick call | `requests.get(url, timeout=5)` | `httpx.get(url)` |
| Shared settings | `requests.Session()` | `httpx.Client(base_url=...)` |
| Default timeout | none (waits forever) | 5 seconds |
| Status error | `requests.HTTPError` | `httpx.HTTPStatusError` |
| Async | no | `httpx.AsyncClient` |
| Redirects | followed | not followed unless `follow_redirects=True` |

Which one should you use? Both are excellent. requests is everywhere in existing code and tutorials; httpx is a great choice for new projects, especially async ones. Once you know one, you know 95% of the other.

<Callout type="tip" title="How pros explore an API">

Before writing code, read the API's documentation (often an OpenAPI `/docs` page, just like FastAPI makes) and try a request by hand, in the browser for `GET`s, or with a tool like `curl` or the **HTTPie** app. Then write the smallest client function that works, and look at `r.status_code` and `r.json()` before building on it.

</Callout>

```python
import requests

BASE = "https://api.pandadev.test"

def make_session(token):
    session = requests.Session()
    session.headers.update({
        "Accept": "application/json",
        "Authorization": f"Bearer {token}",
    })
    return session

def find_movies(session, search, genre=None):
    params = {"search": search, "limit": 50}
    if genre is not None:
        params["genre"] = genre
    r = session.get(f"{BASE}/movies", params=params, timeout=5)
    r.raise_for_status()
    return [movie["title"] for movie in r.json()["results"]]

def add_todo(session, title):
    r = session.post(f"{BASE}/todos",
                     json={"title": title, "done": False}, timeout=5)
    r.raise_for_status()
    return r.json()

session = make_session("demo-token")
print(find_movies(session, "bamboo"))
print(find_movies(session, "", genre="family"))
print(add_todo(session, "Read about sessions"))
```

## Recap

- **requests** is the client side of HTTP: `requests.get/post/put/patch/delete(url, ...)` return a response with `.status_code`, `.headers`, `.text`, `.json()` and `.url`.
- Use **`params=`** for query parameters (correct encoding, `None` values left out) and **`json=`** to send a JSON body.
- A 4xx/5xx answer is **not** an exception: call **`r.raise_for_status()`** right after the request.
- Headers like `Accept`, `User-Agent` and **`Authorization: Bearer <token>`** go in `headers=`. Tokens come from **environment variables**, never from your code or your logs.
- A **`Session`** shares headers and connections between requests; wrap it in a small helper that knows the base URL, timeout and error handling.
- **Always set a timeout**: requests waits forever by default and raises **`requests.Timeout`** when the limit is hit.
- **httpx** works almost the same (`httpx.Client(base_url=..., timeout=...)`), with a default timeout and an async client.
