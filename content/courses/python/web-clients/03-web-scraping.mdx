Not every website has an API. Prices in an online shop, timetables, results tables, job adverts: often the data is only on **web pages** made for people. **Web scraping** means fetching those pages with code and picking the data out of the HTML. With `requests` and a library called **Beautiful Soup**, a small scraper is about 20 lines. 🥣

In this lesson you'll scrape **Panda Books**, a pretend second-hand bookshop that lives on the practice API at `https://api.pandadev.test/shop`: 18 books over 3 pages, categories, and a detail page for each book.

## Scrape or use an API?

**Always look for an API first.** An API gives you clean JSON with a documented, stable format. A web page is designed for human eyes: its HTML can change any day when someone redesigns the site, and your scraper silently breaks. Scrape only when there's no API (or it lacks the data you need), and check the site's rules first:

- **Terms of service.** Many sites say whether automated access is allowed. Follow them.
- **robots.txt.** Sites list the paths that robots (crawlers and scrapers) may and may not visit in a file at `/robots.txt`. You'll read it with Python later in this lesson.
- **Be gentle.** A script can send hundreds of requests a second, enough to slow down a small site for everyone. Pause between requests, and don't download the same page again and again.
- **Personal data.** Names, emails and photos of people are protected by laws like the GDPR, even when they're publicly visible. Don't collect them without a clear legal reason.
- **Copyright.** Facts like prices are generally fine to collect for analysis; republishing someone's articles or photos is not.

## HTML in two minutes, and your first soup

HTML is made of **elements** like `<li class="book" data-id="4">...</li>`: a **tag** name (`li`), **attributes** (`class`, `data-id`) and content, which can contain more elements. Beautiful Soup reads HTML text into a tree of Python objects you can search. It's installed with `pip install beautifulsoup4`, but imported as `bs4`:

<CodeExample output={`Today's menu
Bamboo soup ['dish', 'veggie'] 4.50
- Bamboo soup 4.50
- Dumplings new! None
- Green tea 3.00
2
/order
None`}>

```python
from bs4 import BeautifulSoup

html = """
<div id="menu">
  <h2>Today's menu</h2>
  <ul>
    <li class="dish veggie" data-price="4.50">Bamboo soup</li>
    <li class="dish">Dumplings <b>new!</b></li>
    <li class="dish veggie" data-price="3.00">Green tea</li>
  </ul>
  <a href="/order">Order now</a>
</div>
"""
soup = BeautifulSoup(html, "html.parser")

print(soup.h2.get_text())
first = soup.find("li")
print(first.get_text(), first["class"], first["data-price"])

for dish in soup.find_all("li", class_="dish"):
    print("-", dish.get_text(" ", strip=True),
          dish.get("data-price"))

print(len(soup.find_all("li", class_="veggie")))
print(soup.find("a")["href"])
print(soup.find("table"))
```

</CodeExample>

- `BeautifulSoup(html, "html.parser")` parses the text with Python's built-in HTML parser.
- `soup.h2` is a shortcut for the first `<h2>`; **`find(...)`** returns the first matching element (or **`None`**), **`find_all(...)`** returns a list of all of them.
- `class_="dish"` (with an underscore, because `class` is a Python keyword) matches elements that have that class, even among several classes.
- **`get_text()`** gives the text inside, including nested elements. `get_text(" ", strip=True)` joins the pieces with a space and trims whitespace.
- An element works like a dict for its **attributes**: `first["data-price"]`. `class` comes back as a list, because an element can have several. `dish.get("data-price")` returns `None` instead of raising a `KeyError` when the attribute is missing.

## CSS selectors on a real page

Writing `find` inside `find` gets long. **CSS selectors**, the same patterns web designers use in style sheets, describe the path in one string. **`select(...)`** returns every match, **`select_one(...)`** the first (or `None`):

| Selector | Matches |
| --- | --- |
| `li` | every `<li>` |
| `.price` | elements with `class="price"` |
| `li.book` | `<li>` elements with the class `book` |
| `#menu` | the element with `id="menu"` |
| `.title a` | an `<a>` anywhere **inside** a `.title` |
| `ul.books > li` | an `<li>` **directly** inside `ul.books` |
| `a[rel="next"]` | an `<a>` whose `rel` attribute is `next` |
| `[data-stars]` | anything that has a `data-stars` attribute |

Here's the first page of the shop. (Tip: on a real site, right-click an element in your browser and choose **Inspect** to see its HTML and classes.)

<CodeExample output={`200 text/html; charset=utf-8

1 The Bamboo Code /shop/1

3 Stars for Beginners /shop/3
['Fiction', 'Science', 'Programming', 'Kids']

## Cleaning the values

Everything you scrape is **text** made for people: `"$6.50"`, `"by Kenji Mori"`, `"★★★★★"`. Before you can sort or average anything, turn it into proper Python values. Look for the easiest reliable source: the stars are hard to count from `★★★★☆`, but the `data-stars` attribute has the plain number, and the stock state is in a class:

<CodeExample output={`{'id': 7, 'title': 'Why the Sky Is Blue', 'author': 'Ada Brooks', 'price': 11.0, 'stars': 5, 'in_stock': True}
{'id': 8, 'title': "Dragons Can't Dance", 'author': 'Ravi Patel', 'price': 7.25, 'stars': 4, 'in_stock': False}
{'id': 9, 'title': 'Algorithms in Pictures', 'author': 'Kenji Mori', 'price': 29.0, 'stars': 5, 'in_stock': True}
Cheapest: Counting with Coco 5.99`}>

```python
import requests
from bs4 import BeautifulSoup

def parse_book(li):
    price_text = li.select_one(".price").get_text(strip=True)
    author_text = li.select_one(".author").get_text(strip=True)
    stock = li.select_one(".stock")
    return {
        "id": int(li["data-id"]),
        "title": li.select_one(".title a").get_text(strip=True),
        "author": author_text.removeprefix("by "),
        "price": float(price_text.removeprefix("$")),
        "stars": int(li.select_one(".rating")["data-stars"]),
        "in_stock": "in-stock" in stock["class"],
    }

r = requests.get("https://api.pandadev.test/shop?page=2",
                 timeout=5)
soup = BeautifulSoup(r.text, "html.parser")
books = [parse_book(li) for li in soup.select("li.book")]
for book in books[:3]:
    print(book)
cheapest = min(books, key=lambda b: b["price"])
print("Cheapest:", cheapest["title"], cheapest["price"])
```

</CodeExample>

`str.removeprefix` removes a prefix only if it's there, which is safer than slicing off a fixed number of characters. On real sites you'll meet messier text, like `"£1,299.00"`, `"Only 3 left!"` or `"12 Jan 2026"`: the string methods, regular expressions and `datetime` parsing from [Regular Expressions](/learn/python/regular-expressions) and [Dates and Times](/learn/python/dates-and-times) are exactly the tools for it. For money in real accounting code, use `Decimal` instead of `float`.

## Following links across pages

Links on web pages are usually **relative**: `href="/shop/4"` means "on this same site". To request them, turn them into full URLs with **`urllib.parse.urljoin(page_url, href)`**, which resolves them exactly like a browser does:

<CodeExample output={`https://api.pandadev.test/shop/4
https://api.pandadev.test/shop?page=3
https://api.pandadev.test/reviews
https://example.com/x`}>

```python
from urllib.parse import urljoin

page = "https://api.pandadev.test/shop?page=2"
print(urljoin(page, "/shop/4"))
print(urljoin(page, "?page=3"))
print(urljoin(page, "reviews"))
print(urljoin(page, "https://example.com/x"))
```

</CodeExample>

Now a scraper can **crawl**: fetch a page, follow its "Next" link (`a[rel="next"]`), and stop when there isn't one. It's the HTML version of the pagination loop from [the last lesson](/learn/python/robust-api-clients), and again a generator keeps it tidy:

<CodeExample output={`/shop -> 6 books
/shop?page=2 -> 6 books
/shop?page=3 -> 6 books
18 titles, last: The Map of Lost Things`}>

```python
import requests
from bs4 import BeautifulSoup
from urllib.parse import urljoin

BASE = "https://api.pandadev.test"

def crawl_pages(session, url):
    while url:
        r = session.get(url, timeout=5)
        r.raise_for_status()
        soup = BeautifulSoup(r.text, "html.parser")
        yield url, soup
        next_link = soup.select_one('a[rel="next"]')
        url = urljoin(url, next_link["href"]) if next_link else None

titles = []
with requests.Session() as session:
    session.headers["User-Agent"] = "panda-scraper/1.0"
    for url, soup in crawl_pages(session, BASE + "/shop"):
        links = soup.select("li.book .title a")
        print(url.removeprefix(BASE), "->", len(links), "books")
        titles += [a.get_text() for a in links]
print(len(titles), "titles, last:", titles[-1])
```

</CodeExample>

Following the site's own "Next" link is more robust than guessing URLs like `?page=4`: if the site changes how it numbers pages, your crawler still works, and it stops exactly at the last page.

## Detail pages

List pages show a summary; the full information is on each item's **detail page**. Tables are common there, and a dict comprehension turns a two-column table into a dict:

<CodeExample output={`Panda Goes to School
{'Category': 'Kids', 'Published': '2022', 'Pages': '32'}
Mei (5/5): My daughter asks for it every night.
Ravi (5/5): Lovely drawings.
Ada (4/5): Sweet story.
404 Book not found`}>

```python
import requests
from bs4 import BeautifulSoup

r = requests.get("https://api.pandadev.test/shop/4", timeout=5)
soup = BeautifulSoup(r.text, "html.parser")
book = soup.select_one("article.book-detail")

print(book.h2.get_text())
details = {
    row.th.get_text(): row.td.get_text()
    for row in book.select("table.details tr")
}
print(details)

for review in book.select("section.reviews li.review"):
    name = review.select_one(".reviewer").get_text()
    stars = review.select_one(".stars")["data-stars"]
    text = review.p.get_text()
    print(f"{name} ({stars}/5): {text}")

missing = requests.get("https://api.pandadev.test/shop/99",
                       timeout=5)
print(missing.status_code,
      BeautifulSoup(missing.text, "html.parser").h2.get_text())
```

</CodeExample>

Note the last request: web servers answer a missing page with a **404 status and a friendly HTML page**. If you don't check `status_code` (or call `raise_for_status()`), your scraper happily parses the error page as if it were a book.

Visiting every detail page means one request per item. That's fine for 18 books, but for 10,000 products think twice: is the data you need already on the list pages?

## Reading robots.txt

The shop's rules for robots are at `/robots.txt`. Python's standard library can read them with **`urllib.robotparser`**. Normally `RobotFileParser` downloads the file itself with `rp.set_url(...)` and `rp.read()`, but that uses `urllib` instead of requests and can't reach the practice API, so here you download the text with requests and hand its lines to **`parse()`**. That's a perfectly good habit anyway, because your request uses your session, timeout and User-Agent:

<CodeExample output={`# Rules for robots (scrapers and crawlers) on this site
User-agent: *
Allow: /shop
Disallow: /todos
Crawl-delay: 1

/shop True
/shop/7 True
/shop?page=2 True
/todos False
Crawl delay: 1`}>

```python
import requests
from urllib.robotparser import RobotFileParser

BASE = "https://api.pandadev.test"
AGENT = "panda-scraper/1.0"

text = requests.get(BASE + "/robots.txt", timeout=5).text
print(text)

robots = RobotFileParser()
robots.parse(text.splitlines())
for path in ["/shop", "/shop/7", "/shop?page=2", "/todos"]:
    print(path, robots.can_fetch(AGENT, BASE + path))
print("Crawl delay:", robots.crawl_delay(AGENT))
```

</CodeExample>

- `User-agent: *` means the rules apply to every robot. Sites can also have special rules for named bots.
- `Allow` and `Disallow` list path **prefixes**: `/shop` covers `/shop/7` and `/shop?page=2` too.
- **`can_fetch(agent, url)`** answers the question your scraper should ask before **every** request.
- `Crawl-delay: 1` asks robots to wait 1 second between requests.

## Being polite

A polite scraper behaves like a careful human visitor, not like an attack:

- **Identify yourself** with a `User-Agent` that names your project and gives a contact, like `panda-report/1.0 (mei@example.com)`. Never pretend to be a browser to get around a block.
- **Pause between requests**: `time.sleep(robots.crawl_delay(AGENT) or 1)` between pages. (The examples here skip the pause so they finish instantly; a real scraper shouldn't.)
- **Use one `Session`**, so connections are reused, and **save pages you've already downloaded** instead of fetching them again while you develop your parser.
- **Stop on errors.** Lots of 429 or 503 answers mean "slow down"; back off as you learned in [the last lesson](/learn/python/robust-api-clients).
- Run big jobs at quiet times, and only collect what you need.

## Scrapers that don't break easily

Web pages change. A scraper that worked yesterday can return nonsense today, and the worst failure is a **silent** one: no error, just wrong or missing data in your report. A few habits help:

<CodeExample output={`The Bamboo Code | $12.50
The Bamboo Code | ?
The shop says: 18 books`}>

```python
import re
from bs4 import BeautifulSoup

def text_of(element, selector, default=None):
    found = element.select_one(selector)
    if found is None:
        return default
    return found.get_text(strip=True)

before = """<li class="book" data-id="1">
  <h3 class="title"><a href="/shop/1">The Bamboo Code</a></h3>
  <p class="price">$12.50</p></li>"""
after = """<li class="book" data-id="1">
  <h3 class="title"><a href="/shop/1">The Bamboo Code</a></h3>
  <p class="price-now">$11.90</p></li>"""

for html in [before, after]:
    li = BeautifulSoup(html, "html.parser").li
    print(text_of(li, ".title a"), "|", text_of(li, ".price", "?"))

summary = "Showing 1–6 of 18 books"
match = re.search(r"of (\d+) books", summary)
print("The shop says:", int(match.group(1)), "books")
```

</CodeExample>

- **Choose stable hooks.** Meaningful classes (`.price`), ids and `data-` attributes change less often than layout. Avoid selectors like `div > div:nth-child(3) > span`, which break when anything moves.
- **Expect missing pieces.** `select_one` returns `None` when nothing matches, and `None.get_text()` crashes with an `AttributeError`. A helper like `text_of` makes optional fields explicit.
- **Check your results.** Compare what you collected with what the page says ("Showing 1–6 of **18** books"), check that prices are positive, and **fail loudly** when the numbers don't add up.
- **Test the parser offline.** Save a copy of a real page as a file, and write pytest tests that run your parsing functions on it. Keep fetching and parsing in separate functions, so the parser can be tested without a network.

<Callout type="note" title="Pages built by JavaScript">

Some sites send an almost empty HTML page and build the content with JavaScript in the browser. `requests` doesn't run JavaScript, so Beautiful Soup sees nothing. First check the browser's **Network** tab in the developer tools: often the page loads its data from a JSON API you can call directly, which is much easier. If not, a **browser automation** tool like Playwright drives a real browser for you (on your computer: `pip install playwright`, then `playwright install chromium`):

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("https://example.com/books")
    page.wait_for_selector("li.book")
    html = page.content()       # the HTML after JavaScript ran
    browser.close()
# ...then parse html with BeautifulSoup as usual
```

It's much slower and heavier than requests, so use it only when you have to.

</Callout>

            "author": author.removeprefix("by "),

            "stars": int(li.select_one(".rating")["data-stars"]),

def crawl(session, start_url, robots):
    books = []
    url = start_url
    while url and robots.can_fetch(AGENT, url):
        r = session.get(url, timeout=5)
        r.raise_for_status()
        books += parse_books(r.text, url)
        soup = BeautifulSoup(r.text, "html.parser")
        next_link = soup.select_one('a[rel="next"]')

## Recap

- **Prefer an API**; scrape only when there's none, and follow the site's **terms**, **robots.txt**, rate limits and privacy laws.
- `BeautifulSoup(html, "html.parser")` builds a searchable tree: **`find`/`find_all`** by tag and class, or **`select`/`select_one`** with **CSS selectors** like `li.book .title a` and `a[rel="next"]`.
- **`get_text(strip=True)`** gives an element's text, `element["attr"]` (or `.get("attr")`) its attributes, and `["class"]` is a list.
- **Clean** scraped text into real values (`removeprefix`, `float`, `int`), and prefer machine-friendly sources like `data-` attributes.
- Turn relative links into full URLs with **`urljoin`**, and crawl by following the site's own **`rel="next"`** link until there is none.
- Check **`robots.can_fetch(agent, url)`** before each request (`RobotFileParser.parse(text.splitlines())`), send an honest **User-Agent** and **pause** between requests.
- Make scrapers robust: stable selectors, explicit handling of missing elements, sanity checks against the page's own counts, and offline tests of the parser. JavaScript-built pages need their JSON API or a browser tool like **Playwright**.
