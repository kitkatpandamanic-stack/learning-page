Пора собрать весь модуль воедино. Ваша задача — **генератор отчётов (report generator)**: такой скрипт команды запускают каждое утро, чтобы ответить на вопросы вроде «как наши цены выглядят на фоне конкурентов?» или «как погода повлияла на продажи?». Он **собирает** данные из API и с веб-страниц, **очищает и обобщает** их и **записывает** отчёт в Markdown для людей и CSV-файл для электронных таблиц. 📊

Ваш отчёт будет охватывать фильмы из учебного API и магазин Panda Books. По пути вы увидите приёмы, благодаря которым такие скрипты остаются надёжными и их легко менять.

## План: конвейер из маленьких функций

Генератор отчётов — это **конвейер (pipeline)**. Каждый этап получает результат предыдущего и ничего не знает об остальных:

```text
сбор               очистка и обобщение        запись
────               ───────────────────        ──────
API (JSON)  ──┐
              ├──▶  списки словарей  ──▶  сводки  ──▶  report.md
Shop (HTML) ──┘                                  └──▶  books.csv
```

В коде каждый этап — это несколько маленьких функций:

- Функции **сбора** принимают `session` и `base_url` и возвращают обычные списки словарей Python. Только они обращаются к сети.
- Функции **обобщения (агрегации)** принимают списки и возвращают сводки. Они **чистые (pure)**: никакой сети, никаких файлов, одни и те же входные данные всегда дают один и тот же результат. Поэтому тестировать их проще простого.
- Функции **записи** принимают сводки и папку и создают файлы.

Зачем делать `base_url` параметром? Чтобы один и тот же код мог работать с тестовым сервером, промежуточной копией (staging) или продакшеном, а тесты могли направить его куда угодно. В настоящем проекте этапы жили бы в отдельных модулях (`collect.py`, `analyse.py`, `report.py`), а короткий `main.py` связывал бы их вместе.

## Сбор данных из API

В этом модуле вы уже писали циклы постраничной загрузки и помощники для API. Вот ещё один сборщик — для погоды — с одной новой деталью: **ожидаемые** проблемы, например город, которого API не знает, собираются и попадают в отчёт, а не обрушивают весь запуск:

<CodeExample output={`{'city': 'London', 'temperature': 14, 'condition': 'Cloudy'}
{'city': 'Paris', 'temperature': 17, 'condition': 'Sunny'}
{'city': 'Cairo', 'temperature': 31, 'condition': 'Sunny'}
{'city': 'Moscow', 'temperature': 6, 'condition': 'Snow'}
Не найдены: ['Atlantis']`}>

```python
import requests

BASE = "https://api.pandadev.test"

def fetch_weather(session, base_url, cities):
    """Текущая погода для каждого города; неизвестные города пропускаются."""
    found, missing = [], []
    for city in cities:
        r = session.get(f"{base_url}/weather",
                        params={"city": city}, timeout=5)
        if r.status_code == 404:
            missing.append(city)
            continue
        r.raise_for_status()
        data = r.json()
        found.append({
            "city": data["city"],
            "temperature": data["temperature"],
            "condition": data["condition"],
        })
    return found, missing

cities = ["London", "Paris", "Atlantis", "Cairo", "Moscow"]
with requests.Session() as session:
    weather, missing = fetch_weather(session, BASE, cities)
for row in weather:
    print(row)
print("Не найдены:", missing)
```

</CodeExample>

Кроме того, сборщик **оставляет только нужные поля** и даёт им ваши собственные имена. Если однажды API добавит или переименует поля, изменится только эта функция, а не весь отчёт.

404 для неизвестного города — ожидаемая ситуация, поэтому она обрабатывается. Всё остальное (500, тайм-аут) по-прежнему выбрасывает исключение: отчёт, построенный на половине данных так, что никто этого не заметил, хуже, чем отсутствие отчёта.

## Сбор данных из магазина

Страницы-списки магазина не сообщают, к какой категории относится книга, но сам магазин **устроен** по категориям: у каждой категории есть свой список (`/shop?category=kids`). Вместо того чтобы вписывать четыре категории в код, найдите их в навигации страницы — тогда новая категория появится в отчёте автоматически:

<CodeExample output={`fiction      https://api.pandadev.test/shop?category=fiction
science      https://api.pandadev.test/shop?category=science
programming  https://api.pandadev.test/shop?category=programming
kids         https://api.pandadev.test/shop?category=kids`}>

```python
import requests
from bs4 import BeautifulSoup
from urllib.parse import urljoin

BASE = "https://api.pandadev.test"

def category_links(session, base_url):
    shop_url = base_url + "/shop"
    r = session.get(shop_url, timeout=5)
    r.raise_for_status()
    soup = BeautifulSoup(r.text, "html.parser")
    return {
        a.get_text(strip=True).lower(): urljoin(shop_url, a["href"])
        for a in soup.select("nav.categories a")
    }

with requests.Session() as session:
    for name, url in category_links(session, BASE).items():
        print(f"{name:12} {url}")
```

</CodeExample>

Обойдите каждый из этих URL (переходя по ссылкам `rel="next"` — вдруг категория разрастётся больше чем на одну страницу), добавьте категорию к каждой книге — и у вас будет весь магазин с категориями за 5 запросов. Можно было бы зайти на все 18 страниц с подробностями и прочитать категорию из таблицы: это тоже правильно, но запросов получится больше чем втрое.

## Обобщение на чистом Python

Когда данные представлены списком словарей, в стандартной библиотеке есть всё для сводки: `statistics.mean`, `max`/`sorted` с `key`, `collections.Counter` для подсчёта и `defaultdict` для группировки:

<CodeExample output={`Средняя: 17
Самый тёплый: Cairo
[('Sunny', 2), ('Cloudy', 1)]
{'Cloudy': ['London'], 'Snow': ['Moscow'], 'Sunny': ['Paris', 'Cairo']}
['Moscow', 'London']`}>

```python
from collections import Counter, defaultdict
from statistics import mean

weather = [
    {"city": "London", "temperature": 14, "condition": "Cloudy"},
    {"city": "Paris", "temperature": 17, "condition": "Sunny"},
    {"city": "Cairo", "temperature": 31, "condition": "Sunny"},
    {"city": "Moscow", "temperature": 6, "condition": "Snow"},
]

average = mean(row["temperature"] for row in weather)
print("Средняя:", round(average, 1))

warmest = max(weather, key=lambda row: row["temperature"])
print("Самый тёплый:", warmest["city"])

conditions = Counter(row["condition"] for row in weather)
print(conditions.most_common(2))

by_condition = defaultdict(list)
for row in weather:
    by_condition[row["condition"]].append(row["city"])
print(dict(sorted(by_condition.items())))

coldest_first = sorted(weather, key=lambda row: row["temperature"])
print([row["city"] for row in coldest_first[:2]])
```

</CodeExample>

Обратите внимание: здесь данные вписаны прямо в код, без единого запроса. В этом и прелесть чистых функций обобщения: их можно попробовать (и протестировать) на пяти строках, набранных вручную. В следующем модуле, [Анализ данных с pandas](/learn/python/dataframes), вы освоите библиотеку, которая группирует и усредняет миллионы строк — каждое действие в одну строку кода.

При сортировке думайте о **равных значениях (ties)**. Два фильма с одинаковым рейтингом всегда должны выводиться в одном и том же порядке, иначе ваш отчёт будет без всякой причины меняться от запуска к запуску. Сортируйте по кортежу: `key=lambda m: (-m["rating"], m["title"])` означает «сначала самый высокий рейтинг, затем по названию».

## Пишем Markdown

**Markdown** — это обычный текст с лёгким форматированием (`# Заголовок`, `**жирный**`, `- списки`), и GitHub, GitLab, Slack, Notion и большинство вики красиво его отображают. Таблицы — это строки из ячеек между символами `|`, со строкой `---` под заголовком. Небольшая функция строит такую таблицу из любых заголовков и строк:

<CodeExample output={`| Город | °C | Погода |
| --- | --- | --- |
| Cairo | 31 | Sunny |
| Paris | 17 | Sunny |
| London | 14 | Cloudy |`}>

```python
def markdown_table(headers, rows):
    lines = [
        "| " + " | ".join(str(h) for h in headers) + " |",
        "| " + " | ".join("---" for _ in headers) + " |",
    ]
    for row in rows:
        lines.append("| " + " | ".join(str(c) for c in row) + " |")
    return "\n".join(lines)

rows = [["Cairo", 31, "Sunny"], ["Paris", 17, "Sunny"],
        ["London", 14, "Cloudy"]]
print(markdown_table(["Город", "°C", "Погода"], rows))
```

</CodeExample>

Форматируйте числа **до того**, как они попадут в таблицу: `f"{price:.2f}"` превращает `22.7` в `22.70`, так что столбец цен выравнивается и читается как денежные суммы.

## Записываем файлы с pathlib

`pathlib.Path` аккуратно управляется с папками и файлами: `/` соединяет части пути, `mkdir(parents=True, exist_ok=True)` создаёт папку (и родительские папки), если её ещё нет, а `write_text` записывает весь файл одним вызовом. Для CSV используйте `csv.DictWriter` из урока [CSV и JSON](/learn/python/csv-and-json):

<CodeExample output={`# Отчёт о погоде

- **London**: 14 °C
- **Cairo**: 31 °C
['city,temperature,condition', 'London,14,Cloudy', 'Cairo,31,Sunny']
['report.md', 'weather.csv']`}>

```python
import csv
from pathlib import Path

weather = [
    {"city": "London", "temperature": 14, "condition": "Cloudy"},
    {"city": "Cairo", "temperature": 31, "condition": "Sunny"},
]

folder = Path("weather-report")
folder.mkdir(parents=True, exist_ok=True)

report = folder / "report.md"
lines = ["# Отчёт о погоде", ""]
lines += [f"- **{w['city']}**: {w['temperature']} °C"
          for w in weather]
report.write_text("\n".join(lines) + "\n", encoding="utf-8")

table = folder / "weather.csv"
with table.open("w", newline="", encoding="utf-8") as file:
    writer = csv.DictWriter(
        file, fieldnames=["city", "temperature", "condition"])
    writer.writeheader()
    writer.writerows(weather)

print(report.read_text(encoding="utf-8"), end="")
print(table.read_text(encoding="utf-8").splitlines())
print(sorted(p.name for p in folder.iterdir()))
```

</CodeExample>

- Собирайте отчёт как **список строк** и соединяйте их один раз в конце. Это читается легче, чем одна гигантская f-строка, и в такой отчёт легко добавлять разделы.
- Всегда передавайте `encoding="utf-8"`, иначе на некоторых компьютерах `°C`, `★` и русские буквы могут превратиться в кракозябры.
- `DictWriter(..., extrasaction="ignore")` позволяет передавать словари, в которых ключей **больше**, чем столбцов в CSV (например, `url`, который вам не нужен в файле).

```python
import csv
from pathlib import Path
from statistics import mean
from urllib.parse import urljoin

import requests
from bs4 import BeautifulSoup

BASE = "https://api.pandadev.test"

# --- уже знакомые вам помощники (готовы к использованию) ----

def get_soup(session, url):
    r = session.get(url, timeout=5)
    r.raise_for_status()
    return BeautifulSoup(r.text, "html.parser")

def crawl_books(session, url):
    """Все книги со страницы-списка магазина и следующих за ней страниц."""
    books = []
    while url:
        soup = get_soup(session, url)
        for li in soup.select("li.book"):
            price = li.select_one(".price").get_text(strip=True)
            books.append({
                "id": int(li["data-id"]),
                "title": li.select_one(".title a").get_text(strip=True),
                "price": float(price.removeprefix("$")),
                "stars": int(li.select_one(".rating")["data-stars"]),
                "in_stock": "in-stock" in li.select_one(".stock")["class"],
            })
        next_link = soup.select_one('a[rel="next"]')
        url = urljoin(url, next_link["href"]) if next_link else None
    return books

def markdown_table(headers, rows):
    lines = [
        "| " + " | ".join(str(h) for h in headers) + " |",
        "| " + " | ".join("---" for _ in headers) + " |",
    ]
    for row in rows:
        lines.append("| " + " | ".join(str(c) for c in row) + " |")
    return "\n".join(lines)

# --- ваша часть ---------------------------------------------

def fetch_all_movies(session, base_url):
    movies = []
    page = 1
    while True:
        r = session.get(f"{base_url}/movies",
                        params={"page": page, "limit": 5}, timeout=5)
        r.raise_for_status()
        data = r.json()
        movies += data["results"]
        if page >= data["totalPages"]:
            return movies
        page += 1

def fetch_all_books(session, base_url):
    shop_url = base_url + "/shop"
    books = []
    for a in get_soup(session, shop_url).select("nav.categories a"):
        category = a.get_text(strip=True).lower()
        for book in crawl_books(session, urljoin(shop_url, a["href"])):
            books.append({**book, "category": category})
    return books

def summarise_books(books):
    summary = {}
    for category in sorted({book["category"] for book in books}):
        group = [b for b in books if b["category"] == category]
        summary[category] = {
            "books": len(group),
            "avg_price": round(mean(b["price"] for b in group), 2),
            "in_stock": sum(b["in_stock"] for b in group),
        }
    return summary

def top_movies(movies, n=3):
    ranked = sorted(movies, key=lambda m: (-m["rating"], m["title"]))
    return ranked[:n]

def write_report(folder, movies, books):
    folder = Path(folder)
    folder.mkdir(parents=True, exist_ok=True)
    average = mean(m["rating"] for m in movies)
    in_stock = sum(b["in_stock"] for b in books)
    lines = [
        "# Panda Data Report",
        "",
        "## Movies",
        "",
        f"{len(movies)} movies, average rating {average:.2f}.",
        "",
        markdown_table(
            ["Title", "Year", "Rating"],
            [[m["title"], m["year"], m["rating"]]
             for m in top_movies(movies)],
        ),
        "",
        "## Books",
        "",
        f"{len(books)} books, {in_stock} in stock.",
        "",
        markdown_table(
            ["Category", "Books", "Average price", "In stock"],
            [[c, s["books"], f"{s['avg_price']:.2f}", s["in_stock"]]
             for c, s in summarise_books(books).items()],
        ),
    ]
    report = folder / "report.md"
    report.write_text("\n".join(lines) + "\n", encoding="utf-8")
    fields = ["id", "title", "category", "price", "stars", "in_stock"]
    with (folder / "books.csv").open("w", newline="",
                                     encoding="utf-8") as file:
        writer = csv.DictWriter(file, fieldnames=fields,
                                extrasaction="ignore")
        writer.writeheader()
        writer.writerows(sorted(books, key=lambda b: b["id"]))
    return report

with requests.Session() as session:
    session.headers["User-Agent"] = "panda-report/1.0"
    movies = fetch_all_movies(session, BASE)
    books = fetch_all_books(session, BASE)
report = write_report(Path("panda-report"), movies, books)
if report:
    print(report.read_text(encoding="utf-8"), end="")
```

## Итоги

- Стройте генератор отчётов как **конвейер**: сбор → очистка и обобщение → запись, и каждый этап — несколько маленьких функций.
- **Сборщики** принимают `session` и `base_url`, оставляют только нужные поля, обрабатывают **ожидаемые** проблемы (например, 404 для неизвестного города), а настоящим сбоям позволяют выбросить исключение.
- Следуйте собственной структуре данных: **загружайте страницы** до `totalPages` и **находите** категории и следующие страницы в HTML, а не вписывайте их в код.
- Функции **обобщения** — чистые (на входе списки, на выходе сводки), поэтому их легко тестировать; `mean`, `sorted` с ключом-кортежем (дополнительный критерий при равенстве!), `Counter` и `defaultdict` покрывают большинство задач.
- Пишите **Markdown** для людей (заголовки, таблицы, отформатированные числа) и **CSV** для электронных таблиц с помощью `pathlib` (`mkdir(parents=True, exist_ok=True)`, `/`, `write_text`) и `encoding="utf-8"`.
- Запускайте генератор **по расписанию** (cron, GitHub Actions), храните секреты в переменных окружения, а сбои делайте громкими.
