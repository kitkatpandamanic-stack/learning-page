Time to put the whole module together. Your mission: a **report generator**, the kind of script teams run every morning to answer questions like "how are our prices compared with the competition?" or "what did the weather do to sales?". It **collects** data from an API and from web pages, **cleans and aggregates** it, and **writes** a Markdown report for people and a CSV file for spreadsheets. 📊

Your report will cover the practice API's movies and the Panda Books shop. Along the way you'll see the patterns that keep scripts like this reliable and easy to change.

## The plan: a pipeline of small functions

A report generator is a **pipeline**. Each stage gets the previous stage's output and knows nothing about the others:

```text
collect            clean & aggregate          write
───────            ─────────────────          ─────
API (JSON)  ──┐
              ├──▶  lists of dicts  ──▶  summaries  ──▶  report.md
Shop (HTML) ──┘                                     └──▶  books.csv
```

In code, each stage is a few small functions:

- **Collecting** functions take a `session` and a `base_url` and return plain Python lists of dicts. They're the only ones that touch the network.
- **Aggregating** functions take lists and return summaries. They're **pure**: no network, no files, the same input always gives the same output. That makes them trivial to test.
- **Writing** functions take summaries and a folder and produce files.

Why `base_url` as a parameter? So the same code can run against a test server, a staging copy or production, and tests can point it anywhere. In a real project the stages would live in separate modules (`collect.py`, `analyse.py`, `report.py`) with a short `main.py` that wires them together.

## Collecting from an API

You've written pagination loops and API helpers in this module. Here's one more collector, for the weather, with one new detail: **expected** problems, like a city the API doesn't know, are collected and reported instead of crashing the whole run:

<CodeExample output={`{'city': 'London', 'temperature': 14, 'condition': 'Cloudy'}
{'city': 'Paris', 'temperature': 17, 'condition': 'Sunny'}
{'city': 'Cairo', 'temperature': 31, 'condition': 'Sunny'}
{'city': 'Moscow', 'temperature': 6, 'condition': 'Snow'}
Not found: ['Atlantis']`}>

```python
import requests

BASE = "https://api.pandadev.test"

def fetch_weather(session, base_url, cities):
    """Current weather for each city; unknown cities are skipped."""
    found, missing = [], []
    for city in cities:
        r = session.get(f"{base_url}/weather",
                        params={"city": city}, timeout=5)
        if r.status_code == 404:
            missing.append(city)
            continue
        r.raise_for_status()
        data = r.json()
        found.append({
            "city": data["city"],
            "temperature": data["temperature"],
            "condition": data["condition"],
        })
    return found, missing

cities = ["London", "Paris", "Atlantis", "Cairo", "Moscow"]
with requests.Session() as session:
    weather, missing = fetch_weather(session, BASE, cities)
for row in weather:
    print(row)
print("Not found:", missing)
```

</CodeExample>

The collector also **keeps only the fields it needs** and gives them your own names. If the API adds or renames fields one day, only this function changes, not the whole report.

A 404 for an unknown city is expected, so it's handled. Anything else (a 500, a timeout) still raises: a report built on half the data, without anybody noticing, is worse than no report.

## Collecting from the shop

The shop's list pages don't say which category a book belongs to, but the shop **is** organised by category: each category has its own list (`/shop?category=kids`). Instead of typing the four categories into your code, discover them from the page's navigation, so a new category appears in your report automatically:

<CodeExample output={`fiction      https://api.pandadev.test/shop?category=fiction
science      https://api.pandadev.test/shop?category=science
programming  https://api.pandadev.test/shop?category=programming
kids         https://api.pandadev.test/shop?category=kids`}>

```python
import requests
from bs4 import BeautifulSoup
from urllib.parse import urljoin

BASE = "https://api.pandadev.test"

def category_links(session, base_url):
    shop_url = base_url + "/shop"
    r = session.get(shop_url, timeout=5)
    r.raise_for_status()
    soup = BeautifulSoup(r.text, "html.parser")
    return {
        a.get_text(strip=True).lower(): urljoin(shop_url, a["href"])
        for a in soup.select("nav.categories a")
    }

with requests.Session() as session:
    for name, url in category_links(session, BASE).items():
        print(f"{name:12} {url}")
```

</CodeExample>

Crawl each of those URLs (following `rel="next"` links, in case a category grows past one page), add the category to every book, and you have the whole shop with categories in 5 requests. The other way would be to visit all 18 detail pages and read the category from their table: correct too, but more than three times the requests.

## Aggregating with plain Python

Once the data is a list of dicts, the standard library has everything for a summary: `statistics.mean`, `max`/`sorted` with a `key`, `collections.Counter` for counting and `defaultdict` for grouping:

<CodeExample output={`Average: 17
Warmest: Cairo
[('Sunny', 2), ('Cloudy', 1)]
{'Cloudy': ['London'], 'Snow': ['Moscow'], 'Sunny': ['Paris', 'Cairo']}
['Moscow', 'London']`}>

```python
from collections import Counter, defaultdict
from statistics import mean

weather = [
    {"city": "London", "temperature": 14, "condition": "Cloudy"},
    {"city": "Paris", "temperature": 17, "condition": "Sunny"},
    {"city": "Cairo", "temperature": 31, "condition": "Sunny"},
    {"city": "Moscow", "temperature": 6, "condition": "Snow"},
]

average = mean(row["temperature"] for row in weather)
print("Average:", round(average, 1))

warmest = max(weather, key=lambda row: row["temperature"])
print("Warmest:", warmest["city"])

conditions = Counter(row["condition"] for row in weather)
print(conditions.most_common(2))

by_condition = defaultdict(list)
for row in weather:
    by_condition[row["condition"]].append(row["city"])
print(dict(sorted(by_condition.items())))

coldest_first = sorted(weather, key=lambda row: row["temperature"])
print([row["city"] for row in coldest_first[:2]])
```

</CodeExample>

Notice the data is typed straight into the code here, with no requests at all. That's the beauty of pure aggregating functions: you can try them out (and test them) with five hand-made rows. In the next module, [Data Analysis with pandas](/learn/python/dataframes), you'll learn a library that does grouping and averaging on millions of rows in one line each.

When you sort, think about **ties**. Two movies with the same rating should always come out in the same order, or your report changes from run to run for no reason. Sort by a tuple: `key=lambda m: (-m["rating"], m["title"])` means "highest rating first, then by title".

## Writing Markdown

**Markdown** is plain text with light formatting (`# Heading`, `**bold**`, `- lists`), and GitHub, GitLab, Slack, Notion and most wikis display it nicely. Tables are rows of cells between `|` characters, with a `---` line under the header. A small function builds one from any headers and rows:

<CodeExample output={`| City | °C | Condition |
| --- | --- | --- |
| Cairo | 31 | Sunny |
| Paris | 17 | Sunny |
| London | 14 | Cloudy |`}>

```python
def markdown_table(headers, rows):
    lines = [
        "| " + " | ".join(str(h) for h in headers) + " |",
        "| " + " | ".join("---" for _ in headers) + " |",
    ]
    for row in rows:
        lines.append("| " + " | ".join(str(c) for c in row) + " |")
    return "\n".join(lines)

rows = [["Cairo", 31, "Sunny"], ["Paris", 17, "Sunny"],
        ["London", 14, "Cloudy"]]
print(markdown_table(["City", "°C", "Condition"], rows))
```

</CodeExample>

Format numbers **before** they go into the table: `f"{price:.2f}"` turns `22.7` into `22.70`, so a column of prices lines up and reads like money.

## Writing the files with pathlib

`pathlib.Path` handles folders and files neatly: `/` joins path parts, `mkdir(parents=True, exist_ok=True)` creates a folder (and its parents) unless it's already there, and `write_text` writes a whole file in one call. For the CSV, use `csv.DictWriter` from [CSV and JSON](/learn/python/csv-and-json):

<CodeExample output={`# Weather report

- **London**: 14 °C
- **Cairo**: 31 °C
['city,temperature,condition', 'London,14,Cloudy', 'Cairo,31,Sunny']
['report.md', 'weather.csv']`}>

```python
import csv
from pathlib import Path

weather = [
    {"city": "London", "temperature": 14, "condition": "Cloudy"},
    {"city": "Cairo", "temperature": 31, "condition": "Sunny"},
]

folder = Path("weather-report")
folder.mkdir(parents=True, exist_ok=True)

report = folder / "report.md"
lines = ["# Weather report", ""]
lines += [f"- **{w['city']}**: {w['temperature']} °C"
          for w in weather]
report.write_text("\n".join(lines) + "\n", encoding="utf-8")

table = folder / "weather.csv"
with table.open("w", newline="", encoding="utf-8") as file:
    writer = csv.DictWriter(
        file, fieldnames=["city", "temperature", "condition"])
    writer.writeheader()
    writer.writerows(weather)

print(report.read_text(encoding="utf-8"), end="")
print(table.read_text(encoding="utf-8").splitlines())
print(sorted(p.name for p in folder.iterdir()))
```

</CodeExample>

- Build the report as a **list of lines** and join them once at the end. It's easier to read than one giant f-string, and easy to add sections.
- Always pass `encoding="utf-8"`, or `°C` and `★` may come out garbled on some computers.
- `DictWriter(..., extrasaction="ignore")` lets you pass dicts that have **more** keys than the CSV columns (like a `url` you don't want in the file).

```python
import csv
from pathlib import Path
from statistics import mean
from urllib.parse import urljoin

import requests
from bs4 import BeautifulSoup

BASE = "https://api.pandadev.test"

# --- helpers you already know (ready to use) ----------------

def get_soup(session, url):
    r = session.get(url, timeout=5)
    r.raise_for_status()
    return BeautifulSoup(r.text, "html.parser")

def crawl_books(session, url):
    """Every book on a shop list page and the pages after it."""
    books = []
    while url:
        soup = get_soup(session, url)
        for li in soup.select("li.book"):
            price = li.select_one(".price").get_text(strip=True)
            books.append({
                "id": int(li["data-id"]),
                "title": li.select_one(".title a").get_text(strip=True),
                "price": float(price.removeprefix("$")),
                "stars": int(li.select_one(".rating")["data-stars"]),
                "in_stock": "in-stock" in li.select_one(".stock")["class"],
            })
        next_link = soup.select_one('a[rel="next"]')
        url = urljoin(url, next_link["href"]) if next_link else None
    return books

def markdown_table(headers, rows):
    lines = [
        "| " + " | ".join(str(h) for h in headers) + " |",
        "| " + " | ".join("---" for _ in headers) + " |",
    ]
    for row in rows:
        lines.append("| " + " | ".join(str(c) for c in row) + " |")
    return "\n".join(lines)

# --- your part ----------------------------------------------

def fetch_all_movies(session, base_url):
    movies = []
    page = 1
    while True:
        r = session.get(f"{base_url}/movies",
                        params={"page": page, "limit": 5}, timeout=5)
        r.raise_for_status()
        data = r.json()
        movies += data["results"]
        if page >= data["totalPages"]:
            return movies
        page += 1

def fetch_all_books(session, base_url):
    shop_url = base_url + "/shop"
    books = []
    for a in get_soup(session, shop_url).select("nav.categories a"):
        category = a.get_text(strip=True).lower()
        for book in crawl_books(session, urljoin(shop_url, a["href"])):
            books.append({**book, "category": category})
    return books

def summarise_books(books):
    summary = {}
    for category in sorted({book["category"] for book in books}):
        group = [b for b in books if b["category"] == category]
        summary[category] = {
            "books": len(group),
            "avg_price": round(mean(b["price"] for b in group), 2),
            "in_stock": sum(b["in_stock"] for b in group),
        }
    return summary

def top_movies(movies, n=3):
    ranked = sorted(movies, key=lambda m: (-m["rating"], m["title"]))
    return ranked[:n]

def write_report(folder, movies, books):
    folder = Path(folder)
    folder.mkdir(parents=True, exist_ok=True)
    average = mean(m["rating"] for m in movies)
    in_stock = sum(b["in_stock"] for b in books)
    lines = [
        "# Panda Data Report",
        "",
        "## Movies",
        "",
        f"{len(movies)} movies, average rating {average:.2f}.",
        "",
        markdown_table(
            ["Title", "Year", "Rating"],
            [[m["title"], m["year"], m["rating"]]
             for m in top_movies(movies)],
        ),
        "",
        "## Books",
        "",
        f"{len(books)} books, {in_stock} in stock.",
        "",
        markdown_table(
            ["Category", "Books", "Average price", "In stock"],
            [[c, s["books"], f"{s['avg_price']:.2f}", s["in_stock"]]
             for c, s in summarise_books(books).items()],
        ),
    ]
    report = folder / "report.md"
    report.write_text("\n".join(lines) + "\n", encoding="utf-8")
```

## Recap

- Structure a report generator as a **pipeline**: collect → clean & aggregate → write, each stage a few small functions.
- **Collectors** take a `session` and a `base_url`, keep only the fields they need, handle **expected** problems (like a 404 for an unknown city) and let real failures raise.
- Follow the data's own structure: **paginate** until `totalPages`, and **discover** categories and next pages from the HTML instead of hard-coding them.
- **Aggregating** functions are pure (lists in, summaries out), so they're easy to test; `mean`, `sorted` with a tuple key (tie-breakers!), `Counter` and `defaultdict` cover most needs.
- Write **Markdown** for people (headings, tables, formatted numbers) and **CSV** for spreadsheets, with `pathlib` (`mkdir(parents=True, exist_ok=True)`, `/`, `write_text`) and `encoding="utf-8"`.
- Run it on a **schedule** (cron, GitHub Actions) with secrets in environment variables and loud failures.
