When you tick off a task in a to-do app on your phone, the app doesn't save it on the phone alone. It sends a small message over the internet to a **server**, and the server answers with a small message back. The set of messages a server understands is its **API** (Application Programming Interface). Websites, mobile apps and other programs all talk to servers this way.

In this module you'll build APIs with **FastAPI**, one of the most popular Python web frameworks. It's fast, short to write, and built on the type hints you already know. By the end of the module you'll have a working **To-do API**. 🐼

## HTTP in 5 minutes

APIs on the web speak **HTTP**. Every conversation is one **request** from the client and one **response** from the server. A request to fetch to-do number 3 looks roughly like this:

```text
GET /todos/3?include=notes HTTP/1.1
Host: api.example.com
Accept: application/json
```

And the server's response:

```text
HTTP/1.1 200 OK
Content-Type: application/json

{"id": 3, "title": "Buy bamboo", "done": false}
```

The important parts:

- **Method**: what you want to do. `GET` reads, `POST` creates, `PUT`/`PATCH` change, `DELETE` removes.
- **Path**: which thing you mean, like `/todos/3`. After a `?` come **query parameters** (`include=notes`), extra options as `key=value` pairs.
- **Headers**: extra information as `Name: value` lines, such as `Content-Type: application/json` ("the body is JSON").
- **Status code**: a number saying how it went. Learn these few by heart:

| Code | Meaning | When |
| --- | --- | --- |
| 200 | OK | Everything worked |
| 201 | Created | A `POST` made something new |
| 204 | No Content | Worked, nothing to send back (often after `DELETE`) |
| 404 | Not Found | That thing doesn't exist |
| 405 | Method Not Allowed | The path exists, but not with this method |
| 422 | Unprocessable Content | The data sent was invalid |
| 500 | Internal Server Error | The server crashed (a bug!) |

Codes starting with **2** mean success, **4** means the client did something wrong, and **5** means the server did.

- **Body**: the actual data, almost always **JSON** for APIs. It's the same JSON you met with `json.dumps`.

## REST: nouns in the path, verbs in the method

Most APIs follow a style called **REST**. The idea: the path names a **resource** (a thing, as a plural noun), and the HTTP method says what to do with it.

| Request | Meaning |
| --- | --- |
| `GET /todos` | List all to-dos |
| `POST /todos` | Create a new to-do |
| `GET /todos/3` | Get to-do number 3 |
| `PATCH /todos/3` | Change part of to-do 3 |
| `DELETE /todos/3` | Delete to-do 3 |

Paths like `/getTodos` or `/deleteTodo?id=3` work, but they put the verb in the wrong place. REST-style paths are predictable: once you know one resource, you can guess the rest.

## A first FastAPI app

Here's a complete API with one **endpoint** (one method + path the server answers):

<CodeExample output={`200
{'message': 'Hello from PandaDev!'}
application/json`}>

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()

@app.get("/")
def home():
    return {"message": "Hello from PandaDev!"}

client = TestClient(app)
response = client.get("/")
print(response.status_code)
print(response.json())
print(response.headers["content-type"])
```

</CodeExample>

Step by step:

- `app = FastAPI()` creates the application.
- `@app.get("/")` is a **decorator**: it registers `home` as the function to call for `GET /`. Functions like this are called **path operations** or **endpoints**.
- You return a normal dict, and FastAPI turns it into a JSON response with status 200.
- `TestClient(app)` is a pretend browser. `client.get("/")` sends a request straight into your app (no network needed) and gives back a response with `.status_code`, `.json()` and `.headers`.

In real projects, `TestClient` is exactly how FastAPI apps are **tested**, so you'll use it all through this module.

## Running a real server

On your own computer you'd save the app as `main.py` and start a real web server:

```bash
pip install "fastapi[standard]"
fastapi dev main.py
```

FastAPI prints an address, `http://127.0.0.1:8000`. Open it in a browser and you'll see `{"message":"Hello from PandaDev!"}`. The `dev` mode restarts the server every time you save the file. For production you'd use `fastapi run main.py` instead.

<Callout type="note" title="No server needed to learn">

Lessons on this site can't open network ports, so we call the app with `TestClient`. That's not a shortcut: your app code is exactly the same, and professional test suites do precisely this. The only extra thing a real server adds is listening on a port.

</Callout>

## Path parameters

Put a name in curly braces in the path, and FastAPI passes that part of the URL to your function as an argument of the same name. Add a **type hint** and FastAPI converts it for you:

<CodeExample output={`{'name': 'Mei', 'greeting': 'Hi, Mei!'}
{'number': 7, 'square': 49}
422
Input should be a valid integer, unable to parse string as an integer`}>

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()

@app.get("/pandas/{name}")
def get_panda(name: str):
    return {"name": name, "greeting": f"Hi, {name}!"}

@app.get("/squares/{number}")
def square(number: int):
    return {"number": number, "square": number * number}

client = TestClient(app)
print(client.get("/pandas/Mei").json())
print(client.get("/squares/7").json())

response = client.get("/squares/seven")
print(response.status_code)
print(response.json()["detail"][0]["msg"])
```

</CodeExample>

The URL is just text, but because of `number: int`, FastAPI turned `"7"` into the integer `7`. When the text can't be converted, your function isn't even called: FastAPI answers **422** with a clear message. Type hints aren't just documentation here, they do real work.

<Callout type="warning" title="Route order matters">

FastAPI checks routes **in the order you wrote them** and uses the first match. If `@app.get("/users/{username}")` comes before `@app.get("/users/me")`, then `GET /users/me` goes to the first one with `username="me"`. Always put fixed paths like `/users/me` **before** paths with parameters.

</Callout>

## Query parameters

Any function parameter that is **not** in the path becomes a **query parameter**. Give it a default value to make it optional:

<CodeExample output={`['bamboo', 'honey', 'apple']
['bamboo', 'apple']
['honey']
['bamboo', 'apple']`}>

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()

SNACKS = [
    {"name": "bamboo", "price": 2, "vegan": True},
    {"name": "honey", "price": 5, "vegan": False},
    {"name": "apple", "price": 1, "vegan": True},
]

@app.get("/snacks")
def list_snacks(max_price: int = 100, vegan: bool | None = None):
    result = [s for s in SNACKS if s["price"] <= max_price]
    if vegan is not None:
        result = [s for s in result if s["vegan"] == vegan]
    return [s["name"] for s in result]

client = TestClient(app)
print(client.get("/snacks").json())
print(client.get("/snacks?max_price=2").json())
print(client.get("/snacks?vegan=false").json())
print(client.get("/snacks", params={"max_price": 3, "vegan": True}).json())
```

</CodeExample>

A few things to notice:

- `vegan: bool | None = None` means "optional, and `None` when not given". That's how you tell "not filtered" apart from "filter for `False`".
- FastAPI understands `true`/`false` (also `1`/`0`, `yes`/`no`) for `bool`.
- `params={...}` builds the `?key=value&...` part for you, which is safer than gluing strings together.
- You can return a list too, not only a dict.

A parameter **without** a default is required: leave it out and you get a 422.

## Same path, different methods

The method is part of the endpoint. `GET /likes` and `POST /likes` are two different endpoints, and a method you didn't define gets **405**:

<CodeExample output={`{'count': 0}
{'count': 2}
405`}>

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()
likes = {"count": 0}

@app.get("/likes")
def read_likes():
    return likes

@app.post("/likes")
def add_like():
    likes["count"] += 1
    return likes

client = TestClient(app)
print(client.get("/likes").json())
client.post("/likes")
client.post("/likes")
print(client.get("/likes").json())
print(client.delete("/likes").status_code)
```

</CodeExample>

`GET` should only ever **read**. Browsers, caches and search engines assume they can repeat a `GET` safely, so anything that changes data belongs in `POST`, `PATCH`, `PUT` or `DELETE`. In the next lesson, `POST` endpoints will also receive data in the request body.

## Automatic docs at /docs

Here's FastAPI's party trick. From your type hints it writes a full description of your API in a standard format called **OpenAPI**, served at `/openapi.json`:

<CodeExample output={`Panda Zoo API
['/pandas/{name}']
Look up one panda by name.
name path {'type': 'string', 'title': 'Name'}
hungry query {'type': 'boolean', 'default': False, 'title': 'Hungry'}`}>

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI(title="Panda Zoo API")

@app.get("/pandas/{name}")
def get_panda(name: str, hungry: bool = False):
    """Look up one panda by name."""
    return {"name": name, "hungry": hungry}

client = TestClient(app)
schema = client.get("/openapi.json").json()
print(schema["info"]["title"])
print(list(schema["paths"]))
operation = schema["paths"]["/pandas/{name}"]["get"]
print(operation["description"])
for param in operation["parameters"]:
    print(param["name"], param["in"], param["schema"])
```

</CodeExample>

FastAPI knows `name` is a string in the path and `hungry` is an optional boolean in the query, and it even used your docstring. With a real server running, open `http://127.0.0.1:8000/docs` and you get an interactive page built from this description: every endpoint is listed, and a **"Try it out"** button lets you send requests from the browser. Front-end developers love it, because the docs can never get out of date with the code.

<Callout type="tip" title="How pros work with /docs">

Teams share the `/docs` page (or the `openapi.json` file) instead of writing API documentation by hand. Tools can even generate client code for other languages from it. Good names, type hints and a one-line docstring per endpoint make the generated docs genuinely useful.

</Callout>

<Hint>

Each endpoint is a function with a decorator, e.g. `@app.get("/hello/{name}")` and `def hello(name: str, shout: bool = False):`. Build the message with an f-string and use `.upper()` when `shout` is true. For `/pandas`, use a list comprehension: `[p["name"] for p in PANDAS if p["age"] >= min_age]`. The `int` type hint on `min_age` gives you the 422 for free.

</Hint>

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()

PANDAS = [
    {"name": "Mei", "age": 4},
    {"name": "Bao", "age": 11},
    {"name": "Lin", "age": 7},
]

@app.get("/")
def zoo_info():
    return {"zoo": "Panda Zoo", "pandas": len(PANDAS)}

@app.get("/hello/{name}")
def hello(name: str, shout: bool = False):
    message = f"Hello, {name}!"
    if shout:
        message = message.upper()
    return {"message": message}

@app.get("/pandas")
def list_pandas(min_age: int = 0):
    return [p["name"] for p in PANDAS if p["age"] >= min_age]

client = TestClient(app)
print(client.get("/").json())
print(client.get("/hello/Mei?shout=true").json())
print(client.get("/pandas?min_age=5").json())
```

## Recap

- An HTTP **request** has a method, a path (with optional `?query` parameters), headers and a body; the **response** has a status code, headers and a body (usually JSON).
- Status codes: **2xx** success (200, 201, 204), **4xx** client mistakes (404, 405, 422), **5xx** server bugs.
- **REST**: plural nouns in the path (`/todos/3`), the action in the method (`GET`, `POST`, `PATCH`, `DELETE`).
- `app = FastAPI()` and `@app.get(...)` / `@app.post(...)` define endpoints; returned dicts and lists become JSON.
- `{name}` in the path is a **path parameter**; other function parameters are **query parameters**; type hints convert and validate them (invalid → **422**).
- `TestClient(app)` calls your app without a server, the same way real test suites do; `fastapi dev main.py` runs a real server with docs at `/docs`.
