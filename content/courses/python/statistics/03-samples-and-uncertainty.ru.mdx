Вы спросили 40 покупателей, сколько они готовы потратить, и в среднем получилось £32. Значит ли это, что среднее по **всем** вашим покупателям — £32? Скорее всего, не совсем. А может быть, £25? Или £40? Число без представления о том, насколько оно может ошибаться, — это только половина ответа.

Этот урок — о второй половине: о **неопределённости (uncertainty)**. Вместо тяжёлой математики вы позволите Python **смоделировать** то, что могло бы произойти, тысячи раз, и посмотрите, насколько «гуляет» ответ. Потом та же идея поможет ответить на самый частый вопрос в бизнес-данных: *«это различие настоящее или просто повезло?»* 🎲

## Генеральная совокупность и выборки

**Генеральная совокупность (population)** — это всё, о чём вы хотите узнать: все ваши покупатели, каждый заказ, каждый посетитель за год. Целиком вы её почти никогда не видите. У вас есть **выборка (sample)**: 40 покупателей, которые ответили, или посетители за одну неделю.

Число, посчитанное по выборке, например её среднее, — это **оценка (estimate)** числа для генеральной совокупности. Возьмите другую выборку — и получите немного другую оценку. Эти колебания называются **выборочной изменчивостью (sampling variability)**, и именно их измеряет весь остальной урок.

<Callout type="warning" title="Случайность можно измерить, смещение — нельзя">

Всё в этом уроке предполагает **случайную** выборку: у каждого покупателя были одинаковые шансы попасть в неё. Если вы опросили только тех, кто пользуется приложением, или тех, кто сам решил ответить на опрос, ваша выборка **смещена (biased)**, и никакая формула не скажет, насколько. Больше смещённых данных лишь делает вас увереннее в неправильном ответе. Прежде чем что-то считать, подумайте, *как* собирались данные.

</Callout>

## Случайные числа, которые можно повторить

Симуляциям нужны случайные числа, и для этого есть **генератор случайных чисел (random generator)** NumPy. Он создаётся через **`np.random.default_rng(seed)`**: **seed** (зерно) делает «случайные» числа одинаковыми при каждом запуске, чтобы результаты можно было проверить и повторить, — как `random.seed()` из урока [Модули и импорт](/learn/python/modules-and-imports).

<CodeExample output={`[1 5 4 3 3 6 1 5 2 1]
[0.976 0.761 0.786]
[169.9 163.2 177. ]
['A' 'B' 'B' 'B' 'A' 'B']
[1 5 4 3 3 6 1 5 2 1]`}>

```python
import numpy as np

rng = np.random.default_rng(42)
print(rng.integers(1, 7, size=10))        # кубик: от 1 до 6
print(rng.random(3).round(3))             # от 0 до 1
print(rng.normal(170, 8, size=3).round(1))  # около 170
print(rng.choice(["A", "B"], size=6))     # выбор из списка

rng = np.random.default_rng(42)           # снова тот же seed...
print(rng.integers(1, 7, size=10))        # ...те же броски кубика
```

</CodeExample>

- **`rng.integers(low, high, size=...)`** даёт целые числа от `low` до `high`, не включая `high`.
- **`rng.normal(mean, std, size=...)`** даёт числа, которые группируются вокруг `mean` в форме колокола.
- **`rng.choice(values, size=...)`** выбирает из списка или массива. По умолчанию он выбирает **с возвращением (with replacement)**: один и тот же элемент может выпасть дважды, как при повторном броске кубика. Запомните его — он главный герой бутстрепа ниже.

Создайте **один** генератор в начале и передавайте его дальше (или передавайте seed), а не создавайте новые в цикле. В учебниках ещё встречается старый стиль `np.random.seed(42)`; генератор — современный способ.

## Закон больших чисел

Подбросьте честную монету 10 раз — и может выпасть 8 орлов. Подбросьте 100 000 раз — и доля орлов будет очень близка к 50%. Это **закон больших чисел (law of large numbers)**: чем больше выборка, тем ближе её среднее к среднему генеральной совокупности.

<CodeExample output={`     10 бросков: доля орлов 0.700
    100 бросков: доля орлов 0.540
   1000 бросков: доля орлов 0.501
  10000 бросков: доля орлов 0.494
 100000 бросков: доля орлов 0.502`}>

```python
import numpy as np

rng = np.random.default_rng(7)
for n in [10, 100, 1_000, 10_000, 100_000]:
    flips = rng.integers(0, 2, size=n)    # 1 = орёл
    print(f"{n:>7} бросков: доля орлов {flips.mean():.3f}")
```

</CodeExample>

Среднее массива из 0 и 1 — это **доля** единиц. Этот приём вам постоянно пригодится с данными вида «купил: да/нет». Вот как текущая доля орлов успокаивается по мере накопления бросков. Ось x — в **логарифмическом масштабе** (`set_xscale("log")`), поэтому 10, 100 и 1000 бросков стоят на равных расстояниях:

<TryIt language="python" code={`import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(7)
n = 10_000
fig, ax = plt.subplots(figsize=(8, 4))

for run in range(3):
    flips = rng.integers(0, 2, size=n)
    running = np.cumsum(flips) / np.arange(1, n + 1)
    ax.plot(np.arange(1, n + 1), running, label=f"серия {run + 1}")

ax.axhline(0.5, color="black", linestyle="--")
ax.set_xscale("log")
ax.set_ylim(0, 1)
ax.set_xlabel("Число бросков")
ax.set_ylabel("Доля орлов на данный момент")
ax.legend()
plt.show()`}
/>

`np.cumsum` даёт накопленные суммы (1, 1, 2, 3...), а деление на 1, 2, 3... превращает их в текущие доли. Вначале серии сильно раскачиваются, а после нескольких тысяч бросков все жмутся к 0,5. **Маленькие выборки шумные.** Вспомните об этом, когда в следующий раз увидите оценку в 5 звёзд по 3 отзывам.

## Насколько «гуляют» выборочные средние?

Давайте ненадолго побудем всемогущими. Придумаем **генеральную совокупность** из 100 000 сумм заказов — так мы будем знать настоящее среднее, — а потом возьмём из неё много выборок и посмотрим, насколько далеко от истины окажутся их средние:

<CodeExample output={`истинное среднее £32.44, std £21.41
n =  25: разброс средних 4.28, формула 4.28
n = 100: разброс средних 2.12, формула 2.14
n = 400: разброс средних 1.07, формула 1.07`}>

```python
import numpy as np

rng = np.random.default_rng(0)
population = rng.lognormal(3.3, 0.6, size=100_000)   # £, скошено
sigma = population.std()
print(f"истинное среднее £{population.mean():.2f}, std £{sigma:.2f}")

for n in [25, 100, 400]:
    # 2000 выборок по n заказов: одна выборка в строке
    samples = rng.choice(population, size=(2_000, n))
    means = samples.mean(axis=1)          # среднее каждой строки
    print(f"n = {n:>3}: разброс средних {means.std():.2f},"
          f" формула {sigma / np.sqrt(n):.2f}")
```

</CodeExample>

`size=(2_000, n)` создаёт таблицу из 2000 строк, по одной выборке в строке, а **`mean(axis=1)`** усредняет **вдоль каждой строки** и сразу даёт 2000 выборочных средних без цикла на Python. (`axis=0` усреднял бы по каждому столбцу.)

У разброса выборочных средних есть название: **стандартная ошибка (standard error, SE)**. Она отвечает на вопрос *«насколько далеко выборочное среднее обычно от настоящего?»* И симуляция совпадает с известной формулой:

**SE = std / √n**

В жизни std генеральной совокупности неизвестно, поэтому берут выборочное: `sample.std(ddof=1) / np.sqrt(len(sample))`. Главное здесь — квадратный корень: **в 4 раза больше данных уменьшают неопределённость всего вдвое**. Переход от 100 к 400 заказам уменьшил колебания примерно с £2 до £1.

Нарисуйте выборочные средние, и станут видны ещё две вещи. Попробуйте `n = 2`:

<TryIt language="python" code={`import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(0)
population = rng.lognormal(3.3, 0.6, size=100_000)

fig, axes = plt.subplots(1, 4, figsize=(13, 3.2), sharex=True)
axes[0].hist(population, bins=60, range=(0, 120), color="#999999")
axes[0].set_title("Совокупность: отдельные заказы")

for ax, n in zip(axes[1:], [5, 25, 100]):
    means = rng.choice(population, size=(5_000, n)).mean(axis=1)
    ax.hist(means, bins=40, color="#0072B2")
    ax.set_title(f"Средние выборок по {n}")

fig.tight_layout()
plt.show()`}
/>

С ростом n выборочные средние становятся **уже** (это уменьшается стандартная ошибка) и складываются в **колокол**, хотя отдельные заказы распределены несимметрично. Второй факт — это **центральная предельная теорема (central limit theorem)**, и именно поэтому столько статистических формул предполагают колоколообразную кривую: обычно они о *средних*, а средние выборок приличного размера ведут себя именно так.

## Доверительные интервалы с помощью бутстрепа

В жизни у вас нет генеральной совокупности, из которой можно 2000 раз брать выборки. У вас **одна** выборка. **Бутстреп (bootstrap)** — гениально простой приём: считайте свою выборку заменой генеральной совокупности и **берите из неё повторные выборки с возвращением**.

1. Из ваших n значений вытяните n значений **с возвращением** (какие-то значения попадут дважды, какие-то — ни разу).
2. Посчитайте нужную статистику, например среднее.
3. Повторите тысячи раз.
4. Средние 95% полученных результатов — это **95-процентный доверительный интервал (confidence interval, ДИ)**.

<CodeExample output={`среднее выборки £31.51
бутстреп, 95% ДИ: от £26.25 до £37.53
среднее ± 1.96 SE: от £25.75 до £37.27
медиана £28.36, 95% ДИ от £23.11 до £33.21`}>

```python
import numpy as np

rng = np.random.default_rng(1)
sample = rng.lognormal(3.3, 0.6, size=40).round(2)  # 40 заказов
print(f"среднее выборки £{sample.mean():.2f}")

boot = rng.choice(sample, size=(10_000, len(sample)))
boot_means = boot.mean(axis=1)
low, high = np.percentile(boot_means, [2.5, 97.5])
print(f"бутстреп, 95% ДИ: от £{low:.2f} до £{high:.2f}")

se = sample.std(ddof=1) / np.sqrt(len(sample))
print(f"среднее ± 1.96 SE: от £{sample.mean() - 1.96 * se:.2f}"
      f" до £{sample.mean() + 1.96 * se:.2f}")

boot_medians = np.median(boot, axis=1)
low, high = np.percentile(boot_medians, [2.5, 97.5])
print(f"медиана £{np.median(sample):.2f},"
      f" 95% ДИ от £{low:.2f} до £{high:.2f}")
```

</CodeExample>

Бутстреп и классическая формула (среднее ± 1,96 стандартной ошибки, где 1,96 берётся из колоколообразной кривой) дают похожие ответы. Большое преимущество бутстрепа: он работает для **любой** статистики — медианы, как выше, перцентиля или отношения, — для которых простой формулы нет.

Как же это сформулировать? *«В среднем покупатели тратят около £32 (95% ДИ: от £26 до £38)»*. **95-процентный доверительный интервал** получен методом, который при многократном повторении всего исследования захватывал бы настоящее значение примерно в 95% случаев. Широкий интервал — это честная информация: он говорит, что нужно больше данных, прежде чем делать ставку на точное число.

## Различие настоящее? Проверка гипотез

Магазин попробовал новую страницу товара. 50 случайных посетителей увидели старую страницу (**A**), а 50 — новую (**B**). Средняя корзина на B оказалась больше. B лучше — или на B просто случайно попало несколько щедрых покупателей?

Статистики отвечают своего рода доказательством от противного:

1. Предположите скучное объяснение, которое называется **нулевой гипотезой (null hypothesis)**: *страница ни на что не влияет.*
2. Спросите: **если** это так, как часто мы увидели бы различие **не меньше** нашего просто по случайности?
3. Если ответ — «почти никогда», скучное объяснение выглядит маловероятным, и мы говорим, что различие **статистически значимо (statistically significant)**.

**Перестановочный тест (permutation test)** выполняет шаг 2 симуляцией. Если страница ни на что не влияет, метки A и B ничего не значат, поэтому их можно **перемешать**: сложить все 100 корзин вместе, случайно раздать их в две группы по 50 и измерить разницу. И так 10 000 раз:

<CodeExample output={`A £29.64, B £33.89, разница £4.25
p-значение: 0.0152`}>

```python
import numpy as np

rng = np.random.default_rng(1)
a = rng.normal(30, 10, size=50).round(2)   # старая страница, корзины в £
b = rng.normal(35, 10, size=50).round(2)   # новая страница
observed = b.mean() - a.mean()
print(f"A £{a.mean():.2f}, B £{b.mean():.2f},"
      f" разница £{observed:.2f}")

pooled = np.concatenate([a, b])
n_perm = 10_000
# В каждой строке — все 100 корзин в случайном порядке
shuffled = rng.permuted(np.tile(pooled, (n_perm, 1)), axis=1)
diffs = (shuffled[:, len(a):].mean(axis=1)
         - shuffled[:, :len(a)].mean(axis=1))

p_value = np.mean(np.abs(diffs) >= abs(observed))
print(f"p-значение: {p_value:.4f}")
```

</CodeExample>

- **`np.tile(pooled, (n_perm, 1))`** повторяет объединённый массив в 10 000 строк, а **`rng.permuted(..., axis=1)`** перемешивает каждую строку отдельно. Первые 50 столбцов становятся «ненастоящей A», остальные — «ненастоящей B».
- Мы сравниваем **абсолютные** разницы (`np.abs`), потому что нам было бы интересно и то, что B намного *хуже*. Такой тест называется **двусторонним (two-sided)**, и это разумный выбор по умолчанию.
- **p-значение (p-value)** — это доля перемешиваний, которые дали разницу не меньше настоящей.

Лишь около 1,5% перемешиваний оказались такими же крайними, как настоящие £4.25. Если бы страница ни на что не влияла, такой разрыв мы видели бы редко, поэтому при p < 0,05 мы называем различие **статистически значимым**.

Вот как выглядят эти 10 000 миров «без настоящей разницы», а настоящая разница отмечена линией:

<TryIt language="python" code={`import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(1)
a = rng.normal(30, 10, size=50).round(2)
b = rng.normal(35, 10, size=50).round(2)
observed = b.mean() - a.mean()

pooled = np.concatenate([a, b])
shuffled = rng.permuted(np.tile(pooled, (10_000, 1)), axis=1)
diffs = shuffled[:, 50:].mean(axis=1) - shuffled[:, :50].mean(axis=1)

fig, ax = plt.subplots(figsize=(8, 4))
extreme = np.abs(diffs) >= abs(observed)
bins = np.linspace(diffs.min(), diffs.max(), 60)   # общие интервалы
ax.hist(diffs[~extreme], bins=bins, color="#BBBBBB",
        label="разницы после перемешивания")
ax.hist(diffs[extreme], bins=bins, color="#D55E00",
        label=f"не менее крайние: {extreme.mean():.2%}")
ax.axvline(observed, color="black", label="настоящая разница")
ax.set_xlabel("Разница средних корзин, B - A (£)")
ax.legend()
plt.show()`}
/>

(`~extreme` переворачивает маску: `True` становится `False` и наоборот.) Большинство перемешиваний дают разницу около £0 — так и должно быть, когда метки ничего не значат. А наша настоящая разница находится далеко в хвосте.

## Что такое p-значение, а что — нет

**p-значение** — это *вероятность увидеть результат, не менее крайний, чем наш, **если бы нулевая гипотеза была верна**.* Маленькое p-значение означает: «одна только случайность редко дала бы такое». По соглашению **p < 0,05** называют значимым, но 0,05 — это традиция, а не закон природы.

Это одно из самых неправильно понимаемых чисел в науке. p-значение — **не**:

- вероятность того, что нулевая гипотеза верна (p = 0,03 **не** означает «3% шанс, что страницы одинаковы»),
- вероятность того, что B лучше,
- мера того, насколько различие **большое** или **важное**.

А p > 0,05 не доказывает, что различия **нет**. Это значит лишь, что по этим данным сказать нельзя: «отсутствие доказательств — не доказательство отсутствия».

## Те же тесты в scipy.stats

Теперь вы понимаете, что делают тесты. На практике в **SciPy** (`scipy.stats`) уже есть готовые стандартные тесты, и они быстрые, потому что используют формулы вместо симуляций:

<CodeExample output={`p-значение t-теста: 0.0152
p-значение хи-квадрат: 0.0577
p-значение биномиального теста: 0.0569`}>

```python
import numpy as np
from scipy import stats

rng = np.random.default_rng(1)
a = rng.normal(30, 10, size=50).round(2)
b = rng.normal(35, 10, size=50).round(2)

# Две группы чисел: t-тест Уэлча
result = stats.ttest_ind(b, a, equal_var=False)
print(f"p-значение t-теста: {result.pvalue:.4f}")

# Купил / не купил для двух вариантов: тест хи-квадрат
#         купили  не купили
table = [[120, 880],      # A: 12.0% из 1000
         [150, 850]]      # B: 15.0% из 1000
chi2 = stats.chi2_contingency(table)
print(f"p-значение хи-квадрат: {chi2.pvalue:.4f}")

# Честная ли монета? 60 орлов из 100 бросков
binom = stats.binomtest(60, 100, 0.5)
print(f"p-значение биномиального теста: {binom.pvalue:.4f}")
```

</CodeExample>

- **`stats.ttest_ind(b, a, equal_var=False)`** сравнивает средние двух групп чисел. `equal_var=False` (версия Уэлча) не предполагает, что разброс в группах одинаков, и это более надёжный выбор по умолчанию. Его p-значение почти точно совпадает с результатом нашего перестановочного теста.
- **`stats.chi2_contingency(table)`** сравнивает **доли**: таблицу счётчиков по строке на группу. Конверсия — это как раз такие данные. Заметьте: 12% против 15% при 1000 посетителях в каждой группе — это *ещё не совсем* значимо. Чтобы заметить различие между небольшими процентами, нужно много посетителей.
- **`stats.binomtest(successes, trials, p)`** сравнивает одну долю с ожидаемым значением. 60 орлов из 100 — немного подозрительно, но недостаточно, чтобы назвать монету нечестной.

Перестановочный тест и бутстреп всё равно стоит знать: они работают для любой статистики и помогают понять, что делают формулы.

## Большие выборки, крошечные эффекты

«Значимо» означает «скорее всего, не случайность». Это **не** значит «большое» или «важное». При достаточном количестве данных значимым становится даже бессмысленное различие:

<CodeExample output={`разница 0.18, p = 5.2e-09
размер эффекта d = 0.02`}>

```python
import numpy as np
from scipy import stats

rng = np.random.default_rng(5)
a = rng.normal(50.0, 10, size=200_000)
b = rng.normal(50.2, 10, size=200_000)   # лучше на 0.2: крошечная разница

p = stats.ttest_ind(b, a, equal_var=False).pvalue
pooled_std = np.sqrt((a.var(ddof=1) + b.var(ddof=1)) / 2)
d = (b.mean() - a.mean()) / pooled_std
print(f"разница {b.mean() - a.mean():.2f}, p = {p:.1e}")
print(f"размер эффекта d = {d:.2f}")
```

</CodeExample>

p-значение микроскопическое, но разница — 0,2 при значениях около 50, которые разбросаны примерно на 10. Поэтому вместе с p-значением всегда указывайте **размер эффекта (effect size)**: саму разницу с её доверительным интервалом или стандартизированную версию вроде **d Коэна (Cohen's d)** (разница ÷ стандартное отклонение; примерно 0,2 — маленький эффект, 0,5 — средний, 0,8 — большой). Для бизнеса вопрос никогда не звучит просто как «это реально?», а как **«это реально и достаточно велико, чтобы иметь значение?»**

## Частые ошибки

Эти ошибки настолько распространены, что у них есть имена:

- **Подглядывание (peeking).** Проверять p-значение каждый день и остановить тест, как только оно впервые опустится ниже 0,05. Случайные результаты блуждают, и если смотреть достаточно часто, они пересекут 0,05 просто случайно. Определите **размер выборки до** начала теста и анализируйте один раз в конце.
- **Множественные сравнения (many comparisons).** Проверьте 20 вещей без настоящего эффекта — и в среднем одна из них окажется «значимой» при 0,05. Смотрите:

<CodeExample output={`экспериментов со «значимой» метрикой: 65%
теория: 1 - 0.95**20 = 64%`}>

```python
import numpy as np
from scipy import stats

rng = np.random.default_rng(11)
# 1000 экспериментов, в каждом сравниваются 20 метрик, настоящих эффектов НЕТ
a = rng.normal(size=(1_000, 20, 50))
b = rng.normal(size=(1_000, 20, 50))
p = stats.ttest_ind(a, b, axis=2).pvalue     # форма (1000, 20)

lucky = (p < 0.05).any(axis=1).mean()
print(f"экспериментов со «значимой» метрикой: {lucky:.0%}")
print(f"теория: 1 - 0.95**20 = {1 - 0.95 ** 20:.0%}")
```

</CodeExample>

- **p-хакинг (p-hacking).** Перебирать подгруппы, периоды или метрики, пока что-нибудь не станет значимым, а потом сообщить только об этом. Каждая лишняя попытка — ещё один лотерейный билет.

Как это исправить: заранее выберите **одну главную метрику** и размер выборки, запишите план, а если всё-таки проверяете много вещей, сделайте порог строже. Самое простое правило, **поправка Бонферрони (Bonferroni correction)**, делит 0,05 на число тестов (для 20 тестов берите 0,0025).

<Callout type="tip" title="Как профессионалы сообщают результат">

Скажите, что вы измеряли, каков эффект с его интервалом и p-значение: *«Новая страница увеличила среднюю корзину на £4.25 (95% ДИ: от £0.84 до £7.66, p = 0,015, по 50 посетителей на страницу)»*. Затем одно предложение о том, достаточно ли это много, чтобы иметь значение. Никогда не ограничивайтесь фразой «это было значимо».

```python
import numpy as np

def standard_error(values):
    values = np.asarray(values)
    return values.std(ddof=1) / np.sqrt(len(values))

def bootstrap_ci(values, stat=np.mean, n_boot=5_000,
                 level=0.95, seed=0):
    values = np.asarray(values)
    rng = np.random.default_rng(seed)
    resamples = rng.choice(values, size=(n_boot, len(values)))
    results = stat(resamples, axis=1)
    tail = (1 - level) / 2 * 100
    low, high = np.percentile(results, [tail, 100 - tail])
    return float(low), float(high)

def permutation_p_value(a, b, n_perm=5_000, seed=0):
    a, b = np.asarray(a), np.asarray(b)
    rng = np.random.default_rng(seed)
    observed = b.mean() - a.mean()
    pooled = np.concatenate([a, b])
    shuffled = rng.permuted(np.tile(pooled, (n_perm, 1)), axis=1)
    diffs = (shuffled[:, len(a):].mean(axis=1)
             - shuffled[:, :len(a)].mean(axis=1))
    return float(np.mean(np.abs(diffs) >= abs(observed)))

baskets = [31.5, 22.0, 48.2, 27.9, 35.1, 19.4, 41.0, 29.8,
           25.5, 38.7, 33.3, 24.6, 52.0, 28.4, 30.9, 36.2]
old = [30.1, 27.5, 33.8, 25.0, 29.4, 31.7, 26.8, 28.9]
new = [34.2, 36.9, 31.0, 38.4, 33.5, 35.8, 32.7, 37.1]

print(bootstrap_ci(baskets))
print(bootstrap_ci(baskets, stat=np.median, level=0.9))
```

## Итоги

- Обычно вы видите **выборку**, а не **генеральную совокупность**; оценки «гуляют» от выборки к выборке. Случайность можно измерить, **смещение** — нельзя.
- **`np.random.default_rng(seed)`** даёт повторяемые случайные числа: `integers`, `normal`, `choice` (по умолчанию с возвращением), `permuted`.
- **Закон больших чисел**: большие выборки ближе к истине. Маленькие выборки шумные.
- **Стандартная ошибка** = std / √n показывает, насколько «гуляет» выборочное среднее; в 4 раза больше данных уменьшают её вдвое.
- **Бутстреп**: тысячи раз берите повторные выборки из своих данных с возвращением; средние 95% результатов — это **95-процентный доверительный интервал** для любой статистики.
- **Проверка гипотез**: предположите, что разницы нет (**нулевая гипотеза**), и спросите, как часто одна случайность даёт такой крайний результат. **Перестановочный тест** отвечает на это, перемешивая метки.
- **p-значение** — это не вероятность того, что нулевая гипотеза верна, и не размер эффекта. Указывайте также **размер эффекта** и его интервал.
- `scipy.stats`: `ttest_ind(..., equal_var=False)` для средних, `chi2_contingency` для долей, `binomtest` для одной доли.
- Избегайте **подглядывания**, **множественных сравнений** и **p-хакинга**: заранее зафиксируйте метрику и размер выборки.
