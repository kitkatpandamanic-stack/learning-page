У Panda Shop есть вопрос, от которого зависят деньги. 🐼🛒 На странице оформления заказа стоит серая кнопка **«Продолжить»**. Дизайнер считает, что яркая кнопка **«Купить сейчас»** заставит больше посетителей завершить заказ. Вместо того чтобы спорить, команда провела **A/B-тест (A/B test)**: каждому посетителю случайным образом показывали либо старую кнопку (**A**), либо новую (**B**), а магазин записывал, кто что-нибудь купил.

Ваша задача — проанализировать эксперимент и написать отчёт, по которому решат, что делать дальше. Вам пригодится всё из этого модуля: описание данных, доверительные интервалы, перестановочный тест и понятный график.

Поскольку посетителей распределяли **случайно**, две группы похожи во всём, кроме кнопки: та же доля новых и постоянных покупателей, те же дни недели, та же погода. Поэтому если B конвертирует лучше и это не случайность, то это **вызвала** кнопка. Вот почему эксперименты сильнее корреляций из урока [Описываем данные](/learn/python/describing-data).

## Сначала план, потом данные

Помните подглядывание и p-хакинг из урока [Выборки и неопределённость](/learn/python/samples-and-uncertainty)? Лекарство — записать план **до того**, как придут данные:

1. **Метрика:** **конверсия (conversion rate)** — доля посетителей, которые что-то купили.
2. **Тест:** двусторонний перестановочный тест с **α = 0,05** (порог значимости, «альфа»).
3. **Правило решения:** выпускаем B, только если разница значима **и** весь доверительный интервал выше нуля; оставляем A, если разница значима и весь интервал ниже нуля; иначе — доказательств недостаточно.
4. **Размер выборки:** столько посетителей, чтобы были хорошие шансы заметить самое маленькое изменение, которое стоит внедрять.

Для шага 4 профессионалы проводят **анализ мощности (power analysis)**. Вопрос звучит так: *«если B действительно поднимает конверсию с 10% до 13%, сколько посетителей нужно в каждой группе, чтобы заметить это в 80% случаев?»* На него отвечает пакет `statsmodels`:

<CodeExample output={`мощность 80%: 1,768 посетителей на группу
мощность 90%: 2,367 посетителей на группу
чтобы заметить 10% -> 11%: 14,744 на группу`}>

```python
from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize

effect = proportion_effectsize(0.13, 0.10)   # 10% -> 13%
for power in [0.8, 0.9]:
    n = NormalIndPower().solve_power(effect_size=effect,
                                     alpha=0.05, power=power)
    print(f"мощность {power:.0%}: {n:,.0f} посетителей на группу")

small = proportion_effectsize(0.11, 0.10)    # 10% -> 11%
n = NormalIndPower().solve_power(effect_size=small,
                                 alpha=0.05, power=0.8)
print(f"чтобы заметить 10% -> 11%: {n:,.0f} на группу")
```

</CodeExample>

Около 1800 посетителей на группу, поэтому магазин планирует **4000 посетителей** всего. Посмотрите, как быстро растёт это число для эффектов поменьше: чтобы заметить прирост на 1 пункт, нужно примерно в восемь раз больше трафика. Маленькие магазины могут заметить только большие изменения, и это стоит знать до начала теста.

## Данные

В настоящем магазине данные пришли бы из логов сайта или базы данных (`pd.read_sql`, `pd.read_csv`). Здесь мы их **генерируем** генератором с seed, и в этом есть бонус: мы знаем правду (10% для A и 13% для B), так что можем проверить, находят ли её наши методы. Каждая строка — один посетитель:

<CodeExample output={`   visitor variant  converted  order_value
0        1       A      False          0.0
1        2       B      False          0.0
2        3       B      False          0.0
3        4       A      False          0.0
4        5       A      False          0.0
variant
A    2006
B    1994
Name: count, dtype: int64
0`}>

```python
import numpy as np
import pandas as pd

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

visitors = make_visitors()
print(visitors.head())
print(visitors["variant"].value_counts())
print(visitors.isna().sum().sum())
```

</CodeExample>

- **`np.where(condition, x, y)`** берёт `x` там, где условие `True`, и `y` в остальных местах, значение за значением. Так каждый посетитель получает конверсию своего варианта, а сумма заказа достаётся только тем, кто купил.
- `rng.random(n) < rate` равно `True` с вероятностью `rate`: быстрый способ подбросить для каждого посетителя «нечестную» монету.
- Группы не ровно по 2000, потому что вариант для каждого посетителя выбирался случайно. Это нормально.

## Шаг 1: конверсия

Среднее столбца из `True`/`False` — это доля `True`, поэтому конверсия считается одним `groupby`:

<CodeExample output={`         visitors  buyers    rate
variant                          
A            2006     204  0.1017
B            1994     273  0.1369
разница в процентных пунктах: +3.52
относительный прирост: +34.6%`}>

```python
import numpy as np
import pandas as pd

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

visitors = make_visitors()
summary = visitors.groupby("variant").agg(
    visitors=("converted", "size"),
    buyers=("converted", "sum"),
    rate=("converted", "mean"),
)
print(summary.round(4))

rates = summary["rate"]
diff = rates["B"] - rates["A"]
print(f"разница в процентных пунктах: {diff * 100:+.2f}")
print(f"относительный прирост: {diff / rates['A']:+.1%}")
```

</CodeExample>

Здесь осторожнее со словами. Рост с 10% до 13% — это **+3 процентных пункта**, но **+30% относительного прироста (relative lift)**. Оба утверждения верны, но звучат очень по-разному, поэтому всегда уточняйте, что вы имеете в виду. Отчёты, которые хотят впечатлить, обычно берут относительное число.

## Шаг 2: насколько мы уверены?

B выглядит лучше. Бутстреп из прошлого урока покажет, насколько эта разница может «гулять»: берём повторные выборки каждой группы **с возвращением**, считаем разницу конверсий и повторяем.

<CodeExample output={`95% ДИ: от +1.47 до +5.52 п.п.
быстрый способ: от +1.42 до +5.47 п.п.`}>

```python
import numpy as np
import pandas as pd

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

visitors = make_visitors()
a = visitors.loc[visitors["variant"] == "A", "converted"].to_numpy()
b = visitors.loc[visitors["variant"] == "B", "converted"].to_numpy()

rng = np.random.default_rng(0)
n_boot = 2_000
boot_a = rng.choice(a, size=(n_boot, len(a))).mean(axis=1)
boot_b = rng.choice(b, size=(n_boot, len(b))).mean(axis=1)
low, high = np.percentile(boot_b - boot_a, [2.5, 97.5])
print(f"95% ДИ: от {low * 100:+.2f} до {high * 100:+.2f} п.п.")

# Быстрый способ для данных «да/нет»:
# считаем покупателей в каждой повторной выборке
boot_a = rng.binomial(len(a), a.mean(), size=n_boot) / len(a)
boot_b = rng.binomial(len(b), b.mean(), size=n_boot) / len(b)
low, high = np.percentile(boot_b - boot_a, [2.5, 97.5])
print(f"быстрый способ: от {low * 100:+.2f} до {high * 100:+.2f} п.п.")
```

</CodeExample>

Весь интервал выше нуля: B лучше где-то на 1,5–5,5 процентного пункта (п.п.).

Вторая половина кода — полезный быстрый способ. Когда значения только «да/нет», повторная выборка из n посетителей полностью описывается тем, **сколько** из них купили, а **`rng.binomial(n, rate)`** выдаёт ровно это число — как будто подбрасывает n монет, каждая из которых выпадает «да» с вероятностью `rate`. Результат тот же, но без таблицы 2000 × 2000, поэтому в сотни раз быстрее. Два интервала отличаются только случайным шумом.

## Шаг 3: может, это случайность?

Теперь перестановочный тест из плана: если кнопка ни на что не влияет, метки A и B ничего не значат, поэтому перемешаем их и посмотрим, как часто появляется такая же большая разница. Затем перепроверим классическим тестом для долей, `chi2_contingency`:

<CodeExample output={`p-значение перестановочного теста: 0.0000
p-значение хи-квадрат: 0.0006`}>

```python
import numpy as np
import pandas as pd
from scipy import stats

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

visitors = make_visitors()
a = visitors.loc[visitors["variant"] == "A", "converted"].to_numpy()
b = visitors.loc[visitors["variant"] == "B", "converted"].to_numpy()
observed = b.mean() - a.mean()

rng = np.random.default_rng(0)
n_perm = 2_000
pooled = np.concatenate([a, b])
shuffled = rng.permuted(np.tile(pooled, (n_perm, 1)), axis=1)
diffs = (shuffled[:, len(a):].mean(axis=1)
         - shuffled[:, :len(a)].mean(axis=1))
p_value = np.mean(np.abs(diffs) >= abs(observed))
print(f"p-значение перестановочного теста: {p_value:.4f}")

table = [[a.sum(), len(a) - a.sum()],
         [b.sum(), len(b) - b.sum()]]
chi2 = stats.chi2_contingency(table, correction=False)
print(f"p-значение хи-квадрат: {chi2.pvalue:.4f}")
```

</CodeExample>

**Ни одно** из 2000 перемешиваний не дало такого большого разрыва, как настоящий, поэтому p-значение меньше 1 из 2000 (на самом деле оно никогда не равно нулю — просто мы перемешивали недостаточно раз, чтобы это увидеть). Тест хи-квадрат согласен: p ≈ 0,0006. Если бы кнопка ни на что не влияла, такой разрыв почти никогда не возник бы случайно, так что мы намного ниже нашего α = 0,05.

<Callout type="tip" title="Быстрый способ перемешивать данные «да/нет»">

Перемешивание меток раздаёт `len(a)` посетителей из общей кучи в «ненастоящую A». Для данных «да/нет» важно только, **сколько покупателей** попадёт в ненастоящую A, и **`rng.hypergeometric(buyers, non_buyers, len(a), size=n_perm)`** выдаёт ровно это число — как будто раздаёт карты, не возвращая их в колоду. По этому числу можно получить обе ненастоящие конверсии, ничего не перемешивая:

```python
k = rng.hypergeometric(int(pooled.sum()),
                       int(len(pooled) - pooled.sum()),
                       len(a), size=n_perm)
diffs = (pooled.sum() - k) / len(b) - k / len(a)
```

Он даёт то же p-значение (с точностью до случайного шума) за малую долю времени, так что можно позволить себе 100 000 перемешиваний.

</Callout>

## Шаг 4: решение

Правило зафиксировано в плане, поэтому решение — это просто код. У записи правила в виде кода есть ещё одно преимущество: никто не сможет тихо подогнать его, увидев результаты. Функция возвращает строки на английском: `"ship B"` («выпускаем B»), `"keep A"` («оставляем A») и `"not enough evidence"` («доказательств недостаточно»).

<CodeExample output={`ship B
keep A
not enough evidence`}>

```python
def decide(p_value, low, high, alpha=0.05):
    if p_value < alpha and low > 0:
        return "ship B"
    if p_value < alpha and high < 0:
        return "keep A"
    return "not enough evidence"

print(decide(0.0000, 0.0147, 0.0552))  # наш тест
print(decide(0.0021, -0.050, -0.012))  # B оказался хуже
print(decide(0.2600, -0.034, 0.010))   # может быть случайностью
```

</CodeExample>

«Доказательств недостаточно» — это настоящий и полезный ответ. Он не значит, что кнопки одинаковы; он значит, что этот эксперимент не может их различить. Команда может оставить A (безопасный вариант по умолчанию) или запланировать тест побольше, если изменение дешёвое и многообещающее.

В реальной компании в правиле часто есть ещё одно условие: прирост должен быть **достаточно большим, чтобы иметь значение** (скажем, не меньше +1 пункта), потому что у изменений есть цена. Это бизнес-решение, поэтому, как и всё остальное в плане, его согласуют с командой до теста.

## Шаг 6: проверяем защитные метрики

Изменение может выиграть по главной метрике и незаметно навредить чему-то ещё. Может быть, с кнопкой «Купить сейчас» люди покупают, но **более дешёвые** вещи? Профессионалы следят за несколькими **защитными метриками (guardrail metrics)**, которые не должны ухудшаться. Здесь это средняя сумма заказа у покупателей и выручка на посетителя.

<CodeExample output={`          mean  median
variant               
A        33.88   29.89
B        33.57   30.22
variant
A    3.44
B    4.60
Name: выручка на посетителя, dtype: float64
p-значение для суммы заказа: 0.85`}>

```python
import numpy as np
import pandas as pd
from scipy import stats

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

visitors = make_visitors()
buyers = visitors[visitors["converted"]]

print(buyers.groupby("variant")["order_value"]
      .agg(["mean", "median"]).round(2))
print(visitors.groupby("variant")["order_value"].mean()
      .round(2).rename("выручка на посетителя"))

values_a = buyers.loc[buyers["variant"] == "A", "order_value"]
values_b = buyers.loc[buyers["variant"] == "B", "order_value"]
p = stats.ttest_ind(values_b, values_a, equal_var=False).pvalue
print(f"p-значение для суммы заказа: {p:.2f}")
```

</CodeExample>

С любой кнопкой покупатели тратят примерно одинаково (разница вполне укладывается в случайность), а поскольку покупают чаще, **выручка на посетителя** с B выше. Ни одна защитная метрика не нарушена.

## Шаг 7: пишем отчёт

Результаты полезны, только если люди их понимают. Хороший отчёт об эксперименте умещается на одном экране: что тестировали, результат с его неопределённостью, решение и оговорки. Если собирать отчёт из вычисленных чисел, он никогда не разойдётся с анализом:

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

def split(df):
    a = df.loc[df["variant"] == "A", "converted"].to_numpy()
    b = df.loc[df["variant"] == "B", "converted"].to_numpy()
    return a, b

def conversion_rates(df):
    a, b = split(df)
    return {"A": float(a.mean()), "B": float(b.mean())}

def bootstrap_diff_ci(df, level=0.95, n_boot=2_000, seed=0):
    a, b = split(df)
    rng = np.random.default_rng(seed)
    boot_a = rng.binomial(len(a), a.mean(), size=n_boot) / len(a)
    boot_b = rng.binomial(len(b), b.mean(), size=n_boot) / len(b)
    tail = (1 - level) / 2 * 100
    low, high = np.percentile(boot_b - boot_a, [tail, 100 - tail])
    return float(low), float(high)

def permutation_p_value(df, n_perm=2_000, seed=0):
    a, b = split(df)
    rng = np.random.default_rng(seed)
    observed = b.mean() - a.mean()
    buyers = int(a.sum() + b.sum())
    others = len(a) + len(b) - buyers
    k = rng.hypergeometric(buyers, others, len(a), size=n_perm)
    diffs = (buyers - k) / len(b) - k / len(a)
    return float(np.mean(np.abs(diffs) >= abs(observed)))

def decide(df, alpha=0.05):
    p = permutation_p_value(df)
    low, high = bootstrap_diff_ci(df, level=1 - alpha)
    if p < alpha and low > 0:
        return "ship B"
    if p < alpha and high < 0:
        return "keep A"
    return "not enough evidence"

def plot_rates(df):
    rates = conversion_rates(df)
    fig, ax = plt.subplots(figsize=(5, 4))
    bars = ax.bar(["A", "B"], [rates["A"] * 100, rates["B"] * 100],
                  color=["#999999", "#0072B2"])
    ax.bar_label(bars, fmt="%.1f%%")
    ax.set_title("Конверсия по вариантам")
    ax.set_ylabel("Конверсия (%)")
    return fig

visitors = make_visitors()
print(conversion_rates(visitors))
print(bootstrap_diff_ci(visitors))
print(permutation_p_value(visitors))
print(decide(visitors))
fig = plot_rates(visitors)
plt.show()
```
