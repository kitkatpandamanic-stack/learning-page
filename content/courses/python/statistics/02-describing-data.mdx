A chart shows the whole picture; a few well-chosen numbers let you say it in one sentence: *"A typical delivery takes 2 days, and 9 in 10 arrive within 4."* Those numbers are **descriptive statistics**, and they're the first thing any analyst computes about new data.

In this lesson you'll learn which numbers to pick, when each one **misleads**, and how to compute them with three tools you'll see everywhere: Python's built-in **`statistics`** module for small lists, **NumPy** for arrays of numbers, and **pandas** for tables. 🔎

## The middle: mean, median and mode

There are three common ways to say what a "typical" value is:

- The **mean** (average): add everything up and divide by how many there are.
- The **median**: sort the values and take the middle one (or the average of the middle two).
- The **mode**: the most common value. It's the only one that works for categories like T-shirt sizes.

Watch what happens to a team's salaries when the founder joins the list:

<CodeExample output={`35.875
35.5
137.4
36
M
[1, 2]`}>

```python
import statistics

salaries = [28, 31, 33, 35, 36, 38, 41, 45]   # £1000s a year
print(statistics.mean(salaries))
print(statistics.median(salaries))

salaries.append(950)       # the founder joins the table
print(round(statistics.mean(salaries), 1))
print(statistics.median(salaries))

sizes = ["M", "L", "M", "S", "M", "L"]
print(statistics.mode(sizes))
print(statistics.multimode([1, 1, 2, 2, 3]))
```

</CodeExample>

One very high salary pulled the mean from about 36 to 137: eight of the nine people earn far less than the "average salary". The median barely moved. That's why news reports use the **median income**, and why house prices are quoted as medians.

- Use the **mean** when values are roughly symmetric with no extreme values, or when the total matters (average order value × orders = revenue).
- Use the **median** for skewed data like incomes, prices, waiting times and page load times.
- `statistics.mode` returns one most common value; **`multimode`** returns all of them when there's a tie.

## Spread: how different are the values?

Two cafés both have an average wait of 5 minutes. Would you rather queue at A or B?

<CodeExample output={`A: mean 5, range 2, std 0.76
B: mean 5, range 9, std 3.55`}>

```python
import statistics

cafe_a = [4, 5, 5, 6, 5, 4, 6, 5]     # minutes
cafe_b = [1, 9, 2, 8, 5, 10, 3, 2]

for name, waits in [("A", cafe_a), ("B", cafe_b)]:
    mean = statistics.mean(waits)
    spread = max(waits) - min(waits)
    std = statistics.stdev(waits)
    print(f"{name}: mean {mean}, range {spread}, std {std:.2f}")
```

</CodeExample>

Same mean, very different experience. You need a number for **spread** too:

- The **range** is `max - min`. Simple, but one extreme value changes it completely.
- The **variance** is the average of the **squared distances** from the mean. Squaring makes every distance positive and punishes big ones more.
- The **standard deviation** (std) is the square root of the variance, which brings it back to the original units (minutes, not minutes²). Roughly: *how far a typical value is from the mean.*

Here's the variance by hand, so the formula isn't magic:

<CodeExample output={`deviations: [-4, 4, -3, 3, 0, 5, -2, -3]
squared:    [16, 16, 9, 9, 0, 25, 4, 9]
variance:   12.57
std:        3.55`}>

```python
import math

waits = [1, 9, 2, 8, 5, 10, 3, 2]
mean = sum(waits) / len(waits)                # 5.0

deviations = [round(w - mean) for w in waits]
squared = [d ** 2 for d in deviations]
variance = sum(squared) / (len(waits) - 1)    # n - 1, see below
print("deviations:", deviations)
print("squared:   ", squared)
print(f"variance:   {variance:.2f}")
print(f"std:        {math.sqrt(variance):.2f}")
```

</CodeExample>

Why divide by `n - 1` instead of `n`? When your data is a **sample** from something bigger (8 waits out of every wait at café B), the sample's own mean sits a little *too* close to its values, so dividing by `n` underestimates the true spread. Dividing by `n - 1` corrects that. With lots of data, the difference is tiny.

## Spread in NumPy and pandas

**NumPy** is the number library underneath pandas. Its main type, the **array**, is like a list of numbers where maths applies to every value at once, just like a pandas column. You'll take a full tour in [NumPy Arrays](/learn/python/numpy-arrays); for statistics you only need a few methods:

<CodeExample output={`3.32 3.55
3.32 3.55
3.55
[-4.  4. -3.]`}>

```python
import statistics
import numpy as np
import pandas as pd

waits = [1, 9, 2, 8, 5, 10, 3, 2]
print(round(statistics.pstdev(waits), 2),
      round(statistics.stdev(waits), 2))

arr = np.array(waits)
print(round(arr.std(), 2), round(arr.std(ddof=1), 2))

print(round(pd.Series(waits).std(), 2))

print(arr[:3] - arr.mean())     # maths on every value
```

</CodeExample>

<Callout type="warning" title="Three libraries, two standard deviations">

`statistics.stdev` and pandas' `.std()` divide by `n - 1` (the **sample** standard deviation). NumPy's `.std()` divides by `n` unless you pass **`ddof=1`**, and `statistics.pstdev` divides by `n` too (the "p" is for *population*). Same data, different answers: if your numbers don't match a colleague's, check this first.

</Callout>

## Percentiles and the IQR

The **p-th percentile** is the value that p% of the data is below. You already know one: the median is the 50th percentile. The 25th and 75th percentiles are called the **quartiles** (Q1 and Q3), and the distance between them is the **interquartile range (IQR)**: the spread of the middle half of the data. Unlike the range, extreme values don't affect it.

<CodeExample output={`Q1 1.6, median 2.15, Q3 3.25
IQR 1.65
90th percentile 3.97
count    12.000000
mean      2.591667
std       1.569284
min       0.800000
10%       1.240000
50%       2.150000
90%       3.970000
max       6.500000
dtype: float64`}>

```python
import numpy as np
import pandas as pd

days = np.array([1.2, 2.0, 1.6, 3.1, 2.3, 0.8, 6.5,
                 1.7, 2.6, 4.0, 1.6, 3.7])   # delivery days

q1, median, q3 = np.percentile(days, [25, 50, 75])
print(f"Q1 {q1:.1f}, median {median:.2f}, Q3 {q3:.2f}")
print(f"IQR {q3 - q1:.2f}")
print(f"90th percentile {np.percentile(days, 90):.2f}")

print(pd.Series(days).describe(percentiles=[0.1, 0.5, 0.9]))
```

</CodeExample>

So: a typical delivery takes about 2 days, the middle half take between 1.6 and 3.25 days, and 90% arrive within 4 days. That last kind of number is how pros describe things like website speed: *"p95 latency is 300 ms"* means 95% of requests are faster than 300 ms. Averages hide the slow requests that annoy users; high percentiles show them.

In pandas, `series.quantile(0.9)` gives one percentile (as a fraction), and `describe()`, which you met in [Series and DataFrames](/learn/python/dataframes), shows the quartiles by default.

## The shape of a distribution

The **distribution** of a column is how its values are spread out, and a histogram shows it. Three shapes come up again and again:

- **Symmetric**: most values in the middle, tailing off equally on both sides (like heights). Mean ≈ median.
- **Right-skewed**: most values are small, with a long tail of big ones (incomes, order values, waiting times). The tail drags the **mean above the median**.
- **Bimodal**: two peaks, which usually means two different groups mixed together (lunch and dinner orders, two kinds of customers). Neither the mean nor the median describes anyone well.

Run it, then try changing the numbers that make each shape:

## Outliers

An **outlier** is a value far away from the rest. It might be a typo (a delivery that took 95 days), a special case (a wholesale order), or the most interesting point in the data. Find them first, *then* decide what to do. Two common rules:

1. **The IQR rule** (it's what box plots use): anything below `Q1 - 1.5 × IQR` or above `Q3 + 1.5 × IQR` is an outlier.
2. **z-scores**: how many standard deviations a value is from the mean, `z = (x - mean) / std`. Values with `|z| > 3` (or 2 for small data) are suspicious.

NumPy filters arrays with **masks**, exactly like pandas filters rows: a comparison gives an array of `True`/`False`, and `arr[mask]` keeps the `True` ones.

<CodeExample output={`fences: 20.0 to 30.0
IQR rule: [95]
z-scores: [-0.4 -0.3 -0.3 -0.2 -0.4 -0.2 -0.3 -0.3  3.3 -0.1 -0.5 -0.2]
z rule: [95]
with a second outlier: [95 90] vs z rule: []`}>

```python
import numpy as np

def iqr_outliers(values):
    q1, q3 = np.percentile(values, [25, 75])
    iqr = q3 - q1
    low, high = q1 - 1.5 * iqr, q3 + 1.5 * iqr
    return values[(values < low) | (values > high)]

times = np.array([22, 25, 24, 27, 23, 26, 25, 24, 95, 28, 21, 26])
q1, q3 = np.percentile(times, [25, 75])
iqr = q3 - q1
print("fences:", q1 - 1.5 * iqr, "to", q3 + 1.5 * iqr)
print("IQR rule:", iqr_outliers(times))

z = (times - times.mean()) / times.std()
print("z-scores:", z.round(1))
print("z rule:", times[np.abs(z) > 3])

more = np.append(times, 90)
z_more = (more - more.mean()) / more.std()
print("with a second outlier:", iqr_outliers(more),
      "vs z rule:", more[np.abs(z_more) > 3])
```

</CodeExample>

Look at the last line: with **two** outliers, the z rule finds **none**. The outliers inflate the mean and the standard deviation they're measured against, so they hide each other. The IQR rule uses quartiles, which outliers can't move much, so it's the safer default.

<Callout type="tip" title="Don't just delete outliers">

Removing every outlier is a classic way to fool yourself. Look at each one: fix typos, remove impossible values (a negative age), but keep real extreme values and report them. If they matter, show results **with and without** them, or use statistics that aren't swayed by them, like the median and the IQR.

</Callout>

## Correlation

Do two measurements move together? A scatter plot shows it, and the **correlation coefficient** (Pearson's **r**) puts a number on it, from -1 to 1:

- **r near 1**: when one goes up, the other goes up, in a nearly straight line.
- **r near 0**: no straight-line relationship.
- **r near -1**: when one goes up, the other goes down.

The idea behind the formula: for each point, multiply "how far x is above its mean" by "how far y is above its mean". If big x values usually come with big y values, those products are mostly positive. r is the average product, scaled so that it always lands between -1 and 1.

<TryIt language="python" code={`import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(3)
x = rng.uniform(0, 10, 80)
pairs = {
    "strong positive": 2 * x + rng.normal(0, 2, 80),
    "none": rng.normal(10, 5, 80),
    "negative": 20 - 1.5 * x + rng.normal(0, 4, 80),
    "curved (r misses it!)": (x - 5) ** 2 + rng.normal(0, 1, 80),
}

fig, axes = plt.subplots(1, 4, figsize=(13, 3.2))
for ax, (name, y) in zip(axes, pairs.items()):
    r = np.corrcoef(x, y)[0, 1]
    ax.scatter(x, y, s=12, color="#0072B2")
    ax.set_title(f"{name}\\nr = {r:.2f}", fontsize=10)

fig.tight_layout()
plt.show()`}
/>

The last chart is a strong relationship, yet r is close to 0, because Pearson's r only measures **straight-line** relationships. Always look at the scatter plot. For relationships that go one way but not in a straight line, use **Spearman's** correlation: `df.corr(method="spearman")`.

In code, `np.corrcoef(x, y)` returns a 2 × 2 table (x with x, x with y...), so `[0, 1]` picks the number you want. pandas' **`df.corr()`** gives every pair of columns at once:

<CodeExample output={`0.96

visitors      0.96      1.00    -0.07

## Correlation is not causation

Ice cream sales and sunburns are strongly correlated. Does ice cream cause sunburn? Of course not: **hot, sunny weather** causes both. A hidden variable that drives both things is called a **confounder**:

<CodeExample output={`           temp  ice_cream  sunburn
temp       1.00       0.96     0.92
ice_cream  0.96       1.00     0.86
sunburn    0.92       0.86     1.00
similar days: 0.05`}>

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
temp = rng.uniform(5, 32, 200)                    # °C, 200 days
days = pd.DataFrame({
    "temp": temp,
    "ice_cream": 20 + 6 * temp + rng.normal(0, 15, 200),
    "sunburn": 0.8 * temp + rng.normal(0, 3, 200),
})
print(days.corr().round(2))

# Compare only days with about the same temperature
similar = days[days["temp"].between(24, 28)]
r = similar["ice_cream"].corr(similar["sunburn"])
print("similar days:", round(r, 2))
```

</CodeExample>

Across all days, ice cream and sunburn have r = 0.86. But compare only days with **similar temperatures**, and the link almost disappears: ice cream never did anything to anyone's skin. Holding the confounder (roughly) fixed is one way to check a suspicious correlation. The most reliable way to show cause and effect is an **experiment**, where you change one thing on purpose and randomly decide who gets it, which is exactly what an A/B test does at the end of this module.

## Always plot your data

```python
import numpy as np
import pandas as pd

days = [1.2, 2.0, 1.6, 3.1, 2.3, 0.8, 9.5, 1.7, 2.6, 4.0, 1.6, 3.7]

def summary(values):
    q1, q3 = np.percentile(values, [25, 75])
    stats = {
        "mean": np.mean(values),
        "median": np.median(values),
        "std": np.std(values, ddof=1),
        "q1": q1,
        "q3": q3,
        "iqr": q3 - q1,
    }
    return {name: round(float(v), 2) for name, v in stats.items()}

def outliers(values):
    q1, q3 = np.percentile(values, [25, 75])
    iqr = q3 - q1
    low, high = q1 - 1.5 * iqr, q3 + 1.5 * iqr
    return [v for v in values if v < low or v > high]

def strongest_link(df, target):
    r = df.corr()[target].drop(target)
    return r.abs().idxmax()
```

## Recap

- **Mean** for symmetric data and totals, **median** for skewed data (incomes, prices, waiting times), **mode** for categories.
- **Spread**: range, variance (average squared distance from the mean) and **standard deviation** (its square root, in the original units).
- Sample std divides by `n - 1`: `statistics.stdev` and pandas do, NumPy needs **`ddof=1`**.
- **Percentiles** (`np.percentile`, `quantile`) say "p% of values are below this"; the **IQR** is the spread of the middle half and ignores extremes.
- Read the **shape**: symmetric, right-skewed (mean > median) or bimodal (two groups mixed).
- Find **outliers** with the IQR rule (safer) or z-scores; investigate them before removing anything.
- **Correlation** (`np.corrcoef`, `df.corr()`) measures straight-line relationships from -1 to 1. It is not causation: look for confounders.
- Summary numbers can hide everything interesting: **always plot your data**.
