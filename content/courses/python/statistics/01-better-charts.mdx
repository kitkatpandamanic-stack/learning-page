In [Cleaning and Grouping Data](/learn/python/cleaning-and-grouping) you drew your first charts with `series.plot()` and `plt.title(...)`. That's perfect for a quick look. But charts that go into a report, a slide or a dashboard need more: several charts side by side, labels that explain themselves, colours everyone can read, and a file you can attach.

In this module you'll learn to **describe data** with statistics, measure how **sure** you can be about a result, and finish with a real **A/B test report**. Charts are how you'll show all of it, so we start by drawing them like a pro. 📊

## Figure and Axes

matplotlib has two ways of drawing. The `plt.title()` style you know talks to "the current chart", wherever that is. The **object-oriented** style, which pros use, gives you the chart objects directly:

- A **Figure** is the whole image: the canvas that gets shown or saved.
- An **Axes** is one chart inside the figure, with its own x and y axis, title and data. (Yes, "Axes" with an e, even for one chart. It's not the same as an *axis*.)

**`fig, ax = plt.subplots()`** creates a figure with one Axes, and then you call methods on `ax`. Press **Run**, then try `marker="s"` or `linestyle="--"`:

<TryIt language="python" code={`import matplotlib.pyplot as plt

months = ["Jan", "Feb", "Mar", "Apr", "May", "Jun"]
visitors = [1200, 1350, 1280, 1600, 1750, 1900]

fig, ax = plt.subplots(figsize=(7, 4))   # width, height in inches
ax.plot(months, visitors, marker="o")
ax.set_title("Visitors per month")
ax.set_xlabel("Month")
ax.set_ylabel("Visitors")
plt.show()`}
/>

Most `plt.something()` functions have an `ax.set_something()` twin: `plt.title` becomes `ax.set_title`, `plt.xlabel` becomes `ax.set_xlabel`, `plt.ylim` becomes `ax.set_ylim`. The drawing functions keep their names: `ax.plot`, `ax.bar`, `ax.scatter`...

Why bother? Because with `ax` you always know **which** chart you're changing, which matters as soon as a figure holds more than one. And a function can build a figure and **return** it, so other code (and tests!) can look inside:

<CodeExample output={`1
Visitors per month
Visitors
[1200, 1350, 1280]`}>

```python
import matplotlib.pyplot as plt

def visitors_chart(months, visitors):
    fig, ax = plt.subplots()
    ax.plot(months, visitors, marker="o")
    ax.set_title("Visitors per month")
    ax.set_ylabel("Visitors")
    return fig

fig = visitors_chart(["Jan", "Feb", "Mar"], [1200, 1350, 1280])
ax = fig.axes[0]
print(len(fig.axes))
print(ax.get_title())
print(ax.get_ylabel())
print(ax.lines[0].get_ydata().tolist())
plt.close(fig)   # done with it: free the memory
```

</CodeExample>

`fig.axes` is the list of charts in the figure, `ax.lines` the lines drawn on a chart, and every `set_...` has a `get_...`. Checking the **data** of a chart like this is how real projects test their plotting code, because comparing pixels is fragile.

## Several charts in one figure

`plt.subplots(rows, cols)` makes a **grid** of charts and returns them as an array of Axes. With one row, `axes[0]` and `axes[1]` are the charts; with several rows, use `axes[row, col]`.

Charts that share the same x values (like months) should line up, so pass **`sharex=True`**: the charts share one x axis, and zooming one zooms all. Try changing the grid to `plt.subplots(1, 2)` and removing `sharex`:

<TryIt language="python" code={`import matplotlib.pyplot as plt

months = ["Jan", "Feb", "Mar", "Apr", "May", "Jun"]
visitors = [1200, 1350, 1280, 1600, 1750, 1900]
orders = [96, 101, 90, 136, 140, 171]

fig, axes = plt.subplots(2, 1, figsize=(7, 5), sharex=True)

axes[0].plot(months, visitors, marker="o")
axes[0].set_title("Visitors")

axes[1].bar(months, orders, color="#0072B2")
axes[1].set_title("Orders")
axes[1].set_xlabel("Month")

fig.suptitle("Panda Shop, first half of 2026")
fig.tight_layout()     # stop titles and labels overlapping
plt.show()`}
/>

- **`fig.suptitle()`** gives the whole figure a title; each Axes keeps its own.
- **`fig.tight_layout()`** nudges the charts apart so labels don't overlap. Call it just before showing or saving.
- **`figsize=(width, height)`** is in inches. Wider figures suit side-by-side grids.

## Choosing the right chart

The best chart depends on the **question** you're answering. Five chart types cover most of them:

| Question | Chart | matplotlib |
| --- | --- | --- |
| How does it change over time? | line | `ax.plot(x, y)` |
| How do groups compare? | bar | `ax.bar(names, values)` or `ax.barh` |
| How are the values spread out? | histogram | `ax.hist(values, bins=...)` |
| Do two measurements move together? | scatter | `ax.scatter(x, y)` |
| How do the spreads of groups compare? | box plot | `ax.boxplot([group1, group2])` |

Here are the other four on one figure. The data is made up with **NumPy**, the number library under pandas: `rng.normal(...)` draws random numbers around an average, and the seed `42` makes them the same on every run. You'll meet NumPy properly in the next lessons.

<TryIt language="python" code={`import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(42)
order_values = rng.normal(35, 10, size=300)          # £ per order
distance = rng.uniform(1, 30, size=60)               # km
days = 1 + distance / 10 + rng.normal(0, 0.4, 60)    # delivery
web = rng.normal(33, 8, size=200)
app = rng.normal(39, 12, size=200)

fig, axes = plt.subplots(2, 2, figsize=(9, 7))

axes[0, 0].bar(["Tea", "Mugs", "Snacks", "Books"], [340, 210, 480, 150])
axes[0, 0].set_title("Bar: orders per category")

axes[0, 1].hist(order_values, bins=20, edgecolor="white")
axes[0, 1].set_title("Histogram: order values (£)")

axes[1, 0].scatter(distance, days, alpha=0.7)
axes[1, 0].set_title("Scatter: distance vs delivery days")
axes[1, 0].set_xlabel("Distance (km)")

axes[1, 1].boxplot([web, app], tick_labels=["Web", "App"])
axes[1, 1].set_title("Box plot: order values by channel")

fig.tight_layout()
plt.show()`}
/>

- The **histogram** splits the values into `bins` and counts how many fall in each, so you see the *shape* of the data: most orders are around £35, few are below £10 or above £60. Try `bins=5` and `bins=60`: too few hides the shape, too many makes it noisy.
- The **scatter plot** shows one dot per delivery. `alpha=0.7` makes dots slightly see-through, so overlapping ones show up darker.
- The **box plot** draws the middle half of each group as a box, the median as a line, and outliers as single dots. You'll learn exactly how in the next lesson. It's the quickest way to compare the spread of several groups.

## Titles, labels, legends and annotations

A chart should make sense to someone who reads nothing else. That means a title that says what's shown, axis labels **with units**, a legend when there's more than one series, and an **annotation** that points at the thing you want people to notice:

<TryIt language="python" code={`import matplotlib.pyplot as plt

months = ["Jan", "Feb", "Mar", "Apr", "May", "Jun"]
y2025 = [1100, 1150, 1210, 1240, 1300, 1320]
y2026 = [1200, 1350, 1280, 1600, 1750, 1900]

fig, ax = plt.subplots(figsize=(7, 4))
ax.plot(months, y2025, marker="o", color="#999999", label="2025")
ax.plot(months, y2026, marker="o", color="#0072B2", label="2026")
ax.axhline(1500, linestyle="--", color="#D55E00", label="Target")

ax.annotate("Spring sale starts",
            xy=(3, 1600),          # the point (Apr is position 3)
            xytext=(0.3, 1750),    # where the text goes
            arrowprops=dict(arrowstyle="->"))

ax.set_title("Visitors per month: 2026 beat 2025 after the sale")
ax.set_ylabel("Visitors")
ax.set_ylim(0, 2100)
ax.grid(axis="y", alpha=0.3)
ax.legend(loc="lower right")
plt.show()`}
/>

- **`label=`** names each series, and **`ax.legend()`** shows them. `loc=` moves the legend out of the way.
- **`ax.axhline()`** draws a horizontal reference line, like a target (`ax.axvline()` draws a vertical one, for example on a launch date).
- **`ax.annotate(text, xy=..., xytext=..., arrowprops=...)`** writes text with an arrow pointing at `xy`. With text labels on the x axis, the positions are 0, 1, 2...
- A title can say the **conclusion**, not just the topic. "2026 beat 2025 after the sale" tells a busy reader what to see.

## Charts that mislead

A chart can be technically correct and still give the wrong impression. Some tricks are deliberate, most are accidents. Here are the classics:

**Truncated axes.** A bar's **length** is its value, so bar charts must start at zero. These two charts show the same conversion rates:

<TryIt language="python" code={`import matplotlib.pyplot as plt

variants = ["Button A", "Button B"]
rates = [10.2, 10.8]     # % of visitors who bought

fig, (left, right) = plt.subplots(1, 2, figsize=(8, 3.5))

left.bar(variants, rates, color=["#999999", "#0072B2"])
left.set_ylim(10, 11)
left.set_title("Misleading: starts at 10%")

right.bar(variants, rates, color=["#999999", "#0072B2"])
right.set_ylim(0, 12)
right.set_title("Honest: starts at 0%")

for ax in (left, right):
    ax.set_ylabel("Conversion rate (%)")
fig.tight_layout()
plt.show()`}
/>

On the left, B looks **four times** better; really it's 0.6 percentage points better. (Notice the neat trick for two Axes: `fig, (left, right) = plt.subplots(1, 2)` unpacks them into names.) Line charts are different: they show *change*, so zooming in on the y axis is fine, as long as the axis is clearly labelled.

**Dual axes.** `ax.twinx()` adds a second y axis on the right with its own scale. By choosing the two scales, you can make any two lines look like they move together, or cross wherever you like. Prefer two charts stacked with `sharex=True`, like the visitors and orders above.

**3-D and pie charts.** Perspective makes the front slices of a 3-D pie look bigger than they are, and people are bad at comparing angles even in flat pies. A **sorted bar chart** shows the same thing more precisely.

**Cherry-picked ranges.** Showing only the months where sales went up, or a y axis that changes between charts you're meant to compare (that's what `sharey=True` prevents).

<Callout type="warning" title="Honest charts checklist">

Bars start at zero. Charts that people compare share their axes. Axes have labels and units. The data source and sample size are written somewhere. If you had to explain a chart out loud to stop people misreading it, redraw it.

</Callout>

## Colours everyone can read

About **1 in 12 men** and 1 in 200 women have some colour vision deficiency, usually difficulty telling **red from green**. A red-vs-green chart can be unreadable for them, and it also fails on black-and-white printers. Pros do three things:

1. **Use a colour-blind-safe palette.** The **Okabe-Ito** colours (used in the charts above: `#0072B2` blue, `#D55E00` orange-red, `#009E73` green, `#E69F00` orange, `#56B4E9` sky blue, `#CC79A7` pink) are designed to be told apart by everyone. matplotlib also has safe styles, `"tableau-colorblind10"` and `"petroff10"`.
2. **Don't rely on colour alone.** Add different markers or line styles, or label lines directly.
3. **Use grey for context and one colour for the story.** The eye goes straight to the highlighted bar.

For colour **scales** (heatmaps, maps), use `cmap="viridis"` or `"cividis"`: they go from dark to light evenly and work in black and white. Avoid the rainbow `"jet"`.

<TryIt language="python" code={`import matplotlib.pyplot as plt

categories = ["Books", "Mugs", "Tea", "Snacks"]
orders = [150, 210, 340, 480]
colours = ["#BBBBBB"] * len(orders)
colours[3] = "#0072B2"              # highlight Snacks

months = ["Jan", "Feb", "Mar", "Apr"]

# The style applies only inside the with block
with plt.style.context("tableau-colorblind10"):
    fig, (left, right) = plt.subplots(1, 2, figsize=(9, 3.5))

    left.barh(categories, orders, color=colours)
    left.set_title("Snacks get the most orders")
    left.set_xlabel("Orders")

    channels = [("Web", "o", "-"), ("App", "s", "--"),
                   ("Shop", "^", ":")]
    data = [[50, 55, 61, 70], [30, 41, 52, 66], [40, 38, 41, 39]]
    for (name, marker, style), values in zip(channels, data):
        right.plot(months, values, marker=marker, linestyle=style,
                   label=name)
    right.set_title("Orders by channel")
    right.legend()

    fig.tight_layout()
    plt.show()`}
/>

Notice **`with plt.style.context(...)`**: the style only applies inside the block. `plt.style.use(...)` would change every chart drawn afterwards, which is handy in a notebook but surprising in shared code.

## pandas charts on your own Axes

pandas plotting is matplotlib underneath. Pass **`ax=`** and pandas draws onto the Axes you choose, so you can mix pandas' convenience with your own layout:

<TryIt language="python" code={`import pandas as pd
import matplotlib.pyplot as plt

sales = pd.DataFrame({
    "web": [50, 55, 61, 70, 74, 80],
    "app": [30, 41, 52, 66, 71, 90],
}, index=["Jan", "Feb", "Mar", "Apr", "May", "Jun"])

fig, axes = plt.subplots(1, 2, figsize=(9, 3.5))

sales.plot(ax=axes[0], marker="o")    # one line per column
axes[0].set_title("Orders per month")

sales.sum().plot.bar(ax=axes[1], color=["#0072B2", "#E69F00"],
                     rot=0)
axes[1].set_title("Orders, January to June")

fig.tight_layout()
plt.show()`}
/>

A DataFrame plots **one line per column**, using the index for the x axis and the column names for the legend. `sales.sum()` is a Series (one total per column), and `.plot.bar()` is the same as `.plot(kind="bar")`. Every pandas plot method returns the Axes it drew on, so you can keep customising it.

## Saving charts for reports

**`fig.savefig("name.png", dpi=...)`** writes the figure to a file. The file type comes from the extension:

- **PNG** is an image made of pixels. Its size is `figsize × dpi`: a 6 × 4 inch figure at `dpi=200` is 1200 × 800 pixels. Use 150 to 300 for reports and slides.
- **SVG** and **PDF** are **vector** formats: they stay sharp at any size, which is great for print and web pages.

<CodeExample output={`b'\\x89PNG'
1200 800
True`}>

```python
import matplotlib.pyplot as plt

fig, ax = plt.subplots(figsize=(6, 4))
ax.bar(["A", "B"], [10.2, 10.8])
ax.set_title("Conversion rate (%)")

fig.savefig("conversion.png", dpi=200)
plt.close(fig)

data = open("conversion.png", "rb").read()
print(data[:4])                      # every PNG starts like this
width = int.from_bytes(data[16:20], "big")
height = int.from_bytes(data[20:24], "big")
print(width, height)

fig.savefig("conversion.svg")        # vector version
print(open("conversion.svg").read().startswith("<?xml"))
```

</CodeExample>

Two options you'll use a lot: **`bbox_inches="tight"`** trims empty space around the chart, and **`transparent=True`** drops the white background for slides with a coloured theme. On your own computer the files appear next to your script; here they go to the in-browser file system.

<Callout type="tip" title="One function per chart">

In real projects, write each chart as a function that takes data and **returns the figure**, like `visitors_chart` above. The same function can then feed a notebook, a report script that calls `savefig`, and a test that checks the data. Never compute numbers *inside* the chart code that the rest of the report doesn't also use.

</Callout>

## Recap

- **`fig, ax = plt.subplots()`**: a Figure is the whole image, an Axes is one chart in it. Use `ax.plot`, `ax.set_title`, `ax.set_xlabel`... instead of the `plt.` functions.
- **`plt.subplots(rows, cols, sharex=True)`** builds a grid; `fig.suptitle()` titles the figure and `fig.tight_layout()` stops overlaps.
- Pick the chart from the question: **line** for change over time, **bar** to compare groups, **histogram** for spread, **scatter** for relationships, **box plot** to compare spreads.
- Label everything with units, add a **legend** for several series and **annotate** what matters; a title can state the conclusion.
- Honest charts: bars start at zero, compared charts share axes, avoid dual axes and 3-D pies.
- Use colour-blind-safe colours (Okabe-Ito, `"tableau-colorblind10"`, `viridis`), don't rely on colour alone, and highlight one thing in colour with the rest in grey.
- `df.plot(ax=ax)` draws pandas charts on your Axes; **`fig.savefig("chart.png", dpi=200)`** saves them for reports.
- Write charts as functions that return the figure, so you can test their data.
