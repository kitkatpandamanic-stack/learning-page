The Panda Shop has a question worth money. 🐼🛒 The checkout page has a grey **"Continue"** button. The designer thinks a bright **"Buy now"** button would make more visitors complete their order. Instead of arguing about it, the team ran an **A/B test**: every visitor was randomly shown either the old button (**A**) or the new one (**B**), and the shop recorded who bought something.

Your job is to analyse the experiment and write the report that decides what happens next. You'll use everything from this module: describing data, confidence intervals, a permutation test and a clear chart.

Because visitors were assigned **at random**, the two groups are alike in every way except the button: same mix of new and returning customers, same weekdays, same weather. So if B converts better and it's not luck, the button **caused** it. That's why experiments beat correlations from [Describing Data](/learn/python/describing-data).

## Plan before you look

Remember peeking and p-hacking from [Samples and Uncertainty](/learn/python/samples-and-uncertainty)? The cure is to write the plan down **before** the data comes in:

1. **Metric:** the **conversion rate**, the fraction of visitors who buy.
2. **Test:** a two-sided permutation test, with **α = 0.05** (the significance threshold, "alpha").
3. **Decision rule:** ship B only if the difference is significant **and** the whole confidence interval is above zero; keep A if it's significant and the whole interval is below zero; otherwise, there's not enough evidence.
4. **Sample size:** enough visitors to have a good chance of detecting the smallest change worth having.

For step 4, pros run a **power analysis**. The question is: *"if B really lifts conversion from 10% to 13%, how many visitors per group do we need to detect it 80% of the time?"* The `statsmodels` package answers it:

<CodeExample output={`power 80%: 1,768 visitors per group
power 90%: 2,367 visitors per group
to detect 10% -> 11%: 14,744 per group`}>

```python
from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize

effect = proportion_effectsize(0.13, 0.10)   # 10% -> 13%
for power in [0.8, 0.9]:
    n = NormalIndPower().solve_power(effect_size=effect,
                                     alpha=0.05, power=power)
    print(f"power {power:.0%}: {n:,.0f} visitors per group")

small = proportion_effectsize(0.11, 0.10)    # 10% -> 11%
n = NormalIndPower().solve_power(effect_size=small,
                                 alpha=0.05, power=0.8)
print(f"to detect 10% -> 11%: {n:,.0f} per group")
```

</CodeExample>

About 1,800 visitors per group, so the shop plans **4,000 visitors** in total. Notice how quickly the number grows for smaller effects: detecting a 1-point lift needs about eight times more traffic. Small shops can only detect big changes, which is worth knowing before you start.

## The data

In a real shop the data would come from the website's logs or a database (`pd.read_sql`, `pd.read_csv`). Here we **generate** it with a seeded generator, which has a bonus: we know the truth (10% for A and 13% for B), so we can check whether our methods find it. Each row is one visitor:

<CodeExample output={`   visitor variant  converted  order_value
0        1       A      False          0.0
1        2       B      False          0.0
2        3       B      False          0.0
3        4       A      False          0.0
4        5       A      False          0.0
variant
A    2006
B    1994
Name: count, dtype: int64
0`}>

```python
import numpy as np
import pandas as pd

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

visitors = make_visitors()
print(visitors.head())
print(visitors["variant"].value_counts())
print(visitors.isna().sum().sum())
```

</CodeExample>

- **`np.where(condition, x, y)`** picks `x` where the condition is `True` and `y` elsewhere, value by value. It gives each visitor the rate of their variant, and an order value only to visitors who bought.
- `rng.random(n) < rate` is `True` with probability `rate`: a quick way to flip a biased coin for each visitor.
- The groups aren't exactly 2,000 each, because each visitor's variant was random. That's normal and fine.

## Step 1: conversion rates

The mean of a `True`/`False` column is the fraction of `True`s, so the conversion rate is one `groupby` away:

<CodeExample output={`         visitors  buyers    rate
variant                          
A            2006     204  0.1017
B            1994     273  0.1369
difference: +3.52 percentage points
relative lift: +34.6%`}>

```python
import numpy as np
import pandas as pd

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

visitors = make_visitors()
summary = visitors.groupby("variant").agg(
    visitors=("converted", "size"),
    buyers=("converted", "sum"),
    rate=("converted", "mean"),
)
print(summary.round(4))

rates = summary["rate"]
diff = rates["B"] - rates["A"]
print(f"difference: {diff * 100:+.2f} percentage points")
print(f"relative lift: {diff / rates['A']:+.1%}")
```

</CodeExample>

Be careful with words here. Going from 10% to 13% is **+3 percentage points**, but a **+30% relative lift**. Both are correct and they sound very different, so always say which one you mean. Reports that want to impress tend to use the relative number.

## Step 2: how sure are we?

B looks better. The bootstrap from the last lesson tells us how much that difference could wobble: resample each group **with replacement**, compute the difference in rates, repeat.

<CodeExample output={`95% CI: +1.47 to +5.52 points
shortcut:  +1.42 to +5.47 points`}>

```python
import numpy as np
import pandas as pd

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

visitors = make_visitors()
a = visitors.loc[visitors["variant"] == "A", "converted"].to_numpy()
b = visitors.loc[visitors["variant"] == "B", "converted"].to_numpy()

rng = np.random.default_rng(0)
n_boot = 2_000
boot_a = rng.choice(a, size=(n_boot, len(a))).mean(axis=1)
boot_b = rng.choice(b, size=(n_boot, len(b))).mean(axis=1)
low, high = np.percentile(boot_b - boot_a, [2.5, 97.5])
print(f"95% CI: {low * 100:+.2f} to {high * 100:+.2f} points")

# The shortcut for yes/no data: count buyers in each resample
boot_a = rng.binomial(len(a), a.mean(), size=n_boot) / len(a)
boot_b = rng.binomial(len(b), b.mean(), size=n_boot) / len(b)
low, high = np.percentile(boot_b - boot_a, [2.5, 97.5])
print(f"shortcut:  {low * 100:+.2f} to {high * 100:+.2f} points")
```

</CodeExample>

The whole interval is above zero: B is better by somewhere between about 1.5 and 5.5 percentage points.

The second half is a shortcut worth knowing. When the values are only yes/no, a resample of n visitors is fully described by **how many** of them bought, and **`rng.binomial(n, rate)`** draws exactly that number, as if it flipped n coins that each land "yes" with probability `rate`. Same result, but without building a 2,000 × 2,000 table, so it's hundreds of times faster. The two intervals differ only by random noise.

## Step 3: could it be luck?

Now the permutation test from the plan: if the button made no difference, the labels A and B are meaningless, so shuffle them and see how often a difference this big appears. Then cross-check with the classic test for proportions, `chi2_contingency`:

<CodeExample output={`permutation p-value: 0.0000
chi-squared p-value: 0.0006`}>

```python
import numpy as np
import pandas as pd
from scipy import stats

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

visitors = make_visitors()
a = visitors.loc[visitors["variant"] == "A", "converted"].to_numpy()
b = visitors.loc[visitors["variant"] == "B", "converted"].to_numpy()
observed = b.mean() - a.mean()

rng = np.random.default_rng(0)
n_perm = 2_000
pooled = np.concatenate([a, b])
shuffled = rng.permuted(np.tile(pooled, (n_perm, 1)), axis=1)
diffs = (shuffled[:, len(a):].mean(axis=1)
         - shuffled[:, :len(a)].mean(axis=1))
p_value = np.mean(np.abs(diffs) >= abs(observed))
print(f"permutation p-value: {p_value:.4f}")

table = [[a.sum(), len(a) - a.sum()],
         [b.sum(), len(b) - b.sum()]]
chi2 = stats.chi2_contingency(table, correction=False)
print(f"chi-squared p-value: {chi2.pvalue:.4f}")
```

</CodeExample>

**None** of the 2,000 shuffles produced a gap as big as the real one, so the p-value is below 1 in 2,000 (it's never truly zero; we just didn't shuffle enough times to see it happen). The chi-squared test agrees: p ≈ 0.0006. If the button made no difference, a gap this big would almost never happen by luck, so it's far below our α of 0.05.

<Callout type="tip" title="A shortcut for shuffling yes/no data">

Shuffling the labels deals `len(a)` of the pooled visitors to "fake A". For yes/no data, all that matters is **how many buyers** land in fake A, and **`rng.hypergeometric(buyers, non_buyers, len(a), size=n_perm)`** draws exactly that count, like dealing cards without putting them back. From the count you get both fake rates without shuffling anything:

```python
k = rng.hypergeometric(int(pooled.sum()),
                       int(len(pooled) - pooled.sum()),
                       len(a), size=n_perm)
diffs = (pooled.sum() - k) / len(b) - k / len(a)
```

It gives the same p-value (up to random noise) in a fraction of the time, so you can afford 100,000 shuffles.

</Callout>

## Step 4: the decision

The rule was fixed in the plan, so the decision is just code. Writing it as code has another advantage: nobody can quietly bend it after seeing the results.

<CodeExample output={`ship B
keep A
not enough evidence`}>

```python
def decide(p_value, low, high, alpha=0.05):
    if p_value < alpha and low > 0:
        return "ship B"
    if p_value < alpha and high < 0:
        return "keep A"
    return "not enough evidence"

print(decide(0.0000, 0.0147, 0.0552))  # our test
print(decide(0.0021, -0.050, -0.012))  # B was worse
print(decide(0.2600, -0.034, 0.010))   # could be luck
```

</CodeExample>

"Not enough evidence" is a real, useful answer. It doesn't mean the buttons are equal; it means this experiment can't tell them apart. The team can keep A (the safe default), or plan a bigger test if the change is cheap and promising.

In a real company the rule often has one more condition: the lift must be **big enough to matter** (say, at least +1 point), because changes have costs. That's a business decision, so agree on it with the team before the test, like everything else in the plan.

## Step 5: a chart for the report

The report chart should show the two rates **with their uncertainty**, and the difference with its interval. Error bars (`yerr=`) on a bar chart show each rate's 95% interval (1.96 standard errors), and **`ax.bar_label()`** writes the values on the bars. Remember: bars start at zero!

## Step 6: check the guardrails

A change can win on its main metric and quietly hurt something else. Maybe "Buy now" makes people buy, but **cheaper** things? Pros track a few **guardrail metrics** that must not get worse. Here: the average order value of buyers, and revenue per visitor.

<CodeExample output={`          mean  median
variant               
A        33.88   29.89
B        33.57   30.22
variant
A    3.44
B    4.60
Name: revenue per visitor, dtype: float64
order value p-value: 0.85`}>

```python
import numpy as np
import pandas as pd
from scipy import stats

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

visitors = make_visitors()
buyers = visitors[visitors["converted"]]

print(buyers.groupby("variant")["order_value"]
      .agg(["mean", "median"]).round(2))
print(visitors.groupby("variant")["order_value"].mean()
      .round(2).rename("revenue per visitor"))

values_a = buyers.loc[buyers["variant"] == "A", "order_value"]
values_b = buyers.loc[buyers["variant"] == "B", "order_value"]
p = stats.ttest_ind(values_b, values_a, equal_var=False).pvalue
print(f"order value p-value: {p:.2f}")
```

</CodeExample>

Buyers spend about the same with either button (the difference is well within luck), and because more people buy, **revenue per visitor** is higher with B. No guardrail is broken.

## Step 7: write the report

Results are only useful if people understand them. A good experiment report fits on one screen: what was tested, the result with its uncertainty, the decision, and any caveats. Building it from the computed numbers means it can never get out of sync with the analysis:

<CodeExample output={`A/B TEST: checkout button (4,000 visitors)
Conversion: A 10.2%, B 13.7%
Difference: +3.5 points (+35% relative)
95% CI:     +1.5 to +5.5 points
p-value:    < 0.001 (permutation test, alpha 0.05)
Guardrails: order value unchanged
Decision:   SHIP B`}>

```python
rate_a, rate_b = 0.1017, 0.1369
low, high, p_value = 0.0147, 0.0552, 0.0
decision = "ship B"

diff = rate_b - rate_a
p_text = "< 0.001" if p_value < 0.001 else f"{p_value:.3f}"
print(f"""A/B TEST: checkout button (4,000 visitors)
Conversion: A {rate_a:.1%}, B {rate_b:.1%}
Difference: {diff * 100:+.1f} points ({diff / rate_a:+.0%} relative)
95% CI:     {low * 100:+.1f} to {high * 100:+.1f} points
p-value:    {p_text} (permutation test, alpha 0.05)
Guardrails: order value unchanged
Decision:   {decision.upper()}""")
```

</CodeExample>

Add a sentence or two of plain-language caveats: the test ran for two weeks (maybe including no holidays), it measured the first purchase only, and the true lift is probably somewhere between 1.5 and 5.5 points, so plan the revenue forecast with the low end, not the middle.

1. `conversion_rates(df)`: a dict like `{"A": 0.1017, "B": 0.1369}` (no rounding).
2. `bootstrap_diff_ci(df, level=0.95, n_boot=2_000, seed=0)`: a bootstrap confidence interval for `rate_B - rate_A` as a tuple of two floats. With `level=0.8` it uses the 10th and 90th percentiles.
3. `permutation_p_value(df, n_perm=2_000, seed=0)`: the two-sided permutation-test p-value for `rate_B - rate_A`, as a float.
4. `decide(df, alpha=0.05)`: the decision rule from the plan, using the p-value and the confidence interval with `level=1 - alpha`. Returns `"ship B"`, `"keep A"` or `"not enough evidence"`.
5. `plot_rates(df)`: returns a Figure whose first Axes is a bar chart of the two conversion rates **in percent** (A first), with a title and a y label. Error bars and colours are up to you.

Seeds make your results repeatable. Your numbers don't have to match the lesson's to the last digit (there's more than one correct way to resample), but they must be close to what the formulas say.

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

def make_visitors(n=4_000, rate_a=0.10, rate_b=0.13, seed=42):
    rng = np.random.default_rng(seed)
    variant = rng.choice(["A", "B"], size=n)
    rate = np.where(variant == "A", rate_a, rate_b)
    converted = rng.random(n) < rate
    value = rng.lognormal(3.4, 0.5, size=n).round(2)
    return pd.DataFrame({
        "visitor": np.arange(1, n + 1),
        "variant": variant,
        "converted": converted,
        "order_value": np.where(converted, value, 0.0),
    })

def split(df):
    a = df.loc[df["variant"] == "A", "converted"].to_numpy()
    b = df.loc[df["variant"] == "B", "converted"].to_numpy()
    return a, b

def conversion_rates(df):
    a, b = split(df)
    return {"A": float(a.mean()), "B": float(b.mean())}

def bootstrap_diff_ci(df, level=0.95, n_boot=2_000, seed=0):
    a, b = split(df)
    rng = np.random.default_rng(seed)
    boot_a = rng.binomial(len(a), a.mean(), size=n_boot) / len(a)
    boot_b = rng.binomial(len(b), b.mean(), size=n_boot) / len(b)
    tail = (1 - level) / 2 * 100
    low, high = np.percentile(boot_b - boot_a, [tail, 100 - tail])
    return float(low), float(high)

def permutation_p_value(df, n_perm=2_000, seed=0):
    a, b = split(df)
    rng = np.random.default_rng(seed)
    observed = b.mean() - a.mean()
    buyers = int(a.sum() + b.sum())
    others = len(a) + len(b) - buyers
    k = rng.hypergeometric(buyers, others, len(a), size=n_perm)
    diffs = (buyers - k) / len(b) - k / len(a)
    return float(np.mean(np.abs(diffs) >= abs(observed)))

def decide(df, alpha=0.05):
    p = permutation_p_value(df)
    low, high = bootstrap_diff_ci(df, level=1 - alpha)
    if p < alpha and low > 0:
        return "ship B"
    if p < alpha and high < 0:
        return "keep A"
    return "not enough evidence"

def plot_rates(df):
    rates = conversion_rates(df)
    fig, ax = plt.subplots(figsize=(5, 4))
    bars = ax.bar(["A", "B"], [rates["A"] * 100, rates["B"] * 100],
                  color=["#999999", "#0072B2"])
    ax.bar_label(bars, fmt="%.1f%%")
    ax.set_title("Conversion rate by variant")
    ax.set_ylabel("Conversion rate (%)")
    return fig

visitors = make_visitors()
print(conversion_rates(visitors))
print(bootstrap_diff_ci(visitors))
print(permutation_p_value(visitors))
print(decide(visitors))
fig = plot_rates(visitors)
plt.show()
```

## Recap

- Randomly assigning visitors to A and B makes the groups alike, so a real difference is **caused** by the change.
- **Plan first**: metric, test, α, decision rule and sample size (a **power analysis**, e.g. with `statsmodels`). It stops peeking and p-hacking.
- Conversion rate = mean of a `True`/`False` column; say **percentage points** or **relative lift**, and which one you mean.
- A **bootstrap CI** shows how big the lift might be; a **permutation test** (cross-checked with `chi2_contingency`) shows whether it could be luck. For yes/no data, `rng.binomial` and `rng.hypergeometric` are fast shortcuts.
- Turn the rule into code: **ship B**, **keep A**, or **not enough evidence**, which is a valid answer.
- Check **guardrail** metrics, chart the rates with their uncertainty, and write a short report with the effect, the interval, the p-value, the decision and the caveats.
