"Machine learning" sounds like magic, but the core idea fits in one sentence: instead of writing the rules yourself, you show the computer **examples** and let it **find the rules**. In this lesson you'll train two real models with **scikit-learn**, the most popular machine learning library for Python: one that predicts the rent of a flat, and one that recognises flowers. 🌸

## What is machine learning?

Say you want a function that estimates the monthly rent of a flat. The classic way is to write the rule yourself:

```python
def estimate_rent(size_m2):
    return 300 + 15 * size_m2      # where do 300 and 15 come from?
```

But where do those numbers come from? You'd have to study the market and guess. Machine learning flips it around: you collect **examples** (flats whose rent you know), and an algorithm **learns** the numbers that fit the examples best. The result, a **model**, is just a function that someone else (the algorithm) wrote for you.

This is called **supervised learning**: every example comes with the right answer, like a teacher marking homework. It's what most real-world machine learning is, and it's what this module is about. (Its cousin, **unsupervised** learning, finds groups and patterns in data without any answers, for example grouping customers by how they shop.)

## Features and labels

Every supervised problem has the same two parts:

- **Features**: what you know about each example (a flat's size, its distance to the centre...). By convention they're stored in a 2-D table called **`X`** (capital, because it's a matrix): one **row per example**, one **column per feature**.
- **Labels** (or **targets**): the answer you want to predict (the rent). They're stored in a 1-D array called **`y`**, one value per row of `X`.

<CodeExample output={`(8, 2) (8,)
   size_m2  km_to_centre
0       30             1
1       38             5
2       45             2`}>

```python
import pandas as pd

flats = pd.DataFrame({
    "size_m2": [30, 38, 45, 52, 60, 68, 75, 85],
    "km_to_centre": [1, 5, 2, 8, 3, 10, 4, 6],
    "rent": [950, 880, 1080, 1000, 1300, 1150, 1500, 1600],
})
X = flats[["size_m2", "km_to_centre"]]    # 2-D: the features
y = flats["rent"]                         # 1-D: the labels
print(X.shape, y.shape)
print(X.head(3))
```

</CodeExample>

Each row is one **sample** (one flat). The double brackets in `flats[["size_m2", "km_to_centre"]]` select a DataFrame (2-D), while single brackets give a Series (1-D), which is exactly the difference between `X` and `y`.

## Regression or classification?

What kind of label you predict decides the kind of problem:

- **Regression**: the label is a **number** on a scale. Rent, temperature tomorrow, a house price, how many minutes a delivery takes.
- **Classification**: the label is a **category** from a fixed set. Spam or not spam, which species a flower is, which digit is in an image, whether a payment is fraud.

"How much?" or "how many?" means regression; "which one?" or "yes or no?" means classification. Different models fit each kind, but as you'll see, scikit-learn uses them all the same way.

## The scikit-learn recipe

scikit-learn is a package like any other (`pip install scikit-learn`; on PandaDev it's ready to use), and it's imported as **`sklearn`**. Every model follows the same three steps:

```python
from sklearn.linear_model import LinearRegression

model = LinearRegression()      # 1. choose a model (and its settings)
model.fit(X, y)                 # 2. learn from examples
model.predict(X_new)            # 3. predict for new data
```

Learn this recipe once and you can use dozens of models: swapping one algorithm for another is usually a one-line change. In scikit-learn, models are called **estimators**.

## Predicting rent with linear regression

**Linear regression** finds the straight line that fits the points best: `rent = intercept + slope × size`. Let's train it on eight flats, using only their size for now:

<CodeExample output={`[14.38]
336.91
[1056. 1775.]
1056`}>

```python
import numpy as np
from sklearn.linear_model import LinearRegression

sizes = np.array([30, 38, 45, 52, 60, 68, 75, 85])
rents = np.array([780, 900, 950, 1100, 1180, 1320, 1400, 1580])

X = sizes.reshape(-1, 1)        # 8 rows, 1 feature column
model = LinearRegression()
model.fit(X, rents)

print(model.coef_.round(2))     # slope: £ per extra m2
print(round(model.intercept_, 2))
print(model.predict([[50], [100]]).round())

# The model is just this formula:
print(round(model.intercept_ + model.coef_[0] * 50))
```

</CodeExample>

The model learned that every extra square metre adds about **£14.38** a month, starting from about **£337**. A 50 m² flat comes out at about £1056.

Three things to notice:

- **`X` must be 2-D**, even with one feature. That's why we used `reshape(-1, 1)` from [the NumPy lesson](/learn/python/numpy-arrays), and why `predict` gets `[[50], [100]]`, a list of rows, not `[50, 100]`. Forgetting it is the most common scikit-learn error: `Expected a 2D array, got 1D array instead`.
- Attributes ending in an **underscore**, like `coef_` and `intercept_`, are things the model **learned** during `fit`. They don't exist before training.
- `predict` for 100 m² gives about £1775, even though our biggest flat is 85 m². Models will happily answer about situations they've never seen, and the further you go from the examples, the less you should trust the answer.

## Seeing the line

The dots don't sit exactly on the line, and they never will: real rents depend on more than size. The model finds the line with the smallest overall error (the **least squares** line: it minimises the squared distances from the dots to the line).

## More than one feature

Let's give the model the distance to the centre as well. With a DataFrame as `X`, each column is one feature, and the model learns one coefficient per feature:

<CodeExample output={`size_m2: +15.58
km_to_centre: -39.01
intercept: 490.43
[1191.  918.]`}>

```python
import pandas as pd
from sklearn.linear_model import LinearRegression

flats = pd.DataFrame({
    "size_m2": [30, 38, 45, 52, 60, 68, 75, 85],
    "km_to_centre": [1, 5, 2, 8, 3, 10, 4, 6],
    "rent": [950, 880, 1080, 1000, 1300, 1150, 1500, 1600],
})
X = flats[["size_m2", "km_to_centre"]]
y = flats["rent"]

model = LinearRegression().fit(X, y)
for name, coef in zip(X.columns, model.coef_):
    print(f"{name}: {coef:+.2f}")
print(f"intercept: {model.intercept_:.2f}")

new_flats = pd.DataFrame({
    "size_m2": [50, 50],
    "km_to_centre": [2, 9],
})
print(model.predict(new_flats).round())
```

</CodeExample>

Now the model says: every m² adds about £15.58, and every kilometre from the centre takes off about £39.01. The same 50 m² flat is about £273 cheaper 9 km out. (`fit` returns the model itself, which is why `LinearRegression().fit(X, y)` works in one line.)

<Callout type="tip" title="Predict with the same columns you trained on">

If you train on a DataFrame, predict on a DataFrame with the **same columns in the same order**. Pass a plain list instead and scikit-learn prints a warning (`X does not have valid feature names`), and if you mix up the column order, it won't notice at all and will give you nonsense. In real projects, one function that builds `X` from raw data, used for training **and** predicting, prevents this.

</Callout>

## A classifier: which iris is it?

Now classification. scikit-learn comes with a few small, famous datasets for practising. The **iris** dataset holds measurements of 150 iris flowers from three species, collected in the 1930s:

<CodeExample output={`(150, 4) (150,)
['sepal length (cm)', 'sepal width (cm)', 'petal length (cm)', 'petal width (cm)']
[[5.1 3.5 1.4 0.2]
 [4.9 3.  1.4 0.2]]
[0 1 2]
['setosa' 'versicolor' 'virginica']`}>

```python
from sklearn.datasets import load_iris

iris = load_iris()
print(iris.data.shape, iris.target.shape)
print(iris.feature_names)
print(iris.data[:2])
print(iris.target[[0, 50, 100]])
print(iris.target_names)
```

</CodeExample>

`iris.data` is `X` (150 flowers × 4 measurements in cm) and `iris.target` is `y`. The labels are numbers, 0, 1 and 2, because models work with numbers; `target_names` translates them back to species.

We'll use **k-nearest neighbours** (KNN), the most intuitive classifier there is: to classify a new flower, find the `k` most similar flowers in the training data (the ones with the closest measurements), and let them **vote**:

<CodeExample output={`[0 2 2]
['setosa' 'virginica' 'virginica']
[[1.  0.  0. ]
 [0.  0.  1. ]
 [0.  0.4 0.6]]`}>

```python
from sklearn.datasets import load_iris
from sklearn.neighbors import KNeighborsClassifier

iris = load_iris()
model = KNeighborsClassifier(n_neighbors=5)
model.fit(iris.data, iris.target)

new_flowers = [
    [5.0, 3.4, 1.5, 0.2],
    [6.5, 3.0, 5.5, 2.0],
    [6.0, 2.7, 4.9, 1.6],
]
labels = model.predict(new_flowers)
print(labels)
print(iris.target_names[labels])
print(model.predict_proba(new_flowers))
```

</CodeExample>

Exactly the same recipe as before: create, `fit`, `predict`. Indexing `target_names` with the array of labels turns numbers into names (a NumPy trick: an array of positions picks several values at once).

**`predict_proba`** shows how sure the model is: one column per class. The first two flowers are clear cases (all 5 neighbours agree). The third is borderline: 2 neighbours say versicolor, 3 say virginica, so it's virginica with a probability of 0.6. Change `n_neighbors` and the answer for that flower may change. Settings like `n_neighbors` that **you** choose (rather than the model learning them) are called **hyperparameters**.

## A model you can read: decision trees

A **decision tree** learns a series of yes/no questions. Its rules can be printed, so you can see exactly what it learned:

<CodeExample output={`|--- petal width (cm) <= 0.80
|   |--- class: setosa
|--- petal width (cm) >  0.80
|   |--- petal width (cm) <= 1.75
|   |   |--- class: versicolor
|   |--- petal width (cm) >  1.75
|   |   |--- class: virginica

[1]`}>

```python
from sklearn.datasets import load_iris
from sklearn.tree import DecisionTreeClassifier, export_text

iris = load_iris()
tree = DecisionTreeClassifier(max_depth=2, random_state=0)
tree.fit(iris.data, iris.target)

print(export_text(
    tree,
    feature_names=iris.feature_names,
    class_names=list(iris.target_names),
))
print(tree.predict([[6.0, 2.7, 4.9, 1.6]]))
```

</CodeExample>

The tree found that **petal width** alone separates the species well: under 0.8 cm it's a setosa; otherwise, under 1.75 cm it's a versicolor, and above it a virginica. Nobody told it about petals: it worked that out from the 150 examples. `max_depth=2` limits it to two questions deep; `random_state` makes the training repeatable, as the seed did for random numbers.

Notice that the tree calls our borderline flower class `1` (versicolor), while KNN said virginica. Different models, different answers. So which model is better? That's the question of the next lesson.

<Callout type="warning" title="Don't grade a model on its own homework">

It's tempting to check a model by predicting the flowers it was trained on and counting how many it gets right. That number is too optimistic: the model has **seen** those answers. A 1-nearest-neighbour model would score 100%, because every flower's closest neighbour is itself! In the next lesson you'll test models properly, on data they've never seen.

</Callout>

1. `fit_line(xs, ys)` trains a `LinearRegression` on one feature (`xs`, a plain list) and labels `ys`, and returns a tuple `(slope, intercept)`, both rounded to 2 decimal places. For `xs = [1, 2, 3, 4]` and `ys = [3, 5, 7, 9]` it's `(2.0, 1.0)`, because `y = 1 + 2x`.

```python
import numpy as np
from sklearn.datasets import load_iris
from sklearn.linear_model import LinearRegression
from sklearn.neighbors import KNeighborsClassifier

def fit_line(xs, ys):
    X = np.array(xs).reshape(-1, 1)
    model = LinearRegression().fit(X, ys)
    return round(model.coef_[0], 2), round(model.intercept_, 2)

def train_iris_model(k):
    iris = load_iris()
    model = KNeighborsClassifier(n_neighbors=k)
    return model.fit(iris.data, iris.target)

def name_flowers(model, flowers):
    labels = model.predict(flowers)
    return load_iris().target_names[labels].tolist()

print(fit_line([1, 2, 3, 4], [3, 5, 7, 9]))
model = train_iris_model(5)
print(name_flowers(model, [[5.0, 3.4, 1.5, 0.2], [6.0, 2.7, 4.9, 1.6]]))
```

## Recap

- **Machine learning** learns a function from **examples** instead of hand-written rules; with **supervised learning**, every example has the right answer.
- **Features** `X` are a 2-D table (one row per sample, one column per feature); **labels** `y` are 1-D, one per row.
- **Regression** predicts a number; **classification** predicts a category.
- Every scikit-learn model follows the same recipe: create it (with **hyperparameters**), `fit(X, y)`, `predict(X_new)`.
- `LinearRegression` learns `coef_` (one per feature) and `intercept_`; learned attributes end in `_`.
- `KNeighborsClassifier` votes among the nearest examples; `predict_proba` shows how sure it is. A `DecisionTreeClassifier` learns readable rules (`export_text`).
- `X` must be 2-D: use `reshape(-1, 1)` or `[[value]]` for a single feature, and predict with the same columns you trained on.
- A score on the training data is too optimistic; test on new data (next lesson).
