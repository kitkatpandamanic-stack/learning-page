У вас есть мир (часть 1) и система команд с предметами и запертой сокровищницей (часть 2). Пора превратить эти детали в **настоящую игру**! 🎮 В этой заключительной части вы напишете `play(commands)` — **игровой цикл (game loop)**, который выполняет команды игрока одну за другой, печатает, что происходит, считает ходы и завершается, когда игрок **побеждает**, **проигрывает** или **выходит**.

Вам пригодятся **циклы for** и **while True** из модуля «Циклы», `return` и **аргументы по умолчанию** из модуля «Функции» и всё, что вы построили в первой и второй частях.

## Команды списком

В настоящей игре в терминале игрок вводит каждую команду через `input()`. Здесь, в браузере, `input()` недоступен, поэтому мы поступим как тестировщики игр: запишем команды игрока **заранее**, в виде списка строк. Сами команды, как и раньше, английские.

```python
commands = ["look", "go west", "take key", "go east",
            "go south", "take treasure"]
```

`play(commands)` перебирает этот список так, будто игрок ввёл каждую строку сам. Позже в этом уроке вы увидите, как заменить список настоящим вводом с клавиатуры на своём компьютере, ничего больше не меняя.

## Где живёт состояние игры

Игре нужны четыре части **состояния (state)**: где находится игрок, что он несёт, где лежат предметы и сколько ходов он сделал. Все четыре создаются **внутри** `play`:

```python
def play(commands, max_moves=10):
    room = "hall"
    inventory = []
    world = ["key in garden", "lamp in kitchen", "treasure in vault"]
    moves = 0
    print(look(room, world))
```

Благодаря **области видимости (scope)** каждый вызов `play` получает совершенно новые переменные. Каждая игра начинается с чистого листа: ключ снова лежит в саду, а инвентарь пуст, даже если сыграть десять партий подряд.

<Callout type="warning" title="Не делите мир между играми">

Если бы `world` и `inventory` жили **снаружи** `play`, вторая игра началась бы с ключом уже в кармане и без клада в сокровищнице! Создавая их внутри функции, мы держим каждую игру отдельно.

</Callout>

## Как устроен игровой цикл

Прежде чем писать настоящую версию, посмотрим на крошечную, которая показывает саму форму. Цикл `for` выполняет команды, а `return` **заканчивает игру** в тот же момент, когда случается что-то решающее, даже посреди цикла:

<CodeExample output={`> walk
> dig
Вы нашли сокровище!
won
> walk
> walk
> walk
Сил больше нет...
lost
> quit
quit
quit`}>

```python
def mini_play(commands, max_moves=2):
    moves = 0
    for command in commands:
        print(f"> {command}")
        if command == "quit":
            return "quit"
        if command == "dig":
            print("Вы нашли сокровище!")
            return "won"
        moves += 1
        if moves > max_moves:
            print("Сил больше нет...")
            return "lost"
    return "quit"

print(mini_play(["walk", "dig", "walk"]))
print(mini_play(["walk", "walk", "walk"]))
print(mini_play(["quit", "dig"]))
print(mini_play([]))
```

</CodeExample>

Обратите внимание на три вещи:

- В первой игре последний `"walk"` так и не выполняется: `return "won"` уже завершил функцию.
- `max_moves=2` — это **аргумент по умолчанию (default argument)**, поэтому вызывающий код может сделать игру легче или сложнее: `mini_play(commands, max_moves=5)`.
- Если цикл закончился, а исход так и не решился (последняя игра), строка после цикла возвращает `"quit"`: игрок просто перестал играть.

Результаты `"won"`, `"lost"` и `"quit"` («победа», «поражение», «выход») мы оставляем английскими: это не сообщения для игрока, а значения, которые проверяет код.

## Настоящий игровой цикл

Теперь настоящая `play`. Для каждой команды мы:

1. Печатаем её после `>`, чтобы вывод выглядел как настоящая игровая сессия.
2. Сразу останавливаемся, если это `quit`.
3. Поручаем работу функции `handle` из второй части и печатаем её сообщение.
4. Засчитываем **ход** каждый раз, когда сменилась комната. Удариться о стену или запертую дверь — бесплатно.
5. Проверяем, **победил** ли игрок (клад в инвентаре) или **проиграл** (слишком много ходов).

```python
    for command in commands:
        print(f"> {command}")
        if command.lower().strip() == "quit":
            print("Вы покидаете дом. До встречи!")
            return "quit"

        new_room, message = handle(command, room, inventory, world)
        print(message)
        if new_room != room:
            moves += 1
            room = new_room

        if "treasure" in inventory:
            print(f"Вы нашли сокровище! Сделано ходов: {moves} 🏆")
            return "won"
        if moves > max_moves:
            print("Вы слишком устали, чтобы идти дальше. Игра окончена.")
            return "lost"

    print("На сегодня исследование окончено.")
    return "quit"
```

<Callout type="tip" title="Порядок важен">

Мы проверяем **победу раньше**, чем поражение. Если игрок схватил клад на последнем разрешённом ходу, он должен победить, а не услышать, что слишком устал!

</Callout>

Вот что печатает пример игры из начала урока:


Затем `play` **возвращает** `"won"`. Если возвращать результат, а не только печатать его, другой код сможет им воспользоваться — например, подсчитать, сколько игр вы выиграли, или проверить вашу игру в тестах.

## Играем по-настоящему с input()

На вашем компьютере `input()` работает: он показывает приглашение, ждёт, пока игрок введёт строку, и возвращает её. Вместо перебора списка крутите цикл **бесконечно** с `while True` и выходите из него через `break`, когда игра закончилась. Всё остальное, от `handle` до `look`, остаётся ровно таким же:

```python title="adventure.py"
# ... вставьте сюда все свои функции из упражнения ...

room = "hall"
inventory = []
world = ["key in garden", "lamp in kitchen", "treasure in vault"]
moves = 0
print(look(room, world))

while True:
    command = input("> ")
    if command.lower().strip() == "quit":
        print("Вы покидаете дом. До встречи!")
        break

    new_room, message = handle(command, room, inventory, world)
    print(message)
    if new_room != room:
        moves += 1
        room = new_room

    if "treasure" in inventory:
        print(f"Вы нашли сокровище! Сделано ходов: {moves} 🏆")
        break
```

Сохраните это как `adventure.py` и запустите в терминале:

```bash
python3 adventure.py
```

Не забывайте: команды вводятся по-английски — `go west`, `take key`, `look`, `inventory`, `quit`.

<Callout type="note" title="Почему не здесь?">

PandaDev запускает Python прямо в браузере, где нет клавиатурного приглашения, которого мог бы ждать `input()`. Поэтому наша `play` принимает список команд. Это ещё и удобно для **тестирования**: один и тот же список всегда даёт одну и ту же игру, так что её можно проверять автоматически.

</Callout>

## Что вы построили

- `play(commands, max_moves=10)` хранит всё **состояние игры** в локальных переменных, поэтому каждая игра начинается заново.
- Цикл `for` пропускает каждую команду через `handle` и печатает историю по мере того, как она разворачивается.
- **Ходы** засчитываются, только когда комната действительно меняется.
- `return` завершает игру в тот же момент, когда игрок **побеждает**, **проигрывает** или **выходит**, а результат возвращается, чтобы им мог воспользоваться другой код.
- С `while True` и `input()` те же самые функции превращаются в игру, в которую можно играть в терминале.

## Что дальше

Ваше приключение работает, и теперь его можно развивать по-своему. Несколько идей:

- **Больше комнат**: добавьте чердак (`attic`) над библиотекой или погреб (`cellar`) под кухней. Нужны лишь новые `case` в `describe` и новые строки в `move`.
- **Сокращения**: позвольте игроку вводить `n`, `s`, `e` и `w` или `get` вместо `take`. С `match` и `case "go" | "walk":` синонимы добавляются легко.
- **Тёмная комната**: пусть в библиотеке будет кромешная тьма, если у игрока нет лампы, — тогда `look` там сработает только при `"lamp" in inventory`.
