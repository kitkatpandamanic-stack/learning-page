You have a world (Part 1) and a command system with items and a locked vault (Part 2). Now it's time to turn the pieces into a **real game**! 🎮 In this final part you'll write `play(commands)`: a **game loop** that runs the player's commands one by one, prints what happens, counts the moves, and ends when the player **wins**, **loses** or **quits**.

You'll use **for loops** and **while True** from the Loops module, `return` and **default arguments** from Functions, and everything you built in Parts 1 and 2.

## Commands as a list

In a real terminal game, the player types each command with `input()`. Here in the browser `input()` isn't available, so we do what game testers do: write the player's commands down **in advance**, as a list of strings.

```python
commands = ["look", "go west", "take key", "go east",
            "go south", "take treasure"]
```

`play(commands)` loops over this list as if the player had typed each line. Later in this lesson you'll see how to swap the list for real typing on your own computer, without changing anything else.

## Where the game state lives

The game needs four pieces of **state**: where the player is, what they carry, where the items are and how many moves they've made. All four are created **inside** `play`:

```python
def play(commands, max_moves=10):
    room = "hall"
    inventory = []
    world = ["key in garden", "lamp in kitchen", "treasure in vault"]
    moves = 0
    print(look(room, world))
```

Because of **scope**, every call to `play` gets brand-new variables. Each game starts fresh: the key is back in the garden and the inventory is empty, even if you play ten games in a row.

<Callout type="warning" title="Don't share the world">

If `world` and `inventory` lived **outside** `play`, the second game would start with the key already in your pocket and the treasure already gone! Creating them inside the function keeps every game separate.

</Callout>

## The shape of a game loop

Before writing the real thing, here's a tiny version that shows the shape. A `for` loop runs the commands, and `return` **ends the game** the moment something decisive happens, even in the middle of the loop:

<CodeExample output={`> walk
> dig
You found the treasure!
won
> walk
> walk
> walk
Too tired...
lost
> quit
quit
quit`}>

```python
def mini_play(commands, max_moves=2):
    moves = 0
    for command in commands:
        print(f"> {command}")
        if command == "quit":
            return "quit"
        if command == "dig":
            print("You found the treasure!")
            return "won"
        moves += 1
        if moves > max_moves:
            print("Too tired...")
            return "lost"
    return "quit"

print(mini_play(["walk", "dig", "walk"]))
print(mini_play(["walk", "walk", "walk"]))
print(mini_play(["quit", "dig"]))
print(mini_play([]))
```

</CodeExample>

Three things to notice:

- In the first game, the last `"walk"` never runs: `return "won"` already ended the function.
- `max_moves=2` is a **default argument**, so a caller can make the game easier or harder: `mini_play(commands, max_moves=5)`.
- If the loop finishes without a decision (the last game), the line after the loop returns `"quit"`: the player simply stopped playing.

## The real game loop

Now the real `play`. For each command we:

1. Print it after a `>`, so the output reads like a real game session.
2. Stop straight away if it's `quit`.
3. Let `handle` from Part 2 do the work, and print its message.
4. Count a **move** whenever the room changed. Bumping into a wall or a locked door is free.
5. Check whether the player has **won** (the treasure is in the inventory) or **lost** (too many moves).

```python
    for command in commands:
        print(f"> {command}")
        if command.lower().strip() == "quit":
            print("You leave the house. Bye for now!")
            return "quit"

        new_room, message = handle(command, room, inventory, world)
        print(message)
        if new_room != room:
            moves += 1
            room = new_room

        if "treasure" in inventory:
            print(f"You found the treasure in {moves} moves! 🏆")
            return "won"
        if moves > max_moves:
            print("You are too tired to go on. Game over.")
            return "lost"

    print("You stop exploring for now.")
    return "quit"
```

<Callout type="tip" title="Order matters">

We check for a **win before** checking for a loss. If the player grabs the treasure on their very last allowed move, they should win, not be told they're too tired!

</Callout>


## Playing for real with input()

On your own computer, `input()` works: it shows a prompt, waits for the player to type a line and returns it as a string. Instead of looping over a list, loop **forever** with `while True` and `break` out when the game ends. Everything else, from `handle` to `look`, stays exactly the same:

```python title="adventure.py"
# ... paste all your functions from the exercise here ...

room = "hall"
inventory = []
world = ["key in garden", "lamp in kitchen", "treasure in vault"]
moves = 0
print(look(room, world))

while True:
    command = input("> ")
    if command.lower().strip() == "quit":
        print("You leave the house. Bye for now!")
        break

    new_room, message = handle(command, room, inventory, world)
    print(message)
    if new_room != room:
        moves += 1
        room = new_room

    if "treasure" in inventory:
        print(f"You found the treasure in {moves} moves! 🏆")
        break
```

Save it as `adventure.py` and run it in a terminal:

```bash
python3 adventure.py
```

<Callout type="note" title="Why not here?">

PandaDev runs Python inside your browser, where there's no keyboard prompt for `input()` to wait on. That's why our `play` takes a list of commands. It's also handy for **testing**: the same list always gives the same game, so you can check it automatically.

</Callout>

## What you built

- `play(commands, max_moves=10)` keeps the whole **game state** in local variables, so every game starts fresh.
- A `for` loop runs each command through `handle` and prints the story as it happens.
- **Moves** are counted only when the room really changes.
- `return` ends the game the moment the player **wins**, **loses** or **quits**, and the result is returned for other code to use.
- With `while True` and `input()`, the very same functions become a game you can play in your terminal.

## Take it further

Your adventure works, and now it's yours to grow. Some ideas:

- **More rooms**: add an attic above the library or a cellar below the kitchen. You only need new `case`s in `describe` and new lines in `move`.
- **Shortcuts**: let the player type `n`, `s`, `e` and `w`, or `get` instead of `take`. A `match` with `case "go" | "walk":` makes synonyms easy.
- **A dark room**: make the library pitch black unless the player carries the lamp, so `look` only works there with `"lamp" in inventory`.
- **A help command**: print a list of every command the game understands.
- **A score**: give points for each item found and fewer points the more moves the player needs.
