Now the player gets a voice. ⌨️ In this part you'll understand **typed commands** like `go north` or `take key`, put **items** in the rooms, let the player carry them in an **inventory** and **lock** the vault until they find the key.

You'll use **string methods** (`.lower()`, `.strip()`) from Python Basics, **match** from Operators & Decisions, **lists** and `in` from Looping over Lists, and functions that **return several values** from Default Arguments & Scope. Plus three small new list and string tools, introduced as we go.

## Reading a command

A player might type `go north`, `Go North` or `  GO north  `. They all mean the same thing, so first we tidy the text up:

- `.lower()` makes everything lowercase.
- `.strip()` removes spaces from both ends.
- `.split()` is **new**: it cuts a string into a **list of words** wherever there are spaces.

<CodeExample output={`['go', 'north']
['take', 'key']
['look']
[]`}>

```python
print("  Go NORTH ".lower().strip().split())
print("take key".split())
print("look".split())
print("   ".split())
```

</CodeExample>

Methods can be **chained**: each one works on the result of the one before it. Notice the last line: a command with no words gives an **empty list**.

The first word is the **verb** (what to do) and the second is the **noun** (what to do it with). Some commands, like `look`, have no noun, so we only read `words[1]` when it exists:

<CodeExample output={`[go] [north]
[take] [key]
[look] []
[] []`}>

```python
def parse(command):
    words = command.lower().strip().split()
    if len(words) == 0:
        return "", ""
    verb = words[0]
    noun = ""
    if len(words) > 1:
        noun = words[1]
    return verb, noun

for command in ["Go North", "take key", "LOOK", ""]:
    verb, noun = parse(command)
    print(f"[{verb}] [{noun}]")
```

</CodeExample>

The square brackets in the output just make empty strings visible. `parse` returns **two values**, and `verb, noun = parse(command)` unpacks them, just like `low, high = lowest_and_highest(...)` in the functions module.

<Callout type="warning" title="Empty commands">

If the player just presses Enter, `words` is an empty list and `words[0]` would crash with an `IndexError`. That's why `parse` checks `len(words) == 0` first. Always ask yourself: *"what if the player types nothing?"*

</Callout>

## Where are the items?

Our house has three items: a **key** in the garden, a **lamp** in the kitchen and the **treasure** in the vault. We'll keep track of them in one list called `world`, where every entry is a short sentence:

```python
world = ["key in garden", "lamp in kitchen", "treasure in vault"]
```

This reads like English, and checking whether an item is somewhere is easy with `in`:

<CodeExample output={`True
False`}>

```python
world = ["key in garden", "lamp in kitchen", "treasure in vault"]
print("key in garden" in world)
print("key in hall" in world)
```

</CodeExample>

To find **every** item in a room, loop over the list and `.split()` each entry. `"key in garden".split()` gives `['key', 'in', 'garden']`, so the item is `words[0]` and the room is `words[2]`:

<CodeExample output={`['key']
['key', 'apple']
[]`}>

```python
def items_in(room, world):
    found = []
    for place in world:
        words = place.split()
        if words[2] == room:
            found.append(words[0])
    return found

world = ["key in garden", "apple in garden", "lamp in kitchen"]
print(items_in("garden", ["key in garden"]))
print(items_in("garden", world))
print(items_in("hall", world))
```

</CodeExample>

<Callout type="note" title="Coming up in Level 1">

In Level 1 you'll learn **dictionaries**, which are made for exactly this kind of "what is where" data. For now, a list of short sentences does the job nicely with what you already know.

</Callout>

## Looking around

When the player types `look`, they should hear the room's description **and** what's lying there. `look` builds on `describe` from Part 1 by adding one sentence per item:

<CodeExample output={`An overgrown garden. Exit: east. You see a key.
A quiet library full of books. Exit: south.`}>

```python
def describe(room):
    match room:
        case "garden":
            return "An overgrown garden. Exit: east."
        case "library":
            return "A quiet library full of books. Exit: south."
        case _:
            return "You are lost in the fog."

def items_in(room, world):
    found = []
    for place in world:
        words = place.split()
        if words[2] == room:
            found.append(words[0])
    return found

def look(room, world):
    text = describe(room)
    for item in items_in(room, world):
        text += f" You see a {item}."
    return text

world = ["key in garden", "lamp in kitchen"]
print(look("garden", world))
print(look("library", world))
```

</CodeExample>

(This example uses a shorter `describe` to save space. In your game, it's the full one from Part 1.)

## Taking and dropping

The player's **inventory** is a list of what they carry. It starts empty: `inventory = []`.

Taking an item moves it **out of** `world` and **into** `inventory`. Adding uses `.append()`, which you know. Removing uses `.remove()`, which is **new**: it deletes the first matching value from a list.

<CodeExample output={`You take the key.
['key']
['lamp in kitchen']
You don't see that here.`}>

```python
def take(item, room, inventory, world):
    place = f"{item} in {room}"
    if place not in world:
        return "You don't see that here."
    world.remove(place)
    inventory.append(item)
    return f"You take the {item}."

inventory = []
world = ["key in garden", "lamp in kitchen"]

print(take("key", "garden", inventory, world))
print(inventory)
print(world)
print(take("lamp", "garden", inventory, world))
```

</CodeExample>

`not in` is the opposite of `in`: it's `True` when the value is **missing** from the list.

<Callout type="note" title="Functions can change a list you give them">

`take` never returns `inventory` or `world`, yet both changed! When you pass a list to a function, the function works on **the very same list**, not a copy. `.append()` and `.remove()` change that list in place, so the caller sees the change too. Strings never work like this, because they can't be changed.

</Callout>

**Dropping** is the mirror image: the item leaves the inventory and lands in the room you're standing in. Try writing `drop` yourself in the exercise below: check the item is in `inventory`, `.remove()` it, then `.append()` a new sentence like `"key in hall"` to `world`.

To show the inventory nicely, there's one more **new** tool: `", ".join(items)` glues the strings of a list together, with `", "` between them. It's the opposite of `.split()`:

<CodeExample output={`You are carrying nothing.
You are carrying: key, lamp.`}>

```python
def show_inventory(inventory):
    if len(inventory) == 0:
        return "You are carrying nothing."
    return "You are carrying: " + ", ".join(inventory) + "."

print(show_inventory([]))
print(show_inventory(["key", "lamp"]))
```

</CodeExample>

## A locked door

The vault is locked. Going `south` from the hall only works if `"key"` is in the inventory. A small function answers *"is this way locked right now?"*:

<CodeExample output={`True
False
False`}>

```python
def is_locked(room, direction, inventory):
    if room == "hall" and direction == "south":
        return "key" not in inventory
    return False

print(is_locked("hall", "south", []))
print(is_locked("hall", "south", ["key"]))
print(is_locked("hall", "north", []))
```

</CodeExample>

## Putting it together: handle()

Now one function, `handle`, runs **any** command. It parses the command, uses `match` on the verb and returns **two values**: the room the player is now in, and a message to show them.

```python
def handle(command, room, inventory, world):
    verb, noun = parse(command)
    match verb:
        case "go":
            if is_locked(room, noun, inventory):
                return room, "The vault door is locked. You need a key."
            new_room = move(room, noun)
            if new_room == room:
                return room, "You can't go that way."
            return new_room, look(new_room, world)
        case "look":
            return room, look(room, world)
        # take, drop and inventory go here
        case _:
            return room, "I don't understand that."
```

- For `go`, we check the lock **before** moving, then use `move` from Part 1. Arriving in a new room automatically shows what it looks like.
- Commands that don't move the player, like `look`, return the **same** `room`.
- `case _` catches typos and unknown verbs, so the game never crashes on strange input.

The game then keeps its state in three variables (`room`, `inventory` and `world`) and updates `room` after every command:

```python
room, message = handle("go west", room, inventory, world)
print(message)
```

## What you built

- `parse` turns messy typing into a clean **verb** and **noun** with `.lower().strip().split()`.
- The `world` list records **where every item is**, and `items_in` and `look` read it.
- `take` and `drop` move items between `world` and the player's **inventory** with `.append()` and `.remove()`.
- `is_locked` keeps the vault shut until the player carries the key. 🔑
- `handle` runs any command and returns the new room plus a message.
