Welcome to your first **Python capstone project**! 🗺️ Over three parts you'll build a complete **text adventure game**: the player explores a spooky old house by typing commands like `go north` and `take key`, finds a key, unlocks the vault and grabs the treasure.

You already know everything you need: **strings** and **f-strings** from Python Basics, **if/elif/else** and **match** from Operators & Decisions, **loops** and **lists**, and **functions** with return values. In this first part we'll build the **world**: the rooms and the paths between them. No commands yet, just the map.

## Plan the map first

Before typing any code, sketch the world. Our house has five rooms. The **hall** is in the middle, and every other room is one step away from it:

```text
               library
                  |
    garden  —   hall   —  kitchen
                  |
                vault
```

- North of the hall is the **library**, east is the **kitchen**, west is the **garden** and south is the **vault**.
- From each outer room, the only way out leads back to the hall.
- Later, a **key** will lie in the garden and the **treasure** in the vault (which will be locked).

We'll store each room as a simple **string**, like `"hall"` or `"vault"`. The player's position is just a variable: `room = "hall"`.

| Function                 | Its one job                                    |
| ------------------------ | ---------------------------------------------- |
| `describe(room)`         | Return a sentence describing the room          |
| `move(room, direction)`  | Return the room you end up in                  |

<Callout type="tip" title="One job per function">

Small functions that each do one job are easier to read, test and fix. When the player ends up in the wrong room, you'll know exactly which function to look at.

</Callout>

## Describing a room

`describe` takes a room name and **returns** a description. We compare one value (`room`) against several exact options, which is exactly what `match` is good at:

<CodeExample output={`A dusty hall. Exits: north, south, east, west.
The vault! Gold glitters everywhere. Exit: north.
You are lost in the fog.`}>

```python
def describe(room):
    match room:
        case "hall":
            return "A dusty hall. Exits: north, south, east, west."
        case "library":
            return "A quiet library full of books. Exit: south."
        case "kitchen":
            return "An old kitchen that smells of soup. Exit: west."
        case "garden":
            return "An overgrown garden. Exit: east."
        case "vault":
            return "The vault! Gold glitters everywhere. Exit: north."
        case _:
            return "You are lost in the fog."

print(describe("hall"))
print(describe("vault"))
print(describe("attic"))
```

</CodeExample>

`case _` catches every other value, so even a typo like `"atic"` gets a sensible answer instead of `None`.

Notice that `describe` **returns** the text instead of printing it. That way, the rest of the game decides when and how to show it, and we can easily combine it with other text later.

<Callout type="note" title="if/elif works too">

You could write the same thing with `if room == "hall": … elif room == "library": …`. Both are fine. `match` just reads a little tidier when you check one value against many fixed options.

</Callout>

## Moving between rooms

`move(room, direction)` answers the question *"if I'm in this room and walk this way, where do I end up?"*. Let's start with the hall, which has four exits:

<CodeExample output={`library
vault
hall`}>

```python
def move(room, direction):
    if room == "hall":
        if direction == "north":
            return "library"
        elif direction == "east":
            return "kitchen"
        elif direction == "west":
            return "garden"
        elif direction == "south":
            return "vault"
    return room

print(move("hall", "north"))
print(move("hall", "south"))
print(move("hall", "up"))
```

</CodeExample>

The last line, `return room`, is the important trick. If none of the `return`s above it ran, there's **no exit that way**, so the player simply stays where they are. Remember: `return` ends the function straight away, so `return room` is only reached when nothing matched.

Now add the way back from each outer room. Each one has a single exit, so `and` keeps it short:

```python
    elif room == "library" and direction == "south":
        return "hall"
    elif room == "kitchen" and direction == "west":
        return "hall"
    elif room == "garden" and direction == "east":
        return "hall"
    elif room == "vault" and direction == "north":
        return "hall"
    return room
```

## Taking a walk

With both functions in place, a `for` loop can walk the player along a list of directions. If `move` gives back the **same room**, the way was blocked, so we print a message instead:

<CodeExample output={`A dusty hall. Exits: north, south, east, west.
Going north...
A quiet library full of books. Exit: south.
Going north...
You can't go that way.
Going south...
A dusty hall. Exits: north, south, east, west.
Going west...
An overgrown garden. Exit: east.`}>

```python
def describe(room):
    match room:
        case "hall":
            return "A dusty hall. Exits: north, south, east, west."
        case "library":
            return "A quiet library full of books. Exit: south."
        case "kitchen":
            return "An old kitchen that smells of soup. Exit: west."
        case "garden":
            return "An overgrown garden. Exit: east."
        case "vault":
            return "The vault! Gold glitters everywhere. Exit: north."
        case _:
            return "You are lost in the fog."

def move(room, direction):
    if room == "hall":
        if direction == "north":
            return "library"
        elif direction == "east":
            return "kitchen"
        elif direction == "west":
            return "garden"
        elif direction == "south":
            return "vault"
    elif room == "library" and direction == "south":
        return "hall"
    elif room == "kitchen" and direction == "west":
        return "hall"
    elif room == "garden" and direction == "east":
        return "hall"
    elif room == "vault" and direction == "north":
        return "hall"
    return room

room = "hall"
print(describe(room))

for direction in ["north", "north", "south", "west"]:
    print(f"Going {direction}...")
    new_room = move(room, direction)
    if new_room == room:
        print("You can't go that way.")
    else:
        room = new_room
        print(describe(room))
```

</CodeExample>

The variable `room` is the whole **game state** for now: one string that says where the player is. Each time the player moves, we replace it with the room `move` returned.

<Callout type="warning" title="Same room = blocked">

Our rule is simple: if `move` returns the room you were already in, the way is blocked. That's why `move` must **always** return a room, even when there's no exit. A function that sometimes returns `None` would make the rest of the game crash in confusing ways.

</Callout>

## What you built

- A **map** of five rooms, planned on paper before writing any code.
- `describe(room)` uses `match` to return a sentence for each room, with `case _` as a safety net.
- `move(room, direction)` uses `if/elif` to return the next room, or the **same room** when the way is blocked.
- A `for` loop walked the player around, with `room` holding the game state.
