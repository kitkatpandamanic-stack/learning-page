Некоторые задачи содержат внутри себя уменьшенные копии самих себя. В папке лежат файлы **и другие папки**, в которых лежат файлы и другие папки... В списке могут быть списки. **Рекурсия** (recursion) — это способ решать такие задачи с помощью функции, которая **вызывает саму себя** для части поменьше, пока эта часть не станет такой маленькой, что ответ очевиден. 🪆

## Функция, которая вызывает саму себя

Вот обратный отсчёт без единого цикла:

<CodeExample output={`3
2
1
Пуск!`}>

```python
def countdown(n):
    if n == 0:
        print("Пуск!")
        return
    print(n)
    countdown(n - 1)   # функция вызывает саму себя

countdown(3)
```

</CodeExample>

`countdown(3)` печатает `3` и вызывает `countdown(2)`, которая печатает `2` и вызывает `countdown(1)`, и так далее. Когда `n` становится `0`, функция печатает `Пуск!` и больше себя не вызывает.

## Базовый и рекурсивный случаи

У каждой рекурсивной функции есть две части:

- **Базовый случай** (base case): задача настолько маленькая, что на неё можно ответить сразу, **не** вызывая функцию снова. Здесь это `n == 0`.
- **Рекурсивный случай** (recursive case): сделать немного работы, а затем вызвать функцию для **меньшей** задачи, которая приближает нас к базовому случаю. Здесь это `countdown(n - 1)`.

Классический пример — **факториал** (factorial): `4!` означает `4 × 3 × 2 × 1`. Заметьте, что `4!` — это просто `4 × 3!`, уменьшенная копия той же задачи:

<CodeExample output={`24
1
3628800`}>

```python
def factorial(n):
    if n <= 1:                       # базовый случай
        return 1
    return n * factorial(n - 1)      # рекурсивный случай

print(factorial(4))
print(factorial(1))
print(factorial(10))
```

</CodeExample>

<Callout type="tip" title="Доверьтесь функции">

Когда пишете рекурсивный случай, **считайте, что функция уже работает** для меньшей задачи. «Если `factorial(3)` даёт `6`, то `factorial(4)` — это `4 * 6`». Не нужно прослеживать каждый вызов в голове. В этом и состоит секрет рекурсивного мышления.

</Callout>

## Стек вызовов

Как Python отслеживает все эти незавершённые вызовы? Каждый вызов получает свою маленькую «коробку» с локальными переменными, и коробки складываются в **стек вызовов** (call stack). Вызов остаётся в стеке и **ждёт**, пока не вернётся вызов, который он сделал. Давайте напечатаем, что происходит, и будем сдвигать каждую строку в зависимости от глубины:

<CodeExample output={`вызов factorial(4)
  вызов factorial(3)
    вызов factorial(2)
      вызов factorial(1)
      базовый случай: return 1
    return 2 * 1 = 2
  return 3 * 2 = 6
return 4 * 6 = 24
24`}>

```python
def factorial(n, depth=0):
    indent = "  " * depth
    print(f"{indent}вызов factorial({n})")
    if n <= 1:
        print(f"{indent}базовый случай: return 1")
        return 1
    smaller = factorial(n - 1, depth + 1)
    result = n * smaller
    print(f"{indent}return {n} * {smaller} = {result}")
    return result

print(factorial(4))
```

</CodeExample>

Вызовы идут **вниз**, пока не дойдут до базового случая, а затем ответы поднимаются **вверх**: каждый ждавший вызов заканчивает своё умножение. У каждого вызова своя `n`: в `factorial(4)` переменная `n` всё ещё равна `4`, когда `factorial(3)` возвращает результат.

Это ровно тот стек, который вы видите в трассировке (traceback) — «most recent call last». Вы встречали его в уроке [Исключения](/learn/python/exceptions).

## Рекурсия на списках

Список — это «первый элемент, за которым идёт список поменьше». Поэтому списки отлично подходят для рекурсии:

<CodeExample output={`8
0
15`}>

```python
def sum_list(numbers):
    if not numbers:          # базовый случай: пустой список
        return 0
    return numbers[0] + sum_list(numbers[1:])

print(sum_list([3, 1, 4]))
print(sum_list([]))
print(sum_list([5, 5, 5]))
```

</CodeExample>

Если расписать вызовы, получится так:

```text
sum_list([3, 1, 4])
= 3 + sum_list([1, 4])
= 3 + 1 + sum_list([4])
= 3 + 1 + 4 + sum_list([])
= 3 + 1 + 4 + 0
= 8
```

## Рекурсия на вложенных данных

По-настоящему рекурсия раскрывается, когда данные **вложенные** и вы не знаете, насколько глубоко они уходят. Цикл может пройти по одному уровню, а как быть со списками внутри списков внутри списков? Пусть функция вызывает саму себя каждый раз, когда находит очередной список:

<CodeExample output={`[1, 2, 3, 4, 5, 6]
[]`}>

```python
def flatten(items):
    flat = []
    for item in items:
        if isinstance(item, list):
            flat.extend(flatten(item))   # список: заходим внутрь
        else:
            flat.append(item)            # обычное значение
    return flat

print(flatten([1, [2, 3], [4, [5, [6]]]]))
print(flatten([[], [[]]]))
```

</CodeExample>

Здесь базовый случай спрятан в цикле: обычное значение не вызывает функцию ещё раз, а в пустом списке просто нечего перебирать.

С папками всё так же. Будем хранить папку как **словарь** (dictionary): каждый ключ — это имя, а каждое значение — либо размер файла в КБ (число), либо другая папка (словарь):

<CodeExample output={`notes.txt (120 КБ)
photos/
  cat.jpg (2400 КБ)
  holiday/
    beach.jpg (3100 КБ)
    sea.png (2800 КБ)
todo.txt (40 КБ)`}>

```python
drive = {
    "notes.txt": 120,
    "photos": {
        "cat.jpg": 2400,
        "holiday": {"beach.jpg": 3100, "sea.png": 2800},
    },
    "todo.txt": 40,
}

def show(folder, depth=0):
    indent = "  " * depth
    for name, item in folder.items():
        if isinstance(item, dict):
            print(f"{indent}{name}/")
            show(item, depth + 1)       # вложенная папка
        else:
            print(f"{indent}{name} ({item} КБ)")

show(drive)
```

</CodeExample>

Тот же шаблон подходит для JSON из интернета, генеалогических деревьев, веток комментариев с ответами и меню с подменю.

## RecursionError: когда остановки нет

Если базового случая нет или функция до него никогда не доходит, вызовы копятся бесконечно. Python защищается от этого **ограничением глубины рекурсии** (recursion limit) — по умолчанию 1000 вложенных вызовов — и выбрасывает `RecursionError`:

<CodeExample output={`RecursionError: maximum recursion depth exceeded
1000`}>

```python
import sys

def countdown(n):
    if n == 0:
        return "Пуск!"
    return countdown(n - 2)   # упс: 5, 3, 1, -1, -3...

try:
    countdown(5)
except RecursionError as error:
    print("RecursionError:", error)

print(sys.getrecursionlimit())
```

</CodeExample>

Отсчёт с шагом 2 от нечётного числа перепрыгивает через `0`, поэтому базовый случай так и не наступает. На вашем компьютере трассировка закончится так:

```text
  File "main.py", line 6, in countdown
    return countdown(n - 2)
  [Previous line repeated 996 more times]
RecursionError: maximum recursion depth exceeded
```

<Callout type="warning" title="Чек-лист для рекурсивной функции">

1. Есть ли базовый случай?
2. Становится ли задача **меньше** при **каждом** рекурсивном вызове, чтобы базовый случай гарантированно наступил?

Здесь надёжнее базовый случай `if n <= 0:` — он ловит и отрицательные числа.

</Callout>

## Когда цикл лучше

Рекурсия — не всегда лучший инструмент. `sum_list` выше делает новый вызов (и новый срез списка) для каждого элемента, поэтому список из 5000 чисел упрётся в ограничение рекурсии, а `sum(numbers)` или простой цикл `for` без проблем справятся с миллионами.

| Используйте **цикл**, когда...                  | Используйте **рекурсию**, когда...                        |
| ----------------------------------------------- | --------------------------------------------------------- |
| вы проходите по элементам **один за другим**    | данные **вложенные** (папки, JSON, деревья)               |
| данные могут быть очень длинными (тысячи и больше) | задача делится на **уменьшенные копии** самой себя     |
| цикл читается так же понятно                    | рекурсивная версия намного короче и понятнее              |

Программисты на Python обычно сначала берутся за цикл, а к рекурсии обращаются, когда данные имеют форму дерева. Вы снова встретите её в **сортировке слиянием** в уроке [Поиск и сортировка](/learn/python/searching-and-sorting).

## Мемоизация: запоминаем ответы

**Числа Фибоначчи** идут так: 0, 1, 1, 2, 3, 5, 8, 13... Каждое равно сумме двух предыдущих. Рекурсивная версия восхитительно коротка, но у неё есть скрытая проблема. Давайте посчитаем, сколько раз запускается функция, — с помощью словаря-счётчика, который может обновлять каждый вызов:

<CodeExample output={`fib(5) = 5, вызовов: 15
fib(10) = 55, вызовов: 177
fib(15) = 610, вызовов: 1973
fib(20) = 6765, вызовов: 21891`}>

```python
stats = {"calls": 0}

def fib(n):
    stats["calls"] += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

for n in [5, 10, 15, 20]:
    stats["calls"] = 0
    answer = fib(n)
    print(f"fib({n}) = {answer}, вызовов: {stats['calls']}")
```

</CodeExample>

Почти 22 000 вызовов для `fib(20)`! `fib(20)` вызывает `fib(19)` **и** `fib(18)`, но `fib(19)` снова вызывает `fib(18)`, и каждый из них вызывает `fib(17)`... Одни и те же маленькие ответы вычисляются тысячи раз.

Решение — **мемоизация** (memoisation): запоминать каждый ответ, когда вычисляете его впервые, а в следующий раз просто брать готовый. С этим справится словарь:

<CodeExample output={`6765, вызовов: 21`}>

```python
stats = {"calls": 0}
memo = {}

def fib(n):
    if n in memo:
        return memo[n]          # уже знаем ответ: работы нет
    stats["calls"] += 1
    if n < 2:
        answer = n
    else:
        answer = fib(n - 1) + fib(n - 2)
    memo[n] = answer
    return answer

print(f"{fib(20)}, вызовов: {stats['calls']}")
```

</CodeExample>

### functools.lru_cache сделает это за вас

Мемоизация настолько полезна, что она встроена в стандартную библиотеку. Поставьте `@lru_cache` на строке над функцией — и Python будет запоминать каждый ответ за вас:

<CodeExample output={`6765, вызовов: 21
12586269025, вызовов: 51`}>

```python
from functools import lru_cache

stats = {"calls": 0}

@lru_cache(maxsize=None)
def fib(n):
    stats["calls"] += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(f"{fib(20)}, вызовов: {stats['calls']}")
print(f"{fib(50)}, вызовов: {stats['calls']}")
```

</CodeExample>

С 21 891 вызова до 21, а `fib(50)` понадобилось всего 30 вызовов сверху (от `fib(21)` до `fib(50)`), потому что первые 21 ответ уже лежали в кэше. Без кэша `fib(50)` потребовал бы **миллиарды** вызовов.

<Callout type="note" title="Что это за строка с @?">

`@lru_cache(maxsize=None)` — это **декоратор** (decorator): он оборачивает вашу функцию дополнительным поведением, в данном случае словарём запомненных ответов. Писать собственные декораторы вы научитесь в уроке [Декораторы](/learn/python/decorators). `maxsize=None` означает «запоминать всё». Кэшируйте только те функции, ответ которых зависит **только** от аргументов, а сами аргументы хешируемые (числа, строки, кортежи, но не списки).

</Callout>

Для вложенной папки вызовите саму функцию с `item`: прибавьте результат к сумме или расширьте им свой список через `extend`. В `find_files` передавайте вниз удлинённый путь: `path + name + "/"`. def total_size(folder):
    total = 0
    for name, item in folder.items():
        if isinstance(item, dict):
            total += total_size(item)
        else:
            total += item
    return total


def find_files(folder, ending, path=""):
    found = []
    for name, item in folder.items():
        if isinstance(item, dict):
            found.extend(find_files(item, ending, path + name + "/"))

## Итоги

- **Рекурсивная** функция вызывает саму себя для **меньшей** версии задачи.
- Ей нужен **базовый случай** (ответ сразу) и **рекурсивный случай**, который к нему приближает.
- Каждый вызов ждёт в **стеке вызовов**, пока не вернётся сделанный им вызов; у каждого вызова свои локальные переменные.
- Рекурсия подходит для **вложенных** данных: списков списков, папок, JSON. Циклы подходят для длинных плоских последовательностей.
- Нет достижимого базового случая — получите `RecursionError` (ограничение — около 1000 вложенных вызовов).
- **Мемоизация** запоминает ответы, и повторные вызовы становятся бесплатными: используйте словарь или `@lru_cache(maxsize=None)`.
