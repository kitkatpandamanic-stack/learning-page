Правильно выбранная **структура данных** (data structure) часто важнее хитрого кода. В этом уроке вы познакомитесь со структурами, которые стоят за кнопками отмены, очередями печати, листами ожидания в больницах и навигаторами. Все они собираются из того, что вы уже знаете: списков, `deque`, `heapq`, словарей и множеств. А затем вы соедините их вместе и пройдёте лабиринт. 🧭

## Стеки: последним пришёл — первым ушёл

**Стек** (stack) похож на стопку тарелок: вы кладёте тарелки **сверху** и снимаете тоже **сверху**. Последний пришедший уходит первым (**LIFO**, last in, first out). Список в Python — идеальный стек: `append()` кладёт элемент наверх, а `pop()` снимает сверху, и обе операции работают за O(1).

Любая кнопка **отмены** (undo) — это стек ваших действий:

<CodeExample output={`Отменить: ввести ' мир'
Отменить: сделать жирным
Всё ещё сделано: ["ввести 'Привет'"]
Следующей отменой будет: ввести 'Привет'`}>

```python
history = []
history.append("ввести 'Привет'")
history.append("сделать жирным")
history.append("ввести ' мир'")

print("Отменить:", history.pop())   # самое последнее действие
print("Отменить:", history.pop())
print("Всё ещё сделано:", history)
print("Следующей отменой будет:", history[-1])   # подсматриваем
```

</CodeExample>

### Парные скобки

С помощью стеков редакторы кода проверяют, что скобки расставлены правильно. Каждую открывающую скобку кладём в стек; при закрывающей скобке на **вершине** стека должна оказаться её пара:

<CodeExample output={`(a[1] + b) * {c} -> True
(] -> False
((x) -> False
print('hi')) -> False`}>

```python
def is_balanced(text):
    partners = {")": "(", "]": "[", "}": "{"}
    stack = []
    for char in text:
        if char in "([{":
            stack.append(char)
        elif char in partners:
            if not stack or stack.pop() != partners[char]:
                return False     # не та пара или ничего не открыто
    return not stack             # осталось ли что-то открытым?

for text in ["(a[1] + b) * {c}", "(]", "((x)", "print('hi'))"]:
    print(text, "->", is_balanced(text))
```

</CodeExample>

## Очереди: первым пришёл — первым ушёл

**Очередь** (queue) работает как очередь в магазине: люди встают в **конец**, а обслуживают их с **начала**. Первым пришёл — первым ушёл (**FIFO**, first in, first out). Используйте `deque` (читается «дек») из модуля `collections`: `append()` добавляет в конец, а `popleft()` забирает из начала:

<CodeExample output={`deque(['Mei', 'Sam', 'Kai'])
Mei обслуживается
deque(['Sam', 'Kai'])
2 Sam`}>

```python
from collections import deque

queue = deque(["Mei", "Sam"])
queue.append("Kai")          # встаём в конец
print(queue)

first = queue.popleft()      # обслуживаем первого
print(first, "обслуживается")
print(queue)
print(len(queue), queue[0])  # кто следующий?
```

</CodeExample>

Почему бы просто не взять список и `pop(0)`? Потому что список хранит элементы плотно, один за другим, и при удалении **первого** элемента Python приходится сдвигать **все остальные** на одно место влево. Посчитаем эти сдвиги для очереди из 1000 человек:

<CodeExample output={`list.pop(0): 499500 перемещений элементов
deque.popleft(): 0 перемещений элементов`}>

```python
line = list(range(1000))
moves = 0
while line:
    moves += len(line) - 1   # все, кто стоит сзади, сдвигаются влево
    line.pop(0)
print(f"list.pop(0): {moves} перемещений элементов")
print("deque.popleft(): 0 перемещений элементов")
```

</CodeExample>

`list.pop(0)` работает за **O(n)**, поэтому опустошить список таким способом — это O(n²). А `deque` специально устроен так, чтобы добавлять и удалять элементы с **обоих** концов за O(1).

<Callout type="tip" title="Стек или очередь?">

Сначала самое последнее (отмена, кнопка «назад», парные скобки)? **Стек**: список с `append` / `pop`. Сначала самое старое (задания на печать, покупатели, задачи в ожидании своей очереди)? **Очередь**: `deque` с `append` / `popleft`.

</Callout>

## Очереди с приоритетом и heapq

Иногда первым должен идти самый **важный** элемент, а не самый старый — как в больнице, где сначала принимают самого срочного пациента. Это **очередь с приоритетом** (priority queue). Модуль `heapq` превращает обычный список в **кучу** (heap), которая всегда держит **наименьший** элемент под индексом `0`. Храните кортежи `(priority, item)`, где меньшее число означает большую срочность:

<CodeExample output={`следующая: (1, 'позвонить в банк')
1 позвонить в банк
1 починить сайт
2 ответить на письмо
3 полить цветы`}>

```python
import heapq

tasks = []
heapq.heappush(tasks, (2, "ответить на письмо"))
heapq.heappush(tasks, (1, "починить сайт"))
heapq.heappush(tasks, (3, "полить цветы"))
heapq.heappush(tasks, (1, "позвонить в банк"))

print("следующая:", tasks[0])     # подсматриваем наименьший
while tasks:
    priority, task = heapq.heappop(tasks)
    print(priority, task)
```

</CodeExample>

Кортежи сравниваются поэлементно, поэтому задачи с одинаковым приоритетом упорядочиваются по названию. `heappush` и `heappop` работают за **O(log n)** — гораздо быстрее, чем сортировать весь список каждый раз, когда приходит новая задача.

## Словари и множества — это хеш-таблицы

В большинстве языков структуру, которая сопоставляет ключам значения с помощью хеширования, называют **хеш-таблицей** (hash map, или hash table). В Python это **словарь** (dict), а **множество** (set) — это хеш-таблица, в которой есть только ключи. Как вы видели в уроке [O-нотация](/learn/python/big-o), поиск по ключу работает за **O(1) в среднем**. Эту суперспособность снова и снова используют четыре приёма:

1. **Подсчёт**: `Counter(words)` (из урока [Модули и импорт](/learn/python/modules-and-imports)) или `counts[word] = counts.get(word, 0) + 1`.
2. **Группировка**: складываем элементы с одинаковым ключом в один список.
3. **Запоминание увиденного**: как множество `seen` в `has_duplicates`.
4. **Кэширование**: храним уже вычисленные ответы, как словарь `memo` в уроке [Рекурсия](/learn/python/recursion).

Вот группировка: слова — **анаграммы**, если состоят из одних и тех же букв, поэтому их отсортированные буквы — идеальный ключ:

<CodeExample output={`['listen', 'silent', 'enlist']
['google']`}>

```python
from collections import defaultdict

words = ["listen", "google", "silent", "enlist"]
groups = defaultdict(list)
for word in words:
    key = "".join(sorted(word))     # "eilnst"
    groups[key].append(word)

for group in groups.values():
    print(group)
```

</CodeExample>

А вот знаменитая задача с собеседований — **two-sum** («сумма двух»): найти в списке два числа, которые в сумме дают заданное. Перебор всех пар — это O(n²). Со словарём, который запоминает позицию каждого числа, хватит одного прохода — O(n):

<CodeExample output={`(3, 4)
None`}>

```python
def two_sum(numbers, target):
    seen = {}                      # число -> его индекс
    for i, number in enumerate(numbers):
        needed = target - number
        if needed in seen:         # поиск за O(1)
            return seen[needed], i
        seen[number] = i
    return None

print(two_sum([8, 3, 11, 5, 7], 12))   # 5 + 7
print(two_sum([1, 2], 10))
```

</CodeExample>

## Графы: словари соседей

**Граф** (graph) — это набор объектов (**вершин**, nodes), соединённых связями (**рёбрами**, edges): города и дороги, люди и дружба, веб-страницы и ссылки. Проще всего хранить граф в Python в виде словаря, который сопоставляет каждой вершине **список её соседей**:

<CodeExample output={`['Дом', 'Магазин', 'Озеро']
False
7`}>

```python
town = {
    "Дом": ["Парк", "Школа"],
    "Парк": ["Дом", "Магазин", "Озеро"],
    "Школа": ["Дом", "Библиотека"],
    "Магазин": ["Парк", "Вокзал"],
    "Озеро": ["Парк"],
    "Библиотека": ["Школа", "Вокзал"],
    "Вокзал": ["Магазин", "Библиотека"],
}

print(town["Парк"])              # куда можно пойти из парка?
print("Озеро" in town["Дом"])    # есть ли прямая дорога?
print(len(town))                 # количество мест
```

</CodeExample>


## Поиск в ширину

Сколько дорог нужно пройти от Дома до каждого другого места? **Поиск в ширину** (breadth-first search, BFS) исследует граф, как круги на воде: сначала всё, что в 1 шаге, затем всё, что в 2 шагах, и так далее. **Очередь** держит места в правильном порядке, а словарь запоминает расстояние до каждого места (и заодно отмечает его как посещённое):

<CodeExample output={`посещаем Дом, расстояние 0
посещаем Парк, расстояние 1
посещаем Школа, расстояние 1
посещаем Магазин, расстояние 2
посещаем Озеро, расстояние 2
посещаем Библиотека, расстояние 2
посещаем Вокзал, расстояние 3`}>

```python
from collections import deque

town = {
    "Дом": ["Парк", "Школа"],
    "Парк": ["Дом", "Магазин", "Озеро"],
    "Школа": ["Дом", "Библиотека"],
    "Магазин": ["Парк", "Вокзал"],
    "Озеро": ["Парк"],
    "Библиотека": ["Школа", "Вокзал"],
    "Вокзал": ["Магазин", "Библиотека"],
}

def bfs(graph, start):
    distance = {start: 0}
    queue = deque([start])
    while queue:
        place = queue.popleft()
        print(f"посещаем {place}, расстояние {distance[place]}")
        for neighbour in graph[place]:
            if neighbour not in distance:      # ещё не встречали
                distance[neighbour] = distance[place] + 1
                queue.append(neighbour)
    return distance

bfs(town, "Дом")
```

</CodeExample>

Поскольку BFS заканчивает с **всеми** местами на расстоянии 1, прежде чем перейти к **любому** месту на расстоянии 2, он всегда впервые попадает в место по **кратчайшему** маршруту (если считать дороги). А поскольку каждое место посещается один раз, BFS работает за **O(n)** от количества мест и дорог.

Чтобы получить сам маршрут, запоминайте для каждого места, **откуда вы в него пришли**. Добравшись до цели, пройдите по этим ссылкам назад и разверните результат:

<CodeExample output={`['Дом', 'Парк', 'Магазин', 'Вокзал']
['Озеро', 'Парк', 'Дом', 'Школа', 'Библиотека']
None`}>

```python
from collections import deque

town = {
    "Дом": ["Парк", "Школа"],
    "Парк": ["Дом", "Магазин", "Озеро"],
    "Школа": ["Дом", "Библиотека"],
    "Магазин": ["Парк", "Вокзал"],
    "Озеро": ["Парк"],
    "Библиотека": ["Школа", "Вокзал"],
    "Вокзал": ["Магазин", "Библиотека"],
    "Остров": [],
}

def shortest_path(graph, start, goal):
    came_from = {start: None}
    queue = deque([start])
    while queue:
        place = queue.popleft()
        if place == goal:
            path = []
            while place is not None:     # идём назад к началу
                path.append(place)
                place = came_from[place]
            return path[::-1]
        for neighbour in graph[place]:
            if neighbour not in came_from:
                came_from[neighbour] = place
                queue.append(neighbour)
    return None                          # до цели так и не добрались

print(shortest_path(town, "Дом", "Вокзал"))
print(shortest_path(town, "Озеро", "Библиотека"))
print(shortest_path(town, "Дом", "Остров"))
```

</CodeExample>

<Callout type="warning" title="Всегда отмечайте места как увиденные">

Дороги двусторонние, поэтому у Дома в списке есть Парк, а у Парка — Дом. Без проверки `if neighbour not in came_from` BFS бесконечно метался бы между ними. Отмечайте место как увиденное **в момент добавления в очередь**, а не когда достаёте его оттуда, — тогда оно никогда не попадёт в очередь дважды.

</Callout>

<Callout type="note" title="А если взять стек">

Замените очередь на стек (`pop()` вместо `popleft()`) — и получится **поиск в глубину** (depth-first search, DFS): он идёт по одной дороге как можно дальше и только потом возвращается назад. DFS отлично подходит для вопроса «можно ли вообще туда попасть?» или для обхода всех папок, но, в отличие от BFS, **не** гарантирует кратчайший путь.

</Callout>

## Сетки — тоже графы

Лабиринт (maze), нарисованный сеткой символов, — это замаскированный граф: каждая открытая клетка — вершина, а её соседи — клетки **сверху, снизу, слева и справа**. Клетка — это кортеж `(row, col)`, и четыре маленьких «хода» ведут к клеткам вокруг неё:

<CodeExample output={`(0, 1) .
(2, 1) .
(1, 0) .
(1, 2) #`}>

```python
maze = [
    "S.#",
    "..#",
    "#.E",
]

row, col = 1, 1
for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:   # вверх, вниз, влево, вправо
    r, c = row + dr, col + dc
    print((r, c), maze[r][c])
```

</CodeExample>

`(1, 2)` — это стена, поэтому решатель должен её пропустить. С клетками на **краю** тоже нужна осторожность: из `(0, 0)` ход «вверх» ведёт в строку `-1`, а Python спокойно прочитает `maze[-1]` как **последнюю** строку — коварная ошибка. Всегда сначала проверяйте `0 <= r < len(maze)` и `0 <= c < len(maze[r])`.

Пора собрать весь модуль воедино! Лабиринт — это список строк: `"#"` — стена, `"."` — свободный пол, `"S"` — старт, а `"E"` — выход. Ходить можно вверх, вниз, влево и вправо, но не по диагонали. Допишите решатель:

1. `find(maze, char)` возвращает `(row, col)` первой клетки с символом `char` (читая строку за строкой) или `None`.
2. `neighbours(maze, cell)` возвращает список клеток сверху, снизу, слева и справа от `cell`, которые находятся **внутри** лабиринта и **не** являются стенами. Порядок не важен.

4. `escape_steps(maze)` возвращает количество **ходов** на кратчайшем пути (на единицу меньше количества клеток) или `-1`, если выхода нет.
5. `draw(maze, path)` возвращает **новый** список строк, в котором каждая клетка пути, кроме `S` и `E`, превращается в `"*"`. Если `path` равен `None`, верните лабиринт без изменений.

<Hint>

`solve` — это `shortest_path` из урока, только с клетками вместо названий мест: найдите `start` и `end`, заведите `came_from = {start: None}` и `deque([start])` и используйте `neighbours(maze, cell)` вместо `graph[place]`. В `neighbours` переберите четыре хода `(dr, dc)` и проверьте `0 <= r < len(maze)`, `0 <= c < len(maze[r])` и `maze[r][c] != "#"`. Строки нельзя изменять, поэтому в `draw` превратите каждую строку в список через `list(line)`, замените клетки пути, а затем соберите каждую строку обратно через `"".join(...)`.

<Solution>

```python
from collections import deque

MOVES = [(-1, 0), (1, 0), (0, -1), (0, 1)]   # вверх, вниз, влево, вправо


def find(maze, char):
    for row, line in enumerate(maze):
        for col, value in enumerate(line):
            if value == char:
                return (row, col)
    return None


def neighbours(maze, cell):
    row, col = cell
    result = []
    for dr, dc in MOVES:
        r, c = row + dr, col + dc
        inside = 0 <= r < len(maze) and 0 <= c < len(maze[r])
        if inside and maze[r][c] != "#":
            result.append((r, c))
    return result


def solve(maze):
    start, end = find(maze, "S"), find(maze, "E")
    if start is None or end is None:
        return None
    came_from = {start: None}
    queue = deque([start])
    while queue:
        cell = queue.popleft()
        if cell == end:
            path = []
            while cell is not None:
                path.append(cell)
                cell = came_from[cell]
            return path[::-1]
        for nxt in neighbours(maze, cell):
            if nxt not in came_from:
                came_from[nxt] = cell
                queue.append(nxt)
    return None


def escape_steps(maze):
    path = solve(maze)
    if path is None:
        return -1
    return len(path) - 1


def draw(maze, path):
    if path is None:
        return list(maze)
    grid = [list(line) for line in maze]
    for row, col in path:
        if grid[row][col] not in "SE":
            grid[row][col] = "*"
    return ["".join(line) for line in grid]


maze = [
    "S.#.....",
    ".##.###.",
    "....#...",
    ".##...#E",
]
path = solve(maze)
if path is None:
    print("Выхода нет!")
else:
    for line in draw(maze, path):
        print(line)
    print(f"Выбрались за {escape_steps(maze)} шагов")
```

## Итоги

- **Стек** (список с `append` / `pop`) работает по принципу «последним пришёл — первым ушёл»: отмена, кнопки «назад», парные скобки.
- **Очередь** (`deque` с `append` / `popleft`) работает по принципу «первым пришёл — первым ушёл». `list.pop(0)` — это O(n), а `popleft()` — O(1).
- **Очередь с приоритетом** (`heapq.heappush` / `heappop`) всегда выдаёт следующим наименьший `(priority, item)`.
- Словари и множества — это **хеш-таблицы**: поиск за O(1) для подсчёта, группировки, запоминания увиденного и кэширования.
- **Граф** можно хранить как словарь списков соседей, а сетка — это граф из клеток `(row, col)`.
- **Поиск в ширину** с очередью исследует граф слоями, поэтому находит **кратчайшие пути**; словарь `came_from` позволяет восстановить маршрут.
