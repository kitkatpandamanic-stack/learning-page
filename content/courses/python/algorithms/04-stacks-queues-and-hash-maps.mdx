Choosing the right **data structure** often matters more than clever code. In this lesson you'll meet the structures behind undo buttons, print queues, hospital waiting lists and sat-navs, all built from things you already know: lists, `deque`, `heapq`, dicts and sets. Then you'll put them together to solve a maze. 🧭

## Stacks: last in, first out

A **stack** is like a pile of plates: you put plates on the **top** and take them off the **top**. The last one in is the first one out (**LIFO**). A Python list is a perfect stack: `append()` pushes onto the top and `pop()` takes from the top, both O(1).

Every **undo** button is a stack of the things you did:

<CodeExample output={`Undo: type ' world'
Undo: make bold
Still done: ["type 'Hello'"]
Next undo would be: type 'Hello'`}>

```python
history = []
history.append("type 'Hello'")
history.append("make bold")
history.append("type ' world'")

print("Undo:", history.pop())   # the most recent action
print("Undo:", history.pop())
print("Still done:", history)
print("Next undo would be:", history[-1])   # peek
```

</CodeExample>

### Matching brackets

Stacks are also how code editors check that brackets match. Push every opening bracket; on a closing bracket, the **top** of the stack must be its partner:

<CodeExample output={`(a[1] + b) * {c} -> True
(] -> False
((x) -> False
print('hi')) -> False`}>

```python
def is_balanced(text):
    partners = {")": "(", "]": "[", "}": "{"}
    stack = []
    for char in text:
        if char in "([{":
            stack.append(char)
        elif char in partners:
            if not stack or stack.pop() != partners[char]:
                return False     # wrong partner, or nothing open
    return not stack             # anything left open?

for text in ["(a[1] + b) * {c}", "(]", "((x)", "print('hi'))"]:
    print(text, "->", is_balanced(text))
```

</CodeExample>

## Queues: first in, first out

A **queue** works like a queue at a shop: people join at the **back** and are served from the **front**. First in, first out (**FIFO**). Use `deque` (say "deck") from the `collections` module: `append()` joins the back and `popleft()` serves the front:

<CodeExample output={`deque(['Mei', 'Sam', 'Kai'])
Mei is served
deque(['Sam', 'Kai'])
2 Sam`}>

```python
from collections import deque

queue = deque(["Mei", "Sam"])
queue.append("Kai")          # join the back
print(queue)

first = queue.popleft()      # serve the front
print(first, "is served")
print(queue)
print(len(queue), queue[0])  # who's next?
```

</CodeExample>

Why not just use a list and `pop(0)`? Because a list keeps its items packed side by side, so removing the **first** item makes Python shift **every other item** one place to the left. Let's count those moves for a queue of 1000 people:

<CodeExample output={`list.pop(0): 499500 item moves
deque.popleft(): 0 item moves`}>

```python
line = list(range(1000))
moves = 0
while line:
    moves += len(line) - 1   # everyone behind shifts left
    line.pop(0)
print(f"list.pop(0): {moves} item moves")
print("deque.popleft(): 0 item moves")
```

</CodeExample>

`list.pop(0)` is **O(n)**, so emptying a list this way is O(n²). A `deque` is built to add and remove at **both** ends in O(1).

<Callout type="tip" title="Stack or queue?">

Most recent first (undo, "back" button, matching brackets)? **Stack**: a list with `append` / `pop`. Oldest first (print jobs, customers, tasks waiting their turn)? **Queue**: a `deque` with `append` / `popleft`.

</Callout>

## Priority queues with heapq

Sometimes the most **important** item should go first, not the oldest, like a hospital treating the most urgent patient first. That's a **priority queue**. The `heapq` module turns a plain list into a **heap**, which always keeps the **smallest** item at index `0`. Store `(priority, item)` tuples, with smaller numbers meaning more urgent:

<CodeExample output={`next up: (1, 'call the bank')
1 call the bank
1 fix the website
2 reply to email
3 water the plants`}>

```python
import heapq

tasks = []
heapq.heappush(tasks, (2, "reply to email"))
heapq.heappush(tasks, (1, "fix the website"))
heapq.heappush(tasks, (3, "water the plants"))
heapq.heappush(tasks, (1, "call the bank"))

print("next up:", tasks[0])     # peek at the smallest
while tasks:
    priority, task = heapq.heappop(tasks)
    print(priority, task)
```

</CodeExample>

Tuples compare item by item, so equal priorities are ordered by the task name. `heappush` and `heappop` are **O(log n)**, much faster than sorting the whole list every time a new task arrives.

## Dicts and sets are hash maps

In most languages, a structure that maps keys to values using hashing is called a **hash map** (or hash table). In Python that's the **dict**, and a **set** is a hash map with keys only. As you saw in [Big-O](/learn/python/big-o), looking up a key is **O(1) on average**. Four patterns use that superpower over and over:

1. **Counting**: `Counter(words)` (from [Modules and Imports](/learn/python/modules-and-imports)) or `counts[word] = counts.get(word, 0) + 1`.
2. **Grouping**: put items with the same key into one list.
3. **Remembering what you've seen**: like the `seen` set in `has_duplicates`.
4. **Caching**: storing answers you've already worked out, like the `memo` dict in [Recursion](/learn/python/recursion).

Here's grouping: words are **anagrams** if they have the same letters, so their sorted letters make a perfect key:

<CodeExample output={`['listen', 'silent', 'enlist']
['google']`}>

```python
from collections import defaultdict

words = ["listen", "google", "silent", "enlist"]
groups = defaultdict(list)
for word in words:
    key = "".join(sorted(word))     # "eilnst"
    groups[key].append(word)

for group in groups.values():
    print(group)
```

</CodeExample>

And here's a famous interview puzzle, **two-sum**: find two numbers in a list that add up to a target. Checking every pair is O(n²). With a dict that remembers each number's position, one pass is enough, O(n):

<CodeExample output={`(3, 4)
None`}>

```python
def two_sum(numbers, target):
    seen = {}                      # number -> its index
    for i, number in enumerate(numbers):
        needed = target - number
        if needed in seen:         # O(1) lookup
            return seen[needed], i
        seen[number] = i
    return None

print(two_sum([8, 3, 11, 5, 7], 12))   # 5 + 7
print(two_sum([1, 2], 10))
```

</CodeExample>

## Graphs: dicts of neighbours

A **graph** is a set of things (**nodes**) joined by connections (**edges**): towns and roads, people and friendships, web pages and links. The simplest way to store one in Python is a dict that maps each node to a **list of its neighbours**:

<CodeExample output={`['Home', 'Shop', 'Lake']
False
7`}>

```python
town = {
    "Home": ["Park", "School"],
    "Park": ["Home", "Shop", "Lake"],
    "School": ["Home", "Library"],
    "Shop": ["Park", "Station"],
    "Lake": ["Park"],
    "Library": ["School", "Station"],
    "Station": ["Shop", "Library"],
}

print(town["Park"])              # where can I go from the park?
print("Lake" in town["Home"])    # is there a direct road?
print(len(town))                 # number of places
```

</CodeExample>

Here's that town as a map:

```text
Lake --- Park --- Shop --- Station
          |                  |
         Home --- School --- Library
```

## Breadth-first search

How many roads do you need from Home to every other place? **Breadth-first search** (BFS) explores the graph like ripples in a pond: first everything 1 step away, then everything 2 steps away, and so on. A **queue** keeps the places in the right order, and a dict remembers each place's distance (which also marks it as visited):

<CodeExample output={`visit Home, distance 0
visit Park, distance 1
visit School, distance 1
visit Shop, distance 2
visit Lake, distance 2
visit Library, distance 2
visit Station, distance 3`}>

```python
from collections import deque

town = {
    "Home": ["Park", "School"],
    "Park": ["Home", "Shop", "Lake"],
    "School": ["Home", "Library"],
    "Shop": ["Park", "Station"],
    "Lake": ["Park"],
    "Library": ["School", "Station"],
    "Station": ["Shop", "Library"],
}

def bfs(graph, start):
    distance = {start: 0}
    queue = deque([start])
    while queue:
        place = queue.popleft()
        print(f"visit {place}, distance {distance[place]}")
        for neighbour in graph[place]:
            if neighbour not in distance:      # not seen yet
                distance[neighbour] = distance[place] + 1
                queue.append(neighbour)
    return distance

bfs(town, "Home")
```

</CodeExample>

Because BFS finishes **all** places at distance 1 before **any** place at distance 2, the first time it reaches a place is always by a **shortest** route (counting roads). And because each place is visited once, BFS is **O(n)** in the number of places and roads.

To get the route itself, remember **where you came from** for every place. When you reach the goal, follow those links backwards and reverse:

<CodeExample output={`['Home', 'Park', 'Shop', 'Station']
['Lake', 'Park', 'Home', 'School', 'Library']
None`}>

```python
from collections import deque

town = {
    "Home": ["Park", "School"],
    "Park": ["Home", "Shop", "Lake"],
    "School": ["Home", "Library"],
    "Shop": ["Park", "Station"],
    "Lake": ["Park"],
    "Library": ["School", "Station"],
    "Station": ["Shop", "Library"],
    "Island": [],
}

def shortest_path(graph, start, goal):
    came_from = {start: None}
    queue = deque([start])
    while queue:
        place = queue.popleft()
        if place == goal:
            path = []
            while place is not None:     # walk back to start
                path.append(place)
                place = came_from[place]
            return path[::-1]
        for neighbour in graph[place]:
            if neighbour not in came_from:
                came_from[neighbour] = place
                queue.append(neighbour)
    return None                          # goal never reached

print(shortest_path(town, "Home", "Station"))
print(shortest_path(town, "Lake", "Library"))
print(shortest_path(town, "Home", "Island"))
```

</CodeExample>

<Callout type="warning" title="Always mark places as seen">

Roads go both ways, so Home lists Park and Park lists Home. Without the `if neighbour not in came_from` check, BFS would bounce between them forever. Mark a place as seen **when you add it to the queue**, not when you take it out, so it's never queued twice.

</Callout>

<Callout type="note" title="Using a stack instead">

Swap the queue for a stack (`pop()` instead of `popleft()`) and you get **depth-first search** (DFS): it runs down one road as far as it can before backing up. DFS is great for "can I get there at all?" or exploring every folder, but unlike BFS it does **not** guarantee the shortest path.

</Callout>

## Grids are graphs too

A maze drawn as a grid of characters is a graph in disguise: every open cell is a node, and its neighbours are the cells **up, down, left and right**. A cell is a `(row, col)` tuple, and four small "moves" get you to the cells around it:

<CodeExample output={`(0, 1) .
(2, 1) .
(1, 0) .
(1, 2) #`}>

```python
maze = [
    "S.#",
    "..#",
    "#.E",
]

row, col = 1, 1
for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:   # up, down, left, right
    r, c = row + dr, col + dc
    print((r, c), maze[r][c])
```

</CodeExample>

`(1, 2)` is a wall, so a solver must skip it. Cells on the **edge** need care too: from `(0, 0)`, "up" is row `-1`, and Python happily reads `maze[-1]` as the **last** row, a sneaky bug. Always check `0 <= r < len(maze)` and `0 <= c < len(maze[r])` first.

Time to put the whole module together! A maze is a list of strings: `"#"` is a wall, `"."` is open floor, `"S"` is the start and `"E"` the exit. You can move up, down, left and right, never diagonally. Finish the solver:

1. `find(maze, char)` returns the `(row, col)` of the first cell holding `char` (reading row by row), or `None`.
2. `neighbours(maze, cell)` returns a list of the cells up, down, left and right of `cell` that are **inside** the maze and **not** walls. Any order is fine.
3. `solve(maze)` uses **breadth-first search** to return the **shortest path** from `S` to `E` as a list of `(row, col)` tuples, including both ends. If the exit can't be reached, return `None`.
4. `escape_steps(maze)` returns the number of **moves** on the shortest path (one less than the number of cells), or `-1` if there's no way out.
5. `draw(maze, path)` returns a **new** list of strings where every path cell except `S` and `E` becomes `"*"`. If `path` is `None`, return the maze unchanged.

The checks try other mazes, including one with no way out. For the example, the solver should print:

```text
S.#.....
*##.###.
****#***
.##***#E
Escaped in 12 steps
```

<Hint>

`solve` is `shortest_path` from the lesson with cells instead of town names: find `start` and `end`, keep `came_from = {start: None}` and a `deque([start])`, and use `neighbours(maze, cell)` instead of `graph[place]`. For `neighbours`, loop over the four `(dr, dc)` moves and check `0 <= r < len(maze)`, `0 <= c < len(maze[r])` and `maze[r][c] != "#"`. Strings can't be changed, so in `draw` turn each row into a list with `list(line)`, change the path cells, then `"".join(...)` each row back into a string.

</Hint>

```python
from collections import deque

MOVES = [(-1, 0), (1, 0), (0, -1), (0, 1)]   # up, down, left, right


def find(maze, char):
    for row, line in enumerate(maze):
        for col, value in enumerate(line):
            if value == char:
                return (row, col)
    return None


def neighbours(maze, cell):
    row, col = cell
    result = []
    for dr, dc in MOVES:
        r, c = row + dr, col + dc
        inside = 0 <= r < len(maze) and 0 <= c < len(maze[r])
        if inside and maze[r][c] != "#":
            result.append((r, c))
    return result


def solve(maze):
    start, end = find(maze, "S"), find(maze, "E")
    if start is None or end is None:
        return None
    came_from = {start: None}
    queue = deque([start])
    while queue:
        cell = queue.popleft()
        if cell == end:
            path = []
            while cell is not None:
                path.append(cell)
                cell = came_from[cell]
            return path[::-1]
        for nxt in neighbours(maze, cell):
            if nxt not in came_from:
                came_from[nxt] = cell
                queue.append(nxt)
    return None


def escape_steps(maze):
    path = solve(maze)
    if path is None:
        return -1
    return len(path) - 1


def draw(maze, path):
    if path is None:
        return list(maze)
    grid = [list(line) for line in maze]
    for row, col in path:
        if grid[row][col] not in "SE":
            grid[row][col] = "*"
    return ["".join(line) for line in grid]


maze = [
    "S.#.....",
    ".##.###.",
    "....#...",
    ".##...#E",
]
path = solve(maze)
if path is None:
    print("No way out!")
else:
    for line in draw(maze, path):
        print(line)
    print(f"Escaped in {escape_steps(maze)} steps")
```

## Recap

- A **stack** (list `append` / `pop`) is last in, first out: undo, back buttons, matching brackets.
- A **queue** (`deque` `append` / `popleft`) is first in, first out. `list.pop(0)` is O(n), `popleft()` is O(1).
- A **priority queue** (`heapq.heappush` / `heappop`) always gives you the smallest `(priority, item)` next.
- Dicts and sets are **hash maps**: O(1) lookups for counting, grouping, remembering what you've seen and caching.
- A **graph** can be a dict of neighbour lists, and a grid is a graph of `(row, col)` cells.
- **Breadth-first search** with a queue explores in layers, so it finds **shortest paths**; a `came_from` dict lets you rebuild the route.
