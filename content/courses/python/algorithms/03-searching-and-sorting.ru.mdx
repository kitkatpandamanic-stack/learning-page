Найти нужное и расставить по порядку — две самые частые задачи в программировании. В этом уроке вы сами напишете классические алгоритмы (algorithm), **посчитаете их шаги**, чтобы увидеть, почему одни настолько быстрее других, а затем освоите встроенные инструменты, которыми программисты на Python пользуются каждый день. 🔍

## Линейный поиск: самый простой способ

Самый простой поиск проверяет элементы по очереди, пока не найдёт искомый. Он работает с **любым** списком, отсортированным или нет, и именно это делают «за кулисами» `x in items` и `items.index(x)`:

<CodeExample output={`2
-1`}>

```python
def linear_search(items, target):
    for index, item in enumerate(items):
        if item == target:
            return index
    return -1          # распространённый способ сказать «не найдено»

names = ["Mei", "Sam", "Kai", "Zoe"]
print(linear_search(names, "Kai"))
print(linear_search(names, "Ali"))
```

</CodeExample>

Как вы видели в уроке [O-нотация](/learn/python/big-o), линейный поиск работает за **O(n)**: миллион элементов может означать миллион проверок.

## Бинарный поиск: каждый раз пополам

Когда список **отсортирован**, можно действовать гораздо быстрее. Вспомните угадывание числа от 1 до 100: вы называете 50, слышите «больше» — и **половина** чисел отпадает за один ход. **Бинарный поиск** (binary search) делает то же самое: смотрит на средний элемент и отбрасывает ту половину, в которой искомого быть не может.

<CodeExample output={`low=0 high=9 mid=4 -> 16
low=5 high=9 mid=7 -> 56
low=5 high=6 mid=5 -> 23
5`}>

```python
def binary_search(items, target):
    low, high = 0, len(items) - 1
    while low <= high:
        mid = (low + high) // 2
        print(f"low={low} high={high} mid={mid} -> {items[mid]}")
        if items[mid] == target:
            return mid
        if items[mid] < target:
            low = mid + 1      # искомое в правой половине
        else:
            high = mid - 1     # искомое в левой половине
    return -1

numbers = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
print(binary_search(numbers, 23))
```

</CodeExample>

`low` и `high` отмечают ту часть списка, где искомое ещё может быть. `16` — слишком мало, поэтому всё до него включительно отбрасывается. `56` — слишком много, поэтому отбрасывается всё начиная с него. Затем находится `23` — за 3 проверки вместо 6. Если `low` обгоняет `high`, искать больше негде, и мы возвращаем `-1`.

Посчитаем проверки для списка из миллиона чисел:

<CodeExample output={`линейный поиск: 1000000 проверок
бинарный поиск: 20 проверок`}>

```python
def count_linear(items, target):
    looks = 0
    for item in items:
        looks += 1
        if item == target:
            break
    return looks

def count_binary(items, target):
    low, high, looks = 0, len(items) - 1, 0
    while low <= high:
        mid = (low + high) // 2
        looks += 1
        if items[mid] == target:
            break
        if items[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return looks

numbers = list(range(1_000_000))
print(f"линейный поиск: {count_linear(numbers, 999_999)} проверок")
print(f"бинарный поиск: {count_binary(numbers, 999_999)} проверок")
```

</CodeExample>

Вот **O(log n)** в действии: 20 проверок на миллион элементов, 30 — на миллиард.

<Callout type="warning" title="Правила бинарного поиска">

- Список **обязательно должен быть отсортирован**. На неотсортированном списке бинарный поиск уверенно выдаёт неправильные ответы.
- Пишите `while low <= high` (а не `<`), иначе пропустите последний элемент.
- Сдвигайтесь за `mid` с помощью `mid + 1` и `mid - 1`. Если написать `low = mid`, цикл может стать бесконечным.

В таких ошибках «на единицу» (off-by-one) так легко ошибиться, что даже опытные программисты обычно используют модуль `bisect`.

</Callout>

## Модуль bisect

`bisect` — это готовый и хорошо протестированный бинарный поиск в Python. `bisect_left(items, x)` возвращает позицию, на которой `x` **находится** в отсортированном списке или на которой он **должен был бы стоять**. `insort(items, x)` вставляет `x` в нужное место, чтобы список оставался отсортированным:

<CodeExample output={`3 True
4 False
[12, 25, 31, 47, 50, 58, 66, 90]`}>

```python
from bisect import bisect_left, insort

scores = [12, 25, 31, 47, 58, 66, 90]

i = bisect_left(scores, 47)
print(i, i < len(scores) and scores[i] == 47)   # нашли

i = bisect_left(scores, 50)
print(i, i < len(scores) and scores[i] == 50)   # стоял бы здесь

insort(scores, 50)
print(scores)
```

</CodeExample>

`bisect` также отлично подходит для вопросов вида «в какой диапазон попадает это число?» — например, чтобы превращать баллы в оценки:

<CodeExample output="['F', 'D', 'C', 'B', 'A']">

```python
from bisect import bisect_right

def grade(mark):
    boundaries = [50, 60, 70, 80]   # D от 50, C от 60...
    letters = "FDCBA"
    return letters[bisect_right(boundaries, mark)]

print([grade(m) for m in [35, 50, 69, 70, 99]])
```

</CodeExample>

`bisect_right(boundaries, 69)` считает, сколько границ меньше или равно 69 (их 2), и это выбирает `"C"`. Никакой лесенки из `if`/`elif` не нужно.

## Сортировка вставками

Теперь о сортировке. Почти всегда вы будете использовать `sorted()`, но если самостоятельно написать пару алгоритмов сортировки, станет понятно, **почему** одни быстрее других. К тому же это любимая тема на собеседованиях.

**Сортировка вставками** (insertion sort) похожа на то, как вы раскладываете карты в руке: берёте следующую карту и сдвигаете её влево, пока она не окажется на своём месте:

<CodeExample output={`[2, 5, 4, 1, 3]
[2, 4, 5, 1, 3]
[1, 2, 4, 5, 3]
[1, 2, 3, 4, 5]`}>

```python
def insertion_sort(items):
    items = items.copy()            # не меняем список вызывающего кода
    for i in range(1, len(items)):
        current = items[i]
        j = i - 1
        while j >= 0 and items[j] > current:
            items[j + 1] = items[j]   # сдвигаем больший элемент вправо
            j -= 1
        items[j + 1] = current
        print(items)
    return items

insertion_sort([5, 2, 4, 1, 3])
```

</CodeExample>

Каждая строка показывает список после того, как на место встала ещё одна карта; левая часть всегда отсортирована. В худшем случае каждый новый элемент проезжает мимо **всех** предыдущих, поэтому сортировка вставками — это **O(n²)**. Но на списке, который уже **почти отсортирован**, элементы почти не двигаются, и получается почти O(n). Запомните это: скоро пригодится.

## Сортировка слиянием

**Сортировка слиянием** (merge sort) использует [рекурсию](/learn/python/recursion) и простую идею: слить два **уже отсортированных** списка легко. Нужно просто раз за разом брать меньший из двух первых элементов:

<CodeExample output="[1, 2, 3, 4, 9, 10]">

```python
def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])     # один список закончился:
    result.extend(right[j:])    # добавляем остаток другого
    return result

print(merge([1, 4, 9], [2, 3, 10]))
```

</CodeExample>

Тогда сортировка слиянием выглядит так: разделить список пополам, **отсортировать каждую половину сортировкой слиянием** и слить их. Базовый случай (base case) — список из 0 или 1 элемента, он уже отсортирован:

<CodeExample output={`[1, 2, 3, 4, 5, 6, 7, 8]
['Ali', 'Kai', 'Mei', 'Zoe']`}>

```python
def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    return result + left[i:] + right[j:]

def merge_sort(items):
    if len(items) <= 1:              # базовый случай
        return items
    middle = len(items) // 2
    left = merge_sort(items[:middle])
    right = merge_sort(items[middle:])
    return merge(left, right)

print(merge_sort([5, 8, 1, 4, 7, 3, 6, 2]))
print(merge_sort(["Mei", "Zoe", "Ali", "Kai"]))
```

</CodeExample>

Список делится пополам примерно `log n` раз, и на каждом уровне деления слияние занимает около `n` шагов, поэтому сортировка слиянием всегда работает за **O(n log n)**, даже в худшем случае. Посчитаем сравнения на перемешанных списках:

<CodeExample output={`n = 10: вставками 29, слиянием 23
n = 100: вставками 2498, слиянием 549
n = 1000: вставками 244958, слиянием 8723`}>

```python
import random

def insertion_count(items):
    items, count = items.copy(), 0
    for i in range(1, len(items)):
        current, j = items[i], i - 1
        while j >= 0:
            count += 1
            if items[j] <= current:
                break
            items[j + 1] = items[j]
            j -= 1
        items[j + 1] = current
    return count

def merge_count(items):
    if len(items) <= 1:
        return items, 0
    middle = len(items) // 2
    left, a = merge_count(items[:middle])
    right, b = merge_count(items[middle:])
    result, i, j, count = [], 0, 0, a + b
    while i < len(left) and j < len(right):
        count += 1
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    return result + left[i:] + right[j:], count

random.seed(7)
for n in [10, 100, 1000]:
    items = random.sample(range(n), n)
    _, merge_steps = merge_count(items)
    print(f"n = {n}: вставками {insertion_count(items)}, "
          f"слиянием {merge_steps}")
```

</CodeExample>

Для маленьких списков разница почти не важна. А для 1000 элементов сортировка слиянием делает примерно **в 28 раз меньше работы**, и разрыв продолжает расти вместе с `n`.

## sorted() и list.sort(): используйте их

В реальном коде используйте встроенную сортировку Python. Это алгоритм под названием **Timsort**: хитрая смесь сортировки слиянием и сортировки вставками (помните: сортировка вставками отлично справляется с почти отсортированными кусками), написанная на C. Он работает за **O(n log n)** и особенно быстр на данных, которые уже частично упорядочены, — а реальные данные часто именно такие.

Вы уже знаете, что `sorted(items)` возвращает новый список, а `items.sort()` сортирует на месте, и оба принимают `key=` и `reverse=True` (из урока [Списки подробно](/learn/python/lists-in-depth)). Важно ещё одно свойство: сортировка в Python **устойчивая** (stable sort). Элементы с одинаковыми ключами сохраняют свой **исходный порядок**:

<CodeExample output="[('Sam', 'кофе'), ('Zoe', 'кофе'), ('Mei', 'чай'), ('Kai', 'чай')]">

```python
orders = [("Mei", "чай"), ("Sam", "кофе"),
          ("Kai", "чай"), ("Zoe", "кофе")]

print(sorted(orders, key=lambda order: order[1]))
```

</CodeExample>

Оба кофе идут первыми, и среди них Sam по-прежнему стоит перед Zoe, как в исходном списке. И Mei тоже остаётся перед Kai.

## Сортировка по нескольким ключам

Чтобы отсортировать по одному признаку, а при равенстве — по другому, возвращайте из ключа **кортеж** (tuple). Кортежи сравниваются поэлементно. Знак минус переворачивает **число**, чтобы сортировать его от большего к меньшему:

<CodeExample output={`Kai 90 10
Mei 90 12
Ali 75 9
Sam 75 9`}>

```python
players = [
    {"name": "Mei", "score": 90, "minutes": 12},
    {"name": "Sam", "score": 75, "minutes": 9},
    {"name": "Kai", "score": 90, "minutes": 10},
    {"name": "Ali", "score": 75, "minutes": 9},
]

# сначала больше очков, затем меньше времени, затем имя от A до Z
ranked = sorted(players, key=lambda p: (-p["score"],
                                        p["minutes"],
                                        p["name"]))
for p in ranked:
    print(p["name"], p["score"], p["minutes"])
```

</CodeExample>

Но перед строкой минус не поставишь. Чтобы при равенстве отсортировать строки от Z до A, воспользуйтесь устойчивостью: сортируйте несколько раз, начиная **с наименее важного ключа**:

<CodeExample output={`London Zoe
London Ben
Paris Sam
Paris Kai`}>

```python
people = [("Paris", "Kai"), ("London", "Ben"),
          ("Paris", "Sam"), ("London", "Zoe")]

people.sort(key=lambda p: p[1], reverse=True)   # имя от Z до A
people.sort(key=lambda p: p[0])                 # затем город от A до Z
for city, name in people:
    print(city, name)
```

</CodeExample>

Вторая сортировка упорядочивает города, а поскольку она устойчивая, имена внутри каждого города остаются в порядке от Z до A, полученном после первой сортировки.

## Первые k с помощью heapq

Нужны только **несколько лучших** элементов, например 3 самых высоких результата из миллиона? Сортировать всё целиком — расточительно. Функции `nlargest` и `nsmallest` из модуля `heapq` по ходу дела хранят только лучшие `k` и, как и `sorted()`, принимают `key`:

<CodeExample output={`[99, 95, 88]
[3, 7]
['ручка', 'кружка']`}>

```python
import heapq

scores = [72, 95, 88, 61, 99, 3, 7, 40]
print(heapq.nlargest(3, scores))
print(heapq.nsmallest(2, scores))

products = [("лампа", 25.0), ("ручка", 1.5),
            ("кружка", 6.0), ("стол", 120.0)]
cheapest = heapq.nsmallest(2, products, key=lambda p: p[1])
print([name for name, price in cheapest])
```

</CodeExample>

**Куча** (heap) — это структура, которая всегда держит наименьший элемент в начале. В следующем уроке вы будете использовать её как очередь с приоритетом (priority queue).

<Callout type="tip" title="Что выбрать?">

- Один элемент: `max()` / `min()`.
- Несколько элементов из большого списка: `heapq.nlargest(k, ...)` / `nsmallest`.
- Всё по порядку или большую часть: `sorted()`.
- Много раз ищете в одном и том же отсортированном списке: `bisect`. Ищете один раз или в неотсортированном списке: `in` или множество.

</Callout>

Бинарный поиск: начните с `low, high = 0, len(items) - 1`, крутите цикл `while low <= high`, вычисляйте `mid = (low + high) // 2` и сдвигайте `low = mid + 1` или `high = mid - 1`. Для `rank` используйте `sorted(players, key=lambda p: (-p["score"], p["minutes"], p["name"]))`, а затем списковое включение, чтобы достать имена.

</Hint>

<Solution>

```python
def binary_search(items, target):
    low, high = 0, len(items) - 1
    while low <= high:
        mid = (low + high) // 2
        if items[mid] == target:
            return mid
        if items[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1


def rank(players):
    ordered = sorted(players, key=lambda p: (-p["score"],
                                             p["minutes"],
                                             p["name"]))
    return [p["name"] for p in ordered]


numbers = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
print(binary_search(numbers, 23), binary_search(numbers, 40))

players = [
    {"name": "Mei", "score": 90, "minutes": 12},
    {"name": "Sam", "score": 75, "minutes": 9},
    {"name": "Kai", "score": 90, "minutes": 10},
    {"name": "Ali", "score": 75, "minutes": 9},
    {"name": "Zoe", "score": 60, "minutes": 5},
]
print(rank(players))
```

</Solution>

## Итоги

- **Линейный поиск** проверяет каждый элемент: O(n), работает с любым списком.
- **Бинарный поиск** на каждом шаге делит **отсортированный** список пополам: O(log n). Следите за ошибками «на единицу» или используйте `bisect`.
- `bisect_left` находит, где значение стоит или должно стоять; `insort` вставляет с сохранением порядка; `bisect_right` распределяет числа по диапазонам.
- **Сортировка вставками** — O(n²), но быстра на почти отсортированных данных; **сортировка слиянием** делит список, рекурсивно сортирует половины и сливает их: O(n log n).
- В реальном коде используйте `sorted()` / `.sort()` (**Timsort**, O(n log n), **устойчивая**). Сортируйте по нескольким ключам с помощью ключа-кортежа или нескольких устойчивых сортировок.
- `heapq.nlargest` / `nsmallest` находят первые k, не сортируя всё.
