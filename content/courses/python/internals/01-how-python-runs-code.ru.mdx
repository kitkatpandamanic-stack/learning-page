Вы уже написали на Python немало: API, тесты, асинхронный код, анализ данных. Но что на самом деле **происходит**, когда вы нажимаете «Запустить»? Senior-разработчику не нужно знать каждую деталь интерпретатора, но хорошая мысленная модель объясняет целое семейство «странных» багов: список, который меняется, хотя вы его не трогали; аргумент по умолчанию, который помнит прошлые вызовы; проверку через `is`, которая работает на вашем ноутбуке и ломается в продакшене. В этом уроке мы заглянем под капот. 🔧

## CPython: тот Python, который вы запускаете

«Python» — это язык, его определяет официальный справочник языка (language reference). Программа, которая его выполняет, называется **реализацией** (implementation). Стандартная реализация, которую вы скачиваете с python.org, — это **CPython**: интерпретатор, написанный на C. Есть и другие, например **PyPy** (быстрая реализация с JIT-компилятором) и **MicroPython** (для крошечных микроконтроллеров), но почти все используют CPython, и этот сайт тоже:

<CodeExample output={`cpython
(3, 14)`}>

```python
import sys

print(sys.implementation.name)
print(sys.version_info[:2])
```

</CodeExample>

<Callout type="note" title="CPython в вашем браузере">

PandaDev выполняет ваш код с помощью **Pyodide** — это сам CPython, скомпилированный в WebAssembly. Всё в этом уроке — настоящее поведение CPython 3.14, а не имитация. Некоторые детали (например, размеры объектов в байтах) отличаются от 64-битного ноутбука, и мы будем об этом предупреждать.

</Callout>

## От исходного кода к байт-коду

CPython не выполняет ваш текст напрямую. Работа идёт в два шага:

1. **Компиляция**: исходный код разбирается и превращается в **байт-код (bytecode)** — компактный список простых инструкций для воображаемой машины. Результат называется **объектом кода (code object)**.
2. **Интерпретация**: **цикл интерпретатора (interpreter loop)** — на C это большой цикл, по сути «прочитай следующую инструкцию, выполни её, повтори» — исполняет байт-код.

Оба шага можно сделать самостоятельно с помощью встроенных `compile()` и `exec()`:

<CodeExample output={`code
('price', 'total')
(2, None)
10`}>

```python
source = "total = price * 2"
code = compile(source, "<demo>", "exec")

print(type(code).__name__)
print(code.co_names)
print(code.co_consts)

namespace = {"price": 5}
exec(code, namespace)
print(namespace["total"])
```

</CodeExample>

Объект кода знает, какие **имена** он использует (`price`, `total`) и какие **константы** (`2`, а также `None`, который «возвращает» любой модуль). Такой объект есть и у каждой вашей функции — в `func.__code__`.

## Читаем байт-код с помощью dis

Модуль **`dis`** («дизассемблер», disassembler) показывает инструкции объекта кода:

<CodeExample output={`  3           RESUME                   0

  4           LOAD_FAST_BORROW_LOAD_FAST_BORROW 1 (a, b)
              BINARY_OP                0 (+)
              RETURN_VALUE`}>

```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
```

</CodeExample>

Как это читать: левое число — **строка исходного кода**, дальше **имя инструкции**, её аргумент и понятная человеку подсказка в скобках. Интерпретатор — это **стековая машина** (stack machine):

- `LOAD_FAST_BORROW_LOAD_FAST_BORROW` кладёт локальные переменные `a` и `b` на стек. (Это две загрузки, слитые в одну инструкцию; «borrow» — оптимизация 3.14, которая пропускает часть служебной работы, с ней вы познакомитесь в следующем уроке.)
- `BINARY_OP (+)` снимает со стека два значения, складывает их и кладёт результат.
- `RETURN_VALUE` снимает результат и возвращает его.
- `RESUME` — служебная инструкция в начале каждой функции.

Начиная с Python 3.11, CPython — это **специализирующийся адаптивный интерпретатор** (specialising adaptive interpreter): после того как функция выполнилась несколько раз, он переписывает инструкции в более быстрые версии для тех типов, которые реально встречаются. Посмотрите, как `BINARY_OP` превращается в сложение только для целых чисел:

<CodeExample output={`  3           RESUME_CHECK             0

  4           LOAD_FAST_BORROW_LOAD_FAST_BORROW 1 (a, b)
              BINARY_OP_ADD_INT        0 (+)
              RETURN_VALUE`}>

```python
import dis

def add(a, b):
    return a + b

for i in range(1000):
    add(i, 1)

dis.dis(add, adaptive=True)
```

</CodeExample>

Если потом вызвать `add("a", "b")`, специализированная инструкция заметит неподходящие типы и откатится к общей версии. Поэтому «прогретый» Python-код заметно быстрее, чем был в 3.10. С версии 3.13 в CPython есть и экспериментальный **JIT-компилятор**, но это опция сборки, и даже там, где он включён в сборку, по умолчанию он выключен, так что пока на него не рассчитывайте.

Инструкции можно изучать и как данные — через `dis.get_instructions`. Это удобно в инструментах и тестах:

<CodeExample output={`True True`}>

```python
import dis

def total(prices):
    result = 0
    for price in prices:
        result += price
    return result

ops = [i.opname for i in dis.get_instructions(total)]
print("FOR_ITER" in ops, "JUMP_BACKWARD" in ops)
```

</CodeExample>

Цикл `for` — это просто `FOR_ITER` (взять следующий элемент или выйти из цикла, если элементов больше нет) и `JUMP_BACKWARD` (вернуться в начало). Никакой магии.

<Callout type="warning" title="Байт-код — деталь реализации">

Конкретные инструкции меняются в **каждом** релизе Python (`LOAD_FAST_BORROW` до 3.14 не существовало). Используйте `dis`, чтобы разобраться в происходящем и разрешить спор, но никогда не пишите код, зависящий от конкретных опкодов, и не распространяйте файлы `.pyc` так, будто это стабильный формат.

</Callout>

## Файлы .pyc и __pycache__

Компиляция занимает время, поэтому при **импорте** модуля CPython сохраняет его байт-код в папку `__pycache__` рядом с исходником. В имя файла входит версия Python, так что несколько версий могут работать с одним проектом:

<CodeExample output={`shop/__pycache__/prices.cpython-314.pyc`}>

```python
import importlib.util

print(importlib.util.cache_from_source("shop/prices.py"))
```

</CodeExample>

В следующий раз CPython проверяет, изменился ли файл `.py` (по умолчанию он сравнивает время изменения и размер, сохранённые в `.pyc`), и если нет — сразу загружает байт-код. Несколько практических фактов:

- Кэшируются только **импортируемые** модули. Скрипт, который вы запускаете командой `python app.py`, каждый раз компилируется заново.
- Файлы `.pyc` ускоряют **запуск**, а не ваш код. Байт-код выполняется с одинаковой скоростью в обоих случаях.
- `__pycache__` должен быть в `.gitignore`. В Docker-образах байт-код часто компилируют заранее специально, чтобы контейнер стартовал быстрее:

```bash
python -m compileall src/          # заранее скомпилировать всю папку
PYTHONDONTWRITEBYTECODE=1 pytest   # вообще не записывать файлы .pyc
```

## Всё является объектом

В Python **каждое значение — объект** (object): числа, строки, `None`, а также функции, модули и классы. У каждого объекта есть **идентичность** (identity; `id()`, уникальный, пока объект жив), **тип** (`type()`) и **значение**:

<CodeExample output={`int
str
function
module
type
NoneType
<class 'type'> <class 'type'>
greet True`}>

```python
import math

def greet():
    return "hi"

for thing in [42, "panda", greet, math, int, None]:
    print(type(thing).__name__)

print(type(int), type(type))
print(greet.__name__, math.pi > 3)
```

</CodeExample>

Классы — это объекты типа `type`, а `type` является собственным типом. Запомните эту странную петлю: через неё лежит путь к метаклассам в третьем уроке этого модуля.

## Имена привязываются к объектам

Вот, пожалуй, самая полезная мысленная модель в Python: **переменные — это не коробки, а бирки с именами**. Присваивание никогда ничего не копирует, оно привязывает имя к объекту. Два имени могут быть привязаны к одному и тому же объекту:

<CodeExample output={`True True
True False
True
[1, 2, 3, 4]`}>

```python
a = [1, 2, 3]
b = a          # второе имя для ТОГО ЖЕ списка
c = [1, 2, 3]  # другой список с таким же содержимым

print(a == b, a is b)
print(a == c, a is c)
print(id(a) == id(b))

b.append(4)
print(a)
```

</CodeExample>

- `==` сравнивает **значения** (вызывает `__eq__`).
- `is` сравнивает **идентичность**: это один и тот же объект?

С вызовами функций всё точно так же. Параметр становится новым именем для объекта вызывающего кода (это иногда называют **передачей по соиспользованию**, call by sharing). Поэтому функция может **изменить** (mutate) переданный ей объект, но **перепривязка** (rebinding) параметра снаружи ничего не меняет:

<CodeExample output={`['чай', 'молоко']
panda`}>

```python
def add_item(cart, item):
    cart.append(item)      # изменяет список вызывающего кода

def rename(name):
    name = name.upper()    # перепривязывает только локальное имя

shopping = ["чай"]
add_item(shopping, "молоко")
print(shopping)

title = "panda"
rename(title)
print(title)
```

</CodeExample>

Тонкий момент: `+=` **изменяет** изменяемый объект на месте, но **перепривязывает** имя, если объект неизменяемый. Оператор один и тот же, а поведение разное, потому что у списков есть `__iadd__`, а у кортежей нет:

<CodeExample output={`[1, 2, 3]
(1, 2) (1, 2, 3)`}>

```python
nums = [1, 2]
alias = nums
nums += [3]          # += для списка: меняет на месте
print(alias)

point = (1, 2)
same = point
point += (3,)        # += для кортежа: создаёт НОВЫЙ кортеж
print(same, point)
```

</CodeExample>

## Баги алиасинга, которые встретятся в реальном коде

Как только вы начинаете видеть в именах бирки, три классических бага алиасинга (aliasing — когда у одного объекта несколько имён) становятся очевидными. Вот они все вместе:

<CodeExample output={`[[9, 0, 0], [9, 0, 0]]
[[9, 0, 0], [0, 0, 0]]
['new']
['new', 'sale']`}>

```python
grid = [[0] * 3] * 2
grid[0][0] = 9
print(grid)

grid = [[0] * 3 for _ in range(2)]
grid[0][0] = 9
print(grid)

def add_tag(tag, tags=[]):
    tags.append(tag)
    return tags

print(add_tag("new"))
print(add_tag("sale"))
```

</CodeExample>

1. **`[[0] * 3] * 2`** повторяет **один и тот же** внутренний список дважды. Обе строки — это один объект. Списковое включение (list comprehension) каждый раз создаёт новый внутренний список.
2. **Изменяемые аргументы по умолчанию**: значение по умолчанию `[]` создаётся **один раз**, когда выполняется строка `def`, и хранится в функции. Все вызовы без `tags` используют этот единственный список. Исправление — `tags=None` и `if tags is None: tags = []` внутри функции.
3. **Изменение входных данных** (здесь не показано): функция, которая вызывает `.sort()` или `.append()` для параметра, меняет данные вызывающего кода, и баг часто проявляется очень далеко от места, где он возник.

Когда вам действительно нужна независимая копия, помните: `copy.copy` делает **поверхностную** копию (внешний объект новый, а всё внутри общее), а `copy.deepcopy` копирует всё до самого дна:

<CodeExample output={`['fast', 'cheap']
['fast']`}>

```python
import copy

config = {"name": "shop", "tags": ["fast"]}
shallow = copy.copy(config)
deep = copy.deepcopy(config)

config["tags"].append("cheap")
print(shallow["tags"])
print(deep["tags"])
```

</CodeExample>

История из практики: команда закэшировала словарь «настроек по умолчанию» и отдавала его в каждый запрос, а один эндпоинт для европейских пользователей делал `settings["currency"] = "EUR"`. Меньше чем через час евро видели *все* пользователи. Исправление уместилось в один `deepcopy` (а ещё лучше — неизменяемый frozen dataclass).

## Интернирование: любопытный факт, а не возможность языка

Иногда кажется, что `is` работает для чисел и строк. Дело в том, что CPython **переиспользует** некоторые неизменяемые объекты, чтобы экономить память:

<CodeExample output={`True
False True
True False
True`}>

```python
import sys

a = int("256")
b = int("256")
print(a is b)        # маленькие целые числа кэшируются

x = int("1000")
y = int("1000")
print(x is y, x == y)

s = "".join(["pan", "da"])   # собрана во время выполнения
t = "panda"                  # литерал в коде
print(s == t, s is t)
print(sys.intern(s) is t)
```

</CodeExample>

- Целые числа от **-5 до 256** создаются один раз при запуске и используются всеми.
- Многие строки, похожие на идентификаторы (а также литералы в вашем коде), **интернируются** (interning): хранятся в таблице в единственном экземпляре. `sys.intern()` позволяет интернировать строки самостоятельно, и это может сэкономить память, когда у вас миллионы повторяющихся ключей.
- Компилятор также может объединять одинаковые константы внутри одного файла, поэтому `x = 1000; y = 1000; x is y` в одном месте может дать `True`, а в другом — `False`.

<Callout type="danger" title="Никогда не сравнивайте значения через is">

Для сравнения чисел, строк, списков и прочего используйте `==`. `is` — только для **синглтонов** (singletons): `x is None`, `x is True`/`False` (редко) или для объектов-сентинелов, которые вы создали сами. Python даже выдаёт `SyntaxWarning`, если написать `x is 1000`. Код, который полагается на интернирование, работает в тестах и ломается на больших или вычисленных значениях.

</Callout>

## Фреймы и стек вызовов

При каждом вызове функции CPython создаёт **фрейм** (frame): локальные переменные функции, ссылку на её объект кода, текущую инструкцию и ссылку на фрейм **вызывающей** функции. Эти ссылки образуют **стек вызовов** (call stack) — именно его печатает трейсбек, когда что-то идёт не так.

Пройти по нему можно и самостоятельно (`sys._getframe` есть только в CPython; переносимый, но более медленный вариант — `inspect.stack()`):

<CodeExample output={`['pay', 'checkout']
1000`}>

```python
import sys

def call_stack():
    frame = sys._getframe(1)   # пропускаем этот хелпер
    names = []
    while frame.f_code.co_name != "<module>":
        names.append(frame.f_code.co_name)
        frame = frame.f_back
    return names

def checkout():
    return pay()

def pay():
    return call_stack()

print(checkout())
print(sys.getrecursionlimit())
```

</CodeExample>

Python ограничивает глубину стека (**лимит рекурсии**, recursion limit, по умолчанию 1000) и при его превышении выбрасывает `RecursionError`, а не роняет процесс. Поэтому глубокую рекурсию по большим данным (например, обход длинного связного списка) в Python лучше превращать в цикл. Отладчики, профилировщики и логирование читают фреймы, чтобы понять «где я?»; вы будете опираться на это при профилировании в следующем модуле.

1. `make_board(rows, cols)`: каждая строка поля должна быть **отдельным** списком.
2. `add_score(name, score, scores=...)`: при вызове без `scores` функция каждый раз должна начинать с **нового** словаря; если словарь передан, она должна по-прежнему обновить и вернуть **именно его**.
3. `top_three(scores)`: верните три лучших результата, от большего к меньшему, **не изменяя** переданный список.

<Hint>

Для поля используйте списковое включение: `[["."] * cols for _ in range(rows)]` (внутреннее `* cols` здесь безопасно, потому что строки неизменяемы). Для значения по умолчанию используйте `scores=None` и создавайте словарь внутри: `if scores is None: scores = {}`. Для `top_three`: `sorted()` возвращает новый список, а `.sort()` меняет исходный.

</Hint>

<Solution>

```python
def make_board(rows, cols):
    """Поле rows x cols, заполненное '.'."""
    return [["."] * cols for _ in range(rows)]


def add_score(name, score, scores=None):
    """Добавляет очки в scores (новый словарь, если не передан)."""
    if scores is None:
        scores = {}
    scores[name] = score
    return scores


def top_three(scores):
    """Три лучших результата, от большего к меньшему."""
    return sorted(scores, reverse=True)[:3]


board = make_board(2, 3)
board[0][0] = "X"
print(board)

print(add_score("mei", 5))
print(add_score("li", 7))

results = [3, 9, 1, 7]
print(top_three(results), results)
```

</Solution>

</Exercise>

## Итоги

- **CPython** компилирует исходный код в **байт-код** (объект кода), а затем его **цикл интерпретатора** выполняет этот байт-код на стековой машине.
- **`dis`** показывает байт-код; начиная с 3.11 интерпретатор **специализирует** горячие инструкции под встречающиеся типы. Опкоды меняются в каждом релизе, поэтому никогда не полагайтесь на них.
- Импортированные модули кэшируются в виде файлов **`.pyc`** в `__pycache__`; это ускоряет запуск, а не выполнение.
- **Всё является объектом** с идентичностью, типом и значением; даже функции, модули и классы.
- **Имена привязываются к объектам**; присваивание и вызов функции никогда не копируют. `==` сравнивает значения, `is` — идентичность.
- Остерегайтесь **багов алиасинга**: `[[x] * n] * m`, изменяемых аргументов по умолчанию и функций, которые меняют свои входные данные. `copy.deepcopy` создаёт полностью независимые копии.
- **Интернирование** маленьких целых чисел и строк — это трюк для экономии памяти; используйте `is` только для `None` и других синглтонов.
- Каждый вызов получает **фрейм**; фреймы связываются в **стек вызовов**, который читают трейсбеки, отладчики и профилировщики.
