Каждый программист — и в первый день, и через двадцать лет — пишет код, который ломается. Разница в том, что опытные программисты **читают сообщение об ошибке** (error), а не паникуют. Сообщение об ошибке — это не выговор: это Python показывает на проблему и рассказывает, что он увидел. В этом уроке вы научитесь читать такие сообщения и шаг за шагом находить баги. 🔍

## Читаем трейсбек

Вот небольшая программа с ошибкой. В ней три функции, которые вызывают друг друга:

```python title="main.py"
def average(scores):
    total = sum(scores)
    return total / len(scores)

def report(name, scores):
    avg = average(scores)
    return f"{name}: {avg}"

print(report("Mei", [80, 90]))
print(report("Sam", []))
```

Если запустить её на своём компьютере, она выведет строку для Mei, а затем **трейсбек** (traceback):

```text
Mei: 85.0
Traceback (most recent call last):
  File "main.py", line 10, in <module>
    print(report("Sam", []))
          ~~~~~~^^^^^^^^^^^
  File "main.py", line 6, in report
    avg = average(scores)
  File "main.py", line 3, in average
    return total / len(scores)
           ~~~~~~^~~~~~~~~~~~~
ZeroDivisionError: division by zero
```

Читайте его **снизу вверх**:

1. **Последняя строка** говорит, *что* пошло не так: тип ошибки (`ZeroDivisionError`) и сообщение (`division by zero` — «деление на ноль»).
2. **Строки выше** — это **стек вызовов** (call stack): цепочка вызовов функций, которая привела к ошибке. *Most recent call last* («последний вызов — внизу») означает, что нижняя запись — это место, где Python на самом деле остановился: строка 3 внутри `average`.
3. Поднимаясь выше, вы видите, **кто кого вызвал**: `average` вызвала `report` в строке 6, а саму `report` вызвали в строке 10. Значки `^^^` указывают на тот самый кусок кода, который сломался.

Получается такая история: строка 10 вызвала `report` с пустым списком, `report` передала его в `average`, а `average` разделила на `len(scores)`, то есть на `0`.

Заметьте, что сначала напечаталось `Mei: 85.0`. Python выполняет код сверху вниз, и всё, что было до падения, действительно произошло. На PandaDev в выводе показывается последняя строка трейсбека вместе с номером строки:

<CodeExample output={`Mei: 85.0
ZeroDivisionError: division by zero`}>

```python
def average(scores):
    total = sum(scores)
    return total / len(scores)

def report(name, scores):
    avg = average(scores)
    return f"{name}: {avg}"

print(report("Mei", [80, 90]))
print(report("Sam", []))
```

</CodeExample>

<Callout type="tip" title="Сначала последняя строка">

Когда видите красный текст, сначала прочитайте **последнюю строку**, а потом найдите в коде **номер строки**. Чаще всего этого достаточно.

</Callout>

## Ошибки, которые встречаются чаще всего

Эти несколько типов ошибок покрывают большинство багов новичков. Запомните, что каждая из них *обычно* означает, — и часто вы сразу будете знать, как её исправить:

| Ошибка | Что она обычно означает | Пример |
| --- | --- | --- |
| `NameError` | Опечатка в имени или переменная, которую используют до того, как создали | `print(scroe)` |
| `TypeError` | Смешаны несовместимые типы или функция вызвана с неправильным числом аргументов | `"Age: " + 12` |
| `ValueError` | Тип правильный, но значение Python использовать не может | `int("twelve")` |
| `IndexError` | Позиции в списке не существует | `["cat", "dog"][2]` |
| `KeyError` | Ключа в словаре не существует (словари будут на Уровне 1) | `prices["coffee"]` |
| `ZeroDivisionError` | Деление на ноль — часто потому, что что-то оказалось пустым | `total / len([])` |
| `SyntaxError` | Python даже не может прочитать код: не хватает `:`, скобки или кавычки | `if x > 3` |
| `IndentationError` | Неправильные пробелы в начале строки | тело функции без отступа |

Сообщение после типа ошибки даёт подробности. Несколько настоящих примеров:

```text
NameError: name 'scroe' is not defined. Did you mean: 'score'?
TypeError: can only concatenate str (not "int") to str
TypeError: area() missing 1 required positional argument: 'height'
ValueError: invalid literal for int() with base 10: 'twelve'
IndexError: list index out of range
```

При опечатках Python даже предлагает исправление: *Did you mean: 'score'?* («Возможно, вы имели в виду 'score'?»). Читайте последнюю строку целиком: ответ часто прямо в ней.

### Коварный случай: None

Эта ошибка `TypeError` поначалу сбивает с толку почти всех:

```python
def double(n):
    print(n * 2)       # выводит, но не возвращает!

x = double(4)
print(x + 1)
```

```text
8
Traceback (most recent call last):
  File "main.py", line 5, in <module>
    print(x + 1)
          ~~^~~
TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'
```

`NoneType` в сообщении — важная подсказка: какое-то значение равно `None`. Здесь `double` вывела `8`, но ничего не **вернула**, а, как вы видели в уроке [Пишем функции](/learn/python/writing-functions), функция без `return` возвращает `None`. Исправление — `return n * 2`.

### Синтаксические ошибки: код даже не запускается

`SyntaxError` или `IndentationError` возникает **до** запуска программы, потому что Python вообще не может понять код. Кроме ошибки, ничего не выводится:

```text
  File "main.py", line 1
    if score > 10
                 ^
SyntaxError: expected ':'
```

```text
  File "main.py", line 2
    print(f"Hello, {name}!")
    ^^^^^
IndentationError: expected an indented block after function definition on line 1
```

<Callout type="warning" title="Смотрите и на строку выше">

При синтаксических ошибках Python сообщает о месте, где он **заметил** проблему, а это может быть на строку-две позже настоящей ошибки. Если строка 5 выглядит нормально, проверьте строку 4: не пропущена ли `)` или `"`. Сообщение вроде `'(' was never closed` («`(` так и не закрыта») — сильная подсказка.

</Callout>

## Порядок отладки

Когда что-то идёт не так, не меняйте всё подряд в надежде, что заработает. Каждый раз спокойно проходите одни и те же шаги **отладки** (debugging):

1. **Прочитайте сообщение.** Какой тип ошибки? Что говорит сообщение?
2. **Найдите строку.** Перейдите к номеру строки из трейсбека. Если она внутри функции, посмотрите и на строку, которая эту функцию вызвала.
3. **Выведите значения.** Посмотрите, что *на самом деле* лежит в переменных.
4. **Проверьте свои предположения.** Действительно ли у переменной тот тип и размер, которые вы ожидаете?
5. **Меняйте что-то одно за раз**, а потом запускайте снова. Если поменять три вещи сразу, вы не узнаете, какая из них помогла (или сломала что-то новое).
6. **Объясните код резиновой уточке.** Об этом чуть ниже.

### Выводим значения с помощью `f"{x=}"`

Самый быстрый инструмент отладки — `print`. Если в f-строке поставить `=` после имени, будут выведены **имя и значение** вместе, и подписи печатать не придётся:

<CodeExample output={`price=3 total=3
price=5 total=5
price=2 total=2
2`}>

```python
def total_price(prices):
    for price in prices:
        total = 0
        total += price
        print(f"{price=} {total=}")
    return total

print(total_price([3, 5, 2]))
```

</CodeExample>

Сумма должна быть `10`, но вывод показывает, что на каждом проходе цикла она **начинается заново**. Это прямо указывает на баг: `total = 0` стоит внутри цикла, поэтому обнуляется на каждом элементе. Перенесите эту строку над `for` — и функция заработает. Когда всё исправлено, удалите отладочные `print`.

### Проверяем предположения

Баги часто прячутся в том, в чём вы были *уверены*. Форма с `=` показывает строки в кавычках, поэтому коварную проблему с типом легко заметить:

<CodeExample output={`quantity='3'
33
type(quantity)=<class 'str'>`}>

```python
quantity = "3"   # представьте, что это пришло из формы
print(f"{quantity=}")
print(quantity * 2)
print(f"{type(quantity)=}")
```

</CodeExample>

Кавычки вокруг `'3'` всё выдают: это текст, а не число, поэтому `* 2` повторяет его, а не удваивает. Ошибки нет, просто ответ неверный. Исправляет это `int(quantity)`. Баги без сообщения об ошибке называют **логическими ошибками** (logic errors), и вывод значений — способ их поймать.

<Callout type="tip" title="Метод резиновой уточки 🦆">

Объясните свой код строка за строкой вслух резиновой уточке (или цветку, или плюшевой панде). *«Эта строка обнуляет total, потом для каждой цены... ой, она снова его обнуляет».* Когда вы проговариваете, что каждая строка делает **на самом деле**, а не что вы хотели, находится удивительно много багов. Программисты правда так делают!

</Callout>

## assert: быстрая проверка

`assert` проверяет, что то, во что вы верите, **действительно** верно. Если да, ничего не происходит. Если нет, Python останавливается с ошибкой `AssertionError` и вашим сообщением:

<CodeExample output={`5.0
Всё в порядке!`}>

```python
def average(scores):
    assert len(scores) > 0, "average() нужна хотя бы одна оценка"
    return sum(scores) / len(scores)

print(average([4, 6]))

assert average([4, 6]) == 5
assert average([1, 2, 3]) == 2
print("Всё в порядке!")
```

</CodeExample>

Обе проверки прошли молча. Теперь добавьте в конец `print(average([]))` и запустите снова:

```text
Traceback (most recent call last):
  File "main.py", line 10, in <module>
    print(average([]))
          ~~~~~~~^^^^
  File "main.py", line 2, in average
    assert len(scores) > 0, "average() нужна хотя бы одна оценка"
           ^^^^^^^^^^^^^^^^
AssertionError: average() нужна хотя бы одна оценка
```

Вместо загадочной `ZeroDivisionError` где-то в глубине вы получаете понятное сообщение прямо там, где нарушилось предположение. Несколько строк `assert` после функции, например `assert average([4, 6]) == 5`, — ещё и дешёвый способ проверять, что она по-прежнему работает после каждого изменения.

<Callout type="note" title="assert — чтобы ловить собственные ошибки">

Используйте `assert` для того, что **никогда** не должно случиться, если код правильный. Для ожидаемых проблем, например если пользователь ввёл `"ten"` вместо `10`, делайте проверку через `if` и показывайте дружелюбное сообщение. На Уровне 1 в уроке [Исключения](/learn/python/exceptions) вы научитесь перехватывать ошибки с помощью `try` и `except`, а позже будете писать целые файлы тестов, полные `assert`.

</Callout>

<Hint>

Разбирайтесь с одной ошибкой за раз. `NameError` означает имя с опечаткой. Внимательно проверьте `grade(50)`: верно ли, что `50 > 50`? И `+` не умеет соединять текст и число, так что в `report` используйте f-строку.

```python
def average(scores):
    # среднее по оценкам или 0, если список пуст
    if len(scores) == 0:
        return 0
    total = 0
    for score in scores:
        total += score
    return total / len(scores)

def grade(score):
    # 90+ — это A, 70+ — B, 50+ — C, ниже 50 — F
    if score >= 90:
        return "A"
    elif score >= 70:
        return "B"
    elif score >= 50:
        return "C"
    else:
        return "F"

def report(name, scores):
    # текст вида "Mei: 85.0 (B)"
    avg = average(scores)
    return f"{name}: {avg} ({grade(avg)})"

assert grade(50) == "C", "50 — это C"
assert report("Mei", [80, 90]) == "Mei: 85.0 (B)"
print("Все проверки пройдены!")
```

## Итоги

- Читайте трейсбек **снизу вверх**: последняя строка — это тип ошибки и сообщение, а строки выше — стек вызовов, где последний вызов внизу.
- `NameError` — обычно опечатка, `TypeError` — смешанные типы (или `None` из функции, где забыли `return`), `ValueError` — неподходящее значение, `IndexError`/`KeyError` — нет такой позиции или ключа.
- `SyntaxError` и `IndentationError` останавливают код ещё до запуска; проверяйте и строку выше.
- Порядок отладки: прочитать сообщение, найти строку, вывести значения через `f"{x=}"`, проверить предположения, менять что-то одно за раз, объяснить код уточке.
- `assert condition, "сообщение"` останавливает программу с `AssertionError`, когда то, во что вы верите, оказывается неверным.
