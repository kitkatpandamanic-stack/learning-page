JSON files are fine for one user's settings. But a real app might have thousands of users changing data at the same time, and needs to answer questions like *"which 10 books were borrowed most this month?"* in milliseconds. That's the job of a **database**. 🗄️

Most databases you'll meet (PostgreSQL, MySQL, SQLite) are **relational**, and you talk to them in **SQL** (Structured Query Language). Python ships with **SQLite**, a small but complete database, in the `sqlite3` module, so you can learn real SQL right here.

## Tables, rows and primary keys

A relational database stores data in **tables**. Each table has fixed **columns** (with types), and each record is a **row**:

| id | title   | author        | year |
| -- | ------- | ------------- | ---- |
| 1  | Dune    | Frank Herbert | 1965 |
| 2  | Emma    | Jane Austen   | 1815 |

The `id` column is the **primary key**: a value that is unique for every row and never changes. Titles can repeat (two books can both be called *Emma*), but id `2` always means exactly one row. Other tables use it to point at this row, as you'll see with JOINs.

## Creating a table and adding rows

`sqlite3.connect(":memory:")` opens a database that lives in memory (perfect for learning and for tests). `conn.execute()` runs one SQL statement:

<CodeExample output={`2
[(1, 'Dune', 'Frank Herbert', 1965), (2, 'Emma', 'Jane Austen', 1815)]`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")   # a database in memory
conn.execute("""
    CREATE TABLE books (
        id INTEGER PRIMARY KEY,
        title TEXT NOT NULL,
        author TEXT NOT NULL,
        year INTEGER
    )
""")

conn.execute(
    "INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
    ("Dune", "Frank Herbert", 1965),
)
cursor = conn.execute(
    "INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
    ("Emma", "Jane Austen", 1815),
)
print(cursor.lastrowid)
conn.commit()

rows = conn.execute("SELECT * FROM books").fetchall()
print(rows)
```

</CodeExample>

- **`CREATE TABLE`** lists the columns with their types (`INTEGER`, `TEXT`, `REAL`…) and rules: `NOT NULL` means the value is required.
- An `INTEGER PRIMARY KEY` fills itself in: SQLite gives each new row the next id. **`cursor.lastrowid`** tells you which one.
- **`INSERT INTO ... VALUES (?, ?, ?)`** adds a row. The `?` marks are **placeholders**; the actual values come in a tuple. More on why in a moment.
- **`conn.commit()`** saves the changes for good.
- **`SELECT * FROM books`** reads every column (`*`) of every row. `fetchall()` gives you a list of tuples.

SQL keywords aren't case-sensitive, but writing them in CAPITALS is the common style: it makes the SQL easy to spot.

## SELECT with WHERE, ORDER BY and LIMIT

`executemany()` runs the same INSERT for every tuple in a list. Then `SELECT` can pick **columns**, filter rows with **`WHERE`**, sort with **`ORDER BY`** (add `DESC` for largest first) and keep only the first few with **`LIMIT`**:

<CodeExample output={`('Matilda', 1988)
('The BFG', 1982)
('Dune', 1965)
[('The BFG', 208), ('Matilda', 240)]
(2,)
2`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE books (id INTEGER PRIMARY KEY, "
             "title TEXT, author TEXT, year INTEGER, pages INTEGER)")
books = [
    ("Dune", "Frank Herbert", 1965, 412),
    ("Emma", "Jane Austen", 1815, 474),
    ("Matilda", "Roald Dahl", 1988, 240),
    ("Persuasion", "Jane Austen", 1817, 249),
    ("The BFG", "Roald Dahl", 1982, 208),
]
conn.executemany(
    "INSERT INTO books (title, author, year, pages) "
    "VALUES (?, ?, ?, ?)",
    books,
)

for row in conn.execute(
    "SELECT title, year FROM books WHERE year > 1900 "
    "ORDER BY year DESC"
):
    print(row)

shortest = conn.execute(
    "SELECT title, pages FROM books ORDER BY pages LIMIT 2"
).fetchall()
print(shortest)

austen = conn.execute(
    "SELECT COUNT(*) FROM books WHERE author = ?",
    ("Jane Austen",),
).fetchone()
print(austen)
print(austen[0])
```

</CodeExample>

You can loop over the result of `execute()` directly, call `fetchall()` for a list, or **`fetchone()`** for just the next row (or `None` if there isn't one). Watch the comma in `("Jane Austen",)`: that's a tuple with one item. Without it, it's just a string in brackets.

`WHERE` understands `=`, `!=`, `<`, `>`, `<=`, `>=`, `AND`, `OR`, `NOT`, `IN (...)`, `BETWEEN`, `IS NULL`, and `LIKE 'Dun%'` for simple patterns.

## Rows you can read by name

Tuples like `row[1]` get hard to read. Set **`conn.row_factory = sqlite3.Row`** and you can use column names, or turn a row into a dict:

<CodeExample output={`Dune 1965
{'id': 1, 'title': 'Dune', 'author': 'Frank Herbert', 'year': 1965}
None`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.row_factory = sqlite3.Row      # rows act like dicts
conn.execute("CREATE TABLE books (id INTEGER PRIMARY KEY, "
             "title TEXT, author TEXT, year INTEGER)")
conn.execute(
    "INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
    ("Dune", "Frank Herbert", 1965),
)

row = conn.execute("SELECT * FROM books WHERE id = ?", (1,)).fetchone()
print(row["title"], row["year"])
print(dict(row))

missing = conn.execute(
    "SELECT * FROM books WHERE id = ?", (99,)
).fetchone()
print(missing)
```

</CodeExample>

## UPDATE and DELETE

**`UPDATE`** changes columns in existing rows and **`DELETE`** removes rows. **`cursor.rowcount`** tells you how many rows were affected:

<CodeExample output={`updated: 1
deleted: 2
[('Dune', 896), ('Emma', 474)]`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE books (id INTEGER PRIMARY KEY, "
             "title TEXT, author TEXT, pages INTEGER)")
conn.executemany(
    "INSERT INTO books (title, author, pages) VALUES (?, ?, ?)",
    [("Dune", "Frank Herbert", 412), ("Emma", "Jane Austen", 474),
     ("Matilda", "Roald Dahl", 240), ("The BFG", "Roald Dahl", 208)],
)

cursor = conn.execute(
    "UPDATE books SET pages = ? WHERE title = ?", (896, "Dune")
)
print("updated:", cursor.rowcount)

cursor = conn.execute(
    "DELETE FROM books WHERE author = ?", ("Roald Dahl",)
)
print("deleted:", cursor.rowcount)
conn.commit()

print(conn.execute("SELECT title, pages FROM books").fetchall())
```

</CodeExample>

<Callout type="danger" title="Don't forget WHERE">

`UPDATE books SET pages = 0` and `DELETE FROM books` without a `WHERE` change **every row** in the table. There's no undo button once you commit. A `rowcount` of `0` is also useful: it means nothing matched, for example an id that doesn't exist.

</Callout>

## Counting and grouping

**Aggregate functions** turn many rows into one value: `COUNT(*)`, `SUM()`, `AVG()`, `MIN()` and `MAX()`. With **`GROUP BY`** you get one result row per group, like a report:

<CodeExample output={`(5, 1583, 474)
('Jane Austen', 2, 361.5)
('Roald Dahl', 2, 224.0)
('Frank Herbert', 1, 412.0)`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE books (id INTEGER PRIMARY KEY, "
             "title TEXT, author TEXT, pages INTEGER)")
conn.executemany(
    "INSERT INTO books (title, author, pages) VALUES (?, ?, ?)",
    [("Dune", "Frank Herbert", 412), ("Emma", "Jane Austen", 474),
     ("Matilda", "Roald Dahl", 240), ("Persuasion", "Jane Austen", 249),
     ("The BFG", "Roald Dahl", 208)],
)

print(conn.execute(
    "SELECT COUNT(*), SUM(pages), MAX(pages) FROM books"
).fetchone())

rows = conn.execute("""
    SELECT author, COUNT(*) AS books, AVG(pages)
    FROM books
    GROUP BY author
    ORDER BY books DESC, author
""").fetchall()
for row in rows:
    print(row)
```

</CodeExample>

`AS books` gives the count a name, so we can sort by it. Letting the database do the counting is much faster than fetching every row into Python and counting there, especially with millions of rows.

## Joining two tables

Storing the author's name in every book row repeats data: rename an author and you'd have to fix many rows. Real schemas give authors their own table and store only the author's id in each book. That column is a **foreign key**. A **`JOIN`** puts the tables back together in a query:

<CodeExample output={`Emma by Jane Austen
Matilda by Roald Dahl
Persuasion by Jane Austen`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.executescript("""
    CREATE TABLE authors (
        id INTEGER PRIMARY KEY,
        name TEXT NOT NULL
    );
    CREATE TABLE books (
        id INTEGER PRIMARY KEY,
        title TEXT NOT NULL,
        author_id INTEGER REFERENCES authors(id)
    );
    INSERT INTO authors (name) VALUES ('Jane Austen'), ('Roald Dahl');
    INSERT INTO books (title, author_id) VALUES
        ('Emma', 1), ('Matilda', 2), ('Persuasion', 1);
""")

rows = conn.execute("""
    SELECT books.title, authors.name
    FROM books
    JOIN authors ON books.author_id = authors.id
    ORDER BY books.title
""").fetchall()
for title, name in rows:
    print(f"{title} by {name}")
```

</CodeExample>

`executescript()` runs several statements separated by `;`. `JOIN authors ON books.author_id = authors.id` matches every book with the author whose `id` equals its `author_id`. Writing `table.column` avoids confusion when both tables have a column with the same name (like `id`).

## Parameters and SQL injection

It's tempting to build SQL with an f-string. **Never do this with values**, because whatever the user types becomes part of your SQL. Watch what a cunning "name" does:

<CodeExample output={`SELECT * FROM users WHERE name = 'nobody' OR '1'='1'
[('mei', 'bamboo42'), ('sam', 'hunter2')]
[]`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE users (name TEXT, secret TEXT)")
conn.executemany("INSERT INTO users VALUES (?, ?)",
                 [("mei", "bamboo42"), ("sam", "hunter2")])

name = "nobody' OR '1'='1"     # typed by an attacker

# ❌ f-string: the input becomes part of the SQL
sql = f"SELECT * FROM users WHERE name = '{name}'"
print(sql)
print(conn.execute(sql).fetchall())

# ✅ parameter: the input is only ever a value
print(conn.execute(
    "SELECT * FROM users WHERE name = ?", (name,)
).fetchall())
```

</CodeExample>

The f-string version turned the condition into *"name is nobody OR 1 equals 1"*, which is true for every row, so it leaked everyone's secret. This is **SQL injection**, one of the most common security holes on the web. With a `?` placeholder, the database receives the SQL and the value **separately**, so the value can never change the query. It also fixes an everyday bug: a name like `O'Brien` would break the f-string version.

<Callout type="warning" title="The rule">

Values always go in as **parameters** (`?` in sqlite3; other libraries use `%s` or `:name`). Only use f-strings for parts you control completely in your own code, never for anything that came from a user, a file or a request.

</Callout>

## Transactions: all or nothing

Changes you make are part of a **transaction**. `commit()` makes them permanent; **`rollback()`** throws away everything since the last commit. That matters when several changes belong together, like moving money between two accounts: either both updates happen or neither does.

Using the connection in a **`with`** block does this for you: it commits if the block succeeds and rolls back if an exception happens:

<CodeExample output={`[('mei', 70), ('sam', 50)]
Failed: CHECK constraint failed: balance >= 0
[('mei', 70), ('sam', 50)]`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE accounts (name TEXT PRIMARY KEY, "
             "balance INTEGER NOT NULL CHECK (balance >= 0))")
conn.executemany("INSERT INTO accounts VALUES (?, ?)",
                 [("mei", 100), ("sam", 20)])
conn.commit()

def transfer(conn, sender, receiver, amount):
    with conn:   # commit on success, roll back on error
        conn.execute(
            "UPDATE accounts SET balance = balance + ? "
            "WHERE name = ?", (amount, receiver))
        conn.execute(
            "UPDATE accounts SET balance = balance - ? "
            "WHERE name = ?", (amount, sender))

transfer(conn, "mei", "sam", 30)
print(conn.execute("SELECT * FROM accounts").fetchall())

try:
    transfer(conn, "sam", "mei", 500)   # sam can't afford it
except sqlite3.IntegrityError as error:
    print("Failed:", error)
print(conn.execute("SELECT * FROM accounts").fetchall())
```

</CodeExample>

In the failed transfer, Mei's balance was already increased by 500 when the second update broke the `CHECK` rule. The rollback undid that too, so nobody got free money. 🐼

<Callout type="tip" title="SQLite in real projects">

SQLite stores a whole database in a single file (`sqlite3.connect("library.db")`) and needs no server, so it's great for small apps, desktop tools, phones and tests. Bigger web apps usually use **PostgreSQL**. The SQL you learnt here works almost the same in both.

</Callout>

## Recap

- A relational database stores **rows** in **tables** with typed **columns**; the **primary key** identifies each row.
- `sqlite3.connect(":memory:")` gives you a real SQL database in memory; `conn.execute()` runs SQL.
- `CREATE TABLE`, `INSERT`, `SELECT ... WHERE ... ORDER BY ... LIMIT`, `UPDATE` and `DELETE` cover everyday work. Never forget `WHERE` on UPDATE/DELETE.
- `fetchall()`, `fetchone()`, `lastrowid` and `rowcount` give you results; `sqlite3.Row` lets you use column names.
- `COUNT`, `SUM`, `AVG` with `GROUP BY` build reports; a **foreign key** plus `JOIN` combines tables.
- Always pass values as **`?` parameters**, never with f-strings: that prevents **SQL injection**.
- `commit()` saves, `rollback()` undoes; `with conn:` makes a group of changes all-or-nothing.
