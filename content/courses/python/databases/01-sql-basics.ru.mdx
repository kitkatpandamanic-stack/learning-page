Для настроек одного пользователя JSON-файлов вполне хватает. Но в настоящем приложении тысячи пользователей могут менять данные одновременно, а на вопросы вроде *«какие 10 книг чаще всего брали в этом месяце?»* нужно отвечать за миллисекунды. Это работа для **базы данных (database)**. 🗄️

Большинство баз данных, с которыми вы встретитесь (PostgreSQL, MySQL, SQLite), — **реляционные (relational)**, и общаются с ними на языке **SQL** (Structured Query Language, язык структурированных запросов). В Python есть модуль `sqlite3` со встроенной **SQLite** — маленькой, но полноценной базой данных, так что настоящий SQL можно изучать прямо здесь.

## Таблицы, строки и первичные ключи

Реляционная база данных хранит данные в **таблицах (tables)**. У каждой таблицы есть фиксированный набор **столбцов (columns)** с типами, а каждая запись — это **строка (row)**:

| id | title   | author        | year |
| -- | ------- | ------------- | ---- |
| 1  | Dune    | Frank Herbert | 1965 |
| 2  | Emma    | Jane Austen   | 1815 |

Столбец `id` — это **первичный ключ (primary key)**: значение, уникальное для каждой строки и никогда не меняющееся. Названия могут повторяться (две разные книги вполне могут называться *Emma*), но id `2` всегда означает ровно одну строку. Другие таблицы ссылаются на строку именно по нему — вы увидите это, когда дойдём до JOIN.

## Создаём таблицу и добавляем строки

`sqlite3.connect(":memory:")` открывает базу данных, которая живёт в памяти (идеально для обучения и для тестов). `conn.execute()` выполняет одну SQL-инструкцию:

<CodeExample output={`2
[(1, 'Dune', 'Frank Herbert', 1965), (2, 'Emma', 'Jane Austen', 1815)]`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")   # база данных в памяти
conn.execute("""
    CREATE TABLE books (
        id INTEGER PRIMARY KEY,
        title TEXT NOT NULL,
        author TEXT NOT NULL,
        year INTEGER
    )
""")

conn.execute(
    "INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
    ("Dune", "Frank Herbert", 1965),
)
cursor = conn.execute(
    "INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
    ("Emma", "Jane Austen", 1815),
)
print(cursor.lastrowid)
conn.commit()

rows = conn.execute("SELECT * FROM books").fetchall()
print(rows)
```

</CodeExample>

- **`CREATE TABLE`** перечисляет столбцы с их типами (`INTEGER`, `TEXT`, `REAL`…) и правилами: `NOT NULL` означает, что значение обязательно.
- `INTEGER PRIMARY KEY` заполняется сам: SQLite выдаёт каждой новой строке следующий id. Какой именно — подскажет **`cursor.lastrowid`**.
- **`INSERT INTO ... VALUES (?, ?, ?)`** добавляет строку. Знаки `?` — это **плейсхолдеры (placeholders)**, а сами значения передаются кортежем. Зачем так — расскажем чуть позже.
- **`conn.commit()`** сохраняет изменения окончательно.
- **`SELECT * FROM books`** читает все столбцы (`*`) всех строк. `fetchall()` возвращает список кортежей.

Ключевые слова SQL не чувствительны к регистру, но писать их ЗАГЛАВНЫМИ — общепринятый стиль: так SQL сразу бросается в глаза.

## SELECT с WHERE, ORDER BY и LIMIT

`executemany()` выполняет один и тот же INSERT для каждого кортежа из списка. А `SELECT` умеет выбирать нужные **столбцы**, фильтровать строки через **`WHERE`**, сортировать через **`ORDER BY`** (добавьте `DESC`, чтобы сначала шли самые большие значения) и оставлять только первые несколько строк через **`LIMIT`**:

<CodeExample output={`('Matilda', 1988)
('The BFG', 1982)
('Dune', 1965)
[('The BFG', 208), ('Matilda', 240)]
(2,)
2`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE books (id INTEGER PRIMARY KEY, "
             "title TEXT, author TEXT, year INTEGER, pages INTEGER)")
books = [
    ("Dune", "Frank Herbert", 1965, 412),
    ("Emma", "Jane Austen", 1815, 474),
    ("Matilda", "Roald Dahl", 1988, 240),
    ("Persuasion", "Jane Austen", 1817, 249),
    ("The BFG", "Roald Dahl", 1982, 208),
]
conn.executemany(
    "INSERT INTO books (title, author, year, pages) "
    "VALUES (?, ?, ?, ?)",
    books,
)

for row in conn.execute(
    "SELECT title, year FROM books WHERE year > 1900 "
    "ORDER BY year DESC"
):
    print(row)

shortest = conn.execute(
    "SELECT title, pages FROM books ORDER BY pages LIMIT 2"
).fetchall()
print(shortest)

austen = conn.execute(
    "SELECT COUNT(*) FROM books WHERE author = ?",
    ("Jane Austen",),
).fetchone()
print(austen)
print(austen[0])
```

</CodeExample>

По результату `execute()` можно пройти циклом напрямую, вызвать `fetchall()`, чтобы получить список, или **`fetchone()`**, чтобы взять только следующую строку (или `None`, если строк больше нет). Обратите внимание на запятую в `("Jane Austen",)`: это кортеж из одного элемента. Без запятой это просто строка в скобках.

`WHERE` понимает `=`, `!=`, `<`, `>`, `<=`, `>=`, `AND`, `OR`, `NOT`, `IN (...)`, `BETWEEN`, `IS NULL`, а также `LIKE 'Dun%'` для простых шаблонов.

## Строки, которые можно читать по имени

Обращения вроде `row[1]` читать тяжело. Установите **`conn.row_factory = sqlite3.Row`** — и сможете обращаться к столбцам по имени или превращать строку в словарь:

<CodeExample output={`Dune 1965
{'id': 1, 'title': 'Dune', 'author': 'Frank Herbert', 'year': 1965}
None`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.row_factory = sqlite3.Row      # строки ведут себя как словари
conn.execute("CREATE TABLE books (id INTEGER PRIMARY KEY, "
             "title TEXT, author TEXT, year INTEGER)")
conn.execute(
    "INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
    ("Dune", "Frank Herbert", 1965),
)

row = conn.execute("SELECT * FROM books WHERE id = ?", (1,)).fetchone()
print(row["title"], row["year"])
print(dict(row))

missing = conn.execute(
    "SELECT * FROM books WHERE id = ?", (99,)
).fetchone()
print(missing)
```

</CodeExample>

## UPDATE и DELETE

**`UPDATE`** меняет столбцы в существующих строках, а **`DELETE`** удаляет строки. **`cursor.rowcount`** сообщает, сколько строк затронуто:

<CodeExample output={`обновлено: 1
удалено: 2
[('Dune', 896), ('Emma', 474)]`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE books (id INTEGER PRIMARY KEY, "
             "title TEXT, author TEXT, pages INTEGER)")
conn.executemany(
    "INSERT INTO books (title, author, pages) VALUES (?, ?, ?)",
    [("Dune", "Frank Herbert", 412), ("Emma", "Jane Austen", 474),
     ("Matilda", "Roald Dahl", 240), ("The BFG", "Roald Dahl", 208)],
)

cursor = conn.execute(
    "UPDATE books SET pages = ? WHERE title = ?", (896, "Dune")
)
print("обновлено:", cursor.rowcount)

cursor = conn.execute(
    "DELETE FROM books WHERE author = ?", ("Roald Dahl",)
)
print("удалено:", cursor.rowcount)
conn.commit()

print(conn.execute("SELECT title, pages FROM books").fetchall())
```

</CodeExample>

<Callout type="danger" title="Не забывайте WHERE">

`UPDATE books SET pages = 0` и `DELETE FROM books` без `WHERE` меняют **все строки** таблицы. После коммита кнопки «Отменить» нет. `rowcount`, равный `0`, тоже полезен: он значит, что ничего не подошло, — например, такого id не существует.

</Callout>

## Подсчёт и группировка

**Агрегатные функции (aggregate functions)** превращают много строк в одно значение: `COUNT(*)`, `SUM()`, `AVG()`, `MIN()` и `MAX()`. С **`GROUP BY`** вы получаете по одной строке результата на каждую группу — как в отчёте:

<CodeExample output={`(5, 1583, 474)
('Jane Austen', 2, 361.5)
('Roald Dahl', 2, 224.0)
('Frank Herbert', 1, 412.0)`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE books (id INTEGER PRIMARY KEY, "
             "title TEXT, author TEXT, pages INTEGER)")
conn.executemany(
    "INSERT INTO books (title, author, pages) VALUES (?, ?, ?)",
    [("Dune", "Frank Herbert", 412), ("Emma", "Jane Austen", 474),
     ("Matilda", "Roald Dahl", 240), ("Persuasion", "Jane Austen", 249),
     ("The BFG", "Roald Dahl", 208)],
)

print(conn.execute(
    "SELECT COUNT(*), SUM(pages), MAX(pages) FROM books"
).fetchone())

rows = conn.execute("""
    SELECT author, COUNT(*) AS books, AVG(pages)
    FROM books
    GROUP BY author
    ORDER BY books DESC, author
""").fetchall()
for row in rows:
    print(row)
```

</CodeExample>

`AS books` даёт количеству имя, чтобы по нему можно было сортировать. Пусть считает база данных: это гораздо быстрее, чем выгружать все строки в Python и считать там, особенно когда строк миллионы.

## Соединяем две таблицы

Если хранить имя автора в каждой строке книги, данные повторяются: переименуете автора — и придётся исправлять множество строк. В настоящих схемах у авторов своя таблица, а в каждой книге хранится только id автора. Такой столбец называется **внешним ключом (foreign key)**. **`JOIN`** снова собирает таблицы вместе прямо в запросе:

<CodeExample output={`Emma — Jane Austen
Matilda — Roald Dahl
Persuasion — Jane Austen`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.executescript("""
    CREATE TABLE authors (
        id INTEGER PRIMARY KEY,
        name TEXT NOT NULL
    );
    CREATE TABLE books (
        id INTEGER PRIMARY KEY,
        title TEXT NOT NULL,
        author_id INTEGER REFERENCES authors(id)
    );
    INSERT INTO authors (name) VALUES ('Jane Austen'), ('Roald Dahl');
    INSERT INTO books (title, author_id) VALUES
        ('Emma', 1), ('Matilda', 2), ('Persuasion', 1);
""")

rows = conn.execute("""
    SELECT books.title, authors.name
    FROM books
    JOIN authors ON books.author_id = authors.id
    ORDER BY books.title
""").fetchall()
for title, name in rows:
    print(f"{title} — {name}")
```

</CodeExample>

`executescript()` выполняет несколько инструкций, разделённых `;`. `JOIN authors ON books.author_id = authors.id` сопоставляет каждой книге автора, чей `id` равен её `author_id`. Запись `таблица.столбец` избавляет от путаницы, когда в обеих таблицах есть столбец с одинаковым именем (например, `id`).

## Параметры и SQL-инъекции

Так и хочется собрать SQL через f-строку. **Никогда не делайте так со значениями**: всё, что введёт пользователь, станет частью вашего SQL. Смотрите, что творит хитрое «имя»:

<CodeExample output={`SELECT * FROM users WHERE name = 'nobody' OR '1'='1'
[('mei', 'bamboo42'), ('sam', 'hunter2')]
[]`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE users (name TEXT, secret TEXT)")
conn.executemany("INSERT INTO users VALUES (?, ?)",
                 [("mei", "bamboo42"), ("sam", "hunter2")])

name = "nobody' OR '1'='1"     # ввёл злоумышленник

# ❌ f-строка: ввод становится частью SQL
sql = f"SELECT * FROM users WHERE name = '{name}'"
print(sql)
print(conn.execute(sql).fetchall())

# ✅ параметр: ввод всегда остаётся просто значением
print(conn.execute(
    "SELECT * FROM users WHERE name = ?", (name,)
).fetchall())
```

</CodeExample>

Версия с f-строкой превратила условие в *«имя — nobody ИЛИ 1 равно 1»*, а это верно для каждой строки, — и секреты всех пользователей утекли. Это **SQL-инъекция (SQL injection)**, одна из самых распространённых дыр в безопасности в вебе. С плейсхолдером `?` база данных получает SQL и значение **по отдельности**, поэтому значение никак не может изменить запрос. Заодно исчезает и бытовой баг: имя вроде `O'Brien` сломало бы версию с f-строкой.

<Callout type="warning" title="Правило">

Значения всегда передаются как **параметры** (`?` в sqlite3; другие библиотеки используют `%s` или `:name`). F-строки годятся только для частей, которые полностью под контролем вашего собственного кода, и никогда — для того, что пришло от пользователя, из файла или из запроса.

</Callout>

## Транзакции: всё или ничего

Все ваши изменения входят в **транзакцию (transaction)**. `commit()` делает их постоянными, а **`rollback()`** отбрасывает всё, что было после последнего коммита. Это важно, когда несколько изменений связаны между собой, — например, при переводе денег между двумя счетами: должны пройти либо оба обновления, либо ни одного.

Если использовать соединение в блоке **`with`**, это происходит само: при успешном завершении блока изменения коммитятся, а при исключении — откатываются:

<CodeExample output={`[('mei', 70), ('sam', 50)]
Не удалось: CHECK constraint failed: balance >= 0
[('mei', 70), ('sam', 50)]`}>

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE accounts (name TEXT PRIMARY KEY, "
             "balance INTEGER NOT NULL CHECK (balance >= 0))")
conn.executemany("INSERT INTO accounts VALUES (?, ?)",
                 [("mei", 100), ("sam", 20)])
conn.commit()

def transfer(conn, sender, receiver, amount):
    with conn:   # коммит при успехе, откат при ошибке
        conn.execute(
            "UPDATE accounts SET balance = balance + ? "
            "WHERE name = ?", (amount, receiver))
        conn.execute(
            "UPDATE accounts SET balance = balance - ? "
            "WHERE name = ?", (amount, sender))

transfer(conn, "mei", "sam", 30)
print(conn.execute("SELECT * FROM accounts").fetchall())

try:
    transfer(conn, "sam", "mei", 500)   # у sam столько нет
except sqlite3.IntegrityError as error:
    print("Не удалось:", error)
print(conn.execute("SELECT * FROM accounts").fetchall())
```

</CodeExample>

Во время неудачного перевода баланс Мэй уже успел вырасти на 500, когда второе обновление нарушило правило `CHECK`. Откат отменил и это, так что бесплатных денег никто не получил. 🐼

<Callout type="tip" title="SQLite в реальных проектах">

SQLite хранит всю базу данных в одном файле (`sqlite3.connect("library.db")`) и не требует сервера, поэтому она отлично подходит для небольших приложений, десктопных утилит, телефонов и тестов. Крупные веб-приложения обычно используют **PostgreSQL**. SQL, который вы здесь выучили, почти одинаково работает в обеих.

</Callout>

## Итоги

- Реляционная база данных хранит **строки** в **таблицах** с типизированными **столбцами**; **первичный ключ** однозначно определяет каждую строку.
- `sqlite3.connect(":memory:")` даёт настоящую SQL-базу в памяти; `conn.execute()` выполняет SQL.
- `CREATE TABLE`, `INSERT`, `SELECT ... WHERE ... ORDER BY ... LIMIT`, `UPDATE` и `DELETE` покрывают повседневную работу. Никогда не забывайте `WHERE` в UPDATE/DELETE.
- `fetchall()`, `fetchone()`, `lastrowid` и `rowcount` дают доступ к результатам; `sqlite3.Row` позволяет обращаться к столбцам по имени.
- `COUNT`, `SUM`, `AVG` вместе с `GROUP BY` строят отчёты; **внешний ключ** и `JOIN` объединяют таблицы.
- Всегда передавайте значения как **параметры `?`**, а не через f-строки: это защищает от **SQL-инъекций**.
- `commit()` сохраняет, `rollback()` отменяет; `with conn:` превращает группу изменений в «всё или ничего».
