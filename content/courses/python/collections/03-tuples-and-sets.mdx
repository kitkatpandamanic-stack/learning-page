Lists and dicts get most of the attention, but Python has two more collections you'll use all the time: **tuples** for small fixed groups of values, and **sets** for collections of unique items.

## Tuples: lists that can't change

A **tuple** is written with round brackets. You read it just like a list, with indexes and slices:

<CodeExample output={`(3, 4)
3
2
<class 'tuple'>`}>

```python
point = (3, 4)
print(point)
print(point[0])
print(len(point))
print(type(point))
```

</CodeExample>

The big difference: tuples are **immutable**. Once made, you can't add, remove or change items:

```python
point[0] = 10   # TypeError: 'tuple' object does not support item assignment
```

That sounds like a limitation, but it's a feature. A tuple says *"this group of values belongs together and won't change"*: a point `(x, y)`, a colour `(255, 128, 0)`, a date `(2026, 10, 1)`.

<Callout type="warning" title="One-item tuples">

It's the **comma** that makes a tuple, not the brackets. `(5)` is just the number 5. A tuple with one item needs a trailing comma: `(5,)`.

</Callout>

## Packing and unpacking

Writing values separated by commas **packs** them into a tuple, even without brackets. **Unpacking** splits a tuple back into separate names. Together they give you Python's famous one-line swap:

<CodeExample output={`(12, 'Mei')
12 Mei
2 1`}>

```python
info = 12, "Mei"      # packing
print(info)

age, name = info      # unpacking
print(age, name)

a, b = 1, 2
a, b = b, a           # swap!
print(a, b)
```

</CodeExample>

Unpacking also works in `for` loops, which is perfect for a list of tuples:

<CodeExample output={`Mei scored 88
Sam scored 75`}>

```python
results = [("Mei", 88), ("Sam", 75)]

for name, score in results:
    print(f"{name} scored {score}")
```

</CodeExample>

## Returning several values

In the functions module you returned several values with `return min(numbers), max(numbers)`. Now you know the secret: that's packing! The function returns **one tuple**, and you can unpack it or keep it whole:

<CodeExample output={`(61, 95)
61 95`}>

```python
def lowest_and_highest(numbers):
    return min(numbers), max(numbers)

result = lowest_and_highest([72, 95, 88, 61])
print(result)

low, high = lowest_and_highest([72, 95, 88, 61])
print(low, high)
```

</CodeExample>

## Tuples as dictionary keys

Dict keys must never change, so lists can't be keys, but tuples can. This is great for things like grid positions:

<CodeExample output={`treasure
None
2`}>

```python
board = {
    (0, 0): "start",
    (2, 3): "treasure",
}
print(board[(2, 3)])
print(board.get((1, 1)))
print(len(board))
```

</CodeExample>

Trying `{[2, 3]: "treasure"}` gives `TypeError: unhashable type: 'list'`. "Hashable" roughly means "can't change", which is what keys need.

## Sets: only unique items

A **set** is written with curly braces (like a dict, but with no colons). A set keeps **only one copy** of each value, and has **no order**:

<CodeExample output={`{1, 2, 3}
3
[1, 2, 3, 5]`}>

```python
numbers = {3, 1, 3, 2, 1}
print(numbers)        # duplicates are gone
print(len(numbers))

rolls = [5, 1, 3, 5, 2, 1]
unique = set(rolls)   # turn a list into a set
print(sorted(unique))
```

</CodeExample>

`set(some_list)` is the quickest way to remove duplicates. Wrap it in `sorted()` when you want a list in a predictable order.

<Callout type="warning" title="Empty set">

`{}` makes an empty **dict**, not an empty set. Use `set()` for an empty set.

</Callout>

<Callout type="note" title="Sets have no order">

Because sets don't keep an order, you can't use indexes like `my_set[0]`, and printing a set of strings can show them in a different order each time you run the program. If the order matters, use `sorted(my_set)`.

</Callout>

## Adding, removing and checking

Use `.add()` to add one item and `.discard()` or `.remove()` to take one away. `.remove()` raises a `KeyError` if the item isn't there; `.discard()` quietly does nothing. Checking with `in` is **very fast** on a set, just like on dict keys:

<CodeExample output={`['dog', 'panda']
True
False`}>

```python
seen = set()
seen.add("panda")
seen.add("dog")
seen.add("panda")      # already there: no change
seen.add("cat")
seen.remove("cat")
seen.discard("snake")  # not there: no error
print(sorted(seen))

print("panda" in seen)
print("cat" in seen)
```

</CodeExample>

## Set maths

Sets can be combined like the circles in a Venn diagram:

| Operation        | Operator | Method                | Result                          |
| ---------------- | -------- | --------------------- | ------------------------------- |
| **Union**        | `a \| b` | `a.union(b)`          | Everything in either set        |
| **Intersection** | `a & b`  | `a.intersection(b)`   | Only what's in **both**         |
| **Difference**   | `a - b`  | `a.difference(b)`     | In `a` but **not** in `b`       |

<CodeExample output={`['Ali', 'Ben', 'Mei', 'Sam', 'Zoe']
['Sam', 'Zoe']
['Ali', 'Mei']
['Ben']`}>

```python
chess = {"Mei", "Sam", "Zoe", "Ali"}
art = {"Sam", "Zoe", "Ben"}

print(sorted(chess | art))   # in either club
print(sorted(chess & art))   # in both clubs
print(sorted(chess - art))   # only chess
print(sorted(art.difference(chess)))  # only art
```

</CodeExample>

## Choosing the right collection

| Collection | Looks like            | Ordered? | Changeable? | Duplicates? | Use it for                                   |
| ---------- | --------------------- | -------- | ----------- | ----------- | -------------------------------------------- |
| **list**   | `[1, 2, 2]`           | Yes      | Yes         | Yes         | An ordered sequence you'll add to or sort    |
| **tuple**  | `(3, 4)`              | Yes      | No          | Yes         | A fixed group of values, dict keys           |
| **dict**   | `{"a": 1}`            | Yes      | Yes         | Unique keys | Looking things up by name, counting          |
| **set**    | `{1, 2}`              | No       | Yes         | No          | Unique items, fast `in` checks, set maths    |

<Callout type="tip" title="A quick rule of thumb">

Ask yourself: *Do I look things up by name?* Use a **dict**. *Do I only care whether something is there?* Use a **set**. *Will this group never change?* Use a **tuple**. Otherwise, a **list** is a fine default.

</Callout>

The chess and art clubs keep their members in lists, and the lists may contain duplicates. Finish `club_report(chess, art)` so it **returns a tuple** of three things:

1. a **sorted list** of the people in **both** clubs,
2. a **sorted list** of the people **only** in chess,
3. the **number** of different people in at least one club.

Turn both lists into sets first: `a = set(chess)`. Then use `a & b`, `a - b` and `len(a | b)`. Wrap the first two in `sorted()`, and return all three separated by commas.

```python
def club_report(chess, art):
    a = set(chess)
    b = set(art)
    both = sorted(a & b)
    only_chess = sorted(a - b)
    total = len(a | b)
    return both, only_chess, total

chess = ["Mei", "Sam", "Ali"]

```

## Recap

- **Tuples** `(3, 4)` are like lists that can't change. A comma makes a tuple: `(5,)`.
- Packing `x = 1, 2` and unpacking `a, b = x` power swaps, loops over pairs and returning several values.
- Tuples can be dict keys; lists can't.
- **Sets** `{1, 2, 3}` keep unique items with no order. Use `set()` for an empty set.
- `|` union, `&` intersection, `-` difference.
- Pick the collection that matches the job: list, tuple, dict or set.
