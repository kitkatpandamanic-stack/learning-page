В настоящих программах что-то постоянно идёт не так: пользователь вводит `"ten"` вместо `10`, файла нет на месте, список оказался пустым. Когда Python сталкивается с проблемой, которую не может решить сам, он **выбрасывает исключение** (raises an exception). В этом уроке вы научитесь читать такие ошибки и аккуратно их обрабатывать, а не позволять программе падать. 🛟

## Как читать трассировку

Вот небольшая программа с ошибкой:

```python title="main.py"
def average(numbers):
    return sum(numbers) / len(numbers)

scores = []
print(average(scores))
```

Если запустить её на компьютере, она выведет **трассировку** (traceback):

```text
Traceback (most recent call last):
  File "main.py", line 5, in <module>
    print(average(scores))
          ~~~~~~~^^^^^^^^
  File "main.py", line 2, in average
    return sum(numbers) / len(numbers)
           ~~~~~~~~~~~~~^~~~~~~~~~~~~~
ZeroDivisionError: division by zero
```

Читайте её **снизу вверх**:

1. Последняя строка говорит, **что** пошло не так: тип исключения (`ZeroDivisionError`) и сообщение.
2. Строки выше говорят, **где**: в строке 2 внутри `average`, которую вызвали из строки 5.
3. Значки `^^^` указывают на тот самый фрагмент кода, который не сработал.

Список был пустым, поэтому `len(numbers)` равнялось `0`, и мы поделили на ноль.

<Callout type="tip" title="Трассировка — ваш друг">

Не пугайтесь стены красного текста. Сначала посмотрите на **последнюю строку**, а затем найдите первую строку, где упоминается **ваш** файл. На PandaDev вы увидите последнюю строку и номер строки, в которой произошла ошибка.

</Callout>

## Частые исключения

С этими исключениями вы будете встречаться постоянно:

| Исключение | Что означает | Пример |
| --- | --- | --- |
| `ValueError` | Тип правильный, а значение — нет | `int("abc")` |
| `TypeError` | Неподходящий тип для операции | `"3" + 4` |
| `KeyError` | Такого ключа в словаре нет | `stock["pears"]` |
| `IndexError` | Такой позиции в списке нет | `[10, 20][5]` |
| `ZeroDivisionError` | Деление на ноль | `10 / 0` |
| `FileNotFoundError` | Попытка открыть несуществующий файл | `open("nope.txt")` |

Давайте нарочно вызовем первые пять и выведем, что сообщает каждое из них:

<CodeExample output={`ValueError: invalid literal for int() with base 10: 'abc'
TypeError: can only concatenate str (not "int") to str
KeyError: 'pears'
IndexError: list index out of range
ZeroDivisionError: division by zero`}>

```python
stock = {"apples": 3}

mistakes = [
    lambda: int("abc"),
    lambda: "3" + 4,
    lambda: stock["pears"],
    lambda: [10, 20][5],
    lambda: 10 / 0,
]

for mistake in mistakes:
    try:
        mistake()
    except Exception as e:
        print(f"{type(e).__name__}: {e}")
```

</CodeExample>

Пока не беспокойтесь о каждой детали. В следующих разделах `try`, `except` и `as e` разобраны шаг за шагом.

## try и except

Поместите рискованный код в блок **`try`**. Если возникнет исключение, Python не упадёт, а сразу перейдёт в подходящий блок **`except`**:

<CodeExample output={`'42' в двойном размере — 84
'twelve' — не целое число
'7' в двойном размере — 14`}>

```python
for text in ["42", "twelve", "7"]:
    try:
        number = int(text)
        print(f"'{text}' в двойном размере — {number * 2}")
    except ValueError:
        print(f"'{text}' — не целое число")
```

</CodeExample>

Когда `int("twelve")` не срабатывает, остаток блока `try` пропускается, выполняется блок `except`, а затем цикл переходит к следующему элементу. Программа так и не падает.

## Перехват конкретных исключений через as e

Всегда указывайте, какое именно исключение вы ожидаете. Блоков `except` может быть несколько, а `as e` даёт вам сам объект исключения, чтобы можно было показать его сообщение:

<CodeExample output={`Нет такого товара: 'pears'
Не число: invalid literal for int() with base 10: 'lots'
Bananas: 6`}>

```python
stock = {"apples": "3", "bananas": "6", "kiwis": "lots"}

def show_count(fruit):
    try:
        count = int(stock[fruit])
        print(f"{fruit.title()}: {count}")
    except KeyError as e:
        print(f"Нет такого товара: {e}")
    except ValueError as e:
        print(f"Не число: {e}")

show_count("pears")
show_count("kiwis")
show_count("bananas")
```

</CodeExample>

Можно перехватить сразу несколько типов в одном блоке с помощью кортежа: `except (KeyError, ValueError):`.

<Callout type="warning" title="Не перехватывайте всё подряд">

Голый `except:` (или `except Exception:`) перехватывает **любую** ошибку, включая опечатки, например неправильно написанное имя переменной. Ваши баги тихо прячутся. Перехватывайте только те исключения, которые знаете, как обработать, а остальные пусть громко роняют программу, чтобы вы могли их исправить.

</Callout>

## else и finally

У инструкции (statement) `try` есть две необязательные дополнительные части:

- **`else`** выполняется, только если исключения **не** было. Благодаря ему блок `try` остаётся маленьким: в `try` попадает только рискованная строка.
- **`finally`** выполняется **всегда**, была ошибка или нет. Он идеально подходит для завершающих действий: что-нибудь закрыть или вывести «готово».

<CodeExample output={`Результат: 2.5
Деление 10 на 4 завершено
На ноль делить нельзя!
Деление 10 на 0 завершено
Оба значения должны быть числами.
Деление 10 на 2 завершено`}>

```python
def divide(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print("На ноль делить нельзя!")
    except TypeError:
        print("Оба значения должны быть числами.")
    else:
        print(f"Результат: {result}")
    finally:
        print(f"Деление {a} на {b} завершено")

divide(10, 4)
divide(10, 0)
divide(10, "2")
```

</CodeExample>

## Собственные исключения

Ваши функции тоже могут выбрасывать исключения с помощью **`raise`**. Так функция сообщает: «С этим значением я работать не могу». Выберите подходящий тип и напишите понятное сообщение:

<CodeExample output={`30
Извините: недостаточно денег (на балансе 50)
Извините: сумма должна быть положительной`}>

```python
def withdraw(balance, amount):
    if amount <= 0:
        raise ValueError("сумма должна быть положительной")
    if amount > balance:
        raise ValueError(f"недостаточно денег (на балансе {balance})")
    return balance - amount

print(withdraw(50, 20))

for amount in [80, -5]:
    try:
        withdraw(50, amount)
    except ValueError as e:
        print(f"Извините: {e}")
```

</CodeExample>

`raise` сразу останавливает функцию, как и `return`, но вместо значения возвращает ошибку. Как её обработать, решает тот, кто **вызывает** функцию.

## Проверка ввода

Объедините цикл, `try` и `raise`, чтобы переспрашивать, пока не получите подходящий ответ. Здесь наш код не может использовать `input()`, поэтому то, что вводит пользователь, заменяет список:

<CodeExample output={`'ten' не подходит: введите число
'-4' не подходит: число должно быть от 1 до 10
Спасибо! Вы выбрали 7`}>

```python
typed = ["ten", "-4", "7", "3"]

def parse_choice(text):
    try:
        number = int(text)
    except ValueError:
        raise ValueError("введите число")
    if not 1 <= number <= 10:
        raise ValueError("число должно быть от 1 до 10")
    return number

for text in typed:
    try:
        choice = parse_choice(text)
    except ValueError as e:
        print(f"'{text}' не подходит: {e}")
    else:
        print(f"Спасибо! Вы выбрали {choice}")
        break
```

</CodeExample>

## EAFP или LBYL

Есть два стиля работы с тем, что может не сработать:

- **LBYL** (look before you leap) — «посмотри, прежде чем прыгать»: сначала проверьте через `if`.
- **EAFP** (easier to ask forgiveness than permission) — «проще попросить прощения, чем разрешения»: просто попробуйте и обработайте исключение.

<CodeExample output={`Груш нет (проверили заранее)
Груш нет (перехватили KeyError)`}>

```python
stock = {"apples": 3}

# LBYL: сначала проверяем
if "pears" in stock:
    print(stock["pears"])
else:
    print("Груш нет (проверили заранее)")

# EAFP: пробуем и обрабатываем неудачу
try:
    print(stock["pears"])
except KeyError:
    print("Груш нет (перехватили KeyError)")
```

</CodeExample>

Оба стиля хороши. Python-программисты часто предпочитают **EAFP**, особенно когда проверить заранее сложно: «является ли этот текст правильным числом?» или «существует ли этот файл и можно ли его открыть?».

<Hint>

В `parse_age` напишите `if age < 0 or age > 130:`, а затем `raise ValueError(...)`. В `describe_age` оберните вызов в `try`, перехватите исключение через `except ValueError as e:` и верните `f"Ошибка: {e}"`. Успешный `return` поместите в блок `else`.

```python
def parse_age(text):
    age = int(text)
    if age < 0 or age > 130:
        raise ValueError("возраст должен быть от 0 до 130")
    return age

def describe_age(text):
    try:
        age = parse_age(text)
    except ValueError as e:
        return f"Ошибка: {e}"
    else:
        return f"Возраст подходит: {age}"

print(describe_age("42"))
print(describe_age("-3"))
print(describe_age("forty"))
```

## Итоги

- Читайте трассировку **снизу вверх**: последняя строка говорит, что пошло не так, а строки выше — где.
- Частые исключения: `ValueError`, `TypeError`, `KeyError`, `IndexError`, `ZeroDivisionError`, `FileNotFoundError`.
- `try` / `except SomeError as e:` обрабатывает проблему; `else` выполняется при успехе; `finally` — всегда.
- Перехватывайте **конкретные** исключения, а не всё подряд.
- `raise ValueError("сообщение")` сигнализирует о проблеме из ваших собственных функций.
- Оба стиля — **EAFP** (просто попробуй) и **LBYL** (сначала проверь) — допустимы; EAFP считается очень «питоничным».
