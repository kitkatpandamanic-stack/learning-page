PandaLink работает: ядро покрыто тестами, а у API есть база данных, кэш, API-ключи, ограничение частоты запросов и логи. Но запускается всё это только внутри тестов, а связывается вручную в фикстурах. В этой последней части мы сделаем сервис **готовым к выпуску**: одна сборка, которая работает где угодно, настраивается из окружения, упакована в контейнер, проверяется в CI, находится под наблюдением мониторинга и проверена под нагрузкой. 🚀

Большая часть этой работы происходит *вокруг* кода, поэтому вы увидите больше обычных блоков (Dockerfile, YAML, команды оболочки), которые запускаются на вашем компьютере, а не в редакторе. Части на Python — настройки и **корень композиции (composition root)** — вы соберёте и протестируете по-настоящему. Здесь сходятся вместе уроки [Контейнеры и развёртывание](/learn/python/containers-and-deployment) и [Внедрение зависимостей и DDD](/learn/python/dependency-injection-and-ddd).

## Настройки из окружения

Каждое значение, которое отличается на вашем ноутбуке, в staging и в продакшене, становится настройкой (setting): оно читается из переменных окружения (environment variables) `APP_*` и проверяется **один раз, при запуске**:

| Настройка | Пример | Почему это настройка |
| --- | --- | --- |
| `APP_ENVIRONMENT` | `prod` | от неё зависят некоторые правила |
| `APP_DATABASE_URL` | `postgresql+psycopg://...` | база данных везде своя, и в адресе есть пароль |
| `APP_API_KEYS` | `blog:9f86d0...,ci:60303a...` | **хеши** ключей клиентов, у каждого — своё имя |
| `APP_CACHE_TTL_SECONDS` | `60` | насколько могут устаревать перенаправления и статистика |
| `APP_RATE_LIMIT_BURST`, `APP_RATE_LIMIT_PER_SECOND` | `20`, `1` | подбираются во время нагрузочных тестов без новой сборки |
| `APP_LOG_LEVEL` | `INFO` | `DEBUG`, пока охотитесь за багом |

По сравнению с уроком о контейнерах новое здесь — API-ключи и правило, связывающее несколько полей:

<CodeExample output={`dev **********
['blog', 'ci']
Value error, bad API key entry for 'blog'
Value error, prod needs a real database`}>

```python
import hashlib
import string
from collections.abc import Mapping
from typing import Literal

from pydantic import (
    BaseModel, ConfigDict, SecretStr, ValidationError,
    model_validator,
)

def hash_key(api_key: str) -> str:
    return hashlib.sha256(api_key.encode()).hexdigest()

class Settings(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    environment: Literal["dev", "staging", "prod"] = "dev"
    database_url: SecretStr
    api_keys: str                    # "name:sha256hex,name:..."

    @model_validator(mode="after")
    def check(self):
        self.key_table()             # кривые ключи: падаем сразу
        url = self.database_url.get_secret_value()
        if self.environment == "prod" and url.startswith("sqlite"):
            raise ValueError("prod needs a real database")
        return self

    def key_table(self) -> dict[str, str]:
        table = {}
        for entry in self.api_keys.split(","):
            name, _, digest = entry.strip().partition(":")
            if not name or len(digest) != 64 or any(
                ch not in string.hexdigits for ch in digest
            ):
                raise ValueError(f"bad API key entry for {name!r}")
            table[digest.lower()] = name
        return table

def load_settings(env: Mapping[str, str]) -> Settings:
    values = {
        name.removeprefix("APP_").lower(): value
        for name, value in env.items()
        if name.startswith("APP_")
    }
    return Settings.model_validate(values)

env = {
    "APP_DATABASE_URL": "postgresql://app:s3cret@db/pandalink",
    "APP_API_KEYS": f"blog:{hash_key('k1')}, ci:{hash_key('k2')}",
}
settings = load_settings(env)
print(settings.environment, settings.database_url)
print(sorted(settings.key_table().values()))

for bad in [{**env, "APP_API_KEYS": "blog:1234"},
            {**env, "APP_ENVIRONMENT": "prod",
             "APP_DATABASE_URL": "sqlite://"}]:
    try:
        load_settings(bad)
    except ValidationError as error:
        print(error.errors()[0]["msg"])
```

</CodeExample>

- **`database_url` — это `SecretStr`**, потому что в адресах баз данных есть пароли. Если напечатать настройки или показать их на странице ошибки, пароль не утечёт.
- **`key_table()`** превращает `"name:hash, name:hash"` в словарь `{hash: name}`, который ожидает `create_app`. Валидатор вызывает его один раз, поэтому сломанная запись не даёт сервису запуститься, а не блокирует клиента в три часа ночи.
- **Никакого SQLite в продакшене**: правилу, которому нужны два поля, место в `model_validator(mode="after")`. База данных в памяти в prod теряла бы все ссылки при перезапуске, а эта проверка в одну строку делает такую ошибку невозможной.
- Сообщение об ошибке называет клиента (`'blog'`), но не хеш. Сообщения об ошибках тоже попадают в логи.

Чтобы дать доступ новому клиенту, администратор запускает крошечный скрипт, отправляет ключ клиенту по безопасному каналу и добавляет в `APP_API_KEYS` только хеш:

```python
# make_key.py: запускайте на своём компьютере, раз на клиента
import hashlib
import secrets

key = secrets.token_urlsafe(32)
print("отправьте клиенту:", key)
digest = hashlib.sha256(key.encode()).hexdigest()
print("добавьте в APP_API_KEYS:", f"blog:{digest}")
```

## Корень композиции

До сих пор всё связывали фикстуры. В продакшене этим занимается одна функция — **корень композиции** из урока о внедрении зависимостей, `build_app(settings)`. Это единственное место, которое знает все конкретные классы, и создаёт она их в порядке зависимостей:

```text
settings ─┬─▶ engine ─▶ SqlLinkRepository
          │                     │ обёрнут в
          │             CachedLinkRepository ─▶ LinkService ─┐
          ├─▶ RateLimiter ───────────────────────────────────┤
          └─▶ key_table() ───────────────────────────────────┴─▶ create_app
```

У её сигнатуры есть значения по умолчанию для продакшена и «швы» для тестов:

```python
def build_app(settings: Settings, clock: Clock = utc_now,
              timer: Callable[[], float] = time.monotonic,
              make_code: Callable[[], str] = random_code) -> FastAPI:
```

- **Два вида времени.** `clock` даёт дату и время для `created_at` и `expires_at`. `timer` измеряет **промежутки** для TTL кэша и ведёр токенов. В продакшене таймер — это `time.monotonic()`, потому что настенные часы могут прыгать (сервер синхронизирует время или часы переводят), а прыжок назад сделал бы записи кэша вечными. Тесты передают в оба параметра один и тот же `FakeClock`: `clock=fake, timer=fake.time`.
- **`utc_now()`** возвращает текущее время UTC без часового пояса. Храните время в UTC — всегда; SQLite всё равно отбрасывает часовые пояса, а сравнение времени с поясом и без него выбрасывает `TypeError`.
- **`make_engine(url)`** использует `StaticPool` только для SQLite в памяти в тестах. Для настоящей базы данных он включает `pool_pre_ping=True`, который проверяет соединение из пула перед использованием, — так приложение переживает перезапуск базы данных.
- **`Base.metadata.create_all(engine)`** годится для тестов и первого прототипа. В продакшене схема меняется через **миграции (migrations)** (`alembic revision --autogenerate`, `alembic upgrade head`), которые запускаются один раз на каждое развёртывание, а не каждым воркером при старте.

На вашем компьютере точка входа, которую загружает uvicorn, занимает три строки. Это **единственное** место, которое читает `os.environ` и настраивает логирование:

```python
# main.py: uvicorn main:app --host 0.0.0.0 --port 8000
import os

from pandalink import build_app, configure_logging, load_settings

settings = load_settings(os.environ)   # плохой конфиг: не запускаемся
configure_logging(settings.log_level)  # строки JSON в stdout
app = build_app(settings)
```

`configure_logging` — это настройка `basicConfig(handlers=[...], force=True)` с `JsonFormatter` из части 2. Если держать её вне `build_app`, тесты никогда не трогают глобальные настройки логирования.

## Docker и Compose

Dockerfile — это многоэтапный образ без root из урока «Контейнеры и развёртывание», с новой точкой входа:

```dockerfile
FROM python:3.14-slim AS build
RUN python -m venv /venv
ENV PATH="/venv/bin:$PATH"
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

FROM python:3.14-slim
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1 \
    PATH="/venv/bin:$PATH"
RUN useradd --create-home --uid 10001 app
WORKDIR /app
COPY --from=build /venv /venv
COPY pandalink/ ./pandalink/
COPY main.py .
USER app
EXPOSE 8000
HEALTHCHECK CMD python -c "import urllib.request; \
  urllib.request.urlopen('http://localhost:8000/health/live')"
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000", \
     "--proxy-headers"]
```

Для разработки Compose запускает всю систему, теперь с **Redis** рядом с PostgreSQL. Разовый сервис `migrate` выполняет миграции Alembic до запуска API:

```yaml
services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      APP_ENVIRONMENT: dev
      APP_DATABASE_URL: postgresql+psycopg://app:app@db:5432/app
      APP_REDIS_URL: redis://cache:6379/0   # см. раздел «Переходим на Redis»
    env_file: .env              # APP_API_KEYS хранится здесь, а не в git
    depends_on:
      migrate:
        condition: service_completed_successfully
      cache:
        condition: service_healthy

  migrate:
    build: .
    command: ["alembic", "upgrade", "head"]
    environment:
      APP_DATABASE_URL: postgresql+psycopg://app:app@db:5432/app
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:17
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app"]
      interval: 5s
      retries: 5

  cache:
    image: redis:8
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      retries: 5

volumes:
  pgdata:
```

### Переходим на Redis

Когда воркеров и серверов несколько, словарь в каждом процессе — это не общий кэш, а ведро токенов в каждом процессе позволяет клиенту сделать в N раз больше запросов, чем вы задумали. И то и другое переезжает в **Redis** — общее хранилище в памяти со встроенным истечением срока. Сервис видит только порт репозитория, поэтому замена — это один новый адаптер, одна изменённая строка в `build_app` и настройка `redis_url` (файл Compose выше уже задаёт `APP_REDIS_URL`; без этой настройки `extra="forbid"` отверг бы переменную):

```python
import json
import redis   # pip install redis

class RedisCachedLinkRepository:
    """Тот же порт, что у CachedLinkRepository, общий для всех воркеров."""

    def __init__(self, inner, client: redis.Redis, ttl: int):
        self.inner, self.redis, self.ttl = inner, client, ttl

    def get(self, code):
        cached = self.redis.get(f"link:{code.value}")
        if cached is not None:
            return link_from_json(json.loads(cached))
        link = self.inner.get(code)
        if link is not None:   # SET со сроком жизни, одной командой
            self.redis.set(f"link:{code.value}",
                           json.dumps(link_to_json(link)), ex=self.ttl)
        return link

    def add(self, link):
        self.inner.add(link)

    def record_click(self, code):
        self.inner.record_click(code)
```

Redis сам следит за TTL (`ex=60`), и все воркеры видят одни и те же записи. С ограничителем частоты сложнее, потому что «прочитать ведро, обновить его, записать обратно» должно быть **атомарным** для всех серверов; команды используют короткий скрипт на Lua, который Redis выполняет за один шаг, или библиотеку вроде `limits`. Для тестов пакет `fakeredis` даёт Redis в памяти с тем же API.

## Непрерывная интеграция

CI запускается на каждый pull request. Помимо линтера, модульных тестов и аудита зависимостей, второе задание запускает **тот же набор тестов на настоящем PostgreSQL**, который GitHub Actions поднимает как служебный контейнер. Именно там вы бы поймали, например, столбец, который слишком короток для PostgreSQL, но не для SQLite:

```yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6
        with:
          python-version: "3.14"
          cache: pip
      - run: pip install -r requirements.txt -r requirements-dev.txt
      - run: ruff check .
      - run: pytest
      - run: pip-audit -r requirements.txt

  postgres:
    runs-on: ubuntu-latest
    services:
      db:
        image: postgres:17
        env:
          POSTGRES_PASSWORD: test
        ports: ["5432:5432"]
        options: >-
          --health-cmd pg_isready --health-interval 5s
          --health-retries 5
    env:
      TEST_DATABASE_URL: postgresql+psycopg://postgres:test@localhost:5432/postgres
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6
        with:
          python-version: "3.14"
      - run: pip install -r requirements.txt -r requirements-dev.txt
      - run: alembic upgrade head
      - run: pytest -m integration

  image:
    needs: [test, postgres]
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v5
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/build-push-action@v6
        with:
          push: true
          tags: ghcr.io/${{ github.repository }}:${{ github.sha }}
```

Метка `integration` выбирает тесты, которым нужен адрес базы данных. Здесь это контрактный тест репозитория из части 2 с третьим параметром, `"postgres"`, который пропускается, если не задана `TEST_DATABASE_URL`. Образ помечается хешем коммита, а **постепенное (rolling)** или **канареечное (canary)** развёртывание выкатывает его; проверки готовности не пускают трафик на новые экземпляры, пока `/health/ready` не подтвердит, что база данных доступна.

## Наблюдаемость и оповещения

Перед запуском решите, что значит «работает» в цифрах, и убедитесь, что эти цифры видны. Для PandaLink:

| Сигнал | Метрика | Зачем |
| --- | --- | --- |
| Частота (rate) | перенаправлений/с и созданных ссылок/с | трафик и обнаружение внезапного провала |
| Ошибки (errors) | доля ответов 5xx на `GET /{code}` | SLO для перенаправлений |
| Длительность (duration) | задержка перенаправлений p50 и p99 | требование 50 мс из дизайн-документа |
| Кэш | доля попаданий (`hits / (hits + misses)`) | падение доли означает больше нагрузки на базу данных |
| Злоупотребления | ответы 429 по клиентам | клиент, застрявший в цикле, или слишком низкий лимит |
| Насыщение (saturation) | занятые соединения с базой данных, CPU, память | что под нагрузкой кончится первым |

В приложении вы бы отдавали эти метрики через `prometheus-client` или метрики OpenTelemetry (наш кэш уже считает `hits` и `misses`), добавили бы **трассировку (tracing)** OpenTelemetry для FastAPI и SQLAlchemy и отправляли бы JSON-логи в хранилище логов. А дальше снова прикидочные расчёты — на этот раз для мощности и для **бюджета ошибок (error budget)**:

<CodeExample output={`Запросов в обработке в пик: 35
Чтений из базы в секунду: 175 (без кэша: 3,500)
Редиректов в месяц: 3,024,000,000
Бюджет ошибок: 3,024,000 неудачных редиректов
Это 43 минуты полного простоя`}>

```python
peak_redirects = 3_500          # в секунду, из части 1
latency = 0.010                 # 10 мс на редирект, измерено
hit_ratio = 0.95                # из метрик кэша

# Закон Литтла: запросов в обработке = частота x время на запрос
in_flight = peak_redirects * latency
print(f"Запросов в обработке в пик: {in_flight:.0f}")

db_reads = peak_redirects * (1 - hit_ratio)
print(f"Чтений из базы в секунду: {db_reads:,.0f} "
      f"(без кэша: {peak_redirects:,})")

# SLO: 99.9% редиректов успешны, считаем за 30 дней
monthly = peak_redirects / 3 * 86_400 * 30   # среднее, а не пик
budget = monthly * (1 - 0.999)
print(f"Редиректов в месяц: {monthly:,.0f}")
print(f"Бюджет ошибок: {budget:,.0f} неудачных редиректов")
print(f"Это {30 * 24 * 60 * 0.001:.0f} минуты полного простоя")
```

</CodeExample>

**Закон Литтла (Little's law)** говорит, что при 3 500 запросах в секунду и 10 мс на каждый в любой момент обрабатывается около 35 запросов: хватит нескольких процессов-воркеров, если кэш удерживает чтения из базы данных на уровне примерно 175 в секунду. **SLO** в 99,9% допускает около трёх миллионов неудачных перенаправлений в месяц, или 43 минуты полного простоя. Когда неудачное развёртывание быстро сжигает этот бюджет, кого-то должны разбудить:

```yaml
# Правило оповещения Prometheus
- alert: RedirectErrorBudgetBurn
  expr: |
    sum(rate(http_requests_total{route="/{code}",status=~"5.."}[5m]))
      / sum(rate(http_requests_total{route="/{code}"}[5m]))
      > 14.4 * 0.001
  for: 5m
  labels:
    severity: page
  annotations:
    summary: "Redirects failing: 30-day error budget gone in ~2 days"
    runbook: https://wiki.example/runbooks/pandalink-redirects
```

Множитель 14,4 — распространённое правило «быстрого сгорания»: при такой скорости 30-дневного бюджета хватит примерно на два дня. Более медленное сгорание (скажем, 1x за 6 часов) может вместо этого открывать тикет, никого не будя. Настраивайте оповещения на то, что чувствуют пользователи, как здесь, а оповещения о CPU и доле попаданий в кэш держите как **предупреждения** на дашборде.

## Нагрузочное тестирование

Оценки — это догадки; **нагрузочный тест (load test)** проверяет их раньше, чем это сделают настоящие пользователи. **Locust** описывает поведение пользователей на обычном Python. Этот тест переходит по ссылкам в сто раз чаще, чем создаёт их, — как настоящий трафик:

```python
# loadtest.py: locust -f loadtest.py --host https://staging.pandalink.example
import os
import random

from locust import HttpUser, between, task

CODES = ["k3Xp9Qa", "Zt81bYc", "pandas"]    # заранее созданы в staging

class Visitor(HttpUser):
    wait_time = between(0.05, 0.2)

    @task(100)
    def follow(self):
        self.client.get(f"/{random.choice(CODES)}",
                        allow_redirects=False, name="/{code}")

    @task(1)
    def create(self):
        self.client.post(
            "/links", json={"url": "https://pandas.org"},
            headers={"Authorization": f"Bearer {os.environ['KEY']}"},
        )
```

```bash
locust -f loadtest.py --host https://staging.pandalink.example \
  --headless --users 400 --spawn-rate 20 --run-time 10m
```

Несколько привычек, благодаря которым нагрузочные тесты окупаются:

- Тестируйте **staging**, собранный и настроенный как продакшен, с данными как в продакшене: база данных на 50 строк ведёт себя совсем не так, как база на 50 миллионов.
- **Наращивайте** нагрузку постепенно и ищите **«колено»**: точку, где задержка резко растёт, а пропускная способность перестаёт расти. Потом по метрикам насыщения выясните, что кончилось первым (соединения с базой данных, CPU, ограничитель частоты).
- Проведите и тест с **холодным кэшем** (сначала перезапустите Redis): так бывает после развёртывания или сбоя кэша, и именно тогда на базу данных обрушивается лавина запросов.
- Ожидайте, что клиент, создающий ссылки, получит **429**: здесь это ограничитель частоты делает свою работу, а не ошибки.

## Чек-лист перед продакшеном

Перед первым настоящим пользователем пройдитесь по списку вроде этого — лучше вместе с кем-то, кто не строил этот сервис:

| Область | Проверка |
| --- | --- |
| Конфигурация | Все настройки берутся из переменных `APP_*` и проверяются при запуске, секреты — это `SecretStr`, и они хранятся в хранилище секретов платформы |

class TokenBucket:
    def __init__(self, capacity, per_second, clock):
        self.capacity = capacity
        self.per_second = per_second
        self.clock = clock
        self.tokens = capacity
        self.updated = clock()

    def allow(self):
        now = self.clock()
        earned = (now - self.updated) * self.per_second
        self.tokens = min(self.capacity, self.tokens + earned)
        self.updated = now
        if self.tokens >= 1:
            self.tokens -= 1
            return True
        return False


class RateLimiter:
    """Своё ведро токенов (token bucket) у каждого клиента."""

    def __init__(self, capacity: int, per_second: float,
                 clock: Callable[[], float]):
        self.capacity = capacity
        self.per_second = per_second
        self.clock = clock
        self._buckets: dict[str, TokenBucket] = {}

    def allow(self, client: str) -> bool:
        bucket = self._buckets.get(client)
        if bucket is None:
            bucket = TokenBucket(self.capacity, self.per_second,
                                 self.clock)
            self._buckets[client] = bucket
        return bucket.allow()

    def retry_after(self) -> int:

class LinkService:
    def __init__(self, repo: LinkRepository, clock: Clock,
                 make_code: Callable[[], str] = random_code,
                 max_attempts: int = 5):
        self.repo = repo
        self.clock = clock
        self.make_code = make_code
        self.max_attempts = max_attempts

    def shorten(self, url: str, alias: str | None = None,
                ttl_days: int | None = None) -> ShortLink:
        target = TargetUrl(url)
        if ttl_days is not None and ttl_days < 1:
            raise ValueError("ttl_days must be at least 1")
        now = self.clock()
        expires = None
        if ttl_days:
            expires = now + timedelta(days=ttl_days)
        attempts = 1 if alias else self.max_attempts
        for attempt in range(attempts):
            code = ShortCode(alias or self.make_code())
            link = ShortLink(code, target, now, expires)
            try:
                self.repo.add(link)
                return link
            except CodeTaken:
                if attempt == attempts - 1:
                    raise

    def _find(self, raw_code: str) -> ShortLink:
        try:
            code = ShortCode(raw_code)
        except ValueError:
            raise LinkNotFound(raw_code) from None
        link = self.repo.get(code)
        if link is None:
            raise LinkNotFound(raw_code)
        return link

    def resolve(self, raw_code: str) -> str:
        link = self._find(raw_code)
        if link.is_expired(self.clock()):
            raise LinkExpired(raw_code)
        self.repo.record_click(link.code)
        return link.url.value

    def stats(self, raw_code: str) -> ShortLink:
        return self._find(raw_code)

class CachedLinkRepository:
    """Cache-aside с TTL перед любым LinkRepository."""

    def __init__(self, inner, ttl: float,
                 clock: Callable[[], float]):
        self.inner = inner
        self.ttl = ttl
        self.clock = clock
        self.hits = 0
        self.misses = 0
        self._entries = {}      # код -> (ссылка, expires_at)

    def get(self, code):
        now = self.clock()
        entry = self._entries.get(code)
        if entry is not None and now < entry[1]:
            self.hits += 1
            return replace(entry[0])
        self.misses += 1

class TokenBucket:
    def __init__(self, capacity, per_second, clock):
        self.capacity = capacity
        self.per_second = per_second
        self.clock = clock
        self.tokens = capacity
        self.updated = clock()

    def allow(self):
        now = self.clock()
        earned = (now - self.updated) * self.per_second
        self.tokens = min(self.capacity, self.tokens + earned)
        self.updated = now
        if self.tokens >= 1:
            self.tokens -= 1
            return True
        return False

        self.per_second = per_second
        self.clock = clock

    def allow(self, client: str) -> bool:
        bucket = self._buckets.get(client)
        if bucket is None:
            bucket = TokenBucket(self.capacity, self.per_second,
                                 self.clock)
            self._buckets[client] = bucket

class LinkService:
    def __init__(self, repo: LinkRepository, clock: Clock,
                 make_code: Callable[[], str] = random_code,
                 max_attempts: int = 5):
        self.repo = repo
        self.clock = clock
        self.make_code = make_code
        self.max_attempts = max_attempts

    def shorten(self, url: str, alias: str | None = None,
                ttl_days: int | None = None) -> ShortLink:
        target = TargetUrl(url)
        if ttl_days is not None and ttl_days < 1:
            raise ValueError("ttl_days must be at least 1")
        now = self.clock()
        expires = None
        if ttl_days:
            expires = now + timedelta(days=ttl_days)
        attempts = 1 if alias else self.max_attempts
        for attempt in range(attempts):
            code = ShortCode(alias or self.make_code())
            link = ShortLink(code, target, now, expires)
            try:
                self.repo.add(link)
                return link
            except CodeTaken:
                if attempt == attempts - 1:
                    raise

    def _find(self, raw_code: str) -> ShortLink:
        try:
            code = ShortCode(raw_code)
        except ValueError:
            raise LinkNotFound(raw_code) from None
        link = self.repo.get(code)
        if link is None:
            raise LinkNotFound(raw_code)
        return link

    def resolve(self, raw_code: str) -> str:
        link = self._find(raw_code)
        if link.is_expired(self.clock()):
            raise LinkExpired(raw_code)
        self.repo.record_click(link.code)
        return link.url.value

    def stats(self, raw_code: str) -> ShortLink:
        return self._find(raw_code)

            link = links.shorten(body.url, body.alias, body.ttl_days)
        except CodeTaken:
            raise HTTPException(409, "That code is taken")
        except ValueError as error:
            raise HTTPException(422, str(error))
        log.info("link created", extra={"fields": {
            "code": link.code.value, "client": client}})
        return to_out(link)

    @app.get("/links/{code}", response_model=LinkOut)
    def link_stats(code: str, links: ServiceDep, client: ClientDep):
        try:
            return to_out(links.stats(code))
        except LinkNotFound:
            raise HTTPException(404, "Link not found")

    @app.get("/{code}")
    def follow(code: str, links: ServiceDep):
        try:
            url = links.resolve(code)
        except LinkNotFound:
            raise HTTPException(404, "Link not found")
        except LinkExpired:
            raise HTTPException(410, "Link expired")
        log.info("redirect", extra={"fields": {"code": code}})
        return RedirectResponse(url, status_code=307)

    return app

class Settings(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    environment: Literal["dev", "staging", "prod"] = "dev"
    database_url: SecretStr
    api_keys: str                    # "name:sha256hex,name:..."
    cache_ttl_seconds: float = Field(default=60, ge=0, le=3600)
    rate_limit_burst: int = Field(default=20, ge=1)
    rate_limit_per_second: float = Field(default=1, gt=0)
    log_level: Literal["DEBUG", "INFO", "WARNING"] = "INFO"

    @model_validator(mode="after")
    def check(self):
        self.key_table()             # кривые ключи: падаем сразу
        url = self.database_url.get_secret_value()
        if self.environment == "prod" and url.startswith("sqlite"):
            raise ValueError("prod needs a real database")
        return self

    def key_table(self) -> dict[str, str]:
        table = {}
        for entry in self.api_keys.split(","):
            name, _, digest = entry.strip().partition(":")
            if not name or len(digest) != 64 or any(
                ch not in string.hexdigits for ch in digest
            ):
                raise ValueError(f"bad API key entry for {name!r}")
            table[digest.lower()] = name
        return table


def load_settings(env: Mapping[str, str]) -> Settings:
    values = {
        name.removeprefix("APP_").lower(): value
        for name, value in env.items()
        if name.startswith("APP_")
    }
    return Settings.model_validate(values)


def make_engine(url: str):
    if url == "sqlite://":          # в памяти: одно общее соединение
        return create_engine(
            url, poolclass=StaticPool,
            connect_args={"check_same_thread": False},
        )
    return create_engine(url, pool_pre_ping=True)


def utc_now() -> datetime:
    return datetime.now(timezone.utc).replace(tzinfo=None)


def build_app(settings: Settings, clock: Clock = utc_now,
              timer: Callable[[], float] = time.monotonic,
              make_code: Callable[[], str] = random_code) -> FastAPI:
    """Корень композиции: единственное место, где всё связывается."""
    engine = make_engine(settings.database_url.get_secret_value())
    Base.metadata.create_all(engine)   # в настоящих проектах: Alembic
    sql = SqlLinkRepository(sessionmaker(engine))
    repo = CachedLinkRepository(sql, settings.cache_ttl_seconds,
                                timer)
    service = LinkService(repo, clock, make_code)
    limiter = RateLimiter(settings.rate_limit_burst,
                          settings.rate_limit_per_second, timer)
    return create_app(service, limiter, settings.key_table(),
                      check_db=sql.ping)

PandaLink — настоящий фундамент. Несколько направлений, каждое из которых научит вас чему-то новому:

1. **Общее состояние**: перенесите кэш и ограничитель частоты в Redis, как показано выше, протестируйте их с `fakeredis` и добавьте короткий TTL для негативного кэширования против сканеров.
2. **Асинхронный подсчёт кликов**: вместо `UPDATE` на каждое перенаправление отправляйте событие клика в очередь (или Redis `INCR`), а фоновый воркер пусть записывает итоги пачками. Перенаправления станут быстрее, и можно будет добавить аналитику вроде стран и источников переходов.
3. **Владельцы и удаление**: храните, какой клиент создал каждую ссылку, разрешите клиентам просматривать и удалять только свои ссылки и напишите тест, который доказывает, что клиент A не может прочитать статистику клиента B (проверка владения из урока об аутентификации в API).
