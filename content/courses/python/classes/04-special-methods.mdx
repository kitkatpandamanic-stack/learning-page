Why does `len("panda")` work, and `"a" in ["a", "b"]`, and `sorted(numbers)`? Because strings, lists and numbers have **special methods** that Python calls behind the scenes. Their names start and end with two underscores, like `__init__`, so people call them **dunder** ("double underscore") methods. Add them to your own classes and your objects work with Python's built-in tools too. ✨

## `__str__` and `__repr__`: printing objects

By default, printing an object gives something like `<__main__.Book object at 0x10a2f3e50>`. Two dunder methods fix that:

<CodeExample output={`Dune by Frank Herbert
Book('Dune', 'Frank Herbert')
[Book('Dune', 'Frank Herbert'), Book('Emma', 'Jane Austen')]
Now reading: Dune by Frank Herbert`}>

```python
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def __str__(self):
        return f"{self.title} by {self.author}"

    def __repr__(self):
        return f"Book({self.title!r}, {self.author!r})"

dune = Book("Dune", "Frank Herbert")
emma = Book("Emma", "Jane Austen")

print(dune)            # uses __str__
print(repr(dune))      # uses __repr__
print([dune, emma])    # lists show items with __repr__
print(f"Now reading: {dune}")
```

</CodeExample>

- `__str__` is the **friendly** text for users. `print()`, `str()` and f-strings use it.
- `__repr__` is the **developer** text, ideally looking like the code that creates the object. Containers like lists use it, and so does the Python shell.
- `!r` inside an f-string inserts `repr(value)`, which adds the quotes around strings for you.

<Callout type="tip" title="Start with __repr__">

If you only write one, write `__repr__`: Python falls back to it when there's no `__str__`. It makes debugging so much easier.

</Callout>

## `__eq__`: when are two objects equal?

Without help, `==` only says `True` if both sides are **the very same object**. Two separate copies of the same book aren't equal! `__eq__` lets you decide what "equal" means:

<CodeExample output={`False
True
False
True`}>

```python
class PlainBook:
    def __init__(self, title, author):
        self.title = title
        self.author = author

class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def __eq__(self, other):
        if not isinstance(other, Book):
            return NotImplemented
        return (self.title, self.author) == (other.title, other.author)

print(PlainBook("Dune", "F.H.") == PlainBook("Dune", "F.H."))
print(Book("Dune", "F.H.") == Book("Dune", "F.H."))
print(Book("Dune", "F.H.") == Book("Emma", "J.A."))

shelf = [Book("Emma", "J.A."), Book("Dune", "F.H.")]
print(Book("Dune", "F.H.") in shelf)   # 'in' on a list uses ==
```

</CodeExample>

Returning `NotImplemented` (a special built-in value) for things that aren't books tells Python *"I don't know how to compare these"*, so `Book(...) == "Dune"` simply gives `False`.

<Callout type="warning" title="Equal objects can't go in sets">

When you define `__eq__`, Python makes your objects **unhashable**, so `{Book("Dune", "F.H.")}` or using one as a dict key raises a `TypeError`. That's on purpose: objects you can change shouldn't be dict keys. Keep them in lists, or key your dict by `book.title`.

</Callout>

## `__lt__`: sorting your objects

`sorted()`, `min()` and `max()` need to know when one object is **less than** another. That's `__lt__` (for `<`):

<CodeExample output={`[Book('Coraline'), Book('Dune'), Book('Emma')]
Book('Coraline')
True
['Emma', 'Dune', 'Coraline']`}>

```python
class Book:
    def __init__(self, title, pages):
        self.title = title
        self.pages = pages

    def __repr__(self):
        return f"Book({self.title!r})"

    def __lt__(self, other):
        return self.title < other.title

books = [Book("Emma", 474), Book("Dune", 412),
         Book("Coraline", 162)]

print(sorted(books))         # alphabetical by title
print(min(books))
print(Book("Dune", 1) < Book("Emma", 1))

by_pages = sorted(books, key=lambda b: b.pages, reverse=True)
print([book.title for book in by_pages])
```

</CodeExample>

`__lt__` sets the **natural** order of your objects. For a one-off different order, you don't need another dunder: pass a `key` function to `sorted()`, like the last lines do.

## `__len__`, `__contains__` and `__iter__`: acting like a collection

A class that holds a group of things can work with `len()`, `in` and `for` loops:

<CodeExample output={`3
True
False
- Dune
- Emma
- Coraline`}>

```python
class Shelf:
    def __init__(self):
        self.titles = []

    def add(self, title):
        self.titles.append(title)

    def __len__(self):                  # len(shelf)
        return len(self.titles)

    def __contains__(self, title):      # title in shelf
        return title in self.titles

    def __iter__(self):                 # for t in shelf
        return iter(self.titles)

shelf = Shelf()
for title in ["Dune", "Emma", "Coraline"]:
    shelf.add(title)

print(len(shelf))
print("Emma" in shelf)
print("Matilda" in shelf)
for title in shelf:
    print(f"- {title}")
```

</CodeExample>

- `__len__` must return a whole number (an `int`).
- `__contains__` returns `True` or `False`.
- `__iter__` returns an **iterator**. The easy way is to hand back `iter(...)` of a list you already have.

<Callout type="note" title="Let Python call them">

You almost never call dunder methods yourself. Write `len(shelf)`, not `shelf.__len__()`, and `print(book)`, not `print(book.__str__())`. Python calls them for you at the right moment.

</Callout>

Time to put the whole module together! Finish the library system:

**Book**
- `__str__` returns `"Dune by Frank Herbert (1965)"`.
- `__eq__`: two books are equal when they have the same title **and** author.
- `__lt__` compares by title, so `sorted()` puts books in alphabetical order.

**Library**
- `add_book(book)` adds a book to `self.books`.
- `len(library)` gives the number of books, and `"Dune" in library` checks whether a book with that title exists.
- `find_by_author(author)` returns a list of that author's books (an empty list if none).
- `checkout(title, member)`: raise `BookNotFoundError` if there's no book with that title, or `BookUnavailableError` if it's already checked out. Otherwise mark it unavailable, add it to `member.borrowed` and return it.
- `return_book(title, member)`: raise `LibraryError` if the member hasn't borrowed that title. Otherwise remove it from `member.borrowed` and make it available again.
- `available_books()` returns the available books, **sorted**.

<Hint>

A private helper keeps `checkout` short: `_find(self, title)` loops over `self.books`, returns the book whose `title` matches, and raises `BookNotFoundError(title)` after the loop if nothing matched. In `return_book`, loop over `member.borrowed` to find the book with that title. `available_books` can be `sorted([b for b in self.books if b.available])`, which uses your `__lt__`.

</Hint>

```python
class LibraryError(Exception):
    pass

class BookNotFoundError(LibraryError):
    pass

class BookUnavailableError(LibraryError):
    pass


class Book:
    def __init__(self, title, author, year):
        self.title = title
        self.author = author
        self.year = year
        self.available = True

    def __repr__(self):
        return f"Book({self.title!r}, {self.author!r}, {self.year})"

    def __str__(self):
        return f"{self.title} by {self.author} ({self.year})"

    def __eq__(self, other):
        if not isinstance(other, Book):
            return NotImplemented
        return (self.title, self.author) == (other.title, other.author)

    def __lt__(self, other):
        return self.title < other.title


class Member:
    def __init__(self, name):
        self.name = name
        self.borrowed = []


class Library:
    def __init__(self):
        self.books = []

    def add_book(self, book):
        self.books.append(book)

    def __len__(self):
        return len(self.books)

    def __contains__(self, title):
        return any(book.title == title for book in self.books)

    def _find(self, title):
        for book in self.books:
            if book.title == title:
                return book
        raise BookNotFoundError(f"No book called {title!r}")

    def find_by_author(self, author):
        return [b for b in self.books if b.author == author]

    def checkout(self, title, member):
        book = self._find(title)
        if not book.available:
            raise BookUnavailableError(f"{title} is checked out")
        book.available = False
        member.borrowed.append(book)
        return book

    def return_book(self, title, member):
        for book in member.borrowed:
            if book.title == title:
                member.borrowed.remove(book)
                book.available = True
                return
        raise LibraryError(f"{member.name} hasn't borrowed {title}")

    def available_books(self):
        return sorted([b for b in self.books if b.available])


library = Library()
library.add_book(Book("Dune", "Frank Herbert", 1965))
library.add_book(Book("Emma", "Jane Austen", 1815))
mei = Member("Mei")
library.checkout("Dune", mei)
print(library.available_books())

try:
    library.checkout("Dune", Member("Sam"))
except LibraryError as error:
    print(f"Sorry: {error}")
```

</Solution>

## Recap

- **Dunder methods** let your objects work with Python's built-in syntax and functions. Python calls them for you.
- `__str__` is the friendly text for `print()` and f-strings; `__repr__` is the developer text, used inside lists and as a fallback.
- `__eq__` defines `==` (and `in` on lists); return `NotImplemented` for other types.
- `__lt__` defines `<`, which makes `sorted()`, `min()` and `max()` work; use `key=` for other orders.
- `__len__`, `__contains__` and `__iter__` make a class behave like a collection with `len()`, `in` and `for`.
