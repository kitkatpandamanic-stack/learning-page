A library lends out books, DVDs and magazines. They're all different, but they all have a title and can all be checked out. Instead of copying that shared code into three classes, you write it once in a **parent class** and let the others **inherit** it. 🐼

## Creating a subclass

Put the parent class in brackets after the new class name:

<CodeExample output={`Dune (1965)
True
True`}>

```python
class LibraryItem:
    def __init__(self, title, year):
        self.title = title
        self.year = year

    def describe(self):
        return f"{self.title} ({self.year})"

class Book(LibraryItem):
    def is_classic(self):
        return self.year < 1980

dune = Book("Dune", 1965)
print(dune.describe())     # inherited from LibraryItem
print(dune.is_classic())   # Book's own method
print(isinstance(dune, LibraryItem))
```

</CodeExample>

`Book` is a **subclass** (or child class) of `LibraryItem`, its **parent** (or base class). A book gets everything a library item has, including `__init__` and `describe()`, plus anything extra you add.

## super().__init__: extending the setup

Our `Book` really needs its own `author` and `pages`. If a subclass writes its own `__init__`, it should call the parent's one with `super().__init__(...)` so the shared setup still happens:

<CodeExample output={`Dune (1965)
Frank Herbert
412`}>

```python
class LibraryItem:
    def __init__(self, title, year):
        self.title = title
        self.year = year

    def describe(self):
        return f"{self.title} ({self.year})"

class Book(LibraryItem):
    def __init__(self, title, year, author, pages):
        super().__init__(title, year)   # parent sets title, year
        self.author = author
        self.pages = pages

dune = Book("Dune", 1965, "Frank Herbert", 412)
print(dune.describe())
print(dune.author)
print(dune.pages)
```

</CodeExample>

`super()` means *"my parent class"*. Forget to call `super().__init__` and `dune.title` would never be set, so you'd get an `AttributeError` later.

## Overriding methods

A subclass can **override** a method by defining one with the same name. Python always uses the most specific version it can find. You can still reach the parent's version through `super()`:

<CodeExample output={`Dune (1965): 21 days
Up (2009), 96 min: 7 days`}>

```python
class LibraryItem:
    def __init__(self, title, year):
        self.title = title
        self.year = year

    def loan_days(self):
        return 21

    def describe(self):
        return f"{self.title} ({self.year})"

class DVD(LibraryItem):
    def __init__(self, title, year, minutes):
        super().__init__(title, year)
        self.minutes = minutes

    def loan_days(self):              # replaces the parent's
        return 7

    def describe(self):               # builds on the parent's
        return f"{super().describe()}, {self.minutes} min"

items = [LibraryItem("Dune", 1965), DVD("Up", 2009, 96)]
for item in items:
    days = item.loan_days()
    print(f"{item.describe()}: {days} days")
```

</CodeExample>

Look at the loop: it calls `item.loan_days()` without caring what kind of item it is, and each object answers in its own way. This is called **polymorphism**, and it keeps your code free of long `if type == ...` chains.

## isinstance and issubclass

`isinstance(obj, Class)` checks whether an object is an instance of a class **or any of its subclasses**. `issubclass(A, B)` asks the same about two classes:

<CodeExample output={`True
True
False
True
False`}>

```python
class LibraryItem:
    pass

class DVD(LibraryItem):
    pass

up = DVD()
print(isinstance(up, DVD))
print(isinstance(up, LibraryItem))
print(isinstance(LibraryItem(), DVD))
print(issubclass(DVD, LibraryItem))
print(issubclass(LibraryItem, DVD))
```

</CodeExample>

<Callout type="note" title="Everything inherits from object">

Every class you write secretly inherits from Python's built-in `object`, so `issubclass(DVD, object)` is `True`. That's where default behaviour, like the unhelpful way objects print, comes from.

</Callout>

## Custom exceptions

Inheritance is also how you make your **own error types**. Subclass `Exception` (or one of your own exceptions) and give it a clear name:

<CodeExample output={`Not found: Dune
Library problem: Up is already checked out
True`}>

```python
class LibraryError(Exception):
    """Base class for every library problem."""

class BookNotFoundError(LibraryError):
    pass

class ItemUnavailableError(LibraryError):
    pass

def find(title):
    raise BookNotFoundError(title)

try:
    find("Dune")
except BookNotFoundError as error:
    print(f"Not found: {error}")

try:
    raise ItemUnavailableError("Up is already checked out")
except LibraryError as error:      # catches any subclass
    print(f"Library problem: {error}")

print(issubclass(BookNotFoundError, Exception))
```

</CodeExample>

The triple-quoted line is a **docstring**: it documents the class and also counts as its body, so you don't need `pass`.

<Callout type="tip" title="One base exception per project">

Giving your project one base exception (like `LibraryError`) and specific subclasses lets callers choose: catch `BookNotFoundError` to handle just that case, or `LibraryError` to handle **any** library problem without accidentally hiding unrelated bugs.

</Callout>

## Composition vs inheritance

Inheritance means **"is a"**: a DVD *is a* library item. But a library is not a list of books; a library **has** books. For "has a" relationships, store the other objects as attributes. This is called **composition**:

<CodeExample output={`2
['Dune', 'Emma']`}>

```python
class Book:
    def __init__(self, title):
        self.title = title

class Library:
    def __init__(self):
        self.books = []       # a Library HAS books

    def add_book(self, book):
        self.books.append(book)

    def titles(self):
        return [book.title for book in self.books]

library = Library()
library.add_book(Book("Dune"))
library.add_book(Book("Emma"))
print(len(library.books))
print(library.titles())
```

</CodeExample>

If you made `class Library(list)`, every list method like `sort()`, `clear()` and `pop()` would come along, whether it makes sense for a library or not. Composition lets you choose exactly which methods to offer.

<Callout type="tip" title="Prefer composition">

Ask *"is a"* or *"has a"*? Use inheritance only for a true "is a" relationship. When in doubt, choose composition: it's simpler to change later.

</Callout>

## @dataclass: a shortcut for data classes

Lots of classes just store data. Writing `__init__` with `self.x = x` for every field gets boring, so the `dataclasses` module can write it for you:

<CodeExample output={`Book(title='Dune', author='Frank Herbert', year=1965, tags=[])
True
Member(name='Mei', borrowed=['Dune'])`}>

```python
from dataclasses import dataclass, field

@dataclass
class Book:
    title: str
    author: str
    year: int = 2000          # default value
    tags: list = field(default_factory=list)

@dataclass
class Member:
    name: str
    borrowed: list = field(default_factory=list)

dune = Book("Dune", "Frank Herbert", 1965)
print(dune)
print(dune == Book("Dune", "Frank Herbert", 1965))

mei = Member("Mei")
mei.borrowed.append("Dune")
print(mei)
```

</CodeExample>

- Each `name: type` line becomes a field. `@dataclass` writes `__init__`, a readable printout and `==` comparison for you.
- The type hints (`str`, `int`) are documentation; Python doesn't enforce them.
- For a list default, use `field(default_factory=list)` so each object gets its **own** new list.

You can still add normal methods and properties to a dataclass.

<Hint>

An empty exception class is just `class AlreadyCheckedOutError(LibraryError): pass`. In `checkout`, start with `if self.checked_out:` and raise inside it. Each subclass `__init__` begins with `super().__init__(title)` and then stores its own extra attribute.

```python
class LibraryError(Exception):
    pass

class AlreadyCheckedOutError(LibraryError):
    pass


class LibraryItem:
    def __init__(self, title):
        self.title = title
        self.checked_out = False

    def loan_days(self):
        return 21

    def checkout(self):
        if self.checked_out:
            raise AlreadyCheckedOutError(
                f"{self.title} is already checked out"
            )
        self.checked_out = True


class Book(LibraryItem):
    def __init__(self, title, author):
        super().__init__(title)
        self.author = author


class DVD(LibraryItem):
    def __init__(self, title, minutes):
        super().__init__(title)
        self.minutes = minutes

    def loan_days(self):
        return 7


up = DVD("Up", 96)
up.checkout()

```

## Recap

- `class Child(Parent):` creates a **subclass** that inherits the parent's attributes and methods.
- Call `super().__init__(...)` in a subclass's `__init__` so the parent's setup still runs.
- **Override** a method by redefining it; use `super().method()` to build on the parent's version.
- `isinstance(obj, Class)` and `issubclass(A, B)` check relationships, including parents.
- Make custom exceptions by subclassing `Exception`, ideally with one base error per project.
- Inheritance is for **"is a"**; **composition** (storing objects as attributes) is for **"has a"**.
- `@dataclass` writes `__init__`, printing and `==` for simple data classes; use `field(default_factory=list)` for list defaults.
