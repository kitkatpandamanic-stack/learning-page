Почему работает `len("panda")`, и `"a" in ["a", "b"]`, и `sorted(numbers)`? Потому что у строк, списков и чисел есть **специальные методы (special methods)**, которые Python вызывает за кулисами. Их имена начинаются и заканчиваются двумя подчёркиваниями, как `__init__`, поэтому их называют **dunder-методами** (от «double underscore» — «двойное подчёркивание»). Добавьте их в свои классы — и ваши объекты тоже заработают со встроенными инструментами Python. ✨

## `__str__` и `__repr__`: печать объектов

По умолчанию при печати объекта получается что-то вроде `<__main__.Book object at 0x10a2f3e50>`. Это исправляют два dunder-метода:

<CodeExample output={`Дюна — Фрэнк Герберт
Book('Дюна', 'Фрэнк Герберт')
[Book('Дюна', 'Фрэнк Герберт'), Book('Эмма', 'Джейн Остин')]
Сейчас читаю: Дюна — Фрэнк Герберт`}>

```python
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def __str__(self):
        return f"{self.title} — {self.author}"

    def __repr__(self):
        return f"Book({self.title!r}, {self.author!r})"

dune = Book("Дюна", "Фрэнк Герберт")
emma = Book("Эмма", "Джейн Остин")

print(dune)            # использует __str__
print(repr(dune))      # использует __repr__
print([dune, emma])    # списки показывают элементы через __repr__
print(f"Сейчас читаю: {dune}")
```

</CodeExample>

- `__str__` — это **дружелюбный** текст для пользователей. Его используют `print()`, `str()` и f-строки.
- `__repr__` — это текст **для разработчика**, в идеале похожий на код, который создаёт объект. Его используют контейнеры вроде списков, а также интерактивная оболочка Python.
- `!r` внутри f-строки вставляет `repr(value)`, который сам добавляет кавычки вокруг строк.

<Callout type="tip" title="Начинайте с __repr__">

Если пишете только один из методов, пишите `__repr__`: Python использует его, когда `__str__` нет. С ним отладка становится намного проще.

</Callout>

## `__eq__`: когда два объекта равны?

Без подсказки `==` возвращает `True`, только если с обеих сторон **один и тот же объект**. Два отдельных экземпляра одной и той же книги не равны! `__eq__` позволяет решить, что значит «равны»:

<CodeExample output={`False
True
False
True`}>

```python
class PlainBook:
    def __init__(self, title, author):
        self.title = title
        self.author = author

class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def __eq__(self, other):
        if not isinstance(other, Book):
            return NotImplemented
        return (self.title, self.author) == (other.title, other.author)

print(PlainBook("Дюна", "Ф.Г.") == PlainBook("Дюна", "Ф.Г."))
print(Book("Дюна", "Ф.Г.") == Book("Дюна", "Ф.Г."))
print(Book("Дюна", "Ф.Г.") == Book("Эмма", "Д.О."))

shelf = [Book("Эмма", "Д.О."), Book("Дюна", "Ф.Г.")]
print(Book("Дюна", "Ф.Г.") in shelf)   # 'in' для списка использует ==
```

</CodeExample>

Возвращая `NotImplemented` (специальное встроенное значение) для всего, что не является книгой, вы говорите Python: *«я не знаю, как это сравнивать»*, — и `Book(...) == "Дюна"` просто даёт `False`.

<Callout type="warning" title="Объекты с __eq__ нельзя класть в множества">

Когда вы определяете `__eq__`, Python делает ваши объекты **нехешируемыми (unhashable)**, поэтому `{Book("Дюна", "Ф.Г.")}` или использование такого объекта как ключа словаря вызовет `TypeError`. Так задумано: изменяемые объекты не должны быть ключами словаря. Храните их в списках или используйте как ключ `book.title`.

</Callout>

## `__lt__`: сортировка объектов

`sorted()`, `min()` и `max()` должны знать, когда один объект **меньше** другого. За это отвечает `__lt__` (для `<`):

<CodeExample output={`[Book('Дюна'), Book('Коралина'), Book('Эмма')]
Book('Дюна')
True
['Эмма', 'Дюна', 'Коралина']`}>

```python
class Book:
    def __init__(self, title, pages):
        self.title = title
        self.pages = pages

    def __repr__(self):
        return f"Book({self.title!r})"

    def __lt__(self, other):
        return self.title < other.title

books = [Book("Эмма", 474), Book("Дюна", 412),
         Book("Коралина", 162)]

print(sorted(books))         # по алфавиту, по названию
print(min(books))
print(Book("Дюна", 1) < Book("Эмма", 1))

by_pages = sorted(books, key=lambda b: b.pages, reverse=True)
print([book.title for book in by_pages])
```

</CodeExample>

`__lt__` задаёт **естественный** порядок ваших объектов. Если разово нужен другой порядок, ещё один dunder-метод не нужен: передайте функцию `key` в `sorted()`, как в последних строках.

## `__len__`, `__contains__` и `__iter__`: ведём себя как коллекция

Класс, который хранит группу чего-либо, может работать с `len()`, `in` и циклами `for`:

<CodeExample output={`3
True
False
- Дюна
- Эмма
- Коралина`}>

```python
class Shelf:
    def __init__(self):
        self.titles = []

    def add(self, title):
        self.titles.append(title)

    def __len__(self):                  # len(shelf)
        return len(self.titles)

    def __contains__(self, title):      # title in shelf
        return title in self.titles

    def __iter__(self):                 # for t in shelf
        return iter(self.titles)

shelf = Shelf()
for title in ["Дюна", "Эмма", "Коралина"]:
    shelf.add(title)

print(len(shelf))
print("Эмма" in shelf)
print("Матильда" in shelf)
for title in shelf:
    print(f"- {title}")
```

</CodeExample>

- `__len__` должен возвращать целое число (`int`).
- `__contains__` возвращает `True` или `False`.
- `__iter__` возвращает **итератор (iterator)**. Проще всего вернуть `iter(...)` от списка, который у вас уже есть.

<Callout type="note" title="Пусть их вызывает Python">

Вы почти никогда не вызываете dunder-методы сами. Пишите `len(shelf)`, а не `shelf.__len__()`, и `print(book)`, а не `print(book.__str__())`. Python вызовет их за вас в нужный момент.

</Callout>

```python
class LibraryError(Exception):
    pass

class BookNotFoundError(LibraryError):
    pass

class BookUnavailableError(LibraryError):
    pass


class Book:
    def __init__(self, title, author, year):
        self.title = title
        self.author = author
        self.year = year
        self.available = True

    def __repr__(self):
        return f"Book({self.title!r}, {self.author!r}, {self.year})"

    def __str__(self):
        return f"{self.title} — {self.author} ({self.year})"

    def __eq__(self, other):
        if not isinstance(other, Book):
            return NotImplemented
        return (self.title, self.author) == (other.title, other.author)

    def __lt__(self, other):
        return self.title < other.title


class Member:
    def __init__(self, name):
        self.name = name
        self.borrowed = []


class Library:
    def __init__(self):
        self.books = []

    def add_book(self, book):
        self.books.append(book)

    def __len__(self):
        return len(self.books)

    def __contains__(self, title):
        return any(book.title == title for book in self.books)

    def _find(self, title):
        for book in self.books:
            if book.title == title:
                return book
        raise BookNotFoundError(f"Нет книги с названием {title!r}")

    def find_by_author(self, author):
        return [b for b in self.books if b.author == author]

    def checkout(self, title, member):
        book = self._find(title)
        if not book.available:
            raise BookUnavailableError(f"«{title}» уже выдана")
        book.available = False
        member.borrowed.append(book)
        return book

    def return_book(self, title, member):
        for book in member.borrowed:
            if book.title == title:
                member.borrowed.remove(book)
                book.available = True
                return
        raise LibraryError(f"У читателя {member.name} нет книги «{title}»")

    def available_books(self):
        return sorted([b for b in self.books if b.available])


library = Library()
library.add_book(Book("Дюна", "Фрэнк Герберт", 1965))
library.add_book(Book("Эмма", "Джейн Остин", 1815))
mei = Member("Мэй")
library.checkout("Дюна", mei)
print(library.available_books())

try:
    library.checkout("Дюна", Member("Сэм"))
except LibraryError as error:
    print(f"Увы: {error}")
```

</Solution>

## Итоги

- **Dunder-методы** позволяют вашим объектам работать со встроенным синтаксисом и функциями Python. Python вызывает их за вас.
- `__str__` — дружелюбный текст для `print()` и f-строк; `__repr__` — текст для разработчика, который используется внутри списков и как запасной вариант.
- `__eq__` задаёт `==` (и `in` для списков); для других типов возвращайте `NotImplemented`.
- `__lt__` задаёт `<`, и тогда работают `sorted()`, `min()` и `max()`; для другого порядка используйте `key=`.
- `__len__`, `__contains__` и `__iter__` заставляют класс вести себя как коллекция с `len()`, `in` и `for`.
