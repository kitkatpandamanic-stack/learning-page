An order can be pending, shipped or delivered. You could store that as a string like `"shipped"`, but strings have a problem: Python has no idea which ones are allowed, so a typo slips straight through. In this lesson you'll fix that with **enums**, then meet the full power of **`match`/`case`**, which can check the *shape* of your data and pull values out of it at the same time. 🧩

## Magic strings and why they hurt

A **magic string** is a special value that only works if you type it exactly right, every time, everywhere:

<CodeExample output={`True
False
False`}>

```python
def can_cancel(status):
    return status == "pending"

print(can_cancel("pending"))
print(can_cancel("Pending"))   # capital P
print(can_cancel("pendng"))    # typo
```

</CodeExample>

No error, just a wrong answer. That kind of bug can hide for weeks. And to find out which statuses exist, you'd have to search the whole program.

## Your first enum

An **enum** (short for *enumeration*) is a class that lists every allowed value once. Each value is called a **member**:

<CodeExample output={`Status.SHIPPED
SHIPPED
2
<Status.SHIPPED: 2>
AttributeError: type object 'Status' has no attribute 'SHIPED'`}>

```python
from enum import Enum

class Status(Enum):
    PENDING = 1
    SHIPPED = 2
    DELIVERED = 3

order = Status.SHIPPED
print(order)
print(order.name)
print(order.value)
print(repr(order))

try:
    Status.SHIPED
except AttributeError as error:
    print(f"AttributeError: {error}")
```

</CodeExample>

- Inherit from `Enum` and list the members in CAPITALS, because they're constants.
- `.name` is the member's name as a string; `.value` is whatever you gave it.
- A typo like `Status.SHIPED` now **crashes immediately** with an `AttributeError`, instead of quietly giving the wrong answer. Your editor can also autocomplete `Status.` for you.

## auto(), looping and looking up

Often the values don't matter, only that the members are different. `auto()` numbers them for you. An enum class can also be looped over, and you can look members up by name or by value, which is handy when the data comes from a file or JSON:

<CodeExample output={`PENDING 1
SHIPPED 2
DELIVERED 3
3
Status.SHIPPED
Status.DELIVERED
ValueError: 7 is not a valid Status`}>

```python
from enum import Enum, auto

class Status(Enum):
    PENDING = auto()
    SHIPPED = auto()
    DELIVERED = auto()

for status in Status:
    print(status.name, status.value)

print(len(Status))
print(Status["SHIPPED"])   # look up by name
print(Status(3))           # look up by value

try:
    Status(7)
except ValueError as error:
    print(f"ValueError: {error}")
```

</CodeExample>

Bad data can't sneak in: `Status(7)` raises a `ValueError` straight away.

## Comparing members

Each member exists exactly **once**, so you can compare with `is` (the usual style) or `==`. An enum is a class, so it can have methods and properties too, and members make great dictionary keys:

<CodeExample output={`True
True
False
False True
🚚`}>

```python
from enum import Enum, auto

class Status(Enum):
    PENDING = auto()
    SHIPPED = auto()
    DELIVERED = auto()

    @property
    def is_final(self):
        return self is Status.DELIVERED

order = Status.SHIPPED
print(order is Status.SHIPPED)
print(order == Status.SHIPPED)
print(order == 2)
print(order.is_final, Status.DELIVERED.is_final)

labels = {Status.PENDING: "📝", Status.SHIPPED: "🚚"}
print(labels[order])
```

</CodeExample>

Notice that `order == 2` is `False`: a plain enum member is **not** equal to its value. That's on purpose, so an enum never gets mixed up with ordinary numbers or strings.

### StrEnum and IntEnum

Sometimes you *do* want members to behave like strings or numbers, for example to send them as JSON or to sort them. That's what `StrEnum` and `IntEnum` are for:

<CodeExample output={`True
Size: large
{"size": "small"}
True
[<Priority.LOW: 1>, <Priority.NORMAL: 2>, <Priority.URGENT: 3>]`}>

```python
from enum import StrEnum, IntEnum, auto
import json

class Size(StrEnum):
    SMALL = auto()     # value "small"
    LARGE = auto()

class Priority(IntEnum):
    LOW = 1
    NORMAL = 2
    URGENT = 3

print(Size.SMALL == "small")
print(f"Size: {Size.LARGE}")
print(json.dumps({"size": Size.SMALL}))
print(Priority.URGENT > Priority.LOW)
print(sorted([Priority.URGENT, Priority.LOW, Priority.NORMAL]))
```

</CodeExample>

In a `StrEnum`, `auto()` uses the member's name in lowercase as its value. Reach for plain `Enum` first, and use these two only when you need the string or number behaviour.

<Callout type="tip" title="Why enums beat magic strings">

- **Typos crash** at once instead of hiding.
- **One list** of every allowed value, in one place.
- **Autocomplete** in your editor, and no guessing about spelling or capitals.
- You can **loop** over the options, for example to build a menu.

Whenever you catch yourself writing the same few special strings in many places, make an enum.

</Callout>

## match with enum members

You met `match` in [Making Decisions](/learn/python/if-elif-else) with plain strings, `|` and `case _`. It works just as well with enum members:

<CodeExample output={`PENDING: Pack the parcel
SHIPPED: Wait for the courier
DELIVERED: Nothing to do
CANCELLED: Nothing to do`}>

```python
from enum import Enum, auto

class Status(Enum):
    PENDING = auto()
    SHIPPED = auto()
    DELIVERED = auto()
    CANCELLED = auto()

def next_step(status):
    match status:
        case Status.PENDING:
            return "Pack the parcel"
        case Status.SHIPPED:
            return "Wait for the courier"
        case Status.DELIVERED | Status.CANCELLED:
            return "Nothing to do"

for status in Status:
    print(f"{status.name}: {next_step(status)}")
```

</CodeExample>

### Careful: a bare name catches everything

In a `case`, a dotted name like `Status.PENDING` means *"compare with this value"*. A **bare** name like `PENDING` means *"match anything and store it in a variable called PENDING"*:

<CodeExample output={`Pack it
shipped`}>

```python
PENDING = "pending"
status = "shipped"

match status:
    case PENDING:        # not a comparison!
        print("Pack it")

print(PENDING)
```

</CodeExample>

It matched `"shipped"` and overwrote `PENDING`. If more cases follow it, Python refuses to run at all, with `SyntaxError: name capture 'PENDING' makes remaining patterns unreachable`.

<Callout type="warning" title="Compare with dotted names or literals">

To compare with a value in a `case`, use an enum member (`Status.PENDING`) or a literal (`"pending"`), never a plain variable name.

</Callout>

## Sequence patterns: matching lists

`match` can do much more than compare values. Each `case` is a **pattern**: a description of what the data should *look like*. If it fits, Python can also pull pieces out into variables.

Splitting a command into words gives a list, and a **sequence pattern** checks how many items there are and what they are. Names inside the pattern **capture** values:

<CodeExample output={`You see a quiet library.
You walk north.
You take map, lamp, key.
Say something!
Bye!
I don't understand.`}>

```python
def handle(command):
    match command.split():
        case []:
            return "Say something!"
        case ["look"]:
            return "You see a quiet library."
        case ["go", direction]:
            return f"You walk {direction}."
        case ["take", *things]:
            return f"You take {', '.join(things)}."
        case ["quit" | "exit"]:
            return "Bye!"
        case _:
            return "I don't understand."

for command in ["look", "go north", "take map lamp key",
                "", "exit", "dance wildly"]:
    print(handle(command))
```

</CodeExample>

- `["look"]` matches a list with exactly one item, `"look"`.
- `["go", direction]` matches exactly two items where the first is `"go"`, and **captures** the second in `direction`.
- `*things` captures **all the remaining** items as a list, so `["take", *things]` fits one, two or ten things.
- `"quit" | "exit"` inside the list means either word.
- `case _` is the **wildcard**: it matches anything and captures nothing. Cases are tried top to bottom, so it goes last.

Compare that with splitting, checking `len(words)` and indexing `words[1]` by hand: the patterns *show* what each command looks like.

### Guards: extra conditions with if

A pattern checks shape; a **guard** adds any condition you like. The case only matches if the pattern fits **and** the guard is true:

<CodeExample output={`You walk north.
You can't go up.
Go where?`}>

```python
EXITS = ["north", "south"]

def handle(command):
    match command.split():
        case ["go", direction] if direction in EXITS:
            return f"You walk {direction}."
        case ["go", direction]:
            return f"You can't go {direction}."
        case ["go"]:
            return "Go where?"
        case _:
            return "I don't understand."

print(handle("go north"))
print(handle("go up"))
print(handle("go"))
```

</CodeExample>

When the guard fails, Python simply moves on to the next case.

## Mapping patterns: matching dictionaries

Data from web APIs and JSON files usually arrives as dictionaries. A **mapping pattern** checks for keys and captures their values. It's one of the best uses of `match`:

<CodeExample output={`Order 7: 2 item(s)
Refund 4.5 for order 7
Refund of 250 needs a manager
Ignoring ping event
Not an event: {'kind': 'mystery'}`}>

```python
events = [
    {"type": "order", "id": 7, "items": ["tea", "cake"]},
    {"type": "refund", "id": 7, "amount": 4.5, "reason": "cold"},
    {"type": "refund", "id": 8, "amount": 250},
    {"type": "ping"},
    {"kind": "mystery"},
]

for event in events:
    match event:
        case {"type": "order", "id": order_id, "items": items}:
            print(f"Order {order_id}: {len(items)} item(s)")
        case {"type": "refund", "amount": amount} if amount > 100:
            print(f"Refund of {amount} needs a manager")
        case {"type": "refund", "id": order_id, "amount": amount}:
            print(f"Refund {amount} for order {order_id}")
        case {"type": other}:
            print(f"Ignoring {other} event")
        case _:
            print(f"Not an event: {event}")
```

</CodeExample>

- The pattern lists only the keys you care about. **Extra keys are ignored** (the first refund also has a `"reason"`).
- If a key in the pattern is **missing**, that case doesn't match, so there's no `KeyError` to worry about.
- Literal values like `"order"` must be equal; names like `amount` capture whatever is there.

## Class patterns: matching objects

A **class pattern** checks whether something is an instance of a class (like `isinstance`) and can capture its attributes. It's a great fit for the dataclasses from [Inheritance](/learn/python/inheritance):

<CodeExample output={`Dune: a book
It: a long read
Up: a 96-minute DVD
Something else
('title', 'minutes')`}>

```python
from dataclasses import dataclass

@dataclass
class Book:
    title: str
    pages: int

@dataclass
class DVD:
    title: str
    minutes: int

def describe(item):
    match item:
        case Book(title=title, pages=pages) if pages > 500:
            return f"{title}: a long read"
        case Book(title=title):
            return f"{title}: a book"
        case DVD(title, minutes):
            return f"{title}: a {minutes}-minute DVD"
        case _:
            return "Something else"

items = [Book("Dune", 412), Book("It", 1138), DVD("Up", 96), 42]
for item in items:
    print(describe(item))
print(DVD.__match_args__)
```

</CodeExample>

- `Book(title=title)` means *"a Book; capture its `title` attribute"*. These **keyword patterns** work with any class.
- `DVD(title, minutes)` uses **positions** instead. That works because `@dataclass` writes `__match_args__` for you: the order of the attributes, as the last line shows.
- Always write the brackets: `case Book():` means *"any Book"*, while `case Book:` would be a bare name that captures everything!

For a normal class, either use keyword patterns, or set `__match_args__` yourself:

<CodeExample output={`the origin
on the y-axis at 5
on the x-axis at 3
somewhere else`}>

```python
class Point:
    __match_args__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y

def where(point):
    match point:
        case Point(0, 0):
            return "the origin"
        case Point(0, y):
            return f"on the y-axis at {y}"
        case Point(x=x, y=0):
            return f"on the x-axis at {x}"
        case Point():
            return "somewhere else"

for p in [Point(0, 0), Point(0, 5), Point(3, 0), Point(2, 2)]:
    print(where(p))
```

</CodeExample>

## When to use match (and when not)

`match` shines when you're asking **"what shape is this data?"**: commands split into words, JSON-like dictionaries, different kinds of objects, or a fixed set of enum members. One `case` checks the shape *and* unpacks the values, which would take several lines of `if`, `len()` and indexing.

It's **not** better for everything:

- **Ranges and comparisons** read more naturally with `if`/`elif`: `if score >= 90:` beats `case s if s >= 90:`.
- **Simple value-to-value lookups** are often just a dictionary: `emoji = {"tea": "🍵", "cake": "🍰"}[food]`.
- With only one or two conditions, a plain `if` is shorter and just as clear.

<Callout type="note" title="Python 3.10 and newer">

`match`/`case` arrived in Python 3.10 (2021). On PandaDev you're on Python 3.14, but if you ever see `SyntaxError` on a `match` line on another computer, check the Python version.

</Callout>

<Hint>

Check maintenance mode first: `if self.state is State.MAINTENANCE and words != ["service"]: return "Out of service"`. Then use sequence patterns with guards, from most specific to least: `case ["insert", amount] if amount.isdigit() and int(amount) > 0:` before `case ["insert", _]:`, and `case ["buy", snack] if snack not in PRICES:` before `case ["buy", snack]:`.
```python
from enum import Enum, auto

PRICES = {"crisps": 80, "water": 100, "chocolate": 120}


class State(Enum):
    IDLE = auto()
    HAS_CREDIT = auto()
    MAINTENANCE = auto()


class VendingMachine:
    def __init__(self):
        self.credit = 0
        self.state = State.IDLE

    def handle(self, command):
        words = command.lower().split()
        if self.state is State.MAINTENANCE and words != ["service"]:
            return "Out of service"

        match words:
            case ["insert", amount] if amount.isdigit() and int(amount) > 0:
                self.credit += int(amount)
                self.state = State.HAS_CREDIT
                return f"Credit: {self.credit}"
            case ["insert", _]:
                return "Invalid coin"
            case ["buy", snack] if snack not in PRICES:
                return f"Unknown snack: {snack}"
            case ["buy", snack]:
                price = PRICES[snack]
                if self.credit < price:
                    return f"Need {price - self.credit} more"
                change = self.credit - price
                self.credit = 0
                self.state = State.IDLE
                return f"Enjoy your {snack}! Change: {change}"
            case ["refund"]:
                if self.state is State.IDLE:
                    return "Nothing to refund"
                refund = self.credit
                self.credit = 0
                self.state = State.IDLE
                return f"Refunded {refund}"
            case ["service"]:
                match self.state:
                    case State.IDLE:
                        self.state = State.MAINTENANCE
                        return "Service mode"
                    case State.MAINTENANCE:
                        self.state = State.IDLE
                        return "Ready"
                    case State.HAS_CREDIT:
                        return "Refund first"
            case _:
                return "Unknown command"


machine = VendingMachine()
for command in ["insert 50", "buy water", "insert 50",
                "buy water", "buy pizza", "refund"]:
    print(f"{command} -> {machine.handle(command)}")
```

## Recap

- An **enum** lists every allowed value once: `class Status(Enum): PENDING = auto()`. Typos crash instead of hiding.
- Members have `.name` and `.value`; loop with `for s in Status`, look up with `Status["PENDING"]` or `Status(1)`.
- Compare members with `is`; a plain `Enum` member never equals its value. `StrEnum` and `IntEnum` act like strings and numbers.
- `match`/`case` patterns: literals and `|`, captures (`direction`), the wildcard `_`, and guards (`if ...`).
- **Sequence** patterns (`["go", direction]`, `*rest`), **mapping** patterns (`{"type": "order", "id": order_id}`) and **class** patterns (`Book(title=title)`, or positional with `__match_args__`).
- Use dotted names like `Status.PENDING` in cases: a bare name captures everything.
- Use `match` for the *shape* of data; stick with `if`/`elif` for ranges and simple conditions.
