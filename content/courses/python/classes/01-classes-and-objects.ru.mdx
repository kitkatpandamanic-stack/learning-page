До сих пор вы хранили, например, книгу в словаре: `{"title": "Дюна", "author": "Фрэнк Герберт"}`. Это работает, но ничто не спасёт от опечатки вроде `"titel"`, а код, который работает с книгами, разбросан по всей программе. **Класс (class)** решает обе проблемы: это чертёж, который собирает **данные** и **функции, работающие с ними**, в один аккуратный пакет. 📚

## Ваш первый класс

<CodeExample output={`Дюна
Фрэнк Герберт
Хоббит`}>

```python
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

dune = Book("Дюна", "Фрэнк Герберт")
hobbit = Book("Хоббит", "Дж. Р. Р. Толкин")

print(dune.title)
print(dune.author)
print(hobbit.title)
```

</CodeExample>

- `class Book:` описывает чертёж. Имена классов пишут в стиле **CapWords** (`Book`, `LibraryMember`).
- `Book("Дюна", "Фрэнк Герберт")` создаёт **объект (object)** класса — его ещё называют **экземпляром (instance)**.
- `__init__` — это **инициализатор (initialiser)**. Python вызывает его автоматически при каждом создании объекта и передаёт туда ваши аргументы.
- `self` — это создаваемый объект. `self.title = title` сохраняет значение в этом объекте как **атрибут (attribute)**.

У каждого объекта свои атрибуты: `dune.title` и `hobbit.title` — разные.

## Методы: функции, которые принадлежат классу

**Метод (method)** — это функция, объявленная внутри класса. Его первый параметр — всегда `self`, поэтому метод может читать и менять атрибуты объекта:

<CodeExample output={`Дюна — Фрэнк Герберт
Дюна — Фрэнк Герберт`}>

```python
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def describe(self):
        return f"{self.title} — {self.author}"

dune = Book("Дюна", "Фрэнк Герберт")
print(dune.describe())
print(Book.describe(dune))   # что на самом деле делает Python
```

</CodeExample>

Когда вы пишете `dune.describe()`, Python незаметно превращает это в `Book.describe(dune)`. Вот откуда берётся `self`: вы никогда не передаёте его сами.

## Объекты помнят своё состояние

Методы могут менять атрибуты, и каждый объект хранит свои собственные:

<CodeExample output={`Мэй: книг на руках — 2
Сэм: книг на руках — 0
['Дюна', 'Эмма']`}>

```python
class Member:
    def __init__(self, name):
        self.name = name
        self.borrowed = []

    def borrow(self, title):
        self.borrowed.append(title)

    def summary(self):
        count = len(self.borrowed)
        return f"{self.name}: книг на руках — {count}"

mei = Member("Мэй")
sam = Member("Сэм")
mei.borrow("Дюна")
mei.borrow("Эмма")

print(mei.summary())
print(sam.summary())
print(mei.borrowed)
```

</CodeExample>

<Callout type="note" title="Как напечатать объект">

Сам по себе `print(mei)` покажет что-то бесполезное вроде `<__main__.Member object at 0x10a2f3e50>`. В уроке **«Специальные методы»** вы научите свои классы красиво себя печатать.

</Callout>

## Атрибуты класса и атрибуты экземпляра

Атрибуты, заданные через `self`, принадлежат **одному** объекту. Атрибуты, записанные прямо в теле класса, — это **атрибуты класса (class attributes)**, они общие для всех объектов:

<CodeExample output={`21 21
3
7 21`}>

```python
class Book:
    loan_days = 21      # атрибут класса: общий
    count = 0

    def __init__(self, title):
        self.title = title    # атрибут экземпляра
        Book.count += 1

dune = Book("Дюна")
emma = Book("Эмма")
coraline = Book("Коралина")

print(dune.loan_days, emma.loan_days)
print(Book.count)

coraline.loan_days = 7   # только для этой книги
print(coraline.loan_days, dune.loan_days)
```

</CodeExample>

Когда вы читаете `dune.loan_days`, Python сначала ищет атрибут в объекте, а потом в классе. Присваивание `coraline.loan_days = 7` создаёт атрибут экземпляра только у `coraline`, поэтому остальные книги по-прежнему видят `21`.

<Callout type="warning" title="Не делайте списки общими по ошибке">

Никогда не делайте список (или словарь) атрибутом класса, если каждому объекту нужен свой, — например, `borrowed = []` в теле класса. Тогда у всех читателей будет **один** список на всех! Вместо этого создавайте его в `__init__`: `self.borrowed = []`.

</Callout>

## Свойства: атрибуты с проверкой

А что, если кто-то напишет `book.pages = -5`? **Свойство (property)** позволяет запускать код каждый раз, когда атрибут читают или меняют, — и отклонять плохие значения:

<CodeExample output={`412
Число страниц должно быть положительным
412`}>

```python
class Book:
    def __init__(self, title, pages):
        self.title = title
        self.pages = pages      # проходит через сеттер

    @property
    def pages(self):
        return self._pages

    @pages.setter
    def pages(self, value):
        if value <= 0:
            raise ValueError("Число страниц должно быть положительным")
        self._pages = value

dune = Book("Дюна", 412)
print(dune.pages)

try:
    dune.pages = -5
except ValueError as error:
    print(error)

print(dune.pages)
```

</CodeExample>

- `@property` превращает метод `pages` в то, что **читается как атрибут**: `dune.pages`, без скобок.
- `@pages.setter` срабатывает при **присваивании**: `dune.pages = -5`.
- Настоящее значение хранится в `self._pages`. Подчёркивание в начале имени — это соглашение, которое означает *«внутреннее, пожалуйста, не трогайте»*.

Поскольку `__init__` тоже присваивает `self.pages`, даже `Book("Дюна", 0)` выбросит `ValueError`. Плохие данные просто не попадут внутрь.

Свойство без сеттера доступно **только для чтения** — это отлично подходит для значений, которые вычисляются из других атрибутов:

<CodeExample output={`Мэй Чэнь
МЧ`}>

```python
class Member:
    def __init__(self, first, last):
        self.first = first
        self.last = last

    @property
    def full_name(self):
        return f"{self.first} {self.last}"

    @property
    def initials(self):
        return self.first[0] + self.last[0]

mei = Member("Мэй", "Чэнь")
print(mei.full_name)
print(mei.initials)
```

</CodeExample>

## Альтернативные конструкторы с @classmethod

Иногда данные приходят в другом виде — например, строкой из файла. **Метод класса (class method)** получает не объект, а сам класс (его называют `cls`), поэтому может создать и вернуть новый объект. Это идеальный вариант для **альтернативного конструктора (alternative constructor)**:

<CodeExample output={`Дюна — Фрэнк Герберт
True
False`}>

```python
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    @classmethod
    def from_line(cls, line):
        title, author = line.split(";")
        return cls(title.strip(), author.strip())

    @staticmethod
    def is_valid_isbn(isbn):
        return len(isbn) == 13 and isbn.isdigit()

dune = Book.from_line("Дюна; Фрэнк Герберт")
print(f"{dune.title} — {dune.author}")
print(Book.is_valid_isbn("9780441013593"))
print(Book.is_valid_isbn("12-34"))
```

</CodeExample>

- `@classmethod`: первый параметр — `cls`. `cls(...)` вызывает обычный конструктор. Такой метод вызывают у класса: `Book.from_line(...)`.
- `@staticmethod`: ни `self`, ни `cls`. Это обычная функция, которая живёт внутри класса, потому что связана с ним по смыслу. Используйте такие методы умеренно.

<Callout type="tip" title="Какой метод выбрать?">

Нужны данные объекта? Обычный метод с `self`. Создаёт новый объект? `@classmethod`. Ни то ни другое? `@staticmethod` — или, чаще всего, просто обычная функция вне класса.

</Callout>

## Итоги

- **Класс** — это чертёж; его вызов, например `Book("Дюна", "Фрэнк Герберт")`, создаёт **объект**.
- `__init__` настраивает каждый новый объект; `self` — это сам объект, а `self.x = ...` создаёт **атрибуты экземпляра**.
- **Методы** — это функции внутри класса; `obj.method()` передаёт `obj` как `self`.
- **Атрибуты класса** общие для всех объектов, а атрибуты экземпляра принадлежат одному.
- `@property` (вместе с `@name.setter`) позволяет проверять значения и выбрасывать `ValueError` при плохих данных.
- `@classmethod` получает `cls` и отлично подходит для альтернативных конструкторов; `@staticmethod` не получает ни `self`, ни `cls`.
