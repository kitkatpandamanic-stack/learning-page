Библиотека выдаёт книги, DVD-диски и журналы. Все они разные, но у каждого есть название и каждый можно взять на руки. Вместо того чтобы копировать этот общий код в три класса, вы пишете его один раз в **родительском классе (parent class)**, а остальные классы его **наследуют (inherit)**. 🐼

## Создаём подкласс

Укажите родительский класс в скобках после имени нового класса:

<CodeExample output={`Дюна (1965)
True
True`}>

```python
class LibraryItem:
    def __init__(self, title, year):
        self.title = title
        self.year = year

    def describe(self):
        return f"{self.title} ({self.year})"

class Book(LibraryItem):
    def is_classic(self):
        return self.year < 1980

dune = Book("Дюна", 1965)
print(dune.describe())     # унаследован от LibraryItem
print(dune.is_classic())   # собственный метод Book
print(isinstance(dune, LibraryItem))
```

</CodeExample>

`Book` — это **подкласс (subclass)**, или дочерний класс, класса `LibraryItem`, который для него **родительский** (или базовый, base class). Книга получает всё, что есть у библиотечного экземпляра, включая `__init__` и `describe()`, плюс всё, что вы добавите сверху.

## super().__init__: расширяем настройку

На самом деле нашему `Book` нужны собственные `author` и `pages`. Если подкласс пишет свой `__init__`, он должен вызвать родительский через `super().__init__(...)`, чтобы общая настройка всё равно выполнилась:

<CodeExample output={`Дюна (1965)
Фрэнк Герберт
412`}>

```python
class LibraryItem:
    def __init__(self, title, year):
        self.title = title
        self.year = year

    def describe(self):
        return f"{self.title} ({self.year})"

class Book(LibraryItem):
    def __init__(self, title, year, author, pages):
        super().__init__(title, year)   # родитель задаёт title и year
        self.author = author
        self.pages = pages

dune = Book("Дюна", 1965, "Фрэнк Герберт", 412)
print(dune.describe())
print(dune.author)
print(dune.pages)
```

</CodeExample>

`super()` означает *«мой родительский класс»*. Забудете вызвать `super().__init__` — и `dune.title` так и не появится, а позже вы получите `AttributeError`.

## Переопределение методов

Подкласс может **переопределить (override)** метод, объявив метод с тем же именем. Python всегда берёт самую конкретную версию, какую найдёт. До родительской версии по-прежнему можно добраться через `super()`:

<CodeExample output={`Дюна (1965): 21 дн.
Вверх (2009), 96 мин: 7 дн.`}>

```python
class LibraryItem:
    def __init__(self, title, year):
        self.title = title
        self.year = year

    def loan_days(self):
        return 21

    def describe(self):
        return f"{self.title} ({self.year})"

class DVD(LibraryItem):
    def __init__(self, title, year, minutes):
        super().__init__(title, year)
        self.minutes = minutes

    def loan_days(self):              # заменяет родительский
        return 7

    def describe(self):               # дополняет родительский
        return f"{super().describe()}, {self.minutes} мин"

items = [LibraryItem("Дюна", 1965), DVD("Вверх", 2009, 96)]
for item in items:
    days = item.loan_days()
    print(f"{item.describe()}: {days} дн.")
```

</CodeExample>

Посмотрите на цикл: он вызывает `item.loan_days()`, не задумываясь, что это за экземпляр, а каждый объект отвечает по-своему. Это называется **полиморфизмом (polymorphism)**, и он избавляет код от длинных цепочек `if type == ...`.

## isinstance и issubclass

`isinstance(obj, Class)` проверяет, является ли объект экземпляром класса **или любого его подкласса**. `issubclass(A, B)` задаёт тот же вопрос о двух классах:

<CodeExample output={`True
True
False
True
False`}>

```python
class LibraryItem:
    pass

class DVD(LibraryItem):
    pass

up = DVD()
print(isinstance(up, DVD))
print(isinstance(up, LibraryItem))
print(isinstance(LibraryItem(), DVD))
print(issubclass(DVD, LibraryItem))
print(issubclass(LibraryItem, DVD))
```

</CodeExample>

<Callout type="note" title="Всё наследуется от object">

Каждый ваш класс незаметно наследуется от встроенного в Python класса `object`, поэтому `issubclass(DVD, object)` равно `True`. Именно отсюда берётся поведение по умолчанию — например, тот бесполезный вид, в котором печатаются объекты.

</Callout>

## Собственные исключения

С помощью наследования создают и **собственные типы ошибок**. Унаследуйтесь от `Exception` (или от одного из своих исключений) и дайте классу понятное имя:

<CodeExample output={`Не найдено: Дюна
Проблема в библиотеке: «Вверх» уже выдан
True`}>

```python
class LibraryError(Exception):
    """Базовый класс для всех проблем библиотеки."""

class BookNotFoundError(LibraryError):
    pass

class ItemUnavailableError(LibraryError):
    pass

def find(title):
    raise BookNotFoundError(title)

try:
    find("Дюна")
except BookNotFoundError as error:
    print(f"Не найдено: {error}")

try:
    raise ItemUnavailableError("«Вверх» уже выдан")
except LibraryError as error:      # ловит любой подкласс
    print(f"Проблема в библиотеке: {error}")

print(issubclass(BookNotFoundError, Exception))
```

</CodeExample>

Строка в тройных кавычках — это **строка документации (docstring)**: она описывает класс и одновременно считается его телом, поэтому `pass` не нужен.

<Callout type="tip" title="Одно базовое исключение на проект">

Если у проекта есть одно базовое исключение (например, `LibraryError`) и конкретные подклассы, вызывающий код может выбирать: поймать `BookNotFoundError`, чтобы обработать только этот случай, или `LibraryError`, чтобы обработать **любую** проблему библиотеки и при этом случайно не спрятать посторонние баги.

</Callout>

## Композиция или наследование

Наследование означает **«является»**: DVD *является* библиотечным экземпляром. Но библиотека — это не список книг; у библиотеки **есть** книги. Для отношений «имеет» храните другие объекты в атрибутах. Это называется **композицией (composition)**:

<CodeExample output={`2
['Дюна', 'Эмма']`}>

```python
class Book:
    def __init__(self, title):
        self.title = title

class Library:
    def __init__(self):
        self.books = []       # у Library ЕСТЬ книги

    def add_book(self, book):
        self.books.append(book)

    def titles(self):
        return [book.title for book in self.books]

library = Library()
library.add_book(Book("Дюна"))
library.add_book(Book("Эмма"))
print(len(library.books))
print(library.titles())
```

</CodeExample>

Если бы вы написали `class Library(list)`, вместе с ним пришли бы все методы списка — `sort()`, `clear()`, `pop()`, — независимо от того, есть ли в них смысл для библиотеки. Композиция позволяет выбрать, какие именно методы предлагать.

<Callout type="tip" title="Предпочитайте композицию">

Спросите себя: *«является»* или *«имеет»*? Используйте наследование только для настоящего отношения «является». Сомневаетесь — выбирайте композицию: её проще поменять потом.

</Callout>

## @dataclass: быстрый способ описать класс данных

Многие классы просто хранят данные. Писать `__init__` с `self.x = x` для каждого поля скучно, поэтому модуль `dataclasses` может сделать это за вас:

<CodeExample output={`Book(title='Дюна', author='Фрэнк Герберт', year=1965, tags=[])
True
Member(name='Мэй', borrowed=['Дюна'])`}>

```python
from dataclasses import dataclass, field

@dataclass
class Book:
    title: str
    author: str
    year: int = 2000          # значение по умолчанию
    tags: list = field(default_factory=list)

@dataclass
class Member:
    name: str
    borrowed: list = field(default_factory=list)

dune = Book("Дюна", "Фрэнк Герберт", 1965)
print(dune)
print(dune == Book("Дюна", "Фрэнк Герберт", 1965))

mei = Member("Мэй")
mei.borrowed.append("Дюна")
print(mei)
```

</CodeExample>

- Каждая строка вида `name: type` становится полем. `@dataclass` сам пишет `__init__`, читаемый вывод при печати и сравнение через `==`.
- Подсказки типов (`str`, `int`) служат документацией; Python их не проверяет.
- Для списка по умолчанию используйте `field(default_factory=list)`, чтобы каждый объект получил **свой** новый список.

В dataclass по-прежнему можно добавлять обычные методы и свойства.

## Итоги

- `class Child(Parent):` создаёт **подкласс**, который наследует атрибуты и методы родителя.
- Вызывайте `super().__init__(...)` в `__init__` подкласса, чтобы настройка родителя тоже выполнилась.
- **Переопределяйте** метод, объявляя его заново; через `super().method()` можно дополнить родительскую версию.
- `isinstance(obj, Class)` и `issubclass(A, B)` проверяют отношения между классами, включая родителей.
- Собственные исключения создают, наследуясь от `Exception`, — лучше всего с одной базовой ошибкой на проект.
- Наследование — для отношения **«является»**, а **композиция** (хранение объектов в атрибутах) — для **«имеет»**.
- `@dataclass` пишет `__init__`, вывод при печати и `==` для простых классов данных; для списков по умолчанию используйте `field(default_factory=list)`.
