So far you've stored things like a book in a dictionary: `{"title": "Dune", "author": "Frank Herbert"}`. That works, but nothing stops a typo like `"titel"`, and the code that works with books is scattered around your program. A **class** fixes both: it's a blueprint that bundles **data** and the **functions that use it** into one neat package. 📚

## Your first class

<CodeExample output={`Dune
Frank Herbert
The Hobbit`}>

```python
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

dune = Book("Dune", "Frank Herbert")
hobbit = Book("The Hobbit", "J.R.R. Tolkien")

print(dune.title)
print(dune.author)
print(hobbit.title)
```

</CodeExample>

- `class Book:` defines the blueprint. Class names use **CapWords** (`Book`, `LibraryMember`).
- `Book("Dune", "Frank Herbert")` creates an **object** (also called an **instance**) of the class.
- `__init__` is the **initialiser**. Python calls it automatically every time you create a new object, passing your arguments along.
- `self` is the object being created. `self.title = title` stores the value on that object as an **attribute**.

Each object has its own attributes: `dune.title` and `hobbit.title` are different.

## Methods: functions that belong to a class

A **method** is a function defined inside a class. Its first parameter is always `self`, so it can read and change the object's attributes:

<CodeExample output={`Dune by Frank Herbert
Dune by Frank Herbert`}>

```python
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def describe(self):
        return f"{self.title} by {self.author}"

dune = Book("Dune", "Frank Herbert")
print(dune.describe())
print(Book.describe(dune))   # what Python really does
```

</CodeExample>

When you write `dune.describe()`, Python quietly turns it into `Book.describe(dune)`. That's where `self` comes from: you never pass it yourself.

## Objects remember their state

Methods can change attributes, and each object keeps track of its own:

<CodeExample output={`Mei has 2 book(s)
Sam has 0 book(s)
['Dune', 'Emma']`}>

```python
class Member:
    def __init__(self, name):
        self.name = name
        self.borrowed = []

    def borrow(self, title):
        self.borrowed.append(title)

    def summary(self):
        count = len(self.borrowed)
        return f"{self.name} has {count} book(s)"

mei = Member("Mei")
sam = Member("Sam")
mei.borrow("Dune")
mei.borrow("Emma")

print(mei.summary())
print(sam.summary())
print(mei.borrowed)
```

</CodeExample>

<Callout type="note" title="Printing an object">

`print(mei)` on its own shows something unhelpful like `<__main__.Member object at 0x10a2f3e50>`. In the **Special Methods** lesson you'll teach your classes to print themselves nicely.

</Callout>

## Class attributes vs instance attributes

Attributes set on `self` belong to **one** object. Attributes written directly in the class body are **class attributes**, shared by every object:

<CodeExample output={`21 21
3
7 21`}>

```python
class Book:
    loan_days = 21      # class attribute: shared
    count = 0

    def __init__(self, title):
        self.title = title    # instance attribute
        Book.count += 1

dune = Book("Dune")
emma = Book("Emma")
coraline = Book("Coraline")

print(dune.loan_days, emma.loan_days)
print(Book.count)

coraline.loan_days = 7   # only this book
print(coraline.loan_days, dune.loan_days)
```

</CodeExample>

When you read `dune.loan_days`, Python looks on the object first, then on the class. Assigning `coraline.loan_days = 7` creates an instance attribute on `coraline` only, so the other books still see `21`.

<Callout type="warning" title="Don't share lists by accident">

Never put a list (or dict) as a class attribute when each object needs its own, like `borrowed = []` in the class body. Every member would share **one** list! Create it in `__init__` with `self.borrowed = []` instead.

</Callout>

## Properties: attributes with validation

What if someone writes `book.pages = -5`? A **property** lets you run code whenever an attribute is read or set, so you can reject bad values:

<CodeExample output={`412
Pages must be a positive number
412`}>

```python
class Book:
    def __init__(self, title, pages):
        self.title = title
        self.pages = pages      # goes through the setter

    @property
    def pages(self):
        return self._pages

    @pages.setter
    def pages(self, value):
        if value <= 0:
            raise ValueError("Pages must be a positive number")
        self._pages = value

dune = Book("Dune", 412)
print(dune.pages)

try:
    dune.pages = -5
except ValueError as error:
    print(error)

print(dune.pages)
```

</CodeExample>

- `@property` turns the `pages` method into something you **read like an attribute**: `dune.pages`, no brackets.
- `@pages.setter` runs when you **assign**: `dune.pages = -5`.
- The real value lives in `self._pages`. The leading underscore is a convention meaning *"internal, please don't touch"*.

Because `__init__` also assigns `self.pages`, even `Book("Dune", 0)` raises a `ValueError`. Bad data never gets in.

A property without a setter is **read-only**, which is great for values worked out from other attributes:

<CodeExample output={`Mei Chen
MC`}>

```python
class Member:
    def __init__(self, first, last):
        self.first = first
        self.last = last

    @property
    def full_name(self):
        return f"{self.first} {self.last}"

    @property
    def initials(self):
        return self.first[0] + self.last[0]

mei = Member("Mei", "Chen")
print(mei.full_name)
print(mei.initials)
```

</CodeExample>

## Alternative constructors with @classmethod

Sometimes your data arrives in a different shape, like a line from a file. A **class method** receives the class itself (called `cls`) instead of an object, so it can build and return a new object. It's perfect for an **alternative constructor**:

<CodeExample output={`Dune by Frank Herbert
True
False`}>

```python
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    @classmethod
    def from_line(cls, line):
        title, author = line.split(";")
        return cls(title.strip(), author.strip())

    @staticmethod
    def is_valid_isbn(isbn):
        return len(isbn) == 13 and isbn.isdigit()

dune = Book.from_line("Dune; Frank Herbert")
print(f"{dune.title} by {dune.author}")
print(Book.is_valid_isbn("9780441013593"))
print(Book.is_valid_isbn("12-34"))
```

</CodeExample>

- `@classmethod`: first parameter is `cls`. `cls(...)` calls the normal constructor. You call it on the class: `Book.from_line(...)`.
- `@staticmethod`: no `self` and no `cls`. It's just a plain function that lives inside the class because it's related to it. Use it sparingly.

<Callout type="tip" title="Which kind of method?">

Needs the object's data? Normal method with `self`. Builds a new object? `@classmethod`. Neither? A `@staticmethod`, or often just a regular function outside the class.

</Callout>

## Recap

- A **class** is a blueprint; calling it, like `Book("Dune", "Frank Herbert")`, creates an **object**.
- `__init__` sets up each new object; `self` is the object itself, and `self.x = ...` creates **instance attributes**.
- **Methods** are functions inside a class; `obj.method()` passes `obj` in as `self`.
- **Class attributes** are shared by all objects; instance attributes belong to one.
- `@property` (plus `@name.setter`) lets you validate values and raise `ValueError` for bad data.
- `@classmethod` gets `cls` and is great for alternative constructors; `@staticmethod` gets neither `self` nor `cls`.
