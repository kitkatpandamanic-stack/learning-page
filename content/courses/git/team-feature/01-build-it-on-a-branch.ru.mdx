Добро пожаловать в **итоговый проект уровня 1**! 🎬 **Лина** ведёт «Пятничный киноклуб» в районной библиотеке, а её друг **Омар** помогает с небольшим сайтом клуба. Сайт хранится в Git-репозитории, и вы только что присоединились к команде. Первая задача — страница с **осенним расписанием**, чтобы участники знали, какой фильм покажут в какую пятницу.

В команде не работают прямо в `main`. За две части вы проделаете то, что разработчики делают каждый день:

- **Часть 1 (этот урок):** изучите репозиторий, сделаете страницу расписания в отдельной ветке за несколько небольших коммитов, не пустите в Git сгенерированные файлы и исправите две ошибки.
- **Часть 2:** тем временем в `main` попадёт работа Омара. Вы сольёте её, разрешите конфликт и перенесёте свою задачу в `main`.

Всё нужное вы уже знаете из уровня 1:

- **head**, **wc**, **grep**, конвейеры с **cut**, **sort**, **uniq -c** и **tee** и перенаправления («Конвейеры и текст»),
- **git diff**, **.gitignore**, **git restore** и **git commit --amend** («Git каждый день»),
- **git branch**, **git switch**, **git merge** и конфликты слияния («Ветки и слияние»).

Каждая строка — один фильм: **название**, **год** и **жанр** через запятую. Значит, фильмов 10, из них 4 мультфильма (animation), а `grep -n` подсказывает, на каких строках комедии (comedy).

А сколько фильмов **каждого** жанра? Это работа для конвейера. `cut -d, -f3` оставляет только третье поле (поля разделены запятыми), `sort` ставит одинаковые жанры рядом, а `uniq -c` считает каждую группу одинаковых строк:

```bash
cut -d, -f3 films.txt | head -n 3
cut -d, -f3 films.txt | sort | uniq -c
cut -d, -f3 films.txt | sort | uniq -c | sort -rn
```

</CodeExample>

- Первая строка проверяет начало конвейера отдельно: да, там действительно одни жанры.
- `uniq -c` объединяет только **соседние** строки, поэтому `sort` должен идти первым. Без него два `animation` в начале и те, что ниже, посчитались бы отдельно.
- `sort -rn` в конце сортирует по количеству, сначала самые большие (`-n` — как числа, `-r` — в обратном порядке).

На Mac `wc` и `uniq -c` дополняют числа другим количеством пробелов. Сами числа те же.

Лина хотела бы сохранить этот подсчёт. `tee` показывает то, что идёт по конвейеру, **и** сохраняет это в файл. Положите его в отдельную папку `reports`:

```bash
mkdir reports
cut -d, -f3 films.txt | sort | uniq -c | tee reports/genres.txt
```

<Callout type="tip" title="Собирайте конвейер по шагу">

Запустите первую команду отдельно, посмотрите на её вывод, потом допишите `| следующая-команда` и запустите снова. Если длинный конвейер выводит что-то странное, укорачивайте его, пока странность не пропадёт. Если `|`, `>` и `tee` подзабылись, [вернитесь к конвейерам и перенаправлениям](/learn/git/pipes-and-redirects).

</Callout>

## Ветка для задачи

У Лины одно правило: **`main` всегда работает.** Сайт клуба собирается из `main`, поэтому недоделанная страница туда попадать не должна. Для этого и нужны ветки. Вы сделаете расписание в ветке `schedule`, и `main` не сдвинется, пока задача не будет готова.

`git switch -c` создаёт ветку и сразу на неё переключается. `git branch -v` выводит ветки вместе с коммитом, на который указывает каждая:

Ни одному из двух неотслеживаемых имён в репозитории не место:

- **`.DS_Store`** — мусор от Mac.
- **`reports/genres.txt`** — **сгенерированный** файл: один конвейер в любой момент заново сделает его из `films.txt`. Если его закоммитить, он устареет, как только кто-нибудь добавит фильм, а история заполнится копиями отчёта.

Файл `.gitignore` в верхней папке перечисляет имена, которые Git должен оставить в покое, по одному правилу на строку. `reports/` с косой чертой в конце значит «папка `reports` со всем содержимым». После этого `git status` показывает только сам `.gitignore`, а `git check-ignore` выводит игнорируемые имена: `index.html` в списке нет, значит, Git по-прежнему его отслеживает.

`.gitignore` коммитят, как любой другой файл. Тогда правила общие: когда Mac Омара создаст свой `.DS_Store`, Git проигнорирует и его. Больше шаблонов — [в уроке об игнорировании файлов](/learn/git/ignoring-files).

Вы присоединились к командному проекту и сделали задачу так, как это делают команды:
