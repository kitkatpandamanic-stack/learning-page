You can save versions now. But a history is only useful if you can **read** it: what changed, when, and why? 🔍 In this lesson you'll list the commits with `git log`, look inside any one of them with `git show`, and learn to read the `+` and `-` lines that show exactly what changed. Then you'll build a small recipe book with a history of its own.

## The examples' repository

The examples in this lesson start inside `recipes`, a repository with **three commits**, made with the commands you learned in the last lesson:

```bash
echo "Pancakes: 2 eggs, 1 cup of milk, 1 cup of flour" > pancakes.txt
git add pancakes.txt
git commit -m "Add pancake recipe"

echo "Tomato soup: 4 tomatoes, 1 onion, 2 cups of water" > soup.txt
git add soup.txt
git commit -m "Add tomato soup recipe"

echo "Pancakes: 3 eggs, 1 cup of milk, 1 cup of flour" > pancakes.txt
echo "Fry each pancake for 1 minute on each side" >> pancakes.txt
git add pancakes.txt
git commit -m "Use 3 eggs and add frying time"
```

The last commit rewrote `pancakes.txt` with `>` (3 eggs instead of 2) and then added a second line with `>>`.

## git log: the list of commits

**`git log`** shows the history, **newest commit first**:


</CodeExample>

Each commit is a little block. From the top:

- **`commit 90d4b70…`**: the commit's **hash**, a 40-character ID made of digits and the letters `a` to `f`. Git calculates it from everything in the commit (the files, the message, the author, the date and the commit before it), so no two commits share one.
- **`(HEAD -> main)`**: a label on the newest commit. `main` is the line of history you're on, and **`HEAD`** means "where you are now". After your next commit, the label moves up to it.
- **`Author:`**: who made the commit: the `user.name` and `user.email` you set up earlier. In this practice terminal, everyone is `Panda`.
- **`Date:`**: when the commit was made. `+0000` is the time zone (here UTC). The practice terminal's clock is fixed, so it always says 5 January 2026, one minute apart.
- The indented line is the **message**.

The oldest commit, where the project began, is at the **bottom**.

<Callout type="tip" title="Long logs on your own computer">

On a real computer, a long `git log` opens in a **pager**: a viewer that shows one screen at a time. Scroll with the arrow keys or Space, and press **`q`** to get back to the prompt. This practice terminal just prints the whole log.

</Callout>

## git log --oneline: one line per commit

Most of the time you don't need every detail. **`git log --oneline`** shows one line per commit: a **short hash** and the message.

## Short hashes

Nobody types 40 characters. The **short hash** is just the first 7 characters of the full one: `2929040` is short for `2929040ff06e4dc280b51fdec2e66d833c8dabdd`. You can use it anywhere Git asks for a commit. Git even accepts fewer characters (at least 4), as long as no other commit in the repository starts the same way.

## git show: look inside a commit

**`git show`** followed by a hash shows that commit's details, then exactly what it changed. Here's the commit that added the soup:

<CodeExample setup={`mkdir recipes
cd recipes
git init
echo "Pancakes: 2 eggs, 1 cup of milk, 1 cup of flour" > pancakes.txt
git add pancakes.txt
git commit -m "Add pancake recipe"
echo "Tomato soup: 4 tomatoes, 1 onion, 2 cups of water" > soup.txt
git add soup.txt
git commit -m "Add tomato soup recipe"
echo "Pancakes: 3 eggs, 1 cup of milk, 1 cup of flour" > pancakes.txt
echo "Fry each pancake for 1 minute on each side" >> pancakes.txt
git add pancakes.txt
git commit -m "Use 3 eggs and add frying time"`} output={`commit 2929040ff06e4dc280b51fdec2e66d833c8dabdd
Author: Panda <panda@pandadev.dev>
Date:   Mon Jan 5 09:02:00 2026 +0000

    Add tomato soup recipe

diff --git a/soup.txt b/soup.txt
new file mode 100644
index 0000000..49d6096
--- /dev/null
+++ b/soup.txt
@@ -0,0 +1 @@
+Tomato soup: 4 tomatoes, 1 onion, 2 cups of water`}>

```bash
git show 2929040
```

</CodeExample>

The top part is the same block you saw in `git log`. Below it comes the **diff** ("difference"): what this commit changed compared with the commit before it.

- **`diff --git a/soup.txt b/soup.txt`** starts the changes to one file. `a/` is the file before, `b/` is the file after.
- **`new file mode 100644`** says the file is new in this commit. The `index` line is Git's own bookkeeping; you can skip it.
- **`--- /dev/null`** means "before: nothing" (the file didn't exist), and **`+++ b/soup.txt`** is the file after.
- **`@@ -0,0 +1 @@`** says where in the file the change is. You can skip it for now.
- The line that starts with **`+`** was **added**.

## Reading a change: + and - lines

Now the commit that improved the pancakes. With no hash, `git show` shows the newest commit, the one marked `HEAD`:

<CodeExample setup={`mkdir recipes
cd recipes
git init
echo "Pancakes: 2 eggs, 1 cup of milk, 1 cup of flour" > pancakes.txt
git add pancakes.txt
git commit -m "Add pancake recipe"
echo "Tomato soup: 4 tomatoes, 1 onion, 2 cups of water" > soup.txt
git add soup.txt
git commit -m "Add tomato soup recipe"
echo "Pancakes: 3 eggs, 1 cup of milk, 1 cup of flour" > pancakes.txt
echo "Fry each pancake for 1 minute on each side" >> pancakes.txt
git add pancakes.txt
git commit -m "Use 3 eggs and add frying time"`} output={`commit 90d4b70dfa44769e8fe50fae498686961895ce25 (HEAD -> main)
Author: Panda <panda@pandadev.dev>
Date:   Mon Jan 5 09:03:00 2026 +0000

    Use 3 eggs and add frying time

diff --git a/pancakes.txt b/pancakes.txt
index 810d9db..ada4018 100644
--- a/pancakes.txt
+++ b/pancakes.txt
@@ -1 +1,2 @@
-Pancakes: 2 eggs, 1 cup of milk, 1 cup of flour
+Pancakes: 3 eggs, 1 cup of milk, 1 cup of flour
+Fry each pancake for 1 minute on each side`}>

```bash
git show
```

</CodeExample>

This file already existed, so the diff compares the old version (`--- a/pancakes.txt`) with the new one (`+++ b/pancakes.txt`):

- A line starting with **`-`** was **removed**: the old line with 2 eggs.
- A line starting with **`+`** was **added**: the new line with 3 eggs, and the frying line.
- Git works in **whole lines**. Changing one word, like `2` to `3`, shows up as the old line removed and the new line added, one right after the other.
- Lines starting with a **space** (you'll see them in bigger files) didn't change. Git shows a few of them around each change so you can see where it is.

In a real terminal, removed lines are usually red and added lines green.

## Mini-project: a recipe book with history

Time to put the whole module together: make a repository, save versions of it one step at a time, and read back the story you wrote. 🐼

<Exercise

    { name: "Everything is committed", check: "Object.keys(await git.status()).length === 0" },
    { name: "Checked the history with git log", check: "commands.some(c => /\\bgit log\\b/.test(c))" },
  ]}
>

Panda wants a recipe book where no good version of a recipe is ever lost. You're in `~/recipes`, an empty folder. Build the book in **three commits**:

1. Make `recipes` a Git repository.
2. **Commit 1:** create `omelette.txt` holding the line `Omelette: 2 eggs, a pinch of salt` and commit it with the message `Add omelette recipe`.
3. **Commit 2:** create `tea.txt` holding the line `Green tea: 1 spoon of tea, 1 cup of hot water` and commit it with the message `Add green tea recipe`.
4. **Commit 3:** add a second line, `Cook on low heat for 3 minutes`, to the **end** of `omelette.txt` and commit it with the message `Add cooking time to omelette`.
5. Check your work with `git log --oneline`. Then try `git show` on your last commit and find your new line in the diff.

At the end, `git status` should say the working tree is clean.

<Hint>

## Recap

- **`git log`** lists the commits, **newest first**: hash, author, date and message for each.
- **`(HEAD -> main)`** marks the newest commit on `main`, where you are now.
- **`git log --oneline`** shows one line per commit; **`-n 3`** shows only the newest three.
- A **short hash** is the first 7 characters of the full hash, and works anywhere Git needs a commit.
- **`git show <hash>`** shows a commit and its **diff**; `git show` alone shows the newest commit.
- In a diff, **`+`** lines were added, **`-`** lines were removed, and a changed line shows up as one of each.
