Сохранять версии вы уже умеете. Но история полезна, только если её можно **прочитать**: что изменилось, когда и зачем? 🔍 В этом уроке вы выведете список коммитов командой `git log`, заглянете в любой из них через `git show` и научитесь читать строки с `+` и `-`, которые точно показывают, что изменилось. А потом соберёте небольшую книгу рецептов со своей собственной историей.

## Репозиторий для примеров

Примеры этого урока начинаются внутри `recipes` — репозитория с **тремя коммитами**, сделанными командами из прошлого урока:

```bash
echo "Блины: 2 яйца, 1 стакан молока, 1 стакан муки" > pancakes.txt
git add pancakes.txt
git commit -m "Добавить рецепт блинов"

echo "Томатный суп: 4 помидора, 1 луковица, 2 стакана воды" > soup.txt
git add soup.txt
git commit -m "Добавить рецепт томатного супа"

echo "Блины: 3 яйца, 1 стакан молока, 1 стакан муки" > pancakes.txt
echo "Жарить каждый блин по 1 минуте с каждой стороны" >> pancakes.txt
git add pancakes.txt
git commit -m "Взять 3 яйца и добавить время жарки"
```

Последний коммит переписал `pancakes.txt` через `>` (3 яйца вместо 2), а потом дописал вторую строку через `>>`.

## git log: список коммитов

**`git log`** показывает историю, **начиная с самого нового коммита**:

```bash
git log
```

</CodeExample>

Каждый коммит — небольшой блок. Сверху вниз:

- **`commit dabb0bf…`** — **хеш** (hash) коммита, 40-символьный идентификатор из цифр и букв от `a` до `f`. Git вычисляет его из всего содержимого коммита (файлов, сообщения, автора, даты и предыдущего коммита), поэтому у двух коммитов не бывает одинакового хеша.
- **`(HEAD -> main)`** — метка на самом новом коммите. `main` — линия истории, на которой вы находитесь, а **`HEAD`** означает «где вы сейчас». После следующего коммита метка переедет на него.
- **`Author:`** — автор коммита: `user.name` и `user.email`, которые вы настроили раньше. В учебном терминале все авторы — `Panda`.
- **`Date:`** — когда сделан коммит. `+0000` — часовой пояс (здесь UTC). Часы учебного терминала фиксированные, поэтому дата всегда 5 января 2026 года, с разницей в минуту.
- Строка с отступом — **сообщение**.

Самый старый коммит, с которого начался проект, — **внизу**.

<Callout type="tip" title="Длинный log на вашем компьютере">

На настоящем компьютере длинный `git log` открывается в **пейджере** (pager) — программе, которая показывает текст по одному экрану. Листайте стрелками или пробелом, а чтобы вернуться к приглашению, нажмите **`q`**. Учебный терминал просто выводит весь log целиком.

</Callout>

## Короткие хеши

Никто не набирает 40 символов. **Короткий хеш** — это просто первые 7 символов полного: `3b6ead0` — сокращение от `3b6ead0555b1d1b639f5979293a0110cd25fcaa9`. Его можно использовать везде, где Git ждёт коммит. Git принимает даже меньше символов (не меньше 4), если ни один другой коммит в репозитории не начинается так же.

## git show: заглядываем в коммит

**`git show`** с хешем показывает подробности коммита, а под ними — что именно он изменил. Вот коммит, который добавил суп:

<CodeExample setup={`mkdir recipes
cd recipes
git init
echo "Блины: 2 яйца, 1 стакан молока, 1 стакан муки" > pancakes.txt
git add pancakes.txt
git commit -m "Добавить рецепт блинов"
echo "Томатный суп: 4 помидора, 1 луковица, 2 стакана воды" > soup.txt
git add soup.txt
git commit -m "Добавить рецепт томатного супа"
echo "Блины: 3 яйца, 1 стакан молока, 1 стакан муки" > pancakes.txt
echo "Жарить каждый блин по 1 минуте с каждой стороны" >> pancakes.txt
git add pancakes.txt
git commit -m "Взять 3 яйца и добавить время жарки"`} output={`commit 3b6ead0555b1d1b639f5979293a0110cd25fcaa9
Author: Panda <panda@pandadev.dev>
Date:   Mon Jan 5 09:02:00 2026 +0000

    Добавить рецепт томатного супа

diff --git a/soup.txt b/soup.txt
new file mode 100644
index 0000000..0ef22db
--- /dev/null
+++ b/soup.txt
@@ -0,0 +1 @@
+Томатный суп: 4 помидора, 1 луковица, 2 стакана воды`}>

```bash
git show 3b6ead0
```

</CodeExample>

Верхняя часть — тот же блок, что в `git log`. Под ним идёт **diff** (difference — «разница»): что этот коммит изменил по сравнению с предыдущим.

- **`diff --git a/soup.txt b/soup.txt`** начинает изменения одного файла. `a/` — файл до, `b/` — файл после.
- **`new file mode 100644`** говорит, что файл в этом коммите новый. Строка `index` — служебная информация Git, её можно пропустить.
- **`--- /dev/null`** означает «до: ничего» (файла не было), а **`+++ b/soup.txt`** — файл после.
- **`@@ -0,0 +1 @@`** указывает, в каком месте файла изменение. Пока его можно пропустить.
- Строка, которая начинается с **`+`**, **добавлена**.

## Читаем изменение: строки с + и -

Теперь коммит, который улучшил блины. Без хеша `git show` показывает самый новый коммит — тот, что помечен `HEAD`:

<CodeExample setup={`mkdir recipes
cd recipes
git init
echo "Блины: 2 яйца, 1 стакан молока, 1 стакан муки" > pancakes.txt
git add pancakes.txt
git commit -m "Добавить рецепт блинов"
echo "Томатный суп: 4 помидора, 1 луковица, 2 стакана воды" > soup.txt
git add soup.txt
git commit -m "Добавить рецепт томатного супа"
echo "Блины: 3 яйца, 1 стакан молока, 1 стакан муки" > pancakes.txt
echo "Жарить каждый блин по 1 минуте с каждой стороны" >> pancakes.txt
git add pancakes.txt
git commit -m "Взять 3 яйца и добавить время жарки"`} output={`commit dabb0bfa027675a64ef5884cb98d01f09a5341ae (HEAD -> main)
Author: Panda <panda@pandadev.dev>
Date:   Mon Jan 5 09:03:00 2026 +0000

    Взять 3 яйца и добавить время жарки

diff --git a/pancakes.txt b/pancakes.txt
index a22adea..3e99be3 100644
--- a/pancakes.txt
+++ b/pancakes.txt
@@ -1 +1,2 @@
-Блины: 2 яйца, 1 стакан молока, 1 стакан муки
+Блины: 3 яйца, 1 стакан молока, 1 стакан муки
+Жарить каждый блин по 1 минуте с каждой стороны`}>

```bash
git show
```

</CodeExample>

Этот файл уже существовал, поэтому diff сравнивает старую версию (`--- a/pancakes.txt`) с новой (`+++ b/pancakes.txt`):

- Строка, которая начинается с **`-`**, **удалена**: старая строка с двумя яйцами.
- Строка, которая начинается с **`+`**, **добавлена**: новая строка с тремя яйцами и строка про жарку.
- Git работает **целыми строками**. Замена одного слова, например `2` на `3`, выглядит как удалённая старая строка и сразу за ней добавленная новая.
- Строки, которые начинаются с **пробела** (вы увидите их в файлах побольше), не менялись. Git показывает несколько таких строк вокруг каждого изменения, чтобы было видно, где оно.

В настоящем терминале удалённые строки обычно красные, а добавленные — зелёные.

## Мини-проект: книга рецептов с историей

Пора собрать весь модуль вместе: создать репозиторий, шаг за шагом сохранять его версии и прочитать историю, которую вы написали. 🐼

<Exercise
  title="Мини-проект: книга рецептов с историей"
  language="shell"
  setup={`mkdir recipes
cd recipes`}
  starter={`# Вы в ~/recipes — пустой папке.
# 1. Превратите её в Git-репозиторий
# 2. Коммит 1: omelette.txt
# 3. Коммит 2: tea.txt
# 4. Коммит 3: ещё одна строка в omelette.txt
# 5. Проверьте историю
`}
  tests={[
    { name: "recipes — Git-репозиторий", check: "git.isRepo() && isDir('.git')" },
    { name: "Ровно 3 коммита", check: "(await git.log()).length === 3" },
    { name: "Коммит 1 добавляет только omelette.txt", check: "(await git.show('HEAD~2', 'omelette.txt')) !== null && (await git.show('HEAD~2', 'tea.txt')) === null" },
    { name: "Коммит 2 добавляет tea.txt и не меняет omelette.txt", check: "(await git.show('HEAD~1', 'tea.txt')) !== null && (await git.show('HEAD~1', 'omelette.txt')) === (await git.show('HEAD~2', 'omelette.txt'))" },
    { name: "Коммит 3 дописывает строку в omelette.txt и не трогает tea.txt", check: "(async () => { const before = await git.show('HEAD~1', 'omelette.txt'); const after = await git.show('HEAD', 'omelette.txt'); return before !== null && after !== null && after.length > before.length && after.startsWith(before) && (await git.show('HEAD', 'tea.txt')) === (await git.show('HEAD~1', 'tea.txt')); })()" },
    { name: "В каждом сообщении назван его рецепт", check: "(async () => { const log = await git.log(); return log.length === 3 && /omelette|омлет/i.test(log[2].message) && /tea|ча[йя]/i.test(log[1].message) && /omelette|омлет/i.test(log[0].message); })()" },
    { name: "Всё закоммичено", check: "Object.keys(await git.status()).length === 0" },
    { name: "История проверена через git log", check: "commands.some(c => /\\bgit log\\b/.test(c))" },
  ]}
>

Панда хочет книгу рецептов, в которой ни одна удачная версия рецепта не потеряется. Вы в `~/recipes` — пустой папке. Соберите книгу за **три коммита**:

1. Превратите `recipes` в Git-репозиторий.
2. **Коммит 1:** создайте `omelette.txt` со строкой `Омлет: 2 яйца, щепотка соли` и закоммитьте его с сообщением `Добавить рецепт омлета`.
3. **Коммит 2:** создайте `tea.txt` со строкой `Зелёный чай: 1 ложка чая, 1 стакан горячей воды` и закоммитьте его с сообщением `Добавить рецепт зелёного чая`.
4. **Коммит 3:** допишите в **конец** `omelette.txt` вторую строку, `Готовить на слабом огне 3 минуты`, и закоммитьте с сообщением `Добавить время готовки омлета`.
5. Проверьте работу командой `git log --oneline`. Потом выполните `git show` для последнего коммита и найдите в diff свою новую строку.

В конце `git status` должен сообщить, что рабочая папка чистая.

<Hint>

Каждый коммит — один и тот же ритм: создать или изменить файл, подготовить его, закоммитить с сообщением. Сделайте так три раза, и пусть каждый рецепт будет в своём коммите.

</Hint>

<Hint>

`git init` создаёт репозиторий. `echo "…" > файл` создаёт файл с одной строкой, а `>>` дописывает строку в конец уже существующего файла. Затем для каждого шага — `git add` и `git commit -m "…"`. В конце — `git log --oneline` и `git show`.

</Hint>

## Итоги

- **`git log`** перечисляет коммиты, **начиная с самого нового**: хеш, автор, дата и сообщение для каждого.
- **`(HEAD -> main)`** отмечает самый новый коммит на `main` — то место, где вы сейчас.
- **`git log --oneline`** показывает по строке на коммит; **`-n 3`** — только три самых новых.
- **Короткий хеш** — первые 7 символов полного, он работает везде, где Git нужен коммит.
- **`git show <хеш>`** показывает коммит и его **diff**; просто `git show` — самый новый коммит.
- В diff строки с **`+`** добавлены, с **`-`** удалены, а изменённая строка выглядит как одна удалённая и одна добавленная.
