Бывала у вас такая папка? 🙈

```text
essay.docx
essay_v2.docx
essay_final.docx
essay_final_v2.docx
essay_final_v2_REALLY_final.docx
```

Какой файл самый свежий? Чем `v2` отличается от `final`? Какой из них уже читал преподаватель? Этого не знает никто, даже тот, кто их создал. В этом уроке вы познакомитесь с инструментом, которым программисты пользуются вместо копий, — **контролем версий** (version control). К концу урока ваша папка станет первым **Git-репозиторием**.

## Что не так с копиями

Сохранить копию перед большой правкой — здравая мысль. Беда в том, о чём копии _молчат_:

- **Что изменилось?** Придётся открыть два файла рядом и искать различия глазами.
- **Почему изменилось?** Имя файла не объяснит, что «в v2 убрано скучное вступление».
- **Кто и когда это изменил?** Ни слова. А когда двое пересылают друг другу копии, чья-то работа обязательно потеряется.
- **Какая версия настоящая?** Копии копятся, и скоро никто не решается удалить ни одну.

С кодом та же история, только хуже: в проекте бывают сотни файлов, и одна неудачная правка может сломать всё.

## Что делает контроль версий

**Система контроля версий** — это программа, которая помнит каждую сохранённую версию проекта за вас. Вы работаете в **одной папке**, где у каждого файла **одна копия**, а в удачный момент говорите программе: «сохрани эту версию». Потом можно:

- увидеть **весь список** сохранённых версий, от новых к старым;
- увидеть, **что именно изменилось** в каждой, строка за строкой;
- узнать, **кто** сохранил версию, **когда** и **зачем**;
- вернуться к любой старой версии, если что-то сломалось.

Самая популярная система контроля версий с огромным отрывом — **Git**. Он бесплатный, работает прямо на вашем компьютере, и им пользуются почти все команды разработчиков в мире. Его вы и изучите в этом курсе.

## Репозитории и коммиты

С Git постоянно звучат два слова:

- **Репозиторий** (repository, или **репо**) — папка проекта, за которой следит Git: ваши файлы плюс полная история их сохранённых версий.
- **Коммит** (commit) — одна сохранённая версия, **снимок** (snapshot) всех файлов проекта в один момент. Вместе с ним записываются **сообщение** о том, что изменилось, **автор** и **дата**.

Так папка с сочинениями превращается в один `essay.docx` в репозитории, а в истории Git появляются записи вроде «Написать черновик», «Убрать скучное вступление», «Исправить опечатку в заголовке». Каждая из них — коммит.

<Callout type="note" title="Git и GitHub — не одно и то же">

**Git** — программа на вашем компьютере, которая хранит историю. **GitHub** — сайт, который хранит Git-репозитории в интернете, чтобы ими можно было делиться и работать над ними вместе с другими. Подключать репозиторий к такому сайту вы будете на уровне 2. Всё на уровне 0 происходит на вашем компьютере (здесь — в браузере), без сайтов и аккаунтов.

</Callout>

## Превращаем папку в репозиторий: git init

Каждая команда Git начинается со слова `git`, а дальше идёт то, что нужно сделать. Чтобы Git начал следить за папкой, зайдите в неё и выполните **`git init`** (от initialise — «создать, подготовить»):

<CodeExample output={`Initialized empty Git repository in /home/panda/recipes/.git/`}>

```bash
mkdir recipes
cd recipes
git init
```

</CodeExample>

Готово: `recipes` теперь репозиторий. Empty («пустой») значит, что коммитов в нём пока нет. Сообщения Git пишет по-английски, главные из них мы будем переводить. На вашем компьютере путь будет вашим, например `/Users/mei/recipes/.git/` на Mac.

`git init` выполняют **один раз на проект**, в самом начале. Чтобы сохранять новые версии, он больше не нужен.

## Скрытая папка .git

Git сообщает, что создал внутри `recipes` что-то под названием `.git`. Но обычный `ls` ничего не показывает:

<CodeExample setup={`mkdir recipes
cd recipes
git init`} output={`.  ..  .git`}>

```bash
ls
ls -a
```

</CodeExample>

Имена, которые начинаются с точки, — **скрытые**, и `ls` их пропускает. **`ls -a`** (all — «все») показывает и их: `.` — это текущая папка, `..` — папка уровнем выше, а **`.git`** — место, где Git хранит всю историю проекта: каждый коммит, каждое сообщение, каждую старую версию каждого файла.

<Callout type="warning" title="Никогда не трогайте .git">

Оставьте папку `.git` в покое: за ней следит Git. Не правьте файлы внутри и не удаляйте её. **Удалить `.git` — значит удалить всю историю**, и ваша папка снова станет обычной. Файлы останутся, но все сохранённые версии пропадут.

</Callout>

## Спрашиваем Git, что происходит: git status

**`git status`** — команда, которую вы будете запускать чаще всех остальных. Она показывает, как обстоят дела прямо сейчас. В совсем новом репозитории рассказывать особенно нечего:

<CodeExample setup={`mkdir recipes
cd recipes
git init`} output={`On branch main

No commits yet

nothing to commit (create/copy files and use "git add" to track)`}>

```bash
git status
```

</CodeExample>

- **`On branch main`** — «вы на ветке main». `main` — название основной линии вашей истории. С ветками (branches) вы познакомитесь на уровне 1. На вашем компьютере Git может написать `master`, если вы не настроили его иначе: это просто старое название того же самого.
- **`No commits yet`** — «коммитов пока нет»: ничего ещё не сохранено.
- Последняя строка подсказывает, что делать дальше: «нечего коммитить, создайте файлы».

Создадим файл командой `echo` и `>`, как в модуле «Файлы и папки», и спросим ещё раз:

<CodeExample setup={`mkdir recipes
cd recipes
git init`} output={`On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	pancakes.txt

nothing added to commit but untracked files present (use "git add" to track)`}>

```bash
echo "Блины: 2 яйца, 1 стакан молока, 1 стакан муки" > pancakes.txt
git status
```

</CodeExample>

Git заметил `pancakes.txt`, но записал его в **Untracked files** — **неотслеживаемые файлы**. Это значит: «Git видит файл, но пока не хранит его историю». Новый файл никогда не попадает в Git сам по себе: вы решаете, какие файлы войдут в коммит. Подсказка в скобках упоминает `git add` — именно с него начнётся [следующий урок](/learn/git/staging-and-committing). 🐼

В настоящем терминале `git status` может ещё и раскрасить имена файлов (неотслеживаемые часто красные). Слова будут те же.

## Частые ошибки

Если запустить команду Git в папке, которая не репозиторий, Git так и скажет:

<CodeExample output={`fatal: not a git repository (or any of the parent directories): .git`}>

```bash
git status
```

</CodeExample>

Здесь вы в домашней папке `~`, где нет `.git`. Git заглядывает и в папки выше (parent directories — «родительские папки»), но и там ничего не находит: «это не Git-репозиторий». **`fatal:`** значит, что Git остановился и ничего не сделал. Почти всегда помогает сначала перейти в папку проекта через `cd`. Если сомневаетесь, где вы, спросите `pwd`.

<Callout type="danger" title="git init — в папке проекта, а не в домашней">

`git init` в `~` превращает **всю домашнюю папку** в один гигантский репозиторий, и `git status` перечисляет всё, что у вас есть. Всегда сначала заходите в папку проекта через `cd` и проверяйте себя командой `pwd`. Если это всё же случилось и коммитов там ещё нет, удалите только эту новую папку командой `rm -r .git` из того же места, но сперва убедитесь через `pwd`, что вы там, где думаете.

</Callout>

## Итоги

- Копии вроде `final_v2_REALLY_final` не говорят, что изменилось, зачем, кто и когда. **Контроль версий** говорит.
- **Git** — система контроля версий, которая работает на вашем компьютере. **GitHub** — сайт, где хранят Git-репозитории.
- **Репозиторий** — папка проекта вместе с её историей. **Коммит** — сохранённый снимок с сообщением, автором и датой.
- **`git init`** превращает текущую папку в репозиторий, один раз на проект.
- История живёт в скрытой папке **`.git`** (её показывает `ls -a`). Никогда не правьте и не удаляйте её.
- **`git status`** показывает, как обстоят дела. Новые файлы сначала **неотслеживаемые** (untracked).
- `fatal: not a git repository` значит, что вы не внутри репозитория: сначала перейдите в папку проекта через `cd`.
