Создавать файлы и папки вы уже умеете. Но настоящие проекты всё время меняются: перед большой правкой файл сохраняют в резервную копию, готовый черновик переименовывают, фотографии переносят в отдельную папку, а старьё выбрасывают. 📦 Для этого есть три команды: `cp`, `mv` и `rm`. Они быстрые и мощные, а у одной из них нет отмены, так что последнюю часть урока прочитайте особенно внимательно.

## Копируем файлы: cp

**`cp`** (copy — «копировать») принимает два имени: что копировать и куда положить копию. Здесь в домашней папке лежит один файл `notes.txt` со строкой `Купить бамбук`:

<CodeExample setup={`echo "Купить бамбук" > notes.txt`} output={`notes-backup.txt  notes.txt
Купить бамбук`}>

```bash
cp notes.txt notes-backup.txt
ls
cat notes-backup.txt
```

</CodeExample>

Теперь есть два файла с одинаковым текстом. Если изменить один, другой не изменится.

Если второе имя — **папка**, копия ляжет внутрь неё под тем же именем. Здесь, кроме файла, есть пустая папка `backup`:

<CodeExample setup={`echo "Купить бамбук" > notes.txt
mkdir backup`} output={`notes.txt`}>

```bash
cp notes.txt backup
ls backup
```

</CodeExample>

Чтобы дать копии внутри папки новое имя, напишите полный путь: `cp notes.txt backup/old-notes.txt`.

Осторожно: если файл с таким именем уже есть, `cp` **молча заменит его**, ничего не спросив. Здесь до копирования в `old.txt` была строка `Очень важно`:

<CodeExample setup={`echo "Купить бамбук" > notes.txt
echo "Очень важно" > old.txt`} output={`Купить бамбук`}>

```bash
cp notes.txt old.txt
cat old.txt
```

</CodeExample>

## Копируем папки: cp -r

Сам по себе `cp` копирует только файлы. Чтобы скопировать папку **со всем содержимым**, добавьте **`-r`** (recursive — «рекурсивно»: зайти в каждую вложенную папку, а потом в каждую папку внутри неё). Здесь в `photos` лежат две картинки:

<CodeExample setup={`mkdir photos
touch photos/beach.jpg photos/panda.jpg`} output={`cp: -r not specified; omitting directory 'photos'
beach.jpg  panda.jpg`}>

```bash
cp photos photos-backup
cp -r photos photos-backup
ls photos-backup
```

</CodeExample>

Первый `cp` отказался и объяснил почему: флаг `-r` не указан, папка пропущена. Второй создал `photos-backup` с копиями обеих картинок.

## Переименовываем и перемещаем: mv

**`mv`** (move — «переместить») тоже принимает два имени, но не оставляет оригинал на месте. Если второе имя — **новое имя** в той же папке, `mv` **переименовывает**:

<CodeExample setup={`echo "Дорогая Мей," > draft.txt`} output={`letter.txt
Дорогая Мей,`}>

```bash
mv draft.txt letter.txt
ls
cat letter.txt
```

</CodeExample>

Файл тот же, изменилось только имя. Если последнее имя — **папка**, `mv` перемещает всё **внутрь** неё, и файлов можно перечислить сразу несколько. Здесь есть два файла и пустая папка `done`:

<CodeExample setup={`touch letter.txt poem.txt
mkdir done`} output={`done
letter.txt  poem.txt`}>

```bash
mv letter.txt poem.txt done
ls
ls done
```

</CodeExample>

Что ещё полезно знать про `mv`:

- С папками он работает сразу, без `-r`: `mv done finished` переименует папку `done` в `finished` вместе со всем содержимым.
- Как и `cp`, он молча **заменяет** файл, у которого уже есть такое имя.
- Если вы перечисляете несколько файлов, последним должно идти имя существующей папки. Иначе `mv` скажет `target '…' is not a directory` («цель — не папка»).

## Удаляем: rm и rmdir

**`rm`** (remove — «удалить») удаляет файлы. **`rmdir`** (remove directory) удаляет папки, но **только пустые**. Чтобы удалить папку вместе со всем, что в ней лежит, используйте **`rm -r`**. Здесь в домашней папке два старых файла, пустая папка `empty`, папка `trip` с картой внутри и файл `keep.txt`:

<CodeExample setup={`touch old.txt older.txt keep.txt
mkdir empty trip
touch trip/map.pdf`} output={`rm: cannot remove 'trip': Is a directory
rmdir: failed to remove 'trip': Directory not empty
keep.txt`}>

```bash
rm old.txt older.txt
rm trip
rmdir trip
rmdir empty
rm -r trip
ls
```

</CodeExample>

Прочитайте ошибки: простой `rm` не удаляет папку («это каталог»), а `rmdir` не удаляет папку, в которой что-то осталось («каталог не пуст»). Эти отказы вас защищают. `rmdir empty` и `rm -r trip` сработали, поэтому остался только `keep.txt`.

## Отмены нет

Когда вы удаляете файл в Finder или Проводнике, он попадает в Корзину, и его можно вернуть. **У терминала корзины нет.** `rm` удаляет навсегда, сразу и без вопроса «Вы уверены?». То же касается файла, который заменили `cp`, `mv` или `>`.

<Callout type="danger" title="Очень осторожно с rm -rf">

В инструкциях в интернете часто встречается `rm -rf`. `-r` удаляет папки со всем содержимым, а `-f` (force — «принудительно») ничего не спрашивает и ни на что не жалуется. Вместе они немедленно удаляют всё, что вы назвали.

Для катастрофы хватит одного лишнего пробела: `rm -rf ~/old-stuff` удаляет одну папку, а `rm -rf ~ /old-stuff` — **всю вашу домашнюю папку**. Учебный терминал так делать откажется. Настоящий вас не остановит.

</Callout>

Поэтому заведите привычку: **сначала посмотри, потом удаляй**.

1. Выполните `ls` или `tree` для того, что собираетесь удалить, и убедитесь, что это именно то, о чём вы думаете.
2. Наберите команду `rm` и перечитайте её ещё раз, прежде чем нажать Enter.
3. Удаляйте папки через `rm -r` только после шага 1. А `-f` используйте, только когда точно знаете зачем.

Дальше в этом курсе страховкой станет Git: работу, сохранённую в Git, можно вернуть даже после неудачного `rm`.

## Итоги

- `cp откуда куда` копирует файл; если `куда` — папка, копия ляжет внутрь. `cp -r` копирует папку со всем содержимым.
- `mv откуда куда` переименовывает; `mv a b папка` перемещает файлы в папку. С папками работает без `-r`.
- `rm файл` удаляет файлы, `rmdir папка` удаляет **пустые** папки, а `rm -r папка` — папку со всем, что внутри.
- `cp`, `mv` и `>` молча заменяют файл с таким же именем.
- **Отмены и корзины нет.** Перед удалением посмотрите через `ls` или `tree` и очень осторожно обращайтесь с `rm -rf`.
