So far you've looked around: `pwd` tells you where you are, `ls` shows what's there and `cd` takes you somewhere else. Now it's time to **make** things. 🛠️ In this lesson you'll create folders and files, put text inside them and read it back, all without leaving the terminal.

Every example starts in your home folder `~`, which is empty in this practice terminal. To try one yourself, copy its commands into the [Terminal playground](/playground) or into the exercise at the end of this lesson.

## Making folders with mkdir

**`mkdir`** (short for "make directory") makes a new folder. Give it one name, or several names separated by spaces:

<CodeExample output={`music  notes  photos`}>

```bash
mkdir notes
mkdir music photos
ls
```

</CodeExample>

`mkdir` prints nothing when it works. That's normal in the terminal: **no news is good news**. Run `ls` to check the result.

Two things make `mkdir` complain: a folder with that name is already there, or the folder you want to put it in doesn't exist yet.

<CodeExample output={`mkdir: cannot create directory 'notes': File exists
mkdir: cannot create directory 'school/maths': No such file or directory`}>

```bash
mkdir notes
mkdir notes
mkdir school/maths
```

</CodeExample>

To make a folder inside folders that don't exist yet, add **`-p`** ("parents"). It makes every missing folder along the way, and it doesn't complain if they're already there. The **`tree`** command then draws the folders as a tree:

<CodeExample output={`.
└── school
    └── maths
        └── homework

3 directories, 0 files`}>

```bash
mkdir -p school/maths/homework
tree
```

</CodeExample>

The `.` at the top is the folder you're in, and the last line counts what `tree` found. (On your own computer `tree` may need installing first; `ls` always works.)

## Empty files with touch

**`touch`** makes an empty file. Like `mkdir`, it takes several names at once:

<CodeExample output={`ideas.txt  todo.txt`}>

```bash
touch todo.txt ideas.txt
ls
cat todo.txt
```

</CodeExample>

`cat todo.txt` printed nothing because the file is empty. If the file already exists, `touch` leaves its text alone and only updates its "last changed" time. It never wipes a file.

The part after the dot, like `.txt` or `.md`, is the file's **extension**. It's a hint about what's inside: `.txt` is plain text, `.md` is Markdown, `.jpg` is a photo. The terminal doesn't need it, but people and programs do.

## Writing text into a file

**`echo`** prints the text you give it:

<CodeExample output={`Hello from the terminal`}>

```bash
echo "Hello from the terminal"
```

</CodeExample>

Add **`>`** and a file name, and the text goes **into the file** instead of onto the screen. This is called **redirecting** the output. If the file doesn't exist, it's created:

<CodeExample output={`shopping.txt
Buy bamboo`}>

```bash
echo "Buy bamboo" > shopping.txt
ls
cat shopping.txt
```

</CodeExample>

The `echo` line printed nothing: its text went into `shopping.txt`. Then `cat` showed what's inside.

To **add** a line to the end of a file, use **`>>`** (two arrows) instead:

<CodeExample output={`Buy bamboo
Buy apples
Buy tea`}>

```bash
echo "Buy bamboo" > shopping.txt
echo "Buy apples" >> shopping.txt
echo "Buy tea" >> shopping.txt
cat shopping.txt
```

</CodeExample>

Each `echo` adds one line, because `echo` ends its text with a new line.

A single `>` **empties the file first**, then writes. Here `shopping.txt` already holds the three lines from above, and one `>` wipes them all:

<CodeExample setup={`echo "Buy bamboo" > shopping.txt
echo "Buy apples" >> shopping.txt
echo "Buy tea" >> shopping.txt`} output={`Oops`}>

```bash
echo "Oops" > shopping.txt
cat shopping.txt
```

</CodeExample>

<Callout type="warning" title="> replaces, >> adds">

`>` wipes the file without a warning, and there's no undo. When you want to keep what's in a file, use `>>`.

</Callout>

On your own computer you'd usually write longer files in a text editor. This practice terminal has no editor, so `echo` with `>` and `>>` is how you write files here.

## Reading files with cat

**`cat`** prints a whole file. Give it several files and it prints them one after another. With **`-n`** it numbers the lines, which helps with longer files. Here the home folder holds `shopping.txt` from above and a two-line `todo.txt`:

<CodeExample setup={`echo "Buy bamboo" > shopping.txt
echo "Buy apples" >> shopping.txt
echo "Buy tea" >> shopping.txt
echo "Water the bamboo" > todo.txt
echo "Call Mei" >> todo.txt`} output={`     1	Buy bamboo
     2	Buy apples
     3	Buy tea
Water the bamboo
Call Mei
Buy bamboo
Buy apples
Buy tea`}>

```bash
cat -n shopping.txt
cat todo.txt shopping.txt
```

</CodeExample>

The name comes from "concatenate", which means "join together": `cat` joins files into one stream of text.

## Good file names

The terminal splits a command into words at every space. So a name with a space in it turns into **two** names:

<CodeExample output={`my  notes.txt`}>

```bash
touch my notes.txt
ls
```

</CodeExample>

That made a file called `my` and another called `notes.txt`. To use a space in a name, put the whole name in quotes: `touch "my notes.txt"`. Even then you'd have to type the quotes every time you use it, so most developers simply **avoid spaces**:

- Use dashes or underscores instead: `my-notes.txt`, `my_notes.txt`.
- Stick to letters, numbers, `-`, `_` and `.`.
- Mind the case: on Linux (and on most servers) `Notes.txt` and `notes.txt` are two different files. macOS and Windows usually treat them as the same, which surprises people when a project moves to a server.

<Callout type="note" title="Common first mistakes">

- `mkdir a/b` when `a` doesn't exist yet: add `-p`.
- Using `>` to add a line and losing the file's text: `>>` adds.
- Forgetting the quotes around a name or text with spaces.

</Callout>

## Recap

- `mkdir name` makes a folder; `mkdir -p a/b/c` makes the missing folders along the way.
- `touch name` makes an empty file (and never wipes an existing one).
- `echo "text" > file` writes text into a file, **replacing** what was there; `>>` **adds** to the end.
- `cat file` prints a file, `cat -n` numbers the lines, and `tree` shows folders as a tree.
- Avoid spaces in names (use `-` or `_`), or put the name in quotes.
