Переносить десять фотографий по одной скучно, а тысячу — просто невозможно. 😴 В терминале для этого есть сокращение: **шаблоны** (wildcards), особые символы, которые означают «любое имя, похожее на это». С ними одна команда может переместить все фотографии или удалить все черновики сразу. В конце урока вы с их помощью разберёте захламлённую папку «Загрузки».

В первых примерах в домашней папке лежат такие файлы:

```text
beach.jpg  notes.txt  panda.jpg  report-1.txt  report-2.txt  report-3.txt  sunset.png  todo.txt
```

## Звёздочка * — что угодно

**`*`** (звёздочка) совпадает с **любым текстом** любой длины, даже с пустым. Поэтому `*.txt` означает «все имена, которые заканчиваются на `.txt`», а `report-*` — «все имена, которые начинаются с `report-`»:

<CodeExample setup={`touch beach.jpg notes.txt panda.jpg report-1.txt report-2.txt report-3.txt sunset.png todo.txt`} output={`notes.txt  report-1.txt  report-2.txt  report-3.txt  todo.txt
beach.jpg  panda.jpg
report-1.txt  report-2.txt  report-3.txt`}>

```bash
ls *.txt
ls *.jpg
ls report-*
```

</CodeExample>

А теперь самое важное: `ls` звёздочку вообще не видит. **Оболочка** (shell, программа, которая читает ваши команды) заменяет шаблон на подходящие имена **до того**, как команда запустится. Это легко увидеть с `echo`, ведь он просто выводит то, что получил:

<CodeExample setup={`touch beach.jpg notes.txt panda.jpg report-1.txt report-2.txt report-3.txt sunset.png todo.txt`} output={`beach.jpg panda.jpg
report-1.txt report-2.txt report-3.txt`}>

```bash
echo *.jpg
echo report-*
```

</CodeExample>

Значит, `ls *.jpg` на самом деле выполняет `ls beach.jpg panda.jpg`. Именно поэтому шаблоны работают с **любой** командой: `cp`, `mv`, `rm`, `cat` и всеми остальными.

Шаблоны пропускают **скрытые файлы** (их имена начинаются с точки, например `.gitignore`), так что `*` сам по себе означает «всё, что видно в обычном `ls`».

## ? и [ ] — один символ

**`?`** совпадает **ровно с одним** символом, любым. **`[…]`** совпадает с одним символом **из списка** в скобках, а `[1-3]` означает любой символ от 1 до 3. Здесь в папке четыре отчёта: `report-1.txt`, `report-2.txt`, `report-3.txt` и `report-10.txt`:

<CodeExample setup={`touch report-1.txt report-2.txt report-3.txt report-10.txt`} output={`report-1.txt  report-2.txt  report-3.txt
report-10.txt
report-1.txt  report-3.txt`}>

```bash
ls report-?.txt
ls report-??.txt
ls report-[13].txt
```

</CodeExample>

`report-?.txt` не совпал с `report-10.txt`, потому что `10` — это два символа. А два вопросительных знака совпали.

## Когда ничего не подошло, и кавычки

Если под шаблон не подошло ни одно имя, bash оставляет шаблон как есть. Команда получает странное имя `*.pdf` и жалуется, что такого файла нет. **Кавычки** выключают шаблоны: внутри `"…"` звёздочка — просто звёздочка.

<CodeExample setup={`touch beach.jpg notes.txt panda.jpg report-1.txt report-2.txt report-3.txt sunset.png todo.txt`} output={`ls: cannot access '*.pdf': No such file or directory
ls: cannot access '*.txt': No such file or directory
Это *правда* готово?`}>

```bash
ls *.pdf
ls "*.txt"
echo "Это *правда* готово?"
```

</CodeExample>

Вот почему кавычки вокруг текста для `echo` так важны: они не дают оболочке принять `*` или `?` в вашей фразе за шаблон.

<Callout type="note" title="На Mac">

Терминал на Mac по умолчанию запускает не bash, а **zsh**. Шаблоны там работают так же, но если ничего не подошло, zsh останавливается с ошибкой `zsh: no matches found: *.pdf` и вообще не запускает команду. А ещё настоящий терминал может показывать `ls` колонками и в цвете; имена при этом те же.

</Callout>

## Перемещаем и удаляем много файлов сразу

Теперь самое полезное. Здесь в папке из начала урока появляется папка `photos`, все картинки переезжают в неё одной командой `mv`, а отчёты удаляются одной командой `rm`. Перед удалением `ls` проверяет, что подходит под шаблон:

<CodeExample setup={`touch beach.jpg notes.txt panda.jpg report-1.txt report-2.txt report-3.txt sunset.png todo.txt`} output={`report-1.txt  report-2.txt  report-3.txt
.
├── notes.txt
├── photos
│   ├── beach.jpg
│   ├── panda.jpg
│   └── sunset.png
└── todo.txt

1 directory, 5 files`}>

```bash
mkdir photos
mv *.jpg *.png photos
ls report-*
rm report-*
tree
```

</CodeExample>

`mv *.jpg *.png photos` превратилась в `mv beach.jpg panda.jpg sunset.png photos`, а `tree` сразу показывает результат.

<Callout type="danger" title="Один пробел может удалить всё">

`rm draft-*` удаляет черновики. А `rm draft- *` (с пробелом) означает «удали файл `draft-`, а потом **все файлы здесь**». И `rm *` сам по себе опустошает папку. Отмены по-прежнему нет. Сначала выполните `ls` с тем же шаблоном и перечитайте строку с `rm`, прежде чем нажать Enter.

</Callout>

## Мини-проект: порядок в папке «Загрузки»

Пора собрать вместе всё, что было в модуле. У любого человека папка «Загрузки» (downloads) со временем становится вот такой: картинки, PDF и заметки вперемешку, плюс файлы, скачанные дважды, и никому не нужные черновики. Вы разберёте её с помощью `mkdir`, `mv`, `rm` и шаблонов — так же, как сделали бы это на своём компьютере.

<Exercise
  title="Мини-проект: Порядок в папке «Загрузки»"
  language="shell"
  setup={`mkdir downloads
cd downloads
touch beach.jpg beach-copy.jpg panda-selfie.jpg sunset.png
touch recipe-book.pdf recipe-book-copy.pdf train-ticket.pdf
echo "Молоко, чай, бамбук" > shopping-list.txt
echo "Выучить терминал" > ideas.txt
echo "Дорогая Мей, спасибо за чай" > draft-letter.txt
echo "Розы красные, бамбук зелёный" > draft-poem.txt`}
  starter={`# Вы в ~/downloads. Сначала осмотритесь:
ls
# 1. Удалите копии и черновики
# 2. Создайте папки images, documents и notes
# 3. Переместите в них картинки, PDF и заметки
# 4. Проверьте результат через tree
`}
  tests={[
    { name: "в images лежат три картинки", check: "ls('images').join(' ') === 'beach.jpg panda-selfie.jpg sunset.png'" },
    { name: "в documents лежат два PDF", check: "ls('documents').join(' ') === 'recipe-book.pdf train-ticket.pdf'" },
    { name: "в notes лежат две заметки", check: "ls('notes').join(' ') === 'ideas.txt shopping-list.txt'" },
    { name: "текст заметок на месте", check: "file('notes/shopping-list.txt') === 'Молоко, чай, бамбук\\n' && file('notes/ideas.txt') === 'Выучить терминал\\n'" },
    { name: "копии и черновики удалены", check: "!/copy|draft/.test(await run('tree'))" },
    { name: "в downloads остались только три папки", check: "ls('.').join(' ') === 'documents images notes'" },
    { name: "для перемещения или удаления использованы шаблоны", check: "commands.some((c) => /^\\s*(mv|rm)\\b/.test(c) && /[*?[]/.test(c))" },
  ]}
>

В папке `~/downloads` полный беспорядок, и вы начинаете внутри неё. Выполните `ls`, чтобы на него посмотреть. Затем наведите порядок так, чтобы `tree` показывал ровно вот это:

```text
.
├── documents
│   ├── recipe-book.pdf
│   └── train-ticket.pdf
├── images
│   ├── beach.jpg
│   ├── panda-selfie.jpg
│   └── sunset.png
└── notes
    ├── ideas.txt
    └── shopping-list.txt

3 directories, 7 files
```

- **Удалите** файлы, скачанные дважды (у них перед расширением стоит `-copy`), и черновики (их имена начинаются с `draft-`).
- **Создайте** папки `images`, `documents` и `notes`.
- **Переместите** картинки (`.jpg` и `.png`) в `images`, PDF — в `documents`, а заметки `.txt` — в `notes`.

Пользуйтесь шаблонами: с ними вся работа займёт примерно шесть команд.

<Hint>

Подумайте о порядке действий. Если сначала переместить `*.jpg`, копия фотографии с пляжем уедет в `images` вместе с настоящей. Если первым делом удалить копии и черновики, перемещать будет проще.

</Hint>

<Hint>

`*-copy.*` совпадает со всеми именами, в которых есть `-copy.`, а `draft-*` — со всеми черновиками. Проверьте их через `ls`, прежде чем удалять. Одна команда `mkdir` может создать все три папки, а одна команда `mv` принимает несколько шаблонов, например `*.jpg *.png`.

</Hint>

<Hint>

```bash
ls *-copy.* draft-*
rm *-copy.* draft-*
mkdir images documents notes
mv *.jpg *.png ...
mv *.pdf ...
mv ... notes
tree
```

</Hint>

<Solution>

```bash
ls *-copy.* draft-*
rm *-copy.* draft-*
mkdir images documents notes
mv *.jpg *.png images
mv *.pdf documents
mv *.txt notes
tree
```

</Solution>

## Итоги

- **Шаблоны** выбирают много имён сразу: `*` — любой текст, `?` — ровно один символ, `[abc]` или `[1-3]` — один символ из списка.
- **Оболочка** заменяет шаблон на подходящие имена до запуска команды, поэтому шаблоны работают с любой командой. Скрытые файлы они пропускают.
- Если ничего не подошло, bash передаёт шаблон как есть, и команда пишет No such file or directory. Кавычки выключают шаблоны.
- `mv *.jpg photos`, `cp *.txt backup` и `rm draft-*` работают сразу со многими файлами. Перед любым `rm` выполните `ls` с тем же шаблоном.
- `tree` сразу показывает результат.

Теперь вы умеете создавать, читать, копировать, перемещать и удалять файлы и целые папки, а захламлённую папку разбираете за несколько команд. 🎉 Дальше вас ждёт [Git](/learn/git/why-version-control): он запоминает каждую версию ваших файлов, так что даже неудачный `rm` перестаёт быть концом света.
