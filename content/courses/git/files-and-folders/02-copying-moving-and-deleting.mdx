You can make files and folders now. Real projects change all the time, though: you back a file up before a big edit, rename a draft when it's finished, move photos into their own folder and throw old things away. 📦 This lesson covers the three commands for that: `cp`, `mv` and `rm`. They're quick and powerful, and one of them has no undo, so read the last part carefully.

## Copying files with cp

**`cp`** ("copy") takes two names: what to copy, then where the copy goes. Here the home folder holds one file, `notes.txt`, with the line `Buy bamboo`:

<CodeExample setup={`echo "Buy bamboo" > notes.txt`} output={`notes-backup.txt  notes.txt
Buy bamboo`}>

```bash
cp notes.txt notes-backup.txt
ls
cat notes-backup.txt
```

</CodeExample>

Now there are two files with the same text. Changing one doesn't change the other.

If the second name is a **folder**, the copy goes inside it and keeps its name. Here there's also an empty folder called `backup`:

<CodeExample setup={`echo "Buy bamboo" > notes.txt
mkdir backup`} output={`notes.txt`}>

```bash
cp notes.txt backup
ls backup
```

</CodeExample>

To give the copy a new name inside the folder, write the full path: `cp notes.txt backup/old-notes.txt`.

Careful: if a file with the target name already exists, `cp` **quietly replaces it**, without asking. Here `old.txt` held the line `Very important` before the copy:

<CodeExample setup={`echo "Buy bamboo" > notes.txt
echo "Very important" > old.txt`} output={`Buy bamboo`}>

```bash
cp notes.txt old.txt
cat old.txt
```

</CodeExample>

## Copying folders with cp -r

On its own, `cp` copies files only. To copy a folder **and everything inside it**, add **`-r`** ("recursive": go into every folder inside, and every folder inside those). Here `photos` holds two pictures:

<CodeExample setup={`mkdir photos
touch photos/beach.jpg photos/panda.jpg`} output={`cp: -r not specified; omitting directory 'photos'
beach.jpg  panda.jpg`}>

```bash
cp photos photos-backup
cp -r photos photos-backup
ls photos-backup
```

</CodeExample>

The first `cp` refused and told you why. The second made `photos-backup` with copies of both pictures.

## Renaming and moving with mv

**`mv`** ("move") also takes two names, but it doesn't leave the original behind. If the second name is a **new name** in the same folder, `mv` **renames**:

<CodeExample setup={`echo "Dear Mei," > draft.txt`} output={`letter.txt
Dear Mei,`}>

```bash
mv draft.txt letter.txt
ls
cat letter.txt
```

</CodeExample>

The file is the same, only its name changed. If the last name is a **folder**, `mv` moves things **into** it, and you can list several files at once. Here there are two files and an empty folder `done`:

<CodeExample setup={`touch letter.txt poem.txt
mkdir done`} output={`done
letter.txt  poem.txt`}>

```bash
mv letter.txt poem.txt done
ls
ls done
```

</CodeExample>

A few things to know about `mv`:

- It works on folders straight away, with no `-r`: `mv done finished` renames the folder `done` to `finished`, with everything inside it.
- Like `cp`, it quietly **replaces** a file that already has the target name.
- When you list several things, the last name must be a folder that exists. Otherwise `mv` says `target '…' is not a directory`.

## Deleting with rm and rmdir

**`rm`** ("remove") deletes files. **`rmdir`** ("remove directory") deletes folders, but **only empty ones**. To delete a folder with everything inside it, use **`rm -r`**. Here the home folder holds two old files, an empty folder `empty`, a folder `trip` with a map in it, and `keep.txt`:

<CodeExample setup={`touch old.txt older.txt keep.txt
mkdir empty trip
touch trip/map.pdf`} output={`rm: cannot remove 'trip': Is a directory
rmdir: failed to remove 'trip': Directory not empty
keep.txt`}>

```bash
rm old.txt older.txt
rm trip
rmdir trip
rmdir empty
rm -r trip
ls
```

</CodeExample>

Read the errors: plain `rm` won't delete a folder, and `rmdir` won't delete a folder that still has something in it. Those refusals are there to protect you. `rmdir empty` and `rm -r trip` worked, so only `keep.txt` is left.

## There is no undo

When you delete a file in Finder or Explorer, it goes to the Trash or Recycle Bin and you can get it back. **The terminal has no trash.** `rm` deletes for good, straight away, without asking "Are you sure?". The same goes for a file that `cp`, `mv` or `>` replaced.

<Callout type="danger" title="Be very careful with rm -rf">

You'll see `rm -rf` in tutorials. `-r` deletes folders with everything inside, and `-f` ("force") never asks and never complains. Together they delete whatever you name, at once.

One stray space is enough for a disaster: `rm -rf ~/old-stuff` deletes one folder, but `rm -rf ~ /old-stuff` deletes your **whole home folder**. This practice terminal refuses to do that. A real one won't stop you.

</Callout>

So build a habit: **look before you delete**.

1. Run `ls` or `tree` on what you're about to delete, and check it's really what you think.
2. Type the `rm` command, then read it once more before you press Enter.
3. Delete folders with `rm -r` only after step 1. Use `-f` only when you know exactly why.

Later in this course, Git will be your safety net: work that's saved in Git can be brought back even after a bad `rm`.

## Recap

- `cp from to` copies a file; if `to` is a folder, the copy goes inside. `cp -r` copies a folder with everything in it.
- `mv from to` renames; `mv a b folder` moves things into a folder. It works on folders without `-r`.
- `rm file` deletes files, `rmdir folder` deletes **empty** folders, and `rm -r folder` deletes a folder with everything inside.
- `cp`, `mv` and `>` quietly replace a file with the same name.
- There's **no undo and no trash**. Look with `ls` or `tree` before you delete, and be very careful with `rm -rf`.
