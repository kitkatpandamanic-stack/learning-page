До сих пор вы только осматривались: `pwd` говорит, где вы находитесь, `ls` показывает, что вокруг, а `cd` переносит в другое место. Пора что-нибудь **создать**. 🛠️ В этом уроке вы сделаете папки и файлы, запишете в них текст и прочитаете его обратно, не выходя из терминала.

Каждый пример начинается в домашней папке `~`, которая в учебном терминале пуста. Чтобы попробовать пример самостоятельно, скопируйте его команды в [терминал в песочнице](/playground) или в упражнение в конце урока.

## Папки: mkdir

**`mkdir`** (от make directory — «создать каталог») создаёт новую папку. Ей можно передать одно имя или сразу несколько через пробел:

<CodeExample output={`music  notes  photos`}>

```bash
mkdir notes
mkdir music photos
ls
```

</CodeExample>

Если всё получилось, `mkdir` ничего не пишет. В терминале это нормально: **нет новостей — хорошие новости**. Чтобы проверить результат, выполните `ls`.

`mkdir` жалуется в двух случаях: папка с таким именем уже есть или папки, внутри которой вы хотите её создать, ещё не существует.

<CodeExample output={`mkdir: cannot create directory 'notes': File exists
mkdir: cannot create directory 'school/maths': No such file or directory`}>

```bash
mkdir notes
mkdir notes
mkdir school/maths
```

</CodeExample>

Чтобы создать папку внутри ещё не существующих папок, добавьте **`-p`** (parents — «родительские»). Тогда `mkdir` создаст все недостающие папки по пути и не будет ругаться, если какие-то из них уже есть. А команда **`tree`** нарисует папки в виде дерева:

<CodeExample output={`.
└── school
    └── maths
        └── homework

3 directories, 0 files`}>

```bash
mkdir -p school/maths/homework
tree
```

</CodeExample>

Точка `.` наверху — это папка, в которой вы находитесь, а последняя строка считает, что нашёл `tree` (3 папки, 0 файлов). На вашем компьютере `tree` может понадобиться сначала установить, а `ls` работает всегда.

## Пустые файлы: touch

**`touch`** создаёт пустой файл. Как и `mkdir`, он принимает сразу несколько имён:

<CodeExample output={`ideas.txt  todo.txt`}>

```bash
touch todo.txt ideas.txt
ls
cat todo.txt
```

</CodeExample>

`cat todo.txt` ничего не вывел, потому что файл пустой. Если файл уже существует, `touch` не трогает его текст, а только обновляет время последнего изменения. Стереть файл он не может.

Часть имени после точки, например `.txt` или `.md`, называется **расширением** (extension). Оно подсказывает, что внутри: `.txt` — обычный текст, `.md` — Markdown, `.jpg` — фотография. Терминалу расширение не нужно, а вот людям и программам — очень.

## Записываем текст в файл

**`echo`** выводит текст, который вы ему дали:

<CodeExample output={`Привет из терминала`}>

```bash
echo "Привет из терминала"
```

</CodeExample>

Добавьте **`>`** и имя файла, и текст отправится **в файл**, а не на экран. Это называется **перенаправлением** (redirect) вывода. Если файла ещё нет, он будет создан:

<CodeExample output={`shopping.txt
Купить бамбук`}>

```bash
echo "Купить бамбук" > shopping.txt
ls
cat shopping.txt
```

</CodeExample>

Строка с `echo` ничего не вывела: её текст ушёл в `shopping.txt`. А `cat` потом показал, что внутри.

Чтобы **дописать** строку в конец файла, используйте **`>>`** (две стрелки):

<CodeExample output={`Купить бамбук
Купить яблоки
Купить чай`}>

```bash
echo "Купить бамбук" > shopping.txt
echo "Купить яблоки" >> shopping.txt
echo "Купить чай" >> shopping.txt
cat shopping.txt
```

</CodeExample>

Каждый `echo` добавляет по одной строке, потому что `echo` заканчивает свой текст переводом строки.

Одна стрелка `>` **сначала очищает файл**, а потом пишет. Здесь в `shopping.txt` уже лежат три строки из примера выше, и один `>` стирает их все:

<CodeExample setup={`echo "Купить бамбук" > shopping.txt
echo "Купить яблоки" >> shopping.txt
echo "Купить чай" >> shopping.txt`} output={`Ой`}>

```bash
echo "Ой" > shopping.txt
cat shopping.txt
```

</CodeExample>

<Callout type="warning" title="> заменяет, >> дописывает">

`>` стирает файл без предупреждения, и отменить это нельзя. Если хотите сохранить то, что уже есть в файле, используйте `>>`.

</Callout>

На своём компьютере длинные файлы обычно пишут в текстовом редакторе. В учебном терминале редактора нет, поэтому здесь файлы пишут через `echo` с `>` и `>>`.

## Читаем файлы: cat

**`cat`** выводит файл целиком. Если передать ему несколько файлов, он выведет их один за другим. С флагом **`-n`** он нумерует строки, что удобно в длинных файлах. Здесь в домашней папке лежат `shopping.txt` из примера выше и `todo.txt` из двух строк:

<CodeExample setup={`echo "Купить бамбук" > shopping.txt
echo "Купить яблоки" >> shopping.txt
echo "Купить чай" >> shopping.txt
echo "Полить бамбук" > todo.txt
echo "Позвонить Мей" >> todo.txt`} output={`     1	Купить бамбук
     2	Купить яблоки
     3	Купить чай
Полить бамбук
Позвонить Мей
Купить бамбук
Купить яблоки
Купить чай`}>

```bash
cat -n shopping.txt
cat todo.txt shopping.txt
```

</CodeExample>

Название происходит от английского concatenate — «соединять»: `cat` склеивает файлы в один поток текста.

## Хорошие имена файлов

Терминал делит команду на слова по пробелам. Поэтому имя с пробелом превращается в **два** имени:

<CodeExample output={`my  notes.txt`}>

```bash
touch my notes.txt
ls
```

</CodeExample>

Получились два файла: `my` и `notes.txt`. Чтобы в имени был пробел, возьмите всё имя в кавычки: `touch "my notes.txt"`. Но тогда кавычки придётся писать каждый раз, когда вы обращаетесь к файлу, поэтому большинство разработчиков просто **обходятся без пробелов**:

- Вместо пробела ставьте дефис или подчёркивание: `my-notes.txt`, `my_notes.txt`.
- Используйте латинские буквы, цифры, `-`, `_` и `.`. Русские буквы в именах работают, но в терминале их неудобно набирать, и некоторые программы с ними ошибаются.
- Следите за регистром: в Linux (и на большинстве серверов) `Notes.txt` и `notes.txt` — два разных файла. macOS и Windows обычно считают их одним и тем же, и это неприятно удивляет, когда проект переезжает на сервер.

<Callout type="note" title="Частые ошибки новичков">

- `mkdir a/b`, когда папки `a` ещё нет: добавьте `-p`.
- Дописать строку через `>` и потерять текст файла: дописывает `>>`.
- Забыть кавычки вокруг имени или текста с пробелами.

</Callout>

Мей заводит блог и хочет, чтобы в проекте с первого дня был порядок. Соберите в домашней папке вот такую структуру:

```text
panda-blog
├── README.md
├── images
└── posts
    ├── drafts
    └── first-post.txt
```

- `images`, `posts` и `drafts` — папки.
- В `README.md` одна строка: `# Блог панды`
- В `posts/first-post.txt` две строки: `Привет, мир.` и затем `Панды любят бамбук.`

</Hint>

## Итоги

- `mkdir имя` создаёт папку; `mkdir -p a/b/c` создаёт недостающие папки по пути.
- `touch имя` создаёт пустой файл (и никогда не стирает существующий).
- `echo "текст" > файл` записывает текст в файл, **заменяя** то, что там было; `>>` **дописывает** в конец.
- `cat файл` выводит файл, `cat -n` нумерует строки, а `tree` показывает папки деревом.
- Обходитесь без пробелов в именах (ставьте `-` или `_`) или берите имя в кавычки.
