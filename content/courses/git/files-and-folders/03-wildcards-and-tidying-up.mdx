Moving ten photos one by one is boring, and moving a thousand is impossible. 😴 The terminal has a shortcut: **wildcards**, special characters that stand for "any name that looks like this". With them, one command can move every photo or delete every draft at once. At the end of this lesson you'll use them to tidy up a messy downloads folder.

In the first examples, the home folder holds these files:

```text
beach.jpg  notes.txt  panda.jpg  report-1.txt  report-2.txt  report-3.txt  sunset.png  todo.txt
```

## The star * matches anything

A **`*`** (star) matches **any text**, of any length, even none. So `*.txt` means "every name that ends in `.txt`", and `report-*` means "every name that starts with `report-`":

<CodeExample setup={`touch beach.jpg notes.txt panda.jpg report-1.txt report-2.txt report-3.txt sunset.png todo.txt`} output={`notes.txt  report-1.txt  report-2.txt  report-3.txt  todo.txt
beach.jpg  panda.jpg
report-1.txt  report-2.txt  report-3.txt`}>

```bash
ls *.txt
ls *.jpg
ls report-*
```

</CodeExample>

Here's the important part: `ls` never sees the star. **The shell** (the program that reads your commands) swaps the pattern for the matching names **before** the command runs. `echo` makes this easy to see, because it just prints what it was given:

<CodeExample setup={`touch beach.jpg notes.txt panda.jpg report-1.txt report-2.txt report-3.txt sunset.png todo.txt`} output={`beach.jpg panda.jpg
report-1.txt report-2.txt report-3.txt`}>

```bash
echo *.jpg
echo report-*
```

</CodeExample>

So `ls *.jpg` really runs `ls beach.jpg panda.jpg`. That's why wildcards work with **every** command: `cp`, `mv`, `rm`, `cat` and the rest.

Wildcards skip **hidden files** (names that start with a dot, like `.gitignore`), so `*` on its own means "everything you'd see with plain `ls`".

## ? and [ ] match one character

A **`?`** matches **exactly one** character, any character. **`[…]`** matches one character **from the list** inside the brackets, and `[1-3]` means any one character from 1 to 3. Here the folder holds four reports, `report-1.txt`, `report-2.txt`, `report-3.txt` and `report-10.txt`:

<CodeExample setup={`touch report-1.txt report-2.txt report-3.txt report-10.txt`} output={`report-1.txt  report-2.txt  report-3.txt
report-10.txt
report-1.txt  report-3.txt`}>

```bash
ls report-?.txt
ls report-??.txt
ls report-[13].txt
```

</CodeExample>

`report-?.txt` didn't match `report-10.txt`, because `10` is two characters. Two question marks did.

## When nothing matches, and quotes

If no name matches a pattern, bash leaves the pattern as it is, so the command gets the strange name `*.pdf` and complains that there's no such file. **Quotes** turn wildcards off: inside `"…"`, a `*` is just a star.

<CodeExample setup={`touch beach.jpg notes.txt panda.jpg report-1.txt report-2.txt report-3.txt sunset.png todo.txt`} output={`ls: cannot access '*.pdf': No such file or directory
ls: cannot access '*.txt': No such file or directory
Is it *really* done?`}>

```bash
ls *.pdf
ls "*.txt"
echo "Is it *really* done?"
```

</CodeExample>

That's why the quotes around text for `echo` matter: they stop the shell from treating a `*` or `?` in your sentence as a pattern.

<Callout type="note" title="On a Mac">

The Mac's Terminal runs **zsh** by default, not bash. Wildcards work the same way, but when nothing matches, zsh stops with `zsh: no matches found: *.pdf` and doesn't run the command at all. Also, a real terminal may show `ls` in columns and colours; the names are the same.

</Callout>

## Moving and deleting many files at once

Now the useful part. Here the folder from the top of the lesson gets a `photos` folder, every picture goes into it with one `mv`, and the reports are deleted with one `rm`. Before deleting, `ls` checks what the pattern matches:

<CodeExample setup={`touch beach.jpg notes.txt panda.jpg report-1.txt report-2.txt report-3.txt sunset.png todo.txt`} output={`report-1.txt  report-2.txt  report-3.txt
.
├── notes.txt
├── photos
│   ├── beach.jpg
│   ├── panda.jpg
│   └── sunset.png
└── todo.txt

1 directory, 5 files`}>

```bash
mkdir photos
mv *.jpg *.png photos
ls report-*
rm report-*
tree
```

</CodeExample>

`mv *.jpg *.png photos` became `mv beach.jpg panda.jpg sunset.png photos`, and `tree` shows the result at a glance.

<Callout type="danger" title="One space can delete everything">

`rm draft-*` deletes the drafts. `rm draft- *` (with a space) means "delete a file called `draft-`, then **every file here**", and `rm *` on its own empties the folder. There's still no undo. Run `ls` with the same pattern first, and read the `rm` line before you press Enter.

</Callout>

## Mini-project: tidy up a downloads folder

Time to put the whole module together. Everyone's downloads folder ends up like this one: pictures, PDFs and notes all mixed up, plus copies of things downloaded twice and drafts nobody needs. You'll sort it with `mkdir`, `mv`, `rm` and wildcards, the way you'd do it on your own computer.

<Exercise
  title="Mini-project: Tidy up a downloads folder"
  language="shell"
  setup={`mkdir downloads
cd downloads
touch beach.jpg beach-copy.jpg panda-selfie.jpg sunset.png
touch recipe-book.pdf recipe-book-copy.pdf train-ticket.pdf
echo "Milk, tea, bamboo" > shopping-list.txt
echo "Learn the terminal" > ideas.txt
echo "Dear Mei, thanks for the tea" > draft-letter.txt
echo "Roses are red, bamboo is green" > draft-poem.txt`}
  starter={`# You're in ~/downloads. Look around first:
ls
# 1. Delete the copies and the drafts
# 2. Make the folders images, documents and notes
# 3. Move the pictures, the PDFs and the notes into them
# 4. Check the result with tree
`}
  tests={[
    { name: "images holds the three pictures", check: "ls('images').join(' ') === 'beach.jpg panda-selfie.jpg sunset.png'" },
    { name: "documents holds the two PDFs", check: "ls('documents').join(' ') === 'recipe-book.pdf train-ticket.pdf'" },
    { name: "notes holds the two notes", check: "ls('notes').join(' ') === 'ideas.txt shopping-list.txt'" },
    { name: "the notes still have their text", check: "file('notes/shopping-list.txt') === 'Milk, tea, bamboo\\n' && file('notes/ideas.txt') === 'Learn the terminal\\n'" },
    { name: "the copies and drafts are deleted", check: "!/copy|draft/.test(await run('tree'))" },
    { name: "only the three folders are left in downloads", check: "ls('.').join(' ') === 'documents images notes'" },
    { name: "you used wildcards to move or delete", check: "commands.some((c) => /^\\s*(mv|rm)\\b/.test(c) && /[*?[]/.test(c))" },
  ]}
>

Your `~/downloads` folder is a mess, and you start inside it. Run `ls` to see it. Then tidy it up so that `tree` shows exactly this:

```text
.
├── documents
│   ├── recipe-book.pdf
│   └── train-ticket.pdf
├── images
│   ├── beach.jpg
│   ├── panda-selfie.jpg
│   └── sunset.png
└── notes
    ├── ideas.txt
    └── shopping-list.txt

3 directories, 7 files
```

- **Delete** the files downloaded twice (their names end in `-copy` before the extension) and the drafts (their names start with `draft-`).
- **Make** the folders `images`, `documents` and `notes`.
- **Move** the pictures (`.jpg` and `.png`) into `images`, the PDFs into `documents` and the `.txt` notes into `notes`.

Use wildcards: with them, the whole job takes about six commands.

<Hint>

Think about the order. If you move `*.jpg` first, the copy of the beach photo goes into `images` along with the real one. Deleting the copies and drafts first keeps the moves simple.

</Hint>

<Hint>

`*-copy.*` matches every name with `-copy.` in it, and `draft-*` matches every draft. Check them with `ls` before you delete. One `mkdir` can make all three folders, and one `mv` can take several patterns, like `*.jpg *.png`.

</Hint>

<Hint>

```bash
ls *-copy.* draft-*
rm *-copy.* draft-*
mkdir images documents notes
mv *.jpg *.png ...
mv *.pdf ...
mv ... notes
tree
```

</Hint>

<Solution>

```bash
ls *-copy.* draft-*
rm *-copy.* draft-*
mkdir images documents notes
mv *.jpg *.png images
mv *.pdf documents
mv *.txt notes
tree
```

</Solution>

</Exercise>

## Recap

- **Wildcards** match many names at once: `*` is any text, `?` is exactly one character, `[abc]` or `[1-3]` is one character from a list.
- The **shell** swaps the pattern for the matching names before the command runs, so wildcards work with every command. They skip hidden files.
- If nothing matches, bash passes the pattern on unchanged and the command says "No such file or directory". Quotes turn wildcards off.
- `mv *.jpg photos`, `cp *.txt backup` and `rm draft-*` work on many files at once. Run `ls` with the same pattern before any `rm`.
- `tree` shows the result at a glance.

You can now make, read, copy, move and delete files and whole folders, and sort a messy folder in a few commands. 🎉 Next you'll meet [Git](/learn/git/why-version-control), which remembers every version of your files, so even a bad `rm` stops being the end of the world.
