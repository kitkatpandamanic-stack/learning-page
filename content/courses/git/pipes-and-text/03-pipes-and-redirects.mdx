Each command you've met does one small job: `grep` finds lines, `wc` counts them, `head` takes the first few. On their own they're handy. Joined together they're a superpower: with one line you can answer questions like "which pages of the website are the most popular?" 🦸 The joint is the **pipe**, `|`, and in this lesson you'll build whole chains of commands with it, save their results to files, and finish with a real report from a web server log.

The examples use `access.log` from the first lesson of this module: 20 visits to Timur's tea shop website on March 12, one per line, like `2026-03-12 09:02:13 GET /menu 200` (date, time, method, page, status).

## The pipe: one command's output is the next one's input

A **pipe** `|` takes what the command on its left prints and hands it to the command on its right, instead of to the screen. Here `grep` finds the visits that ended in `404` (page not found), and then `wc -l` counts them:

<CodeExample setup={`echo "2026-03-12 08:58:41 GET / 200" > access.log
echo "2026-03-12 09:02:13 GET /menu 200" >> access.log
echo "2026-03-12 09:02:50 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 09:15:07 GET /about 200" >> access.log
echo "2026-03-12 09:31:22 GET / 200" >> access.log
echo "2026-03-12 09:47:05 GET /contact 200" >> access.log
echo "2026-03-12 10:03:18 GET /menu 200" >> access.log
echo "2026-03-12 10:04:02 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 10:12:45 GET /shop 404" >> access.log
echo "2026-03-12 10:20:31 GET / 200" >> access.log
echo "2026-03-12 10:21:10 GET /menu 200" >> access.log
echo "2026-03-12 10:35:56 POST /contact 200" >> access.log
echo "2026-03-12 10:52:14 GET /menu 200" >> access.log
echo "2026-03-12 11:05:39 GET /about 200" >> access.log
echo "2026-03-12 11:18:27 GET /shop 404" >> access.log
echo "2026-03-12 11:40:03 GET /menu 200" >> access.log
echo "2026-03-12 11:41:48 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 12:09:30 GET /menu 200" >> access.log
echo "2026-03-12 12:30:12 GET /blog 404" >> access.log
echo "2026-03-12 12:55:01 GET / 200" >> access.log`} output={`2026-03-12 10:12:45 GET /shop 404
2026-03-12 11:18:27 GET /shop 404
2026-03-12 12:30:12 GET /blog 404
3`}>

```bash
grep 404 access.log
grep 404 access.log | wc -l
```

</CodeExample>

In the second line, `grep`'s three lines never reached the screen: they went into `wc`, and only `wc`'s answer was printed. Only the **last** command in a chain prints to the screen. Notice also that `wc` printed just `3`, with no file name: it was counting what came through the pipe, not a file.

Every command from this module works this way: give `head`, `tail`, `wc`, `grep` and the rest **no file name**, and they read what comes in through the pipe. Without pipes you'd need a temporary file for every step (`grep 404 access.log > tmp.txt`, then `wc -l tmp.txt`). A chain of commands joined by pipes is called a **pipeline**.

## Sorting lines with sort

**`sort`** puts lines in alphabetical order. **`-r`** ("reverse") flips the order, and **`-u`** ("unique") keeps each line only once. Here `teas.txt` holds six orders, one tea per line: `green`, `oolong`, `green`, `green`, `jasmine`, `oolong`.

<CodeExample setup={`echo "green" > teas.txt
echo "oolong" >> teas.txt
echo "green" >> teas.txt
echo "green" >> teas.txt
echo "jasmine" >> teas.txt
echo "oolong" >> teas.txt`} output={`green
green
green
jasmine
oolong
oolong
oolong
oolong
jasmine
green
green
green
green
jasmine
oolong`}>

```bash
sort teas.txt
sort -r teas.txt
sort -u teas.txt
```

</CodeExample>

Numbers need one more option. A plain `sort` compares text character by character, so `100` comes before `25` (because `1` comes before `2`). **`-n`** ("numeric") compares them as numbers, and `-rn` puts the biggest first. Here `scores.txt` holds `9`, `10`, `100` and `25`:

<CodeExample setup={`echo "9" > scores.txt
echo "10" >> scores.txt
echo "100" >> scores.txt
echo "25" >> scores.txt`} output={`10
100
25
9
9
10
25
100
100
25
10
9`}>

```bash
sort scores.txt
sort -n scores.txt
sort -rn scores.txt
```

</CodeExample>

<Callout type="note" title="On your computer">

`sort` may order capital letters, spaces and punctuation a little differently from the practice terminal, depending on your system's language settings. Lowercase words and numbers with `-n` come out the same everywhere. On a Mac, `uniq -c` and `wc` also pad their counts with a different number of spaces; the counts are the same.

</Callout>

## Counting repeats with uniq

**`uniq`** removes repeated lines, but only repeats that are **next to each other**. That's why it nearly always comes after `sort`, which puts equal lines side by side. **`-c`** ("count") writes how many times each line appeared:

<CodeExample setup={`echo "green" > teas.txt
echo "oolong" >> teas.txt
echo "green" >> teas.txt
echo "green" >> teas.txt
echo "jasmine" >> teas.txt
echo "oolong" >> teas.txt`} output={`green
oolong
green
jasmine
oolong
      3 green
      1 jasmine
      2 oolong`}>

```bash
uniq teas.txt
sort teas.txt | uniq -c
```

</CodeExample>

The first `uniq` merged only the two `green` lines that were neighbours, so `green` and `oolong` still show up twice. After `sort`, each tea appears once, with its count. Add one more `sort -rn`, and the most ordered tea comes first. That three-step chain is one of the most used pipelines there is:

<CodeExample setup={`echo "green" > teas.txt
echo "oolong" >> teas.txt
echo "green" >> teas.txt
echo "green" >> teas.txt
echo "jasmine" >> teas.txt
echo "oolong" >> teas.txt`} output={`      3 green
      2 oolong
      1 jasmine`}>

```bash
sort teas.txt | uniq -c | sort -rn
```

</CodeExample>

`sort -n` reads the number at the start of each line and skips the spaces before it.

## Cutting out columns with cut

Many files are tables in disguise: each line is a row, and some character separates the columns. **`cut`** picks out the columns you want. **`-d`** ("delimiter") says which character separates them, and **`-f`** ("fields") says which ones to keep, counting from 1:

<CodeExample setup={`echo "name,city,role" > team.csv
echo "Mei,Tashkent,designer" >> team.csv
echo "Tom,London,developer" >> team.csv
echo "Ada,Tashkent,developer" >> team.csv`} output={`name
Mei
Tom
Ada
city,role
Tashkent,designer
London,developer
Tashkent,developer`}>

```bash
cut -d , -f 1 team.csv
cut -d , -f 2,3 team.csv
```

</CodeExample>

In `access.log`, a space separates the fields: 1 is the date, 2 the time, 3 the method, 4 the page and 5 the status. A space has to be in quotes, `-d ' '`, or the shell would swallow it:

<CodeExample setup={`echo "2026-03-12 08:58:41 GET / 200" > access.log
echo "2026-03-12 09:02:13 GET /menu 200" >> access.log
echo "2026-03-12 09:02:50 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 09:15:07 GET /about 200" >> access.log
echo "2026-03-12 09:31:22 GET / 200" >> access.log
echo "2026-03-12 09:47:05 GET /contact 200" >> access.log
echo "2026-03-12 10:03:18 GET /menu 200" >> access.log
echo "2026-03-12 10:04:02 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 10:12:45 GET /shop 404" >> access.log
echo "2026-03-12 10:20:31 GET / 200" >> access.log
echo "2026-03-12 10:21:10 GET /menu 200" >> access.log
echo "2026-03-12 10:35:56 POST /contact 200" >> access.log

</CodeExample>

`cut` splits at **every** delimiter, so two spaces in a row make an empty field between them. Real web server logs (nginx, Apache) have more fields in a different order, but the trick is the same: count the fields and pick yours.

## Swapping characters with tr

**`tr`** ("translate") swaps characters: every character from the first set becomes the matching one from the second. **`-d`** ("delete") removes characters instead, and `'\n'` stands for a line break:

<CodeExample output={`GREEN TEA
2026/03/12
tea milk sugar
green
black
oolong`}>

```bash
echo "Green Tea" | tr a-z A-Z
echo "2026-03-12" | tr - /
echo "tea, milk, sugar" | tr -d ,
echo "green black oolong" | tr ' ' '\n'
```

</CodeExample>

`a-z` means every letter from a to z, so `tr a-z A-Z` turns lowercase letters into capitals. The last line put each word on its own line, ready for `sort | uniq -c`.

`tr` is unusual: it never takes a file name, only what comes in. To feed it a file, use a pipe, or **`<`**, the opposite of `>`: it sends a file **into** a command.

<CodeExample setup={`echo "green" > teas.txt
echo "oolong" >> teas.txt
echo "green" >> teas.txt
echo "green" >> teas.txt
echo "jasmine" >> teas.txt
echo "oolong" >> teas.txt`} output={`GREEN
OOLONG
GREEN`}>

```bash
tr a-z A-Z < teas.txt | head -n 3
```

</CodeExample>

## Saving the result: >, >> and tee

The `>` and `>>` from Level 0 work at the end of any pipeline: `>` writes the output into a file (replacing what was there), and `>>` adds it to the end. Here's a small report with a heading:

<CodeExample setup={`echo "green" > teas.txt

<Callout type="danger" title="Never write into the file you're reading">

`sort teas.txt > teas.txt` doesn't sort the file: it **empties** it. The shell empties `teas.txt` for the `>` before `sort` even starts, so `sort` reads an empty file, and the six orders are gone. Write to a new file instead (`sort teas.txt > sorted.txt`), and `mv` it over the old one once you've checked it.

</Callout>

## Errors have their own stream: 2>

Every command has **two** outputs. The normal one is called **standard output**, and error messages go to a second one, **standard error**. Both appear on your screen, but `>` and `|` only take standard output. So when one file exists and one doesn't, the error still lands on your screen:

## Only if it worked: &&

You can put several commands on one line. With **`&&`** between them, the next command runs **only if the one before it worked**:

<CodeExample output={`/home/panda/reports`}>

```bash
mkdir reports && cd reports && pwd
```

</CodeExample>

That's a safety net. Say you want to clean up an `old-logs` folder, but you mistype its name or it isn't there:

<Callout type="warning" title="Common mistakes">

- `uniq` without `sort` first: it only merges neighbouring lines, so the counts come out wrong.
- `sort` without `-n` for numbers: `100` lands before `25`.
- `sort file > file`: it empties the file. Write to a new one.
- `tr a-z A-Z notes.txt`: `tr` takes no file names. Use `tr a-z A-Z < notes.txt` or a pipe.
- A space as the delimiter without quotes: the shell drops it, so write `cut -d ' '`.
- Expecting `>` to catch errors: they need `2>`.

</Callout>

## Recap

- A **pipe** `|` sends one command's output into the next one. Only the last command prints to the screen, and commands given no file name read from the pipe.
- `sort` sorts lines (`-r` reversed, `-n` as numbers, `-u` each line once). `uniq` merges neighbouring repeats, so sort first; `uniq -c` counts them.
- `sort | uniq -c | sort -rn` lists things by how often they appear.
- `cut -d , -f 2` picks columns; `tr a-z A-Z` swaps characters and `tr -d` deletes them; `<` feeds a file into a command.
- Build pipelines step by step, running each step. Save with `>` or `>>`, or see and save at once with `tee`.
- Never redirect into the file you're reading: `>` empties it first.
- Errors go to standard error: `2>` saves them, and `2> /dev/null` throws them away.
- `a && b` runs `b` only if `a` worked.

You can now look inside files of any size, find the lines you need and turn a raw log into a report. 🎉 Next up: [seeing changes with diff](/learn/git/seeing-changes-with-diff), where Git shows you exactly what changed in your files, line by line.
