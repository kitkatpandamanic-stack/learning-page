Каждая команда, с которой вы уже знакомы, делает одно небольшое дело: `grep` находит строки, `wc` их считает, `head` берёт первые несколько. По отдельности они удобны. А вместе — настоящая суперсила: одной строкой можно ответить на вопрос вроде «какие страницы сайта самые популярные?» 🦸 Соединяет команды **конвейер** (pipe), символ `|`. В этом уроке вы соберёте с ним целые цепочки команд, сохраните их результаты в файлы и в конце сделаете настоящий отчёт по журналу веб-сервера.

В примерах используется `access.log` из первого урока этого модуля: 20 посещений сайта чайной Тимура за 12 марта, по одному в строке, например `2026-03-12 09:02:13 GET /menu 200` (дата, время, метод, страница, код ответа).

## Конвейер: вывод одной команды — вход следующей

**Конвейер** `|` берёт то, что выводит команда слева от него, и передаёт команде справа, а не на экран. Здесь `grep` находит посещения, которые закончились кодом `404` (страница не найдена), а `wc -l` их считает:

<CodeExample setup={`echo "2026-03-12 08:58:41 GET / 200" > access.log
echo "2026-03-12 09:02:13 GET /menu 200" >> access.log
echo "2026-03-12 09:02:50 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 09:15:07 GET /about 200" >> access.log
echo "2026-03-12 09:31:22 GET / 200" >> access.log
echo "2026-03-12 09:47:05 GET /contact 200" >> access.log
echo "2026-03-12 10:03:18 GET /menu 200" >> access.log
echo "2026-03-12 10:04:02 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 10:12:45 GET /shop 404" >> access.log
echo "2026-03-12 10:20:31 GET / 200" >> access.log
echo "2026-03-12 10:21:10 GET /menu 200" >> access.log
echo "2026-03-12 10:35:56 POST /contact 200" >> access.log
echo "2026-03-12 10:52:14 GET /menu 200" >> access.log
echo "2026-03-12 11:05:39 GET /about 200" >> access.log
echo "2026-03-12 11:18:27 GET /shop 404" >> access.log
echo "2026-03-12 11:40:03 GET /menu 200" >> access.log
echo "2026-03-12 11:41:48 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 12:09:30 GET /menu 200" >> access.log
echo "2026-03-12 12:30:12 GET /blog 404" >> access.log
echo "2026-03-12 12:55:01 GET / 200" >> access.log`} output={`2026-03-12 10:12:45 GET /shop 404
2026-03-12 11:18:27 GET /shop 404
2026-03-12 12:30:12 GET /blog 404
3`}>

```bash
grep 404 access.log
grep 404 access.log | wc -l
```

</CodeExample>

Во второй строке три строки от `grep` так и не попали на экран: они ушли в `wc`, и напечатан был только ответ `wc`. На экран выводит только **последняя** команда в цепочке. Заметьте ещё, что `wc` вывела просто `3`, без имени файла: она считала то, что пришло по конвейеру, а не файл.

Так работают все команды этого модуля: если не дать `head`, `tail`, `wc`, `grep` и остальным **имени файла**, они читают то, что приходит по конвейеру. Без конвейеров на каждом шаге понадобился бы временный файл (`grep 404 access.log > tmp.txt`, а потом `wc -l tmp.txt`). Цепочку команд, соединённых `|`, тоже называют **конвейером** (pipeline).

## Сортируем строки: sort

**`sort`** расставляет строки по алфавиту. **`-r`** (reverse — «наоборот») переворачивает порядок, а **`-u`** (unique — «уникальные») оставляет каждую строку только один раз. Здесь в `teas.txt` шесть заказов, по одному сорту чая в строке: `green`, `oolong`, `green`, `green`, `jasmine`, `oolong`.

<CodeExample setup={`echo "green" > teas.txt
echo "oolong" >> teas.txt
echo "green" >> teas.txt
echo "green" >> teas.txt
echo "jasmine" >> teas.txt
echo "oolong" >> teas.txt`} output={`green
green
green
jasmine
oolong
oolong
oolong
oolong
jasmine
green
green
green
green
jasmine
oolong`}>

```bash
sort teas.txt
sort -r teas.txt
sort -u teas.txt
```

</CodeExample>

С числами нужна ещё одна опция. Обычный `sort` сравнивает текст символ за символом, поэтому `100` оказывается раньше `25` (ведь `1` идёт раньше `2`). **`-n`** (numeric — «числовая») сравнивает их как числа, а `-rn` ставит самые большие первыми. Здесь в `scores.txt` лежат `9`, `10`, `100` и `25`:

<CodeExample setup={`echo "9" > scores.txt
echo "10" >> scores.txt
echo "100" >> scores.txt
echo "25" >> scores.txt`} output={`10
100
25
9
9
10
25
100
100
25
10
9`}>

```bash
sort scores.txt
sort -n scores.txt
sort -rn scores.txt
```

</CodeExample>

<Callout type="note" title="На вашем компьютере">

`sort` может расставлять заглавные буквы, пробелы и знаки препинания немного не так, как учебный терминал: это зависит от языковых настроек системы. Строчные латинские слова и числа с `-n` сортируются везде одинаково. А на Mac `uniq -c` и `wc` ставят перед числами другое количество пробелов, но сами числа те же.

</Callout>

## Считаем повторы: uniq

**`uniq`** убирает повторяющиеся строки, но только те повторы, что стоят **рядом**. Поэтому перед ней почти всегда идёт `sort`: он ставит одинаковые строки бок о бок. **`-c`** (count — «посчитать») пишет, сколько раз встретилась каждая строка:

<CodeExample setup={`echo "green" > teas.txt
echo "oolong" >> teas.txt
echo "green" >> teas.txt
echo "green" >> teas.txt
echo "jasmine" >> teas.txt
echo "oolong" >> teas.txt`} output={`green
oolong
green
jasmine
oolong
      3 green
      1 jasmine
      2 oolong`}>

```bash
uniq teas.txt
sort teas.txt | uniq -c
```

</CodeExample>

Первая `uniq` склеила только две строки `green`, которые стояли рядом, поэтому `green` и `oolong` всё ещё встречаются по два раза. После `sort` каждый чай появляется один раз вместе со своим числом. Добавьте ещё `sort -rn`, и самый заказываемый чай окажется первым. Эта цепочка из трёх шагов — один из самых популярных конвейеров вообще:

<CodeExample setup={`echo "green" > teas.txt
echo "oolong" >> teas.txt
echo "green" >> teas.txt
echo "green" >> teas.txt
echo "jasmine" >> teas.txt
echo "oolong" >> teas.txt`} output={`      3 green
      2 oolong
      1 jasmine`}>

```bash
sort teas.txt | uniq -c | sort -rn
```

</CodeExample>

`sort -n` читает число в начале каждой строки и пропускает пробелы перед ним.

## Вырезаем столбцы: cut

Многие файлы — это замаскированные таблицы: каждая строка — запись, а столбцы разделены каким-то символом. **`cut`** («вырезать») достаёт нужные столбцы, или **поля** (fields). **`-d`** (delimiter — «разделитель») говорит, какой символ их разделяет, а **`-f`** (fields) — какие поля оставить, считая с 1:

<CodeExample setup={`echo "name,city,role" > team.csv
echo "Mei,Tashkent,designer" >> team.csv
echo "Tom,London,developer" >> team.csv
echo "Ada,Tashkent,developer" >> team.csv`} output={`name
Mei
Tom
Ada
city,role
Tashkent,designer
London,developer
Tashkent,developer`}>

```bash
cut -d , -f 1 team.csv
cut -d , -f 2,3 team.csv
```

</CodeExample>

В `access.log` поля разделены пробелом: 1 — дата, 2 — время, 3 — метод, 4 — страница, 5 — код ответа. Пробел нужно взять в кавычки, `-d ' '`, иначе оболочка его проглотит:

<CodeExample setup={`echo "2026-03-12 08:58:41 GET / 200" > access.log

echo "2026-03-12 09:02:50 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 09:15:07 GET /about 200" >> access.log
echo "2026-03-12 09:31:22 GET / 200" >> access.log
echo "2026-03-12 09:47:05 GET /contact 200" >> access.log
echo "2026-03-12 10:03:18 GET /menu 200" >> access.log
echo "2026-03-12 10:04:02 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 10:12:45 GET /shop 404" >> access.log
echo "2026-03-12 10:20:31 GET / 200" >> access.log
echo "2026-03-12 10:21:10 GET /menu 200" >> access.log
echo "2026-03-12 10:35:56 POST /contact 200" >> access.log
echo "2026-03-12 10:52:14 GET /menu 200" >> access.log
echo "2026-03-12 11:05:39 GET /about 200" >> access.log
echo "2026-03-12 11:18:27 GET /shop 404" >> access.log
echo "2026-03-12 11:40:03 GET /menu 200" >> access.log
echo "2026-03-12 11:41:48 GET /menu/green-tea 200" >> access.log
echo "2026-03-12 12:09:30 GET /menu 200" >> access.log

`cut` режет по **каждому** разделителю, поэтому два пробела подряд дают между собой пустое поле. В журналах настоящих веб-серверов (nginx, Apache) полей больше и порядок другой, но приём тот же: посчитайте поля и выберите своё.

## Заменяем символы: tr

**`tr`** (translate — «перевести») заменяет символы: каждый символ из первого набора становится соответствующим символом из второго. **`-d`** (delete — «удалить») вместо замены удаляет символы, а `'\n'` обозначает перевод строки:

<CodeExample output={`GREEN TEA
2026/03/12
tea milk sugar
green
black
oolong`}>

```bash
echo "Green Tea" | tr a-z A-Z
echo "2026-03-12" | tr - /
echo "tea, milk, sugar" | tr -d ,
echo "green black oolong" | tr ' ' '\n'
```

</CodeExample>

`a-z` означает все латинские буквы от a до z, поэтому `tr a-z A-Z` превращает строчные латинские буквы в заглавные. Последняя строка поставила каждое слово на отдельную строку — как раз для `sort | uniq -c`.

`tr` устроена необычно: она никогда не принимает имя файла, только то, что приходит на вход. Чтобы передать ей файл, используйте конвейер или **`<`** — противоположность `>`: эта стрелка отправляет файл **в** команду.

<CodeExample setup={`echo "green" > teas.txt
echo "oolong" >> teas.txt
echo "green" >> teas.txt
echo "green" >> teas.txt
echo "jasmine" >> teas.txt
echo "oolong" >> teas.txt`} output={`GREEN
OOLONG
GREEN`}>

```bash
tr a-z A-Z < teas.txt | head -n 3
```

</CodeExample>

## Сохраняем результат: >, >> и tee

</Callout>

## У ошибок свой поток: 2>

## Только если получилось: &&

<Callout type="warning" title="Частые ошибки">

- `uniq` без `sort`: она склеивает только соседние строки, и числа получаются неправильными.
- `sort` без `-n` для чисел: `100` оказывается раньше `25`.
- `sort файл > файл`: файл опустеет. Пишите в новый.
- `tr a-z A-Z notes.txt`: `tr` не принимает имён файлов. Пишите `tr a-z A-Z < notes.txt` или используйте конвейер.
- Пробел-разделитель без кавычек: оболочка его выбросит, поэтому пишите `cut -d ' '`.
- Ожидание, что `>` поймает ошибки: для них нужен `2>`.

</Callout>

## Итоги

- **Конвейер** `|` отправляет вывод одной команды на вход следующей. На экран выводит только последняя команда, а команды без имени файла читают то, что пришло по конвейеру.
- `sort` сортирует строки (`-r` — наоборот, `-n` — как числа, `-u` — каждую строку один раз). `uniq` склеивает соседние повторы, поэтому сначала сортируйте; `uniq -c` их считает.
- `sort | uniq -c | sort -rn` показывает, что встречается чаще всего.
- `cut -d , -f 2` вырезает столбцы; `tr a-z A-Z` заменяет символы, а `tr -d` удаляет их; `<` отправляет файл в команду.
- Собирайте конвейеры по шагам и запускайте каждый шаг. Сохраняйте через `>` или `>>`, а чтобы и видеть, и сохранять, — через `tee`.
- Никогда не перенаправляйте вывод в файл, который читаете: `>` сначала его очистит.
- Ошибки идут в стандартный поток ошибок: `2>` сохраняет их, а `2> /dev/null` выбрасывает.
- `a && b` запускает `b`, только если `a` сработала.

Теперь вы умеете заглядывать в файлы любого размера, находить нужные строки и превращать сырой журнал в отчёт. 🎉 Дальше: [смотрим изменения через diff](/learn/git/seeing-changes-with-diff) — там Git покажет, что именно изменилось в ваших файлах, строка за строкой.
