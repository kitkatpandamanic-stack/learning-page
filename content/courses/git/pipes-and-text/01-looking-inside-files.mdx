In Level 0 you read files with `cat`. That's perfect for a shopping list, but real files can be huge: a busy website's log grows by thousands of lines a day, and `cat` would pour every one of them onto your screen. 🌊 In this lesson you'll look at just the part you need: the first lines, the last lines, or simply how big a file is.

Timur's tea shop website from the Level 0 capstone is online now. Its web server writes one line to a file called `access.log` for every page someone opens: the date, the time, the method (`GET` means "show me a page", `POST` sends data, like a filled-in form), the page, and a **status code** (`200` means OK, `404` means "not found"). In the examples, the home folder holds a 20-line `access.log`, with the oldest visits at the top.

## Several files at once

Give `head` or `tail` several files, and each one gets a header line with its name. That's a handy way to see the column names at the top of every **CSV** file (a table saved as text, with commas between the columns):

<CodeExample setup={`echo "id,name,city" > customers.csv
echo "1,Mei,Tashkent" >> customers.csv
echo "2,Tom,London" >> customers.csv
echo "id,customer,tea" > orders.csv
echo "1,1,green tea" >> orders.csv
echo "2,2,oolong" >> orders.csv`} output={`==> customers.csv <==
id,name,city

==> orders.csv <==
id,customer,tea`}>

```bash
head -n 1 *.csv
```

</CodeExample>

The wildcard `*.csv` from Level 0 works here too: the shell swaps it for `customers.csv orders.csv` before `head` runs.

## Counting with wc

**`wc`** ("word count") counts three things: **lines**, **words** and **bytes**. A **byte** is the smallest unit of storage; a plain English letter, digit, space or line break takes one byte. Here's a short file you can count by eye:

<CodeExample setup={`echo "green tea in a cup" > haiku.txt
echo "steam rises in the morning" >> haiku.txt
echo "the panda smiles" >> haiku.txt`} output={`green tea in a cup
steam rises in the morning
the panda smiles
 3 13 63 haiku.txt`}>

```bash
cat haiku.txt
wc haiku.txt
```

</CodeExample>

The columns always come in the same order:

- **3 lines**.
- **13 words**: anything between spaces counts as a word.
- **63 bytes**: 60 letters and spaces, plus 3 invisible line breaks, one at the end of each line.

Ask for just one count with an option: **`-l`** for lines, **`-w`** for words, **`-c`** for bytes. `wc -l` is the one you'll use most: how many visits, how many orders, how many lines of code.

`wc` pads the numbers with spaces so the columns line up. On a Mac, `wc` pads every number with more spaces than Linux does; the numbers themselves are the same.

### Bytes aren't letters

`wc -c` counts bytes, not letters. For plain English the two are the same, but many letters take more than one byte: `é`, `ü`, every Russian letter and every emoji.

<CodeExample output={` 4 a.txt
 6 b.txt
10 total`}>

```bash
echo "tea" > a.txt
echo "café" > b.txt
wc -c a.txt b.txt
```

</CodeExample>

`tea` is 3 letters plus a line break: 4 bytes. `café` has 4 letters, but `é` takes 2 bytes, so the file is 6 bytes. (On your computer, `wc -m` counts characters instead; the practice terminal doesn't have it.)

### wc -l counts line breaks

`wc -l` really counts **line breaks**. `echo` ends its text with one, so every `echo` line counts. `echo -n` ("no newline") leaves the line break out, and then a file with one line of text has **0** lines:

<CodeExample output={`0 note.txt
13 note.txt`}>

```bash
echo -n "no line break" > note.txt
wc -l note.txt
wc -c note.txt
```

</CodeExample>

Some editors save a file without a line break at the end. If `wc -l` says one line fewer than you see, that's why.

## Reading long files on your computer

In the practice terminal, files are small, and `head`, `tail` and `cat -n` are all you need. On your own computer, the tool for reading a long file is **`less`**. It shows one screenful at a time and lets you scroll and search, without printing everything:

```bash
less access.log
```

| Key                   | What it does                         |
| --------------------- | ------------------------------------ |
| **Space**             | Next screen                          |
| **b**                 | Back one screen                      |
| **↓** and **↑**       | One line down or up                  |
| **/** word, **Enter** | Search for the word                  |
| **n**                 | Next match                           |
| **g** and **G**       | Jump to the start or the end         |
| **q**                 | Quit                                 |

`less -N` adds line numbers. You may have met `less` already: `man ls` usually shows the manual in it, which is why **q** quits the manual. And if you `cat` a huge file by mistake, **Ctrl+C** stops it.

<Callout type="note" title="Not in the practice terminal">

`less` needs a real keyboard and screen, so the practice terminal doesn't have it. Here, use `head`, `tail` and `cat -n`.

</Callout>

<Callout type="warning" title="Common mistakes">

- `head 3 access.log` without `-n`: `head` then looks for a file called `3`.
- Reading `wc`'s columns in the wrong order: it's always lines, words, bytes.
- Expecting `wc -c` to count letters: it counts bytes.
- Running `cat` on a huge log: use `head`, `tail` or `less` instead.

</Callout>

## Recap

- `head file` shows the first 10 lines, `tail file` the last 10; `-n 3` picks how many. Logs grow at the bottom, so `tail` shows the newest lines.
- With several files, `head` and `tail` print a `==> name <==` header before each one.
- `wc` counts lines, words and bytes, in that order; `-l`, `-w` and `-c` pick one. With several files it adds a `total` line.
- `wc -l` counts line breaks, and `wc -c` counts bytes, which aren't always letters.
- On your computer, `less file` shows a long file one screen at a time (Space, b, `/` to search, q to quit), and `tail -f` follows a growing log.
