`head` и `tail` показывают начало и конец файла. А как быть с той единственной строкой посередине, где написано, что что-то сломалось? 🔎 Её найдёт **`grep`**: дайте ему текст, и он выведет все строки, в которых этот текст есть. Разработчики пользуются им каждый день: ищут ошибки в журналах, нужную функцию в большом проекте или все заметки, которые оставили себе в коде.

Странное название пришло из команды старого текстового редактора `g/re/p`: «**g**lobally search for a **r**egular **e**xpression and **p**rint» — «найти по всему файлу регулярное выражение и вывести строки».

## Первый grep

`grep` принимает **образец** (pattern — текст, который нужно найти), а за ним файл. Он выводит все строки файла, в которых есть образец. В первых примерах в домашней папке лежит меню чайной, `menu.txt`. Сайт у Тимура на английском, поэтому и меню тоже:

```text
Green tea
Black tea
Jasmine tea
Teapot, glass
Steamed buns
Iced tea with lemon
Tea time cake
```

<CodeExample setup={`echo "Green tea" > menu.txt
echo "Black tea" >> menu.txt
echo "Jasmine tea" >> menu.txt
echo "Teapot, glass" >> menu.txt
echo "Steamed buns" >> menu.txt
echo "Iced tea with lemon" >> menu.txt
echo "Tea time cake" >> menu.txt`} output={`Green tea
Black tea
Jasmine tea
Steamed buns
Iced tea with lemon`}>

```bash
grep tea menu.txt
```

</CodeExample>

Посмотрите внимательно, что он нашёл:

- `Steamed buns` («паровые булочки») попали в список: `grep` ищет буквы `tea` **где угодно** в строке, а не целые слова, а в S**tea**med они есть.
- `Teapot` и `Tea time cake` не попали: по умолчанию заглавные и строчные буквы **различаются**.

Если совпадений нет, `grep` не выводит ничего.

## Опции, которые меняют, что ищет grep

**`-i`** (ignore case — «не учитывать регистр») считает заглавные и строчные буквы одинаковыми:

<CodeExample setup={`echo "Green tea" > menu.txt
echo "Black tea" >> menu.txt
echo "Jasmine tea" >> menu.txt
echo "Teapot, glass" >> menu.txt
echo "Steamed buns" >> menu.txt
echo "Iced tea with lemon" >> menu.txt
echo "Tea time cake" >> menu.txt`} output={`Green tea
Black tea
Jasmine tea
Teapot, glass
Steamed buns
Iced tea with lemon
Tea time cake`}>

```bash
grep -i tea menu.txt
```

</CodeExample>

**`-w`** (word — «слово») находит только **целые слова**. Слово — это подряд идущие буквы, цифры и знаки подчёркивания, поэтому `tea` внутри `Steamed` или `Teapot` больше не считается. Опции объединяются, как в `ls -la`, так что `-iw` — это целые слова в любом регистре:

<CodeExample setup={`echo "Green tea" > menu.txt
echo "Black tea" >> menu.txt
echo "Jasmine tea" >> menu.txt
echo "Teapot, glass" >> menu.txt
echo "Steamed buns" >> menu.txt
echo "Iced tea with lemon" >> menu.txt
echo "Tea time cake" >> menu.txt`} output={`Green tea
Black tea
Jasmine tea
Iced tea with lemon
Green tea
Black tea
Jasmine tea
Iced tea with lemon
Tea time cake`}>

```bash
grep -w tea menu.txt
grep -iw tea menu.txt
```

</CodeExample>

**`-v`** (invert — «наоборот») переворачивает поиск и выводит строки, где образца **нет**. Так удобно отбрасывать лишнее, например обычные сообщения в журнале, чтобы стали видны необычные:

<CodeExample setup={`echo "Green tea" > menu.txt
echo "Black tea" >> menu.txt
echo "Jasmine tea" >> menu.txt
echo "Teapot, glass" >> menu.txt
echo "Steamed buns" >> menu.txt
echo "Iced tea with lemon" >> menu.txt
echo "Tea time cake" >> menu.txt`} output={`Teapot, glass
Tea time cake`}>

```bash
grep -v tea menu.txt
```

</CodeExample>

## Опции, которые меняют, что выводит grep

**`-n`** (number — «номер») ставит перед каждым совпадением номер строки, чтобы вы знали, где смотреть. **`-c`** (count — «посчитать») выводит только число совпавших строк:

<CodeExample setup={`echo "Green tea" > menu.txt
echo "Black tea" >> menu.txt
echo "Jasmine tea" >> menu.txt
echo "Teapot, glass" >> menu.txt
echo "Steamed buns" >> menu.txt
echo "Iced tea with lemon" >> menu.txt
echo "Tea time cake" >> menu.txt`} output={`1:Green tea
2:Black tea
3:Jasmine tea
5:Steamed buns
6:Iced tea with lemon
5
7`}>

```bash
grep -n tea menu.txt
grep -c tea menu.txt
grep -ic tea menu.txt
```

</CodeExample>

`-c` считает **строки**, а не совпадения: строка, где `tea` встречается дважды, всё равно считается один раз.

## Кавычки вокруг образца

Оболочка разбивает команду на слова по пробелам ещё до того, как запустится `grep`. Чтобы найти текст с пробелом, возьмите весь образец в **кавычки**:

<CodeExample setup={`echo "Green tea" > menu.txt
echo "Black tea" >> menu.txt
echo "Jasmine tea" >> menu.txt
echo "Teapot, glass" >> menu.txt
echo "Steamed buns" >> menu.txt
echo "Iced tea with lemon" >> menu.txt
echo "Tea time cake" >> menu.txt`} output={`Iced tea with lemon`}>

```bash
grep "Iced tea" menu.txt
```

</CodeExample>

Без кавычек `grep` считает образцом первое слово, а **все остальные слова — именами файлов**. Здесь кто-то проверяет, есть ли в меню bubble tea, сначала с кавычками, потом без:

<CodeExample setup={`echo "Green tea" > menu.txt
echo "Black tea" >> menu.txt
echo "Jasmine tea" >> menu.txt
echo "Teapot, glass" >> menu.txt
echo "Steamed buns" >> menu.txt
echo "Iced tea with lemon" >> menu.txt
echo "Tea time cake" >> menu.txt`} output={`grep: tea: No such file or directory`}>

```bash
grep "bubble tea" menu.txt
grep bubble tea menu.txt
```

</CodeExample>

Первая команда ничего не нашла (bubble tea в меню нет) и ничего не вывела. Вторая искала `bubble` в двух файлах, `tea` и `menu.txt`, а файла с именем `tea` нет.

Берите в кавычки любой образец с пробелами или символами, которые оболочка понимает по-своему, например `*`, `?` или `$`. Надёжнее всего **одинарные кавычки** `'…'`: внутри них оболочка не меняет ровным счётом ничего.

## Ищем по всему проекту: -r

В следующих примерах вы находитесь внутри небольшого проекта — кода сайта чайной:

```text
tea-shop
├── README.md
└── src
    ├── cart.js
    ├── menu.js
    └── style.css
```

Разработчики оставляют в коде заметки вроде `TODO` («сделать») и `FIXME` («починить»). Если дать `grep` несколько файлов, перед каждой найденной строкой он напишет имя файла:

<CodeExample setup={`mkdir -p tea-shop/src

<Callout type="note" title="На вашем компьютере">

- Файлы могут идти в другом порядке, а имена — начинаться с `./`, как в `./src/menu.js`. Так бывает всегда, если искать в `.` (`grep -r TODO .`), а на Mac — даже без точки.

</Callout>

## Несколько особых символов

Образец для `grep` — не только обычный текст: у некоторых символов есть особое значение. Такие образцы называют **регулярными выражениями** (regular expressions) — это целый маленький язык. Пока хватит трёх символов:

| Символ | Означает                | Пример     | Подходят строки, которые… |
| ------ | ----------------------- | ---------- | ------------------------- |
| `^`    | начало строки           | `'^Tea'`   | начинаются с `Tea`        |
| `$`    | конец строки            | `'lemon$'` | заканчиваются на `lemon`  |
| `.`    | любой один символ       | `'t.a'`    | содержат `t`, любой символ и `a` |

Вот прайс-лист, где они помогают, а один из них даже мешает:

```text
green tea 1.50
black tea 1.20
jasmine tea 2.10
teapot 125
```

<CodeExample setup={`echo "green tea 1.50" > prices.txt
echo "black tea 1.20" >> prices.txt
echo "jasmine tea 2.10" >> prices.txt
echo "teapot 125" >> prices.txt`} output={`teapot 125
green tea 1.50
black tea 1.20
jasmine tea 2.10
green tea 1.50
teapot 125
green tea 1.50`}>

```bash
grep '^t' prices.txt
grep '0$' prices.txt
grep '1.5' prices.txt
grep -F '1.5' prices.txt
```

</CodeExample>

- `'^t'` нашёл только `teapot` («чайник»): `t` есть и в других строках, но не в начале.
- `'0$'` нашёл три цены, которые заканчиваются на `0`.
- `'1.5'` совпал и с `teapot 125`: точка означает **любой** символ, а `2` — тоже символ.
- **`-F`** (fixed — «как есть») отключает все особые значения, и точка становится просто точкой. Берите её, когда ищете текст с точками: цены, версии, имена файлов.

И ещё одно: с **`-E`** (extended — «расширенные») символ `|` означает **или**. Вот все `TODO` и все `FIXME` в проекте сразу:

<CodeExample setup={`mkdir -p tea-shop/src
cd tea-shop

echo "}" >> src/menu.js

src/menu.js:// TODO: load the prices from a file
src/style.css:/* TODO: make the buttons green */`}>

```bash
grep -rE 'TODO|FIXME' src
```

</CodeExample>

<Callout type="tip" title="Образцы grep — не шаблоны оболочки">

В `ls *.txt` звёздочка означает «любой текст». В образце `grep` она значит другое («повтори предыдущий символ»), поэтому не переносите туда привычные шаблоны. Чтобы найти текст, обычно хватает простых слов с `-i`, `-w` и `-F`.

</Callout>

<Callout type="warning" title="Частые ошибки">

- Файл перед образцом: `grep menu.txt tea` ищет текст `menu.txt` в файле с именем `tea`. Образец всегда идёт первым.
- Папка без `-r`: `grep: src: Is a directory`.
- Образец с пробелами без кавычек: слова после первого становятся именами файлов.
- Забытый регистр: `grep error` не найдёт `ERROR`. Если не уверены, добавьте `-i`.
- Нет файла вообще: на вашем компьютере `grep tea` без файла ждёт, что вы будете вводить текст. Нажмите **Ctrl+C**, чтобы вернуть приглашение.

</Callout>

Сервер чайной пишет свои сообщения в `app.log`. В каждой строке есть время, **уровень** заглавными буквами (`INFO` — обычные новости, `WARN` — предупреждения, `ERROR` — сбои) и само сообщение. Выполните `cat app.log`, чтобы его увидеть, а потом:

1. Сохраните все строки уровня `ERROR` вместе с их **номерами** в новый файл `errors.txt`. Только строки, где уровень — `ERROR`: строке `INFO`, в которой встречается строчное слово «error», там не место.
2. Одной командой `grep` выведите, **сколько** строк **не** относятся к `INFO`.

<Hint>

Для первой задачи нужны номера строк и способ сохранить то, что выводит `grep`. С `>` вы знакомы с уровня 0. А нужно ли здесь игнорировать регистр?

</Hint>

<Hint>

`grep -n ERROR app.log` выводит строки с номерами; допишите `> errors.txt`, чтобы сохранить их в файл. `-i` не добавляйте: так попадёт и строчное «error». Для второй задачи `-v` переворачивает поиск, а `-c` считает.

</Hint>

<Hint>

```bash

cat errors.txt
grep ... INFO app.log
```

</Hint>

<Solution>

```bash
grep -n ERROR app.log > errors.txt
cat errors.txt
grep -vc INFO app.log
```

## Итоги

- `grep образец файл` выводит строки, где есть образец, в любом месте строки и с учётом регистра. С несколькими файлами перед строкой ставится имя файла.
- `-i` не учитывает регистр, `-w` ищет целые слова, `-v` выводит строки, где совпадения **нет**.
- `-n` добавляет номера строк, `-c` считает совпавшие строки, `-l` выводит имена файлов с совпадениями.
- `-r` обыскивает папку со всем содержимым, а без папки — ту, где вы находитесь.
- Образцы с пробелами и особыми символами берите в кавычки; одинарные надёжнее всего.
- `^` — начало строки, `$` — конец, `.` — любой один символ. `-F` превращает образец в обычный текст, а с `-E` символ `|` означает «или».
