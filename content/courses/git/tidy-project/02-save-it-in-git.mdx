Timur's folder is tidy! 🎉 In Part 1 you protected it with one copy, `timur-site-backup`. A copy is better than nothing, but it's a single frozen moment: it can't tell you **what** changed since, **when**, or **why**. And after a few clean-ups you end up with `backup`, `backup-2` and `backup-final`, the very mess you just threw away.

Git does this job properly. In this part you'll turn `timur-site` into a **repository**, save it in a first **commit**, add two more commits, and then read the project's history like a logbook.

The folder starts exactly as Part 1 left it:

```text
timur-site
├── about.html
├── css
│   └── style.css
├── images
│   ├── logo.png
│   └── tea.jpg
├── index.html
└── notes
    ├── draft.txt
    └── todo.txt
```

## Turn the folder into a repository

Right now Git knows nothing about this folder. `git init` changes that: it creates a hidden `.git` folder, where Git will keep the whole history.

<CodeExample setup={`mkdir -p timur-site/css timur-site/images timur-site/notes
cd timur-site
echo "<h1>Timur's Tea Shop</h1>" > index.html
echo "<p>Green, black and jasmine tea.</p>" >> index.html
echo "<p>The best tee in Tashkent since 2015.</p>" > about.html
echo "body { font-family: sans-serif; }" > css/style.css
touch images/logo.png images/tea.jpg
echo "1. Make folders: css, images, notes" > notes/todo.txt
echo "2. Throw away old copies and screenshots" >> notes/todo.txt
echo "3. Put every file in its folder" >> notes/todo.txt
echo "About us: a family tea shop" > notes/draft.txt`} output={`fatal: not a git repository (or any of the parent directories): .git
Initialized empty Git repository in /home/panda/timur-site/.git/
.  ..  .git  about.html  css  images  index.html  notes`}>

```bash
git status
git init
ls -a
```

</CodeExample>

- Before `git init`, `git status` fails: this folder isn't a repository yet.
- After it, `ls -a` shows the new hidden `.git` folder. Run `git init` **once per project**, in its top folder.

<Callout type="warning" title="Leave .git alone">

Everything Git saves lives inside `.git`. You never need to change anything in it by hand, and `rm -r .git` would delete the project's whole history in one go. That's also why it's hidden: so nobody tidies it away by accident.

</Callout>

## The first commit

Saving takes two steps, as you know from Your First Repository:

1. **`git add`** puts files in the **staging area**, the list of what goes into the next commit. `git add .` adds everything in this folder (the dot means "here"), including all the folders inside it.
2. **`git commit -m "message"`** saves everything that's staged as one commit, with your message.

<CodeExample setup={`mkdir -p timur-site/css timur-site/images timur-site/notes

touch images/logo.png images/tea.jpg

echo "3. Put every file in its folder" >> notes/todo.txt

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
	new file:   about.html
	new file:   css/style.css

	new file:   images/tea.jpg
	new file:   index.html

```bash
git add .
git status
```

</CodeExample>

All seven files are staged and listed one by one now. A good commit message says **what the commit does**, in a few words, starting with a verb or naming the change: "First version of the tea shop site", "Add a README", "Fix a typo on the about page".

<Callout type="note" title="On your own computer">

- Without `-m`, `git commit` opens a text editor for the message. The practice terminal has no editor, so here it prints a hint instead: always write `-m "message"`.
- The practice terminal already knows who you are (Panda). On your own computer you tell Git your name and email once, with `git config --global user.name` and `git config --global user.email`, before your first commit.

</Callout>

## A README for visitors

Almost every project has a **README** file in its top folder: a short note that says what the project is. Sites like GitHub show it on the project's front page. It's usually called `README.md`; the `.md` stands for **Markdown**, a simple text format where a line starting with `#` is a heading.

You can write a short file without an editor, using `echo` with redirects, as you did in Files & Folders. Remember the difference:

- `>` **replaces** the file's contents (or makes a new file),
- `>>` **adds** a line to the end.

Using `>` twice is a classic mistake. The second line wipes out the first:

<CodeExample setup={`mkdir timur-site
cd timur-site`} output={`The website of a family tea shop in Tashkent.`}>

```bash
echo "# Timur's Tea Shop" > README.md
echo "The website of a family tea shop in Tashkent." > README.md
cat README.md
```

</CodeExample>

The heading is gone. The fix: `>` for the first line, `>>` for every line after it.

## Reading the history

Two commits make a history worth reading. `git log --oneline` gives one line per commit, newest first, and `git show` shows the newest commit in full:

<CodeExample setup={`mkdir -p timur-site/css timur-site/images timur-site/notes
cd timur-site
echo "<h1>Timur's Tea Shop</h1>" > index.html
echo "<p>Green, black and jasmine tea.</p>" >> index.html
echo "<p>The best tee in Tashkent since 2015.</p>" > about.html
echo "body { font-family: sans-serif; }" > css/style.css
touch images/logo.png images/tea.jpg
echo "1. Make folders: css, images, notes" > notes/todo.txt
echo "2. Throw away old copies and screenshots" >> notes/todo.txt
echo "3. Put every file in its folder" >> notes/todo.txt
echo "About us: a family tea shop" > notes/draft.txt
git init
git add .
git commit -m "First version of the tea shop site"
echo "# Timur's Tea Shop" > README.md
echo "The website of a family tea shop in Tashkent." >> README.md
git add README.md
git commit -m "Add a README"`} output={`5150f17 (HEAD -> main) Add a README
6e10c4f First version of the tea shop site
commit 5150f17ea0eaab98f729c7343d68ef0244fa24bb (HEAD -> main)
Author: Panda <panda@pandadev.dev>
Date:   Mon Jan 5 09:02:00 2026 +0000

    Add a README

diff --git a/README.md b/README.md
new file mode 100644
index 0000000..0b56e16
--- /dev/null
+++ b/README.md
@@ -0,0 +1,2 @@
+# Timur's Tea Shop
+The website of a family tea shop in Tashkent.`}>

```bash
git log --oneline
git show
```

</CodeExample>

How to read it:

- `5150f17` and `6e10c4f` are the start of each commit's **hash**, its unique ID. You can use the short form anywhere Git wants a commit: `git show 6e10c4f` shows the first commit, with all seven files.
- `(HEAD -> main)` marks where you are: the newest commit on the `main` branch.
- `git show` prints the commit's details (author, date, message) and then its changes. Lines starting with `+` were **added**; lines starting with `-` were **removed**. A brand-new file is all `+` lines.

The practice terminal's clock is fixed, so you get exactly these hashes and dates when you run the same commands. On your own computer the date is the real one, and the hashes come out different.

## One more fix

Timur reads his about page and groans: "The best **tee** in Tashkent". It should be **tea**. The page is one line long, so you can fix it by writing the whole line again with `>`. (On your own computer you'd open the file in a code editor such as VS Code and change the word.)

As soon as the file differs from the last commit, `git status` says so:

  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)


`modified` means Git already tracks this file, and it has changed since the last commit. Like a new file, a change goes into a commit only after `git add`.

## What you built

Timur's project is tidy **and** under version control:

- **`git init`** turned the folder into a repository, with its history in the hidden `.git` folder,
- **`git status`** told you what's untracked, staged or modified at every step,
- **`git add`** and **`git commit -m`** saved three commits with clear messages,
- **`echo`** with `>` and `>>` wrote a README and fixed a typo without an editor,
- **`git log --oneline`** and **`git show`** let you read the history and see exactly what each commit changed. The first commit still remembers the old typo, so nothing is ever lost.
