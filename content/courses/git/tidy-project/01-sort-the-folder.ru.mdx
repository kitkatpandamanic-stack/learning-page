Добро пожаловать в ваш первый **итоговый проект по терминалу и Git**! 🧹 Ваш друг **Тимур** делает небольшой сайт для семейного чайного магазина в Ташкенте. Страницы работают, но в папке проекта полный беспорядок: старые копии, скриншоты, заметки и картинки свалены в одну кучу, и Тимур боится что-нибудь удалить — вдруг это нужный файл. Он попросил вас навести порядок.

За две части вы сделаете то, что сделал бы разработчик:

- **Часть 1 (этот урок):** осмотрите папку, спланируете порядок, выбросите мусор и разложите все файлы по местам.
- **Часть 2:** превратите аккуратную папку в Git-репозиторий и сохраните её историю в коммитах.

Всё, что для этого нужно, вы уже знаете из уровня 0:

- **pwd**, **ls** (с `-a`, `-l` и `-F`), **cd** и пути («Знакомство с терминалом»),
- **mkdir**, **cp**, **mv**, **rm**, **tree** и шаблоны вроде `*.txt` («Файлы и папки»),
- **git init**, **add**, **commit** и **log** («Ваш первый репозиторий»).

Папка Тимура называется `timur-site` и лежит в вашей домашней папке. Прежде чем что-то менять, осмотритесь. Зайдите в папку и выведите её содержимое:

Тринадцать имён в одной длинной строке. Учебный терминал печатает вывод `ls` в одну строку, разделяя имена двумя пробелами; терминал на вашем компьютере расставит их по столбцам, часто в цвете, а имя `'style copy.css'` может взять в кавычки из-за пробела.

Но `ls` показывает не всё. Имена, которые начинаются с точки, **скрыты**, и увидеть их помогает `-a`. А `-F` ставит `/` после каждой папки, чтобы папки было легко отличить от файлов:

- **`.DS_Store`** — скрытый файл, который Finder в macOS оставляет в папках, чтобы помнить, как их показывать (где стоят значки, какой выбран вид). К сайту он отношения не имеет.
- **`backup`** — папка, единственная здесь. В ней лежит совсем старая копия главной страницы.

Сайт у Тимура на английском (магазин ждёт и туристов), поэтому и заметки он пишет по-английски: «1. Создать папки css, images, notes. 2. Выбросить старые копии и скриншоты. 3. Разложить файлы по папкам». Хороший план. Вот куда отправится каждый файл:

| Файлы                                               | Что это                         | Куда                |
| --------------------------------------------------- | ------------------------------- | ------------------- |
| `index.html`, `about.html`                          | Две страницы сайта              | Остаются наверху    |
| `style.css`                                         | Оформление страниц              | `css/`              |
| `logo.png`, `tea.jpg`                               | Картинки для страниц            | `images/`           |
| `todo.txt`, `draft.txt`                             | Заметки Тимура                  | `notes/`            |
| `index-old.html`, `style-old.css`, `style copy.css` | Старые копии                    | Удалить             |
| `screenshot-1.png`, `screenshot-2.png`              | Скриншоты старого дизайна       | Удалить             |
| `.DS_Store`, `backup/`                              | Мусор от macOS и старая копия   | Удалить             |

Почему страницы остаются наверху? Когда сайт выкладывают в интернет, веб-сервер ищет `index.html` в верхней папке сайта и показывает его как главную страницу. А картинки и стили могут лежать в любой папке, лишь бы страницы на них правильно ссылались.

## Сначала страховка

У `rm` **нет отмены**: корзины, из которой можно достать файл, тоже нет. Поэтому перед большой уборкой сделайте копию всей папки. `cp -r` копирует папку со всем содержимым, включая скрытые файлы:

```bash
cp -r timur-site timur-site-backup
```

Запускайте её из **домашней папки**, где лежит `timur-site`. Если что-то пойдёт не так, нетронутая копия останется в `~/timur-site-backup`. А в части 2 вы познакомитесь со страховкой гораздо лучше — с Git.

## Выбрасываем мусор

Шаблоны позволяют удалить много файлов одной командой — именно поэтому они и опасны. Полезная привычка: **сначала покажите шаблон через `ls`**, проверьте список, а потом запускайте `rm` с тем же шаблоном. Здесь `*old*` значит «что угодно, потом `old`, потом что угодно»:

<CodeExample setup={`mkdir timur-site
cd timur-site
touch index.html index-old.html about.html style.css style-old.css logo.png tea.jpg screenshot-1.png screenshot-2.png`} output={`index-old.html  style-old.css
screenshot-1.png  screenshot-2.png`}>

```bash
ls *old*
ls screenshot-*
```

</CodeExample>

Каждый шаблон ловит ровно те файлы, которые нужно выбросить, и ничего лишнего. Значит, `ls` можно смело заменить на `rm`.

### Файл с пробелом

Терминал делит команду на слова по каждому пробелу. Поэтому `rm style copy.css` — это не один файл `style copy.css`, а два файла, `style` и `copy.css`, и ни одного из них нет:

<CodeExample setup={`mkdir timur-site
cd timur-site
touch style.css style-old.css "style copy.css"`} output={`rm: cannot remove 'style': No such file or directory
rm: cannot remove 'copy.css': No such file or directory
style-old.css  style.css`}>

```bash
rm style copy.css
rm "style copy.css"
ls style*
```

</CodeExample>

Кавычки удерживают имя целым. (Обратная косая черта перед пробелом тоже работает: `rm style\ copy.css`.) Второй `rm` ничего не напечатал — в терминале это значит, что всё получилось, и `ls` подтверждает: файла больше нет. Когда будете называть свои файлы, ставьте дефисы вместо пробелов, например `style-copy.css`, и кавычки не понадобятся.

С папками нужен ещё один шаг: просто `rm backup` ответит `rm: cannot remove 'backup': Is a directory`. Чтобы удалить папку **со всем содержимым**, нужен `rm -r backup`.

<Callout type="danger" title="Посмотрите, прежде чем удалять">

`rm` удаляет сразу: не спрашивает и не кладёт в корзину. Один лишний пробел превращает `rm *old*` в `rm * old*`, а это удалит **все** файлы в папке. Сначала запустите шаблон с `ls` и перечитайте строку, прежде чем нажать Enter.

</Callout>

## Всё по местам

Теперь переезд. `mv` принимает сколько угодно файлов и кладёт их в папку, названную **последней**, а шаблоны сами подставляют имена файлов. В одной команде можно даже указать два шаблона:

```bash
mv *.png *.jpg images
```

После переезда `tree` рисует всю папку целиком: сразу видно каждый файл и папку, в которой он лежит.

<Callout type="warning" title="Если папки нет">

У `mv` две работы: перемещать файлы в папку и **переименовывать**. Если названной папки не существует, `mv` с одним файлом молча его переименует:

<CodeExample setup={`mkdir images notes
echo "body { font-family: sans-serif; }" > style.css`} output={`css  images/  notes/
images/  notes/  style.css`}>

```bash
mv style.css css
ls -F
mv css style.css
ls -F
```

</CodeExample>

После `css` нет `/`, значит, это файл: `style.css` переименовался в `css`! Второй `mv` возвращает старое имя. Сначала создавайте папки, а после переезда проверяйте через `ls -F` или `tree`.

</Callout>

## Что вы сделали

Вы навели порядок в настоящей на вид папке проекта, используя только терминал:

- **осмотрели** её с помощью `cd`, `pwd`, `ls`, `ls -a` (скрытые файлы) и `ls -F` (у папок появляется `/`),
- прочитали план через **`cat`** и создали новые папки через **`mkdir`**,
- сделали **страховочную копию** с `cp -r`, прежде чем что-то удалять,
- удалили старые копии, скриншоты и мусор через **`rm`** и **шаблоны**, каждый раз сначала проверяя шаблон через `ls`, а имя с пробелом взяли в **кавычки**,
- удалили папку через **`rm -r`**,
- переместили целые виды файлов через **`mv`** с шаблонами и проверили результат через **`tree`**.

Папка в порядке, но защищает её пока только одна застывшая копия. В части 2 вы превратите её в Git-репозиторий, и каждое изменение Тимура будет сохраняться с пояснением, чтобы его всегда можно было найти.
