Welcome to your first **terminal and Git capstone project**! 🧹 Your friend **Timur** is building a small website for his family's tea shop in Tashkent. The pages work, but his project folder is a mess: old copies, screenshots, notes and pictures all lie in one heap, and he's scared to delete anything in case it's the wrong file. He's asked you to sort it out.

Over two parts you'll do the job a developer would do:

- **Part 1 (this lesson):** explore the folder, plan a tidy layout, throw out the rubbish and move every file into its place.
- **Part 2:** turn the tidy folder into a Git repository and save its history in commits.

You already know everything you need from Level 0:

- **pwd**, **ls** (with `-a`, `-l` and `-F`), **cd** and paths (Meet the Terminal),
- **mkdir**, **cp**, **mv**, **rm**, **tree** and wildcards like `*.txt` (Files & Folders),
- **git init**, **add**, **commit** and **log** (Your First Repository).

Thirteen names on one long line. The practice terminal prints `ls` on one line with two spaces between names; a terminal on your own computer arranges them in columns, often with colours, and may put quotes around `'style copy.css'` because of its space.

But `ls` doesn't show everything. Names starting with a dot are **hidden**, and `-a` shows them. `-F` adds a `/` after every folder, so you can tell folders from files:

Two discoveries:

- **`.DS_Store`** is a hidden file that macOS's Finder leaves in folders to remember how it shows them (icon positions, view settings). It has nothing to do with the website.
- **`backup`** is a folder, the only one here. It holds an even older copy of the home page.

That's a good plan. Here is where every file goes:

| Files                                             | What they are                 | Where they go       |
| ------------------------------------------------- | ----------------------------- | ------------------- |
| `index.html`, `about.html`                        | The site's two pages          | Stay at the top     |
| `style.css`                                       | How the pages look            | `css/`              |
| `logo.png`, `tea.jpg`                             | Pictures used on the pages    | `images/`           |
| `todo.txt`, `draft.txt`                           | Timur's notes                 | `notes/`            |
| `index-old.html`, `style-old.css`, `style copy.css` | Old copies                  | Deleted             |
| `screenshot-1.png`, `screenshot-2.png`            | Screenshots of an old design  | Deleted             |
| `.DS_Store`, `backup/`                            | Mac junk and an old backup    | Deleted             |

Why do the pages stay at the top? When a website goes online, the web server looks for `index.html` in the top folder of the site and shows it as the home page. Pictures and styles can live in any folder, as long as the pages point to them.

## A safety net first

`rm` has **no undo**: there's no bin to fish a file out of. So before a big clean-up, make a copy of the whole folder. `cp -r` copies a folder with everything inside it, hidden files too:

```bash
cp -r timur-site timur-site-backup
```

Run it from your **home folder**, where `timur-site` is. If something goes wrong, the untouched copy is in `~/timur-site-backup`. In Part 2 you'll meet a much better safety net: Git.

## Throw out the rubbish

Wildcards let you delete many files with one command, which is exactly why they're dangerous. A good habit: **show the pattern with `ls` first**, check the list, then run `rm` with the same pattern. Here `*old*` means "anything, then `old`, then anything":

<CodeExample setup={`mkdir timur-site
cd timur-site
touch index.html index-old.html about.html style.css style-old.css logo.png tea.jpg screenshot-1.png screenshot-2.png`} output={`index-old.html  style-old.css
screenshot-1.png  screenshot-2.png`}>

```bash
ls *old*
ls screenshot-*
```

</CodeExample>

Each pattern catches exactly the files that should go and nothing else, so it's safe to swap `ls` for `rm`.

### The file with a space

The terminal splits a command into words at every space. So `rm style copy.css` doesn't mean one file called `style copy.css`; it means two files, `style` and `copy.css`, and neither exists:

<CodeExample setup={`mkdir timur-site
cd timur-site
touch style.css style-old.css "style copy.css"`} output={`rm: cannot remove 'style': No such file or directory
rm: cannot remove 'copy.css': No such file or directory
style-old.css  style.css`}>

```bash
rm style copy.css
rm "style copy.css"
ls style*
```

</CodeExample>

Quotes keep the name in one piece. (A backslash before the space works too: `rm style\ copy.css`.) The second `rm` printed nothing, which in the terminal means it worked, and `ls` confirms the file is gone. When you name your own files, use dashes instead of spaces, like `style-copy.css`, and you'll never need the quotes.

Folders need one more thing: plain `rm backup` answers `rm: cannot remove 'backup': Is a directory`. Deleting a folder **and everything in it** needs `rm -r backup`.

<Callout type="danger" title="Look before you rm">

`rm` deletes straight away, without asking and without a bin. One stray space can turn `rm *old*` into `rm * old*`, which deletes **every** file in the folder. Run the pattern with `ls` first, and double-check the line before you press Enter.

</Callout>

## Everything in its place

Now the move. `mv` takes any number of files and puts them into the folder named **last**, and wildcards fill in the file names for you. You can even give two patterns in one command:

```bash
mv *.png *.jpg images
```

After a move, `tree` draws the whole folder at once, so you can see every file and the folder it's in.

<Callout type="warning" title="When the folder doesn't exist">

`mv` has two jobs: it moves files into a folder, and it **renames**. If the folder you name doesn't exist, `mv` with one file quietly renames it instead:

<CodeExample setup={`mkdir images notes
echo "body { font-family: sans-serif; }" > style.css`} output={`css  images/  notes/
images/  notes/  style.css`}>

```bash
mv style.css css
ls -F
mv css style.css
ls -F
```

</CodeExample>

There's no `/` after `css`, so it's a file: `style.css` was renamed to `css`! The second `mv` renames it back. Make the folders first, and check with `ls -F` or `tree` after moving.

</Callout>

## What you built

You tidied a real-looking project folder with nothing but the terminal:

- **explored** it with `cd`, `pwd`, `ls`, `ls -a` (hidden files) and `ls -F` (folders get a `/`),
- read the plan with **`cat`** and made the new folders with **`mkdir`**,
- made a **safety copy** with `cp -r` before deleting anything,
- deleted old copies, screenshots and junk with **`rm`** and **wildcards**, checking each pattern with `ls` first, and used **quotes** for a name with a space,
- deleted a folder with **`rm -r`**,
- moved whole kinds of files at once with **`mv`** and wildcards, and checked the result with **`tree`**.

The folder is tidy, but it's still only protected by one frozen copy. Next, in Part 2, you'll turn it into a Git repository, so every change Timur makes from now on is saved with a note and can be looked up later.
