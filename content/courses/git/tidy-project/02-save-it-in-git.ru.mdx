В папке Тимура порядок! 🎉 В части 1 вы защитили её одной копией, `timur-site-backup`. Копия лучше, чем ничего, но это лишь один застывший момент: она не скажет, **что** изменилось с тех пор, **когда** и **зачем**. А после нескольких уборок появляются `backup`, `backup-2` и `backup-final` — тот самый беспорядок, который вы только что выбросили.

Git делает эту работу как следует. В этой части вы превратите `timur-site` в **репозиторий** (repository), сохраните его в первом **коммите** (commit), добавите ещё два и прочитаете историю проекта, как бортовой журнал.

Папка начинается ровно такой, какой её оставила часть 1:

```text
timur-site
├── about.html
├── css
│   └── style.css
├── images
│   ├── logo.png
│   └── tea.jpg
├── index.html
└── notes
    ├── draft.txt
    └── todo.txt
```

## Превращаем папку в репозиторий

Пока Git ничего не знает об этой папке. Это меняет `git init`: команда создаёт скрытую папку `.git`, где Git будет хранить всю историю.

<CodeExample setup={`mkdir -p timur-site/css timur-site/images timur-site/notes
cd timur-site
echo "<h1>Timur's Tea Shop</h1>" > index.html
echo "<p>Green, black and jasmine tea.</p>" >> index.html
echo "<p>The best tee in Tashkent since 2015.</p>" > about.html
echo "body { font-family: sans-serif; }" > css/style.css
touch images/logo.png images/tea.jpg
echo "1. Make folders: css, images, notes" > notes/todo.txt
echo "2. Throw away old copies and screenshots" >> notes/todo.txt
echo "3. Put every file in its folder" >> notes/todo.txt
echo "About us: a family tea shop" > notes/draft.txt`} output={`fatal: not a git repository (or any of the parent directories): .git
Initialized empty Git repository in /home/panda/timur-site/.git/
.  ..  .git  about.html  css  images  index.html  notes`}>

```bash
git status
git init
ls -a
```

</CodeExample>

- До `git init` команда `git status` выдаёт ошибку: эта папка ещё не репозиторий.
- После неё `ls -a` показывает новую скрытую папку `.git`. `git init` запускают **один раз на проект**, в его верхней папке.

<Callout type="warning" title="Не трогайте .git">

Всё, что сохраняет Git, лежит внутри `.git`. Менять там что-то вручную никогда не нужно, а `rm -r .git` одним махом удалит всю историю проекта. Поэтому папка и скрыта: чтобы её никто случайно не «прибрал».

</Callout>

## Первый коммит

Сохранение идёт в два шага, как вы помните из «Вашего первого репозитория»:

1. **`git add`** кладёт файлы в **индекс** (staging area) — список того, что войдёт в следующий коммит. `git add .` добавляет всё в текущей папке (точка значит «здесь»), включая все вложенные папки.
2. **`git commit -m "сообщение"`** сохраняет всё, что лежит в индексе, одним коммитом с вашим сообщением.

<CodeExample setup={`mkdir -p timur-site/css timur-site/images timur-site/notes
cd timur-site
echo "<h1>Timur's Tea Shop</h1>" > index.html
echo "<p>Green, black and jasmine tea.</p>" >> index.html
echo "<p>The best tee in Tashkent since 2015.</p>" > about.html
echo "body { font-family: sans-serif; }" > css/style.css
touch images/logo.png images/tea.jpg
echo "1. Make folders: css, images, notes" > notes/todo.txt
echo "2. Throw away old copies and screenshots" >> notes/todo.txt
echo "3. Put every file in its folder" >> notes/todo.txt
echo "About us: a family tea shop" > notes/draft.txt
git init`} output={`On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
	new file:   about.html
	new file:   css/style.css
	new file:   images/logo.png
	new file:   images/tea.jpg
	new file:   index.html
	new file:   notes/draft.txt
	new file:   notes/todo.txt`}>

```bash
git add .
git status
```

</CodeExample>

Теперь все семь файлов в индексе, и Git перечисляет их по одному. Хорошее сообщение коммита в нескольких словах говорит, **что делает коммит**. Сайт Тимура на английском, и сообщения коммитов во многих командах тоже пишут по-английски, так что и мы будем: «First version of the tea shop site» (первая версия сайта), «Add a README» (добавить README), «Fix a typo on the about page» (исправить опечатку на странице «О нас»).

<Callout type="note" title="На вашем компьютере">

- Без `-m` команда `git commit` открывает текстовый редактор для сообщения. В учебном терминале редактора нет, поэтому здесь она выводит подсказку: всегда пишите `-m "сообщение"`.
- Учебный терминал уже знает, кто вы (Panda). На своём компьютере вы один раз сообщаете Git имя и почту командами `git config --global user.name` и `git config --global user.email` перед первым коммитом.

</Callout>

## README для гостей

Почти в каждом проекте в верхней папке лежит файл **README** — короткая записка о том, что это за проект. Сайты вроде GitHub показывают его на главной странице проекта. Обычно он называется `README.md`; `.md` означает **Markdown** — простой текстовый формат, в котором строка, начинающаяся с `#`, становится заголовком.

Короткий файл можно написать и без редактора — через `echo` с перенаправлением, как вы делали в «Файлах и папках». Помните разницу:

- `>` **заменяет** содержимое файла (или создаёт новый файл),
- `>>` **дописывает** строку в конец.

Два `>` подряд — классическая ошибка. Вторая строка стирает первую:

<CodeExample setup={`mkdir timur-site
cd timur-site`} output={`The website of a family tea shop in Tashkent.`}>

```bash
echo "# Timur's Tea Shop" > README.md
echo "The website of a family tea shop in Tashkent." > README.md
cat README.md
```

</CodeExample>

Заголовок пропал. Как правильно: `>` для первой строки, `>>` для всех следующих.

## Читаем историю

Два коммита — это уже история, которую стоит почитать. `git log --oneline` выводит по строке на коммит, новые сверху, а `git show` подробно показывает последний коммит:

6e10c4f First version of the tea shop site
commit 5150f17ea0eaab98f729c7343d68ef0244fa24bb (HEAD -> main)

Date:   Mon Jan 5 09:02:00 2026 +0000

diff --git a/README.md b/README.md
new file mode 100644
index 0000000..0b56e16
--- /dev/null
+++ b/README.md

```bash
git log --oneline
git show
```

</CodeExample>

Как это читать:

- `5150f17` и `6e10c4f` — начало **хеша** (hash) каждого коммита, его уникального идентификатора. Короткую форму можно указывать везде, где Git ждёт коммит: `git show 6e10c4f` покажет первый коммит со всеми семью файлами.
- `(HEAD -> main)` отмечает, где вы сейчас: на последнем коммите ветки `main`.
- `git show` печатает данные коммита (автор, дата, сообщение), а потом его изменения. Строки с `+` **добавлены**, строки с `-` **удалены**. Совершенно новый файл состоит из одних строк с `+`.

Часы учебного терминала зафиксированы, поэтому при тех же командах у вас получатся ровно такие же хеши и даты. На вашем компьютере дата будет настоящей, и хеши выйдут другими.

## Ещё одно исправление

Тимур перечитывает страницу «О нас» и хватается за голову: «The best **tee** in Tashkent». Должно быть **tea** — «чай» (а tee — это подставка для мяча в гольфе). Страница занимает одну строку, так что исправить её можно, переписав строку целиком через `>`. (На своём компьютере вы бы открыли файл в редакторе кода, например в VS Code, и поменяли слово.)

Как только файл отличается от последнего коммита, `git status` сообщает об этом:

## Что вы сделали

Проект Тимура теперь и в порядке, **и** под контролем версий:
