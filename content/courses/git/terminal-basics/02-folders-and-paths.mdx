In a file manager you find a file by clicking from folder to folder. In the terminal there's nothing to click, so you need two skills instead: knowing **where you are**, and telling the shell **where to go**. That's what this lesson is about. 🗺️

## The folder tree

Your files live in **folders** (also called **directories**), and folders can hold other folders. Together they form a **tree**. The `tree` command draws one. This is the home folder used in this lesson's examples:

<CodeExample setup={`mkdir -p projects/website/css photos/2025 notes
touch projects/website/index.html projects/website/css/style.css photos/2025/beach.jpg photos/2025/panda.jpg notes/ideas.txt notes/shopping.txt todo.txt`} output={`.
├── notes
│   ├── ideas.txt
│   └── shopping.txt
├── photos
│   └── 2025
│       ├── beach.jpg
│       └── panda.jpg
├── projects
│   └── website
│       ├── css
│       │   └── style.css
│       └── index.html
└── todo.txt

6 directories, 7 files`}>

```bash
tree
```

</CodeExample>

- `.` at the top is the folder you're in: here, your home folder.
- `notes`, `photos` and `projects` are folders inside it, and `todo.txt` is a file.
- Folders nest: `style.css` is in `css`, which is in `website`, which is in `projects`.

The whole computer is one big tree. Its top is called the **root** and is written as a single slash, `/`. Your home folder is a few levels down: `/home/panda`.

<Callout type="note" title="tree on your computer">

`tree` isn't always installed on a real computer. If you get `command not found`, that's why. `ls` and `cd` are everywhere.

</Callout>

## Where am I?

The prompt shows where you are in short form, and `pwd` prints the full **path**: the list of folders from the root down to you, separated by `/`.

<CodeExample output={`/home/panda`}>

```bash
pwd
```

</CodeExample>

Read `/home/panda` as "start at the root `/`, go into `home`, then into `panda`". Your **home folder** is so common that it has a nickname: **`~`**. Whenever you see `~`, read it as `/home/panda`.

On your own computer the home folder has a different path, like `/Users/panda` on a Mac or `/c/Users/Panda` in Git Bash on Windows. `~` always means "my home folder", whatever its real path is.

## Looking inside a folder

`ls` on its own lists the folder you're in. Give it a folder's name, and it lists **that** folder instead, without you moving anywhere:

<CodeExample setup={`mkdir -p projects/website/css photos/2025 notes
touch projects/website/index.html projects/website/css/style.css photos/2025/beach.jpg photos/2025/panda.jpg notes/ideas.txt notes/shopping.txt todo.txt`} output={`notes  photos  projects  todo.txt
2025
beach.jpg  panda.jpg`}>

```bash
ls
ls photos
ls photos/2025
```

</CodeExample>

`photos/2025` means "the `2025` folder inside `photos`". The `/` between names is how you go one level deeper.

## Moving around with cd

**`cd`** ("change directory") takes you into another folder. It prints nothing when it works, but the prompt changes to show where you are now:

<CodeExample setup={`mkdir -p projects/website/css photos/2025 notes
touch projects/website/index.html projects/website/css/style.css photos/2025/beach.jpg photos/2025/panda.jpg notes/ideas.txt notes/shopping.txt todo.txt`} output={`/home/panda/projects
website
/home/panda/projects/website/css`}>

```bash
cd projects
pwd
ls
cd website/css
pwd
```

</CodeExample>

In the practice terminal you'd see the prompt go from `~ $` to `~/projects $` and then to `~/projects/website/css $`. You can go several levels at once, like `cd website/css`.

## Absolute and relative paths

There are two ways to write a path:

- An **absolute path** starts at the root, with `/`, like `/home/panda/photos/2025`. It works **from anywhere**, like a full street address. A path starting with `~` works from anywhere too, because `~` stands for `/home/panda`.
- A **relative path** starts from **where you are**, like `photos/2025`. It's like saying "the second door on the left": it only makes sense from the right spot.

So from your home folder, these three commands all go to the same place:

```bash
cd /home/panda/photos/2025
cd ~/photos/2025
cd photos/2025
```

But only the first two would still work if you were in `projects`. From there, `photos/2025` means `/home/panda/projects/photos/2025`, which doesn't exist.

## Going up with ..

Two special names exist in every folder:

- **`..`** (two dots) is the folder **one level up**, the one that holds this folder.
- **`.`** (one dot) is **this folder** itself. You'll use it later, for example in `git add .`.

Each `..` climbs one level, and you can chain them with `/`:

<CodeExample setup={`mkdir -p projects/website/css photos/2025 notes
touch projects/website/index.html projects/website/css/style.css photos/2025/beach.jpg photos/2025/panda.jpg notes/ideas.txt notes/shopping.txt todo.txt
cd projects/website/css`} output={`/home/panda/projects/website
/home/panda
beach.jpg  panda.jpg`}>

```bash
cd ..
pwd
cd ../..
pwd
ls photos/2025
```

</CodeExample>

This example starts in `~/projects/website/css`. One `..` goes up to `website`; then `../..` goes up two more, through `projects` to `panda`. You can mix `..` with folder names too: from `css`, `cd ../../../notes` goes up three levels and then into `notes`.

## Shortcuts home and back

- **`cd`** with nothing after it takes you straight **home**, from anywhere. So does `cd ~`.
- **`cd -`** takes you **back** to the folder you were in before, and prints its path.

<CodeExample setup={`mkdir -p projects/website/css photos/2025 notes
touch projects/website/index.html projects/website/css/style.css photos/2025/beach.jpg photos/2025/panda.jpg notes/ideas.txt notes/shopping.txt todo.txt`} output={`/home/panda
/home/panda/photos/2025`}>

```bash
cd photos/2025
cd
pwd
cd -
```

</CodeExample>

<Callout type="tip" title="On your computer: let Tab type for you">

In a real terminal, type the start of a name, like `cd pho`, and press **Tab**. The shell finishes the name for you. It's faster and prevents typos. (The practice terminal doesn't have Tab completion.)

</Callout>

## When cd goes wrong

Two messages come up all the time. Read them: they tell you exactly what's wrong.

<CodeExample setup={`mkdir -p projects/website/css photos/2025 notes
touch projects/website/index.html projects/website/css/style.css photos/2025/beach.jpg photos/2025/panda.jpg notes/ideas.txt notes/shopping.txt todo.txt`} output={`bash: cd: photo: No such file or directory
bash: cd: todo.txt: Not a directory`}>

```bash
cd photo
cd todo.txt
```

</CodeExample>

- **`No such file or directory`**: there's nothing with that name **here**. Check the spelling (`photo` vs `photos`) and where you are (`pwd`, `ls`). A relative path from the wrong folder is the most common cause.
- **`Not a directory`**: the name exists, but it's a file. You can only `cd` into folders.

<Callout type="warning" title="Common mistakes">

- A relative path from the wrong place. When in doubt, run `pwd` first.
- Writing `cd..` without a space. Bash needs `cd ..` (some other shells forgive it).
- Names with spaces: `cd My Photos` is two arguments. Write `cd "My Photos"` with quotes.
- Starting a relative path with `/` by habit: `/photos` means a `photos` folder at the very root of the computer.

</Callout>

## Recap

- Folders (directories) form a **tree**. Its top is the root `/`, and your **home folder** is `~` (`/home/panda` here).
- `pwd` prints where you are; `ls folder` lists a folder without moving; `cd folder` moves you into it.
- An **absolute path** starts with `/` (or `~`) and works from anywhere. A **relative path** starts from where you are.
- `..` is the folder one level up, `.` is this folder. Chain them: `cd ../..`.
- `cd` alone goes home, and `cd -` goes back to where you were.
- `No such file or directory`: check the spelling and where you are. `Not a directory`: it's a file.
