Welcome to Git & Terminal! 🐼 Most of the time you use a computer by clicking: you open folders, drag files and press buttons. Developers have a second way that is often faster: they **type** what they want, in a window called the **terminal**. Git, the tool every developer uses to save versions of their work, lives there too. By the end of this lesson you'll have typed your first commands, and you don't need any experience to get there.

## Terminal and shell

Two words come up all the time, and they mean slightly different things:

- The **terminal** is the window you type into. It shows your text and the computer's answers. It's sometimes called the **command line** or the **console**.
- The **shell** is the program running inside that window. It reads what you type, runs it and shows you the result. The most common shell is **bash**. Macs use **zsh** by default, which works almost the same way.

Think of the terminal as a chat window and the shell as the one you're chatting with. You type a **command** (an instruction), press Enter, and the shell answers with its **output** (what the command prints). In everyday talk people mix the two words up, and that's fine.

## The prompt

When the shell is ready for a command, it shows a **prompt**. In this course's practice terminal the prompt looks like this:

```text
~ $
```

- **`~`** (a tilde) says **where you are**. `~` is short for your **home folder**, the folder that belongs to you. You'll learn all about folders in the next lesson.
- **`$`** marks the end of the prompt. Whatever you type comes after it.

On your own computer the prompt shows more, for example `panda@laptop:~$` on Linux or `panda@MacBook ~ %` on a Mac (zsh ends with `%`). It's the same idea: who you are, where you are, and "I'm ready".

<Callout type="warning" title="Don't type the prompt">

When a guide shows `~ $ pwd`, you type only `pwd`. The `~ $` part is the shell's, not yours.

</Callout>

## Your first commands

**`echo`** prints back whatever you give it. The quotes hold the text together:

<CodeExample output={`Hello, terminal`}>

```bash
echo "Hello, terminal"
```

</CodeExample>

**`pwd`** means "print working directory". A **directory** is another word for a folder, so `pwd` tells you **which folder you're in** right now:

<CodeExample output={`/home/panda`}>

```bash
pwd
```

</CodeExample>

`/home/panda` is the full name of your home folder, the same place the prompt calls `~`. The practice terminal's user is called **panda**, which you can check with **`whoami`** ("who am I?"):

<CodeExample output={`panda`}>

```bash
whoami
```

</CodeExample>

**`ls`** ("list") shows what's in the folder you're in. Here the home folder holds two folders, `notes` and `photos`, and a file called `todo.txt`:

<CodeExample setup={`mkdir notes photos
touch todo.txt`} output={`notes  photos  todo.txt`}>

```bash
ls
```

</CodeExample>

The practice terminal prints the names on one line, in alphabetical order, with two spaces between them. A real terminal may lay them out in columns and colour folders differently from files. The names are the same.

<Callout type="note" title="Commands are short words">

Commands are usually short English words or abbreviations: `ls` for list, `pwd` for print working directory, `cd` for change directory. They're written in lower case, and they must be spelt exactly.

</Callout>

## How the practice terminal works

The examples in this lesson show commands with their **output** underneath. Terminal boxes with a **Run** button, like the one below and the exercises, are a real little shell running in your browser. You can't break anything on your computer with it.

- Write **one command per line**. Lines starting with `#` are **comments**: notes for humans that the shell skips.
- Press **Run** (or **Ctrl/⌘ + Enter**). The commands run from top to bottom.
- Each command is shown after a prompt like `~ $ pwd`, followed by its output, so you can see which answer belongs to which command.
- **Every run starts fresh**, in the same starting folder. If something goes wrong, just change your commands and run again.
- Lost? Type **`help`** to see every command this terminal knows.

Try it now: change the text after `echo`, add your own commands and press **Run**:

whoami
`} />

## Errors are normal

If the shell doesn't know a word, it says so. Here `hello` isn't a command, and `pdw` is a typo for `pwd`:

<CodeExample output={`bash: hello: command not found
bash: pdw: command not found`}>

```bash
hello
pdw
```

</CodeExample>

**`command not found`** means "I don't know a program with that name". It's the most common message in any terminal. Check the spelling, fix it and run again. Every developer sees it many times a day, and nothing bad happens. 💪

<Callout type="warning" title="Common first mistakes">

- Typing the prompt: `$ pwd` instead of `pwd`.
- Typos: `pdw`, `sl`, `ehco`.
- Forgetting a space: `echoHello` is one unknown word, `echo Hello` is a command and its text.

</Callout>

## Recap

- The **terminal** is the window you type into; the **shell** (bash, zsh) is the program that reads and runs your commands.
- The **prompt** (`~ $` here) means the shell is ready. `~` is your **home folder**. Don't type the prompt yourself.
- `echo` prints text, `pwd` shows the folder you're in, `whoami` shows your user name and `ls` lists a folder.
- In the practice terminal you write one command per line and press **Run** (Ctrl/⌘ + Enter). Every run starts fresh, and `help` lists every command.
- `command not found` means a typo or an unknown command. Fix it and run again.
