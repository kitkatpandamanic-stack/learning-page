The practice terminal is perfect for learning: nothing to install and nothing to break. But your real projects will live on your own computer, so sooner or later you'll want a terminal and Git there too. This lesson shows you how to get both, and how to **introduce yourself to Git**, which is the first thing everyone does after installing it. 💻

<Callout type="tip" title="Steps you do on your own computer">

Sections marked **On your computer** happen in a real terminal, not on this page. You can do them now, or skip them and come back later: the whole course works in the browser. The exercise at the end runs in the practice terminal as usual.

</Callout>

## On your computer: open a terminal

**macOS.** Open the **Terminal** app: press **⌘ + Space**, type `Terminal` and press Enter (it also lives in Applications → Utilities). The shell is **zsh**, and the prompt ends with `%`, like `panda@MacBook ~ %`. Every command in this course works there the same way.

**Windows.** Windows' own shells (Command Prompt and PowerShell) use different commands. For this course, use **Git Bash**: it's bash, with the same commands as the practice terminal, and it comes with Git for Windows (see the next section). After installing, open **Git Bash** from the Start menu. Its prompt shows your name, `MINGW64` and a path, then a `$` on the next line.

There's also **WSL** (Windows Subsystem for Linux), which runs a full Linux inside Windows. You open it in the **Windows Terminal** app. It's great for professional work later, but Git Bash is simpler to start with.

**Linux.** Open the **Terminal** app from your applications menu. On Ubuntu and many other systems, **Ctrl + Alt + T** opens one. The shell is usually bash.

## On your computer: install Git

First check whether Git is already there. Type this and press Enter:

```bash
git --version
```

If it prints a version number, you can skip to the next section. If it says `command not found`, install Git:

**macOS.** The easiest way is Apple's Command Line Tools, which include Git. Running `git --version` often offers to install them for you; if it doesn't, run:

```bash
xcode-select --install
```

If you use the Homebrew package manager, `brew install git` works too and gives you a newer Git.

**Windows.** Go to [git-scm.com](https://git-scm.com), download **Git for Windows** and run the installer. The default choices are fine. This also installs **Git Bash**.

**Linux.** Use your system's package manager. On Ubuntu or Debian:

```bash
sudo apt install git
```

On Fedora, run `sudo dnf install git`. **`sudo`** runs a command as the computer's administrator, so it asks for your password. Nothing appears on the screen while you type it, not even dots. That's normal: type it and press Enter.

## Check that Git works

Close the terminal, open a new one and run `git --version` again. In the practice terminal it looks like this:

<CodeExample output={`git version 2.47.1`}>

```bash
git --version
```

</CodeExample>

Your number will probably be different. Any recent version is fine for this course.

## Tell Git who you are

Git saves every version of your project as a **commit**, and every commit records **who made it**: a name and an email. That's how a team can see who changed what, and you'll see these names in the history in a few lessons. So before your first commit, tell Git yours with **`git config`**:

<CodeExample output={`Mei Lin
user.name=Mei Lin
user.email=mei@example.com`}>

```bash
git config --global user.name "Mei Lin"
git config --global user.email "mei@example.com"
git config --global user.name
git config --list
```

</CodeExample>

- `git config --global user.name "Mei Lin"` saves your **name**. The quotes keep the two words together. Like `cd`, it prints nothing when it works.
- `git config --global user.email "mei@example.com"` saves your **email**.
- **`--global`** means "for me, in **every** project on this computer". You only do this once per computer.
- `git config --global user.name`, without a value, **reads** the setting back.
- **`git config --list`** shows all your settings, one `key=value` per line.

On your own computer `git config --list` shows more lines than this: Git keeps other settings too, and the installer may add some. If the list is longer than the screen and you see a `:` at the bottom, press **q** to get back.

<Callout type="note" title="Which email?">

Use the email you'll use for GitHub or your team later, so your commits are linked to you. If you'd rather keep your email private, GitHub can give you a private "noreply" address to use here instead. Git never checks the email or sends anything to it: it's just written into your commits.

</Callout>

### A common mistake: forgetting the quotes

Without quotes, a name with a space is cut short. Here Git takes `Mei` as the name, and `Lin` gets lost:

<CodeExample output={`Mei`}>

```bash
git config --global user.name Mei Lin
git config --global user.name
```

</CodeExample>

If that happens, just run the command again with quotes: the new value replaces the old one.

In the practice terminal, settings last for one run only, like everything else. Later lessons commit as a ready-made user called **Panda**, so you won't have to set your name every time. On your own computer, `--global` settings stay until you change them.

## Recap

- **On your computer**: Terminal on macOS (zsh), **Git Bash** on Windows (installed with Git for Windows), the Terminal app on Linux (Ctrl + Alt + T on Ubuntu).
- Install Git with `xcode-select --install` or `brew install git` (macOS), the installer from git-scm.com (Windows) or `sudo apt install git` / `sudo dnf install git` (Linux). Check it with `git --version`.
- Every commit records who made it, so set `git config --global user.name "Your Name"` and `git config --global user.email "you@example.com"` once per computer.
- `--global` means every project on this computer. `git config --global user.name` reads a setting back; `git config --list` shows them all.
- Quote values with spaces, or Git keeps only the first word.
