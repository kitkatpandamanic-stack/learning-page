So far each command did one thing. Most commands can do much more if you ask: show hidden files, add details, work on another folder. You ask with **options**. In this lesson you'll learn how every command is built, how to find out what a command can do, and how to read the shell's error messages. 🧠

## The parts of a command

A command line is a few words separated by **spaces**:

```bash
ls -l photos
```

- **`ls`** is the **command**: the program to run. It always comes first.
- **`-l`** is an **option** (also called a **flag**). It changes **how** the command works, here "show details". Options start with a dash.
- **`photos`** is an **argument**: **what** the command works on, here the folder to list.

You've already used arguments: in `cd projects` and `echo "Hello"`, the words after the command are arguments. Usually the order is command, then options, then arguments. The spaces matter: `ls-l` is one unknown word, but `ls -l` is a command and an option.

Options come in two styles:

- **Short options**: one dash and one letter, like `-a` or `-l`.
- **Long options**: two dashes and a whole word, like `--all` or `--help`. Easier to read, longer to type.

## Hidden files with ls -a

Names that start with a dot, like `.secret` or `.config`, are **hidden**: `ls` leaves them out so they don't clutter your listing. Programs keep their settings in files like these. Git does too: its whole history lives in a hidden `.git` folder, as you'll see later in the course.

The **`-a`** option ("all") shows hidden names too. In this example the home folder holds `notes.txt`, a `photos` folder, a hidden `.secret` file and a hidden `.config` folder:

<CodeExample setup={`mkdir -p .config photos
echo "Buy bamboo" > notes.txt
echo "The cake is in the fridge" > .secret
touch photos/beach.jpg`} output={`notes.txt  photos
.  ..  .config  .secret  notes.txt  photos`}>

```bash
ls
ls -a
```

</CodeExample>

`ls -a` also shows `.` and `..`, the "this folder" and "one level up" names from the last lesson. `--all` is the long form of `-a`, so `ls --all` prints the same. On some computers the hidden names are sorted in among the others instead of first; the names are the same.

## Details with ls -l

The **`-l`** option ("long") shows one line per name, with details:

<CodeExample setup={`mkdir -p .config photos
echo "Buy bamboo" > notes.txt
echo "The cake is in the fridge" > .secret
touch photos/beach.jpg`} output={`total 8
-rw-r--r-- 1 panda panda   11 Jan  5 09:00 notes.txt
drwxr-xr-x 2 panda panda 4096 Jan  5 09:00 photos`}>

```bash
ls -l
```

</CodeExample>

Take the `notes.txt` line from left to right:

| Part         | Means                                                                                         |
| ------------ | --------------------------------------------------------------------------------------------- |
| `-rw-r--r--` | The first letter is the type: `-` for a file, `d` for a directory. The rest are permissions.  |
| `1`          | The number of links to it. You can ignore this one.                                           |
| `panda`      | The **owner**: the user it belongs to.                                                        |
| `panda`      | The **group** it belongs to.                                                                  |
| `11`         | The **size** in bytes. `Buy bamboo` is 10 letters and spaces plus an invisible line break.    |
| `Jan  5 09:00` | When it was last changed.                                                                   |
| `notes.txt`  | The name.                                                                                     |

The `total` line at the top is the disk space used, which you can ignore too. Permissions (who may read, change or run a file) come later in the course. On your own computer the numbers and dates will differ, but the columns are the same.

## Combining options

You can give several options at once, and short ones can be squeezed together behind one dash. These all do the same thing:

```bash
ls -l -a
ls -la
ls -al
```

Options and arguments work together, too. `ls -la photos` shows the details of everything in `photos`, hidden files included:

<CodeExample setup={`mkdir -p .config photos
echo "Buy bamboo" > notes.txt
echo "The cake is in the fridge" > .secret
touch photos/beach.jpg`} output={`total 8
drwxr-xr-x 2 panda panda 4096 Jan  5 09:00 .
drwxr-xr-x 4 panda panda 4096 Jan  5 09:00 ..
-rw-r--r-- 1 panda panda    0 Jan  5 09:00 beach.jpg`}>

```bash
ls -la photos
```

</CodeExample>

`beach.jpg` is 0 bytes because it's an empty practice file.

## Getting help

Nobody remembers every option. Developers look them up all the time, and so should you:

- **`ls --help`**: most commands print a short guide to their options when you add `--help`.
- **`help`**: in the practice terminal, lists every command it knows, with its main options.
- **`git help`**: lists the Git commands.

<CodeExample output={`Usage: ls [-a] [-A] [-l] [-F] [path] list a folder (-a: hidden files too, -l: details)`}>

```bash
ls --help
```

</CodeExample>

<Callout type="note" title="On your computer">

On Linux and in Git Bash, `ls --help` prints a long page of options. On a Mac, `ls` doesn't know `--help`; use **`man ls`** instead, which opens the full manual (press **q** to quit). In real bash, `help` lists only the shell's own built-in commands, like `cd`, not every program.

</Callout>

## history: what did I run?

**`history`** lists the commands you've run, numbered. In the practice terminal that's the commands of this run:

<CodeExample output={`/home/panda
panda
    1  pwd
    2  whoami
    3  history`}>

```bash
pwd
whoami
history
```

</CodeExample>

On your own computer, the history is kept between sessions. Press the **Up arrow** to bring back the last command, edit it and press Enter: no need to type it all again.

## Reading error messages

When something goes wrong, the message usually has three parts: **who** is complaining, **what** went wrong, and sometimes **what to try**.

<CodeExample setup={`mkdir -p .config photos
echo "Buy bamboo" > notes.txt
echo "The cake is in the fridge" > .secret
touch photos/beach.jpg`} output={`ls: cannot access 'photo': No such file or directory
ls: invalid option -- 'z'
Try 'ls --help' for more information.`}>

```bash
ls photo
ls -z
```

</CodeExample>

- `ls:` at the start says it's `ls` complaining, not the shell.
- **`No such file or directory`**: there's no `photo` here. The **argument** is wrong (it's `photos`).
- **`invalid option -- 'z'`**: `ls` has no `-z` option. The **option** is wrong, and the next line tells you where to look: `ls --help`.

So the message tells you which part of your command to fix. Read it slowly before you change anything.

<Callout type="warning" title="Common mistakes">

- No space between the parts: `ls-a` or `ls -lphotos`.
- A space inside an option: `ls - a`. The dash and the letter belong together.
- One dash for a long option: `-all` means `-a -l -l`, not `--all`.
- Guessing an option instead of checking `--help` or `man`.

</Callout>

## Recap

- A command line is the **command**, then **options** (flags, starting with `-` or `--`) that change how it works, then **arguments**: what it works on. Spaces separate the parts.
- `ls -a` shows hidden names (they start with a dot), and `ls -l` shows details: type and permissions, owner, size, date, name.
- Short options combine: `ls -la` is `ls -l -a`.
- `--help`, `help` and (on your computer) `man` tell you what a command can do. `history` lists what you've run.
- Error messages say who complains and what's wrong: `No such file or directory` is about a name, `invalid option` is about an option.
