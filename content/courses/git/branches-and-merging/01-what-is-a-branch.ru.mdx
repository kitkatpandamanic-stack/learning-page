Панда хранит меню кафе в Git-репозитории. Теперь Панда хочет попробовать страницу с десертами, но меню на `main` работает, и недоделанная идея не должна ему мешать. Скопировать всю папку в `cafe-desserts-test`? Вы знаете, чем это кончается: `backup`, `backup-2`, `backup-final`. 🌱

У Git есть ответ получше — **ветка** (branch). Ветка позволяет работать над идеей в отдельной линии истории, а `main` тем временем остаётся ровно таким, каким был. Если идея удалась, вы возвращаете её в `main` (это тема следующего урока). Если нет — просто выбрасываете ветку. В этом уроке вы будете создавать ветки, переходить между ними и смотреть, что при этом происходит с файлами.

## Репозиторий для примеров

Примеры этого урока начинаются внутри `cafe` — репозитория с двумя коммитами на `main`:

```bash
echo "Зелёный чай" > menu.txt
git add menu.txt
git commit -m "Начать меню"

echo "Открыто с 9 до 17" > hours.txt
git add hours.txt
git commit -m "Добавить часы работы"
```

## Ветка — это метка на коммите

Всё это время вы уже были на ветке — на `main`. Каждый `git status` начинается с `On branch main`.

**Ветка** — это просто **имя, которое указывает на коммит**, что-то вроде наклейки. `main` указывает на ваш последний коммит, `Добавить часы работы`. Когда вы делаете коммит, Git создаёт его и переклеивает метку на новый коммит. Вот и всё, что такое ветка: чтобы её создать, Git не копирует ни одного файла. Поэтому ветка появляется мгновенно, даже в огромном проекте.

Вот репозиторий `cafe` в виде картинки. Блок **«Коммиты»** вы видели на уровне 0: по точке на коммит, новые сверху.

## HEAD: где вы сейчас

В репозитории может быть много веток, но вы всегда находитесь на одной из них. **`HEAD`** — это то, как Git запоминает, на какой: он указывает на текущую ветку. Именно это значит `(HEAD -> main)` в `git log`: «HEAD указывает на main, а main указывает на этот коммит».

Когда вы делаете коммит, сдвигается та ветка, на которую указывает HEAD. Остальные ветки стоят на месте.

## Список веток: git branch

**`git branch`** без аргументов выводит список веток. Звёздочка отмечает ту, на которой вы сейчас:

<CodeExample setup={`mkdir cafe
cd cafe
git init
echo "Зелёный чай" > menu.txt
git add menu.txt
git commit -m "Начать меню"
echo "Открыто с 9 до 17" > hours.txt
git add hours.txt
git commit -m "Добавить часы работы"`} output={`* main
* main bfa1c10 Добавить часы работы`}>

```bash
git branch
git branch -v
```

</CodeExample>

**`git branch -v`** (verbose, «подробно») добавляет коммит, на который указывает каждая ветка: его короткий хеш и сообщение.

## Создаём ветку: git branch имя

**`git branch`** с именем создаёт новую ветку, которая указывает на коммит, где вы сейчас:

<CodeExample setup={`mkdir cafe
cd cafe
git init
echo "Зелёный чай" > menu.txt
git add menu.txt
git commit -m "Начать меню"
echo "Открыто с 9 до 17" > hours.txt
git add hours.txt
git commit -m "Добавить часы работы"`} output={`  desserts
* main
bfa1c10 (HEAD -> main, desserts) Добавить часы работы
f1707e2 Начать меню`}>

```bash
git branch desserts
git branch
git log --oneline
```

</CodeExample>

- `git branch desserts` ничего не выводит. Тишина значит, что всё получилось.
- Теперь на одном коммите две метки: `main` и `desserts`. Ни один файл не скопирован, ни один коммит не создан.
- Звёздочка по-прежнему у `main`. **Создание ветки не переводит вас на неё.** Это самая частая ошибка с ветками: создали ветку, сделали коммит — а он попал в `main`.

<GitGraph setup={`mkdir cafe
cd cafe
git init
echo "Зелёный чай" > menu.txt
git add menu.txt
git commit -m "Начать меню"
echo "Открыто с 9 до 17" > hours.txt
git add hours.txt
git commit -m "Добавить часы работы"
git branch desserts`} caption="Две метки на одном коммите. HEAD всё ещё на main." />

В именах веток не бывает пробелов. Берите короткие имена через дефис: `desserts`, `fix-typo`, `new-logo`.

## Переключаемся: git switch

**`git switch`** с именем ветки переводит вас на эту ветку:

<CodeExample setup={`mkdir cafe
cd cafe
git init
echo "Зелёный чай" > menu.txt
git add menu.txt
git commit -m "Начать меню"
echo "Открыто с 9 до 17" > hours.txt
git add hours.txt
git commit -m "Добавить часы работы"
git branch desserts`} output={`Switched to branch 'desserts'
* desserts
  main
bfa1c10 (HEAD -> desserts, main) Добавить часы работы
f1707e2 Начать меню`}>

```bash
git switch desserts
git branch
git log --oneline
```

</CodeExample>

Звёздочка переехала, а в log теперь написано `HEAD -> desserts`: следующий коммит попадёт в `desserts`.

## Коммитим на ветке

Добавим торт на ветке `desserts`. Команды всё те же, знакомые:

## Что происходит с файлами при переключении

А вот что в первый раз удивляет всех. Следите за `cake.txt`:

<CodeExample setup={`mkdir cafe
cd cafe
git init
echo "Зелёный чай" > menu.txt
git add menu.txt
git commit -m "Начать меню"
echo "Открыто с 9 до 17" > hours.txt
git add hours.txt
git commit -m "Добавить часы работы"
git branch desserts
git switch desserts
echo "Шоколадный торт" > cake.txt
git add cake.txt
git commit -m "Добавить шоколадный торт"`} output={`cake.txt  hours.txt  menu.txt
Switched to branch 'main'
hours.txt  menu.txt
c5e7ee1 (desserts) Добавить шоколадный торт
bfa1c10 (HEAD -> main) Добавить часы работы
f1707e2 Начать меню`}>

```bash
ls
git switch main
ls
git log --oneline --all
```

</CodeExample>

- На `main` файла `cake.txt` в папке нет! Так и должно быть: у `main` торта пока нет. **При переключении Git делает папку такой, как в последнем коммите этой ветки.**
- Ничего не потеряно. Торт надёжно хранится в коммите `desserts`, и `git switch desserts` тут же вернёт `cake.txt`.
- Обычный `git log` показывает только историю того места, где вы находитесь, так что на `main` коммита с тортом в нём вообще не видно. **`git log --all`** показывает коммиты **всех** веток, каждый со своими метками.

Теперь допустим, что Панда сделала коммит и на `main`, пока десерты ещё в работе: в меню появился чёрный чай. Обе ветки ушли вперёд от одного и того же коммита, и картинка показывает их рядом, каждую на своей **дорожке**:

## Сокращения: git switch -c и git switch -

Создавать ветку и сразу переключаться на неё вы будете так часто, что для этого есть сокращение. **`git switch -c имя`** (create, «создать») делает и то и другое за раз. А **`git switch -`** возвращает на ветку, где вы были до этого, — так же, как `cd -` для папок:

<CodeExample setup={`mkdir cafe
cd cafe
git init
echo "Зелёный чай" > menu.txt
git add menu.txt
git commit -m "Начать меню"
echo "Открыто с 9 до 17" > hours.txt
git add hours.txt
git commit -m "Добавить часы работы"`} output={`Switched to a new branch 'drinks'
Switched to branch 'main'
Switched to branch 'drinks'`}>

```bash
git switch -c drinks
git switch -
git switch -
```

</CodeExample>

Дальше в курсе ветки обычно начинаются с `git switch -c`.

<Callout type="tip" title="Начали работу на main по ошибке?">

Так бывает: вы начали менять файлы и только потом поняли, что им место на отдельной ветке. Если коммита ещё не было, выполните `git switch -c новая-ветка`. Незакоммиченные изменения переедут вместе с вами на новую ветку, и закоммитите вы их уже там. `main` останется прежним.

</Callout>

## По-старому: git checkout

`git switch` появился в Git 2.23, в 2019 году. До этого все переключали ветки командой **`git checkout`**, и вы ещё встретите её в старых руководствах и в командах коллег:

| Старая команда           | Новая команда          |
| ------------------------ | ---------------------- |
| `git checkout desserts`  | `git switch desserts`  |
| `git checkout -b drinks` | `git switch -c drinks` |
| `git checkout -`         | `git switch -`         |

Работают обе — и здесь, и на вашем компьютере. `git switch` добавили потому, что `git checkout` делает сразу несколько разных дел (например, умеет и затереть файл старой версией), а команду, которая только переключает ветки, труднее применить не так. Документация Git называла `git switch` «экспериментальной» вплоть до Git 2.51 (2025), но сейчас это рекомендуемый способ.

## Переименование и удаление веток

Опечатка в имени? **`git branch -m старое новое`** (move, «переместить») переименовывает ветку. Её коммиты остаются ровно там, где были, — меняется только метка. Если вы стоите на ветке, которую хотите переименовать, хватит `git branch -m новое`.

**`git branch -d имя`** удаляет ветку, то есть её метку:

<CodeExample setup={`mkdir cafe
cd cafe
git init
echo "Зелёный чай" > menu.txt
git add menu.txt
git commit -m "Начать меню"
echo "Открыто с 9 до 17" > hours.txt
git add hours.txt
git commit -m "Добавить часы работы"
git branch desert`} output={`  desserts
* main
Deleted branch desserts (was bfa1c10).`}>

```bash
git branch -m desert desserts
git branch
git branch -d desserts
```

</CodeExample>

Эту ветку можно было спокойно удалить: она указывала на коммит, который есть и у `main`. А если у ветки есть коммиты, которых нет больше ни на одной ветке? Здесь на `snacks` есть коммит, которого нет у `main`:

<CodeExample setup={`mkdir cafe
cd cafe
git init
echo "Зелёный чай" > menu.txt
git add menu.txt
git commit -m "Начать меню"
echo "Открыто с 9 до 17" > hours.txt
git add hours.txt
git commit -m "Добавить часы работы"
git switch -c snacks
echo "Чипсы" > snacks.txt
git add snacks.txt
git commit -m "Добавить чипсы"
git switch main`} output={`error: the branch 'snacks' is not fully merged
hint: If you are sure you want to delete it, run 'git branch -D snacks'
hint: Disable this message with "git config set advice.forceDeleteBranch false"
Deleted branch snacks (was eb6f12b).`}>

```bash
git branch -d snacks
git branch -D snacks
```

</CodeExample>

- **`-d`** — безопасное удаление. Оно отказывается, если на ветке есть коммиты, которых ещё нет на текущей ветке («not fully merged», «не полностью слита»): после удаления метки у этих коммитов не осталось бы имени, по которому их можно найти.
- **`-D`** удаляет в любом случае. Пользуйтесь им только для идеи, которую действительно хотите выбросить, как эта.
- Ветку, на которой вы стоите, удалить нельзя. Сначала переключитесь на другую.

## «Your local changes would be overwritten»

А что, если у вас есть незакоммиченные изменения, а вы переключаетесь? Тут два случая.

Если на другой ветке **та же** версия изменённого файла, Git просто переключается, и ваше незакоммиченное изменение переезжает вместе с вами. Оно пока не принадлежит ни одной ветке: оно попадёт на ту, где вы его закоммитите.

Если на другой ветке **другая** версия этого файла, Git пришлось бы затереть ваше изменение. Вместо этого он отказывается. Здесь `desserts` поменяла `menu.txt` в одном из своих коммитов, а у Панды на `main` в `menu.txt` есть незакоммиченная строка:

<CodeExample setup={`mkdir cafe
cd cafe
git init
echo "Зелёный чай" > menu.txt
git add menu.txt
git commit -m "Начать меню"
echo "Открыто с 9 до 17" > hours.txt
git add hours.txt
git commit -m "Добавить часы работы"
git switch -c desserts
echo "Зелёный чай с лимоном" > menu.txt
git commit -am "Добавить лимон"
git switch main`} output={`error: Your local changes to the following files would be overwritten by checkout:
	menu.txt
Please commit your changes or stash them before you switch branches.
Aborting
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   menu.txt

no changes added to commit (use "git add" and/or "git commit -a")`}>

```bash
echo "Жасминовый чай" >> menu.txt
git switch desserts
git status
```

</CodeExample>

`Aborting` («отмена») значит, что ничего не произошло: вы всё ещё на `main`, и изменение на месте. Выходов три:

- **Закоммитить** изменение на этой ветке (`git add`, `git commit`), а потом переключиться. Обычно так и делают.
- **Выбросить изменение** командой `git restore menu.txt`, если оно вам не нужно (`git restore` вы встречали в модуле «Git каждый день»). Потом переключиться.
- **Отложить** его на потом через `git stash` — это тот самый «stash» из сообщения. Его вы изучите на уровне 2.

## Итоги

- **Ветка** — имя, которое указывает на коммит. Коммит сдвигает текущую ветку на новый коммит. Создание ветки не копирует файлы.
- **`HEAD`** указывает на ветку, где вы сейчас: `(HEAD -> main)`.
- **`git branch`** выводит список веток (звёздочка — где вы); **`-v`** добавляет коммит каждой. **`git branch имя`** создаёт ветку, но не переключает на неё.
- **`git switch имя`** переводит на ветку; **`git switch -c имя`** создаёт её и переключает; **`git switch -`** возвращает назад. Старые команды: `git checkout имя`, `git checkout -b имя`.
- При переключении папка становится такой, как в последнем коммите ветки. **`git log --oneline --all`** показывает коммиты всех веток.
- **`git branch -m старое новое`** переименовывает; **`-d`** удаляет слитую ветку; **`-D`** — ветку, чьих коммитов больше нигде нет.
- «Your local changes … would be overwritten»: сначала закоммитьте (или откатите через restore) изменение, потом переключайтесь.
