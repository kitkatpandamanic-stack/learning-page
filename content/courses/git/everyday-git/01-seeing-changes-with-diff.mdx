`git status` tells you **which** files changed. It doesn't tell you **what** changed inside them. And that's exactly what you want to know before a commit: did you change the price you meant to change, or did a stray key press sneak in too? 🔍

**`git diff`** answers that question line by line, in the same `+` and `-` format you met with `git show`. In this lesson you'll learn which two versions each form of `git diff` compares, compare any two commits, and finally read the `@@` lines you skipped in Level 0.

</CodeExample>

`git status -s` only says ` M hours.txt`: modified, not staged. `git diff` shows the change itself: the line with `18:00` was removed (`-`) and a line with `19:00` was added (`+`).

**`git diff`** with nothing after it compares your **working folder** with the **staging area**. In other words, it shows the changes you could still `git add` but haven't yet. Right after a commit, the staging area holds exactly what that commit holds, so here it's the same as "what changed since the last commit".

<Callout type="tip" title="git diff on your own computer">

On a real computer, removed lines are usually red and added lines green. A long diff opens in the same **pager** as a long `git log`: scroll with the arrow keys or Space, and press **`q`** to get back to the prompt.

</Callout>

The four lines at the top are the file's header, as in `git show`: `diff --git` names the file, the `index` line is Git's bookkeeping, and `---`/`+++` mark the old version (`a/`) and the new one (`b/`).

The rest comes in **hunks**: pieces of the file around each change. Each hunk starts with a line between `@@` signs:

- **`@@ -1,4 +1,4 @@`**: the part after `-` is about the **old** version, the part after `+` about the **new** one. `-1,4` means "this piece starts at line 1 and is 4 lines long in the old version". `+1,4` says the same for the new version.
- Lines starting with a **space** didn't change. They're **context**: Git shows up to 3 unchanged lines around each change, so you can see where it is.
- Lines with **`-`** were removed, lines with **`+`** were added, as you already know.
- **`@@ -6,5 +6,5 @@`** starts the second hunk, at line 6. Line 5 is too far from both changes to be context, so Git leaves it out. When two changes are close together (6 unchanged lines between them or fewer), their context would overlap, so Git joins them into one hunk.

The numbers in the header get interesting when the file grows or shrinks. Here Zara adds a carrot cake at the end:

**`@@ -8,3 +8,4 @@`**: in the old version the piece is lines 8 to 10 (3 lines); in the new version it's lines 8 to 11 (4 lines). One more line, the one with `+`. Two small extras:

- When a piece is just **one line** long, Git leaves out the count: `@@ -1 +1 @@` (the hours change above) means "line 1, old and new".
- For a **new file** you'll see `@@ -0,0 +1 @@`: zero lines before, one line after.

<Callout type="note" title="Text after the second @@">

On your own computer, a hunk header sometimes has text after it, like `@@ -3,4 +3,4 @@ Bagel`. That's the nearest line **above** the hunk that starts with a letter. In code, it's usually the name of the function the change is in, so you know where you are. The practice terminal leaves it out. (Our menu lines start with numbers, so this menu won't show it on your computer either.)

</Callout>

## Staged changes: git diff --staged

What happens to `git diff` once a change is staged? Zara stages the new hours and looks again:

-Open every day, 8:00 to 18:00
+Open every day, 8:00 to 19:00`}>

```bash
echo "Open every day, 8:00 to 19:00" > hours.txt
git add hours.txt
git diff
git diff --staged
```

</CodeExample>

The first `git diff` prints **nothing**. The change hasn't gone anywhere: it's in the staging area now, so the working folder and the staging area match, and plain `git diff` has nothing to show.

**`git diff --staged`** compares the staging area with the **last commit**. It shows exactly what your next `git commit` will save, which makes it the best last check before you commit. **`git diff --cached`** is another name for the same thing; you'll see both in other people's notes.

There's one more gap you can look across: **`git diff HEAD`** compares your working folder with the last commit, staged or not. (`HEAD`, as you saw in `git log`, means the commit you're on.) Here `hours.txt` is staged and `menu.txt` isn't:

So there are three ways to look, one for each gap between the three places your work lives:

| Command             | Compares                            | Shows                              |
| ------------------- | ----------------------------------- | ---------------------------------- |
| `git diff`          | staging area → working folder       | changes you haven't staged yet     |
| `git diff --staged` | last commit → staging area          | what the next commit will save     |
| `git diff HEAD`     | last commit → working folder        | everything since the last commit   |

## Comparing two commits

`git diff` can also compare any two commits. Give it two hashes, **older first**, and it shows what changed from the first to the second:

<CodeExample setup={`mkdir bakery

echo "3. Muffin - 2.20" >> menu.txt
echo "4. Cinnamon roll - 3.00" >> menu.txt
echo "5. Brownie - 2.80" >> menu.txt
echo "6. Cookie - 1.50" >> menu.txt
echo "7. Lemon tart - 3.50" >> menu.txt
echo "8. Cheesecake - 4.00" >> menu.txt
echo "9. Apple pie - 3.80" >> menu.txt

git add menu.txt

27cd93f Add opening hours
5f7cd15 Add the menu
diff --git a/hours.txt b/hours.txt
new file mode 100644
index 0000000..25f1308
--- /dev/null
+++ b/hours.txt
@@ -0,0 +1 @@
+Open every day, 8:00 to 18:00

index bfdaa41..60cb0cf 100644
--- a/menu.txt
+++ b/menu.txt
@@ -7,3 +7,4 @@
 7. Lemon tart - 3.50
 8. Cheesecake - 4.00
 9. Apple pie - 3.80
+10. Banana bread - 2.60`}>

```bash
git log --oneline
git diff 5f7cd15 984dd91
```

</CodeExample>

From the first commit to the newest, `hours.txt` appeared (`new file`) and the menu got one more line. Notice that it's **one** diff, not one per commit: Git compares the two snapshots and skips everything in between.

- **The order matters.** `git diff 984dd91 5f7cd15` shows the same changes the other way round: `hours.txt` as deleted, and the banana bread as a `-` line.
- **Two dots** do the same thing: `git diff 5f7cd15..984dd91` is just another way to write `git diff 5f7cd15 984dd91`.
- **One commit** compares that commit with your working folder: `git diff 5f7cd15` shows everything that changed since the first commit, including edits you haven't committed.

## Just the numbers: --stat

When a diff is long, start with a summary. **`--stat`** prints one line per file instead of the lines themselves:

<CodeExample setup={`mkdir bakery
cd bakery
git init
echo "1. Croissant - 2.50" > menu.txt
echo "2. Bagel - 2.00" >> menu.txt
echo "3. Muffin - 2.20" >> menu.txt
echo "4. Cinnamon roll - 3.00" >> menu.txt
echo "5. Brownie - 2.80" >> menu.txt
echo "6. Cookie - 1.50" >> menu.txt
echo "7. Lemon tart - 3.50" >> menu.txt
echo "8. Cheesecake - 4.00" >> menu.txt
echo "9. Apple pie - 3.80" >> menu.txt
git add menu.txt
git commit -m "Add the menu"
echo "Open every day, 8:00 to 18:00" > hours.txt
git add hours.txt
git commit -m "Add opening hours"
echo "10. Banana bread - 2.60" >> menu.txt
git add menu.txt
git commit -m "Add banana bread"`} output={` hours.txt | 1 +
 menu.txt  | 1 +
 2 files changed, 2 insertions(+)
 hours.txt | 2 +-

```bash
git diff 5f7cd15 984dd91 --stat
echo "Open every day, 8:00 to 19:00" > hours.txt
git diff --stat
```

</CodeExample>

`hours.txt | 1 +` means one line changed in that file, and it was added. `hours.txt | 2 +-` means two lines changed: one added and one removed (a changed line counts as both). The last line adds them all up, just like the summary `git commit` prints.

## Common mistakes

- **Expecting `git diff` to show staged changes.** After `git add`, plain `git diff` goes quiet. Use `git diff --staged` to see what you're about to commit.
- **Looking for a new file in `git diff`.** Untracked files never show up there. `git status` lists them.
- **Putting the commits the wrong way round.** `git diff new old` turns every `+` into `-`. Older first, newer second.
- **Thinking a hunk header counts changes.** `@@ -6,5 +6,5 @@` is a start line and a length for each version, not "6 removed, 5 added".

## Recap

- **`git diff`** shows unstaged changes: working folder compared with the staging area.
- **`git diff --staged`** (or `--cached`) shows what the next commit will save: staging area compared with the last commit.
- **`git diff HEAD`** shows everything since the last commit, staged or not.
- **`git diff A B`** (or `A..B`) compares two commits, older first. One diff shows the difference between the two ends, whatever happened in between.
- **`--stat`** gives a one-line summary per file; **`-- file`** limits the diff to one file.
- In a hunk header like **`@@ -8,3 +8,4 @@`**, each side is a start line and a length: old version after `-`, new version after `+`. Lines with a space are unchanged context.
- New, untracked files don't appear in `git diff`; `git status` shows them.
