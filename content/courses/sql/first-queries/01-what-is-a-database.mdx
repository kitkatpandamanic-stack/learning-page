Welcome to SQL! 🐼 Almost every app you use keeps its information in a **database**: your messages, your playlists, the products in an online shop, the films on a streaming service. **SQL** (say "S-Q-L" or "sequel") is the language people use to ask a database questions. By the end of this lesson you'll have asked your first one, and you don't need any coding experience to get there.

## What is a database?

A **database** is an organised collection of information that a computer can search quickly. The program that looks after it is called a **database management system**. It stores the data safely, lets many people use it at once and answers questions about it.

In this course you'll use **PostgreSQL** (often just "Postgres"), one of the most popular database systems in the world. It's free, and companies of every size run it.

The questions you ask are called **queries**, and the answer that comes back is called the **result**. You write a query in SQL, the database works out the answer and shows you the result as a table.

<Callout type="tip" title="Where does this run?">

Right here! A real PostgreSQL 18 database runs inside your browser on PandaDev. Every code box has a **Run** button, and every run starts with a **fresh copy** of the sample database. So you can't break anything: if you make a mess, just run again.

</Callout>

## Tables, rows and columns

A database keeps its data in **tables**. A table looks a lot like a spreadsheet. Here's part of a table called `departments`, which lists the teams in a company:

```text
 id |    name     | location
----+-------------+----------
  1 | Engineering | London
  2 | Design      | London
  3 | Sales       | Madrid
```

- Each **column** holds one kind of information and has a name: `id`, `name` and `location`.
- Each **row** is one thing, here one department. A row is sometimes called a **record**.
- Every column has a **data type**: `id` holds whole numbers, `name` and `location` hold text. The database won't let you put text in a number column.
- The `id` column gives every row its own number, so you can always tell rows apart, even if two departments had the same name.

A database usually has **many tables**, one for each kind of thing: customers, products, orders and so on.

## Your first query

Let's ask the database to show the whole `departments` table. Click **Run** in any example to try it yourself:

<CodeExample output={` id |    name     | location
----+-------------+----------
  1 | Engineering | London
  2 | Design      | London
  3 | Sales       | Madrid
  4 | Support     | Tokyo
  5 | Research    | Berlin
(5 rows)`}>

```sql
SELECT * FROM departments;
```

</CodeExample>

Read it almost like English: "**select everything from** departments".

- **`SELECT`** says you want to get some data back.
- **`*`** (a star) means "all the columns".
- **`FROM departments`** says which table to look in.
- The **semicolon** `;` marks the end of the query, like a full stop at the end of a sentence.

Words like `SELECT` and `FROM` are SQL **keywords**: words with a special meaning in SQL. `departments` is a **name** you chose when the table was made.

## Reading a result

The result is a table too:

- The first line shows the **column names**, and the dashed line separates them from the data.
- Each line after that is one **row**. Numbers line up on the right, text lines up on the left.
- The last line, `(5 rows)`, counts the rows in the result. Handy when a result is long!

<Callout type="note" title="No promised order">

A table is like a bag of rows: it has **no built-in order**. Here the rows happen to come back in the order they were added, but SQL doesn't promise that. When order matters, you'll ask for it with `ORDER BY`, which you'll learn in [Sorting with ORDER BY](/learn/sql/sorting-with-order-by).

</Callout>

## SQL's grammar rules

SQL is relaxed about some things and strict about others.

**Relaxed:** keywords can be written in any case, and spaces and line breaks don't matter. All three of these are the same query:

```sql
SELECT * FROM departments;

select * from departments;

SELECT *
FROM departments;
```

In this course we write keywords in **UPPER CASE** and names in **lower case**, so it's easy to see which is which. Bigger queries go on **several lines**, one part per line.

**Strict:** names must be spelt exactly right, and you can run **several queries** in one go if each one ends with a semicolon. They run from top to bottom, and you get one result for each:

<CodeExample output={` id |    name     | location
----+-------------+----------
  1 | Engineering | London
  2 | Design      | London
  3 | Sales       | Madrid
  4 | Support     | Tokyo
  5 | Research    | Berlin
(5 rows)

 count
-------
    40
(1 row)`}>

```sql
-- Every department
SELECT * FROM departments;

-- How many orders are there? (count comes in a later module)
SELECT count(*) FROM orders;
```

</CodeExample>

Lines starting with **two dashes** `--` are **comments**. The database ignores them; they're notes for humans.

## When something goes wrong

Mistakes are normal, and the database tells you what went wrong. Here the table name is misspelt (`product` instead of `products`):

<CodeExample output={`ERROR:  relation "product" does not exist
LINE 1: SELECT * FROM product;
                      ^`}>

```sql
SELECT * FROM product;
```

</CodeExample>

- **`ERROR:`** explains the problem. "Relation" is PostgreSQL's formal word for a table.
- **`LINE 1:`** shows the line with the problem, and the **caret** `^` points at the exact spot.

When you see an error, read it slowly, look where the caret points, fix that part and run again. Every programmer does this all day long! 💪

<Callout type="warning" title="Common first mistakes">

- A misspelt table or column name: `costumers` instead of `customers`.
- A missing comma or an extra one (you'll meet commas in the next lesson).
- Forgetting `FROM`: `SELECT * movies;` is a syntax error.

</Callout>

## Recap

- A **database** stores organised data; **PostgreSQL** is the database system you'll use.
- Data lives in **tables** made of **columns** (kinds of information) and **rows** (one item each).
- A **query** is a question written in **SQL**; the database answers with a **result**.
- `SELECT * FROM table_name;` shows every column and every row of a table.
- Keywords can be any case and line breaks don't matter, but names must be spelt exactly. End each query with `;`.
- `--` starts a comment. Errors tell you what went wrong and the caret `^` shows where.
