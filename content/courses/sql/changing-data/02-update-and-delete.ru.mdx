Цены меняются, заказы отправляются, покупатели переезжают, а старые данные приходится чистить. Этим занимаются **UPDATE** (изменить существующие строки) и **DELETE** (удалить строки).

Обе инструкции пишутся просто, и обе могут натворить бед из-за одной пропущенной строчки. Поэтому в этом уроке вы изучите сами инструкции **и** привычки, с которыми профессионалы изменяют данные без неприятных сюрпризов.

## UPDATE: изменить часть строк

`UPDATE` указывает таблицу, с помощью `SET` говорит, что изменить, и выбирает строки с помощью `WHERE`:

<CodeExample output={`UPDATE 1

 id |    name     | price
----+-------------+-------
  1 | Jasmine Tea |  7.00
(1 row)`}>

```sql
UPDATE products
SET price = 7.00
WHERE id = 1;

SELECT id, name, price
FROM products
WHERE id = 1;
```

</CodeExample>

Тег `UPDATE 1` сообщает, **сколько строк** изменилось. Привыкайте его читать: если вы ждали 1, а там 15, что-то пошло не так.

Можно изменить несколько столбцов сразу, через запятую, а новое значение можно вычислить из старого. Чай дорожает на 10%, и приходит новая поставка — по 10 пачек каждого:

<CodeExample output={`UPDATE 3

     name      | price | stock
---------------+-------+-------
 Jasmine Tea   |  7.15 |    50
 Matcha Powder | 15.40 |    22
 Earl Grey     |  5.78 |    10
(3 rows)`}>

```sql
UPDATE products
SET
  price = round(price * 1.10, 2),
  stock = stock + 10
WHERE category = 'tea';

SELECT name, price, stock
FROM products
WHERE category = 'tea'
ORDER BY id;
```

</CodeExample>

Справа от `=` имена `price` и `stock` означают **текущие** значения строки, так что `stock = stock + 10` прибавляет 10 к тому, что было в каждой строке.

## Забытый WHERE

`WHERE` необязателен, и в этом опасность. Без него `UPDATE` изменяет **каждую строку** таблицы:

<CodeExample output={`UPDATE 15

 priced_at_1
-------------
          15
(1 row)`}>

```sql
-- Хотели исправить цену одного товара...
UPDATE products
SET price = 1.00;

SELECT count(*) AS priced_at_1
FROM products
WHERE price = 1.00;
```

</CodeExample>

Теперь все 15 товаров стоят 1.00. Никакого «вы уверены?» и никакой кнопки отмены. В настоящей базе данных вернуть всё можно только из резервной копии или с помощью транзакции, которую вы ещё не зафиксировали (об этом — в следующем уроке).

<Callout type="danger" title="Сначала SELECT, потом UPDATE">

Прежде чем что-то изменять или удалять, напишите это как **SELECT** с тем же `WHERE` и выполните. Проверьте строки и их количество. Только после этого замените `SELECT … FROM` на `UPDATE … SET` (или `DELETE FROM`), оставив `WHERE` в точности прежним. Многие разработчики пишут строку с `WHERE` **первой**, чтобы случайно не выполнить инструкцию без неё.

</Callout>

Вот эта привычка в действии. Какие товары закончились?

<CodeExample output={` id |     name     | stock
----+--------------+-------
  3 | Earl Grey    |     0
  9 | Clean Python |     0
(2 rows)`}>

```sql
SELECT id, name, stock
FROM products
WHERE stock = 0
ORDER BY id;
```

</CodeExample>

Две строки, как и ожидалось. Теперь тот же `WHERE` в `UPDATE`:

<CodeExample output={`UPDATE 2`}>

```sql
UPDATE products
SET stock = 50
WHERE stock = 0;
```

</CodeExample>

`UPDATE 2` — совпадает с `SELECT`. 👍

## Смотрим, что изменилось, с RETURNING

Как и `INSERT`, `UPDATE` может заканчиваться `RETURNING`, чтобы показать изменённые строки. Начиная с **PostgreSQL 18**, можно даже запросить значение **до** и **после** изменения с помощью `old.` и `new.`. Вот весенняя распродажа игрушек со скидкой 20%:

<CodeExample output={`     name      |  was  |  now
---------------+-------+-------
 Plush Panda   | 18.00 | 14.40
 Wooden Puzzle | 11.40 |  9.12
 Kite          | 15.00 | 12.00
(3 rows)`}>

```sql
UPDATE products
SET price = round(price * 0.8, 2)
WHERE category = 'toys'
RETURNING name, old.price AS was, new.price AS now;
```

</CodeExample>

Это идеальная запись того, что сделала инструкция. (В более старых версиях PostgreSQL `RETURNING price` даёт только новое значение.)

<Callout type="warning" title="WHERE city = NULL ничего не находит">

Чтобы найти пропущенные значения в `UPDATE` или `DELETE`, используйте `IS NULL` — так же, как в `SELECT`. `UPDATE customers SET city = 'Unknown' WHERE city = NULL` сообщит `UPDATE 0`, потому что `= NULL` никогда не истинно. Пишите `WHERE city IS NULL`. А вот присвоить значение `NULL` можно без проблем: `SET city = NULL`.

</Callout>

## UPDATE … FROM: значения из другой таблицы

Иногда новые значения хранятся где-то ещё. Приходит поставка со списком товаров и количеств. `UPDATE … FROM` соединяет изменяемую таблицу с другим источником, а `WHERE` говорит, как они сопоставляются.

Здесь накладная записана как маленькая встроенная таблица через `VALUES` с именем `d` и столбцами `(name, qty)`:

<CodeExample output={`     name     | was | now
--------------+-----+-----
 Earl Grey    |   0 |  24
 Clean Python |   0 |  10
 Tea Pot      |   6 |  12
(3 rows)`}>

```sql
UPDATE products AS p
SET stock = p.stock + d.qty
FROM (VALUES
  ('Earl Grey', 24),
  ('Clean Python', 10),
  ('Tea Pot', 6)
) AS d (name, qty)
WHERE p.name = d.name
RETURNING p.name, old.stock AS was, new.stock AS now;
```

</CodeExample>

Источником после `FROM` может быть любая таблица, подзапрос или список `VALUES`. Изменяются только те строки `products`, для которых нашлось соответствие.

<Callout type="warning" title="Одно совпадение на строку">

Если строка изменяемой таблицы совпадает с **несколькими** строками источника из `FROM`, PostgreSQL использует только одну из них, и какую именно — не угадать. Будь Earl Grey в накладной дважды, прибавилась бы только одна строчка, причём молча. Если в источнике возможны дубликаты, сначала сложите их (например, подзапросом или CTE с `GROUP BY`), чтобы каждая строка совпадала ровно один раз.

</Callout>

Для простого условия по другой таблице подойдёт и подзапрос: `UPDATE orders SET status = 'shipped' WHERE status = 'paid' AND customer_id IN (SELECT id FROM customers WHERE country = 'Japan')`.

## DELETE: удаление строк

`DELETE FROM` вместе с `WHERE` удаляет подходящие строки. Nina Novak (покупатель 20) ни разу ничего не заказывала и хочет удалить свой аккаунт:

<CodeExample output={`DELETE 1

 customers
-----------
        19
(1 row)`}>

```sql
DELETE FROM customers
WHERE id = 20;

SELECT count(*) AS customers FROM customers;
```

</CodeExample>

Всё, что вы узнали про `UPDATE`, верно и здесь: тег сообщает, сколько строк удалено, `DELETE FROM customers;` без `WHERE` опустошает всю таблицу, а `RETURNING` показывает, что было удалено.

Внешние ключи (foreign keys) не дают оставить «сирот». У Mei Lin (покупатель 1) есть заказы, которые ссылаются на её строку, поэтому база отказывается её удалять:

<CodeExample output={`ERROR:  update or delete on table "customers" violates foreign key constraint "orders_customer_id_fkey" on table "orders"
DETAIL:  Key (id)=(1) is still referenced from table "orders".`}>

```sql
DELETE FROM customers
WHERE id = 1;
```

</CodeExample>

Чтобы её удалить, сначала пришлось бы удалить (или переназначить) строки, которые на неё ссылаются: позиции её заказов, затем сами заказы, а уже потом покупателя. Удаляйте «детей» раньше «родителя».

Подзапрос в `WHERE` позволяет удалять строки на основе другой таблицы. Этот запрос удаляет все позиции, которые относятся к отменённым заказам:

<CodeExample output={`DELETE 15`}>

```sql
DELETE FROM order_items
WHERE order_id IN (
  SELECT id FROM orders WHERE status = 'cancelled'
);
```

</CodeExample>

<Callout type="tip" title="Удалять по-настоящему — серьёзное решение">

Многие приложения никогда по-настоящему не удаляют важные строки. Вместо этого они добавляют столбец вроде `deleted_at` и заполняют его (это **мягкое удаление (soft delete)**), чтобы ошибки можно было исправить, а история сохранялась. Вы спроектируете такое на уровне 3. Чтобы быстро опустошить всю таблицу, есть ещё `TRUNCATE table_name;` — на больших таблицах это гораздо быстрее, чем `DELETE`, и ещё бесповоротнее.

</Callout>

1. Сначала удалите строки отменённых заказов из `order_items` (иначе внешний ключ не даст удалить сами заказы).

## Итоги

- `UPDATE table SET col = value, … WHERE …;` изменяет строки; `DELETE FROM table WHERE …;` удаляет их.
- Тег (`UPDATE 3`, `DELETE 1`) — это число затронутых строк. Проверяйте его.
- **Нет `WHERE` — значит, все строки.** Сначала выполните `SELECT` с тем же `WHERE`.
- В `SET` имена столбцов означают текущие значения строки: `stock = stock + 10`.
- `RETURNING` показывает изменённые строки; в PostgreSQL 18 `old.col` и `new.col` показывают значения до и после.
- `UPDATE … FROM` берёт новые значения из другой таблицы, подзапроса или списка `VALUES`; следите, чтобы каждая строка совпадала один раз.
- Внешние ключи не дают удалить строку, на которую ссылаются другие: сначала удаляйте «детей».
