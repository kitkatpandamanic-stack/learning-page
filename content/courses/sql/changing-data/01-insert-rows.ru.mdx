До сих пор вы только **читали** данные. Настоящие приложения постоянно пишут в базу данных: регистрируется новый покупатель, кто-то оформляет заказ, на товар объявляют скидку. В этом модуле вы изучите три инструкции, которые изменяют данные: **INSERT** добавляет строки, **UPDATE** изменяет их, а **DELETE** удаляет.

Этот урок — про `INSERT`. Не бойтесь что-нибудь сломать: каждый запуск здесь начинается со свежей копии учебной базы, так что ваши изменения исчезнут при следующем нажатии «Запустить». Экспериментируйте смело! 🐼

## Ваш первый INSERT

Чтобы добавить строку, укажите таблицу, перечислите столбцы, которые заполняете, и передайте значения в том же порядке:

<CodeExample output={`INSERT 0 1

 id |     name      | category | price | stock
----+---------------+----------+-------+-------
  1 | Jasmine Tea   | tea      |  6.50 |    40
  2 | Matcha Powder | tea      | 14.00 |    12
  3 | Earl Grey     | tea      |  5.25 |     0
 16 | Oolong Tea    | tea      |  9.50 |    30
(4 rows)`}>

```sql
INSERT INTO products (name, category, price, stock)
VALUES ('Oolong Tea', 'tea', 9.50, 30);

SELECT id, name, category, price, stock
FROM products
WHERE category = 'tea'
ORDER BY id;
```

</CodeExample>

Когда `INSERT` выполняется успешно, PostgreSQL отвечает **тегом команды (command tag)**: `INSERT 0 1`. `1` — это число добавленных строк. (`0` — наследие очень старых версий PostgreSQL, он всегда равен 0, и его можно не замечать.)

Значения должны соответствовать столбцам **один к одному**: первое значение попадает в `name`, второе — в `category`, и так далее. Текст пишется в одинарных кавычках, числа — без кавычек.

## Столбцы, которые вы пропустили

Посмотрите на `id` новой строки: вы его не указывали, но он равен `16`. Столбец `id` настроен так, чтобы **нумеровать новые строки автоматически**, поэтому база выбирает следующий свободный номер. Пропускать его — совершенно правильно: если выбирать id самостоятельно, рано или поздно они столкнутся.

Любой другой пропущенный столбец получает своё **значение по умолчанию (default)** или `NULL`, если значения по умолчанию нет. В `products` у `stock` по умолчанию `0`:

<CodeExample output={`INSERT 0 1

 id |   name    | price | stock
----+-----------+-------+-------
 16 | Panda Mug |  8.00 |     0
(1 row)`}>

```sql
INSERT INTO products (name, category, price)
VALUES ('Panda Mug', 'kitchen', 8.00);

SELECT id, name, price, stock
FROM products
WHERE name = 'Panda Mug';
```

</CodeExample>

Как самим настраивать значения по умолчанию и автоматические id, вы узнаете в модуле «Проектирование таблиц».

<Callout type="warning" title="Всегда перечисляйте столбцы">

Список столбцов *можно* опустить — `INSERT INTO products VALUES (…)`, — но тогда нужно передать значение для **каждого** столбца в том порядке, в котором они создавались, включая id. В тот день, когда кто-нибудь добавит в таблицу столбец, каждый такой `INSERT` сломается или, что хуже, запишет значения не в те столбцы. Список столбцов делает так, что ваш `INSERT` говорит ровно то, что имеет в виду.

</Callout>

## Несколько строк сразу

Перечислите после `VALUES` несколько строк через запятую. Это одна инструкция, поэтому она быстрее, чем много отдельных вставок, и работает по принципу **всё или ничего**: если хотя бы одна строка отклонена, не добавится ни одна.

<CodeExample output={`INSERT 0 3

 id |     name     |  city  | joined_on
----+--------------+--------+------------
 21 | Liam O'Brien | Dublin | 2025-07-01
 22 | Aisha Bello  | Lagos  | 2025-07-02
 23 | Mateo Rossi  | NULL   | 2025-07-02
(3 rows)`}>

```sql
INSERT INTO customers (name, email, city, country, joined_on)
VALUES
  ('Liam O''Brien', 'liam@pandadev.test', 'Dublin', 'Ireland',
   '2025-07-01'),
  ('Aisha Bello', 'aisha@pandadev.test', 'Lagos', 'Nigeria',
   '2025-07-02'),
  ('Mateo Rossi', 'mateo@pandadev.test', NULL, 'Italy', '2025-07-02');

SELECT id, name, city, joined_on
FROM customers
WHERE joined_on >= '2025-07-01'
ORDER BY id;
```

</CodeExample>

Здесь есть две детали:

- Чтобы поместить апостроф внутрь текстового значения, **удвойте его**: `'Liam O''Brien'` сохраняет `Liam O'Brien`.
- Для неизвестного значения пишите `NULL` (без кавычек). `'NULL'` в кавычках — это просто слово «NULL» из четырёх букв.

## Получаем значения обратно через RETURNING

После добавления покупателя приложению обычно сразу нужен его новый **id** — например, чтобы показать страницу профиля. Добавьте `RETURNING`, и `INSERT` вернёт запрошенные столбцы — так же, как `SELECT`:

<CodeExample output={` id |   name   | joined_on
----+----------+------------
 21 | Jun Park | 2025-07-03
(1 row)`}>

```sql
INSERT INTO customers (name, email, country, joined_on)
VALUES ('Jun Park', 'jun@pandadev.test', 'South Korea', '2025-07-03')
RETURNING id, name, joined_on;
```

</CodeExample>

`RETURNING *` возвращает все столбцы, включая те, что база заполнила за вас. Он работает и при вставке нескольких строк — по одной строке результата на каждую добавленную строку. Вы ещё встретите `RETURNING` в `UPDATE` и `DELETE`.

## Когда база говорит «нет»

У таблиц есть **ограничения (constraints)** — правила, которым должны подчиняться данные. PostgreSQL проверяет по ним каждую новую строку и отклоняет всю инструкцию, если правило нарушено. В учебной базе email каждого покупателя должен быть уникальным:

<CodeExample output={`ERROR:  duplicate key value violates unique constraint "customers_email_key"
DETAIL:  Key (email)=(mei@pandadev.test) already exists.`}>

```sql
INSERT INTO customers (name, email, country, joined_on)
VALUES ('Mei Again', 'mei@pandadev.test', 'UK', '2025-07-01');
```

</CodeExample>

Строка `DETAIL` точно говорит, какое значение вызвало конфликт. Другие правила, на которые вы будете натыкаться:

- **NOT NULL**: не заполнен обязательный столбец, например у покупателя нет email.
- **CHECK**: значение нарушает правило, например у товара цена `0` (цены должны быть больше нуля).
- **FOREIGN KEY** (внешний ключ): ссылка указывает в пустоту, например заказ для несуществующего покупателя:

<CodeExample output={`ERROR:  insert or update on table "orders" violates foreign key constraint "orders_customer_id_fkey"
DETAIL:  Key (customer_id)=(999) is not present in table "customers".`}>

```sql
INSERT INTO orders (customer_id, ordered_at, status)
VALUES (999, '2025-07-01 10:00', 'paid');
```

</CodeExample>

Эти ошибки — ваши друзья. Они останавливают плохие данные на пороге, и остальная часть приложения может доверять тому, что лежит в базе.

## Копирование строк с INSERT … SELECT

Вместо `VALUES` можно передать `INSERT` **запрос**. Каждая строка, которую вернёт запрос, будет вставлена. Так данные копируют, архивируют или заполняют заранее, не перечисляя их вручную.

Пример сначала создаёт небольшую таблицу `wishlist`. Не беспокойтесь пока о `CREATE TABLE` — его подробно разбирает модуль «Проектирование таблиц». Затем он одним махом добавляет весь чай в список желаний Mei (покупатель 1):

<CodeExample output={`CREATE TABLE

INSERT 0 3

     name      |  added_on
---------------+------------
 Earl Grey     | 2025-07-01
 Jasmine Tea   | 2025-07-01
 Matcha Powder | 2025-07-01
(3 rows)`}>

```sql
CREATE TABLE wishlist (
  customer_id integer,
  product_id integer,
  added_on date
);

INSERT INTO wishlist (customer_id, product_id, added_on)
SELECT 1, id, '2025-07-01'
FROM products
WHERE category = 'tea';

SELECT p.name, w.added_on
FROM wishlist AS w
JOIN products AS p ON p.id = w.product_id
ORDER BY p.name;
```

</CodeExample>

`SELECT` должен вернуть столько же столбцов, сколько указано в списке столбцов, и в том же порядке. Полезная привычка: сначала напишите и запустите `SELECT` отдельно, убедитесь, что строки правильные, и только потом поставьте перед ним `INSERT INTO … (…)`.

## Используем новый id сразу

Помните CTE из [урока про WITH](/learn/sql/common-table-expressions)? CTE может содержать `INSERT … RETURNING`, а основная инструкция — использовать то, что он вернул. Здесь совершенно новый покупатель и его первый заказ создаются **одной** инструкцией, и заказ ссылается на новый id покупателя:

<CodeExample output={` id | customer_id | status
----+-------------+--------
 41 |          21 | paid
(1 row)`}>

```sql
WITH new_customer AS (
  INSERT INTO customers (name, email, country, joined_on)
  VALUES ('Kofi Mensah', 'kofi@pandadev.test', 'Ghana', '2025-07-04')
  RETURNING id
)
INSERT INTO orders (customer_id, ordered_at, status)
SELECT id, '2025-07-04 12:00', 'paid'
FROM new_customer
RETURNING id, customer_id, status;
```

</CodeExample>

Новый покупатель получил id 21, заказ — id 41, и заказ уже ссылается на своего покупателя. Никаких угадываний id и никакого промежутка между двумя шагами, где что-то могло бы пойти не так.

В магазине два новых товара, и нужен список того, что пора дозаказать.

1. Измените первый `INSERT` так, чтобы **одна** инструкция добавляла оба новых товара: `Oolong Tea` (tea, 9.50, запас 30) и `Panda Mug` (kitchen, 8.00, запас 50).
2. После `CREATE TABLE` напишите `INSERT … SELECT`, который добавляет в `restock` строку для **каждого товара, которого на складе меньше 10**: его `id` как `product_id`, его `name` и `needed` — сколько заказать, чтобы запас дошёл до **20** (то есть `20 - stock`). Завершите его `RETURNING name, needed`.

<Hint>

Для части 1 поставьте запятую после скобок первой строки и добавьте вторую: `VALUES (…), (…)`. Для части 2 сначала напишите `SELECT id, name, 20 - stock FROM products WHERE stock < 10`, затем поставьте над ним `INSERT INTO restock (product_id, name, needed)`, а в конце — `RETURNING name, needed`.

</Hint>

<Solution>

```sql
INSERT INTO products (name, category, price, stock)
VALUES
  ('Oolong Tea', 'tea', 9.50, 30),
  ('Panda Mug', 'kitchen', 8.00, 50);

CREATE TABLE restock (
  product_id integer,
  name text,
  needed integer
);

INSERT INTO restock (product_id, name, needed)
SELECT id, name, 20 - stock
FROM products
WHERE stock < 10
RETURNING name, needed;
```

## Итоги

- `INSERT INTO table (col1, col2) VALUES (v1, v2);` добавляет строку; тег `INSERT 0 n` сообщает, сколько строк добавлено.
- Пропустите `id` — и база пронумерует строку сама; другие пропущенные столбцы получат своё **значение по умолчанию** или `NULL`.
- Всегда **перечисляйте столбцы**; апостроф внутри текста удваивается: `'O''Brien'`.
- `VALUES (…), (…), (…)` добавляет много строк одной инструкцией по принципу «всё или ничего».
- `RETURNING id` (или `RETURNING *`) возвращает то, что было вставлено, включая сгенерированные значения.
- Ограничения (NOT NULL, UNIQUE, CHECK, FOREIGN KEY) отклоняют плохие строки с понятной ошибкой.
- `INSERT INTO … SELECT …` вставляет все строки, которые возвращает запрос; CTE с `INSERT … RETURNING` позволяет сразу использовать новый id.
