So far your queries have shown data exactly as it's stored. But often you want it **shaped** a little differently: a full label like `Mei Lin (London)`, a name in capitals, just the part of an email before the `@`. That's what **functions** are for. 🧰

A **function** is a ready-made tool built into PostgreSQL. You write its name, then the values it should work on in brackets, and it gives back a new value:

```sql
upper('panda')   -- gives 'PANDA'
```

The values in the brackets are called **arguments**. You can use functions anywhere you'd write a value: in `SELECT`, in `WHERE`, in `ORDER BY`. In this lesson you'll meet the functions for **text** (also called **strings**), and the next two lessons cover numbers and dates.

## Gluing text together with ||

Two vertical bars, **`||`**, join (or **concatenate**) pieces of text into one. You can mix columns and your own text in single quotes:

<CodeExample output={`          sentence
----------------------------
 Mei Lin lives in London
 Sam Ortiz lives in Madrid
 Ada Brooks lives in London
(3 rows)`}>

```sql
SELECT name || ' lives in ' || city AS sentence
FROM customers
ORDER BY id
LIMIT 3;
```

</CodeExample>

Notice the spaces inside `' lives in '`: `||` adds nothing between the pieces, so you have to put the spaces in yourself.

### concat and missing values

There's a catch. If **any** piece is `NULL`, the whole result is `NULL`. Zara Khan has no city, so her label disappears completely. The function **`concat(...)`** joins any number of pieces too, but it treats `NULL` as empty text:

<CodeExample output={`       with_bars        |      with_concat
------------------------+------------------------
 Mei Lin (London)       | Mei Lin (London)
 Ada Brooks (London)    | Ada Brooks (London)
 NULL                   | Zara Khan ()
 Tom Baker (Manchester) | Tom Baker (Manchester)
(4 rows)`}>

```sql
SELECT
  name || ' (' || city || ')' AS with_bars,
  concat(name, ' (', city, ')') AS with_concat
FROM customers
WHERE country = 'UK'
ORDER BY id;
```

</CodeExample>

Neither is "right": `Zara Khan ()` isn't pretty either. Often the best answer is to fill the gap first with `coalesce`, which you met in [the lesson on NULL](/learn/sql/null-values): `name || ' (' || coalesce(city, 'no city') || ')'`.

There's also **`concat_ws(separator, ...)`**, "concat with separator", which puts the separator between the pieces and skips `NULL`s: `concat_ws(', ', city, country)` gives `London, UK`, or just `UK` when the city is missing.

## Changing capitals: upper, lower, initcap

- **`upper(text)`** turns every letter into a capital,
- **`lower(text)`** turns every letter into a small one,
- **`initcap(text)`** gives Each Word A Capital First Letter.

<CodeExample output={`      shout      |     whisper     |      title
-----------------+-----------------+-----------------
 THE BAMBOO CODE | the bamboo code | The Bamboo Code
(1 row)`}>

```sql
SELECT
  upper(name) AS shout,
  lower(name) AS whisper,
  initcap('the BAMBOO code') AS title
FROM products
WHERE id = 7;
```

</CodeExample>

`lower` is especially useful in `WHERE`. Text comparison in PostgreSQL is **case-sensitive**: `'london'` and `'London'` are different values. When you're not sure how something was typed, compare the lower-case versions:

<CodeExample output={`    name    |  city
------------+--------
 Mei Lin    | London
 Ada Brooks | London
(2 rows)`}>

```sql
SELECT name, city
FROM customers
WHERE lower(city) = 'london'
ORDER BY id;
```

</CodeExample>

## Measuring and cutting: length, left, right, substring

**`length(text)`** counts the characters. Spaces count too, and letters like `ã` count as one character:

<CodeExample output={`    city     | letters
-------------+---------
 Mexico City |      11
 São Paulo   |       9
 New York    |       8
(3 rows)`}>

```sql
SELECT city, length(city) AS letters
FROM customers
WHERE country IN ('Brazil', 'Mexico', 'USA')
ORDER BY letters DESC, city;
```

</CodeExample>

To cut out a piece of text:

- **`left(text, n)`** keeps the first `n` characters,
- **`right(text, n)`** keeps the last `n` characters,
- **`substring(text FROM start FOR count)`** takes `count` characters starting at position `start`. Positions start at **1**, not 0. Leave out `FOR count` to take everything to the end.

<CodeExample output={` first_five | last_seven | middle | from_seventh
------------+------------+--------+--------------
 Panda      | Cookies    | Cook   | Cookies
(1 row)`}>

```sql
SELECT
  left(name, 5) AS first_five,
  right(name, 7) AS last_seven,
  substring(name FROM 7 FOR 4) AS middle,
  substring(name FROM 7) AS from_seventh
FROM products
WHERE name = 'Panda Cookies';
```

</CodeExample>

`substring(name, 7, 4)` with commas does the same thing; the `FROM … FOR …` form is the SQL standard and reads a bit more clearly.

## Searching and replacing: position, replace, trim

- **`position(part IN text)`** tells you **where** `part` starts, or `0` when it isn't there.
- **`replace(text, old, new)`** swaps **every** `old` for `new`.
- **`trim(text)`** removes spaces from both ends. `ltrim` and `rtrim` only trim the left or right end.

<CodeExample output={` at_sign | not_found |   renamed    | trimmed
---------+-----------+--------------+---------
       4 |         0 | Panda Crisps | [tea]
(1 row)`}>

```sql
SELECT
  position('@' IN 'mei@pandadev.test') AS at_sign,
  position('?' IN 'mei@pandadev.test') AS not_found,
  replace('Bamboo Crisps', 'Bamboo', 'Panda') AS renamed,
  '[' || trim('   tea   ') || ']' AS trimmed;
```

</CodeExample>

Yes, `SELECT` works without `FROM`: when you only work with values you typed yourself, PostgreSQL gives back one row. It's a handy way to try a function out.

`trim` matters more than it looks: data typed by people often has stray spaces, and `'tea '` with a space at the end is **not equal** to `'tea'`.

## Splitting text: split_part

**`split_part(text, separator, n)`** cuts text at every `separator` and gives you the `n`th piece. It's perfect for emails:

<CodeExample output={`        email        | username |    domain
---------------------+----------+---------------
 mei@pandadev.test   | mei      | pandadev.test
 sam@pandadev.test   | sam      | pandadev.test
 ada@pandadev.test   | ada      | pandadev.test
 kenji@pandadev.test | kenji    | pandadev.test
(4 rows)`}>

```sql
SELECT
  email,
  split_part(email, '@', 1) AS username,
  split_part(email, '@', 2) AS domain
FROM customers
ORDER BY id
LIMIT 4;
```

</CodeExample>

<Callout type="tip" title="Functions inside functions">

The result of one function can go straight into another, like boxes inside boxes. PostgreSQL works from the inside out:

```sql
upper(left('panda', 3))   -- left gives 'pan', upper gives 'PAN'
```

Build big expressions one step at a time: run the inner part first, check it, then wrap the next function around it.

</Callout>

## Functions in WHERE and ORDER BY

Functions aren't only for the `SELECT` list. Here are the customers whose names start with A, L or S, shortest name first, using `left` to filter and `length` to sort:

<CodeExample output={`     name     | letters
--------------+---------
 Sam Ortiz    |       9
 Ada Brooks   |      10
 Lucas Silva  |      11
 Sofia Rossi  |      11
 Anna Ivanova |      12
 Lena Fischer |      12
(6 rows)`}>

```sql
SELECT name, length(name) AS letters
FROM customers
WHERE left(name, 1) IN ('A', 'L', 'S')
ORDER BY letters, name;
```

</CodeExample>

<Callout type="note" title="Your data stays the same">

Functions in a `SELECT` change only the **result** you see, never the table. After `SELECT upper(name) FROM customers`, the names are still stored exactly as before. Changing stored data is a job for `UPDATE`, which you'll learn in Level 1.

</Callout>

- a **`slug`** for its web address: the name in lower case with every space replaced by a dash. `The Bamboo Code` becomes `the-bamboo-code`.

Show the columns `code`, `name` and `slug` (in that order) for every product, sorted by `id`.

<Hint>

For the code, cut the category with `left(category, 3)`, make it capitals with `upper(...)`, and join the pieces with `||`: `upper(left(category, 3)) || '-' || id`.   upper(left(category, 3)) || '-' || id AS code,
```sql
  name,
  replace(lower(name), ' ', '-') AS slug

ORDER BY id;
```

## Recap

- A **function** takes arguments in brackets and returns a new value: `upper('panda')`. Use functions in `SELECT`, `WHERE` and `ORDER BY`.
- **`||`** joins text, but any `NULL` makes the result `NULL`. **`concat(...)`** treats `NULL` as empty, and **`concat_ws(sep, ...)`** adds a separator and skips `NULL`s.
- **`upper`**, **`lower`** and **`initcap`** change capitals. Compare with `lower(...)` when the case might differ.
- **`length`** counts characters; **`left`**, **`right`** and **`substring(text FROM start FOR count)`** cut text (positions start at 1).
- **`position(part IN text)`** finds, **`replace(text, old, new)`** swaps, **`trim`** removes spaces at the ends, and **`split_part(text, sep, n)`** takes the `n`th piece.
- Functions only change the result you see, never the stored data.
