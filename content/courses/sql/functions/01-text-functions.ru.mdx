До сих пор ваши запросы показывали данные ровно такими, какими они хранятся. Но часто их хочется немного **преобразовать**: собрать подпись вроде `Mei Lin (London)`, написать имя заглавными буквами, взять только часть email до `@`. Для этого и нужны **функции** (functions). 🧰

**Функция** — это готовый инструмент, встроенный в PostgreSQL. Вы пишете её имя, а в скобках — значения, с которыми она должна работать, и она возвращает новое значение:

```sql
upper('panda')   -- даёт 'PANDA'
```

Значения в скобках называются **аргументами** (arguments). Функции можно использовать везде, где вы написали бы значение: в `SELECT`, в `WHERE`, в `ORDER BY`. В этом уроке вы познакомитесь с функциями для **текста** (его ещё называют **строками**, strings), а следующие два урока посвящены числам и датам.

## Склеиваем текст с помощью ||

Две вертикальные черты, **`||`**, соединяют (или **конкатенируют**, concatenate) куски текста в один. Можно смешивать столбцы и собственный текст в одинарных кавычках:

<CodeExample output={`          sentence
----------------------------
 Mei Lin lives in London
 Sam Ortiz lives in Madrid
 Ada Brooks lives in London
(3 rows)`}>

```sql
SELECT name || ' lives in ' || city AS sentence
FROM customers
ORDER BY id
LIMIT 3;
```

</CodeExample>

Обратите внимание на пробелы внутри `' lives in '`: `||` ничего не добавляет между кусками, поэтому пробелы нужно ставить самим.

### concat и отсутствующие значения

Здесь есть подвох. Если **хотя бы один** кусок равен `NULL`, весь результат становится `NULL`. У Zara Khan не указан город, поэтому её подпись пропадает целиком. Функция **`concat(...)`** тоже соединяет любое количество кусков, но считает `NULL` пустым текстом:

<CodeExample output={`       with_bars        |      with_concat
------------------------+------------------------
 Mei Lin (London)       | Mei Lin (London)
 Ada Brooks (London)    | Ada Brooks (London)
 NULL                   | Zara Khan ()
 Tom Baker (Manchester) | Tom Baker (Manchester)
(4 rows)`}>

```sql
SELECT
  name || ' (' || city || ')' AS with_bars,
  concat(name, ' (', city, ')') AS with_concat
FROM customers
WHERE country = 'UK'
ORDER BY id;
```

</CodeExample>

Ни один вариант не «правильный»: `Zara Khan ()` тоже выглядит не очень. Часто лучше всего сначала заполнить пропуск с помощью `coalesce`, с которой вы познакомились в [уроке про NULL](/learn/sql/null-values): `name || ' (' || coalesce(city, 'no city') || ')'`.

Есть ещё **`concat_ws(separator, ...)`** — «concat with separator», то есть «склеить с разделителем». Она ставит разделитель между кусками и пропускает `NULL`: `concat_ws(', ', city, country)` даёт `London, UK`, а если города нет — просто `UK`.

## Меняем регистр: upper, lower, initcap

- **`upper(text)`** делает все буквы заглавными,
- **`lower(text)`** делает все буквы строчными,
- **`initcap(text)`** пишет Каждое Слово С Заглавной Буквы.

<CodeExample output={`      shout      |     whisper     |      title
-----------------+-----------------+-----------------
 THE BAMBOO CODE | the bamboo code | The Bamboo Code
(1 row)`}>

```sql
SELECT
  upper(name) AS shout,
  lower(name) AS whisper,
  initcap('the BAMBOO code') AS title
FROM products
WHERE id = 7;
```

</CodeExample>

`lower` особенно полезна в `WHERE`. Сравнение текста в PostgreSQL **чувствительно к регистру** (case-sensitive): `'london'` и `'London'` — разные значения. Если вы не уверены, как именно что-то было набрано, сравнивайте варианты в нижнем регистре:

<CodeExample output={`    name    |  city
------------+--------
 Mei Lin    | London
 Ada Brooks | London
(2 rows)`}>

```sql
SELECT name, city
FROM customers
WHERE lower(city) = 'london'
ORDER BY id;
```

</CodeExample>

## Измеряем и вырезаем: length, left, right, substring

**`length(text)`** считает символы. Пробелы тоже считаются, а буквы вроде `ã` считаются за один символ:

<CodeExample output={`    city     | letters
-------------+---------
 Mexico City |      11
 São Paulo   |       9
 New York    |       8
(3 rows)`}>

```sql
SELECT city, length(city) AS letters
FROM customers
WHERE country IN ('Brazil', 'Mexico', 'USA')
ORDER BY letters DESC, city;
```

</CodeExample>

Чтобы вырезать кусок текста:

- **`left(text, n)`** оставляет первые `n` символов,
- **`right(text, n)`** оставляет последние `n` символов,
- **`substring(text FROM start FOR count)`** берёт `count` символов, начиная с позиции `start`. Позиции начинаются с **1**, а не с 0. Если не писать `FOR count`, возьмётся всё до конца.

<CodeExample output={` first_five | last_seven | middle | from_seventh
------------+------------+--------+--------------
 Panda      | Cookies    | Cook   | Cookies
(1 row)`}>

```sql
SELECT
  left(name, 5) AS first_five,
  right(name, 7) AS last_seven,
  substring(name FROM 7 FOR 4) AS middle,
  substring(name FROM 7) AS from_seventh
FROM products
WHERE name = 'Panda Cookies';
```

</CodeExample>

`substring(name, 7, 4)` через запятые делает то же самое; форма `FROM … FOR …` — это стандарт SQL, и читается она чуть понятнее.

## Ищем и заменяем: position, replace, trim

- **`position(part IN text)`** сообщает, **где** начинается `part`, или `0`, если его там нет.
- **`replace(text, old, new)`** заменяет **каждое** вхождение `old` на `new`.
- **`trim(text)`** убирает пробелы с обоих концов. `ltrim` и `rtrim` обрезают только левый или правый конец.

<CodeExample output={` at_sign | not_found |   renamed    | trimmed
---------+-----------+--------------+---------
       4 |         0 | Panda Crisps | [tea]
(1 row)`}>

```sql
SELECT
  position('@' IN 'mei@pandadev.test') AS at_sign,
  position('?' IN 'mei@pandadev.test') AS not_found,
  replace('Bamboo Crisps', 'Bamboo', 'Panda') AS renamed,
  '[' || trim('   tea   ') || ']' AS trimmed;
```

</CodeExample>

Да, `SELECT` работает и без `FROM`: когда вы работаете только со значениями, которые ввели сами, PostgreSQL возвращает одну строку. Это удобный способ опробовать функцию.

`trim` важнее, чем кажется: в данных, которые вводят люди, часто бывают лишние пробелы, а `'tea '` с пробелом в конце **не равно** `'tea'`.

## Разбиваем текст: split_part

**`split_part(text, separator, n)`** разрезает текст по каждому `separator` и отдаёт `n`-й кусок. Идеально подходит для email:

<CodeExample output={`        email        | username |    domain
---------------------+----------+---------------
 mei@pandadev.test   | mei      | pandadev.test
 sam@pandadev.test   | sam      | pandadev.test
 ada@pandadev.test   | ada      | pandadev.test
 kenji@pandadev.test | kenji    | pandadev.test
(4 rows)`}>

```sql
SELECT
  email,
  split_part(email, '@', 1) AS username,
  split_part(email, '@', 2) AS domain
FROM customers
ORDER BY id
LIMIT 4;
```

</CodeExample>

<Callout type="tip" title="Функции внутри функций">

Результат одной функции можно сразу передать в другую — как коробки в коробках. PostgreSQL вычисляет их изнутри наружу:

```sql
upper(left('panda', 3))   -- left даёт 'pan', upper даёт 'PAN'
```

Собирайте большие выражения по шагу: сначала запустите внутреннюю часть, проверьте её, потом оберните вокруг неё следующую функцию.

</Callout>

## Функции в WHERE и ORDER BY

Функции нужны не только в списке `SELECT`. Вот покупатели, чьи имена начинаются на A, L или S, от самого короткого имени к самому длинному: `left` фильтрует, а `length` сортирует:

<CodeExample output={`     name     | letters
--------------+---------
 Sam Ortiz    |       9
 Ada Brooks   |      10
 Lucas Silva  |      11
 Sofia Rossi  |      11
 Anna Ivanova |      12
 Lena Fischer |      12
(6 rows)`}>

```sql
SELECT name, length(name) AS letters
FROM customers
WHERE left(name, 1) IN ('A', 'L', 'S')
ORDER BY letters, name;
```

</CodeExample>

<Callout type="note" title="Ваши данные не меняются">

Функции в `SELECT` меняют только **результат**, который вы видите, но никогда не саму таблицу. После `SELECT upper(name) FROM customers` имена хранятся точно так же, как раньше. Изменять сохранённые данные — работа для `UPDATE`, его вы изучите на Уровне 1.

</Callout>

Магазин делает новый сайт, и для каждого товара ему нужны две вещи: 🏷️

<Hint>

Для кода вырежьте категорию с помощью `left(category, 3)`, сделайте её заглавной через `upper(...)` и соедините куски с помощью `||`: `upper(left(category, 3)) || '-' || id`. SELECT
```sql
  upper(left(category, 3)) || '-' || id AS code,
  name,
  replace(lower(name), ' ', '-') AS slug
FROM products
ORDER BY id;
```

## Итоги

- **Функция** принимает аргументы в скобках и возвращает новое значение: `upper('panda')`. Используйте функции в `SELECT`, `WHERE` и `ORDER BY`.
- **`||`** соединяет текст, но любой `NULL` делает результат `NULL`. **`concat(...)`** считает `NULL` пустым, а **`concat_ws(sep, ...)`** добавляет разделитель и пропускает `NULL`.
- **`upper`**, **`lower`** и **`initcap`** меняют регистр. Если регистр может отличаться, сравнивайте через `lower(...)`.
- **`length`** считает символы; **`left`**, **`right`** и **`substring(text FROM start FOR count)`** вырезают текст (позиции начинаются с 1).
- **`position(part IN text)`** ищет, **`replace(text, old, new)`** заменяет, **`trim`** убирает пробелы по краям, а **`split_part(text, sep, n)`** берёт `n`-й кусок.
- Функции меняют только результат, который вы видите, но никогда не сохранённые данные.
