Пора завершать проект! 🎉 Организатор клуба хочет получать перед каждой встречей **отчёт для киновечера**: каталог в общих чертах, лучшие фильмы, сравнение жанров и, самое главное, **фильм на сегодня**.

Такой отчёт — это не один гигантский запрос. Это **скрипт** (script): несколько запросов подряд, каждый из которых отвечает на один вопрос. База данных выполняет их один за другим и по очереди выводит результаты. Когда каталог меняется, вы просто запускаете скрипт заново, и весь отчёт обновляется.

## Планируем отчёт

Прежде чем писать SQL, решите, что показывает каждый раздел и какие инструменты для него нужны:

| Раздел               | На какой вопрос отвечает                          | Инструменты                             |
| -------------------- | ------------------------------------------------- | --------------------------------------- |
| 1. Общая картина     | Насколько большой каталог?                        | `count`, `count(DISTINCT …)`, `avg`, `sum` |
| 2. Лучшая тройка     | У каких фильмов самый высокий рейтинг?            | Соединение текста, `ORDER BY … DESC`, `LIMIT` |
| 3. Жанры             | Какие жанры удаются клубу лучше всего?            | `GROUP BY`, `HAVING`, `round`           |
| 4. Фильм на сегодня  | Что смотрим и когда закончится?                   | `WHERE`, функции, `LIMIT 1`             |

## Разделы 1 и 2: главное

Подпишите каждый раздел **комментарием** (comment): всё, что стоит в строке после `--`, база данных игнорирует, а людям это подсказывает, что будет дальше. Вот первые два раздела в одном скрипте:

<CodeExample output={` films | directors | genres | avg_rating | total_hours
-------+-----------+--------+------------+-------------
    12 |         5 |      8 |       7.21 |        21.3
(1 row)

             film              | rating
-------------------------------+--------
 The Quiet Algorithm (2024)    |    8.4
 Midnight in the Forest (2015) |    8.1
 Mountain of Echoes (2016)     |    7.9
(3 rows)`}>

```sql
-- 1. Каталог в общих чертах
SELECT count(*) AS films,
  count(DISTINCT director) AS directors,
  count(DISTINCT genre) AS genres,
  round(avg(rating), 2) AS avg_rating,
  round(sum(minutes) / 60.0, 1) AS total_hours
FROM movies;

-- 2. Лучшая тройка
SELECT title || ' (' || year || ')' AS film, rating
FROM movies
ORDER BY rating DESC, title
LIMIT 3;
```

</CodeExample>

`count(DISTINCT director)` считает **разных** режиссёров: фильмов 12, но сняли их всего 5 человек. Каждый `SELECT` заканчивается на `;`, и результаты выводятся в том же порядке, что и запросы.

## Немного занимательных фактов

Клуб любит начинать встречу с пары забавных фактов. Функции работают не только в `SELECT`, но и в `ORDER BY`, поэтому «самое длинное название» — это просто сортировка по `length(title)`:

<CodeExample output={`         title          | letters
------------------------+---------
 Midnight in the Forest |      22
(1 row)

         title         | minutes
-----------------------+---------
 The Great Bamboo Race |      88
(1 row)`}>

```sql
SELECT title, length(title) AS letters
FROM movies
ORDER BY letters DESC, title
LIMIT 1;

SELECT title, minutes
FROM movies
ORDER BY minutes, title
LIMIT 1;
```

</CodeExample>

`ORDER BY … LIMIT 1` — классический способ найти **ту самую** строку с наибольшим или наименьшим значением. Дополнительный критерий (`title`) решает, какая строка победит, если у двух фильмов значения совпадут.

## Раздел 4: фильм на сегодня

Правило клуба для киновечера простое: **фильм с самым высоким рейтингом, который идёт 110 минут или меньше**, чтобы все вовремя добрались домой. Фильм начинается в **19:00**, и участники хотят знать, когда он закончится. Именно это и делает прибавление интервала `interval` ко времени `time`:

<CodeExample output={`     tonight      | runtime | ends_at
------------------+---------+----------
 THE BAMBOO HEIST | 1h 44m  | 20:44:00
(1 row)`}>

```sql
SELECT upper(title) AS tonight,
  concat(minutes / 60, 'h ', minutes % 60, 'm') AS runtime,
  time '19:00' + minutes * interval '1 minute' AS ends_at
FROM movies
WHERE minutes <= 110
ORDER BY rating DESC, title
LIMIT 1;
```

</CodeExample>

`minutes * interval '1 minute'` превращает 104 в интервал длиной 104 минуты, а 19:00 плюс 1 час 44 минуты — это 20:44. И наконец, строка-приглашение для чата клуба с датой встречи из Части 2:

<CodeExample output={`              invitation
---------------------------------------
 Movie night: Friday 14 November, 7 pm
(1 row)`}>

```sql
SELECT 'Movie night: ' || to_char(date '2025-11-14', 'FMDay DD FMMonth')
  || ', 7 pm' AS invitation;
```

</CodeExample>

`SELECT` не всегда нужен `FROM`: здесь он просто вычисляет одно значение.

<Callout type="warning" title="Никогда не вписывайте ответ в отчёт вручную">

Когда ответ уже известен, так и тянет написать `SELECT 12 AS films;`. Не надо! В следующем месяце клуб добавит фильмы, и отчёт будет незаметно выводить устаревшее число. Каждое значение в отчёте должно **вычисляться из таблицы** — тогда повторный запуск скрипта всегда покажет актуальную картину.

</Callout>

<Callout type="tip" title="Проверяйте на других данных">

Полезная привычка: представьте, что каталог изменился. Выберет ли ваш запрос правильный фильм, если появится новая драма с рейтингом 8.0 на 99 минут? Сработает ли он, если у двух фильмов окажется одинаковый рейтинг? Запросы с понятными фильтрами, дополнительным критерием в `ORDER BY` и без вписанных вручную ответов проходят эту проверку.

</Callout>

Напишите отчёт клуба в виде **четырёх запросов, именно в таком порядке**. Используйте ровно эти имена столбцов:

1. **Общая картина**: одна строка с `films` (сколько фильмов), `directors` (сколько *разных* режиссёров), `avg_rating` (округлён до 2 знаков) и `total_hours` (все минуты в часах, округлено до 1 знака).
2. **Лучшая тройка**: `film` в виде `The Quiet Algorithm (2024)` и `rating` для трёх фильмов с самым высоким рейтингом, сначала лучший (при равенстве — по названию).
3. **Жанры**: `genre`, `films` и `avg_rating` (округлён до 1 знака) для жанров, в которых **не меньше 2 фильмов**, сначала самый высокий средний рейтинг, затем по жанру.
4. **Фильм на сегодня**: одна строка с `film` (в виде `The Bamboo Heist (2019)`), `runtime` (в виде `1h 44m`) и `rating` для фильма с самым высоким рейтингом, который идёт **110 минут или меньше** (при равенстве — по названию).

Последний запрос должен вычислять ответ: проверки добавляют новые фильмы и запускают его заново.

<Hint>

Большинство частей есть в этом уроке и в Части 2. Для часов делите на `60.0`, чтобы не потерять дробную часть: `round(sum(minutes) / 60.0, 1)`. Для жанров — `GROUP BY genre` с `HAVING count(*) >= 2`. Для фильма на сегодня отфильтруйте с помощью `WHERE minutes <= 110`, отсортируйте с помощью `ORDER BY rating DESC, title` и оставьте одну строку с помощью `LIMIT 1`.

</Hint>

<Solution>

```sql
-- 1. Общая картина
SELECT count(*) AS films,
  count(DISTINCT director) AS directors,
  round(avg(rating), 2) AS avg_rating,
  round(sum(minutes) / 60.0, 1) AS total_hours
FROM movies;

-- 2. Лучшая тройка
SELECT title || ' (' || year || ')' AS film, rating
FROM movies
ORDER BY rating DESC, title
LIMIT 3;

-- 3. Жанры, в которых не меньше двух фильмов
SELECT genre,
  count(*) AS films,
  round(avg(rating), 1) AS avg_rating
FROM movies
GROUP BY genre
HAVING count(*) >= 2
ORDER BY avg_rating DESC, genre;

-- 4. Фильм на сегодня
SELECT title || ' (' || year || ')' AS film,
  concat(minutes / 60, 'h ', minutes % 60, 'm') AS runtime,
  rating
FROM movies
WHERE minutes <= 110
ORDER BY rating DESC, title
LIMIT 1;
```

</Solution>
