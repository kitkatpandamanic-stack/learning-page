Time to finish the project! 🎉 The club's organiser wants a **movie night report** to share before each meeting: the catalogue at a glance, the top films, how the genres compare and, most importantly, **tonight's film**.

A report like this isn't one giant query. It's a **script**: several queries in a row, each answering one question. The database runs them one after another and prints each result in turn. When the catalogue changes, you simply run the script again and the whole report updates.

## Planning the report

Before writing SQL, decide what each section shows and which tools it needs:

| Section            | Question it answers                               | Tools                                   |
| ------------------ | ------------------------------------------------- | --------------------------------------- |
| 1. At a glance     | How big is the catalogue?                         | `count`, `count(DISTINCT …)`, `avg`, `sum` |
| 2. The top three   | Which films are rated highest?                    | Joining text, `ORDER BY … DESC`, `LIMIT` |
| 3. Genres          | Which genres does the club do best?               | `GROUP BY`, `HAVING`, `round`           |
| 4. Tonight's film  | What do we watch, and when does it end?           | `WHERE`, functions, `LIMIT 1`           |

## Sections 1 and 2: the headline

Label each section with a **comment**: anything after `--` on a line is ignored by the database, but it tells human readers what comes next. Here are the first two sections as one script:

<CodeExample output={` films | directors | genres | avg_rating | total_hours
-------+-----------+--------+------------+-------------
    12 |         5 |      8 |       7.21 |        21.3
(1 row)

             film              | rating
-------------------------------+--------
 The Quiet Algorithm (2024)    |    8.4
 Midnight in the Forest (2015) |    8.1
 Mountain of Echoes (2016)     |    7.9
(3 rows)`}>

```sql
-- 1. The catalogue at a glance
SELECT count(*) AS films,
  count(DISTINCT director) AS directors,
  count(DISTINCT genre) AS genres,
  round(avg(rating), 2) AS avg_rating,
  round(sum(minutes) / 60.0, 1) AS total_hours
FROM movies;

-- 2. The top three
SELECT title || ' (' || year || ')' AS film, rating
FROM movies
ORDER BY rating DESC, title
LIMIT 3;
```

</CodeExample>

`count(DISTINCT director)` counts **different** directors: 12 films, but only 5 people made them. Each `SELECT` ends with `;`, and the results print in the same order as the queries.

## A little trivia

The club likes to open with a fun fact or two. Functions work inside `ORDER BY` as well as `SELECT`, so "the longest title" is just a sort by `length(title)`:

<CodeExample output={`         title          | letters
------------------------+---------
 Midnight in the Forest |      22
(1 row)

         title         | minutes
-----------------------+---------
 The Great Bamboo Race |      88
(1 row)`}>

```sql
SELECT title, length(title) AS letters
FROM movies
ORDER BY letters DESC, title
LIMIT 1;

SELECT title, minutes
FROM movies
ORDER BY minutes, title
LIMIT 1;
```

</CodeExample>

`ORDER BY … LIMIT 1` is the classic way to find **the** row with the biggest or smallest value. The tie-breaker (`title`) decides which row wins if two films ever tie.

## Section 4: tonight's film

The club's rule for movie night is simple: **the highest-rated film that runs 110 minutes or less**, so everyone gets home on time. The film starts at **7 pm**, and members want to know when it ends. Adding an `interval` to a `time` does exactly that:

<CodeExample output={`     tonight      | runtime | ends_at
------------------+---------+----------
 THE BAMBOO HEIST | 1h 44m  | 20:44:00
(1 row)`}>

```sql
SELECT upper(title) AS tonight,
  concat(minutes / 60, 'h ', minutes % 60, 'm') AS runtime,
  time '19:00' + minutes * interval '1 minute' AS ends_at
FROM movies
WHERE minutes <= 110
ORDER BY rating DESC, title
LIMIT 1;
```

</CodeExample>

`minutes * interval '1 minute'` turns 104 into an interval of 104 minutes, and 19:00 plus 1 hour 44 minutes is 20:44. Finally, the invitation line for the club's chat, using the meeting date from Part 2:

<CodeExample output={`              invitation
---------------------------------------
 Movie night: Friday 14 November, 7 pm
(1 row)`}>

```sql
SELECT 'Movie night: ' || to_char(date '2025-11-14', 'FMDay DD FMMonth')
  || ', 7 pm' AS invitation;
```

</CodeExample>

A `SELECT` doesn't always need a `FROM`: here it just calculates one value.

<Callout type="warning" title="Never type the answer into the report">

It's tempting to write `SELECT 12 AS films;` once you know the answer. Don't! Next month the club adds films, and the report would quietly print an old number. Every value in a report should be **calculated from the table**, so running the script again always gives the current truth.

</Callout>

<Callout type="tip" title="Test with different data">

A good habit: imagine the catalogue changes. Would your query still pick the right film if a new 8.0-rated, 99-minute drama arrived? Would it still work if two films tied? Queries with clear filters, a tie-breaker in `ORDER BY` and no typed-in answers pass that test.

</Callout>

Write the club's report as **four queries, in this order**. Use exactly these column names:

1. **At a glance**: one row with `films` (how many), `directors` (how many *different* directors), `avg_rating` (rounded to 2 decimals) and `total_hours` (all minutes in hours, rounded to 1 decimal).
2. **The top three**: `film` written like `The Quiet Algorithm (2024)`, and `rating`, for the three highest-rated films, best first (ties by title).
3. **Genres**: `genre`, `films` and `avg_rating` (rounded to 1 decimal) for genres with **at least 2 films**, highest average first, then by genre.
4. **Tonight's film**: one row with `film` (like `The Bamboo Heist (2019)`), `runtime` (like `1h 44m`) and `rating`, for the highest-rated film that runs **110 minutes or less** (ties by title).

The last query must calculate its answer: the checks add new films and run it again.

<Hint>

Most of the pieces are in this lesson and Part 2. For the hours, divide by `60.0` so the fraction isn't lost: `round(sum(minutes) / 60.0, 1)`. For the genres, `GROUP BY genre` with `HAVING count(*) >= 2`. For tonight's film, filter with `WHERE minutes <= 110`, sort with `ORDER BY rating DESC, title` and keep one row with `LIMIT 1`.

</Hint>

<Solution>

```sql
-- 1. At a glance
SELECT count(*) AS films,
  count(DISTINCT director) AS directors,
  round(avg(rating), 2) AS avg_rating,
  round(sum(minutes) / 60.0, 1) AS total_hours
FROM movies;

-- 2. The top three
SELECT title || ' (' || year || ')' AS film, rating
FROM movies
ORDER BY rating DESC, title
LIMIT 3;

-- 3. Genres with at least two films
SELECT genre,
  count(*) AS films,
  round(avg(rating), 1) AS avg_rating
FROM movies
GROUP BY genre
HAVING count(*) >= 2
ORDER BY avg_rating DESC, genre;

-- 4. Tonight's film
SELECT title || ' (' || year || ')' AS film,
  concat(minutes / 60, 'h ', minutes % 60, 'm') AS runtime,
  rating
FROM movies
WHERE minutes <= 110
ORDER BY rating DESC, title
LIMIT 1;
```

</Solution>

</Exercise>

## Recap

You've finished Level 0 of SQL! 🏆 In this project you:

- **explored** a table before answering questions about it,
- **filtered** and **sorted** with `WHERE`, `ORDER BY` (with tie-breakers) and `LIMIT`,
- **calculated** runtimes, labels, ages and times with operators and functions,
- **summarised** with aggregates, `GROUP BY` and `HAVING`,
- and combined it all into a **report script** that recalculates everything each time it runs.

So far every answer came from one table. Real databases spread information across many tables: orders in one, customers in another. In Level 1 you'll learn to combine them, starting with [inner joins](/learn/sql/inner-join).
