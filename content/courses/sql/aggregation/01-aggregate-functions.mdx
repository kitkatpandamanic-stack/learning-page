Until now, every query gave you **rows**: one result row for each row in the table that matched. But many questions want a **single answer** about lots of rows: How many customers do we have? What's our stock worth? What's the most expensive product? 🔢

For those you use **aggregate functions**. An aggregate function takes a whole column of values, from many rows, and squeezes them into **one** value. In this module you'll learn to count, add up and average your data, then group it and filter the groups.

## Counting rows with count(*)

**`count(*)`** counts rows. The `*` means "whole rows", so it doesn't care what's in them:

<CodeExample output={` customers
-----------
        20
(1 row)`}>

```sql
SELECT count(*) AS customers
FROM customers;
```

</CodeExample>

Twenty customers, one row of result. Combine it with `WHERE` to count only some rows: `WHERE` picks the rows **first**, then `count(*)` counts what's left.

<CodeExample output={` uk_customers
--------------
            4
(1 row)`}>

```sql
SELECT count(*) AS uk_customers
FROM customers
WHERE country = 'UK';
```

</CodeExample>

## count(column) skips NULLs

You can also put a column in the brackets. **`count(column)`** counts only the rows where that column is **not `NULL`**. Two customers have no city, so:

<CodeExample output={` customers | with_a_city | without_a_city
-----------+-------------+----------------
        20 |          18 |              2
(1 row)`}>

```sql
SELECT
  count(*) AS customers,
  count(city) AS with_a_city,
  count(*) - count(city) AS without_a_city
FROM customers;
```

</CodeExample>

That makes `count(column)` a quick way to check how complete your data is.

## Counting different values: count(DISTINCT ...)

How many **countries** do our customers come from? `count(country)` would give 20, because it counts every customer. Put **`DISTINCT`** in front of the column to count each different value only once:

<CodeExample output={` rows_with_country | countries | cities
-------------------+-----------+--------
                20 |        15 |     16
(1 row)`}>

```sql
SELECT
  count(country) AS rows_with_country,
  count(DISTINCT country) AS countries,
  count(DISTINCT city) AS cities
FROM customers;
```

</CodeExample>

16 cities, not 18: London and Moscow appear twice each, and the two missing cities (`NULL`s) aren't counted at all.

## Adding up and averaging: sum and avg

**`sum(column)`** adds up all the values, and **`avg(column)`** calculates the average (the sum divided by how many values there are). Both work on numbers, and on expressions too: `sum(price * stock)` multiplies on every row first, then adds up the results.

<CodeExample output={` units_in_stock | stock_value |    average_price    | average_rounded
----------------+-------------+---------------------+-----------------
            585 |     3584.25 | 18.1320000000000000 |           18.13
(1 row)`}>

```sql
SELECT
  sum(stock) AS units_in_stock,
  sum(price * stock) AS stock_value,
  avg(price) AS average_price,
  round(avg(price), 2) AS average_rounded
FROM products;
```

</CodeExample>

`avg` gives back a long, exact decimal, so you'll almost always wrap it in `round(..., 2)`, just like in [the numbers lesson](/learn/sql/number-functions).

## Smallest and largest: min and max

**`min(column)`** and **`max(column)`** find the smallest and largest value. They work on numbers, but also on **dates** (earliest and latest) and **text** (first and last in alphabetical order). A script can hold several queries; each one prints its own result:

<CodeExample output={` cheapest | priciest
----------+----------
     2.50 |    89.90
(1 row)

 first_joined | last_joined | first_alphabetically
--------------+-------------+----------------------
 2024-01-15   | 2025-01-05  | Ada Brooks
(1 row)`}>

```sql
SELECT min(price) AS cheapest, max(price) AS priciest
FROM products;

SELECT
  min(joined_on) AS first_joined,
  max(joined_on) AS last_joined,
  min(name) AS first_alphabetically
FROM customers;
```

</CodeExample>

## Several aggregates at once

You can calculate as many aggregates as you like in one query. Here's a quick health check of everything ever sold, from the `order_items` table (one row per product in an order):

<CodeExample output={` order_lines | orders | units_sold | revenue | average_line
-------------+--------+------------+---------+--------------
          80 |     40 |        160 | 2809.32 |        35.12
(1 row)`}>

```sql
SELECT
  count(*) AS order_lines,
  count(DISTINCT order_id) AS orders,
  sum(quantity) AS units_sold,
  sum(quantity * unit_price) AS revenue,
  round(avg(quantity * unit_price), 2) AS average_line
FROM order_items;
```

</CodeExample>

<Callout type="note" title="Aggregates ignore NULL">

`sum`, `avg`, `min`, `max` and `count(column)` all **skip `NULL` values**. That's usually what you want, but watch out with `avg`: the average of `10`, `NULL` and `20` is `15` (two values), not `10` (three values with the gap counted as zero). If a missing value really means zero, say so with `avg(coalesce(column, 0))`.

</Callout>

## When no rows match

What happens if `WHERE` leaves no rows at all? `count` says `0`, but the others have nothing to work with, so they return `NULL`:

<CodeExample output={` products | units | units_or_zero | priciest
----------+-------+---------------+----------
        0 |  NULL |             0 |     NULL
(1 row)`}>

```sql
SELECT
  count(*) AS products,
  sum(stock) AS units,
  coalesce(sum(stock), 0) AS units_or_zero,
  max(price) AS priciest
FROM products
WHERE category = 'garden';
```

</CodeExample>

`coalesce(sum(...), 0)` turns that `NULL` into a friendlier `0`. Notice that an aggregate query **without** `GROUP BY` always returns exactly one row, even when the table is empty.

## Mixing aggregates and plain columns

Here's a mistake everybody makes once. "Show each product's name and how many products there are":

<CodeExample output={`ERROR:  column "products.name" must appear in the GROUP BY clause or be used in an aggregate function
LINE 1: SELECT name, count(*) AS products
               ^`}>

```sql
SELECT name, count(*) AS products
FROM products;
```

</CodeExample>

Think about it: `count(*)` squeezes 15 rows into **one** value, but there are 15 different names. Which name should go next to the count? PostgreSQL can't know, so it refuses. In the next lesson you'll learn what the error message suggests: **`GROUP BY`**, which gives you one result row per group, for example one count **per category**.

Try a few aggregates of your own: the average film rating, the longest film, the number of directors…

<TryIt language="sql" code={`SELECT
  count(*) AS films,
  count(DISTINCT director) AS directors,
  round(avg(rating), 2) AS average_rating,
  max(minutes) AS longest,
  min(year) AS oldest
FROM movies;`}
/>

The finance team wants a one-line payroll summary of the `employees` table. 💰 Write a query that returns **one row** with these columns, in this order:

- **`people`**: how many employees there are,
- **`departments`**: how many **different** departments they work in (the CEO has no department, and a `NULL` shouldn't count as a department),
- **`payroll`**: all salaries added up,
- **`average_salary`**: the average salary, rounded to a whole number,
- **`lowest`** and **`highest`**: the smallest and largest salary.

<Hint>

All six columns are aggregates over the whole table, so there's no `WHERE` and no `GROUP BY`. Use `count(*)`, `count(DISTINCT department_id)` (it skips `NULL` by itself), `sum(salary)`, `round(avg(salary))`, `min(salary)` and `max(salary)`, each with an `AS` name.

</Hint>

<Solution>

```sql
SELECT
  count(*) AS people,
  count(DISTINCT department_id) AS departments,
  sum(salary) AS payroll,
  round(avg(salary)) AS average_salary,
  min(salary) AS lowest,
  max(salary) AS highest
FROM employees;
```

</Solution>

## Recap

- **Aggregate functions** turn many rows into one value. Without `GROUP BY`, an aggregate query returns exactly one row.
- **`count(*)`** counts rows; **`count(column)`** counts non-`NULL` values; **`count(DISTINCT column)`** counts different values.
- **`sum`** adds up, **`avg`** averages (wrap it in `round`), **`min`** and **`max`** find the extremes of numbers, dates and text.
- `WHERE` filters rows **before** they're aggregated.
- Aggregates skip `NULL`s. With no rows, `count` gives `0` and the others give `NULL`: use `coalesce(sum(x), 0)`.
- You can't mix plain columns with aggregates like `SELECT name, count(*)`: that's what `GROUP BY` is for.
