В настоящем магазине может быть миллион товаров, но на главной странице показаны **3 хита продаж**, а в каталоге — **20 товаров на страницу**. Все строки сразу нужны редко. В этом уроке вы научитесь обрезать результат до нужного размера с `LIMIT`, пропускать строки с `OFFSET` и объединять их, чтобы показывать результаты **по одной странице за раз**.

## LIMIT: только первые несколько строк

**`LIMIT n`** оставляет первые `n` строк результата. Вместе с `ORDER BY` он отвечает на вопросы вида **«топ-N»** (top-N), например: «Какие 3 товара у нас самые дорогие?»:

<CodeExample output={`          name          | price
------------------------+-------
 Rice Cooker            | 89.90
 Tea Pot                | 32.00
 Algorithms in Pictures | 29.00
(3 rows)`}>

```sql
SELECT name, price
FROM products
ORDER BY price DESC
LIMIT 3;
```

</CodeExample>

`LIMIT` пишется в самом **конце** запроса, после `ORDER BY`. Сначала база данных сортирует все строки, а затем оставляет первые три.

`LIMIT 1` находит «самое большое» или «самое маленькое». Какой фильм самый длинный?

<CodeExample output={`        title        | minutes
---------------------+---------
 The Quiet Algorithm |     131
(1 row)`}>

```sql
SELECT title, minutes
FROM movies
ORDER BY minutes DESC
LIMIT 1;
```

</CodeExample>

А вот 5 самых новых покупателей:

<CodeExample output={`    name     | joined_on
-------------+------------
 Nina Novak  | 2025-01-05
 Tom Baker   | 2024-12-12
 Grace Kim   | 2024-11-23
 Ivan Petrov | 2024-11-04
 Emma Wilson | 2024-10-16
(5 rows)`}>

```sql
SELECT name, joined_on
FROM customers
ORDER BY joined_on DESC
LIMIT 5;
```

</CodeExample>

Если строк в результате меньше, чем лимит, вы просто получите их все: `LIMIT 10` для трёх видов чая вернёт 3 строки, а не ошибку.

<Callout type="warning" title="LIMIT без ORDER BY">

`SELECT * FROM products LIMIT 3;` выполнится без ошибок, но какие именно 3 строки вы получите, решает база данных. «Первые» имеет смысл только после сортировки. Всегда используйте `LIMIT` вместе с `ORDER BY`.

</Callout>

## OFFSET: пропускаем строки

**`OFFSET n`** пропускает первые `n` строк результата. «4-й, 5-й и 6-й по дороговизне товары» означает: отсортировать, пропустить 3, оставить 3:

<CodeExample output={`     name     | price
--------------+-------
 Clean Python | 24.99
 Plush Panda  | 18.00
 Kite         | 15.00
(3 rows)`}>

```sql
SELECT name, price
FROM products
ORDER BY price DESC
LIMIT 3 OFFSET 3;
```

</CodeExample>

## Листаем результаты по страницам

Вместе `LIMIT` и `OFFSET` позволяют показывать длинный список **по одной странице** — как кнопка «Следующая страница» в интернет-магазине. Это называется **постраничным выводом** (pagination). Если на каждой странице `size` строк, то для страницы с номером `page` нужно:

```text
LIMIT  size
OFFSET (page - 1) * size
```

При 5 товарах на странице: страница 1 пропускает 0 строк, страница 2 — 5, страница 3 — 10. Вот страницы 2 и 3 каталога, отсортированного по названию:

<CodeExample output={` id |     name      | price
----+---------------+-------
  1 | Jasmine Tea   |  6.50
 12 | Kite          | 15.00
  2 | Matcha Powder | 14.00
  5 | Panda Cookies |  3.75
 10 | Plush Panda   | 18.00
(5 rows)

 id |      name       | price
----+-----------------+-------
 15 | Rice Cooker     | 89.90
  6 | Rice Crackers   |  2.50
 13 | Tea Pot         | 32.00
  7 | The Bamboo Code | 12.50
 11 | Wooden Puzzle   | 11.40
(5 rows)`}>

```sql
-- Страница 2
SELECT id, name, price
FROM products
ORDER BY name
LIMIT 5 OFFSET 5;

-- Страница 3
SELECT id, name, price
FROM products
ORDER BY name
LIMIT 5 OFFSET 10;
```

</CodeExample>

В магазине 15 товаров, поэтому страница 4 (`OFFSET 15`) вернулась бы пустой: `(0 rows)`. Так приложение понимает, что кнопку «Далее» показывать не нужно.

### Страницам нужен предсказуемый порядок

Постраничный вывод работает, только если порядок **в точности одинаковый** при каждом запросе. Посмотрите, что происходит со страницами по 2 товара, отсортированными только по `category`. Книг три, и у всех одинаковая `category`, то есть между ними ничья:

<CodeExample output={`          name          | category
------------------------+----------
 The Bamboo Code        | books
 Algorithms in Pictures | books
(2 rows)

      name       | category
-----------------+----------
 The Bamboo Code | books
 Tea Pot         | kitchen
(2 rows)`}>

```sql
-- Страница 1
SELECT name, category
FROM products
ORDER BY category
LIMIT 2;

-- Страница 2
SELECT name, category
FROM products
ORDER BY category
LIMIT 2 OFFSET 2;
```

</CodeExample>

*The Bamboo Code* попала на **обе** страницы, а *Clean Python* — **ни на одну**! При ничьей база данных может расставить такие строки в любом порядке, а каждая страница — это отдельный запрос, поэтому каждый раз порядок может оказаться другим. Решение — разрешение ничьей из прошлого урока: завершайте сортировку чем-то уникальным, например `id`:

<CodeExample output={`     name     | category
--------------+----------
 Clean Python | books
 Tea Pot      | kitchen
(2 rows)`}>

```sql
SELECT name, category
FROM products
ORDER BY category, id
LIMIT 2 OFFSET 2;
```

</CodeExample>

Теперь порядок зафиксирован: на странице 1 — книги с двумя наименьшими `id`, а страница 2 продолжает ровно с того места, где закончилась первая.

<Callout type="tip" title="Большие OFFSET работают медленно">

Чтобы выполнить `OFFSET 100000`, базе данных всё равно нужно найти и выбросить 100 000 строк. Для маленьких таблиц это нормально, для огромных — медленно. Большие сайты используют более быстрый приём — **пагинацию по ключу** (keyset pagination: «дай следующие 20 после последней, которую я видел»). С ней вы познакомитесь в модуле «Индексы и производительность».

</Callout>

## FETCH FIRST: стандартный способ

В большинстве кода для PostgreSQL используют `LIMIT`, но он не входит в официальный стандарт SQL. По стандарту то же самое записывается через **`FETCH FIRST`**. Его понимает и PostgreSQL, и многие другие базы данных, например Oracle и Db2:

<CodeExample output={`          name          | price
------------------------+-------
 Rice Cooker            | 89.90
 Tea Pot                | 32.00
 Algorithms in Pictures | 29.00
(3 rows)`}>

```sql
SELECT name, price
FROM products
ORDER BY price DESC
FETCH FIRST 3 ROWS ONLY;
```

</CodeExample>

Со смещением это читается как английское предложение: `OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY` («пропустить 3 строки, взять следующие 3 строки»). `FIRST` и `NEXT` означают одно и то же, как и `ROW` и `ROWS`.

### WITH TIES

У `FETCH FIRST` есть приём, которого нет у `LIMIT`. Какого товара на складе меньше всего? У двух товаров ничья — по 0 штук, но `LIMIT 1` оставляет только один из них:

<CodeExample output={`   name    | stock
-----------+-------
 Earl Grey |     0
(1 row)

     name     | stock
--------------+-------
 Clean Python |     0
 Earl Grey    |     0
(2 rows)`}>

```sql
SELECT name, stock
FROM products
ORDER BY stock
LIMIT 1;

SELECT name, stock
FROM products
ORDER BY stock
FETCH FIRST 1 ROW WITH TIES;
```

</CodeExample>

**`WITH TIES`** дополнительно оставляет все строки, у которых ничья с последней. Это честнее для вопросов вроде «У кого самый высокий балл?», когда первое место могут разделить двое.

На странице «Скидки» магазин показывает товары от **самого дешёвого** до самого дорогого, **по 4 товара на страницу**. Напишите запрос для **страницы 2**: покажите `name` и `price`.

<Hint>

Отсортируйте по `price` (сначала дешёвые — это порядок по умолчанию). На каждой странице 4 строки, значит, `LIMIT 4`. Страница 2 пропускает всю страницу 1: `OFFSET (2 - 1) * 4`, то есть 4.

</Hint>

<Solution>

```sql
SELECT name, price
FROM products
ORDER BY price
LIMIT 4 OFFSET 4;
```

</Solution>

## Итоги

- `LIMIT n` оставляет первые `n` строк; вместе с `ORDER BY` он отвечает на вопросы «топ-N».
- `OFFSET n` пропускает первые `n` строк. Для страницы `p` размером `s`: `LIMIT s OFFSET (p - 1) * s`.
- Всегда используйте `ORDER BY` вместе с `LIMIT` и завершайте сортировку уникальным столбцом, чтобы страницы не пересекались и не теряли строки.
- `FETCH FIRST n ROWS ONLY` — версия `LIMIT` из стандарта SQL; `WITH TIES` дополнительно оставляет строки с ничьей с последней.
- На больших таблицах большие смещения работают медленно; более быстрая альтернатива — пагинация по ключу.
