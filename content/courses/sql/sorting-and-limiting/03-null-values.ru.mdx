В реальных данных бывают пробелы. Покупатель при регистрации не заполнил поле «город», а у руководителя компании нет начальника. SQL обозначает отсутствующее значение особым значением **`NULL`**. NULL ведёт себя не так, как все остальные значения, и именно из-за него часто возникает вопрос «почему мой результат неправильный?». После этого урока NULL вас врасплох не застанет. 🕵️

## Что означает NULL

`NULL` означает **«неизвестно»** или **«здесь нет значения»**. У двух покупателей в учебной базе данных не указан город:

<CodeExample output={`    name     |    city    | country
-------------+------------+---------
 Mei Lin     | London     | UK
 Ada Brooks  | London     | UK
 Omar Haddad | NULL       | Egypt
 Zara Khan   | NULL       | UK
 Tom Baker   | Manchester | UK
(5 rows)`}>

```sql
SELECT name, city, country
FROM customers
WHERE country IN ('UK', 'Egypt')
ORDER BY id;
```

</CodeExample>

NULL — это **не** то же самое, что `0`, и не то же самое, что пустой текст `''`. Ноль — это известное нам число; пустой текст — это текст, про который мы знаем, что он пуст. А NULL говорит: «мы не знаем».

<Callout type="note" title="Как отображается NULL">

На этом сайте отсутствующие значения выводятся как `NULL`, чтобы их было легко заметить. В собственной консольной программе PostgreSQL, `psql`, по умолчанию они выглядят как **пустая ячейка**, и их легко спутать с пустым текстом.

</Callout>

## Почему = NULL ничего не находит

Найдём покупателей без города. Запрос выглядит правильным, но ничего не возвращает:

<CodeExample output={` name | city
------+------
(0 rows)`}>

```sql
SELECT name, city
FROM customers
WHERE city = NULL;
```

</CodeExample>

Думайте о NULL как о «неизвестно». Равен ли неизвестный город неизвестному значению? Этого никто не знает, поэтому ответ — ни «истина», ни «ложь», а тоже **«неизвестно»**. Любое сравнение с NULL (`=`, `<>`, `<`, `>`…) даёт NULL:

<CodeExample output={`  a   |  b   |  c   | d
------+------+------+---
 NULL | NULL | NULL | t
(1 row)`}>

```sql
SELECT NULL = NULL AS a,
  1 = NULL AS b,
  NULL <> 'London' AS c,
  NULL IS NULL AS d;
```

</CodeExample>

(PostgreSQL выводит **истину** (true) как `t`, а **ложь** (false) как `f`.) `WHERE` оставляет только строки, для которых условие **истинно**, поэтому `city = NULL` никогда ничего не оставляет.

## IS NULL и IS NOT NULL

Чтобы проверить, отсутствует ли значение, используйте специальные операторы **`IS NULL`** и **`IS NOT NULL`**. Они всегда отвечают обычным «истина» или «ложь»:

<CodeExample output={`    name     | city | country
-------------+------+---------
 Omar Haddad | NULL | Egypt
 Zara Khan   | NULL | UK
(2 rows)

     name     | job_title
--------------+-----------
 Grace Hopper | CEO
(1 row)`}>

```sql
SELECT name, city, country
FROM customers
WHERE city IS NULL
ORDER BY name;

-- У кого нет руководителя?
SELECT name, job_title
FROM employees
WHERE manager_id IS NULL;
```

</CodeExample>

`WHERE city IS NOT NULL` вернёт остальных 18 покупателей.

## Трёхзначная логика

Из-за NULL у условия в SQL может быть **три** результата: **истина**, **ложь** или **неизвестно** (NULL). Это называется **трёхзначной логикой** (three-valued logic). `AND`, `OR` и `NOT` подчиняются здравому смыслу, если читать NULL как «неизвестно»:

| Выражение         | Результат | Почему                                         |
| ----------------- | --------- | ---------------------------------------------- |
| `TRUE AND NULL`   | NULL      | зависит от неизвестной части                   |
| `FALSE AND NULL`  | `false`   | ложь, что бы ни скрывалось за неизвестным      |
| `TRUE OR NULL`    | `true`    | истина, что бы ни скрывалось за неизвестным    |
| `FALSE OR NULL`   | NULL      | зависит от неизвестной части                   |
| `NOT NULL`        | NULL      | противоположность неизвестного — тоже неизвестно |

В реальных запросах это важно. Какие покупатели из UK живут **не** в Лондоне?

<CodeExample output={`   name    |    city
-----------+------------
 Tom Baker | Manchester
(1 row)`}>

```sql
SELECT name, city
FROM customers
WHERE country = 'UK' AND city <> 'London'
ORDER BY name;
```

</CodeExample>

Пропала Зара Хан (Zara Khan)! Её город — NULL, поэтому `city <> 'London'` даёт «неизвестно», и `WHERE` её отбрасывает. Правильно это или нет, зависит от вопроса. Если «не известно, что живёт в Лондоне» должно её включать, скажите об этом явно:

<CodeExample output={`   name    |    city
-----------+------------
 Tom Baker | Manchester
 Zara Khan | NULL
(2 rows)`}>

```sql
SELECT name, city
FROM customers
WHERE country = 'UK'
  AND (city <> 'London' OR city IS NULL)
ORDER BY name;
```

</CodeExample>

Для этого в PostgreSQL есть и сокращение: `city IS DISTINCT FROM 'London'` считает NULL обычным значением, поэтому для Зары оно тоже истинно.

<Callout type="warning" title="Ловушка NOT IN">

`3 NOT IN (1, 2, NULL)` — не истина! Это означает `3 <> 1 AND 3 <> 2 AND 3 <> NULL`, а последняя часть неизвестна, поэтому и всё выражение неизвестно. Если в списке `NOT IN` (или, позже, в подзапросе) есть NULL, `NOT IN` не совпадает **ни с чем**. Не допускайте NULL в списках `NOT IN`.

</Callout>

## NULL в вычислениях

Арифметика с неизвестным значением даёт неизвестный ответ. Если какая-то часть выражения равна NULL, результат обычно тоже NULL:

<CodeExample output={` sum_result | product
------------+---------
       NULL |    NULL
(1 row)`}>

```sql
SELECT 1 + NULL AS sum_result, NULL * 10 AS product;
```

</CodeExample>

Поэтому `price * stock` дал бы NULL для любого товара, у которого не указано количество на складе. А когда в модуле «Подсчёт и группировка» вы будете складывать значения функциями вроде `sum()`, то увидите, что они, наоборот, **пропускают** NULL.

## COALESCE: запасное значение вместо пропуска

**`coalesce(a, b, ...)`** возвращает **первое значение, которое не NULL**. Это стандартный способ показать запасное значение вместо NULL:

<CodeExample output={`    name     |    city
-------------+------------
 Mei Lin     | London
 Ada Brooks  | London
 Omar Haddad | unknown
 Zara Khan   | unknown
 Tom Baker   | Manchester
(5 rows)`}>

```sql
SELECT name, coalesce(city, 'unknown') AS city
FROM customers
WHERE country IN ('UK', 'Egypt')
ORDER BY id;
```

</CodeExample>

Если у `city` есть значение, `coalesce` возвращает его; если там NULL, функция переходит к `'unknown'`. Значений можно передать сколько угодно:

<CodeExample output={` first_known
-------------
 third
(1 row)`}>

```sql
SELECT coalesce(NULL, NULL, 'third', 'fourth') AS first_known;
```

</CodeExample>

Запасное значение должно быть **того же типа**, что и столбец. В `department_id` хранятся числа, поэтому и запасное значение должно быть числом:

<CodeExample output={`     name     | department
--------------+------------
 Grace Hopper |          0
 Alan Turing  |          1
 Ada Lovelace |          1
(3 rows)`}>

```sql
SELECT name, coalesce(department_id, 0) AS department
FROM employees
WHERE id <= 3
ORDER BY id;
```

</CodeExample>

`coalesce(department_id, 'none')` завершится ошибкой `invalid input syntax for type integer: "none"`, потому что PostgreSQL попытается превратить `'none'` в число.

<Callout type="tip" title="COALESCE меняет только результат">

`coalesce(city, 'unknown')` не меняет таблицу: в базе данных город по-прежнему NULL. Меняется только то, что показывает этот запрос. Для отчётов обычно именно это и нужно.

</Callout>

## Сортировка NULL

При сортировке PostgreSQL считает NULL **больше любого другого значения**. Поэтому при сортировке по возрастанию NULL оказываются **в конце**, а с `DESC` — **в начале**:

<CodeExample output={`    name     |    city
-------------+------------
 Ada Brooks  | London
 Mei Lin     | London
 Tom Baker   | Manchester
 Omar Haddad | NULL
 Zara Khan   | NULL
(5 rows)

    name     |    city
-------------+------------
 Omar Haddad | NULL
 Zara Khan   | NULL
 Tom Baker   | Manchester
 Ada Brooks  | London
 Mei Lin     | London
(5 rows)`}>

```sql
SELECT name, city
FROM customers
WHERE country IN ('UK', 'Egypt')
ORDER BY city, name;

SELECT name, city
FROM customers
WHERE country IN ('UK', 'Egypt')
ORDER BY city DESC, name;
```

</CodeExample>

Чтобы выбрать самостоятельно, добавьте **`NULLS FIRST`** или **`NULLS LAST`** после столбца (и после `DESC`, если он есть):

<CodeExample output={`    name     |    city
-------------+------------
 Omar Haddad | NULL
 Zara Khan   | NULL
 Ada Brooks  | London
 Mei Lin     | London
 Tom Baker   | Manchester
(5 rows)

    name     |    city
-------------+------------
 Tom Baker   | Manchester
 Ada Brooks  | London
 Mei Lin     | London
 Omar Haddad | NULL
 Zara Khan   | NULL
(5 rows)`}>

```sql
-- Сначала пропущенные города, чтобы их исправить
SELECT name, city
FROM customers
WHERE country IN ('UK', 'Egypt')
ORDER BY city NULLS FIRST, name;

-- От Z до A, но пропущенные города в конце
SELECT name, city
FROM customers
WHERE country IN ('UK', 'Egypt')
ORDER BY city DESC NULLS LAST, name;
```

</CodeExample>

`ORDER BY rating DESC NULLS LAST` встречается часто: «сначала лучшие, а элементы без оценки — внизу, а не вверху».

Магазин планирует доставки за пределами Лондона. Напишите запрос к `customers`, который:

- показывает столбцы `name`, `town` и `country`, где `town` — это город покупателя или текст `'unknown'`, если город не указан;
- не включает покупателей из London, но **оставляет** покупателей без города (кому-то нужно им позвонить!);
- выводит сначала покупателей с **пропущенным городом** (по имени), а затем всех остальных **по городу, от A до Z**.

В стартовом запросе две ошибки, связанные с NULL: он теряет покупателей без города и поставил бы их в конец. У вас должно получиться 18 строк.

<Hint>

- Столбец: `coalesce(city, 'unknown') AS town`.
- Фильтр: `city <> 'London' OR city IS NULL`.
- Сортируйте по настоящему столбцу `city`, а не по псевдониму, чтобы NULL можно было поставить первыми: `ORDER BY city NULLS FIRST, name`.

</Hint>

<Solution>

```sql
SELECT name,
  coalesce(city, 'unknown') AS town,
  country
FROM customers
WHERE city <> 'London' OR city IS NULL
ORDER BY city NULLS FIRST, name;
```

## Итоги

- `NULL` означает отсутствующее или неизвестное значение. Это не `0` и не `''`.
- Сравнение с NULL даёт NULL («неизвестно»), а `WHERE` оставляет только **истинные** строки. Используйте `IS NULL` / `IS NOT NULL`.
- В SQL действует **трёхзначная логика**: истина, ложь и «неизвестно». Условия вроде `city <> 'London'` незаметно отбрасывают строки с NULL; добавьте `OR city IS NULL`, если они нужны.
- Не допускайте NULL в списках `NOT IN`: один-единственный NULL — и `NOT IN` не совпадёт ни с чем.
- Арифметика с NULL даёт NULL. `coalesce(a, b, ...)` возвращает первое значение, которое не NULL.
- При сортировке по возрастанию NULL идут последними, а с `DESC` — первыми; это можно изменить с `NULLS FIRST` / `NULLS LAST`.
