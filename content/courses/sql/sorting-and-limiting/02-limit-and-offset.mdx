A real shop might have a million products, but its home page shows the **3 best sellers**, and its catalogue shows **20 products per page**. You rarely want every row at once. In this lesson you'll cut a result down to size with `LIMIT`, skip rows with `OFFSET`, and put the two together to show results **one page at a time**.

## LIMIT: only the first few rows

**`LIMIT n`** keeps the first `n` rows of the result. Together with `ORDER BY`, it answers **top-N** questions, like "What are our 3 most expensive products?":

<CodeExample output={`          name          | price
------------------------+-------
 Rice Cooker            | 89.90
 Tea Pot                | 32.00
 Algorithms in Pictures | 29.00
(3 rows)`}>

```sql
SELECT name, price
FROM products
ORDER BY price DESC
LIMIT 3;
```

</CodeExample>

`LIMIT` goes at the very **end** of the query, after `ORDER BY`. The database sorts all the rows first, then keeps the first three.

`LIMIT 1` finds "the most" or "the least" of something. Which film is the longest?

<CodeExample output={`        title        | minutes
---------------------+---------
 The Quiet Algorithm |     131
(1 row)`}>

```sql
SELECT title, minutes
FROM movies
ORDER BY minutes DESC
LIMIT 1;
```

</CodeExample>

And the 5 newest customers:

<CodeExample output={`    name     | joined_on
-------------+------------
 Nina Novak  | 2025-01-05
 Tom Baker   | 2024-12-12
 Grace Kim   | 2024-11-23
 Ivan Petrov | 2024-11-04
 Emma Wilson | 2024-10-16
(5 rows)`}>

```sql
SELECT name, joined_on
FROM customers
ORDER BY joined_on DESC
LIMIT 5;
```

</CodeExample>

If the result has fewer rows than the limit, you just get them all: `LIMIT 10` on the 3 teas returns 3 rows, not an error.

<Callout type="warning" title="LIMIT without ORDER BY">

`SELECT * FROM products LIMIT 3;` runs fine, but which 3 rows you get is up to the database. "First" only means something once you've sorted. Always pair `LIMIT` with `ORDER BY`.

</Callout>

## OFFSET: skipping rows

**`OFFSET n`** skips the first `n` rows of the result. "The 4th, 5th and 6th most expensive products" means: sort, skip 3, keep 3:

<CodeExample output={`     name     | price
--------------+-------
 Clean Python | 24.99
 Plush Panda  | 18.00
 Kite         | 15.00
(3 rows)`}>

```sql
SELECT name, price
FROM products
ORDER BY price DESC
LIMIT 3 OFFSET 3;
```

</CodeExample>

## Paging through results

`LIMIT` and `OFFSET` together let you show a long list **one page at a time**, like the "Next page" button in an online shop. If every page shows `size` rows, then page number `page` needs:

```text
LIMIT  size
OFFSET (page - 1) * size
```

With 5 products per page: page 1 skips 0 rows, page 2 skips 5, page 3 skips 10. Here are pages 2 and 3 of the catalogue, sorted by name:

<CodeExample output={` id |     name      | price
----+---------------+-------
  1 | Jasmine Tea   |  6.50
 12 | Kite          | 15.00
  2 | Matcha Powder | 14.00
  5 | Panda Cookies |  3.75
 10 | Plush Panda   | 18.00
(5 rows)

 id |      name       | price
----+-----------------+-------
 15 | Rice Cooker     | 89.90
  6 | Rice Crackers   |  2.50
 13 | Tea Pot         | 32.00
  7 | The Bamboo Code | 12.50
 11 | Wooden Puzzle   | 11.40
(5 rows)`}>

```sql
-- Page 2
SELECT id, name, price
FROM products
ORDER BY name
LIMIT 5 OFFSET 5;

-- Page 3
SELECT id, name, price
FROM products
ORDER BY name
LIMIT 5 OFFSET 10;
```

</CodeExample>

The shop has 15 products, so a page 4 (`OFFSET 15`) would come back empty: `(0 rows)`. That's how an app knows there's no "Next" button to show.

### Pages need a predictable order

Paging only works if the order is **exactly the same** every time you ask. Watch what happens with pages of 2 products sorted by `category` alone. There are three books, all tied on `category`:

<CodeExample output={`          name          | category
------------------------+----------
 The Bamboo Code        | books
 Algorithms in Pictures | books
(2 rows)

      name       | category
-----------------+----------
 The Bamboo Code | books
 Tea Pot         | kitchen
(2 rows)`}>

```sql
-- Page 1
SELECT name, category
FROM products
ORDER BY category
LIMIT 2;

-- Page 2
SELECT name, category
FROM products
ORDER BY category
LIMIT 2 OFFSET 2;
```

</CodeExample>

*The Bamboo Code* shows up on **both** pages, and *Clean Python* is on **neither**! With ties, the database may put tied rows in any order, and each page is a separate query, so each one can pick a different order. The fix is the tie-breaker from the last lesson: end the sort with something unique, like `id`:

<CodeExample output={`     name     | category
--------------+----------
 Clean Python | books
 Tea Pot      | kitchen
(2 rows)`}>

```sql
SELECT name, category
FROM products
ORDER BY category, id
LIMIT 2 OFFSET 2;
```

</CodeExample>

Now the order is fixed: page 1 has the books with the two smallest ids, and page 2 picks up exactly where it stopped.

<Callout type="tip" title="Big offsets are slow">

To answer `OFFSET 100000`, the database still has to find and throw away 100,000 rows. Fine for small tables, slow for huge ones. Big sites use a faster trick called **keyset pagination** ("give me the next 20 after the last one I saw"), which you'll meet in the Indexes & Performance module.

</Callout>

## FETCH FIRST: the standard way

`LIMIT` is what most PostgreSQL code uses, but it isn't part of the official SQL standard. The standard way to write the same thing is **`FETCH FIRST`**, which PostgreSQL understands too, along with many other databases such as Oracle and Db2:

<CodeExample output={`          name          | price
------------------------+-------
 Rice Cooker            | 89.90
 Tea Pot                | 32.00
 Algorithms in Pictures | 29.00
(3 rows)`}>

```sql
SELECT name, price
FROM products
ORDER BY price DESC
FETCH FIRST 3 ROWS ONLY;
```

</CodeExample>

With an offset, it reads like a sentence: `OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY`. `FIRST` and `NEXT` mean the same, and so do `ROW` and `ROWS`.

### WITH TIES

`FETCH FIRST` has one trick `LIMIT` doesn't. Which product has the lowest stock? Two products are tied at 0, but `LIMIT 1` keeps only one of them:

<CodeExample output={`   name    | stock
-----------+-------
 Earl Grey |     0
(1 row)

     name     | stock
--------------+-------
 Clean Python |     0
 Earl Grey    |     0
(2 rows)`}>

```sql
SELECT name, stock
FROM products
ORDER BY stock
LIMIT 1;

SELECT name, stock
FROM products
ORDER BY stock
FETCH FIRST 1 ROW WITH TIES;
```

</CodeExample>

**`WITH TIES`** also keeps every row that's tied with the last one. That's fairer for questions like "Who has the highest score?", where two people can share first place.

## Recap

- `LIMIT n` keeps the first `n` rows; with `ORDER BY` it answers top-N questions.
- `OFFSET n` skips the first `n` rows. For page `p` of size `s`: `LIMIT s OFFSET (p - 1) * s`.
- Always use `ORDER BY` with `LIMIT`, and end it with a unique column so pages never overlap or skip rows.
- `FETCH FIRST n ROWS ONLY` is the SQL-standard version of `LIMIT`; `WITH TIES` also keeps rows tied with the last one.
- Large offsets get slow on big tables; keyset pagination is the faster alternative.
