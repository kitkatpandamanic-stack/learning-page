You've been adding `ORDER BY` to the end of queries to keep results tidy. Time to meet it properly! Remember that a table has **no built-in order**: without `ORDER BY`, the database returns rows in whatever order is quickest for it, and that can change. Whenever the order matters (a top-10 list, the newest orders, a price list), you have to **ask for it**.

## ORDER BY: smallest first

`ORDER BY column` sorts the result by that column. By default it sorts in **ascending** order: smallest number first, earliest date first, A before Z:

<CodeExample output={`         title          | rating
------------------------+--------
 Ninja Pandas II        |    5.9
 Code Red               |    6.4
 The Great Bamboo Race  |    6.5
 Tea for Two Thousand   |    6.7
 Panda Express to Mars  |    6.9
 Bug in the Machine     |    7.1
 The Last Dumpling      |    7.2
 Snow Leopard Summer    |    7.6
 The Bamboo Heist       |    7.8
 Mountain of Echoes     |    7.9
 Midnight in the Forest |    8.1
 The Quiet Algorithm    |    8.4
(12 rows)`}>

```sql
SELECT title, rating
FROM movies
ORDER BY rating;
```

</CodeExample>

## DESC: largest first

Add **`DESC`** (short for **descending**) to flip the order: largest first, latest date first, Z before A. There's also **`ASC`** (ascending), but since it's the default, you rarely need to write it.

<CodeExample output={`         title          | rating
------------------------+--------
 The Quiet Algorithm    |    8.4
 Midnight in the Forest |    8.1
 Mountain of Echoes     |    7.9
 The Bamboo Heist       |    7.8
 Snow Leopard Summer    |    7.6
 The Last Dumpling      |    7.2
 Bug in the Machine     |    7.1
 Panda Express to Mars  |    6.9
 Tea for Two Thousand   |    6.7
 The Great Bamboo Race  |    6.5
 Code Red               |    6.4
 Ninja Pandas II        |    5.9
(12 rows)`}>

```sql
SELECT title, rating
FROM movies
ORDER BY rating DESC;
```

</CodeExample>

Dates sort by time, so `ORDER BY hired_on` lists the engineering team from the longest-serving employee to the newest:

<CodeExample output={`       name        |  hired_on
-------------------+------------
 Alan Turing       | 2016-06-15
 Barbara Liskov    | 2017-11-30
 Ada Lovelace      | 2018-01-10
 Margaret Hamilton | 2019-04-22
 Linus Park        | 2020-09-01
 Ken Thompson      | 2022-02-14
(6 rows)`}>

```sql
SELECT name, hired_on
FROM employees
WHERE department_id = 1
ORDER BY hired_on;
```

</CodeExample>

`ORDER BY` always comes **last**, after `WHERE`: first the database picks the rows, then it sorts them.

<Callout type="note" title="How text is sorted">

Text is sorted letter by letter, like a dictionary. The exact rules (called the **collation**) depend on how the database was set up. In the database on this site, capital letters come before small ones, so `'Zebra'` sorts before `'apple'`. Many servers use language-aware rules where `'apple'` comes first. If capitals could be mixed, sort by `lower(name)`, which you'll meet in the Text, Numbers & Dates module.

</Callout>

## Sorting by several columns

List several columns, separated by commas. The database sorts by the **first** column; only when two rows have the **same** value there does it look at the second column, and so on. Each column gets its own direction:

<CodeExample output={`         title          |   genre   | rating
------------------------+-----------+--------
 Ninja Pandas II        | action    |    5.9
 Mountain of Echoes     | adventure |    7.9
 The Bamboo Heist       | comedy    |    7.8
 The Last Dumpling      | comedy    |    7.2
 Midnight in the Forest | drama     |    8.1
 Snow Leopard Summer    | drama     |    7.6
 The Great Bamboo Race  | family    |    6.5
 Tea for Two Thousand   | romance   |    6.7
 The Quiet Algorithm    | sci-fi    |    8.4
 Panda Express to Mars  | sci-fi    |    6.9
 Bug in the Machine     | thriller  |    7.1
 Code Red               | thriller  |    6.4
(12 rows)`}>

```sql
SELECT title, genre, rating
FROM movies
ORDER BY genre, rating DESC;
```

</CodeExample>

Genres go from A to Z, and **inside each genre** the best-rated film comes first. Read it as "sort by genre, then by rating, highest first".

<Callout type="warning" title="DESC belongs to one column">

`ORDER BY genre, rating DESC` sorts genre A to Z and rating high to low. The `DESC` only applies to the column right before it. If you want both descending, write `ORDER BY genre DESC, rating DESC`.

</Callout>

## Ties and tie-breakers

When two rows have the same value in every sort column, they're **tied**, and SQL doesn't promise which one comes first. Two products are out of stock:

<CodeExample output={`          name          | stock
------------------------+-------
 Clean Python           |     0
 Earl Grey              |     0
 Algorithms in Pictures |     3
 Rice Cooker            |     4
 Tea Pot                |     6
 The Bamboo Code        |     7
 Wooden Puzzle          |     9
(7 rows)`}>

```sql
SELECT name, stock
FROM products
WHERE stock < 10
ORDER BY stock, name;
```

</CodeExample>

With only `ORDER BY stock`, `Clean Python` and `Earl Grey` could come back in either order, and the order might even change from one run to the next. Adding `name` as a second column is a **tie-breaker**: it makes the order fully predictable.

<Callout type="tip" title="End with something unique">

For results that people page through or compare, finish the sort with a column that's different for every row, such as `id`: `ORDER BY price DESC, id`. Then the order can never change by surprise. You'll see why this matters for paging in the next lesson.

</Callout>

## Sorting by a calculated value

You can sort by any expression, and you can also sort by a column **alias**:

<CodeExample output={`       name        | price | stock | stock_value
-------------------+-------+-------+-------------
 Bamboo Chopsticks |  4.20 |   200 |      840.00
 Plush Panda       | 18.00 |    25 |      450.00
 Rice Cooker       | 89.90 |     4 |      359.60
 Kite              | 15.00 |    14 |      210.00
 Tea Pot           | 32.00 |     6 |      192.00
 Wooden Puzzle     | 11.40 |     9 |      102.60
(6 rows)`}>

```sql
SELECT name, price, stock,
  price * stock AS stock_value
FROM products
WHERE category IN ('kitchen', 'toys')
ORDER BY stock_value DESC;
```

</CodeExample>

Writing `ORDER BY price * stock DESC` would give the same result. You can even sort by a column you don't show, like `ORDER BY id`.

### Why an alias works in ORDER BY but not in WHERE

The database doesn't work through a query in the order you write it. It goes roughly like this:

```text
1. FROM      pick the table
2. WHERE     keep the matching rows
3. SELECT    work out the columns (aliases are made here)
4. ORDER BY  sort the result
```

`ORDER BY` runs after `SELECT`, so it knows the alias `stock_value`. `WHERE` runs **before** `SELECT`, when the alias doesn't exist yet:

<CodeExample output={`ERROR:  column "stock_value" does not exist
LINE 3: WHERE stock_value > 100;
              ^`}>

```sql
SELECT name, price * stock AS stock_value
FROM products
WHERE stock_value > 100;
```

</CodeExample>

In `WHERE`, repeat the calculation instead: `WHERE price * stock > 100`.

<Callout type="note" title="Sorting by position">

You may see `ORDER BY 2 DESC` in other people's code. It means "sort by the second column in the `SELECT` list". It's short, but it breaks quietly when someone adds a column, so we'll always use names.

</Callout>

## Recap

- Tables have no order: use `ORDER BY` whenever the order matters.
- `ORDER BY col` sorts ascending (smallest, earliest, A first); add `DESC` for the opposite.
- `ORDER BY a, b DESC` sorts by `a`, then by `b` inside rows with the same `a`. Each column has its own direction.
- Tied rows can come back in any order: add a tie-breaker, ideally something unique like `id`.
- You can sort by expressions and by aliases. Aliases don't work in `WHERE`, because `WHERE` runs before `SELECT`.
