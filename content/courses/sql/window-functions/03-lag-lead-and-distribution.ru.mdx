«Выросла ли выручка с прошлого месяца?» «Сколько дней проходит между заказами покупателя?» «Входит ли этот фильм в верхнюю четверть каталога?» Во всех этих вопросах строка сравнивается с **другими конкретными строками**: с предыдущей, со следующей, с лучшей в группе.

Этот урок завершает набор инструментов для оконных функций: **функции смещения (offset functions)** (`lag`, `lead`), **функции значений (value functions)** (`first_value`, `last_value`, `nth_value`) и **функции распределения (distribution functions)** (`ntile`, `percent_rank`, `cume_dist`). Все они используют уже знакомое вам `OVER (PARTITION BY ... ORDER BY ...)`. 🔍

## LAG: смотрим на предыдущую строку

**`lag(выражение)`** возвращает значение выражения из **предыдущей строки** в порядке окна. У первой строки предыдущей нет, поэтому она получает `NULL`. Больше ничего не нужно для отчётов **«период к периоду» (period-over-period)**:

<CodeExample output={`  month  | revenue | prev_revenue | change  | change_pct
---------+---------+--------------+---------+------------
 2025-01 |  518.30 |         NULL |    NULL |       NULL
 2025-02 |  331.69 |       518.30 | -186.61 |      -36.0
 2025-03 |  525.80 |       331.69 |  194.11 |       58.5
 2025-04 |  331.69 |       525.80 | -194.11 |      -36.9
 2025-05 |  467.80 |       331.69 |  136.11 |       41.0
 2025-06 |  270.54 |       467.80 | -197.26 |      -42.2
(6 rows)`}>

```sql
WITH monthly AS (
  SELECT to_char(o.ordered_at, 'YYYY-MM') AS month,
    sum(oi.quantity * oi.unit_price) AS revenue
  FROM orders AS o
  JOIN order_items AS oi ON oi.order_id = o.id
  WHERE o.status <> 'cancelled'
  GROUP BY month
),
compared AS (
  SELECT month, revenue,
    lag(revenue) OVER (ORDER BY month) AS prev_revenue
  FROM monthly
)
SELECT month, revenue, prev_revenue,
  revenue - prev_revenue AS change,
  round(100 * (revenue - prev_revenue)
    / nullif(prev_revenue, 0), 1) AS change_pct
FROM compared
ORDER BY month;
```

</CodeExample>

Несколько деталей, которые стоит перенести в ваши собственные отчёты:

- Второе CTE даёт `lag(...)` имя, поэтому итоговый `SELECT` может трижды использовать `prev_revenue`, а не повторять окно.
- **`nullif(prev_revenue, 0)`** превращает ноль в `NULL`, поэтому месяц после месяца без выручки даёт `NULL`, а не ошибку «division by zero».
- У первого месяца нет предыдущего, поэтому его изменение — `NULL`. Это честно: «рост по сравнению с ничем» — это не 0%.

У `lag` есть два необязательных аргумента: **`lag(x, n, default)`** смотрит на `n` строк назад (по умолчанию на 1) и возвращает `default` вместо `NULL`, когда такой строки нет. На месячных данных `lag(revenue, 12)` даёт сравнение **год к году (year-over-year)**.

## LEAD: смотрим на следующую строку

**`lead()`** — зеркальное отражение: значение из **следующей** строки. Вместе с `PARTITION BY` эта пара описывает ритм покупателя: сколько времени прошло с его прошлого заказа и когда (и вернулся ли вообще) он пришёл снова:

<CodeExample output={`    name    | order_id |    day     | days_since_prev | next_order
------------+----------+------------+-----------------+------------
 Mei Lin    |       17 | 2025-03-14 |            NULL | 2025-05-24
 Mei Lin    |       34 | 2025-05-24 |              71 | NULL
 Ravi Patel |        3 | 2025-01-15 |            NULL | 2025-03-27
 Ravi Patel |       20 | 2025-03-27 |              71 | 2025-06-05
 Ravi Patel |       37 | 2025-06-05 |              70 | NULL
 Sam Ortiz  |        5 | 2025-01-24 |            NULL | 2025-04-04
 Sam Ortiz  |       22 | 2025-04-04 |              70 | 2025-06-13
 Sam Ortiz  |       39 | 2025-06-13 |              70 | NULL
(8 rows)`}>

```sql
SELECT c.name, o.id AS order_id, o.ordered_at::date AS day,
  o.ordered_at::date - lag(o.ordered_at::date) OVER w
    AS days_since_prev,
  lead(o.ordered_at::date) OVER w AS next_order
FROM orders AS o
JOIN customers AS c ON c.id = o.customer_id
WHERE o.customer_id IN (1, 2, 5)
WINDOW w AS (PARTITION BY o.customer_id ORDER BY o.ordered_at)
ORDER BY c.name, o.ordered_at;
```

</CodeExample>

Разность двух значений типа `date` — целое число дней. `NULL` в `next_order` означает «более позднего заказа (пока) нет». В реальном магазине «последний заказ больше 90 дней назад, и следующего нет» — классическое определение покупателя, который, возможно, **уходит (churn)**, и хороший список для письма «мы по вам скучаем».

<Callout type="warning" title="Предыдущая строка — не всегда предыдущий месяц">

`lag` смотрит на предыдущую **строку**, а не на предыдущий месяц. Если в каком-то месяце заказов не было вовсе, строки для него нет, и `lag` спокойно сравнит май с мартом. Если пробелы возможны, сначала постройте **календарь** с помощью `generate_series` и присоедините к нему данные через `LEFT JOIN`, чтобы у каждого месяца была строка (с 0, если ничего не произошло).

</Callout>

Вот такое исправление для Mei Lin, которая делала заказы только в марте и мае:

<CodeExample output={`  month  | orders | prev_month
---------+--------+------------
 2025-01 |      0 |       NULL
 2025-02 |      0 |          0
 2025-03 |      1 |          0
 2025-04 |      0 |          1
 2025-05 |      1 |          0
 2025-06 |      0 |          1
(6 rows)`}>

```sql
WITH months AS (
  SELECT to_char(m, 'YYYY-MM') AS month
  FROM generate_series(date '2025-01-01', date '2025-06-01',
    interval '1 month') AS m
),
meis_orders AS (
  SELECT to_char(ordered_at, 'YYYY-MM') AS month, count(*) AS orders
  FROM orders
  WHERE customer_id = 1
  GROUP BY month
)
SELECT m.month, coalesce(mo.orders, 0) AS orders,
  lag(coalesce(mo.orders, 0)) OVER (ORDER BY m.month) AS prev_month
FROM months AS m
LEFT JOIN meis_orders AS mo ON mo.month = m.month
ORDER BY m.month;
```

</CodeExample>

Без календаря в результате было бы две строки, и «предыдущим месяцем» для мая оказался бы март.

## FIRST_VALUE и LAST_VALUE

**`first_value(x)`** и **`last_value(x)`** возвращают `x` из первой или последней строки **рамки**. Сравним каждого сотрудника с тем, кто больше всех зарабатывает в его отделе, и попробуем найти того, кто зарабатывает меньше всех:

<CodeExample output={` department_id |    name     | salary | top_earner | lowest_oops | lowest_earner
---------------+-------------+--------+------------+-------------+---------------
             3 | Mary Kay    |  90000 | Mary Kay   | Mary Kay    | Paul Allen
             3 | Elena Gomez |  54000 | Mary Kay   | Elena Gomez | Paul Allen
             3 | Carlos Ruiz |  52000 | Mary Kay   | Carlos Ruiz | Paul Allen
             3 | Paul Allen  |  41000 | Mary Kay   | Paul Allen  | Paul Allen
             4 | Hana Sato   |  70000 | Hana Sato  | Hana Sato   | Taro Yamada
             4 | Aiko Suzuki |  39500 | Hana Sato  | Aiko Suzuki | Taro Yamada
             4 | Taro Yamada |  38000 | Hana Sato  | Taro Yamada | Taro Yamada
(7 rows)`}>

```sql
SELECT department_id, name, salary,
  first_value(name) OVER by_salary AS top_earner,
  last_value(name) OVER by_salary AS lowest_oops,
  last_value(name) OVER (
    PARTITION BY department_id
    ORDER BY salary DESC
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
  ) AS lowest_earner
FROM employees
WHERE department_id IN (3, 4)
WINDOW by_salary AS (PARTITION BY department_id ORDER BY salary DESC)
ORDER BY department_id, salary DESC;
```

</CodeExample>

`first_value` работает, а вот `lowest_oops` просто повторяет имя самого сотрудника. Вспомните рамку по умолчанию из [прошлого урока](/learn/sql/running-totals-and-frames): с `ORDER BY` она заканчивается на **текущей строке**, поэтому «последняя строка рамки» — это текущая строка (или последняя из её peers). Чтобы видеть всю партицию, явно напишите `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`, как в `lowest_earner`. (Или переверните порядок и используйте `first_value` — часто так проще.)

**`nth_value(x, n)`** возвращает значение из n-й строки рамки: `nth_value(name, 2)` — это второй по счёту. У неё та же ловушка с рамкой, что и у `last_value`.

## NTILE, PERCENT_RANK и CUME_DIST

Последнее семейство функций определяет место каждой строки **в распределении** всех строк:

- **`ntile(n)`** делит упорядоченные строки на `n` групп (buckets) как можно более равного размера и возвращает номер группы: `ntile(4)` даёт квартили, `ntile(10)` — децили, `ntile(100)` — перцентили.
- **`percent_rank()`** — это `(rank - 1) / (rows - 1)`: 0 для первой строки, 1 для последней.
- **`cume_dist()`** — «доля строк, которые идут до этой строки или равны ей», от 0 до 1.

<CodeExample output={`         title          | rating | quartile | pct_rank | cume_dist
------------------------+--------+----------+----------+-----------
 The Quiet Algorithm    |    8.4 |        1 |     1.00 |      1.00
 Midnight in the Forest |    8.1 |        1 |     0.91 |      0.92
 Mountain of Echoes     |    7.9 |        1 |     0.82 |      0.83
 The Bamboo Heist       |    7.8 |        2 |     0.73 |      0.75
 Snow Leopard Summer    |    7.6 |        2 |     0.64 |      0.67
 The Last Dumpling      |    7.2 |        2 |     0.55 |      0.58
 Bug in the Machine     |    7.1 |        3 |     0.45 |      0.50
 Panda Express to Mars  |    6.9 |        3 |     0.36 |      0.42
 Tea for Two Thousand   |    6.7 |        3 |     0.27 |      0.33
 The Great Bamboo Race  |    6.5 |        4 |     0.18 |      0.25
 Code Red               |    6.4 |        4 |     0.09 |      0.17
 Ninja Pandas II        |    5.9 |        4 |     0.00 |      0.08
(12 rows)`}>

```sql
SELECT title, rating,
  ntile(4) OVER (ORDER BY rating DESC) AS quartile,
  round(percent_rank() OVER (ORDER BY rating)::numeric, 2)
    AS pct_rank,
  round(cume_dist() OVER (ORDER BY rating)::numeric, 2)
    AS cume_dist
FROM movies
ORDER BY rating DESC;
```

</CodeExample>

Двенадцать фильмов в четырёх группах — по три на квартиль: тройка лидеров — это «верхние 25%». `percent_rank` и `cume_dist` возвращают `double precision`, поэтому перед `round(x, 2)` их приводят к `numeric` (округление до знаков после запятой работает только с `numeric`). `cume_dist = 0.75` у The Bamboo Heist читается как «у 75% фильмов такой же или более низкий рейтинг».

<Callout type="tip" title="ntile — про количество строк, а не про значения">

`ntile(4)` делает группы с одинаковым **числом строк**, даже если для этого приходится разделить равные значения: два фильма с одинаковым рейтингом могут попасть в разные квартили. Если вам нужны диапазоны значений («самые дешёвые 25% диапазона цен») или настоящая медиана, используйте `percentile_cont(0.5) WITHIN GROUP (ORDER BY price)` — упорядоченный агрегат (ordered-set aggregate), который интерполирует значения. Выбирайте осознанно: они отвечают на разные вопросы.

</Callout>

Попробуйте: замените `ntile(4)` на `ntile(3)`, разбейте фильмы на партиции по `genre` или используйте `lead`, чтобы показать следующий фильм каждого режиссёра.

Киноклуб хочет посмотреть, как складывалась карьера каждого режиссёра. Для каждого фильма покажите:

- `director`, `year`, `title` и `rating`,
- `years_since_prev`: сколько лет прошло с предыдущего фильма **того же режиссёра**,
- `rating_change`: рейтинг этого фильма минус рейтинг предыдущего,
- `NULL` в обоих столбцах для первого фильма режиссёра,
- сортировка по режиссёру, затем по году.

<Hint>

Используйте `lag(year)` и `lag(rating)` с окном `PARTITION BY director ORDER BY year` и вычитайте: `year - lag(year) OVER w AS years_since_prev`. Предложение `WINDOW w AS (...)` избавит от необходимости писать окно дважды. Вычитание из `NULL` даёт `NULL`, поэтому первые фильмы не требуют особой обработки.

</Hint>

```sql
SELECT director, year, title, rating,
  year - lag(year) OVER w AS years_since_prev,
  rating - lag(rating) OVER w AS rating_change
FROM movies
WINDOW w AS (PARTITION BY director ORDER BY year, id)
ORDER BY director, year;
```

## Итоги

- **`lag(x)`** / **`lead(x)`** читают `x` из предыдущей / следующей строки в порядке окна; `lag(x, n, default)` смотрит дальше и подставляет значение вместо отсутствующего `NULL`.
- Период к периоду: `revenue - lag(revenue)`, а для процентов делите на `nullif(prev, 0)`. Сначала заполните пробелы календарём из `generate_series`, ведь `lag` считает строки, а не месяцы.
- **`first_value`**, **`last_value`** и **`nth_value`** выбирают значения из **рамки**; для `last_value` и `nth_value` расширьте её до `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`.
- **`ntile(n)`** делит строки на n групп одинакового размера; **`percent_rank()`** и **`cume_dist()`** дают относительное положение каждой строки от 0 до 1.
- С ранжированием из [первого урока](/learn/sql/window-functions-and-ranking) и рамками из второго у вас теперь есть весь набор инструментов оконных функций. Дальше — продвинутые запросы с `CASE`, рекурсией и JSON.
