В прошлом уроке вы усредняли суммы заказов с помощью подзапроса во `FROM`. Это сработало, но из-за скобок запрос приходилось читать **изнутри наружу**: первое, что делает PostgreSQL, спрятано в середине. Добавьте ещё один шаг — и никто не захочет к такому запросу прикасаться.

`WITH` решает эту проблему. Он позволяет дать каждому шагу **имя** в начале запроса, а затем использовать это имя как таблицу. Такие именованные шаги называются **обобщёнными табличными выражениями (common table expressions)**, или **CTE**. Это один из самых полезных инструментов повседневного SQL: они превращают головоломку в рецепт, который читается сверху вниз.

## Ваше первое CTE

Вот снова запрос «средняя сумма заказа», переписанный с `WITH`:

<CodeExample output={` orders | average_order
--------+---------------
     40 |         70.23
(1 row)`}>

```sql
WITH order_totals AS (
  SELECT order_id, sum(quantity * unit_price) AS total
  FROM order_items
  GROUP BY order_id
)
SELECT count(*) AS orders, round(avg(total), 2) AS average_order
FROM order_totals;
```

</CodeExample>

Форма всегда одна и та же:

```text
WITH step_name AS (
  запрос
)
SELECT … FROM step_name …;
```

- `WITH order_totals AS ( … )` выполняет внутренний запрос и называет его результат `order_totals`.
- Следующий за ним основной запрос может использовать `order_totals` точно так же, как таблицу.
- После закрывающей скобки **нет точки с запятой**: часть `WITH` и основной запрос — это одна инструкция (statement).

Результат такой же, как с производной таблицей, но теперь первый шаг идёт первым, и у него есть имя, которое говорит, что это такое.

## Несколько шагов подряд

Шаги разделяются **запятыми**. Каждый шаг может использовать шаги выше него. Этот запрос находит лучших покупателей магазина, пропуская отменённые заказы:

<CodeExample output={`    name     | orders | spent
-------------+--------+--------
 Ravi Patel  |      3 | 282.23
 Sam Ortiz   |      2 | 273.83
 Sofia Rossi |      3 | 260.13
 Diego López |      2 | 258.17
 Kenji Mori  |      2 | 207.67
(5 rows)`}>

```sql
WITH order_totals AS (
  SELECT o.id, o.customer_id, sum(oi.quantity * oi.unit_price) AS total
  FROM orders AS o
  JOIN order_items AS oi ON oi.order_id = o.id
  WHERE o.status <> 'cancelled'
  GROUP BY o.id
),
customer_spend AS (
  SELECT customer_id, count(*) AS orders, sum(total) AS spent
  FROM order_totals
  GROUP BY customer_id
)
SELECT c.name, cs.orders, cs.spent
FROM customer_spend AS cs
JOIN customers AS c ON c.id = cs.customer_id
ORDER BY cs.spent DESC, c.name
LIMIT 5;
```

</CodeExample>

Читайте его как рецепт:

1. **order_totals**: посчитать, на какую сумму был каждый (неотменённый) заказ.
2. **customer_spend**: сложить эти суммы по каждому покупателю.
3. Основной запрос: подставить имена покупателей и оставить первую пятёрку.

Каждый шаг — небольшой запрос, который можно понять сам по себе. Попробуйте написать то же самое вложенными подзапросами, и вы поймёте, за что все любят CTE.

<Callout type="tip" title="Собирайте и отлаживайте по одному шагу">

Если запрос с CTE даёт странный ответ, замените основной запрос на `SELECT * FROM order_totals;` (или на тот шаг, который вызывает подозрение) и посмотрите, что этот шаг на самом деле выдаёт. Затем переходите к следующему шагу. Новые запросы пишутся так же: сначала добейтесь правильного первого шага, потом добавьте второй.

</Callout>

## Один шаг — дважды

Шаг можно использовать больше одного раза. Какие заказы были на сумму **больше средней**? Суммы заказов нужны дважды: один раз для списка, второй — для среднего.

<CodeExample output={` order_id | total
----------+--------
        2 | 200.17
       17 | 200.17
       32 | 200.17
        5 | 149.73
       20 | 149.73
       35 | 149.73
(6 rows)`}>

```sql
WITH order_totals AS (
  SELECT order_id, sum(quantity * unit_price) AS total
  FROM order_items
  GROUP BY order_id
)
SELECT order_id, total
FROM order_totals
WHERE total > (SELECT avg(total) FROM order_totals)
ORDER BY total DESC, order_id
LIMIT 6;
```

</CodeExample>

Без CTE пришлось бы написать весь запрос «сумма каждого заказа» дважды и следить, чтобы обе копии совпадали. С CTE он живёт в одном месте.

## Имена столбцов

Имена столбцов шага можно перечислить сразу после его имени. Это удобно, когда во внутреннем запросе есть выражения, которым иначе пришлось бы давать псевдонимы по одному:

<CodeExample output={` category | products | avg_price
----------+----------+-----------
 kitchen  |        3 |     42.03
 books    |        3 |     22.16
 toys     |        3 |     14.80
(3 rows)`}>

```sql
WITH category_stats (category, products, avg_price) AS (
  SELECT category, count(*), round(avg(price), 2)
  FROM products
  GROUP BY category
)
SELECT category, products, avg_price
FROM category_stats
WHERE avg_price > 10
ORDER BY avg_price DESC;
```

</CodeExample>

## CTE живёт одну инструкцию

CTE нигде не сохраняется. Оно существует только в пределах своей инструкции, а после точки с запятой исчезает:

<CodeExample output={` cheap_products
----------------
              3
(1 row)

ERROR:  relation "cheap" does not exist
LINE 6: SELECT name FROM cheap;
                         ^`}>

```sql
WITH cheap AS (
  SELECT name, price FROM products WHERE price < 4
)
SELECT count(*) AS cheap_products FROM cheap;

SELECT name FROM cheap;
```

</CodeExample>

Если один и тот же шаг нужен во многих запросах, вам пригодится **представление (view)** — сохранённый запрос с именем. Вы познакомитесь с ним на уровне 2.

<Callout type="note" title="CTE медленнее подзапросов?">

Вам может попасться старый совет: CTE — это «барьер оптимизации» (optimisation fence), который PostgreSQL вычисляет отдельно. Так было до PostgreSQL 12. Сегодня CTE, которое используется **один раз**, встраивается в основной запрос, и планируется точно так же, как эквивалентный подзапрос. CTE, которое используется **больше одного раза**, вычисляется один раз и переиспользуется — обычно именно это и нужно. Любое из этих поведений можно включить принудительно с помощью `WITH step AS MATERIALIZED ( … )` или `AS NOT MATERIALIZED`, но это редко бывает нужно.

</Callout>

## CTE или подзапросы?

Они делают одно и то же, так что выбирайте то, что читается лучше:

| Подзапрос, когда… | CTE, когда… |
| --- | --- |
| он короткий и используется один раз, как `WHERE price > (SELECT avg(price) FROM products)` | в запросе два шага или больше |
| это фильтр `EXISTS` / `IN` | шаг используется больше одного раза |
| | хочется назвать, что означает каждый шаг |

У `WITH` есть ещё два приёма, с которыми вы встретитесь позже: **рекурсивные (recursive)** CTE, которые обходят деревья вроде оргструктуры в `employees` (на уровне 2), и CTE, которые **изменяют данные**, — их показывает [урок про INSERT](/learn/sql/insert-rows).

<TryIt language="sql" code={`-- Измените первый шаг и посмотрите, как за ним следует второй.
WITH stock_value AS (
  SELECT category, sum(price * stock) AS value
  FROM products
  GROUP BY category
),
ranked AS (
  SELECT category, value
  FROM stock_value
  WHERE value > 300
)
SELECT category, value
FROM ranked
ORDER BY value DESC;`} />

Оставьте столбцы `name, headcount, avg_salary` и порядок (сначала самое высокое среднее).

<Hint>

Добавьте после запятой второй шаг: `company AS (SELECT avg(salary) AS avg_salary FROM employees)`. Затем в основном запросе сравните с ним, например так: `WHERE dp.avg_salary > (SELECT avg_salary FROM company)`.

```sql
WITH dept_pay AS (
  SELECT
    department_id,
    count(*) AS headcount,
    avg(salary) AS avg_salary
  FROM employees
  WHERE department_id IS NOT NULL
  GROUP BY department_id
),
company AS (
  SELECT avg(salary) AS avg_salary
  FROM employees
)
SELECT d.name, dp.headcount, round(dp.avg_salary) AS avg_salary
FROM dept_pay AS dp
JOIN departments AS d ON d.id = dp.department_id
WHERE dp.avg_salary > (SELECT avg_salary FROM company)
ORDER BY dp.avg_salary DESC;
```

## Итоги

- `WITH name AS ( запрос )` даёт шагу имя; основной запрос использует его как таблицу.
- Шаги объединяются в цепочку через **запятые**; каждый шаг может использовать шаги выше. Точка с запятой одна — в самом конце.
- Шаг можно использовать **больше одного раза**, так что одну и ту же логику не приходится копировать.
- `WITH name (col1, col2) AS ( … )` задаёт имена столбцов шага.
- CTE живёт **одну инструкцию**; для сохранённого запроса, который можно переиспользовать, нужно представление.
- Начиная с PostgreSQL 12, CTE работают так же быстро, как эквивалентные подзапросы, — выбирайте то, что читается лучше.
