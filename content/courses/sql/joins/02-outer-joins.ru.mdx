Внутреннее соединение (inner join) оставляет только строки, у которых есть пара с **обеих** сторон. Обычно это то, что нужно, но иногда весь смысл как раз в строках *без* пары: покупатели, которые ни разу не заказывали, товары, которые никто не купил, сотрудники без отдела. **Внешние соединения** (outer joins) сохраняют такие строки, и именно с их помощью отвечают на вопросы «чего не хватает?». 🔍

## Покупатели, о которых забывает внутреннее соединение

В магазине 20 покупателей. Сколько из них окажется в результате, если соединить покупателей с заказами?

<CodeExample output={` customers_in_join
-------------------
                17
(1 row)

 all_customers
---------------
            20
(1 row)`}>

```sql
SELECT count(DISTINCT c.id) AS customers_in_join
FROM customers AS c
JOIN orders AS o ON o.customer_id = c.id;

SELECT count(*) AS all_customers FROM customers;
```

</CodeExample>

У трёх покупателей нет заказов, поэтому для них не находится ни одной пары, и внутреннее соединение молча их отбрасывает. Отчёт «заказы по покупателям», построенный на таком соединении, просто не покажет их, и никто этого не заметит.

## LEFT JOIN сохраняет все строки слева

`LEFT JOIN` сохраняет **все строки левой таблицы** (той, что во `FROM`). Строки с парой соединяются как обычно, а строки без пары получают **NULL** во всех столбцах правой таблицы:

<CodeExample output={`    name     | order_id |  status
-------------+----------+-----------
 Emma Wilson |        7 | shipped
 Emma Wilson |       24 | cancelled
 Ivan Petrov |       12 | shipped
 Ivan Petrov |       29 | cancelled
 Grace Kim   |     NULL | NULL
 Tom Baker   |     NULL | NULL
 Nina Novak  |     NULL | NULL
(7 rows)`}>

```sql
SELECT c.name, o.id AS order_id, o.status
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE c.id >= 16
ORDER BY c.id, o.id;
```

</CodeExample>

Grace, Tom и Nina на месте, каждый по одному разу, а там, где был бы заказ, стоит `NULL`. Слово **OUTER** необязательно: `LEFT JOIN` и `LEFT OUTER JOIN` означают одно и то же.

<Callout type="tip" title="Какая таблица слева?">

«Левая» — это просто таблица, записанная **перед** `LEFT JOIN`. Таблицу, все строки которой нужно сохранить (здесь — всех покупателей), ставьте во `FROM`, а необязательную — после `LEFT JOIN`.

</Callout>

## Подсчёт с LEFT JOIN

Теперь посчитаем заказы каждого покупателя, включая нули. Здесь есть ловушка:

<CodeExample output={`    name     | wrong_count | orders
-------------+-------------+--------
 Emma Wilson |           2 |      2
 Ivan Petrov |           2 |      2
 Grace Kim   |           1 |      0
 Tom Baker   |           1 |      0
 Nina Novak  |           1 |      0
(5 rows)`}>

```sql
SELECT c.name,
  count(*) AS wrong_count,
  count(o.id) AS orders
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE c.id >= 16
GROUP BY c.id, c.name
ORDER BY c.id;
```

</CodeExample>

У Grace Kim **нет** заказов, но `count(*)` показывает 1. Дело в том, что `count(*)` считает **строки**, а левое соединение дало ей одну строку (полную NULL). `count(o.id)` считает только id заказов, отличные от NULL, поэтому правильно показывает 0. Во внешних соединениях всегда считайте столбец из необязательной стороны.

Мы сгруппировали по `c.id` *и* `c.name`: у двух покупателей может совпасть имя, но id — никогда.

## Поиск недостающих строк: анти-соединение

Какие покупатели **ни разу** не делали заказ? Сделайте левое соединение и оставьте только строки, у которых нет правой части:

<CodeExample output={`    name    | joined_on
------------+------------
 Grace Kim  | 2024-11-23
 Nina Novak | 2025-01-05
 Tom Baker  | 2024-12-12
(3 rows)`}>

```sql
SELECT c.name, c.joined_on
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE o.id IS NULL
ORDER BY c.name;
```

</CodeExample>

Этот шаблон называется **анти-соединением** (anti-join): «строки из A, у которых нет пары в B». Проверяйте столбец, который никогда не бывает NULL при настоящем совпадении, например первичный ключ правой таблицы (`o.id`). И не забывайте писать `IS NULL`: `o.id = NULL` никогда не бывает истинным, так что запрос ничего не вернёт.

## ON или WHERE? Это важно

Допустим, нам нужны **все покупатели из UK** с количеством их **отменённых** заказов. Куда поставить `o.status = 'cancelled'`?

<CodeExample output={`   name    | cancelled
-----------+-----------
 Mei Lin   |         1
 Zara Khan |         1
(2 rows)

    name    | cancelled
------------+-----------
 Ada Brooks |         0
 Mei Lin    |         1
 Tom Baker  |         0
 Zara Khan  |         1
(4 rows)`}>

```sql
-- Условие в WHERE: покупатели без отменённых заказов исчезают
SELECT c.name, count(o.id) AS cancelled
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE c.country = 'UK' AND o.status = 'cancelled'
GROUP BY c.id, c.name
ORDER BY c.name;

-- Условие в ON: все покупатели из UK остаются
SELECT c.name, count(o.id) AS cancelled
FROM customers AS c
LEFT JOIN orders AS o
  ON o.customer_id = c.id AND o.status = 'cancelled'
WHERE c.country = 'UK'
GROUP BY c.id, c.name
ORDER BY c.name;
```

</CodeExample>

Всё объясняет порядок выполнения:

1. Сначала выполняется соединение. `ON` решает, **какие заказы считаются парой**; покупатели без пары сохраняются, с NULL.
2. Затем `WHERE` фильтрует соединённые строки. У Tom Baker `o.status` равен NULL, а `NULL = 'cancelled'` не истинно, поэтому `WHERE` его выбрасывает — и весь смысл левого соединения пропадает.

<Callout type="warning" title="Простое правило">

В `LEFT JOIN` условия на **правую** (необязательную) таблицу пишите в `ON`. Условия на **левую** таблицу, которую вы сохраняете, — в `WHERE`. Условие на правую таблицу в `WHERE` незаметно превращает левое соединение обратно во внутреннее.

</Callout>

## RIGHT JOIN

`RIGHT JOIN` — зеркальное отражение: он сохраняет все строки таблицы, записанной **после** `RIGHT JOIN`. Этот запрос сохраняет всех покупателей, хотя `customers` стоит второй:

<CodeExample output={`    name     | order_id
-------------+----------
 Ivan Petrov |       12
 Ivan Petrov |       29
 Grace Kim   |     NULL
 Tom Baker   |     NULL
 Nina Novak  |     NULL
(5 rows)`}>

```sql
SELECT c.name, o.id AS order_id
FROM orders AS o
RIGHT JOIN customers AS c ON c.id = o.customer_id
WHERE c.id >= 17
ORDER BY c.id, o.id;
```

</CodeExample>

Он возвращает ровно те же строки, что и `FROM customers AS c LEFT JOIN orders AS o ON …`. На практике большинство всегда пишет `LEFT JOIN` и ставит таблицу «сохранить всё» первой, потому что так запрос естественно читается сверху вниз. Но `RIGHT JOIN` всё равно встречается в чужом коде, так что его полезно узнавать.

## FULL JOIN сохраняет обе стороны

`FULL JOIN` (или `FULL OUTER JOIN`) сохраняет строки без пары из **обеих** таблиц. Это удобно для сравнения двух списков. У нашего CEO, Grace Hopper, нет отдела. А ещё давайте откроем в Париже новый отдел Legal, в котором пока нет сотрудников. (`INSERT` добавляет строку; ему будет посвящён отдельный урок позже на Уровне 1. Как и любое изменение здесь, при следующем запуске оно исчезнет.)

<CodeExample output={`INSERT 0 1

   employee   | department
--------------+------------
 Grace Hopper | NULL
 NULL         | Legal
(2 rows)`}>

```sql
INSERT INTO departments (name, location) VALUES ('Legal', 'Paris');

SELECT e.name AS employee, d.name AS department
FROM employees AS e
FULL JOIN departments AS d ON d.id = e.department_id
WHERE e.id IS NULL OR d.id IS NULL
ORDER BY employee, department;
```

</CodeExample>

Без `WHERE` вы получили бы всех 20 сотрудников с их отделами, плюс пустой отдел Legal. С ним видны только «хвосты» с **любой** стороны: сотрудник без отдела и отдел без сотрудников. Это быстрая проверка согласованности двух таблиц.

| Соединение   | Сохраняет строки без пары из…    |
| ------------ | -------------------------------- |
| `JOIN`       | ни одной таблицы                 |
| `LEFT JOIN`  | левой таблицы                    |
| `RIGHT JOIN` | правой таблицы                   |
| `FULL JOIN`  | обеих таблиц                     |

Выведите `name` и `orders`: сначала больше всего заказов, при равенстве — по `name`. Сейчас ответ такой: Ada Brooks 2, Mei Lin 1, Zara Khan 1 и Tom Baker 0.

В заготовке используется внутреннее соединение, поэтому Tom Baker пропадает, а ещё она считает и отменённые заказы. Исправьте и то и другое.

Правило о статусе относится к таблице **orders** (необязательной стороне), поэтому оно идёт в `ON`: `ON o.customer_id = c.id AND o.status <> 'cancelled'`. ## Итоги

- `LEFT JOIN` сохраняет все строки левой таблицы; недостающие столбцы правой становятся **NULL**. `RIGHT JOIN` — его зеркальное отражение, а `FULL JOIN` сохраняет строки без пары с обеих сторон.
- Считайте по столбцу из необязательной стороны (`count(o.id)`), а не через `count(*)`, чтобы «нет пары» давало 0.
- **Анти-соединение**: `LEFT JOIN … WHERE right.id IS NULL` находит строки без пары.
- Условия на необязательную таблицу пишите в `ON`; в `WHERE` они превращают левое соединение обратно во внутреннее.
- Большинство пишет `LEFT JOIN` с таблицей «сохранить всё» на первом месте, а не `RIGHT JOIN`.
