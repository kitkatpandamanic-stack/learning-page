You've got typed questions (Part 1) and a safe grader (Part 2). Now let's play! In this final part you'll run a whole quiz from start to finish: show each question, react to the player's answer with ✅ or ❌, and finish with a **results report** that gives the player a rank. 🏆

Along the way you'll use **arrays and indexes** (Arrays and Tuples), **literal unions** for the rank (Literal Types & switch), an **interface** for the report and lots of small typed functions working together.

## Simulating the player

A real quiz would wait for the player to type an answer. PandaDev runs your code without a keyboard, so instead we'll **simulate** the player: their answers come in as an array of numbers, one per question. `[2, 1, 3]` means "choice 2 for the first question, choice 1 for the second, choice 3 for the third".

This is actually a great habit. A game that gets its input as a **parameter** is predictable: the same choices always give the same result, so you can test it. Swap the array and you have a different player.

What if the player gives fewer answers than there are questions? Remember the warning from Arrays and Tuples: **indexing isn't checked**. TypeScript says `choices[5]` is a `number`, but there's nothing there:

<CodeExample output={`1
undefined
1
null`}>

```ts
const playerChoices: number[] = [2, 1];

console.log(playerChoices[1]);
console.log(playerChoices[5]); // typed as number, but it's missing!

function choiceFor(choices: number[], round: number): number | null {
  if (round < choices.length) {
    return choices[round];
  }
  return null; // ran out of answers: count it as skipped
}

console.log(choiceFor(playerChoices, 1));
console.log(choiceFor(playerChoices, 5));
```

</CodeExample>

`choiceFor` checks the length first, and honestly returns `number | null`. And `null` is exactly what `grade` from Part 2 already understands as "skipped". The pieces fit together. 🧩

## Feedback for the player

After each question the player wants to know how they did. `feedback` turns a graded answer into a friendly line. It takes the `AnswerResult` from `grade`, so it doesn't need to grade anything itself:

<CodeExample output={`You chose 2 ✅ +10 points
You chose 3 ❌ The answer was: string
Skipped ❌ The answer was: string`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

type AnswerResult = {
  questionId: number;
  correct: boolean;
  points: number;
};

function feedback(
  q: Question,
  choice: number | null,
  result: AnswerResult,
): string {
  const answer = q.choices[q.answer];
  if (choice === null) {
    return `Skipped ❌ The answer was: ${answer}`;
  }
  if (result.correct) {
    return `You chose ${choice} ✅ +${result.points} points`;
  }
  return `You chose ${choice} ❌ The answer was: ${answer}`;
}

const q1: Question = {
  id: 1,
  prompt: "Which type holds text?",
  choices: ["number", "string", "boolean"],
  answer: 1,
  difficulty: "easy",
};

const right: AnswerResult = { questionId: 1, correct: true, points: 10 };
const wrong: AnswerResult = { questionId: 1, correct: false, points: 0 };

console.log(feedback(q1, 2, right));
console.log(feedback(q1, 3, wrong));
console.log(feedback(q1, null, wrong));
```

</CodeExample>

Playing one **round** is then three steps: grade the choice, print the question, print the feedback. In the exercise you'll write it as `playRound(q, choice)`, which also returns the `AnswerResult` so we can add up the score later.

## The results report

At the end, the player gets a **rank**. There are exactly three, so it's another union of literals. A typo in a rank name can't slip through:

```ts
type Rank = "Panda Master" | "Bamboo Expert" | "Curious Cub";

function rankFor(percentage: number): Rank {
  if (percentage >= 80) {
    return "Panda master";
    // ❌ Error: Type '"Panda master"' is not assignable to type 'Rank'. Did you mean '"Panda Master"'?
  }
  // ...
}
```

The rank depends on the **percentage** of points the player won. One small new thing here: `Math.round(n)` rounds a number to the **nearest whole number**, so `12.5` becomes `13` and `74.6` becomes `75`.

There's also a trap. With no questions, the maximum score is `0`, and dividing by `0` gives `NaN` ("not a number"), which would look silly in a report. A guard fixes it:

<CodeExample output={`75 Bamboo Expert
13 Curious Cub
100 Panda Master
NaN
0`}>

```ts
type Rank = "Panda Master" | "Bamboo Expert" | "Curious Cub";

function rankFor(percentage: number): Rank {
  if (percentage >= 80) {
    return "Panda Master";
  }
  if (percentage >= 50) {
    return "Bamboo Expert";
  }
  return "Curious Cub";
}

function percentOf(score: number, max: number): number {
  if (max === 0) {
    return 0; // no questions: don't divide by 0
  }
  return Math.round((score / max) * 100);
}

console.log(percentOf(60, 80), rankFor(percentOf(60, 80)));
console.log(percentOf(10, 80), rankFor(percentOf(10, 80)));
console.log(percentOf(80, 80), rankFor(percentOf(80, 80)));
console.log(0 / 0);
console.log(percentOf(0, 0));
```

</CodeExample>

The whole report is one object, so it gets an interface. Notice that `rank` is a `Rank`, not a plain `string`:

```ts
interface QuizReport {
  score: number;
  maxScore: number;
  correctCount: number;
  questionCount: number;
  percentage: number;
  rank: Rank;
}
```

## Choosing which questions to play

Because `playQuiz` takes the questions as a parameter, you decide **which** questions to play, and in **which order**, before the game starts. Want an easy round? `filter` by difficulty. Want a different order? Pass a list of positions:

<CodeExample output={`[ 3 ]
[ 3, 1, 2 ]
[ 2 ]`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

function byDifficulty(list: Question[], level: Difficulty): Question[] {
  return list.filter((q) => q.difficulty === level);
}

function pickQuestions(list: Question[], order: number[]): Question[] {
  const picked: Question[] = [];
  for (const index of order) {
    if (index >= 0 && index < list.length) {
      picked.push(list[index]); // skip positions that don't exist
    }
  }
  return picked;
}

function makeQuestion(id: number, level: Difficulty): Question {
  return {
    id: id,
    prompt: `Question ${id}`,
    choices: ["yes", "no"],
    answer: 0,
    difficulty: level,
  };
}

const questions: Question[] = [
  makeQuestion(1, "easy"),
  makeQuestion(2, "medium"),
  makeQuestion(3, "hard"),
];

console.log(byDifficulty(questions, "hard").map((q) => q.id));
console.log(pickQuestions(questions, [2, 0, 1]).map((q) => q.id));
console.log(pickQuestions(questions, [1, 7]).map((q) => q.id));
```

</CodeExample>

Then play the round you picked: `playQuiz(byDifficulty(questions, "easy"), [2])`. The order is **injected** as a parameter, just like the player's choices, so even a "shuffled" quiz stays predictable and testable.

<Callout type="tip" title="Inject what changes">

Player input, random order, the current time: anything that changes from run to run is easiest to handle when it's passed **in** as a parameter. Your game logic stays the same, and you can test it with any input you like.

</Callout>

## What you built

- `choiceFor`, which safely turns a missing answer into `null` (a skipped question).
- `feedback` and `playRound`, which show each question and react with ✅ or ❌.
- A `Rank` union and `rankFor`, so a rank name can never be misspelt.
- `percentOf`, with a guard so an empty quiz gives `0%` instead of `NaN`.
- A `QuizReport` interface, `playQuiz` to run the whole game and `printReport` to show the results.
- `byDifficulty` and `pickQuestions`, to choose which questions to play and in which order.

## Take it further

Your quiz game works, and every part of it is typed. Here are some ideas to make it your own:

- **Write your own questions.** Add five questions about something you love to the bank. Run every one through `isValidQuestion` first!
- **Shuffle the questions.** `Math.random()` gives a random number from 0 up to (but not including) 1. Use it to build a random `order` array and pass it to `pickQuestions`. Keep the shuffling separate from the game, so your tests can still use a fixed order.
- **Streak bonus.** Give 5 extra points for every correct answer in a row after the first. Add a `streak` to the report.
- **Category reports.** Add a `category: string` to `Question` and use a `Record<string, number>` to show the score for each category.
- **A rank badge.** Write `badgeFor(rank: Rank): string` with a `switch` and a `never` check that returns an emoji for each rank, then add a new rank and watch TypeScript point at the missing case.
