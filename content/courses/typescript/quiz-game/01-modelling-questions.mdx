Welcome to your first TypeScript capstone! Over three parts you'll build a **typed quiz game** that runs in the console: it asks questions, grades the answers, adds up a score and prints a results report. 🐼

You already know everything you need. This part uses **literal types** and `type` aliases (Control Flow), **interfaces** with optional and `readonly` properties, **arrays of objects** (Arrays, Objects & Interfaces) and **loops** and typed **functions**.

Here's the plan:

- **Part 1 (this one):** design the types and build a question bank.
- **Part 2:** grade the player's answers and add up the score.
- **Part 3:** play a whole quiz and print a results report.

In a real project you start by asking "what does my **data** look like?". Get the types right and the rest of the code almost writes itself.

## Difficulty: a union of literals

Every question will be **easy**, **medium** or **hard**. That's a short, fixed list of options, which is exactly what a union of literal types is for:

<CodeExample output={`[ 'easy', 'medium', 'hard' ]
hard`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

const levels: Difficulty[] = ["easy", "medium", "hard"];
let current: Difficulty = "easy";
current = "hard";

console.log(levels);
console.log(current);
```

</CodeExample>

A plain `string` would accept any text at all. `Difficulty` only accepts those three, so a made-up level is caught straight away:

```ts
current = "impossible";
// ❌ Error: Type '"impossible"' is not assignable to type 'Difficulty'.
```

## The Question interface

Now the main character: one quiz **question**. Let's list what it needs:

- an `id`, so we can tell questions apart (it should never change, so it's `readonly`),
- the `prompt`, the question text,
- the `choices` the player can pick from, a `string[]`,
- the `answer`: the **position** of the right choice in `choices`, counting from 0,
- its `difficulty`,
- optional bonus `points`, for questions worth more than usual.

<CodeExample output={`Which type holds text?
Answer: string
undefined`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number; // position of the right choice, from 0
  difficulty: Difficulty;
  points?: number; // optional bonus points
}

const q1: Question = {
  id: 1,
  prompt: "Which type holds text?",
  choices: ["number", "string", "boolean"],
  answer: 1,
  difficulty: "easy",
};

console.log(q1.prompt);
console.log(`Answer: ${q1.choices[q1.answer]}`);
console.log(q1.points);
```

</CodeExample>

`answer: 1` points at `choices[1]`, which is `"string"`. And because `points` is optional, `q1` can leave it out: reading it gives `undefined`.

## Let the types catch your mistakes

Typing quiz data by hand is fiddly, and this is where the interface pays off. Every question in your game is checked against `Question`, so mistakes like these never reach the player:

```ts
const q2: Question = {
  id: 2,
  prompt: "Which type has no values at all?",
  choices: ["void", "never"],
  answer: "1",
  // ❌ Error: Type 'string' is not assignable to type 'number'.
  difficulty: "medum",
  // ❌ Error: Type '"medum"' is not assignable to type 'Difficulty'. Did you mean '"medium"'?
};
```

Misspell a property name and TypeScript even suggests the right one:

```ts
const q3: Question = {
  id: 3,
  prompt: "Which type has no values at all?",
  choises: ["void", "never"],
  // ❌ Error: Object literal may only specify known properties, but 'choises' does not exist in type 'Question'. Did you mean to write 'choices'?
  answer: 1,
  difficulty: "hard",
};
```

And thanks to `readonly`, nobody can quietly change a question's `id` later:

```ts
q1.id = 5;
// ❌ Error: Cannot assign to 'id' because it is a read-only property.
```

## A typed question bank

A quiz needs more than one question. `Question[]` is a list of them, our **question bank**. Because TypeScript knows the shape of every item, `filter` and `map` are fully typed too:

<CodeExample output={`3 questions
[ 'Which type has no values at all?' ]
Worth extra: 50`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

const questions: Question[] = [
  {
    id: 1,
    prompt: "Which type holds text?",
    choices: ["number", "string", "boolean"],
    answer: 1,
    difficulty: "easy",
  },
  {
    id: 2,
    prompt: "Which values make ?? use its fallback?",
    choices: ["0 and empty strings", "null and undefined"],
    answer: 1,
    difficulty: "medium",
  },
  {
    id: 3,
    prompt: "Which type has no values at all?",
    choices: ["void", "unknown", "never", "null"],
    answer: 2,
    difficulty: "hard",
    points: 50,
  },
];

console.log(`${questions.length} questions`);

const hard = questions.filter((q) => q.difficulty === "hard");
console.log(hard.map((q) => q.prompt));

for (const q of questions) {
  if (q.points !== undefined) {
    console.log(`Worth extra: ${q.points}`);
  }
}
```

</CodeExample>

Even your comparisons are checked. There's no `"expert"` difficulty, so this filter could never match anything, and TypeScript tells you:

```ts
questions.filter((q) => q.difficulty === "expert");
// ❌ Error: This comparison appears to be unintentional because the types 'Difficulty' and '"expert"' have no overlap.
```

## Printing a question

The player needs to see the prompt and **numbered** choices. Let's write `formatQuestion(q)`, which turns a question into text ready to print.

One small new thing: inside a string, `\n` is a **newline** character. It starts a new line when the text is printed. We build the text with `+=`, which adds more text onto the end of a string, just as it adds to a number:

<CodeExample output={`Q1 (easy): Which type holds text?
  1. number
  2. string
  3. boolean`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

function formatQuestion(q: Question): string {
  let text = `Q${q.id} (${q.difficulty}): ${q.prompt}`;
  for (let i = 0; i < q.choices.length; i++) {
    text += `\n  ${i + 1}. ${q.choices[i]}`;
  }
  return text;
}

const q1: Question = {
  id: 1,
  prompt: "Which type holds text?",
  choices: ["number", "string", "boolean"],
  answer: 1,
  difficulty: "easy",
};

console.log(formatQuestion(q1));
```

</CodeExample>

We use a counting `for` loop here (not `for...of`) because we need the position `i` to number the choices. Arrays count from 0, but people count from 1, so we print `i + 1`.

<Callout type="note" title="Return text, don't print it">

`formatQuestion` **returns** a string instead of calling `console.log` itself. That makes it more useful: you can print the result, test it, or add more text to it later. In Part 3 we'll reuse it to show each question during the game.

</Callout>

## Types check the shape, not the sense

Here's a question TypeScript is perfectly happy with:

```ts
const broken: Question = {
  id: 9,
  prompt: "Pick one",
  choices: ["yes", "no"],
  answer: 5, // there is no choice 5!
  difficulty: "easy",
};
```

`answer` is a `number`, so the **shape** is right. But there's no `choices[5]`, so nobody could ever get this question right. Types can't know how long an array will be, so some checks have to happen while the program runs. That's the job of `isValidQuestion(q)`:

<CodeExample output={`true
false
false
false`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

function isValidQuestion(q: Question): boolean {
  if (q.choices.length < 2) {
    return false; // not much of a choice!
  }
  if (q.answer < 0 || q.answer >= q.choices.length) {
    return false; // the answer must point at a real choice
  }
  if (q.points !== undefined && q.points <= 0) {
    return false; // bonus points must be positive
  }
  return true;
}

const good: Question = {
  id: 1,
  prompt: "Pick one",
  choices: ["yes", "no"],
  answer: 1,
  difficulty: "easy",
};

console.log(isValidQuestion(good));
console.log(isValidQuestion({ ...good, answer: 2 }));
console.log(isValidQuestion({ ...good, choices: ["yes"] }));
console.log(isValidQuestion({ ...good, points: 0 }));
```

</CodeExample>

`{ ...good, answer: 2 }` copies `good` and replaces one property, a handy way to make test questions. With 2 choices the valid positions are `0` and `1`, so `answer: 2` is out of range.

Notice the check on `points`: it's optional, so we only test it when it's **not** `undefined`. Leaving out bonus points is fine.

<Callout type="tip" title="Two kinds of safety">

The compiler checks your code **before** it runs: right properties, right types, no typos. Validation functions check your data **while** it runs: values in range, lists long enough. Good programs use both.

</Callout>

## What you built

- A `Difficulty` union that only allows `"easy"`, `"medium"` or `"hard"`.
- A `Question` interface with a `readonly` id, an optional `points` property and an `answer` that points into `choices`.
- A typed question bank, `Question[]`, where every question is checked for missing properties, wrong types and typos.
- `formatQuestion(q)`, which returns a question as text with numbered choices (using `\n` for new lines).
- `isValidQuestion(q)`, which catches mistakes the types can't see, like an answer that's out of range.
