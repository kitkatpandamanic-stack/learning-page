In Part 1 you modelled the questions. Now it's time to **grade** them: did the player pick the right choice, and how many points is that worth? 🎯

Grading is where bugs love to hide: a player might skip a question or type a number that isn't one of the choices. This part uses **narrowing** with `null` checks (Basics and Control Flow), `switch` with a `never` check (Literal Types & switch), the `??` operator and a loop with an **accumulator** (Typed Loops).

## What a graded answer looks like

Before writing any grading code, let's decide what grading **gives back**. For each question we want to know which question it was, whether the player got it right and how many points they earned:

<CodeExample output={`{ questionId: 1, correct: true, points: 10 }
{ questionId: 2, correct: false, points: 0 }`}>

```ts
type AnswerResult = {
  questionId: number;
  correct: boolean;
  points: number;
};

const right: AnswerResult = { questionId: 1, correct: true, points: 10 };
const wrong: AnswerResult = { questionId: 2, correct: false, points: 0 };

console.log(right);
console.log(wrong);
```

</CodeExample>

This time we used a `type` alias instead of an `interface`. For object shapes they work almost the same, so either is fine. Whichever you pick, every `AnswerResult` must have all three properties:

```ts
const oops: AnswerResult = { questionId: 1, correct: true };
// ❌ Error: Property 'points' is missing in type '{ questionId: number; correct: true; }' but required in type 'AnswerResult'.
```

## Points by difficulty

Harder questions should be worth more: **10** points for easy, **20** for medium and **30** for hard. One value, a few exact options: that's a job for `switch`. We add the `never` check in `default`, so TypeScript warns us if we ever forget a difficulty:

<CodeExample output={`10
20
30`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

function pointsFor(difficulty: Difficulty): number {
  switch (difficulty) {
    case "easy":
      return 10;
    case "medium":
      return 20;
    case "hard":
      return 30;
    default: {
      const unreachable: never = difficulty;
      return unreachable;
    }
  }
}

console.log(pointsFor("easy"));
console.log(pointsFor("medium"));
console.log(pointsFor("hard"));
```

</CodeExample>

Imagine that next month you add an `"expert"` level to `Difficulty`. You'd probably forget about `pointsFor`, but TypeScript won't:

```ts
type Difficulty = "easy" | "medium" | "hard" | "expert";

// ...same switch as above...
    default: {
      const unreachable: never = difficulty;
      // ❌ Error: Type '"expert"' is not assignable to type 'never'.
      return unreachable;
    }
```

## Bonus points win

Remember the optional `points` property from Part 1? When a question has its own `points`, they replace the difficulty points. The `??` operator says exactly that: "use `q.points`, unless it's `undefined`, then use the difficulty points":

<CodeExample output={`10
50`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

function pointsFor(difficulty: Difficulty): number {
  switch (difficulty) {
    case "easy":
      return 10;
    case "medium":
      return 20;
    case "hard":
      return 30;
    default: {
      const unreachable: never = difficulty;
      return unreachable;
    }
  }
}

function questionPoints(q: Question): number {
  return q.points ?? pointsFor(q.difficulty);
}

const easy: Question = {
  id: 1,
  prompt: "Which type holds text?",
  choices: ["number", "string", "boolean"],
  answer: 1,
  difficulty: "easy",
};

console.log(questionPoints(easy));
console.log(questionPoints({ ...easy, points: 50 }));
```

</CodeExample>

## Grading an answer safely

Now the main event: `grade(q, choice)`. Two decisions shape it:

- **`choice` is the number the player sees.** The choices are printed as 1, 2, 3..., so a player who picks the first choice gives us `1`. Our `answer` counts from 0, so we compare `choice - 1` with `q.answer`.
- **The player might skip.** We'll use `null` for "no answer", so the type of `choice` is `number | null`.

A first try forgets about skipping, and TypeScript stops us:

```ts
function isRight(q: Question, choice: number | null): boolean {
  return choice - 1 === q.answer;
  // ❌ Error: 'choice' is possibly 'null'.
}
```

The fix is to deal with the awkward cases **first**, each with an early `return`. These checks are often called **guards**. Once `null` has been handled, TypeScript **narrows** `choice` to a plain `number` for the rest of the function:

<CodeExample output={`{ questionId: 1, correct: true, points: 10 }
{ questionId: 1, correct: false, points: 0 }
{ questionId: 1, correct: false, points: 0 }
{ questionId: 1, correct: false, points: 0 }`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

type AnswerResult = {
  questionId: number;
  correct: boolean;
  points: number;
};

function grade(q: Question, choice: number | null): AnswerResult {
  if (choice === null) {
    // skipped: no points
    return { questionId: q.id, correct: false, points: 0 };
  }
  // from here on, choice is a number
  if (choice < 1 || choice > q.choices.length) {
    // not one of the choices: no points
    return { questionId: q.id, correct: false, points: 0 };
  }
  if (choice - 1 !== q.answer) {
    // a real choice, but the wrong one
    return { questionId: q.id, correct: false, points: 0 };
  }
  return { questionId: q.id, correct: true, points: 10 };
}

const q1: Question = {
  id: 1,
  prompt: "Which type holds text?",
  choices: ["number", "string", "boolean"],
  answer: 1,
  difficulty: "easy",
};

console.log(grade(q1, 2)); // "string": correct!
console.log(grade(q1, 1)); // "number": wrong
console.log(grade(q1, 7)); // there is no choice 7
console.log(grade(q1, null)); // skipped
```

</CodeExample>

To keep this example short, a correct answer is always worth `10` here. In the exercise you'll use `questionPoints(q)` instead.

Why check the range at all, if a wrong number just gives `false` anyway? Because it makes our intent clear, and it protects us from strange input like `0` or `-1`. Good grading code never assumes the player behaves.

<Callout type="warning" title="Counting from 0 or from 1?">

Mixing up "position from 0" and "number from 1" is one of the most common bugs in programming (it even has a name: an **off-by-one error**). Here, `answer` counts from 0 like an array, and `choice` counts from 1 like a person. The only place the two meet is `choice - 1`, so keep it in one spot.

</Callout>

## Adding up the score

The player answers several questions, so we'll get an `AnswerResult[]`. The total score is a classic **accumulator** loop. We also want the **maximum** possible score, so we can show "60 out of 80" later:

<CodeExample output={`Score: 60/80`}>

```ts
type AnswerResult = {
  questionId: number;
  correct: boolean;
  points: number;
};

function totalScore(results: AnswerResult[]): number {
  let total = 0;
  for (const result of results) {
    total += result.points;
  }
  return total;
}

const results: AnswerResult[] = [
  { questionId: 1, correct: true, points: 10 },
  { questionId: 2, correct: false, points: 0 },
  { questionId: 3, correct: true, points: 50 },
];

// the most points the three questions could give
const max = 10 + 20 + 50;

console.log(`Score: ${totalScore(results)}/${max}`);
```

</CodeExample>

In the exercise, `maxScore(list)` works out that maximum with the same kind of loop, adding up `questionPoints(q)` for every question.

<Callout type="tip" title="Small functions, big game">

`pointsFor`, `questionPoints`, `grade`, `totalScore`: each function does **one** job and has clear types for what goes in and what comes out. That makes each one easy to test on its own, and in Part 3 they'll snap together like building blocks.

</Callout>

## What you built

- An `AnswerResult` type that describes the result of grading one question.
- `pointsFor(difficulty)`, a `switch` with a `never` check, so a new difficulty can't be forgotten.
- `questionPoints(q)`, which uses `??` to let bonus `points` win over the difficulty points.
- `grade(q, choice)`, which uses **guards** to handle skipped (`null`), out-of-range and wrong answers before rewarding a right one.
- `totalScore(results)` and `maxScore(list)`, two accumulator loops for the score.
