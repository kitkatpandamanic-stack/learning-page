Добро пожаловать в ваш первый итоговый проект по TypeScript! За три части вы соберёте **типизированную игру-викторину**, которая работает в консоли (console): она задаёт вопросы, проверяет ответы, подсчитывает очки и выводит отчёт с результатами. 🐼

Всё необходимое вы уже знаете. В этой части пригодятся **литеральные типы** (literal types) и псевдонимы `type` (модуль «Управление потоком»), **интерфейсы** с необязательными и `readonly`-свойствами, **массивы объектов** (модуль «Массивы, объекты и интерфейсы»), а также **циклы** и типизированные **функции**.

План такой:

- **Часть 1 (эта):** проектируем типы и собираем банк вопросов.
- **Часть 2:** проверяем ответы игрока и подсчитываем очки.
- **Часть 3:** играем викторину целиком и выводим отчёт с результатами.

В настоящем проекте всё начинается с вопроса «как выглядят мои **данные**?». Если типы выбраны правильно, остальной код почти пишется сам.

## Сложность: объединение литералов

Каждый вопрос будет **лёгким** (easy), **средним** (medium) или **сложным** (hard). Это короткий фиксированный список вариантов — ровно то, для чего нужно объединение литеральных типов:

<CodeExample output={`[ 'easy', 'medium', 'hard' ]
hard`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

const levels: Difficulty[] = ["easy", "medium", "hard"];
let current: Difficulty = "easy";
current = "hard";

console.log(levels);
console.log(current);
```

</CodeExample>

Обычный `string` принял бы любой текст. `Difficulty` принимает только эти три значения, поэтому выдуманный уровень сразу же отлавливается:

```ts
current = "impossible";
// ❌ Error: Type '"impossible"' is not assignable to type 'Difficulty'.
```

## Интерфейс Question

Теперь главный герой — один **вопрос** викторины. Перечислим, что ему нужно:

- `id`, чтобы различать вопросы (он никогда не должен меняться, поэтому он `readonly`),
- `prompt` — текст вопроса,
- `choices` — варианты ответа, из которых выбирает игрок, `string[]`,
- `answer` — **позиция** правильного варианта в `choices`, считая с 0,
- `difficulty` — сложность вопроса,
- необязательные бонусные очки `points` — для вопросов, которые стоят больше обычного.

<CodeExample output={`Какой тип хранит текст?
Ответ: string
undefined`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number; // позиция правильного варианта, с 0
  difficulty: Difficulty;
  points?: number; // необязательные бонусные очки
}

const q1: Question = {
  id: 1,
  prompt: "Какой тип хранит текст?",
  choices: ["number", "string", "boolean"],
  answer: 1,
  difficulty: "easy",
};

console.log(q1.prompt);
console.log(`Ответ: ${q1.choices[q1.answer]}`);
console.log(q1.points);
```

</CodeExample>

`answer: 1` указывает на `choices[1]`, то есть на `"string"`. А раз `points` — необязательное свойство, в `q1` его можно не указывать: при чтении получится `undefined`.

## Пусть типы ловят ваши ошибки

Набирать данные викторины вручную — кропотливое дело, и именно здесь интерфейс окупается. Каждый вопрос в игре проверяется на соответствие `Question`, поэтому такие ошибки никогда не дойдут до игрока:

```ts
const q2: Question = {
  id: 2,
  prompt: "У какого типа нет ни одного значения?",
  choices: ["void", "never"],
  answer: "1",
  // ❌ Error: Type 'string' is not assignable to type 'number'.
  difficulty: "medum",
  // ❌ Error: Type '"medum"' is not assignable to type 'Difficulty'. Did you mean '"medium"'?
};
```

Опечатайтесь в имени свойства — и TypeScript даже подскажет правильное:

```ts
const q3: Question = {
  id: 3,
  prompt: "У какого типа нет ни одного значения?",
  choises: ["void", "never"],
  // ❌ Error: Object literal may only specify known properties, but 'choises' does not exist in type 'Question'. Did you mean to write 'choices'?
  answer: 1,
  difficulty: "hard",
};
```

А благодаря `readonly` никто не сможет потихоньку изменить `id` вопроса позже:

```ts
q1.id = 5;
// ❌ Error: Cannot assign to 'id' because it is a read-only property.
```

## Типизированный банк вопросов

Одного вопроса для викторины мало. `Question[]` — это список вопросов, наш **банк вопросов**. Поскольку TypeScript знает форму каждого элемента, `filter` и `map` тоже полностью типизированы:

<CodeExample output={`Вопросов: 3
[ 'У какого типа нет ни одного значения?' ]
Бонус: 50`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

const questions: Question[] = [
  {
    id: 1,
    prompt: "Какой тип хранит текст?",
    choices: ["number", "string", "boolean"],
    answer: 1,
    difficulty: "easy",
  },
  {
    id: 2,
    prompt: "При каких значениях ?? берёт запасное значение?",
    choices: ["0 и пустые строки", "null и undefined"],
    answer: 1,
    difficulty: "medium",
  },
  {
    id: 3,
    prompt: "У какого типа нет ни одного значения?",
    choices: ["void", "unknown", "never", "null"],
    answer: 2,
    difficulty: "hard",
    points: 50,
  },
];

console.log(`Вопросов: ${questions.length}`);

const hard = questions.filter((q) => q.difficulty === "hard");
console.log(hard.map((q) => q.prompt));

for (const q of questions) {
  if (q.points !== undefined) {
    console.log(`Бонус: ${q.points}`);
  }
}
```

</CodeExample>

Проверяются даже сравнения. Сложности `"expert"` не существует, поэтому такой фильтр никогда ничего не найдёт, и TypeScript вам об этом скажет:

```ts
questions.filter((q) => q.difficulty === "expert");
// ❌ Error: This comparison appears to be unintentional because the types 'Difficulty' and '"expert"' have no overlap.
```

## Выводим вопрос

Игроку нужно увидеть текст вопроса и **пронумерованные** варианты. Напишем `formatQuestion(q)`, которая превращает вопрос в текст, готовый к выводу.

Одна небольшая новинка: внутри строки `\n` — это символ **перевода строки**. При выводе он начинает новую строку. Текст мы собираем с помощью `+=`: он дописывает текст в конец строки так же, как прибавляет к числу:

<CodeExample output={`Q1 (easy): Какой тип хранит текст?
  1. number
  2. string
  3. boolean`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

function formatQuestion(q: Question): string {
  let text = `Q${q.id} (${q.difficulty}): ${q.prompt}`;
  for (let i = 0; i < q.choices.length; i++) {
    text += `\n  ${i + 1}. ${q.choices[i]}`;
  }
  return text;
}

const q1: Question = {
  id: 1,
  prompt: "Какой тип хранит текст?",
  choices: ["number", "string", "boolean"],
  answer: 1,
  difficulty: "easy",
};

console.log(formatQuestion(q1));
```

</CodeExample>

Здесь мы используем цикл `for` со счётчиком (а не `for...of`), потому что для нумерации вариантов нужна позиция `i`. Массивы считают с 0, а люди — с 1, поэтому выводим `i + 1`.

<Callout type="note" title="Возвращайте текст, а не выводите его">

`formatQuestion` **возвращает** строку, а не вызывает `console.log` сама. Так она полезнее: результат можно вывести, протестировать или дописать к нему текст позже. В части 3 мы снова используем её, чтобы показывать каждый вопрос во время игры.

</Callout>

## Типы проверяют форму, а не смысл

Вот вопрос, которым TypeScript совершенно доволен:

```ts
const broken: Question = {
  id: 9,
  prompt: "Выберите вариант",
  choices: ["да", "нет"],
  answer: 5, // варианта 5 не существует!
  difficulty: "easy",
};
```

`answer` — это `number`, так что **форма** правильная. Но `choices[5]` нет, а значит, ответить на этот вопрос правильно невозможно. Типы не знают, какой длины будет массив, поэтому часть проверок приходится делать во время работы программы. Это задача `isValidQuestion(q)`:

<CodeExample output={`true
false
false
false`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

function isValidQuestion(q: Question): boolean {
  if (q.choices.length < 2) {
    return false; // какой же это выбор!
  }
  if (q.answer < 0 || q.answer >= q.choices.length) {
    return false; // ответ должен указывать на существующий вариант
  }
  if (q.points !== undefined && q.points <= 0) {
    return false; // бонусные очки должны быть положительными
  }
  return true;
}

const good: Question = {
  id: 1,
  prompt: "Выберите вариант",
  choices: ["да", "нет"],
  answer: 1,
  difficulty: "easy",
};

console.log(isValidQuestion(good));
console.log(isValidQuestion({ ...good, answer: 2 }));
console.log(isValidQuestion({ ...good, choices: ["да"] }));
console.log(isValidQuestion({ ...good, points: 0 }));
```

</CodeExample>

`{ ...good, answer: 2 }` копирует `good` и заменяет одно свойство — удобный способ делать тестовые вопросы. При 2 вариантах допустимые позиции — `0` и `1`, так что `answer: 2` выходит за пределы.

Обратите внимание на проверку `points`: это свойство необязательное, поэтому мы проверяем его, только если оно **не** `undefined`. Не указывать бонусные очки — нормально.

<Callout type="tip" title="Два вида безопасности">

Компилятор проверяет код **до** запуска: правильные свойства, правильные типы, никаких опечаток. Функции валидации проверяют данные **во время** работы: значения в допустимых пределах, списки достаточной длины. Хорошие программы используют и то и другое.

</Callout>

  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

const questions: Question[] = [
  {
    id: 1,
    prompt: "Какой тип хранит текст?",
    choices: ["number", "string", "boolean"],
    answer: 1,
    difficulty: "easy",

}

## Что вы собрали

- Объединение `Difficulty`, которое допускает только `"easy"`, `"medium"` или `"hard"`.
- Интерфейс `Question` с `readonly`-полем id, необязательным свойством `points` и полем `answer`, которое указывает на позицию в `choices`.
- Типизированный банк вопросов `Question[]`, где каждый вопрос проверяется на пропущенные свойства, неверные типы и опечатки.
- `formatQuestion(q)`, которая возвращает вопрос в виде текста с пронумерованными вариантами (используя `\n` для переноса строк).
- `isValidQuestion(q)`, которая ловит ошибки, не видимые типам, например ответ за пределами списка вариантов.

В части 2 вы будете проверять ответы игрока и подсчитывать его очки. 🎯
