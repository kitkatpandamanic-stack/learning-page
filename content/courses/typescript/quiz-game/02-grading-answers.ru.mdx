В части 1 вы смоделировали вопросы. Теперь пора их **проверять**: выбрал ли игрок правильный вариант и сколько очков он за это получает? 🎯

Проверка ответов — любимое место для багов: игрок может пропустить вопрос или ввести номер, которого нет среди вариантов. В этой части пригодятся **сужение типа** (narrowing) с проверками на `null` (модули «Основы» и «Управление потоком»), `switch` с проверкой `never` (урок «Литеральные типы и switch»), оператор `??` и цикл с **накопителем** (урок «Типизированные циклы»).

## Как выглядит проверенный ответ

Прежде чем писать код проверки, решим, что проверка будет **возвращать**. Для каждого вопроса мы хотим знать, что это был за вопрос, ответил ли игрок правильно и сколько очков он заработал:

<CodeExample output={`{ questionId: 1, correct: true, points: 10 }
{ questionId: 2, correct: false, points: 0 }`}>

```ts
type AnswerResult = {
  questionId: number;
  correct: boolean;
  points: number;
};

const right: AnswerResult = { questionId: 1, correct: true, points: 10 };
const wrong: AnswerResult = { questionId: 2, correct: false, points: 0 };

console.log(right);
console.log(wrong);
```

</CodeExample>

На этот раз мы взяли псевдоним `type` вместо `interface`. Для форм объектов они работают почти одинаково, так что подойдёт любой. Что бы вы ни выбрали, у каждого `AnswerResult` должны быть все три свойства:

```ts
const oops: AnswerResult = { questionId: 1, correct: true };
// ❌ Error: Property 'points' is missing in type '{ questionId: number; correct: true; }' but required in type 'AnswerResult'.
```

## Очки по сложности

Сложные вопросы должны стоить больше: **10** очков за лёгкий, **20** за средний и **30** за сложный. Одно значение и несколько точных вариантов — работа для `switch`. В `default` добавим проверку `never`, чтобы TypeScript предупредил нас, если мы когда-нибудь забудем какую-то сложность:

<CodeExample output={`10
20
30`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

function pointsFor(difficulty: Difficulty): number {
  switch (difficulty) {
    case "easy":
      return 10;
    case "medium":
      return 20;
    case "hard":
      return 30;
    default: {
      const unreachable: never = difficulty;
      return unreachable;
    }
  }
}

console.log(pointsFor("easy"));
console.log(pointsFor("medium"));
console.log(pointsFor("hard"));
```

</CodeExample>

Представьте, что в следующем месяце вы добавите в `Difficulty` уровень `"expert"`. Про `pointsFor` вы, скорее всего, забудете, а вот TypeScript — нет:

```ts
type Difficulty = "easy" | "medium" | "hard" | "expert";

// ...тот же switch, что и выше...
    default: {
      const unreachable: never = difficulty;
      // ❌ Error: Type '"expert"' is not assignable to type 'never'.
      return unreachable;
    }
```

## Бонусные очки важнее

Помните необязательное свойство `points` из части 1? Если у вопроса есть свои `points`, они заменяют очки за сложность. Оператор `??` говорит ровно это: «возьми `q.points`, а если там `undefined` — очки за сложность»:

<CodeExample output={`10
50`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

function pointsFor(difficulty: Difficulty): number {
  switch (difficulty) {
    case "easy":
      return 10;
    case "medium":
      return 20;
    case "hard":
      return 30;
    default: {
      const unreachable: never = difficulty;
      return unreachable;
    }
  }
}

function questionPoints(q: Question): number {
  return q.points ?? pointsFor(q.difficulty);
}

const easy: Question = {
  id: 1,
  prompt: "Какой тип хранит текст?",
  choices: ["number", "string", "boolean"],
  answer: 1,
  difficulty: "easy",
};

console.log(questionPoints(easy));
console.log(questionPoints({ ...easy, points: 50 }));
```

</CodeExample>

## Безопасная проверка ответа

Теперь главное событие — `grade(q, choice)`. Её форму определяют два решения:

- **`choice` — это номер, который видит игрок.** Варианты выводятся как 1, 2, 3..., поэтому игрок, выбравший первый вариант, передаёт нам `1`. А наш `answer` считается с 0, поэтому мы сравниваем `choice - 1` с `q.answer`.
- **Игрок может пропустить вопрос.** «Нет ответа» обозначим через `null`, так что тип `choice` — `number | null`.

Первая попытка забывает о пропуске, и TypeScript нас останавливает:

```ts
function isRight(q: Question, choice: number | null): boolean {
  return choice - 1 === q.answer;
  // ❌ Error: 'choice' is possibly 'null'.
}
```

Решение — сначала разобраться с неудобными случаями, каждый раз выходя из функции ранним `return`. Такие проверки часто называют **защитными условиями** (guards). Как только `null` обработан, TypeScript **сужает** тип `choice` до обычного `number` до конца функции:

<CodeExample output={`{ questionId: 1, correct: true, points: 10 }
{ questionId: 1, correct: false, points: 0 }
{ questionId: 1, correct: false, points: 0 }
{ questionId: 1, correct: false, points: 0 }`}>

```ts
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

type AnswerResult = {
  questionId: number;
  correct: boolean;
  points: number;
};

function grade(q: Question, choice: number | null): AnswerResult {
  if (choice === null) {
    // пропущен: без очков
    return { questionId: q.id, correct: false, points: 0 };
  }
  // дальше choice — это число
  if (choice < 1 || choice > q.choices.length) {
    // такого варианта нет: без очков
    return { questionId: q.id, correct: false, points: 0 };
  }
  if (choice - 1 !== q.answer) {
    // настоящий вариант, но неправильный
    return { questionId: q.id, correct: false, points: 0 };
  }
  return { questionId: q.id, correct: true, points: 10 };
}

const q1: Question = {
  id: 1,
  prompt: "Какой тип хранит текст?",
  choices: ["number", "string", "boolean"],
  answer: 1,
  difficulty: "easy",
};

console.log(grade(q1, 2)); // "string": верно!
console.log(grade(q1, 1)); // "number": неверно
console.log(grade(q1, 7)); // варианта 7 нет
console.log(grade(q1, null)); // пропущен
```

</CodeExample>

Чтобы пример был коротким, правильный ответ здесь всегда стоит `10`. В упражнении вы будете использовать `questionPoints(q)`.

Зачем вообще проверять диапазон, если неверный номер и так даст `false`? Потому что так намерение понятнее, и это защищает от странного ввода вроде `0` или `-1`. Хороший код проверки никогда не полагается на то, что игрок будет вести себя хорошо.

<Callout type="warning" title="Считать с 0 или с 1?">

Путаница между «позицией с 0» и «номером с 1» — одна из самых частых ошибок в программировании (у неё даже есть название: **ошибка на единицу**, off-by-one error). Здесь `answer` считается с 0, как в массиве, а `choice` — с 1, как у людей. Единственное место, где они встречаются, — это `choice - 1`, так что держите это преобразование в одном месте.

</Callout>

## Подсчитываем очки

Игрок отвечает на несколько вопросов, поэтому у нас будет `AnswerResult[]`. Общий счёт — классический цикл с **накопителем**. Ещё нам нужен **максимально** возможный счёт, чтобы потом показать «60 из 80»:

<CodeExample output={`Счёт: 60/80`}>

```ts
type AnswerResult = {
  questionId: number;
  correct: boolean;
  points: number;
};

function totalScore(results: AnswerResult[]): number {
  let total = 0;
  for (const result of results) {
    total += result.points;
  }
  return total;
}

const results: AnswerResult[] = [
  { questionId: 1, correct: true, points: 10 },
  { questionId: 2, correct: false, points: 0 },
  { questionId: 3, correct: true, points: 50 },
];

// максимум очков, который могут дать три вопроса
const max = 10 + 20 + 50;

console.log(`Счёт: ${totalScore(results)}/${max}`);
```

</CodeExample>

В упражнении `maxScore(list)` вычисляет этот максимум таким же циклом, складывая `questionPoints(q)` для каждого вопроса.

<Callout type="tip" title="Маленькие функции, большая игра">

`pointsFor`, `questionPoints`, `grade`, `totalScore`: каждая функция делает **одну** работу и имеет понятные типы того, что принимает и что возвращает. Поэтому каждую легко протестировать отдельно, а в части 3 они сложатся вместе, как кубики конструктора.

</Callout>

```ts
// ===== Часть 1: вопросы (готово!) =====
type Difficulty = "easy" | "medium" | "hard";

interface Question {
  readonly id: number;
  prompt: string;
  choices: string[];
  answer: number;
  difficulty: Difficulty;
  points?: number;
}

const questions: Question[] = [
  {
    id: 1,
    prompt: "Какой тип хранит текст?",
    choices: ["number", "string", "boolean"],
    answer: 1,
    difficulty: "easy",
  },
  {
    id: 2,
    prompt: "При каких значениях ?? берёт запасное значение?",
    choices: ["0 и пустые строки", "null и undefined"],
    answer: 1,
    difficulty: "medium",
  },
  {
    id: 3,
    prompt: "У какого типа нет ни одного значения?",
    choices: ["void", "unknown", "never", "null"],
    answer: 2,
    difficulty: "hard",
    points: 50,
  },
];

function formatQuestion(q: Question): string {
  let text = `Q${q.id} (${q.difficulty}): ${q.prompt}`;
  for (let i = 0; i < q.choices.length; i++) {
    text += `\n  ${i + 1}. ${q.choices[i]}`;
  }
  return text;
}

function isValidQuestion(q: Question): boolean {
  if (q.choices.length < 2) {
    return false;
  }
  if (q.answer < 0 || q.answer >= q.choices.length) {
    return false;
  }
  if (q.points !== undefined && q.points <= 0) {
    return false;
  }
  return true;
}

// ===== Часть 2: проверка ответов =====
type AnswerResult = {
  questionId: number;
  correct: boolean;
  points: number;
};

function pointsFor(difficulty: Difficulty): number {
  switch (difficulty) {
    case "easy":
      return 10;
    case "medium":
      return 20;
    case "hard":
      return 30;
    default: {
      const unreachable: never = difficulty;
      return unreachable;
    }
  }
}

function questionPoints(q: Question): number {
  return q.points ?? pointsFor(q.difficulty);
}

function grade(q: Question, choice: number | null): AnswerResult {
  if (choice === null) {
    return { questionId: q.id, correct: false, points: 0 };
  }
  if (choice < 1 || choice > q.choices.length) {
    return { questionId: q.id, correct: false, points: 0 };
  }
  if (choice - 1 !== q.answer) {
    return { questionId: q.id, correct: false, points: 0 };
  }
  return { questionId: q.id, correct: true, points: questionPoints(q) };
}

function totalScore(results: AnswerResult[]): number {
  let total = 0;
  for (const result of results) {
    total += result.points;
  }
  return total;
}

function maxScore(list: Question[]): number {
  let total = 0;
  for (const q of list) {
    total += questionPoints(q);
  }
  return total;
}

const results: AnswerResult[] = [
  grade(questions[0], 2),
  grade(questions[1], 1),
  grade(questions[2], 3),
];
console.log(results);
console.log(`Счёт: ${totalScore(results)}/${maxScore(questions)}`);
// Счёт: 60/80
```

## Что вы собрали

- Тип `AnswerResult`, который описывает результат проверки одного вопроса.
- `pointsFor(difficulty)` — `switch` с проверкой `never`, так что новую сложность невозможно забыть.
- `questionPoints(q)`, которая с помощью `??` даёт бонусным `points` приоритет над очками за сложность.
- `grade(q, choice)`, которая с помощью **защитных условий** обрабатывает пропущенные (`null`), выходящие за диапазон и неверные ответы, прежде чем наградить за верный.
- `totalScore(results)` и `maxScore(list)` — два цикла с накопителем для подсчёта очков.
