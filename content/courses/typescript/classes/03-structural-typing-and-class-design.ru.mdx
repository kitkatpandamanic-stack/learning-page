В языках вроде Java или C# объект имеет тип `Point`, только если его создал класс `Point`. TypeScript устроен иначе: ему важна **форма** объекта, а не то, откуда он взялся. Для классов у этого есть неожиданные и полезные последствия. В этом уроке вы их изучите, узнаете, как проектировать классы, которые легко менять и тестировать, поймёте, когда класс писать **не** нужно, а затем построите парковку. 🚗

## Структурная типизация: формы, а не имена

TypeScript проверяет, есть ли у значения нужные **свойства нужных типов**. Если есть — значение подходит, кто бы его ни создал. Это называется **структурной типизацией** (structural typing), или «утиной типизацией» (duck typing): если что-то ходит как утка и крякает как утка, то это утка 🦆:

<CodeExample output={`5
10
false`}>

```ts
class Point {
  constructor(public x: number, public y: number) {}
}

function distance(a: Point, b: Point): number {
  return Math.hypot(b.x - a.x, b.y - a.y);
}

// Объектный литерал может быть Point: `new` не нужен
const corner: Point = { x: 3, y: 4 };
console.log(distance(new Point(0, 0), corner));

// Другой класс с такими же x и y тоже подходит
class Pixel {
  constructor(
    public x: number,
    public y: number,
    public colour: string,
  ) {}
}
console.log(distance(new Pixel(0, 0, "red"), { x: 6, y: 8 }));

// ...но Point его никогда не создавал
console.log(corner instanceof Point);
```

</CodeExample>

`Pixel` никак не связан с `Point`, но у него есть числовые `x` и `y`, поэтому он подходит везде, где нужен `Point`. Лишнее поле `colour` не мешает. Методы тоже входят в форму: будь у `Point` метод `describe()`, он понадобился бы и объектному литералу.

Подвох — в последней строке: TypeScript согласился, что `corner` — это `Point`, но во время выполнения это обычный объект. `instanceof` проверяет, **как объект был создан**, а не его форму, поэтому выдаёт `false`.

## Приватные члены меняют правила

Есть одно исключение. Класс с членом `private` или `protected` подделать нельзя: его типу соответствуют только объекты, созданные этим классом (или его подклассами):

```ts
class Account {
  constructor(private balance: number) {}
}

const fake: Account = { balance: 1_000_000 };
// ❌ Error: Type '{ balance: number; }' is not assignable to type 'Account'.
```

Не подходит даже другой класс с точно таким же приватным членом, потому что, по словам TypeScript, эти два приватных поля происходят из «разных объявлений» (separate declarations):

```ts
class SavingsAccount {
  constructor(private balance: number) {}
}

const savings: Account = new SavingsAccount(50);
// ❌ Error: Type 'SavingsAccount' is not assignable to type 'Account'.
```

Это не баг, а возможность: если класс хранит приватное состояние, то каждый объект этого типа действительно прошёл через его конструктор и его правила. Никто не подсунет вам самодельный «счёт» с балансом в миллион.

## Класс — это и тип, и значение

Когда вы пишете `class Lamp { ... }`, вы получаете **две** вещи с одним именем:

- **тип** `Lamp` — форму объектов, которые он создаёт;
- **значение** `Lamp` — сам класс, который можно вызвать через `new`, передать в функцию и прочитать у него статические члены.

Иногда нужно передать сам класс, а не один из его объектов. Тип «чего-то, что можно вызвать через `new`» записывается как `new (...params) => Type`:

<CodeExample output={`💡 лампа (прихожая)
💡 лампа (кухня)
🌀 вентилятор (спальня)`}>

```ts
interface Device {
  readonly room: string;
  describe(): string;
}

class Lamp implements Device {
  constructor(readonly room: string) {}
  describe(): string {
    return `💡 лампа (${this.room})`;
  }
}

class Fan implements Device {
  constructor(readonly room: string) {}
  describe(): string {
    return `🌀 вентилятор (${this.room})`;
  }
}

// Любой класс, чей конструктор принимает room и создаёт Device
type DeviceClass = new (room: string) => Device;

function install(Kind: DeviceClass, rooms: string[]): Device[] {
  return rooms.map((room) => new Kind(room));
}

const devices = [
  ...install(Lamp, ["прихожая", "кухня"]),
  ...install(Fan, ["спальня"]),
];
for (const d of devices) {
  console.log(d.describe());
}
```

</CodeExample>

Чтобы сослаться на тип одного **конкретного** класса (вместе с его статическими членами), используйте **`typeof`**: `typeof Lamp` — это тип самого класса, а `Lamp` — тип его объектов. Путать их — классическая ошибка:

```ts
function build(Kind: Lamp): Lamp {
  return new Kind("прихожая");
  // ❌ Error: This expression is not constructable.
}

function buildLamp(Kind: typeof Lamp): Lamp {
  return new Kind("прихожая"); // всё в порядке
}
```

## Сужение через `instanceof`

В уроке [Объединения типов](/learn/typescript/union-types) вы сужали значения с помощью `instanceof`. С собственными классами это становится по-настоящему полезным, особенно для **собственных ошибок**. Пойманная ошибка имеет тип `unknown` (выбросить можно что угодно), а `instanceof` точно сообщает TypeScript, с каким классом вы имеете дело:

<CodeExample output={`Гараж заполнен (мест: 2). Попробуйте другой!
Машина припаркована`}>

```ts
class GarageFullError extends Error {
  constructor(readonly capacity: number) {
    super(`Гараж заполнен (мест: ${capacity})`);
    this.name = "GarageFullError";
  }
}

function enter(parked: number, capacity: number): void {
  if (parked >= capacity) {
    throw new GarageFullError(capacity);
  }
  console.log("Машина припаркована");
}

function tryToPark(parked: number): void {
  try {
    enter(parked, 2);
  } catch (err) {
    // err: unknown
    if (err instanceof GarageFullError) {
      // err: GarageFullError, поэтому .capacity доступен
      console.log(`${err.message}. Попробуйте другой!`);
    } else {
      throw err; // не наша ошибка: пусть летит дальше
    }
  }
}

tryToPark(2);
tryToPark(1);
```

</CodeExample>

`instanceof` работает только с **классами**, потому что только классы существуют во время выполнения. Он не может проверить интерфейс или псевдоним типа и выдаёт `false` для обычных объектов, у которых просто подходящая форма (как `corner` выше), включая всё, что приходит из `JSON.parse`. Для данных различать варианты обычно лучше по полю-метке вроде `kind`, как вы видели в уроке [Размеченные объединения](/learn/typescript/discriminated-unions).

## Композиция вместо наследования

Допустим, паркомату нужно знать время и прейскурант. Можно попробовать наследование (`class Meter extends Clock`?), но паркомат **не является** часами. У него **есть** часы. В этом и состоит идея **композиции** (composition): вместо того чтобы наследовать поведение, объект **получает** нужные ему части, обычно через конструктор.

<CodeExample output={`£0
£4
£2`}>

```ts
interface Clock {
  now(): number; // миллисекунды
}

interface PricingRule {
  price(minutes: number): number;
}

class Meter {
  private startedAt = 0;

  constructor(
    private readonly clock: Clock,
    private readonly pricing: PricingRule,
  ) {}

  start(): void {
    this.startedAt = this.clock.now();
  }

  stop(): string {
    const ms = this.clock.now() - this.startedAt;
    const minutes = Math.ceil(ms / 60_000);
    return `£${this.pricing.price(minutes)}`;
  }
}

// Часы, которыми управляем мы: идеально для примеров и тестов
class FakeClock implements Clock {
  private time = 0;
  now(): number {
    return this.time;
  }
  advance(minutes: number): void {
    this.time += minutes * 60_000;
  }
}

// Обычные объекты могут быть PricingRule: структурная типизация!
const perHour: PricingRule = {
  price: (minutes) => Math.ceil(minutes / 60) * 2,
};
const firstHourFree: PricingRule = {
  price: (minutes) =>
    minutes <= 60 ? 0 : Math.ceil((minutes - 60) / 60) * 2,
};

const clock = new FakeClock();
const town = new Meter(clock, perHour);
const mall = new Meter(clock, firstHourFree);

town.start();
mall.start();
clock.advance(50);
console.log(mall.stop()); // 50 минут у торгового центра
clock.advance(40);
console.log(town.stop()); // 90 минут в городе
console.log(mall.stop()); // 90 минут у торгового центра
```

</CodeExample>

Посмотрите, что нам дала композиция:

- **Свободные сочетания.** Двое часов и два правила оплаты дают четыре вида паркоматов — и ни одного подкласса. С наследованием понадобились бы `TownMeter`, `MallMeter`, `TestTownMeter`...
- **Простое тестирование.** Паркомат никогда сам не вызывает `Date.now()`. В реальной работе вы передадите часы, чей `now()` возвращает `Date.now()`, а в тестах `FakeClock` заставит время делать ровно то, что вам нужно. Такая передача классу всего, что ему нужно, называется **внедрением зависимостей** (dependency injection).
- **Маленькие обещания.** `Meter` зависит только от двух крошечных интерфейсов, поэтому подойдёт всё, что им соответствует.

<Callout type="tip" title="«Является» или «имеет»?">

Прежде чем писать `extends`, проговорите вслух: «`Lamp` **является** `Device`» звучит правильно, значит, наследование может подойти. «`Meter` является `Clock`» звучит неправильно: у паркомата **есть** часы, так что передайте их ему. Если сомневаетесь, выбирайте композицию. Добавить наследование потом гораздо проще, чем распутывать его.

</Callout>

## Когда класс — это перебор

Классы прекрасны, но не всему нужен класс. Класс без состояния — это просто функция в маскарадном костюме:

```ts
// Класс, которому нечего запоминать...
class FeeCalculator {
  calculate(minutes: number, rate: number): number {
    return Math.ceil(minutes / 60) * rate;
  }
}
const fee1 = new FeeCalculator().calculate(90, 2);

// ...проще в виде обычной функции
function calculateFee(minutes: number, rate: number): number {
  return Math.ceil(minutes / 60) * rate;
}
const fee2 = calculateFee(90, 2);
```

То же касается объектов, которые только хранят данные: их описывает `interface` или `type`, и подходит любой объектный литерал. Данные из API или `JSON.parse` всё равно **никогда** не бывают экземплярами вашего класса.

Класс оправдывает себя, когда:

- у него есть **состояние, которое меняется** со временем, и **правила**, которые должны его защищать (поля `private`, проверки в методах), как у банковского счёта или парковки;
- вы создаёте **много объектов** с одинаковым поведением;
- вам нужен **`instanceof`**, как с собственными ошибками;
- инструменты, которыми вы пользуетесь, ожидают классы.

В остальных случаях берите **типы и функции**. В очень многих отличных проектах на TypeScript классов совсем немного. 🐼

На парковке есть места разных размеров (`motorbike` — мотоцикл, `car` — легковушка, `van` — фургон), транспорт приезжает и уезжает, и за каждую стоянку берут плату в зависимости от её длительности. Размеры, цены, `Vehicle`, `FakeClock` и типы результатов уже даны. Постройте остальное:

1. **`fee(size, minutes)`**: стоянка до `FREE_MINUTES` (15) минут включительно бесплатна. Иначе каждый **начатый** час стоит `HOURLY_RATE[size]`, так что 16 или 60 минут для легковушки стоят £2, а 61 минута — £4. (Состояния нет, поэтому обычная функция — то, что нужно.)
2. **`Spot`**: сделайте `id` и `size` полями `readonly` и допишите `fits(vehicle)`: транспорт помещается на место своего размера или больше. Используйте `SIZE_RANK`.
3. **`Garage`**:
   - Сделайте `spots` **приватным**. Храните заработок парковки в приватном поле и откройте его через геттер `get earned()`.
   - `freeSpots`: сколько мест свободно.
   - `park(vehicle)`: если машина с таким номером уже стоит на парковке, верните `{ ok: false, reason: "already-parked" }`. Иначе займите **первое** свободное подходящее место через `occupy` со временем из часов и верните `{ ok: true, spotId }`. Мест нет? `{ ok: false, reason: "full" }`.
   - `leave(plate)`: найдите место с этим номером (или верните `{ ok: false, reason: "not-found" }`). Посчитайте минуты через `Math.ceil((now - since) / 60_000)` и плату по размеру **транспорта** (легковушка на месте для фургона платит по тарифу легковушки). Освободите место, добавьте плату к выручке и верните `{ ok: true, spotId, minutes, fee }`.

```ts
// ===== Дано: размеры, цены, транспорт, время =====
type Size = "motorbike" | "car" | "van";

// Для сравнения размеров: чем больше число, тем больше размер
const SIZE_RANK: Record<Size, number> = {
  motorbike: 1,
  car: 2,
  van: 3,
};
// £ за каждый начатый час, по размеру ТРАНСПОРТА
const HOURLY_RATE: Record<Size, number> = {
  motorbike: 1,
  car: 2,
  van: 3,
};
const FREE_MINUTES = 15;

class Vehicle {
  constructor(readonly plate: string, readonly size: Size) {}
}

interface Clock {
  now(): number; // миллисекунды
}

class FakeClock implements Clock {
  private time = 0;
  now(): number {
    return this.time;
  }
  advance(minutes: number): void {
    this.time += minutes * 60_000;
  }
}

type ParkResult =
  | { ok: true; spotId: string }
  | { ok: false; reason: "full" | "already-parked" };

type LeaveResult =
  | { ok: true; spotId: string; minutes: number; fee: number }
  | { ok: false; reason: "not-found" };

type Parked = { readonly vehicle: Vehicle; readonly since: number };

// ===== Ваш код =====

function fee(size: Size, minutes: number): number {
  if (minutes <= FREE_MINUTES) {
    return 0;
  }
  return Math.ceil(minutes / 60) * HOURLY_RATE[size];
}

class Spot {
  private current: Parked | null = null;

  constructor(readonly id: string, readonly size: Size) {}

  get parked(): Parked | null {
    return this.current;
  }

  get isFree(): boolean {
    return this.current === null;
  }

  fits(vehicle: Vehicle): boolean {
    return SIZE_RANK[vehicle.size] <= SIZE_RANK[this.size];
  }

  occupy(vehicle: Vehicle, since: number): void {
    this.current = { vehicle, since };
  }

  release(): void {
    this.current = null;
  }
}

class Garage {
  private readonly spots: Spot[];
  private takings = 0;

  constructor(spots: Spot[], private readonly clock: Clock) {
    this.spots = [...spots]; // собственная копия списка
  }

  get earned(): number {
    return this.takings;
  }

  get freeSpots(): number {
    return this.spots.filter((s) => s.isFree).length;
  }

  park(vehicle: Vehicle): ParkResult {
    const plate = vehicle.plate;
    if (this.spots.some((s) => s.parked?.vehicle.plate === plate)) {
      return { ok: false, reason: "already-parked" };
    }
    const spot = this.spots.find((s) => s.isFree && s.fits(vehicle));
    if (spot === undefined) {
      return { ok: false, reason: "full" };
    }
    spot.occupy(vehicle, this.clock.now());
    return { ok: true, spotId: spot.id };
  }

  leave(plate: string): LeaveResult {
    for (const spot of this.spots) {
      const parked = spot.parked;
      if (parked !== null && parked.vehicle.plate === plate) {
        const ms = this.clock.now() - parked.since;
        const minutes = Math.ceil(ms / 60_000);
        const cost = fee(parked.vehicle.size, minutes);
        spot.release();
        this.takings += cost;
        return { ok: true, spotId: spot.id, minutes, fee: cost };
      }
    }
    return { ok: false, reason: "not-found" };
  }
}

// Тесты типов (никогда не вызываются). Не меняйте их.
function typeTests(garage: Garage, spot: Spot): void {
  const free: number = garage.freeSpots;
  const earned: number = garage.earned;
  // Структурная типизация: подходит любой объект { plate, size }
  garage.park({ plate: "PLAIN 1", size: "car" });
  // @ts-expect-error: места — внутреннее дело парковки
  garage.spots;
  // @ts-expect-error: выручку меняет только сама парковка
  garage.earned = 1_000_000;
  // @ts-expect-error: id места никогда не меняется
  spot.id = "Z9";
  // @ts-expect-error: размер места никогда не меняется
  spot.size = "van";
}

const clock = new FakeClock();
const garage = new Garage(
  [
    new Spot("M1", "motorbike"),
    new Spot("C1", "car"),
    new Spot("C2", "car"),
    new Spot("V1", "van"),
  ],
  clock,
);

console.log(garage.park(new Vehicle("MOTO 1", "motorbike")));
console.log(garage.park(new Vehicle("CAR 1", "car")));
console.log(garage.park(new Vehicle("CAR 1", "car")));
console.log(garage.park(new Vehicle("VAN 1", "van")));
console.log(`Свободных мест: ${garage.freeSpots}`);

clock.advance(130);
const result = garage.leave("CAR 1");
if (result.ok) {
  console.log(
    `CAR 1 заплатил £${result.fee} за ${result.minutes} мин`,
  );
} else {
  console.log(`Не удалось выехать: ${result.reason}`);
}
console.log(garage.leave("NOBODY"));
console.log(`Заработано: £${garage.earned}`);
```

## Итоги

- TypeScript сравнивает классы по **форме** (структурная типизация): объектные литералы и несвязанные классы с теми же членами подходят к типу класса.
- Члены `private` и `protected` делают тип класса неподделываемым: подходят только объекты, созданные этим классом.
- Класс — это и **тип** (его объекты), и **значение** (сам класс). `typeof Lamp` — собственный тип класса; `new (room: string) => Device` описывает любой подходящий класс.
- `instanceof` сужает тип до класса, что идеально для собственных ошибок в `catch`. С интерфейсами и обычными объектами он не работает.
- Предпочитайте **композицию** («имеет») наследованию («является»): передайте часы или правило оплаты — и тестировать станет просто.
- Используйте класс для меняющегося состояния с правилами, которые нужно защищать; для простых данных и логики без состояния проще типы и функции.

🎉 Вы прошли модуль о классах! Дальше — **дженерики** (generics): они позволяют одному классу или функции безопасно работать со многими типами.
