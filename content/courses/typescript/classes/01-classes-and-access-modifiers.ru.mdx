До сих пор вы описывали объекты интерфейсами и создавали их через `{ ... }`. Для простых данных это идеально. Но у некоторых объектов есть ещё **поведение** и **данные, которые нужно защищать**: банковский счёт не должен позволять кому угодно выставить баланс в миллион. **Класс** (class) объединяет данные и методы, которые с ними работают, а TypeScript добавляет две вещи, которых нет у классов JavaScript: **типы** для каждого поля и метода и **модификаторы доступа** (access modifiers), которые говорят, кому что можно трогать. 🔒

## Класс с типизированными полями

В классе TypeScript каждое поле **объявляется** вверху вместе с типом — так же, как свойства интерфейса. Параметры конструктора (constructor) типизируются, как у любой функции:

<CodeExample output={`Mei, возраст: 3
Panda { name: 'Mei', age: 3 }
Bao старше`}>

```ts
class Panda {
  name: string;
  age: number;

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
  }

  describe(): string {
    return `${this.name}, возраст: ${this.age}`;
  }
}

function older(a: Panda, b: Panda): Panda {
  return a.age >= b.age ? a : b;
}

const mei = new Panda("Mei", 3);
const bao = new Panda("Bao", 5);
console.log(mei.describe());
console.log(mei);
console.log(`${older(mei, bao).name} старше`);
```

</CodeExample>

Обратите внимание на две вещи:

- **Класс — это ещё и тип.** `older(a: Panda, b: Panda)` принимает любой объект `Panda`. С каждым написанным классом вы бесплатно получаете тип.
- **Методы типизируются как функции.** `describe(): string` обязан вернуть строку, а вызов `mei.describe(42)` был бы ошибкой.

В JavaScript в конструкторе можно добавить любое свойство. TypeScript хочет узнать о нём заранее:

```ts
class Ticket {
  constructor(plate: string) {
    this.plate = plate;
    // ❌ Error: Property 'plate' does not exist on type 'Ticket'.
  }
}
```

Решение — объявить поле: `plate: string;` над конструктором. Эта одна строка заодно документирует форму каждого `Ticket` для того, кто будет читать класс после вас.

## Каждое поле должно получить значение

При включённом `strict` TypeScript проверяет, что каждое объявленное поле действительно получает значение, чтобы вы не забыли о нём и потом не прочитали `undefined`:

```ts
class Ticket {
  plate: string;
  spot: number;
  // ❌ Error: Property 'spot' has no initializer and is not definitely assigned in the constructor.

  constructor(plate: string) {
    this.plate = plate;
  }
}
```

Исправить это можно четырьмя способами, и каждый говорит что-то своё:

<CodeExample output={`Game { turn: 'X', moves: 0, winner: undefined, board: [ '', '', '' ] }
undefined`}>

```ts
class Game {
  turn: "X" | "O";   // 1. присваивается в конструкторе
  moves = 0;         // 2. инициализатор (выведен тип number)
  winner?: "X" | "O"; // 3. необязательное: может быть undefined
  board!: string[];  // 4. «поверь мне»: его задаёт reset()

  constructor() {
    this.turn = "X";
    this.reset();
  }

  reset(): void {
    this.board = ["", "", ""];
  }
}

const game = new Game();
console.log(game);
console.log(game.winner);
```

</CodeExample>

Каждое объявленное поле существует в объекте с самого начала, в том порядке, в котором вы их объявили. Поэтому `winner` показывается как `undefined`, пока партия не выиграна.

`!` после `board` — это **утверждение явного присваивания** (definite assignment assertion). TypeScript не заглядывает внутрь `reset()`, поэтому не видит, что конструктор задаёт `board`. `!` говорит ему: «обещаю, значение будет». Пользуйтесь этим редко: если вы ошиблись, TypeScript промолчит, а ваш код прочитает `undefined`. Варианты 1–3 всегда безопаснее.

## Свойства-параметры: сокращённая запись

Объявить поле, принять параметр и скопировать одно в другое — настолько частая задача, что в TypeScript для неё есть сокращение. Поставьте модификатор, например `public` или `readonly`, перед параметром конструктора — и он автоматически станет полем:

<CodeExample output={`Panda { name: 'Mei', age: 3 }
Mei`}>

```ts
class Panda {
  constructor(public name: string, public age: number) {}
}

// Ровно то же самое, что:
//   name: string;
//   age: number;
//   constructor(name: string, age: number) {
//     this.name = name;
//     this.age = age;
//   }

const mei = new Panda("Mei", 3);
console.log(mei);
console.log(mei.name);
```

</CodeExample>

Это называется **свойствами-параметрами** (parameter properties). Тело конструктора пустое (`{}`), потому что копирование TypeScript пишет за вас. Без модификатора `name` был бы просто обычным параметром, а не полем.

<Callout type="note" title="Синтаксис только для TypeScript">

Свойства-параметры — одна из немногих возможностей TypeScript, которые **генерируют** код на JavaScript, а не просто удаляются. Большинство проектов охотно ими пользуется, но некоторые инструменты, которые только вырезают типы (например, встроенная поддержка TypeScript в Node), их не принимают. Почему — узнаете на Уровне 3. А пока: пользоваться ими можно, и в реальном коде они встречаются постоянно.

</Callout>

## `public`, `private` и `protected`

**Модификатор доступа** говорит, кто может использовать член класса (поле или метод):

| Модификатор | Кто может использовать |
| --- | --- |
| `public` (по умолчанию) | Кто угодно |
| `private` | Только код внутри этого класса |
| `protected` | Этот класс и его подклассы (следующий урок) |

Сделав поле `private`, класс может защитить свои **правила**. Здесь баланс можно изменить только через `deposit` и `withdraw`, и оба метода проверяют сумму:

<CodeExample output={`Баланс: 30
Не хватает денег на 100
Баланс: 30`}>

```ts
class BankAccount {
  private balance = 0;

  constructor(public owner: string) {}

  deposit(amount: number): void {
    if (amount <= 0) {
      throw new RangeError("Сумма пополнения должна быть больше 0");
    }
    this.balance += amount;
  }

  withdraw(amount: number): boolean {
    if (amount > this.balance) {
      console.log(`Не хватает денег на ${amount}`);
      return false;
    }
    this.balance -= amount;
    return true;
  }

  report(): string {
    return `Баланс: ${this.balance}`;
  }
}

const account = new BankAccount("Mei");
account.deposit(50);
account.withdraw(20);
console.log(account.report());
account.withdraw(100);
console.log(account.report());
```

</CodeExample>

Код снаружи класса не может обойти правила:

```ts
account.balance = 1_000_000;
// ❌ Error: Property 'balance' is private and only accessible within class 'BankAccount'.
```

Писать `public` необязательно, ведь это значение по умолчанию. Многие команды не пишут его у полей и методов, но пишут в свойствах-параметрах, где модификатор всё равно нужен.

## Поля `readonly`

Поле `readonly` можно задать там, где оно объявлено, или в конструкторе — и **больше никогда**. Это идеально для id и всего, что идентифицирует объект. Модификаторы можно сочетать: `private readonly` — это значение, которое видит только класс и которое даже сам класс не может изменить после создания объекта:

<CodeExample output={`Заказ #17 для Sam, позиций: 2
[ 'tea', 'cake' ]`}>

```ts
class Order {
  readonly items: string[] = [];

  constructor(
    readonly id: number,
    private readonly customer: string,
  ) {}

  add(item: string): void {
    this.items.push(item); // можно: сам массив может меняться
  }

  summary(): string {
    const count = this.items.length;
    return `Заказ #${this.id} для ${this.customer}, позиций: ${count}`;
  }
}

const order = new Order(17, "Sam");
order.add("tea");
order.add("cake");
console.log(order.summary());
console.log(order.items);
```

</CodeExample>

```ts
order.id = 18;
// ❌ Error: Cannot assign to 'id' because it is a read-only property.
order.items = [];
// ❌ Error: Cannot assign to 'items' because it is a read-only property.
```

Заметьте, что `order.items.push(...)` по-прежнему работает. `readonly` не даёт направить **поле** на новый массив, но сам массив, который в нём лежит, меняться может. Если и содержимое меняться не должно, используйте тип `readonly string[]`, который вы встречали в уроке о массивах.

## `private` в TypeScript и `#private` в JavaScript

В JavaScript есть собственные приватные поля, которые пишутся через `#`. Выглядят они похоже, но работают в совершенно разное время:

- **`private`** в TypeScript — это проверка **во время компиляции**. Она стирается вместе с остальными типами, поэтому во время выполнения поле — обычное свойство.
- **`#private`** в JavaScript обеспечивается **во время выполнения** самим движком JavaScript. Снаружи класса такое поле действительно не видно.

Разницу видно, если вывести объекты:

<CodeExample output={`TsWallet { balance: 10 }
JsWallet {}
{"balance":10}
{}
10`}>

```ts
class TsWallet {
  private balance = 10;
}

class JsWallet {
  #balance = 10;

  get balance(): number {
    return this.#balance;
  }
}

const ts = new TsWallet();
const js = new JsWallet();
console.log(ts);
console.log(js);
console.log(JSON.stringify(ts));
console.log(JSON.stringify(js));
console.log(ts["balance"]); // разрешено: запасной выход
```

</CodeExample>

Баланс `TsWallet` виден при выводе и в JSON, а TypeScript даже разрешает `ts["balance"]` с квадратными скобками как намеренный запасной выход. Поле `#balance` снаружи невидимо, и TypeScript сообщает о любой попытке им воспользоваться:

```ts
js.#balance;
// ❌ Error: Property '#balance' is not accessible outside class 'JsWallet' because it has a private identifier.
```

<Callout type="tip" title="Что же выбрать?">

Подходят оба, так что следуйте стилю своего проекта. `private` распространён в коде на TypeScript и хорошо читается, особенно в свойствах-параметрах. Выбирайте `#private`, когда приватность должна соблюдаться **и во время выполнения**: например, в библиотеке, которой пользуются из обычного JavaScript, или когда объекты попадают в логи или превращаются в JSON и не должны раскрыть секрет.

</Callout>

## Методы и `this`

Внутри метода `this` — это объект, у которого метод вызвали. Это ломается, если передать метод куда-то **сам по себе**, как колбэк. Метод отрывается от своего объекта, и `this` становится `undefined`:

```ts
class Counter {
  count = 0;

  increment(): void {
    this.count++;
  }
}

const counter = new Counter();
const inc = counter.increment;
inc();
// 💥 TypeError: Cannot read properties of undefined (reading 'count')
```

По умолчанию TypeScript этого не ловит. Но его можно попросить — с помощью фиктивного первого параметра с именем `this`, который говорит, какой объект нужен методу. Его проверяет TypeScript, а из JavaScript он удаляется:

```ts
class Counter {
  count = 0;

  increment(this: Counter): void {
    this.count++;
  }
}

const counter = new Counter();
const inc = counter.increment;
inc();
// ❌ Error: The 'this' context of type 'void' is not assignable to method's 'this' of type 'Counter'.
```

Если метод **задуман** для передачи в качестве колбэка, запишите его как **поле со стрелочной функцией**. У стрелочных функций нет собственного `this`: они сохраняют `this` объекта, в котором были созданы:

<CodeExample output={`6
2`}>

```ts
class Counter {
  count = 0;
  clicks = 0;

  add = (amount: number): void => {
    this.count += amount;
    this.clicks++;
  };
}

const counter = new Counter();
[1, 2, 3].forEach(counter.add); // никакого падения!
console.log(counter.count);

const other = new Counter();
other.add(1);
other.add(1);
console.log(other.clicks);
```

</CodeExample>

Цена такого решения: обычный метод общий для всех экземпляров, а поле со стрелочной функцией — это новая функция в **каждом** объекте. Для нескольких объектов это не страшно, так что используйте его для колбэков, а для всего остального оставьте обычные методы.

## Геттеры и сеттеры

**Геттер** (getter, `get`) снаружи выглядит как свойство, но при чтении запускает метод. **Сеттер** (setter, `set`) срабатывает при присваивании, поэтому в нём удобно проверять значения. Геттер без сеттера автоматически становится **доступным только для чтения**:

<CodeExample output={`Цель: 21°C (69.8°F)
Термостат: 30°C — вне допустимого диапазона
Цель: 21°C (69.8°F)`}>

```ts
class Thermostat {
  private celsius = 20;

  get target(): number {
    return this.celsius;
  }

  set target(value: number) {
    if (value < 5 || value > 28) {
      console.log(
        `Термостат: ${value}°C — вне допустимого диапазона`,
      );
      return;
    }
    this.celsius = value;
  }

  get fahrenheit(): number {
    return (this.celsius * 9) / 5 + 32;
  }

  show(): string {
    return `Цель: ${this.target}°C (${this.fahrenheit}°F)`;
  }
}

const home = new Thermostat();
home.target = 21; // запускает сеттер
console.log(home.show());
home.target = 30; // отклонено
console.log(home.show());
```

</CodeExample>

```ts
home.fahrenheit = 100;
// ❌ Error: Cannot assign to 'fahrenheit' because it is a read-only property.
```

Поле `private` плюс **публичный геттер** — очень распространённый приём: прочитать значение может кто угодно, а изменить — только сам класс.

## Статические члены

**Статический** (static) член принадлежит **самому классу**, а не каждому объекту. Используйте его для того, что общее у всех экземпляров: счётчика для id, константы или вспомогательного метода, который создаёт объекты:

<CodeExample output={`#1 Mei
#2 Sam
#3 Гость
Билет стоит £3`}>

```ts
class Ticket {
  static readonly PRICE = 3;
  private static nextNumber = 1;

  readonly number: number;

  constructor(readonly holder: string) {
    this.number = Ticket.nextNumber++;
  }

  static forGuest(): Ticket {
    return new Ticket("Гость");
  }
}

const tickets = [
  new Ticket("Mei"),
  new Ticket("Sam"),
  Ticket.forGuest(),
];
for (const t of tickets) {
  console.log(`#${t.number} ${t.holder}`);
}
console.log(`Билет стоит £${Ticket.PRICE}`);
```

</CodeExample>

К статическим членам обращаются через имя класса, `Ticket.PRICE`, и никогда — через экземпляр. Модификаторы работают и с ними: `nextNumber` — `private static`, поэтому раздавать номера может только `Ticket`.

```ts
const t = new Ticket("Mei");
t.PRICE;
// ❌ Error: Property 'PRICE' does not exist on type 'Ticket'. Did you mean to access the static member 'Ticket.PRICE' instead?
```

Кофейня дарит бесплатный кофе за каждые 5 штампов. Класс в заготовке работает как обычный JavaScript: типов нет, и кто угодно может менять что угодно. Сделайте его безопасным:

1. Дайте тип каждому полю и параметру (сейчас параметр `owner` — это ошибка **неявного any**, implicit any).
2. `id` и `owner` не должны меняться после создания карты.
3. **Читать** `stamps` может кто угодно, но менять — только класс. Храните штампы в поле `private` и добавьте геттер `get stamps()`.
4. `nextId` должен быть доступен только внутри класса, а `STAMPS_NEEDED` должен быть константой.
5. Допишите `addStamp()` и `redeem()`, как описано в комментариях.

Строки с `@ts-expect-error` внизу — это **тесты типов**: каждая проходит, только если строка под ней **является** ошибкой. Пока строка ещё компилируется, TypeScript сообщает "Unused '@ts-expect-error' directive."

<Hint>

У геттера и поля не может быть одного имени, поэтому переименуйте поле: `private count = 0;` и `get stamps(): number { return this.count; }`. С владельцем справится свойство-параметр `readonly`: `constructor(readonly owner: string)`. Объявите `readonly id: number;` и оставьте строку, которая задаёт его в конструкторе. Затем используйте `private static nextId = 1;` и `static readonly STAMPS_NEEDED = 5;`. В `addStamp` добавляйте штамп, только если `this.count < LoyaltyCard.STAMPS_NEEDED`.

</Hint>

<Solution>

```ts
class LoyaltyCard {
  static readonly STAMPS_NEEDED = 5;
  private static nextId = 1;

  readonly id: number;
  private count = 0;

  constructor(readonly owner: string) {
    this.id = LoyaltyCard.nextId++;
  }

  get stamps(): number {
    return this.count;
  }

  addStamp(): void {
    if (this.count < LoyaltyCard.STAMPS_NEEDED) {
      this.count++;
    }
  }

  redeem(): boolean {
    if (this.count < LoyaltyCard.STAMPS_NEEDED) {
      return false;
    }
    this.count = 0;
    return true;
  }
}

// Тесты типов: каждая строка под @ts-expect-error ОБЯЗАНА
// быть ошибкой. Не меняйте эту функцию: она пройдёт, когда
// ваш класс будет защищать свои данные. (Она не вызывается.)
function typeTests(card: LoyaltyCard): void {
  const stamps: number = card.stamps; // читать можно
  // @ts-expect-error: владелец никогда не меняется
  card.owner = "Кто-то другой";
  // @ts-expect-error: id никогда не меняется
  card.id = 99;
  // @ts-expect-error: штампы меняет только класс
  card.stamps = 100;
  // @ts-expect-error: id раздаёт только класс
  LoyaltyCard.nextId = 1;
  // @ts-expect-error: правило — это константа
  LoyaltyCard.STAMPS_NEEDED = 1;
}

const card = new LoyaltyCard("Mei");
for (let i = 0; i < 6; i++) {
  card.addStamp();
}
console.log(card.stamps); // 5
console.log(card.redeem()); // true
console.log(card.stamps); // 0
```

## Итоги

- Объявляйте каждое поле с его типом; имя класса — это ещё и тип его объектов.
- При `strict` каждому полю нужно значение: инициализатор, присваивание в конструкторе, `?` для необязательного или (редко) `!`.
- **Свойства-параметры** вроде `constructor(readonly id: string)` объявляют и задают поле за один раз.
- `public` — по умолчанию, `private` — только для класса, `protected` добавляет подклассы; поля `readonly` нельзя переприсвоить после создания объекта.
- `private` в TypeScript проверяется при компиляции и стирается; `#private` в JavaScript соблюдается во время выполнения.
- Передавайте методы как колбэки осторожно: параметр `this` ловит ошибки, а поля со стрелочными функциями сохраняют `this`.
- Геттеры и сеттеры выглядят как свойства, но выполняют код; геттер без сеттера доступен только для чтения. **Статические** члены принадлежат самому классу.
