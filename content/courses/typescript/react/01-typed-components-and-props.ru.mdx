Большая часть TypeScript, который вы будете писать на работе, живёт в приложении на **React**. Хорошая новость: React-компонент — это просто **функция, которая принимает один объект и возвращает разметку**, а типизировать функции и объекты вы уже умеете. В этом модуле вы типизируете все части React-приложения и в конце соберёте типизированную **канбан-доску** (доску задач с колонками «Сделать», «В работе» и «Готово»). ⚛️

В этом уроке каждая идея React кратко объясняется по ходу дела. Если сначала хочется спокойнее познакомиться с самим React, в курсе JavaScript есть такое введение: [Компоненты и JSX](/learn/javascript/components-and-jsx).

## Компонент на TypeScript

Файлы React с разметкой имеют расширение **`.tsx`** вместо `.ts`. Разметка — это **JSX**: похожий на HTML синтаксис внутри JavaScript, который инструмент сборки превращает в вызовы функций. **Компонент** (component) — это функция, имя которой начинается с заглавной буквы и которая возвращает JSX. Нажмите **«Запустить»**:

<TryIt
  language="tsx"
  code={`import { createRoot } from "react-dom/client";

function Greeting({ name }: { name: string }) {
  return <h1>Привет, {name}! 🐼</h1>;
}

const root = createRoot(document.getElementById("root")!);
root.render(
  <>
    <Greeting name="Mei" />
    <Greeting name="Bao" />
  </>
);`}
/>

Что здесь происходит:

- `Greeting` получает свои **пропсы** (props, сокращение от properties — «свойства») одним объектом. Мы сразу деструктурируем `name` и типизируем объект, как любой другой параметр: `{ name: string }`.
- Компонент используют как HTML-тег, а пропсы передают как атрибуты: `<Greeting name="Mei" />`. Строки пишутся в кавычках, всё остальное — в фигурных скобках, например `count={3}`.
- `<>...</>` — это **фрагмент** (fragment): он группирует два элемента, не добавляя лишний `<div>` (компонент должен возвращать один корневой элемент).
- `createRoot(...)` передаёт React элемент страницы `<div id="root">`, а `render` рисует внутри него приложение.

Обратите внимание на **`!`** после `getElementById("root")`. По типам DOM этот метод возвращает `HTMLElement | null`, потому что элемента с таким id может и не быть. `createRoot` нужен настоящий элемент, поэтому без `!` вы получите:

```tsx
createRoot(document.getElementById("root"));
// ❌ Error: Argument of type 'HTMLElement | null' is not assignable to parameter of type 'Container'.
```

`!` — это **утверждение non-null** (non-null assertion): «поверь мне, он там есть». Здесь это допустимо: в HTML страницы этот элемент есть всегда, и это единственная строка, где он нужен (более безопасные проверки для других мест — в уроке [Типизация DOM](/learn/typescript/typing-the-dom)). Внутри компонентов `null` вы будете обрабатывать по-честному.

## Типизируем пропсы

Тип пропсов прямо в параметре быстро становится длинным. Лучше дать ему имя. По соглашению это имя компонента плюс **`Props`**:

<TryIt
  language="tsx"
  code={`import { createRoot } from "react-dom/client";

type TaskCardProps = {
  title: string;
  assignee: string;
  points: number;
};

function TaskCard({ title, assignee, points }: TaskCardProps) {
  return (
    <article className="card">
      <h3>{title}</h3>
      <p>
        {assignee} · {points} {points === 1 ? "балл" : "балла"}
      </p>
    </article>
  );
}

createRoot(document.getElementById("root")!).render(
  <>
    <TaskCard title="Спроектировать доску" assignee="Mei" points={3} />
    <TaskCard title="Написать редьюсер" assignee="Sam" points={1} />
  </>
);`}
/>

Теперь TypeScript проверяет **каждое место**, где используется компонент, а именно там прячется большинство ошибок в React:

```tsx
<TaskCard title="Спроектировать доску" assignee="Mei" />
// ❌ Error: Property 'points' is missing in type '{ title: string; assignee: string; }' but required in type 'TaskCardProps'.

<TaskCard title="Дизайн" assignee="Mei" points="3" />
// ❌ Error: Type 'string' is not assignable to type 'number'.

<Greeting nme="Mei" />
// ❌ Error: Type '{ nme: string; }' is not assignable to type 'IntrinsicAttributes & { name: string; }'.
// Property 'nme' does not exist on type 'IntrinsicAttributes & { name: string; }'. Did you mean 'name'?
```

`IntrinsicAttributes` в последнем сообщении — это набор пропсов React, которые принимает **любой** компонент, например `key`. При чтении ошибки его можно пропустить: полезная часть — в конце.

А если вообще забыть типизировать пропсы, строгий режим этого не пропустит:

```tsx
function Card({ title }) {
  // ❌ Error: Binding element 'title' implicitly has an 'any' type.
  return <h2>{title}</h2>;
}
```

### `type` или `interface`?

Для пропсов подходят оба, ровно как в уроке [Объектные типы и интерфейсы](/learn/typescript/object-types-and-interfaces):

```tsx
interface TaskCardProps {
  title: string;
  assignee: string;
  points: number;
}
```

Во многих React-проектах для пропсов используют **`type`**, потому что пропсы часто превращаются в объединения и комбинации (`A & B`, `A | B`), которые умеет выражать только `type`, — ниже вы это увидите. Выберите один стиль на проект и придерживайтесь его; в этом модуле мы используем `type`.

## Необязательные пропсы и значения по умолчанию

Пометьте проп как **необязательный** с помощью `?`. Если у него есть разумное значение по умолчанию, задайте его при деструктуризации, как параметр по умолчанию. Тогда внутри компонента TypeScript знает, что значение есть всегда:

<TryIt
  language="tsx"
  code={`import { createRoot } from "react-dom/client";

type BadgeProps = {
  label: string;
  count?: number; // number | undefined
  tone?: "neutral" | "warning";
};

function Badge({ label, count, tone = "neutral" }: BadgeProps) {
  // здесь tone — это "neutral" | "warning" (никогда не undefined)
  const colour = tone === "warning" ? "#b45309" : "#6d28d9";
  return (
    <span style={{ color: colour, marginRight: 12 }}>
      {label}
      {count !== undefined && <strong> ({count})</strong>}
    </span>
  );
}

createRoot(document.getElementById("root")!).render(
  <p>
    <Badge label="Сделать" count={4} />
    <Badge label="Заблокировано" count={0} tone="warning" />
    <Badge label="Архив" />
  </p>
);`}
/>

У `count` нет значения по умолчанию, поэтому он остаётся `number | undefined`, и перед использованием его нужно проверить. Заметьте, что проверка — `count !== undefined`, а не просто `count &&`: с `&&` счётчик `0` считался бы «отсутствующим» (и React вывел бы лишний `0`). Двойные фигурные скобки в `style={{ ... }}` — это выражение (внешняя пара), внутри которого объект с CSS-свойствами (внутренняя пара).

## Children: `ReactNode`

Всё, что вы помещаете **между** тегами компонента, приходит в проп **`children`**. Его используют компоненты-обёртки: карточки, панели, макеты. Тип этого пропа — **`ReactNode`**: всё, что React умеет отрисовать (элементы, строки, числа, массивы из них, а также `null`, `undefined` и логические значения, которые ничего не рисуют):

<TryIt
  language="tsx"
  code={`import type { ReactNode } from "react";
import { createRoot } from "react-dom/client";

type PanelProps = {
  title: string;
  children: ReactNode;
};

function Panel({ title, children }: PanelProps) {
  return (
    <section
      style={{ border: "1px solid #7c3aed", borderRadius: 12,
               padding: "4px 16px", marginBottom: 12 }}
    >
      <h3>{title}</h3>
      {children}
    </section>
  );
}

createRoot(document.getElementById("root")!).render(
  <>
    <Panel title="В работе">
      <p>Написать редьюсер</p>
      <p>Оформить карточки</p>
    </Panel>
    <Panel title="Готово">Завершено задач: {2 + 1} 🎉</Panel>
  </>
);`}
/>

`import type` импортирует только тип, который исчезает при компиляции. Компонент, в пропсах которого нет `children`, отказывается их принимать, и это ловит содержимое, которое тихо никогда бы не появилось на экране:

```tsx
<Greeting name="Mei">Привет всем</Greeting>
// ❌ Error: Type '{ children: string; name: string; }' is not assignable to type 'IntrinsicAttributes & { name: string; }'.
// Property 'children' does not exist on type 'IntrinsicAttributes & { name: string; }'.
```

<Callout type="tip" title="ReactNode, а не JSX.Element">

В старом коде можно встретить `children: JSX.Element` или `ReactElement`. Они допускают только **один элемент**, так что обычный текст, числа, списки и `null` отвергаются. Для children почти всегда нужен именно `ReactNode`. В React есть и помощник `PropsWithChildren<P>`, который добавляет `children?: ReactNode` к типу пропсов `P`.

</Callout>

## Варианты как объединение в пропсах

Кнопки, уведомления и бейджи обычно бывают нескольких видов. Описывайте их **объединением строковых литералов**, а не типом `string` и не набором логических флагов:

```tsx
// ❌ Как выглядит <Button isPrimary isGhost />?
type ButtonProps = { isPrimary?: boolean; isGhost?: boolean };

// ✅ Ровно один вариант, и редактор подсказывает возможные значения
type ButtonProps = { variant: "primary" | "ghost" };
```

С флагами ничто не мешает включить оба сразу. Объединение делает невозможную комбинацию невозможной для записи. А `Record` с ключами из этого объединения гарантирует, что стиль есть для **каждого** варианта:

<TryIt
  language="tsx"
  code={`import type { ReactNode } from "react";
import { createRoot } from "react-dom/client";

type Variant = "primary" | "ghost" | "danger";

const STYLES: Record<Variant, { background: string; color: string }> = {
  primary: { background: "#7c3aed", color: "white" },
  ghost: { background: "transparent", color: "#7c3aed" },
  danger: { background: "#dc2626", color: "white" },
};

type ButtonProps = {
  variant: Variant;
  children: ReactNode;
};

function Button({ variant, children }: ButtonProps) {
  return (
    <button style={{ ...STYLES[variant], marginRight: 8 }}>
      {children}
    </button>
  );
}

createRoot(document.getElementById("root")!).render(
  <>
    <Button variant="primary">Добавить карточку</Button>
    <Button variant="ghost">Отмена</Button>
    <Button variant="danger">Удалить</Button>
  </>
);`}
/>

Добавьте `"success"` в `Variant` — и TypeScript сразу сообщит, что в `STYLES` его не хватает. Опечатка в варианте ловится там, где используется кнопка:

```tsx
<Button variant="dagner">Удалить</Button>
// ❌ Error: Type '"dagner"' is not assignable to type 'Variant'. Did you mean '"danger"'?
```

## Пропсы, которые идут вместе

Иногда пропсы имеют смысл только **в определённых сочетаниях**. Аватар показывает либо картинку (для неё нужны `src` **и** `alt`), либо инициалы, но не то и другое сразу. Необязательные пропсы так сказать не могут: `{ src?: string; alt?: string; initials?: string }` спокойно примет и ни одного, и все три. А **размеченное объединение** (discriminated union) может — точно такое же, как в уроке [Размеченные объединения](/learn/typescript/discriminated-unions):

<TryIt
  language="tsx"
  code={`import { createRoot } from "react-dom/client";

type AvatarProps =
  | { kind: "image"; src: string; alt: string }
  | { kind: "initials"; initials: string };

function Avatar(props: AvatarProps) {
  if (props.kind === "image") {
    // Здесь TypeScript знает, что у props есть src и alt
    return <img src={props.src} alt={props.alt} width={40} />;
  }
  // А здесь это может быть только вариант "initials"
  return (
    <span style={{ background: "#ede9fe", borderRadius: 20,
                   padding: 10 }}>
      {props.initials}
    </span>
  );
}

createRoot(document.getElementById("root")!).render(
  <p>
    <Avatar kind="initials" initials="ML" />{" "}
    <Avatar kind="image" src="/panda.png" alt="Панда Бао" />
  </p>
);`}
/>

(Файла с картинкой в этом превью нет, поэтому браузер показывает её текст `alt`.) Перепутанные пропсы теперь — ошибки типов:

```tsx
<Avatar kind="image" initials="ML" />
// ❌ Error: Type '{ kind: "image"; initials: string; }' is not assignable to type 'IntrinsicAttributes & AvatarProps'.
// Property 'initials' does not exist on type 'IntrinsicAttributes & { kind: "image"; src: string; alt: string; }'.
```

Обратите внимание: `Avatar` принимает `props` целиком и проверяет `props.kind` **до того**, как читать остальные пропсы. Деструктуризация `{ kind, src }` прямо в списке параметров не сработает, потому что `src` есть не у каждого члена объединения.

## Пропсы-колбэки

Данные текут **вниз** через пропсы. Когда дочернему компоненту нужно сообщить родителю, что что-то произошло (клик, выбор), родитель передаёт **функцию** в виде пропа. Типизируйте её как любой колбэк и по соглашению давайте ей имя, начинающееся с `on`:

<TryIt
  language="tsx"
  code={`import { createRoot } from "react-dom/client";

type Task = { id: string; title: string };

type TaskListProps = {
  tasks: Task[];
  onSelect: (id: string) => void;
};

function TaskList({ tasks, onSelect }: TaskListProps) {
  return (
    <ul>
      {tasks.map((task) => (
        <li key={task.id}>
          <button onClick={() => onSelect(task.id)}>
            {task.title}
          </button>
        </li>
      ))}
    </ul>
  );
}

const tasks: Task[] = [
  { id: "t1", title: "Спроектировать доску" },
  { id: "t2", title: "Написать редьюсер" },
];

function handleSelect(id: string) {
  console.log("Выбрано:", id);
}

createRoot(document.getElementById("root")!).render(
  <TaskList tasks={tasks} onSelect={handleSelect} />
);`}
/>

Пощёлкайте по кнопкам и посмотрите на вывод. Несколько деталей:

- `onSelect: (id: string) => void` точно описывает, что дочерний компонент отправляет наверх. Возвращаемый тип **`void`** означает «дочерний компонент игнорирует то, что вы вернёте», так что подойдёт любая функция, принимающая строку.
- `onClick={() => onSelect(task.id)}` оборачивает вызов в стрелочную функцию. Если написать `onClick={onSelect(task.id)}`, функция вызовется **во время рендера**, и TypeScript это поймает: `Type 'void' is not assignable to type 'MouseEventHandler<HTMLButtonElement> | undefined'.`
- Спискам, отрисованным через `map`, нужен **`key`** у каждого элемента: значение, уникальное среди соседей и стабильное, например id. По нему React отличает элементы друг от друга, когда список меняется.
- Соглашение об именах: пропсы называются `onSomething`, а функции, которые вы в них передаёте, — `handleSomething`.

## Расширяем пропсы нативных элементов

Компонент `Button`, который оборачивает `<button>`, должен по-прежнему принимать всё, что принимает обычная кнопка: `type`, `disabled`, `onClick`, `aria-label`... Перечислять всё вручную — безнадёжное дело. **`ComponentProps<"button">`** даёт полный типизированный набор пропсов элемента `<button>`, а свои вы добавляете через `&`:

<TryIt
  language="tsx"
  code={`import type { ComponentProps } from "react";
import { createRoot } from "react-dom/client";

type ButtonProps = ComponentProps<"button"> & {
  variant?: "primary" | "ghost";
};

function Button({ variant = "primary", ...rest }: ButtonProps) {
  return <button className={\`btn \${variant}\`} {...rest} />;
}

createRoot(document.getElementById("root")!).render(
  <p>
    <Button type="submit" onClick={(e) => console.log(e.type)}>
      Сохранить
    </Button>{" "}
    <Button variant="ghost" disabled aria-label="Закрыть">✕</Button>
  </p>
);`}
/>

`...rest` собирает все остальные пропсы (включая `children` и `onClick`), а `{...rest}` раскладывает их на настоящий `<button>`. Даже `e` в обработчике клика типизирован за вас — как событие мыши на кнопке. Нативные пропсы остаются строгими:

```tsx
<Button type="sumbit">Сохранить</Button>
// ❌ Error: Type '"sumbit"' is not assignable to type '"button" | "submit" | "reset" | undefined'. Did you mean '"submit"'?

<Button href="/board">Доска</Button>
// ❌ Error: Property 'href' does not exist on type 'IntrinsicAttributes & ClassAttributes<HTMLButtonElement> & ButtonHTMLAttributes<HTMLButtonElement> & { ...; }'. Did you mean 'ref'?
```

Два родственных приёма, которые встречаются в реальных проектах (`Omit` — один из [утилитных типов](/learn/typescript/utility-types)):

```tsx
// Заменить нативный проп своей версией: сначала Omit его убирает
type TextFieldProps = Omit<ComponentProps<"input">, "onChange"> & {
  onChange: (value: string) => void;
};

// Переиспользовать пропсы ДРУГОГО компонента, например чтобы обернуть его
type FancyAvatarProps = ComponentProps<typeof Avatar> & {
  online: boolean;
};
```

## Обобщённые компоненты

У компонента может быть **параметр типа** (type parameter), как у [обобщённой функции](/learn/typescript/generic-functions). Вот список, который работает с элементами любого типа и при этом знает, какой тип в нём хранится:

<TryIt
  language="tsx"
  code={`import type { ReactNode } from "react";
import { createRoot } from "react-dom/client";

type ListProps<T> = {
  items: T[];
  getKey: (item: T) => string;
  renderItem: (item: T) => ReactNode;
};

function List<T>({ items, getKey, renderItem }: ListProps<T>) {
  return (
    <ul>
      {items.map((item) => (
        <li key={getKey(item)}>{renderItem(item)}</li>
      ))}
    </ul>
  );
}

const people = [
  { id: "u1", name: "Mei", tasks: 3 },
  { id: "u2", name: "Sam", tasks: 1 },
];

createRoot(document.getElementById("root")!).render(
  <List
    items={people}
    getKey={(person) => person.id}
    renderItem={(person) => \`\${person.name}: задач — \${person.tasks}\`}
  />
);`}
/>

`T` **выводится** из `items`, поэтому внутри `renderItem` у `person` тип `{ id: string; name: string; tasks: number }`. Попробуйте `person.age` — будет ошибка. (Если пишете обобщённый компонент **стрелочной функцией** в файле `.tsx`, пишите `<T,>(props: ListProps<T>) => ...` с запятой, чтобы парсер не принял `<T>` за JSX-тег.)

## Почему не `React.FC`?

Такой стиль встречается во многих туториалах и старых проектах:

```tsx
import type { FC } from "react";

const Greeting: FC<{ name: string }> = ({ name }) => <h1>Привет, {name}</h1>;
```

Он работает, но большинство команд сейчас предпочитают обычную функцию с типизированными пропсами, как в этом уроке, потому что:

- `FC` раньше (до React 18) добавлял скрытый проп `children` **каждому** компоненту, и компоненты принимали содержимое, которое никогда не показывали. Старые привычки и старые ответы в интернете до сих пор на это рассчитывают.
- Он **не умеет выражать обобщённые компоненты** вроде `List<T>` выше.
- Он не даёт ничего сверх типизированного параметра, а читать его дольше.

Аннотировать **возвращаемый тип** компонента тоже не нужно: TypeScript выводит его из JSX.

<Callout type="note" title="В реальных проектах">

Обычно файл компонента экспортирует и тип его пропсов, чтобы другие компоненты могли его переиспользовать: `export type TaskCardProps = { ... }` рядом с `export function TaskCard(...)`. import type { ComponentProps, ReactNode } from "react";
import { createRoot } from "react-dom/client";

type Priority = "low" | "medium" | "high";

type ButtonProps = ComponentProps<"button"> & {
  variant?: "primary" | "ghost";
};

function Button({ variant = "primary", ...rest }: ButtonProps) {
  return <button className={`btn ${variant}`} {...rest} />;
}

type TaskCardProps = {
  id: string;
  title: string;
  priority: Priority;
  tags?: string[];
  onDelete: (id: string) => void;
  children?: ReactNode;
};

function TaskCard({
  id,
  title,
  priority,
  tags = [],
  onDelete,
  children,
}: TaskCardProps) {
  return (
    <article className={`card ${priority}`}>
      <h3>{title}</h3>
      <span className="priority">{priority}</span>
      {tags.length > 0 && (
        <ul className="tags">
          {tags.map((tag) => (
            <li key={tag}>{tag}</li>
          ))}
        </ul>
      )}
      {children}
      <Button
        variant="ghost"
        aria-label={`Delete ${title}`}
        onClick={() => onDelete(id)}
      >
        ✕
      </Button>
    </article>
  );
}

function handleDelete(id: string) {
  console.log("Удаляем", id);
}

createRoot(document.getElementById("root")!).render(
  <>
    <TaskCard id="t1" title="Design the board" priority="high"
      tags={["ui", "design"]} onDelete={handleDelete}>
      <small className="due">Due Friday</small>
    </TaskCard>
    <TaskCard id="t2" title="Write the reducer" priority="medium"
      onDelete={handleDelete} />
    <TaskCard id="t3" title="Tidy the CSS" priority="low"
      tags={["ui"]} onDelete={handleDelete} />
  </>
);

// Тесты типов: каждая строка под @ts-expect-error ДОЛЖНА быть ошибкой
const log = (id: string) => console.log(id);
<Button type="submit" disabled>Save</Button>;
<TaskCard id="t9" title="Test" priority="low" onDelete={log} />;
// @ts-expect-error: "urgent" — не Priority
<TaskCard id="t9" title="Test" priority="urgent" onDelete={log} />;
// @ts-expect-error: onDelete обязателен
<TaskCard id="t9" title="Test" priority="low" />;
// @ts-expect-error: "danger" — не вариант Button
<Button variant="danger">Save</Button>;
// @ts-expect-error: у кнопки нет href
<Button href="/board">Board</Button>;

## Итоги

- Компоненты — это функции в файлах **`.tsx`**; пропсы приходят **одним объектом** и типизируются как любой параметр. Называйте тип `ComponentNameProps`; подходят и `type`, и `interface`.
- `createRoot(document.getElementById("root")!)`: `!` нужен, потому что `getElementById` возвращает `HTMLElement | null`.
- Необязательные пропсы помечаются `?`; значение по умолчанию при деструктуризации убирает `undefined` внутри компонента.
- **`children: ReactNode`** принимает всё, что React умеет отрисовать. Компоненты без `children` в пропсах отказываются принимать содержимое.
- Используйте **объединения** для вариантов (`"primary" | "ghost"`) вместо `string` или логических флагов и **размеченные объединения** для пропсов, которые имеют смысл только вместе; сужайте тип через `props.kind`, прежде чем читать остальное.
- Пропсы-колбэки выглядят как `onSelect: (id: string) => void`; передавайте функции, а не вызывайте их.
- **`ComponentProps<"button">`** (плюс `&`, `Omit` и `...rest`) расширяет нативные элементы; `ComponentProps<typeof X>` переиспользует пропсы другого компонента.
- Компоненты могут быть **обобщёнными** (`List<T>`). Предпочитайте обычные функции с типизированными пропсами вместо `React.FC`.
