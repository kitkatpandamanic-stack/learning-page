Компоненты из прошлого урока при одних и тех же пропсах всегда показывают одно и то же. Настоящие интерфейсы меняются: счётчик растёт, форма заполняется, карточка переезжает в другую колонку. Данные, которые меняются со временем и должны обновлять экран, называются **состоянием** (state). В этом уроке вы типизируете состояние, события и формы — те части React-приложения, откуда берётся большинство ошибок во время выполнения (и где TypeScript ловит большую их часть). 🔁

Если состояние и события в React для вас в новинку, курс JavaScript объясняет их шаг за шагом в уроке [Состояние и события](/learn/javascript/state-and-events). Здесь мы сосредоточимся на типах.

## useState и вывод типов

**`useState(initial)`** даёт компоненту память. Он возвращает пару: текущее значение и **сеттер** (setter). Вызов сеттера сохраняет новое значение, и React **перерисовывает** компонент (снова вызывает функцию) уже с ним:

<TryIt
  language="tsx"
  code={`import { useState } from "react";
import { createRoot } from "react-dom/client";

function Counter() {
  const [count, setCount] = useState(0);     // number
  const [label, setLabel] = useState("Bao"); // string

  return (
    <p>
      <button onClick={() => setCount(count + 1)}>
        {label}: съедено бамбука — {count} 🎋
      </button>{" "}
      <button onClick={() => setLabel(label === "Bao" ? "Mei" : "Bao")}>
        Сменить панду
      </button>
    </p>
  );
}

createRoot(document.getElementById("root")!).render(<Counter />);`}
/>

Вы не написали ни одного типа, но типизировано всё: TypeScript **выводит** (infers) тип состояния из начального значения, поэтому `count` — это `number`, а `setCount` принимает только числа:

```tsx
setCount("1");
// ❌ Error: Argument of type 'string' is not assignable to parameter of type 'SetStateAction<number>'.
```

`SetStateAction<number>` означает «число **или** функция, которая получает предыдущее число и возвращает следующее». Вторая форма — **функция-обновитель** (updater function) — нужна, когда новое значение зависит от старого: `setCount((c) => c + 1)`. Её параметр `c` тоже выводится как `number`.

Два правила для хуков (hooks — функций, чьи имена начинаются с `use`): вызывайте их только внутри компонентов или собственных хуков и только на **верхнем уровне**, никогда внутри `if` или цикла. React различает их по порядку вызова.

## Когда вывода типов недостаточно

Вывод типов видит только **первое** значение. Если оно не рассказывает всей истории, передайте тип сами как **аргумент типа** (type argument): `useState<Type>(initial)`. Три таких случая встречаются постоянно.

**1. Состояние, которое начинается пустым.** «Пользователь ещё не выбран» — это `null`, но позже там будет `User`. Из одного лишь `useState(null)` TypeScript выводит тип `null` — навсегда:

```tsx
const [user, setUser] = useState(null);
setUser(mei);
// ❌ Error: Argument of type '{ name: string; email: string; }' is not assignable to parameter of type 'SetStateAction<null>'.
```

**2. Пустые массивы.** Пустой литерал массива ничего не говорит TypeScript, поэтому `useState([])` превращается в `never[]` — массив, в котором никогда ничего не может лежать.

```tsx
const [tasks, setTasks] = useState([]);
setTasks([{ id: "t1", title: "План" }]);
// ❌ Error: Type '{ id: string; title: string; }' is not assignable to type 'never'.
```

**3. Несколько допустимых значений.** `useState("idle")` выводит просто `string`, так что `setStatus("idel")` компилируется. Объединение типов держит состояние в честных рамках.

Вот все три случая, исправленные. Нажмите на имена:

<TryIt
  language="tsx"
  code={`import { useState } from "react";
import { createRoot } from "react-dom/client";

type User = { id: number; name: string; email: string };
type Status = "idle" | "saving" | "saved";

const USERS: User[] = [
  { id: 1, name: "Mei Lin", email: "mei@pandadev.test" },
  { id: 2, name: "Sam Ortiz", email: "sam@pandadev.test" },
];

function UserPicker() {
  const [selected, setSelected] = useState<User | null>(null);
  const [history, setHistory] = useState<string[]>([]);
  const [status, setStatus] = useState<Status>("idle");

  function pick(user: User) {
    setSelected(user);
    setHistory((h) => [...h, user.name]);
    setStatus("saved");
  }

  return (
    <>
      {USERS.map((u) => (
        <button key={u.id} onClick={() => pick(u)}>{u.name}</button>
      ))}
      <p>
        {selected === null
          ? "Никто не выбран"
          : \`Выбран: \${selected.email}\`}
      </p>
      <p>Статус: {status} · История: {history.join(", ")}</p>
    </>
  );
}

createRoot(document.getElementById("root")!).render(<UserPicker />);`}
/>

С `User | null` TypeScript заставляет обработать случай «пока никого», прежде чем трогать пользователя: напишите `selected.email` вне проверки — и получите `'selected' is possibly 'null'.`. Это ровно та ошибка («Cannot read properties of null»), которую иначе вы нашли бы в продакшене.

<Callout type="warning" title="Не обманывайте useState">

`useState<User>({} as User)` или `useState<any>(null)` убирают ошибки, **отключая** проверки: пустой объект заявляет, что у него есть `email`, которого нет. Если значения может не быть, скажите об этом через `| null` и обработайте этот случай. Тогда компилятор напомнит о нём везде, где это важно.

</Callout>

## Обновляем объекты и массивы

React решает, нужно ли перерисовать компонент, проверяя, **новое** ли значение у состояния. Поэтому никогда не меняйте состояние на месте (`tasks.push(...)`, `task.done = true`); всегда создавайте новый массив или объект с помощью spread, `map` и `filter`. TypeScript присматривает и за этими копиями:

```tsx
const [task, setTask] = useState<Task>(firstTask);

setTask({ ...task, done: true });       // ✅ новый объект
setTask({ ...task, dnoe: true });
// ❌ Error: Object literal may only specify known properties, and 'dnoe' does not exist in type 'SetStateAction<Task>'.

setTasks((prev) => [...prev, newTask]);                  // добавить
setTasks((prev) => prev.filter((t) => t.id !== id));     // удалить
setTasks((prev) =>
  prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t))
);                                                       // изменить один
```

Если пометить типы элементов как `readonly` (или использовать `ReadonlyArray<Task>`), даже случайный `push` станет ошибкой типов — если вашей команде нужна такая дополнительная страховка.

## Типы событий

React передаёт каждому обработчику события (event handler) **объект события**. Когда вы пишете обработчик **прямо в JSX**, TypeScript уже знает его тип по пропу, так что аннотировать его почти никогда не нужно:

```tsx
<input onChange={(e) => setText(e.target.value)} />
// e — это ChangeEvent<HTMLInputElement>, e.target.value — строка
```

Стоит вынести обработчик в именованную функцию — контекст пропадает, и строгий режим требует тип:

```tsx
function handleChange(event) {
  // ❌ Error: Parameter 'event' implicitly has an 'any' type.
  setText(event.target.value);
}
```

Самые ходовые типы, все импортируются из `"react"`:

| Проп | Тип события |
| --- | --- |
| `onChange` у `<input>` | `ChangeEvent<HTMLInputElement>` |
| `onChange` у `<select>` / `<textarea>` | `ChangeEvent<HTMLSelectElement>` / `ChangeEvent<HTMLTextAreaElement>` |
| `onSubmit` у `<form>` | `SubmitEvent<HTMLFormElement>` |
| `onClick` | `MouseEvent<HTMLButtonElement>` (или того элемента, на котором он висит) |
| `onKeyDown` / `onKeyUp` | `KeyboardEvent<HTMLInputElement>` |

Аргумент типа — это элемент, к которому привязан обработчик. У каждого события есть и тип обработчика, например `ChangeEventHandler<HTMLInputElement>`, если удобнее типизировать функцию целиком: `const handleChange: ChangeEventHandler<HTMLInputElement> = (e) => ...`.

<TryIt
  language="tsx"
  code={`import { useState } from "react";
import type { ChangeEvent, KeyboardEvent, MouseEvent } from "react";
import { createRoot } from "react-dom/client";

function SearchBox() {
  const [query, setQuery] = useState("");

  function handleChange(event: ChangeEvent<HTMLInputElement>) {
    setQuery(event.target.value);
  }

  function handleKeyDown(event: KeyboardEvent<HTMLInputElement>) {
    if (event.key === "Escape") setQuery("");
  }

  function handleClick(event: MouseEvent<HTMLButtonElement>) {
    const button = event.currentTarget; // HTMLButtonElement
    console.log(\`нажата \${button.name}, shift: \${event.shiftKey}\`);
  }

  return (
    <p>
      <input
        value={query}
        onChange={handleChange}
        onKeyDown={handleKeyDown}
        placeholder="Введите текст и нажмите Escape"
      />{" "}
      <button name="search" onClick={handleClick}>Найти</button>
      <br />Вы ввели: {query || "(ничего)"}
    </p>
  );
}

createRoot(document.getElementById("root")!).render(<SearchBox />);`}
/>

Такое поле, чьё `value` берётся из состояния, а `onChange` это состояние обновляет, называется **управляемым полем ввода** (controlled input): React всегда решает, что в нём показано, поэтому очистить его — это просто `setQuery("")`.

Обратите внимание на `event.currentTarget.name`. **`currentTarget`** — это элемент, к которому привязан обработчик, поэтому React типизирует его точно (`HTMLButtonElement`). **`target`** — это место, где событие началось; при клике это может быть иконка внутри кнопки, поэтому его тип — всего лишь `EventTarget`: `event.target.name` — ошибка (`Property 'name' does not exist on type 'EventTarget'.`). Исключение — события изменения у полей формы: там `target` типизирован как само поле.

<Callout type="tip" title="Не уверены в типе события? Спросите редактор">

Сначала напишите обработчик прямо в JSX, затем наведите курсор на `e` в редакторе: он покажет точный тип, например `ChangeEvent<HTMLSelectElement, HTMLSelectElement>` (свежие типы React добавляют вторым аргументом типа элемент, на котором сработало событие; его можно опустить). Скопируйте этот тип в именованный обработчик. И проверьте, что тип импортирован из `"react"`: `MouseEvent`, `KeyboardEvent` и `SubmitEvent` существуют и как **DOM**-типы с теми же именами, и если забыть импорт, вы получите DOM-тип и запутанную ошибку.

</Callout>

В старом коде и туториалах для обработчиков отправки формы встречается `FormEvent<HTMLFormElement>`. Он по-прежнему работает, но свежие версии `@types/react` помечают его как устаревший в пользу `SubmitEvent`, поэтому редактор показывает его зачёркнутым.

## Значения select — это просто строки

`<select>` обычно соответствует объединению, например приоритету задачи. Но браузер знает только текст, поэтому `event.target.value` — это `string`:

```tsx
const PRIORITIES = ["low", "medium", "high"] as const;
type Priority = (typeof PRIORITIES)[number]; // "low" | "medium" | "high"

function handlePriority(event: ChangeEvent<HTMLSelectElement>) {
  setPriority(event.target.value);
  // ❌ Error: Argument of type 'string' is not assignable to parameter of type 'SetStateAction<"low" | "medium" | "high">'.
}
```

Не глушите ошибку через `as Priority`: варианты в HTML и тип могут разойтись, а приведение это скроет. Вместо этого проверьте значение [защитником типа](/learn/typescript/type-guards-and-unknown) (type guard) — и объединению по-прежнему можно доверять:

```tsx
function isPriority(value: string): value is Priority {
  return PRIORITIES.some((p) => p === value);
}

function handlePriority(event: ChangeEvent<HTMLSelectElement>) {
  const value = event.target.value;
  if (isPriority(value)) setPriority(value); // ✅ здесь value — Priority
}
```

`as const` делает `PRIORITIES` неизменяемым кортежем из трёх точных строк, а `(typeof PRIORITIES)[number]` превращает его в объединение. Один список даёт и **варианты для отрисовки**, и **тип**, поэтому разойтись они не могут.

## Управляемые формы с типизированным состоянием

В настоящей форме несколько полей. Храните их вместе в **одном объекте**, типизированном как данные формы, и напишите один маленький обобщённый помощник, который обновляет любое поле значением **правильного типа** для этого поля:

<TryIt
  language="tsx"
  code={`import { useState } from "react";
import type { ChangeEvent, SubmitEvent } from "react";
import { createRoot } from "react-dom/client";

const PRIORITIES = ["low", "medium", "high"] as const;
type Priority = (typeof PRIORITIES)[number];

type TaskDraft = { title: string; priority: Priority; points: number };

const EMPTY: TaskDraft = { title: "", priority: "medium", points: 1 };

function isPriority(value: string): value is Priority {
  return PRIORITIES.some((p) => p === value);
}

function TaskForm() {
  const [draft, setDraft] = useState<TaskDraft>(EMPTY);

  function update<K extends keyof TaskDraft>(
    key: K,
    value: TaskDraft[K],
  ) {
    setDraft((d) => ({ ...d, [key]: value }));
  }

  function handlePriority(event: ChangeEvent<HTMLSelectElement>) {
    const value = event.target.value;
    if (isPriority(value)) update("priority", value);
  }

  function handlePoints(event: ChangeEvent<HTMLInputElement>) {
    const points = event.target.valueAsNumber;
    update("points", Number.isNaN(points) ? 0 : points);
  }

  // Вычисляется из состояния, поэтому никогда не устаревает
  const problem =
    draft.title.trim() === "" ? "Дайте задаче название"
    : draft.points < 1 ? "Баллов должно быть не меньше 1"
    : null;

  function handleSubmit(event: SubmitEvent<HTMLFormElement>) {
    event.preventDefault(); // без перезагрузки страницы
    if (problem !== null) return;
    console.log("Новая задача:", { ...draft, title: draft.title.trim() });
    setDraft(EMPTY);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={draft.title}
        onChange={(e) => update("title", e.target.value)}
        placeholder="Название"
      />{" "}
      <select value={draft.priority} onChange={handlePriority}>
        {PRIORITIES.map((p) => <option key={p}>{p}</option>)}
      </select>{" "}
      <input type="number" value={draft.points} onChange={handlePoints}
        style={{ width: 50 }} />{" "}
      <button type="submit" disabled={problem !== null}>Добавить</button>
      <p>{problem ?? "Можно добавлять ✔"}</p>
    </form>
  );
}

createRoot(document.getElementById("root")!).render(<TaskForm />);`}
/>

Помощник `update<K extends keyof TaskDraft>(key: K, value: TaskDraft[K])` — это паттерн `keyof` / `T[K]` из урока [Обобщённые функции](/learn/typescript/generic-functions) в деле: `update("points", "3")` — ошибка, потому что `TaskDraft["points"]` — это `number`, а `update("titel", ...)` — ошибка, потому что такого ключа нет. Ещё несколько моментов:

- **Числовые поля тоже отдают строки.** `event.target.value` — всегда строка; `valueAsNumber` даёт число или `NaN`, если поле пустое.
- **Сообщение о проблеме вычисляется**, а не хранится в состоянии: оно пересчитывается из `draft` при каждом рендере, поэтому не может рассинхронизироваться.
- **`onSubmit` у формы** (а не `onClick` у кнопки) срабатывает и от кнопки, и от клавиши Enter, а `event.preventDefault()` не даёт браузеру перезагрузить страницу.

<Callout type="note" title="Сокращение [event.target.name]">

Во многих туториалах по JavaScript форму обновляют одним обработчиком: `setDraft({ ...draft, [e.target.name]: e.target.value })`. Это компилируется, но TypeScript не может это проверить: `name` — любая строка, и любое значение — строка, так что опечатка в атрибуте `name` или текст в числовом поле проскочат незамеченными. Помощник с ключом выше стоит на одну строку больше и сохраняет типы всех полей. Библиотеки форм вроде React Hook Form построены на той же идее.

</Callout>

## Рефы: добираемся до DOM-элемента

Иногда нужен настоящий DOM-элемент, например чтобы **поставить фокус** в поле после отправки. **`useRef`** даёт коробку, в свойство `.current` которой React положит элемент. Передайте тип элемента и `null` как начальное значение, потому что элемента не существует, пока React его не нарисовал:

<TryIt
  language="tsx"
  code={`import { useRef, useState } from "react";
import { createRoot } from "react-dom/client";

function QuickAdd() {
  const inputRef = useRef<HTMLInputElement>(null);
  const renders = useRef(0); // значение, которое переживает перерисовки
  const [items, setItems] = useState<string[]>([]);
  renders.current++;

  function add() {
    const input = inputRef.current;
    if (input === null) return; // элемента ещё нет на странице
    if (input.value.trim() !== "") {
      setItems((list) => [...list, input.value.trim()]);
    }
    input.value = "";
    input.focus();
  }

  return (
    <>
      <input ref={inputRef} placeholder="Идея" />{" "}
      <button onClick={add}>Добавить</button>
      <ul>{items.map((item, i) => <li key={i}>{item}</li>)}</ul>
      <small>Рендеров: {renders.current}</small>
    </>
  );
}

createRoot(document.getElementById("root")!).render(<QuickAdd />);`}
/>

У `useRef<HTMLInputElement>(null)` тип `RefObject<HTMLInputElement | null>`, поэтому TypeScript настаивает, чтобы вы обработали момент, когда React ещё не привязал элемент:

```tsx
inputRef.current.focus();
// ❌ Error: 'inputRef.current' is possibly 'null'.

inputRef.current?.focus(); // ✅ ничего не делает, если элемента нет
```

Забудьте аргумент типа — и получите `useRef(null)`, реф, в котором может лежать только `null`: тогда `ref.current?.focus()` падает с ошибкой `Property 'focus' does not exist on type 'never'.`

Второй реф, `useRef(0)`, хранит обычное **значение**, которое переживает перерисовки, но, в отличие от состояния, **не вызывает** перерисовку при изменении. Это место для таких вещей, как id таймеров: `useRef<number | null>(null)`. (Это поле — **неуправляемое**: текст хранит браузер, а мы читаем его через реф. Для быстрого поля добавления это нормально; для форм с валидацией лучше управляемые поля. Индекс в качестве `key` здесь допустим только потому, что элементы никогда не удаляются и не переставляются.)

## Поднимаем состояние с типизированными колбэками

Когда двум компонентам нужно одно и то же состояние, перенесите его в ближайшего общего **родителя**, передайте вниз как пропсы, а для изменений передайте вниз **колбэки**. Форме, которая добавляет задачи, и списку, который их показывает, обоим нужен список задач, поэтому им владеет `App`:

<TryIt
  language="tsx"
  code={`import { useState } from "react";
import type { SubmitEvent } from "react";
import { createRoot } from "react-dom/client";

type Task = { id: string; title: string };

type AddTaskProps = { onAdd: (title: string) => void };

function AddTask({ onAdd }: AddTaskProps) {
  const [title, setTitle] = useState("");

  function handleSubmit(event: SubmitEvent<HTMLFormElement>) {
    event.preventDefault();
    if (title.trim() === "") return;
    onAdd(title.trim());
    setTitle("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={title} onChange={(e) => setTitle(e.target.value)} />
      <button>Добавить</button>
    </form>
  );
}

type TaskListProps = { tasks: Task[]; onRemove: (id: string) => void };

function TaskList({ tasks, onRemove }: TaskListProps) {
  if (tasks.length === 0) return <p>Дел нет 🎉</p>;
  return (
    <ul>
      {tasks.map((t) => (
        <li key={t.id}>
          {t.title} <button onClick={() => onRemove(t.id)}>✕</button>
        </li>
      ))}
    </ul>
  );
}

function App() {
  const [tasks, setTasks] = useState<Task[]>([
    { id: "t1", title: "Спланировать доску" },
  ]);

  function addTask(title: string) {
    setTasks((prev) => [...prev, { id: crypto.randomUUID(), title }]);
  }

  function removeTask(id: string) {
    setTasks((prev) => prev.filter((t) => t.id !== id));
  }

  return (
    <>
      <AddTask onAdd={addTask} />
      <TaskList tasks={tasks} onRemove={removeTask} />
      <p>Задач: {tasks.length}</p>
    </>
  );
}

createRoot(document.getElementById("root")!).render(<App />);`}
/>

Данные текут **вниз** (`tasks`), события — **вверх** (`onAdd`, `onRemove`), и у каждого кусочка состояния **один владелец**. Счётчик вообще не состояние: он вычисляется из `tasks`.

Можно было бы передать вниз сам сеттер: у `setTasks` тип `Dispatch<SetStateAction<Task[]>>`, и дочерний компонент мог бы принимать проп такого типа. Но лучше колбэки, названные по тому, **что произошло** (`onAdd: (title: string) => void`): дочернему компоненту не нужно знать, как родитель хранит задачи, родитель сохраняет контроль над id и валидацией, а тип пропа точно документирует, что именно отправляет дочерний компонент.

```tsx
import { useRef, useState } from "react";
import type { ChangeEvent, SubmitEvent } from "react";
import { createRoot } from "react-dom/client";

const PRIORITIES = ["low", "medium", "high"] as const;
type Priority = (typeof PRIORITIES)[number];

type Task = { id: string; title: string; priority: Priority };
type TaskDraft = Omit<Task, "id">;

const EMPTY: TaskDraft = { title: "", priority: "medium" };

function isPriority(value: string): value is Priority {
  return PRIORITIES.some((p) => p === value);
}

type TaskFormProps = { onAdd: (draft: TaskDraft) => void };

function TaskForm({ onAdd }: TaskFormProps) {
  const [draft, setDraft] = useState<TaskDraft>(EMPTY);
  const [error, setError] = useState<string | null>(null);
  const titleRef = useRef<HTMLInputElement>(null);

  function handleTitle(event: ChangeEvent<HTMLInputElement>) {
    setDraft({ ...draft, title: event.target.value });
  }

  function handlePriority(event: ChangeEvent<HTMLSelectElement>) {
    const value = event.target.value;
    if (isPriority(value)) setDraft({ ...draft, priority: value });
  }

  function handleSubmit(event: SubmitEvent<HTMLFormElement>) {
    event.preventDefault();
    const title = draft.title.trim();
    if (title === "") {
      setError("Дайте задаче название");
      return;
    }
    onAdd({ title, priority: draft.priority });
    setDraft(EMPTY);
    setError(null);
    titleRef.current?.focus();
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        name="title"
        ref={titleRef}
        value={draft.title}
        onChange={handleTitle}
        placeholder="Новая задача"
      />
      <select
        name="priority"
        value={draft.priority}
        onChange={handlePriority}
      >
        {PRIORITIES.map((p) => <option key={p}>{p}</option>)}
      </select>
      <button type="submit">Добавить</button>
      {error !== null && <p className="error">{error}</p>}
    </form>
  );
}

let nextId = 1;

function App() {
  const [tasks, setTasks] = useState<Task[]>([]);

  function handleAdd(draft: TaskDraft) {
    setTasks((prev) => [...prev, { id: `t${nextId++}`, ...draft }]);
  }

  return (
    <main>
      <TaskForm onAdd={handleAdd} />
      <ul className="tasks">
        {tasks.map((task) => (
          <li key={task.id} className={task.priority}>
            {task.title}
          </li>
        ))}
      </ul>
      <p className="count">Задач: {tasks.length}</p>
    </main>
  );
}

createRoot(document.getElementById("root")!).render(<App />);
```

## Итоги

- `useState` **выводит** свой тип из начального значения. Передавайте аргумент типа, когда этого мало: `useState<User | null>(null)`, `useState<Task[]>([])`, `useState<Status>("idle")`. Никогда не заклеивайте проблему через `any` или `{} as T`.
- Сеттеры принимают значение или **функцию-обновитель** `(prev) => next`; всегда создавайте новые объекты и массивы.
- Обработчики, написанные прямо в JSX, типизированы за вас. Именованным обработчикам нужны типы событий React: `ChangeEvent<HTMLInputElement>`, `SubmitEvent<HTMLFormElement>`, `MouseEvent<HTMLButtonElement>`, `KeyboardEvent<...>` — импортируйте их из `"react"`. `currentTarget` типизирован точно, `target` — не всегда.
- Поля формы отдают **строки**: сужайте значения `<select>` до объединения защитником типа, а для чисел используйте `valueAsNumber`.
- Храните форму в одном типизированном объекте и обновляйте её помощником с ключом `update<K extends keyof T>(key: K, value: T[K])`; сообщения валидации вычисляйте, а не храните.
- `useRef<HTMLInputElement>(null)` даёт доступ к DOM-элементу; обрабатывайте `null` через `?.`. `useRef(value)` хранит значение без перерисовок.
- **Поднимайте состояние** в общего родителя и передавайте вниз колбэки, названные по тому, что произошло (`onAdd: (draft: TaskDraft) => void`).
