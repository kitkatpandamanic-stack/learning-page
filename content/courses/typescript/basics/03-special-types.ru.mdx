Иногда тип значения ещё неизвестен, а иногда значения может вообще **не быть**. Для таких ситуаций в TypeScript есть особые типы. Одни вас защищают, а один незаметно отключает всю страховку. Давайте познакомимся с ними, а потом соберём с их помощью генератор приветствий.

## `any`: выключаем проверку

Переменная типа `any` может хранить что угодно, и TypeScript перестаёт её проверять совсем. Звучит удобно, но из-за этого ошибки проскакивают незамеченными:

<CodeExample output="105">

```ts
let price: any = "10"; // упс, это строка
const total = price + 5;

console.log(total);
```

</CodeExample>

Мы хотели получить `15`, но `"10" + 5` склеивает текст и даёт `"105"`. TypeScript промолчал, потому что `any` велел ему не смотреть. Дальше хуже: с `any` даже вызов несуществующего **метода** (method) компилируется без ошибок и падает только во время работы программы.

<Callout type="warning" title="Избегайте any">

Каждый `any` — это дыра в вашей страховке. Если тип пока неизвестен, используйте вместо него `unknown` (о нём ниже). Многие команды вообще запрещают `any`.

</Callout>

## `unknown`: безопасное «пока не знаю»

`unknown` тоже может хранить что угодно, но TypeScript не даст **использовать** значение, пока вы не проверите, что это такое:

```ts
let input: unknown = "привет";
input.toUpperCase();
// ❌ Error: 'input' is of type 'unknown'.
```

Для проверки используйте `typeof` внутри `if`. Код в блоке `if` выполняется, только когда **условие** (condition) истинно, а в остальных случаях выполняется блок `else`. (Подробно `if` разберём в следующем модуле.)

<CodeExample output={`ПРИВЕТ
Это не текст!`}>

```ts
let input: unknown = "привет";

if (typeof input === "string") {
  console.log(input.toUpperCase()); // здесь input — строка
}

input = 42;

if (typeof input === "string") {
  console.log(input.toUpperCase());
} else {
  console.log("Это не текст!");
}
```

</CodeExample>

Внутри `if (typeof input === "string")` TypeScript знает, что `input` — строка, поэтому `.toUpperCase()` разрешён. Это называется **сужением типа** (narrowing).

## `null` и `undefined`: отсутствующие значения

В JavaScript есть два способа сказать «значения нет»:

- **`undefined`**: сюда ещё ничего не положили — например, переменная объявлена без значения.
- **`null`**: намеренно пусто, то есть «значения нет, и так задумано».

PandaDev использует **строгую проверку null** (strict null checks, рекомендуемая настройка), поэтому в обычный `string` нельзя положить `null`:

```ts
let nickname: string = null;
// ❌ Error: Type 'null' is not assignable to type 'string'.
```

Чтобы это разрешить, пишите `string | null`. Символ `|` означает **«или»**: «строка или null». Это называется **объединением типов** (union type), и скоро вы встретите их очень много.

<CodeExample output={`null
Панди`}>

```ts
let nickname: string | null = null;
console.log(nickname);

nickname = "Панди";
console.log(nickname);
```

</CodeExample>

Теперь TypeScript следит, чтобы вы никогда не забывали про случай «значения нет»:

```ts
function shout(nickname: string | null) {
  console.log(nickname.toUpperCase());
  // ❌ Error: 'nickname' is possibly 'null'.
}
```

## Работаем с отсутствующими значениями: `?.` и `??`

Два коротких оператора упрощают работу с отсутствующими значениями:

- **Опциональная цепочка** (optional chaining) `a?.b`: если `a` равно `null` или `undefined`, остановиться и вернуть `undefined` вместо падения.
- **Оператор нулевого слияния** (nullish coalescing) `a ?? b`: взять `a`, а если это `null` или `undefined`, взять `b`.

<CodeExample output={`ПАНДИ
undefined
Панди
нет прозвища`}>

```ts
function shout(nickname: string | null): void {
  console.log(nickname?.toUpperCase());
}

function label(nickname: string | null): string {
  return nickname ?? "нет прозвища";
}

shout("Панди");
shout(null);
console.log(label("Панди"));
console.log(label(null));
```

</CodeExample>

Возвращаемый тип `void` означает «эта функция не возвращает ничего полезного», она просто что-то делает (здесь — выводит текст).

<Callout type="tip" title="?? или ||?">

Вам может встретиться и `a || b`. Он подставляет запасное значение для **любого** «ложного» значения, включая `""` и `0`, а `??` — только для `null` и `undefined`. Поэтому `0 ?? 10` даёт `0`, а `0 || 10` даёт `10`. Выбирайте `??`, когда `0` или пустая строка — вполне нормальные значения.

</Callout>

Пора собрать проект модуля! Допишите `greet(name, nickname, excited)`, чтобы функция возвращала приветствие:

- `greet("Мария", null, true)` возвращает `"Привет, Мария!"` (прозвища нет, поэтому берём имя).
- `greet("Александр", "Саша", false)` возвращает `"Привет, Саша."` (берём прозвище).

В стартовом коде есть **ошибки типов**: у параметров пока нет типов. Сначала добавьте их, а также возвращаемый тип `string`.

<Hint>

Параметры такие: `name: string, nickname: string | null, excited: boolean`. Выберите, кого приветствовать: `const who = nickname ?? name;`. Затем `if (excited)` верните `` `Привет, ${who}!` ``, а иначе — вариант с точкой в конце.

</Hint>

<Solution>

```ts
function greet(
  name: string,
  nickname: string | null,
  excited: boolean,
): string {
  const who = nickname ?? name;

  if (excited) {
    return `Привет, ${who}!`;
  }
  return `Привет, ${who}.`;
}

console.log(greet("Мария", null, true)); // Привет, Мария!
console.log(greet("Александр", "Саша", false)); // Привет, Саша.
```

</Solution>

</Exercise>

## Итоги

- `any` отключает проверку типов — избегайте его.
- `unknown` хранит что угодно, но перед использованием значение нужно проверить (например, с помощью `typeof`).
- `undefined` значит «ещё не задано», `null` — «пусто намеренно».
- При строгой проверке null отсутствующее значение нужно разрешать явно: `string | null`.
- `a?.b` безопасно останавливается на `null`/`undefined`; `a ?? b` подставляет запасное значение.
