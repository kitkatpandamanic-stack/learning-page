Every value in a program has a **type**: is it text, a number, or a yes/no answer? In this lesson you'll meet the three types you'll use all the time, learn when TypeScript can work types out **by itself**, and take a first look at lists of values.

## The three everyday types

| Type      | Holds                          | Examples               |
| --------- | ------------------------------ | ---------------------- |
| `string`  | Text, in quotes                | `"Tokyo"`, `'hi'`      |
| `number`  | Any number, whole or decimal   | `42`, `-3`, `13.96`    |
| `boolean` | A yes/no answer                | `true`, `false`        |

<CodeExample output={`Tokyo 13.96 true
string number boolean`}>

```ts
const city: string = "Tokyo";
const population: number = 13.96;
const isCapital: boolean = true;

console.log(city, population, isCapital);
console.log(typeof city, typeof population, typeof isCapital);
```

</CodeExample>

`console.log` can print several values at once, separated by commas. The `typeof` operator asks JavaScript for a value's type while the program is running.

## Type inference: TypeScript works it out

You don't have to annotate everything. When you give a variable a starting value, TypeScript **infers** (works out) its type from that value:

<CodeExample output="HELLO, WORLD">

```ts
let message = "Hello"; // TypeScript infers: string
message = message + ", world";
console.log(message.toUpperCase());
```

</CodeExample>

There's no `: string` here, but `message` is still a string, and it's still checked:

```ts
let score = 10; // inferred: number
score = 15; // fine
score = "fifteen";
// ❌ Error: Type 'string' is not assignable to type 'number'.
```

## `let` vs `const` (and literal types)

A `let` variable can be given a new value; a `const` can't:

```ts
const lives = 3;
lives = 2;
// ❌ Error: Cannot assign to 'lives' because it is a constant.
```

Because a `const` can never change, TypeScript infers a more exact type for it, called a **literal type**:

```ts
let pet = "cat"; // type: string (it could change later)
const sound = "meow"; // type: "meow" (it can only ever be "meow")
```

You don't need to do anything with literal types yet. They become really useful in the Control Flow module.

<Callout type="tip" title="Prefer const">

Use `const` by default and switch to `let` only when the value really needs to change. Your code is easier to follow when most values stay put.

</Callout>

## Arrays: a first look

An **array** is a list of values in square brackets. Its type is the item type followed by `[]`, so `string[]` means "a list of strings":

<CodeExample output={`[ 'apple', 'banana', 'mango' ]
3
apple`}>

```ts
const fruits: string[] = ["apple", "banana"];
fruits.push("mango");

console.log(fruits);
console.log(fruits.length);
console.log(fruits[0]);
```

</CodeExample>

- `.push(...)` adds an item to the end.
- `.length` is how many items there are.
- `fruits[0]` is the **first** item: counting starts at 0.

TypeScript makes sure only the right kind of item gets in:

```ts
fruits.push(42);
// ❌ Error: Argument of type 'number' is not assignable to parameter of type 'string'.
```

## A first look at functions

A **function** is a named, reusable block of code. Its **parameters** are its inputs, and `return` sends a result back. Parameters can't be inferred (the function could be called with anything), so you always annotate them. You can also annotate what the function returns:

<CodeExample output={`14
2.5`}>

```ts
function double(n: number): number {
  return n * 2;
}

console.log(double(7));
console.log(double(1.25));
```

</CodeExample>

You'll learn much more about functions in the Typed Functions module. For now, just remember: **parameters always get a type**.

## When should I annotate?

<CodeExample output={`12
[ 'Ana' ]`}>

```ts
let total: number; // no starting value, so annotate
total = 5 + 7;
console.log(total);

const names: string[] = []; // empty array, so annotate
names.push("Ana");
console.log(names);
```

</CodeExample>

A simple rule of thumb:

- **Let TypeScript infer** when you give a variable a value straight away: `let count = 0`.
- **Annotate** when there's no starting value, when you start with an empty array, and on function parameters.

<Callout type="note">

Adding an annotation where inference would work isn't wrong, it's just extra typing. While you're learning, writing a few extra annotations can help you think about your types.

</Callout>

## Recap

- `string` is text, `number` is any number, `boolean` is `true` or `false`.
- TypeScript **infers** a variable's type from its starting value.
- `const` can't be reassigned, so it gets an exact **literal type**; `let` gets the wider type.
- `string[]` is an array of strings; `.push` adds items and `.length` counts them.
- Annotate when there's no starting value, for empty arrays and for function parameters.
