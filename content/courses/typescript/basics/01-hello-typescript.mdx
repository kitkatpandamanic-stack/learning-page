A **program** is a list of instructions the computer follows from top to bottom. **TypeScript** is a programming language for writing those instructions. It's **JavaScript plus types**: you describe what kind of value each thing should be, and the TypeScript **compiler** checks your code for mistakes _before_ it runs. 🐼

## Your first program

`console.log(...)` prints whatever you put in the brackets. Text goes inside quotes and is called a **string**. Numbers are written without quotes:

<CodeExample output={`Hello, TypeScript! 🐼
5`}>

```ts
console.log("Hello, TypeScript! 🐼");
console.log(2 + 3);
```

</CodeExample>

Each line is one **statement**, and they run in order. The `;` at the end marks where a statement finishes.

## Variables and your first type annotation

A **variable** is a named box that holds a value. You create one with `const` (the value never changes) or `let` (you can change it later). In TypeScript you can add a **type annotation**, a colon followed by a type, to say what the box may hold:

<CodeExample output={`Mei
12
Mei is 12 years old`}>

```ts
const petName: string = "Mei";
let age: number = 12;

console.log(petName);
console.log(age);
console.log(`${petName} is ${age} years old`);
```

</CodeExample>

- `: string` means "this holds text".
- `: number` means "this holds a number".
- Text in backticks is a **template literal**: `${...}` drops a value into the string.

## Catching mistakes before running

Here's the big idea. Once `age` is a `number`, TypeScript won't let you put text in it:

```ts
let age: number = 12;
age = "thirteen";
// ❌ Error: Type 'string' is not assignable to type 'number'.
```

Plain JavaScript would happily run this, and the bug might only show up much later. TypeScript stops you **straight away** and tells you which line is wrong.

It also knows what you can _do_ with each type. Numbers don't have an upper case, so this is caught too:

```ts
const score: number = 10;
score.toUpperCase();
// ❌ Error: Property 'toUpperCase' does not exist on type 'number'.
```

Fix the mistakes and the program runs normally:

<CodeExample output={`14
HiHiHi`}>

```ts
let age: number = 12;
age = 13;
console.log(age + 1);

const greeting: string = "Hi";
console.log(greeting.repeat(3));
```

</CodeExample>

<Callout type="note" title="Types disappear when the code runs">

Computers (and browsers) actually run **JavaScript**. The compiler checks your types, then removes them, leaving plain JavaScript behind. Types are a safety net for _you_ while you write code; they don't change what the program does.

</Callout>

## How PandaDev checks your code

In the editors on PandaDev, pressing **Run** or **Check** first **type-checks** your code. If there are type errors, nothing runs. Instead you'll see messages like this:

```text
Line 2: Type 'string' is not assignable to type 'number'.
```

Read the line number, fix that line, then press Run again. In a real project you do the same job with the `tsc` compiler on your computer:

```bash
npx tsc hello.ts   # check the types and create hello.js
node hello.js      # run the JavaScript
```

<Callout type="tip" title="Error messages are your friend">

Type errors can look scary at first, but they follow a pattern: "Type **X** is not assignable to type **Y**" means you gave a value of type X where type Y was expected. Read them slowly, they nearly always tell you exactly what's wrong.

</Callout>

## Recap

- TypeScript is **JavaScript plus types**; the compiler checks your code before it runs.
- `console.log(...)` prints a value; strings go in quotes, numbers don't.
- `const` makes a variable that can't change, `let` one that can.
- A **type annotation** like `let age: number = 12` says what a variable may hold.
- Type errors stop the code from running and tell you the line and the problem.
