Sometimes you don't know a value's type yet, or a value might be **missing** altogether. TypeScript has special types for these situations. Some keep you safe, and one quietly switches the safety net off. Let's meet them, then build a greeting generator with them.

## `any`: switching the checker off

A variable of type `any` can hold anything, and TypeScript stops checking it completely. That sounds handy, but it means bugs slip straight through:

<CodeExample output="105">

```ts
let price: any = "10"; // oops, a string
const total = price + 5;

console.log(total);
```

</CodeExample>

We wanted `15`, but `"10" + 5` joins text and gives `"105"`. TypeScript said nothing, because `any` told it not to look. It gets worse: with `any`, even calling a method that doesn't exist compiles fine and only crashes when the code runs.

<Callout type="warning" title="Avoid any">

Every `any` is a hole in your safety net. If you don't know a type yet, use `unknown` instead (below). Many teams ban `any` completely.

</Callout>

## `unknown`: the safe "I don't know yet"

`unknown` can also hold anything, but TypeScript won't let you **use** the value until you've checked what it is:

```ts
let input: unknown = "hello";
input.toUpperCase();
// ❌ Error: 'input' is of type 'unknown'.
```

To check, use `typeof` inside an `if`. The code in the `if` block only runs when the condition is true, and the `else` block runs otherwise. (You'll learn `if` properly in the next module.)

<CodeExample output={`HELLO
That's not text!`}>

```ts
let input: unknown = "hello";

if (typeof input === "string") {
  console.log(input.toUpperCase()); // input is a string here
}

input = 42;

if (typeof input === "string") {
  console.log(input.toUpperCase());
} else {
  console.log("That's not text!");
}
```

</CodeExample>

Inside `if (typeof input === "string")`, TypeScript knows `input` is a string, so `.toUpperCase()` is allowed. This is called **narrowing**.

## `null` and `undefined`: missing values

JavaScript has two ways to say "no value":

- **`undefined`**: nothing has been put here yet, for example a variable declared without a value.
- **`null`**: deliberately empty, meaning "there is no value on purpose".

PandaDev uses **strict null checks** (the recommended setting), so `null` isn't allowed in an ordinary `string`:

```ts
let nickname: string = null;
// ❌ Error: Type 'null' is not assignable to type 'string'.
```

To allow it, write `string | null`. The `|` means **"or"**: "a string or null". This is called a **union type**, and you'll see a lot more of them soon.

<CodeExample output={`null
Pandy`}>

```ts
let nickname: string | null = null;
console.log(nickname);

nickname = "Pandy";
console.log(nickname);
```

</CodeExample>

Now TypeScript makes sure you never forget the "no value" case:

```ts
function shout(nickname: string | null) {
  console.log(nickname.toUpperCase());
  // ❌ Error: 'nickname' is possibly 'null'.
}
```

## Handling missing values: `?.` and `??`

Two short operators make missing values easy to deal with:

- **Optional chaining** `a?.b`: if `a` is `null` or `undefined`, stop and give `undefined` instead of crashing.
- **Nullish coalescing** `a ?? b`: use `a`, unless it's `null` or `undefined`, then use `b`.

<CodeExample output={`PANDY
undefined
Pandy
no nickname`}>

```ts
function shout(nickname: string | null): void {
  console.log(nickname?.toUpperCase());
}

function label(nickname: string | null): string {
  return nickname ?? "no nickname";
}

shout("Pandy");
shout(null);
console.log(label("Pandy"));
console.log(label(null));
```

</CodeExample>

The return type `void` means "this function doesn't return anything useful", it just does something (here, printing).

<Callout type="tip" title="?? or ||?">

You may also see `a || b`. It falls back for **any** "falsy" value, including `""` and `0`, while `??` only falls back for `null` and `undefined`. So `0 ?? 10` is `0`, but `0 || 10` is `10`. Reach for `??` when `0` or an empty string is a perfectly good value.

</Callout>

<Hint>

The parameters are `name: string, nickname: string | null, excited: boolean`. Pick who to greet with `const who = nickname ?? name;`. Then `if (excited)`, return `` `Hello, ${who}!` ``; otherwise return the version ending in a full stop.

</Hint>

<Solution>

```ts
function greet(
  name: string,
  nickname: string | null,
  excited: boolean,
): string {
  const who = nickname ?? name;

  if (excited) {
    return `Hello, ${who}!`;
  }
  return `Hello, ${who}.`;
}

console.log(greet("Mei", null, true)); // Hello, Mei!
console.log(greet("Samuel", "Sam", false)); // Hello, Sam.
```

</Solution>

## Recap

- `any` turns type checking off: avoid it.
- `unknown` holds anything, but you must check it (for example with `typeof`) before using it.
- `undefined` means "not set yet"; `null` means "empty on purpose".
- With strict null checks, allow a missing value explicitly: `string | null`.
- `a?.b` stops safely on `null`/`undefined`; `a ?? b` supplies a fallback value.
