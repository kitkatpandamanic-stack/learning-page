In Part 1 you designed `@pandadev/sdk` and built its foundation: `pandaApi` describes every endpoint, `Client<A>` derives every method's type from it, and `buildRequest` turns checked input into a request. But nothing talks to the network yet. In this part, the description becomes a **working client**. 🔌

We'll build `createClient(api, options)`, and with it everything a real SDK does between "the user called a method" and "the user got a `Result`":

- **one method per endpoint**, created at runtime from the description, with the types from Part 1,
- **typed errors**: every way a request can fail becomes one of the three `ApiError` kinds,
- **retries with backoff and jitter** for the requests that are safe to repeat, with an injected `sleep`, so tests never wait,
- **pagination as an async iterator**: `for await (const movie of paginate(panda.searchMovies))`,
- **hooks** to add headers and watch every attempt, for auth, logs and metrics,
- and **tests** with a fake `fetch`, plus a few against the practice API.

It brings together the error strategy from [Designing Types for Large Codebases](/learn/typescript/designing-types-for-large-codebases), `Result` from [Typed Fetch](/learn/typescript/typed-fetch), injected clocks and fakes from [Dependency Injection & Fakes](/learn/typescript/dependency-injection-and-fakes), and backoff with jitter from the JavaScript lesson [Real-time and Resilience](/learn/javascript/real-time-and-resilience).

## Types outside, one cast inside

`Client<A>` is a promise about an object: "for every key of the description, there's a method with these types". `createClient` has to **keep** that promise at runtime, and the simplest way is a loop over the description's keys. Here's the idea in miniature, with two endpoints and stand-in schemas:

<CodeExample output={`The Bamboo Heist
[ 'Learn fetch', 'Build the movie app', 'Eat some bamboo' ]
[ 'firstMovie', 'todos' ]`}>

```ts
type Schema<T> = { parse: (value: unknown) => T };
type Infer<S extends Schema<unknown>> = ReturnType<S["parse"]>;

// Stand-in schemas, just enough for this example
const titled: Schema<{ title: string }> = {
  parse(value) {
    if (
      typeof value === "object" && value !== null &&
      "title" in value && typeof value.title === "string"
    ) {
      return { title: value.title };
    }
    throw new Error("expected an object with a title");
  },
};
const titledList: Schema<{ title: string }[]> = {
  parse(value) {
    if (!Array.isArray(value)) throw new Error("expected an array");
    return value.map((item) => titled.parse(item));
  },
};

interface Endpoint {
  path: string;
  response: Schema<unknown>;
}
type ApiDescription = Record<string, Endpoint>;

// The promise: one method per endpoint
type Client<A extends ApiDescription> = {
  [K in keyof A]: () => Promise<Infer<A[K]["response"]>>;
};

function createClient<A extends ApiDescription>(
  api: A,
  baseUrl: string,
): Client<A> {
  // Keeping the promise: a loop over the description
  const client: Record<string, () => Promise<unknown>> = {};
  for (const name of Object.keys(api)) {
    const endpoint = api[name];
    client[name] = async () => {
      const res = await fetch(baseUrl + endpoint.path);
      return endpoint.response.parse(await res.json());
    };
  }
  return client as Client<A>; // the one cast
}

const panda = createClient(
  {
    firstMovie: { path: "/movies/1", response: titled },
    todos: { path: "/todos", response: titledList },
  },
  "https://api.pandadev.test",
);

const movie = await panda.firstMovie(); // { title: string }
const todos = await panda.todos(); // { title: string }[]
console.log(movie.title);
console.log(todos.map((todo) => todo.title));
console.log(Object.keys(panda));
```

</CodeExample>

TypeScript can't follow the loop. It sees a `Record<string, ...>` being filled, so without the cast it refuses:

```ts
return client;
// ❌ Error: Type 'Record<string, () => Promise<unknown>>' is not assignable to type 'Client<A>'.
```

That's the same deal you made in [Mapped Types](/learn/typescript/mapped-types) with `makeGetters`: when the type and the runtime code follow the same rule ("one method per key"), the type can't verify the code, so you write the rule twice, keep both halves next to each other, cast **once**, and let tests prove the code keeps its promise. One cast in one place inside the SDK buys precise types at every call site outside it.

Why not a `Proxy` from [Proxies, Reflect and Symbols](/learn/javascript/proxies-reflect-and-symbols), whose `get` trap could invent each method the moment it's called? Some SDKs do that, but here we know every method up front, and a plain object is friendlier: `Object.keys(panda)` lists the methods, `console.log(panda)` shows them, and a debugger doesn't step through proxy traps. Prefer boring runtime code when the types already do the clever part.

### Everything slow, random or outside is injected

The real `createClient` takes an options object. Everything the client needs from the outside world is in it, each with a sensible default, so normal users pass nothing and tests pass fakes:

```ts
interface ClientOptions {
  baseUrl?: string;
  fetch?: typeof fetch;
  retry?: Partial<RetryOptions>;
  hooks?: Hooks;
  sleep?: (ms: number) => Promise<void>;
  random?: () => number;
  now?: () => number;
}
```

`fetch` is the network, `sleep` is waiting, `random` is the jitter in backoff and `now` is the clock that times each attempt. That's the list from [Dependency Injection & Fakes](/learn/typescript/dependency-injection-and-fakes): inject what's slow, random or outside your program. `retry` is a `Partial` so users can change one setting and keep the defaults for the rest: `{ ...DEFAULT_RETRY, ...options.retry }`.

## Every failure has a kind

`attemptOnce` sends one request and reports how it went as a `Result`. It decides which `ApiError` each failure becomes, so it's worth reading closely:

<CodeExample output={`/movies/1   ok, a JSON body
/status/204 ok, no content
/movies/99  HTTP 404: Movie not found
/status/503 HTTP 503: Service Unavailable
/offline    no answer (Failed to fetch)`}>

```ts
type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E };

type ApiError =
  | { kind: "network"; message: string }
  | { kind: "http"; status: number; message: string }
  | { kind: "invalid-response"; message: string };

// Result<never, ...> fits a Result of ANY value type
function fail(error: ApiError): Result<never, ApiError> {
  return { ok: false, error };
}

function apiMessage(body: unknown): string | undefined {
  return typeof body === "object" && body !== null &&
    "error" in body && typeof body.error === "string"
    ? body.error
    : undefined;
}

async function attemptOnce(
  url: string,
): Promise<Result<unknown, ApiError>> {
  let res: Response;
  try {
    res = await fetch(url);
  } catch (error) {
    // fetch only rejects when there's no answer at all
    const message =
      error instanceof Error ? error.message : String(error);
    return fail({ kind: "network", message });
  }
  const body: unknown =
    res.status === 204 ? null : await res.json().catch(() => null);
  if (!res.ok) {
    const message = apiMessage(body) ?? `HTTP ${res.status}`;
    return fail({ kind: "http", status: res.status, message });
  }
  return { ok: true, value: body };
}

function describeError(error: ApiError): string {
  switch (error.kind) {
    case "network":
      return `no answer (${error.message})`;
    case "http":
      return `HTTP ${error.status}: ${error.message}`;
    case "invalid-response":
      return `odd answer: ${error.message}`;
  }
}

const API = "https://api.pandadev.test";
for (const path of [
  "/movies/1",
  "/status/204",
  "/movies/99",
  "/status/503",
  "/offline",
]) {
  const result = await attemptOnce(API + path);
  const text = result.ok
    ? `ok, ${result.value === null ? "no content" : "a JSON body"}`
    : describeError(result.error);
  console.log(path.padEnd(11), text);
}
```

</CodeExample>

| What happened | Becomes | Retry? |
| --- | --- | --- |
| `fetch` rejected: offline, DNS failure, connection reset | `{ kind: "network" }` | yes |
| 429 Too Many Requests, or any 5xx | `{ kind: "http", status }` | yes |
| Any other 4xx: 400, 401, 404… | `{ kind: "http", status }` | no: asking again gives the same answer |
| A 2xx whose body breaks the schema | `{ kind: "invalid-response" }` | no: the API changed, not the network |
| The caller's input breaks its schema | a thrown `ValidationError` | never sent at all |

A few details are easy to get wrong:

- **`fetch` only rejects when there's no answer at all.** A 404 or 503 is a perfectly good `Response`, so `res.ok` decides.
- **Error bodies may not be JSON.** A proxy in front of the API can answer with an HTML error page, so `res.json().catch(() => null)` keeps a broken body from turning into an exception, and the message falls back to `HTTP 503`.
- **A 204 has no body**, and calling `res.json()` on it would throw. It becomes `null`, which is exactly what `nothing()` from Part 1 expects.
- **`fail` returns `Result<never, ApiError>`**, a result whose success side can't exist, so it fits a `Result` of any value type, as in [Designing Types for Large Codebases](/learn/typescript/designing-types-for-large-codebases).

`describeError` handles every kind in a `switch` without a `default`, and that's on purpose. If 1.1 adds a `{ kind: "timeout" }`, every such function stops compiling until somebody decides what a timeout means there:

```ts
function describeError(error: ApiError): string {
// ❌ Error: Function lacks ending return statement and return type does not include 'undefined'.
```

That's great inside the SDK. For the SDK's **users**, though, it means a new error kind breaks their builds, which makes it a breaking change. We'll decide what to do about that in Part 3.

## Retries that don't make things worse

Retrying looks easy: if it failed, try again. Done carelessly, retries turn a small outage into a big one, or charge a customer twice. A senior retry policy answers three questions.

**Which requests?** Only those that are safe to send twice. `GET`, `PUT` and `DELETE` are **idempotent**: doing them twice leaves the server in the same state as doing them once. A `POST` isn't: if `POST /todos` timed out, the server may well have created the to-do before the connection dropped, and a retry creates a second one. A payments company I know learnt this the expensive way, when an automatic retry on a "create charge" call charged a few hundred customers twice during a network blip. APIs that need safe `POST` retries accept an **idempotency key** header (Stripe's `Idempotency-Key`), so the server can recognise a repeat; ours doesn't, so the SDK never retries `POST` or `PATCH`:

```ts
// Sending these twice does no harm, so they may be retried
const IDEMPOTENT = new Set<Method>(["GET", "PUT", "DELETE"]);
```

**Which failures?** Only the ones that might go away: network errors, 429 and 5xx, as in the table above.

**How long to wait?** Long enough for the server to recover, and not all at the same time:

<CodeExample output={`after attempt 1: wait 100-200 ms
after attempt 2: wait 200-400 ms
after attempt 3: wait 400-800 ms
after attempt 4: wait 800-1600 ms
after attempt 5: wait 1000-2000 ms
after attempt 6: wait 1000-2000 ms
without jitter: 200, 200, 200, 200, 200
with jitter:    100, 192, 129, 121, 173`}>

```ts
interface RetryOptions {
  attempts: number;
  baseDelayMs: number;
  maxDelayMs: number;
}

// Exponential, capped, with "equal jitter": half fixed, half random
function backoff(
  attempt: number,
  retry: RetryOptions,
  random: () => number,
): number {
  const exp = Math.min(
    retry.maxDelayMs,
    retry.baseDelayMs * 2 ** (attempt - 1),
  );
  return Math.round(exp / 2 + (exp / 2) * random());
}

const retry = { attempts: 7, baseDelayMs: 200, maxDelayMs: 2_000 };
for (let attempt = 1; attempt < retry.attempts; attempt++) {
  const low = backoff(attempt, retry, () => 0);
  const high = backoff(attempt, retry, () => 1);
  console.log(`after attempt ${attempt}: wait ${low}-${high} ms`);
}

// 5 clients fail at the same moment. When do they come back?
// (A predictable "random" so this example prints the same output)
let seed = 7;
function fakeRandom(): number {
  seed = (seed * 16807) % 2147483647;
  return seed / 2147483647;
}
const noJitter = [1, 2, 3, 4, 5].map(() => backoff(1, retry, () => 1));
const jitter = [1, 2, 3, 4, 5].map(() => backoff(1, retry, fakeRandom));
console.log("without jitter:", noJitter.join(", "));
console.log("with jitter:   ", jitter.join(", "));
```

</CodeExample>

- **Exponential backoff**: each wait is twice the last (100–200 ms, then 200–400, 400–800), so a struggling server gets more and more breathing room.
- **A cap** (`maxDelayMs`) stops the waits from growing for ever.
- **Jitter** spreads clients out. Look at the last two lines: when a server restarts, thousands of clients fail at the same moment. Without jitter they all come back at exactly 200 ms and knock it over again (the **thundering herd**). With jitter they arrive spread out. The JavaScript lesson used "full jitter" (anywhere from 0 to the maximum); we use **"equal jitter"**: half of the wait is fixed and half is random, so no client ever retries instantly.

The `random` function is injected for the same reason as `sleep`: so a test can say "random is always 1" and expect exactly `[200, 400]`. Real SDKs also respect a **`Retry-After`** header when the server sends one with a 429 or 503; ours is on the "take it further" list.

Put together, `send` (which you'll write in the exercise) is a loop: build the request, run the `onRequest` hook, then call `attemptOnce`. On success, parse the body with the endpoint's response schema. On failure, if there are attempts left **and** the method is idempotent **and** the error is retryable, `await sleep(backoff(...))` and go round again; otherwise return the error.

<Callout type="tip" title="Retries multiply">

If your app retries 3 times, the SDK under it retries 3 times, and the load balancer retries 3 times, one click can become 27 requests to a server that is already down. Retry in **one** layer (an SDK is a good one), keep the number of attempts small, and make it configurable, so apps that retry themselves can turn the SDK's retries off.

</Callout>

## Pagination as an async iterator

`searchMovies` returns one **page** at a time: `{ page, totalPages, total, results }`. Users nearly always want "all the movies" or "movies until I find one", and writing the page loop every time is boring and easy to get wrong (off by one, forgetting the last page). An **async generator** hides the pages: `async function*` can `await` between items and `yield` them one at a time, and `for await` consumes them. You may remember `allMovies` from the JavaScript lesson [The Event Loop in Depth](/learn/javascript/the-event-loop-in-depth); here it is with types:

<CodeExample output={`First film before 2017: Midnight in the Forest
Requests so far: 1
12 films, 5 requests in total`}>

```ts
interface Page<T> {
  page: number;
  totalPages: number;
  total: number;
  results: T[];
}
type Movie = { title: string; year: number };

let requests = 0;
async function moviePage(page: number): Promise<Page<Movie>> {
  requests++;
  const url = `https://api.pandadev.test/movies?limit=3&page=${page}`;
  const res = await fetch(url);
  return (await res.json()) as Page<Movie>; // the SDK validates instead
}

async function* allMovies(): AsyncGenerator<Movie, void, undefined> {
  for (let page = 1; ; page++) {
    const { results, totalPages } = await moviePage(page);
    yield* results; // hand out this page's movies, one by one
    if (page >= totalPages) return;
  }
}

for await (const movie of allMovies()) {
  if (movie.year < 2017) {
    console.log(`First film before 2017: ${movie.title}`);
    break; // the generator stops: no more pages are fetched
  }
}
console.log(`Requests so far: ${requests}`);

const titles: string[] = [];
for await (const movie of allMovies()) {
  titles.push(movie.title);
}
console.log(`${titles.length} films, ${requests} requests in total`);
```

</CodeExample>

Two properties make generators perfect for this:

- **They're lazy.** The first loop found its film on page 1 and `break`, which ends the generator, so pages 2 to 4 were never fetched. A function that returned a big array would have loaded all four pages first.
- **`yield*` hands out a whole array**, item by item, so the generator's body stays a tiny loop over pages.

The SDK's version works with **any** method whose response is a page. Its signature is where the types come in:

```ts
async function* paginate<Q extends { page?: number }, T>(
  method: (input: { query?: Q }) => Promise<Result<Page<T>, ApiError>>,
  query?: NoInfer<Q>,
): AsyncGenerator<T, void, undefined>
```

- **The `method` parameter is the constraint.** `T` is inferred from the method's result, so `paginate(panda.searchMovies)` yields `Movie`s. A method that doesn't return pages doesn't fit; the message ends with a clear line: `Property 'params' is missing in type '{ query?: { page?: number | undefined; } | undefined; }' but required in type '{ params: { id: Brand<number, "MovieId">; }; }'.`
- **`NoInfer<Q>`** (from [Variance & Inference](/learn/typescript/variance-and-inference)) makes `Q` come from the method only. Without it, a misspelt option in `query` would simply widen `Q`. With it, you get the error you want:

```ts
paginate(panda.searchMovies, { genr: "drama" });
// ❌ Error: Object literal may only specify known properties, but 'genr' does not exist in type '{ page?: number | undefined; search?: string | undefined; genre?: string | undefined; limit?: number | undefined; }'. Did you mean to write 'genre'?
```

- **`AsyncGenerator<T, void, undefined>`** spells out what `for await` gets (`T`), what the generator returns at the end (nothing) and what callers may pass into `next()` (nothing).

Inside, each page request becomes `method({ query: { ...query, page } as Q })`. That cast is the one TypeScript asks for, and it's worth understanding why: spreading a `Q` that might be `undefined` gives `{ page: number }`, and TypeScript can't prove that's a valid `Q` in general (`'{ page: number; }' is assignable to the constraint of type 'Q', but 'Q' could be instantiated with a different subtype of constraint '{ page?: number | undefined; }'.`). It's right: a `Q` with a **required** field would break. Paged endpoints have only optional query fields, and `buildRequest` would throw a `ValidationError` if one didn't, so the cast is safe here.

What about errors? A `for await` loop has no place for a `Result`: there's no value to hand back when page 3 fails. So `paginate` **throws**, an `ApiFailure` that carries the `ApiError`, so a `catch` still gets the typed error:

```ts
try {
  for await (const movie of paginate(panda.searchMovies)) {
    show(movie);
  }
} catch (error) {
  if (error instanceof ApiFailure) report(error.error); // ApiError
  else throw error;
}
```

`ApiFailure` declares its `error` field and assigns it in the constructor, instead of using a parameter property like `constructor(readonly error: ApiError)`. That keeps the SDK's source **erasable** (see [How the Compiler Works](/learn/typescript/how-the-compiler-works)), so it runs as it is under Node's type stripping and any transpile-only tool.

## Hooks for auth, logs and metrics

Every real SDK gets the same feature requests within a month: "how do I add my API key?", "how do I log requests?", "how do I measure latency?". Instead of an option for each, we offer two **hooks**:

```ts
interface Hooks {
  onRequest?: (request: SdkRequest) => SdkRequest;
  onResponse?: (info: ResponseInfo) => void;
}

interface ResponseInfo {
  request: SdkRequest;
  attempt: number;
  status: number | null; // null: the request never got an answer
  ms: number;
}
```

`onRequest` runs **once** per call, before the first attempt, and returns the request to send, so it can add headers without mutating anything the SDK holds. `onResponse` runs after **every** attempt, including failed ones, with the attempt number and the time it took (measured with the injected `now`). Here's how an app might use them:

```ts
const panda = createClient(pandaApi, {
  hooks: {
    onRequest: (request) => ({
      ...request,
      headers: { ...request.headers, Authorization: `Bearer ${key}` },
    }),
    onResponse: ({ request, status, attempt, ms }) => {
      metrics.timing("panda.request", ms, { status, attempt });
      if (status === null || status >= 500) {
        log.warn(`${request.method} ${request.url} -> ${status}`);
      }
    },
  },
});
```

Libraries such as ky and axios offer full middleware chains (any number of interceptors that can also change responses). Two hooks cover the requests we actually get, and adding a third later is a minor release, while removing one would be a major. Start small. And one rule for anything that logs requests: **never log the `Authorization` header**. Hooks see everything, including secrets.

## Testing the client

The client is the part of the SDK that talks to the outside world, so it's where injected fakes pay off. Two tiny helpers cover almost every test. `fakeFetch` answers with a list of prepared responses (or throws an `Error` from the list), using real `Response` objects, so it needs no casts, as you saw in [Dependency Injection & Fakes](/learn/typescript/dependency-injection-and-fakes):

```ts
function fakeSleep() {
  const waits: number[] = [];
  const sleep = async (ms: number) => {
    waits.push(ms);
  };
  return { sleep, waits };
}

// A fetch that gives these answers in order (an Error is thrown)
function fakeFetch(...answers: (Response | Error)[]) {
  return vi.fn<typeof fetch>(async () => {
    const next = answers.shift();
    if (next === undefined) throw new Error("No more answers");
    if (next instanceof Error) throw next;
    return next;
  });
}
```

With them, the backoff schedule is one line to check, and the test doesn't wait at all (`busy()` makes a 503 response, and `movieJson` is a movie as the API sends it):

```ts
it("retries a GET with backoff, then succeeds", async () => {
  const { sleep, waits } = fakeSleep();
  const fetch = fakeFetch(busy(), busy(), Response.json(movieJson));
  const panda = createClient(pandaApi, {
    fetch,
    sleep,
    random: () => 1,
  });
  const result = await panda.getMovie({
    params: { id: MovieId.parse(1) },
  });
  expect(result.ok).toBe(true);
  expect(fetch).toHaveBeenCalledTimes(3);
  expect(waits).toEqual([200, 400]);
});
```

Fakes test the rare cases you can't produce on demand (a dropped connection, a broken body). A few tests also run against the **practice API**, which stands in for the real service: they check that our description matches what the API really sends. One of them shows off a property of the design: `createClient` works with **any** description, so a test can describe the practice API's `/flaky` endpoint (it fails twice with 503, then works) without adding it to the SDK:

```ts
const testApi = defineApi({
  flaky: {
    method: "GET",
    path: "/flaky",
    response: object({ ok: boolean(), attempt: number() }),
  },
});
const client = createClient(testApi, { sleep });
expect(await client.flaky()).toEqual({
  ok: true,
  value: { ok: true, attempt: 3 },
});
```

<Callout type="note" title="Tests against a live API">

In a real repository, tests that call the live API are **contract tests**: slower, and they can fail because of the network rather than your code. Keep them few, run them on a schedule or before releases, and keep the fast fake-based tests for every push. PandaDev's practice API answers within 100 ms and the same way every time, so here they can run with the rest.

</Callout>

<Exercise
  title="Build it: The client"
  language="typescript"
  starter={`import { describe, it, expect, vi } from "vitest";

// ---------- schemas: Level 2's library, grown up ----------
class ValidationError extends Error {
  constructor(path: string, expected: string, got: unknown) {
    const where = path || "value";
    super(\`\${where}: expected \${expected}, got \${JSON.stringify(got)}\`);
    this.name = "ValidationError";
  }
}

type Schema<T> = {
  parse: (value: unknown, path?: string) => T;
  optional?: true;
};
type Infer<S extends Schema<unknown>> = ReturnType<S["parse"]>;
type Simplify<T> = { [K in keyof T]: T[K] } & {};

function primitive<T>(
  expected: string,
  test: (value: unknown) => value is T,
): Schema<T> {
  return {
    parse(value, path = "") {
      if (!test(value)) {
        throw new ValidationError(path, expected, value);
      }
      return value;
    },
  };
}

const string = () =>
  primitive("a string", (v): v is string => typeof v === "string");
const number = () =>
  primitive("a number", (v): v is number => typeof v === "number");
const boolean = () =>
  primitive("a boolean", (v): v is boolean => typeof v === "boolean");
// 204 No Content: the client reads it as null
const nothing = () =>
  primitive("no content", (v): v is null => v === null);

function array<T>(item: Schema<T>): Schema<T[]> {
  return {
    parse(value, path = "") {
      if (!Array.isArray(value)) {
        throw new ValidationError(path, "an array", value);
      }
      return value.map((v, i) => item.parse(v, \`\${path}[\${i}]\`));
    },
  };
}

function optional<T>(
  schema: Schema<T>,
): Schema<T | undefined> & { optional: true } {
  return {
    optional: true,
    parse: (value, path) =>
      value === undefined ? undefined : schema.parse(value, path),
  };
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return (
    typeof value === "object" && value !== null && !Array.isArray(value)
  );
}

type Shape = Record<string, Schema<unknown>>;
// The keys whose schema is optional(...)
type OptionalKeys<S extends Shape> = {
  [K in keyof S]: S[K] extends { optional: true } ? K : never;
}[keyof S];
type ObjectOf<S extends Shape> = Simplify<
  { [K in Exclude<keyof S, OptionalKeys<S>>]: Infer<S[K]> } & {
    [K in OptionalKeys<S>]?: Infer<S[K]>;
  }
>;

function object<S extends Shape>(shape: S): Schema<ObjectOf<S>> {
  return {
    parse(value, path = "") {
      if (!isRecord(value)) {
        throw new ValidationError(path, "an object", value);
      }
      const result: Record<string, unknown> = {};
      for (const key in shape) {
        const where = path ? \`\${path}.\${key}\` : key;
        const parsed = shape[key].parse(value[key], where);
        if (parsed !== undefined) result[key] = parsed;
      }
      // every key was checked, so this cast is safe
      return result as ObjectOf<S>;
    },
  };
}

type ParamsInput<E> = E extends { params: infer P extends Shape }
  ? { params: ObjectOf<P> }
  : {};
type QueryInput<E> = E extends { query: infer Q extends Schema<object> }
  ? {} extends Infer<Q>
    ? { query?: Infer<Q> } // every query field is optional
    : { query: Infer<Q> }
  : {};
type BodyInput<E> = E extends { body: infer B extends Schema<unknown> }
  ? { body: Infer<B> }
  : {};

type Input<E extends Endpoint> = Simplify<
  ParamsInput<E> & QueryInput<E> & BodyInput<E>
>;
type Output<E extends Endpoint> = Infer<E["response"]>;
// No required input: the argument may be left out
type InputArgs<E extends Endpoint> = {} extends Input<E>
  ? [input?: Input<E>]
  : [input: Input<E>];

type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E };

type ApiError =
  | { kind: "network"; message: string }
  | { kind: "http"; status: number; message: string }
  | { kind: "invalid-response"; message: string };

type Client<A extends ApiDescription> = {
  [K in keyof A]: (
    ...input: InputArgs<A[K]>

// ---------- from input to request ----------
interface SdkRequest {
  method: Method;
  url: string;
  headers: Record<string, string>;
  body?: string;
}

// Inside the SDK, input is loosely typed (and checked at runtime)
type RawInput = {
  params?: Record<string, unknown>;
  query?: unknown;
  body?: unknown;
};

function buildRequest(
  baseUrl: string,
  endpoint: Endpoint,
  input: RawInput = {},
): SdkRequest {
  const path = endpoint.path.replace(/:(\\w+)/g, (_, name: string) => {
    const schema = endpoint.params?.[name];
    if (!schema) throw new Error(\`No schema for :\${name}\`);
    const value = schema.parse(input.params?.[name], \`params.\${name}\`);
    return encodeURIComponent(String(value));
  });
  let url = baseUrl.replace(/\\/+$/, "") + path;
  if (endpoint.query) {
    const query = endpoint.query.parse(input.query ?? {}, "query");
    const search = new URLSearchParams();
    for (const [key, value] of Object.entries(query)) {
      search.set(key, String(value));
    }
    if (search.size > 0) url += \`?\${search}\`;
  }
  const headers: Record<string, string> = {
    Accept: "application/json",
  };
  const request: SdkRequest = { method: endpoint.method, url, headers };
  if (endpoint.body) {
    const body = endpoint.body.parse(input.body, "body");
    request.body = JSON.stringify(body);
    headers["Content-Type"] = "application/json";
  }
  return request;
}

function buildRequest(
  baseUrl: string,
  endpoint: Endpoint,
  input: RawInput = {},
): SdkRequest {
  const path = endpoint.path.replace(/:(\w+)/g, (_, name: string) => {
    const schema = endpoint.params?.[name];
    if (!schema) throw new Error(`No schema for :${name}`);
    const value = schema.parse(input.params?.[name], `params.${name}`);
    return encodeURIComponent(String(value));
  });
  let url = baseUrl.replace(/\/+$/, "") + path;
  if (endpoint.query) {
    const query = endpoint.query.parse(input.query ?? {}, "query");
    const search = new URLSearchParams();
    for (const [key, value] of Object.entries(query)) {
      search.set(key, String(value));
    }
    if (search.size > 0) url += `?${search}`;
  }
  const headers: Record<string, string> = {
    Accept: "application/json",
  };
  const request: SdkRequest = { method: endpoint.method, url, headers };
  if (endpoint.body) {
    const body = endpoint.body.parse(input.body, "body");
    request.body = JSON.stringify(body);
    headers["Content-Type"] = "application/json";
  }
  return request;
}

function isRetryable(error: ApiError): boolean {
  switch (error.kind) {
    case "network":
      return true;
    case "http":
      return error.status === 429 || error.status >= 500;
    case "invalid-response":
      return false;
  }

// Exponential, capped, with "equal jitter": half fixed, half random
function backoff(
  attempt: number,
  retry: RetryOptions,
  random: () => number,
): number {
  const exp = Math.min(
    retry.maxDelayMs,
    retry.baseDelayMs * 2 ** (attempt - 1),
  );
  return Math.round(exp / 2 + (exp / 2) * random());
}

        return { ok: true, value };
      } catch (error) {
        if (!(error instanceof ValidationError)) throw error;
        const { message } = error;
        return fail({ kind: "invalid-response", message });
      }
    }
  }

  // One method per endpoint: Client<A> is the promise, this loop
  // keeps it, and the cast says so in exactly one place
  const client: Record<string, (input?: RawInput) => unknown> = {};
  for (const name of Object.keys(api)) {
    const endpoint = api[name];
    client[name] = (input = {}) => send(endpoint, input);
  }
  return client as Client<A>;
}

// ---------- pagination ----------
// For APIs without a Result channel, like async iteration
class ApiFailure extends Error {
  readonly error: ApiError;
  constructor(error: ApiError) {
    super(error.message);
    this.name = "ApiFailure";
    this.error = error;
  }
}

// Every item of every page, fetching one page at a time
async function* paginate<Q extends { page?: number }, T>(
  method: (input: { query?: Q }) => Promise<Result<Page<T>, ApiError>>,
  query?: NoInfer<Q>,
): AsyncGenerator<T, void, undefined> {
  for (let page = query?.page ?? 1; ; page++) {
    const result = await method({ query: { ...query, page } as Q });
    if (!result.ok) throw new ApiFailure(result.error);
    yield* result.value.results;
    if (page >= result.value.totalPages) return;
  }
}

## What you built

- **`createClient(api, options)`**: one method per endpoint, built by a loop and typed by `Client<A>` with a single cast, and every dependency (fetch, sleep, random, clock) injected with a default.
- **Typed errors**: `attemptOnce` turns every outcome into a `Result`, with `network`, `http` and `invalid-response` errors, while bad input still throws a `ValidationError` before anything is sent.
- **Retries that don't make things worse**: only idempotent methods, only retryable errors, exponential backoff with a cap and equal jitter.
- **`paginate`**: an async generator that walks pages lazily, accepts only page-returning methods, and throws an `ApiFailure` when a page fails.
- **Hooks** for headers, logs and metrics, and a fast **test suite** with fakes, plus a few tests against the practice API.

The SDK works. In **Part 3** we make it something other people can depend on: a polished public API, type tests for all of it, and a package that's ready for npm. 📦
