`@pandadev/sdk` works: one description, typed methods, checked answers, typed errors, retries, pagination and hooks, all tested. But "works in my repository" is not the same as "ready for other people". Once a package is on npm, its public API is a promise to strangers: every exported name, every type and even every default is something their code depends on, and you can't take it back without a major version. 📦

In this last part we get the SDK ready for that: a **public API** that makes the common case one line, **overloads** where the return type depends on the input, **JSDoc** that shows up in users' editors, **type tests** for the whole surface, and then the package itself: `exports`, declaration files, versioning, a changelog, CI and `npm publish`. It's where [API Design & Migrations](/learn/typescript/api-design-and-migrations), [Building & Publishing Packages](/learn/typescript/building-and-publishing-packages) and [Testing Types](/learn/typescript/testing-types) meet a real project.

## The public surface

Start with the question every library author must answer explicitly: **what can users import?** Everything you export is supported for the life of the major version, so export what users need and nothing else. The package's one entry point, `src/index.ts`, lists it:

```ts title="src/index.ts"
export { ValidationError } from "./schema.js";
export type { Result, ApiError } from "./describe.js";
export { MovieId, TodoId, UserId, PostId } from "./api.js";
export type { Movie, Todo, User, Post, Page } from "./api.js";
export type { SdkRequest } from "./request.js";
export {
  createPandaClient,
  paginate,
  unwrap,
  ApiFailure,
  SDK_VERSION,
} from "./client.js";
export type {
  PandaClient,
  ClientOptions,
  RetryOptions,
  Hooks,
  ResponseInfo,
} from "./client.js";
```

- **Every type that appears in a public signature is exported**, so users can write `function show(error: ApiError)` or keep their settings in a `const options: ClientOptions`, instead of digging types out with `Parameters<typeof createPandaClient>[0]`.
- **Start small.** Adding an export later is a minor release; removing one is a major. `createClient` and `defineApi` are tempting to export (users could describe their own APIs!), but then the schema builders become public too, and that's a second product to document and support. In 1.0 they stay internal, along with `buildRequest`, `RawInput`, `isRetryable` and `backoff`. The tests import them from the source files, not from the package.
- **A barrel is right here.** [Designing Types for Large Codebases](/learn/typescript/designing-types-for-large-codebases) warned about `index.ts` barrels inside an app. A package's entry point is the one place a barrel belongs: it **is** the public API, and `exports` in `package.json` makes sure nothing else can be imported.
- **Relative imports end in `.js`**, the extension of the **output** file, because the library builds with `"module": "nodenext"`, as in [Building & Publishing Packages](/learn/typescript/building-and-publishing-packages).

### The common case in one line

Users want a client for the PandaDev API, not a client for "any description", so the public entry point is `createPandaClient(options?)`: one line with no arguments, and every option has a default. It simply calls the internal `createClient(pandaApi, options)`. If `createClient` becomes public one day, it'll stay a **separate** function rather than an overload, `createClient(options?)` **or** `createClient(api, options?)`: one function would have to guess at runtime whether its first argument is a description or an options object, both plain objects. As [API Design & Migrations](/learn/typescript/api-design-and-migrations) put it, two clear functions beat one clever one.

`createPandaClient` returns a **named** type, `PandaClient`, which is just `Client<PandaApi>`. Hovers and error messages then say `PandaClient` instead of spelling out the mapped type, and users can type their own variables with it.

### Options that can grow

Options objects are the most stable part of an API: adding an optional property never breaks a caller. Part 3 adds one more choice to `retry`: apps that do their own retrying can switch the SDK's off with `retry: false`. A **union** in the options type says exactly that:

```ts
interface ClientOptions {
  /**
   * Retries for GET, PUT and DELETE. Default: 3 attempts,
   * 200 ms doubling up to 2,000 ms. `false` turns them off.
   */
  retry?: Partial<RetryOptions> | false;
  // ...the other options as before
}
```

Inside `createClient`, `false` means a single attempt, and anything else is still merged over `DEFAULT_RETRY`, so users only mention what they want to change:

<CodeExample output={`{ attempts: 3, baseDelayMs: 200, maxDelayMs: 2000 }
{ attempts: 5, baseDelayMs: 200, maxDelayMs: 2000 }
{ attempts: 1, baseDelayMs: 200, maxDelayMs: 2000 }`}>

```ts
interface RetryOptions {
  attempts: number; // in total, including the first
  baseDelayMs: number;
  maxDelayMs: number;
}

const DEFAULT_RETRY: RetryOptions = {
  attempts: 3,
  baseDelayMs: 200,
  maxDelayMs: 2_000,
};

// Partial: change one setting, keep the rest. false: no retries
function retrySettings(
  retry?: Partial<RetryOptions> | false,
): RetryOptions {
  if (retry === false) return { ...DEFAULT_RETRY, attempts: 1 };
  return { ...DEFAULT_RETRY, ...retry };
}

console.log(retrySettings());
console.log(retrySettings({ attempts: 5 }));
console.log(retrySettings(false));
```

</CodeExample>

`true` isn't allowed, because "retry, but how?" has no good answer:

```ts
createPandaClient({ retry: true });
// ❌ Error: Type 'true' is not assignable to type 'false | Partial<RetryOptions> | undefined'.
```

### Saying who's calling

Every request now carries an `X-Panda-SDK: 1.0.0` header (from `SDK_VERSION`), added before the `onRequest` hook runs, so the hook can see it. That one header is surprisingly valuable for the API's team: they can see which SDK versions are still in use, and when they want to remove an old endpoint, they know exactly whom it would break. Stripe's and AWS's SDKs send similar headers for the same reason. Browsers don't let `fetch` change `User-Agent`, which is why it's a custom header; and because it's custom, a browser asks the API's CORS rules first (the preflight from [CSRF, CORS and Secrets](/learn/javascript/csrf-cors-and-secrets)), so the API must list `X-Panda-SDK` in `Access-Control-Allow-Headers`. That's the kind of detail an SDK team agrees with the API team **before** 1.0.

## Overloads where the return type depends on the input

Results are the right default, but in scripts, tests and quick experiments, checking `ok` on every call gets tedious. `unwrap` gives the value of a successful `Result` or throws an `ApiFailure`. It accepts a result **or** a promise of one, so `await unwrap(panda.listTodos())` reads naturally. Its return type depends on which one it got: a `T` for a result, a `Promise<T>` for a promise. A few distinct cases with different return types: that's what overloads are for ([Branded Types & Type-Safe APIs](/learn/typescript/branded-types-and-type-safe-apis)):

<CodeExample output={`THE BAMBOO HEIST
true The Bamboo Heist
ApiFailure: 404 Movie not found`}>

```ts
type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E };

type ApiError =
  | { kind: "network"; message: string }
  | { kind: "http"; status: number; message: string }
  | { kind: "invalid-response"; message: string };

class ApiFailure extends Error {
  readonly error: ApiError;
  constructor(error: ApiError) {
    super(error.message);
    this.name = "ApiFailure";
    this.error = error;
  }
}

/** The value of a successful result; throws an ApiFailure if not. */
function unwrap<T>(result: Result<T, ApiError>): T;
/** Waits for the result first: `await unwrap(panda.listTodos())` */
function unwrap<T>(result: Promise<Result<T, ApiError>>): Promise<T>;
function unwrap<T>(
  result: Result<T, ApiError> | Promise<Result<T, ApiError>>,
): T | Promise<T> {
  if (result instanceof Promise) {
    return result.then((settled) => unwrap(settled));
  }
  if (!result.ok) throw new ApiFailure(result.error);
  return result.value;
}

const found: Result<string, ApiError> = {
  ok: true,
  value: "The Bamboo Heist",
};
const missing: Result<string, ApiError> = {
  ok: false,
  error: { kind: "http", status: 404, message: "Movie not found" },
};

const title = unwrap(found); // string
const later = unwrap(Promise.resolve(found)); // Promise<string>
console.log(title.toUpperCase());
console.log(later instanceof Promise, await later);

try {
  unwrap(missing);
} catch (error) {
  if (error instanceof ApiFailure && error.error.kind === "http") {
    const { status } = error.error;
    console.log(`${error.name}: ${status} ${error.message}`);
  }
}

type Equal<A, B> =
  (<X>() => X extends A ? 1 : 2) extends
  (<X>() => X extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;

type _tests = [
  Expect<Equal<typeof title, string>>,
  Expect<Equal<typeof later, Promise<string>>>,
];
```

</CodeExample>

Callers only see the two overload signatures, each with its own JSDoc, and the type tests at the bottom pin both return types. Anything else is rejected:

```ts
unwrap({ title: "Nap" });
// ❌ Error: No overload matches this call.
```

The known weakness of overloads applies too: a value that's `Result<T, ApiError> | Promise<Result<T, ApiError>>` matches **neither** signature. Nobody holds such a value in practice, so we don't add a third overload for it. If users ever do, adding one later is a minor release.

<Callout type="tip" title="Make the safe way the default way">

`unwrap` exists for convenience, and convenience can undo a design: if the README's first example used `unwrap` everywhere, every app built from it would throw on the first 404. So the README shows `Result` first, and `unwrap` under "scripts and tests". What you put in the first example is what most of your users will copy.

</Callout>

## Documentation that travels: JSDoc

For an SDK, JSDoc comments are not decoration: they're copied into the declaration files and shown in users' editors on every hover and autocomplete, which is where people actually read documentation. Document every export, every option with its default, and give the main entry point an example:

```ts
/**
 * A client for the PandaDev practice API.
 *
 * @example
 * const panda = createPandaClient();
 * const id = MovieId.parse(1);
 * const movie = await panda.getMovie({ params: { id } });
 * if (movie.ok) console.log(movie.value.title);
 */
function createPandaClient(options: ClientOptions = {}): PandaClient {
  return createClient(pandaApi, options);
}
```

The client's methods are created by a mapped type, so where do **their** docs come from? From the description itself. `Client<A>` maps over `keyof A`, and homomorphic mapped types keep each property's declaration, JSDoc included. So a comment on a description entry shows up when users hover `panda.getMovie`. The same goes for `@deprecated`, which gives the SDK a smooth path for renaming a method in a minor release, exactly the three steps from [API Design & Migrations](/learn/typescript/api-design-and-migrations):

```ts
const pandaApi = defineApi({
  /** One movie by its id. A missing movie is an http 404 error. */
  getMovie: { /* ... */ },
  /** Movies, a page at a time. Use paginate() to get them all. */
  listMovies: { /* ... */ },
  /** @deprecated Renamed to listMovies. Removed in 2.0. */
  searchMovies: { /* ... */ },
});

panda.searchMovies(); // editors strike it through and show the note
```

typescript-eslint's `no-deprecated` rule then turns those strike-throughs into lint errors in users' projects, when **they** decide to finish the move.

## Type tests for the whole surface

In Part 1 the type tests checked the derived types. Before a release, they get a bigger job: pinning down **everything a user can see**, so that no refactor changes the public API by accident. Tests like these sit in the repository next to the runtime tests:

```ts
// The public surface, pinned: a change here is a new version
type _surface = [
  Expect<Equal<Parameters<typeof createPandaClient>,
    [options?: ClientOptions]>>,
  Expect<Equal<ReturnType<typeof createPandaClient>, PandaClient>>,
  Expect<Equal<ClientOptions["retry"],
    Partial<RetryOptions> | false | undefined>>,
  Expect<Equal<Awaited<ReturnType<PandaClient["getMovie"]>>,
    Result<Movie, ApiError>>>,
];
```

Imagine a teammate "tidies up" `createPandaClient(options: ClientOptions = {})` into `createPandaClient(options: ClientOptions)`. The implementation still works, and every test that passes options still passes. But every user who wrote `createPandaClient()` now has a broken build, and the first line of the type tests says so: `Type 'false' does not satisfy the constraint 'true'.` The fix isn't always to undo the change; sometimes the change is right. The test's job is to make it a **decision** (and a major version) rather than an accident.

In a real repository, type tests live in their own files, for example `test/types.test-d.ts`, and are checked, not run: `tsc --noEmit` over the tests folder, or Vitest's `vitest --typecheck`, which also understands `expectTypeOf(...)`. Teams with many users add **API Extractor**, which writes the whole public surface into a committed report file, so any change to it shows up in code review.

## What users' TypeScript sees

When we build, `tsc` writes a `.d.ts` next to each `.js` file, and users' compilers read **only** those. Here's part of the real declaration output for our SDK:

```ts title="dist/index.d.ts (parts of it)"
declare const pandaApi: {
    readonly getMovie: {
        readonly method: "GET";
        readonly path: "/movies/:id";
        readonly params: {
            readonly id: Schema<Brand<number, "MovieId">>;
        };
        // ...over 100 more lines: every endpoint, spelt out
// ...
/**
 * Every item of every page, fetching one page at a time:
 * `for await (const movie of paginate(panda.searchMovies))`.
 * Throws an ApiFailure if a page can't be loaded.
 */
declare function paginate<Q extends {
    page?: number;
}, T>(method: (input: {
    query?: Q;
}) => Promise<Result<Page<T>, ApiError>>, query?: NoInfer<Q>): AsyncGenerator<T, void, undefined>;
declare const SDK_VERSION = "1.0.0";
/** The client for the PandaDev practice API. */
type PandaClient = Client<PandaApi>;
```

Reading your own `.d.ts` before a release is a habit worth having, because it shows three things the source hides:

- **The JSDoc made it.** Good.
- **`NoInfer` is in there.** It only exists since TypeScript 5.4, so a user on 5.3 gets an error inside our package, or, with `skipLibCheck`, silently looser types. The TypeScript versions you support are part of your API: write the minimum in the README, test it in CI, and treat raising it as a breaking change, as the table in [API Design & Migrations](/learn/typescript/api-design-and-migrations) said.
- **Inferred types are spelt out in full.** `pandaApi` isn't even exported, but `PandaClient` needs its type, so all of it is in there, over 100 lines, and every user's compiler reads them. For 8 endpoints that's fine; for 300 it would slow down every project that installs the SDK, the cost from [Faster Type Checking](/learn/typescript/faster-type-checking). Big API SDKs generate an explicit, named type per endpoint instead.

Also notice `fetch?: typeof fetch` in `ClientOptions`: our declarations need a `fetch` type in the user's project. Browser projects have it from the DOM library and Node projects from `@types/node`, so that's fine, but it's exactly the kind of thing "Are the types wrong?" checks for.


```json title="package.json"
{

  "version": "1.0.0",
  "description": "A type-safe client for the PandaDev practice API",
  "license": "MIT",
  "type": "module",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    },
    "./package.json": "./package.json"
  },
  "files": ["dist", "src"],
  "sideEffects": false,
  "engines": { "node": ">=20" },
  "scripts": {
    "build": "tsc -p tsconfig.build.json",
    "typecheck": "tsc --noEmit",
    "test": "vitest run",
    "check:package": "publint && attw --pack . --profile esm-only",
    "prepublishOnly": "npm run build"
  }

```

- **ESM only**, with `"types"` first in the conditions, as [Building & Publishing Packages](/learn/typescript/building-and-publishing-packages) taught: no dual-package hazard for `instanceof ApiFailure` to fall into.
- **No `dependencies` at all.** Every dependency of an SDK becomes a dependency of every app that installs it, with its own updates and security advisories. Zero is a feature you can put in the README.
- **`engines`** says Node 20, and it's not arbitrary: `buildRequest` uses `URLSearchParams.size`, which older versions don't have. Runtime APIs you use are part of your compatibility promise too.
- **`src` ships with `dist`**, so declaration maps let "Go to Definition" open our real source.

## Versions, changelog and CI

Semantic versioning for an SDK means deciding, for each kind of change, which number goes up. Most of the rules come from the semver-for-types table you already know; a few are specific to SDKs:

| Change to `@pandadev/sdk` | Release |
| --- | --- |
| Add an endpoint to `pandaApi` | minor |
| Add an optional option, such as `timeoutMs` | minor |
| The API adds a field, and the schema learns it | minor: output types only grow (but say so: test fixtures typed as `Movie` need the field) |
| Make a response field optional | **major**: `movie.rating.toFixed()` stops compiling |
| Make a query field required | **major** |
| Rename a method | minor with a `@deprecated` alias, **major** to remove it |
| Change a default, such as 3 retries to 4 | minor, with a line in the changelog |
| Need a newer TypeScript or Node | **major** |
| Add a kind to `ApiError` | **major**, by our policy (below) |

The last line needs a decision. Adding `{ kind: "timeout" }` is "just a new feature" for us, but users who handle errors the way this course taught them, with an exhaustive `switch` ending in `assertNever`, get a compile error:

```ts
    default:
      return assertNever(error);
      // ❌ Error: Argument of type '{ kind: "timeout"; ms: number; }' is not assignable to parameter of type 'never'.
```

Some libraries say "new kinds may arrive in minor versions; always handle unknown ones". We'd rather reward users for writing exhaustive code, so our README promises: **new error kinds only in major versions.** Either policy is fine; not having one is not.

**Changesets** keeps the changelog honest. Every pull request that changes behaviour adds a small file that says which number goes up and why:

```md title=".changeset/brave-pandas-sing.md"
---
"@pandadev/sdk": minor
---

Add `getRecipe` and `searchRecipes`.
```

On release, `changeset version` adds up the files, bumps `package.json` and writes `CHANGELOG.md`. CI runs everything on every push, on every Node version we support, and publishes from `main` with **provenance**, a signed record of which repository and workflow built the package:

```yaml title=".github/workflows/ci.yml"
name: CI
on:
  push:
    branches: [main]
  pull_request:

jobs:
  check:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node: [20, 22, 24]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
          cache: npm
      - run: npm ci
      - run: npm run typecheck # source, tests AND type tests
      - run: npx -p typescript@5.4 tsc --noEmit # oldest TS we support
      - run: npm test
      - run: npm run build
      - run: npm run check:package # publint + attw

  release:
    needs: check
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      id-token: write # lets npm sign the provenance
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          registry-url: https://registry.npmjs.org
      - run: npm ci
      - uses: changesets/action@v1
        with:
          publish: npx changeset publish --provenance
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
```

The `release` job doesn't publish on every push. While there are changesets waiting, the Changesets action keeps a "Version Packages" pull request up to date; merging **that** pull request is the decision to release.

## Publishing to npm

The very first release is worth doing by hand, slowly, looking at everything:

```bash
npm run build
npm pack --dry-run        # exactly which files will be published
npx publint               # package.json and exports mistakes
npx @arethetypeswrong/cli --pack . --profile esm-only
npm login
npm publish --access public   # scoped packages are private by default
```

After that, releases come from CI. And remember the rule that never changes: a published version can't be changed or reused. A mistake in 1.0.0 is fixed in 1.0.1.

## The README

The README is the SDK's front page, and it's mostly the design doc's call-site sketch from Part 1, now true:

```md title="README.md"
# @pandadev/sdk

A type-safe client for the PandaDev practice API: typed methods,
checked responses, typed errors, retries and pagination. No
dependencies.

## Install

    npm install @pandadev/sdk

## Quick start

    import { createPandaClient, MovieId } from "@pandadev/sdk";

    const panda = createPandaClient();
    const id = MovieId.parse(1);
    const movie = await panda.getMovie({ params: { id } });
    if (movie.ok) console.log(movie.value.title);
    else console.error(movie.error.kind, movie.error.message);

## Errors

Every method returns a `Result`. Failures are values with a
`kind`: `"network"`, `"http"` (with `status`) or
`"invalid-response"`. Bad input throws a `ValidationError`.
In scripts and tests, `await unwrap(...)` returns the value
or throws an `ApiFailure`.

## Retries, pages and hooks

GET, PUT and DELETE are retried on network errors, 429 and
5xx (3 attempts, exponential backoff with jitter; `retry:
false` turns it off). `paginate(panda.searchMovies)` walks
every page. `hooks.onRequest` and `hooks.onResponse` add
headers and see every attempt.

## Compatibility

Node 20+, modern browsers, TypeScript 5.4+. ESM only.
Semantic versioning, types included: new error kinds only
in major versions.
```

<Exercise
  title="Build it: The finished SDK"
  language="typescript"
  starter={`import { describe, it, expect, vi } from "vitest";

// ---------- schemas: Level 2's library, grown up ----------
class ValidationError extends Error {
  constructor(path: string, expected: string, got: unknown) {
    const where = path || "value";
    super(\`\${where}: expected \${expected}, got \${JSON.stringify(got)}\`);
    this.name = "ValidationError";
  }
}

type Schema<T> = {
  parse: (value: unknown, path?: string) => T;
  optional?: true;
};
type Infer<S extends Schema<unknown>> = ReturnType<S["parse"]>;
type Simplify<T> = { [K in keyof T]: T[K] } & {};

function primitive<T>(
  expected: string,
  test: (value: unknown) => value is T,
): Schema<T> {
  return {
    parse(value, path = "") {
      if (!test(value)) {
        throw new ValidationError(path, expected, value);
      }
      return value;
    },
  };
}

const string = () =>
  primitive("a string", (v): v is string => typeof v === "string");
const number = () =>
  primitive("a number", (v): v is number => typeof v === "number");
const boolean = () =>
  primitive("a boolean", (v): v is boolean => typeof v === "boolean");
// 204 No Content: the client reads it as null
const nothing = () =>
  primitive("no content", (v): v is null => v === null);

function array<T>(item: Schema<T>): Schema<T[]> {
  return {
    parse(value, path = "") {
      if (!Array.isArray(value)) {
        throw new ValidationError(path, "an array", value);
      }
      return value.map((v, i) => item.parse(v, \`\${path}[\${i}]\`));
    },
  };
}

function optional<T>(
  schema: Schema<T>,
): Schema<T | undefined> & { optional: true } {
  return {
    optional: true,
    parse: (value, path) =>
      value === undefined ? undefined : schema.parse(value, path),
  };
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return (
    typeof value === "object" && value !== null && !Array.isArray(value)
  );
}

type Shape = Record<string, Schema<unknown>>;
// The keys whose schema is optional(...)
type OptionalKeys<S extends Shape> = {
  [K in keyof S]: S[K] extends { optional: true } ? K : never;
}[keyof S];
type ObjectOf<S extends Shape> = Simplify<
  { [K in Exclude<keyof S, OptionalKeys<S>>]: Infer<S[K]> } & {
    [K in OptionalKeys<S>]?: Infer<S[K]>;
  }
>;

function object<S extends Shape>(shape: S): Schema<ObjectOf<S>> {
  return {
    parse(value, path = "") {
      if (!isRecord(value)) {
        throw new ValidationError(path, "an object", value);
      }
      const result: Record<string, unknown> = {};
      for (const key in shape) {
        const where = path ? \`\${path}.\${key}\` : key;
        const parsed = shape[key].parse(value[key], where);
        if (parsed !== undefined) result[key] = parsed;
      }
      // every key was checked, so this cast is safe
      return result as ObjectOf<S>;
    },
  };
}

type ParamsInput<E> = E extends { params: infer P extends Shape }
  ? { params: ObjectOf<P> }
  : {};

  ? {} extends Infer<Q>
    ? { query?: Infer<Q> } // every query field is optional
    : { query: Infer<Q> }
  : {};
type BodyInput<E> = E extends { body: infer B extends Schema<unknown> }
  ? { body: Infer<B> }
  : {};

type InputArgs<E extends Endpoint> = {} extends Input<E>
  ? [input?: Input<E>]
  : [input: Input<E>];

type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E };

type ApiError =
  | { kind: "network"; message: string }
  | { kind: "http"; status: number; message: string }
  | { kind: "invalid-response"; message: string };

  [K in keyof A]: (

// ---------- from input to request ----------
interface SdkRequest {
  method: Method;
  url: string;
  headers: Record<string, string>;
  body?: string;
}

// Inside the SDK, input is loosely typed (and checked at runtime)
type RawInput = {
  params?: Record<string, unknown>;
  query?: unknown;
  body?: unknown;
};

function buildRequest(
  baseUrl: string,
  endpoint: Endpoint,
  input: RawInput = {},
): SdkRequest {
  const path = endpoint.path.replace(/:(\\w+)/g, (_, name: string) => {
    const schema = endpoint.params?.[name];
    if (!schema) throw new Error(\`No schema for :\${name}\`);
    const value = schema.parse(input.params?.[name], \`params.\${name}\`);
    return encodeURIComponent(String(value));
  });
  let url = baseUrl.replace(/\\/+$/, "") + path;
  if (endpoint.query) {
    const query = endpoint.query.parse(input.query ?? {}, "query");
    const search = new URLSearchParams();
    for (const [key, value] of Object.entries(query)) {
      search.set(key, String(value));
    }
    if (search.size > 0) url += \`?\${search}\`;
  }
  const headers: Record<string, string> = {
    Accept: "application/json",
  };
  const request: SdkRequest = { method: endpoint.method, url, headers };
  if (endpoint.body) {
    const body = endpoint.body.parse(input.body, "body");
    request.body = JSON.stringify(body);
    headers["Content-Type"] = "application/json";
  }
  return request;
}

// ---------- the client: options ----------
interface RetryOptions {
  attempts: number; // in total, including the first
  baseDelayMs: number;
  maxDelayMs: number;
}

interface ResponseInfo {
  request: SdkRequest;
  attempt: number;
  status: number | null; // null: the request never got an answer
  ms: number;
}

interface Hooks {
  /** Change a request before it's sent, e.g. to add a header. */
  onRequest?: (request: SdkRequest) => SdkRequest;
  /** See every attempt, e.g. for logs and metrics. */
  onResponse?: (info: ResponseInfo) => void;
}

interface ClientOptions {
  /** Default: "https://api.pandadev.test" */
  baseUrl?: string;
  /** Default: the global fetch. Pass your own for tests. */
  fetch?: typeof fetch;
  /**
   * Retries for GET, PUT and DELETE. Default: 3 attempts,
   * 200 ms doubling up to 2,000 ms. \`false\` turns them off.
   */
  // TODO: also accept false
  retry?: Partial<RetryOptions>;
  hooks?: Hooks;
  /** How to wait between attempts. Default: setTimeout. */
  sleep?: (ms: number) => Promise<void>;
  /** For the jitter in backoff. Default: Math.random. */
  random?: () => number;
  /** Times each attempt for onResponse. Default: Date.now. */
  now?: () => number;
}

const DEFAULT_RETRY: RetryOptions = {
  attempts: 3,
  baseDelayMs: 200,
  maxDelayMs: 2_000,
};

// Sending these twice does no harm, so they may be retried
const IDEMPOTENT = new Set<Method>(["GET", "PUT", "DELETE"]);

function fail(error: ApiError): Result<never, ApiError> {
  return { ok: false, error };
}

function apiMessage(body: unknown): string | undefined {
  return isRecord(body) && typeof body.error === "string"
    ? body.error
    : undefined;
}

// ---------- retries ----------
function isRetryable(error: ApiError): boolean {
  switch (error.kind) {
    case "network":
      return true;
    case "http":
      return error.status === 429 || error.status >= 500;
    case "invalid-response":
      return false;
  }
}

// Exponential, capped, with "equal jitter": half fixed, half random
function backoff(
  attempt: number,
  retry: RetryOptions,
  random: () => number,
): number {
  const exp = Math.min(
    retry.maxDelayMs,
    retry.baseDelayMs * 2 ** (attempt - 1),
  );
  return Math.round(exp / 2 + (exp / 2) * random());
}

// ---------- the client ----------
/**
 * A typed client for any API description: one method per
 * endpoint. Most people want createPandaClient() instead.
 */
function createClient<A extends ApiDescription>(
  api: A,
  options: ClientOptions = {},
): Client<A> {
  const {
    baseUrl = "https://api.pandadev.test",
    fetch: fetchFn = fetch,
    hooks = {},
    sleep = (ms: number) =>
      new Promise<void>((resolve) => setTimeout(resolve, ms)),
    random = Math.random,
    now = Date.now,
  } = options;
  // TODO: retry: false means one attempt only
  const retry: RetryOptions = { ...DEFAULT_RETRY, ...options.retry };

  // One attempt: fetch, read the body, and say how it went
  async function attemptOnce(
    request: SdkRequest,
    attempt: number,
  ): Promise<Result<unknown, ApiError>> {
    const started = now();
    const report = (status: number | null) => {
      const ms = now() - started;
      hooks.onResponse?.({ request, attempt, status, ms });
    };
    let res: Response;
    try {
      res = await fetchFn(request.url, {
        method: request.method,
        headers: request.headers,
        body: request.body,
      });
    } catch (error) {
      report(null);
      const message =
        error instanceof Error ? error.message : String(error);
      return fail({ kind: "network", message });
    }
    const body: unknown =
      res.status === 204 ? null : await res.json().catch(() => null);
    report(res.status);
    if (!res.ok) {
      const message = apiMessage(body) ?? \`HTTP \${res.status}\`;
      return fail({ kind: "http", status: res.status, message });
    }
    return { ok: true, value: body };
  }

  // Build the request, try it (again), check what comes back
  async function send(
    endpoint: Endpoint,
    input: RawInput,
  ): Promise<Result<unknown, ApiError>> {
    let request = buildRequest(baseUrl, endpoint, input);
    // TODO: add the X-Panda-SDK header (before onRequest runs)
    if (hooks.onRequest) request = hooks.onRequest(request);
    const attempts = IDEMPOTENT.has(endpoint.method)
      ? retry.attempts
      : 1;
    for (let attempt = 1; ; attempt++) {
      const result = await attemptOnce(request, attempt);
      if (!result.ok) {
        if (attempt < attempts && isRetryable(result.error)) {
          await sleep(backoff(attempt, retry, random));
          continue;
        }
        return result;
      }
      try {
        const value = endpoint.response.parse(result.value);
        return { ok: true, value };
      } catch (error) {
        if (!(error instanceof ValidationError)) throw error;
        const { message } = error;
        return fail({ kind: "invalid-response", message });
      }
    }
  }

  // One method per endpoint: Client<A> is the promise, this loop
  // keeps it, and the cast says so in exactly one place
  const client: Record<string, (input?: RawInput) => unknown> = {};
  for (const name of Object.keys(api)) {
    const endpoint = api[name];
    client[name] = (input = {}) => send(endpoint, input);
  }
  return client as Client<A>;
}

// For APIs without a Result channel, like async iteration
class ApiFailure extends Error {
  readonly error: ApiError;
  constructor(error: ApiError) {
    super(error.message);
    this.name = "ApiFailure";
    this.error = error;
  }
}

/**
 * Every item of every page, fetching one page at a time:
 * \`for await (const movie of paginate(panda.searchMovies))\`.
 * Throws an ApiFailure if a page can't be loaded.
 */
async function* paginate<Q extends { page?: number }, T>(
  method: (input: { query?: Q }) => Promise<Result<Page<T>, ApiError>>,
  query?: NoInfer<Q>,
): AsyncGenerator<T, void, undefined> {
  for (let page = query?.page ?? 1; ; page++) {
    const result = await method({ query: { ...query, page } as Q });
    if (!result.ok) throw new ApiFailure(result.error);
    yield* result.value.results;
    if (page >= result.value.totalPages) return;
  }
}

```ts
class ValidationError extends Error {
  constructor(path: string, expected: string, got: unknown) {
    const where = path || "value";
    super(`${where}: expected ${expected}, got ${JSON.stringify(got)}`);
    this.name = "ValidationError";
  }
}

type Schema<T> = {
  parse: (value: unknown, path?: string) => T;
  optional?: true;
};
type Infer<S extends Schema<unknown>> = ReturnType<S["parse"]>;
type Simplify<T> = { [K in keyof T]: T[K] } & {};

function primitive<T>(
  expected: string,
  test: (value: unknown) => value is T,
): Schema<T> {
  return {
    parse(value, path = "") {
      if (!test(value)) {
        throw new ValidationError(path, expected, value);
      }
      return value;
    },
  };
}

function array<T>(item: Schema<T>): Schema<T[]> {
  return {
    parse(value, path = "") {
      if (!Array.isArray(value)) {
        throw new ValidationError(path, "an array", value);
      }
      return value.map((v, i) => item.parse(v, `${path}[${i}]`));
    },
  };
}

function optional<T>(
  schema: Schema<T>,
): Schema<T | undefined> & { optional: true } {
  return {
    optional: true,
    parse: (value, path) =>
      value === undefined ? undefined : schema.parse(value, path),
  };
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return (
    typeof value === "object" && value !== null && !Array.isArray(value)
  );
}

type Shape = Record<string, Schema<unknown>>;
// The keys whose schema is optional(...)
type OptionalKeys<S extends Shape> = {
  [K in keyof S]: S[K] extends { optional: true } ? K : never;
}[keyof S];
type ObjectOf<S extends Shape> = Simplify<
  { [K in Exclude<keyof S, OptionalKeys<S>>]: Infer<S[K]> } & {
    [K in OptionalKeys<S>]?: Infer<S[K]>;
  }
>;

function object<S extends Shape>(shape: S): Schema<ObjectOf<S>> {
  return {
    parse(value, path = "") {
      if (!isRecord(value)) {
        throw new ValidationError(path, "an object", value);
      }
      const result: Record<string, unknown> = {};
      for (const key in shape) {
        const where = path ? `${path}.${key}` : key;
        const parsed = shape[key].parse(value[key], where);
        if (parsed !== undefined) result[key] = parsed;
      }
      // every key was checked, so this cast is safe
      return result as ObjectOf<S>;
    },
  };
}

interface SdkRequest {
  method: Method;
  url: string;
  headers: Record<string, string>;
  body?: string;
}

// Inside the SDK, input is loosely typed (and checked at runtime)
type RawInput = {
  params?: Record<string, unknown>;
  query?: unknown;
  body?: unknown;

function buildRequest(
  baseUrl: string,
  endpoint: Endpoint,
  input: RawInput = {},
): SdkRequest {
  const path = endpoint.path.replace(/:(\w+)/g, (_, name: string) => {
    const schema = endpoint.params?.[name];
    if (!schema) throw new Error(`No schema for :${name}`);
    const value = schema.parse(input.params?.[name], `params.${name}`);
    return encodeURIComponent(String(value));
  });
  let url = baseUrl.replace(/\/+$/, "") + path;
  if (endpoint.query) {
    const query = endpoint.query.parse(input.query ?? {}, "query");
    const search = new URLSearchParams();
    for (const [key, value] of Object.entries(query)) {
      search.set(key, String(value));
    }
    if (search.size > 0) url += `?${search}`;
  }
  const headers: Record<string, string> = {
    Accept: "application/json",
  };
  const request: SdkRequest = { method: endpoint.method, url, headers };
  if (endpoint.body) {
    const body = endpoint.body.parse(input.body, "body");
    request.body = JSON.stringify(body);
    headers["Content-Type"] = "application/json";
  }
  return request;
}

interface RetryOptions {
  attempts: number; // in total, including the first
  baseDelayMs: number;
  maxDelayMs: number;
}

interface ResponseInfo {
  request: SdkRequest;
  attempt: number;
  status: number | null; // null: the request never got an answer

}

interface Hooks {
  /** Change a request before it's sent, e.g. to add a header. */
  onRequest?: (request: SdkRequest) => SdkRequest;
  /** See every attempt, e.g. for logs and metrics. */
  onResponse?: (info: ResponseInfo) => void;
}

interface ClientOptions {
  /** Default: "https://api.pandadev.test" */
  baseUrl?: string;
  /** Default: the global fetch. Pass your own for tests. */
  fetch?: typeof fetch;
  /**
   * Retries for GET, PUT and DELETE. Default: 3 attempts,
   * 200 ms doubling up to 2,000 ms. `false` turns them off.
   */
  retry?: Partial<RetryOptions> | false;

  /** How to wait between attempts. Default: setTimeout. */

  /** For the jitter in backoff. Default: Math.random. */
  random?: () => number;
  /** Times each attempt for onResponse. Default: Date.now. */
  now?: () => number;
}

const DEFAULT_RETRY: RetryOptions = {
  attempts: 3,
  baseDelayMs: 200,
  maxDelayMs: 2_000,

// Sending these twice does no harm, so they may be retried
const IDEMPOTENT = new Set<Method>(["GET", "PUT", "DELETE"]);

function fail(error: ApiError): Result<never, ApiError> {
  return { ok: false, error };
}

function apiMessage(body: unknown): string | undefined {
  return isRecord(body) && typeof body.error === "string"
    ? body.error
    : undefined;
}

// ---------- retries ----------
function isRetryable(error: ApiError): boolean {
  switch (error.kind) {
    case "network":
      return true;
    case "http":
      return error.status === 429 || error.status >= 500;
    case "invalid-response":
      return false;
  }
}

// Exponential, capped, with "equal jitter": half fixed, half random
function backoff(
  attempt: number,
  retry: RetryOptions,
  random: () => number,
): number {
  const exp = Math.min(
    retry.maxDelayMs,
    retry.baseDelayMs * 2 ** (attempt - 1),
  );
  return Math.round(exp / 2 + (exp / 2) * random());
}

/**
 * A typed client for any API description: one method per
 * endpoint. Most people want createPandaClient() instead.
 */
function createClient<A extends ApiDescription>(
  api: A,
  options: ClientOptions = {},
): Client<A> {
  const {
    baseUrl = "https://api.pandadev.test",
    fetch: fetchFn = fetch,
    hooks = {},
    sleep = (ms: number) =>
      new Promise<void>((resolve) => setTimeout(resolve, ms)),
    random = Math.random,
    now = Date.now,
  } = options;
  const retry: RetryOptions =
    options.retry === false
      ? { ...DEFAULT_RETRY, attempts: 1 }
      : { ...DEFAULT_RETRY, ...options.retry };

  // One attempt: fetch, read the body, and say how it went
  async function attemptOnce(
    request: SdkRequest,
    attempt: number,
  ): Promise<Result<unknown, ApiError>> {
    const started = now();
    const report = (status: number | null) => {
      const ms = now() - started;
      hooks.onResponse?.({ request, attempt, status, ms });
    };
    let res: Response;
    try {
      res = await fetchFn(request.url, {
        method: request.method,
        headers: request.headers,
        body: request.body,
      });
    } catch (error) {
      report(null);
      const message =
        error instanceof Error ? error.message : String(error);
      return fail({ kind: "network", message });
    }
    const body: unknown =
      res.status === 204 ? null : await res.json().catch(() => null);
    report(res.status);
    if (!res.ok) {
      const message = apiMessage(body) ?? `HTTP ${res.status}`;
      return fail({ kind: "http", status: res.status, message });
    }
    return { ok: true, value: body };
  }

  // Build the request, try it (again), check what comes back
  async function send(
    endpoint: Endpoint,
    input: RawInput,
  ): Promise<Result<unknown, ApiError>> {
    let request = buildRequest(baseUrl, endpoint, input);
    request.headers["X-Panda-SDK"] = SDK_VERSION;
    if (hooks.onRequest) request = hooks.onRequest(request);
    const attempts = IDEMPOTENT.has(endpoint.method)
      ? retry.attempts
      : 1;
    for (let attempt = 1; ; attempt++) {
      const result = await attemptOnce(request, attempt);
      if (!result.ok) {
        if (attempt < attempts && isRetryable(result.error)) {
          await sleep(backoff(attempt, retry, random));
          continue;
        }
        return result;
      }
      try {
        const value = endpoint.response.parse(result.value);
        return { ok: true, value };
      } catch (error) {
        if (!(error instanceof ValidationError)) throw error;
        const { message } = error;
        return fail({ kind: "invalid-response", message });
      }
    }
  }

  // One method per endpoint: Client<A> is the promise, this loop
  // keeps it, and the cast says so in exactly one place
  const client: Record<string, (input?: RawInput) => unknown> = {};
  for (const name of Object.keys(api)) {
    const endpoint = api[name];
    client[name] = (input = {}) => send(endpoint, input);
  }
  return client as Client<A>;
}

// For APIs without a Result channel, like async iteration
class ApiFailure extends Error {
  readonly error: ApiError;
  constructor(error: ApiError) {
    super(error.message);
    this.name = "ApiFailure";
    this.error = error;
  }
}

/**
 * Every item of every page, fetching one page at a time:
 * `for await (const movie of paginate(panda.searchMovies))`.
 * Throws an ApiFailure if a page can't be loaded.
 */
async function* paginate<Q extends { page?: number }, T>(
  method: (input: { query?: Q }) => Promise<Result<Page<T>, ApiError>>,
  query?: NoInfer<Q>,
): AsyncGenerator<T, void, undefined> {
  for (let page = query?.page ?? 1; ; page++) {
    const result = await method({ query: { ...query, page } as Q });
    if (!result.ok) throw new ApiFailure(result.error);
    yield* result.value.results;
    if (page >= result.value.totalPages) return;
  }
}

function unwrap<T>(
  result: Result<T, ApiError> | Promise<Result<T, ApiError>>,
): T | Promise<T> {
  if (result instanceof Promise) {
    return result.then((settled) => unwrap(settled));
  }
  if (!result.ok) throw new ApiFailure(result.error);
```

## What you built

- A deliberate, small **public surface**: one entry point, every type in a public signature exported, internals (even `createClient`) kept private, and `createPandaClient` for the common case with a named `PandaClient` type.
- **Options that can grow** (`retry: false`), an **`X-Panda-SDK`** header so the API team knows who's calling, and **`unwrap`** with overloads for scripts and tests.
- **JSDoc** that travels into users' editors, including through the mapped `Client` type, and a `@deprecated` path for renaming methods.
- **Type tests for the whole surface**, so the public API changes only when someone decides it should.
- A **package**: ESM only, `exports` with types first, no dependencies, a real look at the declaration files, a semver policy (including error kinds), Changesets, CI on every supported Node version, and publishing with provenance.

And the finished SDK: one description of the API, every type derived from it, every answer checked, every failure typed, retries that don't make outages worse, pagination with `for await`, and a promise to its users that is written down, tested and versioned.

## Take it further

1. **Timeouts**: add a `timeoutMs` option using `AbortSignal.timeout(ms)` and test it with the practice API's `/delay/:ms` endpoint. Then make the real decision: is a timeout a new `{ kind: "timeout" }` (a major release, by our policy) or a `network` error (a minor one)?
2. **Respect `Retry-After`**: when a 429 or 503 comes with a `Retry-After: 2` header, wait that long (in seconds, capped by `maxDelayMs`) instead of the backoff, and expose the header to `onResponse`.
3. **Recipes**: add `getRecipe` and `searchRecipes` to the description with their schemas, contract tests against the practice API and a changeset: a complete minor release.
4. **Bring your own schemas**: accept any **Standard Schema** (the shared interface that zod, valibot and ArkType implement) in descriptions, then make `createClient` and `defineApi` public in a minor release, so users can describe their own APIs with the library they already use.
5. **Idempotency keys**: let `createTodo` send an `Idempotency-Key` header with a `crypto.randomUUID()`, and retry `POST`s that carry one. (The practice API ignores the header, so test it with a fake server that remembers keys.)
