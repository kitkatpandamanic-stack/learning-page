До сих пор TypeScript сужал типы по проверкам, которые он и так понимает: `typeof`, `in`, `instanceof`, метки. А как быть с данными, которые приходят **извне** программы — из JSON-файла, формы или с другого сервера? TypeScript понятия не имеет, что внутри. В этом уроке вы научите TypeScript новым проверкам с помощью **защитников типа** (type guards), будете шаг за шагом проверять неизвестные данные и увидите, почему сокращения `!` и `as` могут незаметно продырявить вашу страховочную сетку. А затем соберёте обработчик статусов платежей, который ничему не верит на слово. 🛡️

## Когда логического значения мало

Проверки становятся длинными, и их естественно хочется вынести в функцию. Но посмотрите, что происходит с сужением:

```ts
interface Fish {
  name: string;
  swim(): string;
}

interface Bird {
  name: string;
  fly(): string;
}

function isFish(pet: Fish | Bird): boolean {
  return "swim" in pet;
}

function move(pet: Fish | Bird): string {
  if (isFish(pet)) {
    return pet.swim();
    // ❌ Error: Property 'swim' does not exist on type 'Fish | Bird'.
  }
  return pet.fly();
}
```

Проверка внутри `isFish` правильная, но её возвращаемый тип `boolean` говорит только «true или false». Он не говорит, **что** означает true, поэтому TypeScript не может сузить `pet` в `move`.

## Предикаты типа: `value is Type`

Замените возвращаемый тип на **предикат типа** (type predicate): `pet is Fish`. Во время выполнения функция по-прежнему возвращает логическое значение, но теперь она сообщает TypeScript: «если я вернула `true`, то `pet` — это `Fish`». Такую функцию называют **защитником типа**:

<CodeExample output={`[ 'Немо плывёт', 'Твити летит', 'Дори плывёт' ]
[ 'Немо', 'Дори' ]`}>

```ts
interface Fish {
  name: string;
  swim(): string;
}

interface Bird {
  name: string;
  fly(): string;
}

function isFish(pet: Fish | Bird): pet is Fish {
  return "swim" in pet;
}

function move(pet: Fish | Bird): string {
  if (isFish(pet)) {
    return pet.swim(); // pet: Fish
  }
  return pet.fly(); // pet: Bird
}

const pets: (Fish | Bird)[] = [
  { name: "Немо", swim: () => "Немо плывёт" },
  { name: "Твити", fly: () => "Твити летит" },
  { name: "Дори", swim: () => "Дори плывёт" },
];

console.log(pets.map(move));

const fish = pets.filter(isFish); // Fish[]
console.log(fish.map((f) => f.name));
```

</CodeExample>

Ветка `false` тоже сужает тип: после `if` переменная `pet` — это `Bird`. И посмотрите на `filter`: если передать ему защитника типа, получится `Fish[]`, а не `(Fish | Bird)[]`.

Для простых проверок TypeScript даже сам выводит предикат, если вы не пишете возвращаемый тип. Поэтому отфильтровав `null`, вы получаете чистый массив:

<CodeExample output="[ 'MEI', 'SAM', 'ANA' ]">

```ts
const names = ["Mei", null, "Sam", null, "Ana"];
// names: (string | null)[]

const real = names.filter((name) => name !== null);
// real: string[]
console.log(real.map((name) => name.toUpperCase()));
```

</CodeExample>

<Callout type="danger" title="Предикат типа — это ваше обещание">

TypeScript **не проверяет**, правильный ли у вас защитник. Он верит всему, что говорит предикат, поэтому неверный защитник хуже, чем никакого:

```ts
// ⚠️ Неверно: «рыбы — это те, у кого имя из 4 букв»
function isFish(pet: Fish | Bird): pet is Fish {
  return pet.name.length === 4;
}

const toby: Bird = { name: "Тоби", fly: () => "Тоби летит" };
if (isFish(toby)) {
  toby.swim(); // компилируется, а потом падает: toby.swim is not a function
}
```

Делайте защитников маленькими и очевидно правильными и проверяйте их как на хороших, **так и** на плохих значениях.

</Callout>

## Снова `unknown` против `any`

В уроке [any, unknown, null и undefined](/learn/typescript/special-types) вы узнали, что `unknown` — это безопасное «пока не знаю». Вот почему это так важно: `JSON.parse` возвращает **`any`**. Всё, что из него выходит, отключает проверку типов, включая опечатки:

<CodeExample output="Cannot read properties of undefined (reading 'toUpperCase')">

```ts
const text = '{ "name": "Mei", "age": 31 }';

const user = JSON.parse(text); // any: никаких проверок!
try {
  console.log(user.nmae.toUpperCase()); // опечатка, но ошибки нет
} catch (error) {
  if (error instanceof Error) {
    console.log(error.message);
  }
}
```

</CodeExample>

Исправление — одна аннотация: `const data: unknown = JSON.parse(text);`. Теперь TypeScript не даст вам трогать `data`, пока вы не докажете, что это такое:

```ts
const data: unknown = JSON.parse(text);
console.log(data.name);
// ❌ Error: 'data' is of type 'unknown'.
```

Так обращайтесь со всем, что приходит из внешнего мира: с разобранным JSON, данными из `localStorage`, сообщениями из других окон, ответами серверов. Всё это начинается как `unknown`, а защитники типа превращают это в типы, которым можно доверять.

## Шаг за шагом проверяем неизвестные данные

Как доказать, что значение типа `unknown` — это `User`? По одному свойству за раз. Первый шаг делает маленький защитник `isObject`: он превращает `unknown` в `Record<string, unknown>` — объект, свойства которого можно **читать**, но всё ещё нужно проверять:

<CodeExample output={`✅ Mei, возраст 31
❌ Не пользователь: { "name": "Sam", "age": "31" }
❌ Не пользователь: [1, 2, 3]
❌ Не пользователь: null`}>

```ts
interface User {
  name: string;
  age: number;
  email?: string;
}

function isObject(value: unknown): value is Record<string, unknown> {
  return (
    typeof value === "object" && value !== null && !Array.isArray(value)
  );
}

function isUser(value: unknown): value is User {
  if (!isObject(value)) {
    return false;
  }
  // value: Record<string, unknown>, все свойства — unknown
  if (typeof value.name !== "string") {
    return false;
  }
  if (typeof value.age !== "number") {
    return false;
  }
  if (value.email !== undefined && typeof value.email !== "string") {
    return false;
  }
  return true;
}

const inputs = [
  '{ "name": "Mei", "age": 31 }',
  '{ "name": "Sam", "age": "31" }',
  '[1, 2, 3]',
  'null',
];

for (const text of inputs) {
  const data: unknown = JSON.parse(text);
  if (isUser(data)) {
    console.log(`✅ ${data.name}, возраст ${data.age}`); // data: User
  } else {
    console.log(`❌ Не пользователь: ${text}`);
  }
}
```

</CodeExample>

Каждая проверка исключает один из способов, которыми данные могут быть неправильными, с помощью инструментов сужения из урока [Объединения типов](/learn/typescript/union-types). Обратите внимание: в JavaScript `typeof null === "object"`, поэтому `isObject` проверяет `null` отдельно.

<Callout type="warning" title="Array.isArray даёт any[]">

Для значения типа `unknown` проверка `Array.isArray(data)` сужает тип до `any[]`, а не до `unknown[]`. Поэтому после неё TypeScript снова перестаёт проверять: `return data;` спокойно выдаст непроверенные элементы за `User[]`. Проверяйте и элементы тоже, например через `data.filter(isUser)`, — это даёт настоящий `User[]`.

</Callout>

## Функции-утверждения: `asserts value is Type`

Защитник типа возвращает `true` или `false`, а `if` пишете вы. Но иногда плохие данные означают просто «стоп»: разумно только выбросить исключение. Именно это делает **функция-утверждение** (assertion function). Её возвращаемый тип `asserts value is User` означает «если эта функция вообще вернула управление, то `value` — это `User`»:

<CodeExample output={`{ name: 'Mei', age: 31 }
Ожидался пользователь, получено {"name":"Sam"}`}>

```ts
interface User {
  name: string;
  age: number;
}

function isObject(value: unknown): value is Record<string, unknown> {
  return (
    typeof value === "object" && value !== null && !Array.isArray(value)
  );
}

function isUser(value: unknown): value is User {
  return (
    isObject(value) &&
    typeof value.name === "string" &&
    typeof value.age === "number"
  );
}

function assertIsUser(value: unknown): asserts value is User {
  if (!isUser(value)) {
    const got = JSON.stringify(value);
    throw new Error(`Ожидался пользователь, получено ${got}`);
  }
}

function loadUser(text: string): User {
  const data: unknown = JSON.parse(text);
  assertIsUser(data);
  // Начиная отсюда, data: User
  return data;
}

console.log(loadUser('{ "name": "Mei", "age": 31 }'));
try {
  loadUser('{ "name": "Sam" }');
} catch (error) {
  if (error instanceof Error) {
    console.log(error.message);
  }
}
```

</CodeExample>

После вызова `if` не нужен: сужение действует на **каждую** строку ниже. Используйте защитника, когда плохие данные — нормальный случай, который вы обрабатываете (пропускаете, показываете сообщение), и утверждение, когда плохие данные означают, что что-то сломалось.

<Callout type="note" title="Пишите функции-утверждения через function">

Если записать функцию-утверждение как стрелочную функцию в `const`, её вызов даст загадочную ошибку: "Assertions require every name in the call target to be declared with an explicit type annotation." Простое решение — объявить её через `function`, как выше.

</Callout>

## Утверждение non-null `!`

`!` после выражения говорит TypeScript: «это **не** `null` и не `undefined`, поверь мне». Это утверждение non-null (non-null assertion) убирает их из типа, но во время выполнения ничего не проверяет. Если вы ошиблись, падение произойдёт позже, в другом месте и с туманным сообщением:

<CodeExample output={`Mei
Cannot read properties of undefined (reading 'name')`}>

```ts
interface User {
  id: number;
  name: string;
}

const users: User[] = [
  { id: 1, name: "Mei" },
  { id: 2, name: "Sam" },
];

// «Поверь, он там есть»: ! убирает undefined
const mei = users.find((u) => u.id === 1)!;
console.log(mei.name);

try {
  const ghost = users.find((u) => u.id === 3)!;
  console.log(ghost.name);
} catch (error) {
  if (error instanceof Error) {
    console.log(error.message);
  }
}
```

</CodeExample>

Привычка получше: обработайте случай отсутствия или упадите **сразу** с сообщением, которое всё объясняет. Крошечный универсальный помощник `assert` делает это одной строкой и сужает тип так же, как `!`:

<CodeExample output={`Sam
Нет пользователя с id 3`}>

```ts
interface User {
  id: number;
  name: string;
}

const users: User[] = [
  { id: 1, name: "Mei" },
  { id: 2, name: "Sam" },
];

function assert(
  condition: unknown,
  message: string,
): asserts condition {
  if (!condition) {
    throw new Error(message);
  }
}

function getUser(id: number): User {
  const user = users.find((u) => u.id === id); // User | undefined
  assert(user, `Нет пользователя с id ${id}`);
  return user; // user: User
}

console.log(getUser(2).name);
try {
  console.log(getUser(3).name);
} catch (error) {
  if (error instanceof Error) {
    console.log(error.message);
  }
}
```

</CodeExample>

`asserts condition` (без `is`) означает «если функция вернула управление, `condition` было истинным», поэтому после вызова `user` не может быть `undefined`. «Нет пользователя с id 3» отлаживать гораздо проще, чем «reading 'name'».

## Приведения через `as` и их опасность

`value as User` — это **утверждение типа** (type assertion), которое часто называют приведением (cast). Оно ничего не преобразует и не проверяет, а просто велит компилятору считать значение типом `User`. С внешними данными это ложь, которую TypeScript поймать не может:

<CodeExample output="NaN">

```ts
interface User {
  name: string;
  age: number;
}

const user = JSON.parse('{ "name": "Mei" }') as User;
console.log(user.age + 1); // TypeScript думает, что age — число
```

</CodeExample>

Самую очевидную чепуху, когда у двух типов нет ничего общего, TypeScript всё же останавливает:

```ts
const n = "hello" as number;
// ❌ Error: Conversion of type 'string' to type 'number' may be a mistake because neither type sufficiently overlaps with the other. If this was intentional, convert the expression to 'unknown' first.
```

Сообщение подсказывает лазейку — `"hello" as unknown as number`, и это компилируется. Если вы вдруг поймали себя на таком двойном приведении, остановитесь: типы говорят вам, что что-то не так.

Вот как соотносятся инструменты из этого урока:

| Инструмент | Проверяет во время выполнения? | Для чего подходит |
| --- | --- | --- |
| Защитник типа `x is T` | ✅ да, проверки пишете вы | данные, которые могут быть корректными, а могут и нет |
| Утверждение `asserts x is T` | ✅ да, выбрасывает ошибку | данные, которые **обязаны** быть корректными |
| Non-null `x!` | ❌ нет | редкие случаи, которые можно доказать; лучше избегать |
| Приведение `x as T` | ❌ нет | редкие случаи, когда вы знаете больше, чем TypeScript |

<Callout type="tip" title="В реальных проектах">

Многие команды включают правила линтера, которые подсвечивают `!` и `as` на ревью кода, и пишут защитников или используют библиотеку валидации (например, zod) на границах приложения, где данные приходят внутрь. Крошечную библиотеку валидации вы сами напишете на Уровне 2. А пока хорошее правило: **`unknown` на границах, защитники на входе, настоящие типы внутри.**

</Callout>

```ts
// Суммы в пенсах (1250 = £12.50), поэтому суммы точные.
type Payment =
  | { status: "pending"; id: string; amount: number }
  | { status: "paid"; id: string; amount: number }
  | { status: "failed"; id: string; amount: number; reason: string }
  | {
      status: "refunded";
      id: string;
      amount: number;
      refunded: number; // возвращено пенсов
    };

interface Summary {
  count: number; // корректные платежи
  collected: number; // пенсы, которые остаются у нас
  pending: number; // платежи в ожидании
  failed: number; // неудачные платежи
}

function assertNever(value: never): never {
  throw new Error(`Неожиданное значение: ${JSON.stringify(value)}`);
}

function isObject(value: unknown): value is Record<string, unknown> {
  return (
    typeof value === "object" && value !== null && !Array.isArray(value)
  );
}

function pounds(pence: number): string {
  return `£${(pence / 100).toFixed(2)}`;
}

// ===== Ваш код =====

function isPayment(value: unknown): value is Payment {
  if (!isObject(value)) {
    return false;
  }
  if (typeof value.id !== "string") {
    return false;
  }
  if (typeof value.amount !== "number") {
    return false;
  }
  switch (value.status) {
    case "pending":
    case "paid":
      return true;
    case "failed":
      return typeof value.reason === "string";
    case "refunded":
      return typeof value.refunded === "number";
    default:
      return false; // незнакомый статус
  }
}

function parsePayments(json: string): Payment[] {
  let data: unknown;
  try {
    data = JSON.parse(json);
  } catch {
    return []; // невалидный JSON
  }
  if (!Array.isArray(data)) {
    return [];
  }
  return data.filter(isPayment);
}

function describePayment(payment: Payment): string {
  const { id, amount } = payment;
  switch (payment.status) {
    case "pending":
      return `${id}: ${pounds(amount)} pending`;
    case "paid":
      return `${id}: ${pounds(amount)} paid`;
    case "failed":
      return `${id}: ${pounds(amount)} failed (${payment.reason})`;
    case "refunded": {
      const back = pounds(payment.refunded);
      return `${id}: ${back} of ${pounds(amount)} refunded`;
    }
    default:
      return assertNever(payment);
  }
}

function summarise(payments: Payment[]): Summary {
  const summary: Summary = {
    count: payments.length,
    collected: 0,
    pending: 0,
    failed: 0,
  };
  for (const payment of payments) {
    switch (payment.status) {
      case "pending":
        summary.pending++;
        break;
      case "paid":
        summary.collected += payment.amount;
        break;
      case "failed":
        summary.failed++;
        break;
      case "refunded":
        summary.collected += payment.amount - payment.refunded;
        break;
      default:
        assertNever(payment);
    }
  }
  return summary;
}
```

## Итоги

- **Защитник типа** возвращает **предикат типа** `value is T`: если он вернул `true`, TypeScript сужает тип до `T` (а `filter(guard)` даёт `T[]`).
- TypeScript верит вашему предикату без проверки, поэтому делайте защитников маленькими, правильными и протестированными.
- `JSON.parse` возвращает `any`: сохраняйте результат как `unknown` и проверяйте перед использованием.
- Проверяйте шаг за шагом: сначала `isObject`, затем каждое свойство через `typeof`; помните, что `Array.isArray` даёт `any[]`, поэтому проверяйте и элементы.
- **Функция-утверждение** (`asserts value is T` или `asserts condition`) выбрасывает ошибку на плохих данных и сужает тип на каждой строке после вызова.
- `!` и `as` меняют то, во что верит TypeScript, ничего не проверяя; предпочитайте защитников, утверждения и понятные ошибки.
- **`unknown` на границах, защитники на входе, настоящие типы внутри.**
