In Level 0 you met `string | number` and narrowed it with `typeof`. Real data is messier than that: a search box gives you a word **or** a list of words, a lookup finds a product **or** nothing, a price arrives as a number **or** a ready-made label. In this lesson you'll build unions of **any** types and learn the whole narrowing toolbox, so you can handle every shape safely. 🧰

## Unions of any types

The `|` works between **any** types, not just `string` and `number`: object types, arrays, `null`, `undefined`, even other unions. A type alias gives the union a name you can reuse:

<CodeExample output={`null
{ id: 'gift-card', name: 'Gift card', price: 20 }
undefined`}>

```ts
type Id = string | number;

interface Product {
  id: Id;
  name: string;
  price: number;
}

const products: Product[] = [
  { id: 1, name: "Tea", price: 3.5 },
  { id: "gift-card", name: "Gift card", price: 20 },
];

function findProduct(id: Id): Product | undefined {
  return products.find((p) => p.id === id);
}

let selected: Product | null = null;
console.log(selected);
selected = findProduct("gift-card") ?? null;
console.log(selected);
console.log(findProduct(99));
```

</CodeExample>

Read `Product | undefined` out loud as "a product, or nothing". That return type is honest: it tells everyone who calls `findProduct` that they must handle the "not found" case. You'll see `T | null` and `T | undefined` everywhere in real code.

## What you can do with a union

A value of a union type could be **any** of its members, so TypeScript only lets you use what **every** member has. Both strings and arrays have a `length`, so that's fine. Only strings have `toUpperCase`:

```ts
function shout(input: string | string[]): string {
  console.log(input.length); // ✅ both have length
  return input.toUpperCase();
  // ❌ Error: Property 'toUpperCase' does not exist on type 'string | string[]'.
}
```

The same goes for object types. A `Cat` and a `Dog` both have a `name`, but only a dog can `bark`:

```ts
interface Cat {
  name: string;
  meow(): string;
}

interface Dog {
  name: string;
  bark(): string;
}

function greet(pet: Cat | Dog) {
  console.log(pet.name); // ✅ every pet has a name
  pet.bark();
  // ❌ Error: Property 'bark' does not exist on type 'Cat | Dog'.
}
```

To use the members that only **some** types have, you first find out which type you've got. That's **narrowing**, and TypeScript understands many more checks than `typeof`.

## The narrowing toolbox

You already know two tools from [Conditions & Narrowing](/learn/typescript/conditions-and-narrowing): `typeof` checks, and truthiness checks like `if (name)` (with their trap: `0` and `""` are falsy too). Here are four more.

### Arrays: `Array.isArray`

`typeof` can't tell an array from an object: `typeof []` is `"object"`. Use `Array.isArray` instead:

<CodeExample output={`HELLO
HELLO THERE`}>

```ts
function shout(input: string | string[]): string {
  if (Array.isArray(input)) {
    return input.map((word) => word.toUpperCase()).join(" ");
  }
  return input.toUpperCase();
}

console.log(shout("hello"));
console.log(shout(["hello", "there"]));
```

</CodeExample>

Inside the `if`, `input` is a `string[]`. After the `if` returns, only a `string` is left.

### Properties: the `in` operator

`"bark" in pet` checks whether the object has a property called `bark`. TypeScript narrows to the members of the union that have it:

<CodeExample output={`Mo: Meow!
Rex: Woof!`}>

```ts
interface Cat {
  name: string;
  meow(): string;
}

interface Dog {
  name: string;
  bark(): string;
}

function speak(pet: Cat | Dog): string {
  if ("bark" in pet) {
    return `${pet.name}: ${pet.bark()}`; // pet: Dog
  }
  return `${pet.name}: ${pet.meow()}`; // pet: Cat
}

const mo: Cat = { name: "Mo", meow: () => "Meow!" };
const rex: Dog = { name: "Rex", bark: () => "Woof!" };

console.log(speak(mo));
console.log(speak(rex));
```

</CodeExample>

### Classes: `instanceof`

Values created with `new`, such as a `Date` or an `Error`, can be checked with `instanceof`:

<CodeExample output={`2026-03-14
tomorrow`}>

```ts
function formatDate(when: Date | string): string {
  if (when instanceof Date) {
    return when.toISOString().slice(0, 10); // when: Date
  }
  return when; // when: string
}

console.log(formatDate(new Date(Date.UTC(2026, 2, 14))));
console.log(formatDate("tomorrow"));
```

</CodeExample>

### Equality: `===`

When you compare two values with `===`, TypeScript knows they must have the **same** type inside the `if`. Here, the only type `a` and `b` can share is `string`:

<CodeExample output={`AB-12
different`}>

```ts
function sameId(a: string | number, b: string | boolean): string {
  if (a === b) {
    // Only a string can be in both unions
    return a.toUpperCase(); // a: string, b: string
  }
  return "different";
}

console.log(sameId("ab-12", "ab-12"));
console.log(sameId(12, true));
```

</CodeExample>

You've used this one for a while without noticing: `if (value === null)` is equality narrowing too.

| Check | Use it for |
| --- | --- |
| `typeof x === "string"` | `string`, `number`, `boolean`, `undefined`, `function` |
| `Array.isArray(x)` | arrays (`typeof` says `"object"`) |
| `"prop" in x` | objects that differ by their properties |
| `x instanceof Date` | values made with `new` from a class |
| `x === null`, `x === y` | exact values, including `null` and `undefined` |
| `if (x)` | ruling out `null` and `undefined` when `0` and `""` don't matter |

## TypeScript follows your code

Narrowing isn't magic attached to `if`. TypeScript reads your code from top to bottom like a careful colleague and tracks what each variable **can** be at every line. This is called **control-flow analysis**, and it understands more than you might expect.

**Assignments narrow.** A variable declared as `string | number` is, right after you assign a string to it, a `string`:

<CodeExample output={`2
42.0`}>

```ts
let input: string | number = "42";
console.log(input.length); // input: string

input = Number(input);
console.log(input.toFixed(1)); // input: number
```

</CodeExample>

After the second assignment, `input.length` would be an error: TypeScript knows `input` now holds a number.

**Early exits narrow.** `return` and `throw` end a branch, so whatever they handled is gone for the rest of the function. Here `null` is thrown out first, then strings are turned into numbers, so every path reaches the last line with a number:

<CodeExample output={`31
42
Oops: Age is required`}>

```ts
function parseAge(input: string | number | null): number {
  if (input === null) {
    throw new Error("Age is required");
  }
  // null is gone: input is string | number
  if (typeof input === "string") {
    input = Number.parseInt(input, 10); // now input: number
  }
  // Both paths end with a number here
  return input;
}

console.log(parseAge(31));
console.log(parseAge("42"));
try {
  parseAge(null);
} catch (error) {
  if (error instanceof Error) {
    console.log("Oops:", error.message);
  }
}
```

</CodeExample>

Notice the `instanceof Error` in the `catch`: in TypeScript a caught `error` could be anything (JavaScript can `throw "oops"`), so you narrow it before reading `.message`.

<Callout type="tip" title="Handle the awkward cases first">

Checking for `null`, empty or invalid input at the **top** of a function and returning (or throwing) straight away is called a **guard clause**. Each guard narrows the type a bit more, and the main code at the bottom works with a clean, simple type. It's easier to read than deeply nested `if`/`else` blocks too.

</Callout>

## Unions in arrays

Where you put the brackets matters. Compare these two types:

- `(string | number)[]`: **one** array whose items can each be a string or a number, mixed freely.
- `string[] | number[]`: **either** an array of only strings, **or** an array of only numbers.

A mixed list of answers, where a player can type a number or `"skip"`, needs the first one. You narrow each item as you go:

<CodeExample output="Total 12, skipped 2">

```ts
const answers: (string | number)[] = [3, "skip", 5, "skip", 4];

let total = 0;
let skipped = 0;
for (const answer of answers) {
  if (typeof answer === "number") {
    total += answer;
  } else {
    skipped++;
  }
}

console.log(`Total ${total}, skipped ${skipped}`);
```

</CodeExample>

The second type is stricter, so a mixed array isn't allowed:

```ts
const scores: string[] | number[] = [1, "a"];
// ❌ Error: Type '(string | number)[]' is not assignable to type 'string[] | number[]'.
```

A `string[] | number[]` is also awkward to add to: TypeScript doesn't know which kind of array it is, so it won't let you `push` either a string or a number until you narrow it. If items can be mixed, you want `(string | number)[]`.

## Missing values: `null` and `undefined` in unions

With **strict null checks** (always on at PandaDev, and in every modern project), `null` and `undefined` are just members of a union like any other. They turn up in more places than you might think:

- `find` returns `T | undefined`: maybe nothing matched.
- An optional property `address?: Address` has the type `Address | undefined`.
- Your own functions return `T | null` when "no result" is a normal answer.

TypeScript won't let you forget them:

```ts
function cityOf(name: string): string {
  const customer = customers.find((c) => c.name === name);
  return customer.address.city;
  // ❌ Error: 'customer' is possibly 'undefined'.
  // ❌ Error: 'customer.address' is possibly 'undefined'.
}
```

Optional chaining `?.` and nullish coalescing `??` (from [any, unknown, null & undefined](/learn/typescript/special-types)) handle a whole chain of maybe-missing values in one line:

<CodeExample output={`Leeds
Unknown city
Unknown city`}>

```ts
interface Address {
  city: string;
  postcode?: string; // string | undefined
}

interface Customer {
  name: string;
  address?: Address; // Address | undefined
}

const customers: Customer[] = [
  { name: "Mei", address: { city: "Leeds", postcode: "LS1" } },
  { name: "Sam" },
];

function cityOf(name: string): string {
  const customer = customers.find((c) => c.name === name);
  // customer: Customer | undefined
  return customer?.address?.city ?? "Unknown city";
}

console.log(cityOf("Mei"));
console.log(cityOf("Sam"));
console.log(cityOf("Ana"));
```

</CodeExample>

`customer?.address?.city` is `string | undefined`: it stops at the first missing value. Then `?? "Unknown city"` replaces `undefined` with a fallback, so the result is a plain `string`, exactly what the return type promises.

<Callout type="warning" title="Don't reach for ?. everywhere">

`?.` is for values that can **legitimately** be missing. Sprinkling it on everything "just in case" hides real bugs: instead of a clear error where the data went wrong, you get a quiet `undefined` that pops up somewhere else much later. If a value should always be there, fix its type instead.

</Callout>

A shop gets prices from several old systems, and each one sends them in a different shape. Write one `formatPrice(input)` that handles them all.

The starter has **type errors**: `PriceInput` only allows a `number`. First widen it to a union of all six shapes, then return:

| Input | Example | Label |
| --- | --- | --- |
| a number | `12.5` | `"£12.50"` |
| a string (a ready-made label) | `"Free"` | `"Free"` (unchanged) |
| a list of numbers | `[2, 3.5]` | `"£5.50 (2 items)"`, or `"(1 item)"` for one |
| a `Money` object | `{ amount: 9, currency: "EUR" }` | `"9.00 EUR"` |
| `null` or `undefined` | `null` | `"Price on request"` |

Watch out for `0` and `""`: they are real prices, not missing ones.

<Hint>

Start with a guard for the missing cases: `if (input === null || input === undefined)`. Don't use `if (!input)`, which would also catch `0` and `""`. Then use `typeof` for numbers and strings, and `Array.isArray` for the list (add the items up with a `for...of` loop). After those checks, TypeScript knows only `Money` is left, so `input.amount` and `input.currency` just work. Use `toFixed(2)` for two decimal places.

</Hint>

<Solution>

```ts
interface Money {
  amount: number;
  currency: string;
}

type PriceInput =
  | number
  | string
  | number[]
  | Money
  | null
  | undefined;

function formatPrice(input: PriceInput): string {
  if (input === null || input === undefined) {
    return "Price on request";
  }
  if (typeof input === "number") {
    return "£" + input.toFixed(2);
  }
  if (typeof input === "string") {
    return input;
  }
  if (Array.isArray(input)) {
    let total = 0;
    for (const price of input) {
      total += price;
    }
    const items = input.length === 1 ? "item" : "items";
    return `£${total.toFixed(2)} (${input.length} ${items})`;
  }
  // Only Money is left
  return `${input.amount.toFixed(2)} ${input.currency}`;
}

console.log(formatPrice(12.5)); // £12.50
console.log(formatPrice(0)); // £0.00
console.log(formatPrice("Free")); // Free
console.log(formatPrice([2, 3.5])); // £5.50 (2 items)
console.log(formatPrice({ amount: 9, currency: "EUR" }));
// 9.00 EUR
console.log(formatPrice(null)); // Price on request
console.log(formatPrice(undefined)); // Price on request
```

</Solution>

## Recap

- A **union** `A | B` can combine any types: objects, arrays, `null`, `undefined` and more.
- Without narrowing, you can only use what **every** member of the union has.
- The narrowing toolbox: `typeof`, truthiness, `===`, `Array.isArray`, `"prop" in x` and `instanceof`.
- **Control-flow analysis** tracks types line by line: assignments, `return` and `throw` all narrow.
- `(string | number)[]` is one mixed array; `string[] | number[]` is one kind of array or the other.
- `find`, optional properties and "no result" functions give `T | undefined` or `T | null`; handle them with guards, `?.` and `??`.
