На Уровне 0 вы познакомились со `string | number` и сужали его через `typeof`. Реальные данные устроены сложнее: поле поиска даёт вам слово **или** список слов, поиск находит товар **или** ничего, цена приходит числом **или** готовой подписью. В этом уроке вы будете строить объединения из **любых** типов и освоите весь набор инструментов сужения, чтобы безопасно обрабатывать любую форму данных. 🧰

## Объединения любых типов

`|` работает между **любыми** типами, а не только между `string` и `number`: объектными типами, массивами, `null`, `undefined` и даже другими объединениями. Псевдоним типа даёт объединению (union type) имя, которое можно использовать повторно:

<CodeExample output={`null
{ id: 'gift-card', name: 'Gift card', price: 20 }
undefined`}>

```ts
type Id = string | number;

interface Product {
  id: Id;
  name: string;
  price: number;
}

const products: Product[] = [
  { id: 1, name: "Tea", price: 3.5 },
  { id: "gift-card", name: "Gift card", price: 20 },
];

function findProduct(id: Id): Product | undefined {
  return products.find((p) => p.id === id);
}

let selected: Product | null = null;
console.log(selected);
selected = findProduct("gift-card") ?? null;
console.log(selected);
console.log(findProduct(99));
```

</CodeExample>

Читайте `Product | undefined` вслух как «товар или ничего». Такой возвращаемый тип честен: он сообщает всем, кто вызывает `findProduct`, что им нужно обработать случай «не найдено». `T | null` и `T | undefined` встречаются в реальном коде повсюду.

## Что можно делать с объединением

Значение типа-объединения может оказаться **любым** из его членов, поэтому TypeScript разрешает использовать только то, что есть у **каждого** члена. И у строк, и у массивов есть `length`, так что с ним всё в порядке. А `toUpperCase` есть только у строк:

```ts
function shout(input: string | string[]): string {
  console.log(input.length); // ✅ length есть у обоих
  return input.toUpperCase();
  // ❌ Error: Property 'toUpperCase' does not exist on type 'string | string[]'.
}
```

С объектными типами то же самое. И у `Cat` (кошки), и у `Dog` (собаки) есть `name`, но лаять (`bark`) умеет только собака:

```ts
interface Cat {
  name: string;
  meow(): string;
}

interface Dog {
  name: string;
  bark(): string;
}

function greet(pet: Cat | Dog) {
  console.log(pet.name); // ✅ имя есть у любого питомца
  pet.bark();
  // ❌ Error: Property 'bark' does not exist on type 'Cat | Dog'.
}
```

Чтобы использовать члены, которые есть только у **некоторых** типов, сначала выясните, какой именно тип у вас в руках. Это и есть **сужение типа** (narrowing), и TypeScript понимает гораздо больше проверок, чем один `typeof`.

## Набор инструментов для сужения

Два инструмента вы уже знаете из урока [Условия и сужение типов](/learn/typescript/conditions-and-narrowing): проверки `typeof` и проверки на истинность вроде `if (name)` (с их ловушкой: `0` и `""` тоже ложные). Вот ещё четыре.

### Массивы: `Array.isArray`

`typeof` не отличает массив от объекта: `typeof []` — это `"object"`. Используйте вместо него `Array.isArray`:

<CodeExample output={`HELLO
HELLO THERE`}>

```ts
function shout(input: string | string[]): string {
  if (Array.isArray(input)) {
    return input.map((word) => word.toUpperCase()).join(" ");
  }
  return input.toUpperCase();
}

console.log(shout("hello"));
console.log(shout(["hello", "there"]));
```

</CodeExample>

Внутри `if` переменная `input` — это `string[]`. После того как `if` делает `return`, остаётся только `string`.

### Свойства: оператор `in`

`"bark" in pet` проверяет, есть ли у объекта свойство с именем `bark`. TypeScript сужает тип до тех членов объединения, у которых оно есть:

<CodeExample output={`Мурка: Мяу!
Рекс: Гав!`}>

```ts
interface Cat {
  name: string;
  meow(): string;
}

interface Dog {
  name: string;
  bark(): string;
}

function speak(pet: Cat | Dog): string {
  if ("bark" in pet) {
    return `${pet.name}: ${pet.bark()}`; // pet: Dog
  }
  return `${pet.name}: ${pet.meow()}`; // pet: Cat
}

const mo: Cat = { name: "Мурка", meow: () => "Мяу!" };
const rex: Dog = { name: "Рекс", bark: () => "Гав!" };

console.log(speak(mo));
console.log(speak(rex));
```

</CodeExample>

### Классы: `instanceof`

Значения, созданные через `new`, например `Date` или `Error`, можно проверять с помощью `instanceof`:

<CodeExample output={`2026-03-14
завтра`}>

```ts
function formatDate(when: Date | string): string {
  if (when instanceof Date) {
    return when.toISOString().slice(0, 10); // when: Date
  }
  return when; // when: string
}

console.log(formatDate(new Date(Date.UTC(2026, 2, 14))));
console.log(formatDate("завтра"));
```

</CodeExample>

### Равенство: `===`

Когда вы сравниваете два значения через `===`, TypeScript знает, что внутри `if` у них должен быть **одинаковый** тип. Здесь единственный общий тип, который могут иметь `a` и `b`, — это `string`:

<CodeExample output={`AB-12
разные`}>

```ts
function sameId(a: string | number, b: string | boolean): string {
  if (a === b) {
    // Только строка может быть в обоих объединениях
    return a.toUpperCase(); // a: string, b: string
  }
  return "разные";
}

console.log(sameId("ab-12", "ab-12"));
console.log(sameId(12, true));
```

</CodeExample>

Этим вы давно пользуетесь, сами того не замечая: `if (value === null)` — это тоже сужение через равенство.

| Проверка | Для чего подходит |
| --- | --- |
| `typeof x === "string"` | `string`, `number`, `boolean`, `undefined`, `function` |
| `Array.isArray(x)` | массивы (`typeof` говорит `"object"`) |
| `"prop" in x` | объекты, которые различаются свойствами |
| `x instanceof Date` | значения, созданные через `new` из класса |
| `x === null`, `x === y` | точные значения, включая `null` и `undefined` |
| `if (x)` | исключение `null` и `undefined`, когда `0` и `""` неважны |

## TypeScript следит за вашим кодом

Сужение — это не магия, привязанная к `if`. TypeScript читает код сверху вниз, как внимательный коллега, и отслеживает, чем каждая переменная **может** быть на каждой строке. Это называется **анализом потока управления** (control-flow analysis), и он понимает больше, чем можно подумать.

**Присваивания сужают тип.** Переменная, объявленная как `string | number`, сразу после присваивания ей строки — это `string`:

<CodeExample output={`2
42.0`}>

```ts
let input: string | number = "42";
console.log(input.length); // input: string

input = Number(input);
console.log(input.toFixed(1)); // input: number
```

</CodeExample>

После второго присваивания `input.length` был бы ошибкой: TypeScript знает, что теперь в `input` лежит число.

**Ранние выходы сужают тип.** `return` и `throw` завершают ветку, поэтому всё, что в ней обработано, исчезает до конца функции. Здесь сначала отбрасывается `null`, затем строки превращаются в числа, так что любой путь доходит до последней строки с числом:

<CodeExample output={`31
42
Ой: Укажите возраст`}>

```ts
function parseAge(input: string | number | null): number {
  if (input === null) {
    throw new Error("Укажите возраст");
  }
  // null исчез: input — это string | number
  if (typeof input === "string") {
    input = Number.parseInt(input, 10); // теперь input: number
  }
  // Здесь оба пути заканчиваются числом
  return input;
}

console.log(parseAge(31));
console.log(parseAge("42"));
try {
  parseAge(null);
} catch (error) {
  if (error instanceof Error) {
    console.log("Ой:", error.message);
  }
}
```

</CodeExample>

Обратите внимание на `instanceof Error` в `catch`: в TypeScript пойманная ошибка `error` может быть чем угодно (в JavaScript можно написать `throw "oops"`), поэтому её сужают, прежде чем читать `.message`.

<Callout type="tip" title="Сначала разберитесь с неудобными случаями">

Проверку на `null`, пустой или некорректный ввод в **начале** функции с немедленным `return` (или `throw`) называют **защитным условием** (guard clause). Каждое такое условие ещё немного сужает тип, и основной код внизу работает с чистым и простым типом. К тому же это читается легче, чем глубоко вложенные блоки `if`/`else`.

</Callout>

## Объединения в массивах

Важно, где стоят скобки. Сравните два типа:

- `(string | number)[]`: **один** массив, каждый элемент которого может быть строкой или числом, вперемешку.
- `string[] | number[]`: **либо** массив только из строк, **либо** массив только из чисел.

Для смешанного списка ответов, где игрок может ввести число или `"skip"` (пропустить), нужен первый вариант. Каждый элемент вы сужаете по ходу дела:

<CodeExample output="Сумма 12, пропущено 2">

```ts
const answers: (string | number)[] = [3, "skip", 5, "skip", 4];

let total = 0;
let skipped = 0;
for (const answer of answers) {
  if (typeof answer === "number") {
    total += answer;
  } else {
    skipped++;
  }
}

console.log(`Сумма ${total}, пропущено ${skipped}`);
```

</CodeExample>

Второй тип строже, поэтому смешанный массив в нём не допускается:

```ts
const scores: string[] | number[] = [1, "a"];
// ❌ Error: Type '(string | number)[]' is not assignable to type 'string[] | number[]'.
```

В `string[] | number[]` ещё и неудобно добавлять элементы: TypeScript не знает, какой это массив, поэтому не даст сделать `push` ни строки, ни числа, пока вы не сузите тип. Если элементы могут быть вперемешку, вам нужен `(string | number)[]`.

## Отсутствующие значения: `null` и `undefined` в объединениях

Со **строгими проверками на null** (strict null checks; на PandaDev они включены всегда, как и в любом современном проекте) `null` и `undefined` — просто члены объединения, как и любые другие. Они встречаются чаще, чем можно подумать:

- `find` возвращает `T | undefined`: возможно, ничего не нашлось.
- Необязательное свойство `address?: Address` имеет тип `Address | undefined`.
- Ваши собственные функции возвращают `T | null`, когда «нет результата» — нормальный ответ.

TypeScript не даст о них забыть:

```ts
function cityOf(name: string): string {
  const customer = customers.find((c) => c.name === name);
  return customer.address.city;
  // ❌ Error: 'customer' is possibly 'undefined'.
  // ❌ Error: 'customer.address' is possibly 'undefined'.
}
```

Опциональная цепочка `?.` и оператор `??` (из урока [any, unknown, null и undefined](/learn/typescript/special-types)) обрабатывают целую цепочку возможно отсутствующих значений в одну строку:

<CodeExample output={`Leeds
Город неизвестен
Город неизвестен`}>

```ts
interface Address {
  city: string;
  postcode?: string; // string | undefined
}

interface Customer {
  name: string;
  address?: Address; // Address | undefined
}

const customers: Customer[] = [
  { name: "Mei", address: { city: "Leeds", postcode: "LS1" } },
  { name: "Sam" },
];

function cityOf(name: string): string {
  const customer = customers.find((c) => c.name === name);
  // customer: Customer | undefined
  return customer?.address?.city ?? "Город неизвестен";
}

console.log(cityOf("Mei"));
console.log(cityOf("Sam"));
console.log(cityOf("Ana"));
```

</CodeExample>

`customer?.address?.city` имеет тип `string | undefined`: цепочка останавливается на первом отсутствующем значении. Затем `?? "Город неизвестен"` заменяет `undefined` запасным значением, и результат становится обычной `string` — ровно тем, что обещает возвращаемый тип.

<Callout type="warning" title="Не ставьте ?. везде подряд">

`?.` нужен для значений, которые **законно** могут отсутствовать. Если расставлять его повсюду «на всякий случай», он прячет настоящие ошибки: вместо понятной ошибки там, где данные испортились, вы получаете тихий `undefined`, который всплывает где-то совсем в другом месте гораздо позже. Если значение должно быть всегда, лучше исправьте его тип.

</Callout>

Магазин получает цены из нескольких старых систем, и каждая присылает их в своей форме. Напишите одну функцию `formatPrice(input)`, которая справится со всеми. Магазин британский, поэтому подписи на ценниках — на английском.

В заготовке есть **ошибки типов**: `PriceInput` допускает только `number`. Сначала расширьте его до объединения всех шести форм, а затем возвращайте:

| Ввод | Пример | Подпись |
| --- | --- | --- |
| число | `12.5` | `"£12.50"` |
| строка (готовая подпись) | `"Free"` | `"Free"` (без изменений) |
| список чисел | `[2, 3.5]` | `"£5.50 (2 items)"`, или `"(1 item)"` для одного |
| объект `Money` | `{ amount: 9, currency: "EUR" }` | `"9.00 EUR"` |
| `null` или `undefined` | `null` | `"Price on request"` (цена по запросу) |

Осторожно с `0` и `""`: это настоящие цены, а не отсутствующие.

<Hint>

Начните с защитного условия для отсутствующих случаев: `if (input === null || input === undefined)`. Не используйте `if (!input)`: оно поймает ещё и `0` и `""`. Затем используйте `typeof` для чисел и строк и `Array.isArray` для списка (сложите элементы циклом `for...of`). После этих проверок TypeScript знает, что остался только `Money`, поэтому `input.amount` и `input.currency` просто работают. Для двух знаков после запятой используйте `toFixed(2)`.

</Hint>

<Solution>

```ts
interface Money {
  amount: number;
  currency: string;
}

type PriceInput =
  | number
  | string
  | number[]
  | Money
  | null
  | undefined;

function formatPrice(input: PriceInput): string {
  if (input === null || input === undefined) {
    return "Price on request";
  }
  if (typeof input === "number") {
    return "£" + input.toFixed(2);
  }
  if (typeof input === "string") {
    return input;
  }
  if (Array.isArray(input)) {
    let total = 0;
    for (const price of input) {
      total += price;
    }
    const items = input.length === 1 ? "item" : "items";
    return `£${total.toFixed(2)} (${input.length} ${items})`;
  }
  // Остался только Money
  return `${input.amount.toFixed(2)} ${input.currency}`;
}

console.log(formatPrice(12.5)); // £12.50
console.log(formatPrice(0)); // £0.00
console.log(formatPrice("Free")); // Free
console.log(formatPrice([2, 3.5])); // £5.50 (2 items)
console.log(formatPrice({ amount: 9, currency: "EUR" }));
// 9.00 EUR
console.log(formatPrice(null)); // Price on request
console.log(formatPrice(undefined)); // Price on request
```

</Solution>

</Exercise>

## Итоги

- **Объединение** `A | B` может сочетать любые типы: объекты, массивы, `null`, `undefined` и многое другое.
- Без сужения можно использовать только то, что есть у **каждого** члена объединения.
- Инструменты сужения: `typeof`, проверка на истинность, `===`, `Array.isArray`, `"prop" in x` и `instanceof`.
- **Анализ потока управления** отслеживает типы строка за строкой: присваивания, `return` и `throw` — всё это сужает тип.
- `(string | number)[]` — один смешанный массив; `string[] | number[]` — массив либо одного вида, либо другого.
- `find`, необязательные свойства и функции без результата дают `T | undefined` или `T | null`; обрабатывайте их защитными условиями, `?.` и `??`.
