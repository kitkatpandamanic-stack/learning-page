В прошлом уроке вы писали обобщённые **функции**. Та же идея работает для **типов** и **классов**: опишите форму один раз, поставьте параметр типа туда, где нужны детали, и заполните его позже. Так устроены `Array<T>`, `Record<K, V>` и `Map<K, V>`, а к концу урока вы напишете собственный `Result<T, E>` и обобщённый `Stack<T>`. 📦

## Обобщённые псевдонимы типов и интерфейсы

Добавьте параметр типа после имени интерфейса (interface) или псевдонима типа (type alias) и используйте его внутри:

<CodeExample output={`{ value: 28, label: 'возраст' }
{ first: 'Mei', second: 120 }
Sam`}>

```ts
interface Box<T> {
  value: T;
  label: string;
}

type Pair<A, B> = {
  first: A;
  second: B;
};

type Nullable<T> = T | null;

const age: Box<number> = { value: 28, label: "возраст" };
const score: Pair<string, number> = { first: "Mei", second: 120 };
let winner: Nullable<string> = null;
winner = "Sam";

console.log(age);
console.log(score);
console.log(winner);
```

</CodeExample>

`Box<number>` — это `Box`, у которого `value` имеет тип `number`, а `Box<string[]>` хранил бы список строк. Одно отличие от обобщённых функций: в аннотации типа TypeScript **не** угадывает аргумент типа за вас. Его нужно написать:

```ts
const b: Box = { value: 1, label: "x" };
// ❌ Error: Generic type 'Box<T>' requires 1 type argument(s).
```

Обобщённые типы и обобщённые функции отлично работают вместе. Многие API отдают длинные списки по одной **странице** за раз. `Page<T>` описывает страницу чего угодно, а `paginate` собирает её из любого списка:

<CodeExample output={`{ items: [ 'Leeds', 'Lagos' ], page: 2, totalPages: 3 }
[ 5 ]`}>

```ts
interface Page<T> {
  items: T[];
  page: number;
  totalPages: number;
}

function paginate<T>(all: T[], page: number, size: number): Page<T> {
  const start = (page - 1) * size;
  return {
    items: all.slice(start, start + size),
    page,
    totalPages: Math.ceil(all.length / size),
  };
}

const cities = ["Lima", "Oslo", "Leeds", "Lagos", "Rome"];
console.log(paginate(cities, 2, 2)); // Page<string>
console.log(paginate([1, 2, 3, 4, 5], 3, 2).items); // number[]
```

</CodeExample>

## `Result<T, E>`: обобщённое размеченное объединение

Вот один из самых полезных обобщённых типов, какие вам доведётся написать. Функция, которая может завершиться неудачей, возвращает либо **значение**, либо **ошибку**. Опишите это как объединение с меткой `ok` и сделайте обе стороны обобщёнными:

```ts
type Result<T, E = string> =
  | { ok: true; value: T }
  | { ok: false; error: E };
```

`T` — тип успешного значения, а `E` — тип ошибки. `E = string` — это **значение по умолчанию**, поэтому `Result<number>` означает `Result<number, string>`. Поскольку `ok` — метка (`true` или `false`), её проверка сужает результат, как в любом другом [размеченном объединении](/learn/typescript/discriminated-unions) (discriminated union):

<CodeExample output={`В следующем году вам будет 29
Ошибка: "-3" — это не возраст
Ошибка: "old" — это не возраст`}>

```ts
type Result<T, E = string> =
  | { ok: true; value: T }
  | { ok: false; error: E };

function parseAge(text: string): Result<number> {
  const age = Number(text);
  if (!Number.isInteger(age) || age < 0) {
    return { ok: false, error: `"${text}" — это не возраст` };
  }
  return { ok: true, value: age };
}

for (const input of ["28", "-3", "old"]) {
  const result = parseAge(input);
  if (result.ok) {
    console.log(`В следующем году вам будет ${result.value + 1}`);
  } else {
    console.log(`Ошибка: ${result.error}`);
  }
}
```

</CodeExample>

Вызывающий код **не может забыть**, что разбор может не удаться. Читать `value` до проверки `ok` — ошибка, потому что у неудачного результата нет `value`:

```ts
const result = parseAge("28");
console.log(result.value);
// ❌ Error: Property 'value' does not exist on type 'Result<number, string>'.
```

Сторона ошибки не обязана быть строкой. Объединение литералов точно говорит вызывающему коду, что может пойти не так: `Result<User, "not-found" | "banned">`. Это пригодится вам в мини-проекте этого модуля.

<Callout type="tip" title="Result или throw">

Выброшенное исключение не видно в типе функции: ничто в `parseAge(text: string): number` не предупреждает, что она может бросить ошибку. `Result` помещает неудачу **в тип**, и TypeScript напоминает каждому вызывающему коду её обработать. Используйте `Result` для неудач, которые случаются в обычной жизни (неверный ввод, отсутствующая запись), а `throw` оставьте для настоящих багов.

</Callout>

Тот же приём работает для любого набора состояний. Данные с сервера либо загружаются, либо загружены, либо не загрузились. Один обобщённый тип покрывает любые данные, и одна обобщённая функция может описать их все:

<CodeExample output={`Загрузка…
Сообщений: 3
Что-то пошло не так: Сервер не отвечает
Сейчас 14°C`}>

```ts
type RemoteData<T> =
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; message: string };

function describe<T>(
  state: RemoteData<T>,
  show: (data: T) => string,
): string {
  switch (state.status) {
    case "loading":
      return "Загрузка…";
    case "success":
      return show(state.data);
    case "error":
      return `Что-то пошло не так: ${state.message}`;
  }
}

const inbox: RemoteData<string[]> = {
  status: "success",
  data: ["Привет", "Обедать?", "До встречи"],
};
const failed: RemoteData<string[]> = {
  status: "error",
  message: "Сервер не отвечает",
};
const weather: RemoteData<{ temp: number }> = {
  status: "success",
  data: { temp: 14 },
};

const count = (list: string[]) => `Сообщений: ${list.length}`;
console.log(describe({ status: "loading" }, count));
console.log(describe(inbox, count));
console.log(describe(failed, count));
console.log(describe(weather, (w) => `Сейчас ${w.temp}°C`));
```

</CodeExample>

## Обобщённые классы

У [класса](/learn/typescript/classes-and-access-modifiers) тоже могут быть параметры типа. Поставьте их после имени класса — и ими смогут пользоваться все поля и методы. Вот **стек** (stack): последний добавленный элемент извлекается первым, как в стопке тарелок (или как кнопка «Назад» в браузере):

<CodeExample output={`/basket
/shop
2`}>

```ts
class Stack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T | undefined {
    return this.items.pop();
  }

  peek(): T | undefined {
    return this.items[this.items.length - 1];
  }

  get size(): number {
    return this.items.length;
  }
}

const history = new Stack<string>();
history.push("/home");
history.push("/shop");
history.push("/basket");

console.log(history.pop());
console.log(history.peek());
console.log(history.size);
```

</CodeExample>

`new Stack<string>()` создаёт стек строк, и об этом знает каждый метод: `pop()` возвращает `string | undefined`, а попытка положить что-то не то ловится:

```ts
history.push(42);
// ❌ Error: Argument of type 'number' is not assignable to parameter of type 'string'.
```

Когда конструктор принимает `T`, TypeScript выводит его, как и в обобщённых функциях. Когда не принимает, как `new Stack()` без аргументов, выводить не из чего, и `T` становится `unknown`. Поэтому всегда пишите аргумент типа, когда создаёте пустую коллекцию.

<Callout type="note" title="Map — тоже обобщённый класс">

Встроенный в JavaScript `Map` хранит пары «ключ — значение», и TypeScript типизирует его как `Map<K, V>`. В отличие от `Record`, его метод `get` честно сообщает об отсутствующих ключах:

```ts
const stock = new Map<string, number>();
stock.set("tea", 12);
const cake = stock.get("cake"); // number | undefined
stock.set("cake", "3");
// ❌ Error: Argument of type 'string' is not assignable to parameter of type 'number'.
```

Дополняют картину `has(key)`, `delete(key)`, `size` и `values()`. `Set<T>` (коллекция уникальных значений) обобщён точно так же.

</Callout>

## Ограничения в классах

Ограничения (constraints) работают в классах так же, как в функциях. Этой таблице лидеров нужен `score` для сортировки и `name` для показа, но она хранит **полный** тип того, что вы в неё кладёте, поэтому дополнительные свойства вроде `country` никуда не деваются, когда вы получаете записи обратно:

<CodeExample output={`Ana (BR): 150
Mei (CN): 120`}>

```ts
class Leaderboard<T extends { name: string; score: number }> {
  private entries: T[] = [];

  add(entry: T): void {
    this.entries.push(entry);
  }

  top(count: number): T[] {
    return [...this.entries]
      .sort((a, b) => b.score - a.score)
      .slice(0, count);
  }
}

interface Player {
  name: string;
  score: number;
  country: string;
}

const board = new Leaderboard<Player>();
board.add({ name: "Mei", score: 120, country: "CN" });
board.add({ name: "Sam", score: 95, country: "NG" });
board.add({ name: "Ana", score: 150, country: "BR" });

for (const p of board.top(2)) {
  console.log(`${p.name} (${p.country}): ${p.score}`);
}
```

</CodeExample>

Тип, который не подходит под ограничение, отклоняется сразу при создании экземпляра класса:

```ts
const broken = new Leaderboard<{ name: string }>();
// ❌ Error: Type '{ name: string; }' does not satisfy the constraint '{ name: string; score: number; }'.
```

## Массивы только для чтения: `ReadonlyArray<T>`

Классы вроде `Stack` и `Leaderboard` держат свой список `private`, чтобы никто не мог испортить его снаружи. Но что, если вызывающему коду нужно **видеть** элементы? Если вернуть сам массив, в ваши приватные данные можно будет тайком сделать `push`.

Решение — тип только для чтения. На Уровне 0 вы встречали [`readonly string[]`](/learn/typescript/arrays-and-tuples). `ReadonlyArray<T>` — тот же тип, записанный как дженерик, и у обоих нет `push`, `pop`, `sort` и других методов, изменяющих массив:

```ts
class Playlist<T> {
  private songs: T[] = [];

  add(song: T): void {
    this.songs.push(song);
  }

  get all(): ReadonlyArray<T> {
    return [...this.songs]; // копия с типом только для чтения
  }
}

const playlist = new Playlist<string>();
playlist.add("Panda Blues");
playlist.all.push("Sneaky song");
// ❌ Error: Property 'push' does not exist on type 'readonly string[]'.
```

Массивы только для чтения — ещё и лучший тип для **параметров**, которые список только читают. Функция с параметром `readonly number[]` принимает и обычные массивы, и массивы только для чтения, а функция с `number[]` отказывается от последних, потому что *могла бы* их изменить:

<CodeExample output={`12.5
6`}>

```ts
function total(prices: readonly number[]): number {
  let sum = 0;
  for (const p of prices) {
    sum += p;
  }
  return sum;
}

const basket: number[] = [4.5, 8];
const fixed: ReadonlyArray<number> = [1, 2, 3];

console.log(total(basket)); // обычный массив подходит
console.log(total(fixed)); // и массив только для чтения тоже
```

</CodeExample>

<Callout type="warning" title="Только для чтения — обещание на этапе компиляции">

Как и любой тип, `readonly` исчезает при запуске кода. Если вы отдаёте свой приватный массив с типом `ReadonlyArray<T>`, обычный JavaScript (или хитрое приведение `as`) всё равно может его изменить. Поэтому `Playlist` возвращает **копию**: тип останавливает честные ошибки, а копия защищает данные в любом случае.

</Callout>

Копицентру нужна **очередь** (queue): задания печатаются в том порядке, в каком пришли (первым пришёл — первым ушёл), — противоположность стеку. `Queue` в заготовке использует `any`, поэтому принимает что угодно и ничего не проверяет. Сделайте её обобщённой и допишите:

1. Превратите её в `class Queue<T>` и замените каждый `any` правильным типом.
2. `enqueue(item)` добавляет элемент в **конец**.
3. `dequeue()` удаляет **первый** элемент и возвращает `{ ok: true, value: item }` или `{ ok: false, error: "Очередь пуста" }`, если удалять нечего.
4. `peek()` возвращает первый элемент, не удаляя его (`undefined`, если очередь пуста), а `size` — количество элементов.
5. `toArray()` возвращает **копию** элементов, начиная с первого, с типом массива только для чтения.

Тесты типов внизу написаны для готовой `Queue<T>`: строки с `// @ts-expect-error` проходят, только если строка под ними **является** ошибкой.

<Hint>

Начните с `class Queue<T>` и `private items: T[] = [];`. `enqueue` — это `push`. В `dequeue` сначала верните результат с ошибкой, если `this.items.length === 0`. Иначе прочитайте первый элемент через `this.items[0]`, а затем удалите его через `this.items.shift()`. (Взять значение, которое возвращает `shift()`, напрямую не получится: его тип — `T | undefined`, а `value` должен быть `T`.) В `toArray` верните `[...this.items]` с возвращаемым типом `readonly T[]` (или `ReadonlyArray<T>`).

</Hint>

<Solution>

```ts
type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E };

interface PrintJob {
  file: string;
  pages: number;
}

class Queue<T> {
  private items: T[] = [];

  enqueue(item: T): void {
    this.items.push(item);
  }

  dequeue(): Result<T, string> {
    if (this.items.length === 0) {
      return { ok: false, error: "Очередь пуста" };
    }
    const item = this.items[0];
    this.items.shift();
    return { ok: true, value: item };
  }

  peek(): T | undefined {
    return this.items[0];
  }

  get size(): number {
    return this.items.length;
  }

  toArray(): readonly T[] {
    return [...this.items];
  }
}

// ===== Тесты типов: ниже ничего не меняйте =====
const test = new Queue<PrintJob>();
// @ts-expect-error: в эту очередь можно ставить только задания печати
test.enqueue("notes.txt");
// @ts-expect-error: копия только для чтения
test.toArray().push({ file: "x.pdf", pages: 1 });

const jobs = new Queue<PrintJob>();
jobs.enqueue({ file: "report.pdf", pages: 12 });
jobs.enqueue({ file: "photo.png", pages: 1 });
const next = jobs.dequeue();
if (next.ok) {
  const pages: number = next.value.pages;
  console.log(`Печатаю ${next.value.file} (страниц: ${pages})`);
} else {
  console.log(next.error);
}
console.log(jobs.size, jobs.peek());
// Печатаю report.pdf (страниц: 12)
// 1 { file: 'photo.png', pages: 1 }
```

</Solution>

## Итоги

- У интерфейсов и псевдонимов типов могут быть параметры типа: `Box<T>`, `Pair<A, B>`, `Page<T>`. В аннотациях аргумент типа нужно писать явно.
- `Result<T, E>` — обобщённое размеченное объединение: проверяйте `ok`, прежде чем читать `value` или `error`, и неудачу уже не проигнорировать.
- Обобщённые объединения вроде `RemoteData<T>` описывают состояния (загрузка, успех, ошибка) для любых данных.
- Обобщённые классы (`Stack<T>`, `Queue<T>`, встроенный `Map<K, V>`) держат все методы в согласии с одним типом элементов.
- Ограничения (`T extends { score: number }`) работают и в классах, а полный тип `T` сохраняется.
- `ReadonlyArray<T>` (`readonly T[]`) позволяет отдавать списки, которые нельзя случайно изменить; используйте его для параметров, которые только читают, и возвращайте копии приватных данных.
