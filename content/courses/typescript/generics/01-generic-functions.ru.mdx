Вы уже пользовались дженериками, даже не написав ни одного: `Array<string>`, `Record<string, number>` и `Partial<Contact>` — это **обобщённые типы** (generic types), то есть типы, которые принимают на вход другой тип. В этом уроке вы напишете собственные **обобщённые функции** (generic functions): одну функцию, которая работает с числами, строками, пользователями и чем угодно ещё и при этом точно знает, что в неё входит и что из неё выходит. 🧩

## Проблема: одна задача, много типов

Вот крошечная задача: вернуть первый элемент списка. С тем, что вы знаете сейчас, пришлось бы писать её заново для каждого типа:

<CodeExample output={`3
Mei`}>

```ts
function firstNumber(items: number[]): number | undefined {
  return items[0];
}

function firstString(items: string[]): string | undefined {
  return items[0];
}

console.log(firstNumber([3, 1, 2]));
console.log(firstString(["Mei", "Sam"]));
```

</CodeExample>

Тела у функций одинаковые. Различаются только типы, и для третьего вида списка понадобится третья копия. Можно попробовать сбежать в `any`, но это выключает проверку. TypeScript понятия не имеет, что вернётся, и спокойно пропускает ошибку:

```ts
function firstAny(items: any[]): any {
  return items[0];
}

const n = firstAny([3, 1, 2]);
n.toUpperCase(); // ошибки нет... 💥 падает при запуске
```

`unknown` безопасен, но теперь с результатом ничего нельзя сделать без проверки, хотя вы *знаете*, что это число:

```ts
function firstUnknown(items: unknown[]): unknown {
  return items[0];
}

const u = firstUnknown([1.5, 2]);
console.log(u.toFixed(1));
// ❌ Error: 'u' is of type 'unknown'.
```

Нам нужен способ сказать: «элемент на выходе имеет **тот же тип**, что и элементы на входе, каким бы этот тип ни был».

## Параметры типа

Именно это и делает **параметр типа** (type parameter). Его пишут в угловых скобках после имени функции, а потом используют как любой другой тип:

<CodeExample output={`3.0
MEI
[ true ]`}>

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}

function wrap<T>(value: T): T[] {
  return [value];
}

const n = first([3, 1, 2]); // T — это number
const who = first(["Mei", "Sam"]); // T — это string
const flags = wrap(true); // T — это boolean

console.log(n?.toFixed(1));
console.log(who?.toUpperCase());
console.log(flags);
```

</CodeExample>

Читайте `first<T>` как «first для некоторого типа `T`». `T` — это заполнитель, так же как обычный параметр — заполнитель для значения. При каждом вызове функции TypeScript подставляет вместо `T` конкретный тип: `number` в первом вызове и `string` во втором. Поэтому `n` имеет тип `number | undefined`, и вызов `.toUpperCase()` на нём был бы ошибкой — как и должно быть.

Функцию с параметром типа называют **обобщённой функцией**, или дженериком. Имя `T` (от type — «тип») — всего лишь соглашение. Подойдёт любое имя, а длинные имена вроде `Item` отлично выручают, когда параметров несколько.

<Callout type="note" title="Типы по-прежнему исчезают">

Параметры типа существуют только на этапе компиляции. Во время выполнения `first` — обычная функция JavaScript. Дженерики не делают код медленнее или больше, они только делают проверку типов умнее.

</Callout>

## Вывод или явные аргументы типа

Чаще всего при вызове обобщённой функции вы вообще не пишете `T`: TypeScript **выводит** (infers) его из аргументов. Но его *можно* передать явно в угловых скобках, и тогда TypeScript сверит с ним аргументы:

```ts
first<string>([1, 2]);
// ❌ Error: Type 'number' is not assignable to type 'string'.
```

Явный аргумент типа нужен, когда аргументы рассказывают не всё. Здесь `fill` создаёт список заданной длины. `fill(3, 0)` — очевидно `number[]`, но для пустых мест в кинотеатре `fill(4, null)` выведет `T` как `null`, и посадить на место человека будет нельзя:

```ts
const seats = fill(4, null);
seats[1] = "Mei";
// ❌ Error: Type '"Mei"' is not assignable to type 'null'.
```

Скажите, что имеете в виду, с помощью `<string | null>`:

<CodeExample output={`[ 0, 0, 0 ]
[ null, 'Mei', null, null ]`}>

```ts
function fill<T>(length: number, value: T): T[] {
  return Array.from({ length }, () => value);
}

const zeros = fill(3, 0); // number[]
const seats = fill<string | null>(4, null); // (string | null)[]
seats[1] = "Mei";

console.log(zeros);
console.log(seats);
```

</CodeExample>

<Callout type="tip" title="Пусть работает вывод типов">

Начинайте без аргументов типа. Добавляйте их, только если TypeScript выводит слишком узкий тип (как `null` выше) или ему не из чего выводить (такой случай вы увидите ниже, в разделе «Параметры типа по умолчанию»).

</Callout>

## Несколько параметров типа

У функции может быть столько параметров типа, сколько нужно, — через запятую. `pair` хранит вместе два значения двух разных типов, а `swap` меняет их местами, так что типы тоже меняются местами:

<CodeExample output={`[ 'Mei', 28 ]
[ 28, 'Mei' ]
28.0`}>

```ts
function pair<A, B>(first: A, second: B): [A, B] {
  return [first, second];
}

function swap<A, B>(p: [A, B]): [B, A] {
  return [p[1], p[0]];
}

const person = pair("Mei", 28); // [string, number]
const flipped = swap(person); // [number, string]

console.log(person);
console.log(flipped);
console.log(flipped[0].toFixed(1));
```

</CodeExample>

Эти функции возвращают [кортежи](/learn/typescript/arrays-and-tuples), поэтому TypeScript знает, что `flipped[0]` — это `number`, а `flipped[1]` — `string`.

## Ограничения с `extends`

Внутри обобщённой функции TypeScript разрешает только то, что работает для **любого** возможного `T`. Это мешает, когда вам нужно что-то конкретное, например `id`:

```ts
function findById<T>(items: T[], id: string): T | undefined {
  return items.find((item) => item.id === id);
  // ❌ Error: Property 'id' does not exist on type 'T'.
}
```

TypeScript прав: `T` может оказаться `number`, а у чисел нет `id`. **Ограничение** (constraint) сужает круг типов, которыми может быть `T`. `T extends { id: string }` означает «любой тип, лишь бы у него был строковый `id`»:

<CodeExample output={`3.5
pro`}>

```ts
interface Product {
  id: string;
  name: string;
  price: number;
}

interface Member {
  id: string;
  name: string;
  plan: "free" | "pro";
}

function findById<T extends { id: string }>(
  items: T[],
  id: string,
): T | undefined {
  return items.find((item) => item.id === id);
}

const products: Product[] = [
  { id: "p1", name: "Tea", price: 3.5 },
  { id: "p2", name: "Cake", price: 4 },
];
const members: Member[] = [{ id: "m1", name: "Mei", plan: "pro" }];

const tea = findById(products, "p1"); // Product | undefined
console.log(tea?.price);

const mei = findById(members, "m1"); // Member | undefined
console.log(mei?.plan);
```

</CodeExample>

Почему бы просто не написать `items: { id: string }[]` без дженерика? Потому что тогда результат был бы просто `{ id: string }`, а всё остальное о товаре забылось бы:

```ts
function findAny(items: { id: string }[], id: string) {
  return items.find((item) => item.id === id);
}

const tea = findAny(products, "p1"); // { id: string } | undefined
console.log(tea?.price);
// ❌ Error: Property 'price' does not exist on type '{ id: string; }'.
```

Обобщённая версия **запоминает** полный тип, который вы передали. А элементы без `id` по-прежнему отклоняются:

```ts
const pets = [{ name: "Mo" }];
findById(pets, "1");
// ❌ Error: Argument of type '{ name: string; }[]' is not assignable to parameter of type '{ id: string; }[]'.
```

Ограничения работают с любыми типами. `T extends { length: number }` принимает и строки, и массивы, потому что у обоих есть `length`:

<CodeExample output={`panda
[ 1, 2, 3 ]`}>

```ts
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}

console.log(longest("panda", "fox"));
console.log(longest([1, 2], [1, 2, 3]));
```

</CodeExample>

## `keyof` и `T[K]`

Два маленьких оператора типов делают дженерики по-настоящему мощными при работе с объектами:

- **`keyof T`** — объединение имён свойств `T`. Для `User` с полями `id`, `name` и `age` тип `keyof User` равен `"id" | "name" | "age"`.
- **`T[K]`** — это **индексированный доступ к типу** (indexed access type): тип свойства `K` в `T`. `User["age"]` — это `number`.

Соедините их — и получится функция, которая читает любое свойство и возвращает его точный тип:

<CodeExample output={`29
MEI`}>

```ts
interface User {
  id: string;
  name: string;
  age: number;
}

type UserKey = keyof User; // "id" | "name" | "age"
type Age = User["age"]; // number

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const mei: User = { id: "u1", name: "Mei", age: 28 };

const age = getProperty(mei, "age"); // number
const name = getProperty(mei, "name"); // string

console.log(age + 1);
console.log(name.toUpperCase());
```

</CodeExample>

`K extends keyof T` — это ограничение, которое использует **первый** параметр типа: «`K` должен быть одним из ключей `T`». Поэтому опечатка в ключе ловится, а редактор даже подсказывает список допустимых ключей:

```ts
getProperty(mei, "emial");
// ❌ Error: Argument of type '"emial"' is not assignable to parameter of type 'keyof User'.
```

## Обобщённые колбэки

Дженерики особенно хороши, когда вы передаёте [колбэки](/learn/typescript/arrow-functions-and-callbacks). Вот самодельные `map` и `filter`. Функции `mapItems` нужны два параметра типа: `T` для входящих элементов и `U` для того, что возвращает колбэк:

<CodeExample output={`[ '£4.50', '£12.00', '£7.25' ]
[ 4.5, 7.25 ]`}>

```ts
function mapItems<T, U>(items: T[], fn: (item: T) => U): U[] {
  const result: U[] = [];
  for (const item of items) {
    result.push(fn(item));
  }
  return result;
}

function filterItems<T>(
  items: T[],
  keep: (item: T) => boolean,
): T[] {
  const result: T[] = [];
  for (const item of items) {
    if (keep(item)) {
      result.push(item);
    }
  }
  return result;
}

const prices = [4.5, 12, 7.25];

const labels = mapItems(prices, (p) => `£${p.toFixed(2)}`);
const cheap = filterItems(prices, (p) => p < 10);

console.log(labels); // string[]
console.log(cheap); // number[]
```

</CodeExample>

Проследите, как «текут» типы. Из `prices` TypeScript выводит `T = number`. Отсюда параметр колбэка `p` получает тип `number` (аннотация не нужна), а колбэк возвращает строку, значит `U = string` и `labels` — это `string[]`. Именно так типизированы настоящие методы массивов `map` и `filter`.

## Параметры типа по умолчанию

Иногда выводить не из чего. `createInbox()` не принимает аргументов, поэтому TypeScript не может угадать, какие сообщения там будут храниться. Без подсказки `T` становится `unknown`, и пользоваться сообщениями неудобно:

```ts
const chat = createInbox();
chat.send("Hi!");
console.log(chat.all()[0].toUpperCase());
// ❌ Error: Object is of type 'unknown'.
```

**Параметр типа по умолчанию** (default type parameter, `T = string`) говорит, каким должен быть `T`, если никто не указал иного. Другой тип по-прежнему можно выбрать явно:

<CodeExample output={`[ 'Привет!', 'Обедать?' ]
[ { level: 2, text: 'Диск почти заполнен' } ]`}>

```ts
function createInbox<T = string>() {
  const messages: T[] = [];
  return {
    send(message: T) {
      messages.push(message);
    },
    all() {
      return messages;
    },
  };
}

const chat = createInbox(); // T = string (по умолчанию)
chat.send("Привет!");
chat.send("Обедать?");

const alerts = createInbox<{ level: number; text: string }>();
alerts.send({ level: 2, text: "Диск почти заполнен" });

console.log(chat.all());
console.log(alerts.all());
```

</CodeExample>

Значения по умолчанию ещё чаще встречаются у обобщённых **типов** — их вы будете писать в следующем уроке.

## Когда дженерик НЕ нужен

Дженерики — это весело, и их хочется добавлять везде. Хорошее эмпирическое правило: **параметр типа должен встречаться хотя бы дважды**. Он нужен, чтобы связывать вещи, например тип входа с типом выхода. Если он используется лишь один раз, он не делает ничего, чего не сделал бы обычный тип:

```ts
// 🤔 T используется один раз, поэтому ничего не связывает
function printLength<T extends { length: number }>(value: T): void {
  console.log(value.length);
}

// ✅ то же самое, только проще
function printLength(value: { length: number }): void {
  console.log(value.length);
}
```

<Callout type="warning" title="Обобщённый возвращаемый тип может обманывать">

Остерегайтесь параметра типа, который встречается **только в возвращаемом типе**:

```ts
function parseJson<T>(text: string): T {
  return JSON.parse(text);
}

const user = parseJson<User>('{ "nmae": "Mei" }');
// ошибки нет, но это НЕ User!
```

Ничто не проверяет, что разобранные данные действительно `User`. Это замаскированное приведение типа. Данные из внешнего мира разбирайте в `unknown` и [проверяйте защитниками типа](/learn/typescript/type-guards-and-unknown), прежде чем им доверять.

</Callout>

const books: Book[] = [

// Замените каждый any параметрами типа.

function last(items: any[]): any {
  return items[items.length - 1];
}

// 2. Значения одного ключа у всех элементов
function pluck(items: any[], key: any): any[] {
  return items.map((item) => item[key]);
}

function countBy(
  items: any[],
  getKey: (item: any) => string,

  return {};
}

function updateById(items: any[], id: string, changes: any): any[] {

Коллега написал эти помощники для списков с `any`. Они работают, но TypeScript не может проверить ничего, что через них проходит. Сделайте их **обобщёнными** и допишите два тела, которые пока пустые:

1. `last(items)` возвращает последний элемент или `undefined` для пустого массива.
2. `pluck(items, key)` возвращает значение `key` у каждого элемента. `pluck(books, "year")` должен иметь тип `number[]`, а несуществующий ключ должен быть ошибкой.
3. `countBy(items, getKey)` возвращает, сколько элементов дают каждый ключ, например `{ "sci-fi": 2, classic: 1 }`. Внутри колбэка элемент должен иметь свой настоящий тип.
4. `updateById(items, id, changes)` возвращает **новый** массив, в котором к элементу с этим `id` применены `changes`. Разрешены только элементы со строковым `id`, а `changes` должен быть `Partial` от типа элемента.

Строки с `// @ts-expect-error` — это **тесты типов**: они проходят, только если строка под ними действительно **является** ошибкой. С `any` ошибок нет вообще, поэтому TypeScript сообщает "Unused '@ts-expect-error' directive.", пока ваши типы не станут правильными.

<Hint>

1. `last<T>(items: T[]): T | undefined`.
2. Используйте два параметра типа, как у `getProperty` в уроке: `pluck<T, K extends keyof T>(items: T[], key: K): T[K][]`.

interface Book {
  id: string;
  title: string;
  genre: string;
  year: number;
}

const books: Book[] = [
  { id: "b1", title: "Dune", genre: "sci-fi", year: 1965 },
  { id: "b2", title: "Emma", genre: "classic", year: 1815 },
  { id: "b3", title: "Neuromancer", genre: "sci-fi", year: 1984 },
];

function last<T>(items: T[]): T | undefined {
  return items[items.length - 1];
}

function pluck<T, K extends keyof T>(items: T[], key: K): T[K][] {
  return items.map((item) => item[key]);
}

function countBy<T>(
  items: T[],
  getKey: (item: T) => string,
): Record<string, number> {
  const counts: Record<string, number> = {};
  for (const item of items) {
    const key = getKey(item);
    counts[key] = (counts[key] ?? 0) + 1;
  }
  return counts;
}

function updateById<T extends { id: string }>(
  items: T[],
  id: string,
  changes: Partial<T>,
): T[] {
  return items.map((item) =>
    item.id === id ? { ...item, ...changes } : item,
  );
}

// ===== Тесты типов: ниже ничего не меняйте =====
const newest: Book | undefined = last(books);
const years: number[] = pluck(books, "year");
// @ts-expect-error: у Book нет ключа "author"
pluck(books, "author");
const perGenre = countBy(books, (b) => b.genre);
// @ts-expect-error: b — это Book, а у книг нет pages
countBy(books, (b) => b.pages);
const fixed: Book[] = updateById(books, "b2", { year: 1816 });
// @ts-expect-error: year должен быть числом
updateById(books, "b2", { year: "1816" });
// @ts-expect-error: у чисел нет id
updateById([1, 2, 3], "1", {});

console.log(newest?.title); // Neuromancer
console.log(years); // [ 1965, 1815, 1984 ]
console.log(perGenre); // { 'sci-fi': 2, classic: 1 }
console.log(fixed[1]);
// { id: 'b2', title: 'Emma', genre: 'classic', year: 1816 }

## Итоги

- **Параметр типа** вроде `<T>` — это заполнитель для типа, который подставляется при каждом вызове функции.
- Обычно TypeScript **выводит** аргументы типа сам; пишите их явно (`fill<string | null>(...)`), когда вывод слишком узкий или ему не на что опереться.
- У функции может быть несколько параметров типа (`<A, B>`) и **значения по умолчанию** (`<T = string>`) на случай, когда вывести нечего.
- **Ограничения** (`T extends { id: string }`) позволяют пользоваться конкретными свойствами и при этом помнить полный тип.
- `keyof T` — объединение ключей `T`, а `T[K]` — тип одного свойства: `<T, K extends keyof T>` даёт безопасные помощники для работы со свойствами.
- Параметр типа должен что-то связывать: если он встречается лишь раз или только в возвращаемом типе, скорее всего, он не нужен.
