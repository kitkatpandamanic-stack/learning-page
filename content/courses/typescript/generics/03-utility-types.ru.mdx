На Уровне 0 вы использовали [`Partial<T>` и `Record<K, V>`](/learn/typescript/typed-data), чтобы типизировать объекты с изменениями и таблицы поиска. Они входят в целый набор инструментов, который поставляется вместе с TypeScript: **утилитные типы** (utility types) — обобщённые типы, которые принимают один тип и превращают его в другой. В этом уроке вы познакомитесь с самыми полезными из них, каждый — на реальной задаче, а потом соберёте с их помощью обобщённое хранилище данных. 🧰

## Утилитные типы — это обобщённые типы

В утилитных типах нет никакой магии. Это обычные обобщённые типы, записанные в файлах стандартной библиотеки TypeScript. Вот как определён `Partial`:

```ts
type Partial<T> = {
  [K in keyof T]?: T[K];
};
```

Читайте это так: «для каждого ключа `K` из `T` — **необязательное** свойство с тем же типом `T[K]`». `keyof` и `T[K]` вы знаете из урока про [обобщённые функции](/learn/typescript/generic-functions). Часть `[K in ...]` — это **сопоставленный тип** (mapped type); писать такие типы самостоятельно вы научитесь на Уровне 3. А пока важно научиться ими пользоваться.

Зачем выводить типы, а не выписывать их вручную? Потому что выведенный тип **остаётся синхронизированным**. Добавьте свойство в `User` — и каждый построенный на нём тип (`Partial<User>`, `Omit<User, "id">`, ...) обновится сам. С копиями, написанными вручную, пришлось бы не забыть поменять каждую.

## `Partial`, `Required` и `Readonly`

Эти три типа меняют **модификаторы** всех свойств:

- `Partial<T>` делает все свойства необязательными (идеально для объектов с изменениями).
- `Required<T>` делает все свойства обязательными — противоположность `Partial`.
- `Readonly<T>` делает все свойства `readonly`.

`Required` удобен для настроек. Пользователь может задать часть параметров, а остальные вы заполните значениями по умолчанию. После этого каждый параметр гарантированно на месте, и тип должен это отражать:

<CodeExample output={`{ theme: 'dark', pageSize: 20, language: 'en' }
40`}>

```ts
interface Settings {
  theme?: "light" | "dark";
  pageSize?: number;
  language?: string;
}

const defaults: Required<Settings> = {
  theme: "light",
  pageSize: 20,
  language: "en",
};

function resolveSettings(chosen: Settings): Required<Settings> {
  return { ...defaults, ...chosen };
}

const settings = resolveSettings({ theme: "dark" });
console.log(settings);
console.log(settings.pageSize * 2); // число, никогда не undefined
```

</CodeExample>

Без `Required` у `settings.pageSize` был бы тип `number | undefined`, и при каждом использовании понадобилась бы проверка или `??`.

`Readonly<T>` отлично подходит для параметров, которые функция не должна менять. А `Object.freeze` возвращает объект `Readonly`, так что вы получаете защиту во время выполнения **и** ошибку типа ещё до запуска:

```ts
interface Order {
  readonly id: string;
  status: "pending" | "shipped";
}

function printLabel(order: Readonly<Order>) {
  order.status = "shipped";
  // ❌ Error: Cannot assign to 'status' because it is a read-only property.
}

const limits = Object.freeze({ maxItems: 50, maxWeight: 20 });
limits.maxItems = 500;
// ❌ Error: Cannot assign to 'maxItems' because it is a read-only property.
```

<Callout type="note" title="Поверхностно, а не глубоко">

`Partial`, `Required` и `Readonly` меняют только свойства **верхнего уровня**. В `Readonly<User>` нельзя заново присвоить `user.address`, но `user.address.city` по-прежнему можно изменить. Как строить «глубокие» версии, покажет Уровень 3.

</Callout>

## `Pick` и `Omit`: придаём объектам форму

`Pick<T, Keys>` оставляет только некоторые свойства, а `Omit<T, Keys>` оставляет всё, **кроме** некоторых. Они идеально подходят для разных форм, которые одни и те же данные принимают на пути через приложение. Форма регистрации отправляет пользователя без `id` (его создаёт сервер), а публичный профиль никогда не должен содержать хеш пароля:

<CodeExample output={`{
  name: 'Mei',
  email: 'mei@panda.dev',
  passwordHash: 'x8f2',
  id: 'u1',
  createdAt: '2026-03-14'
}
{ id: 'u1', name: 'Mei' }`}>

```ts
interface User {
  id: string;
  name: string;
  email: string;
  passwordHash: string;
  createdAt: string;
}

// Что отправляет форма регистрации: всё, кроме id и createdAt
type NewUser = Omit<User, "id" | "createdAt">;

// Что могут видеть другие люди
type PublicUser = Pick<User, "id" | "name">;

let nextId = 1;

function createUser(input: NewUser): User {
  const id = `u${nextId}`;
  nextId++;
  return { ...input, id, createdAt: "2026-03-14" };
}

function toPublic(user: User): PublicUser {
  return { id: user.id, name: user.name };
}

const mei = createUser({
  name: "Mei",
  email: "mei@panda.dev",
  passwordHash: "x8f2",
});
console.log(mei);
console.log(toPublic(mei));
```

</CodeExample>

Формы вроде `NewUser` и `PublicUser` часто называют **DTO** (data transfer objects, объекты передачи данных): это форма данных, которые перемещаются между частями системы. Если вывести их из `User`, регистрация не сможет протащить собственный `id`:

```ts
createUser({
  id: "admin",
  name: "Mei",
  email: "mei@panda.dev",
  passwordHash: "x8f2",
});
// ❌ Error: Object literal may only specify known properties, and 'id' does not exist in type 'NewUser'.
```

<Callout type="warning" title="Типы не удаляют данные">

`toPublic` строит **новый** объект только с двумя свойствами. Если бы она просто делала `return user;`, TypeScript бы это принял (в `User` есть всё, что нужно `PublicUser`), но хеш пароля во время выполнения остался бы в объекте и ушёл бы туда же, куда и сам объект. Тип описывает данные, но никогда ничего из них не вырезает. Если данные не должны утечь, копируйте только то, что нужно.

</Callout>

Ещё одно отличие: `Pick` проверяет, что ключи существуют, а `Omit` — нет. `Omit<User, "passwrd">` спокойно принимается и ничего не убирает, так что перепроверяйте написание:

```ts
type Oops = Pick<User, "passwrd">;
// ❌ Error: Type '"passwrd"' does not satisfy the constraint 'keyof User'.
```

## `Record`: полные таблицы поиска

`Record<K, V>` — это объект с ключами типа `K` и значениями типа `V`. Если `K` — объединение литералов, TypeScript следит, чтобы присутствовал **каждый** ключ, поэтому, когда позже вы добавите новый статус, он укажет на каждую таблицу, которой нужна новая запись:

<CodeExample output={`{ pending: 2, shipped: 1, delivered: 0 }
⏳ Ожидает оплаты`}>

```ts
type OrderStatus = "pending" | "shipped" | "delivered";

const labels: Record<OrderStatus, string> = {
  pending: "⏳ Ожидает оплаты",
  shipped: "🚚 В пути",
  delivered: "✅ Доставлен",
};

function countByStatus(
  statuses: OrderStatus[],
): Record<OrderStatus, number> {
  const counts: Record<OrderStatus, number> = {
    pending: 0,
    shipped: 0,
    delivered: 0,
  };
  for (const status of statuses) {
    counts[status]++;
  }
  return counts;
}

console.log(countByStatus(["pending", "shipped", "pending"]));
console.log(labels.pending);
```

</CodeExample>

Забудьте один ключ — и TypeScript скажет, какой именно:

```ts
const short: Record<OrderStatus, string> = {
  pending: "⏳",
  shipped: "🚚",
};
// ❌ Error: Property 'delivered' is missing in type '{ pending: string; shipped: string; }' but required in type 'Record<OrderStatus, string>'.
```

## `Exclude`, `Extract` и `NonNullable`

Следующие три работают с **объединениями** (union types), а не с объектами:

- `Exclude<U, X>` убирает из `U` члены, которые подходят под `X`.
- `Extract<U, X>` оставляет в `U` только члены, которые подходят под `X`.
- `NonNullable<T>` убирает `null` и `undefined`.

`Extract` особенно полезен с [размеченными объединениями](/learn/typescript/discriminated-unions): он вытаскивает один вариант по его метке, так что можно написать функцию, которая принимает только круги:

<CodeExample output={`[ 'pending', 'paid' ]
12.57
[ 'mei@panda.dev', 'sam@panda.dev' ]`}>

```ts
type Status = "pending" | "paid" | "shipped" | "cancelled";

// "pending" | "paid" | "shipped"
type ActiveStatus = Exclude<Status, "cancelled">;
// "shipped" | "cancelled"
type FinalStatus = Extract<Status, "shipped" | "cancelled">;

const canStillCancel: Exclude<ActiveStatus, FinalStatus>[] = [
  "pending",
  "paid",
];
console.log(canStillCancel);

type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number };

type Circle = Extract<Shape, { kind: "circle" }>;

function circleArea(c: Circle): number {
  return Math.PI * c.radius ** 2; // kind проверять не нужно
}
console.log(circleArea({ kind: "circle", radius: 2 }).toFixed(2));

// Обобщённый помощник: убирает из списка null и undefined
function compact<T>(items: T[]): NonNullable<T>[] {
  const result: NonNullable<T>[] = [];
  for (const item of items) {
    if (item !== null && item !== undefined) {
      result.push(item);
    }
  }
  return result;
}

const emails = ["mei@panda.dev", null, "sam@panda.dev", undefined];
console.log(compact(emails)); // string[]
```

</CodeExample>

У `emails` тип `(string | null | undefined)[]`, поэтому `T` — это `string | null | undefined`, и `compact` возвращает `NonNullable<T>[]`, то есть ровно `string[]`.

## `ReturnType`, `Parameters` и `Awaited`

Иногда нужный тип спрятан внутри **функции**: это то, что она возвращает или принимает. Эти утилиты достают его для вас. Чтобы сослаться на функцию в типе, используйте `typeof` с её именем:

<CodeExample output={`{ userId: 'u1', token: 'tok-u1', expiresInDays: 7 }`}>

```ts
function createSession(userId: string, days: number) {
  return { userId, token: `tok-${userId}`, expiresInDays: days };
}

// { userId: string; token: string; expiresInDays: number }
type Session = ReturnType<typeof createSession>;
// [userId: string, days: number]
type SessionArgs = Parameters<typeof createSession>;

const args: SessionArgs = ["u1", 7];
const session: Session = createSession(...args);
console.log(session);
```

</CodeExample>

Это полезно, когда у результата функции нет именованного типа (так часто бывает с библиотеками) или когда вы хотите, чтобы тип автоматически следовал за функцией. Забыть `typeof` — классическая оплошность, и TypeScript даже подсказывает исправление:

```ts
type Session = ReturnType<createSession>;
// ❌ Error: 'createSession' refers to a value, but is being used as a type here. Did you mean 'typeof createSession'?
```

Функция с `async` всегда возвращает **промис** (Promise) — значение, которое придёт позже. (Как следует работать с промисами вы будете на Уровне 2.) `await` разворачивает промис во время выполнения, а **`Awaited<T>`** делает то же самое для типов:

<CodeExample output={`У Mei 120 подписчиков`}>

```ts
async function loadProfile(id: string) {
  return { id, name: "Mei", followers: 120 };
}

// Promise<{ id: string; name: string; followers: number }>
type ProfilePromise = ReturnType<typeof loadProfile>;
// { id: string; name: string; followers: number }
type Profile = Awaited<ProfilePromise>;

function describeProfile(p: Profile): string {
  return `У ${p.name} ${p.followers} подписчиков`;
}

const profile = await loadProfile("u1");
console.log(describeProfile(profile));
```

</CodeExample>

## Комбинируем утилитные типы

Утилитные типы — это просто типы, поэтому их можно вкладывать друг в друга. Самая частая комбинация — **патч для обновления** (update patch): меняться может любое свойство, кроме тех, что не должны меняться никогда. Это `Partial` от `Omit`:

<CodeExample output={`{ id: 'u1', name: 'Mei Lin', email: 'mei@panda.dev' }`}>

```ts
interface User {
  id: string;
  name: string;
  email: string;
}

type UserPatch = Partial<Omit<User, "id">>;

function updateUser(user: User, patch: UserPatch): User {
  return { ...user, ...patch };
}

const mei: User = { id: "u1", name: "Mei", email: "mei@panda.dev" };
console.log(updateUser(mei, { name: "Mei Lin" }));
```

</CodeExample>

Теперь изменение `id` — это ошибка типа, а не баг-репорт через три недели:

```ts
updateUser(mei, { id: "u99" });
// ❌ Error: Object literal may only specify known properties, and 'id' does not exist in type 'Partial<Omit<User, "id">>'.
```

<Callout type="tip" title="Давайте комбинациям имена">

`Partial<Omit<User, "id">>` легко прочитать один раз, но на пятый уже утомляет. Дайте ему имя вроде `UserPatch` и используйте его везде. Имя к тому же объясняет читателю, **зачем** этот тип существует.

</Callout>

(В настоящем приложении за теми же методами стояла бы база данных.) Для ошибок оно использует тип `Result` из прошлого урока и сообщает **подписчикам** о каждом изменении, чтобы другие части приложения (список на экране, журнал, кнопка сохранения) могли на него реагировать.

**Типы.** Три комментария `ТИПЫ:` отмечают, что нужно исправить. Строки с `// @ts-expect-error` — это тесты типов, которые проходят, только если строка под ними **является** ошибкой, поэтому заготовка не запустится, пока вы не сделаете все три пункта:

1. Хранить можно только типы со строковым `id`: добавьте ограничение на `T`.
2. `changes` в `update` может содержать любое свойство, **кроме** `id`.
3. `list()` возвращает массив **только для чтения**.

**Поведение.** Затем заставьте каждый метод работать, как описано в комментариях:

- `add(item)` сохраняет элемент или возвращает ошибку `"duplicate-id"`, если этот id занят.
- `get(id)` возвращает элемент или `undefined`.
- `update(id, changes)` заменяет элемент **новым** объектом с применёнными изменениями (старый объект не меняйте: подписчики получат его как `previous`). Отсутствующий id — ошибка `"not-found"`.
- `remove(id)` удаляет элемент и возвращает его или ошибку `"not-found"`.
- `find(predicate)` возвращает все элементы, для которых `predicate` возвращает `true`.
- `list()` возвращает копию всех элементов в порядке добавления.
- `subscribe(listener)` регистрирует подписчика и возвращает функцию, которая его удаляет. После каждого **успешного** `add`, `update` и `remove` вызывайте каждого подписчика с событием `"added"`, `"updated"` (с `previous`) или `"removed"`.

<Hint>

**Типы:** `class Store<T extends { id: string }>`, `changes: Partial<Omit<T, "id">>` и `list(): readonly T[]`.

**Поведение:** большую часть работы делает `Map`: `has`, `get`, `set` и `delete`, и он помнит порядок вставки. В `add` сначала проверьте `this.items.has(item.id)` и для повтора сделайте `return fail(...)`. В `update` получите элемент `previous`, верните `fail(...)`, если он `undefined`, и соберите новый через `const item: T = { ...previous, ...changes, id };`. `list()` может быть `[...this.items.values()]`, а `find` может фильтровать этот список. Напишите небольшой метод `private emit(event: StoreEvent<T>)`, который проходит по `this.listeners` и вызывает каждого, и вызывайте его после каждого успешного изменения. Чтобы отписать подписчика, отфильтруйте его из `this.listeners` через `filter`.

</Hint>

```ts
type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E };

type StoreError =
  | { type: "duplicate-id"; id: string }
  | { type: "not-found"; id: string };

type StoreEvent<T> =
  | { type: "added"; item: T }
  | { type: "updated"; item: T; previous: T }
  | { type: "removed"; item: T };

type Listener<T> = (event: StoreEvent<T>) => void;

function fail(error: StoreError): { ok: false; error: StoreError } {
  return { ok: false, error };
}

class Store<T extends { id: string }> {
  private items = new Map<string, T>();
  private listeners: Listener<T>[] = [];

  add(item: T): Result<T, StoreError> {
    if (this.items.has(item.id)) {
      return fail({ type: "duplicate-id", id: item.id });
    }
    this.items.set(item.id, item);
    this.emit({ type: "added", item });
    return { ok: true, value: item };
  }

  get(id: string): T | undefined {
    return this.items.get(id);
  }

  update(
    id: string,
    changes: Partial<Omit<T, "id">>,
  ): Result<T, StoreError> {
    const previous = this.items.get(id);
    if (previous === undefined) {
      return fail({ type: "not-found", id });
    }
    // новый объект; id всегда остаётся прежним
    const item: T = { ...previous, ...changes, id };
    this.items.set(id, item);
    this.emit({ type: "updated", item, previous });
    return { ok: true, value: item };
  }

  remove(id: string): Result<T, StoreError> {
    const item = this.items.get(id);
    if (item === undefined) {
      return fail({ type: "not-found", id });
    }
    this.items.delete(id);
    this.emit({ type: "removed", item });
    return { ok: true, value: item };
  }

  find(predicate: (item: T) => boolean): T[] {
    return this.list().filter(predicate);
  }

  list(): readonly T[] {
    return [...this.items.values()];
  }

  subscribe(listener: Listener<T>): () => void {
    this.listeners.push(listener);
    return () => {
      this.listeners = this.listeners.filter((l) => l !== listener);
    };
  }

  private emit(event: StoreEvent<T>): void {
    for (const listener of this.listeners) {
      listener(event);
    }
  }
}

interface Book {
  id: string;
  title: string;
  author: string;
  year: number;
}

// ===== Тесты типов: не меняйте их =====
// @ts-expect-error: элементы без id хранить нельзя
const noIds = new Store<{ title: string }>();
const test = new Store<Book>();
// @ts-expect-error: update не может менять id
test.update("b1", { id: "b9" });
// @ts-expect-error: year должен быть числом
test.update("b1", { year: "1965" });
// @ts-expect-error: list() только для чтения
test.list().push({ id: "b2", title: "?", author: "?", year: 0 });

// ===== Попробуйте =====

const stopLogging = books.subscribe((event) => {
  console.log(`[${event.type}] ${event.item.title}`);
});

books.add({ id: "b1", title: "Dune", author: "Herbert", year: 1965 });

if (!again.ok) {
  console.log(`Ошибка: ${again.error.type} (${again.error.id})`);
}
books.update("b2", { year: 1816 });
const old = books.find((b) => b.year < 1900);
console.log(old.map((b) => b.title));

stopLogging();

console.log(books.list());
// [added] Dune
// [added] Emma
// Ошибка: duplicate-id (b1)
// [updated] Emma
// [ 'Emma' ]
// [ { id: 'b2', title: 'Emma', author: 'Austen', year: 1816 } ]
```

## Итоги

- **Утилитные типы** — это обобщённые типы из библиотеки TypeScript, которые выводят новые типы из существующих, поэтому всё остаётся синхронизированным.
- `Partial`, `Required` и `Readonly` меняют модификаторы всех свойств (поверхностно).
- `Pick` и `Omit` придают объектам форму DTO вроде `NewUser` или `PublicUser`; типы никогда не вырезают данные во время выполнения, поэтому копируйте только то, что нужно.
- `Record<Union, V>` создаёт полные таблицы поиска: каждый ключ обязан быть на месте.
- `Exclude`, `Extract` и `NonNullable` фильтруют объединения; `Extract` вытаскивает один вариант из размеченного объединения.
- `ReturnType<typeof fn>`, `Parameters<typeof fn>` и `Awaited<T>` достают типы из функций и промисов.
- Комбинируйте их для реальных задач: `Partial<Omit<T, "id">>` — классический патч для обновления.
