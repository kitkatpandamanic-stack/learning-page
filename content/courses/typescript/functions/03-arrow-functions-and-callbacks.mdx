In JavaScript, functions are values: you can store them in variables and pass them to other functions. TypeScript lets you describe the **type of a function** too, so it can check that the right kind of function gets passed around. Let's see how, then build a typed calculator. 🧮

## Typed arrow functions

Arrow functions take types in exactly the same places as normal functions: after each parameter, and after the brackets for the return type:

<CodeExample output={`7
Hi, Mei!`}>

```ts
const add = (a: number, b: number): number => a + b;

const greet = (name: string) => `Hi, ${name}!`;

console.log(add(3, 4));
console.log(greet("Mei"));
```

</CodeExample>

`greet` has no return type written, so TypeScript infers `string` from the template literal.

## Function types

What's the type of `add` itself? It's written like an arrow function, but with a **type** after the arrow instead of code:

```ts
(a: number, b: number) => number
```

Read it as: "a function that takes two numbers and returns a number". You can use it to annotate a variable, and then only functions with that shape can be stored in it:

<CodeExample output={`8
2`}>

```ts
let operation: (a: number, b: number) => number;

operation = (a, b) => a + b;
console.log(operation(5, 3));

operation = (a, b) => a - b;
console.log(operation(5, 3));
```

</CodeExample>

<Callout type="note" title="The names are just labels">

In a function type, the parameter names (`a` and `b`) are only there to make it readable. A function with parameters called `x` and `y` fits the type just as well. What matters are the **types** and their **order**.

</Callout>

## Naming function types with `type`

Writing the full function type again and again gets noisy. Give it a name with a **type alias**:

<CodeExample output={`12
4`}>

```ts
type MathFn = (a: number, b: number) => number;

const multiply: MathFn = (a, b) => a * b;
const divide: MathFn = (a, b) => a / b;

console.log(multiply(3, 4));
console.log(divide(12, 3));
```

</CodeExample>

If a function doesn't match the alias, you find out immediately:

```ts
const shout: MathFn = (a: string) => a;
// ❌ Error: Type '(a: string) => string' is not assignable to type 'MathFn'.
```

## Contextual typing

Did you notice that `multiply` and `divide` above have **no** parameter types, and still no "implicit any" error? That's **contextual typing**: TypeScript already knows the function must be a `MathFn`, so it gives `a` and `b` the type `number` for you.

The same happens with array methods. `map` knows it's looping over numbers, so `n` is a `number` without any annotation:

<CodeExample output={`[ 2, 4, 6 ]
[ 'MEI', 'SAM' ]`}>

```ts
const nums = [1, 2, 3];
const doubled = nums.map((n) => n * 2); // n: number

const names = ["mei", "sam"];
const loud = names.map((name) => name.toUpperCase()); // name: string

console.log(doubled);
console.log(loud);
```

</CodeExample>

## Callbacks

A **callback** is a function you pass to another function, so it can call it later. To accept one, give the parameter a function type:

<CodeExample output={`Round 1
Round 2
Round 3`}>

```ts
function repeat(times: number, action: (round: number) => void) {
  for (let i = 1; i <= times; i++) {
    action(i);
  }
}

repeat(3, (round) => {
  console.log(`Round ${round}`);
});
```

</CodeExample>

Thanks to contextual typing, `round` is a `number` inside the arrow function, and TypeScript checks that the callback you pass really accepts a number.

<Callout type="tip">

A `void` return type on a callback means "I won't use what you return". That's why `(round: number) => void` happily accepts a callback that just prints.

</Callout>

Build a small calculator where every operation is a typed function:

1. Write `multiply` and `divide` as arrow functions of type `MathFn`.
2. Finish `calculate(a, b, op)`: use a `switch` on `op` to call the matching function and return the result.
3. Finish `calculateAll(a, b, ops)`: return an array with the result of every operation in `ops`, in order. For example, `calculateAll(10, 2, ["add", "divide"])` returns `[12, 5]`.

<Hint>

`const multiply: MathFn = (a, b) => a * b;` needs no parameter types, thanks to contextual typing. In `calculate`, write one `case` per operation, each with a `return`. For `calculateAll`, `ops.map((op) => calculate(a, b, op))` does the whole job.

</Hint>

<Solution>

```ts
type Operation = "add" | "subtract" | "multiply" | "divide";
type MathFn = (a: number, b: number) => number;

const add: MathFn = (a, b) => a + b;
const subtract: MathFn = (a, b) => a - b;
const multiply: MathFn = (a, b) => a * b;
const divide: MathFn = (a, b) => a / b;

function calculate(a: number, b: number, op: Operation): number {
  switch (op) {
    case "add":
      return add(a, b);
    case "subtract":
      return subtract(a, b);
    case "multiply":
      return multiply(a, b);
    case "divide":
      return divide(a, b);
  }
}

function calculateAll(
  a: number,
  b: number,
  ops: Operation[],
): number[] {
  return ops.map((op) => calculate(a, b, op));
}

console.log(calculate(6, 3, "add")); // 9
console.log(calculate(6, 3, "divide")); // 2
console.log(calculateAll(10, 2, ["add", "subtract", "multiply"]));
// [ 12, 8, 20 ]
```

</Solution>

## Recap

- Arrow functions take types in the same places: `(a: number, b: number): number => a + b`.
- A function type looks like `(a: number, b: number) => number`; name it with `type MathFn = ...`.
- **Contextual typing** fills in parameter types when TypeScript already knows the function's type, for example in `map` or when assigning to a `MathFn`.
- A **callback** is a function passed to another function. Type the parameter with a function type, such as `(round: number) => void`.
