Именно в функциях (functions) типы начинают по-настоящему окупаться. Стоит сказать TypeScript, что функция **принимает** и что **возвращает**, — и он проверит за вас каждый её вызов, так что неправильный аргумент будет пойман ещё до запуска кода.

## Типизируем параметры

Поставьте тип после имени каждого **параметра** (parameter) через двоеточие — ровно так же, как для переменных:

<CodeExample output={`Привет, Маша!
Привет, Маша!`}>

```ts
function greet(name: string, times: number) {
  for (let i = 0; i < times; i++) {
    console.log(`Привет, ${name}!`);
  }
}

greet("Маша", 2);
```

</CodeExample>

Теперь TypeScript знает, что `name` — строка, а `times` — число. Передайте значение не того типа — и сразу получите ошибку:

```ts
greet("Маша", "2");
// ❌ Error: Argument of type 'string' is not assignable to parameter of type 'number'.
```

## Почему параметры нужно аннотировать

TypeScript отлично угадывает (**выводит**) типы, но тип параметра угадать не может: функцию могут вызвать с чем угодно. В строгом режиме (strict mode) параметр без типа — это ошибка:

```ts
function double(n) {
  // ❌ Error: Parameter 'n' implicitly has an 'any' type.
  return n * 2;
}
```

Если бы так было можно, `n` молча стал бы `any`, и TypeScript перестал бы его проверять. Поэтому правило простое: **всегда указывайте тип параметров**.

<CodeExample output="14">

```ts
function double(n: number) {
  return n * 2;
}

console.log(double(7));
```

</CodeExample>

## Возвращаемые типы

Можно также указать, что функция **возвращает**, — это **возвращаемое значение** (return value). Возвращаемый тип пишут после закрывающей скобки списка параметров:

<CodeExample output={`12
5`}>

```ts
function area(width: number, height: number): number {
  return width * height;
}

const room = area(3, 4);
console.log(room);
console.log(area(2.5, 2));
```

</CodeExample>

Возвращаемый тип — это обещание: «эта функция всегда возвращает число». Если вы нарушите обещание, TypeScript скажет об этом:

```ts
function area(width: number, height: number): number {
  return `${width * height} м²`;
  // ❌ Error: Type 'string' is not assignable to type 'number'.
}
```

## Выведенные возвращаемые типы

Писать возвращаемый тип _не обязательно_. TypeScript посмотрит на ваши инструкции `return` и определит его сам:

<CodeExample output={`5
number
pass`}>

```ts
function add(a: number, b: number) {
  return a + b; // выведенный возвращаемый тип: number
}

function grade(score: number) {
  if (score >= 50) {
    return "pass";
  }
  return "fail";
}

const total = add(2, 3); // total — число
console.log(total);
console.log(typeof total);
console.log(grade(72)); // тип: "pass" | "fail"
```

</CodeExample>

Обратите внимание: `grade` получает объединение литералов `"pass" | "fail"` («сдал» или «не сдал»), и это точнее, чем просто `string`.

<Callout type="tip" title="Когда писать возвращаемый тип">

**Параметры:** всегда. **Возвращаемые типы:** по желанию. Многие команды всё равно пишут их для важных функций: так функция лучше документирована, а ошибки _внутри_ неё ловятся — например, если вы забыли `return` в одной из веток.

</Callout>

## `void`: функции, которые ничего не возвращают

Некоторые функции выполняют работу (например, что-то выводят), но ничего не возвращают. Их возвращаемый тип — **`void`**:

<CodeExample output={`Маша: очков — 42
Саша: очков — 7
undefined`}>

```ts
function logScore(player: string, score: number): void {
  console.log(`${player}: очков — ${score}`);
}

logScore("Маша", 42);
const result = logScore("Саша", 7);
console.log(result);
```

</CodeExample>

Во время работы программы функция с `void` возвращает `undefined`, но тип говорит: «не используйте этот результат». Если случайно вернуть значение, ошибка будет поймана:

```ts
function logScore(player: string, score: number): void {
  return score;
  // ❌ Error: Type 'number' is not assignable to type 'void'.
}
```

<Callout type="note">

Для функции без `return` и без аннотации тип `void` выводится автоматически, поэтому у `function sayHi() { console.log("Привет"); }` уже есть возвращаемый тип `void`.

</Callout>

В стартовом коде есть **ошибки типов**: у параметров нет типов. Добавьте типы, а затем допишите `ticketPrice(age)`, чтобы функция возвращала `5` для детей младше 12 лет, `7` для людей от 65 лет и старше и `10` для всех остальных.

<Hint>

Напишите `age: number` и `name: string`. Для цены сначала используйте `if (age < 12)`, затем `if (age >= 65)` и в конце `return 10`. Если добавить `: number` после `ticketPrice(age: number)`, TypeScript проверит, что каждая ветка возвращает число.

</Hint>

<Solution>

```ts
function ticketPrice(age: number): number {
  if (age < 12) {
    return 5;
  }
  if (age >= 65) {
    return 7;
  }
  return 10;
}

function describeTicket(name: string, age: number): string {
  return name + " платит " + ticketPrice(age);
}

console.log(describeTicket("Маша", 9)); // Маша платит 5
console.log(describeTicket("Саша", 30)); // Саша платит 10
```

</Solution>

</Exercise>

## Итоги

- Типизируйте параметры так: `name: type`. В строгом режиме параметр без типа — ошибка (неявный `any`).
- Возвращаемый тип пишут после скобок: `function area(w: number, h: number): number`.
- Если не указать возвращаемый тип, TypeScript выведет его из ваших инструкций `return`.
- `void` означает «не возвращает ничего полезного» — для функций, которые только выполняют работу, например выводят текст.
