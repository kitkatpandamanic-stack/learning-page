В части 1 вы написали **чистую** логику: расписания, `isDue` и серии. Но чистые функции ничего не запоминают. Приложению нужно место, где **хранить** привычки и отметки, **правила** их изменения и способ их **сохранять**, чтобы они пережили перезагрузку страницы. Этим и займёмся. 💾

Вы многое возьмёте из Уровня 1: дженерик `Store<T>` и `Result` из [Дженериков](/learn/typescript/utility-types), `private` и `readonly` из [Классов](/learn/typescript/classes-and-access-modifiers), `Omit` и `Pick`, а также [защитники типа](/learn/typescript/type-guards-and-unknown) (type guards) для проверки сохранённого JSON. В итоге у вас будет класс `HabitTracker`, который страница в части 3 сможет просто вызывать: `tracker.checkIn(id, today)`.

## Хранилище, собранное заново

Модуль «Дженерики» заканчивался мини-проектом: `Store<T>`, обобщённым хранилищем в памяти для всего, у чего есть строковый `id`, с типизированными ошибками и событиями для подписчиков. Это ровно то, что нам нужно, причём дважды: `Store<Habit>` и `Store<CheckIn>`.

Мы соберём его заново с тремя изменениями, потому что настоящий код подстраивается под приложение, для которого он написан:

- **Без `update`.** Это приложение никогда не редактирует привычки и отметки: оно их добавляет и удаляет. Ненужный код — это код, который приходится читать, тестировать и поддерживать в рабочем состоянии, поэтому он уходит. (Его можно вернуть, если вы сделаете переименование; см. идеи в части 3.)
- **Новый метод `has(id)`** — быстрый ответ «да или нет» на вопрос «есть ли такой элемент?».
- **Новый метод `removeWhere(predicate)`**, который удаляет все подходящие элементы. Когда вы удаляете привычку, вместе с ней должны уйти и все её отметки.

Есть ещё два крошечных дженерик-помощника, `ok` и `err`, которые собирают каждую из сторон `Result`. `return ok(item)` читается лучше, чем `return { ok: true, value: item }`, а типы TypeScript выводит из аргумента.

Вот хранилище в деле, на отметках:

<CodeExample output={`added: h1@2026-03-16
added: h2@2026-03-16
added: h1@2026-03-17
{ ok: false, error: { type: 'duplicate-id', id: 'h1@2026-03-17' } }
removed: h1@2026-03-16
removed: h1@2026-03-17

```ts
type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E };

function ok<T>(value: T): { ok: true; value: T } {
  return { ok: true, value };
}

function err<E>(error: E): { ok: false; error: E } {
  return { ok: false, error };
}

type StoreError =
  | { type: "duplicate-id"; id: string }
  | { type: "not-found"; id: string };

type StoreEvent<T> =
  | { type: "added"; item: T }
  | { type: "removed"; item: T };

type Listener<T> = (event: StoreEvent<T>) => void;

class Store<T extends { id: string }> {
  private items = new Map<string, T>();
  private listeners: Listener<T>[] = [];

  add(item: T): Result<T, StoreError> {
    if (this.items.has(item.id)) {
      return err({ type: "duplicate-id", id: item.id });
    }
    this.items.set(item.id, item);
    this.emit({ type: "added", item });
    return ok(item);
  }

  get(id: string): T | undefined {
    return this.items.get(id);
  }

  has(id: string): boolean {
    return this.items.has(id);
  }

  remove(id: string): Result<T, StoreError> {
    const item = this.items.get(id);
    if (item === undefined) {
      return err({ type: "not-found", id });
    }
    this.items.delete(id);
    this.emit({ type: "removed", item });
    return ok(item);
  }

  // Удаляет все подходящие элементы; возвращает удалённые
  removeWhere(predicate: (item: T) => boolean): T[] {
    const doomed = this.find(predicate);
    for (const item of doomed) {
      this.remove(item.id);
    }
    return doomed;
  }

  find(predicate: (item: T) => boolean): T[] {
    return this.list().filter(predicate);
  }

  list(): readonly T[] {
    return [...this.items.values()];
  }

  subscribe(listener: Listener<T>): () => void {
    this.listeners.push(listener);
    return () => {
      this.listeners = this.listeners.filter((l) => l !== listener);
    };
  }

  private emit(event: StoreEvent<T>): void {
    for (const listener of this.listeners) {
      listener(event);
    }
  }
}

// ===== Попробуем на отметках =====
interface CheckIn {
  readonly id: string;
  readonly habitId: string;
  readonly date: string;
}

function makeCheckIn(habitId: string, date: string): CheckIn {
  return { id: `${habitId}@${date}`, habitId, date };
}

const checkIns = new Store<CheckIn>();
checkIns.subscribe((e) => console.log(`${e.type}: ${e.item.id}`));

checkIns.add(makeCheckIn("h1", "2026-03-16"));
checkIns.add(makeCheckIn("h2", "2026-03-16"));
checkIns.add(makeCheckIn("h1", "2026-03-17"));

// У той же привычки в тот же день — тот же id
const again = checkIns.add(makeCheckIn("h1", "2026-03-17"));
console.log(again);

const gone = checkIns.removeWhere((c) => c.habitId === "h1");
console.log(`Удалено: ${gone.length}, осталось: ${checkIns.list().length}`);
```

</CodeExample>

Посмотрите на четвёртую строку вывода. В части 1 мы собирали id каждой отметки из привычки и дня, поэтому у второй отметки для `h1` на 17-е **тот же id**, и хранилище её отклоняет. Правилу «одна отметка на привычку в день» не нужен собственный код: оно само вытекает из устройства данных.

`removeWhere` построен из методов, которые у хранилища уже есть (`find`, а затем `remove` для каждого элемента), поэтому каждый удалённый элемент по-прежнему отправляет своё событие `"removed"`.

## Ошибки на языке трекера

Методы трекера могут не сработать несколькими вполне обычными способами: пустое название, несуществующая привычка, отметка в выходной, вторая отметка в тот же день, отмена того, что не было выполнено. Это работа для размеченного объединения ошибок, возвращаемого в `Result`, чтобы ни один вызывающий код не мог о них забыть:

```ts
type TrackerError =
  | { type: "invalid-habit"; reason: string }
  | { type: "unknown-habit"; habitId: string }
  | { type: "not-due"; habitId: string; date: IsoDate }
  | { type: "already-done"; habitId: string; date: IsoDate }
  | { type: "not-done"; habitId: string; date: IsoDate };
```

Почему бы просто не передать дальше ошибки хранилища? Потому что `"duplicate-id"` — это деталь того, **как** трекер хранит отметки. Странице незачем знать, что отметка — это элемент `Store` с придуманным id; она хочет услышать «уже отмечено на 2026-03-17». Поэтому трекер **переводит** ошибки хранилища в свои. TypeScript следит, чтобы вы это делали: вернуть `Result` хранилища напрямую не получится, потому что `StoreError` — это не `TrackerError`:

```ts
checkIn(habitId: string, date: IsoDate): Result<CheckIn, TrackerError> {
  const id = checkInId(habitId, date);
  return this.checkInStore.add({ id, habitId, date });
  // ❌ Error: Type 'Result<CheckIn, StoreError>' is not assignable to type 'Result<CheckIn, TrackerError>'.
}
```

У новой привычки ещё нет id: его выбирает трекер. Это `Omit` из [Утилитных типов](/learn/typescript/utility-types), и он остаётся в согласии с `Habit`, если вы когда-нибудь добавите свойство:

```ts
type NewHabit = Omit<Habit, "id">;

tracker.addHabit({ id: "h9", name: "Чтение", schedule: { kind: "daily" } });
// ❌ Error: Object literal may only specify known properties, and 'id' does not exist in type 'NewHabit'.
```

Типы гарантируют **форму** новой привычки, но не её осмысленность. Пустое название или еженедельная привычка без дней — вполне правильные формы. Для таких правил нужна проверка во время выполнения, как `isValidQuestion` в викторине Уровня 0. `habitProblem` возвращает, что не так, или `null`, а `errorMessage` превращает любую ошибку в предложение для страницы:

<CodeExample output={`✅ всё в порядке
Дайте привычке название
Выберите хотя бы один день
Число раз в неделю — от 1 до 7
Эта привычка не запланирована на 2026-03-17`}>

```ts

type Weekday = "mon" | "tue" | "wed" | "thu" | "fri" | "sat" | "sun";
type Schedule =
  | { kind: "daily" }
  | { kind: "weekly"; days: Weekday[] }
  | { kind: "timesPerWeek"; times: number };
interface Habit {
  readonly id: string;
  name: string;
  schedule: Schedule;

function assertNever(value: never): never {
  throw new Error(`Неожиданное значение: ${JSON.stringify(value)}`);

// ===== Новое в части 2 =====
type NewHabit = Omit<Habit, "id">;

type TrackerError =
  | { type: "invalid-habit"; reason: string }
  | { type: "unknown-habit"; habitId: string }
  | { type: "not-due"; habitId: string; date: IsoDate }
  | { type: "already-done"; habitId: string; date: IsoDate }
  | { type: "not-done"; habitId: string; date: IsoDate };

  switch (error.type) {
    case "invalid-habit":
      return error.reason;
    case "unknown-habit":
      return `Нет привычки с id ${error.habitId}`;
    case "not-due":
      return `Эта привычка не запланирована на ${error.date}`;
    case "already-done":
      return `Уже отмечено на ${error.date}`;
    case "not-done":
      return `На ${error.date} отметки нет, отменять нечего`;
    default:
      return assertNever(error);
  }

// Что не так с новой привычкой, или null, если всё в порядке
function habitProblem(input: NewHabit): string | null {
  const name = input.name.trim();
  if (name === "") return "Дайте привычке название";
  if (name.length > 40) return "Название — не длиннее 40 символов";
  const schedule = input.schedule;
  switch (schedule.kind) {
    case "daily":
      return null;
    case "weekly":
      return schedule.days.length > 0 ? null : "Выберите хотя бы один день";
    case "timesPerWeek": {
      const { times } = schedule;
      const valid = Number.isInteger(times) && times >= 1 && times <= 7;

    default:

  }
}
```

Оба `switch` заканчиваются `assertNever`, так что новый вид расписания или новый вид ошибки забыть не получится. В ветке `"timesPerWeek"` фигурные скобки `{ ... }` дают ветке собственный блок, чтобы в нём можно было объявить `const`.

## Класс HabitTracker

Теперь класс, который связывает всё вместе. Его два хранилища **`private`**: страница может менять привычки и отметки только через методы трекера, поэтому не может обойти правила (никаких отметок в выходной, никаких отметок для удалённой привычки). Вот его сердце:

```ts
class HabitTracker {
  private readonly habitStore = new Store<Habit>();
  private readonly checkInStore = new Store<CheckIn>();
  private nextNumber = 1;

  addHabit(input: NewHabit): Result<Habit, TrackerError> {
    const problem = habitProblem(input);
    if (problem !== null) {
      return err({ type: "invalid-habit", reason: problem });
    }
    const habit: Habit = {
      id: this.newId(),
      name: input.name.trim(),
      schedule: input.schedule,
    };
    this.habitStore.add(habit);
    return ok(habit);
  }

  checkIn(
    habitId: string,
    date: IsoDate,
  ): Result<CheckIn, TrackerError> {
    const habit = this.habitStore.get(habitId);
    if (habit === undefined) {
      return err({ type: "unknown-habit", habitId });
    }
    if (!isDue(habit, date)) {
      return err({ type: "not-due", habitId, date });
    }
    const id = checkInId(habitId, date);
    const added = this.checkInStore.add({ id, habitId, date });
    if (!added.ok) {
      return err({ type: "already-done", habitId, date });
    }
    return ok(added.value);
  }

  isDone(habitId: string, date: IsoDate): boolean {
    return this.checkInStore.has(checkInId(habitId, date));
  }

  // h1, h2, h3... пропуская id, занятые загруженными привычками
  private newId(): string {
    let id: string;
    do {
      id = `h${this.nextNumber}`;
      this.nextNumber++;
    } while (this.habitStore.has(id));
    return id;
  }

  // ...undo, removeHabit, statsFor, сохранение и загрузка
}
```

`checkIn` — это ряд **охранных условий** (guard clauses): каждая проваленная проверка сразу возвращает ошибку, а код внизу выполняется, только когда всё в порядке. `undo` и `removeHabit` устроены так же; их вы напишете в упражнении.

Id простые: `h1`, `h2`, `h3`… Цикл `do...while` выполняет тело хотя бы один раз, а затем повторяет его, пока id занят. Это важно после загрузки сохранённых привычек: трекер никогда не выдаст id, который уже используется.

## Показатели дня с Pick

Страница в части 3 показывает привычки, которые нужно выполнить в выбранный день, у каждой — кнопка ✓ и значок серии. Трекер отдаёт всё это одним вызовом, `statsFor(date)`, в виде списка `HabitStats`:

```ts
interface HabitStats extends Pick<Habit, "id" | "name" | "schedule"> {
  done: boolean; // отмечена в этот день
  streak: number;
  thisWeek: number; // отметки за ту неделю до этого дня
}
```

`extends Pick<...>` берёт три свойства прямо из `Habit` вместе с типами и добавляет три значения, нужные странице. `thisWeek` позволяет странице показывать прогресс вроде «1/2 за неделю» для привычек «N раз в неделю» с помощью `timesInWeek` из части 1. Как и `streak`, это значение учитывает только отметки до заданного дня: заглянув в понедельник, вы видите понедельник таким, каким он был, без отметок, добавленных в среду.

`statsFor` — место, где чистые функции из части 1 встречаются с сохранёнными данными: метод оставляет привычки, которые нужно выполнить (`isDue`), и для каждой спрашивает `isDone`, `streak` и `timesInWeek`, всегда с переданной ему датой `date`. Трекер никогда не спрашивает, какой день **на самом деле**.

## Сохранение через интерфейс

Дальше — сохранение. В браузере данные уходят в `localStorage`, но трекер не должен зависеть от него напрямую: тесты запускаются там, где `localStorage` вообще нет, и тест никогда не должен оставлять данные следующему тесту. Поэтому трекер просит **самое малое, что ему нужно** — объект с `getItem` и `setItem`:

```ts
interface StorageLike {
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
}
```

Благодаря [структурной типизации](/learn/typescript/structural-typing-and-class-design) (structural typing) настоящий `localStorage` браузера **уже подходит** под этот интерфейс: у него есть оба метода с такими типами (и ещё много чего, но это неважно). Так что страница в части 3 просто напишет `new HabitTracker(localStorage)`, а тесты передадут `FakeStorage`, который хранит всё в `Map`. Это снова внедрение зависимостей (dependency injection), как часы на парковке. Сначала посмотрим на идею на крошечном классе:

<CodeExample output={`✓ VisitCounter > начинает с 1
✓ VisitCounter > запоминает визиты в своём хранилище

Tests  2 passed (2)`}>

```ts
import { describe, it, expect } from "vitest";

interface StorageLike {
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
}

// Для тестов: хранит всё в Map
class FakeStorage implements StorageLike {
  private data = new Map<string, string>();

  getItem(key: string): string | null {
    return this.data.get(key) ?? null;
  }

  setItem(key: string, value: string): void {
    this.data.set(key, value);
  }
}

class VisitCounter {
  constructor(private readonly storage: StorageLike) {}

  visit(): number {
    const count = Number(this.storage.getItem("visits") ?? "0") + 1;
    this.storage.setItem("visits", String(count));
    return count;
  }
}

describe("VisitCounter", () => {
  it("начинает с 1", () => {
    const counter = new VisitCounter(new FakeStorage());
    expect(counter.visit()).toBe(1);
  });
  it("запоминает визиты в своём хранилище", () => {
    const storage = new FakeStorage();
    new VisitCounter(storage).visit();
    new VisitCounter(storage).visit(); // как перезагрузка страницы
    expect(storage.getItem("visits")).toBe("2");
  });
});
```

</CodeExample>

Каждый тест создаёт **своё** фейковое хранилище, поэтому тесты не влияют друг на друга. Второй тест создаёт два счётчика на одном хранилище — ровно это и происходит при перезагрузке страницы: новый объект, те же сохранённые данные.

## Загрузка без доверия

Сохранять легко: `JSON.stringify` для привычек и отметок. Проблемы начинаются при загрузке. Данные в хранилище могли остаться от старой версии приложения, записаться наполовину или быть отредактированы вручную в DevTools браузера. Как вы узнали в уроке [Защитники типа и unknown](/learn/typescript/type-guards-and-unknown): **`unknown` на границах, защитники на входе, настоящие типы внутри.**

Нам нужен защитник для каждого сохраняемого типа. Но сначала ловушка: проверка дня недели через `includes` не компилируется, если значение — обычная строка:

```ts
function isWeekday(value: unknown): value is Weekday {
  return typeof value === "string" && WEEKDAYS.includes(value);
  // ❌ Error: Argument of type 'string' is not assignable to parameter of type 'Weekday'.
}
```

`WEEKDAYS` — это `Weekday[]`, поэтому его `includes` принимает только `Weekday`, а доказать, что значение им является, — вся суть этой функции! `WEEKDAYS.some((day) => day === value)` задаёт тот же вопрос и принимает любое значение.

Для дат тоже нужен защитник. `isIsoDate` превращает текст в `Date` и обратно: если получился тот же текст, это была настоящая дата. Так отсеивается и `"hello"` (неверная дата, у которой `getTime()` равен `NaN`), и `"2026-02-30"`, которую JavaScript молча перекатывает на 2 марта.

Затем `parseSaved` собирает защитников вместе. Эта функция **никогда не бросает исключений** и **никогда не выбрасывает всё разом**: сломанный JSON или неверная форма дают пустые списки, а внутри хороших данных каждая привычка и каждая отметка проверяются по отдельности, так что один повреждённый элемент не утянет за собой остальные:

<CodeExample output={`true false
[ 'Чтение', 'Растяжка' ] 1
{ habits: [], checkIns: [] }
{ habits: [], checkIns: [] }`}>

```ts
type IsoDate = string;
type Weekday = "mon" | "tue" | "wed" | "thu" | "fri" | "sat" | "sun";
const WEEKDAYS: Weekday[] = [
  "sun", "mon", "tue", "wed", "thu", "fri", "sat",
];
function toDate(date: IsoDate): Date {
  return new Date(`${date}T00:00:00Z`);
}
function toIsoDate(date: Date): IsoDate {
  return date.toISOString().slice(0, 10);
}

  | { kind: "daily" }
```

Вся проверка происходит в одном месте, в `parseSaved`, которая запускается один раз — при старте трекера. Каждый метод после этого работает с настоящими значениями `Habit` и `CheckIn`, и больше проверок не нужно. Если бы проверки были разбросаны по коду, где-нибудь вы бы о них забыли.

</Callout>

## Сохраняем при каждом изменении

Последний кусочек — **когда** сохранять. Хранилища уже сообщают подписчикам о каждом изменении, поэтому трекер подписывается на оба и сохраняет данные, что бы ни случилось. Кроме того, он передаёт новость своим слушателям через `onChange`, чтобы страница могла перерисоваться:

```ts
constructor(private readonly storage: StorageLike) {
  const saved = parseSaved(storage.getItem(STORAGE_KEY));
  for (const habit of saved.habits) {
    this.habitStore.add(habit);
  }
  for (const checkIn of saved.checkIns) {
    if (this.habitStore.has(checkIn.habitId)) {
      this.checkInStore.add(checkIn);
    }
  }
  // Только теперь: загрузку сохранять не нужно
  this.habitStore.subscribe(() => this.changed());
  this.checkInStore.subscribe(() => this.changed());
}

private changed(): void {
  this.save();
  for (const listener of this.listeners) {
    listener();
  }
}
```

Здесь важны две детали. Трекер подписывается **после** загрузки, так что заполнение хранилищ из сохранённых данных не вызывает бессмысленного сохранения для каждого элемента. А отметки для несуществующих привычек при загрузке пропускаются, так что остатки удалённой привычки не прокрадутся обратно.

<Callout type="note" title="Здесь простота лучше хитрости">

Удаление привычки с 30 отметками отправляет 31 событие `"removed"`, и трекер сохраняет данные 31 раз подряд. Для нескольких килобайт JSON трекера привычек это пустяк, а код остаётся простым: ни один метод не может забыть сохранить данные, потому что ни один метод не сохраняет их вручную. Приложение побольше могло бы **группировать** изменения и сохранять один раз в конце. Сначала измерьте, потом оптимизируйте.

</Callout>

// ===== Дженерик-хранилище (из модуля «Дженерики») =====
type StoreError =
  | { type: "duplicate-id"; id: string }
  | { type: "not-found"; id: string };

type StoreEvent<T> =
  | { type: "added"; item: T }
  | { type: "removed"; item: T };

type Listener<T> = (event: StoreEvent<T>) => void;

class Store<T extends { id: string }> {
  private items = new Map<string, T>();
  private listeners: Listener<T>[] = [];

  add(item: T): Result<T, StoreError> {
    if (this.items.has(item.id)) {
      return err({ type: "duplicate-id", id: item.id });
    }
    this.items.set(item.id, item);
    this.emit({ type: "added", item });
    return ok(item);
  }

  get(id: string): T | undefined {
    return this.items.get(id);
  }

  has(id: string): boolean {
    return this.items.has(id);
  }

  remove(id: string): Result<T, StoreError> {
    const item = this.items.get(id);
    if (item === undefined) {
      return err({ type: "not-found", id });
    }
    this.items.delete(id);
    this.emit({ type: "removed", item });
    return ok(item);
  }

  // Удаляет все подходящие элементы; возвращает удалённые
  removeWhere(predicate: (item: T) => boolean): T[] {
    const doomed = this.find(predicate);
    for (const item of doomed) {
      this.remove(item.id);
    }
    return doomed;
  }

  find(predicate: (item: T) => boolean): T[] {
    return this.list().filter(predicate);
  }

  list(): readonly T[] {
    return [...this.items.values()];
  }

  subscribe(listener: Listener<T>): () => void {
    this.listeners.push(listener);
    return () => {
      this.listeners = this.listeners.filter((l) => l !== listener);
    };
  }

  private emit(event: StoreEvent<T>): void {
    for (const listener of this.listeners) {
      listener(event);
    }
  }
}

function habitProblem(input: NewHabit): string | null {
  const name = input.name.trim();
  if (name === "") return "Дайте привычке название";
  if (name.length > 40) return "Название — не длиннее 40 символов";
  const schedule = input.schedule;
  switch (schedule.kind) {
    case "daily":
      return null;
    case "weekly":
      return schedule.days.length > 0 ? null : "Выберите хотя бы один день";
    case "timesPerWeek": {
      const { times } = schedule;
      const valid = Number.isInteger(times) && times >= 1 && times <= 7;
      return valid ? null : "Число раз в неделю — от 1 до 7";
    }
    default:
      return assertNever(schedule);
  }
}

interface HabitStats extends Pick<Habit, "id" | "name" | "schedule"> {
  done: boolean; // отмечена в этот день
  streak: number;
  thisWeek: number; // отметки за ту неделю до этого дня
}

const STORAGE_KEY = "pandadev-habits";

class HabitTracker {
  // 4. Трогать хранилища может только сам трекер
  readonly habitStore = new Store<Habit>();
  readonly checkInStore = new Store<CheckIn>();
  private listeners: (() => void)[] = [];
  private nextNumber = 1;

  constructor(private readonly storage: StorageLike) {
    const saved = parseSaved(storage.getItem(STORAGE_KEY));
    for (const habit of saved.habits) {
      this.habitStore.add(habit);
    }
    for (const checkIn of saved.checkIns) {
      if (this.habitStore.has(checkIn.habitId)) {
        this.checkInStore.add(checkIn);
      }
    }
    // Только теперь: загрузку сохранять не нужно
    this.habitStore.subscribe(() => this.changed());
    this.checkInStore.subscribe(() => this.changed());
  }

  addHabit(input: NewHabit): Result<Habit, TrackerError> {
    const problem = habitProblem(input);
    if (problem !== null) {
      return err({ type: "invalid-habit", reason: problem });
    }
    const habit: Habit = {
      id: this.newId(),
      name: input.name.trim(),
      schedule: input.schedule,
    };
    this.habitStore.add(habit);
    return ok(habit);
  }

  // 5. Удалить привычку И её отметки
  //    ("unknown-habit", если такой привычки нет)
  removeHabit(habitId: string): Result<Habit, TrackerError> {
    return err({ type: "unknown-habit", habitId });
  }

  // 6. Отметить привычку на дату date. Ошибки: "unknown-habit",
  //    "not-due" (через isDue) или "already-done" (хранилище
  //    отметок не примет один и тот же id дважды)
  checkIn(
    habitId: string,
    date: IsoDate,
  ): Result<CheckIn, TrackerError> {
    return err({ type: "unknown-habit", habitId });
  }

  // 7. Удалить отметку за этот день ("not-done", если её нет)
  undo(
    habitId: string,
    date: IsoDate,
  ): Result<CheckIn, TrackerError> {
    return err({ type: "not-done", habitId, date });
  }

  isDone(habitId: string, date: IsoDate): boolean {
    return this.checkInStore.has(checkInId(habitId, date));
  }

  listHabits(): readonly Habit[] {
    return this.habitStore.list();
  }

  // 8. По одному HabitStats на каждую привычку на дату date:
  //    выполнена ли в этот день, её серия и её отметки за ту
  //    неделю до date (более поздних ещё не было)
  statsFor(date: IsoDate): HabitStats[] {
    return [];
  }

  // Вызывать listener после каждого изменения; вернёт "отписку"
  onChange(listener: () => void): () => void {
    this.listeners.push(listener);
    return () => {
      this.listeners = this.listeners.filter((l) => l !== listener);
    };
  }

  private changed(): void {
    this.save();
    for (const listener of this.listeners) {
      listener();
    }
  }

  private save(): void {
    const data: SavedData = {
      habits: this.habitStore.list(),
      checkIns: this.checkInStore.list(),
    };
    this.storage.setItem(STORAGE_KEY, JSON.stringify(data));
  }

  // h1, h2, h3... пропуская id, занятые загруженными привычками
  private newId(): string {
    let id: string;
    do {
      id = \`h\${this.nextNumber}\`;
      this.nextNumber++;
    } while (this.habitStore.has(id));
    return id;
  }
}

```ts
  dates: IsoDate[],
  today: IsoDate,

type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E };

function ok<T>(value: T): { ok: true; value: T } {
  return { ok: true, value };

function err<E>(error: E): { ok: false; error: E } {
  return { ok: false, error };

// ===== Дженерик-хранилище (из модуля «Дженерики») =====
type StoreError =
  | { type: "duplicate-id"; id: string }
  | { type: "not-found"; id: string };

type StoreEvent<T> =
  | { type: "added"; item: T }
  | { type: "removed"; item: T };

type Listener<T> = (event: StoreEvent<T>) => void;

class Store<T extends { id: string }> {
  private items = new Map<string, T>();
  private listeners: Listener<T>[] = [];

  add(item: T): Result<T, StoreError> {
    if (this.items.has(item.id)) {
      return err({ type: "duplicate-id", id: item.id });
    }
    this.items.set(item.id, item);
    this.emit({ type: "added", item });
    return ok(item);
  }

  get(id: string): T | undefined {
    return this.items.get(id);
  }

  has(id: string): boolean {
    return this.items.has(id);
  }

  remove(id: string): Result<T, StoreError> {
    const item = this.items.get(id);
    if (item === undefined) {
      return err({ type: "not-found", id });
    }
    this.items.delete(id);
    this.emit({ type: "removed", item });
    return ok(item);
  }

  // Удаляет все подходящие элементы; возвращает удалённые
  removeWhere(predicate: (item: T) => boolean): T[] {
    const doomed = this.find(predicate);
    for (const item of doomed) {
      this.remove(item.id);
    }
    return doomed;
  }

  find(predicate: (item: T) => boolean): T[] {
    return this.list().filter(predicate);
  }

  list(): readonly T[] {
    return [...this.items.values()];
  }

  subscribe(listener: Listener<T>): () => void {
    this.listeners.push(listener);
    return () => {
      this.listeners = this.listeners.filter((l) => l !== listener);
    };
  }

  private emit(event: StoreEvent<T>): void {
    for (const listener of this.listeners) {
      listener(event);
    }
  }
}

  );
}

function isWeekday(value: unknown): value is Weekday {
  return WEEKDAYS.some((day) => day === value);
}

function isIsoDate(value: unknown): value is IsoDate {
  if (typeof value !== "string") return false;
  const date = toDate(value);
  // Неверный текст даёт NaN; "2026-02-30" перескочит на март
  return !Number.isNaN(date.getTime()) && toIsoDate(date) === value;
}

function isSchedule(value: unknown): value is Schedule {
  if (!isObject(value)) return false;
  switch (value.kind) {
    case "daily":
      return true;
    case "weekly":
      return Array.isArray(value.days) && value.days.every(isWeekday);
    case "timesPerWeek":
      return typeof value.times === "number";
    default:
      return false; // незнакомый вид
  }
}

function isHabit(value: unknown): value is Habit {
  return (
    isObject(value) &&
    typeof value.id === "string" &&
    typeof value.name === "string" &&
    isSchedule(value.schedule)
  );
}

function isCheckIn(value: unknown): value is CheckIn {
  return (
    isObject(value) &&
    typeof value.habitId === "string" &&
    isIsoDate(value.date) &&
    value.id === checkInId(value.habitId, value.date)
  );
}

interface SavedData {
  habits: readonly Habit[];
  checkIns: readonly CheckIn[];
}

// Что бы ни было сохранено, вернуть корректные данные (может, пустые)
function parseSaved(text: string | null): SavedData {
  const empty: SavedData = { habits: [], checkIns: [] };
  if (text === null) return empty; // пока ничего не сохранено
  let data: unknown;
  try {
    data = JSON.parse(text);
  } catch {
    return empty; // это даже не JSON
  }
  if (!isObject(data)) return empty;
  const { habits, checkIns } = data;
  return {
    habits: Array.isArray(habits) ? habits.filter(isHabit) : [],
    checkIns: Array.isArray(checkIns) ? checkIns.filter(isCheckIn) : [],
  };
}

type NewHabit = Omit<Habit, "id">;

type TrackerError =
  | { type: "invalid-habit"; reason: string }
  | { type: "unknown-habit"; habitId: string }
  | { type: "not-due"; habitId: string; date: IsoDate }
  | { type: "already-done"; habitId: string; date: IsoDate }
  | { type: "not-done"; habitId: string; date: IsoDate };

function errorMessage(error: TrackerError): string {
  switch (error.type) {
    case "invalid-habit":
      return error.reason;
    case "unknown-habit":
      return `Нет привычки с id ${error.habitId}`;
    case "not-due":
      return `Эта привычка не запланирована на ${error.date}`;
    case "already-done":
      return `Уже отмечено на ${error.date}`;
    case "not-done":
      return `На ${error.date} отметки нет, отменять нечего`;
    default:
      return assertNever(error);
  }
}

// Что не так с новой привычкой, или null, если всё в порядке
function habitProblem(input: NewHabit): string | null {
  const name = input.name.trim();
  if (name === "") return "Дайте привычке название";
  if (name.length > 40) return "Название — не длиннее 40 символов";
  const schedule = input.schedule;
  switch (schedule.kind) {
    case "daily":
      return null;
    case "weekly":
      return schedule.days.length > 0 ? null : "Выберите хотя бы один день";
    case "timesPerWeek": {
      const { times } = schedule;
      const valid = Number.isInteger(times) && times >= 1 && times <= 7;
      return valid ? null : "Число раз в неделю — от 1 до 7";
    }
    default:
      return assertNever(schedule);
  }
}

// Одна строка в списке дня
interface HabitStats extends Pick<Habit, "id" | "name" | "schedule"> {
  done: boolean; // отмечена в этот день
  streak: number;
  thisWeek: number; // отметки за ту неделю до этого дня
}

const STORAGE_KEY = "pandadev-habits";

class HabitTracker {
  private readonly habitStore = new Store<Habit>();
  private readonly checkInStore = new Store<CheckIn>();
  private listeners: (() => void)[] = [];
  private nextNumber = 1;

  constructor(private readonly storage: StorageLike) {
    const saved = parseSaved(storage.getItem(STORAGE_KEY));
    for (const habit of saved.habits) {
      this.habitStore.add(habit);
    }
    for (const checkIn of saved.checkIns) {
      if (this.habitStore.has(checkIn.habitId)) {
        this.checkInStore.add(checkIn);
      }
    }
    // Только теперь: загрузку сохранять не нужно
    this.habitStore.subscribe(() => this.changed());
    this.checkInStore.subscribe(() => this.changed());
  }

  addHabit(input: NewHabit): Result<Habit, TrackerError> {
    const problem = habitProblem(input);
    if (problem !== null) {
      return err({ type: "invalid-habit", reason: problem });
    }
    const habit: Habit = {
      id: this.newId(),
      name: input.name.trim(),
      schedule: input.schedule,
    };
    this.habitStore.add(habit);
    return ok(habit);
  }

  removeHabit(habitId: string): Result<Habit, TrackerError> {
    const removed = this.habitStore.remove(habitId);
    if (!removed.ok) {
      return err({ type: "unknown-habit", habitId });
    }
    this.checkInStore.removeWhere((c) => c.habitId === habitId);
    return ok(removed.value);
  }

  checkIn(
    habitId: string,
    date: IsoDate,
  ): Result<CheckIn, TrackerError> {
    const habit = this.habitStore.get(habitId);
    if (habit === undefined) {
      return err({ type: "unknown-habit", habitId });
    }
    if (!isDue(habit, date)) {
      return err({ type: "not-due", habitId, date });
    }
    const id = checkInId(habitId, date);
    const added = this.checkInStore.add({ id, habitId, date });
    if (!added.ok) {
      return err({ type: "already-done", habitId, date });
    }
    return ok(added.value);
  }

  undo(
    habitId: string,
    date: IsoDate,
  ): Result<CheckIn, TrackerError> {
    const removed = this.checkInStore.remove(checkInId(habitId, date));
    if (!removed.ok) {
      return err({ type: "not-done", habitId, date });
    }
    return ok(removed.value);
  }

  isDone(habitId: string, date: IsoDate): boolean {
    return this.checkInStore.has(checkInId(habitId, date));
  }

  listHabits(): readonly Habit[] {
    return this.habitStore.list();
  }

  // Привычки на дату date и их показатели
  statsFor(date: IsoDate): HabitStats[] {
    const checkIns = this.checkInStore.list();
    const monday = startOfWeek(date);
    return this.habitStore
      .find((habit) => isDue(habit, date))
      .map((habit) => {
        const dates = doneDates(habit.id, checkIns)
          .filter((d) => d <= date);
        return {
          id: habit.id,
          name: habit.name,
          schedule: habit.schedule,
          done: this.isDone(habit.id, date),
          streak: streak(habit, checkIns, date),
          thisWeek: timesInWeek(dates, monday),
        };
      });
  }

  // Вызывать listener после каждого изменения; вернёт "отписку"
  onChange(listener: () => void): () => void {
    this.listeners.push(listener);
    return () => {
      this.listeners = this.listeners.filter((l) => l !== listener);
    };
  }

  private changed(): void {
    this.save();
    for (const listener of this.listeners) {
      listener();
    }
  }

  private save(): void {
    const data: SavedData = {
      habits: this.habitStore.list(),
      checkIns: this.checkInStore.list(),
    };
    this.storage.setItem(STORAGE_KEY, JSON.stringify(data));
  }

  // h1, h2, h3... пропуская id, занятые загруженными привычками
  private newId(): string {
    let id: string;
    do {
      id = `h${this.nextNumber}`;
      this.nextNumber++;
    } while (this.habitStore.has(id));
    return id;
  }
}
```

## Что вы построили

- Заново собранный дженерик **`Store<T>`**, урезанный до того, что нужно приложению, и дополненный `has` и `removeWhere`, плюс дженерик-помощники `ok` и `err` для `Result`.
- **`TrackerError`** — размеченное объединение, говорящее на языке трекера, с исчерпывающей `errorMessage`, и **`habitProblem`** для правил, которые не выразить типами.
- Класс **`HabitTracker`** с приватными хранилищами, так что каждое изменение проходит через методы, следящие за правилами, и с id, которые никогда не используются повторно.
- **`NewHabit`** через `Omit` и **`HabitStats`** через `Pick`, выведенные из `Habit`, чтобы они всегда оставались с ним в согласии.
- Сохранение через крошечный интерфейс **`StorageLike`**, под который `localStorage` подходит структурно, и **`FakeStorage`** для тестов.
- **`parseSaved`** и семейство защитников типа, которые превращают недоверенный JSON в корректные данные, элемент за элементом и без единого исключения.
