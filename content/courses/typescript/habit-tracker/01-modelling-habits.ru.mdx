Добро пожаловать в итоговый проект Уровня 1! За три части вы соберёте **трекер привычек** (habit tracker), который работает в браузере: вы добавляете привычки вроде «Читать 10 страниц» или «Плавать по понедельникам и средам», отмечаете их каждый день и смотрите, как растут ваши **серии** (streaks). 🔥 Всё типизировано, сохраняется в `localStorage`, а логика покрыта тестами.

План такой:

- **Часть 1 (эта):** типы для привычек, расписаний и отметок, а также чистые функции, которые отвечают на вопросы «нужно ли выполнять эту привычку сегодня?» и «какой длины моя серия?».
- **Часть 2:** дженерик `Store<T>`, класс `HabitTracker` с приватным состоянием, а также сохранение и загрузка с проверкой JSON.
- **Часть 3:** страница: типизированная форма, список дел на сегодня с кнопками отметки и значками серий.

В этой части пригодятся [размеченные объединения](/learn/typescript/discriminated-unions) и `assertNever`, таблицы соответствия на `Record` из [Утилитных типов](/learn/typescript/utility-types), свойства `readonly` и идея из [парковки](/learn/typescript/structural-typing-and-class-design): никогда не читайте настоящие часы внутри логики.

## Даты как простые строки

Трекер привычек целиком про **дни**: в какие дни привычку нужно выполнять и в какие дни вы её выполнили. Каждый день мы будем хранить как строку в **формате ISO** `"2026-03-16"`: год, месяц, день, причём месяц и день всегда из двух цифр. Рядом с объектами `Date` из JavaScript это может показаться старомодным, но у строк здесь большие преимущества:

- Они превращаются в JSON и обратно без всяких усилий, а это важно, когда в части 2 мы будем сохранять данные в `localStorage`. (`Date` в JSON всё равно становится строкой и обратно в `Date` уже не превращается.)
- В них **нет времени и часового пояса**. Привычка выполнена «16 марта», а не «в 23:59:59.999 по Лондону».
- Поскольку самая крупная единица идёт первой, ISO-даты **правильно сравниваются и сортируются как текст**:

<CodeExample output={`true
false
[ '2026-02-28', '2026-03-02', '2026-03-14' ]`}>

```ts
type IsoDate = string; // "2026-03-16": год-месяц-день

const start: IsoDate = "2026-03-09";
const end: IsoDate = "2026-03-14";

console.log(start < end); // сравниваются посимвольно
console.log("2026-12-01" < "2026-02-01");

const days: IsoDate[] = ["2026-03-14", "2026-02-28", "2026-03-02"];
console.log([...days].sort()); // от старых к новым
```

</CodeExample>

`type IsoDate = string` — это просто **имя** для `string`: оно подсказывает читателю, какую строку ждать, но TypeScript по-прежнему примет любую строку, даже `"14/03/2026"`. На Уровне 3 вы познакомитесь с **брендированными типами** (branded types), которые умеют отличать одно от другого. А пока мы будем проверять даты там, где они **входят** в программу (часть 2), и держать всё внутри в чистоте.

### Несколько помощников для дат

Для **арифметики** с датами («предыдущий день», «какой день недели?») мы ненадолго превращаем строку в `Date` и обратно. Две небольшие новинки делают это безопасным:

- `new Date("2026-03-16T00:00:00Z")` — это полночь этого дня по **UTC**, часовому поясу без перехода на летнее время. `Z` в конце означает UTC.
- Методы `getUTC...` и `setUTC...` тоже работают в UTC, поэтому результат одинаков на любом компьютере в мире. `getUTCDay()` возвращает день недели числом, **начиная с воскресенья**: 0 — воскресенье, 1 — понедельник… 6 — суббота.

<CodeExample output={`2026-03-02
2026-02-28
mon
2026-03-16`}>

```ts
type IsoDate = string;
type Weekday = "mon" | "tue" | "wed" | "thu" | "fri" | "sat" | "sun";

// getUTCDay() считает от воскресенья (0) до субботы (6)
const WEEKDAYS: Weekday[] = [
  "sun", "mon", "tue", "wed", "thu", "fri", "sat",
];

function toDate(date: IsoDate): Date {
  return new Date(`${date}T00:00:00Z`); // полночь по UTC
}

function toIsoDate(date: Date): IsoDate {
  return date.toISOString().slice(0, 10);
}

function addDays(date: IsoDate, days: number): IsoDate {
  const d = toDate(date);
  d.setUTCDate(d.getUTCDate() + days);
  return toIsoDate(d);
}

function weekdayOf(date: IsoDate): Weekday {
  return WEEKDAYS[toDate(date).getUTCDay()];
}

// Понедельник той недели, в которую попадает date
function startOfWeek(date: IsoDate): IsoDate {
  const daysSinceMonday = (toDate(date).getUTCDay() + 6) % 7;
  return addDays(date, -daysSinceMonday);
}

console.log(addDays("2026-02-27", 3)); // через границу месяца
console.log(addDays("2026-03-01", -1)); // и обратно
console.log(weekdayOf("2026-03-16"));
console.log(startOfWeek("2026-03-22")); // воскресенье
```

</CodeExample>

`setUTCDate` устроен хитро: дайте ему 30 февраля, и он перейдёт на март, так что `addDays` не нужно знать, сколько дней в месяце. `toISOString()` возвращает `"2026-03-02T00:00:00.000Z"`, а `.slice(0, 10)` оставляет только дату. В `startOfWeek` выражение `(getUTCDay() + 6) % 7` превращает «дней с воскресенья» в «дней с понедельника»: понедельник даёт 0, воскресенье — 6.

## «Сегодня» — это параметр

Вот правило для всего проекта: **ни одна функция логики не читает настоящую дату**. Никаких `new Date()` без аргумента, никаких `Date.now()`. Если функции нужно «сегодня», она получает его параметром:

```ts
// 🤔 Сложно тестировать: ответ меняется каждый день
function streakToday(habit: Habit, checkIns: CheckIn[]): number {
  const today = toIsoDate(new Date()); // смотрит на часы
  // ...
}

// ✅ Легко тестировать: те же входы — тот же ответ, всегда
function streak(
  habit: Habit,
  checkIns: CheckIn[],
  today: IsoDate,
): number {
  // ...
}
```

Это та же идея, что и `FakeClock` на парковке: если время приходит **снаружи** через параметр, тест может сказать «представь, что сегодня вторник, 17 марта 2026 года» и получать один и тот же ответ при каждом запуске, в любом часовом поясе. Только страница в части 3 спрашивает у браузера настоящую дату, один раз, на самом краю приложения.

<Callout type="tip" title="Чистые функции">

Функция, результат которой зависит только от её параметров и которая ничего не меняет за своими пределами, называется **чистой функцией** (pure function). Всё в этой части чистое: ни часов, ни хранилища, ни страницы. Чистые функции проще всего на свете тестировать, переиспользовать и понимать, поэтому выгодно держать в них как можно больше логики.

</Callout>

## Три вида расписания

Привычки повторяются по-разному. Одни — **каждый день** («Читать 10 страниц»), другие — **в определённые дни недели** («Плавать в Пн, Ср, Пт»), а третьи нужно выполнить **несколько раз в неделю** в любые удобные дни («Йога дважды в неделю»). Каждому виду нужны свои данные, и это идеальное [размеченное объединение](/learn/typescript/discriminated-unions) (discriminated union):

```ts
type Schedule =
  | { kind: "daily" }
  | { kind: "weekly"; days: Weekday[] }
  | { kind: "timesPerWeek"; times: number };
```

Ежедневной привычке больше ничего не нужно, еженедельной нужны её дни, а привычке «N раз в неделю» — число. Бессмысленное расписание даже не получится записать:

```ts
const a: Schedule = { kind: "weekly" };
// ❌ Error: Type '{ kind: "weekly"; }' is not assignable to type 'Schedule'.

const b: Schedule = { kind: "daily", days: ["mon"] };
// ❌ Error: Object literal may only specify known properties, and 'days' does not exist in type '{ kind: "daily"; }'.

const c: Schedule = { kind: "weekly", days: ["mon", "thur"] };
// ❌ Error: Type '"thur"' is not assignable to type 'Weekday'. Did you mean '"thu"'?
```

Сравните это с одним объектом, полным необязательных свойств (`days?`, `times?`), где каждой функции пришлось бы гадать, какие из них на самом деле есть.

Первая функция для расписаний превращает его в текст для страницы. `Record<Weekday, string>` даёт каждому дню недели короткое название (и TypeScript следит, чтобы ни один не потерялся), а `assertNever` гарантирует, что обработан каждый вид расписания:

<CodeExample output={`Каждый день
Пн, Ср, Пт
2× в неделю`}>

```ts
type Weekday = "mon" | "tue" | "wed" | "thu" | "fri" | "sat" | "sun";

type Schedule =
  | { kind: "daily" }
  | { kind: "weekly"; days: Weekday[] }
  | { kind: "timesPerWeek"; times: number };

function assertNever(value: never): never {
  throw new Error(`Неожиданное значение: ${JSON.stringify(value)}`);
}

const DAY_NAMES: Record<Weekday, string> = {
  mon: "Пн", tue: "Вт", wed: "Ср", thu: "Чт",
  fri: "Пт", sat: "Сб", sun: "Вс",
};

function describeSchedule(schedule: Schedule): string {
  switch (schedule.kind) {
    case "daily":
      return "Каждый день";
    case "weekly":
      return schedule.days.map((day) => DAY_NAMES[day]).join(", ");
    case "timesPerWeek":
      return `${schedule.times}× в неделю`;
    default:
      return assertNever(schedule);
  }
}

console.log(describeSchedule({ kind: "daily" }));
console.log(
  describeSchedule({ kind: "weekly", days: ["mon", "wed", "fri"] }),
);
console.log(describeSchedule({ kind: "timesPerWeek", times: 2 }));
```

</CodeExample>

Мы пишем `2× в неделю`, а не «2 раза в неделю», чтобы не возиться с русскими формами множественного числа («1 раз», «2 раза», «5 раз»). В части 3 мы всё же напишем для них маленькую функцию.

Выгода проявится позже. Если вы когда-нибудь добавите расписание `{ kind: "monthly"; dayOfMonth: number }`, `describeSchedule` перестанет компилироваться с ошибкой `Argument of type '{ kind: "monthly"; dayOfMonth: number; }' is not assignable to parameter of type 'never'.`, как и любой другой `switch` по расписаниям в проекте. Список дел за вас составит компилятор. 📋

## Привычки и отметки

Теперь два главных героя. У **привычки** (habit) есть id, который никогда не меняется, название и расписание. **Отметка** (check-in) фиксирует, что привычка выполнена в определённый день:

```ts
interface Habit {
  readonly id: string;
  name: string;
  schedule: Schedule;
}

interface CheckIn {
  readonly id: string; // одна на привычку в день
  readonly habitId: string;
  readonly date: IsoDate;
}

function checkInId(habitId: string, date: IsoDate): string {
  return `${habitId}@${date}`;
}
```

Обратите внимание на `id` отметки. Вместо случайного id он собирается из привычки и дня: `"h1@2026-03-16"`. Это маленькое проектное решение с большим эффектом: нельзя выполнить одну и ту же привычку дважды за день, потому что у второй отметки будет **тот же id**. В части 2 хранилище будет отклонять повторяющиеся id, так что это правило мы получим даром.

Отметки `readonly` целиком: отметка — это факт из прошлого. Чтобы её отменить, её удаляют, но никогда не редактируют.

## Нужно ли сегодня?

Страница будет показывать привычки, которые **нужно выполнить** в выбранный день. Ежедневная привычка нужна всегда, еженедельная — только в свои дни. Привычка «N раз в неделю» нужна **каждый** день, ведь любой день может засчитаться в цель. Выведем целую неделю:

<CodeExample output={`mon: Чтение, Плавание, Йога
tue: Чтение, Йога
wed: Чтение, Плавание, Йога
thu: Чтение, Йога
fri: Чтение, Плавание, Йога
sat: Чтение, Йога
sun: Чтение, Йога`}>

```ts
type IsoDate = string;
type Weekday = "mon" | "tue" | "wed" | "thu" | "fri" | "sat" | "sun";
const WEEKDAYS: Weekday[] = [
  "sun", "mon", "tue", "wed", "thu", "fri", "sat",
];

function toDate(date: IsoDate): Date {
  return new Date(`${date}T00:00:00Z`);
}
function addDays(date: IsoDate, days: number): IsoDate {
  const d = toDate(date);
  d.setUTCDate(d.getUTCDate() + days);
  return d.toISOString().slice(0, 10);
}
function weekdayOf(date: IsoDate): Weekday {
  return WEEKDAYS[toDate(date).getUTCDay()];
}

type Schedule =
  | { kind: "daily" }
  | { kind: "weekly"; days: Weekday[] }
  | { kind: "timesPerWeek"; times: number };

interface Habit {
  readonly id: string;
  name: string;
  schedule: Schedule;
}

function assertNever(value: never): never {
  throw new Error(`Неожиданное значение: ${JSON.stringify(value)}`);
}

function isDue(habit: Habit, date: IsoDate): boolean {
  const schedule = habit.schedule;
  switch (schedule.kind) {
    case "daily":
      return true;
    case "weekly":
      return schedule.days.includes(weekdayOf(date));
    case "timesPerWeek":
      return true; // к цели засчитывается любой день
    default:
      return assertNever(schedule);
  }
}

const habits: Habit[] = [
  { id: "h1", name: "Чтение", schedule: { kind: "daily" } },
  {
    id: "h2",
    name: "Плавание",
    schedule: { kind: "weekly", days: ["mon", "wed", "fri"] },
  },
  {
    id: "h3",
    name: "Йога",
    schedule: { kind: "timesPerWeek", times: 2 },
  },
];

for (let i = 0; i < 7; i++) {
  const day = addDays("2026-03-16", i); // с понедельника по воскресенье
  const names = habits.filter((h) => isDue(h, day)).map((h) => h.name);
  console.log(`${weekdayOf(day)}: ${names.join(", ")}`);
}
```

</CodeExample>

Перед `switch` мы копируем `habit.schedule` в `const`. Сужение типа работает и напрямую на `habit.schedule.kind`, но короткое имя читается лучше, и сразу видно, что каждый `case` работает именно с суженным `schedule`.

## Считаем серии

**Серия** (streak) — это сколько раз подряд вы поддерживали привычку. Звучит просто, но за словом «подряд» прячутся три правила. Вот ежедневная привычка с отметками 14, 15 и 16 числа, если смотреть из разных дней:

```text
           13   14   15   16   17   18
отметки     ·    ✓    ✓    ✓    ·    ·
на 16-е:         ←─── 3 ───→             серия 3
на 17-е:         ←─── 3 ───→  (сегодня)  серия 3
на 18-е:                        ✗        серия 0
```

1. **Считаем назад от сегодня**, по одному дню по плану, пока дни выполнены.
2. **Сегодняшний день серию не обрывает.** 17-го вы ещё не выполнили привычку, но день не закончился, так что серия по-прежнему 3. Пропущенный день в **прошлом** её обрывает: 18-го оказывается, что 17-е пропущено, и серия равна 0.
3. **Выходные не считаются.** Для привычки на Пн, Ср и Пт вторник пропускается, будто его нет.

Вот эти правила в виде кода. `dayStreak` получает даты, когда привычка была выполнена, и идёт назад от `today`:

```ts
// Выполненные подряд дни по плану, считая назад от today
function dayStreak(
  habit: Habit,
  dates: IsoDate[],
  today: IsoDate,
): number {
  if (dates.length === 0) return 0;
  const first = [...dates].sort()[0];
  let count = 0;
  for (let day = today; day >= first; day = addDays(day, -1)) {
    if (!isDue(habit, day)) continue; // выходной
    if (dates.includes(day)) {
      count++;
    } else if (day !== today) {
      break; // пропущенный день обрывает серию
    }
  }
  return count;
}
```

Обратите внимание на несколько вещей:

- Цикл `for` перебирает **даты**, а не числа: он начинается с `today`, а `addDays(day, -1)` каждый раз делает шаг на день назад. В цикле `for` этот шаг выполняется и после `continue`, так что пропуск выходного не приведёт к зависанию.
- Цикл **обязан** где-то закончиться. `day >= first` (сравнение строк, которое работает для ISO-дат) останавливает его на самой старой отметке: раньше неё ничего выполнено быть не могло. Без этого условия еженедельная привычка вообще без дней крутилась бы вечно.
- `[...dates].sort()` сортирует **копию**, так что массив вызывающего кода не меняется.

Привычки «N раз в неделю» считают **недели**, а не дни: сколько недель подряд цель была достигнута. Текущая неделя засчитывается, как только цель достигнута, но, как и сегодняшний день, пока она идёт, серию не обрывает. `timesInWeek` считает даты с понедельника по следующее за ним воскресенье:

```ts
// Сколько дат попадает в неделю, начинающуюся с monday
function timesInWeek(dates: IsoDate[], monday: IsoDate): number {
  const sunday = addDays(monday, 6);
  return dates.filter((d) => d >= monday && d <= sunday).length;
}

// Недели подряд, в которые цель достигнута
function weekStreak(
  times: number,
  dates: IsoDate[],
  today: IsoDate,
): number {
  if (dates.length === 0 || times < 1) return 0;
  const first = startOfWeek([...dates].sort()[0]);
  const thisMonday = startOfWeek(today);
  let count = 0;
  let monday = thisMonday;
  while (monday >= first) {
    if (timesInWeek(dates, monday) >= times) {
      count++;
    } else if (monday !== thisMonday) {
      break; // пропущенная неделя обрывает серию
    }
    monday = addDays(monday, -7);
  }
  return count;
}
```

Наконец, `streak` собирает всё вместе. Она выбирает даты этой привычки, отбрасывает отметки **после** `today` (с точки зрения сегодняшнего дня их ещё не было) и выбирает подходящий счётчик для расписания. Две метки `case` подряд разделяют одну ветку:

function assertNever(value: never): never {
  throw new Error(`Неожиданное значение: ${JSON.stringify(value)}`);
}
function isDue(habit: Habit, date: IsoDate): boolean {
  const schedule = habit.schedule;
  switch (schedule.kind) {
    case "daily":
    case "timesPerWeek":
      return true;
    case "weekly":
      return schedule.days.includes(weekdayOf(date));
    default:
      return assertNever(schedule);
  }
}

// ===== Серии =====
function doneDates(
  habitId: string,
  checkIns: readonly CheckIn[],
): IsoDate[] {
  return checkIns
    .filter((c) => c.habitId === habitId)
    .map((c) => c.date);
}

function timesInWeek(dates: IsoDate[], monday: IsoDate): number {
  const sunday = addDays(monday, 6);
  return dates.filter((d) => d >= monday && d <= sunday).length;
}

function dayStreak(
  habit: Habit,
  dates: IsoDate[],
  today: IsoDate,
): number {
  if (dates.length === 0) return 0;
  const first = [...dates].sort()[0];
  let count = 0;
  for (let day = today; day >= first; day = addDays(day, -1)) {
    if (!isDue(habit, day)) continue;
    if (dates.includes(day)) {
      count++;
    } else if (day !== today) {
      break;
    }
  }
  return count;
}

function weekStreak(
  times: number,
  dates: IsoDate[],
  today: IsoDate,
): number {
  if (dates.length === 0 || times < 1) return 0;
  const first = startOfWeek([...dates].sort()[0]);
  const thisMonday = startOfWeek(today);
  let count = 0;
  let monday = thisMonday;
  while (monday >= first) {
    if (timesInWeek(dates, monday) >= times) {
      count++;
    } else if (monday !== thisMonday) {
      break;
    }
    monday = addDays(monday, -7);
  }
  return count;
}

function streak(
  habit: Habit,
  checkIns: readonly CheckIn[],
  today: IsoDate,
): number {
  // Отметки после today (пока) не считаются
  const dates = doneDates(habit.id, checkIns)
    .filter((d) => d <= today);
  const schedule = habit.schedule;
  switch (schedule.kind) {
    case "daily":
    case "weekly":
      return dayStreak(habit, dates, today);
    case "timesPerWeek":
      return weekStreak(schedule.times, dates, today);
    default:
      return assertNever(schedule);
  }
}

## Тестируем с Vitest

До сих пор вы проверяли результаты, выводя их и читая вывод. В настоящих проектах проверку делает **тестовый раннер** (test runner). В редактор PandaDev встроен [Vitest](https://vitest.dev) — популярный тестовый раннер для TypeScript. Как следует вы изучите его на Уровне 2, а для этого проекта хватит трёх функций:

- `describe(name, fn)` объединяет связанные тесты в группу;
- `it(name, fn)` — один тест, названный как предложение: «it counts days in a row» («считает дни подряд»);
- `expect(actual).toBe(expected)` проверяет одно значение. (`toEqual` сравнивает массивы и объекты по содержимому.)

Их импортируют в начале файла, а тесты запускаются после остального кода. Каждый пройденный тест получает ✓, а проваленный — × с описанием того, что пошло не так:

];

function toDate(date: IsoDate): Date {
  return new Date(`${date}T00:00:00Z`); // полночь по UTC
}

function toIsoDate(date: Date): IsoDate {
  return date.toISOString().slice(0, 10);
}

function addDays(date: IsoDate, days: number): IsoDate {
  const d = toDate(date);
  d.setUTCDate(d.getUTCDate() + days);
  return toIsoDate(d);
}

function weekdayOf(date: IsoDate): Weekday {
  return WEEKDAYS[toDate(date).getUTCDay()];
}

// Понедельник той недели, в которую попадает date
function startOfWeek(date: IsoDate): IsoDate {
  const daysSinceMonday = (toDate(date).getUTCDay() + 6) % 7;
  return addDays(date, -daysSinceMonday);
}

// ===== Привычки =====
type Schedule =
  | { kind: "daily" }
  | { kind: "weekly"; days: Weekday[] }
  | { kind: "timesPerWeek"; times: number };

interface Habit {
  readonly id: string;
  name: string;
  schedule: Schedule;
}

interface CheckIn {
  readonly id: string; // одна на привычку в день
  readonly habitId: string;
  readonly date: IsoDate;
}

function checkInId(habitId: string, date: IsoDate): string {
  return `${habitId}@${date}`;
}

function assertNever(value: never): never {
  throw new Error(`Неожиданное значение: ${JSON.stringify(value)}`);
}

const DAY_NAMES: Record<Weekday, string> = {
  mon: "Пн", tue: "Вт", wed: "Ср", thu: "Чт",
  fri: "Пт", sat: "Сб", sun: "Вс",
};

function describeSchedule(schedule: Schedule): string {
  switch (schedule.kind) {
    case "daily":
      return "Каждый день";
    case "weekly":
      return schedule.days.map((day) => DAY_NAMES[day]).join(", ");
    case "timesPerWeek":
      return `${schedule.times}× в неделю`;
    default:
      return assertNever(schedule);
  }
}

function isDue(habit: Habit, date: IsoDate): boolean {
  const schedule = habit.schedule;
  switch (schedule.kind) {
    case "daily":
      return true;
    case "weekly":
      return schedule.days.includes(weekdayOf(date));
    case "timesPerWeek":
      return true; // к цели засчитывается любой день
    default:
      return assertNever(schedule);
  }
}

// ===== Серии =====
function doneDates(
  habitId: string,
  checkIns: readonly CheckIn[],
): IsoDate[] {
  return checkIns
    .filter((c) => c.habitId === habitId)
    .map((c) => c.date);
}

// Сколько дат попадает в неделю, начинающуюся с monday
function timesInWeek(dates: IsoDate[], monday: IsoDate): number {
  const sunday = addDays(monday, 6);
  return dates.filter((d) => d >= monday && d <= sunday).length;
}

// Выполненные подряд дни по плану, считая назад от today
function dayStreak(
  habit: Habit,
  dates: IsoDate[],
  today: IsoDate,
): number {
  if (dates.length === 0) return 0;
  const first = [...dates].sort()[0];
  let count = 0;
  for (let day = today; day >= first; day = addDays(day, -1)) {
    if (!isDue(habit, day)) continue; // выходной
    if (dates.includes(day)) {
      count++;
    } else if (day !== today) {
      break; // пропущенный день обрывает серию
    }
  }
  return count;
}

// Недели подряд, в которые цель достигнута
function weekStreak(
  times: number,
  dates: IsoDate[],
  today: IsoDate,
): number {
  if (dates.length === 0 || times < 1) return 0;
  const first = startOfWeek([...dates].sort()[0]);
  const thisMonday = startOfWeek(today);
  let count = 0;
  let monday = thisMonday;
  while (monday >= first) {
    if (timesInWeek(dates, monday) >= times) {
      count++;
    } else if (monday !== thisMonday) {
      break; // пропущенная неделя обрывает серию
    }
    monday = addDays(monday, -7);
  }
  return count;
}

function streak(
  habit: Habit,
  checkIns: readonly CheckIn[],
  today: IsoDate,
): number {
  // Отметки после today (пока) не считаются
  const dates = doneDates(habit.id, checkIns)
    .filter((d) => d <= today);
  const schedule = habit.schedule;
  switch (schedule.kind) {
    case "daily":
    case "weekly":
      return dayStreak(habit, dates, today);
    case "timesPerWeek":
      return weekStreak(schedule.times, dates, today);
    default:
      return assertNever(schedule);
  }
}

## Что вы построили

- **ISO-строки дат** (`"2026-03-16"`), которые даром превращаются в JSON и сравниваются и сортируются как текст, плюс маленькие помощники в UTC: `addDays`, `weekdayOf` и `startOfWeek`.
- Правило, благодаря которому всё легко тестировать: **`today` — это параметр**, его никогда не читают с часов внутри логики.
- **Размеченное объединение** `Schedule` с тремя видами, а также `describeSchedule` и `isDue`, исчерпывающие благодаря `assertNever`.
- Типы `Habit` и `CheckIn`, где id отметки собирается из привычки и дня, так что привычку можно выполнить только раз в день.
- `streak()`: дни подряд для ежедневных и еженедельных привычек (с пропуском выходных) и недели подряд для привычек «N раз в неделю», причём сегодняшний день серию никогда не обрывает.
- Ваши первые тесты на **Vitest**: `describe`, `it` и `expect(...).toBe(...)`.
