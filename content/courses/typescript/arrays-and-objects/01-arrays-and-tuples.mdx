Most programs work with **lists** of things: scores, names, prices. In this lesson you'll learn how TypeScript types arrays, how to stop them being changed, and how **tuples** describe short lists with a fixed shape.

## `T[]` and `Array<T>`

An array type is the type of its items followed by `[]`. So a list of numbers is `number[]` and a list of strings is `string[]`. There's also a longer spelling, `Array<number>`, which means exactly the same thing:

<CodeExample output={`[ 72, 95, 88, 61 ]
2 Lagos`}>

```ts
const scores: number[] = [72, 95, 88];
const names: Array<string> = ["Mei", "Sam"];
const cities = ["Paris", "Lagos"]; // inferred: string[]

scores.push(61);
console.log(scores);
console.log(names.length, cities[1]);
```

</CodeExample>

Most people use the short `number[]` form. Either way, TypeScript now guards what goes in:

```ts
scores.push("ten");
// ❌ Error: Argument of type 'string' is not assignable to parameter of type 'number'.
```

If a list can hold more than one type, put a union in brackets: `(string | number)[]`. The brackets matter: `string | number[]` would mean "a string, or an array of numbers".

## Readonly arrays

Add **`readonly`** in front of an array type to make a list that can't be changed. Methods like `push`, `pop` and `sort` (which change the array) simply aren't available:

```ts
const days: readonly string[] = ["Mon", "Tue"];
days.push("Wed");
// ❌ Error: Property 'push' does not exist on type 'readonly string[]'.
```

This is especially useful for function parameters: it promises callers that your function only **reads** their array. You can still loop, `map`, `filter`, or copy it:

<CodeExample output={`9.5
[ 2.5, 3, 4 ]
[ 4, 2.5, 3 ]`}>

```ts
function total(prices: readonly number[]): number {
  let sum = 0;
  for (const price of prices) {
    sum += price;
  }
  return sum;
}

const basket: readonly number[] = [4, 2.5, 3];
console.log(total(basket));

const sorted = [...basket].sort((a, b) => a - b); // sort a copy
console.log(sorted);
console.log(basket); // unchanged
```

</CodeExample>

## Tuples: fixed-length arrays

A **tuple** is an array with a fixed number of items, where each position has its own type. Write the types in square brackets:

<CodeExample output={`Mei has 42 points
3 1
[ 3, 4 ]`}>

```ts
const point: [number, number] = [3, 4];
const entry: [string, number] = ["Mei", 42];

const [player, score] = entry; // player: string, score: number
console.log(`${player} has ${score} points`);

function divide(a: number, b: number): [number, number] {
  return [Math.floor(a / b), a % b]; // [result, remainder]
}

const [result, remainder] = divide(10, 3);
console.log(result, remainder);
console.log(point);
```

</CodeExample>

Tuples are handy for returning two values from a function, like `divide` above. TypeScript checks the length and the type at each position:

```ts
const p: [number, number] = [1, 2, 3];
// ❌ Error: Type '[number, number, number]' is not assignable to type '[number, number]'.
```

## Array methods know your types

Array methods work out their result types for you. `map` gives a new array of whatever your callback returns, `filter` keeps the same item type, and `find` gives **one item or `undefined`**, because it might not find anything:

<CodeExample output={`[ '£12', '£5', '£30', '£8' ]
[ 5, 8 ]
30 undefined`}>

```ts
const prices = [12, 5, 30, 8];

const labels = prices.map((p) => `£${p}`); // string[]
const cheap = prices.filter((p) => p < 10); // number[]
const big = prices.find((p) => p > 20); // number | undefined
const huge = prices.find((p) => p > 100); // number | undefined

console.log(labels);
console.log(cheap);
console.log(big, huge);
```

</CodeExample>

Because `find` returns `T | undefined`, TypeScript makes you handle the "not found" case before using the result:

```ts
const names = ["Mei", "Sam", "Ana"];
const found = names.find((n) => n.startsWith("S"));
found.toUpperCase();
// ❌ Error: 'found' is possibly 'undefined'.
```

Narrow it with a check, and the error goes away:

<CodeExample output={`SAM
Nobody found`}>

```ts
function shoutFirst(names: string[], letter: string): string {
  const found = names.find((n) => n.startsWith(letter));
  if (found === undefined) {
    return "Nobody found";
  }
  return found.toUpperCase(); // found: string here
}

console.log(shoutFirst(["Mei", "Sam", "Ana"], "S"));
console.log(shoutFirst(["Mei", "Sam", "Ana"], "Z"));
```

</CodeExample>

<Callout type="warning" title="Indexing isn't checked">

Reading an item by position, like `scores[10]`, is typed as `number` even if the array is shorter, and you'll get `undefined` at runtime. When you're not sure an item exists, check the `length` first or use `find`.

</Callout>

Finish three small helpers for working with a list of words:

1. `longWords(words, minLength)` returns the words with **at least** `minLength` letters.
2. `firstStartingWith(words, letter)` returns the first word that starts with `letter`, or `undefined`.
3. `lengthRange(words)` returns a tuple `[shortest length, longest length]`.

<Hint>

Use `filter` for the first one and `find` for the second (`find` already returns `undefined` when nothing matches). For the third, `words.map((w) => w.length)` gives a `number[]`; spread it into `Math.min(...)` and `Math.max(...)`.

</Hint>

<Solution>

```ts
function longWords(
  words: readonly string[],
  minLength: number,
): string[] {
  return words.filter((w) => w.length >= minLength);
}

function firstStartingWith(
  words: readonly string[],
  letter: string,
): string | undefined {
  return words.find((w) => w.startsWith(letter));
}

function lengthRange(words: readonly string[]): [number, number] {
  const lengths = words.map((w) => w.length);
  return [Math.min(...lengths), Math.max(...lengths)];
}

const words = ["panda", "bamboo", "tea", "pebble"];
console.log(longWords(words, 6)); // [ 'bamboo', 'pebble' ]
console.log(firstStartingWith(words, "b")); // bamboo
console.log(lengthRange(words)); // [ 3, 6 ]
```

</Solution>

## Recap

- `number[]` and `Array<number>` both mean "an array of numbers".
- `readonly string[]` can be read but not changed; great for function parameters.
- A tuple like `[string, number]` has a fixed length and a type for each position.
- `map` and `filter` return new arrays with inferred types; `find` returns `T | undefined`, so check before using it.
