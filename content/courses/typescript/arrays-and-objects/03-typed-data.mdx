Real apps are mostly **lists of objects**: contacts, products, messages. This is where TypeScript shines. Once it knows the shape of one item, every `filter`, `map` and `sort` you write is checked, and typos in property names are caught instantly. At the end you'll put it all together in a contact book. 📇

## Arrays of objects

Combine what you know: an interface describes one item, and `Contact[]` is a list of them:

<CodeExample output={`Mei lives in Leeds
Sam lives in Lagos
Ana lives in Leeds
3 contacts`}>

```ts
interface Contact {
  name: string;
  city: string;
  age: number;
}

const contacts: Contact[] = [
  { name: "Mei", city: "Leeds", age: 28 },
  { name: "Sam", city: "Lagos", age: 19 },
  { name: "Ana", city: "Leeds", age: 41 },
];

for (const c of contacts) {
  console.log(`${c.name} lives in ${c.city}`);
}
console.log(`${contacts.length} contacts`);
```

</CodeExample>

Every object in the list is checked against `Contact`, so a missing `age` or a misspelt `citty` is an error before the code runs.

## Filtering and mapping records

`filter` keeps the item type (`Contact[]`), `map` turns it into whatever you return, and `find` gives one `Contact` or `undefined`. You don't write any of these types yourself, TypeScript works them out:

<CodeExample output={`[ 'Mei', 'Ana' ]
Sam is 19`}>

```ts
interface Contact {
  name: string;
  city: string;
  age: number;
}

const contacts: Contact[] = [
  { name: "Mei", city: "Leeds", age: 28 },
  { name: "Sam", city: "Lagos", age: 19 },
  { name: "Ana", city: "Leeds", age: 41 },
];

const inLeeds = contacts.filter((c) => c.city === "Leeds");
const names = inLeeds.map((c) => c.name); // string[]
console.log(names);

const sam = contacts.find((c) => c.name === "Sam");
if (sam !== undefined) {
  console.log(`${sam.name} is ${sam.age}`);
}
```

</CodeExample>

## Sorting records

`sort` takes a **compare function** `(a, b) => number`. Thanks to contextual typing, `a` and `b` are both `Contact`. Return a negative number to put `a` first, a positive one to put `b` first:

<CodeExample output={`[ 'Sam', 'Mei', 'Ana' ]
[ 'Ana (41)', 'Mei (28)', 'Sam (19)' ]`}>

```ts
interface Contact {
  name: string;
  age: number;
}

const contacts: Contact[] = [
  { name: "Mei", age: 28 },
  { name: "Sam", age: 19 },
  { name: "Ana", age: 41 },
];

// Numbers: youngest first
const byAge = [...contacts].sort((a, b) => a.age - b.age);
console.log(byAge.map((c) => c.name));

// Strings: A to Z
const byName = [...contacts].sort((a, b) =>
  a.name.localeCompare(b.name),
);
console.log(byName.map((c) => `${c.name} (${c.age})`));
```

</CodeExample>

Typos in the compare function are caught too:

```ts
contacts.sort((a, b) => a.agee - b.age);
// ❌ Error: Property 'agee' does not exist on type 'Contact'. Did you mean 'age'?
```

<Callout type="warning" title="sort changes the original array">

`sort` rearranges the array **in place**. To keep the original order, sort a copy: `[...contacts].sort(...)`, as in the example above.

</Callout>

## Lookups with `Record<string, T>`

Sometimes you want to look things up **by key** instead of searching a list. `Record<string, T>` is the type of an object whose keys are strings and whose values are all `T`:

<CodeExample output={`0789 012
[ 'Mei', 'Sam', 'Ana' ]
{ Leeds: 2, Lagos: 1, Lima: 1 }`}>

```ts
const phoneBook: Record<string, string> = {
  Mei: "0123 456",
  Sam: "0789 012",
};
phoneBook["Ana"] = "0555 333"; // add a new key
console.log(phoneBook["Sam"]);
console.log(Object.keys(phoneBook));

// Count how many times each city appears
const cities = ["Leeds", "Lagos", "Leeds", "Lima"];
const counts: Record<string, number> = {};
for (const city of cities) {
  counts[city] = (counts[city] ?? 0) + 1;
}
console.log(counts);
```

</CodeExample>

The `?? 0` is important: the first time we see a city, `counts[city]` is `undefined`, so we start from `0` instead.

<Callout type="note" title="Missing keys">

TypeScript types `counts["Paris"]` as a `number`, even though a key you never added gives `undefined` at runtime. When a key might be missing, use a fallback with `??` or check with `"Paris" in counts`.

</Callout>

If the keys are a fixed set, use a union of literals instead of `string`. Then TypeScript makes sure **every** key is there:

```ts
type Operation = "add" | "subtract";
const symbols: Record<Operation, string> = { add: "+" };
// ❌ Error: Property 'subtract' is missing in type '{ add: string; }' but required in type 'Record<Operation, string>'.
```

## Updating records with `Partial<T>`

When you update a contact, you usually change just one or two properties. **`Partial<Contact>`** is a ready-made type that has all the properties of `Contact`, but every one is **optional**. It's perfect for a "changes" object:

<CodeExample output={`{ name: 'Mei', city: 'York', age: 28 }
{ name: 'Mei', city: 'Leeds', age: 29 }
{ name: 'Mei', city: 'Leeds', age: 28 }`}>

```ts
interface Contact {
  name: string;
  city: string;
  age: number;
}

function updateContact(
  contact: Contact,
  changes: Partial<Contact>,
): Contact {
  return { ...contact, ...changes }; // a new object
}

const mei: Contact = { name: "Mei", city: "Leeds", age: 28 };
console.log(updateContact(mei, { city: "York" }));
console.log(updateContact(mei, { age: 29 }));
console.log(mei); // the original is unchanged
```

</CodeExample>

Even though every property is optional, the types are still checked:

```ts
updateContact(mei, { age: "29" });
// ❌ Error: Type 'string' is not assignable to type 'number'.
updateContact(mei, { town: "York" });
// ❌ Error: Object literal may only specify known properties, and 'town' does not exist in type 'Partial<Contact>'.
```

Build the core of a typed contact book. Finish the three functions:

1. `favouriteNames(list)` returns the names of the favourite contacts, sorted **A to Z**.
2. `countByCity(list)` returns a `Record<string, number>` such as `{ Leeds: 2, Lagos: 1 }`.
3. `updateContact(list, id, changes)` returns a **new** array where the contact with that `id` has the `changes` applied. Don't change the original array or its objects.

<Hint>

1. `filter` the favourites, `map` them to names, then `sort` with `(a, b) => a.localeCompare(b)`.
2. Start with `const counts: Record<string, number> = {}` and use `(counts[c.city] ?? 0) + 1` in a loop.
3. Use `map`: if `c.id === id` return `{ ...c, ...changes }`, otherwise return `c` unchanged.

</Hint>

<Solution>

```ts
interface Contact {
  readonly id: number;
  name: string;
  city: string;
  favourite: boolean;
}

const contacts: Contact[] = [
  { id: 1, name: "Sam", city: "Leeds", favourite: true },
  { id: 2, name: "Mei", city: "Lagos", favourite: false },
  { id: 3, name: "Ana", city: "Leeds", favourite: true },
];

function favouriteNames(list: Contact[]): string[] {
  return list
    .filter((c) => c.favourite)
    .map((c) => c.name)
    .sort((a, b) => a.localeCompare(b));
}

function countByCity(list: Contact[]): Record<string, number> {
  const counts: Record<string, number> = {};
  for (const c of list) {
    counts[c.city] = (counts[c.city] ?? 0) + 1;
  }
  return counts;
}

function updateContact(
  list: Contact[],
  id: number,
  changes: Partial<Contact>,
): Contact[] {
  return list.map((c) => (c.id === id ? { ...c, ...changes } : c));
}

console.log(favouriteNames(contacts)); // [ 'Ana', 'Sam' ]
console.log(countByCity(contacts)); // { Leeds: 2, Lagos: 1 }
console.log(updateContact(contacts, 2, { city: "York" })[1]);
// { id: 2, name: 'Mei', city: 'York', favourite: false }
```

</Solution>

## Recap

- An interface plus `[]` (like `Contact[]`) types a whole list of records.
- `filter`, `map`, `find` and `sort` infer their types from your records, and catch property typos.
- `sort` changes the array in place, so sort a copy with `[...list].sort(...)`.
- `Record<string, T>` types a lookup object; use `??` for keys that may be missing.
- `Partial<T>` makes every property optional: ideal for "changes" objects in update functions.
