Объекты (objects) собирают связанные значения вместе: у пользователя есть имя, email и возраст. В TypeScript вы один раз описываете эту **форму**, а компилятор проверяет, что у каждого объекта она действительно такая. Больше никаких опечаток вроде `user.emial`! 🐼

## Аннотации типов для объектов

Тип объекта перечисляет каждое свойство (property) с его типом внутри фигурных скобок, через точку с запятой:

<CodeExample output={`Mo, возраст: 3
Bao, возраст: 1`}>

```ts
const pet: { name: string; age: number } = { name: "Mo", age: 3 };

function describePet(p: { name: string; age: number }): string {
  return `${p.name}, возраст: ${p.age}`;
}

console.log(describePet(pet));
console.log(describePet({ name: "Bao", age: 1 }));
```

</CodeExample>

Если обязательного свойства не хватает, TypeScript скажет, какого именно:

```ts
const pet: { name: string; age: number } = { name: "Mo" };
// ❌ Error: Property 'age' is missing in type '{ name: string; }' but required in type '{ name: string; age: number; }'.
```

## Даём формам имена с помощью `type`

Писать одну и ту же форму дважды утомительно, и в ней легко ошибиться. **Псевдоним типа** (type alias) даёт ей имя, которое можно использовать где угодно:

<CodeExample output={`{ name: 'Mo', age: 3 }
Mo старше`}>

```ts
type Pet = {
  name: string;
  age: number;
};

const mo: Pet = { name: "Mo", age: 3 };
const bao: Pet = { name: "Bao", age: 1 };

function older(a: Pet, b: Pet): Pet {
  return a.age >= b.age ? a : b;
}

console.log(mo);
console.log(`${older(mo, bao).name} старше`);
```

</CodeExample>

## Интерфейсы

**Интерфейс** (interface) — ещё один способ назвать форму объекта. Выглядит почти так же, только без `=`:

<CodeExample output="Mei <mei@panda.dev>">

```ts
interface User {
  name: string;
  email: string;
}

function contactLine(user: User): string {
  return `${user.name} <${user.email}>`;
}

const mei: User = { name: "Mei", email: "mei@panda.dev" };
console.log(contactLine(mei));
```

</CodeExample>

Так что же выбрать? Для описания объектов они почти взаимозаменяемы:

| | `type` | `interface` |
| --- | --- | --- |
| Описывает формы объектов | ✅ | ✅ |
| Можно расширить | ✅ (через `&`) | ✅ (через `extends`) |
| Объединения вроде `"a" \| "b"` и типы функций | ✅ | ❌ |

<Callout type="tip" title="Простое правило">

Используйте `interface` для форм объектов, а `type` — для всего остального (объединений, типов функций, кортежей). Так делают многие команды. Главное — придерживаться одного подхода в рамках проекта.

</Callout>

## Необязательные свойства и свойства только для чтения

Поставьте **`?`** после имени свойства, чтобы сделать его **необязательным**: объекты могут его не указывать. Добавьте **`readonly`** перед именем, чтобы свойство нельзя было изменить после создания объекта:

<CodeExample output={`Mei Lin (нет телефона)
Sam: 0123 456`}>

```ts
interface Member {
  readonly id: number;
  name: string;
  phone?: string; // string | undefined
}

function phoneLine(m: Member): string {
  if (m.phone === undefined) {
    return `${m.name} (нет телефона)`;
  }
  return `${m.name}: ${m.phone}`;
}

const mei: Member = { id: 1, name: "Mei" };
const sam: Member = { id: 2, name: "Sam", phone: "0123 456" };
mei.name = "Mei Lin"; // можно: name не readonly

console.log(phoneLine(mei));
console.log(phoneLine(sam));
```

</CodeExample>

Попытка изменить свойство `readonly` — это ошибка:

```ts
mei.id = 99;
// ❌ Error: Cannot assign to 'id' because it is a read-only property.
```

<Callout type="note">

Как и массивы `readonly`, свойства `readonly` проверяются только **во время компиляции**. Они не «замораживают» объект во время выполнения, а лишь не дают вашему коду (и коду ваших коллег) случайно его изменить.

</Callout>

## Проверка лишних свойств

Когда вы пишете объектный литерал прямо там, где ожидается определённый тип, TypeScript ругается и на **лишние** свойства, которых он не знает. Так ловятся опечатки и забытые данные:

```ts
type Pet = { name: string; age: number };

const pet: Pet = { name: "Mo", age: 2, colour: "black" };
// ❌ Error: Object literal may only specify known properties, and 'colour' does not exist in type 'Pet'.
```

Если `colour` действительно нужен питомцу, добавьте его в тип (например, как `colour?: string`). Если нет — уберите.

## Расширение интерфейсов

Интерфейс может **расширять** (extend) другой: он получает все свойства родителя плюс свои собственные. Так не приходится повторять общие свойства:

<CodeExample output={`Rex, порода: лабрадор, возраст: 4
{ name: 'Rex', age: 4, breed: 'лабрадор' }`}>

```ts
interface Animal {
  name: string;
  age: number;
}

interface Dog extends Animal {
  breed: string;
}

const rex: Dog = { name: "Rex", age: 4, breed: "лабрадор" };

function introduce(dog: Dog): string {
  return `${dog.name}, порода: ${dog.breed}, возраст: ${dog.age}`;
}

console.log(introduce(rex));
console.log(rex);
```

</CodeExample>

`Dog` — это одновременно и `Animal`, поэтому `rex` можно передать в любую функцию, которая ждёт `Animal`. С псевдонимами `type` тот же эффект даёт `&`: `type Dog = Animal & { breed: string };`.

```ts
interface Book {
  readonly isbn: string;
  title: string;
  author: string;
  pages: number;
  rating?: number;
}

function describeBook(book: Book): string {
  const text = `${book.title} — ${book.author}, ${book.pages} стр.`;
  if (book.rating === undefined) {
    return text;
  }
  return `${text}, оценка ${book.rating}/5`;

const dune: Book = {
  isbn: "978-0441013593",
  title: "Дюна",
  author: "Фрэнк Герберт",
  pages: 412,
  rating: 5,
};

console.log(describeBook(dune));
// Дюна — Фрэнк Герберт, 412 стр., оценка 5/5
```

## Итоги

- Описывайте объекты через `{ name: string; age: number }` или давайте форме имя с помощью `type` или `interface`.
- `interface` отлично подходит для форм объектов; `type` умеет называть ещё и объединения и типы функций.
- `prop?: T` делает свойство необязательным; `readonly prop: T` запрещает его переприсваивать.
- Объектные литералы с неизвестными лишними свойствами помечаются ошибкой (проверка лишних свойств).
- `interface Dog extends Animal` переиспользует все свойства `Animal` и добавляет новые.
