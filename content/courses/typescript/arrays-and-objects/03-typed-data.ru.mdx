Настоящие приложения в основном состоят из **списков объектов**: контакты, товары, сообщения. Здесь TypeScript раскрывается во всей красе. Как только он знает форму одного элемента, каждый ваш `filter`, `map` и `sort` проверяется, а опечатки в именах свойств ловятся мгновенно. В конце вы соберёте всё вместе в книге контактов. 📇

## Массивы объектов

Объедините то, что уже знаете: интерфейс описывает один элемент, а `Contact[]` — список таких элементов:

<CodeExample output={`Mei живёт в городе Leeds
Sam живёт в городе Lagos
Ana живёт в городе Leeds
Контактов: 3`}>

```ts
interface Contact {
  name: string;
  city: string;
  age: number;
}

const contacts: Contact[] = [
  { name: "Mei", city: "Leeds", age: 28 },
  { name: "Sam", city: "Lagos", age: 19 },
  { name: "Ana", city: "Leeds", age: 41 },
];

for (const c of contacts) {
  console.log(`${c.name} живёт в городе ${c.city}`);
}
console.log(`Контактов: ${contacts.length}`);
```

</CodeExample>

Каждый объект в списке проверяется на соответствие `Contact`, так что пропущенный `age` или опечатка `citty` станут ошибкой ещё до запуска кода.

## Фильтрация и преобразование записей

`filter` сохраняет тип элементов (`Contact[]`), `map` превращает их в то, что вы вернёте, а `find` даёт один `Contact` или `undefined`. Ни один из этих типов писать не нужно — TypeScript выводит их сам:

<CodeExample output={`[ 'Mei', 'Ana' ]
Sam, возраст: 19`}>

```ts
interface Contact {
  name: string;
  city: string;
  age: number;
}

const contacts: Contact[] = [
  { name: "Mei", city: "Leeds", age: 28 },
  { name: "Sam", city: "Lagos", age: 19 },
  { name: "Ana", city: "Leeds", age: 41 },
];

const inLeeds = contacts.filter((c) => c.city === "Leeds");
const names = inLeeds.map((c) => c.name); // string[]
console.log(names);

const sam = contacts.find((c) => c.name === "Sam");
if (sam !== undefined) {
  console.log(`${sam.name}, возраст: ${sam.age}`);
}
```

</CodeExample>

## Сортировка записей

`sort` принимает **функцию сравнения** `(a, b) => number`. Благодаря контекстной типизации и `a`, и `b` имеют тип `Contact`. Верните отрицательное число, чтобы `a` оказался первым, и положительное — чтобы первым был `b`:

<CodeExample output={`[ 'Sam', 'Mei', 'Ana' ]
[ 'Ana (41)', 'Mei (28)', 'Sam (19)' ]`}>

```ts
interface Contact {
  name: string;
  age: number;
}

const contacts: Contact[] = [
  { name: "Mei", age: 28 },
  { name: "Sam", age: 19 },
  { name: "Ana", age: 41 },
];

// Числа: сначала самые молодые
const byAge = [...contacts].sort((a, b) => a.age - b.age);
console.log(byAge.map((c) => c.name));

// Строки: от A до Z
const byName = [...contacts].sort((a, b) =>
  a.name.localeCompare(b.name),
);
console.log(byName.map((c) => `${c.name} (${c.age})`));
```

</CodeExample>

Опечатки в функции сравнения тоже ловятся:

```ts
contacts.sort((a, b) => a.agee - b.age);
// ❌ Error: Property 'agee' does not exist on type 'Contact'. Did you mean 'age'?
```

<Callout type="warning" title="sort меняет исходный массив">

`sort` переставляет элементы **на месте**. Чтобы сохранить исходный порядок, сортируйте копию: `[...contacts].sort(...)`, как в примере выше.

</Callout>

## Поиск по ключу с `Record<string, T>`

Иногда удобнее искать данные **по ключу**, а не перебирать список. `Record<string, T>` — это тип объекта, у которого ключи — строки, а все значения имеют тип `T`:

<CodeExample output={`0789 012
[ 'Mei', 'Sam', 'Ana' ]
{ Leeds: 2, Lagos: 1, Lima: 1 }`}>

```ts
const phoneBook: Record<string, string> = {
  Mei: "0123 456",
  Sam: "0789 012",
};
phoneBook["Ana"] = "0555 333"; // добавляем новый ключ
console.log(phoneBook["Sam"]);
console.log(Object.keys(phoneBook));

// Считаем, сколько раз встречается каждый город
const cities = ["Leeds", "Lagos", "Leeds", "Lima"];
const counts: Record<string, number> = {};
for (const city of cities) {
  counts[city] = (counts[city] ?? 0) + 1;
}
console.log(counts);
```

</CodeExample>

`?? 0` здесь важен: когда город встречается впервые, `counts[city]` равно `undefined`, поэтому мы начинаем с `0`.

<Callout type="note" title="Отсутствующие ключи">

TypeScript считает `counts["Paris"]` числом (`number`), хотя ключ, который вы не добавляли, во время выполнения даёт `undefined`. Если ключа может не быть, используйте запасное значение через `??` или проверку `"Paris" in counts`.

</Callout>

Если набор ключей фиксирован, используйте вместо `string` объединение литеральных типов (literal types). Тогда TypeScript проследит, чтобы были указаны **все** ключи:

```ts
type Operation = "add" | "subtract";
const symbols: Record<Operation, string> = { add: "+" };
// ❌ Error: Property 'subtract' is missing in type '{ add: string; }' but required in type 'Record<Operation, string>'.
```

## Обновление записей с `Partial<T>`

Обновляя контакт, вы обычно меняете одно-два свойства. **`Partial<Contact>`** — готовый тип, в котором есть все свойства `Contact`, но каждое из них **необязательное**. Он идеально подходит для объекта «изменений»:

<CodeExample output={`{ name: 'Mei', city: 'York', age: 28 }
{ name: 'Mei', city: 'Leeds', age: 29 }
{ name: 'Mei', city: 'Leeds', age: 28 }`}>

```ts
interface Contact {
  name: string;
  city: string;
  age: number;
}

function updateContact(
  contact: Contact,
  changes: Partial<Contact>,
): Contact {
  return { ...contact, ...changes }; // новый объект
}

const mei: Contact = { name: "Mei", city: "Leeds", age: 28 };
console.log(updateContact(mei, { city: "York" }));
console.log(updateContact(mei, { age: 29 }));
console.log(mei); // исходный объект не изменился
```

</CodeExample>

Хотя все свойства необязательные, их типы всё равно проверяются:

```ts
updateContact(mei, { age: "29" });
// ❌ Error: Type 'string' is not assignable to type 'number'.
updateContact(mei, { town: "York" });
// ❌ Error: Object literal may only specify known properties, and 'town' does not exist in type 'Partial<Contact>'.
```

Соберите ядро типизированной книги контактов. Допишите три функции:

1. `favouriteNames(list)` возвращает имена избранных контактов, отсортированные **от A до Z**.
2. `countByCity(list)` возвращает `Record<string, number>`, например `{ Leeds: 2, Lagos: 1 }`.
3. `updateContact(list, id, changes)` возвращает **новый** массив, в котором к контакту с этим `id` применены изменения `changes`. Не меняйте исходный массив и его объекты.

<Hint>

1. Отберите избранных через `filter`, превратите их в имена через `map`, затем отсортируйте с `(a, b) => a.localeCompare(b)`.
2. Начните с `const counts: Record<string, number> = {}` и в цикле используйте `(counts[c.city] ?? 0) + 1`.
3. Используйте `map`: если `c.id === id`, верните `{ ...c, ...changes }`, иначе верните `c` без изменений.

</Hint>

<Solution>

```ts
interface Contact {
  readonly id: number;
  name: string;
  city: string;
  favourite: boolean;
}

const contacts: Contact[] = [
  { id: 1, name: "Sam", city: "Leeds", favourite: true },
  { id: 2, name: "Mei", city: "Lagos", favourite: false },
  { id: 3, name: "Ana", city: "Leeds", favourite: true },
];

function favouriteNames(list: Contact[]): string[] {
  return list
    .filter((c) => c.favourite)
    .map((c) => c.name)
    .sort((a, b) => a.localeCompare(b));
}

function countByCity(list: Contact[]): Record<string, number> {
  const counts: Record<string, number> = {};
  for (const c of list) {
    counts[c.city] = (counts[c.city] ?? 0) + 1;
  }
  return counts;
}

function updateContact(
  list: Contact[],
  id: number,
  changes: Partial<Contact>,
): Contact[] {
  return list.map((c) => (c.id === id ? { ...c, ...changes } : c));
}

console.log(favouriteNames(contacts)); // [ 'Ana', 'Sam' ]
console.log(countByCity(contacts)); // { Leeds: 2, Lagos: 1 }
console.log(updateContact(contacts, 2, { city: "York" })[1]);
// { id: 2, name: 'Mei', city: 'York', favourite: false }
```

</Solution>

## Итоги

- Интерфейс плюс `[]` (например, `Contact[]`) типизирует целый список записей.
- `filter`, `map`, `find` и `sort` выводят типы из ваших записей и ловят опечатки в свойствах.
- `sort` меняет массив на месте, поэтому сортируйте копию: `[...list].sort(...)`.
- `Record<string, T>` типизирует объект для поиска по ключу; для ключей, которых может не быть, используйте `??`.
- `Partial<T>` делает все свойства необязательными — идеально для объектов «изменений» в функциях обновления.
