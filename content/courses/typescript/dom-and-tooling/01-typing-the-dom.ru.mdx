Вы уже умеете менять веб-страницу с помощью [DOM](/learn/javascript/the-dom) и [событий](/learn/javascript/events) в JavaScript. TypeScript тоже знает DOM: у каждого элемента, каждого события и каждого API браузера есть тип. Значит, он может предупредить о классических ошибках на странице **ещё до того**, как вы откроете браузер: элемента нет на месте, значение поля читается как число, обработчик клика ждёт клавишу. В этом уроке вы напишете код для страницы, которым TypeScript будет доволен и который не развалится, если страница окажется не совсем такой, как вы ожидали. 🧩

Примеры в этом уроке работают на настоящей странице рядом с кодом. Нажмите **«Запустить»**, чтобы попробовать их, и меняйте сколько угодно.

## У элементов есть типы

Каждый элемент (element) на странице — это объект, и у TypeScript есть тип для каждого вида элементов. Они образуют генеалогическое дерево — от самого общего типа к самому конкретному:

```text
EventTarget              может получать события
└─ Node                  что угодно в дереве страницы, даже текст
   └─ Element            любой тег, HTML или SVG
      └─ HTMLElement     любой HTML-тег: style, hidden, dataset…
         ├─ HTMLInputElement    value, checked, valueAsNumber…
         ├─ HTMLButtonElement   disabled, type…
         ├─ HTMLFormElement     reset(), requestSubmit()…
         └─ HTMLLIElement, HTMLParagraphElement, …
```

Чем ниже, тем больше TypeScript разрешает делать. У `HTMLInputElement` есть `value`, а у простого `Element` — нет, потому что у большинства элементов (`<p>`, круга в SVG) никакого значения нет вовсе.

Так какой тип вы получаете, когда ищете элемент? Это зависит от того, что TypeScript может понять из вашего кода:

| Код                                  | Тип                           |
| ------------------------------------ | ----------------------------- |
| `document.querySelector("input")`    | `HTMLInputElement \| null`    |
| `document.querySelector("#name")`    | `Element \| null`             |
| `document.getElementById("name")`    | `HTMLElement \| null`         |
| `document.querySelectorAll("li")`    | `NodeListOf<HTMLLIElement>`   |
| `document.createElement("button")`   | `HTMLButtonElement`           |

С **именем тега** вроде `"input"` TypeScript точно знает, какой элемент вы получите. С **id или классом** знать он не может: `#name` может стоять на поле ввода, заголовке или фигуре SVG. А поиск всегда может вернуться ни с чем — отсюда `| null`.

<TryIt

  html={`<label>Ваше имя <input value="Mei"></label>
<button>Поздороваться</button>
<p id="out"></p>`}
  code={`// Имена тегов дают точные типы
const input = document.querySelector("input");
const button = document.querySelector("button");
// id точного типа не даёт, но у HTMLElement есть textContent
const out = document.getElementById("out");

if (input && button && out) {
  button.addEventListener("click", () => {
    out.textContent = \`Привет, \${input.value}! 🐼\`;
  });
  console.log("Значение:", input.value);
  console.log("Отключена?", button.disabled);
}`}
/>

Наведите курсор на переменные в настоящем редакторе — и увидите `HTMLInputElement | null`, `HTMLButtonElement | null` и `HTMLElement | null`. Внутри `if` никакого `null` уже нет, и TypeScript помнит это даже внутри обработчика клика.

## Что делать с null

Без проверки TypeScript вас остановит. Вот что происходит, если прочитать поле ввода по его id:

```ts
const nameInput = document.querySelector("#name");
console.log(nameInput.value);
// ❌ Error: 'nameInput' is possibly 'null'.
// ❌ Error: Property 'value' does not exist on type 'Element'.
```

Здесь две разные проблемы: элемента может **не быть**, а даже если он есть, TypeScript не знает, что это **поле ввода**. Разберём их по очереди.

Отсутствующий элемент — реальная ошибка, которая случается постоянно: опечатка в селекторе, id переименовали в HTML, скрипт запустился раньше, чем страница готова. Обращаться с `null` можно тремя способами:

1. **Проверить и выйти пораньше.** `if (!button) throw new Error("Нет кнопки #save")` даёт понятное сообщение об ошибке в нужном месте, а после этой строки TypeScript знает, что элемент существует.
2. **Опциональная цепочка** (optional chaining) для элементов, которые действительно необязательны: `banner?.remove()` ничего не делает, если баннера нет.
3. **Утверждение non-null `!`** (non-null assertion): `document.querySelector("button")!` говорит TypeScript «поверь, он есть». Оно убирает `null` из типа и ничего не проверяет (подробнее — в уроке [Защитники типа и unknown](/learn/typescript/type-guards-and-unknown)).

<Callout type="warning" title="! — это обещание, а не проверка">

Если вы ошиблись с `!`, код упадёт позже с невнятным `Cannot read properties of null` где-то далеко от настоящей ошибки. Предпочитайте проверку, которая бросает полезное сообщение. Оставьте `!` для мест, где вы действительно уверены, — например, для элемента, который записан прямо в вашем HTML строчкой выше скрипта.

</Callout>

У первого способа в больших скриптах есть подвох: сужение типа не проникает внутрь **объявлений функций** (function declarations).

```ts
const list = document.querySelector("ul");
if (!list) throw new Error("На странице нет списка");

function render(): void {
  list.replaceChildren();
  // ❌ Error: 'list' is possibly 'null'.
}
```

Объявления функций **поднимаются** (hoisting): `render()` можно вызвать в самом начале файла, ещё до того, как сработала проверка, поэтому TypeScript на неё не полагается. (Стрелочные функции, созданные после проверки, как обработчик клика выше, работают нормально.) Изящное решение — делать проверку **внутри функции, которая возвращает элемент**, чтобы в типе переменной вообще никогда не было `null`. Именно такую функцию вы соберёте в следующем разделе.

## Получаем правильный тип элемента

Теперь вторая проблема: у `Element` нет `value`. TypeScript предлагает три способа сказать, какой элемент вы ожидаете, и они **не** одинаково безопасны:

```ts
// 1. Аргумент типа: «этот селектор находит поле ввода»
const a = document.querySelector<HTMLInputElement>("#name");
// a: HTMLInputElement | null

// 2. Приведение через as: «поверь, это поле ввода»
const b = document.querySelector("#name") as HTMLInputElement;
// b: HTMLInputElement (null тихо исчез!)

// 3. instanceof: настоящая проверка во время выполнения
const c = document.querySelector("#name");
if (c instanceof HTMLInputElement) {
  // c: HTMLInputElement
}
```

Способы 1 и 2 — только **заявления**. При запуске кода типы исчезают, поэтому, если в HTML написано `<p id="name">`, никто не пожалуется: `b.value` будет `undefined`, а `b.value.trim()` упадёт. Способ 3 — настоящая проверка во время выполнения, и TypeScript **сужает** тип внутри `if`, точно так же как при [сужении через `instanceof`](/learn/typescript/union-types), которое вы применяли к своим классам.

Проверять каждый элемент вручную быстро надоедает, поэтому во многих проектах это оборачивают в небольшой [обобщённый](/learn/typescript/generic-functions) помощник. Он находит элемент, проверяет, что тот существует и имеет нужный вид, и возвращает его с точным типом, без `null`:

<TryIt
  language="typescript"
  html={`<label>Цельсий <input id="celsius" type="number" value="20"></label>
<p id="result"></p>`}
  code={`function query<T extends Element>(
  selector: string,
  type: new () => T,
): T {
  const element = document.querySelector(selector);
  if (!(element instanceof type)) {
    throw new Error(\`Ожидалось, что \${selector} — это \${type.name}\`);
  }
  return element;
}

const celsius = query("#celsius", HTMLInputElement);
const result = query("#result", HTMLParagraphElement);

function convert(): void {
  const c = celsius.valueAsNumber; // число, NaN для пустого поля
  result.textContent = Number.isNaN(c)
    ? "Введите температуру"
    : \`\${c} °C = \${(c * 9 / 5 + 32).toFixed(1)} °F\`;
}

celsius.addEventListener("input", convert);
convert();

// Неверная догадка падает громко и с полезным сообщением
try {
  query("#result", HTMLInputElement);
} catch (error) {
  console.log(error instanceof Error ? error.message : error);
}`}
/>

Второй параметр — это **сам класс**: как и [любой класс](/learn/typescript/structural-typing-and-class-design), `HTMLInputElement` — это одновременно значение и тип, а `new () => T` означает «то, с помощью чего можно создать `T`». Передайте `HTMLInputElement` — и `T` станет `HTMLInputElement`, так что `celsius.valueAsNumber` разрешён. И отсутствующий, и не тот элемент сразу бросают ошибку с сообщением, в котором назван селектор. Дальше в уроке примеры используют `query`; в настоящем проекте эта функция жила бы в отдельном модуле — это тема следующего урока.

Обратите внимание на `valueAsNumber`. `value` у поля ввода — **всегда строка**, даже при `type="number"`, поэтому `const age: number = ageInput.value` — ошибка типа. Используйте `valueAsNumber` (или `Number(input.value)`) и проверяйте на `NaN`.

## Создаём элементы

`document.createElement` принимает имя тега, поэтому его результат всегда точный: `createElement("li")` — это `HTMLLIElement`, `createElement("input")` — `HTMLInputElement`. Затем TypeScript проверяет, что вы с ним делаете:

```ts
const item = document.createElement("li");
item.disabled = true;
// ❌ Error: Property 'disabled' does not exist on type 'HTMLLIElement'.
```

Элемент списка нельзя отключить, так что эта строка в любом случае была ошибкой. А `createElement("button")` её бы принял.

**Data-атрибуты** тоже типизированы. `element.dataset` хранит только **строки**, а чтение даёт `string | undefined`, потому что атрибута может не быть:

```ts
const button = document.createElement("button");
button.dataset.id = 3;
// ❌ Error: Type 'number' is not assignable to type 'string'.
button.dataset.id = String(3); // ✅

const id: string = button.dataset.id;
// ❌ Error: Type 'string | undefined' is not assignable to type 'string'.
const id2 = Number(button.dataset.id); // ✅ число (NaN, если нет)
```

В JavaScript `button.dataset.id = 3` тихо превращает `3` в `"3"`. TypeScript заставляет написать преобразование явно, чтобы потом никто не удивлялся, когда `"3" + 1` даст `"31"`.

## Типизированные события

Когда вы вызываете `addEventListener` с именем события (event), TypeScript сам подбирает нужный тип события:

| Имя события            | Тип события     | Полезные свойства                   |
| ---------------------- | --------------- | ----------------------------------- |
| `"click"`              | `PointerEvent`  | `clientX`, `button`, `shiftKey`     |
| `"keydown"`, `"keyup"` | `KeyboardEvent` | `key`, `code`, `ctrlKey`            |
| `"submit"`             | `SubmitEvent`   | `submitter`, `preventDefault()`     |
| `"input"`              | `InputEvent`    | `data`, `inputType`                 |
| `"change"`             | `Event`         | `target`, `currentTarget`           |

(`PointerEvent` — это `MouseEvent` с дополнительными сведениями об указателе, например о стилусе или пальце.) Во встроенной стрелочной функции всё это вы получаете бесплатно, а опечатки ловятся:

```ts
document.addEventListener("keydown", (event) => {
  console.log(event.kye);
  // ❌ Error: Property 'kye' does not exist on type 'KeyboardEvent'.
});
```

Когда обработчик — **отдельная функция**, выводить тип не из чего, поэтому аннотируйте параметр сами. Тогда TypeScript проверит, что функция подходит к событию:

<TryIt
  language="typescript"
  html={`<p>Кликните здесь, а потом нажимайте ← и →</p>
<p id="slide" style="font-size: 48px">🐼</p>
<p id="info"></p>`}
  code={`function query<T extends Element>(
  selector: string,
  type: new () => T,
): T {
  const element = document.querySelector(selector);
  if (!(element instanceof type)) {
    throw new Error(\`Ожидалось, что \${selector} — это \${type.name}\`);
  }
  return element;
}

const slides = ["🐼", "🎋", "🍵", "🏯"];
let index = 0;

const slide = query("#slide", HTMLParagraphElement);
const info = query("#info", HTMLParagraphElement);

function show(): void {
  slide.textContent = slides[index];
  info.textContent = \`Слайд \${index + 1} из \${slides.length}\`;
}

function onKey(event: KeyboardEvent): void {
  if (event.key === "ArrowRight") {
    index = (index + 1) % slides.length;
  } else if (event.key === "ArrowLeft") {
    index = (index - 1 + slides.length) % slides.length;
  } else {
    return; // не наша клавиша
  }
  show();
}

document.addEventListener("keydown", onKey);
show();`}
/>

Попробуйте зарегистрировать `onKey` для `"click"`: TypeScript сообщит `No overload matches this call.` с длинным объяснением, потому что клик — это `PointerEvent`, а у него нет `key`.

## event.target и делегирование

Есть одно свойство события, которое удивляет всех:

```ts
form.addEventListener("submit", (event) => {
  console.log(event.target.value);
  // ❌ Error: 'event.target' is possibly 'null'.
  // ❌ Error: Property 'value' does not exist on type 'EventTarget'.
});
```

`event.target` имеет самый общий тип `EventTarget | null`. Это честно: события **всплывают**, поэтому целью может быть любой вложенный элемент или даже документ и окно. (У `event.currentTarget` тот же тип по той же причине.) Есть два хороших выхода:

- Если элемент уже лежит в переменной, **используйте переменную**. Внутри обработчика отправки формы читайте `nameInput.value`, а не `event.target`.
- При **делегировании событий** (event delegation), когда один обработчик обслуживает много дочерних элементов, **сужайте** цель через `instanceof`.

Вот делегирование с типизированными данными. Один обработчик на списке обслуживает все кнопки голосования, включая те, что `render()` создаст позже:

<TryIt
  language="typescript"
  html={`<style>
  li { margin: 6px 0; }
  li button { margin-left: 8px; }
</style>
<p>Голосуйте за лучший перекус:</p>
<ul></ul>`}
  code={`function query<T extends Element>(
  selector: string,
  type: new () => T,
): T {
  const element = document.querySelector(selector);
  if (!(element instanceof type)) {
    throw new Error(\`Ожидалось, что \${selector} — это \${type.name}\`);
  }
  return element;
}

interface Snack {
  id: number;
  name: string;
  votes: number;
}

const snacks: Snack[] = [
  { id: 1, name: "Бамбук", votes: 2 },
  { id: 2, name: "Яблоки", votes: 0 },
  { id: 3, name: "Листовой чай", votes: 1 },
];

const list = query("ul", HTMLUListElement);

function render(): void {
  list.replaceChildren();
  for (const snack of snacks) {
    const item = document.createElement("li");
    item.textContent = snack.name;

    const button = document.createElement("button");
    button.textContent = \`👍 \${snack.votes}\`;
    button.dataset.id = String(snack.id);

    item.append(button);
    list.append(item);
  }
}

list.addEventListener("click", (event) => {
  // Клики по тексту и промежуткам игнорируются
  if (!(event.target instanceof HTMLButtonElement)) return;

  const id = Number(event.target.dataset.id);
  const snack = snacks.find((s) => s.id === id);
  if (!snack) return;

  snack.votes++;
  console.log(\`\${snack.name}: голосов — \${snack.votes}\`);
  render();
});

render();`}
/>

Внутри обработчика после проверки `instanceof` у `event.target` тип `HTMLButtonElement`, поэтому `dataset` доступен. А `find` возвращает `Snack | undefined`, так что TypeScript следит, чтобы вы обработали неизвестный id.

## Сохраняем данные в localStorage

`localStorage` хранит **строки**. `getItem` возвращает `string | null` (`null`, если ещё ничего не сохранено), и передать это прямо в `JSON.parse` — ошибка:

```ts
JSON.parse(localStorage.getItem("settings"));
// ❌ Error: Argument of type 'string | null' is not assignable to parameter of type 'string'.
```

Бо́льшая опасность — с обратной стороны. `JSON.parse` возвращает `any`, поэтому вот это компилируется без единого слова:

```ts
const settings: Settings = JSON.parse(text); // ни ошибки, ни проверки!
```

Но сохранённый текст может оказаться чем угодно: данными от старой версии приложения, значением, которое кто-то поправил в DevTools браузера, или недописанным JSON. Относитесь к нему как к любым другим данным извне: дайте ему тип `unknown` и проверьте [защитником типа](/learn/typescript/type-guards-and-unknown) (type guard), прежде чем использовать.

<TryIt
  language="typescript"
  html={`<label><input type="checkbox" id="dark"> Тёмная тема</label>
<label>Размер <input type="range" id="size" min="12" max="28"></label>
<p id="sample">Шустрая панда дремлет под бамбуком.</p>`}
  code={`function query<T extends Element>(
  selector: string,
  type: new () => T,
): T {
  const element = document.querySelector(selector);
  if (!(element instanceof type)) {
    throw new Error(\`Ожидалось, что \${selector} — это \${type.name}\`);
  }
  return element;
}

interface Settings {
  dark: boolean;
  fontSize: number;
}

const DEFAULTS: Settings = { dark: false, fontSize: 16 };

function isSettings(value: unknown): value is Settings {
  return (
    typeof value === "object" &&
    value !== null &&
    "dark" in value &&
    typeof value.dark === "boolean" &&
    "fontSize" in value &&
    typeof value.fontSize === "number"
  );
}

function loadSettings(): Settings {
  const text = localStorage.getItem("settings");
  if (text === null) return DEFAULTS; // ещё ничего не сохранено
  try {
    const data: unknown = JSON.parse(text);
    return isSettings(data) ? data : DEFAULTS;
  } catch {
    return DEFAULTS; // это даже не корректный JSON
  }
}

function saveSettings(settings: Settings): void {
  localStorage.setItem("settings", JSON.stringify(settings));
}

const dark = query("#dark", HTMLInputElement);
const size = query("#size", HTMLInputElement);
const sample = query("#sample", HTMLParagraphElement);

function apply(settings: Settings): void {
  dark.checked = settings.dark;
  size.value = String(settings.fontSize);
  sample.style.fontSize = \`\${settings.fontSize}px\`;
  sample.style.background = settings.dark ? "#1e1b4b" : "";
  sample.style.color = settings.dark ? "#e0e7ff" : "";
}

function onChange(): void {
  const settings: Settings = {
    dark: dark.checked,
    fontSize: Number(size.value),
  };
  saveSettings(settings);
  apply(settings);
}

dark.addEventListener("change", onChange);
size.addEventListener("input", onChange);

const settings = loadSettings();
console.log("Загружено:", settings);
apply(settings);`}
/>

Поменяйте настройки и снова нажмите **«Запустить»**: предпросмотр сохраняет хранилище между запусками — так же, как браузер сохраняет его между перезагрузками страницы, — поэтому ваши настройки вернутся. Испорченное сохранённое значение не уронит страницу: будут использованы значения по умолчанию.

<Callout type="tip" title="Проверяйте данные там, где они входят">

Проверяйте внешние данные **один раз**, на границе, в функции вроде `loadSettings`. Всё, что дальше, работает с настоящим `Settings`, и больше проверок не нужно. Та же идея работает для данных из форм, URL и — позже в курсе — API.

</Callout>

```ts
type Theme = "bamboo" | "night";

interface Profile {
  name: string;
  age: number;
  theme: Theme;
}

function isTheme(value: string): value is Theme {
  return value === "bamboo" || value === "night";
}

function query<T extends Element>(
  selector: string,
  type: new () => T,
): T {
  const element = document.querySelector(selector);
  if (!(element instanceof type)) {
    throw new Error(`Ожидалось, что ${selector} — это ${type.name}`);
  }
  return element;
}

const form = query("#profile", HTMLFormElement);
const nameInput = query("#name", HTMLInputElement);
const ageInput = query("#age", HTMLInputElement);
const themeSelect = query("#theme", HTMLSelectElement);
const message = query("#message", HTMLParagraphElement);
const card = query("#card", HTMLDivElement);
const cardName = query("#card-name", HTMLElement);
const cardAge = query("#card-age", HTMLParagraphElement);

function renderPreview(): void {
  cardName.textContent = nameInput.value.trim() || "Ваше имя";
  cardAge.textContent = `Возраст: ${ageInput.value || "?"}`;
  card.dataset.theme = themeSelect.value;
}

function readProfile(): Profile | string {
  const name = nameInput.value.trim();
  if (name.length < 2) {
    return "В имени должно быть не меньше 2 символов";
  }
  const age = ageInput.valueAsNumber; // NaN для пустого поля
  if (!Number.isInteger(age) || age < 1 || age > 120) {
    return "Возраст должен быть целым числом от 1 до 120";
  }
  const theme = themeSelect.value;
  if (!isTheme(theme)) {
    return "Выберите тему";
  }
  return { name, age, theme };
}

function isProfile(value: unknown): value is Profile {
  return (
    typeof value === "object" &&
    value !== null &&
    "name" in value &&
    typeof value.name === "string" &&
    "age" in value &&
    typeof value.age === "number" &&
    "theme" in value &&
    typeof value.theme === "string" &&
    isTheme(value.theme)
  );
}

function loadProfile(): Profile | null {
  const text = localStorage.getItem("profile");
  if (text === null) return null;
  try {
    const data: unknown = JSON.parse(text);
    return isProfile(data) ? data : null;
  } catch {
    return null;
  }
}

form.addEventListener("input", renderPreview);

form.addEventListener("submit", (event) => {
  event.preventDefault();
  const result = readProfile();
  if (typeof result === "string") {
    message.textContent = result;
    return;
  }
  localStorage.setItem("profile", JSON.stringify(result));
  message.textContent = "Сохранено!";
});

// Бонус: заполнить форму из сохранённого профиля
// (нажмите «Запустить» ещё раз)
const saved = loadProfile();
if (saved) {
  nameInput.value = saved.name;
  ageInput.value = String(saved.age);
  themeSelect.value = saved.theme;
}

renderPreview();
```

## Итоги

- Типы DOM образуют семейство: `Element` → `HTMLElement` → `HTMLInputElement` и его родня. Селекторы по тегу и `createElement` дают точные типы; id и классы дают `Element`.
- Поиск может вернуть `null`. Проверяйте и бросайте полезную ошибку, используйте `?.` для необязательных элементов, а `!` оставьте для случаев, когда вы действительно уверены.
- `querySelector<T>` и `as` — заявления; `instanceof` — настоящая проверка, которая сужает тип. Небольшой обобщённый помощник `query(selector, Class)` делает её повсюду.
- `addEventListener` выводит тип события (`PointerEvent`, `KeyboardEvent`, `SubmitEvent`…); именованные обработчики аннотируйте сами. `event.target` — это `EventTarget | null`: используйте переменную с элементом или сужайте через `instanceof`.
- Значения полей ввода и `dataset` — строки: преобразуйте их через `valueAsNumber`, `Number()` или `String()`.
- `localStorage` даёт `string | null`, а `JSON.parse` — `any`: считайте сохранённые данные `unknown` и проверяйте их защитником типа.
