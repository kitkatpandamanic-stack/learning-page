Настоящие проекты не умещаются в один файл. Ваш код разбит на **модули** (modules), а большая часть кода, который вы запускаете, вообще не ваша: npm-пакеты, скрипты, загруженные с CDN, сам браузер. В этом уроке вы увидите, как типы путешествуют между вашими файлами, где TypeScript находит типы чужого кода и что делать, когда их нет. 📦

<Callout type="note" title="Примеры в этом уроке">

Редактор PandaDev запускает по одному файлу за раз, поэтому примеры из нескольких файлов показаны как обычные файлы с именем сверху. Каждый фрагмент, который вы здесь запускаете, всё равно является модулем, так что `import` из встроенных пакетов, `export`, `declare` и `declare global` работают.

</Callout>

## Модули в TypeScript

TypeScript использует те же `import` и `export`, что и JavaScript (загляните в урок [Модули: import и export](/learn/javascript/modules), если нужно освежить память). Разница в том, что экспортировать можно не только значения, но и **типы**. Вот помощник `query` из прошлого урока, перенесённый в отдельный модуль, и модуль с общими типами:

```ts title="src/dom.ts"
export function query<T extends Element>(
  selector: string,
  type: new () => T,
): T {
  const element = document.querySelector(selector);
  if (!(element instanceof type)) {
    throw new Error(`Ожидалось, что ${selector} — это ${type.name}`);
  }
  return element;
}
```

```ts title="src/profile.ts"
export type Theme = "bamboo" | "night";

export interface Profile {
  name: string;
  age: number;
  theme: Theme;
}

export function isTheme(value: string): value is Theme {
  return value === "bamboo" || value === "night";
}
```

```ts title="src/main.ts"
import { query } from "./dom";
import { isTheme, type Profile } from "./profile";

const nameInput = query("#name", HTMLInputElement);
const fallback: Profile = { name: "Гость", age: 1, theme: "bamboo" };
```

Типы переходят из файла в файл: в `main.ts` объект `fallback` проверяется по интерфейсу `Profile` из `profile.ts`, и если кто-то переименует там `theme`, ошибку получит каждый файл, который его использует.

<Callout type="warning" title="Иногда для файла .ts пишут .js">

С бандлером (bundler) вроде Vite вы пишете `"./profile"`, как выше. Проекты, которые работают на Node.js с `"module": "nodenext"`, должны писать `"./profile.js"`, хотя на диске лежит `profile.ts`, потому что импорт должен указывать на файл, который будет **выполняться** после компиляции. Если забудете, TypeScript напомнит:

```text
error TS2835: Relative import paths need explicit file extensions in ECMAScript imports when '--moduleResolution' is 'node16' or 'nodenext'. Did you mean './profile.js'?
```

</Callout>

## Импорт только типов

Ещё раз посмотрите на второй импорт в `main.ts`: `type Profile`. Слово `type` помечает импорт как **импорт только типа** (type-only import): его использует проверка типов, а потом он удаляется полностью, и в JavaScript от него ничего не остаётся. Записать это можно двумя способами:

```ts
// Весь импорт — только типы
import type { Profile, Theme } from "./profile";

// Смешанный: isTheme — значение, Profile — тип
import { isTheme, type Profile } from "./profile";

// Реэкспорт типов из другого модуля
export type { Profile, Theme } from "./profile";
```

Импорты из пакетов работают так же. В этом примере Express (популярный пакет для веб-серверов, с которым вы как следует поработаете на Уровне 2) даёт и значения (`express()`), и типы (`Request`, `Response`). Обработчик написан отдельно, поэтому его параметрам нужны типы Express:

<CodeExample output={`200 [ { id: 1, text: 'Купить бамбук' } ]`}>

```ts
import express from "express";
import type { Request, Response } from "express";
import request from "supertest";

interface Note {
  id: number;
  text: string;
}

const notes: Note[] = [{ id: 1, text: "Купить бамбук" }];

// Обработчику, написанному отдельно, нужны типы Express
function listNotes(req: Request, res: Response<Note[]>): void {
  res.json(notes);
}

const app = express();
app.get("/notes", listNotes);

const res = await request(app).get("/notes");
console.log(res.status, res.body);
```

</CodeExample>

### Почему это важно

Зачем вообще помечать типы? Потому что многие инструменты, которые запускают TypeScript, **вообще не проверяют типы**. Vite, Node.js и большинство бандлеров просто удаляют типы и запускают то, что осталось, причём смотрят на **один файл за раз**. Когда такой инструмент видит `import { Item } from "./prices.ts"`, он не может понять, тип ли `Item` (удалить) или значение (оставить), не прочитав другой файл. Если он угадает неправильно, код упадёт. Вот что на самом деле выводит Node.js, когда запускает файл, импортирующий интерфейс `Item` без `type`:

```text
SyntaxError: The requested module './prices.ts' does not provide an export named 'Item'
```

С `import { total, type Item }` импорт `Item` удаляется, и тот же файл работает без проблем. Параметр **`verbatimModuleSyntax`** в `tsconfig.json` (урок 3) заставляет TypeScript требовать этого, так что вы узнаете о проблеме в редакторе, а не во время выполнения:

```ts
import { Item } from "./prices.js";
// ❌ Error: 'Item' is a type and must be imported using a type-only import when 'verbatimModuleSyntax' is enabled.
```

## Откуда берутся типы

Когда вы пишете `import ... from "something"`, TypeScript отправляется на поиски типов:

1. **Ваши собственные файлы.** `"./profile"` находит `profile.ts` (или `profile.tsx`, или `profile.d.ts`). Типы берутся прямо из вашего кода.
2. **Пакеты со своими типами.** Многие пакеты, например Vitest, Zod или date-fns, написаны на TypeScript или содержат файлы с типами. Их `package.json` указывает на эти файлы, и типы появляются в момент установки пакета.
3. **DefinitelyTyped.** Для пакетов, написанных на чистом JavaScript, сообщество хранит типы в огромном общем репозитории (repository) под названием **DefinitelyTyped**. Они публикуются как отдельные пакеты `@types/...`, которые устанавливают как dev-зависимости:

```bash
npm install express            # сам код
npm install -D @types/express  # его типы из DefinitelyTyped
```

На npmjs.com маленький значок **TS** рядом с именем пакета означает, что он поставляется со своими типами, а значок **DT** — что для него есть пакет `@types`.

4. **Ничего не найдено.** Тогда TypeScript сдаётся. В строгом режиме использовать пакет без типов — ошибка; вот она для выдуманного пакета `panda-slug`:

```text
error TS7016: Could not find a declaration file for module 'panda-slug'. '…/node_modules/panda-slug/index.js' implicitly has an 'any' type.
  Try `npm i --save-dev @types/panda-slug` if it exists or add a new declaration (.d.ts) file containing `declare module 'panda-slug';`
```

Собственные типы браузера устроены так же. `HTMLInputElement`, `document` и `localStorage` из прошлого урока описаны в **`lib.dom.d.ts`** — файле примерно на 45 000 строк, который поставляется вместе с TypeScript. Вот его крошечный кусочек, немного упрощённый:

```ts title="node_modules/typescript/lib/lib.dom.d.ts"
interface HTMLInputElement extends HTMLElement {
  value: string;
  valueAsNumber: number;
  // …и ещё сотни строк
}

declare var HTMLInputElement: {
  prototype: HTMLInputElement;
  new(): HTMLInputElement;
};
```

Именно благодаря `new(): HTMLInputElement` вызов `query("#name", HTMLInputElement)` подошёл к параметру `new () => T` вашего помощника.

## Файлы объявлений

Файл с расширением **`.d.ts`** — это **файл объявлений** (declaration file). В нём только типы: никаких тел функций, никаких значений, ничего, что выполняется. Он описывает код, который живёт где-то ещё. При компиляции библиотеки TypeScript может сам записать такой файл рядом с каждым `.js` (параметр `declaration`). Для такого файла:

```ts title="src/prices.ts"
export interface Item {
  name: string;
  price: number;
}

export function total(items: Item[]): number {
  return items.reduce((sum, item) => sum + item.price, 0);
}
```

компилятор создаёт код (`prices.js`) и вот такой файл объявлений:

```ts title="dist/prices.d.ts"
export interface Item {
    name: string;
    price: number;
}
export declare function total(items: Item[]): number;
```

Ключевое слово **`declare`** означает «это существует, поверь мне, вот его тип». Оно никогда ничего не создаёт. Именно так JavaScript-пакет и его типы поставляются вместе.

### Пишем объявления для нетипизированного пакета

Когда у пакета нет ни своих типов, ни пакета `@types`, объявления можно написать самим. Опишите только те части, которыми пользуетесь, в файле `.d.ts` внутри своего проекта:

```ts title="src/types/panda-slug.d.ts"
declare module "panda-slug" {
  export function slugify(text: string, separator?: string): string;
}
```

Теперь импорт типизирован, а ошибки ловятся:

```ts title="src/main.ts"
import { slugify } from "panda-slug";

slugify("Hello Panda World"); // "hello-panda-world"
slugify(42);
// ❌ Error: Argument of type 'number' is not assignable to parameter of type 'string'.
```

Если торопитесь, однострочная версия `declare module "panda-slug";` (без тела) тоже заглушит ошибку, но тогда всё из пакета будет `any`, и `slugify(42)` скомпилируется. Для первого шага сойдёт, но не как окончательное решение.

<Callout type="danger" title="TypeScript верит вашим объявлениям">

Объявление — это обещание, и никто не сверяет его с настоящим JavaScript. Если ваш `.d.ts` говорит, что `slugify` возвращает `string`, а на самом деле для пустого ввода она возвращает `undefined`, TypeScript охотно вам поверит, и ошибка проскочит. Читайте документацию или код библиотеки, описывайте только то, чем пользуетесь, и обновляйте объявления, когда обновляете пакет. Если вы написали хорошие типы для популярного пакета, подумайте о том, чтобы отправить их в DefinitelyTyped, — пусть пользу получат все.

</Callout>

## Глобальные объявления

Не всё приходит через `import`. Тег `<script>` может загрузить с CDN скрипт аналитики или старую библиотеку, а серверы часто записывают настройки прямо в страницу. Так появляются **глобальные** переменные, о которых TypeScript никогда не слышал:

```ts
miniChart.bars(chart, [3, 8, 5]);
// ❌ Error: Cannot find name 'miniChart'.
console.log(window.appConfig.siteName);
// ❌ Error: Property 'appConfig' does not exist on type 'Window & typeof globalThis'.
```

Описывайте их с помощью **`declare global`**. Внутри него `const` объявляет глобальную переменную, а `interface Window` **добавляет** свойства в существующий интерфейс `Window` (интерфейсы с одинаковым именем сливаются). На этой странице тег script создаёт обе глобальные переменные до того, как запустится ваш код:

<TryIt
  language="typescript"
  html={`<script>
  // Старая библиотека графиков, загруженная тегом script. Без типов!
  window.miniChart = {
    version: "1.2.0",
    bars: function (target, values, options) {
      var color = (options && options.color) || "#7c3aed";
      target.replaceChildren();
      values.forEach(function (value) {
        var bar = document.createElement("div");
        bar.style.height = "18px";
        bar.style.margin = "4px 0";
        bar.style.borderRadius = "4px";
        bar.style.width = value * 16 + "px";
        bar.style.background = color;
        target.append(bar);
      });
    },
  };
  // Настройки, которые сервер записал в страницу
  window.appConfig = { siteName: "Bamboo Times", maxBars: 5 };
</script>
<h3 id="title"></h3>
<div id="chart"></div>`}
  code={`interface ChartOptions {
  color?: string;
}

interface MiniChart {
  version: string;
  bars(
    target: HTMLElement,
    values: number[],
    options?: ChartOptions,
  ): void;
}

interface AppConfig {
  siteName: string;
  maxBars: number;
}

// Описываем то, что создал тег script. Здесь ничего не выполняется!
declare global {
  const miniChart: MiniChart;
  interface Window {
    appConfig: AppConfig;
  }
}

const title = document.getElementById("title");
const chart = document.getElementById("chart");

Попробуйте заменить `{ color: "#16a34a" }` на `{ colour: "#16a34a" }`: объявление поймает опечатку. Потом удалите весь блок `declare global` и посмотрите, как возвращаются ошибки, показанные выше.

В настоящем проекте такие объявления кладут в файл вроде `src/globals.d.ts`. Одна деталь: файл, в котором есть `import` или `export`, — это **модуль**, и глобальные объявления в модуле нужно оборачивать в `declare global { … }`, как выше. Файл `.d.ts` без импортов и экспортов — это **глобальный скрипт**, поэтому там можно писать `declare const miniChart: MiniChart;` и `interface Window { … }` напрямую. В любом случае убедитесь, что файл лежит в папках, которые включает ваш `tsconfig.json`, — с этого как раз и начинается следующий урок.

Страница загружает **panda-toast**, старую библиотеку уведомлений, через тег `<script>`. Типов у неё нет, так что TypeScript даже не знает, что она существует. Прочитайте скрипт на странице, чтобы понять, что она предоставляет:

- `pandaToast.version`: строка;
- `pandaToast.show(message, options?)`: показывает уведомление и возвращает его **числовой** id. `options.kind` — это `"info"`, `"success"` или `"error"`;
- `pandaToast.dismiss(id)`: убирает это уведомление и возвращает `true` или `false`, если такого уведомления не было.

1. В начале файла напишите типы для библиотеки (объединение `ToastKind`, `ToastOptions` и интерфейс `PandaToast`) и объявите глобальную `pandaToast` через `declare global`. **Тесты типов** в `typeTests()` проходят, только если ваши типы точные: с `any` или `kind?: string` TypeScript сообщит `Unused '@ts-expect-error' directive.`, потому что строка под директивой больше не ошибка.
2. `notifySaved(count)` показывает уведомление **об успехе** `Сохранено заметок: 3` (`Сохранена 1 заметка` для одной) и возвращает id уведомления.
3. `notifyError(error)` показывает уведомление **об ошибке** с `message` ошибки, если это `Error`, или `Что-то пошло не так` в противном случае, и возвращает id.
4. `clearAll(ids)` закрывает все id и возвращает, сколько уведомлений действительно было убрано.

```ts
type ToastKind = "info" | "success" | "error";

interface ToastOptions {
  kind?: ToastKind;
}

interface PandaToast {
  version: string;
  show(message: string, options?: ToastOptions): number;
  dismiss(id: number): boolean;
}

declare global {
  const pandaToast: PandaToast;
}

function notifySaved(count: number): number {
  const text =
    count === 1 ? "Сохранена 1 заметка" : `Сохранено заметок: ${count}`;
  return pandaToast.show(text, { kind: "success" });
}

function notifyError(error: unknown): number {
  const message =
    error instanceof Error ? error.message : "Что-то пошло не так";
  return pandaToast.show(message, { kind: "error" });
}

function clearAll(ids: number[]): number {
  let removed = 0;
  for (const id of ids) {
    if (pandaToast.dismiss(id)) {
      removed++;
    }
  }
  return removed;
}

// Тесты типов: функция не вызывается, только проверяется.
// Строка под каждым комментарием expect-error ОБЯЗАНА быть
// ошибкой типа.
function typeTests(): void {
  // @ts-expect-error: сообщения — это строки
  pandaToast.show(42);
  // @ts-expect-error: "warning" — не вид уведомления
  pandaToast.show("Осторожно", { kind: "warning" });
  // @ts-expect-error: show() возвращает числовой id
  const wrongId: string = pandaToast.show("Привет");
  // @ts-expect-error: dismiss() нужен id
  pandaToast.dismiss();

  // Это должно компилироваться
  const id: number = pandaToast.show("Привет", { kind: "info" });
  const removed: boolean = pandaToast.dismiss(id);
  const version: string = pandaToast.version;
}

// Кнопки на странице
const shown: number[] = [];
document.querySelector("#save")?.addEventListener("click", () => {
  shown.push(notifySaved(shown.length + 1));
});
document.querySelector("#fail")?.addEventListener("click", () => {
  shown.push(notifyError(new Error("Диск заполнен")));
});
document.querySelector("#clear")?.addEventListener("click", () => {
  console.log(`Убрано уведомлений: ${clearAll(shown)}`);
  shown.length = 0;
});
```

## Итоги

- Модули TypeScript экспортируют и импортируют не только значения, но и **типы**, поэтому одним интерфейсом могут пользоваться все файлы.
- `import type { X }` и `import { value, type X }` помечают импорт только типов; из JavaScript он исчезает. Он нужен инструментам, которые компилируют по одному файлу за раз, а `verbatimModuleSyntax` требует его использовать.
- TypeScript находит типы в ваших файлах `.ts`, в пакетах со своими типами, в пакетах `@types/*` из DefinitelyTyped (`npm install -D @types/x`) и в своих встроенных файлах `lib.*.d.ts`.
- **Файл объявлений `.d.ts`** содержит только типы. `declare` говорит «это существует», ничего не создавая; `declare module "x" { … }` типизирует нетипизированный пакет.
- `declare global { … }` описывает глобальные переменные, созданные тегами script; `interface Window { … }` внутри него дополняет window. Объявления — это обещания: TypeScript им верит, поэтому следите за их точностью.
