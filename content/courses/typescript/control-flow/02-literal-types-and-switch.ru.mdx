`string` может быть **любым** текстом, но часто осмысленны лишь несколько значений: светофор бывает `"red"` (красный), `"amber"` (жёлтый) или `"green"` (зелёный), но никак не `"purple"`. TypeScript позволяет сказать именно это, а потом проверяет, что вы обработали каждый вариант. 🚦

## Литеральные типы

**Литеральный тип** (literal type) — это тип, который допускает ровно одно точное значение. Сам по себе он не слишком полезен, но объедините несколько таких типов через `|` — и получите точный список допустимых значений:

<CodeExample output="right">

```ts
let direction: "left" | "right" = "left";
direction = "right";

console.log(direction);
```

</CodeExample>

Всё, что не входит в список, — ошибка, так что опечатки тоже ловятся:

```ts
direction = "up";
// ❌ Error: Type '"up"' is not assignable to type '"left" | "right"'.
```

## Даём типам имена с помощью `type`

Писать всё объединение каждый раз долго. **Псевдоним типа** (type alias) даёт ему имя с помощью ключевого слова `type` (по соглашению имена типов начинаются с заглавной буквы):

<CodeExample output={`paper
[ 'rock', 'paper', 'scissors' ]
6`}>

```ts
type Move = "rock" | "paper" | "scissors";
type DiceRoll = 1 | 2 | 3 | 4 | 5 | 6;

const myMove: Move = "paper";
const allMoves: Move[] = ["rock", "paper", "scissors"];
const roll: DiceRoll = 6;

console.log(myMove);
console.log(allMoves);
console.log(roll);
```

</CodeExample>

Литеральные типы работают и с числами, как показывает `DiceRoll`. А `Move[]` — это массив, в котором каждый элемент должен быть `Move` (ход в игре «камень, ножницы, бумага»).

## `switch`: одно значение, много вариантов

Когда вы сравниваете одно значение с несколькими точными вариантами, `switch` выглядит аккуратнее длинной цепочки `if`/`else if`. Каждый `case` — это один вариант, а `break` (или `return`) не даёт выполнению перейти в следующий case:

<CodeExample output={`Стойте
Приготовьтесь
Идите`}>

```ts
type Light = "red" | "amber" | "green";

function action(light: Light): string {
  switch (light) {
    case "red":
      return "Стойте";
    case "amber":
      return "Приготовьтесь";
    case "green":
      return "Идите";
  }
}

console.log(action("red"));
console.log(action("amber"));
console.log(action("green"));
```

</CodeExample>

TypeScript понимает, что эти три case охватывают все возможные значения `Light`, поэтому знает, что функция всегда возвращает строку. Он также не даст проверить значение, которого быть не может:

```ts
case "blue":
// ❌ Error: Type '"blue"' is not comparable to type 'Light'.
```

Несколько case могут делить один блок, если поставить их друг под другом, а `default` ловит всё, что не перечислено:

<CodeExample output={`Выходной! 🎉
Будний день`}>

```ts
type Day = "Mon" | "Tue" | "Wed" | "Thu" | "Fri" | "Sat" | "Sun";

function describe(day: Day): string {
  switch (day) {
    case "Sat":
    case "Sun":
      return "Выходной! 🎉";
    default:
      return "Будний день";
  }
}

console.log(describe("Sun"));
console.log(describe("Wed"));
```

</CodeExample>

<Callout type="warning" title="Не забывайте break">

Если `case` не заканчивается на `return` или `break`, код продолжает выполняться в **следующем** case. Именно благодаря такому «проваливанию» (fall-through) `"Sat"` и `"Sun"` выше делят один блок, но если оно случилось нечаянно, получаются запутанные ошибки.

</Callout>

## Проверка полноты с помощью `never`

`never` — это тип, у которого **нет** ни одного значения. Поэтому он отлично работает как сигнализация. В ветке `default`, после того как все варианты обработаны, TypeScript сужает значение до `never`, и его можно присвоить переменной типа `never`:

<CodeExample output={`scissors
rock`}>

```ts
type Move = "rock" | "paper" | "scissors";

function beats(move: Move): Move {
  switch (move) {
    case "rock":
      return "scissors";
    case "paper":
      return "rock";
    case "scissors":
      return "paper";
    default: {
      const unreachable: never = move;
      return unreachable;
    }
  }
}

console.log(beats("rock"));
console.log(beats("paper"));
```

</CodeExample>

Теперь представьте, что позже кто-то добавит в `Move` вариант `"lizard"` (ящерица), но забудет обновить `beats`. Случай `"lizard"` не обработан, поэтому он попадает в `default`, и TypeScript сразу на него указывает:

```ts
type Move = "rock" | "paper" | "scissors" | "lizard";

// ...тот же switch, что и выше...
    default: {
      const unreachable: never = move;
      // ❌ Error: Type '"lizard"' is not assignable to type 'never'.
      return unreachable;
    }
```

<Callout type="tip">

Трюк с `never` превращает «я забыл один случай» из скрытой ошибки в ошибку типа. Используйте его всякий раз, когда делаете `switch` по объединению, которое может расшириться.

</Callout>

Допишите `play(player, computer)`, чтобы функция возвращала для игрока `"win"` (победа), `"lose"` (поражение) или `"draw"` (ничья). Возвращаемый тип — `Result`, поэтому TypeScript будет ругаться, если вернуть что-то другое (попробуйте вернуть `"won"` и посмотрите). Для бонуса используйте `switch` с проверкой через `never`, как в `beats` из урока.

<Hint>

Если `player === computer`, это ничья. Иначе напишите вспомогательную функцию `beats(move: Move): Move` со `switch`, которая возвращает ход, побеждаемый данным (для rock — `"scissors"` и так далее). Если `beats(player) === computer`, игрок выигрывает, а если нет — проигрывает.

</Hint>

<Solution>

```ts
type Move = "rock" | "paper" | "scissors";
type Result = "win" | "lose" | "draw";

function beats(move: Move): Move {
  switch (move) {
    case "rock":
      return "scissors";
    case "paper":
      return "rock";
    case "scissors":
      return "paper";
    default: {
      const unreachable: never = move;
      return unreachable;
    }
  }
}

function play(player: Move, computer: Move): Result {
  if (player === computer) {
    return "draw";
  }
  if (beats(player) === computer) {
    return "win";
  }
  return "lose";
}

console.log(play("rock", "scissors")); // win
console.log(play("rock", "paper")); // lose
console.log(play("paper", "paper")); // draw
```

</Solution>

</Exercise>

## Итоги

- **Литеральный тип** допускает одно точное значение; объединение литералов вроде `"rock" | "paper" | "scissors"` — это точный список вариантов.
- `type Name = ...` даёт типу имя, которое можно использовать повторно.
- `switch` сравнивает одно значение с множеством `case`; заканчивайте каждый на `return` или `break`.
- TypeScript проверяет, что каждый case — допустимый вариант.
- Присваивание переменной типа `never` в `default` заставляет TypeScript предупредить вас о забытых случаях.
