Programs need to make **decisions**: is the player old enough? Is the value a number or some text? In this lesson you'll write conditions with `if` and `else`, and see one of TypeScript's best tricks: it **narrows** a value's type as your code branches.

## `if`, `else if` and `else`

An `if` runs its block only when its **condition** is `true`. Add `else if` for more choices and `else` for "everything else". Conditions are checked from top to bottom, and only the **first** matching block runs:

<CodeExample output="Wear a jumper 🧶">

```ts
const temperature: number = 14;

if (temperature >= 25) {
  console.log("Shorts weather ☀️");
} else if (temperature >= 10) {
  console.log("Wear a jumper 🧶");
} else {
  console.log("Coat and scarf! 🧣");
}
```

</CodeExample>

## Comparison and logical operators

Comparisons give back a `boolean`, which is exactly what a condition needs:

| Operator          | Meaning                     |
| ----------------- | --------------------------- |
| `===` / `!==`     | equal / not equal           |
| `<` `>` `<=` `>=` | smaller, bigger, or equal   |
| `&&`              | AND: both must be true      |
| `\|\|`            | OR: at least one is true    |
| `!`               | NOT: flips true and false   |

<CodeExample output={`true
false
false`}>

```ts
const age: number = 15;
const hasTicket: boolean = true;

const canEnter: boolean = age >= 12 && hasTicket;
console.log(canEnter);
console.log(age === 18 || !hasTicket);
console.log(!canEnter);
```

</CodeExample>

TypeScript also spots comparisons that can never be true, like comparing a number with a string:

```ts
const age: number = 15;

if (age === "18") {
  // ❌ Error: This comparison appears to be unintentional because the types 'number' and 'string' have no overlap.
}
```

<Callout type="tip" title="Always use ===">

Use `===` and `!==`, never `==` and `!=`. The double-equals versions convert types behind your back (`"1" == 1` is `true`!), which is exactly the kind of surprise TypeScript is trying to save you from.

</Callout>

## Union types: this OR that

Sometimes a value can legitimately be one of several types. An ID might be a number like `42` or a code like `"ab-12"`. A **union type** says so with `|`:

```ts
let id: string | number = 42;
id = "ab-12"; // also fine
id = true;
// ❌ Error: Type 'boolean' is not assignable to type 'string | number'.
```

But there's a catch: you can only use things that work for **every** type in the union.

```ts
function formatId(id: string | number): string {
  return id.toUpperCase();
  // ❌ Error: Property 'toUpperCase' does not exist on type 'string | number'.
}
```

That makes sense: if `id` is a number, `.toUpperCase()` would crash.

## Narrowing with `typeof`

Check the type with `typeof` and TypeScript **narrows** the union inside each branch:

<CodeExample output={`AB-12
#0042`}>

```ts
function formatId(id: string | number): string {
  if (typeof id === "string") {
    return id.toUpperCase(); // id: string
  }
  // Only numbers get here, so id: number
  return "#" + id.toString().padStart(4, "0");
}

console.log(formatId("ab-12"));
console.log(formatId(42));
```

</CodeExample>

After the `if` returns, TypeScript knows only numbers can reach the last line. You didn't write any extra types: the check itself taught TypeScript what `id` is.

## Truthiness narrowing for `null`

Values that count as false in a condition are called **falsy**: `false`, `0`, `""` (empty string), `null`, `undefined` and `NaN`. Everything else is **truthy**. So `if (name)` is a quick way to rule out `null`:

<CodeExample output={`Welcome back, Mei!
Welcome, guest!`}>

```ts
function welcome(name: string | null): string {
  if (name) {
    return `Welcome back, ${name}!`; // name: string
  }
  return "Welcome, guest!";
}

console.log(welcome("Mei"));
console.log(welcome(null));
```

</CodeExample>

<Callout type="warning" title="Watch out for 0 and empty strings">

`if (value)` also rejects `0` and `""`. If those are valid values (a score of `0` is still a score!), check for null exactly with `if (value !== null)` instead.

</Callout>

<CodeExample output={`Score: 0
No score yet`}>

```ts
function showScore(score: number | null): string {
  if (score !== null) {
    return `Score: ${score}`; // score: number
  }
  return "No score yet";
}

console.log(showScore(0));
console.log(showScore(null));
```

</CodeExample>

A weather sensor sends its reading to `describeTemp(temp)`. The reading can be a **number** (degrees), a **string** (a status message such as `"offline"`) or **null** (no reading at all). First fix the type error by giving `temp` a union type, then return the right description for each case listed in the starter.

<Hint>

Handle `null` first with `if (temp === null)`. Don't use `if (!temp)`: that would treat `0` degrees as "no reading". Next, `if (typeof temp === "string")` handles messages. After those two checks, TypeScript knows `temp` is a number, so you can compare it with `<`.

</Hint>

<Solution>

```ts
function describeTemp(temp: number | string | null): string {
  if (temp === null) {
    return "No reading";
  }
  if (typeof temp === "string") {
    return "Sensor says: " + temp;
  }
  // temp is a number here
  if (temp < 10) {
    return "Cold";
  } else if (temp < 25) {
    return "Mild";
  } else {
    return "Hot";
  }
}

console.log(describeTemp(18)); // Mild
console.log(describeTemp("offline")); // Sensor says: offline
console.log(describeTemp(null)); // No reading
```

</Solution>

## Recap

- `if` / `else if` / `else` run the first block whose condition is `true`.
- Comparisons (`===`, `<`, ...) and logic (`&&`, `||`, `!`) produce booleans.
- A **union type** like `string | number` allows several types, but you can only use what works for all of them.
- `typeof` checks **narrow** a union inside each branch.
- `if (value)` rules out `null`, but also `0` and `""`; use `!== null` when those are valid.
