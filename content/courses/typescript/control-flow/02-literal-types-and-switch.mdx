A `string` can be **any** text, but often only a few values make sense: a traffic light is `"red"`, `"amber"` or `"green"`, never `"purple"`. TypeScript lets you say exactly that, and then checks that you handle every option. 🚦

## Literal types

A **literal type** is a type that allows just one exact value. On its own that's not very useful, but combine a few with `|` and you get a precise list of allowed values:

<CodeExample output="right">

```ts
let direction: "left" | "right" = "left";
direction = "right";

console.log(direction);
```

</CodeExample>

Anything outside the list is an error, so typos get caught too:

```ts
direction = "up";
// ❌ Error: Type '"up"' is not assignable to type '"left" | "right"'.
```

## Naming your types with `type`

Writing the whole union every time gets long. A **type alias** gives it a name with the `type` keyword (by convention, type names start with a capital letter):

<CodeExample output={`paper
[ 'rock', 'paper', 'scissors' ]
6`}>

```ts
type Move = "rock" | "paper" | "scissors";
type DiceRoll = 1 | 2 | 3 | 4 | 5 | 6;

const myMove: Move = "paper";
const allMoves: Move[] = ["rock", "paper", "scissors"];
const roll: DiceRoll = 6;

console.log(myMove);
console.log(allMoves);
console.log(roll);
```

</CodeExample>

Literal types work for numbers too, as `DiceRoll` shows. And `Move[]` is an array where every item must be a `Move`.

## `switch`: one value, many cases

When you compare one value against several exact options, `switch` is tidier than a long `if`/`else if` chain. Each `case` is one option, and `break` (or `return`) stops it from running into the next case:

<CodeExample output={`Stop
Get ready
Go`}>

```ts
type Light = "red" | "amber" | "green";

function action(light: Light): string {
  switch (light) {
    case "red":
      return "Stop";
    case "amber":
      return "Get ready";
    case "green":
      return "Go";
  }
}

console.log(action("red"));
console.log(action("amber"));
console.log(action("green"));
```

</CodeExample>

TypeScript understands that these three cases cover every possible `Light`, so it knows the function always returns a string. It also stops you from checking for a value that can't happen:

```ts
case "blue":
// ❌ Error: Type '"blue"' is not comparable to type 'Light'.
```

Several cases can share one block by stacking them, and `default` catches everything not listed:

<CodeExample output={`Weekend! 🎉
Weekday`}>

```ts
type Day = "Mon" | "Tue" | "Wed" | "Thu" | "Fri" | "Sat" | "Sun";

function describe(day: Day): string {
  switch (day) {
    case "Sat":
    case "Sun":
      return "Weekend! 🎉";
    default:
      return "Weekday";
  }
}

console.log(describe("Sun"));
console.log(describe("Wed"));
```

</CodeExample>

<Callout type="warning" title="Don't forget break">

If a `case` doesn't end with `return` or `break`, the code keeps running into the **next** case. That "fall-through" is how `"Sat"` and `"Sun"` share a block above, but by accident it causes confusing bugs.

</Callout>

## Exhaustiveness checking with `never`

`never` is the type with **no** values at all. That makes it a great alarm bell. In a `default` case, after every option has been handled, TypeScript has narrowed the value down to `never`, so you can assign it to a `never` variable:

<CodeExample output={`scissors
rock`}>

```ts
type Move = "rock" | "paper" | "scissors";

function beats(move: Move): Move {
  switch (move) {
    case "rock":
      return "scissors";
    case "paper":
      return "rock";
    case "scissors":
      return "paper";
    default: {
      const unreachable: never = move;
      return unreachable;
    }
  }
}

console.log(beats("rock"));
console.log(beats("paper"));
```

</CodeExample>

Now imagine someone adds `"lizard"` to `Move` later but forgets to update `beats`. The `"lizard"` case isn't handled, so it reaches `default`, and TypeScript points straight at it:

```ts
type Move = "rock" | "paper" | "scissors" | "lizard";

// ...same switch as above...
    default: {
      const unreachable: never = move;
      // ❌ Error: Type '"lizard"' is not assignable to type 'never'.
      return unreachable;
    }
```

<Callout type="tip">

The `never` trick turns "I forgot a case" from a hidden bug into a type error. Use it whenever you `switch` over a union that might grow.

</Callout>

Finish `play(player, computer)` so it returns `"win"`, `"lose"` or `"draw"` for the player. The return type is `Result`, so TypeScript will complain if you return anything else (try returning `"won"` to see it). For a bonus, use a `switch` with a `never` check, like `beats` in the lesson.

<Hint>

If `player === computer`, it's a draw. Otherwise, write a helper `beats(move: Move): Move` with a `switch` that returns the move each one defeats (rock returns `"scissors"`, and so on). If `beats(player) === computer`, the player wins; if not, they lose.

</Hint>

<Solution>

```ts
type Move = "rock" | "paper" | "scissors";
type Result = "win" | "lose" | "draw";

function beats(move: Move): Move {
  switch (move) {
    case "rock":
      return "scissors";
    case "paper":
      return "rock";
    case "scissors":
      return "paper";
    default: {
      const unreachable: never = move;
      return unreachable;
    }
  }
}

function play(player: Move, computer: Move): Result {
  if (player === computer) {
    return "draw";
  }
  if (beats(player) === computer) {
    return "win";
  }
  return "lose";
}

console.log(play("rock", "scissors")); // win
console.log(play("rock", "paper")); // lose
console.log(play("paper", "paper")); // draw
```

</Solution>

## Recap

- A **literal type** allows one exact value; a union of literals like `"rock" | "paper" | "scissors"` is a precise list of options.
- `type Name = ...` gives a type a reusable name.
- `switch` compares one value against many `case`s; end each with `return` or `break`.
- TypeScript checks that every case is a valid option.
- Assigning to a `never` variable in `default` makes TypeScript warn you about forgotten cases.
