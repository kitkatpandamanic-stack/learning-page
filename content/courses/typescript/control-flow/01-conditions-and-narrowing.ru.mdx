Программам нужно **принимать решения**: достаточно ли игроку лет? Это значение — число или текст? В этом уроке вы будете писать условия с `if` и `else` и увидите один из лучших трюков TypeScript: он **сужает** тип значения, когда код разветвляется.

## `if`, `else if` и `else`

`if` выполняет свой блок, только когда его **условие** (condition) равно `true`. Добавьте `else if` для дополнительных вариантов и `else` для «всего остального». Условия проверяются сверху вниз, и выполняется только **первый** подходящий блок:

<CodeExample output="Наденьте свитер 🧶">

```ts
const temperature: number = 14;

if (temperature >= 25) {
  console.log("Погода для шорт ☀️");
} else if (temperature >= 10) {
  console.log("Наденьте свитер 🧶");
} else {
  console.log("Пальто и шарф! 🧣");
}
```

</CodeExample>

## Операторы сравнения и логические операторы

Сравнения возвращают `boolean` — ровно то, что нужно условию:

| Оператор          | Значение                         |
| ----------------- | -------------------------------- |
| `===` / `!==`     | равно / не равно                 |
| `<` `>` `<=` `>=` | меньше, больше или равно         |
| `&&`              | И: оба должны быть истинны       |
| `\|\|`            | ИЛИ: хотя бы один истинен        |
| `!`               | НЕ: меняет true на false и наоборот |

<CodeExample output={`true
false
false`}>

```ts
const age: number = 15;
const hasTicket: boolean = true;

const canEnter: boolean = age >= 12 && hasTicket;
console.log(canEnter);
console.log(age === 18 || !hasTicket);
console.log(!canEnter);
```

</CodeExample>

TypeScript также замечает сравнения, которые никогда не могут быть истинными, — например, сравнение числа со строкой:

```ts
const age: number = 15;

if (age === "18") {
  // ❌ Error: This comparison appears to be unintentional because the types 'number' and 'string' have no overlap.
}
```

<Callout type="tip" title="Всегда используйте ===">

Пишите `===` и `!==`, а не `==` и `!=`. Версии с двумя знаками равенства тайком преобразуют типы (`"1" == 1` даёт `true`!) — а именно от таких сюрпризов TypeScript и пытается вас уберечь.

</Callout>

## Объединения типов: это ИЛИ то

Иногда значение законно может быть одного из нескольких типов. Идентификатор может быть числом вроде `42` или кодом вроде `"ab-12"`. **Объединение типов** (union type) говорит об этом с помощью `|`:

```ts
let id: string | number = 42;
id = "ab-12"; // тоже можно
id = true;
// ❌ Error: Type 'boolean' is not assignable to type 'string | number'.
```

Но есть подвох: использовать можно только то, что работает для **каждого** типа в объединении.

```ts
function formatId(id: string | number): string {
  return id.toUpperCase();
  // ❌ Error: Property 'toUpperCase' does not exist on type 'string | number'.
}
```

Это логично: если `id` — число, вызов `.toUpperCase()` упал бы.

## Сужение типа с помощью `typeof`

Проверьте тип через `typeof`, и TypeScript **сузит** объединение внутри каждой ветки — это называется **сужение типа** (narrowing):

<CodeExample output={`AB-12
#0042`}>

```ts
function formatId(id: string | number): string {
  if (typeof id === "string") {
    return id.toUpperCase(); // id: string
  }
  // Сюда доходят только числа, поэтому id: number
  return "#" + id.toString().padStart(4, "0");
}

console.log(formatId("ab-12"));
console.log(formatId(42));
```

</CodeExample>

После того как `if` сделал `return`, TypeScript знает, что до последней строки могут дойти только числа. Вы не писали никаких дополнительных типов: сама проверка объяснила TypeScript, что такое `id`.

## Сужение по истинности для `null`

Значения, которые в условии считаются ложью, называются **ложными** (falsy): `false`, `0`, `""` (пустая строка), `null`, `undefined` и `NaN`. Все остальные — **истинные** (truthy). Поэтому `if (name)` — быстрый способ исключить `null`:

<CodeExample output={`С возвращением, Маша!
Добро пожаловать, гость!`}>

```ts
function welcome(name: string | null): string {
  if (name) {
    return `С возвращением, ${name}!`; // name: string
  }
  return "Добро пожаловать, гость!";
}

console.log(welcome("Маша"));
console.log(welcome(null));
```

</CodeExample>

<Callout type="warning" title="Осторожно с 0 и пустыми строками">

`if (value)` отбрасывает ещё и `0`, и `""`. Если это допустимые значения (счёт `0` — тоже счёт!), проверяйте именно на null: `if (value !== null)`.

</Callout>

<CodeExample output={`Счёт: 0
Счёта пока нет`}>

```ts
function showScore(score: number | null): string {
  if (score !== null) {
    return `Счёт: ${score}`; // score: number
  }
  return "Счёта пока нет";
}

console.log(showScore(0));
console.log(showScore(null));
```

</CodeExample>

Датчик погоды передаёт показание в `describeTemp(temp)`. Показание может быть **числом** (градусы), **строкой** (сообщение о состоянии, например `"не в сети"`) или **null** (показаний нет вообще). Сначала исправьте ошибку типа, задав `temp` объединение типов, а затем верните правильное описание для каждого случая из стартового кода.

<Hint>

Сначала обработайте `null` с помощью `if (temp === null)`. Не используйте `if (!temp)`: так `0` градусов превратится в «нет данных». Затем `if (typeof temp === "string")` обработает сообщения. После этих двух проверок TypeScript знает, что `temp` — число, и его можно сравнивать через `<`.

</Hint>

<Solution>

```ts
function describeTemp(temp: number | string | null): string {
  if (temp === null) {
    return "Нет данных";
  }
  if (typeof temp === "string") {
    return "Датчик сообщает: " + temp;
  }
  // здесь temp — число
  if (temp < 10) {
    return "Холодно";
  } else if (temp < 25) {
    return "Тепло";
  } else {
    return "Жарко";
  }
}

console.log(describeTemp(18)); // Тепло
console.log(describeTemp("не в сети")); // Датчик сообщает: не в сети
console.log(describeTemp(null)); // Нет данных
```

</Solution>

## Итоги

- `if` / `else if` / `else` выполняют первый блок, условие которого равно `true`.
- Сравнения (`===`, `<`, ...) и логические операторы (`&&`, `||`, `!`) дают логические значения.
- **Объединение типов** вроде `string | number` допускает несколько типов, но использовать можно только то, что подходит им всем.
- Проверки `typeof` **сужают** объединение внутри каждой ветки.
- `if (value)` исключает `null`, но заодно и `0` с `""`; если они допустимы, используйте `!== null`.
